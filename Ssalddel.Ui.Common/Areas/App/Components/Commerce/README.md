## 페이지 책임

### 공개 안내

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 익명 포함 전체 사용자, `/commerce/notices`, `통신판매안내Page.razor`; 통합·웹·주문자·음식점 wrapper |
| 대상·진입 문맥 | 홈·회원가입·거래 확인에서 현재 안내를 읽기 위해 진입 |
| 한 문장 목적 | 누구나 현재 중개·개인정보 기준과 문의할 곳을 확인한다 |
| 완료 결과·상태별 주 행동 | 조회 성공은 현재 문서 확인, 실패는 재조회. 거래 실행 없음 |
| 기본 정보 | 중개 사실·안내 버전·운영 준비·운영 연락처 |
| 보조 정보 | 개별 문서는 펼쳐 원문 확인; 모든 원문을 첫 화면에 나열하지 않음 |
| 독립 업무·제외 정보 | 판매자 정보 등록·권리 요청·분쟁은 독립 경로; 개인 원장·증거 제외 |
| 진입·실패·복귀 | loading/error/retry, 홈 복귀. 익명 조회 유지 |
| 코드·API·DB | `통신판매안내ViewModel` → `통신판매보호Client` → 공개 notices API → 서버 운영 설정 |
| 책임 판정·검증 | 안내 조회에 단일 책임. 실제 공유 Razor 예시 렌더, 운영 설정·법적 준비 완료 증거 아님 |

| 책임 판정·검증 | 요청 접수와 진행 확인에 단일 책임. 접수/보존/실패 예시 렌더; 실제 권리 실행 완료 증거 아님 |

### 거래 문제 신고

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 인증된 거래 당사자, `/commerce/disputes`와 `/{caseId}`, `보호지원Page` |
| 대상·진입 문맥 | 상세의 sourceKind/sourceId로 연결한 본인 참여 거래와 선택 사건 |
| 한 문장 목적 | 거래 당사자가 해당 원장의 문제를 접수하고 처리 경과를 확인한다 |
| 완료 결과·상태별 주 행동 | 접수·서버 허용 추가 내용·이의제기; 처리 준비를 실제 통지로 표시하지 않음 |
| 기본 정보 | 거래 종류·문제 내용 입력·현재 상태·영업일 기한/달력 확인 상태 |
| 보조 정보 | 처리 이력은 접기; 공개 목록에 증빙 원문을 나열하지 않음 |
| 독립 업무·제외 정보 | 주문 상태 변경·배송 수행·환불은 해당 원장 업무; 상대 비공개 증거와 신원 제외 |
| 진입·실패·복귀 | 연결 없는 진입은 거래 상세에서 시작 안내. 로그인/loading/empty/error/retry/disabled, 상세에서 목록 복귀 |
| 코드·API·DB | `보호지원ViewModel` 분쟁 모드 → transaction-disputes API → 서버 원장 소유 검증·`commerce_privacy_support_private` |
| 책임 판정·검증 | 특정 거래 문제와 경과 확인에 단일 책임. 접수/추가 내용/잠정 기한 예시 렌더; 운영 통지·환불 증거 아님 |

서버의 원장·권한·성년·판매자 확인 결과가 실행을 결정한다. 화면 확인은 신원 인증, 신고·입금·외부 알림 실행이 아니다. 공개 안내와 본인 처리 화면은 분리한다. 개인정보 증빙과 상대방 신원은 공통 목록에 노출하지 않는다. 거래 관련 안내는 주문 확인 단계에 같은 글자 크기로 표시하고 전체 안내로 연결한다.

Figma `01 Community`에는 이 신규 공통 페이지에 대응하는 동기화 증거가 없다. 실제 공유 Razor를 로컬 호스트에서 320/390px 검토하며, Figma 동기화·실휴대폰·Azure·실공개 운영은 별도 확인한다.

페이지·ViewModel·API·저장의 구체적 연결은 [공통 화면 매핑](../../../../../docs/ProjectOverview/page-docs/commerce-protection-r25.md)을 참조한다. 법령과 운영 설정은 [통신판매 중개와 개인정보 보호](../../../../../docs/Architecture/CommerceIntermediaryPrivacy.md)를 단일 기준으로 사용한다.
