# 법정동별 소형 화물·퀵 배차 학습 준비

[구현 범위 r67](../../../docs/AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-regional-training.implementation.r67.md)을 따르는 로컬 검토 도구다. 공식 법정동 코드에 가상 주문·기사 조건을 결합해 **기존 규칙·모델 제안·사람 의견**을 비교한다. 모델 가중치를 학습하거나 운영 배차를 실행하지 않는다.

## 준비된 자료

- [지역 이름표](legal-dong-regions.json): 서울 15개 법정동의 10자리 코드·명칭과 공식 보관 원문의 연결이다. 행정동 코드를 섞지 않는다.
- 검토 20개: 장기 대기, 기한 변화, 다른 법정동의 가까운 후보, 현재 수행의 마지막 목적지, 적재 중량, 적재 부피, 신규 수신, 위치 관측 나이, 복귀 방향, ETA 누락의 10상황군 × 2변형이다.
- 독립 평가 8개: 기한·적재 결합, 수행 중·오래된 위치 결합, 적격 후보 없음, 동등한 복수 선택의 별도 4상황군 × 2변형이다. 같은 상황군을 검토와 평가 양쪽에 나누지 않는다.
- 모든 기사·주문·ETA·적재·위치 나이·보수는 가상이다. 고객·상세 주소·좌표·실제 기사 식별자를 넣지 않는다. 5,000원 운임도 가상 입력이다.
- `국내화물배차조율Service`의 순수 조율을 실제 호출한 결과는 비교 기준(`current_cargo_rule`)이다. 최적 정답이나 사람의 승인이 아니다. 모델은 최초 `not_run`, 사람 검토는 최초 미기록이다.

## 실행

저장소 루트에서 .NET 10 SDK를 사용한다. 로컬 준비와 검토에는 운영 서버·운영 DB·휴대폰이 필요하지 않다. 공식 원본 ZIP이 로컬 비공개 보관 위치에 있어야 지역의 출처까지 검증할 수 있다. 이 도구는 누락 원본을 자동 다운로드하지 않는다.

```powershell
# 자료와 출처 해시를 준비하고 조회한다. 모델을 호출하지 않는다.
dotnet run --project eng/CargoRegionalTrainingReview -- --prepare

# 별도 사본과 대역 모델로 검토·동시 변경·내보내기 경계를 확인한다.
dotnet run --project eng/CargoRegionalTrainingReview -- --self-check

# 데스크톱 브라우저 검토 화면을 연다.
dotnet run --project eng/CargoRegionalTrainingReview -- --port 5595
```

검토 주소는 `http://127.0.0.1:5595/admin/freight-delivery/dispatch-ai-review/training`이다. 호스트는 loopback HTTP와 Blazor SignalR를 사용한다. 외부 공개 서버나 실제 운영 API/DB에 연결하는 경로가 아니다. 기본 포트는 5595이며 같은 포트가 사용 중이면 다른 로컬 포트를 지정한다. `Ctrl+C`로 호스트를 종료한다.

화면에서는 픽업 법정동·자료 구분·미검토 여부로 찾고, 주문 조건과 후보별 ETA·대기·가용 지역·적재 조건을 확인한다. 기존 규칙과 모델을 비교한 뒤 `적절함 / 수정 의견 / 판단 보류`, 허용 후보 여러 명 또는 배차 보류, 메모를 저장한다. 메모에 실제 이름·주소·연락처를 입력하지 않는다.

## 기존 Ollama와 비교

이미 사용 중인 Docker Ollama의 `http://127.0.0.1:12681/`와 설치된 `qwen3:1.7b`만 사용한다. 컨테이너·모델을 자동 설치하거나 시작하지 않으며 다른 원격 모델로 바꾸지 않는다. 모델 digest와 프롬프트·입력 해시를 결과에 연결한다.

대상은 기존 `mirror-local-dispatch-ai-ollama-1` 컨테이너다. 추론 요청은 `http://127.0.0.1:12681/api/generate`에 JSON Schema를 전달하며 `temperature=0`, `think=false`, `stream=false`를 사용한다. 공식 근거는 [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)과 [Generate API](https://docs.ollama.com/api/generate)다. 구조화 출력과 결정적 입력은 판단의 정확성이나 모델 학습을 자동 보장하지 않는다.

```powershell
# 앞의 검토 사례 세 개만 실제 로컬 모델과 비교한다.
dotnet run --project eng/CargoRegionalTrainingReview -- --compare-first 3
```

화면의 `이 사례 모델과 비교`로 한 사례만 실행할 수도 있다. 모델은 가능한 후보 ID 또는 보류와 허용된 이유 코드만 반환한다. 제외 후보·근거 없는 이유·잘못된 구조는 유효한 선택으로 취급하지 않는다. 한 비교의 제한은 20초이며 지연·미설치·연결 실패·잘못된 응답을 따로 기록한다. 실패를 기존 엔진과 같은 선택이나 판단 성공으로 집계하지 않는다. 이 제한은 실제 퀵 운영 SLA가 아니다.

## 검토 원장과 승인 자료

기본 저장 위치는 `artifacts/local/cargo-regional-training-r113/review/<자료 SHA-256>/`다. `--data-root`로 바꿀 때도 저장소의 `artifacts/local/` 아래를 사용한다.

| 파일 | 의미 |
| --- | --- |
| `dataset.json` | 변하지 않는 초기 사례·지역·입력·기존 엔진 결과 |
| `sources.json` | 실제 사용 소스 경로·해시와 자료/정책 판본 |
| `review-events.jsonl` | 사람 검토와 모델 비교의 추가 이력 |
| `approved-<SHA-256>.jsonl` | 명시적으로 승인·정정한 검토 사례만 내보낸 자료 |
| `approved-<SHA-256>.manifest.json` | 내보낸 파일의 해시·행 수·평가 제외 수 |

자료·입력·정책 해시와 검토 revision을 확인한다. 같은 요청 ID·내용은 중복 기록하지 않고, 같은 ID의 다른 내용이나 오래된 revision은 충돌로 반환한다. 모델 비교가 달라지면 그 결과를 본 상태에 맞춰 다시 검토한다. 소스가 바뀌면 예전 판본의 승인을 현재 판본에 소급하지 않는다.

```powershell
# 모델 실행과 별개다. 사람이 승인한 review만 내보낸다.
dotnet run --project eng/CargoRegionalTrainingReview -- --export-approved
```

사람 검토가 없으면 승인 자료는 빈 파일이다. `holdout`은 검토했더라도 학습 자료 내보내기에서 제외한다. 내보내기는 학습기의 대화 형식 변환·학습 실행·Ollama 모델 교체가 아니다. 화면에서 평가 문제를 보거나 반복 조정에 사용했다면 이후 새 모델의 미지 자료 성능을 증명하는 평가로 그대로 재사용하지 않는다.

## 출처와 해석의 한계

지역은 행정표준코드관리시스템의 **2026-08-11 수집 원본**에 존재하는 코드만 사용한다. 공급처의 효력 기준일은 원문에 없어 `null`이며 오늘의 현행 상태를 재확인한 자료가 아니다. 원본 ZIP·내부 CP949 텍스트·선택한 원문 행의 해시를 검증한다. 공급처 이용조건은 추가 검토가 필요하고 재배포 승인은 없다.

법정동은 이름표와 집계 단위다. 경계·인접·도로 연결·거리·차량별 실제 이동시간은 확보한 것으로 표시하지 않는다. 같은 법정동이면 항상 가깝다거나 다른 법정동이면 멀다고 결론내리지 않는다. 현재 위치와 수행 종료 후 가용 지역을 분리하고, 가상 ETA는 **가용까지 남은 분 + 가용 후 이동 분**으로 계산한다.

28개 사례와 15개 법정동은 첫 문답·검토 범위다. 학습 자료가 충분하다거나 새로운 지역·실제 운영에서 잘 배차한다는 성능 증거가 아니다.

검토용 적격성·점수 함수는 신규 수신, 기존 약속, 남은 kg/L, 위치 나이 5분, ETA 유무와 픽업 기한을 투명하게 검사하는 fixture다. 실제 제품 guard·차량 자격·특수 취급·구간 적재·실제 원장의 현재성 검증을 대신하지 않는다. 개인 평균 4,000원이나 플랫폼 확정 손익은 이번 학습 목표로 넣지 않았다.

기존 운영 관리자 화면·운영 DI·메뉴·worker 설정을 바꾸지 않는다. 공유 검토 컴포넌트는 이 로컬 호스트에서 연결해 사용한다. APK·휴대폰·Unity·영상·운영 DB·실제 추천/수락/알림·결제/지급·외부 배포·커밋/푸시는 이 도구의 실행 범위가 아니다. 빌드·시험·브라우저 확인·실제 모델 비교의 실행 결과는 별도 검증 기록에서 확인한다.
