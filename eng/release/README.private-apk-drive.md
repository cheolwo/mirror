# Google Drive APK 보관과 GitHub 다운로드 안내

기존 APK 제작 절차를 유지하고 보관 위치만 Google Drive로 선택할 수 있다. 이 문서는 [주문 한 건 마감 r70](../../docs/AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/order-closeout.design.r70.md)의 배포 준비 범위다. Google Play 등록 여부와 관계없이 앱의 서명·버전·서버 접속·접근 권한 검증은 필요하다.

## 이번 판본의 구분

- USB 시험판: `publish-mobile-usb-test.ps1`이 만든 Debug APK. 서버 주소는 `http://127.0.0.1:5363/`이며 PC 서버와 USB 포트 연결이 있어야 통신한다. 개인 Drive에 시험판을 보관할 수 있지만 일반 사용자용 서비스로 안내하지 않는다.
- 외부 시험 배포판: `publish-mobile-field-test.ps1`이 요구하는 외부 HTTPS 주소와 저장소 밖의 배포 서명키로 제작한다. 기존 앱 업데이트 시 같은 앱 식별자·서명과 증가한 버전 번호를 확인한다. 새 키로 바꿔 이전 앱을 지우거나 데이터를 초기화하는 일을 자동 수행하지 않는다.

## 보관·안내 순서

1. 같은 주문의 로컬 업무 마감과 수정판 앱 빌드를 확인한다.
2. 기존 제작 도구가 기록한 앱 식별자·버전·서명 인증서 지문·APK 크기/해시·내장 서버 주소를 대조한다.
3. 연결된 Google Drive의 실제 업로드 도구에 **검증한 APK 파일의 절대 경로**만 전달한다. 파일 본문이나 자격 증명을 대화에 출력하지 않는다. 이전 판본은 덮어쓰지 않고 판본을 포함한 새 파일로 보관한다.
4. 완료 응답의 실제 파일 ID/URL을 저장하고 메타데이터에서 이름·크기·가능한 원격 체크섬을 재확인한다. 업로드 완료와 원격 파일 전체 재다운로드 해시 일치는 구분한다.
5. GitHub 다운로드 안내에는 그 확인된 URL과 아래의 최소 정보만 넣는다. 로컬 원본 경로·전체 dirty 목록·인증 자료가 들어 있는 시험 manifest는 공개하지 않는다.
6. 소유자 전용·지정 사용자 공유·익명 다운로드를 구분한다. 링크가 생겼다는 이유만으로 누구나 내려받을 수 있다고 보고하지 않는다. 연결 도구가 지원하지 않는 공유 권한은 설정 성공으로 간주하지 않는다.

## GitHub에 남길 최소 정보

| 항목 | 내용 |
| --- | --- |
| 판본 | 앱 이름, 앱 식별자, 표시 버전, 증가한 버전 번호 |
| 용도 | USB 로컬 시험 / 외부 비공개 시험 / 운영 중 실제 해당 범위 |
| 다운로드 | 실제 업로드 응답에서 확인한 Drive URL만 사용 |
| 무결성 | APK 크기와 로컬 SHA-256, 원격 확인 수준 |
| 업데이트 | 서명 인증서 지문, 이전 판본과 업데이트 호환 여부 |
| 접속 | 내장 서버 주소와 현재 서버 통신 검증 여부 |
| 검증 | 빌드·설치·기기 업무 완주·푸시 수신을 각각 표시 |
| 변경 | 사용자가 알아야 할 이번 보완 사항 |

외부 주소·배포 서명·접근 권한이 준비되지 않았으면 해당 항목을 미준비로 남긴다. 임의의 다운로드 URL이나 공개 성공 상태를 채우지 않는다. GitHub 게시·commit/push는 실제 실행 결과와 별도로 보고한다.
