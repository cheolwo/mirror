# Unity 2D 지도 객체 배치·조작

기존 지도에서 무엇이 보이고 선택되는지와 그 입력이 어느 상태를 바꾸는지 연결한다. 현재 요청과 대상 checkout의 AGENTS를 먼저 따르며 스킬 호출을 Scene 변경·게임 규칙·배차 실행의 추가 권한으로 해석하지 않는다.

## 대상과 입력 확인

- [현재 작업](../../../docs/AI/CURRENT_WORK.md)과 [Unity 작업 영역](../../../eng/work-areas/unity.json)에서 실제 게임 소스·검토판·Scene·허용 경로·판본·실행 소유를 확인한다. 기본 Unity checkout과 별도 검토 게임을 같은 판본으로 단정하지 않는다.
- 객체의 고유 ID, 현재 배치 위치·방향·그림·충돌/선택 영역, 선택 상세와 복귀, 카메라·UI 입력 경로를 확인한다. Presenter/View와 Inspector/Prefab 연결까지 읽는다.
- 사용자가 바꾸려는 한 조작을 정한다. 예: 기사 선택 뒤 상세 보기, 동네 핀 선택 뒤 이동, 지도 드래그와 클릭 분리. 현재 바퀴 방향·줌 범위·지역 전환 조건을 다른 지도 기획의 값으로 덮지 않는다.

## 필요한 정본만 읽기

- 배치 책임·계획·실제 조립은 [지도구성과 세계자산배치 분리](../../../docs/Architecture/지도구성과세계자산배치분리.md)를 따른다.
- 입력·카메라·초점·업무 권위는 [전략 카메라 기준](../../../docs/Architecture/UnitySimulationWorldStrategyCamera.md)과 대상 소스에서 대조한다. 이 문서의 과거 키·거리·기본 3D Rig를 현재 2D 게임의 확정 입력으로 이식하지 않는다.
- 자료→객체 연결 자체가 바뀔 때만 [지도 데이터 연결](../hongdal-unity-map-data-binding/SKILL.md)을 함께 읽는다. 단순 선택·줌 문제 때문에 외부 자료를 새로 수집하지 않는다.
- 시각적 구성이 바뀌면 [화면 시안 절차](../../../docs/Architecture/화면시안선행제작절차.md)의 현재 승인·검토 범위를 확인한다. 승인된 같은 작업을 다시 승인받게 만들지 않는다.

## 좁게 배치·입력 정리

1. 같은 합성 입력과 카메라 위치에서 문제를 재현한다. 화면 좌표·지도 좌표·World 좌표와 배치 원점·축·축척을 구분한다. 잘못된 위치를 임의 좌표로 가리지 않는다.
2. 기존 Sprite/Renderer/Prefab·선택 영역·정렬 값을 재사용한다. 아이콘에 필요한 범위에서만 시각 요소를 바꾸고 새 Tilemap·프레임워크·MCP 설치를 전제하지 않는다. 오토바이만으로 식별되는 기존 화면에 설명 텍스트를 자동 추가하지 않는다.
3. 화면→World 변환은 현재 Camera와 지면 평면/깊이를 기준으로 확인한다. 2D 평면의 실제 축과 UI Canvas 모드를 확인하고 예제의 z=0이나 3D Raycast를 무조건 적용하지 않는다.
4. UI 위 입력은 World 선택·카메라 드래그와 겹치지 않게 한다. 현재 Input System/UI 모듈을 재사용하고 클릭과 드래그의 시작·이동·해제, 선택 해제와 같은 업무 복귀를 검증한다.
5. 같은 ID/판본을 다시 적용해 객체·이벤트 구독이 중복되지 않는지, 화면 밖 관심 범위와 해제 후 참조·선택 상태가 올바른지 확인한다. 동일 자료의 표현 중복은 현재 View·구독 수명에서 먼저 조사하고, 원본 정규화·자료 계약 변경이 필요할 때만 자료 연결 작업으로 인계한다. 단순 레이어 묶음을 세로 높이·게임 단계로 해석하지 않는다.
6. 객체 이동·방향 전환은 검증된 기존 경로와 가상 시계 상태를 표현한다. 카메라 이동·선택·애니메이션만으로 수령·보수·운영 완료를 확정하지 않는다. 허용된 게임 명령은 기존 명령 경로로 전달한다.

## 검증과 반환

- 바뀐 로직의 의미 있는 회귀와 해당 소비 프로젝트 검증을 실행한다. 현재 checkout의 검증 계약과 대상 AGENTS의 Pipeline/CLI 순서를 사용하고 다른 Editor·게임 창을 점유하지 않는다.
- 선택·카메라·배치처럼 화면에서 판단할 항목과 사용자가 실제 화면을 요청한 항목은 같은 Scene·합성 ID·입력·폭에서 Game View와 실제 입력을 확인한다. 코드 시험·Scene View·스크린샷 한 장을 실제 조작 완료로 승격하지 않는다.
- 예를 들어 UI 위 클릭, 지도 드래그 후 객체 오선택, 줌 전후 같은 핀 선택, 선택 해제·복귀, 같은 판본 재적용과 늦은 응답을 변경 영향에 맞춰 고른다. 관련 없는 전수 시험을 반복하지 않는다.
- 입력·카메라 상태와 게임/운영 상태를 따로 기록한다. 실제 화면 검증이 막히면 코드/시험 결과와 화면 미완료를 구분하고 같은 항목의 재개 위치를 남긴다.
- 결과는 대상 판본·입력→변경한 배치/조작→실제 검증→남은 한 가지로 반환한다. 새 API·게임 정책·배차·정산 규칙이나 운영 쓰기는 현재 요청에 별도로 포함된 경우에만 다룬다.
