# 기존 업무 화면 가독성 정리

현재 역할의 업무를 더 읽고 조작하기 쉽게 만들고 같은 입력·선택·조회·저장·복귀 결과를 보존한다.
프로젝트의 상시 규칙과 실제 실행 소유는 [AGENTS.md](../../../AGENTS.md)를 따른다. 이 스킬은 새 실행권을 만들지 않는다.

## 시작 입력

- 대상 화면의 역할·route 또는 기존 화면 ID, 실제 소비 플랫폼과 현재 코드 판본을 확인한다.
- 사용자가 읽거나 조작하기 어려워한 조건, 대표 가상 업무·입력·상태와 기존 검증 근거를 찾는다.
- 허용된 수정 경로와 화면·빌드·호스트·기기 소유를 확인한다. 이미 승인된 같은 범위를 다시 묻지 않는다.
- 정보가 부족하면 확인 가능한 기존 구조부터 조사하고, 완료에 필요한 미확인 값만 분리한다.

## 필요한 기준만 읽기

- [역할 앱 시각 디자인 기준](../../../docs/Architecture/RoleAppVisualDesignStandard.md): 해당 역할의 우선 정보·조작과 기존 디자인 값.
- [페이지 단일 책임 기준](../../../docs/Architecture/WholeRoadmapPagePrinciple.md): 같은 업무의 정보·행동·실패·복귀 경계.
- [화면 시안 선행 절차](../../../docs/Architecture/화면시안선행제작절차.md): 의미 있는 시각 변경의 현재 시안·구현·대조 절차.
- 대상 역할·화면의 기존 상세 README와 책임 카드를 먼저 읽고 필요한 부분만 갱신한다.
- 실제 화면이 바뀌면 [시각 변경 기록](../../../docs/Changes/README.md)의 근거 구분을 함께 적용한다.

## 보존할 결과와 읽는 순서 정하기

책임 카드에서 이 화면의 업무 질문 하나, 우선 정보 세 가지, 현재 상태의 주 행동과 같은 업무 복귀를 확인한다.
판매자·창고·음식점·주문자·기사·운영자의 판단을 구분하고 다른 역할의 표나 카드 구조를 그대로 이식하지 않는다.
변경 전에 무엇을 더 읽기·이해·수정하기 쉽게 할지와 동일 조건에서 보존할 결과를 짧게 기록한다.
기존 route·stable ID·표시 내용·중요 값·권한·행동 조건·요청 ID를 보존 대상으로 둔다.
없음·미확인·부분 완료·오류를 구분하고, 미확인 금액·수량·시각을 0이나 성공으로 채우지 않는다.

## 실제 연결을 따라 좁게 정리하기

대상 컴포넌트와 부모 조립, ViewModel·바인딩, 조회 서비스·계약까지 따라가 표시 값과 상태의 소유자를 확인한다.
현재 공통 테마·컴포넌트·디자인 값·역할 예외를 찾고, 영향이 분명한 한 부분부터 수정한다.
제목·본문·상태·수량의 위계, 줄바꿈·정렬·대비·간격·정보 밀도 중 재현한 문제에 필요한 항목을 고른다.
설명을 늘리거나 새 요약 수치·버튼·업무 단계를 추가해 빈 공간을 채우지 않는다.
기존 글꼴·아이콘·컨트롤을 재사용하고 대규모 이름 변경·폴더 이동·새 UI 의존성을 이 작업에 섞지 않는다.
공통 UI 변경이면 실제 소비 역할을 확인하고 한 역할의 보기 개선으로 다른 역할의 주 행동을 가리지 않는다.

플랫폼별 구현 방식은 유지한다.

- Blazor는 기존 Razor 조립·CSS·테마·바인딩과 라우터의 연결을 확인한다.
- MAUI·WPF는 기존 네이티브 컨트롤·리소스·스타일과 글자 측정·입력 방식을 확인한다.
- CSS를 네이티브에 복사하거나 Web 렌더를 네이티브 화면 검증으로 표현하지 않는다.

의미 있는 화면 변경은 현재 승인과 시안 절차에 맞춰 선택한 범위만 구현한다.
이미 같은 시안·범위의 구현이 승인되어 있으면 새 확인 절차를 만들지 않고 필요한 보완과 검증을 이어간다.
외형이 바뀌지 않는 순수 코드 정리에는 화면 변경이나 비교 시안을 억지로 만들지 않는다.

## 같은 조건으로 검증하기

같은 가상 ID·입력·선택·상태에서 중요한 값과 허용 행동을 대조한다.
입력 중 값과 적용된 검색·필터, 늦은 조회 응답, 선택·초점, 저장 결과와 목록 복귀를 확인한다.
로딩·빈 목록·오류·재시도·비활성과 긴 식별자·금액·수량 단위가 읽히는지 확인한다.
좁은 폭과 넓은 폭에서 겹침·잘림·가로 넘침·스크롤·고정 행동을 확인한다. 해당 화면에 필요한 폭만 고른다.
키보드·터치 방식과 네이티브 복귀 상태도 실제 소비 플랫폼의 검증 범위로 구분한다.

화면이 바뀌면 같은 조건의 수정 전후 원본과 비교 근거를 새 로컬 산출물에 남긴다.
실제 라우터·클릭·입력 또는 승인된 기기의 현재 화면을 사용하고 정적 출력·이벤트 시험과 구분한다.
Figma·computer-use 등 보유 도구는 해당 작업과 실제 사용 환경에 맞을 때 활용한다.
도구가 없다는 이유로 새 MCP·Playwright·브라우저 의존성 설치나 다른 UI 기술 전환을 강제하지 않는다.
필수 화면을 확인할 수 없으면 제한과 마지막 정상 화면을 남기고 해당 항목을 `screen_pending`으로 유지한다. 이전 화면 원본이 없으면 미확보로 기록한다.

실제 변경 경로를 현재 `eng/validate-changes.ps1 -Paths` 계약에 맞게 지정해 Fast·관련 회귀·필요 소비 빌드·Task를 수행한다.
같은 판본에서 이미 통과한 원본 근거는 대조해 재사용하고, 0-test·중간·실패·미실행을 통과로 쓰지 않는다.

## 반환할 결과

대상 역할·화면과 판본 → 발생 조건 → 최소 수정 → 실제 검증 결과 → 먼저 재개할 한 가지와 정확한 위치를 연결하고 다른 미확인 항목도 보존한다.
변경 경로와 명령·종료값·화면 원본 위치를 기존 상세 README·변경 기록·현재 작업에 필요한 범위만 반영한다.
코드·자동시험·웹 화면·네이티브/기기·운영 사용을 구분하고 보지 않은 화면의 완료를 선언하지 않는다.
