# Unity 지도 자료와 배치 객체 연결

## 먼저 대상과 범위를 확인한다

- [공통 지침](../../../AGENTS.md)과 대상 checkout의 가까운 `AGENTS.md`, [현재 작업](../../../docs/AI/CURRENT_WORK.md)을 읽는다.
- 요청한 결과, 실제 소스·실행판·자료 판본, 현재 편집·실행 소유와 허용 경로를 확인한다. 이미 명시된 사용자 범위는 그대로 수행하며 같은 승인을 다시 묻는 단계를 만들지 않는다.
- 현재 경영 게임 검토판, 원 Unity checkout, backend의 `Ssalddel.Unity`를 같은 소스로 간주하지 않는다. 현재 기록에서 실제 소비 프로젝트를 찾고 그 branch·HEAD·관련 dirty·참조 파일 지문을 기록한다.
- [Unity 작업 영역](../../../eng/work-areas/unity.json)과 [작업 흐름 분리](../../../docs/Architecture/OperationsSimulationUnity작업흐름분리.md)는 저장소·책임을 찾을 때 읽는다. 과거 검토판이나 보관한 담당의 완료 기록을 현재 실행권으로 쓰지 않는다.
- 이번 변경은 자료 한 종류에서 기존 객체 한 종류까지의 검증 가능한 연결로 좁힌다. 다른 화면·수집기·정책·배포를 함께 확장하지 않는다.

## 입력 자료의 의미를 고정한다

1. 원본 또는 승인된 정리본에서 자료 ID·출처·SHA와 자료 판본을 확인한다. 공급자 안내 `metadata`, 관측 `dataset`, 게임용 합성 사례를 구분한다.
2. 관측 기준시각과 취득시각, 단위·통화, 지역 고유 ID, 좌표계·정밀도·변환 기준, 결측·오류·stale 상태를 대조한다. 취득한 날짜를 관측 기준일로 덮지 않는다.
3. 연결할 source ID·world ID·presentation ID와 사용 역할을 찾는다. 기존 고유 ID·공개 계약·직렬화 필드·`.meta` GUID를 이름 정리 때문에 바꾸지 않는다.
4. 명시된 좌표·지역 결속이 없으면 미배치·미확인으로 남긴다. 실제 위치를 임의의 `0,0`이나 화면 중앙으로 채우지 않는다. 승인된 가상 사례의 합성 좌표는 실제 지리 자료와 구분해 사용할 수 있다.
5. 현재 자료와 게임의 호환성·자료 revision을 확인하고, 진행 중 회차가 동결한 입력을 외부 자료 갱신만으로 바꾸지 않는다. 없는 값·연결·실패를 성공 fixture로 숨기지 않는다.

## 기존 연결을 따라 좁게 적용한다

- 실제 소비 경로를 `입력/조회 → Mapper·Adapter → 해석 결과 → Presenter → View·배치 객체` 순으로 추적한다. 부모 조립·주입·Inspector·설정까지 확인해 사용되지 않는 새 구현을 완료로 보고하지 않는다.
- Data에는 허용된 값·출처·시각·단위·판본을, Interpretation에는 그 관계와 공간 의미를, Presentation에는 기존 화면·객체 표현을 둔다. 새로운 공통 엔진·Tilemap·프레임워크·MCP를 전제로 삼지 않는다.
- 같은 ID의 갱신·삭제·재등장, 낮은 revision·늦은 응답, 부분 실패와 마지막 정상 상태의 처리 방식을 기존 소비 계약과 맞춘다. 캐시·관심 영역 로드/해제가 선택·객체 수명을 잘못 끊지 않는지 확인한다.
- 명시적 배치 키와 좌표 변환을 사용해 위치·방향·크기·표현을 결속한다. 이미 있는 결속 대장·계획·검증기를 재사용하고, 배치 계획 확인과 실제 Renderer·Collider·선택 연결을 구분한다.
- 실제 사용자 입력을 바꾸어야 할 때만 2D 지도 조작 절차를 함께 읽는다. 자료 연결만 하는 작업에 새 줌·드래그·패널·선택 기능을 추가하지 않는다.

## 상태 권위를 보존한다

- Solo 가상 게임 상태와 시계·배차·정산 판정은 현재 Simulation Core가 맡고 Unity는 그 결과와 허용된 명령을 연결한다. 애니메이션·객체 도착만으로 가상 수령·정산을 새로 확정하지 않는다.
- 운영 Projection은 서버가 허용한 상태 사본이다. 읽기 전용 범위를 유지하고, 자료를 연결한다는 이유로 실제 주문·배차·결제·원장·운영 DB 쓰기를 만들지 않는다.
- 공급자를 게임 Tick·조회·객체 생성에서 직접 호출하지 않는다. 현재 수집·검증·반입 경계를 사용하고, 원본·키·고객 정보·비공개 원장을 공개 객체나 Save에 복제하지 않는다.
- 정기 수집·자료 인계의 검증 통과를 게임 적용·실행 소유·외부 배포 승인으로 해석하지 않는다. 현재 요청과 기존 경계 안에서 실행 가능한 부분을 이어가고 차단된 부분의 재개 조건을 남긴다.

## 같은 입력으로 검증한다

1. 같은 자료 ID·SHA·판본에서 위치 변환, ID 결속, 수량·단위·기준시각과 해석 결과를 대조한다. 변경 전의 정확한 시험 증거는 판본이 일치할 때 재사용한다.
2. 영향 있는 결측·중복 ID·stale/늦은 revision·삭제·재적용과 소유 자원 해제를 기존 관련 회귀로 확인한다. 새로운 시험은 실제로 달라질 결과나 결속 위험을 검증할 때만 추가한다.
3. 현재 [공통 검증 계약](../../../AGENTS.md#검증-단계)에 따라 실제 변경 경로만 Fast·관련 회귀·소비 빌드·최종 Task에 지정한다. 0-test·실패·미실행을 통과로 쓰지 않는다.
4. 입력·카메라·배치의 실제 시각 결과가 대상이거나 사용자가 화면을 요청했으면 현재 소유한 소비 Unity에서 동일 조건으로 조작·대조한다. 사용 가능한 Pipeline·CLI를 선택하고 한 도구의 존재를 필수 전제로 새로 만들지 않는다.
5. 화면을 의미 있게 바꾸는 범위는 [화면 시안 선행 절차](../../../docs/Architecture/화면시안선행제작절차.md)를 따른다. 코드·headless 출력·Game View·실제 플레이의 검증 범위를 구분한다.

## 결과를 연결한다

현재 작업 기록과 필요한 변경 기록에 **입력 판본 → 실제 소비 binding → 변경한 경로 → 명령과 원본 검증 결과 → 미완료 한 가지와 정확한 재개 위치**를 남긴다.

코드 연결·자동시험·실제 화면·클라우드 실행·운영 사용을 각각 사실대로 기록한다. 다른 도구가 이어받을 때는 출처와 코드 지문·허용 출력 범위를 전달하고 원본·구판·기존 미완료를 보존한다.
