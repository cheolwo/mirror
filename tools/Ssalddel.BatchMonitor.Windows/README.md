## 음식 배차 경영 체험

상단의 **경영 체험**에서 열린 스테이지를 고르고 **스테이지 시작**을 누르면 가상 시계가 시작된다. 지도에서 기사 마커를 고르고 **새 주문** 배지가 뜬 매장 핀을 누르면 연결된다. 왼쪽에서도 픽업 거리와 도착 예정 시각을 비교하고 **기사 지정**을 누를 수 있다. 가상 기사는 수락한 뒤 점선으로 표시한 도로를 따라 매장으로 이동하고, 픽업한 뒤 실선을 따라 전달한다.

| 기본 확장 순서 | 주문 | 배차 제한 |
|---|---|---|
| 1. 사가정 첫 배차 | 중랑 2건 | 가상 6분 |
| 2. 장안으로 확장 | 중랑 1건, 동대문 2건 | 가상 8분 |
| 3. 중곡으로 확장 | 중랑·동대문 각 1건, 광진 2건 | 가상 10분 |
| 4. 공릉으로 확장 | 중랑·동대문·광진 각 1건, 노원 2건 | 가상 12분 |

구마다 배차 가능한 기사 두 명을 둔다. 제한 시각까지 지정한 주문은 정산 때 건당 600원 보너스를 더한다. 늦게 지정해도 수령과 정산을 마치고 기본 차액을 받는다. 모든 주문을 제시간에 지정하고 정산까지 마치면 확장 후보가 열린다. 결산에서 제시간에 지정한 건수, 늦은 주문, 전달 시간, 기사별 보수, 기본 차액과 보너스를 확인한다. 정산 금액은 모두 가상 값이다.

통과한 뒤 지도를 축소하면 아직 운영하지 않는 권역의 확장 표식이 나타난다. 원하는 표식이나 왼쪽 권역 선택을 누른 뒤 새 스테이지를 시작한다. 선택한 구에서 주문 2건, 기존 구마다 주문 1건을 이어서 맡는다. 배차 제한은 열린 구 수에 따라 6·8·10·12 가상 분으로 늘어난다.

같은 스테이지를 다시 시작하거나 열린 스테이지를 골라 재도전할 수 있다. 통과한 스테이지와 단계별 마지막 재생 기록은 사용자 PC의 `%LOCALAPPDATA%/Ssalddel/BatchMonitor/food-campaign-v1.json`에 저장한다. 재생 기록에는 스테이지 ID, 배차 명령과 가상 시각, 주문 사건과 결산을 담는다. 앱을 닫기 전 진행 중이던 회차는 다음 실행에서 해당 스테이지의 시작 상태로 플레이한다.

**자유 연습**에서 기존 중랑구 1·2건 배차를 바로 열 수 있다. **기존 관찰**과 오가도 실행 중인 앱에서는 경영 회차를 이어간다. 지도를 열 수 없을 때도 왼쪽에서 주문을 배차하고 결산을 확인할 수 있다.

## 자동 관찰

실행하면 중랑구 사가정·동대문구 장안·광진구 중곡·노원구 공릉의 가상 음식 배달과 구 사이 화물 운송이 같은 시계로 반복된다. 왼쪽에서 각 구 기사와 주문·화물 상태 및 누계를 확인하고 오른쪽 네이버 지도에서 음식 배송지 번호, 기사별 경로, 주황색 화물 차량과 구간을 볼 수 있다.

- 음식은 구마다 가상 A·B 매장과 기사 한 명을 두고 6초마다 다음 구에서 가상 주문을 접수한다. 기사는 전달을 마친 위치에서 직전과 다른 매장으로 이동한다. 다른 매장의 주문이 대기 중일 때 배정되며 지도에는 구별 현재 픽업 매장이 표시된다. 전달 뒤 가상 주문자가 2초 후 수령을 확인한다. 수령 확인 뒤 8초 동안 완료를 표시한다.
- 화물은 중랑구 → 동대문구 → 광진구 → 노원구 → 중랑구 순으로 구간별 가상 의뢰를 반복한다. 기존 `SIM-FREIGHT-TRANSPORT-1`의 300kg 의뢰와 400kg 차량 표본을 재생한다. 하차지 도착 3초 뒤 수령인이 인수를 확인하고 완료 표시는 8초 뒤 정리한다. [화물 시나리오 단계](../../docs/Changes/2026-08-11-simulation-freight-transport.md)
- 지도 연결이 끊겨도 왼쪽의 업무 상태와 완료 누계가 계속 바뀐다. 음식 `D-` 번호와 화물 `F` 번호는 실행 안에서 유지된다.

## 로컬 실행

1. [음식 배달 캠페인 Windows Release](../../artifacts/local/batch-monitor-food-campaign-20261110/app/Ssalddel.BatchMonitor.Windows.exe)를 열거나 이 프로젝트를 Windows에서 Release로 발행한다. WebView2 런타임과 .NET 10 데스크톱 런타임이 필요하다. 발행 폴더의 구성 파일을 함께 둔다.
2. 기본 실행판은 동봉된 `Samples/SeoulEast`를 읽는다. 실행 파일 옆에 기존 `delivery-sample.json`과 `road-graph.json` 두 파일을 함께 두면 그 표본을 사용한다. 기존 사가정 검토판은 [이전 실행판](../../artifacts/local/batch-monitor-mixed-20261110/app/Ssalddel.BatchMonitor.Windows.exe)에 있다. 선택된 표본의 파일이 없거나 형식이 잘못되면 기본 가상 배치 예제를 연다.
3. 실행판은 로컬 `Ssalddel/appsettings.Local.json`의 네이버 지도 브라우저용 ID를 찾는다. 다른 환경에서는 `SSALDDEL_BATCH_MONITOR_NAVER_CLIENT_ID`를 지정한다. 지도 앱의 등록 웹 주소는 `http://localhost:8792/`다.

지역 시나리오의 주문과 거점은 합성 표본이다. 지도 배경은 [NAVER Maps JavaScript API](https://navermaps.github.io/maps.js.ncp/docs/)를 사용한다. [도로 표본 안내](Samples/SeoulEast/NOTICE.md)에 공개 데이터 판본·범위·표시 한계를 기록했다.

기존 사가정 자료에 쓰는 `build-delivery-sample.py --delivery-root <배달 작업 폴더> --output <로컬 delivery-sample.json>`은 원본 DB를 읽기 전용으로 열고 본인 완료 주문의 메뉴와 시간대, 공개 매장 위치만 추출한다. 배송지와 화물 상·하차지는 공개 도로 표본에서 따로 정한다.
