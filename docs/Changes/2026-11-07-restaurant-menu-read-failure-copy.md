# 음식점 메뉴 첫 조회와 새로고침 실패 안내

첫 메뉴 조회가 실패했을 때도 ‘이전 목록은 유지합니다’가 표시됐다. [메뉴 조회 화면](../../RestaurantDeskApp/Components/Pages/Menus.razor.cs)에서 이 화면에서 메뉴 조회에 성공한 적이 있는지에 따라 안내를 나눴다. 처음 조회에 실패하면 불러오지 못했다고 알리고, 갱신에 실패하면 마지막 조회 결과를 표시하고 있다고 알린다. 마지막 결과가 0건일 때도 같은 갱신 안내를 사용한다.

[메뉴 화면의 안내](../../RestaurantDeskApp/Components/Pages/Menus.razor)는 320px·390px에서 단어 단위로 줄바꿈한다. **새로고침**으로 다시 조회해 성공하면 결과가 표시되고 실패 안내가 사라진다. 정상 메뉴 카드는 기존 [390px 가상 메뉴 화면](../assets/changes/2026-11-06-restaurant-menu-readability/menus-390.png)에서 확인할 수 있다.

2026-11-07 로컬 Chrome의 320px·390px·1280px에서 가상 메뉴 네 건의 이름과 가격을 대조했다. 첫 실패에서 메뉴가 없는 상태와 조회 실패를 구분했고, 새로고침 실패에는 같은 네 건을 표시했다. 390px에서는 정상 0건 뒤의 갱신 실패, 같은 메뉴 수정 화면에서 목록 복귀, 만료 응답의 로컬 로그인 진입을 확인했다.

변경 전 브라우저 검사 88개와 최종 97개가 통과했다. Fast 관련 시험 57개와 통합 3.5 Task 시험 17,054개가 통과했고, 환경 조건이 필요한 17개를 건너뛰었다. 빌드 경고는 Fast 20개, Task 63개였고 오류는 각각 0개였다.

로컬 브라우저에서 현재 메뉴 화면을 가상 조회와 연결했다. 실제 앱·운영 서버·메뉴 저장은 미검증이다. 실패 상태의 전후 캡처와 조회 순서는 `artifacts/local/mirror-ui-assist/20261107T024606447Z-restaurant-menu-read-failure-copy/validation.json`에 연결했다.
