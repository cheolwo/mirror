# 다중 정차 지도 실제 휴대폰 검증 r22

2026-10-27. 사용자의 `휴대폰 화면으로 검증해봐` 요청에 따라 [r22 실행 범위](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-ordered-map.device-review.r22.md)에서 USB SM-A346N(Android SDK36)의 실제 native 지도 화면을 확인했다. [r21의 코드/자동시험](2026-10-27-cargo-ordered-map-r21.md)과 이번 실제 화면 결과를 구분한다.

## 확인하며 보완한 점

초기 APK134에서 실제 NAVER 배경 지도가 표시됐지만 기본 방문 순서 설명과 기존 운송 요약이 중앙 핀을 가렸다. 접힌 방문 순서 패널을 제목·버튼으로 줄이고 상세 설명·범례·마감은 펼침에서 확인하도록 바꿨다. 좌표 공백·순서 보류 경고는 기본에서도 유지한다.

운행 지도에서만 운송 요약의 반복 주소/운임 줄을 상세 펼침으로 이동한다. 현재 운송·다음 행동·상세/목록 버튼은 남기고 다른 호출 화면은 기존 표시를 유지한다. 운송 상태·서버 순서·권한·업무 명령은 변경하지 않았다.

가까운 핀 설명이 서로 겹치며, 확대하면 일부 핀이 기존 상단 패널에 가려진다. 기존 하단 버튼이 NAVER 로고/도구 일부를 가리는 점도 남았다. 따라서 전체 지도 가독성·출시 완성을 통과한 것으로 표시하지 않는다. 위치 누락 화면은 보이는 핀/경고를 확인했으며 패널에 가려진 모든 geometry를 스크린샷만으로 검증했다고 주장하지 않는다. 자동시험의 좌표 공백/연결선 계약과 실제 화면 관측을 분리한다.

검토용 HTTP fixture의 초기 chunked 요청 지원 누락 때문에 첫 로그인은 실패했다. 16KiB 한도·시간 제한·CRLF·전송 헤더 충돌을 검사하는 chunked 지원을 보완하고 정상/잘린/초과 요청의 실제 HTTP 전송 회귀8개를 추가했다. 앱의 제품 인증 코드를 완화하지 않았고 새 임시 계정으로 정상 로그인 화면을 거쳤다. Samsung Pass의 비밀번호 저장은 취소했다.

APK134 소스 목록의 같은 CodeMetadata props 경로/SHA가 슬래시 표기 차이로 두 번 집계된 점은 기존 raw3,053행을 보존하고 동일 경로·동일 SHA만 unique3,052개로 정규화해 기록한다. 충돌하는 중복은 거절하며 APK135는 승인된 제품4파일 차이만 수용한다. 시험 파일을 포함한 전체 소스 지문은 별도 고정한다.

## 결과의 범위

실제 기기의 제품 native UI/지도 SDK에 합성 HTTP 자료를 제공하는 검증이다. 시나리오 전환은 fixture 제어이며 실제 상하차·제품 서버/운영 DB·실GPS/운행·실시간 허브·FCM·금융·전역 최단경로 또는 도로 geometry를 검증하지 않는다. SignalR 허브를 모의 성공으로 처리하지 않아 실시간 연결 경고가 화면에 남는다. 현재 운송은 별도의 GET 결과로 확인한다.

원래 일반 기사 앱·다른 앱 데이터·기기 보안/잠금은 보존했다. 기존 검토 패키지만 갱신하고 APK134·이전 기록·초기 가림 캡처를 남겼다. 마지막 상태를 저장한 뒤 명령행으로 소유를 재확인한 fixture PID46164만 종료했으며 5384 listener·추가한 USB reverse·검토 앱 프로세스가 없는 것을 확인했다. 앱 데이터·설치 APK·기록은 남겼다. commit/push·외부 배포·MYBOX·운영 활성화는 수행하지 않았다.

입력/서명/endpoint/설치·비공개 화면·fixture·정리 근거는 `artifacts/local/cargo-ordered-map-device-r22/`에 보존한다. 대표 색인: `visual-review-final.json`, `installed-r135.json`, `final-source-audit-r22.json`, `cleanup-proof.json`. 초기 사례 기록의 `markerVisualReview: Pending`은 원기록으로 보존하고, 실제 화면 대조와 한계는 별도 최종 색인에 기록했다.
