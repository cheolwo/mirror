# 기사 완료 배달 상세와 3일 열람 기한

2026-10-04. 사용자 선택1·2번과 후속 답변 `한. 3일정도`에 따라 완료 후72시간 동안 본인 배달의 주문·고객 정보를 조회하고, 이후에는 정산·동결 요금 구성·요금 기준 거리만 확인하도록 구현했다. 기존 정산 목록에서 한 건의 `배달 상세 보기`로 진입하며 긴 요금 구성은 상세 화면으로 옮겼다. 상세는 정산·요금 구성, 주문 정보, 고객 정보 카드로 나눈다.

[페이지 책임·화면→코드→API→DB](../ProjectOverview/page-docs/driver-completed-delivery-detail-r1.md)에 조회 권한·기간·실패/복귀·정보 수명을 정리했다. 서버 운영 설정 `FoodDelivery:CompletedDetailAccess:WindowMinutes`는 생략 시 기본4320을 적용한다. 명시적 null·0·음수 또는 사용할 수 없는 설정·완료 근거 불일치는 주문·고객 상세를 제공하지 않는다. DB 원본 보관·파기 정책과 본인 상세 열람 기한을 구별한다.

## 서버와 앱의 정보 경계

새 `GET api/v1/driver/food-deliveries/settlements/{settlementId}/detail`은 인증한 기사와 저장된 정산·최종 배달 시도·운송·주문의 완료 관계를 확인한다. 다른 기사/없는 정산은404, 인증 실패는401/403이다. 기간 후에는 고객·주문 DTO 자체를 null로 반환하고 금융 투영을 유지한다. 일반 운송 상세·기사의 운송 원장 이벤트에서도 음식 주문의 고객 정보·좌표를 우회 조회하지 못하도록 분리했다. 기존 화물·관리자 권한은 유지한다.

정산 목록·업무·상세 응답은 캐시 저장을 금지한다. 앱은 서버가 보낸 현재/만료 시각과 요청 경과 시간을 기준으로 단조 시간 타이머를 사용하며, 기기 시각 변경이 열람을 연장하지 않는다. 기한 만료·계정 변경·상세 이탈·앱 백그라운드 전환 때 바인딩된 개인정보 문자열을 비우고, 재개 시 서버 권한을 다시 조회한다. 늦은 응답은 선택·계정·화면 수명으로 배제한다.

자동 업무 갱신은 읽고 있는 상세 선택과 원래 만료 시각을 유지한다. 명시적인 상세 다시 조회는 새 권한을 확인하고, 목록 복귀는 선택 날짜를 유지한다. 현재 운영 요율로 과거 요금·공제를 재계산하지 않으며 실제 GPS 주행거리가 없는 완료 기록은 `요금 기준 거리`로 표시한다. 입금 미확인을 지급 완료로 바꾸지 않는다.
