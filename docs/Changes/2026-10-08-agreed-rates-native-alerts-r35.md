# 합의 요금표와 배차·주문 알림

사용자가 우선순위 3·4번을 승인하고 기사 배차와 음식점 새 주문에 메시지·알림음을 함께 요청했다. [구현 범위 r4](../AI/Planning/시스템/PLAN-SYSTEM-ROLE-BUSINESS-OPTIONS/agreements-alerts.implementation.r4.md)와 [페이지 책임](../ProjectOverview/page-docs/agreed-rates-notification-settings-r1.md)에 따라 기존 요금 산정·배차·정산 및 알림을 연결했다.

## 합의한 조건을 실제 업무에 연결

음식점/화주와 기사는 사전 요금표를 제안·수락·거절·철회할 수 있다. 관리 화면에서 합의만 했다고 기존 업무의 요금이 바뀌지 않는다. 음식점/화주가 실제 주문·운송 의뢰 번호가 연결된 화면에서 수락된 요금표를 명시적으로 선택해야 한다. 기사 쪽 화면에서는 조건과 계산 예시를 확인하고 합의에 응답한다. 미리보기는 저장·청구·송금이 아니다.

서버는 로그인한 실제 당사자·업무 종류·차량·기간·수락 판본과 업무 소유권을 확인한다. 원 요청 식별자와 판본으로 중복 응답·늦은 확인을 처리하고, 결과가 불명확하면 같은 요청을 조회·재시도한다. 다른 업무·당사자의 조건, 철회/만료된 새 선택, 진행 중인 업무의 덮어쓰기를 차단한다.

음식 배차는 합의한 기사로 후보를 제한하면서 운행 상태·위치·반경 등 기존 조건을 검사한다. 기사의 직접 수락과 음식점의 기사 배정 뒤 조리 시작은 유지한다. 합의 기본요금은 기존 계산기로 산정하고 기존 시간·지역 등 할증은 보존한다. 제안 시점의 금액·합의 판본을 고정해 정산 조회까지 전달한다.

화물은 기사 수행요금과 화주 견적·결제액을 구분한다. 합의 요금을 SQL에 고정하고 기존 Mongo 원장으로 동기화한 뒤 적용 완료를 표시한다. 동기화가 보류되면 업무 소유자만 같은 선택 요청을 재시도하며 새로 계산하지 않는다. 기사 수락과 지급 준비 조회도 고정된 합의 근거를 확인한다. 실제 청구·지급 완료 상태를 만들거나 기존 금액을 소급 변경하지 않는다.

## 메시지와 소리 설정

음식 기사 Android에는 `살뜰 배달 · 새 배달 요청`, 음식점 Android에는 `살뜰 주문 · 새 주문` 메시지와 서로 다른 짧은 기계음을 연결했다. 직접 생성한 0.58초 WAV를 사용하며 음성 합성 문구는 이번에 추가하지 않았다. 잠금 화면 메시지에 고객 주소·전화·주문 세부를 넣지 않고 앱에서 최신 정보를 다시 확인한다.

기사의 내 정보 → 알림 설정은 기존 서버 설정을 실제 조회·저장하고 저장 뒤 재조회한다. 기존 배차 알림 기본 OFF와 운행/정지 세부 설정을 보존한다. 음식점의 주문 알림 설정은 이 계정·이 기기의 선택으로 저장한다. 알림·소리·진동·야간 무음을 각각 선택하며 한국 시각 22:00~07:00에는 메시지를 유지하고 소리·진동만 끈다.

기기 알림 권한·앱 차단·기존/새 채널의 무음·낮은 중요도를 존중하며, 설정을 바꿔 차단을 우회하지 않는다. 계정 변경·로그아웃·늦은 응답은 이전 계정의 설정과 알림을 적용하지 않게 처리한다. 같은 배차가 FCM과 재조회로 중복 수신되어도 만료 전 같은 요청의 소리를 다시 내지 않는다. 읽지 않은 알림 상태는 별도로 보존한다.

이번 소리 적용 대상은 음식 기사·음식점 Android다. 화물 기사에는 기존 추천 메시지/배너 경로가 있으나 추천 OS 소리는 이번에 추가하지 않았다. 주문자·운영자에 새로운 알림 사건을 만들지 않았다. 이번 기사 APK에는 Firebase 수신기가 포함되지 않았으므로 현재 시험 경로는 앱이 열린 상태의 배차 조회다. 기존 FCM 조건부 소스는 유지하지만 백그라운드 원격 푸시 연결·전달은 미완료다. 음식점 알림은 기존 실행 중 SignalR/재조회 경로이며 앱 강제 종료 뒤 원격 푸시 보장은 별도다.

## 검증 기록

공통 화면 42개 시험과 음식점·음식기사·화주·화물기사의 320/390/1280px 등 16개 예시 화면 시나리오를 검증했다. 실제 인증 HTTP/DB 화면이 아니라 고정 검토 입력을 사용했다. 버튼 48px·가로 넘침·복귀 구조와 사용한 소스 지문을 확인하고 검토 호스트를 종료했다.

요금표 migration은 기존 음식 배차 snapshot 컬럼을 nullable로 추가하고 합의/요청 receipt/업무 선택 테이블만 생성한다. 누락된 현재 EF model snapshot도 보완하되 이전의 148줄 변경은 보존했다. MySQL model/snapshot 및 생성 SQL 대조와 격리 SQLite의 기존 요금 보존·신규 CRUD/유일성·UTC 경계 3개 시험이 통과했다. 기존 DB에는 실행하지 않았다.

최종 관련 Fast 217개·전체 Task 8,708개가 통과했다. 실패는 0개이며 격리 Mongo 환경을 요구하는 2개는 미실행이다. 두 실행 모두 전체 솔루션 빌드가 통과했으며 제품/시험 소스 77개는 검증 전후 및 최종 인계 시 지문이 일치한다. 첫 전체 실행에서 기존 도구 메뉴가 없다고 단정한 시험 2개가 실패했다. 실제 업무 행동은 기존 영역에 유지하고 새 합의 요금표 도구 링크는 별도로 검증하도록 해당 구조 시험만 보완했다. 실패 TRX·수정 전 시험과 최초 집중 시험 실패 근거도 보존한다.

두 개인 Debug APK는 `0.1.35/35`, 로컬 USB 서버 `http://127.0.0.1:5363/`용이다. 음식점은 이전 실폰 시험의 명시적인 `sagajeong-food-mobile-dispatch.r1` 설정을 포장할 때만 선택하며 일반 기본 설정을 바꾸지 않았다. 서명·정렬·양 ABI의 실제 내장 DLL/화면/계산 계약·음원·CSS를 대조하고 기사 지도·독립 카드·기존 아이콘의 내장 구조를 확인했다. 이 검사는 실제 기기에서 울리는 소리나 조작 화면을 검증한 것이 아니다.
