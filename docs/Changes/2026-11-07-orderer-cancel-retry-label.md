# 주문 취소의 결과 조회와 같은 요청 재시도

주문 취소 결과가 확인되지 않은 화면에서 **결과 다시 확인**과 **같은 요청 다시 확인**이 함께 표시됐다. 첫 버튼은 조회만 하고, 두 번째 버튼은 최신 조회가 성공해도 반영이 확인되지 않으면 같은 요청을 다시 보낼 수 있다. [이전 390px 가상 화면](../assets/changes/2026-10-10-exception-continuity/food-explicit-recovery-390.png)

[공용 음식 업무 화면](../../Ssalddel.Ui.Common/Areas/App/RoleWorkspace/Food/FoodRoleActionForm.razor)에서 두 번째 버튼을 **같은 요청 재시도**로 바꾸고, 바로 위에 다시 요청하는 조건을 설명한다. 320px·390px에서 안내를 단어 단위로 줄바꿈하고 두 버튼 사이에 간격을 뒀다.

2026-11-07 로컬 Chrome에서 가상 주문 취소를 320px 터치, 390px 키보드, 1280px 클릭으로 확인했다. **결과 다시 확인**은 조회만 했고, **같은 요청 재시도**는 조회를 먼저 한 뒤 원래 번호와 내용으로 한 번 더 요청했다. 최신 조회가 실패하거나 명령 응답을 이미 받은 경우 재시도 버튼이 표시되지 않았다. 로그인 필요 상태와 가상 음식점 조리 시간 변경도 대조했다. 음식점 요청은 조회에서 반영을 확인해 추가 요청 없이 완료됐다. 화면의 **업무로 돌아가기**는 같은 주문을 가리켰다.

변경 전 브라우저 검사 71개와 최종 87개가 통과했다. 기존 브라우저 실행기의 버튼 이름도 맞췄다. Fast 관련 시험 104개와 통합 3.5 Task 시험 17,054개가 통과했고, 환경 조건이 필요한 17개를 건너뛰었다. 음식기사 코드 지도 검사도 두 단계에서 통과했다. 빌드 경고는 Fast 0개, Task 63개였고 오류는 각각 0개였다.

공용 화면은 격리된 메모리 자료로 확인했다. 제품 서버·실기기와 실제 주문 상태 변경, 업무 목록 진입은 미검증이다. 전후 캡처와 합성 요청 순서는 `artifacts/local/mirror-ui-assist/20261107T014605569Z-orderer-cancel-retry-label/validation.json`에 연결했다.
