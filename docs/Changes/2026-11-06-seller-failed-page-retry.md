# 판매 주문 목록에서 실패한 페이지 다시 읽기

2페이지에서 3페이지로 이동하다 조회에 실패하면 **다시 시도**와 30초 자동 조회가 마지막으로 성공한 2페이지를 읽었다. 판매 주문 목록은 실패한 조회의 페이지를 기억하고 재시도에서 같은 페이지를 읽는다. 정상적으로 읽으면 화면의 페이지 표시와 상세 복귀 주소는 서버 응답의 페이지를 사용한다. [목록 모델](../../Ssalddel.Ui.Common/Areas/App/ViewModels/판매채널주문페이지ViewModels.cs) · [판매 주문 화면](../../Ssalddel.Ui.Common/Areas/App/Components/Sales/ShipperSalesOrderWorkspace.razor.cs)

실제 Razor의 페이지 선택과 다시 시도 버튼, 자동 조회 진입점을 합성 서비스로 검증했다. 화면에서 2페이지를 읽은 뒤 3페이지 조회에 실패하면 수정 전에는 두 경로 모두 2페이지로 돌아갔다. 수정 후 두 경로 모두 3페이지와 기존 검색 조건으로 다시 조회했다.

공통 UI와 판매자 앱을 포함한 통합 3.5 빌드가 오류 없이 끝났다. 관련 시험 40건과 전체 시험 17,034건이 통과했고, 환경 조건이 필요한 17건은 생략했다. 현재 공통 UI를 읽는 루프백 미리보기의 320px·390px에서 입력 유지와 접근 실패·복구 14건이 통과했다. 브라우저의 업무·외부 요청은 0건이었다. 페이지 번호 검증은 다중 페이지를 제공하는 합성 Razor 시험에서 수행했다. 실기기와 제품 API는 미검증이다.

수정 전 실패, 시험 결과와 합성 화면은 `artifacts/local/mirror-ui-assist/20261106T073119883Z-seller-failed-page-retry/completion.json`에 연결했다.

다음 회차에는 창고 입고 요청 목록에서 조회 실패 뒤 입고 건을 다시 확인하는 흐름을 살핀다.
