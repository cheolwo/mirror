# 사가정 영상 근거와 건물별 외관 보완

2026-10-26. [사용자가 승인한 좁은 구현 범위](../AI/Planning/시스템/PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/video-facade-refinement.implementation.r109.md).

## 변경한 동작

- Synty 요청이 있어도 검토된 상세 공간 overlay가 있으면 그 원형·건물 ID·선택을 유지한다. 기존 602건물 Synty 배치를 다른 판본의 건물에 자동 대응하지 않는다.
- 건물별 외관 입력에 정확한 ID·공간 hash·영상 근거 참조·비공개 검토·부품 대장 판본·범위와 transform 검사를 추가했다. 잘못된 입력은 기존 표시를 유지하며, 개별 제거·건물별 제거·전체 정리로 복구한다.
- 원본 Synty 자산을 수정하지 않고 기존 자산 대장의 차양 5개·간판 1개를 후보로 참조하는 얇은 외관 대장을 준비했다. 후보 등록은 사용 승인·배포 승인이 아니다.
- 원본의 기존 전체 SHA 근거와 현재 stat, 실제 PTS 색인·프레임 hash, 동일 원본 보호창과 현재 WAL 보호 메모·저장 native 파일/파일 집합을 대조하는 Python 어댑터를 추가했다. 근거 변경 시 표시·내보내기를 보류하고, 출력은 최종 재검사 뒤 새 폴더로 확정한다.

## 실제 자료와 적용 경계

기존 0111 원본의 실제 PTS 표본 5개를 시각 대조하고 와플대학·맥주아비·뚜레쥬르 사가정역점의 외관 3건을 마련했다. 공개 주소·사업자 PNU·공식 건물 원형 내부 관계와 실제 간판/상대 배치를 대조한 비공개 식별 검토다. 현재 입점·영업·실측 높이·사용자 지도 승인과 구분한다. 새 원본 전체 해시·복사·디코드는 하지 않았다.

현재 EditorPrefs는 Overture 2,247건물 자료를 가리킨다. 세 GIS 대상과 직접 ID 대응은 0건이고 과거 ALD 4,062건물 사본은 기록된 경로와 조사한 로컬 범위에 없다. 전체 디스크나 MYBOX에도 없다고 단정하지 않는다. 기본 지도·환경·Prefs를 바꾸거나 가까운 Overture 건물에 배정하지 않았다.

따라서 실제 공개 원형 3개를 별도로 읽는 `PrivateBuildingStudy`와 정본 `CanonicalSagajeong`를 상호 거부하도록 분리했다. 연구에서는 실제 원형에 관측 근사색·큰 유리면·간판띠·차양을 보완한다. 높이 4m는 기호값이고 최장면의 정면 배치는 가설이다. 실제 층수·창문 수·정면 방향·정밀 치수·동기 카메라 복원으로 보고하지 않는다.

이미지는 로컬 비공개 `배달/edit-kit/private/diorama-facade-refinement/20261026-r1/`에 보관한다. 공급자 이용 범위와 개인정보 경계를 유지하며 공개 저장소 문서 자산으로 복사하지 않는다. 원본 장면은 텍스처로 쓰지 않고 관측 상호의 시안 글꼴 이미지만 별도 생성한다. 원본 사진·폰트 파일을 배포 자산으로 복사하지 않는다.

## 검증과 발견 이력

- 첫 Unity 실행은 새 renderer의 `Application` 이름 충돌로 컴파일에 실패했고, `UnityEngine.Application`로 정정했다. 다음 실행에서 관련 96/96을 확인했다.
- 첫 부품 캡처는 exit 0이었지만 이미지 6장이 같은 배경뿐이었다. 성공으로 인정하지 않고 camera.scene 결속과 전경 픽셀·분산 검사를 보완했다. 후속 부품 이미지 6개를 실제 확인했다.
- 첫 연구 3건의 전후·제거 뒤 복구 이미지가 생성됐고 제거 뒤 PNG hash가 모두 전과 같았다.
- 추가 동적 TextMesh 간판 렌더에서는 엔진이 비정상 종료됐다. 특정 원인을 단정하지 않고 실패 로그와 미완료 판본을 보존했다. 동적 Font/TextMesh 경로는 제거하고 관측 상호만 담은 정적 이미지의 quad 방식으로 대체했다.
- 최종 범위 시험과 정적 간판 연구의 결과는 아래 마감 기록에서 실제 성공 여부를 구분한다. 과거 시험·오프스크린 렌더는 Game View 또는 실사용 입력 증거가 아니다.
