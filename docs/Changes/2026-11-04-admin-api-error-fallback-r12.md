# 관리자 업무 조회의 오류 원문 표시 보완 r12

관리자 화면의 업무 조회가 실패할 때 서버의 HTML·일반 문자열·불완전한 JSON을 그대로 안내하던 경계를 보완했다. 기존 고정 안내를 재사용하며 화면 배치·경로·인증/업무 권한·서버 원장은 바꾸지 않았다.

## 발견과 최소 수정

`/operations`의 조회는 `AdminOperationsService` → `AdminAuthenticatedApiClient`를 거치고, 예외 메시지를 화면의 오류 안내에 전달한다. 클라이언트의 `ReadProblemMessage`는 정형 `detail`·`message`·`title`을 찾지 못하면 본문 전체를 반환했다. Razor의 문자 표시이며 HTML 실행 결함으로 판정한 것은 아니다.

실제 관리자 HTTP 클라이언트·인증 세션·음식 목록 서비스를 합성 응답에 연결한 새 8사례에서 수정 전 5실패·3통과를 확인했다. 마지막 원문 반환 한 줄만 빈 문자열 반환으로 바꾸어 기존 “관리자 요청을 처리하지 못했습니다.” 안내로 연결했다. 정상 Problem의 메시지 우선순위, HTTP 상태·`ErrorCode`, 기존 401 갱신과 1회 재전송·FeatureDisabled/404 구분은 보존한다. 음식 목록 실패 뒤 사용자가 명시적으로 재조회할 때만 다음 GET을 보내 정상 내용을 받는 것도 검증한다.

## 코드 검증

- Fast `20261104-225427`: 실제 20/20 통과·실패/생략 0. 새 8사례와 기존 관리자 음식 클라이언트 12사례다. 시험 의존 빌드 오류 0/기존 경고 229, 관리자 Android 소비 앱 빌드 오류 0/기존 경고 5다. 선택 필터의 훈련 클라이언트 이름에는 일치 결과가 없으므로 해당 시험을 실행했다고 표시하지 않는다.
- Task `20261104-225608`: `Ssalddel.v1.5.slnx` 통합 빌드 오류 0/기존 경고 5, 전체 16,957통과·환경 17생략·실패 0. 실제 TRX의 개별 결과를 확인했으며 과거 통과 수를 승계하지 않았다.
- 독립 읽기 검토에서 이번 한 줄과 관련 회귀의 차단 문제는 발견하지 못했다. 정형 메시지 값 자체의 정화, 전송 내부 예외·인증 저장 경합까지 해결한 것으로 확대하지 않는다.

## 실제 기기와 검증 서버

이번에는 r11에서 이미 검증한 화주 APK145를 다시 만들지 않고 재사용했다. 등록 단일 USB·OS 잠금·같은 기기/paused checkpoint, 화면 켜짐/잠금 해제·최근 사용자 활동 없음과 수집 프로세스 없음, 설치144·서명/endpoint·선택 입력 3,610개를 다시 대조했다. 다른 앱의 전면 자체를 사용 중이라는 근거로 삼지 않고 현재 유휴를 확인한 뒤 기존 실제 휴대폰 검증 권한 안에서 진행했다.

데이터 삭제·uninstall 없이145로 한 번 업데이트했고 설치 SHA `81c0f0f92a5d6975bc582973d412d510a6d8281bad8af161e576739af2186015`·최초 설치 시각·원래 앱 메타데이터 보존을 확인했다. 실제 설치 MAIN 진입점을 한 번 열었고, 설치145가 전면인 기존 홈의 참여 집계 영역을 메모리 안의 화면으로 확인했다. 새 관리자 수정은 이 화주 APK의 변경 내용이 아니며 관리자 APK를 새로 만들거나 기기에 적용한 것도 아니다.

최초 읽기 관찰의 두 화면이 달라 그 결과는 보류 기록으로 남겼다. MAIN/설치를 반복하지 않고 별도 읽기 관찰로 현재 홈만 확인했다. 메뉴가 현재 화면 밖에 있어 좌표를 추측하지 않았고 탐색 탭·로그인/권한 입력·업무 제출은 실행하지 않았다. **창고 작업대 진입·조회/재조회·복귀와 오류 응답의 실기기 재현은 미검증**이다. 처음 설치 전 커널 활동 시각의 필드명을 인식하지 못한 사전 점검 실패도 보존했고, 실제 필드명 파서만 맞춘 뒤 한 번의 설치 명령을 실행했다.

같은 r6 호스트의 현재 PID·부모·시작 시각·명령/DLL과 격리 DB를 대조했다. 전후 live/ready·홈·업무 proof2개 HTTP는 각각 5/5가 200이고 두 업무 proof는 불변·금융 행은 0이다. 서버/DB 재시작·업무 명령·새 중계 실행은 없다. 이전 readiness21개와 수집 checkpoint SHA가 그대로이고 새 실패 관측은 0이다. 다른 작업의 기준 SHA가 있던 파일230개도 불변이다. 기준 파일 SHA가 없던17항목까지 보존 검증한 것으로 확대하지 않으며 과거 모든503의 해결을 선언하지 않는다.

재개 근거는 `artifacts/local/app-stability-r12/f81ea584b8784deb8bd6400f87d4fd0a/`의 수정 전 TRX·현재 검증·설치 영수증·단일 MAIN/관찰 기록이다. r11의 당시 미설치 완료 기록은 고치지 않고 이번 실제 후속 설치와 구분한다. 다음 한 가지는 사용자 기기 사용·인증 조건과 현재 판본을 다시 대조한 뒤 설치된145의 정상 메뉴로 창고 작업대 조회·명시적 재조회·홈 복귀를 확인하는 것이다. 관리자 수정의 새 APK·실기기 오류, 기사 직접 로그인, 다른 역할·원격 운영/출시는 별도이며 앱 전체 안정화 완료가 아니다.
