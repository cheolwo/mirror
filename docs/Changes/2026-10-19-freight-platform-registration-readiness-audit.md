# 무료 퀵·화물 플랫폼 등록 준비 및 기사 자격 확인 감사

> 이후 사용자의 구현 요청으로 [등록 준비 보완 r71](2026-10-19-freight-registration-readiness-r71.md)을 진행했다. 이 문서는 보완 전의 감사 근거를 보존하며 최신 구현·검증 상태는 후속 기록에서 확인한다.

- 확인일: 2026-10-19
- 목표: 2027-09-23 개정법 시행에 맞춰 등록·운영 준비
- 상태: **소스·기존 시험 대조 완료 / 법정 등록 적격 및 실제 서류 미확인**
- 기준: `dev/mirror-integration`, HEAD `fd55a1c4b` 및 현재 작업 트리. 시작 당시 기존 변경 350개를 보존했다.
- 범위: 무료 연결 방향과 현재 기사·차량·플랫폼 자격, 화물 입력, 신고, 요금의 연결 점검. 제품 코드·설정·DB·외부 서비스·운영 활성화는 변경하지 않았다.

## 결론

접수·추천·수락·사진·전달 업무의 기반은 재사용할 수 있다. 그러나 **내부 기사 역할·활동중 상태·수락 적격성 검사와 법정 자격 확인은 다르다.** 현재 등록 경로는 기본 정보를 입력하면 기사 역할과 활동중 상태를 부여하며, 확인한 경로에서는 면허·화물운송 종사자격·운송사업 허가·보험의 증빙, 검토자, 유효기간, 취소를 판독하지 않는다.

따라서 지금 상태를 법령 요건 충족 또는 실제 영업 준비 완료로 표시하지 않는다. 사용자가 보유했다고 설명한 것은 사업자등록증의 퀵서비스 종목이며, 이 감사에서 사업자 서류 원본·허가·보험·사무실·결격사유를 확인한 것은 아니다.

## 법령과 적용 범위

1. [화물자동차법 개정문 — 법률 제21970호](https://law.go.kr/LSW/lsRvsDocListP.do?chrClsCd=010202&lsId=001748&lsRvsGubun=all)는 2027-09-23 시행이다. 제34조의5는 화물정보 처리·보안, 이용요금·부가서비스 사업계획, 사무실 등의 등록기준을 두며 세부 기준을 국토교통부령에 위임한다. 제34조의11에서 제4조 결격사유 등도 준용한다.
2. 개정 제34조의6·8은 이용요금·이용약관 신고를 정한다. 무료 0원 요금의 신청서 처리 방식은 확인하지 못했다. 무료이므로 신고가 면제된다고 판단하지 않는다.
3. 개정 제34조의7은 무허가 운송·무자격 운전·과적·불법 재위탁 등의 사전 고지, 확인 시 장관 신고, 위반 확인 회원 이용 제한과 화물 종류·무게(깔판·포장 포함)·부피(길이·너비·높이)·출도착지 등록을 규정한다.
4. 현재도 화물차의 [운송사업 허가 제3조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0003&lsiSeq=286393&urlMode=lsScJoRltInfoR)와 [운전업무 종사자격 제8조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0008&lsiSeq=286393&urlMode=lsScJoRltInfoR)를 구분해야 한다. 기사 개인에게 항상 독립된 사업허가증을 요구하기보다 실제 운송사업자·소속/위수탁 차량 관계를 확인해야 한다.
5. 오토바이에는 화물차 운송 종사자격을 일괄 요구하지 않는다. [생활물류법](https://www.law.go.kr/법령/생활물류서비스산업발전법)의 사업 유형·인증 여부·계약 형태를 별도로 대조한다. 보험도 의무보험, 유상 배송 보장, 적용 대상인 적재물배상보험을 구분한다.
6. 이번 공식 검색에서는 신설 플랫폼 등록의 세부 하위규정 공포·입법예고를 확보하지 못했다. 부존재를 확정한 것은 아니며, 추후 확정 기준에 따라 다시 대조해야 한다. 특정 자격증 업로드 방식이나 검증 API를 개정법 본문이 직접 의무화한 것으로 설명하지 않는다. 아래 자격 관리 구조는 준법 운영을 지원하기 위한 설계 권고다.

## 발견 1 — 등록만으로 활동중이 된다

- [용달기사프로필UseCase](../../Ssalddel/Application/Driver/Profile/용달기사프로필UseCase.cs) 44행의 필수 입력은 성명·연락처·차량·지역이다. 63~77행은 기사 역할을 부여하며 86행은 요청 상태 또는 기본 `활동중`을 저장한다.
- [등록 DTO](../../Ssalddel.Contracts/Driver/Profile/용달기사Dtos.cs), [용달기사](../../Ssalddel.Domain/기사/용달기사.cs), [배달기사](../../Ssalddel.Domain/기사/배달기사.cs)에서 추적한 자격 증빙·검토자·유효기간·취소 상태를 찾지 못했다.
- [기사관리Controller](../../Ssalddel/Controllers/Admin/06_관리/기사관리Controller.cs)의 현재 관리 경로는 목록·상세·배차내역 조회다. 이 경로에 자격 승인·반려·정지 명령은 없다.
- [CommunityProfessionalEligibilityService](../../Ssalddel/Services/Community/CommunityProfessionalEligibilityService.cs)의 도로 운송 역할은 내부 역할 매핑이다. 메서드 이름의 `Verified`를 공식기관 확인으로 해석하지 않는다.

- [용달운송배차업무정책](../../Ssalddel/Services/Dispatch/Queue/용달운송배차업무정책.cs) 127행 이후와 [국내화물배차후보금지정책](../../Ssalddel/Services/Dispatch/Coordination/국내화물배차후보금지정책.cs) 66행 이후에는 활동·운행·위치 조건이 있다.
- [화물배차수락적격성Service](../../Ssalddel/Services/Dispatch/Recommendation/화물배차수락적격성Service.cs)는 차량·적재·시간창 조건을 다룬다. 기존 운송이 있는데 차량 제원이 없으면 막지만 첫 단독 운송은 경고를 확인하면 수락을 허용한다.

## 발견 3 — 한국 허가 확인은 감사용이며 강제 관문이 아니다

- [OperatingMarketFreightPolicies](../../Ssalddel.Contracts/Common/Operations/OperatingMarketFreightPolicies.cs) 93~102행은 한국 프로필을 `AuditOnly`로 정의한다.
- [OperatingMarketFreightWorkflowPolicy](../../Ssalddel/Services/Operations/OperatingMarketFreightWorkflowPolicy.cs) 79행 이후는 `Required`가 아니면 자격 평가가 미완료여도 진행을 허용한다.
- [기존 정책 시험](../../Ssalddel.Tests/Services/Operations/OperatingMarketFreightWorkflowPolicyTests.cs) 19행은 한국 허가 누락을 기록하면서도 `CanProceed=true`를 기대한다.
- 따라서 법령 이름·허가 코드의 존재를 실제 허가 확인·등록 적격 확보의 근거로 삼지 않는다. 무료 정보연결·유상 주선·자기 명의 운송을 구분해 필요한 검증 강도를 정해야 하며, 무조건 주선허가를 요구하도록 바꾸는 것도 이번 결론이 아니다.

## 발견 4 — 무료 운영 방향과 기존 설정이 일치하지 않는다

- [기본 설정](../../Ssalddel/appsettings.json) 678~681행과 [개발 설정](../../Ssalddel/appsettings.Development.json) 109~112행에 `무료배차=false`, 기본이용료 500원, 월상한 5,000원이 남아 있다.
- [기사이용료정책Options](../../Ssalddel/Services/Options/기사이용료정책Options.cs)의 C# 기본값은 무료이지만 JSON이 이를 덮어쓴다. [기사월정산Service](../../Ssalddel/Services/Settlement/기사월정산Service.cs) 125행은 이 정책으로 이용료를 계산한다.
- [화주직접운임제안Policy](../../Ssalddel/Application/Shipper/Request/화주직접운임제안Policy.cs) 20~31행의 특정 직접 제안 경로는 수수료 0원·화주 금액과 기사 금액 일치를 강제한다. 이를 모든 접수·정산 경로의 기본값이라고 볼 수 없다.

## 발견 5 — 일반 신고·선택 화물 입력을 준법 절차로 연결해야 한다

- [화주운송의뢰 DTO](../../Ssalddel.Contracts/Shipper/Request/화주운송의뢰Dtos.cs)에 종류·중량·치수·출도착 필드가 있다. [화물 작성 화면](../../Ssalddel.Ui.Common/Areas/App/Components/Transport/ShipperRequestCargoScreen.razor)은 중량·부피를 받지만 필수가 아니며 수량·중량·부피 중 하나로 다음 단계에 진행한다.
- [의뢰생성CommandHandler](../../Ssalddel/Application/Shipper/Request/Handlers/의뢰생성CommandHandler.cs)는 기본 종류·주소·시간을 검사하고 중량·부피 누락을 그대로 저장하는 경로를 가진다.
- [운송문제신고CommandHandler](../../Ssalddel/Application/Driver/Transport/Handlers/운송문제신고CommandHandler.cs)와 [비정상운송사건운영UseCase](../../Ssalddel/Application/Admin/Progress/비정상운송사건운영UseCase.cs)는 본인 운송·증빙·사유·사건·사후처리를 연결한다. 이를 법 위반 신고와 동일하다고 표시하지 않는다.
- 적법한 창고 인계·다른 업무의 위탁을 법에서 금지하는 화물 재위탁으로 일괄 분류하지 않는다. 운송계약·위탁 주체와 실제 금지 요건을 대조해야 한다.

## 최소 보완 순서

1. **무료 운영 계약과 설정 일치:** 무료 정보연결 범위, 실제 운송계약 당사자, 운임 직접지급을 명확히 하고 모든 공개 진입 경로의 수수료·수납·이용료를 대조한다. 관할기관의 적용 판단은 별도로 확인한다.
2. **법정 자격 기록:** 플랫폼 자신의 등록, 운송사업자 허가·소속/위수탁 관계, 기사 개인 자격, 실제 차량·보험을 분리한다. 기존 기사 프로필과 안정 ID로 연결하고 별도 역할을 새로 만들어 승인으로 대체하지 않는다.
3. **검토와 유효성 상태:** 미제출 → 검토 중 → 유효 / 반려 / 만료 / 정지로 나누고, 확인 근거·검토자·확인일·재확인일을 보존한다. 문서 수령·관리자 확인·공식기관 조회는 서로 다른 확인 수준이다. 모든 자격증에 일률적인 만료일을 만들지 않고 실제 유효·정지 조건을 사용한다.
4. **서버 공통 관문:** 수단·업무별 필수 요건을 판정하고 운행 시작·추천 생성·수락 시 재확인한다. AI는 이 관문을 통과한 후보만 평가하게 한다. 정지·만료 중인 기존 배송은 숨기지 않고 안전 인계·관리자 지원으로 분리한다.
5. **화물 입력·위반 관리:** 법령상 화물 필수 항목, 적재 근거 미확인 처리, 위반 확인·기관 신고·이용제한·이의제기·복구를 기존 전문 원장과 연결한다.

서류 수집 시 주민번호·불필요한 면허번호·원본 사진 전체를 무조건 저장하지 않는다. 필요한 항목과 보관 근거, 비공개 접근 권한, 만료 후 보관·삭제를 먼저 정한다. 법령 준수를 특정 AI 모델 판단이나 자체 점수로 대체하지 않는다.
