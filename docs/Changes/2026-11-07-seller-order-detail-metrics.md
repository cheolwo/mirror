# 판매 주문 상세의 좁은 폭 요약 배치

390px에서 가상 판매 주문 42번을 열면 출고 라인 수·예약 수량·출고 창고 수·운송 인계 표시가 한 열로 쌓였다. 요약의 높이는 286px였고 첫 출고 후보는 초기 화면 아래에 있었다. [이전 390px 상세](../assets/changes/2026-11-06-seller-order-row-readability/detail-390.png)

좁은 폭에서도 기존 두 열 규칙을 사용한다. 같은 주문의 390px 요약 높이는 138px로 줄고, 첫 출고 후보를 보려면 이전보다 148px 덜 내려가면 된다. [공용 화면 스타일](../../Ssalddel.Ui.Common/Areas/App/Components/Sales/ShipperSalesOrderWorkspace.razor.css) · [2026-11-07 390px 가상 주문 상세](../assets/changes/2026-11-07-seller-order-detail-metrics/detail-390.png)

가상 주문 4건을 320px·390px·1280px에서 조회하고 수정 전후 각각 52개 브라우저 검사를 통과했다. 320px에서도 첫 출고 후보가 148px 앞당겨졌고 두 좁은 폭에서 네 항목은 한 줄씩 읽을 수 있었다. 1280px의 네 열과 첫 후보 위치는 유지됐다. 검색 결과에서 터치·키보드·클릭으로 같은 주문을 열고 두 출고 라인의 수량과 창고를 확인했다. **주문 목록**으로 돌아왔을 때 검색 조건을 유지했다.

Fast 관련 시험 51개와 통합 3.5 Task 전체 시험 17,051개가 통과했다. 별도 환경이 필요한 17개는 생략했다. 빌드 오류는 0개였고 Fast 경고는 0개, 통합 빌드 경고는 62개였다.

격리 브라우저는 판매자 앱의 실제 목록·상세와 공용 컴포넌트에 가상 조회 응답을 연결했다. 통합 웹과 통합 앱은 같은 상세 컴포넌트를 사용하는 경로와 빌드를 확인했다. 제품 서버·DB, 실기기, 주문 변경은 미검증이다. 전후 캡처·측정·시험 근거는 `artifacts/local/mirror-ui-assist/20261106T151623997Z-seller-order-detail-metrics/completion.json`에 연결했다.
