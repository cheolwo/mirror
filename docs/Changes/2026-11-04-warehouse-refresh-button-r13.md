# 창고 작업대 새로고침 버튼의 좁은 화면 보완 r13

등록 휴대폰의 화주145에서 창고 작업대의 새로고침 글자가 한 글자씩 네 줄로 꺾이는 것을 확인했다. 기존 버튼의 줄바꿈과 축소만 막아 문구·위치·조회/로딩 동작·업무 권한을 유지한다.

## 실제 화면에서 확인한 경로

초기 화면은 역할 선택 홈의 최상단이다. 생산 참여 집계 아래로 스크롤하면 업무 역할 카드가 나온다. r12 비공개 시각 메모의 ‘낮은 스크롤 위치’라는 해석은 이번 소스/실기기 대조로 정정하며 원본 기록은 보존한다.

실제 보인 화주 카드 → 목록 → 업무 도구의 운송 내역 → 화주 메뉴 열기 → 화주 창고 작업공간으로 이동했다. 기존 합성 의뢰와 타임라인은 재로그인 없이 조회됐다. 현재 계정의 창고 조회는 HTTP403으로 안내됐으며 명시적 새로고침 뒤에도 같은 권한 오류가 유지됐다. 정상 하단 홈으로 돌아가 화주 홈을 확인했다. **창고 데이터를 성공적으로 조회하거나 빈 재고임을 확인한 것은 아니다.** 일반 화주와 창고 HR 권한의 기존 구분은 바꾸지 않는다.

145의 새로고침 버튼은 실제 화면에서 `[745,1171]~[967,1523]`으로 좁고 길게 표시됐다. 화면은 메모리에서만 검토했고 스크린샷·원시 UI 파일은 저장하지 않았다. 화면의 기존 안내·단일 새로고침·홈 복귀와 좁은 폭의 글자 깨짐을 각각 구분해 기록했다.

## 최소 수정과 코드 검증

`ShipperOperationsWorkspace.razor`의 기존 새로고침 버튼에 `white-space: nowrap; flex-shrink: 0;` 한 속성만 추가했다. 이를 제거하면145의 기존 Razor SHA와 정확히 같아진다. 제목·설명·부모 행·경로·Disabled/isBusy·LoadAsync·상태/권한은 유지한다. 새 기능·정보 구조나 상호작용을 바꾸는 시안 작업이 아니라 기존 버튼 글자 줄바꿈 오류의 보완이다. 별도 공통 스타일이나 새 시험은 추가하지 않았다.

- Fast `20261104-232903`: 기존 표시/경로·창고 응답·홈 구성 회귀51/51 통과·실패/생략0. 화주 소비 앱 빌드 오류0/기존 경고20이다. 창고 응답 회귀21개는 기존 시험이며 새 시험이나 합성 재현 TRX로 표시하지 않는다.
- Task `20261104-233112`: 현재 변경 경로에 대한 계획의 `Ssalddel.v0.0.slnx` 통합 빌드 오류0/기존 경고5, 전체16,957통과·환경17생략·실패0이다. 실제 TRX와 계획/빌드 로그를 대조했고 이전 결과를 승계하지 않았다.
- 독립 읽기 검토에서 한 속성 수정이 기존 조회 동작을 바꾸는 문제는 찾지 못했다. 새146의 기기 렌더는 아래 실제 관측으로 따로 검증했다.

## 판본과 실제 수정 결과

145 재사용 전에는 등록 단일 USB·OS 잠금·현재 유휴/전면·같은 설치 바이트/서명/endpoint와 기존 수집 checkpoint를 다시 확인했다. r11의 넓은3610개 입력 중 이후 바뀐 관리자 소스/README 두 경로는 실제 Shipper 참조 그래프·DLL/PDB의 화주 소스 밖임을 별도 기록했다. 나머지3608개는 같지만 전체3610개가 현재 일치한다고 쓰지 않으며 기존 r12 설치 guard는 바꾸지 않았다. 이번 화주 Razor 수정 이후에는 이전145용 조작 도구를 계속 쓰지 않는다.

146는 별도 출력으로1회 포장해3611입력 변경0·같은 서명/두 ABI/내장 DLL/5378·오류0/경고행17을 확인했다. 실제 설치 바이트·최초 설치 시각·원래 앱 보존도 대조했다. APK SHA는 `8afe8a293c541d44b4fc0bbcd66b9afb966447c1745355f225ead74ea0620965`다.

설치 직후 이전 배민 전면 복원과 MAIN 직후 비동기 전환 때문에 후속 검사에서 멈춘 기록은 그대로 보존했다. 단일 설치나 단일 MAIN을 재실행하지 않았다. 별도 읽기에서 같은 설치146·유휴 화면·설치 전과 같은 커널 활동·수집 중지를 확인하고, 이후 안정된146 전면을 다시 읽은 뒤 정상 메뉴로 이어갔다. 기존 중단 영수증의 상태를 성공으로 덮어쓰거나 승인 검토의 거절을 우회한 것이 아니다.

등록 휴대폰의 세로 화면에서 새로고침 버튼은 `[638,1261]~[967,1382]`로 표시됐으며 글자가 한 줄이고 카드 안에서 잘림/겹침이 없었다. 실제로 활성 새로고침을1회 누른 뒤에도 같은 한 줄 표시와 HTTP403 안내가 유지됐고, 정상 하단 홈을 눌러 화주 홈으로 돌아왔다. 이는 권한 오류 뒤 재조회·화면 복귀와 버튼 표시의 확인이며 창고 데이터 조회 성공은 아니다. 다른 폭/가로 화면·권한 있는 계정의 조회는 별도다. 스크린샷·원시 UI는 저장하지 않았다.
