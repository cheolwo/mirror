# 화주 창고 목록의 불완전한 응답 처리 r11

화주 창고 작업대의 입고·재고 조회가 불완전한 서버 응답을 정상 빈목록으로 받아들이거나 null 항목을 화면 계산으로 넘기던 경계를 보완했다. 창고 목록을 사용하는 기존 화주 기능도 같은 검증을 사용한다. 화면 배치·경로·API/원장 계약과 실제 창고 업무 명령은 변경하지 않았다.

## 발견과 수정

`ServerBackedShipperOperationsService`의 창고·입고·재고 조회는 `response?.Items ?? []`를 반환했다. HTTP200의 `null`과 `{"items":null}`은 성공한 빈목록이 됐고 `{"items":[null]}`도 통과했다. 작업대의 입고 상태·가용수량 계산에서는 null 항목을 역참조할 수 있다. 실제 `WarehouseOperationService`는 사용자 접근 범위의 원장을 배열로 조회해 `Items`에 넣으며, 정상 빈 결과는 `{"items":[]}`다.

실제 서비스·인증·HTTP 클라이언트와 합성 응답을 연결한 새 21사례 중 수정 전 12개가 실패하고 9개가 통과했다. 세 반환 지점에 private 목록 검증을 연결해 null 목록·null 원소만 거절한다. 정상 빈목록·정상 내용, 기존 HTTP401/403/503·취소·요청 횟수와 명시적 재조회는 유지한다. 공용 전송/JSON 해석·인증·샘플 전환은 바꾸지 않았으며 기존 r2 변경은 보존했다. 404/204를 이번에 바꾼 것으로 표시하지 않는다.

## 검증과 현재 단계

- Fast `20261104-220230`: 새 21사례를 포함해 관련 58/58 통과, 실패·생략 0. 시험 의존 빌드 오류 0/기존 경고 229, 화주 소비 앱 빌드 오류 0/기존 경고 22다.
- Task `20261104-220351`: 통합 빌드 오류 0/기존 경고 60, 전체 16,949 통과·환경 17생략·실패 0. 실제 TRX의 개별 결과를 확인했다. 과거 통과 수를 이번 판본에 승계하지 않았다.
- 같은 소유 r6 호스트의 실제 PID·부모·시작 시각·명령·DLL 해시와 격리 DB를 대조했다. 전후 live/ready·홈·업무 proof2개의 HTTP는 각각 5/5가 200이며 proof2개 불변·금융 행은 0이다. 기존 readiness journal21개도 보존됐고 새 실패 관측은 없다. 과거 모든503의 해결을 선언하지 않으며 서버/DB 재시작이나 실제 창고·금융 명령은 실행하지 않았다.
- 새 화주 APK145를 별도 출력으로1회 포장했다. 선택 입력3,610개 변경0, 같은 서명·두 ABI의 내장 앱 DLL·5378 주소를 확인했고 포장 오류0·경고행17이다. APK SHA는 `81c0f0f92a5d6975bc582973d412d510a6d8281bad8af161e576739af2186015`, 앱 DLL SHA는 `8b380dcedc9174811f897e9463193ace3e200f92fa4b848f7c82b6e026a625b3`다. 이전144와 기존 정상/실패 출력은 보존했다.
- 등록 휴대폰의 설치144 바이트를 기존 서명/endpoint 검증본과 대조했다. 관찰 화면은 배민 내역이고 기존 수집 checkpoint가 미완료라 전면·기존 자료와 기사 직접 로그인 대기를 보존해 기기 조작은 하지 않았다. **145는 미설치·실제 화면/보안 저장/서버 통신 미검증**이며 포장 결과와 구분한다.

실제 HTTP는 합성 응답기에서만 오류를 재현했으며 새 21사례는 정상 빈값/내용·오류 거절·typed API 작업 ViewModel의 명시적 재조회 복귀를 검증한다. 작업대의 최초 실패 시 기본 0 메트릭, 여러 목록의 전체 원자 갱신, `Items`를 생략한 `{}`의 해석은 이번 완료 범위 밖이다. 기존 화면 캡처를 새 렌더 근거로 사용하지 않는다.

재개 기록은 `artifacts/local/app-stability-r11/1911f749ae1a4ef28ff913d2cf30e2ba/completion.json`이다. 원본 소스·실패 TRX·현재 Fast/Task·포장·서버/기기 관찰 근거를 같은 폴더에 보존한다. 다음 한 가지는 기기 작업·인증 조건이 갖춰졌을 때 같은 소스/145·서버·기기를 다시 대조해 데이터 보존 업데이트와 창고 작업대 조회·오류 후 재조회를 확인하는 것이다. 앱 전체 안정화·다른 역할/원격 운영·출시 완료는 아니며 배달 수집·실제 배차/운행·금융·배포·commit/push는 실행하지 않았다.
