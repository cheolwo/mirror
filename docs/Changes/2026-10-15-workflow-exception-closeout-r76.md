## 화면 책임

기존 활동 정산 화면의 목록·선택 약정 상세·주간 명세는 서로 배타적으로 표시한다. 지급 신고는 약정 상세에서만, 수령 해결은 정본의 실제 주문자·판매자에게만 제공한다. 음식 지원 후속은 기존 보호지원관리 상세에서 현재 사건과 원주문을 인계하는 책임이다. 공간 반출은 기존 분산 업무 안에서 물품 인계와 공간 사용 종료를 별도 행동으로 구분한다.

[활동 정산 화면 책임](../ProjectOverview/page-docs/activity-weekly-statement-r76.md)과 [업무 트리](../ProjectOverview/page-docs/role-workflow-tree-r76.md)에 기본 정보·주 행동·복귀·오류 경계를 기록한다. 공유 Razor 렌더와 동작 회귀 시험은 수행 대상이며, 실제 브라우저 화면 캡처·휴대폰 터치·카메라·소리 청취 검증은 수행하지 않았다.

공통 업무 규칙은 수정 없이 전체 Task를 통과했다. 이후 음식점의 이전 조리 문구 기대와 합의 보수가 없는 기존 수락 시험 자료만 보정했다. 최종 Fast 통과 뒤 제품 전체도 다시 통과했으며, 이미 통과한 공통 규칙은 소스 불변 해시를 확인해 다시 실행하지 않았다. Fast의 Simulation 대상 필터는 일치 0개였으며 이를 2,001개의 전체 검증과 혼동하지 않는다. 건너뛴 16개는 실제 격리 MongoDB/MySQL 설정이 필요한 시험이다.

초기 시험에서 발견한 EF 조회식·구형 주문 연결·대기 시각 fixture·중복 시도 ID·반출 클라이언트의 네 명령 연결 누락은 수정했다. 반출 보수 보존 시험은 실제 로컬 사진 업로드·결속 근거를 사용하며 사진/정산 관문을 완화하지 않았다. 실패 로그와 최종 소스 해시·기존 파일 보존 점검은 `artifacts/local/workflow-exception-closeout-r76/`에 별도로 남긴다. UI 상호작용·서버/SQLite 시험은 실제 휴대폰·MySQL/Mongo·외부 알림·송금 증거가 아니다.

## 아직 별도로 필요한 일

- 음식점 수락 이후 취소 승인·재배송·재조리 비용과 기사 보수 책임의 실제 결정 명령은 운영 정책이 필요하다. 이번에는 검토 인계까지 제공한다.
- 불량 물품 처분·소실 정정, 별도 반출 보수·기사 알림과 200개 반출 계획 이후 보관 재개 정책은 남아 있다. 반출 이후 정확한 보관기간·수량 구간 재구성도 후속이며 이번에는 해당 물품의 새 보관료·기간 원가 배부를 보류한다. 기존 인계·철회·취소를 위해 기록을 삭제하거나 상한을 우회하지 않는다.
- 활동 지급 신고의 유실 복구는 현재 로그인 세션 범위다. 앱 프로세스 종료 뒤 미확정 요청의 영속 복원은 별도 보완이다.
- 주간 명세는 읽기 전용이며 자동 주간 송금이 아니다. 실제 은행 확인·공제·Provider 지급·Toss 실제 거래는 별도다.
- 실제 MySQL/Mongo 동시성·클라우드 서버·FCM/알림음·휴대폰·APK 설치 검증은 별도다. 기존 운영 기본 OFF와 Simulation 경계를 유지하고 공유 DB migration·운영 활성화·클라우드 변경·Unity 장면·commit/push를 실행하지 않는다.
- 기존 시험 프로젝트의 `Microsoft.AspNetCore.SignalR.Common 10.0.9`에 대한 `NU1903`, AndroidX 의존성 버전 경고와 일부 앱 Firebase 미설정 경고는 남아 있다. 이번 업무 수정의 빌드 통과를 패키지 보안 조치나 실제 푸시 준비 완료로 확대하지 않는다.
