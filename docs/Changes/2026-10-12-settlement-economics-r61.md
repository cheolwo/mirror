## 변경

확정된 입고·보관 비용을 실제 예약 Lot·수량의 출고 원가에 연결한다. 고정비의 분모는 불변 원래 약정 수량이며 원천 청구 항목의 Quantity=1을 쓰지 않는다. 단일 입고 근거와 전체 수량을 확인한 비용만 자동 귀속하고, 보관 기간 전체가 최초 피킹 이전이어야 한다. 여러 입고회차·부분 비용·겹치는 보관 기간은 추정하지 않는다. 입고·보관은 각각 명시적인 비용 또는 무료 확정 근거가 있어야 하며, 기존 작업자의 채무를 다시 만들지 않는다.

새 `ActivityRewardTerms.Economics` 약정만 비용 차감 후 잔여금의 5% 또는 10%를 명시적으로 플랫폼에 배분한다. 기본 작업비·연결 원가·기타비·예비금은 각각 별도 차감한다. 참여자 풀은 나머지 95% 또는 90%의 정수 원 내림이고 그 내림 잔액은 플랫폼 몫에 명시적으로 포함한다. 기존 Economics 없는 요청의 JSON·멱등 지문과 계산 방식을 유지한다.

원천 항목+주문 고유 원가 귀속 기록은 상세 금액·수량을 보호된 JSON에 동결한다. 기존 Serializable 명령 트랜잭션과 공유 원천 약정 Revision으로 동시 변경을 보호하고, 원가 귀속·성과금·플랫폼 몫·계산 영수증을 함께 저장한다. 이미 귀속한 항목이나 성과금은 새 조건·조정으로 덮어쓰지 않는다. 미확정 조정이나 원천 순액 부족은 새 발생을 보류한다.

서버에 설정된 기존 서버관리자 플랫폼 수령자의 약정 동의를 별도로 확인하며 창고·배송 역할을 만들지 않는다. 플랫폼 항목·전용 수익 기록을 추가하고 기간 성과환원 계산에서는 주문에서 이미 분배한 잔여금 수익원을 제외한다. 기본 지급의 확정·신고·수령 확인은 기존 절차를 그대로 거친다.

보관 원가의 과거 수량은 전체 재고 변화의 사진·완료 영수증을 대조한 뒤 변화 시점별 상수량 구간으로 판정한다. 입고 3개 뒤 1개씩 두 번 피킹해도 최초 피킹 전 3개 보관 근거는 유지된다. 기존 연속 보관 구간과 입고 작업 목록은 바꾸지 않는다. 새 약정 당사자는 과거 성과금을 조회할 수 없고, 플랫폼 수령자의 항목 응답에서는 다른 작업자의 증빙 참조를 숨긴다. 원래 부담자의 감사 근거와 저장 원문은 유지한다.

## 검증 상태

- Fast 집중 시험 239건 통과, 실패·건너뜀 0. 전체 앱 빌드 오류 0. 증거 `artifacts/local/validation/20261012-132028/`.
- Task 전체 시험 11,088건 통과, 실패 0, 환경 의존 MongoDB 15건 건너뜀(전체 11,103건). 전체 앱 빌드 오류 0·경고 64건. 기존 의존성 제약·Firebase 미설정·nullable 등 경고를 해소했다고 보고하지 않는다. 증거 `artifacts/local/validation/20261012-132234/`.
- 격리 SQLite에서 실제 입고 사진·재고·주문 예약·피킹·전달·고객 수령을 연결하여 입고비 200원과 유료 보관비 60원을 출고 원가로만 반영했다. 잔여금 2,540원을 참여자 2,286원과 플랫폼 254원으로 나누고 원래 입고비 채무를 다시 만들지 않는 것을 확인했다. 사진·지급 신고는 시험 자료이며 실제 이체가 아니다.
- 원천 고정비 101원을 세 주문에 33·34·34원으로 배분, 미확정 조정·원천 부족·수량 초과·다른 주문의 선행 귀속 후 재확인, 재전송·과거 약정·타인 비용 접근을 검증했다. 실제 resolver의 순차 피킹·같은 시각 변화·반환 공백·누락 사진·미래 작업·음수 재고 시험 11건을 추가했다.
- UI HtmlRenderer 21건에서 연결 원가·플랫폼 몫·참여자 풀과 당시 계산 비율, 미확정 값·개인정보 비노출을 검증했다. 실제 브라우저·APK·휴대폰 화면 사용은 별도다.
- 최초 빌드는 시험의 잘못된 `Summary.Revision` 참조에서 실패해 `Agreement.Revision`으로 정정했다. 중간 공백 검사는 문서 말미 빈 줄을 정리했다. 첫 실행 시험은 213건 통과·12건 실패(`20261012-130806/`), 다음은 224건 통과·1건 실패(`20261012-131402/`)했다. 명시적 무료 금액 준비, 강화된 과거 접근권 기대값과 CSS 격리 속성에 영향을 받지 않는 항목/값 검증을 보완했다. 별도 코드 검토에서 발견한 플랫폼 증빙 참조 노출 및 과거 보관 수량 문제도 수정하고 새 회귀 시험을 포함했다.
- 이번 r61 문서와 정확한 신규 목차 참조의 로컬 링크 17개는 모두 존재한다. 기존 목차 전체의 링크 감사 완료를 뜻하지 않는다. 현재 소스 26개 지문과 수용 문서 해시는 작업 명세에 기록하고 과거 r59/r60 지문은 보존한다. 새 migration은 격리 SQLite의 생성 작업 및 MySQL 모델 대조로 확인했으며 실제 운영 DB에 적용하지 않았다.

## 적용 범위

기본 비활성·Simulation 전용이다. 실제 DB migration 적용·은행 이체·실제 수익/영업이익 대사·Azure·기기 설치·Unity·AI 경제 연계·commit/push는 수행하지 않는다. 기존 r53/r54/r59/r60 변경을 보존한다.

여러 입고회차의 물품 계보·부분 비용·피킹을 가로지르는 보관 기간의 임의 배분과 새 실패/반품 비용 정책은 이번 범위에 포함하지 않는다. 불명확한 근거는 0원으로 보완하지 않고 추가 배분을 보류한다.
