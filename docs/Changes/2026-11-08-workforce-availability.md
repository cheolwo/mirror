# 창고 처리 묶음의 인력 계획과 근무 가능 답변

기존 공정·실제 작업 묶음에서 남은 수량을 확인하고, 관리자가 처리량·순작업시간 가정으로 필요 인원을 검토한 뒤 기존 창고 등록 인력에게 근무 가능 여부를 묻는다. 본인은 가능·불가·철회하고, 관리자는 가능 답변만 정원 안에서 인력 계획에 확정한다. 기존 고용·HR 역할·실제 작업 배정·출근·급여 상태는 변경하지 않는다.

- 관리자: 출고 웹의 피킹·포장 단계 → **이 공정의 인력 계획** → 실제 묶음 선택 → 시간·인원·대상 확인 → **가능 여부 요청 등록** → **인력 계획에 확정**.
- 작업자: 역할 지원 → **내 근무 요청 · 가능 여부 답변** → 수신 동의 → 받은 요청의 **가능 / 불가 / 내 답변 철회**.
- 요청에는 원래 창고·공정·묶음 키·조회 구간·수량 관측 시각을 보존한다. **같은 처리 묶음으로**는 그 키와 구간으로 돌아간다. 접수 구간을 근무 회차로 해석하지 않는다.
- 새 연락 수신 설정은 기본 거부다. 대상은 같은 창고 등록·현재 동의로 제한하고 본인 답변은 본인에게만 보인다. 기존 HR 관리자 권한과 창고 경로 범위를 함께 확인한다.
- 동일 요청 ID의 재시도는 동일 결과로 확인하며 다른 내용은 거부한다. 현재 답변 판본·정원·시간 중복을 확인하고 겹치는 확정과 오래된 수정은 충돌로 반환한다.
- 앱 수신함 등록, 카카오 공급자 접수/불명확/미발송, 본인 답변, 인력 계획 확정을 구분한다. 카카오는 기존 실행기에 인력 템플릿·응답 주소 설정을 추가했으나 기본 비활성이며 실제 발송하지 않았다. 문자 실행기는 미연결이다. 불명확한 외부 전송은 자동 재발송하지 않는다.
- 저장용 세 테이블의 신규 마이그레이션을 제공한다. 운영 데이터베이스에는 적용하지 않는다. 기존 개인 연락처를 요청 테이블에 복제하지 않는다.

화면 책임은 [페이지 카드](../ProjectOverview/page-docs/warehouse-workforce.md), 실행 근거와 원본은 [검증 폴더](../../artifacts/local/workforce-availability-20261108/)에 있다. 기존 출고 진입의 변경 전 원본을 보존하고 신규 인력 화면은 이전 동등 화면이 없다는 점을 구분해 비교한다.

검증 완료: 최종 Fast 관련 회귀 183개와 Task 전체 17,503개가 통과했다. 환경 조건이 필요한 17개는 건너뜀이다. 마감 Task는 기존 운영 사용자 정책을 관리자 경로에도 적용한 최종 Controller/시험 판본까지 포함한다. 중간의 새 화면 capability 분류 누락과 feature gate 설명 누락은 수정했으며 원본 실패 기록은 보존했다.

- [전후 비교와 신규 화면](../../artifacts/local/workforce-availability-20261108/comparison.html) · [최종 실제 Chrome 조작](../../artifacts/local/workforce-availability-20261108/browser-after/receipt.json) · [최종 소스 지문](../../artifacts/local/workforce-availability-20261108/frozen-source.json)
- 실제 현재 WebApp/WASM/라우터에서 390·320·1280px의 요청 등록·본인 답변·관리자 확정·동일 출고1102/작업903 복귀, 조회 중/오류 복구·로그인 복귀·초점·가로 넘침을 대조했다. 요청 두 건은 업무 시간·필요 인원·안내 금액과 확정 상태를 달리한다.
- 브라우저 API는 격리 SQLite에서 실행한 신규 UseCase의 응답을 전달하는 유한 합성 API다. 원래 출고 계약의 작업903·수량6을 재사용했다. 실제 운영 HTTP 인증/권한·운영 DB·공급자 전송/휴대폰 수신을 검증한 것은 아니다. 서버 본인/창고 범위·판본·중복·정원·시간 충돌·금액 정밀도는 격리 UseCase 회귀로 확인했다.
- 전체 빌드 뒤 공통/웹 WASM 판본 혼합을 한 번 관측해 실패 화면을 보존하고, 소비 웹을 새로 빌드해 최종 판본에서 다시 조작했다. 네이티브/USB는 미실행이며 이번 신규 소비 화면은 웹이다. 기존 공통 출고 화면의 앱 소비는 추가 링크를 전달하지 않으면 동일하다.
- 운영 DB 마이그레이션·인력용 카카오 승인 템플릿/발송 설정·실제 수신은 남아 있다. 문자 전송 연결은 없으며 앱 수신함과 별도다. 관리자 취소·대상 추가·마감 후 재모집·교대표/실제 근무 배정은 초기 범위 밖이다. 기존 W3의 화면/USB 미완료는 보존하고 다음 정기 재개 항목으로 둔다.
