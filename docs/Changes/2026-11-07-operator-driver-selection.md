## 완료 조건과 수정

완료 조건은 **재조회 뒤 선택 표시·현재 기사 목록·저장 요청의 기사가 일치하고, 사라진 기사 ID로 저장하지 않는 것**이다. [기존 페이지](../../SsalddelAdmin/Components/Pages/DomesticCargoDispatchAIReview.razor)의 초기 선택·제안 선택·직접 기사 선택·판단 저장과 버튼/지도 강조가 같은 현재 기사 판별을 사용한다. 비어 있지 않고 현재 응답에 Ordinal로 정확히 한 번 있는 ID만 선택한다.

추천이 없으면 현재 목록에 남은 기존 선택은 유지한다. 유효한 새 추천은 기존처럼 선택하고, 사라진 선택은 비워 기존 기사 선택 안내를 사용한다. 사용 가능한 묶음이 없을 때의 기존 첫 기사 초기 선택은 첫 유효 기사로 유지한다. 이전 화면의 늦은 기사 선택 콜백도 현재 유효한 선택을 다른 ID로 바꾸지 않는다. 저장 직전에도 다시 대조해 유효하지 않으면 판단 요청을 보내지 않는다.

동일한 가상 구성 의뢰 `REQUEST-CURRENT`·`REQUEST-SECOND`, 묶음 `BUNDLE-CURRENT`와 화물 내용을 재조회 전후 유지한 시험에서, D2를 명시적으로 선택한 뒤 기존 구성 ID와 D2가 같은 판단 요청으로 전달됨을 확인했다. 이 확인은 검토 화면에서 기존 판단 요청으로 이어지는 경계다. 실제 기사 배정·배차·역할 인계 완료나 서버의 최신 기사 자격을 새로 판정한 것이 아니다.

## 검증 범위

구현·시험 두 경로를 지정한 Fast는 **56개 통과·실패 0개**다. 신규 실제 부모 선택·저장 25개, 기존 구성 렌더 30개와 기존 서버 판단 서비스 1개를 포함한다. Tests 빌드 경고 236개·Admin 소비 빌드 경고 0개, 오류는 모두 0개다. 신규 시험에는 정적 renderer 정리의 BL0006 1곳과 `Assert.Single` 사용의 xUnit2031 2곳이 포함돼 있다. 로그는 `artifacts/local/validation/20261107-174616`이다.

신규 시험은 정상 추천·새 유효 추천·추천 없는 유효한 수동 선택 유지, 목록 밖·빈·중복 기사, Ordinal/공백 비정규화, 늦은 이전 버튼 콜백과 저장 직전 목록 변경을 대조한다. 실제 Razor 출력의 기사 버튼 강조와 동일 기사 지도 핀 강조를 요청 본문과 함께 검사했다. 503·401·403·정상 0건에서는 이전 기사를 표시하거나 판단 요청을 보내지 않는다. 중복·빈 ID는 합성 경계이며 실제 운영에서 발생했다고 주장하지 않는다.

같은 두 경로를 지정한 마감 Task는 **전체 17,380개 통과·실패 0개·환경 의존 17개 생략**이다. 통합 1.5 소비 빌드 오류 0개·기존 앱 설정 경고 5개이며 실제 푸시·지도 설정을 추가하지 않았다. 로그는 `artifacts/local/validation/20261107-174744`이다. 실행한 Tests 사본의 Admin DLL과 현재 소비 DLL, 페이지·신규 시험의 portable PDB 소스 지문을 대조해 같은 판본의 결과임을 확인했다.

사용한 페이지는 실제 컴파일된 부모 인스턴스이고, 제품의 InteractiveServer 모드를 바꾸지 않았다. 공개 StaticHtmlRenderer와 `IHandleEvent`를 통해 실제 이벤트 메서드를 실행했으며 서비스의 GET/POST는 허용한 `fixture.invalid` 경로의 메모리 handler만 사용했다. POST는 메모리에 요청을 기록하고 합성 응답을 반환한 것이며 외부·제품 서버의 판단 자료는 저장하지 않았다.

브라우저의 실제 클릭·키보드·초점·주소창/라우터, 실제 인증·서버·DB·실기기·운영 사용은 이번에 실행하지 않았다. 가독성·HTML 구조·CSS를 바꾸지 않아 루트 README와 [현재 구성 확인 대표 캡처](2026-11-07-operator-bundle-members.md)는 보존했다. 이전 정상 렌더의 소스 일치와 DLL 차이도 기록해 종전 캡처를 이번 O1 재현으로 사용하지 않았다.
