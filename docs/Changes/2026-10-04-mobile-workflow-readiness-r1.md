# Android 업무 상태와 설치 준비 r1

2026-10-04. 기존 앱을 설치한 휴대폰에서 역할별 업무가 현재 상태에 맞는 정보·행동으로 이어지도록 보완한다. [총괄 책임·OS 기준](../ProjectOverview/page-docs/mobile-workflow-readiness-r1.md)을 따른다.

## 구현 범위

- 주문자 선택 주문은 모바일에서 상세에 집중하고 목록 복귀를 제공한다. 취소·거절 상태에는 전달·수령 대기 안내를 제외한다.
- 음식점 인증 만료 뒤 같은 계정으로 로그인하면 원래 주문 상세를 다시 조회한다. 명시 로그아웃·다른 계정은 이전 복귀 문맥을 정리한다.
- 음식 기사 초기 인증 복원과 새 로그인·로그아웃, 업무 명령과 늦은 조회 사이의 충돌을 막는다.
- 음식 기사 대기의 운행 시작·신규 배차 수신·위치 확인을 고정 하단의 주 행동으로 표시한다. 없는 배달의 지도 선택·상세는 숨기며, 서버의 기사별 배차 제한과 초기 실효 판정 대기를 구별한다.
- 화물 기사 업무 화면은 재진입 시 정본 상태로 갱신하고, 늦은 응답과 실패한 이전 업무 카드의 실행을 차단한다.
- 화물 기사 업무 라우트는 인증 확인 뒤 생성한다. 만료는 안전한 원래 업무 복귀 경로가 있는 독립 로그인으로 이동하고, 계정의 세션 판본이 바뀌면 기존 업무 화면을 폐기한다. 로그인 제목·상태 중복과 개발 안내로 생긴 가로 넘침도 제거했다.
- 창고 홈은 기능 확인·인증·비활성·오류·업무 표시를 구별한다. 익명·역할 불일치·비활성의 보호 조회와, 로그아웃·계정 변경 뒤 늦은 조회의 업무 진입을 차단한다.
- 화물 기사·화주·창고 APK도 지정 서버 주소를 실제 소비한다. 화주·창고의 HTTP 예외는 정확한 로컬 시험 호스트에 한정한다.

기존 headless 검증 도구에도 운행 시작 뒤 명시적 배차 수신 `On`을 연결했다. 운행 시작을 수신 동의나 실효 배차 가능 상태로 자동 승격하지 않는다. 별도 observer Runner는 수정·실행하지 않았다.

세부 구현과 책임은 [주문자·음식점](../ProjectOverview/page-docs/mobile-workflow-orderer-restaurant-r1.md), [두 기사 앱](../ProjectOverview/page-docs/mobile-workflow-drivers-r1.md), [환경주소](../ProjectOverview/page-docs/mobile-workflow-environment-r1.md)에 연결한다. 서버 정책·상태 전이·원장 스키마를 화면 편의를 위해 바꾸지 않는다.

### 실제 서버·DB 실행

새 격리 DB의 `ssalddel-mobile-readiness` Development/Simulation 환경에서 현재 역할 Client로 주문 접수 → 음식점 인지 → 기사 배정 → 조리 → 픽업 → 전달 → 주문자 수령 확인을 완료했다. 주문 `FOOD-20261004071201176`, `serverRuntimeProof=true`, `databaseRoundTripProof=true`, `driverBeforeCookingVerified=true`다. 모의 정산 실패·재시도·중복 방지와 관리자 조회도 확인했다. 실제 지도 호출·결제·입금이나 Unity 앱 실행을 뜻하지 않는다.

첫 시도는 운행 시작만으로 수신을 켜지 않아 추천 대기가 끝났다. explicit On을 적용한 후 같은 서버에서 전체 흐름이 완료됐다. 후속 UI 주문 준비의 로그인 429는 정상 인증 요청 제한에 해당하며 제한 정책은 완화하지 않았다. 완료된 주문과 기존 대기 주문으로 APK 화면을 확인했다.

사용자에게 위 네 화면을 대화에서 직접 제시하며 다시 대조했다. 창고 캡처의 상단 Android 상태 표시줄과 앱 제목·메뉴가 겹치는 부분은 남은 화면 보완 대상이다. 내부 가로 넘침 0과 별개의 세로 안전 영역 문제이며, 현재 캡처를 정상 정렬 완료의 근거로 해석하지 않는다. 이 후속 확인에서는 화면을 수정하거나 APK를 다시 생성하지 않았다.

첫 다중 앱 관찰 세션은 에뮬레이터 응답 지연으로 재시작했다. 이후 앱별로 다른 앱을 종료하고 재확인했다. 초기 화면 캡처의 stale XML은 최종 근거에서 제외했고, 최종 캡처는 새 파일명·패키지 확인과 실제 DOM 상태로 대조했다. 이는 실제 휴대폰의 메모리·백그라운드·배터리 조건 검증을 대신하지 않는다.

## 설치·실운영 경계

현재 시험 서버는 localhost5361의 격리 Development/Simulation 환경이다. 개인 Debug APK가 서버를 보려면 PC 서버와 USB `adb reverse` 또는 에뮬레이터 연결이 필요하다. 휴대폰 단독 사용을 위한 공개 HTTPS 서버·정식 서명·실제 휴대폰 설치 및 실운영 검증과 구별한다. 지도 인증은 이전 차단 상태를 유지하며 이번 작업으로 정상 타일이나 실제 경로를 검증하지 않는다. 실제 결제·입금도 이번 범위가 아니다.

시험용 에뮬레이터와 이번 Docker 프로젝트는 종료했고 격리 DB 볼륨·원시 근거·APK는 보존했다. 다른 저장소·dirty 작업·서버·기기는 변경하지 않았다. 커밋·푸시는 수행하지 않았다.
