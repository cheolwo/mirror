# 창고 로그인 후 같은 단계·묶음·출고로 복귀

창고의 단계·묶음 주소에서 **로그인**을 누르면 원래 조회 조건이 사라졌고, 반환 주소를 전달해도 역할01 공통 로그인에서 역할05 창고 주소를 거절했다. 실제 Chrome에서 가상 로그인 성공 뒤 로그인 화면에 남는 두 경로를 재현했다. 로그인 뒤 같은 창고·구간·공정·묶음과 기존 출고 검토로 돌아오는 연결을 보완한다.

| --- | --- | --- |
| `dev/mirror-integration` · 기준 HEAD `e67cdbf0bbb086dc9ed547bdcd640074c9a18c86` · 로컬 미커밋 | 통합 웹과 역할05 창고 웹의 기존 출고 검토·단계별 처리 묶음 | 기존 인증·서버 권한·업무 상태를 유지하고 같은 원래 주소로 복귀 |

## 실제 소비 경로와 변경

역할05에는 별도 로그인 페이지가 없다. [역할 웹 구성](../../eng/web-role-app/Ssalddel.RoleWebApp.props)은 기존 로그인 페이지를 역할01에 포함하고 [배포 경로](../../deploy/azure-vm/Caddyfile)는 `/login`을 `/roles/01/login`으로 이동시킨다. 현재 앱에 `login`을 상대 연결하면 된다는 초기 가정은 이 소비·배포 근거로 폐기했다.

[창고 페이지](../../Ssalddel.WebApp/Pages/WarehouseOutboundPlanReviewPage.razor)는 기존 `/login` 목적지에 현재 `PathAndQuery`를 한 번 인코딩한 `returnUrl`을 붙인다. stage·창고·UTC 구간·묶음/구성/출고 페이지·선택 출고와 기존 별칭을 다른 주소로 재구성하지 않는다.

[공통 로그인](../../Ssalddel.WebApp/Pages/LoginPage.razor)은 기존 외부 URL·네트워크 경로·역슬래시·제어문자·인코딩 우회 검사를 먼저 수행한다. 그 뒤 `/roles/01/`에서 같은 scheme·host·port의 `/roles/05/warehouse/general/outbound-plan-review`와 `/roles/05/work/outbound/plans` 두 기존 경로만 추가 반환한다. 다른 역할·다른 창고 업무·유사 접두어나 하위 경로는 이 예외에 포함하지 않는다. 로그인 UI의 제한된 복귀 연결이며 새 로그인 route·서버 권한·업무 정책을 추가한 것이 아니다.

## 실제 실행에서 확인한 시작 실패

첫 실제 WASM 실행은 필수 위치/사진 어댑터 등록 누락으로 페이지 전에 실패했다. [역할 bootstrap](../../eng/web-role-app/Program.cs)에 기존 웹 위치 구현과 미지원 사진 어댑터를, [통합 bootstrap](../../Ssalddel.WebApp/Program.cs)에 미지원 사진 어댑터를 연결했다. 새 구현이나 패키지는 없다. 등록만으로 위치·카메라를 호출하지 않으며 웹 사진 촬영은 기존 미지원 상태다. Development 의존성 검증을 끄지 않고 실제 화면 시작을 다시 확인했다.

생산자 4파일의 허용 7개 변경 블록을 역적용하면 각 원본 전체와 같음을 확인했다. 선행 dirty 변경을 보존했고 인증 서비스·역할 구성·Caddy·인증 계약은 수정하지 않았다. 기존 dirty/untracked 창고 계약을 이번 작업의 변경으로 정리하거나 HEAD로 돌리지 않았다.

## 실행 환경과 한계

실제 Chrome/WASM에 격리 가상 인증·읽기 응답을 연결했다. 운영 인증·서버/DB·실물·휴대폰 검증이 아니며 이 변경의 소비 대상은 웹이다. 모든 외부 요청과 업무 쓰기는 차단하고 가상 로그인 POST만 허용한다. 실제 GPS·카메라·APK 설치·결제·배차·운영 저장·배포·커밋·푸시는 실행하지 않았다.

초기 시험의 동명 인증 서비스 fixture 오류, 가상 토큰의 JWT 사용자 문맥 누락, 미리보기 실행기의 gzip CSS/통합 HTML·JS 전달 오류와 접근성 이름을 잘못 가정한 선택자 오류는 제품 결함과 분리해 보존했다. 제품 자산을 바꾸지 않고 실제 빌드의 비압축 원본·해시를 그대로 브라우저에 전달했다. 실패·보정 전 캡처와 통합 호스트 최초 실패는 보존하며 공개용 정상 화면으로 사용하지 않는다.

미리보기 host의 재시작은 자동 승인 검토에서 차단돼 재시도하지 않았다. 기존 loopback 자산 host를 유지하고 브라우저 내부의 격리 응답 연결로 검증을 이어갔다. 실제 C# 화면 실행을 정적 HTML이나 직접 C# 핸들러 호출로 대체하지 않았다. 각 캡처·응답·판본·소스/PDB·실행 DLL·CSS 해시와 미실행은 `artifacts/local/warehouse-login-return-20261107/validation.json`에 연결한다. 이전 화면과 원본은 [기존 단계 진입 기록](2026-11-07-warehouse-stage-entry.md)에 보존한다.

다음 한 가지는 S3 판매자 목록의 현재 페이지만 0건인 상태와 복구다. 현재 조회 서비스·총건수/페이지 계약과 기존 회귀를 다시 읽고 같은 합성 주문의 목록·상세 복귀에서 재현 여부부터 확인한다.
