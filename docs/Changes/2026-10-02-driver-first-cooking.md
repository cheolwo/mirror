# 음식점의 주문 확인과 조리 시작 분리

- 검증 수준: 코드·시험·Android 앱 build / 실제 기기 화면 미검증.
- 결과: 주문 확인은 배차 요청까지만 수행한다. 서버에서 유효한 기사 배정을 확인한 뒤 별도 조리 시작 버튼을 제공한다. 준비 완료 행동은 실제 조리 시작 이후에 제공하고, 예상 조리 분은 재조회 뒤 복원한다.
- 전표: 배차 전에는 `조리대기`로 표시하며, 실제 조리 시작·준비 완료에 따라 `조리중 / 픽업준비`로 구분한다.
- 전체 검사: Simulation 2,001건 통과, 서버 5,471건 중 5,464건 통과. 이번 수정 범위 밖의 문서·메타데이터·화면 검사 7건이 실패했다.
- 최종 범위 검사: 관련 시험 170건 통과, Android 앱 build 오류 0·경고 0. 실제 기기 화면 검증과 구별한다.
- 기준: [r62 구현](../AI/Planning/시스템/PLAN-SYSTEM-FRANCHISE-OPERATIONS/driver-first-cooking.implementation.r62.md).
- 실제 화면 캡처·휴대폰 설치·commit·push는 수행하지 않았다.
