# 업무 OS 생명주기·절차·상태 정적 조사 r23

사용자 요청에 따라 등록된 10개 운영 OS 전체를 현재 계약·소스·문서와 대조했다. [전체 조사 보고서](../ProjectOverview/page-docs/os-lifecycle-static-audit-r23.md)에 책임 단계, 실제 절차, 독립 상태축, 선행 조건, 인계·회복과 보완 순서를 정리하고 [JSON 원장](../ProjectOverview/page-docs/os-lifecycle-static-audit-r23.json)에 소스·시험 근거를 결속했다.

- 공통 생명주기 대장의 5개 OS·41개 책임 단계 모두를 절차에 연결했다. 나머지 5개 OS는 현재 코드에서 관찰한 절차를 기록했으며 공통 단계 부재를 기능 전체의 미구현으로 판단하지 않는다.
- 조사 범위는 절차 연결 112개·상태묶음 101개다. 공유 소비·조회 투영을 포함한 조사 묶음 수이며 고유 enum 수나 완성률이 아니다. 근거·시험 후보 파일 518개를 SHA-256에 결속했고 모든 후보의 모든 분기를 깊게 조사했다고 주장하지 않는다.
- 우선 보완은 친구 응답의 동의자·인증 actor 결속, 음식 배차 Outbox 재시도에서 진행 상태 보존, 교육 제출 worker에서 학교 최종 결정 보존이다. 조건부 소스 경로를 확인했으며 실제 개인정보 유출·운영 사고를 재현한 결과는 아니다.
- 기존 창고 put-away/pack 진입점의 상태·수량 관문, 화주 일부 비가격 조건 변경의 판본·재동의, 일부 저장 후 후속 처리 복구를 다음으로 둔다. 기존 권한 검사를 없는 것으로 설명하지 않는다.
- 마트→음식 기사 실행·전달 결과 반환, 창고 수량 이상 회복 등은 명시한 조사 경로에서 연결 확인이 남은 항목이다. 결제·환불 관련 연결 확인 항목을 플랫폼 결제나 수수료의 새 필수 요건으로 승격하지 않는다.

제품 API·DB·상태 전이·역할 권한·UI·요금·정산·Unity·배달 영상을 변경하지 않았다. [정적 조사 도구](../../eng/Ssalddel.OperatingSystemAudit/README.md)는 공통 계약과 API 메타데이터를 컴파일해 대장·조사 범위·파일 해시·소스 anchor·줄을 검사하며 서버/DB/외부 서비스는 시작하지 않는다.

## 검증

현재 소스 빌드 후 관련 기존 시험 **1,582/1,582** 통과, 실패·건너뜀 0이다. 카탈로그·공통 인계 38개, 음식 생명주기·Guard·정산/표시 415개, 나머지 OS 절차·동의·복구 1,129개를 실행했다. 시험 후보와 실제 실행한 클래스를 JSON에서 구분했다. 기존 시험 통과가 이번에 확인한 모든 실패·동시성·재시도 경로를 닫는다는 뜻은 아니다.

새 정적 도구의 4,631개 검사 중 **4,628개 통과, 3개 불일치 탐지**다. 화면의 역할이 workflow 참여자 대장에 없는 `CustomsAndTradeData/ShipperOrSeller`, `FoodDelivery/PlatformOperator`, `SsalddelMart/Orderer`가 대상이다. 현재 종료 코드 1은 이 대장 불일치이며 빌드 오류·단위시험 실패가 아니다. OS 누락/미지원 ID/중복 단계/빈 절차/오래된 해시/없는 anchor/잘못된 줄, JSON·schema·CLI 오류와 출력 충돌 등 **오류 입력 21개**도 각각 탐지했다. 충돌 검사에는 격리 입력·근거 사본을 사용했고 입력 바이트 보존을 확인했다. 감사 입력을 생략한 카탈로그 검사도 같은 대장 불일치 3개만 기록했다.
