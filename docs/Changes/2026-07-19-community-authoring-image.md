# 커뮤니티 글쓰기 이미지 생성

## 변경 기록

| 변경 축 | 화면 변경 여부 | 시각 증거 |
| --- | --- | --- |
| 관리자 글쓰기 `이미지` 도구 | 화면 변경 | 글 전체를 최대 5개 문맥으로 나누고 각 프롬프트·비율·생성 상태·첨부 선택을 독립 관리하도록 공통 Razor 도구 확장, 브라우저 연결 제한으로 PNG 미확보 |
| Kie.ai GPT Image Market API Adapter | 간접 확인 | 생성 요청·통합 작업 조회 계약 테스트 |
| 공통 이미지 작업·GCS 후처리 재사용 | 간접 확인 | server build와 기존 영속·후처리 호출 경계 검토 |
| 글 저장 뒤 선택 이미지 첨부 | 간접 확인 | 여러 생성 요청과 문맥 순서 첨부를 검증한 페이지 ViewModel 통합 테스트 |

## 동작 범위

- 글 제목, 소제목과 문단을 최대 5개 연속 문맥으로 나누고 각 문맥의 편집용 이미지 프롬프트를 준비한다. 이 단계는 외부 API를 호출하지 않는다.
- 문맥별 프롬프트에는 글 제목·원문 맥락·업무별 시각적 초점·시리즈 일관성과 글자·로고·공식 증빙 오인 방지 제약을 포함한다.
- 운영자가 선택한 문맥마다 `생성`을 눌렀을 때 Kie.ai `gpt-image-2-text-to-image` 작업을 한 건씩 등록한다.
- 문맥마다 대기·생성 중·실패·완료 상태를 표시하고, 완료 결과는 GCS에 보관한 URL로 미리 본다.
- 운영자가 `게시글 이미지로 선택`한 결과만 글 저장 성공 뒤 문맥 순서대로 기존 게시글 첨부 UseCase에 전달한다.
- 이미지 첨부 실패는 게시글 저장 성공을 되돌리지 않고 재시도 필요 메시지로 남긴다.

## 운영 경계

- API key는 tracked 파일에 저장하지 않는다.
- 문맥 계획과 프롬프트 수정에는 외부 비용이 발생하지 않으며, 선택 문맥별 생성 명령에만 비용이 발생할 수 있다.
- 생성 결과는 실제 상품·현장·통계·공식 문서 증빙으로 취급하지 않는다.
- 이미지 생성은 다이어그램, 가원장, 주문, 계약, 결제, 배차, 통관, 알림 또는 이메일을 실행하지 않는다.

## 구조 정리

- 392줄 planner를 입력 조율, 문맥 분할, 외부 프롬프트 조립 파일로 분리했다.
- 695줄 이미지 ViewModel을 계획 상태, 생성·조회·첨부 작업, 문맥 항목 상태로 분리했다.
- 계획 이미지 수와 제목·본문·프롬프트 길이 제한을 공통 계약 상수로 모아 서버와 UI의 값 불일치를 막았다.
- 긴 원문은 내부 문맥에 보존하고 외부 프롬프트에서만 생략 위치를 명시해 길이를 조정한다.
