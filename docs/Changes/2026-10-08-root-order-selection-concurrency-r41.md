# 원주문 선택과 동시 변경 보호 r41

[승인 r35](../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/root-order-selection-concurrency.implementation.r35.md)에 따라 r40에서 남은 원주문 선택 양식과 관계 편집/하위원장 진행의 동시 변경 보호를 구현했다. 원주문을 화면 목록에서 고르면 현재 권한·조건·판본을 서버가 재검사한다. 하위 업무가 진행됐으면 연결 분리·역할 변경·필수 해제를 저장 단계에서 차단한다.

## 변경과 책임

- [기존 분산 주문 작성 화면](../ProjectOverview/page-docs/distributed-fulfillment-r36.md)의 선택 항목 → `분산이행PageViewModel`/`분산이행Client` → 인증된 `GET api/v1/distributed-fulfillment/waves/{waveId}/order-ledger-candidates`와 기존 주문 저장 API → 기존 화물·보호된 원주문 조회·연결 Adapter를 사용한다. 내부 ID를 직접 입력하지 않고 표시명·상태로 선택한다. 기본은 미연결이며 기존 작성 요청과 재처리 계약을 유지한다.
- 후보는 실제 본인 화물과 판매자·수령인·현재 계정의 열린 주문 중 허용된 것만 제공한다. 후보 응답은 표시명·상태·검증용 ID/판본으로 제한한다. 계정·화물·묶음 변경과 조회 실패는 오래된 목록·선택을 무효화하고, 원주문 조회 실패 시 작성 물품은 보존한다. 늦은 성공/실패 응답은 새 선택을 덮어쓰지 않는다. 401은 재로그인 안내로 이어진다.
- `Mongo커뮤니티원장저장소`의 일반 저장·상태 명령과 관계 편집이 같은 내부 저장 판본을 검사한다. 기존 주문 루트의 삭제성 관계 변경은 Snapshot/Majority 트랜잭션에서 원주문·변경 대상 하위원장을 다시 읽고 하위원장 내부 fence를 실제 쓰기로 변경한 뒤 루트를 조건부 저장한다. 서로 다른 서버/클라이언트의 하위 상태 진행과 관계 편집도 충돌하며 부분 적용은 롤백한다.
- 진행 뒤 초안으로 정정했더라도 보존된 진행 이력으로 연결 삭제를 막는다. 자식 ID 대소문자만 바꿔 기존 진행 연결을 없애는 우회도 정확 ID 대응으로 막는다. 새 연결·표시 순서 변경·필수 조건 강화와 다른 종류의 묶음 원장은 기존 허용 의미를 유지한다.
- 저장용 `관계편집Revision`은 기존 Mongo 문서의 내부 필드이며 없는 문서는 0으로 다룬다. 공개 DTO·업무 revision·상태 이력·Event·투영의 업무 의미는 바꾸지 않는다. 개인정보 파기의 별도 문서 교체도 같은 조건부 저장을 사용해 보호 표식을 복원하지 못하게 한다. 새 SQL 테이블·migration·하위 상태 복제는 추가하지 않는다.

소유 경로·검증 로그·지문·화면·격리 환경 정보는 Git 제외 `artifacts/local/order-root-followups-r41/`에 보관한다. 소유 27경로 중 컴파일 대상 19소스의 SHA-256은 최종 Fast·Task 직전/검증 이후 동일했다. 초기 ASCII 목록과 최종 검증 전 보충한 비ASCII 목록 중 비소유 27,720파일의 지문도 동일하며 추가·삭제된 비소유 경로는 없었다. 내부 링크 839개는 모두 대상이 존재한다. `source-validation-before.json`/`source-validation-after.json`, `verification.json`, `doc-links.json`에 실제 비교 결과를 남겼다. 이전 r40의 남은 두 항목에는 이번 완료 기록을 연결하며 당시 시험 결과는 보존한다.

## 확인 범위

트랜잭션을 지원하는 Mongo replica set 또는 sharded 환경이 안전한 관계 분리·역할 변경·필수 해제의 전제다. standalone 등 미지원 환경에서는 `OrderLedgerRelationTransactionRequired`로 해당 변경을 거부하며 비파괴 저장은 유지한다. commit 적용 여부가 불명확하면 `OrderLedgerRelationCommitUnknown`으로 최신 원장을 다시 조회하게 하며 성공으로 단정하지 않는다. SQL 예약과 Mongo 연결 사이의 DB 간 전체 원자성을 주장하지 않는다.

원주문 연결 여부, 독립 배송 상태·기사 전달·고객 수령·정산·실지급은 별개다. 기존 OFF/Simulation 경계를 유지하며 공용 DB·실제 업무 HTTP·휴대폰·APK·Azure·실제 거래/금전·Unity·영상·운영 활성화·commit/push는 이번에 진행하지 않았다.
