# 화물 조건 비교 카드 r1

2026-10-24. 화주·기사·화물 관리자가 의뢰의 운송 방식, 차량, 중량·수량과 상하차 시간을 목록과 현재 카드에서 바로 비교하도록 보완했다. [페이지 책임과 표시 기준](../ProjectOverview/page-docs/cargo-condition-comparison-r1.md)을 따른다.

첫 로컬 판본은 **구현·집중 시험·소비 빌드·로컬 합성 화면 확인 완료, 운영 비활성**이다. 이후 사용자의 요청으로 아래 226 APK 실제 단말 확인을 추가했다. 브라우저·단말의 합성 자료 확인과 제품 HTTP·DB 여정을 구분한다. 로컬 집계 근거는 `artifacts/local/cargo-conditions-r1/20261024-r1/validation-final.json`, 단말 후속은 별도 기록을 따른다. commit·push·배포·운영 설정 변경은 실행하지 않았다.

| 기록 | 내용 |
| --- | --- |
| 커밋 | 미생성. 기존 다른 dirty 변경을 보존한 로컬 작업 |
| 변경 축 | 기존 원장 조건의 응답 투영, 세 역할의 조건 비교 표시, 수락 직전 재확인 |
| 화면 변경 | 있음. 목록 행·선택 카드·수락 전 화면과 전문 기사 추천 카드·설정 미리보기 |
| 시각 근거 | 로컬 합성 브라우저의 실제 Razor 렌더와 아래 대표 PNG |

## 바뀐 결과

기존 추천의 `서버 추천` 문구와 차량의 `조건 확인·적합` 표시는 실제 운송 방식이나 요청 차량을 설명하지 못했다. 원장에 있는 다음 8개 값을 인증된 공개 배차 콜·추천·의뢰 상세·진행 운송·관리자 운송 조회에 전달하고 같은 표시 도구로 읽는다.

`운송방식`, `차량종류`, `화물중량Kg`, `화물수량`, `상차시간창시작일시`, `상차시간창종료일시`, `하차시간창시작일시`, `하차시간창종료일시`.

| 정보 | 표시와 경계 |
| --- | --- |
| 운송 방식 | 혼적은 혼적, 원문 `단독`은 화면에서 `독차`로 표시한다. 원장·전송 값을 바꾸지 않는다. |
| 차량·화물 | 요청 차량 종류와 중량·수량을 각각 표시한다. 차량 적합 판정이나 기사 보수를 요청 조건으로 대신 쓰지 않는다. |
| 상하차 시간 | 기존 UTC 계약을 한국 시각으로 표시한다. 같은 날은 날짜를 한 번, 날짜를 넘으면 양쪽 날짜를 표시한다. |
| 미확인 값 | 누락 조건은 `미확인`이다. 한쪽 시간만 있으면 그 시각과 `시작 미확인` 또는 `종료 미확인`을 함께 표시한다. 없는 시간을 협의·당일·현재 시각으로 채우지 않는다. |
| 기본 노출 | 목록 행·현재 선택 카드·수락 전 화면에 조건을 표시한다. 전문 기사 앱의 간단·표준 카드에서도 조건을 숨기지 않는다. |

화주 `/workspace/shipper`, 기사 `/workspace/cargo-driver`, 관리자 `/workspace/operator?business=freight-delivery`의 기존 업무 문맥을 유지한다. 전문 기사 앱의 추천 상세·대화상자·별도 배차 처리 화면에도 같은 조건을 표시하며, Native 추천 카드는 실제 본문 폭과 높이를 측정하고 작은 화면에서는 기존 본문 스크롤을 유지한다. 설정 미리보기는 실제 의뢰 주소 대신 명시적인 예시 조건으로 같은 컴포넌트를 사용한다.

익명 공개 화물 요약 API·계약과 상세 정보 제공 범위는 확장하지 않았다. [로그인 전 공개 탐색](2026-10-24-cargo-restart-guest-r1.md)의 경계, 역할 권한·현재 운송 상태·보수·사진·미확정 요청 보호와 운영 기본 비활성을 유지한다.

## 수락 전 재확인

공통 수락 화면은 추천과 의뢰 상세의 8개 조건이 서로 다르면 확인과 수락을 막는다. 확인 후 재조회에서 어느 한쪽의 조건이 바뀌어도 두 확인을 해제하고 수락 POST를 보내지 않는다. 둘 다 누락된 구버전 응답은 같은 미확인 상태이며, 한쪽에만 값이 있으면 일치로 추정하지 않는다.

Native 추천은 실제 카드 문구에 적용한 불변 조건을 보관한다. 탭한 카드와 현재 선택 조건, 수락 직전 재조회 조건을 각각 비교하고 달라지면 다시 검토하도록 안내한다. 기존 인증·차수·경고·미확정 수락 보호는 유지한다. 이는 화면과 재조회 사이의 보호이며, 새 서버 조건 판본 토큰을 도입하거나 최종 POST까지 원자적으로 결속한 변경은 아니다.

## 후속 226 APK · 실제 휴대폰

사용자는 화면 보완 결과를 휴대폰 APK로 보여 달라고 요청했다. `0.1.226 / versionCode 226`의 통합 화주 앱과 전문 기사 앱을 기존 서명으로 패키징하고, 실제 Galaxy A34 `SM-A346N / Android 16`에 데이터 보존 갱신 설치했다. 두 설치본의 APK SHA가 최종 handoff와 일치하고 선택 소스46개 및 패키징 전후 소스 판본이 유지됐다. 삭제 설치나 앱 데이터 초기화는 하지 않았다.

통합 앱에서 화주·운영자, 전문 앱에서 기사 추천 목록과 Native 추천을 실제로 열었다. 화주·운영자의 혼적·차량·중량·수량·한국시간 상하차와 화주의 독차·자정 경계를 확인했다. Native 첫 혼적 카드에서는 8개 조건과 수락/거절 버튼이 함께 보이며, 미확인 카드도 실제 표시됐다. 수락·거절을 실행한 검증은 아니다.

**남은 결함을 별도로 보존한다.** 기존 전문 기사 앱의 하단 메뉴와 시스템 막대 겹침 때문에 본문 진입을 사용했다. Native에서 두 번째 카드로 넘길 때 카드가 화면 중간에 걸리는 정렬, 복귀 과정의 헤더 번호/카드 불일치와 버튼 비활성도 관측했다. [정렬 문제 캡처](../assets/changes/2026-10-24-cargo-conditions-device/driver-carousel-issue.png)는 정상 완료 화면으로 분류하지 않는다. 이번 단말 확인에서 제품 코드를 추가 수정하거나 이 문제를 해결했다고 표시하지 않는다.

단말은 별도 루프백 읽기용 합성 HTTP 자료를 사용했다. 운영자도 별도 임시 합성 세션으로 조회했다. 시험 응답의 실제 wire 상태 `Eligible` 보정과 제품 변경을 구분하며 이전 fixture를 보존했다. 지도 배경 타일은 보이지만 시험 추천의 좌표가 없어 위치 미확인 안내가 표시된다. 실제 GPS·운송 경로·핀, 제품 DB 완주·실금융·외부 푸시 성공으로 합치지 않는다. 전체 시험과 111사례를 이 단말 확인에서 다시 실행하지 않았다.

직접 판독한 단말 PNG는 11개다. 수락·거절·수신 의사·운행 시작/정지·신고·인수증·의뢰 생성 요청은 0개다. 자동 푸시 등록·SignalR 연결·추천 표시 영수증의 시험 서버 409는 제품의 실제 기능 성공/실패로 판정하지 않는다. 보호 저장 전체 바이트 비교와 초안·미확정 요청의 재실행 왕복 재검증은 이번 범위에 포함하지 않았다.

새 임시 운영자 세션만 종료하고 원래 비로그인을 실제 화면으로 확인했다. 기존 화주·기사 주계정과 수신 의사를 유지하고 USB 연결을 원래 `5363→5363`으로 복구했으며, 기존 시험 서버를 유지하고 이번 5683 helper만 종료했다. 패키징, 설치, 화면, 요청, 정리의 최종 범위는 `artifacts/local/cargo-conditions-device/20261024-r1/validation-device-final.json`을 따른다. 이전 로컬 검증 JSON의 `physicalPhoneVerified=false`와 빌드 당시 미설치 flag는 당시 사실로 보존한다.
