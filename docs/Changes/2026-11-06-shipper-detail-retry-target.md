# 화주 의뢰 상세에서 다시 조회할 번호 표시

선택한 운송 의뢰의 첫 조회에 일시적인 연결·서버 오류가 나면, 기존 화면은 편집 가능한 번호와 별도 조회 버튼을 표시했다. 상단 **새로고침**과 오류 안내의 **운송 의뢰 확인**은 주소로 진입한 원래 번호를 다시 조회하므로, 입력란을 바꾸면 화면에 보이는 값과 재조회 대상이 달라질 수 있었다.

[공통 상세 화면](../../Ssalddel.Ui.Common/Areas/App/Components/Transport/ShipperRequestDetailScreenFrame.razor)은 기존 분류가 기술 실패이고 이미 선택한 의뢰와 재조회 동작이 있을 때만 **조회 미완료** 아래에 그 의뢰 번호를 읽기 전용으로 보여 준다. 기존 새로고침으로 같은 의뢰를 조회한다는 안내를 붙였다. 의뢰를 찾지 못했거나 번호 없이 진입하면 번호 직접 입력을 유지한다. 로그인, 조회 중, 기능 중지, 이미 읽은 상세와 나머지 상세 탭에는 이 안내를 표시하지 않는다. 기존 읽기 계약과 복귀 주소를 사용한다. [320px 실패 화면](../assets/changes/2026-11-06-shipper-detail-retry-target/selected-error-320.png)

320px·390px의 실제 공통 컴포넌트를 합성 응답으로 비교했다. 수정 전 8개 표시 불일치를 재현했고, 수정 후 62개 검사에 통과했다. 같은 의뢰 번호로 한 번 새로고침해 상세를 표시하고, 상단과 오류 안내 창의 복귀에서 모두 원래 목록 2페이지로 돌아갔다. 404의 다른 번호 조회, 번호 미입력, 로그인, 조회 중 버튼 잠금과 긴 번호 줄바꿈도 확인했다. 404에서 번호를 바꿀 때 기존 안내 창이 한 번 다시 열리는 동작은 이번 수정 범위에 포함하지 않았다. 브라우저 오류, 페이지 전체 가로 넘침, 외부·업무 API 요청은 없었다.

관련 시험 157건과 전체 시험 17,034건이 통과했다. 환경 조건이 필요한 17건은 생략했다. 화주 앱을 포함한 통합 빌드 오류 0개(Fast 경고 2개, Task 경고 149개)였다. 실기기·제품 서버·DB는 실행하지 않았다. 화면과 검증 판본은 artifacts/local/mirror-ui-assist/20261106T090121257Z-shipper-detail-retry-target/completion.json에 연결했다.

다음 회차에는 화물기사의 진행 중 운송 화면에서 정상적으로 진행할 운송이 없는 경우와 조회에 실패한 경우의 다음 행동을 대조한다.
