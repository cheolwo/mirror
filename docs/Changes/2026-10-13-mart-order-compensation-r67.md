# 주문별 원가·보수와 마트 완료 근거 연결 r67

주문 원장을 기준으로 본인이 수행한 작업과 보수, 주문에 나누어 반영한 입고·보관 원가를 조회한다. 살뜰마트의 신규 피킹·포장 완료는 실제 처리자·수량·시각을 고정해 기존 정산의 근거로 연결한다. 새 앱 화면이나 실제 지급을 추가하는 작업은 아니다.

## 주문별 읽기

기존 정산 API에 `GET /api/v1/neighborhood-settlements/orders/{rootOrderLedgerId}`를 추가했다. 원주문에 현재 포함된 정확한 음식·마트·물품 출고·운송 참조만 조합하며, 루트에 금액이나 하위 상태를 복제하지 않는다. 루트 및 자녀 판본과 공개 승인 상태를 응답 전에 다시 확인한다.

본인 작업과 본인이 지급하거나 받을 정산만 기존 권한으로 조회한다. 작업자에게 최소 조회를 허용하더라도 전체 재고나 동료 보수를 보여주지 않는다. 주문 원가 귀속은 정확히 연결된 비용 부담자에게만 제공한다.

상품 대금·보수·배송비에 포함된 참고액·내부 이동·통과자금을 분류한다. 입고 작업자에게 이미 발생한 보수와 판매 주문별 원가 배부는 별개다. 지급 신고·수령 진술은 은행 입금 확인이 아니며, 충분한 수익·비용 근거가 없으면 플랫폼 손익은 미확인으로 둔다.

## 피킹·포장 완료와 보수

기존 작업에 보호 대상인 `완료근거Json`을 추가했다. 실제 완료 처리와 같은 저장에서 작업·주문·출고·재고·실제 완료자·수량·시각을 고정한다. 완료 근거는 후속 작업 투영이나 담당자 변경으로 다시 쓰지 않는다. 포장 일괄 완료는 각 작업의 수량과 배치 이력을 대조한다.

보수는 작업 전 양측이 동의한 약정 판본과 확인 처리량으로 기존 명시적 발생 명령에서 계산한다. 단가 미정은 null로 유지한다. 같은 실제 작업을 반복하거나 다른 약정·수령자로 바꾸어 중복 청구할 수 없게 한다.

현재 포장에는 실제 시작 명령이 없으므로 같은 출고의 첫 피킹 시작을 보수적인 사전 합의 기한으로 사용한다. 실제 포장 시작시각으로 표시하지 않는다. 근거 없는 과거 완료, 실제 완료자와 배정자 불일치, 선행 시작 없는 포장은 자동 청구를 보류한다. 큰 배치 때문에 근거를 안전하게 남길 수 없는 경우도 업무 완료와 보수 보류를 구분한다.

기존 포장 표시·실패 후 재처리에 필요한 시작시각 기본값은 유지한다. 완료시각으로 채워진 기존 표시값을 실제 시작 증빙으로 복사하지 않고, 새 포장 완료 근거의 실제 시작시각은 null로 보존한다.

## 검증

Fast 집중 시험 250개가 통과했다. 조회 전용 class 19개도 별도 실행에서 통과했다. 한 재고의 두 주문 사용, 서로 다른 피킹/포장 담당자, 실제 완료자 불일치 보류, 사전 동의·미정 단가·소급 합의·반복 청구, 정액/건당 수량 구분, 기존 배송 참고 금액, 지급 환불 부호, 권한 철회·원장 판본 변경, 완료 후 투영 보존, 상태 충돌 409, 보호 저장과 격리 SQLite migration을 확인했다. 기존 포장 후속 실패·재요청 통합시험도 포함했다.

초기 실행에서 발견한 .NET 10 배열 `Contains`의 EF 실행 오류는 명시적인 목록 조회로 수정했고, 시험 자료의 약정 판본·재고 관계도 실제 외래키에 맞췄다. 전체 시험에서 발견한 기존 포장 시작시각 표시·복구 계약 누락도 보완했다. 실패 기록을 보존하고 수정 후 Fast를 재실행했다. 최종 Fast 근거는 `artifacts/local/validation/20261013-113030/`다.

Task 전체 시험은 11,202개 통과·실패 0개이며 환경 의존 MongoDB 15개는 건너뛰었다. `Ssalddel.v3.5.slnx` 앱 소비 프로젝트 빌드는 오류 0개·기존 경고 61개다. 최종 Task 근거는 `artifacts/local/validation/20261013-113347/`다.

문서의 로컬 링크 8개가 유효하며 범위 밖의 기존 변경 파일 154개는 모두 기준선과 해시가 같다. stage·commit·push는 하지 않았다. 소스 24개 해시·검증 결과·기존 변경 보존 기록은 `artifacts/local/mart-order-compensation-20261013/`에 보관한다. 실제 Mongo/HTTP/단말·입금·공유 DB 운영을 인증하지 않는다.

## 경계와 후속

정산 기본 OFF·Simulation 전용 경계를 유지한다. 스키마 변경 파일은 준비하지만 공유 DB에는 적용하지 않는다. 마트 고객 수령의 전문 근거가 없어 이 원천의 지급 해제는 후속으로 보류한다. 이번에는 작업 완료→보수 근거→본인 조회까지 연결한다.

단가, 교육 보수·기본 보장·추가 성과금, 지급 해제, 화면·APK·단말·실제 송금은 별도다. Azure/GCS·Unity·커밋·푸시는 수행하지 않는다.
