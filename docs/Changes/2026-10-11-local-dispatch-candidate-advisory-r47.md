# 배달권·기사 후보 근거를 연결하는 로컬 배차 AI r47

사용자가 기존 배달권과 인접 배달권 안의 주문·기사를 고려한 기획을 Ollama가 참고하도록 리팩토링을 요청했다. [승인 설계](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/candidate-advisory.implementation.r47.md)와 [현재 스레드 작업 명세](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/candidate-advisory.r47.work-order.json)를 따른다. 화면 변경 없음.

## 변경 범위

- 기존 음식 후보 정책을 재사용해 같은 권역·인접권·제한 확장의 실제 탐색, 후보 관문·정렬과 선정 근거를 읽기 전용 검토 결과로 분리한다. 기존 `다음후보선정Async`의 동작을 보존한다.
- 별도 합성 도구가 실제 정책을 시험용 저장소·경로 응답에서 실행한다. 모델 입력은 허용 후보·제약·현재 코드/사용자 방향/시험 가정/후속 제안을 구분하고 소스·입력 해시와 연결한다.
- Ollama는 제한된 후보·근거 코드만 검토하고 운영 경로가 읽지 않는 로컬 기록에 남긴다. 무효 응답에는 현재 정책 결과를 유지한다. r47 누적 모델 시도 상한은 4회이며 기존 r46 36회 기록과 별개다.

## 실제 모델의 한계와 재검증

실제 실행의 인접권 사례는 사실과 맞지 않는 근거로 `reason_conflicts_with_facts`, 픽업 적시성과 동급 장기 대기 사례는 선택/결정 불일치로 각각 `decision_selection_mismatch`가 되어 기존 정책 결과를 유지했다. 여력 부족 사례만 최초 검사를 통과했다. 개별 CPU 응답은 44.781·51.171·49.406·49.344초였다. 이 소수 표본을 전체 판단 정확도나 실시간 배차 성능으로 일반화하지 않는다.

이후 독립 검토에서 근거 코드와 관련 출처의 대응도 확인해야 함을 발견해 검사를 보강했다. 기존 원응답을 바꾸지 않고 최종 검사로 다시 대조했으며 여력 부족 사례도 `reason_source_required`로 복귀했다. 최종 유효 AI 응답은 0개이고 4개 모두 기존 정책 결과를 유지한다. 최초 1개 통과·3개 복귀 결과를 덮어써 과거 기록을 바꾸지 않는다.

원본 실행 폴더의 `results.json`·요청·원응답·검토표와 별도로 `artifacts/local/local-dispatch-ai/candidate-advisory-r47/post-call-revalidation.json`에 원본/최종 상태와 원본 결과·현재 검사 도구의 SHA-256을 연결했다. 재검증의 새 모델 호출은 0회이며 r47 누적 시작 시도 4회를 모두 사용했다. 모든 응답은 사람 검토 대기, 승인·학습 후보·학습 쓰기·운영 쓰기 0건이다. 실행을 반복하거나 예산 기록을 삭제해 추가 호출하지 않는다.

현재 판정과 최초 기록의 차이는 [최종 검토표](../../artifacts/local/local-dispatch-ai/candidate-advisory-r47/최종검토표.md)에서 확인한다. 실행 당시 표의 최초 통과를 현재 유효 응답으로 읽지 않도록 최종 0개 통과·4개 복귀를 따로 표시했다. 이 자료는 비공개 로컬 근거이며 저장소 게시 자산이 아니다.

최초 준비 검사에서 r47 규칙 앵커의 null-forgiving `!` 표기 차이를 만료로 검출했고 새 r47 규칙만 실제 소스에 맞췄다. Python 시험의 초기 합성 fixture 2개 불일치도 수정 후 97개 전체가 통과했으며 실패 로그를 보존했다. 이전 r46의 규칙·기록은 수정하지 않았다.

## 로컬에서 다시 확인하기

`eng/local-dispatch-ai/candidate_advisor.py`를 기본 옵션으로 실행하면 현재 소스·규칙·근거 해시와 합성 10개 사례를 확인하고 새 준비 기록·검토표를 만든다. 기본값은 모델 호출 0회다. 소스·규칙이 달라지면 현재 자료로 다시 연결해야 하며 기존 입력을 조용히 갱신해 통과시키지 않는다. r47 실제 모델 예산은 소진됐으므로 추가 추론은 별도 후속 범위에서 다룬다.

## 이력과 경계

기존 r46의 실행·원응답·보고서와 36회 예산은 보존한다. 후보 정책 소스의 동작 보존 변경으로 r46의 과거 소스 해시가 현재 소스와 달라지면 현재 검사에서 `stale`이 되는 것이 정상이다. 과거 해시를 덮어써 다시 통과시키지 않는다.

사용자 확인 방향과 구현된 정책은 구별한다. 약 4건/h는 사용자 계획 가정이며 현재 contract 기본 3.5건/h를 바꾸지 않는다. 조건이 비슷할 때 장기 대기자 우선 방향은 임계값·픽업 지연 절충안의 승인과 다르다. 시간대 전환 가점과 마지막 전달지 기반 다음 픽업은 후속 제안으로 유지한다.

실제 배차·DB·요금·지급·외부 알림·화물/생활 배송·새 UI·Unity·APK·단말·Azure·배포·가중치 학습·commit/push는 이 작업의 완료로 보고하지 않는다. 합성 후보의 구조 검사와 실제 운영 적합성은 별도다.
