# 화주 운송 목록의 요약·상세 연결 보완

2026-11-05. 사용자에게 제안한 첫 적용 범위인 운송 목록을 보완했다. 다른 화면 분리 제안은 이번 묶음에 구현하지 않았다.

## 바뀐 화면 책임

[운송 목록](../../SsalddelApp/Components/Pages/TransportWorkspace.razor)은 내 의뢰를 고르고 현재 상태·결제 예정·다음 확인을 읽는 역할로 정리했다. 제목은 화물 종류, 적재 형태와 전체 의뢰 ID는 보조 정보다. 반복된 주소·결제 수단·등록 시각은 기존 상세로 인계한다. 주소를 포함하던 관련 대상 문자열도 목록에서 제거했다.

‘상세 보기’·‘진행 이력’·기존 `CanPay` 조건의 ‘결제 확인’은 같은 ID의 기존 경로에 연결한다. 실제 목적지가 요약이던 ‘타임라인’ 문구와 플랫폼 안내창만 열던 결제 버튼을 정리했다. 기존 `ShipperRequestDetailNavigationContext`로 목록 복귀 경로를 전달하고 공백 ID의 링크를 막는다. 결제 확인은 화면 이동이며 결제·시험 결제·업무 명령을 실행하지 않는다.

정책 플래그 또는 실제 경고 목록이 있으면 접기 밖에 경고를 표시한다. 기본false/빈값만으로 ‘정책정상’을 표시하지 않는다. 상세에 없는 적재 형태·알선 단계/재알선 금지와 기존 두 운임 항목은 목록에 보존한다. 알선·운임의 보조 정보만 한 펼침으로 모았다. 결제 예정액 null은 ‘미확인’, 실제0은0원이며 금액 계산은 바꾸지 않았다.

## 보존한 경계와 검증

조회 직렬화·최신 요청/로그인 세션/이탈 보호·첫 실패/빈 결과 구분·재조회 실패 뒤 기존 목록은 유지한다. 서버 DTO·정책·금액 mapper와 공용 상세 projection은 수정하지 않았다. 현재 mapper의 정책 필드 연결 부족까지 이 UI 작업으로 해결한 것으로 표시하지 않는다.

기준선은 `artifacts/local/shipper-transport-summary/91f53342764941bab64be0e7777e5360/TransportWorkspace.before.razor`와 동일 바이트의 동결 원본이다. 실제 원본 Razor/기존 계약·수명 코드를 사용한 합성 회귀에서 변경 전후의 정보 배치·이동과 기존 상태 보호를 대조한다. 브라우저 CSS/좁은 폭의 시각 검수·새 APK 설치·휴대폰 확인은 별도로 기록한다.

새 검토용 APK를 포장하거나 설치하지 않았다. 등록 기기의 기존146·원앱230/공유 잠금·같은 paused 수집 checkpoint는 읽기로 확인했으나 다른 전면 작업을 보존해 앱 전환·입력은 없었다. 이전에 거절된 정적 미리보기/브라우저 경로도 재시도하지 않았다. 기존 합성 이미지와 제안 시안을 새 실행 화면으로 표시하지 않는다.

현재 소스/컴파일·회귀·Fast/Task·같은 격리 서버 조회와 보존 근거는 위 실행 폴더의 `completion.json`에서 연결한다. 테스트·실제 HTML 의미/상태·소비 빌드·브라우저/기기·운영 완료를 구분하며 전체 화면 보완이나 앱 전체 안정화를 완료했다고 주장하지 않는다.
