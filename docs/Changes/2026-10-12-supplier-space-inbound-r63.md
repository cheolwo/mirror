# 공급자·공간 제공자 입고 협의 r63

상태: `Implemented / LocalValidated / OperationalDeferred`.

농가·공장·제조업체 등이 물품을 공급하고 생활 공간에 맡길 때, 공간 제공자가 받을 품목과 조건을 정하고 당사자끼리 입고 조건을 협의할 수 있게 했다. 기존 공간·보관 합의·입고 행·사진 검수·정산을 확장했으며 새 물류 앱이나 Unity 구현을 추가하지 않았다. [승인 설계](../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/supplier-space-inbound.implementation.r63.md)·[작업 명세](../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/supplier-space-inbound.r63.work-order.json)·[페이지→코드→DB 책임](../ProjectOverview/page-docs/distributed-inbound-collaboration-r63.md).

## 실제 사용 흐름

1. 공간 소유자가 농산물 거부·공산품 허용 등 상품 분류와 식품/가공/포장/온도 조건, 공간 전체 용량과 출입 조건을 설정한다. 거부 조건을 우선하고 모르는 상품 특성·단위·기존 점유량은 0으로 가정하지 않는다.
2. 공급자가 기존 입고 원천으로 초안을 만들고 행별 수량·상품 사실·도착 시간창·보관 종료·공급대금 또는 무상 조건·책임·반환 조건을 제안한다. 실제 물품 소유자와 판매자가 다를 수 있으며 공급 담당 선택은 이 확인된 관계 안에서 한다.
3. 물품 소유자와 공간 소유자가 같은 제안 판본에 동의하면 공간 예약을 확정한다. 협의 메모나 위탁 판매자의 제안을 소유자 동의로 바꾸지 않는다. 한쪽 동의 뒤 정책이 바뀌면 이전 동의를 그대로 사용하지 못한다.
4. 현장 담당자가 유효 예약·보관 계약·시간창·전체 공간 용량을 다시 확인한 뒤 바코드와 사진으로 받은 수량을 확정한다. 3상자 예약 후 2상자를 받으면 재고와 입고 작업 근거는 2상자뿐이다.
5. 실제 입고 작업을 기존 입고·보관 정산에 연결한다. 출고·배송 정산과 실제 송금은 별개다. 입고 승인이나 예약만으로 보수를 발생시키거나 지급하지 않는다.

## 변경·예외 처리

현재 유효한 보관 합의는 변경 제안만으로 사라지지 않는다. 변경안을 따로 저장하고 같은 변경 판본의 양측 동의 뒤 적용한다. 이미 받은 물품의 당시 조건과 정산 근거는 보존한다. 부분 입고 뒤 정책이나 계약이 바뀌면 받은 물품의 사실은 고정하고 남은 입고를 재협의한다. 실제 입고 수량보다 낮게 취소하거나 상품 특성을 바꿔 기존 재고를 지우지 못한다.

여러 물품 소유자의 실재고와 확정 미수령 물량을 같은 공간의 용량에 합산한다. 협의 수정 중에도 앞서 승인한 예약 용량은 유지하며, 미수령 거절·취소는 기록을 남기고 예약을 해제한다. 공간·원천·합의의 동시 변경 검사, 행별 요청 결속과 영수증 재조회로 중복 처리와 다른 행의 성공 오인을 방지한다. 사진 근거도 해당 협의/정책 판본에 연결한다.

현장 관리자는 상품과 도착 조건을 읽지만 당사자가 아니면 공급대금·책임/반환 협의와 대화를 받지 않는다. 새 JSON 조건·협의·변경안을 개인정보 보호 변환에 연결했다. DB는 새 테이블 대신 기존 3개 테이블에 7개 컬럼을 추가하며 기존 영수증과 정책 없는 과거 공간 흐름을 보존한다. 실제 공용 DB에는 적용하지 않았다.

## 실행 범위와 제한

기본 OFF·기존 Simulation profile을 유지한다. 격리 SQLite·실제 사진 서비스와 합성 시험 사진·공통 Razor 검증은 실제 Android 카메라나 운영 계약의 증거가 아니다. 실제 휴대폰/APK 설치·Azure·공유 MySQL/Mongo DB 변경·실제 계약 체결·외부 알림/송금·commit/push·Unity는 수행하지 않았다.

출입 가능 시간은 자유문구와 양측 명시 확인이며 자동 출입 시간 파서가 아니다. 실제 공급자 반송 완료·반복 자동 입고는 추가하지 않는다. 이미 받은 물품의 배송 취소 반환은 기존 사진 반환 절차를 유지한다. 반환으로 용량을 초과하면 신규 입고를 보류하며, 실물 반환 책임을 자동 삭제하거나 다른 공간으로 임의 이동시키지 않는다.
