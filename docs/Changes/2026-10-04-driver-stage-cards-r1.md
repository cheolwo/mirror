# 기사 수행 단계별 하단 카드

2026-10-04. 사용자가 수행 상태에 필요한 정보와 다음 행동만 읽도록 요청했다. [수행 단계 책임 카드](../ProjectOverview/page-docs/driver-workspace-sections-r1.md#수행-단계별-하단-카드-r5--구현-전-책임-카드)와 [시각 기준](../Architecture/RoleAppVisualDesignStandard.md#나열감을-줄이는-구성-규칙)을 따른다. 이전 항상 전달지 우선 화면은 [r4 기록](2026-10-04-driver-three-cards-r1.md)에 보존한다.

| 단계 | 펼친 정보 | 하단 주요 버튼 |
| --- | --- | --- |
| 배차 대기 | 수행 카드 없음, 추천 확인/수락은 유지 | 선택한 추천 수락 |
| 수락 후 음식점 이동 | 음식점·픽업 주소·주문·확인된 준비 예정 시각 | 가게 도착 |
| 도착 기록 확인 | 픽업·주문·확인된 준비 예정 시각 | 픽업 완료 |
| 픽업 후 전달 | 전달지·고객 요청/수령인·주문 정보 | 전달 완료 |

서버가 미도착에 도착과 픽업을 동시에 허용하는 현행 계약에서 앱은 도착을 우선한다. 도착 재조회 전에는 픽업 명령도 보내지 않는다. 도착 행동이나 시도 ID 없이 픽업만 제공하는 기존 계약은 픽업 접근을 유지한다. 도착 시각은 `RestaurantArrivedAtUtc`, 전달 단계는 `MovingToDropoff`/`PickupConfirmed`와 서버 행동 투영을 사용한다. 픽업/전달 버튼의 활성화는 기존 인증·서버 권한·처리 중·중단 요청 가드를 따른다. 준비 예정 시각을 준비 완료로 추정하지 않고, 실제 준비 미완료는 서버 거절을 표시한다.

하단 접기/펼치기는 현재 업무 본문만 바꾼다. 접혀도 전체 현재 목적지 요약·배달료·경로/상태 안내와 주요 버튼은 유지한다. 오류/GPS 복구는 접힘 밖이다. 같은 OfferId·시도 ID·단계의 자동 재조회는 사용자 선택을 유지하고 단계 또는 현재 건이 달라지면 펼친 기본 정보로 복귀한다. 새 단계는 업무 시작으로 스크롤하며 `delivery` focus와 추천 focus를 분리한다. 한 본문 스크롤·지도 공간 예약·서버 재조회에 따른 다음 건 선택을 유지한다.

제품 변경은 기존 MainPage XAML/코드, 표현 모델과 픽업/도착 명령 가드·단계 안내다. `PickupConfirmed`의 지도 목적지도 전달로 연결했다. 외부 DTO·API·DB·금액·배차·원장·동시 픽업 처리 방식은 변경하지 않았다. 관련 시험은 도착 우선/실제 API 미호출, 권한 없는 단계, 준비 상태 한계, 접기 의도 유지/새 문맥 복귀와 기존 경로·인증/중단 경계를 다룬다.

최종 Fast `20261004-101822`는 앱/시험 빌드와 관련 **53/53**을 통과했다. Task `20261004-102023`는 전체 3.5 빌드 통과, **6,326/6,333 통과·7실패**다. 기준 `20261004-033045`와 실패 이름·오류·전체 스택 7개가 정확히 같으며 새 실패는 없다. 기존 시험 이름 6개를 단계별 사례로 바꿔 결과 이름 차이는 23개이고, 전체 사례의 순증은 11개다. 전체 시험 게이트는 통과하지 않았다.

최종 Debug APK 보관본과 전용 Android 에뮬레이터 설치본의 SHA-256은 `06ADACAD0E6AEE20B624D1A43205B5B5A9C249999A00855FC1EC67783EA88B76`로 일치한다. 제품 6경로·시험 3경로의 최종 소스 지문을 결속했다. 로컬 제어 HTTP로 실제 APK의 수락 → 가게 도착 → 준비 미완료 거절 → 픽업 재시도 성공 → 전달 완료와 각 정본 재조회를 확인했다. 서버 거절은 픽업 단계/판본을 유지했으며, 대기와 완료 후에는 수행 카드 및 접기 버튼이 없다.

자동 업무 조회가 실제 발생한 동안 접힘 유지, 아래로 스크롤한 뒤 접기/펼치기의 업무 시작 복귀, 픽업 단계에서 스크롤한 뒤 전달 단계의 첫 카드 복귀도 확인했다. 큰 글자에서는 긴 주소·요청·주문·접힌 금액을 본문 스크롤로 읽었고 역방향 스크롤 및 고정 버튼 접근을 확인했다. 캡처는 수정하지 않았다. 화면 크기·글자 설정은 원래 값으로 복원했다.

이번 실행은 실제 APK와 제어된 로컬 응답의 UI 검증이다. 실제 준비 상태·운영 DB·다른 역할 앱 전체·입금·물리 단말 확인은 아니다. 다음 건/새 시도 펼침은 모델 시험 근거이며, 이번 설치본 실행의 완료 후에는 다음 건이 없어 대기로 돌아왔다. 지도 SDK ID가 없으므로 실제 지도 타일·핀·도로선·제스처는 미검증이며, 320 DIP·글자 2.0의 SDK 미설정 안내는 지도 범례/현위치와 겹치는 기존 한계가 있다. 카드 본문/고정 행동 검증과 구분한다. 에뮬레이터 시계는 UTC였고 준비 시각은 기기 현지 시간으로 표시했다.

원시 근거는 Git 제외 `artifacts/local/driver-stage-cards-r1/`의 `verification.json`, 단계별 XML/PNG·정본 상태·HTTP 경로 기록·APK/소스 지문·시험 비교에 보관한다. 전용 실행의 종료 확인은 해당 폴더의 `cleanup.json`에 기록한다. 원장·영상/MYBOX 및 관련 없는 작업은 보존했으며 커밋·푸시는 수행하지 않았다.
