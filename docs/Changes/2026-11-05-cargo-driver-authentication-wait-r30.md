# 화물기사 최초 인증 대기 중 계정 교체 차단

2026-11-05. 내 현재 운송을 조회하기 위해 인증 갱신을 기다리는 동안 새 로그인 계정으로 이전 조회가 이어지는 경합을 보완했다. 페이지·경로·DTO·시장 헤더·원장 권한과 실제 운송/금융 동작은 유지한다.

## 발견과 책임

실제 `DriverTransportApiService` → `DriverApiClient` → `AuthApiService` → 기존 `AuthSession`을 합성 HTTP·장치 저장소 대역으로 연결했다. 원본7사례 중4실패/3통과로, 같은/다른 사용자 재로그인 뒤 이전 인증 준비가 성공하고 현재 운송 조회가 새 bearer를 채택하는 문제를 재현했다. 새 계정이 만료됐을 때 이전 요청이 그 갱신/종료까지 실행하는 경우도 포함한다.

기존401 응답 이후에는 정확한 토큰 `Version`·조건부 종료·한 번 재전송·응답 `SessionRevision` 검사가 있다. 문제는 최초 인증 대기 전의 계정 수명을 잡지 않던 경계였다. 정상 refresh는 토큰 Version만 올리고 같은 SessionRevision을 유지하므로 둘을 구분해 사용한다. 최초 대기에 Version을 그대로 고정해 정상 갱신까지 거절하지 않는다.

- 인증 API는 기존 장치 복원을 마친 뒤 계정 수명을 캡처하고 갱신 대기 전후에 확인한다. refresh의 사용자/토큰은 지역 변수로 보관하고 전송 전에 판본을 재검사한다.
- 업무 Client는 최초 복원 뒤 원 SessionRevision을 유지하며 해당 문맥의 인증 준비를 요청한다. 인증 후와 헤더를 만든 뒤 다시 확인해 새 계정으로 요청을 보내지 않는다.
- 기존 Session의 복원 직렬화·저장과 기존401 토큰 판본/한 번 재전송·조건부 종료·시장 헤더·본문 복제는 유지한다. 새 복원 gate나 공용 계약을 추가하지 않았다.

수정 소스는 `DriverApp/Services/AuthApiService.cs`, `DriverApiClient.cs`다. 기존 Session·IAuthSession·운송 Service·UI의 책임을 이동하지 않았다. 최초 복원 도중의 명시적 계정 교체나 이미 전송한 모든 응답의 수명까지 해결한 것으로 확대하지 않는다.

## 검증과 재개

새 회귀는 정상 갱신 때 Version 증가/SessionRevision 불변, 새 계정 차단, 정상 첫 복원과 첫 복원 호출자 취소 뒤 다른 호출자의 복구를 대조했다. 최종 Fast는 관련435통과/실패0/생략0이며 신규 인증7사례를 포함한다. 필수 Task는17,022통과/실패0/환경17생략이다. 기사 Android·Windows/시험 빌드는 경고65/227·오류0, 통합3.5 Task 빌드는 경고60·오류0이다. 별도 관리형 실행기는 NU1902 의존 패키지 경고2·오류0이며 패키지를 변경하지 않았다. Android 의존성/Push 설정 경고는 인증 결함과 분리한다.

후보 복사 때 수정 시각이 보존돼 첫 Fast가 이전 시험 DLL을 재사용한 실패도 보존했다. 당시 PDB에는 원본2소스의 체크섬만 있고 수정 소스 체크섬은 없었다. 소스 바이트는 바꾸지 않고 소유된 두 입력의 수정 시각만 갱신해 다시 빌드했다. 최종 실제 통신 전에 PDB 문서별로 현재4소스·지원3소스의 SHA 일치를 확인했다. 이전 실패/컴파일 출력은 덮어쓰지 않았고 최초 실패를 현재 소스의 검증 결과로 쓰지 않는다.

같은 소유 Simulation/격리 DB에서 실제 기사 로그인·현재/목록/상세·운송1 정본·전후 원장7단계 HTTP200을 확인했다. 의뢰 `fe458c5c-f4a2-b91d-d37b-592875dfdea3`/운송1·담당 기사·상태·이동 정보가 서로 일치하며 실제 Client의 Bearer/KR 시장 헤더와 전후 원장 proof 불변·금융3종0을 대조했다. 새 메모리 토큰 저장소와 기존 시험용 Preferences 대역을 명시했으며 실제 장치 저장·인계 명령·통신 장애 주입이나 휴대폰 E2E 완료로 쓰지 않는다.

원본/실패·소스 SHA·컴파일 출력·현재 실행과 보존/다음 한 가지는 `artifacts/local/app-resume-r30/251a6683a9904df0a3ec630438566322/completion.json`을 따른다. 포함 관계인 시험 수를 합산하지 않는다.

기기에서는 등록 USB·공유 OS 잠금과 기존 관리자 설치 바이트를 읽기 대조했으나 음식점 검토 앱의 인증 입력 화면을 보존했다. 이번 기사 package/내장 endpoint·실제 화면은 미확인이다. 설치·전환·인증 입력·새 검토 APK 준비는 없다. 기존 과거 판본·업무/금융/배차 상태와 배민 checkpoint를 보존한다.

다음은 기기 조건과 현재 검토 판본을 대조해 같은 합성 업무의 관리자 상세/복귀를 이어가는 것이다. 화주·기사도 해당 판본의 목록/상세·인증 오류 후 복귀를 실제 기기에서 확인해야 한다. 기존 업무를 새로 만들거나 운송/배차/금융 명령을 검증 명목으로 실행하지 않는다. 과거 원인 미확정503도 해결로 승격하지 않는다.
