## 책임과 구현

- 기사 화면의 내부 번호와 중복 배지는 현재 운송·상차·하차에서만 숨긴다. 내부 ScreenCode와 다른 역할/화면은 유지한다. 주소·수령자·금액·시간·접힌 상세·재시도·복귀는 기존 조건을 따른다.
- 상차의 원시 의뢰 ID는 기본 정보에서 제외하되 현재 운송의 접힌 의뢰 번호 상세와 API/원장 식별자는 유지한다.
- 상하차 ViewModel은 안내 반환 문자열만 바뀌었다. 도착·촬영·체크·인수증·서명/합의된 생략·미확정 결과·전송/취소 조건은 바꾸지 않았다.
- 화주 공통 Screen은 중복 제목 설명·내부 번호·구현 문단을 제거하고 현재 상태·담당·다음 이동을 남긴다. 실제 사진 검수로 확인되지 않은 내용을 검수 완료로 표시하지 않는다.
- MAUI/Web의 정상 조회 성공 메시지는 생산자에서 비우고 사용자 행동 성공 메시지는 짧게 유지한다. 성공/안내 severity 전체를 숨기던 중간 시도는 최종 구현에 포함하지 않았다.
- 테스트 결제 문구는 UI 표시이며 FakePG 식별자·API·조건·모의/실금융 경계는 바꾸지 않는다.

상세 책임 카드는 [기사 현재 운송](../ProjectOverview/page-docs/DriverApp/DriverApp-P11/README.md), [상차](../ProjectOverview/page-docs/DriverApp/DriverApp-P12/README.md), [하차](../ProjectOverview/page-docs/DriverApp/DriverApp-P13/README.md), [화주 상세](../ProjectOverview/page-docs/cargo-order-closeout-r70.md)에 반영했다. 공통 문구 기준은 [역할 앱 시각 기준](../Architecture/RoleAppVisualDesignStandard.md)을 따른다.

## 검증 기록

실행 증거는 `artifacts/local/cargo-concise-ui/20261021-r1/`에 보존한다. Fast는 소비 솔루션 빌드와 집중355개 시험을 통과했다. 최종 소스를 동결한 Task의 소비 솔루션 빌드는 오류0·기존 경고308개였고 전체 시험에서 기존 `FDriverFoodPushTests.Receiver_CallbackTimeoutCannotPublishAfterDelayedLocalRestore`1건이 시간 초과로 실패했다. 소스·시간 제한·병렬 조건을 바꾸지 않고 해당 시험을 단독 재실행해1개 통과, 같은 빌드의 전체 시험을 재실행해14,139개 통과·환경 의존16개 미실행·실패0개를 확인했다. 초기 실패 기록과 두 재실행 TRX를 모두 보존한다. 새 시험을 추가하거나 시간 제한을 늘리지 않았다.

기존 dirty 변경을 포함한 제품 전체 diff와 이번 문구 차이를 같은 것으로 계산하지 않는다. 기사 소유9파일과 화주 후속 파일은 수정 전 사본·SHA를 보존했다. 화주 최초 Frame/Summary/Navigation3파일은 별도 전 사본을 놓쳤으며, 당시 읽기와 좁은 patch 기록을 근거로 검토했다. 추정 원본을 만들지 않는다.

완료된 선행 운송9는 다시 수락·완료하지 않는다. 이전 PNG·APK·완료 원장·사진은 그대로 보존하고 새 판본의 실제 화면은 별도 캡처한다. 서버 업무 검증·APK 빌드·설치·단말 화면·실제 운송/금융·외부 FCM은 각각 구분한다. 모델 가중치 학습·운영 활성화·클라우드 배포·commit/push는 하지 않는다.

기존 USB Debug 제작 도구로 두 ABI 내장·서명·정렬·버전을 검사했다. 제작 전후 선택 소스 fingerprint `5cfe438a31825a0c0422db358752ccdef6e1eba6b524f25e2029276fbebf16d5`가 같았다. 기존 설치판과 서명이 일치하고 `adb install -r`로 업데이트했다. 데이터 초기화·삭제·uninstall 없이 설치된 APK를 다시 읽어 위 바이트 SHA와 일치함을 확인했다. `installed-app.json`이 별도 기기 근거다. 이 APK는 로컬 USB 시험용이며 공개 배포·외부 서버 연결을 뜻하지 않는다.

실제 Samsung SM-A346N에서 기사 현재 운송·하차 완료와 화주 진행 이력·증빙·결제 화면을 재조회했다. 기본 화면의 내부 번호·정상 조회 배너·adapter/endpoint 설명이 사라지고 현재 상태·금액·짧은 행동이 보였다. 화주 요약의 의뢰 번호는 기본으로 접혔고 직접 펼쳤을 때 같은 번호를 확인했다. 새 촬영·등록·결제·완료 요청은 보내지 않았다. 새 상하차 미완료 분기의 체크/촬영 문구는 소스·소비 빌드·관련 회귀로 검증했고, 이번 단말 사진은 기존 완료 건의 읽기 화면이다.

같은 의뢰 `d828af66-2803-4c14-2415-a56ddbb25fcc`/운송9를 앱 갱신 전후에 서버에서 다시 조회해 `인수완료`, 추천차수1, 동결6,200원, 실제 AI Applied가 유지됨을 대조했다. 기존5364 수동 검증 서버는 중지되어 있어 같은 DB·프로필·기존 DLL로 다시 시작했다. 자동 배우·FCM·지급은 비활성이며 이전 migration health 경고는 그대로다. 기존5595 검토 서버·5392 선행 갤러리·Ollama는 유지했다.

전후8PNG는 원본 픽셀을 그대로 복사했고 촬영 시각·앱 판본·SHA를 연결했다. 기사 완료/화주 진행/증빙3쌍과 기사 현재 운송·화주 결제2장을 비교한다. 추가 의뢰 번호 펼침 화면은 raw에 별도 보존한다. 첫 작업의 추천→카메라→완주 증거와 이번 문구 변경 후 조회 증거를 같은 실행으로 합치지 않는다.

비교 HTML은 Chrome의 로컬 파일로 1280px·390px에서 확인했다. 이미지8장 로드·가로 넘침0·콘솔 오류0·외부 요청0을 기록했다. 추가 HTTP5394 미리보기 서버 실행은 정책에 의해 차단됐으며 실행 성공으로 기록하지 않는다. 비교 화면은 위 로컬 HTML 파일로 제공한다.
