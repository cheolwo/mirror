# 주문 내역을 다시 읽을 때 적용한 검색어 유지

개별주문 원장 목록은 검색창에 입력한 값으로 조회했다. 실패한 조회를 다시 시도하기 전에 다른 검색어를 입력하면 기존 요청의 페이지 번호에 새 검색어가 섞였다. 이제 **검색** 버튼을 눌러 적용한 검색어를 별도로 보관한다. **다시 시도**와 목록 새로고침은 적용한 검색어와 요청한 페이지를 읽고, 이전·다음은 같은 검색어로 해당 페이지를 읽는다. **검색**을 누르면 입력한 검색어로 첫 페이지를 읽는다. [주문 내역 화면 소스](../../OrdererApp/Components/Orders/OrdererIndividualOrderLedgerList.razor)

실제 목록 Razor, 입력·버튼 콜백과 기존 조회 ViewModel을 메모리 서비스로 검증했다. 수정 전에는 재시도·새로고침·페이지 이동 3건에서 미제출 검색어가 전송됐다. 수정 후에는 이 3건과 명시적 검색의 첫 페이지 복귀를 합한 4건이 통과했다. 실제 브라우저 화면 폭, 기기와 제품 API는 미검증이다.

주문자 앱과 통합 1.5 빌드는 오류 0개였다. 관련 시험 38건, 전체 시험 17,031건이 통과했고, 환경 조건이 필요한 17건은 생략했다. 소스 판본과 시험 결과는 `artifacts/local/mirror-ui-assist/20261106T063118819Z-orderer-applied-search/completion.json`에 기록했다.

다음 회차에는 음식기사가 완료한 배달 내역의 조회 실패 뒤 재확인 흐름을 살핀다.
