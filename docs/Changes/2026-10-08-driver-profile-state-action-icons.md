# 기사 내 정보·배달 내역과 상태 카드 행동 아이콘

배달 내역 진입을 내 정보 안으로 옮기고, 내 정보에는 사람 아이콘과 문구를 함께 표시한다. 후속 사용자 요청에 따라 OS 생명주기·절차·현재 상태별 기존 카드 버튼에도 행동을 알아보기 쉬운 아이콘을 덧붙인다. 버튼의 업무 의미와 서버 허용 조건은 유지한다.

## 책임과 구현 범위

[기사 영역 책임 카드 r8·r9](../ProjectOverview/page-docs/driver-workspace-sections-r1.md), [페이지 책임 기준](../Architecture/WholeRoadmapPagePrinciple.md), [역할 시각 기준](../Architecture/RoleAppVisualDesignStandard.md)을 따른다. 음식 기사·공통 역할의 기존 상태 카드에 적용하며 모든 앱의 독립 화면이 완료됐다는 뜻은 아니다.

- 메인 진입은 배달·내 정보다. 배달 내역은 내 정보에서 목록→상세로 이동하며 복귀도 내 정보로 이어진다. 이전 settlement 진입 경로는 같은 내 정보 흐름으로 연결한다.
- 네이티브 버튼에는 기존 Fluent 폰트의 실제 글리프를 사용한다. 가게 도착=매장, 픽업 완료=포장 확인, 전달 완료=체크, 위치 재조회=새로고침, 문제 접수=주의, 배달 내역=목록이다.
- 접기·펼치기는 기존 확장 bool에 따라 위/아래 화살표를 표시한다. 운행 버튼은 운행 상태에 따라 시작/정지로 바뀌고, 중단 요청이 결과 확인 대기라면 새로고침으로 바뀐다. 수신 상태가 불명확하거나 변경 결과를 확인하는 버튼에는 상태를 단정하지 않는 알림 아이콘을 사용한다.
- `DriverActionIcon`은 버튼 문구·명령·가시/활성 조건에 관여하지 않는다. 아이콘 색은 버튼 글자 색을 따라 밝은/어두운 테마, 선택, 위험 행동, 비활성 상태에 대응하며 크기는 기존 글자 설정과 함께 고정한다.
- 공통 역할 카드의 아이콘은 안정적인 행동 키에만 연결한다. 문구를 분석하거나 OS 단계 번호에서 행동을 추정하지 않는다. 모르는 키에는 기존 문구만 표시하며 아이콘은 보조 장식으로 처리한다.

버튼 문구, API/JSON/DB, 금액, 고객 정보 보호, 가능 행동, 확인 절차, 명령 및 결과 재확인 방식은 변경하지 않는다. 기존 전문화 음식점·운영자 화면의 아이콘 체계를 재사용한다.

## 로컬 검증

네이티브 세 XAML의 41개 기존 버튼에서 문구·명령·명령 인수·클릭·가시·활성 및 기존 버튼 트리거가 유지됨을 수정 직전 사본과 대조했다. 그중 상태별 버튼, 정보 접기, 내역 탐색에 아이콘을 추가했다. 새 버튼을 생성하지 않았다. 기존 폰트의 사용 글리프를 실제 포함 파일과 대조했고 의존성·폰트 패키지를 추가하지 않았다.

수정 완료 소스를 고정한 최종 Fast 검증은 기사 앱(Android)·공통 UI·시험 프로젝트 빌드와 관련 **254개 시험 통과·실패 0**이다(`artifacts/local/validation/20261008-084307/`). 12개 제품/시험 파일 지문이 검증 전후 일치한다. 알 수 없는 행동 키의 문구 전용 표시, HTML 인코딩, 장식 아이콘의 접근성 제외·상속 색, 기존 링크/비활성 조건을 확인하는 새 렌더 시험 8개와 기존 선택 도구 7사례를 포함한다. native·shared 독립 읽기 검토에서 차단 문제를 발견하지 않았다. HTML 렌더 시험은 실제 휴대폰 레이아웃·터치·테마 전환을 대신하지 않는다.

최종 Task는 전체 3.5 빌드와 **8,597개 시험 통과·실패 0·Mongo 환경 조건 2개 건너뜀**으로 완료됐다(`artifacts/local/validation/20261008-084956/`). 12개 제품/시험 파일 지문이 검증 전후 일치한다. 검증된 제품 10개 파일의 지문이 r33 APK 제작에 사용한 소스와 일치하는 것도 `apk/bound-validation.json`에 결속했다. 별도 포장 소스 전체의 시험을 다시 실행한 것은 아니며, 해당 소스의 새 Android 포장은 완료했다.

최초 native Fast에서는 스타일 압축 중간 파일 누락(`XA2001`)으로 빌드가 실패했다. source 수정이 끝난 뒤 동일 설정의 첫 통합 Fast 247개가 통과했으며 제품 코드나 빌드 옵션을 바꾸어 우회하지 않았다. 첫 전체 Task는 빌드가 통과했지만 기존 선택 도구 시험 6개가 문구 바로 뒤의 `</a>`/`</button>`을 가정해 실패했다(8,591개 통과·6개 실패·Mongo 환경 조건 2개 건너뜀). 해당 시험 한 파일만 아이콘을 제외한 실제 control 문구와 해당 control의 정확한 href·disabled·class·메뉴 배치·미실행에 결속하도록 보완했다. 기존 7사례는 유지했고 제품 10개 파일은 변경하지 않았다. 위 최종 Fast에서 모두 통과했다.

두 번째 Task는 빌드 통과 후 기존 Warehouse 시험의 EF 초기화·`Expression.Compile` 안에서 시험 호스트가 `Internal CLR error 0x80131506`으로 중단됐다. 3,091개 통과는 중단 전 부분 결과이며 전체 통과로 기록하지 않았다. 원인은 미확정이고 이번 UI 코드로 이어지는 스택은 없었다. 소스·빌드/실행 설정을 그대로 유지한 새 프로세스의 세 번째 Task가 위 최종 결과로 완주했다. 첫 실패와 CLR 중단 로그도 보존한다. 로컬 근거는 Git 제외 `artifacts/local/state-card-action-icons-r33-20261008/`에 보관한다.

## APK와 다음 휴대폰 확인

내 정보·배달 내역 변경만 담은 개인 Debug APK `0.1.32/32`의 포장과 실제 내장 XAML/폰트 대조는 완료했다. 이 판본에는 후속 상태 카드 아이콘이 포함되지 않는다. APK SHA-256은 `9ad750c13b6b2a62789eaf14871b24da14515a8e72bd33e9825d34f8b657ed99`다. 같은 Debug 서명·기존 지도 ID·USB용 로컬 서버 설정을 유지하며 실제 휴대폰 설치와 실행은 별도다.

아이콘을 포함한 새 개인 Debug APK는 `0.1.33/33`, 153,307,063 bytes이며 SHA-256은 `f3e64575198b84ed51e42661cf47473755f41b89323c55681b9dac6647e0ddcc`다. Git 제외 `artifacts/local/state-card-action-icons-r33-20261008/apk/0.1.33-33/handoff/driver-usb-debug.apk`에 준비했다. 보존한 r32 소스의 별도 사본에 승인한 제품 10개 파일만 반영했고, 새 파일 4개를 포함한 2,614개 소스의 빌드 전후 지문이 유지됐다. r32·r31·r27 원본도 보존했다. 양 ABI에서 내장 XAML 3개, 행동 아이콘 helper/글리프 상수, 이번 공통 UI DLL·renderer 호출·scoped CSS·폰트와 빌드한 DLL의 바이트 일치를 대조했다. 기존 Debug 서명·지도 ID·교통정보 OFF·GPS 보완·USB 로컬 서버5363 설정을 유지했다. APK 내부 확인은 실제 화면·터치 검증이 아니다.

사용자는 추가 에뮬레이터 검증을 중지하고 다음 휴대폰 USB 연결 때 APK 검증·설치를 하도록 요청했다. 개인 에뮬레이터 시험은 알림 권한 화면까지 진행했으며 내 정보·내역 탐색이나 새 아이콘 화면의 렌더 검증을 완료하지 않았다. 소유한 에뮬레이터만 종료했고 기존 에뮬레이터 원본 지문이 유지됨을 확인했다. 전역 ADB나 실제 휴대폰을 종료하지 않았다.

다음 USB 연결 때 최신 아이콘 포함 판본을 먼저 대조한 뒤 내 정보→목록→상세→복귀, 가게 이동→도착→픽업→전달, 접기·펼치기, 비활성·문제 접수·응답 미확정 재확인 버튼을 실제 화면에서 확인한다. 실기기 화면 캡처·APK 설치·Azure·실운행·실지급·커밋/푸시는 이번 소스 검증과 구분한다.
