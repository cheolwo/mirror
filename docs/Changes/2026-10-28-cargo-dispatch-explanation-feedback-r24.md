# 화물 추천 당시 기록과 사용자 의견 r24

새 화물 추천을 저장할 때 당시 접수 조건과 확인한 수행계획을 함께 남기고, 화주/주문자와 대상 기사 본인이 그 기록에 의견을 제출하도록 연결했다. 예전 추천에 기록이 없으면 `기록 없음`으로 표시한다. 현재 값을 다시 계산해 과거 AI의 판단 근거로 만들지 않는다.

[승인 범위](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-dispatch-explanation-feedback.r24.md) · [화면 책임](../ProjectOverview/page-docs/cargo-dispatch-explanation-feedback-r24.md).

## 사용 흐름

1. 화주/주문자는 기존 수락·진행 알림의 운송 상세에서 `배차 설명·의견`을 연다. 전문 기사는 추천 상세를 펼쳐 같은 이름의 버튼을 누른다.
2. 추천 라운드·저장 시각·접수 중량/운송 방식/온도/상하차 마감을 본다. 조율 경로에서 실제 확인된 경우에는 수행계획·구간 적재와 해당 의뢰의 상하차 순서도 표시한다.
3. 의견 종류를 직접 고르고 선택적으로 500자 이내의 한 줄 의견을 보낸다. 접수 시각과 내 의견 접수 기록을 다시 조회한다.

이 화면은 당시 저장된 조건과 처리 경로를 설명한다. 각 접수 항목이 AI가 특정 기사를 고른 직접 원인이라는 뜻은 아니며, 모든 규칙·수동 추천을 AI 판단으로 표시하지 않는다. 아직 모든 후보 비교·귀가 가점의 실제 선택 원인을 저장한 것은 아니다. [r23의 미완성 연결](2026-10-28-cargo-cross-region-return-r23.md)은 유지한다.

## 저장·권한·재시도

- 기존 추천의 SQL 저장 집합에 보호된 추가 전용 설명 사건을 넣는다. 조율과 엔진/수동 추천 경로를 연결하고, 같은 원장·대상·라운드의 중복 기록을 막는다. 저장 실패 때 이번에 추가한 사건과 추천 변경만 복원하며 기존 추적 자료는 보존한다.
- 과거 대상 기사는 만료·거절·다른 기사 재추천 뒤에도 자신의 설명만 확인한다. 다른 기사의 100개 이상 새 기록이 앞에 있어도 본인 이력을 `미기록`으로 숨기지 않는다. 화주/주문자 관계와 사용자 신원은 서버가 다시 확인한다.
- 다른 기사 후보·점수·집/거점·GPS·고객 상세주소·연락처·원시 AI 문장은 공개 응답에 넣지 않는다. 의견은 별도 보호 Mongo 저장소에 접수하며, 요청번호·설명·작성자·내용을 결속한다.
- 같은 요청번호/같은 내용은 원 접수 결과, 같은 번호/다른 내용은 충돌을 반환한다. 화면은 접수 응답의 설명ID·번호·종류·내용 지문을 확인한다. 응답 유실은 보호된 임시 입력을 복구하고 GET 조회를 먼저 하며 POST를 자동 반복하지 않는다.
- 정상 토큰 갱신은 입력을 보존한다. 계정·세션·서버·의뢰 변경이나 화면 폐기 뒤의 응답은 현재 화면을 덮지 않는다.

의견 접수는 운영자 검토·답변·배차 수정·운임 변경·자동 학습 완료와 다르다. 기존 알림 링크와 안내를 연결했으며 이메일 발송·전역 개인화 설정·새 운영자 답변 화면·자동 재추천은 추가하지 않았다.

최종 전체17생략에는 별도로 통과한 신규 Mongo1건과 이번에 실행하지 않은 기존 외부 DB 환경16건이 들어 있다. 전체 회귀를 모든 외부 시스템의 성공으로 집계하지 않는다.

첫 전체 빌드는 복원 자산이 없는 9개 프로젝트에서 중단됐다. 패키지 복원을 포함한 재실행에서 전체 솔루션 빌드를 통과했다. 최초 집중 시험의 교차 의뢰 fixture는 추천 상태 두 필드가 빠져 캡처 입력 검증에서 실패했고, 실제 유효한 추천 상태로 고친 뒤 권한 차단을 재검증했다.

기존 모바일 시험용 Mongo의 초기 환경변수로 인증되지 않아 첫 DB 시도는 실패했다. 기존 컨테이너·인증·compose를 바꾸지 않고 로컬에 있던 공식 Mongo 이미지를 별도 이름·임의 loopback 포트로 띄워 이 작업 전용 시험만 수행했다. 시험 DB와 소유 컨테이너는 정리했다. 운영 DB나 영구 암호키 재시작 검증이 아니다.

실제 Razor가 생성한 합성 HTML 4종은 `artifacts/local/cargo-dispatch-feedback-r24/render/`에 보존했다. 브라우저가 `file:` 열기를 보안 정책으로 거부하여 우회하지 않았으며 360/390px 실제 브라우저 배치·Android 기기 화면은 미검증이다. 정적 Razor와 ViewModel/adapter 회귀를 화면 실측으로 표현하지 않는다.

## 범위와 남은 단계

원시 로그·TRX·소스 해시는 `artifacts/local/cargo-dispatch-feedback-r24/`에 둔다. 기존 변경 소스38개 중 추천 상세의 명시적 연결이 필요한 `DriverApp/NativeDriverRecommendationPage.cs`만 병합하고 나머지37개의 해시를 보존했다. 기존 r20~r23 변경·개인 산출물과 HEAD를 보존했다.

문서 Fast `20261028-082720`과 공백 검사를 통과했다. 변경 문서6개의 로컬 링크1,624개를 검사해 이번 추가 링크의 누락은0개였고, HEAD에도 존재하는 이전 링크 오류284개는 별도 목록으로 보존했다. 기존 기획 목차의 오탈자 경로를 이 기능 작업에 섞어 수정하지 않았다.

새 코드의 실제 로그인/제품 Startup·SQL/Mongo 왕복·최신 APK의 조회/제출/복구와 알림 딥링크는 후속 기기 검증이 필요하다. 이번에 실제 알림/이메일 발송·자동 학습·운영 활성화·commit/push·배포는 수행하지 않았다.
