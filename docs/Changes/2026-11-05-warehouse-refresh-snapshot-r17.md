## 재현한 문제와 최소 수정

한 번 정상 조회한 뒤 새로고침할 때 입고 조회는 성공하고 재고 조회가 실패하면 새 입고 수치와 이전 재고·알림이 함께 표시됐다. 기존 `hasLoaded`는 true인 상태이고 각 조회 결과를 바로 필드에 대입했기 때문이다. 실제 서버 연결은 입고/재고 GET이며, 뒤의 출고 알림·HS 검토·판매채널은 현재 로컬 저장소 조회다. 뒤 세 서비스에 주입한 실패를 실제 네트워크 오류로 표현하지 않는다.

[ShipperOperationsWorkspace](../../SsalddelApp/Components/Shared/ShipperOperationsWorkspace.razor)의 `LoadAsync`에서 같은 순서로 다섯 결과를 지역변수에 모은 뒤, 모두 성공했을 때 화면 필드와 성공 상태를 연속 반영한다. 대기 중이거나 어느 조회든 실패하면 마지막 전체 표시를 유지한다. 초기 미확인/정상0건 구분, 오류 안내, 중복 조회 차단과 명시 새로고침은 보존한다. 여러 API나 DB를 같은 시점의 트랜잭션으로 묶은 것은 아니다.
