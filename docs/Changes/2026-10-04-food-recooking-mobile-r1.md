# 재조리·새 기사 인계와 휴대폰 서버 연결 준비 r1

2026-10-04. 음식·화물 배차 분리 이후의 다음 우선순위인 픽업 후 중단 → 재조리 → 새 기사 인계를 보완한다. 목표는 기존 APK의 정상 업무와 서버 통신이며, 현재 요청의 미래 Azure 사용 계획에 맞춰 배포 설정도 대조한다. [페이지·코드/API·DB 책임](../ProjectOverview/page-docs/food-recooking-mobile-r1.md)을 따른다.

## 구현

첫 음식의 준비 기록이 재조리 이후의 준비 완료 버튼을 닫거나 새 기사 픽업에 사용되는 문제를 수정한다. 과거 이력은 보존하고 현재 차수의 조리·준비를 별도로 투영한다. 서버의 실제 픽업 검증과 조회 행동이 같은 판정을 사용한다. 픽업 전 재배차는 준비된 같은 음식을 유지한다.

음식점 상세는 다시 조리 중·이번 준비 완료를 표시하고, 기사 화면은 이번 음식 준비 대기·예정·실제 완료를 구별한다. 기존 페이지·카드·행동을 재사용한다. 준비 조회 자체로 픽업을 실행하지 않는다. 중단 시도·동일 요청 재시도·revision·새 기사 정산 연결은 기존 원장을 유지한다.

Azure App Service의 컨테이너 포트·키링/PFX·Redis 선택과 VM의 실제 인증서 경로·음식 현장 검증 모드를 현행 코드에 맞춰 문서화한다. 기존 HTTPS·SignalR·서명·APK 주소 도구를 재사용한다. 유료 리소스 생성·클라우드 배포는 실행하지 않는다.

- 제품·시험·검증 도구·Azure 문서 24개의 최종 동결 지문과 범위 밖 기존 dirty 337개의 지문 변경 0을 독립 확인했다. 커밋·푸시는 수행하지 않았다. 원시 자료는 Git 제외 `artifacts/local/food-recooking-mobile-r1/`에 보관한다.

## 다음 설치·배포 단계

현재 APK 생성이나 로컬 HTTP 검증을 개인 휴대폰·Azure 공개 HTTPS 검증으로 확대하지 않는다. 공개 서버 주소, 외부 보관 Release 서명, 대상 Azure 구독·지역·예산·DB·도메인을 먼저 확정하고 기존 field-test 도구로 `Staging + Simulation` 환경을 검증한다. 현재 요청에서는 Azure 유료 리소스 생성·배포를 실행하지 않았다.

음식 앱의 별도 푸시 토큰 등록·Android 수신 연결, 네이버 지도 인증·타일, 기존 전체 시험 실패 7개는 별도 마감 대상이다. 이번 재조리 보완은 앱이 전경에 있는 동안의 실제 조회·명령 흐름을 검증하며 백그라운드 알림이나 실결제·입금의 완료를 뜻하지 않는다.

다음 보완은 운영자 모바일의 음식 주문 관제를 화물 기능에서 독립시키는 것이다. `AdminDashboardService`의 홈 API와 `AdminOperationsService`의 화물·음식 동시 조회가 화물 비활성 때 음식 화면도 막는다. 서버의 기존 음식 주문 추적·중단 검토 API를 기존 관리자 인증으로 연결하고 음식 ON·화물 OFF 서버와 APK에서 검증한다. 이번에는 읽기 전용으로 확인했으며 구현하지 않았다.
