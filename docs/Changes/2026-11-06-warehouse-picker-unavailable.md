# 입고 예정 조회에서 선택할 창고가 없을 때

창고 목록을 처음 읽다가 실패하면 ‘창고 다시 조회’와 선택지가 없는 창고 메뉴가 함께 표시됐다. 조회 오류가 있고 표시할 창고가 없으면 **창고 다시 조회**만 안내한다. 목록 조회가 정상적으로 끝나 0건이면 ‘조회 가능한 창고가 없습니다’ 안내를 표시한다. 이미 읽은 창고가 있으면 기존 메뉴에서 선택할 수 있다. [입고 예정 화면](../../WarehouseManagerApp/Components/Pages/ExpectedInbounds.razor)

실제 입고 예정 Razor와 MudBlazor 버튼을 합성 창고 상태로 비교했다. 수정 전에는 처음 조회에 실패한 화면에 빈 선택 메뉴가 표시돼 1건이 실패했다. 수정 후 첫 조회 실패와 버튼 복구, 정상 0건, 이전 창고 목록이 있는 상태의 재조회 실패 3건이 통과했다. 버튼은 합성 재조회 상태를 사용했다. 실제 앱의 네이티브 화면 폭과 제품 API는 미검증이다.

창고 앱과 통합 3.5 빌드가 오류 없이 끝났다. 관련 시험 89건과 전체 시험 17,034건이 통과했고, 환경 조건이 필요한 17건은 생략했다. 수정 전후 렌더와 시험 결과는 `artifacts/local/mirror-ui-assist/20261106T080120380Z-warehouse-picker-unavailable/completion.json`에 연결했다.

다음 회차에는 공통 서버 목록의 조회 실패 안내와 정상 빈 상태가 함께 표시되는 조건을 살핀다.
