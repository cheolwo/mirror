# 판매 주문 원장 목록의 모바일 요약 배치

판매자가 출고 후보를 찾을 때 좁은 화면에서는 요약 카드 네 개가 한 열로 쌓여 검색과 목록을 아래로 밀었다. [공용 판매 주문 화면](../../Ssalddel.Ui.Common/Areas/App/Components/Sales/ShipperSalesOrderWorkspace.razor)에서 목록 요약만 기존 두 열 배치를 유지하도록 바꿨다. 후보 건수·출고 라인·창고 연결·운송 인계의 읽는 순서와 상세 화면 배치는 그대로다.

가상 주문 4건을 넣은 판매자 화면의 320px·390px 비교에서 요약 높이는 263px에서 125px로 줄었다. 주문 표 시작점은 각각 138px·137px 위로 올라왔고, 1280px의 네 열과 표 위치는 유지됐다. 320px에서 긴 주문번호가 있는 표 내부에 가로 스크롤이 남고, 320px·390px의 긴 행에서 수량 문구가 말줄임된다. 선택한 주문의 상세에서는 전체 수량을 읽을 수 있다.

판매자 목록·상세 Razor와 실제 스타일을 사용한 격리 브라우저에서 36개 검사를 통과했다. 상품명·상태·수량이 다른 가상 주문 4건으로 **조회**, 같은 주문의 **상세**, 검색어를 유지한 **주문 목록** 복귀, 검색 결과가 없을 때 **필터 지우기**를 확인했다. [390px 주문 목록](../assets/changes/2026-11-06-seller-order-readability/orders-390.png) · [같은 주문 상세](../assets/changes/2026-11-06-seller-order-readability/detail-390.png)

390px에서는 출고 상태 필터와 가상 조회 실패 후 **다시 시도**도 확인했다. Fast 관련 시험 50건과 통합 3.5 Task 전체 시험 17,045건이 통과했다. 환경 조건이 필요한 17건은 생략했다. 빌드 오류는 0개였고 Fast 경고는 0개, 통합 빌드 경고는 62개였다.

제품 서버·DB, 실기기, 주문 상태 변경은 실행하지 않았다. 전후 측정과 시험 기록은 `artifacts/local/mirror-ui-assist/20261106T113923772Z-seller-order-readability/completion.json`에서 확인할 수 있다.
