# 기사 전달지 우선 세 카드

2026-10-04. 사용자가 전달 주소를 최우선으로 보고 그 아래 고객 요청과 주문을 읽도록 요청했다. [페이지 책임 카드](../ProjectOverview/page-docs/driver-workspace-sections-r1.md#전달지-우선-세-카드-r4--구현-전-책임-카드)와 [시각 기준](../Architecture/RoleAppVisualDesignStandard.md#나열감을-줄이는-구성-규칙)을 따른다.

| 순서 | 카드와 섹션 |
| --- | --- |
| 1 | 전달지: 전체 고객 주소 → 픽업 중의 음식점 주소 → 진행 상황·경로 안내 |
| 2 | 고객 요청 사항: 전달 요청 → 수령인 이름·관계·연락처 |
| 3 | 주문 정보: 주문 요약·기사 배달료 → 기존 상세 보기 안의 픽업 정보·현장 처리 |

고객 요청은 상세 보기 없이 읽는다. 수령인 정보가 없는 경우 빈 고객 카드는 표시하지 않는다. 픽업 중에는 전달 주소와 픽업 주소를 구분하고, 픽업 확인 뒤에는 같은 건의 전달 정보가 유지된다. 완료 뒤에는 다음 건의 세 카드로 갱신한다. 다른 배달 목록은 계속 제외한다.

본문 스크롤과 하단 주요 버튼·지도 공간 예약을 유지한다. 배달 focus는 세 카드의 시작으로 돌아온다. 카드마다 독립 스크롤이나 접기 상태를 추가하지 않았다. 기존 추천·운행/수신 설정·오류 복구·가게 도착·중단 행동을 보존한다.

320 DIP·글자 배율 2.0의 첫 실행에서 상단 메뉴의 두 줄 배치와 새 추천 알림이 본문을 거의 가리는 것을 확인했다. 메뉴 및 알림 보기 버튼의 여백을 `8,8`로 줄이고 알림 버튼을 수직 가운데에 놓았다. 현재 배달이 있으면 세 기본 카드에 기존 확장 높이 한도(70%)를 적용하고, 지도 조작 공간 예약 및 본문 실측 상한을 유지한다. 상세 접기는 세 카드 중 주문 정보의 보조 필드를 접고, 기존 추천 목록의 펼침도 유지한다. 기존 글자 크기·알림 내용·명령·48 DIP 최소 조작 크기는 유지한다. 첫 설치본 및 실패 캡처는 원시 근거에 보존하고 최종 설치본으로 다시 확인한다.

제품 변경은 `MainPage.xaml`의 세 카드·상단 여백과 `MainPageModel.FoodPresentation.cs`의 표시용 픽업 여부·활성 배달 높이 및 변경 알림이다. API/DB·금액·배차·업무 상태는 바꾸지 않았다. 기본 높이와 픽업/전달 전환 시 보조 주소 표시를 기존 표현 테스트에서 확인한다. 기존 한 카드의 실행 기록은 [r3 변경 기록](2026-10-04-driver-card-sections-r1.md)에 보존한다.

최종 Fast `20261004-093631`은 FDriverApp·시험 프로젝트 빌드 및 관련 15/15건이 통과했다. Task `20261004-093741`은 전체 빌드가 통과하고 6,315/6,322건이 통과했다. 기준 `20261004-033045`와 기존 7개 실패의 이름·오류·전체 스택 및 모든 시험 결과가 정확히 같아 새 실패는 없다. 전체 시험 게이트는 미통과다. 문서 검증은 별도 Fast로 기록한다.

최종 Debug APK의 보관본과 Android 설치본 SHA-256은 `ACF679341CF1F80FBAEB27713FAEACB24373573DA0B0DB1B5D5F9599194FDF51`로 일치한다. 설치본에서 기본 고객 요청·수령인 정보와 주문/배달료, 픽업 후 같은 건의 전달 행동, 완료 후 다음 건의 주소·수령인·배달료 자동 갱신을 확인했다. 두 건을 완료한 뒤에는 선택한 추천의 전달 주소와 수락 버튼을 표시했다. 이는 격리된 메모리 HTTP 자료를 사용한 실제 Android UI 확인이며 실제 서버/DB·배차 수행·지급 증거는 아니다.

320 DIP·글자 2.0의 최종 설치본은 본문 `[42,842][798,1511]`, 주요 버튼 `[42,1532][798,1695]`로 서로 겹치지 않았다. 초기 설치본의 본문 높이 12px와 구별한다. 양방향 스크롤로 전달 주소·고객 요청·수령인·주문 정보·상세 보기까지 확인했고 지도 범례와 현위치 버튼도 분리됐다. 최종 캡처는 새 추천 알림이 없는 상태이며 알림이 표시된 초기 실패 캡처를 최종 통과 근거로 사용하지 않는다. 원래 1080×2400·글자 1.0·density 420 설정을 복원했다.
