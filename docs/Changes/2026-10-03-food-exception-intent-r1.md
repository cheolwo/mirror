# 음식 배달 취소·현장 중단 연결과 신규 수신 분리 r1

주문자 취소, 기사 가게 도착·현장 중단, 운영자 중단 검토를 기존 서버 API에 연결했다. 기사에게 새 일을 받는 의사와 현재 배달을 수행하는 상태를 따로 표시하며 신규 수신 OFF로 운행이나 위치 전송을 종료하지 않는다. [페이지 책임·코드·API·DB](../ProjectOverview/page-docs/food-exception-intent-r1.md)는 다섯 업무의 입력과 권한을 분리한다.

## 변경 내용

- 주문 상세의 서버 허용 행동에 따라 `주문 취소 검토`를 표시한다. 사유·선택 주문 확인 후 명시 제출하며 성공·판본 충돌·응답 유실 뒤 같은 주문을 다시 읽는다. 같은 계정의 인증 복귀에는 초안을 보존하고 다른 계정·로그아웃·화면 이탈에는 이전 응답을 적용하지 않는다. 주문 내역의 바깥 셸도 인증 표시 계약을 소비한다.
- 기사 앱에 `가게 도착`과 독립된 `현장 중단` 입력 영역을 연결했다. 현재 시도 ID·revision과 준비/지연 시각을 보존한다. 불확실한 중단 결과는 같은 요청·같은 입력으로 재확인하며 다른 명령을 잠근다. 중단 뒤 기사가 큐에서 해제되더라도 원래 기사·주문·제안·요청·동일 사유의 재시도는 저장된 결과를 읽도록 서버 멱등 경계를 보완했다.
- 운영자 주문 추적에서 별도 중단 검토 영역으로 진입한다. 시도·판본·판정 근거를 확인하고 저장하며 추적으로 복귀할 때 같은 주문을 재조회한다. 보호 사유를 기사 책임으로 변경할 때 기존의 명시적 악용 확인 조건을 유지한다. 검토 저장을 지급·재배차 완료로 표시하지 않는다.
- `신규 배차 받기 ON/OFF`와 `운행 시작/종료`를 분리했다. 후보 추천·신규 제안 조회·수락은 명시 ON과 기록된 서버 수신 조건을 공통으로 검사한다. OFF나 조회 실패를 ON으로 간주하지 않고 서버 제한을 기사 의사로 덮어쓰지 않는다. 이미 수락한 배달의 허용 행동은 유지한다.
- 실제 food-only 서버의 공통 수신 API가 `FeatureBoundaryUnclassified`로404를 반환했다. 공통 Controller에 `OperationalDispatchCore` 실행 기능을 명시했다. 기존 유효 음식 OR 화물 조건의 파생 key이며 화물 선행조건·legacy aliases를 유지한다. 음식만 켠 환경에서 화물 API와 자동 작업은 계속 차단한다. 기존 Job·운영 모드·옵션 기본값을 바꾸지 않는다.
- 최종 생산30·시험12·시험 연결/지원3경로를 동결 소스45개에 결속했다. 신규94건은 주문자30·기사16·운영자20·수신 정책7·서버/후보6·실행 기능 경계15건이다. 기존 원장과 API contract를 사용하며 새 DB migration이나 요금·지급 정책은 추가하지 않는다.

요청 재시도·401/409·응답 유실·계정/화면 수명은 자동 시험 근거다. 실제 앱에서는 초기 시작 지연과 기사 첫 시작의 ANR 대기가 관찰됐다. 지도 키가 없어 실제 지도 타일은 검증하지 않았고, 만료된 추천 알림이 남는 기존 알림 문제도 관찰했다. 이를 실제 신규 추천이나 서버 수신 허용으로 해석하지 않는다. 원시 근거·최종45소스 일치·설치 지문·역할별 정본은 `artifacts/local/food-exception-intent-r1/verification-final.json`과 `runtime/`에 결속한다.

## 적용 경계

`dev/mirror-integration`의 기존 dirty 작업을 보존하며 이번 소스 지문·전후 사본·TRX·합성 실행 근거는 Git 제외 `artifacts/local/food-exception-intent-r1/`에 둔다. 제품 소스와 실행 근거의 변경 시점을 구별한다. 커밋·푸시는 하지 않는다.

배차 재탐색/만료 Job의 음식·화물 활성화 결속, 앱 밖 알림·전표 복구, 동결 요금 구성의 완료 정산 전달·당일 집계는 별도 후속이다. 격리 검증 서버는 Development/Simulation이며 기존 서버/DB와 영상/MYBOX는 변경하지 않는다. 실제 지도·물리 단말·모든 화면·운영 외부 연동·은행 지급은 이번 검증 범위가 아니다. 전용 서버·운영자 프로세스·ADB5351/9226 연결은 검증 뒤 종료하고 검증 DB 볼륨·설치본·원시 근거는 보존한다.

요청 키·작성 초안은 현재 페이지/프로세스 메모리에 보존한다. 앱 재시작 뒤 미확정 명령을 영속 복원하는 구현은 아니다. 주문자 직접 취소는 서버가 허용한 주문대기 범위이며 환불 완료와 별개다. 신규 수신 분리는 음식 배달의 현재 수행 경계를 검증하며 화물 업무 전수 동작까지 확대하지 않는다.
