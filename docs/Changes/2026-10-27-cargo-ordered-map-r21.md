# 수락한 다중 정차를 지도에서 안내하는 r21

2026-10-27. [직접 승인 범위](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-ordered-map.r21.md)와 [페이지 책임](../ProjectOverview/page-docs/cargo-driver-native-continuity-r64.md#다중-정차-지도-r21)에 따라 기존 기사 지도의 현재 한 건 표시를 저장된 미완료 정차 순서에 연결했다.

후속 실제 휴대폰 화면과 표시 보완은 [r22](2026-10-27-cargo-ordered-map-device-r22.md)에 별도로 기록했다. 아래 r21 당시의 미검증 범위는 당시 결과로 보존한다.

## 바뀌는 동작

- 서버의 저장된 수락 순서가 현재 활성 운송·다음 행동과 일치하면 첫 미완료 상차는 주황, 하차는 파랑으로 강조하고 이후 정차는 회색·번호로 표시한다. A를 먼저 수락했더라도 현재 순서가 `B 상차 → B 하차 → A 하차`이면 B 상차가 먼저 보인다. 2·3·4건의 교차 상하차를 같은 방식으로 처리한다.
- 완료 후에는 기존 정본 재조회가 완료한 정차를 제거하고 남은 첫 정차를 지정한다. 지도 핀/접기 선택으로 순서를 재정렬하거나 업무 완료를 생성하지 않는다. 기존 현재 운송 카드와 상세/길찾기 진입은 같은 다음 운송을 따른다.
- 전체 순서와 확인된 마감을 한국시간으로 펼쳐 볼 수 있다. 기본은 접고 높이를 제한해 지도 공간을 유지한다. 번호는 이번 응답에 남은 정차의 순번이다.
- 네이버·Google의 기존 공통 핀 정책을 재사용한다. 회색 연결선을 먼저, 현재 강조선을 나중에 그리고 다음 핀을 위에 놓아 겹침 때도 구분한다. 같은 좌표의 다른 정차를 업무 한 건으로 합치지 않는다.

## 데이터와 보류 경계

- 기존 작업공간 응답에 nullable 운송 ID·허용된 정차 좌표·원요청 시간창 시작과 저장 순서 반영/보류 상태를 추가했다. 기존 route·RuleRevision·저장 계약은 보존했다. ID는 현재 기사 목록의 유일한 실제 원장 ID로 대조하고 표시용 운송번호나 주소로 복원하지 않는다.
- 공개 보류·무ID·중복/목록 밖 ID에는 좌표를 제공하지 않는다. 범위 밖·영점·누락 좌표는 좌표쌍과 근거를 함께 비운다. 시작 시간은 일정의 예정 기준시각에서 추정하지 않고, 검증·공개 허용 상태에서 기존 원요청의 시간창 투영을 재사용한다. 구판·보류·원요청 시작 미확인은 null이다.
- 같은 계정·세션의 현재 조회만 지도 자료를 제공한다. 조회 중/실패·빈 결과·계정 변경에는 순서 snapshot을 비운다. 저장 순서 보류·ID/다음 행동 불일치·운송 진행 보류는 전체 강조를 지우고 재확인을 안내한다. 보류 코드가 없는 구판만 기존 현재 업무 표시를 유지한다.
- 좌표가 빠진 정차 앞뒤를 건너 연결하지 않고, 첫 위치가 비공개라는 이유로 다음 정차를 먼저 처리할 곳으로 승격하지 않는다. 현재 위치 지연 시 현재 위치에서 시작하는 강조선을 만들지 않는다.

## 경로의 의미

지도는 `수락 시 확인한 방문 순서`와 `지점 연결선 · 실제 도로 경로 아님`을 표시한다. r20의 약속·작업시간·적재·독차/혼적 검사를 통과한 기존 순서를 소비하며, 모든 기존 업무의 전역 최단거리·현재 시각 전체 ETA 재탐색이나 실제 도로 geometry를 새로 계산하지 않는다. 현재 위험과 마감, 수락 시 확인한 순서, 실제 운행 가능성은 별도다.
