# 주문자 음식 주문 상세 진입의 키보드 초점

320px Chrome 미리보기에서 가상 주문 네 건 중 마지막 주문 EX-1106-039를 Tab과 Enter로 열었다. 상세가 열린 뒤 본문 스크롤이 67px 남아 화면 제목이 가려졌고 키보드 초점은 본문으로 풀렸다. 주문번호와 **주문 목록**은 보였다. 320px·390px·1280px의 클릭과 키보드 진입 여섯 경우 모두 정확한 주문번호를 조회했고 목록에는 네 건이 돌아왔다.

[음식 주문 내역 페이지](../../OrdererApp/Components/Pages/FoodOrderHistory.razor)는 직접 고른 주문 번호가 상세 주소에 적용되면 기존 화면 제목으로 초점을 한 번 옮긴다. 로그인 화면, 목록 복귀와 재조회에서는 별도 초점 이동을 요청하지 않는다. 수정 범위는 주문자 앱의 해당 페이지다.

수정 후 격리 미리보기를 복제·빌드·실행하고 브라우저 검사를 돌리는 명령이 자동 승인 검토에서 차단됐다. 도구가 남긴 사유는 정책 차단이다. 수정 전 브라우저 캡처와 측정은 보존했고 [기존 README 대표 화면](../../README.md#음식-주문-목록에서-주문-찾기)은 이전 검증 판본을 유지한다.

주문자 앱 Fast 관련 시험 130개와 통합 1.5 Task 시험 17,051개가 통과했다. 별도 환경이 필요한 17개는 생략했다. 주문자 앱 빌드 경고는 0개, 통합 빌드 경고는 7개였고 두 빌드 모두 오류는 0개였다. 제품 서버·DB와 실기기 검증은 미실행이다.

수정 전·시험 근거는 artifacts/local/mirror-ui-assist/20261106T184628936Z-orderer-detail-entry/completion.json에 연결했다. 기존 브라우저 대표는 [배달 진행 표시 변경 기록](2026-11-06-orderer-detail-delivery-summary.md)에서 볼 수 있다.
