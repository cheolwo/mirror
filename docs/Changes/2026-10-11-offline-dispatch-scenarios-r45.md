# AI 가정형 오프라인 운영 시나리오 r45

사용자의 “차단은 풀지 말고 AI가 있다는 가정에서 여러 데이터를 가지고 시나리오를 돌려보자” 요청을 반영했다. [승인 설계](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/offline-scenarios.implementation.r45.md)와 [정확한 작업 범위](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/offline-scenarios.r45.work-order.json)를 따른다.

## 변경

- `eng/local-dispatch-ai/ScenarioRunner/`: 고정 합성 주문·기사 시간표, 실제 `음식배달수요참여Policy` 호출, 모의 AI 신호, 순차 수행 가정, 결과·재현·안전 검사.
- [실행 안내](../../eng/local-dispatch-ai/README.md)와 `run-scenarios.ps1`: 모델을 실행하지 않는 별도 진입점.
- 기획·현재 작업·변경 목차 연결. 앞선 r44 제품 구현·시험·실추론 차단 기록은 보존한다.

12가지 상황을 8가지 비교와 계획 처리량 3·3.5·4건/h로 조합한다. 120분 접수 후 120분 잔여 처리한다. 정확 모의 AI는 고정 미래 시간표를 아는 비교값이며 실제 모델이 아니다. OFF 비교도 가상 FIFO/최근 배정 횟수 기준이고 실제 서버의 거리·ETA 후보 선정을 재현하지 않는다. 실제 제품에서 기본 OFF인 수요 참여·자동 배차를 활성화하지 않는다.

## 검증

- 기존 서버의 정상 수직 업무·주문자 취소·운영 지연·중단 책임 검토 **61/61 통과**, 실패·건너뜀 0. r44 최종 Task가 빌드한 Debug 시험 DLL을 `--no-build --no-restore`로 실행했다. SQLite 상태·새 Context 복구·후속 Outbox와 모의 외부 서비스 시험이며 HTTP·실기기·실제 알림·입금의 증거는 아니다.
- 도구 빌드 **경고 0·오류 0**, 합성 **12개 사례·288개 비교** 실행, 내부 점검 **165/165 통과**. 모든 비교의 독립 재실행 결과 해시가 일치했고, 과소 예측·응답 없음·무효·만료의 관측 기준 동일성, 기존 적격 보호·동시 3건·주문별 단일 소속 보존을 확인했다. 이는 별도의 서버 시험 165건을 뜻하지 않는다.
- **213개 비교는 운영 검토 대상**이다. 배정 대기 10분 이상·모의 완료소요 45분 초과·미완료를 숨기지 않는다. 검사 통과는 시간 기준 만족이나 운영 안정성 보장이 아니다. 두 시간값은 탐색 가정이며 실제 메뉴별 SLA·자동 취소 설정이 아니다.
- 도구 내부 점검에서 기본 경계 사례가 없는 단일 합성 입력도 처리하도록 보완했다. 입력·정책·실행 파일·결과 해시별 `campaign/runs/`에 원본 입력 사본과 결과를 보존하고 최신 포인터만 갱신한다. 첫 비교도 `first-pass/`에 보존했다.
- 원시 결과: `artifacts/local/local-dispatch-scenarios-r45/`. 가상 비교와 기존 서버 시험을 독립 기록한다.
- 범위 Fast·Task는 각각 `validation/20261011-111453`, `validation/20261011-111648`에서 통과했다. 기존 검사기는 `eng/`를 지침 경로로 분류하므로 제품 빌드·시험을 생략한다. 이를 도구 빌드/시험으로 보고하지 않으며 위의 전용 .NET 빌드·모의 실행·서버 61개 시험이 별도 실행 증거다.
- 동일 근거로 다시 실행해 결과·보고서·입력 사본 3개 해시가 모두 유지됐다. 기존 r44 제품/시험 경로 13개는 내용 변경 0, 범위 밖 변경 0, 신규 문서/안내 로컬 링크 6개·공백 검사 통과. 모델 실행 도구와 기존 차단 기록도 보존했다.

## 발견한 운영 위험

정확한 미래량을 준 모의 AI도 관측 기준보다 배정 대기 p95가 개선된 조합은 **0/36개**다. 이 단순 순차 모형에서 예측을 넣었다는 이유만으로 효과가 생긴다고 볼 수 없다. 기사가 부족한 상황은 계획 처리량 3.5건/h에서 가상 4시간 뒤에도 14건 미배정·24건 미완료가 남았다. 긴 45분 순차 수행에서는 배정 대기는 0분이어도 신규 주문 완료소요 p95는 135분이었다. 실제 이동·멀티 경로를 재현한 값은 아니지만 **배정이 됐다는 사실과 제시간에 완료할 여력은 별도로 봐야 한다**는 반례다.

따라서 후속 검토의 우선순위는 예상 완료시간·현재 약속을 고려한 추가 제안, 기사 부족 시 접수 용량·약속 시간·대안 안내, 수요 과대 예측에 따른 기사 유입·기회 편중 비교다. 이번에는 해당 운영 설정이나 제품 코드를 자동 변경하지 않았다.

## 운영에 적용할 판단 순서

관측 수요와 미완료 업무를 먼저 사용하고 AI 예측이 낮아도 관측을 지우지 않는다. 응답 없음·무효·만료는 예측을 버리고 규칙으로 복귀한다. 수요 관측 자체가 누락되면 0건으로 간주해 신규 참여를 차단하지 않는다. 실제 적격·GPS·수신 의사·수행 상한과 픽업 적시성은 계속 별도 관문이다.

장기 대기 권고와 실제 주문 배정은 다르다. 기사 과잉 유입을 수요 참여 순서로 완화할 수 있는지 살피되 소득 보장으로 표현하지 않는다. 기사 부족·긴 수행시간에서 생긴 지연은 예측만으로 해소되지 않으므로 접수 용량·약속 시간·대안을 운영자가 검토해야 한다. 결과의 10분 검토 기준은 실제 SLA나 운영 자동 설정이 아니다.

## 하지 않은 작업

모델 시작·차단 해제·다른 추론 실행·네트워크/운영 API 호출·운영 DB 쓰기·외부 알림·실제 배차·운임/지급·제품 화면·Unity·APK·단말·Azure·배포·commit/push는 수행하지 않았다. 화면 변경 없음. 시나리오 통과만으로 플랫폼 실운영 안정성을 확정하지 않는다.
