# 화주 등록 준비 실패의 내부 오류 표시 보완

2026-11-04 정기 안정화 회차. 화물·주소·시간 조건을 작성한 뒤 최종 검토에 진입할 때 인증 또는 보호 저장소를 읽지 못하면, 내부 예외 원문이 화면 안내 뒤에 붙던 문제를 보완한다. 새 기능·화면 구성·서버 계약은 추가하지 않는다.

## 재현과 수정

[작성 화면 ViewModel](../../SsalddelApp/ViewModels/Shipper/ShipperRequestAuthoringPageViewModel.cs)의 `InitializeAsync`는 실패 시 입력과 재시도 경계를 유지하지만 `ex.Message`를 `StatusMessage`에 붙였다. [최종 검토 페이지](../../SsalddelApp/Components/Pages/ShipperRequestReviewPage.razor)는 이 문구를 공용 화면에 그대로 전달하므로, 저장소 예외에 내부 경로나 인증 관련 내용이 있으면 노출될 수 있었다. API 오류 정제와 별개인 초기화 경로다.

기존 안내에서 예외 원문만 제거했다. 등록 준비 실패·경고 표시·현재 입력 유지·같은 화면의 `등록 준비 다시 확인`·접수 미전송·기존 결과 우선 조회는 보존한다. 실제 저장소의 고장이나 간헐 서버 503을 고친 변경은 아니다.

[회귀 시험](../../Ssalddel.Tests/Clients/ShipperRequestSubmissionRecoveryTests.cs)은 실제 인증/보호 저장소 어댑터에 합성 읽기 예외를 주입한다. 접수 기록 읽기·초안 읽기·인증 복원 세 사례에서 원문 차단, 입력과 동의 체크 상태 보존, 동의 증적 미생성, 접수/조회/이동 미실행을 확인한다. 보호 저장소 두 사례는 같은 ViewModel의 재시도 뒤 정상 준비 복귀도 확인한다.

수정 전 실제 실행은 총12개 중 기존9개 통과·새3개 실패였다. 세 실패 모두 합성 원문이 안내에 포함된다는 동일한 재현 근거이며, 로그와 TRX를 보존했다. 수정 후 접수 복구·재실행 복구22/22개를 통과했다. 실패한 시도의 로그를 성공 결과로 덮어쓰지 않았다.
