# 창고 최초 조회 실패의 미확인 표시 r15

화주 창고 작업대의 첫 조회가403·통신 오류로 끝나거나 아직 로딩 중이면, 확인하지 못한 기본값을0건과 ‘주문 출고 알림 없음’으로 표시하던 문제를 보완했다. 기존 카드·경로·새로고침·조회 순서와 권한을 유지하고 최초 미확인 상태만 구분한다.

## 재현과 최소 교정

`ShipperOperationsWorkspace.razor`는 네 목록을 빈값으로 시작하고 채널 수를0으로 둔다. 첫 입고 조회에서 실패하면 이후 네 조회가 실행되지 않아도 메트릭·우선 업무 제목·빈 알림이 그대로 표시됐다. 서비스는 오류를 정상적으로 전달하므로 컴포넌트의 표시 상태 경계가 원인이다.

전체5조회가 완료된 뒤에만 `hasLoaded`를true로 만든다. 그 전의 네 메트릭과 업무 제목 숫자는 `—`로 표시하고, 출고 알림은 조회 중/확인 실패를 구분한다. 정상적으로 조회한 빈값은 기존0건과 빈 알림을 유지한다. 재조회 시작/예외에서 성공 상태를 지우지 않으며 기존 r13 버튼 스타일·중복 실행 보호·catch/finally를 보존했다. 새 페이지·기능·정책이나 카드 재배치는 없다.

정상 조회 뒤 첫 쿼리에서 재조회가 실패하면 이전 성공값을 유지한다. 여러 쿼리 중 일부만 성공한 뒤 실패할 때의 전체 원자 갱신은 기존 별도 문제이며 이번 수정으로 해결한 것으로 표시하지 않는다.

## 실제 컴포넌트 회귀와 앱 검증

기존 xunit 프로젝트를 Razor SDK로 바꾸거나 제품 계층을 옮기지 않았다. 비공개 로컬 검증기에 원본 Razor·원본 서비스 계약/모델을 명시적으로 링크하고 기존 HtmlRenderer와 합성 읽기 서비스를 사용했다. 실제 소스 SHA와 컴파일 어셈블리 metadata의 SHA를 대조했다. 새 패키지·실서버/DB 호출은 없다.

- 수정 전8사례 중5실패/3통과, 수정 후8/8통과·실패0이다. 첫403/통신 실패·뒤 조회 실패·미완료 로딩과 정상 빈값/수치·같은 컴포넌트의 명시 재조회 복구·기존 성공값 보존을 확인했다.
- 로딩 HTML은 첫 조회의 완료를 지연한 상태에서 캡처했고 새로고침 비활성과 조회1회도 대조했다. 완료 뒤 화면을 로딩 증거로 사용하지 않았다. 수정 전후 HTML각8개·빌드/실행 결과는 보존한다.
- 수정 후 소스/컴파일 SHA는 `ca40d351f15e27064d81b127db3585b29fdd0598e9d7cc85933091f2ab511b67`다. 로컬 검증기 빌드 오류0·기존 경고2이며 사례8개는 기존 xunit 통과 수와 별도로 기록한다.
- Fast `20261105-081835`: 화주 소비 앱 빌드 오류0·기존 경고20, 기존 표시/경로·창고 응답·홈 구성 회귀51/51통과·실패/생략0이다. 새 xunit 시험은 추가하지 않았다.
- Task `20261105-081931`: 현재 경로 계획의 `Ssalddel.v0.0.slnx` 빌드 오류0·기존 경고5, 전체16,957통과·환경17생략·실패0이다. 실제 TRX의 NotExecuted17개를 대조했고 이전 수를 승계하지 않았다. 새147 포장도 이 결과와 실제 Razor8사례·소스/SHA 일치를 요구했다.

## 검토용147 포장과 같은 서버 대조

새 화주147을 별도 출력에1회 포장했고 APK SHA는 `826dd17d768a541e13265ec35bdba82c714e3ee12649548c53910bb606f495bf`다. 선택 입력3614개 변경0·같은 검토용 package/서명·두 ABI·내장 앱 DLL·5378 endpoint를 대조했다. 실제 Razor 회귀 원문/컴파일 SHA·실제 Fast/Task TRX와 소스/SHA가 일치해야 포장이 시작되도록 묶었다. 포장과 설치/실제 기기 검증은 구분하며147은 미설치다. 같은 소스·완료 시험·정상 출력을 다시 생성하지 않는다.

같은 r14 재개 서버 PID12912/시작 UTC23:02:46과 현재 DLL·5378을 다시 대조했다. 이번 전후 실제 GET은 각각6/6 HTTP200이고 두 업무 proof의 SHA는 같으며 금융 행0이다. 같은 Simulation/격리 DB의 조회이며 서버·DB 재시작·초기화·로그인/토큰 갱신·업무 명령은 없다. 후속200으로 모든 과거503을 해결 처리하거나 합성 화면을 실제 기기 왕복으로 올리지 않는다.

## 기기·시각 검수의 제한

등록 단일 USB·공유 OS 잠금·현재146 설치 바이트/SHA·잠금 해제 상태는 읽기로 대조했다. 다른 전면 작업을 보존해 새 설치·앱 전환·화면 입력을 하지 않았다. 원시 UI나 스크린샷도 저장하지 않았다. 146은 이전 버튼 수정본이며 이번 새 표시의 기기 검증으로 사용할 수 없다.

화면 검수용 임시 정적 서버 실행은 자동 승인 검토에서 `blocked by policy`로 거절됐다. 같은 서버를 다른 경로로 재실행하지 않았다. CUA의 iab는 사용할 수 없었고 연결 브라우저 목록도 비어 있었다. 설치된 Chrome의 새 탭 창을1회 연 뒤 대상에 연결하는 단계에서도 Windows의 현재 브라우저 주소를 충분히 확인할 수 없어 Computer Use가 종료됐다. HTML 탐색·스크린샷 검수는 수행하지 않았고 이 회차에 UI/서버를 재시도하지 않는다. 초기 미연결과 후속 정책 중단은 각각 `preview-visual-blocker.json`·`computer-use-policy-stop.json`에 보존했다. 실제 Razor의 HTML 의미·상태 회귀를 브라우저 폭·전체 테마·실기기 화면 검증으로 확대하지 않는다.

기준 소스와 현재 회귀·기기 읽기·차단 근거는 `artifacts/local/app-stability-r15/a736274ee6e94c1dae6dfe8912aacfa7/completion.json`, `validation.json`, `render-regression-evidence.json`, `render-regression/baseline-result.json`/`revised-result.json`, `shipper147/proof.json`, `phone-readonly.json`, 두 시각 중단 기록을 따른다. 다음 한 가지는 새 기기/사용/인증/판본 확인 뒤 준비147의 데이터 보존 업데이트·최초 오류 표시·명시 재조회·홈 복귀 검증이다. 전체 안정화·출시·권한 있는 창고 데이터 조회 완료는 아니다. 실제 결제·정산·배차·운영·공개·commit/push는 실행하지 않았다.
