# 화물 약속·적재 조건을 지키는 B 우선 정차 r20

2026-10-27. [사용자 승인 범위](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-feasible-stop-order.r20.md)에 따라 수락 순서와 실제 정차 순서를 분리했다. 최종 개인정보 보류 연결 보완 뒤의 동일 판본 검증은 아래 표에 기록한다.

## 바뀌는 동작

기존 일정 삽입 평가가 B 우선 경로를 계산해도 추천 조회와 자동 큐의 A 완료 뒤 이어가기 필수 조건 때문에 후보가 제외됐다. 이제 전체 시간창·확인된 상하차 작업시간·실제 경로 옵션·혼적/독차·구간 적재를 함께 지키는 시도의 B 상차 ETA를 사용한다. 어떤 순서도 약속을 지킬 수 없거나 필요한 근거가 없으면 새 후보를 보류한다.

수락 직전에 최신 원장과 조건을 다시 검사한 typed 정차를 기존 JSON 근거에 보존하고, 재조회에서는 완료한 정차만 제외해 다음 행동을 선택한다. 순서 근거가 변경/손상됐으면 재확인을 안내하고 새 수락을 차단하며 기존 맡은 업무를 지우지 않는다. 상태·운임·상하차 시각을 정렬 수단으로 덮어쓰지 않는다.

예를 들어 이미 A를 상차했어도 `B 상차 → B 하차 → A 하차`가 A·B 모두의 약속과 적재 조건을 지키면 이 순서를 선택할 수 있다. 기존 모든 정차를 임의로 다시 섞는 전역 탐색은 아니며 기존 일정에 새 건을 연속·분리 삽입하는 범위다. 확인되지 않은 작업시간을 새 동적 경로의 0분으로 쓰지 않는다.

추천 지도는 실제 정차 근거가 없는 A→B 연결선을 생략한다. 추천 상세의 순서와 조건 변경을 재조회하고, 적재 주행이 섞인 접근 전체를 공차 또는 B만의 비용으로 표시하지 않는다. 차량은 기존 실차 조회의 유효제원 정책을 재사용하며 차종 제원만 있는 경우를 이번에 별도 실차 인증으로 승격하지 않는다.

## 기존 업무와 공개 보류 보존

- 수락·저장·일정 재조회는 같은 등록 차량 provider를 사용한다. 기본 DB 조회와 주입된 확인 경로가 달라 정상 수락을 막던 연동을 정리했다.
- 기존 분산 창고는 한 주문을 여러 거점에서 상차할 수 있으므로 일반 화물의 단일 상차 모델로 바꾸지 않는다. 같은 현재 Wave·기사·의뢰 지문·예약·거점·선택된 typed 계획을 확인한 전문 인계에만 기존 순차 수락을 보존한다. 일반 B 우선 경로나 미확인 0분 ETA의 인증을 만들지 않으며 원장 작업시간도 고치지 않는다.
- 분산 인계도 시간창·좌표를 현재 원요청/거점과 대조하고 모든 필수 상차 뒤 배송·배송 한 번·현재 차량 지문을 확인한다. 계획 변경이나 다른 Wave/기사로의 범위 확대를 허용하지 않는다.
- 작업공간의 경로 주소 가림은 표시용 운송번호가 아닌 현재 목록의 유일한 typed 운송 ID로 대조한다. 공개 보류·무ID·목록 밖 ID·중복 ID는 주소와 좌표 근거를 가린다. 별도 표시 번호가 있어도 공개 보류를 우회하지 않는다.
