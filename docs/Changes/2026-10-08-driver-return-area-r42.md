# 기사 기준 위치와 권역 복귀 우대 r42

기사 본인의 고정 기준점과 현재 GPS를 구분하고, 기존 전체 배달을 마친 뒤보다 추가 콜까지 마친 뒤 기준점에 더 가까워지는 후보를 우대한다. [사용자 승인과 구현 기준 r38](../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/driver-return-area.implementation.r38.md)을 따른다.

## 변경

음식 기사 앱의 `내 정보`에 복귀 기준점·끄기/자동/켜기·진입/해제 반경과 저장·재조회 행동을 추가했다. 현재 위치를 명시적으로 기준점으로 선택하고, 저장 응답이 끊기거나 계정이 변경되면 다시 조회하도록 한다. Web 운행 시작의 복귀 좌표와 서버 선호 코드도 분리했다. 전체 화면 지도와 현재 업무 카드는 유지한다.

설정은 기사 본인 인증과 판본을 확인해 보호된 Mongo 문서로 저장한다. 기준점을 공개 지도나 다른 역할 응답에 새로 제공하지 않으며 경로 실패 로그에도 정확한 좌표·원문 예외를 남기지 않는다. 기존 운송·주문·정산 원장은 별개다.

공통 평가를 화물 개인 추천·조율·연속 추천과 음식의 실제 큐에 연결했다. 음식의 차량별 전체 구간과 현재 조리 회차·최신 배달 시도·이미 픽업한 음식의 전달만 남긴 일정을 확인한다. 최대 3건과 기존 적격 조건을 유지한다. 화물의 활성 우대는 허용 후보 최대 40개를 평가한 뒤 10개를 선택한다. 새 정책을 선택하면 기존 복귀 점수를 중복 가산하지 않는다. 끄기 기본값과 확인되지 않은 경로의 가점 0을 유지한다.

## 검증

관련 집중 시험 184개와 최종 Fast 157개가 모두 통과했다. 최종 Task는 총 9,248개 중 9,235개 통과·실패 0개·환경 의존 기존 Mongo 시험 13개 미실행이다. 새 권역 복귀 설정의 실제 격리 Mongo 시험은 실행·통과했으며 초기 저장 경합·암호문 결속·판본과 GPS 재시도를 확인했다. 실제 지도 API 대신 시험 경로 응답을 사용한 평가 검증이며 공용 DB를 사용하지 않았다.

기존 소비 앱을 포함한 `Ssalddel.v3.5.slnx` 빌드와 음식 기사 Android 빌드가 성공했다. 최종 Task 빌드는 경고 55개·오류 0개, 별도 Android 빌드는 경고 36개·오류 0개다. 패키지 버전·기존 Android 알림 API와 nullable 등의 경고는 남아 있다. 실제 앱 화면이나 단말 실행 결과로 해석하지 않는다.

처음 집중 시험에서 찾은 시험 데이터의 숫자 형식·주문 키/이력 누락 fixture와 실제 조율 조회의 LINQ 호환 오류를 보완했다. 독립 검토에서 찾은 계산 중 설정 변경과 화물 구간 적재 미확인도 가점 보류 회귀로 추가했다. 첫 전체 Task의 개인정보 시험 실패는 기록 시각의 `010`을 전화번호로 오인한 검사였다. 원래 삭제 필드·금액/메뉴 보존 확인을 유지하고 실제 전화번호의 표준/숫자 표현을 검사하도록 바꾼 뒤 Fast·Task를 재실행했다. 최초 실패 로그를 보존한다.

소유 경로 45개, 그중 컴파일 관련 37소스의 SHA-256은 최종 검증 전후 동일했다. 처음 기록한 비소유 변경 파일의 지문도 대조한다. 이는 전체 저장소의 모든 경로를 새로 비교한 결과가 아니다. 결과·소유 경로·지문·격리 DB와 정리 기록은 Git 제외 `artifacts/local/driver-return-area-r42/`에 보관한다. 이전 시험 수를 이번 실행 결과로 재사용하지 않는다.

## 다음 단말 확인

1. `내 정보`에서 본인 설정 조회→현재 위치를 고정 기준점으로 선택→저장→다시 조회를 확인한다. 로그아웃·다른 계정 전환과 통신 실패에서 이전 비공개 값이 남지 않는지 확인한다.
2. 안전한 시험 위치에서 자동 진입/해제와 새 제안의 복귀 사유를 확인한다. 지도·운행 수신·기존 수락 업무가 설정 변경으로 바뀌지 않는지 대조한다.
3. 서버 지도 경로 설정과 차량 옵션을 확인하고 경로 실패·오래된 GPS에서 가점이 보류되는지 확인한다. 기존 화물·음식/화물 동시 수행의 미확인 적재/일정은 확인 완료로 표시하지 않는다.

## 확인 범위

자동 기본 7km 진입·6km 해제와 최대 20점·목표 개선 3km는 최초 보정값이다. 위치 오차와 최신 GPS·설정 판본을 확인한다. 실제 경로가 없으면 기준점까지 직선 참고값으로 가점을 확정하지 않는다. 지도에서 임의 기준점 선택은 이번 화면에 추가하지 않았으며 현재 위치를 선택한 뒤 고정 저장하는 방식이다.

음식/화물 공동 적재·일정은 [r36 후속 설계](../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/driver-flexible-multi-work.design.r36.md)로 남아 있다. 다른 유형의 진행 업무를 확인하면 복귀 우대 계산을 보류한다. 기존 화물 일정이 있는 경우도 선택된 경로의 구간 적재 근거가 연결되기 전까지 가점을 보류하며 차량 명세 누락도 확정 가점으로 바꾸지 않는다. 실제 휴대폰 화면·소리·GPS·지도·APK 설치·Azure·실운행·지급·Unity·영상·commit/push는 이번 구현의 완료 주장에 포함하지 않는다. 모바일 화면의 실제 캡처는 다음 단말 검증에서 남긴다.
