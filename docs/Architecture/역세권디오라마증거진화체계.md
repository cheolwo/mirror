# 역세권 디오라마 증거 진화 체계

- 판본: `station-diorama-evidence-evolution.r2`
- 적용 범위: 역 중심 공간 자료, 디오라마 조립, 생활 관찰 표현과 다른 역으로의 규칙 재사용
- 기획 승인: [사가정 기준 증거 진화 구현 r23](../AI/Planning/시스템/PLAN-SYSTEM-STATION-AREA-DIORAMA-MODULES/diorama-evidence-evolution.implementation.r23.md)
- 기계 대장: [`station-diorama-evidence-rules.json`](../../eng/execution-ledgers/station-diorama-evidence-rules.json)

## 목적과 경계

사가정역을 깊게 조사·구현하며 얻은 결과에서 재사용 가능한 규칙을 추출한다. 출처와 반례를 잃지 않고 면목역·용마산역과 이후 역에 적용하되, 한 역의 우연한 특성을 보편 법칙으로 과잉 일반화하지 않는다.

이 체계는 [E1~E7 수직 폐루프와 E8~E10 수평 증거 체계](E1-E7수직폐루프와E8-E10수평증거체계.md)를 확장하는 보조 계보다. 새 E 단계를 만들거나 E 성숙도를 자동 승격하지 않는다. 자료 확보, 개발 수용, Simulation 상태, Unity 표현, Play Mode와 Game View는 계속 별도 증거다.

## 세 기록

### 자료 출처 기록

`SourceReceipt`는 자료 한 묶음의 공급자·공식 링크·기준일·수집일·원본 hash·좌표계와 단위·권리·결손을 보존한다. 실제 원본이 비공개 `artifacts/local` 또는 로컬 DB에 있더라도 추적 가능한 비밀값 없는 공식 링크와 저장소 내 수집 기록을 남긴다.

- API key, 접근 token, 서명된 임시 URL과 개인정보를 기록하지 않는다.
- 원본을 확보하지 못했으면 hash를 만들지 않고 접근 실패나 미확보 상태를 보존한다.
- 자료의 이용조건이 Unity 모델링·배포 권리를 자동으로 허용한다고 해석하지 않는다.
- 플레이어 화면은 간결한 출처 요약만 제공할 수 있으며 전체 링크는 개발·검토용 증거 카드에서 조회할 수 있다.

공공자료의 실제 수집·저장·재조회 범위는 [게임 자료 조사 전문 운영](게임자료조사전문운영.md)의 D429를 그대로 따른다. 이 대장은 별도 수집 파이프라인이나 운영 DB를 만들지 않는다.

### 디오라마 규칙 후보

`RuleCandidate`는 관찰된 문제, 제안 규칙, 적용 범위, 예외·반례, 근거 출처, 관련 E 단계와 무효화 조건을 가진다. 상태는 다음 순서로만 진행한다.

1. `Observed`: 한 역에서 발견한 사실
2. `Candidate`: 반복 확인되어 재사용 가능성을 검토하는 후보
3. `ProvisionalSharedRule`: 사가정과 성격이 다른 역 한 곳 이상에서 검증하고 사람이 승인한 임시 공통 규칙
4. `AcceptedSharedRule`: 세 역 이상, 누락 또는 반례, 사람 검토를 모두 거친 승인 공통 규칙
5. `StationException`: 특정 역 Profile의 예외
6. `Superseded`: 새 판본으로 대체된 이력
7. `Rejected`: 보편화하지 않기로 한 이력

개발 에이전트는 `Observed`와 `Candidate`를 별도 승인 없이 기록할 수 있다. `ProvisionalSharedRule` 이상으로 승격하거나 공통 생성·조립·검사 동작에 적용하려면 명시적인 사람 승인 근거가 필요하다. 후보 수, 시험 통과 수나 관리 완료만으로 승격하지 않는다.

### 역별 증거 프로필

`StationEvidenceProfile`은 역 고유 식별자, 역할, 출처 기록, 관찰된 규칙 후보, 실제 승인 적용 규칙, 역별 보고서와 결손을 연결한다. 역별 건물 수·자료 hash·표현 범위·성능 예산은 이 프로필이 소유하고 공통 규칙에 고정값으로 복사하지 않는다.

### 디오라마 공간 기반 증거 확인

각 `StationEvidenceProfile`은 `spatialFoundationEvidenceChecks`에서 다음 세 종류를 정확히 한 번씩 평가한다.

| `evidenceKind` | 확인 대상 | 서로 대신할 수 없는 경계 |
| --- | --- | --- |
| `RoadAddress` | 화면 건물별 도로명주소 값 또는 후보·복수·미해결 상태 대장 | 주소 후보 수집은 공식 건물 동일성, 출입구, 배달 가능성을 증명하지 않는다. |
| `ParcelIdentifier` | 화면 건물에 연결된 PNU 등 필지 식별자와 중복을 제거한 필지 수 | PNU 문자열은 필지 경계 도형이 아니다. |
| `ParcelGeometry` | 식별된 필지의 실제 경계 원본·판본·좌표계·hash와 coverage | 건물 외곽이나 주소 점을 필지 도형으로 대체하지 않는다. |

`collectionState`는 `Collected / NotCollected / NotAssessed`, `coverageState`는 `Complete / Missing / Unassessed`를 사용한다. **수집 상태와 사용 가능 상태(`usageState`)는 별개다.** 모든 확인 항목은 `applicationAuthorized=false`를 명시하며, 사람 검토와 별도 소비 관문 없이 이 값이 참이 될 수 없다. `Collected + Complete`도 `PrivateReviewOnly`일 수 있으며 공개·Unity·배달·가격·업체 기능 승인을 만들지 않는다. `Complete`는 대상 전체에 값 또는 명시적 결손 상태가 기록됐다는 뜻이지 모든 대상에 확정값이 있다는 뜻이 아니다.

평가한 Profile은 대상 수, 상태 대장 수, 값이 있는 대상 수, 결손 대상 수, 서로 다른 값 수, 상태별 수량, 출처 기록과 제한을 함께 보존한다. 평가하지 않은 역은 숫자 0을 만들지 않고 `NotAssessed / Unassessed / Unassessed`와 `null` 수량을 남긴다.

현재 동결 판정은 다음과 같다.

| 역 | RoadAddress | ParcelIdentifier | ParcelGeometry |
| --- | --- | --- | --- |
| 사가정역 | `Collected / Complete / PrivateReviewOnly`, 화면 건물 상태 4,062/4,062, 원시 필지 주소 후보 단일 3,796·복수 60·없음 206 | `Collected / Complete / PrivateReviewOnly`, 건물 4,062/4,062, 서로 다른 PNU 3,774 | `NotCollected / Missing / Blocked`, 필지 도형 0/3,774 |
| 면목역 | `NotAssessed / Unassessed` | `NotAssessed / Unassessed` | `NotAssessed / Unassessed` |
| 용마산역 | `NotAssessed / Unassessed` | `NotAssessed / Unassessed` | `NotAssessed / Unassessed` |

사가정 도로명주소 근거는 행정안전부 2026-08 건물DB·관련지번, 필지 식별자 근거는 브이월드 `AL_D010` A2 PNU다. 2026-09-14에는 연속지적 `AL_D002`의 A1 PNU·EPSG:5186 계약과 서울 전체자료 2026-09-08 판본을 확인하고 결정적 추출·coverage 감사 도구를 준비했다. 그러나 브이월드 로그인 제약으로 실제 SHP 원본을 수집하지 못했으므로 `BlockedExternalAccess`, `ParcelGeometry NotCollected / Missing`을 유지한다. metadata·컬럼 정의서·synthetic SHP 시험은 실제 경계 원본을 대신하지 않으며, 이 준비는 기존 12개 규칙 후보나 E 단계를 승격하거나 적용 승인하지 않는다.

## 개발 작업 종료 순환

역세권 디오라마 자료·조립·표현을 변경한 에이전트는 작업 종료 전에 다음을 판정한다.

1. 이번 작업이 추가·강화·약화·무효화한 증거를 식별한다.
2. 공식 링크, 기준 시각, 실제 확보 hash와 권리 상태를 기존 또는 새 `SourceReceipt`에 연결한다.
3. 새 반복 패턴이 있으면 `Observed` 또는 `Candidate`로 기록한다.
4. 기존 규칙의 지지 근거와 반례·예외를 함께 갱신한다.
5. 영향을 받는 Logic·Presentation E 단계를 적되 자동 승격하지 않는다.
6. 승격 또는 실제 공통 적용이 필요하면 사람 검토 대상으로 반환한다.
7. 새 후보가 없으면 종료 보고에 `새 디오라마 규칙 후보 없음`을 명시한다.

후보 등록은 구현 범위를 자동으로 넓히지 않는다. Scene·Prefab·서버 계약·수집·DB·배포·commit·push는 각각 현재 요청의 권한을 다시 따른다.

## E 증거와 연결

| 단계 | 디오라마 보조 증거 |
| --- | --- |
| E1 | 관찰 약속, 권위 경계, 안정 식별자와 출처 기록 참조 |
| E2 | 수집기·변환기·Profile·Host·Adapter 구현과 규칙 참조 |
| E3 | 동일 입력 결정성, hash, 오래된 자료·교차 역 fallback·변조 거부 |
| E4 | 역·모듈·시간·H·자료 출처·시각 fallback 후보 결속 |
| E5 | 같은 revision의 권위 상태 사본과 실제 World 표현 객체 결속 |
| E6 | 사람이 공간 타당성·판독성·권리·개인정보·성능·반례를 검토 |
| E7 | 실제 입력, 저장 Scene, Game View에서 결과·회복·귀환 검증 |
| E8 | 동결된 자료·규칙·Profile hash로 반복·저장·재진입 검증 |
| E9 | 한 역 안의 둘 이상 E8 생활 폐루프가 논리·표현에서 조화를 이루는지 검증 |
| E10 | 동결 빌드 제한 관찰과 출처 만료·갱신 영향 감시 |

여러 역이 렌더링된 사실은 E9가 아니다. 역 간 재사용성은 `CrossStationConformance` 관점으로 검사하고, 각 WI의 Logic·Presentation 성숙도와 분리한다.

## 교차 역 승격 관문

- 사가정 단독 결과는 최대 `Candidate`다.
- `ProvisionalSharedRule`은 사가정과 구조가 다른 한 역 이상의 지지 또는 반례 검토와 사람 승인이 필요하다.
- `AcceptedSharedRule`은 세 역 이상, 누락 또는 반례가 존재하는 표본 하나 이상, 명시적인 사람 승인이 필요하다.
- 역 이름·건물 수·원본 hash·자료 수량이 공통 규칙에 들어가면 역 Profile로 돌려보낸다.
- 다른 역 자료를 fallback으로 사용하거나 결손을 실제 공터·높이·통행 가능성으로 바꾸는 규칙은 승인 후보가 될 수 없다.

## 현재 자동 검사 상한
