# 역할 앱 시각 디자인 기준

2026-10-16 r8. 사용자 요청은 **기존 내용과 기능을 유지하면서 모던하고 단순하며 쓰기 편한 화면으로 다듬는 것**이다. 이 문서는 색·글자·여백·표면·상호작용 표현의 기준이다. 업무 목적·정보 공개·독립 업무 분리는 [페이지 단일 책임 기준](WholeRoadmapPagePrinciple.md)이 소유한다. 단순한 색·여백 변경을 이유로 새로운 기능·설명·요약 수치를 추가하지 않는다. 사용성 보완에서 필요한 입력·실패·다음 행동 안내는 기존 상태와 책임 카드에 근거해 제공한다. r2는 일반적인 UI·UX 용어를, r3는 정보 섹션 구분을, r4는 세 카드 구성을, r5는 수행 단계별 정보와 접기/펼치기를, r6는 카드 정렬을, r7는 사용자가 정한 기사 화면의 고정 글자 크기를 적용한다. r8은 공식 자료를 다시 확인해 첫 이용·입력 보존·복구·정확한 완료 표시 기준을 보완하며 r7의 사용자 선택을 되돌리지 않는다.

## 화면 문구와 설명

2026-10-21 사용자 후속 요청: 화물 기사·화주 수행 화면은 **현재 상태·핵심 값·다음 행동**을 짧게 표시한다. 제목과 같은 설명, 정상 조회 알림, 내부 화면 번호·원장 ID·구현 설명은 기본 화면에서 제외한다. 확인 항목은 `주소 확인`, `화물 수량·외관 확인`처럼 대상과 행동을 남기며 아이콘만으로 바꾸지 않는다. 오류·미확정 결과·필수 사진/동의·테스트 결제와 실제 지급 구분은 짧고 정확하게 유지한다. 사용자 행동의 성공 결과까지 정상 조회 알림과 함께 숨기지 않는다. 이번 적용 범위와 실제 확인 상태는 [화물 핵심 문구 r1](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-concise-ui.r1.md)을 따른다.

화면 설명에는 **지도, 현재 배달 카드, 배달 목록, 상세 정보, 주요 버튼, 접기·펼치기**처럼 사용자가 화면에서 확인할 수 있는 말을 쓴다. 기사 업무는 **현재 배달, 픽업 장소, 전달 장소, 배달료, 수령인, 전달 요청**으로 설명한다. 완료 알림은 “음식을 픽업했습니다”, “전달을 완료했습니다”처럼 결과를 바로 말한다.

예시 화면의 배달 제목·음식점명·수령인·완료 알림에 “합성 검증”, “fixture” 등 개발용 표시를 반복해서 붙이지 않는다. 예시 값은 “배달 1”, “음식점 1”, “픽업 장소 1”, “전달 장소 1”, “수령인 1”로 표시한다. 예시 데이터의 출처와 검증 상태는 문서·내부 메타데이터에 보존하며, 결제·입금·오류에 필요한 사용자 안내는 유지한다. 코드 식별자·API 필드·실제 주문 기록을 표시 문구 변경으로 바꾸지 않는다.

## 예외 안내와 업무 복귀

2026-10-21 사용자 후속 요청에 따라 긴 빨간 기술 오류를 기본 업무 화면에 반복 나열하지 않는다. 알려진 조회 장애는 짧은 중립 안내 창과 명시적 재조회/기존 업무 복귀를 제공한다. 닫은 뒤에는 간단한 미완료 상태와 안내 다시 열기를 남기며, 같은 배경 갱신 실패로 창을 반복하지 않는다. 여러 공통 CRUD 조각이 있는 화면은 모달이 겹치지 않도록 수동 안내 열기를 기본으로 사용할 수 있다.

조회 실패·입력 오류·명령 결과 미확정을 구분한다. 입력 검증은 해당 입력 옆에 유지하고, 사진·입고·신고·결제 등의 결과 미확정은 같은 요청의 결과 확인을 우선한다. 안내 창을 닫았다고 성공 처리·초안 초기화·자동 POST 재시도·강제 홈 이동을 하지 않는다. 모달을 표시할 때 필요한 업무 경고와 실제/테스트 구분까지 숨기지 않는다. 이번 조사·적용·단말 범위는 [역할 앱 오류 복구 r1](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/role-error-recovery.r1.md)을 따른다.

1. **현재 상태 → 필요한 정보 → 다음 행동** 순서로 읽히게 한다. 빈 목록·기능 준비 중·권한 부족·조회 실패를 각각 설명하고 가능한 복귀/재시도를 남긴다. 로딩 중에는 로딩을 실패처럼 표현하지 않는다.
2. **완료와 준비 상태를 사실대로 표현한다.** 서버나 본인 확인 근거 없이 확인 완료·저장 완료·접수 완료를 표시하지 않는다. 현재 앱 세션 안에서만 유지되는 초안은 재실행 뒤에도 저장되는 것처럼 이름 붙이지 않는다.
3. **사용자에게 내부 구현을 풀게 하지 않는다.** FeatureKey·OAuth·FCM 토큰·API·원시 예외·원장 ID 설명은 현재 과업 판단에 필요한 경우만 전문 상세에 둔다. 기능/권한·미확정 결과·모의/실금융 구분과 중요한 경고는 유지한다.
4. **입력과 문맥을 보존한다.** 주기적 갱신으로 컴포넌트를 새로 만들어 사용자의 검색/필터/작성을 초기화하지 않는다. 불명확한 전송은 같은 요청 결과 확인으로 복구하며 무조건 재전송하지 않는다.
5. **주 행동을 찾기 쉽게 한다.** 동일한 목적의 보조 이동은 낮은 강조로, 현재 상태를 완료하는 행동은 명확한 동사와 기존 아이콘으로 표현한다. 기사 추천의 파랑 거절·주황 수락, 지도 위 독립 카드와 고정 글자 크기는 기존 사용자 결정대로 유지한다.
6. **코드 목록 확인과 실제 사용 검증을 나눈다.** 전체 route 목록은 누락을 찾는 도구다. 대표 과업의 로딩/빈/오류/성공과 320/390px·뒤로/복귀를 실제 렌더에서 확인하고, APK·단말·운영은 별도 증거로 남긴다. 대표 화면은 [시각 변경 기록 원칙](../Changes/README.md#기록-원칙)에 따라 코드 판본과 함께 보존한다.

| 포커스/모션 | 진한2~3px outline, 짧은 상태 전환 | 보이는 포커스. WCAG의 특정2px/3:1 AAA 규격을 AA 요구로 오인하지 않음 |

네이티브 기사 메인은 지도와 업무 패널을 함께 쓰므로 페이지20·섹션16·핵심 값18의 압축형 예외를 적용한다. 본문16·보조14·버튼14는 유지한다. Web 줄높이는 CSS/MudTypography가 소유하고 네이티브는 플랫폼 글자 측정을 사용하므로 CSS의 줄높이 수치를 네이티브 구현 완료로 취급하지 않는다. 필수 입력 경계는 `#788C97`로 흰 표면뿐 아니라 중립 캔버스 위의 대비도 확보한다.

기사의 긴 주소는 일반 굵기·본문16·왼쪽 정렬·줄바꿈/줄높이1.15로 읽고, 상태·제목·금액과 강조를 분리한다. 2026-10-04 최신 사용자 요청에 따라 FDriverApp의 Driver 글자/버튼/입력 스타일은 `FontAutoScalingEnabled=False`로 정해진 DIP 크기를 유지한다. 페이지20·섹션/본문/입력16·보조/버튼14·금액18은 유지하며 앱의 지도 상태 안내도 Android DIP14로 표시한다. 이 요청은 r6의 기사 글자 자동 확대 유지 기준을 대체하며 다른 앱의 확대 정책은 바꾸지 않는다. 긴 주소를 생략하지 않고 필요한 본문 스크롤은 유지한다. 접힌 업무도 흰 카드 표면과 동일한 내부 여백16을 사용하고 상태 제목은 카드 안에 둔다. 지도 도구는 실제 타일 준비 상태에서만 표시해 로딩/오류 안내를 가리지 않는다. [글자 크기 책임](../ProjectOverview/page-docs/driver-workspace-sections-r1.md#고정-글자-크기-r7--사용자-후속-기준)과 [변경 기록](../Changes/2026-10-04-driver-fixed-font-r1.md)을 따른다.

## 나열감을 줄이는 구성 규칙

2026-10-08 최신 사용자 정정에 따라 FDriverApp의 배달 수행 지도는 전체 수행 영역을 채우고, 기존 상태 카드는 그 위 하단에서 독립적으로 접었다 펼친다. 카드 높이로 지도 크기·중심·줌·SDK 여백을 조정하지 않으며 카드 뒤의 핀/경로 가림을 허용한다. 투명한 상단/도구의 빈 공간은 지도 입력을 통과시키고 실제 버튼과 카드만 입력을 받는다. 내 정보·완료 내역·현장 중단의 독립 문맥, 기존 상태별 주 행동·본문 스크롤·지도 준비/오류 안내는 유지한다. 이 배치 규칙은 네이티브 기사 수행 화면만 적용하며 [페이지 책임 r10](../ProjectOverview/page-docs/driver-workspace-sections-r1.md#전체-화면-지도와-독립-하단-카드-r10--최신-사용자-정정)이 소유한다.

맥락이 다르면 **짧은 섹션 제목·얇은 중립 구분선·여백**으로 구분한다. 기사 수행 카드는 수락한 현재 건에만 표시한다. 픽업 전에는 음식점·픽업 주소·주문을, 픽업 후에는 전달지 → 고객 요청 사항 → 주문 정보의 세 카드를 표시한다. 전달 단계의 고객 요청은 주문의 보조 상세 접기와 관계없이 읽고 실제 수령인·관계·연락처는 같은 카드의 수령인 정보로 묶는다. 제목과 구분선도 정보의 가시 조건을 따라 빈 섹션을 만들지 않는다. 업무 전체를 접어도 현재 목적지 요약과 고정 주 버튼은 유지하며 오류를 숨기지 않는다. 다른 배달 목록을 넣지 않고, 완료 후 다음 건의 정보로 갱신한다. 카드별 독립 스크롤은 만들지 않고 하나의 본문 스크롤을 유지한다. 카드 안의 각 섹션을 다시 카드로 감싸지 않는다. 수행 상태·권한·접기 복귀 기준은 [페이지 책임 카드](../ProjectOverview/page-docs/driver-workspace-sections-r1.md#수행-단계별-하단-카드-r5--구현-전-책임-카드)가 소유한다.

1. **여백으로 그룹화한다.** 같은 주문 안의 메뉴·금액·상태는 가까이 놓고 다음 주문과 간격을 둔다. 같은 목록에 큰 외곽 카드와 큰 내부 카드를 반복 중첩하지 않는다.
2. **강조를 배분한다.** 제목은 짧고 분명한 크기, 금액은 숫자 축, 식별자/시각은 차분한 보조 글자다. 현재 선택/주 행동/오류만 명확하게 강조한다.
3. **표면을 절제한다.** 밝은 중립 배경과 흰 표면, 약한 경계가 기본이다. 그라데이션·강한 그림자·색상별 큰 배경 상자를 줄인다. shadow 제거가 dialog/메뉴의 가림 순서를 바꾸면 안 된다.
4. **행동과 상태는 보존한다.** 버튼 문구·활성 조건·로딩·재시도·오류·수령/정산·개인정보 접기는 유지한다. 조회 실패를 빈 목록으로 바꾸거나 unknown을0으로 채우지 않는다.
5. **단순한 시각 변경과 수행 흐름 변경을 구분한다.** 시각 변경만으로 기능 통합·정보 삭제·새 접기/탭·route 변경을 하지 않는다. 사용자가 수행 단계별 정보나 접기를 요청하면 페이지 책임 카드에 기본/보조 정보·상태·복귀를 먼저 정하고 적용한다.

## 코드에서 참조할 위치

업무 오류는 기존 실패 계약의 OS·단계·처리 결과·허용 복구 행동을 역할별 문구와 표시 방식으로 변환한다. 내부 코드·raw 응답을 제품 본문에 출력하지 않으며, 조회 실패와 실제 업무 거절·결과 미확정을 구분한다. 단계별 구체 기준과 적용 상태는 [업무 단계·예외·복구 대응표](../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/domain-workflow-recovery.matrix.r2.md)가 소유한다. 화면이 도메인 상태를 새로 판정하거나 완료 명령을 자동 재전송하지 않는다.

| 소비 지점 | 토큰/표현 소유 |
| --- | --- |
| 주문자·음식점·관리자 역할 MAUI | `Ssalddel.Ui.Common/Areas/App/Theme/RoleAppTheme.cs`, `wwwroot/Areas/App/css/role-app-foundation.css` |
| 관리자 웹 | `Areas/BackOffice/Theme/BackOfficeTheme.cs`가 같은 팔레트/글자 체계를 재사용. 실제 호스트의 `SsalddelAdmin/wwwroot/app.css` |

Figma `01 Community`와 `SsalddelApp` Community는 [호환성 정책](FigmaMauiCompatibilityPolicy.md)의 별도 대상이다. 이번 역할 업무 앱 변경을 그 디자인 적용 완료나 Figma 동기화로 보고하지 않는다. 기존 Community 전용 테마/배치/route는 보존한다.

## 적용과 검증

먼저 공통 토큰과 실제 소비 shell을 적용하고 주문자 음식 내역, 음식점 수신함/상세, 기사 메인/정산, 관리자 음식 추적을 대표 화면으로 확인한다. 공통 테마 상속과 각 페이지 수동 정리/실제 검증은 별개다. 전수 페이지 준수 완료를 선언하지 않는다.

변경 전후에는 문구·바인딩·행동/조건·API/DB·금액이 보존됐는지 대조한다. 실제 소비 앱과 웹의 좁은 폭·긴 식별자·빈/로딩/오류/비활성 상태, 키보드 포커스, 스크롤/고정 navigation, 확대를 검증한다. PNG·APK·소스 판본과 남은 제한은 해당 `docs/Changes/` 및 상세 적용 문서에 기록한다. 소스 검사·build·브라우저 렌더·Android APK·물리 단말·실운영 증거를 구분한다.
