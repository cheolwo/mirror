# 통신판매 중개와 개인정보 보호

미러의 사업자 음식 거래와 개인 생활 거래에 공통으로 적용하는 서버·화면 기준이다. 기능 무료 제공과 당사자 직접 지급을 유지하며, 판매자 확인·정보 최소 공개·분쟁 처리·개인정보 권리 요청을 거래 흐름에 연결한다. 현재는 로컬 구현과 검증 단계다. 실제 신원기관, 운영주체 정보, 법적 검토와 보존 전체 목록이 준비되지 않은 `Operational` 환경의 새 거래는 차단한다.

## 법령과 적용 범위

2026년 10월 6일 기준 전자상거래법 제20조·제20조의2는 중개 사실 고지, 사업자 판매자 신원 확인·제공과 불만·분쟁 조치에 관한 기준이다. 약관의 면책 문구만으로 플랫폼 자신의 의무를 없애지 않는다. 결제나 주문을 실제로 맡는 범위에 따라 제20조의3 등을 검토하며, 직접 계좌이체 또는 무료 플랫폼이라는 이유로 일괄 적용 제외하지 않는다. [전자상거래법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=282793), [중개자 책임](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000466758).

2026년 7월 21일 시행된 제20조의4는 개인 판매자 신원 확인, 개인·사업자 구분 표시, 이용 가능한 결제대금예치 안내·권고와 분쟁 해결 협조를 다룬다. 개인 신원은 공개 닉네임 화면에 노출하지 않는다. 분쟁조정기구·법원의 적법한 요청 또는 판매자가 동의한 소비자 제공을 각각 검토한다. 전화번호와 이메일 확인 또는 지정 본인확인기관 보유 정보에 관한 시행령 제25조의3 조건은 실제 인증기관 연결에서 검토한다. [개정 원문](https://law.go.kr/LSW/lsRvsDocListP.do?lsId=009318), [시행령 제25조의3](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=03&joNo=0025&lsiSeq=288143&urlMode=lsScJoRltInfoR).

분쟁 진행 경과 3영업일, 처리방안 10영업일 통지는 접수 확인과 구분한다. 법령상 영업일은 실제 공휴일 달력을 반영해야 한다. 달력이 검증되지 않으면 기한은 잠정값으로 표시한다. [시행령 제25조의2](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=63492).

개인정보보호법 제17조의 제공, 제26조의 위탁, 제28조의8의 국외 이전은 실제 처리 경로별로 판단한다. 업무 수행에 필요한 수집·이용 근거가 모든 제3자 제공을 자동으로 허용하지 않는다. 정보가 불필요해지면 제21조의 파기를 적용하고 별도 법정 보존은 분리한다. 처리방침은 제30조에 따라 실제 항목·목적·기간·수신자·권리 절차를 반영해야 한다. [개인정보보호법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=283839), [파기](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1033214873), [국외 이전](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=08&joNo=0028&lsiSeq=283839&urlMode=lsScJoRltInfoR).

개인정보 유출 또는 유출 가능성을 인지한 사건은 사실관계와 통지·신고 요건을 검토한다. 실제 대상자 통지와 감독기관 신고는 준비된 문안과 다른 증거다. 72시간 기한과 신고 규모·민감정보·고유식별정보·외부 불법 접근 기준은 사건별로 검토하고, 오인한 유출 가능성은 정정 이력을 남긴다. [제34조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034293621), [시행령](https://law.go.kr/lsLinkCommonInfo.do?lspttninfSeq=67073).

접속기록은 현행 안전성 확보조치 기준의 1년 또는 해당 요건 충족 시 2년 보존과 월별 점검을 적용한다. 2026년 10월 31일 시행되는 제8조 제1·2항 변경의 접근자 범위도 옵션에 시점을 기록했다. 자신의 정보만 조회하는 정보주체의 예외와 실제 개인정보처리시스템 범위는 운영 목록에서 구별한다. [안전성 확보조치 제8조와 부칙](https://www.law.go.kr/LSW/admRulSideInfoP.do?admRulSeq=2100000281400&chrClsCd=010201&dashNo=&docCls=jo&joBrNo=00&joNo=0008&urlMode=admRulScJoRltInfoR).

## 화면과 서버의 책임

| 화면 또는 절차 | 서버 책임 | 저장과 권한 |
| --- | --- | --- |
| 홈과 `/commerce/notices` | 버전이 있는 중개 안내·약관·처리방침·운영 준비 조회 | 안내는 공개, 운영주체 값 미설정은 준비 미완료 |
| `/commerce/seller` | 개인·사업자 등록, 현재 프로필에 결속된 외부 확인 결과 검사 | Mongo `commerce_seller_verifications`의 프로필·확인 원문 보호 저장, 본인만 수정 |
| 음식 주문과 생활 거래·배송 신청 | 현재 안내 확인, 성년·판매자 자격을 원장 저장 전에 검사 | `commerce_transaction_disclosures`는 최초 사전 확인 증거이며 거래 성립 증명이 아님 |
| `/commerce/disputes` | 자신의 원장과 연결한 접수·목록·이의제기 | 상대방에 비공개 증거·개인 주소·연락처를 반환하지 않음 |
| `/commerce/privacy` | 열람·정정·삭제·처리정지 등 권리 요청 접수 | 실제 실행 증명이 없는 완료 처리 금지 |
| 운영자 지원 API | 담당자 배정, 진행·처리방안 준비, 실제 통지 증거·사고 판단 | 서버 운영자 정책과 담당자 일치 확인, 원문 열람 사유·감사 저장 필수 |
| 보존·파기 worker | 기한·보존 중지·재시도·복원 차단 | 정확한 원장 ID와 허용 필드만 처리, 금융 사실 보존 |

공통 UI를 통합 앱·웹과 주문자·음식점의 얇은 경로 페이지에서 사용한다. 기존 역할 업무·로그인·지도 상태를 새 법률 안내 페이지로 합치지 않는다. 음식 주문은 서버 음식점 ID에 연결된 계약 판매자를 조회한다. 개인 거래의 공개 판매자 응답은 표시명·유형·확인 상태로 제한하고, 검증된 사업자 응답만 사업자 공개 정보를 포함한다.

진행·결과 통지 증거는 현재 안내문과 검토 주기에 결속한다. 문안 또는 사고 판단 범위가 바뀌면 과거 증거로 현재 처리 완료를 인정하지 않는다. 사건 접수·명령의 멱등성은 보존 중인 원장에 적용한다. 사건의 물리 파기 이후 같은 접수 번호가 영구 중복 차단된다고 주장하지 않으며 다시 접수할 때에는 새 원장 당사자 검증을 수행한다.

새 신청은 만 19세 이상으로 제한한다. 나이 체크박스나 역할 선택은 인증 증거가 아니다. `I거래신원확인Gateway`의 기본 구현은 미연결이며, 확인 참조의 계정·현재 시각·유효기간·연락처·프로필 해시를 검사한다. 프로필 변경 시 기존 인증은 해제한다. 이미 접수된 음식 주문의 같은 요청 재조회, 기존 판매 종료·철회, 협업 취소는 새 거래 자격 차단과 구분한다.

과거 익명 게시글의 비밀번호 수정 권한은 판매자 확인 권한이 아니다. 운영 판매 글의 발행·수정에는 확인된 계약 판매자가 반드시 연결돼야 하며 판매자 없는 기존 글을 활성 판매 글로 전환하지 않는다. 판매자가 없는 생활 배송 신청의 성년·안내 확인은 이 판매 게시 요건과 구분한다.

## 보존과 파기

법정 거래 기록은 플랫폼이 실제 처리한 기록의 종류에 따라 구별한다. 표시·광고 6개월, 계약·철회 및 대금결제·공급 5년, 소비자 불만·분쟁 3년 기준을 모든 원시 고객 주소·GPS의 일괄 보존 기간으로 쓰지 않는다. [거래 기록 보존](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=63460).

현재 파기 adapter는 음식·생활 배송의 완료 후 업무 개인정보, 기사 위치, 접속 감사 기록을 다룬다. 기존 사용자 확인에 따른 완료 업무 상세 3일 열람 정책은 별도다. 금융·배달료·거리·정산 사실과 개인 주소록을 일괄 삭제하지 않는다. 정해진 원장·투영·원문 필드를 처리하고 Mongo 원장의 오래된 재저장과 대기 중 투영 재실행을 manifest로 차단한다. 기사 위치는 과거 기록의 기본 1일 기준이며 최신 1점은 유지한다. 위치 사용 목적이 끝난 계정 전체 삭제와 같지 않다.

음식 원장·배달 시도·연결 운송·상태 이벤트·outbox 및 정확히 결속된 Mongo 원장의 허용 개인정보 필드가 현재 대상이다. 생활 배송은 의뢰 prefix와 정확한 연결 관계를 추가 검사한다. 불변 배차 판단 감사와 아직 포함되지 않은 다른 사본은 전체 목록 검토 대상이다. 처리 중인 outbox·투영 또는 정확한 원장 부재는 파기 완료로 단정하지 않고 보류한다. SQL 파기와 Mongo marker의 교차 저장소 복구도 재시도 결과로 확인해야 한다.

파기에는 재시도 상태, 작업 임대, 원장별 보존 중지 사유·재검토 기한·사건 ID를 둔다. 활성 객체 부재와 클라우드 버전·백업의 부재는 별도 결과다. Azure·Google의 단일 객체 삭제가 과거 버전 또는 백업의 삭제를 뜻하지 않는다. 소유한 정확한 객체 prefix 밖의 삭제는 허용하지 않는다. 실제 복원 절차에서도 manifest 재적용을 검증해야 한다.

사건의 보존 중지·해제는 사건 원장의 적용 대기 CAS, 외부 원장의 사건별 순번·내용 지문 확인, 실제 적용 재조회, 사건 완료 CAS 순서로 처리한다. 해제 뒤에도 확인 기록을 유지해 늦은 과거 보존 중지 요청이 다시 적용되지 않게 한다. 결과가 미확인이면 적용 대기와 파기 차단을 유지하며 같은 요청과 worker로 재확인한다. 장기 장애로 아직 적용하지 못한 보존 중지의 재검토 기한이 지난 경우에는 운영자의 재검토가 필요하며 자동 완료하지 않는다.

전체 사용자 삭제 자동 실행, 판매자 프로필·동의 증거·첨부·모든 백업의 자동 파기는 아직 전체 목록 검증을 요구한다. 종료 분쟁의 폐쇄 후 3년은 내부 보수 보존 기준이며 법정 기산점을 확정하는 설명이 아니다. 재개·보존 중지 사건은 파기 대상에서 제외한다. 권리·사고 증거의 보존 정책은 실제 근거와 목적을 확정한 뒤 활성화한다.

## 운영 설정과 남은 연결

| 설정 | 활성화 조건 |
| --- | --- |
| `CommerceProtection` | 운영주체 7개 항목, 약관·처리방침·지원·보존·외부 처리·권리 실행·사건 보존·개인 신원 제공 검토 참조, 거래 활성화 검토 |
| 신원 확인 gateway | 실제 제공자 계약·확인 참조의 서버 귀속·성년과 판매자 정보 검증 연결. 기본 미연결 유지 |
| `CommercePrivacySupport` | 실제 한국 공휴일 목록과 검증 범위·버전, 종료 분쟁 보존 정책. 접수·통지 문안 준비는 실제 발송을 뜻하지 않음 |
| `PrivacyRetention` | `Enabled`, `InventoryVerified`, `ProvidersVerified`, `BackupRestoreBarrierVerified` 모두 확인. 기존 운영 데이터에 임의 활성화하지 않음 |
| `ExternalPrivacyProcessing:Providers` | `AzureBlob`, `GoogleCloud`, `GoogleGeocoding`, `NaverDirections`, `NaverReverseGeocoding`별 목적·수신자·국가·항목·근거·계약·방침·이전 경로 검토. 검토 없으면 전송 차단 |

실제 권리 실행기와 통지·신고 채널, 적법한 개인 신원 제공 승인, 신원기관·운영자 담당·전체 파기 목록을 연결하고 검증한 뒤 공개 거래를 검토한다. 권리 실행 원장 확인 adapter가 미연결이면 검토 참조를 입력해도 준비 완료가 되지 않는다. 사고의 일부 수동 통지 기록은 전체 영향 대상의 통지 완료를 증명하지 않으며 대상 명부·전달 결과 결속이 필요하다. 설정의 검토 참조는 사람의 검토 근거를 연결하는 값이며 법적 적합성을 자동 판정한 결과가 아니다. 보호 저장 키와 Data Protection key ring은 재시작·복원 후 복호화를 검증해 운영 설정으로 관리해야 한다. ISMS 인증, 실휴대폰·Azure 운영, 실제 금융 지급·환불 완료로 표시하지 않는다. [변경과 실행 검증](../Changes/2026-10-06-commerce-privacy-r25.md).

화면별 책임·상태·API와 저장 연결은 [페이지 책임 카드](../ProjectOverview/page-docs/commerce-protection-r25.md)에 정리한다.
