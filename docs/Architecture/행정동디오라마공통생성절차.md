# 면목제3·8동을 기준으로 행정동 디오라마 만들기

어느 동을 열어도 같은 축척에서 골목과 차도를 구분하고 건물을 눌러 그 건물의 정보를 읽을 수 있어야 한다. 기준 장면은 기존 Windows 검토판의 **중랑구 면목제3·8동**(`1126057500`)이다. 건물 수·층수·도로 밀도·공원 면적은 대상 동의 공공자료에서 가져온다. [기준 동의 Windows 실행 기록](../AI/Handoffs/2026-11-15-Codex-기사빛-행정동-디오라마-r4.md) · [공통 생성 설정](../../eng/neighborhood/dong_diorama_reference.json)

## 새 동을 추가할 때

1. **행정동 코드와 경계 판본을 고른다.** 현재 입력은 2026년 10월 경계 후보로 잘라 둔 자료 목록이다. 건물·도로·도보 및 차선·공원·지번과 인허가를 같은 행정동으로 묶는다. 새 지역은 해당 코드·기준시점·좌표계·출처·이용 조건을 먼저 등록한다. 법정동 지번은 선택한 건물의 주소로 보관한다. [자료 준비 방법](../AI/Handoffs/2026-11-15-Codex-행정동별-디오라마-정밀모듈-r3.md)
2. **기준 동을 먼저 재현한다.** 기존에 검토한 면목제3·8동의 원본 명세, HDIO 메시, 건물 선택 색인은 각각 고정된 SHA-256이 있다. 세 값이 맞아야 같은 설정을 대상 동에 적용한다. 건물 색인에는 안마당·분리된 별동과 필지 정보가 포함된다.
3. **같은 표현 규칙으로 굽는다.** 실측 높이를 우선하고, 결측이면 지상 층수 × 3m, 둘 다 없으면 상징 높이 4m를 사용한다. 그 근거를 건물마다 남긴다. 같은 높이 압축·재질·그림자 방향과 도로·보행로·차선의 기호 폭을 사용한다. 건물에 덮인 도보면을 덜어 내고 차선은 차도 안에서 자른다. 입체 보행시설을 지상 골목에 겹쳐 그리지 않는다.
4. **원본과 구운 도형을 검사한다.** 필수 레이어, 지문, 동 코드, 경계와 좌표계, 고유 식별자, 지번·인허가 연결을 대조한다. 지면·공원 계획면·보행면·도로 가장자리·차도·차선은 표현 폭과 절단을 원본에 적용해 얻은 면적을 실제 메시 삼각형 면적과 비교한다. 해당 동의 원자료가 0건인 경우와 입력 도형이 있었지만 절단 뒤 표시 면적이 0인 경우를 구별한다. 필수 파일 누락, 다른 동의 파일, 중복 ID, 원본과 다른 표시 결과는 오류다.
5. **같은 거리에서 비교한다.** 동별 그림의 왼쪽은 경계 전체, 오른쪽은 가로 300m 근경이다. 모든 동에 같은 회전 30°·고도 60°와 채색 방식을 쓴다. 전체 그림의 상자는 오른쪽 확대 위치다. 품질표에서 동 이름을 누르면 그 동의 비교 그림이 열린다.
6. **Unity에 넣은 동은 실제 창에서 마감한다.** 한 번에 선택한 동 하나가 보이는지, 전체→거리 확대→건물 선택에서 같은 지번과 높이 근거가 나오는지 확인한다. 기사 상태가 있는 곳에서는 기사 빛을 선택하고, 다른 동으로 넘어가면 이전 동의 기사·매장 표식이 남는지도 본다. 캡처에 행정동 코드·메시 지문·실행판 판본을 함께 남긴다. 자료 품질표와 Unity 실행 기록은 따로 조회한다.

## 실행 방법

Hongdal 루트에서 다음 명령을 실행한다. 한 동을 지정하면 기준동과 지정한 동이 같이 만들어진다. 여러 동은 `--code`를 반복하면 된다. `--all`은 현재 자료 목록의 전 동을 개별 파일로 굽고, Unity 형식 확인용 `Resources`에는 기준 동을 담는다.

```powershell
$py = "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe"
& $py -B -X utf8 eng/neighborhood/prepare_dong_dioramas.py --code 1135064000
& $py -B -X utf8 eng/neighborhood/prepare_dong_dioramas.py --all
```

결과는 `artifacts/local/admin-dong-reference-review/run-…/`에 생긴다. 새 경로를 지정할 때는 `--output`을 붙인다. 원자료와 프로젝트 GIS 패키지가 필요하고, 다른 작업본에서 실행하면 `--consumer`로 해당 WindowsGame의 `Resources`를 지정한다. 출력 폴더에는 검사가 끝난 결과만 남긴다. 자료와 게임 판본의 호환성은 [지도 자료 검증기](../../eng/neighborhood/verify_dong_unity_modules.py)와 [전체 생성 명령](../../eng/neighborhood/prepare_dong_dioramas.py)에서 확인할 수 있다.

| `QUALITY.md` | 동별 건물, 실측·층수·상징 높이, 지번 연결, 도로·도보, 공원과 음식점 인허가 후보. |

## 품질 차이를 읽는 법

면목제3·8동은 건물 2,722개 중 899개에 높이 자료가 있고, 1,563개는 층수로 높이를 환산하며, 260개에는 상징 높이를 쓴다. 다른 동에서 상징 높이가 많으면 높이 자료를 보강할 동으로 기록한다. 상계2동처럼 입력된 공원 계획면이 0건이면 그 사실을 표시한다. 이는 해당 판본의 계획면 건수다. 실제 동네에 공원이 있는지와 나무가 어디에 있는지는 별도 자료로 확인한다.

새 자료나 의도한 스타일 변경이 기준 동의 외형 또는 선택 결과를 바꾸면, 달라진 부분을 기존 근경·건물 선택 결과와 함께 검토하고 새 판본의 기준 지문을 기록한다. 출처·권리와 규칙 승격 기준은 [역세권 디오라마 증거 진화 체계](역세권디오라마증거진화체계.md)를 따른다.

건물 117,551조각 중 49,120조각은 원본 높이, 45,487조각은 층수 환산 높이, 22,944조각은 상징 높이를 썼다. 원본 항목이 일치해 지번을 표시할 수 있는 건물은 117,501조각이고 50조각은 미확인이다. 예를 들어 상계3·4동은 4,301조각 중 3,161조각이 상징 높이이며, 이문제2동은 27조각의 지번이 미확인이다. 이 값으로 후속 자료 수집 대상을 고를 수 있다.
