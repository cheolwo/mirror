# 커뮤니티 대화에서 공동 행동으로 이어지는 경계

## 기본 원칙

홍달의 첫 진입점은 업무 대시보드가 아니라 가볍게 글을 읽고 쓰는 생활 게시판이다.
평범한 글, 질문, 음성 게시글과 댓글은 그 자체로 유지한다. 게시글 내용만 분석해 주문, 계약,
배차, 운송 주선 또는 원장을 자동 생성하지 않는다.

게시글을 보는 방식은 다음 두 가지를 같은 화면에서 제공한다.

- 목록형: 제목, 작성자, 작성일, 추천과 댓글 수를 빠르게 훑는 기본 보기
- 카드형: 제목과 짧은 본문을 함께 읽는 보기

보기 방식이 달라도 게시판 분류, 글 필터, 검색, 글쓰기와 게시글 상세 진입은 동일하다.
작성자 국적은 추정하지 않는다. 작성자가 공개에 동의해 직접 입력한 ISO 알파-2 코드와
`활동 국가` 이름만 게시글 스냅샷으로 저장해 목록형, 카드형과 상세 화면에 표시한다.
신고·분쟁 게시글에서는 이 값도 공개하지 않는다.

## 단계

1. **대화**: 누구나 게시글과 댓글로 생각을 나눈다.
2. **관심 표현**: 한 사용자가 `같이 해볼까요?`를 명시적으로 시작한다.
3. **역할 탐색**: 구매자, 판매자, 운송 주선업자, 운송인, 관세사,
   창고 운영자, 대화 정리자 또는 단순 구독자가 비구속적으로 관심 역할을 표시한다.
4. **가원장**: 서로 다른 관심 참여자가 2명 이상 모이면 게시글 작성자가 현재 관심과
   역할의 해시를 비구속적 공동구매 초안으로 기록할 수 있다.
5. **구체적 수요 확인**: 상품, 수량, 지역과 수령 조건이 정해졌을 때만 기존
   `GroupPurchaseDemand` 투표로 전환한다.
6. **경제성 검토**: 참여자가 별도로 공동조달 계획을 만들고 물량별 비용과 편익을 계산한다.
7. **명시적 합의**: 현재 계산 리비전을 모든 당사자가 독립적으로 수락한 경우에만 실행 준비로 본다.

## 관심 모집의 경계

`CollectiveActionInterest` 투표는 다음 조건을 항상 지킨다.

- 원본 게시글이 반드시 존재한다.
- 여러 가능한 역할을 함께 선택할 수 있다.
- 주문, 계약, 배차, 운송 주선, 결의문, 전자서명 또는 커뮤니티 원장을 만들지 않는다.
- 같은 게시글에 열린 관심 투표가 있으면 새로 만들지 않고 재사용한다.
- 닫힌 관심 투표 뒤에는 사용자가 다시 명시적으로 새 모집을 시작할 수 있다.
- 게시글 작성자가 아니어도 로그인한 독자가 모집을 시작할 수 있다.

관심 역할을 선택할 때에는 알림을 보내지 않는다. 가원장 승격은 게시글 작성자만 할 수 있고,
가원장·비구속 증빙·참여자 알림을 각각 확인해야 한다. 이때 로그인 상태로 관심을 표시한
참여자만 내부 사용자 ID로 원장 참여자에 연결되며, 공개 투표 응답에는 사용자 ID를 내보내지 않는다.
익명 참여는 인원과 역할 증빙에는 포함되지만 개별 푸시 알림 대상이 될 수 없다.

가원장은 항상 `group-purchase` 템플릿의 `초안`이다. 해외 조달 가능성이 있어도 곧바로
공동수입 실행 원장을 만들지 않고 `GroupImportCandidate` 의도만 기록한다. 주문, 계약, 결제,
배차, 운송 주선과 공동수입 실행은 이후의 별도 확인과 업무 원장에서 시작한다.

관심 역할은 자격이나 업무 권한을 부여하지 않는다. 실제 운송 주선, 운송, 통관과 보관 업무는
각 제공자가 자신의 면허, 등록, 계약과 책임 범위 안에서 별도로 제안하고 수락해야 한다.
플랫폼은 특정 제공자를 배정하거나 거래 조건을 대신 결정하지 않는다.

## 거래 참여팀 구성

가원장을 만들 때 `거래 방향`, `출발국`, `도착국`, `예상 운송수단`을 기록한다. 이 정보는
계약 조건이 아니라 필요한 역할을 빠뜨리지 않기 위한 계획 메타데이터다. 출발국과 도착국은
ISO 알파-2 코드를 사용하며, 해상·항공·도로·철도·복합운송을 복수 선택할 수 있다.

역할 슬롯은 다음 책임을 섞지 않는다.

- 거래 당사자: 구매자, 판매자, 수입 책임 당사자, 수출 책임 당사자
- 통관·문서: 수입 통관 관세사, 수출 통관 관세사
- 운송 중개·주선: 해상 포워더, 항공 화물 주선업자, 육상 화물 브로커, 복합운송 주선업자
- 실제 운송: 선사, 항공사, 육상 운송사·기사, 철도 운송사
- 현장 이행: 창고 운영자
- 미국 공동수입 보세-주소 배송: 보세창고·FTZ 운영자, 통관 전 보세운송사,
  미국 내 풀필먼트 운영자, 참여자 주소 배송 사업자

한 사용자가 여러 역할을 맡을 수 있지만 역할별 수락과 확인 근거는 따로 기록한다. 관심 투표는
`관심 있음`, 구매자·판매자·수입자·수출자의 직접 수락은 `명시적 역할 수락`, 플랫폼
프로필·관리자 승인으로 확인한 전문 참여는 `플랫폼 역할 확인`으로 표시한다.
`플랫폼 역할 확인`은 정부기관 면허·등록, 영업 권한, 보험·보증 또는 실제 수임을 증명하지 않는다.
관할 확인이 필요한 역할은 응답의 `VerificationRequirementCode`로 구분한다.

도착국이 미국인 공동수입 가원장에는 일반 `WarehouseOperator` 한 슬롯으로 책임을 합치지 않고
다음 네 슬롯을 별도로 연다.

| 역할 코드 | 담당 경계 | 별도 확인 |
| --- | --- | --- |
| `CustomsControlledFacilityOperator` | CBP bonded warehouse 또는 활성화된 FTZ 보관 | 정확한 시설 authorization·activation·FIRMS code·가용 공간·계약 |
| `InBondCarrier` | 통관 전 시설 간 ACE in-bond 이동 | bonded carrier 권한·carrier bond·경로·도착 보고·운송계약 |
| `DomesticFulfillmentOperator` | 반출 완료 화물의 일반 창고 입고, 소분·kitting·보관·parcel 인계 | 상품 취급·시설 역량·SLA·요금·계약 |
| `ParticipantAddressDeliveryProvider` | 풀필먼트 창고에서 참여자 주소까지 배송 | 운송 권한·서비스 권역·parcel 계약·주소 동의 |

각 슬롯은 미국 보세-주소 물류 후보 디렉터리의 해당 단계 필터를 함께 반환한다. 디렉터리는
조사 후보일 뿐 슬롯 참여자가 아니다. 업체 담당자가 플랫폼 계정을 만들고 관리자가 해당 역할을
확인한 뒤, 담당자가 비구속 참여와 알림을 명시적으로 수락해야 기존 전문 역할 참여 API를 통해
가원장 `참여자목록`과 역할 구성 블록에 들어간다. 이 참여도 시설 승인·면허·계약·업무 수임을
확정하지 않으며 `ExternalCredentialVerified=false` 상태를 유지한다.

관심 표시는 모집 신호일 뿐 필수 슬롯을 채우지 않는다. 필수 슬롯의 참여자들이 각 역할을
명시적으로 수락하고 거래 경로가 구체화되면
`실원장 전환 검토 준비` 상태가 될 수 있다. 이 상태도 주문·계약·결제·배차·운송 주선의 확정이나
법률상 실행 준비 완료를 뜻하지 않는다. 역할 참여로 원장이 변경되면 기존 가원장 참여자에게
역할명과 이 경계를 포함한 알림을 보낸다.

참여자 알림에 동의한 가원장이 처음 만들어질 때에는 확정 참여자가 없는 역할 슬롯을 계산해
기존 참여자에게 한 번만 함께 안내한다. 필수 역할을 먼저 보여 주고 알림은 원본 게시글의 역할
참여 영역으로 연결한다. 이 안내는 역할을 자동 배정하지 않으며, 참여자가 직접 비구속적 역할
수락을 해야 한다. 후속 원장 수정에서는 같은 빈 슬롯 안내를 반복하지 않는다. 향후 역할 이탈을
지원할 때에는 이탈 Event로 새로 열린 슬롯의 재안내 시점을 별도로 기록한다.

## 관할별 업무 경계 근거

아래 자료는 역할을 분리하는 기준이며 개별 거래에 대한 법률 의견이 아니다.

- 한국 `화물자동차 운수사업법` 제24조는 화물자동차 운송주선사업을 경영하려는 자에게 허가를
  요구한다. 플랫폼은 운송사를 선택하거나 운임·배차를 결정하지 않고, 허가된 주선업자가 별도
  계약으로 제안·수락하도록 둔다.
  - https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=&joNo=&languageType=KO&lsNm=%ED%99%94%EB%AC%BC%EC%9E%90%EB%8F%99%EC%B0%A8%EC%9A%B4%EC%88%98%EC%82%AC%EC%97%85%EB%B2%95&paras=1
- 한국 `관세사법` 제2조는 수출입 신고·관련 절차와 관세 상담 등을 관세사의 직무로 규정한다.
  수입·수출 전문 여부와 관세사 프로필을 나누되 실제 수임과 등록 유효성은 별도 확인한다.
  - https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900015000
- 관세청은 화주가 직접 수입신고할 수 있고 관세사 이용 여부를 선택할 수 있다고 안내한다.
  따라서 수입 책임 당사자 슬롯과 관세사 슬롯을 분리하고 플랫폼이 관세사를 자동 선임하지 않는다.
  - https://www.customs.go.kr/kcs/na/ntt/selectNttInfo.do?mi=2889&nttSn=22315&nttSnUrl=search
- 미국 FMCSA는 motor carrier, broker, freight forwarder의 책임을 서로 다르게 정의한다.
  특히 broker는 운송을 주선하지만 직접 운송하거나 화물 책임을 맡는 주체와 구분된다.
  - https://www.fmcsa.dot.gov/faq/what-are-definitions-motor-carrier-broker-and-freight-forwarder-authorities
- 미국 해상 운송의 Ocean Freight Forwarder와 NVOCC는 FMC의 OTI 규정·면허·재정책임 확인 대상이다.
  해상 포워더 슬롯과 선사 슬롯을 하나로 합치지 않는다.
  - https://www.fmc.gov/about/bureaus-offices/bureau-of-enforcement-investigations-and-compliance-beic/office-of-compliance/ocean-transportation-intermediaries/
- 미국 수입에서는 수입 책임 당사자와 licensed customs broker를 구분하고, 수출에서는 USPPI와
  authorized agent의 AES 역할을 구분한다. 플랫폼 운영자를 기본 수입자·수출자 또는 신고 대리인으로
  자동 지정하지 않는다.
  - https://www.help.cbp.gov/s/article/Article-1390?language=en_US
  - https://www.census.gov/foreign-trade/aes/gettingstarted/overview.html

## 경제성 및 편익 공유

공동조달 경제성 모듈은 상위 계산 도구로 사용한다. 공급가 구간, 고정비, 단위비,
적재 구간비, 비율 비용과 위험 준비금을 합산해 최소 경제 물량과 권장 물량을 계산한다.

- 계산값은 거래 권고나 공통 가격 지시가 아닌 추정치다.
- 참여자의 최소 수용 편익은 본인에게만 보인다.
- 정확한 참여자별 편익은 현재 계산 리비전에 전원이 동의해야 공유된다.
- 계산 조건이 바뀌면 공개 동의와 수락을 다시 받아야 한다.
- 한 참여자에게 편익이 과도하게 집중되는지 참여자들이 정한 상한으로 확인한다.

관심 투표에서 계획을 만들 때는 다음 출처를 기록한다.

```text
SourceTypeCode: community-interest-vote
SourceReferenceId: {interestVoteId}
```

## 커뮤니티 공동행동 페이지

게시판에서 시작한 대화가 업무 화면으로 갑자기 끊기지 않도록 `/community/actions` 아래에서
같은 공동행동을 다음 관점으로 이어서 보여준다.

| 순서 | 경로 | 화면 책임 |
| --- | --- | --- |
| 1 | `/community/actions/gathering` | 관심, 참여 의향과 최소 수량 |
| 2 | `/community/actions/conditions` | 상품, 수량, 가격, 수령과 현재 리비전 |
| 3 | `/community/actions/party` | 거래 당사자, 전문·현장 역할 슬롯 |
| 4 | `/community/actions/readiness` | 역할 수락, 결의문, 서명과 이행 여력 |
| 5 | `/community/actions/in-progress` | 실행 진행, 추가 참여 창과 다음 배치 대기 |
| 6 | `/community/actions/completed` | 완료 결과, 증빙과 다음 모임에 남길 기록 |
| 7 | `/community/actions/mine` | 현재 사용자가 관심을 표시하거나 참여한 일 |
| 8 | `/community/actions/stories` | 완료된 공동행동의 공개 결과 |
| 9 | `/community/actions/professionals` | 통관·운송·창고·문서 역할 참여 요청 |

각 경로는 별도 업무를 만드는 것이 아니라 같은 가원장·공동구매 캠페인·실행 원장을 서로 다른
시점과 역할에서 조립해 보여준다. Page ViewModel은 조건, 역할, 준비 상태, 실행 여력과 결과
ViewModel을 주입받고 Razor 컴포넌트는 이 상태를 직접 재해석하지 않는다.

## 한국 도착 수입육과 전통시장 2차 가공 시나리오

한국 구매자들이 호주 등 해외의 육류를 함께 수입하는 공동행동은 도착국이 `KR`, 출발국이
`KR`이 아니며 정규화한 HS 코드가 `02`로 시작할 때 별도 배송 ViewModel로 조립한다. 이
시나리오는 전통시장을 도축장으로 다루지 않는다. 해외 승인시설에서 도축·1차 가공과 수출 검역을
마치고, 국내 검역·수입검사·통관 반출이 확인된 뒤에만 전통시장 내 허가 영업장의 역할이 시작된다.

| 구간 | 단계 | 표시 원칙 |
| --- | --- | --- |
| 해외 생산 | 승인시설 생산, 수출 검역, 국제 콜드체인 | 해외 생산자·수출자·운송 계약의 별도 근거 필요 |
| 공식 관문 | 국내 검역·수입검사, 통관 반출 | 공식 결과 전에는 이후 단계를 `대기`로 표시 |
| 지역 이행 | 냉장 입고, 이력 확인, 2차 가공, 소비자 포장, 주문 인계, 생활권 배송 | 역할 참여, 영업 범위, 시설 역량과 계약을 각각 확인 |

수입육 가원장에는 일반 창고·운송 슬롯만 두지 않고 전통시장 거점 운영자, 허가된 식육 가공
담당자, 식육 판매자, 국내 콜드체인 운송인, 생활권 냉장배송 수행자를 분리한다. 역할 관심이나
플랫폼 프로필은 영업신고와 작업 수임을 대신하지 않는다. 발골·정형·절단·소분 중 실제로 필요한
작업과 적용되는 영업 종류는 반입 형태와 업무 범위에 따라 사업자와 관할 관청이 확인한다.

공동행동 화면은 수입육 원가뿐 아니라 전통시장 2차 가공 보상, 포장·표시·이력관리, 생활권
냉장배송과 감량·폐기 위험을 별도 비용으로 표시한다. 지역 상인의 작업을 무료 절감으로 취급하지
않으며, 공식 반출·영업 범위·처리량·온도·수율이 확인되지 않은 값은 확정 편익으로 공개하지 않는다.
세부 운영 경계와 공식 확인 경로는
[전통시장 공공데이터 모듈](TraditionalMarketPublicDataModule.md#수입육-국내-2차-가공과-생활권-배송)을 따른다.

## 공동구매에서 장날로 이어지는 흐름

전통시장 생활권의 공동구매는 배송 완료만을 목표로 하지 않는다. 상인회·시장관리자와 품목별
상인이 직접 참여한 경우, 특정 입고일을 `공동구매 장날`로 제안할 수 있다. 장날 하위 ViewModel은
일정, 예약 재고, 현장판매 재고, 참여 상점, 공개 홍보와 마감 결과를 공동행동 Page ViewModel에
조립한다.

```text
게시글의 가벼운 관심
  -> 공동구매 예약 수요
  -> 국내 생산자·산지 공급 주체의 출하 조건 직접 수락
  -> 산지 선별·포장과 시장 직송 운송 주체 수락
  -> 상인회·시장관리자 공동사업 합의
  -> 청과·채소·수산물·정육 등 품목별 상인의 직접 수락
  -> 산지 lot를 전통시장에 직입고하고 품질·수량·원산지 검수
  -> 가정 예약 물량 잠금과 시장 조리 가게 식재료 수요 직접 수락
  -> 가정 예약/가게 공급/공개판매 lot 분리
  -> 장날 일정·확정 공개물량 홍보
  -> 가정 예약 수령·가게 조리장 인계와 주민 현장구매
  -> 생산자·운송인·상인 보상과 잔량·다음 장날 기록
```

국내 농수산물은 `KR -> KR` 거래로 별도 판정해 수입 검역·통관 단계를 열지 않는다. 농가·생산자단체
또는 어업인·양식업자·산지 공급 주체, 산지 선별·포장 주체, 국내 직송 운송 주체와 시장 입고 주체가
각자 물량과 책임을 직접 수락해야 한다. 수산물은 냉장·냉동 운송과 선도·온도 확인을 기본으로 두며,
해외산 상품에는 이 국내 산지 직입고 여정을 적용하지 않는다.

시장 안의 반찬·도시락·음료·제과·음식점 등 조리 가게가 같은 식재료를 필요로 하면 가정 예약분을
먼저 잠근 뒤 별도 공급 참여자로 들어올 수 있다. 가게는 품목·수량·사용 목적·보관과 가격 조건을
직접 수락하고 실제 영업 범위를 확인한다. 이 식재료 인계는 메뉴나 음식 주문을 자동 만들지 않으며,
가게의 소비자 판매는 기존 음식 주문 원장에서 별도로 시작한다.

장날 홍보는 일정, 공용공간과 현장판매 재고가 확정된 뒤에만 연다. 미확정 관심 수량이나 공동구매
예약 물량을 현장판매 가능 물량처럼 광고하지 않는다. 게시판과 현장판에는 시장·품목·시간·공개판매
수량을 표시할 수 있지만 참여자의 주소와 개인 구매내역은 공개하지 않는다. 상인회 합의는 개별
상인의 영업 자격과 판매 책임을 대신하지 않으며, 플랫폼은 상인이나 가격을 자동 배정하지 않는다.

## 미국 구매자 공동수입 배송 시나리오

미국 운영 서버에서 해외 출발 상품을 미국 구매자들이 함께 수입하는 경우에는
`게시글 -> 수요 집계 -> 가원장 -> 역할 구성 -> 출발지 전처리 -> 보세·통관 -> 풀필먼트 -> 참여자 주소 배송`을
하나의 공동행동 여정으로 보여준다. 다음 조건을 모두 충족할 때 이 시나리오를 사용한다.

- 공동구매가 `InboundGroupImportCandidate`로 판정됐다.
- 원장에 보존된 운영 국가와 최종 배송국가가 모두 `US`다.
- 상품 출발국가와 최종 배송국가가 다르다.

| 순서 | 단계 | 주 책임 | 현재 시스템 의미 |
| --- | --- | --- | --- |
| 1 | 미국 구매자 수요 모으기 | 구매 참여자 | Census 기반 공개 배달권으로 인원·수량 집계 |
| 2 | 비구속 가원장 | 공동구매 대표 | 가격·수량·수령 조건 기록, 주문·계약 미확정 |
| 3 | 수입·물류 역할 구성 | 수입 책임 당사자 | 당사자와 전문 역할별 명시적 수락 |
| 4 | 출발지 공장 전처리 | 제조사·판매자·수출자 | 개별포장·라벨·문서 원천자료·카톤 식별과 QC 증빙 |
| 5 | 보세창고·FTZ 인계 | 보세시설 운영자 | 시설 승인·FIRMS·공간·계약 별도 확인 |
| 6 | 통관 전 in-bond 이동 | 보세운송사 | ACE·carrier bond·경로·계약 별도 확인 |
| 7 | 수입 신고·반출 | 수입자 또는 수임한 통관 전문가 | 신고·관세·허가·반출 근거 별도 확인 |
| 8 | 미국 내 풀필먼트 입고 | 풀필먼트 운영자 | 반출 화물 일괄 입고와 검수 |
| 9 | 미국 내 예외 소분·재라벨 | 풀필먼트 운영자 | 공장 미처리분과 검수 예외만 보완 |
| 10 | 참여자별 피킹·parcel 인계 | 풀필먼트 운영자 | 동의된 주문만 포장해 배송사에 인계 |
| 11 | 참여자 주소 배송 | 주소 배송 사업자 | 동의·서비스 권역·별도 운송계약 확인 |

공동행동 Page ViewModel의 배송 하위 ViewModel이 위 11단계를 조립한다. 1~3단계는 현재 캠페인,
가원장과 역할 수락 상태에서 `기록됨`, `지금 확인`, `앞 단계 대기`로 계산한다. 4~11단계는
실행 상태를 추측하지 않고 `별도 계약 필요`로 표시한다. 미국 도착 후 단계에는 보세-주소 3PL
디렉터리의 단계별 필터 경로만 제공하며 조사 업체를 자동 추천·배정·예약하지 않는다.

커뮤니티에는 `us-state`, `us-county`, `us-place`, `us-zcta` 범위와 공개 가능한 집계만 보인다.
street, apartment/suite/unit, 정확한 좌표는 표시하지 않고 참여자의 배송 동의를 받은 뒤 필요한
담당자에게만 전달한다. 현재 구현은 시나리오 읽기 모델과 화면까지이며, 통관 신고, 업체 계약,
창고 작업, label 생성과 배송 실행은 각 권한 주체의 별도 Command와 운영 검증을 추가해야 한다.

### 출발지 공장 전처리와 비용 비교

중국 등 출발지 공장에서 작업하는 편이 항상 저렴하다고 단정하지 않는다. 미국 3PL 후처리 견적과
공장 전처리 견적을 같은 수량·포장규격·서비스 수준·계획 리비전으로 받은 뒤 다음 식으로 비교한다.

```text
예상 순절감액 = 미국 후처리 회피비용
              - 공장 전처리비
              - 개별포장에 따른 추가 국제운임
              - 공장 설정·검수비
              - 주소·운송사·규제 변경 재작업 위험준비금
```

기존 공동조달 경제성 엔진을 그대로 사용한다. 미국 후처리 전체 단가를 `ComparisonUnitPrice`로,
공장 전처리 고정비·단위비, 국제운임 증분과 검수비를 `CostComponents`로 넣고 재작업 가능성은
`RiskReservePercent`로 반영한다. 공장 견적과 미국 3PL 견적의 출처·유효시점이 없으면
`SavingsConfirmed=false`를 유지한다.

- 출항 전에 확정: SKU·개별포장 규격, 제품·원산지 라벨, 판매자·수출자가 확정할 상업송장 초안·원천자료,
  패킹리스트·카톤 manifest, 카톤·팔레트 식별, QC·공급망 추적 증빙
- 공장에서 데이터만 준비: 참여자 주문과 포장 ID 연결
- 주소·배송사 확정 뒤 발급: 실제 parcel 운송장·배송라벨, 반품 주소와 서비스 코드
- 수입자 또는 수임한 통관 담당자 검토: 신고가격, HTS 분류, 관세, 제품별 허가·표시 요건

개별포장을 통관 회피 수단으로 사용하지 않는다. 중국산 저가 화물도 de minimis 면세를 가정하지
않고, Section 301 적용 여부는 원산지와 품목분류에 따라 별도로 확인한다. 식품이면 FDA 표시,
Prior Notice, 시설 등록과 FSVP 등 제품별 검토를 출항 전에 끝낸다.

확인 기준:

- [CBP 원산지 표시 안내](https://www.help.cbp.gov/s/article/Article-1397)
- [CBP 상업송장 신고가격 안내](https://www.help.cbp.gov/s/article/Article-1162?language=en_US)
- [CBP 중국산 de minimis 중단 안내](https://www.help.cbp.gov/s/article/Article-1915?language=en_US)
- [CBP Section 301 FAQ](https://www.cbp.gov/trade/programs-administration/entry-summary/section-301-trade-remedies/faqs?language_content_entity=en)
- [CBP 공급망 추적 안내](https://www.cbp.gov/document/fact-sheets/know-your-supply-chain-slick-sheet)
- [FDA 미국 식품 수입 안내](https://www.fda.gov/industry/importing-fda-regulated-products/importing-human-foods)

## 실행 중 추가 참여

합의가 끝났다고 즉시 참여 문을 닫지는 않는다. 공급 확정, 포장 또는 상차 마감 전에는
기존 참여자의 약속을 훼손하지 않는 범위에서 추가 참여 의향을 받을 수 있다.

```text
추가 가능량 = min(
  공급 가능량,
  창고·수령소 처리량,
  포장 가능량,
  운송 적재 여력,
  통관·서류 허용량
) - 현재 잠재 수량
```

- 수량마다 확인 책임자, 근거, 리비전과 유효 시점을 따로 표시한다.
- 필수 근거 중 하나라도 확인 전이면 `확인된 추가 가능량`으로 표현하지 않는다.
- 추가 의향은 주문·예약·계약 확정과 구분한다.
- 가격, 일정, 책임 또는 기존 참여자의 편익이 달라지면 새 리비전과 명시적 동의를 받는다.
- 포장·서류·상차 마감 뒤에는 현재 배치를 변경하지 않고 다음 배치 대기로 이동한다.
- 플랫폼은 여력 정보를 모아 보여주지만 공급, 창고 처리, 배차, 운송 또는 통관 가능 여부를
  대신 확정하지 않는다. 각 역할 담당자가 자신의 권한과 계약 범위에서 확인한다.

## 지역 디자인 참여

공동행동이 전통시장 장날로 이어지면 해당 시장의 게시판·장날·상품·수령 표식을 하나의 꾸미기 팩으로
연결할 수 있다. 디자이너는 역할 슬롯에 참여해 초안을 제출하지만, 플랫폼 검토와 해당 상인회 승인이
모두 끝난 팩만 `traditional-market:{market-key}` 범위에 공식 적용한다. 꾸미기는 시장의 이야기를
드러내는 표현 계층이며 가격, 수량, 원산지, 알레르기, 보관 조건과 수령 정보는 변경하지 않는다.
