# 화면 시안 선행 제작 절차

## 적용 범위

Web·MAUI·네이티브 앱과 Unity의 새 화면, 화면 구성·정보 구조·상호작용·공간 표현을 의미 있게 바꾸는 작업에 적용한다. 사용자가 화면 작업을 요청하면 기존 화면과 가까운 기획·자료를 먼저 확인하고, 개발할 화면을 이미지로 보여준 뒤 피드백을 반영한다. 순수 서버·계약·시험 변경처럼 사용자에게 보이는 화면이 바뀌지 않는 작업에는 새 시안을 만들지 않는다.

## 화면 작업의 순서

1. **현재 모습 확인:** 실제 앱 화면·Unity 캡처·기존 시안과 그 판본을 찾는다. 확인한 화면의 실행 환경, 자료 출처, 검증 수준을 구분한다. 현재 이미지가 없으면 코드·기획으로 확인한 내용과 미확인 부분을 표시한다.
2. **먼저 시각화:** 현재 화면을 바탕으로 바꿀 부분이 보이는 시안 이미지 또는 시각 목업을 만든다. 화면의 주 행동, 필요한 정보, 정상·대기·오류·완료 상태와 복귀 경로 중 이번 작업에 필요한 것을 짧은 설명으로 붙인다. 실제 화면에서 확인한 요소와 새로 제안한 요소, 예시 수치·가상 위치를 구분한다.
3. **사용자 검토와 반영:** 시안을 사용자에게 먼저 보여주고 바꾸고 싶은 점을 받아 필요한 범위만 다시 시각화한다. 선택한 시안의 판본·대상 화면·남은 미정 사항을 해당 PLAN 또는 페이지 책임 카드에 연결한다. 시안 검토가 별도 구현 관문이나 운영 실행 승인을 대신하지 않는다.
4. **확정 범위 개발:** 기존 승인 기획·작업 명세·허용 경로 등 적용되는 구현 관문을 확인하고 선택한 화면 범위만 개발한다. 시안의 가상 자료를 실제 업무 사실, 실제 위치, 완료 상태로 승격하지 않는다.
5. **실제 화면 대조:** 구현된 화면을 해당 소비 환경에서 캡처해 선택한 시안과 비교한다. 주 행동·상태별 표시·좁은 폭·복귀를 확인하고 차이와 남은 문제를 기록한다. 정적 시안, 렌더, API 연결, APK·기기, Unity Game View, 운영 검증은 각각의 근거로 보고한다.

첫 시안은 한 화면·한 대표 상황부터 만든다. 기존 자료가 부족하면 확인된 구조만 사용하고 가정은 시안 설명에 적는다. 디오라마 시안은 기존 공간의 배치·근거를 존중하며, 새 인물·주문·경로·숫자는 가상 게임 표현으로 표시한다. 이미지가 실제 장소의 정밀 복원이나 기능 구현을 증명하지 않는다.
