# Ssalddel 3.5

## 목표

알뜰살뜰 마트와 도심 즉시배송을 운영 가능한 흐름으로 확장합니다.

3.5는 Ssalddel의 **최종 배포 목표**입니다. 현재 완성 단계 0.0부터 각 릴리즈 게이트를 순서대로 통과하며, `Ssalddel.v3.5.slnx`와 Azure `mart-v35` bundle이 전체 제품 조립의 기준입니다. 목표 지정은 기능 플래그의 즉시 운영 활성화를 의미하지 않습니다.

3.5는 3.0 음식점 일반 음식 배달과 구분됩니다. 알뜰살뜰 마트는 음식점 조리 흐름이 아니라 도심 재고, 피킹, 포장, 음식 배달 기사형 픽업/배송이 결합된 창고형 즉시배송 흐름입니다.

## 포함 범위

| 영역 | 내용 |
| --- | --- |
| 알뜰살뜰 마트 주문 | 주문자 앱에서 알뜰살뜰 마트 상품 주문 |
| 도심 재고 | 마트형 재고 보충과 가용 재고 관리 |
| 피킹/포장 | 도심 창고 공간이 협소할 수 있으므로 기본은 피킹/포장 통합 운영. 창고 옵션으로 분리 운영 전환 가능 |
| 즉시배송 | 음식 배달 기사 앱과 연결된 짧은 거리 배송 |
| 묶음 배달 | 도심 재고/거리/시간 기준으로 묶음 가능성 판단 |

## 보류 범위

- 2.0 핵심 운송 흐름을 흔드는 대규모 구조 변경
- 1.0 주문자 집단 같이 주문 모델을 알뜰살뜰 마트 실시간 주문으로 흡수
- 일반 음식점 조리 흐름과 알뜰살뜰 마트 피킹/포장 흐름의 무리한 통합

## 우선 앱/모듈

- `WarehouseManagerApp`
- `OrdererApp`
- `FoodDeliveryDispatchEngine`
- `피킹배치Engine`
- `FDriverApp`

## 안정화 기준

- 알뜰살뜰 마트 주문이 재고 확인, 피킹, 포장을 거쳐 배차 대기 상태로 전환된다.
- 알뜰살뜰 마트 도심 창고는 기본적으로 `피킹포장통합`으로 운영하고, 피킹 작업자가 피킹한 물량은 작업자 휴대폰 뒤 8자리 바코드 아래에 묶어 추적한다.
- 포장 완료 전에는 음식 배달 배차가 진행되지 않는다.
- 음식 배달 기사 앱에서 픽업/배송에 필요한 정보만 확인한다.
- 알뜰살뜰 마트 흐름이 2.0 화물/용달 운송 흐름과 3.0 음식점 일반 배달 흐름을 침범하지 않는다.

## 현재 배포 가능한 화면 경계

- 주문자는 공개 상품 목록, stable-ID 상세, 후기, 비구속 주문 요청을 각각 독립 Route에서 사용한다.
- 창고 Web·App은 피킹 주문 목록과 `/orders/{OrderId}` 상세를 독립 Route에서 읽는다.
- 마트 홈과 업무 흐름은 샘플 현황을 만들지 않고 입고 예정, 가용 재고, 피킹 주문의 서버 원장 화면으로만 연결한다.
- 작업자 진입은 인증된 계정의 서버 HR 역할 배정을 확인하며, 입고·피킹 상태 전이는 서버 원장에서 수행한다.
- 배달 기사 인계 전용 영속 화면은 아직 준비 중이며, 준비 전에는 비활성 상태로 표시한다.
- Azure 3.5 조립은 `compose.mart-v35.override.yaml`에서 `SsalddelExecution__Mode=Operational`, `SsalddelMartWorkflow=true`, 판매채널 주문 동기화를 사용한다. Toss 비밀키와 외부 판매채널 자격 증명이 없으면 서버 또는 해당 공급자 호출은 실패하도록 유지한다.
- CI는 `Ssalddel.v3.5.slnx`를 빌드하고 `mart-v35` 배포 bundle을 생성하되, 운영 전환은 이 문서의 안정화 기준과 공통 릴리즈 게이트 통과 뒤 별도로 승인한다.
