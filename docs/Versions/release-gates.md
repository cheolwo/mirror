# Release Gates

릴리즈 게이트는 특정 버전을 배포 가능하다고 판단하기 전에 반드시 확인해야 하는 조건입니다. 체크리스트는 작업 목록이고, 릴리즈 게이트는 배포 여부를 결정하는 기준입니다.

## 공통 게이트

모든 버전은 다음 조건을 만족해야 합니다.

| 구분 | 게이트 |
| --- | --- |
| 빌드 | 해당 버전 대상 솔루션 또는 프로젝트가 경고/오류 없이 빌드됩니다. |
| 마이그레이션 | DB 마이그레이션이 버전 범위에 기록되어 있고, 이전 버전 운영 흐름을 깨지 않습니다. |
| 기능 플래그 | 해당 버전 범위 밖 기능은 기본값이 `false`이거나 UI 노출이 꺼져 있습니다. |
| 문서 | `README.md`, `scope.md`, `checklist.md`, `migration-notes.md`가 실제 구현 상태와 맞습니다. |
| 보안/개인정보 | 주민 주소, 계좌, 연락처, 통관 정보 등 민감 데이터는 마스킹 또는 최소 노출 원칙을 따릅니다. |
| 개인정보/계약 준비도 | 개인정보 또는 계약 데이터를 다루는 기능은 [ISMS-P 준비도](../Compliance/ISMS-P-readiness.md)의 필수 항목, `IsmsPProtectedDataAttribute`, 개인정보 필드 보호 카탈로그를 내부 검토 기준으로 통과합니다. |
| 보호 데이터 흐름 | 민감 입력값은 클라이언트 앱 레벨 암호화 봉투로 전송하고, 서버에서 복호화해 업무 검증 후 DB 저장 전 `AES-256-GCM` 또는 증적 해시로 다시 보호합니다. |
| 운영 회귀 | 이전 안정 버전의 핵심 업무 흐름이 새 기능 때문에 차단되지 않습니다. |

## 버전별 게이트

| 버전 | 릴리즈 가능 조건 |
| --- | --- |
| `0.0` | 운송·창고·통관·음식·마트 모듈 없이도 가입 또는 책임 있는 별명 참여, 게시글·댓글·모집·투표, 상호 동의, 공동 원장·다이어그램, 신고·차단·숙고, 개인정보를 줄인 완료 사례와 신뢰 기록이 서버 영속 데이터로 이어져야 합니다. |
| `1.0` | 화주가 국내 화물/용달 운송 의뢰를 등록하고, 기사가 추천/수락/거절/상차지도착/상차완료/하차지도착/인수완료를 처리합니다. 수령자 정보는 단계별로 최소 노출되고, 인수완료 후에는 증빙/인수증/정산 후보가 남아야 합니다. 1.5 이후 기능 없이도 운송 정보 서비스가 단독으로 동작해야 합니다. |
| `1.5` | 입고, 적재, 출고, 재위탁 운송 흐름이 1.0 운송 흐름 위에서 동작합니다. 출고 배치 엔진은 단일/복수 상품 주문을 단일/복수 창고 출고 계획으로 나눌 수 있어야 하며, 창고 선택에는 주문자 주소와 창고의 배송권, 거리, 예상 운송비가 반영되어야 합니다. 창고 기능은 2.0 통관/HS 데이터에 강하게 의존하지 않아야 합니다. |
| `2.0` | HS 코드, 통관/수입 대행 조회, 관세사 보정 권한이 분리됩니다. 통관 데이터는 1.0 운송과 1.5 창고 업무의 참고 정보로만 연결되고 기본 업무를 불필요하게 막지 않습니다. |
| `2.5` | 도로명주소/Kakao 지역 2단계 기반 주문자 집단 후보, 공동주택 하위 식별, 공동 주문 모집, FCL/대량 입고, 집단 내 분류/배분 흐름이 동작합니다. 통관은 선택적 연결이며, 공동 주문이 반드시 수입 통관을 전제로 하지 않아야 합니다. |
| `3.0` | 음식점 일반 주문이 접수, 조리, 픽업, 음식 배달 기사 배차, 고객 배송 완료로 이어집니다. 알뜰살뜰 마트의 재고/피킹/포장 흐름은 포함하지 않아야 합니다. |
| `3.5` | 알뜰살뜰 마트 주문이 도심 재고, 피킹, 포장, 음식 배달 기사 픽업으로 이어집니다. 2.5 주문자 집단 공동 주문 모델, 3.0 음식점 일반 배달 모델과 즉시배송 모델이 UI/정산/배차 정책에서 섞이지 않아야 합니다. |

## 버전 간 의존성

| 버전 | 의존 가능 | 강한 의존 금지 |
| --- | --- | --- |
| `0.0` | 없음 | 1.0/1.5/2.0/2.5/3.0/3.5 전체 |
| `1.0` | 0.0 커뮤니티·원장·동의·신뢰 기반 | 1.5/2.0/2.5/3.0/3.5 전체 |
| `1.5` | 1.0 운송 흐름 | 2.0 통관 필수화, 2.5 공동주문 필수화 |
| `2.0` | 1.0 화물 운송, 선택적 1.5 창고 참조 | 1.5 창고 필수화, 2.5 공동주문 필수화 |
| `2.5` | 1.0 운송, 1.5 창고, 2.0 통관 참고 | 통관 필수화, 알뜰살뜰 마트 즉시배송 흡수 |
| `3.0` | 음식 배달 배차 | 2.5 공동주문, 3.5 알뜰살뜰 마트 즉시배송 혼합 |
| `3.5` | 1.5 창고, 3.0 음식 배달 배차 | 2.5 공동주문 흡수, 3.0 음식점 일반 배달과 정책 혼합 |

## 릴리즈 판정 절차

1. 해당 버전의 `scope.md`에서 포함/보류 범위를 확인합니다.
2. 해당 버전의 `checklist.md`를 완료합니다.
3. `migration-notes.md`에 DB/설정/운영 데이터 변경을 기록합니다.
4. [feature-flags.md](./feature-flags.md)의 기본값과 운영 노출 상태를 확인합니다.
5. 빌드와 핵심 흐름 검증을 통과하면 `release/{version}` 브랜치 또는 `v{version}.0` 태그 기준으로 릴리즈합니다.
