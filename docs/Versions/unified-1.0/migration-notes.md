# 단일 1.0 목표로의 호환 이행

1. 새 릴리스 목표는 통합 앱 `1.0`이다. 옛 `1.0` 공동주문 분류와는 별도의 통합 목표 정의로 관리한다.
2. 기존 기능 도입 번호·PageKey·route·명령 FeatureKey·저장 원장·조건 판본·기존 APK의 식별자는 보존한다. 기존 숫자값을 일괄 `1.0`으로 치환하지 않는다.
3. 현재 기본 공개 기준을 보존하는 호환 값과 통합 제품의 완성 목표를 분리한다. 현재 기능 플래그·인증·실행 모드·배포 manifest의 확인값을 자동 승격하지 않는다.
4. 코드·서버 이미지·앱 표시 버전·Android versionCode·내부 마감 회차는 서로 다른 식별자다. r121 시험 APK는 통합 1.0 출시 완료가 아니다.
5. 기존 버전 폴더는 이전 업무 분류의 호환 문서다. 현재 제품 범위는 [통합 1.0](README.md), 실제 완성 여부는 [업무별 마감표](checklist.md)를 따른다.
6. 이 변경은 데이터 마이그레이션이나 운영 배포를 수행하지 않는다. 이후 API 호환 변경이 필요하면 별도 계약·소비 앱·회귀를 확인한다.

## 빌드와 코드에서 구분하기

통합 제품의 정본은 `SsalddelProductRoadmapCatalog.UnifiedReleaseTarget`이며 `BuildSolution`은 **`Ssalddel.slnx`**다. 명령 기능 분류에서는 `Command기능버전Catalog.UnifiedDeploymentTarget`으로 같은 정의를 참조한다. 전체 서버·웹 조립을 확인한 뒤 Android 전문 앱은 각각 해당 프로젝트의 `net10.0-android` 대상으로 별도 검증한다.

기존 **`Ssalddel.v1.0.slnx`는 옛 공동주문 분류 솔루션**이다. 통합 앱 1.0의 전체 빌드로 사용하지 않는다. `v0.0`~`v3.5` 솔루션은 이전 업무 분류의 회귀와 변경 영향 검사에 계속 쓴다. `validate-changes.ps1`의 선택된 빌드·시험 계획을 기록하고, 솔루션 빌드만으로 Android 설치·휴대폰 실행·운영 공개를 확인했다고 하지 않는다.
