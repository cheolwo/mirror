# 통합 앱 1.0 업무별 마감표

2026-10-29 제품 기준 정리, 2026-11-05 최근 제한 검증 연결. 기존 검증을 보존하고 [r31 로컬 세 업무 실행](../../Changes/2026-10-29-three-workflow-local-r31.md)의 서버 완료·실제 역할 앱 조회·재시작 보존을 따른다. 완료 상태는 현재 소스·시험 서버·APK 판본이 일치하는 근거로 갱신한다. 과거 통과를 최신 판본의 완료로 승계하지 않는다. 아래 표는 제품 1.0의 내부 업무 묶음이며 별도 제품 버전이 아니다. 당시 제품 기준선과 최근 제한 검증은 [변경·검증 판본](current-validation-baseline.md)에서 나누어 확인하고 현재 업무의 재개 순서는 [CURRENT_WORK](../../AI/CURRENT_WORK.md) 상단을 따른다.

## 모든 업무에 적용할 확인

r31에서 이번 요청의 세 업무를 별도로 확인했다. 화물은 운송9 인수완료, 음식은 주문자 수령확인, 창고는 수령·검수·적재/가용5까지 제품 API·독립 DB를 대조했다. 최종 동일 서버/DB 재시작 후 세 업무의 지문이 일치했다. 실제 휴대폰에서는 기사 상차지 도착 버튼과 창고/주문자 조회·재실행 인증, PC에서는 음식점 로그인·수신함·재실행 인증을 확인했다. 이 결과로 아래의 전체 역할 공통 체크박스를 일괄 완료하지 않는다. 창고 출고·인계와 모든 native 버튼 수행·실물 장치는 여전히 별도다.

r31 당시 전체 자동시험은 `20261029-124128`의 **16,740통과·실패0·환경17생략**이다. 새 창고 수령/검수 실행 전략 수정과 회귀11개, 관련 집중80개를 포함한다. r31의 앞선 두 전체 시험 실패는 테스트 fixture의 EF 제공자 격리 문제로 보존하고 최종 통과와 구분한다. 음식점 PC의 빌지 설정은 Release 허용 경로에 없어 다음 보완 대상으로 남긴다. 게시글 작성·수정·삭제와 AI 학습은 이번 범위에 포함하지 않았다.

- [ ] 최신 APK의 첫 실행·반복 실행과 데이터 보존 업데이트
- [ ] 공개 탐색과 로그인 후 원래 업무 복귀
- [ ] 정상 처리 후 같은 원장을 모든 관련 역할에서 재조회
- [ ] 종료·통신 단절·응답 유실 후 복구, 자동 재전송·중복 완료 없음
- [ ] 다른 계정·서버·대상으로 전환한 뒤 이전 자료/응답 차단
- [ ] 취소·거절·변경·사진 실패·미확정·신고의 복귀 경로
- [ ] 모바일 읽기·터치·키보드·하단 메뉴·시스템 막대 확인
- [ ] 실제 업무·수령·정산 준비·실수납·실지급을 별도 확인

체크박스는 전체 역할에 공통으로 완료했을 때만 채운다. 일부 업무가 확인된 것은 위 표와 변경 기록에 남긴다. r2 당시 전체 회귀16,210통과·환경16생략과 Fast292, r28의Fast536·Task16,681통과, r29의Fast124·Task16,716통과·실패0·환경17생략은 이전 이력으로 보존한다. 최신 r31 전체 시험과 역할별 실제 확인 범위는 위 단락을 따른다. 실제 기기는 r121의 통합122, 이후 화물 세 역할128·기사131·지도135·수명/좌표136·현재화물137 및 창고/음식138 등 검증 범위별로 다르다. 현재 소스와 동일한 전체 역할 설치/완주나 제품1.0 공개 완료로 표시하지 않는다.

표의 `HTTP 완료`는 합성 자료를 이용한 현재 제품 API/격리 DB 검증이며 실운송·카메라·GPS·실금융·운영 공개가 아니다. 세부 결과는 [r121 변경 기록](../../Changes/2026-10-25-mobile-app-closeout-r121.md)에 연결한다.
