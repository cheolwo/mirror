# 최신 변경·검증 판본 정리

2026-10-29 제품 기준선과 이후 업무별 제한 검증을 구분한다. 사용자가 요청한 로컬 서버의 화주 접수·음식 주문·창고 입고를 [r31 실제 실행](../../Changes/2026-10-29-three-workflow-local-r31.md)으로 확인했다. 제품 목표는 통합1.0으로 유지하며 세 업무의 서버 완료와 역할 앱에서 실제로 확인한 행동을 구분한다. 아래 r31/r29 및 이전 기록은 당시 이력으로 보존한다.

## 최근 제한 검증의 진입점 — 2026-11-05

[CURRENT_WORK](../../AI/CURRENT_WORK.md) 상단은 현재 업무·다음 후보·차단/재개 조건을, [업무별 마감표](checklist.md#최근-제한-검증--전체-업무-마감과-구분)는 최근 자동시험/서버/휴대폰의 실제 범위와 미완료를 연결한다. 두 문서를 갱신해도 아래 r31 실행을 새 판본의 완료로 바꾸지 않는다.

최근 제품 수정/기기 검증은 [음식점 설정 r23](../../Changes/2026-11-05-restaurant-settings-operational-client-r23.md)이며 실제 읽기·재열기·연결 복구 범위다. [관리자 주문 상세](../../Changes/2026-11-05-admin-order-summary-r1.md)와 [화주 운송 목록](../../Changes/2026-11-05-shipper-transport-summary-r1.md)은 코드/자동검증과 실제 기기 대기를 구분한다. 해당 기록의 제품·시험·실행기/설정·APK/서버 입력을 현재 상태와 대조한 범위만 재사용한다. 이 연결 정리는 새 제품 시험·HTTP/DB·기기 실행이 아니다.

문서 관측과 제품 검증 입력의 구분은 [공통 제작 절차](../../AI/Planning/시스템/PLAN-SYSTEM-PLANNING-IMPLEMENTATION-CHECKLIST/app-production-input-guide.md#현재-판본을-함께-확인하는-법)를 따른다. 과거 manifest·성공/실패·문서 hash는 보존하며 변경 영향은 새 회차 근거에 남긴다.

## 이전 정리 결과와 당시 다음 경계

현재 소스·이전 시험·서버·기기 기록을 분리해 [업무별 마감표](checklist.md)에 반영했다. 첫 정리는 문서와 지문만 확인했으며 이후 직접 승인한 r29에서 기사 리팩토링·재빌드·APK 제작/설치·합성 표시 확인을 추가했다. 제품 서버/DB·운영·stage·commit·push·배포는 변경하지 않았다. 다음 실행 회차에서도 이 소스 기준을 다시 대조하고 같은 서버와 대상 앱 판본을 결속한 뒤 해당 업무를 검증한다.

정리 전 개별 파일 지문과 Git index 상태는 로컬 `artifacts/local/unified-validation-baseline-20261028-r1/worktree-before.json`, 소스/실행파일 재대조는 `evidence-review.json`, 문서 검사·기존 변경 보존 결과는 `verification-summary.json`에 둔다. 이 자료는 로컬 확인 기록이며 공개 후보·원격 보관·새 승인 DB가 아니다. 이 문서의 현재성은 그 확인 시점까지이며 이후 소스가 바뀌면 관련 범위부터 다시 대조한다.
