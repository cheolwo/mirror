## 1. 결론

LH 엔진은 **결정론적 셀 계획과 서버 없는 로컬 스트리밍을 실행할 수 있는 기반 수직 단위**까지 만들어졌다. 125m L3 셀을 중심으로 상세 3×3, 활성 5×5, 선행 적재 9×9 범위를 계산하고, 셀 상태 전이·캐시·늦은 응답 차단·NPC 경로 선행 준비·부동 원점 이동을 처리한다. 서버에서는 같은 계약으로 H5 세계 배치 구성 대장을 읽어 LH 셀 후보를 제공하며, 상태 사본의 저장·재생 계약도 존재한다.

그러나 현재 LH가 실제 지형을 완성하는 엔진이라고 보기는 어렵다. 서버 H5 공급자는 H4 AreaSet과 H3 기준점 및 네 방향 연결선을 셀 계획으로 변환하는 단계이고, 실제 DEM·토지피복·도로·건물·통과 가능한 지형, 실제 NavMesh, 완전한 H1 상호작용은 결속되지 않았다. Unity 로컬 엔진도 시나리오 절차생성 자료를 사용하며, 로컬 LH 변화량을 실제 저장 파일에 넣는 조립은 확인되지 않았다.

## 3. 서버 구현 현황

### 3.1 셀 계획과 계약

`SimulationLhWorldService`는 플레이어의 양자화된 L3 위치와 이동 방향을 받아 다음 범위를 계산한다.

- 상세 반경 1: 3×3, 최대 9셀
- 활성 반경 2: 5×5, 최대 25셀
- 선행 적재 반경 4: 9×9, 최대 81셀
- 동시 준비 상한: 4셀
- 경계 선행 적재 시작점: 셀 경계의 25%
- 주 스레드 조립 예산: 프레임당 2ms
- 캐시 용량: 32셀
- 부동 원점 이동 기준: 2,048 월드 단위
- 계절: 봄·여름·가을·겨울, 각 28일

셀 범위 계산은 `ISimulationLhWindowPlanner`, 내용 생성은 `ISimulationLhCellContentSource`로 분리되어 있다. 이 구조 때문에 같은 L 범위를 유지하면서 절차생성, H5 권위 자료, 향후 실제 E5·E6 공급자를 교체할 수 있다.

### 3.2 H5 권위 자료 연결

서버 DI는 `eng/world-seedbeds/generated/h5-world-layout.v1.json`을 읽는 `FileSimulationWorldLayoutCatalogReader`와 `H5AuthoritativeSimulationLhCellContentSource`를 등록한다. 현재 H5 구성 대장은 다음을 포함한다.

- 구성 대장: `world-layout:sim:pyeongchang:nature-farm-hub-town.v1`, revision 2
- AreaSet 4개: Farm, 기존 `CityHub`, NatureHome, Town
- H3 Graph instance 14개
- 영역 간 corridor 3개
- 구성 대장 hash: `5a60deb9205ec983a2dc11dd417eb23a24488c78ef28ff185953f4674060c603`

H5 공급자는 셀마다 가장 가까운 H4 AreaSet과 H3 Graph를 선택하고, 해당 셀 안의 H3 기준점을 표현 전용 배치 객체로 만든다. 또한 네 방향 연결선을 생성한다. H5 기준점은 `CollisionEligible=false`, `PresentationOnly=true`이므로 실제 건물·도로·충돌 지형의 완성을 뜻하지 않는다. H1과 H2 결속도 현재 H5 공급자 결과에는 포함되지 않는다.

매개변수 없는 `SimulationLhWorldService` 생성자는 여전히 `ScenarioProceduralSimulationLhCellContentSource`를 사용하지만, 실제 서버 DI는 H5 공급자를 명시적으로 주입한다. 시험은 H5 대장이 없을 때 서버가 절차생성으로 조용히 후퇴하지 않는 것도 확인한다.

### 3.3 API와 권위 경계

조회 경로는 `POST /api/simulation/v1/world-stream/lh/cells/preview`이다.

- 입력은 정확한 Transform이 아니라 L3 셀 키, 세션, 이동 방향, 필요한 능력, 기대 세계 개정 번호다.
- 서버 세션의 날짜·WorldTick·WorldRevision을 사용한다.
- 오래된 `ExpectedWorldRevision`은 충돌로 거부한다.
- 결과는 `IsCandidateOnly=true`, `DoesNotApplyResourceLedgers=true`, `IsOperationalState=false`다.
- Preview는 공간 권위, 운영 원장, 자원 원장을 변경하지 않는다.

### 3.4 저장·재생

`SimulationLhWorldStateSnapshot`과 저장·재생 검증은 다음 정보를 봉인할 수 있다.

- 월드 시드와 생성기 판본
- AreaSet revision과 경계 hash
- 마지막 L3 위치
- 선택적인 H5 데이터 계보
- 발견, 상태 변경, 배치, 제거 변화량

서버 시험은 기본 월드 전체가 아니라 시드와 변화량을 저장하고 다시 재생하는 계약을 확인한다. 다만 Unity 저장 코드에서 로컬 LH 상태를 수집해 이 상태 사본으로 전달하는 호출은 발견되지 않았다. 그러므로 저장 계약은 구현됐지만 솔로 플레이 저장 통합은 부분 구현이다.

## 4. Unity 구현 현황

### 4.1 서버 없는 솔로 플레이

`로컬공간LHWorldEngine`은 서버 접속 없이 플레이어 위치, 월드 시드, 로컬 날짜로 셀 계획을 생성한다. 저장된 `SimulationWorldShell`을 여는 EditMode 시험은 다음을 확인한다.

- `공간LHStreamingEngine` 존재
- L3 월드 크기 125m
- `LH_L3CellPool_125m` 존재
- 부동 원점 설정 존재
- `공간TileStreamingCompositionRoot.서버기준사용중 == false`
- 기본 로컬 시드와 시작일 1일

따라서 **LH 주변 공간 생성 자체는 서버 없는 솔로 플레이 경로가 기본값**이다. 이것이 전체 Simulation의 모든 기능과 저장이 서버 없이 완결됐다는 뜻은 아니다.

`서버기준사용=true`이면 동일한 Repository 계약을 통해 서버 LH Preview를 사용한다. 실제 E5 AreaSet Network 조회는 별도 경계이며, 서버 설정이 없거나 응답이 실패해도 로컬 타일 플레이를 유지하도록 구성되어 있다.

### 4.2 스트리밍 생명주기

셀은 다음 상태를 거친다.

`Requested → DependenciesReady → GeneratedDataReady → VisualPrepared → PlayerTraversalReady → Active → Cached/Released`

실패 상태도 별도로 존재한다. 구현된 실행 제어는 다음과 같다.

- 새 요청 epoch가 이전 늦은 응답을 덮어쓰지 못하도록 차단
- 활성 창 밖 셀을 캐시하고 용량을 넘으면 해제
- NPC 경로 앞쪽 셀을 보조 관심점으로 선행 준비
- 2km 이상 이동할 때 월드 Root를 125m 배수로 이동
- 주 스레드 조립을 프로필의 2ms 예산 안에서 처리
- 상세 셀에서만 카탈로그 Prefab 배치를 시도

### 4.3 시각·충돌·이동 능력의 한계

활성·통과 필요 셀에는 Cube 바닥과 Collider를 만들고 `Collision`, `Connector` 능력을 준비 상태로 표시한다. `NpcNavigation`은 충돌과 연결선이 준비되면 논리적으로 준비된 것으로 표시된다. 소스 주석대로 실제 NavMesh 빌드는 아직 별도 능력으로 남아 있다.

`H1Interaction`도 H1 binding이 존재하면 준비 능력으로 표시하지만, 이것만으로 실제 작업 객체와 Preview→Confirm→WorldTick 행동이 연결됐다고 볼 수 없다. 누락된 시각 Prefab은 통과 가능 상태를 막지 않으므로, 스트리밍 성공과 완성된 경관도 구분해야 한다.

### 4.4 현재 공식 화면 정책과의 충돌 가능성

`단일PlayerViewController`는 Play 중 플레이어 시각 Root 이외의 모든 하위 Renderer를 끄고 Terrain도 비활성화하며, 시점 전환 Canvas만 남긴다. 30프레임 간격으로 새로 생성된 Renderer도 다시 검사한다.

LH가 생성하는 셀 바닥과 배치 객체가 플레이어 시각 Root 밖에 있으므로 현재 정책에서는 생성은 성공해도 Game View에서 숨겨질 가능성이 높다. 이는 정적 코드에서 확인한 통합 충돌이며, 실제 Play Mode·Game View로 최종 확인된 결함은 아니다.

2. **로컬 LH 저장 통합**: 활성 셀 전체가 아니라 시드·마지막 L3·발견/변경/배치/제거 변화량을 `SimulationLhWorldStateSnapshot`에 연결하고 저장·재생 hash 시험을 추가한다.
3. **H1/H2 기능 결속**: H5 기준점만 배치하는 단계에서 H2 조합 계획과 H1 작업 공간을 읽어 실제 상호작용 식별자 및 객체 능력으로 연결한다.
4. **실제 E6 지형 공급자**: 승인된 DEM, 토지피복, 경사·배치 mask, 수계, 도로·건물을 셀 내용 공급자로 제공하고, 자료 계보·revision·hash가 없는 경우 현실 근거로 승격하지 않는다.
5. **실제 이동 검증**: Collider 생성과 논리 `NpcNavigation` 표시에 머물지 않고 NavMesh 또는 동등한 이동 자료를 생성해 셀 연결구 통과, 경계 선행 적재, 재계획 폐루프를 검증한다.
