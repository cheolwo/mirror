## 현재 서버 연결의 한계

- 면목역 정의에는 전용 Region·행정동 사본 참조가 없어 metadata-only `WaitingForSpatialCoverage`다.
- 현재 Region catalog에는 사가정 패키지만 있다. 사가정 Region ID를 면목역에 재사용하지 않는다.
- 현재 Mongo 행정동 공간 투영은 면목제3·8동 하나이며 원천이 `sagajeong-reference.r3`다. 면목역 전용 투영이 아니다.
- 역 manifest의 현재 공간 참조 검증은 500m 타일 summary의 격자 교차를 보지만 실제 tile payload의 경계·hash·도형 교차까지 읽어 검증하지 않는다. 면목 참조를 먼저 붙이면 빈 교차 tile까지 준비된 것으로 보일 수 있다.

따라서 이번 점검으로 면목역을 `PartialCoverage`로 승격하지 않는다.

## 가장 작은 다음 절편

1. 공통 공간 추출기를 역 descriptor와 1km 창을 받도록 매개변수화한다.
2. 서울 건물 원천을 창으로 먼저 자르고 원본 법정동 코드를 보존한다. 면목동 밖 결손은 `MissingBuildingCoverage`로 남긴다.
3. 같은 창에서 전국 표준노드링크를 자르되 방향별 link 의미를 보존한다.
4. 위 6개 행정동 교차와 실제 생성된 500m tile을 면목 `private-review.r1` manifest에 기록한다.
5. 실제 tile payload의 schema·ID·hash·bounds·경계와 창 안 건물/도로 교차를 서버가 검증한 뒤에만 `PartialCoverage` 후보로 삼는다.
6. 면목 전용 표면 원천과 건물 이용조건이 검토되기 전에는 `Ready`, 공개·배포·통행·gameplay·Unity Runtime을 승인하지 않는다.

이 절편의 목표는 빈 구역을 사실처럼 채우는 것이 아니라, 어떤 자료가 있고 없는지를 유지한 채 두 번째 역에서도 같은 모듈 경계가 작동하는지 확인하는 것이다.

여기서 `private-review.r1`은 후보 산출물의 판본 이름이다. 기존 API 상태 코드를 새로 만드는 뜻이 아니며, 서버 상태는 payload 검증 전까지 `WaitingForSpatialCoverage`다.
