# 동북서울 30개 행정동 디오라마 깊이 기준선 및 주소 후보 결과

대상 기획: `PLAN-SYSTEM-ADMIN-DONG-DIORAMA` 구현 r5·r6·r8·r9·r10·r11·r12

## 결론

동북서울 30개 행정동은 모두 Unity에서 기초 형상을 조립하고 실제 Play Mode Game View로 캡처할 수 있는 `G6 UnityBaseView` 기준선을 확보했다. 동시에 61,897개 건물 전부에 PNU·도로명주소 후보 판정 상태를 로컬 MySQL 원장으로 저장하고 독립 재조회해 `G2a AddressParcelCandidateLedger`를 닫았다. 후속 자료 절편에서는 횡단보도 점 1,533건과 교차로 점 554건을 같은 30개 동에 결속하고, 사업장 후보 29,721곳과 음식 업종 후보 8,246곳을 별도 보호 원장으로 만들었다.

그러나 현행 행정동 경계, 실제 필지 도형·출입구, 실폭도로·골목·보도·차로·신호 현시, 공개 사업체의 확정 건물 결속, 생활인구, NPC·운영 생명주기가 같은 판본으로 결속되지 않았다. 따라서 30개 모듈은 사가정역 생활 디오라마와 동등한 완성본이 아니라, 결손을 눈으로 비교하고 다음 자료를 붙일 수 있는 비공개 기초 모듈이다. 새 점·사업장 후보만으로 장식 화면을 만들지 않았고 기존 30개 기초 화면을 현행 비교 기준으로 유지했다.

## 권위와 완료 상한

- 실제 서버 도구 빌드와 주소 후보 self-test 6/6, G3a Python 17/17·C# 15/15, G3b Python 15/15·C# 16/16, G4a r2 Python 25/25·C# 59,482/59,482, 각 적용 원장의 MySQL 독립 재조회, Unity 검토 묶음의 2회 무변경 재생성, Unity EditMode와 실제 Game View까지 검증했다.
- live HTTP 서버 연결, 운영 DB, 공개 API 게시, 실제 길찾기, 차선·신호 제어, NPC 생활상, 주문·배차·정산은 검증하지 않았다.
- `currentPointerUsed=false`, `distributionApproved=false`, `traversalReady=false`, `gameplayReady=false`를 유지한다.
- 기존 역세권 디오라마 규칙의 `MissingCoverage`, 실제 Game View와 게임플레이 증거 분리, 역사 경계 비승격 원칙을 지지한다. 새 공통 규칙 후보는 없고 기존 Candidate·E 단계도 승격하지 않는다.
- commit·push·배포는 수행하지 않았다.
