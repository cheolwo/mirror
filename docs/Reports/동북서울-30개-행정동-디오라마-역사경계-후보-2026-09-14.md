# 동북서울 30개 행정동 디오라마 역사 경계 후보

작성일: 2026-09-14
기획: `PLAN-SYSTEM-ADMIN-DONG-DIORAMA r4`
결과: `HistoricalBoundaryCandidateBatchStoredAndVerified / CurrentPublicationBlocked`

## 결론

광진구 4개, 동대문구 10개, 중랑구 16개 행정동을 같은 좌표계와 같은 생성 규칙으로 잘라 30개 디오라마 입력 모듈로 만들었다. 건물 61,897개와 도로 선분 11,769개를 C# 투영기로 다시 조립해 500m tile 297개를 만들고, 로컬 MongoDB의 현행 자료와 분리된 candidate collection에 358개 문서로 저장·독립 재조회했다.

다만 사용한 서울시 경계 파일은 실제 내용이 2023년인 역사 자료다. 따라서 이 결과는 행정동별 자료 수집·분석·표현을 위한 비공개 후보이며, 현행 행정동 경계·공개 배포·Unity 배치·통행 가능성을 증명하지 않는다. 최신 주소정보누리집 `TL_SCCO_GEMD` 서울 전체분을 승인 반입해 같은 파이프라인으로 다시 생성하기 전에는 API current pointer를 바꾸지 않는다.

## 공간 처리 결과

### 건물

- 61,897개를 원본 `PointOnSurface`가 포함되는 하나의 행정동에만 귀속했다.
- 미해결 27개는 경계 밖 13개, 원본 무효 형상 11개, 1mm 반올림 후 자기교차 3개다. 복수 판정은 0개다.
- v1 계약이 외곽 ring 하나만 지원해 hole이 있는 건물 16개의 내부 ring 18개는 감사자료에만 남겼다. multipart 생략은 0개다.
- 원본 법정동 코드와 동결 crosswalk가 다른 259개는 진단으로 남겼고 공간 판정을 덮어쓰지 않았다.
- 중복 원본 ID 23개는 결정적 suffix로 분리했다. 원본 판정점과 v1 외곽 ring 판정이 다른 2개는 명시적 assignment anchor를 보존했다.

### 도로

- 합집합 경계와 교차하는 방향 NodeLink 4,209개를 행정동별 출현 4,620개로 절단했다. 397개 링크가 둘 이상의 행정동에 걸린다.
- 최종 결과는 100m 이하 두 점 선분 11,769개이며 최대 길이는 99.86221m다.
- 1mm로 게시한 경계에 다시 잘랐고 1µm 허용오차보다 많이 경계 밖으로 나간 선분은 0개다. GEOS의 정확 `covers`가 거짓인 454개는 최대 약 `1.303e-11m`의 부동소수점 잔차이며 모두 허용오차 안이다.

## 결정성·저장 증거

- 반복 Python build: `changedFiles=0`; `verify`, `self-test`, Python compile 통과.
- Python 도구 영수증: Python 3.12.14, pyshp 2.3.1, pyproj 3.7.2, Shapely 2.1.2, GEOS 3.13.1, PROJ 9.5.1, EPSG DB v11.022.
- C# 반입기는 원본·scope·생성기·각 module hash를 확인하고, 원본 `OA-22160`을 독립 변환한 경계와 생성 경계의 모든 꼭짓점이 2mm 이내인지 검사했다.
- 기존 투영 Builder가 입력 건물 61,897개와 도로 11,769개를 모두 받아 297개 tile로 조립했다.
- Mongo candidate batch: `candidate-batch:ff8689fb8cee013e4ccf88bca2bf4acd9986f418f1f561fa5b50c0f06b1c2b1f`.
- 첫 적용은 358개 문서를 삽입했다. 반복 적용은 신규 0개·정확히 같은 기존 문서 358개였고, standalone verify와 새 연결 독립 재조회가 통과했다.
- `administrative_dong_diorama_current` 대상 수는 1개로 유지됐고 snapshot hash `F60B1913F67E4DEEB15C6CBE69BA5A1BBE28041952219BC358F45053759374FD`는 적용 전후 같았다.
- 과거 r1 candidate는 삭제하지 않고 `PreservedNotPromoted`로 보존한다.

## 검증 상한과 다음 관문

- Python `verify`·`self-test`와 결정적 재생성, C# preview·standalone Mongo verify가 통과했다.
- 서버 집중 회귀는 경계 reader·투영 Builder·조회 UseCase·Controller·배달운영권역 source 합계 34/34, Unity 읽기 계약은 4/4가 통과했다.
- 이번 16개 파일로 제한한 Fast 검증은 `git diff --check`, 서버·시험 project build와 표적 시험을 통과했고 상세 기록은 `artifacts/local/validation/20260914-224141`에 있다.
- 역세권 디오라마 증거 대장 검사는 `Sources=10 / Rules=12 / Candidates=12 / Provisional=0 / Accepted=0`으로 통과했다. 이번 결과는 `자료 결손은 실제 공터가 아니다`, `원천·Simulation·Unity 표현을 분리한다`, `보충 공간층은 원천별 시각·좌표계·권위를 보존한다`는 기존 후보 규칙을 지지한다. 새 공통 규칙 후보는 없고 자동 승격도 없다.
- 완료: 공식 출처 조사, 동결 입력 영수증, 30개 경계 fan-out, 단일 건물 귀속, 도로 경계 절단, 결정적 재생성, candidate 저장·멱등 재적용·독립 재조회, current 불변.
- 미완료: 최신 `TL_SCCO_GEMD` 반입, SGIS 독립 경계 대조, 공개 배포 권리 확정, 주소·필지·출입구, 골목·보도·차로·신호·통행 그래프, 업체·광고, Unity Scene·Prefab·Play Mode·Game View.
- 공용 current 저장 경로의 기존 `ProjectionHash`는 manifest의 생성 시각·좌표 프레임·범위·권위 플래그와 overlay 기준 시각을 모두 포함하지 않으며 중복 시 전체 BSON까지 대조하지 않는다. r2 candidate는 전체 투영 집합 hash와 exact BSON 검증을 사용하므로 이번 후보 무결성에는 영향이 없지만, 공개 승격 전에 공용 hash·중복 본문 검증을 보강해야 한다.
- 실제 반복 apply·독립 verify는 통과했지만 BSON 상한, 중간 종료 후 복구, 미래 current drift, orphan 충돌을 주입하는 batch 전용 자동 통합시험은 아직 없다. 공개 승격 전 회귀 시험으로 고정한다.
- 다음 실행 관문은 최신 JUSO 서울 전체분의 기준월·파일명·SHA-256·이용조건을 동결하고 `행정동경계JusoShapefileZipReader`로 30개 경계를 재생성하는 것이다. 경계·코드 기준일과 위상이 맞고 역사 후보와의 차이를 사람 검토하고 공용 current 저장 검증을 보강한 뒤에만 면목제3·8동 하나를 먼저 current 교체 후보로 올린다.
