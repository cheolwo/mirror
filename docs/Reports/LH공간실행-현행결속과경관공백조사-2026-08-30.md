# LH 공간 실행: 현행 연결과 경관 공백 조사

- 작성일: 2026-08-30
- 상태: 읽기 전용 소스 조사와 후속 제안. 신규 구현·기획 승인·E 승격 아님.
- 요청: 기존 LH를 적절히 활용하여 공간과 경관을 발전시키기 전에 부족한 부분을 조사한다.
- 증거: 아래 소스와 문서의 정적 대조. 이번 조사에서는 게임 빌드·시험·Editor·Play Mode·Game View를 실행하지 않았다. 병렬 작업 중인 파일은 조사 이후 달라질 수 있다.

## 1. 결론

LH의 기본 기능 부재보다 **승인된 공간 계획을 실제 셀에 연결하고, 실제 사용 가능 여부와 재진입을 증명하는 과정**이 우선이다. 아름다운 공간 구성은 지도·배치 계획과 LS-01 경관 연구가 맡고, LH는 그것을 언제 준비·활성·캐시·해제할지 맡는다. 이번 조사를 이유로 모든 책임을 LH로 합치거나 새 엔진을 만들지 않는다.

## 3. 우선 조사·보완할 공백

### P0 — 실제 준비 능력의 구분

`공간LHStreamingEngine.ApplyPlan`은 바닥 준비 후 Collision·Connector를 추가하고, H1 연결 표기가 있으면 H1Interaction을 추가한다. NPC 경로 요청에는 Collision·Connector가 있으면 NpcNavigation을 추가한다. 이 지점만으로 실제 출입구·상호작용 기준점·목적지까지의 이동 가능성을 증명하지 못한다.

후속 기술 검증은 표면 표시, 충돌, 연결 지점, 플레이어 통행, NPC 경로, WI 상호작용을 각각 확인해야 한다. 기존 식별자나 저장 계약을 곧바로 변경하지 말고 실제 소비자가 어떤 준비 상태를 요구하는지 먼저 추적한다. 이는 사용자에게 농장 규칙을 다시 고르게 할 사안이 아니다.

### P0 — 활성화와 표현 검증 성공의 차이

`World공간표현조립Coordinator.ApplyPreparedCell`은 조명 검증 실패를 DirectionalLightingRejected로 기록하고 PresentationReady는 추가하지 않지만, 반환값은 true다. 호출 측은 그 뒤 셀을 Active로 만든다. Sky가 없을 때도 SkyUnavailable을 기록하고 이후 조립을 계속한다.

따라서 Active를 완전한 표현 검증 성공으로 보고하면 안 된다. 경고를 허용하는 표시와 상호작용 차단이 필요한 실패를 분리할 필요가 있다. 이번 조사만으로 어두운 셀을 숨기거나 이동을 차단하도록 변경하지 않는다. 실제 현상 재현·소비 경로 대조가 먼저다.

### P0 — Farm 경관 계획의 실제 소비

H5 공급자의 존재, Farm H2 후보의 자동시험, 실제 Scene 배치는 서로 다른 증거다. 개발의 최신 D362 반환은 동일 조건 A/B 비교와 자산 실측 절차를 제한된 연구 기준으로 수용한 상태이며, 후보 승인·수관 가림 완화·국소 조명·Farm과 Sky의 동일 상태 사본·생활 흔적 공급 완료가 아니다. 이 보고서는 해당 전문 근거를 재검증하거나 승격하지 않는다.

승인된 후보의 셀·좌표·H·배치 객체 식별자·권위 개정이 실제 LH 응답과 Unity 소비에 어떻게 이어지는지 개발이 정리하고, 공간 담당이 동일 조건 비교와 Game View를 검증한다. [기존 LS-01 문답](../Architecture/PlayableLoops/PlanningSessions/건물공간배치/landscape-composition.inquiry.r1.md)의 승인 사항을 반복 질문하지 않는다.

### P1 — 경계 통과와 재방문

세계 개정 알림과 계획 hash 검사는 이미 있다. 다만 그것만으로 수확·벌목·건설 결과가 셀 해제 후 복귀해도 유지되고, 객체가 중복되지 않으며, 강·길·건물 경계가 이어짐을 보장하지 않는다.

같은 계획 식별자의 조용한 변경을 거부하는 기존 원칙을 유지하면서, 승인된 새 판본으로 바꾸는 실제 경로를 검증한다. 권위 상태 저장과 표현 캐시는 분리한다. 표면 이음새·법선·길 연결·경계 건물 소유는 현재 결함으로 단정하지 않고 재현 항목으로 둔다.

### P1 — 높은 관리 시점과 조립 성능

조립 예산과 캐시가 이미 있으므로 기능을 다시 만드는 제안은 하지 않는다. 현재 예산 처리는 작업 사이에서 시간을 확인하므로, 무거운 단일 조립의 비용은 별도 측정이 필요하다. 높은 관리 시점·빠른 이동·NPC 관심 셀 증가에서 보이는 범위, 준비 범위, 실제 이동 범위를 대조한다.

원경 랜드마크와 가까운 상세 표현을 어떻게 나눌지는 이후 시각 기획 후보다. 화면 밖 NPC의 업무 진행을 렌더링 활성 여부에 종속시키는 규칙은 승인하지 않는다.

### P2 — 설명 문서와 현재 코드의 정합성

[LH 공간 실행 계층](../Architecture/LH공간실행계층.md)의 향후 공급자·재계획 설명과 달리, 현재 코드에는 H5 권위 공급자·서버 등록·NotifyAuthorityRevision이 있다. 그러나 이를 실제 전체 실행 연결 완료로 고쳐 써도 부정확하다. 현재 구현, 호출 연결, 실제 검증을 나눠 기준 문서를 정리하는 것이 적절하다.

## 4. 제안하는 첫 검증 단위

**강변 Farm을 멀리서 발견 → 자유롭게 접근 → 밭·건물 주변 이용 → 떠남 → 재방문해 같은 공간과 작업 결과 확인.**

- 지도·배치: 기존 승인 후보와 LS-01 구성을 사용한다. 강제 이동 경로를 추가하지 않는다.
- LH: 필요한 셀 선행 준비, 준비 능력 확인, 캐시·해제·재진입을 담당한다.
- Sky·표현: 같은 상태 사본에 맞는 날씨·조명·배치를 확인한다.
- Simulation: 작물·자원·건설 등 확정 상태의 권위를 유지한다.
- 공간 전문: 비교 이미지와 실제 Game View·입력·경계 통과를 구분해 증거를 남긴다.

이는 새 실행 승인이나 E5 완료 선언이 아닌 후속 범위 제안이다. 기존 승인 작업은 계속 진행하며, 기술 누락 때문에 이미 답한 공간 취향을 재질문하지 않는다.

## 5. 다음 문답의 방향

먼저 기존 승인과 기술 공백을 닫고, 실제 비교 자료로 아직 정하지 않은 플레이 경험만 묻는다. 첫 후보는 **높은 시점에서 먼 농장을 어느 정도까지 식별하고 싶은가**이다. 지붕·강·밭 윤곽 같은 원경 정보와 가까운 작업 소품·상호작용을 구분하는 방향을 제안하되, 거리 수치나 모든 건물의 원거리 완전 조립을 미리 확정하지 않는다.

기획 질문은 LH 내부 알고리즘을 사용자에게 대신 결정하도록 요구하지 않고, 발견·접근·활동·재방문에서 무엇이 보여야 자연스러운지를 중심으로 만든다.
