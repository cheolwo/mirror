# 면목역 1km 관찰 디오라마 구현 기록

## 결과

면목역 `station:kr:kric:s1107:0721`의 공식 기준점(위도 37.588671, 경도 127.087503)을 중심으로 정북 1,000m × 1,000m인 비공개 검토용 공간 사본을 만들었다. 사가정 도형이나 지역 식별자를 복사하지 않았고, 수집 뒤에도 근거가 부족한 부분은 합성하지 않고 `MissingCoverage`로 보존했다.

- 사본 schema: `ssalddel.station-spatial-snapshot.v1`
- revision: `myeonmok-station-spatial-snapshot.private-review.r1`
- 상태: `LocalPrivateReview / PassedWithMissingCoverage`
- content hash: `48FED5BFA9B06075B27D7DCF22EFDF3AE3F98222D337D0298C01C098A62B913A`
- 파일 SHA-256: `4B8D45AE3414218228FEB1436AE8E99AB3999C83A30607292AC594C0099530B1`
- 파일 크기: 10,111,746 bytes
- audit hash: `14443C09D65ABA18CCF9D9369136EB0B839584AB29C9F887E28D38B1A17DFC24`

```text
동결 공공·공개 원천
├─ 국가철도공단 역 기준점
├─ 건물 도형·높이 근거
```

## 원천·수집 경계

- 기존 동결 자료는 국가철도공단 도시광역철도 역사정보, VWorld 계열 건물 자료, 표준 NodeLink, 서울시 행정동 경계를 재절단했다.
- 면목역 표면 후보는 OSM API v0.6의 정확 bbox `127.0818422,37.5841659,127.0931645,37.5931758` 한 번만 수집하고 원본과 영수증을 동결했다.
- OSM 원본은 1,503,543 bytes, SHA-256 `BD218CB2D9CC49F996DB7BCF2384F6950CCEAC772D5322987879AA21570D0A66`이다. 후속 검증은 `ReusedFrozenSource / networkRequested=false`로 수행했다.
- OSM은 ODbL과 저작자 표시를 보존하며, 다른 원천과 결합된 전체 사본의 배포 권리는 승인하지 않았다.

## 로컬 영속화

기존 `eng/Ssalddel.PublicDataPortalImport`에 `myeonmok-station-spatial-*` 명령을 추가했다. 로컬 Docker MySQL `hongdal-mysql-1 / hongdal_dev`의 비공개 검토 원본 대장에 OSM 원본·영수증과 공간 사본·감사 결과 네 건을 ID 48~51로 저장했다.

- 첫 적용: 네 건 등록
- 같은 입력 재적용: 신규 0건
- 별도 프로세스 `verify`: ID 48~51과 hash·수량·결손을 독립 재조회
- 공유 운영 DB·원격 DB: 미변경

## 서버 조회 경계

면목역 지역 Experience Package와 역세권 manifest에는 1km 사본 후보의 revision, hash, byte 길이, 수량과 결손 코드를 넣었다. 그러나 `ServerLoadable=false`, `WaitingForSpatialCoverage`, `DistributionApproved=false`, `TraversalReady=false`, `GameplayReady=false`를 유지한다.

현재 Mongo 공간 투영은 `administrativeAreaStableId`별 current projection 하나를 소유한다. 역 중심 좌표계로 자른 면목역 자료를 여섯 행정동 current projection에 게시하면 기존 행정동 자료, 특히 사가정에서 만든 면목3·8동 사본을 덮어쓰거나 좌표계를 섞게 된다. 그래서 이번에는 `StationScopedProjectionStoreContractRequired;AdministrativeAreaCurrentProjectionMustNotBeOverwritten`로 게시를 차단했다. 건물 hole과 도로 polyline을 손실 압축해 기존 행정동 계약에 끼워 넣지도 않았다.

기존 행정동 사본을 역 manifest가 참조할 때는 tile summary뿐 아니라 실제 payload의 schema·행정동 ID·projection hash·tile ID/hash/index·수량·500m 경계·실제 도형 교차까지 검사하도록 강화했다. 한 tile이라도 모순이면 그 행정동 연결 전체를 버리고 역 metadata만 `WaitingForSpatialCoverage`로 남긴다.

## Unity 표현

별도 Unity 저장소에 역별 descriptor/profile, 비공개 사본 경로 해석기, JSON 계약 검사, fail-closed 조립기, 4×4 Mesh 조립기와 공통 View를 추가했다. 면목역은 `SSALDDEL_MYEONMOK_STATION_SPATIAL_SNAPSHOT` 환경 변수 또는 Editor 설정으로만 로컬 사본을 읽고, 경로나 원문을 자산·Scene·로그에 영속화하지 않는다. 파일 부재·hash/revision/역 ID·좌표·권리·수량이 어긋나면 다른 역 도형을 섞지 않고 `NoData / MissingCoverage`로 돌아간다.

실제 10,111,746-byte 사본 교차 실행은 성공했다.

- 조립 상태: `LocalPrivateReview / PartialCoverage / Ready`
- 실제 해석: source receipt 5, 건물 4,165, 도로 124, 표면 48, 행정동 6, coverage cell 100, 결손 항목 5
- Mesh: 4×4 chunk 16개, renderer batch 16개, vertex 127,629개, triangle 67,935개
- 안전성: 잘못된 index 0, 모든 vertex 유한, `MissingCoverage` cell 2개 유지
- 제품 코드와 실제 parser·Mesh·View 직접 실행 직전 Unity 재컴파일: 신규 Console 오류 0
- canonical Scene 변경: 없음

새 focused EditMode 15 case는 Unity 시험 목록에 등록됐고, Play Mode가 완전히 끝난 것을 확인한 뒤 컴파일된 fixture를 직접 호출해 15/15 통과했다. 정식 Test Runner는 두 차례 실행을 요청했지만 새 결과를 게시하지 않고 이전 사가정 시험 7/7 결과만 유지했으므로, 정식 Runner 통과로는 보고하지 않는다. 복원 후 Unity 생성 `Ssalddel.Unity.Tests.EditMode.csproj` 전체 build는 최종 소스에서 오류 0·기존 경고 888개로 통과했다.

실제 Unity `6000.5.6f1`의 canonical `SimulationWorldShell`에서 Play Mode를 실행하고, 면목역 View를 임시 host로 붙여 Unity 자체 `ScreenCapture.CaptureScreenshot`으로 Game View를 캡처했다. 화면에는 `면목역 1km 공간 표현`, `LocalPrivateReview · PartialCoverage`, 건물 4,165·도로 124·표면 48·`MissingCoverage 2`, snapshot `48FED5BFA9B0 · Ready`가 표시됐다. 사가정 View와 면목역 View의 `OnGUI` 좌표가 겹치는 현상은 남아 있어, 면목역 단독 증거에서는 기존 사가정·역 방어 UI만 Play Mode 중 일시 비활성화했다. 면목역 관련 Console 오류는 0건이었지만, 서버를 연결하지 않은 canonical Scene의 다른 composition root와 기존 replay에서 범위 밖 오류 9건이 발생했다.

- 단독 Game View: `artifacts/local/validation/myeonmok-station-gameview-r2/myeonmok-station-playmode-gameview-clean.png`
- 캡처 SHA-256: `E34E68888776895B126517D8686080D5B2E89B6FB607C0546A6AC2710849DBE9`
- 실행 전후 Scene SHA-256: `36D81A6986598F08D1EA1EA94E83F7FC7BD2D67B166FE6ABA4ED2A1395A34C55`로 동일
- Scene 저장: 없음, 종료 후 `isDirty=false`, 임시 Editor 설정 복원 완료

## 완료하지 않은 범위

- 역 전용 Mongo 저장소와 station-scoped tile API
- 면목역 View의 canonical Scene 영속 결속과 사가정·면목 공존 overlay 배치
- 공개·배포 승인과 CDN/Resources 영속 자산화
- 도로 폭·보도·NavMesh·통행·방어 gameplay 권위
- 운영 주문·배차·기사 위치 또는 개인정보 결합
- 모바일·Web 화면 변경
- 원격 push와 배포

가장 이른 후속 구현 지점은 기존 행정동 current projection과 독립된 역 범위 공간 저장 계약이다. 그 전에도 Unity 로컬 비공개 관찰 표본은 사용할 수 있지만, 서버 제공 완료나 실서비스 준비로 표현하지 않는다.
