- 후보가 있는 역사 행정동: 30개
- 대상 밖 원본: 19,770행
- 원천 자치구와 역사 경계 귀속 자치구 충돌 후보: 48개
- 둘 이상의 행정동에 걸친 원천 LINK: 728개

  `43248F7F563DCDFE059650F3EC000085CD0D7CFB65FC5300EFDFCBDD685990AA`

후보 40,739행과 계보 사본 17건을 저장하고 새 연결 독립 재조회와 반복 무쓰기를

## 식별·공간 검증

현재 CSV에는 `RONUM` 열이 없다. 원천 occurrence는 `동결 CSV 역할 + 1부터 시작하는
data-row 번호`로 만들며 NODE와 LINK 식별자 모두 이 값을 포함한다. 따라서 완전히
같은 원문 행이 반복돼도 하나로 합치지 않는다. 원천 ID는 후보 원장에 digest로만
전달한다.

NODE는 역사 경계 하나가 점을 덮을 때만 귀속한다. LINK는 EPSG:5186에서 역사 경계로
실제 절단한다. 방향을 뒤집어도 같은 1mm 정수 좌표 물리 조각 hash가 되게 하고,
행정동 공유 경계와 일치한 물리 조각은 양쪽 후보로 보존하도록 했다. 이번 동결
입력에서는 공유 경계 완전 일치 물리 조각이 0개였으며 동일 행정동 안 중복 조각도
0개다.

원선과 대상 30개 경계 합집합의 교차 길이는 882,519.308089m이고, 고유 물리 조각
합집합 길이도 882,519.308089m다. 원천 LINK별 최대 길이 보존 오차는 0m였다.
1mm 좌표로 직렬화한 각 fragment가 지정 경계의 2mm 수치 허용대 안에 다시 포함되고
허용대 밖 선 길이가 1mm 이하인지 검사했다.

## RDB 검증과 알려진 문제

C# importer는 전체 98,781,674-byte 후보 파일을 읽어 같은 framed hash를 Python
호출 없이 독립 재계산했다. geometry를 2,000자 이하 RDB payload에 복제하지 않고
40,739개 요약 후보와 정확 17개 계보 snapshot을 로컬 MySQL에 저장했다. build는
경고 0·오류 0, 자체 시험은 16/16이고, 새 연결에서 30개 동 exact set과 후보 hash를
재조회했다. 동일 입력 반복 적용은 신규·갱신·snapshot 0이다.

G3a r2·G3b r1·G4a r2·사가정 r27 `OA-21208`을 포함해 importer가 보호 대상으로
고정한 71,501행·snapshot 84건·ingestion run 84건의 전체 상태 digest는 G3c 적용
전후 같았다. 부분 적재와 잘못된 기존 결속을 DB 쓰기 전에 거절하는 반례까지 포함한
최종 C# 독립 감사도 High·Medium·Low 0이다.

G3b r1의 기존 동반 자료 계약은 실행 전 문서라
`ledgerPersistenceCompletedClaimed=false`와
`consumedCandidateDatabasePersistenceCompleted=false`를 유지하지만, 후속 보고는 실제
DB 저장·재조회 완료를 기록한다. 이 서로 다른 의미의 flag 불일치는 기존 파일을
조용히 고치지 않고 알려진 계약 정합화 문제로 남긴다.
