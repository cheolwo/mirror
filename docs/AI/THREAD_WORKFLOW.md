## 2026-11-11 사용자 직접 요청 — 데이터 수집 채팅 분리

사용자가 기존 수집 자료를 전수 조사하고 데이터 맥락별 채팅과 정기 수집 예약을 만들도록 별도 요청했다. 이 요청 범위에서는 [데이터 수집 운영](DataCollection/README.md)에 명시한 전용 채팅·예약을 허용한다. 보관된 전문 개발 채팅을 재개하는 조치가 아니며 웹·앱 마감과 WPF 예약의 일시정지는 유지한다. 개인 배달 관측은 기존 예약4의 내용·6시간 주기·상태를 보존해 전용 채팅으로 옮기고, 프랜차이즈의 기존 예약7은 그대로 둔다.

수집 채팅은 공급자별 제한 원본과 자신의 결과 기록만 쓴다. 공통 제품 파일·CURRENT_WORK·실행 정책을 각 채팅에서 동시에 편집하지 않으며, 공개 원본 취득은 별도 OS 수집 잠금을 사용한다. DB 반입·게시·게임 적용·제품 빌드·USB 조작은 일반 공개 수집의 후속 동작으로 자동 실행하지 않는다. USB는 기존 예약4의 별도 phone-ui.lock과 전체 보호 절차를 따른다. 정확한 연결은 [예약·채팅 등록 기록](../../artifacts/local/data-collection-audit-20261111/automation-links.json)을 우선한다.

2026-11-08 사용자가 반복되는 전문 채팅 접근 요청 뒤 “그냥 거두어들여줘”라고 명시했다. 미러 개발은 기존 **리팩토링 채팅** `01a0d5d5-5aa7-7b50-a338-ec91d95d5012`에서 통합한다. 제품 루트는 `C:/Users/user/source/repos/Hongdal`이다.

## 0-1 — 현재 예약과 보존

- 통합 예약 `1-2` 하나를 이 채팅에서 **1시간마다, 한국 시각 매시 15분** 실행한다.
- 전문 채팅 네 곳은 기록을 지우지 않고 보관했다. 개별 예약 `30`·`ui-ux-30`·`ai-30`·`automation-6`을 중지한 뒤, 채팅 보관 후 네 예약이 제거된 것을 확인했다. 옛 예약을 다시 만들지 않고 이 채팅의 통합 예약 하나만 등록했다.
- 이 통합 지시는 과거 ‘전문 채팅만 실행·공통 상태 작성’, ‘아이디어 채팅의 미러 실행 금지’, 별도 전문 예약 지시를 대체한다. 이전 기록은 역사적 근거이며 현재 grant가 아니다.
- 배달 수집·영상·대본과 다른 예약, 원본/기기/설정/checkpoint는 보존한다. 새 예약·전문 채팅을 만들거나 보관한 채팅을 자동 재개하지 않는다.
- [통합 전 원문·상태·설정 사본](../../artifacts/local/thread-workflow-20261107/consolidation-20261108/before-manifest.json)과 [통합 실제 검증](../../artifacts/local/thread-workflow-20261107/consolidation-20261108/verification.json)을 보존한다. 보관은 제품 수정·화면 검증 완료가 아니다.

## 0-2 — 현재 운영: 기존 웹·앱 마감

2026-11-09 사용자의 요청에 따라 이미 구현된 업무를 [통합 앱 마감표](../Versions/unified-1.0/checklist.md)와 대조해 회차당 한 항목을 마감한다. 진행 중인 필수 검증과 같은 판본의 증거를 먼저 확인한다. 다음으로 입력·데이터 오류, 진행·복귀 차단처럼 실제 사용을 막는 기존 문제를 우선한다. 기존 사용자 흐름에서 재현된 결함만 현행 계약 안에서 최소 수정하고 관련 회귀·소비 빌드·필수 검증으로 마감한다. 새 기능·화면·API나 업무 정책은 별도 요청에서 다룬다.

실행 제한이 남으면 항목의 기존 대기 상태와 정확한 재개 조건을 보존한다. 거절된 실행을 반복하거나 우회하지 않는다. 실행 소유가 비어 있고 자원·작업 범위가 겹치지 않을 때만 이미 구현된 다른 항목의 미완료 검증을 한 건 진행한다. 대기 항목을 지우거나 덮어쓰지 않는다. 확인 가능한 일이 없으면 기존 기록을 유지한다.

### 이전 옵션 D — 미완료 검증

2026-11-09 사용자 요청에 따라 이미 작업한 항목의 미완료 검증을 이어간다. 실행 가능한 검증은 바로 수행하고 결과를 기록한다. 동일 판본의 통과 근거를 재사용하며 실행 제한이 남은 화면은 기존 재개 위치에 둔다. 이전 D 예약에서는 새 정리 후보를 고르지 않았다. 현재 예약에는 위의 마감 기준을 적용한다.

### 옵션 A를 선택했을 때의 코드·화면 정리

2026-11-09 사용자는 **옵션 A(코드·화면 정리)**와 30분 주기를 선택했다. 예약 문구에는 실행 범위와 우선순위를 두고, 세부 기준은 이 문서에, 미완료 항목과 재개 위치는 CURRENT_WORK와 현재 실행 상태에 둔다. 예약 주기는 현장 업무 마감이나 묶음 처리 주기와 별개다.

현재 기능·중요 값·권한·업무 흐름·route/stable ID·허용 행동을 보존하면서 중복 코드·긴 함수·복잡한 조건·이름/관심사 혼합, 화면의 읽는 순서·글자·간격·줄바꿈·정렬·대비·표/카드 밀도·터치/초점·가로 넘침 중 근거가 가장 분명한 최소 부분을 정리한다. 실제 호출/주입/바인딩/동적 사용과 읽기 계약을 확인하고 기존 패턴/디자인 값을 재사용한다. 역할별 과업과 정상/빈 결과/오류·입력/적용 조건·선택/복귀를 유지한다.

예약 회차를 채우기 위해 새 기능·화면·버튼·업무 단계·API·공개 계약·저장 모델·알림·자동화·AI 학습 과제를 만들지 않는다. 별도 직접 기능 요청을 상시 확장 근거로 쓰지 않으며, 근거 없는 대규모 재명명·폴더 이동·추상화·새 프레임워크/의존성도 도입하지 않는다. 이 최신 중점은 아래의 ‘구현’을 새 기능 확장으로 해석하지 않도록 제한한다.

수정 전에 **무엇을 읽기/이해/수정하기 쉽게 할지**와 **같은 입력·선택·조회·저장·복귀에서 보존할 결과**를 기록한다. 완료 때는 실제 검증 결과와 남은 한 가지를 연결한다. 기능 수나 코드 변경량을 성과로 쓰지 않는다. 순수 코드 정리는 필요한 회귀·소비 빌드·현행 마감 계약으로 확인하고 외형이 같으면 새 화면 변경/캡처를 억지로 만들지 않는다. 실제 UI 변경의 같은 조건 전후 원본·비교와 화면 마감, 실행 제한 비우회·코드/자동시험/무서버/실제 화면의 구분은 그대로 유지한다.

## 1-1 — 실행 시작과 현재 작업

AGENTS·CURRENT_WORK 상단·이 문서·[현재 실행 상태](../../artifacts/local/thread-workflow-20261107/active-work.json)를 읽고 실제 checkout/브랜치/HEAD/dirty와 같은 편집·시험·빌드·렌더/host·기기 점유를 먼저 확인한다. 이 리팩토링 채팅이 조사·좁은 구현·검증·공통 문서 마감을 소유한다. 같은 checkout의 실행자는 한 번에 하나이며 실제 실행 전에 현재 소유·동결 지문·허용 경로와 실행/제품 쓰기 권한을 좁게 확인·기록한다. 보관한 채팅의 옛 배정/메시지/승인으로 실행하지 않는다.

통합 초기 W3의 원본·이전 dispatch는 보존한다. W3는 실제 웹/등록 USB까지 마감했고 후속 Admin의 시작 누락 보완·O1/O2 실제 브라우저 확인도 마쳤다. 과거 시작 설명을 미완료로 반복하지 않고 CURRENT_WORK와 active-work의 최신 소스·raw 검증·완료/재개 위치를 우선한다. 같은 판본의 완료 시험·화면을 이유 없이 반복하거나 진행 중 새 후보를 겹쳐 시작하지 않는다.

로그인 복귀 후속도 실제 웹/전후 비교까지 마감했다. [현재 작업](CURRENT_WORK.md)의 최신 완료·다음 한 가지를 우선하고 과거 P37 반환 주소 후보를 고정 재실행하지 않는다.

## 2-1 — 한 회차의 조사와 좁은 구현

미완료 필수 검증·새 실패·사용자 영향 높은 항목을 먼저 고른다. 다른 주문/기사/수량 표시·입력 유실, 진행/복귀 차단, 상태 구분, 가독성 순서를 대조한다. 우선순위가 같은 기존 미완료 항목은 주문→판매→입고/재고→피킹/포장/출고→배송/배차→공통 순서로 살핀다.

결과는 **확인한 업무 → 현재 판본 → 확인된 문제 또는 미완료 → 필요한 최소 작업 → 검증 방법/실제 결과 → 정확한 재개 위치**로 연결한다. 후보가 없다는 이유로 파일명·과거 완료 목록만 읽지 않고 실제 부모/컴포넌트/조회 서비스·계약과 작은 격리 재현을 대조한다. 같은 판본의 기존 후보·보호 시험은 재사용하고 근거 없는 수정이나 관련 없는 과제를 만들지 않는다. 이미 고친 기능의 화면 대기는 재구현 결함과 구분한다. 승인된 작은 보완은 같은 승인을 다시 묻지 않고 구현·검증까지 진행한다.

## 3-1 — 업무 연결과 역할별 정보

생명주기→기존 번호 메뉴의 단계→실제 처리 묶음→구성→기존 개별 업무→같은 구성/목록 복귀를 유지한다. 번호/route/stable ID·Guard·허용 행동을 보존하고 표시 순서를 자동 실행 순서로 쓰지 않는다. 단건·실제 묶음·시간 구간 조회·시스템 재조회 간격을 섞거나 없는 마감·담당·연결을 추정하지 않는다.

기존 원주문/출고/운송의 명시 키로 앞뒤 한 구간의 대상·수량·상태·다음 조건을 대조한다. 업무 확정과 Outbox 투영/알림 대기, 미확정 요청의 화면/세션/프로세스 복구 수명, 완료·수령·정산 준비·실수납/실지급을 구분한다. 기존 서버 보호를 미구현으로 재제안하거나 worker/과거 이벤트를 켜지 않는다.

[역할별 정보와 조작](../Architecture/RoleAppVisualDesignStandard.md#역할의-업무에-맞춘-정보와-조작)과 책임 카드에서 업무 질문1개·우선 정보3개·주 행동과 같은 업무 복귀·폭/입력을 정한다. 판매자는 주문/상품/수량/출고 비교, 창고는 공정/실제 묶음/구성 수량·완료/보류, 음식점은 주문/메뉴/조리 준비, 주문자는 자기 주문 상태/금액/수령, 기사는 현재 목적지·화물/메뉴·허용 행동, 운영자는 막힌 업무/다음 담당/근거·복구를 우선한다. 역할명/색만 바꾸거나 판매자 표를 전 역할에 이식하지 않는다. 없음·미확인·부분 완료·오류·표현 불가의 의미를 보존한다.

## 4-1 — 실제 화면과 수정 전후

정상 가상 업무 여러 건의 서로 다른 상태·길이·수량을 먼저 확인한다. 같은 업무의 단계·묶음·구성·개별 상세·복귀에서 ID와 수량·조회 문맥을 대조하고 관련 입력/적용 조건·로딩·로그인·오류·전체0/현재페이지만0·늦은 응답·키보드/초점을 구분한다.

웹은 실제 소비 웹의 라우터/클릭/입력, 앱은 기존 승인된 등록 USB·패키지/서명·격리 endpoint의 새 판본을 확인한다. 같은 가상 업무/입력/상태·390px/필요한320px/넓은 폭·비교 가능한 스크롤의 전후 원본과 나란한 비교 HTML을 새 artifacts/local에 보존한다. 중요한 정보·수량·주 행동·같은 업무 복귀의 퇴보를 확인한다. 정적 HTML·C# 이벤트·시험·연결 확인은 실제 화면 완료가 아니며 수정 전 미확보·다른 소비 플랫폼·물리 한글 조합·운영 사용은 미확인으로 남긴다. 필수 화면이 남으면 `screen_pending`으로 유지하고 같은 항목에서 이어간다. 실행 제한으로 막힌 경우에는 제한 해제 근거가 생긴 뒤 재개한다.

USB는 기존 공유 phone-ui.lock의 실제 OS잠금·등록 한 대/device_hash·전면·대상 패키지/서명·가상 endpoint를 확인하고 원앱/데이터/설정/배달 checkpoint를 보존한다. 같은 패키지·서명·기존 데이터 보존 검토 업데이트는 기존 승인 범위만 사용한다. 사용자 점유·보안 잠금·인증/새 권한·명확한 실행 거절을 우회하지 않는다. 화면 깨우기/일반 잠금 해제는 기존 명시 승인된 비보안 범위만 적용하고 사용자 화면 전환 시 중단한다.

## 5-1 — AI 자료와 업무 경계

AI의 [최초 r67 범위](Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-regional-training.implementation.r67.md), [이후 자료 판본](Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/local-ai-lab.guide.r1.md), [출처 검사](../../eng/CargoRegionalTrainingReview/CargoTrainingDatasetEvidence.cs)를 함께 대조한다. 출처/자료/정책/모델/프롬프트 지문과 관측 날짜, 후보·중복 격리·사람 검토·승인·미사용 평가를 구분한다. 과거 결과나 반복 관측을 현재 성능·독립 학습 사례로 올리지 않는다. 대표 한 사례의 검토 준비와 서버의 현재 후보/허용 집합 재검증·규칙 복귀를 보존한다. AI 실행은 기존에 승인된 격리 비교 범위로 한정한다.

새 업무·공개 계약·권한·생명주기/상태 전이·원장·멱등성·배정/배차·마감/일괄 확정·정산/지급 정책, 운영 쓰기·실금융·새 비용·가중치/개인자료 학습·자동 사람 승인은 이 예약에서 만들거나 바꾸지 않는다. 필요한 결정은 구체 근거/시안으로 별도 검토한다. 배달 영상/Gemini/Kling/TTS 제작·예산과 과거 전체 기기 순회는 별개다.

## 6-1 — 검증·기록과 다음 재개

실제 변경 경로만 현재 eng/validate-changes.ps1 계약에 따라 지정해 Fast·의미 있는 회귀·소비 빌드·최종 Task를 수행한다. 같은 판본에서 이미 실행한 원본 증거는 지문·범위를 대조해 재사용한다. 0-test·중간/실패·미실행은 성공이 아니다. 화면에서 작은 문제가 보이면 같은 항목에서 수정→필요 회귀/빌드→실제 화면 재확인으로 마감한다. 문서만 바꾸면 문서 전용 Fast·상대 링크·diff를 검사한다.

[통합 앱 마감표](../Versions/unified-1.0/checklist.md)와 [판본 기준](../Versions/unified-1.0/current-validation-baseline.md), CURRENT_WORK·최근 변경 기록을 대조한다. 발생 조건→수정→실제 검증→남은 한 가지를 연결하고 구현·자동시험·실제 웹·실제 휴대폰·운영 사용을 구분한다. 검증된 정상 가상 실제 캡처만 같은 화면 또는 명시 역할 후속 README에 날짜/판본·버튼·다음 화면·근거로 연결하며 전후 원본과 구판을 보존한다.

통상 아이디어 대화는 계속 받되, 보관한 전문 채팅을 반복 poll하거나 진행 상황만 중계하지 않는다. 의미 있는 완료·새 실패·필요한 사용자 결정만 알린다. 관련 없는 dirty 정리·stage·덮어쓰기·checkout 변경·배포·commit/push는 하지 않는다. [보존한 상세 UI 기준](../../artifacts/local/thread-workflow-20261107/ui-procedure-preserved.txt)은 현재 통합 책임과 충돌하지 않는 범위에서 계속 적용한다.
