## 1. 실제로 확인한 지도와 제작 경로

[J2 반환](../../Handoffs/2026-11-17-Claude-중랑구-J2-16동게임에-반환.md)의 중랑16동 입력은 2026-10-01 편집 경계 후보와 2026-11-09 건물을 사용한다. `dong-bake-jungnang-20261117-r1/proof-j2/after/01-yaw030-pitch55-default.png`와 `renders/mangu.jpg`를 직접 열었다. 전자는 기존 실행판 촬영이고 후자는 자료 기반 별도 렌더다. 이번에 새 Unity 화면을 실행한 것은 아니다.

건물은 많이 배치돼 있지만 망우 렌더의 넓은 산림은 단색 면으로 읽히고, 건물의 개별 외관 차이는 작다. **관측된 시각 문제**이며 실제 지형 원본에 높이값이 없다는 뜻은 아니다. 공통 생성 프로필 `eng/neighborhood/dong_diorama_reference.json`은 색/표시 높이/도로면 기준을 이미 소유한다. 이 설정과 진행 중 굽기 파일은 수정하지 않았다.

별도 카페 미술 시험의 `CafeFront.blend/.fbx`, 운영 소품 모델9종과 Blender5.2.1 설치를 확인했다. City 팩에는 역출입구·교량·수목 후보가 있지만 현행 일반판의 채택·대량 배치 성능은 미검증이다. 원 모델·구성 대장 존재와 실제 World 배치를 구분한다. 기존 [카페 시험 반환](../../Handoffs/2026-11-15-Codex-면목38동-카페-재질시험.md)과 [모델 제작 순서 r231](../../Planning/시스템/PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/operation-modeling-brief-for-claude.r231.md)을 이어 읽는다.

## 3. 행정동별로 실제 정리한 범위

- 기존 전국 OSM ZIP의 POI/교통/종교시설 점·면6층을 **메모리에서만** 읽었다. 새 대용량 압축해제·다운로드는 없다. 이름 관련59고유행에서 이름/분류가 맞는8후보점·면 대표점을 보존하고 버스정류장·따릉이·일반명 등을 분리했다. [추출 결과](../../../../artifacts/local/research/jungnang-landmarks-20261117-r271/osm-landmark-coordinate-candidates.json)
- 서울관광의 용마폭포·캠핑숲 공개 페이지에서 시설별 `lat`/`lng` 값을 별도 취득했다. 일반 서울 중심점과 구별했고 응답 지문/관측 바이트를 남겼다. 원 HTML을 파일로 재배포하지 않았다. [공식점·경계 확인](../../../../artifacts/local/research/jungnang-landmarks-20261117-r271/official-coordinate-boundary-checks.json)
- 중랑16동 경계 파일을 각각 지문 확인했다. 공식2점+OSM8점=10관측 중9점은 한 후보 동에, 동명 장미공원1점은 범위 밖에 있었다. 이는 **5개 시설 후보의 대표점 귀속**이며 개별 건물/출입구 배치 완료가 아니다. 16동 모두의 색인을 만들고 없는 동은 빈 후보 목록으로 남겼다. [동별 색인](../../../../artifacts/local/research/jungnang-landmarks-20261117-r271/dong-index.json)
- 용마폭포의 공식 관광점과 OSM 폭포점은 약248.89m, 공원 면 대표점과는68.59m 떨어진다. 캠핑숲의 공식점과 OSM 면 대표점은146.33m 차이다. 출입구/공원/폭포 등 다른 기준점일 수 있으므로 오류로 단정하거나 가까운 건물로 자동 흡착하지 않는다. [기준점 비교](../../../../artifacts/local/research/jungnang-landmarks-20261117-r271/coordinate-comparisons.json)

경계는 **2026-10-01 편집 후보**이며 최신 공식 행정동 경계를 확보한 상태로 올리지 않는다. 좌표점이 동 안에 있다는 사실과 시설 전체의 범위·소유·출입 방향·건물 고유 ID는 별개다. 아차산봉수대/망우공간 등의 미발견은 이번 OSM층의 결손이지 현장 부재가 아니다.

## 4. 주소기반산업지원서비스를 계획에 연결하기

**2026-11-18 후속:** [주소·출입구 재대조](2026-11-18-address-road-building-coverage-audit.md)에서 PC Downloads의 내비/주소출입구 원본을 실제 읽고 중랑구 행을 추출했다. 공개 카탈로그·샘플·가이드도 수집했다. 아래 미수령/색인 발췌는 11월17일 조사 시점 이력이다. 계정의 신청 목록·승인조건은 계속 미확인이며 원문 수령과 구분한다.

사용자가 제시한 [신청 목록](https://business.juso.go.kr/jsm/JsmAddressInfoAplyList)은 로그인 계정 화면이다. 현재 GPT 내 탭의 URL만 전달됐고 본문 읽기는 제공되지 않았다. 일반 웹 접근도 본문을 확인하지 못했다. **실제 신청 항목·승인/처리 상태·제공 기준월은 미확인**이다. 사용자의 종전 ‘신청 완료’는 사용자 전달 사실로 유지하며 수령/검증 완료로 올리지 않는다. 자료명·상태·기준월의 텍스트 확인을 요청했다.

공개 기능 설명을 근거로 다음 반입 후보를 준비했다. 파일을 실제 받았다고 쓰지 않으며 새 신청·인증·다운로드·예약은 수행하지 않았다.

## 5. 이번 결과의 상한

실제 완료는 공개 자료 조사, 소량 좌표 취득, 기존 OSM 추출, 경계 지문/포함 검사와 모델 후보·개발계획 정리다. 신규 모델·텍스처·Blender 실행·Unity 통합/새 굽기는 없다. 공식 경계/주소자료의 사용자 계정 반입·모델 파생권리 검토·현장 치수는 다음 단계다.

기존 규칙의 지지는 이름/현재 상태 검증, 원천/좌표계/기준점 분리, 외관 근거 준비 전 기본 매스 유지에 한정한다. 새 디오라마 규칙 후보 없음. 공통 규칙/E 상태를 승격하지 않았다.
