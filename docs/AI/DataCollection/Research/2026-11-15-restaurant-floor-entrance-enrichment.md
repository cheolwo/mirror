# 음식점 입점 층·건물 총층수·출입구 근거 보완

2026-11-15 사용자 요청으로 [음식점–건물 연결 자료](2026-11-15-restaurant-building-dong-binding.md)에 층수와 출입구 근거를 보충했다. 기존 자료상 영업 인허가 19,804키, 그중 건물 후보가 있는 16,988키를 대상으로 한다. [수량·출처·지문](2026-11-15-restaurant-floor-entrance-enrichment.json)과 [로컬 자료 안내](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/README.md)에 연결했다.

## 음식점의 입점 층

일반·휴게음식점 원문 CSV 8개의 19,820관측을 읽고 원문 도로명·지번 주소의 층 표현을 대조했다. 같은 인허가의 여러 원본행과 두 주소 열이 다르면 충돌 상태를 유지한다. 원본 데이터 레코드 바이트의 SHA, 파일 지문, 행 번호와 원문 발췌를 보존했다.

| 원문 층 표현 | 영업 인허가 전체 | 건물 후보에 연결된 인허가 |
| --- | ---: | ---: |
| 숫자로 명시된 단일 층 | 13,725 | 12,250 |
| 여러 층 열거 | 213 | 134 |
| 층 범위 | 93 | 77 |
| 번호 미상 지층·반지하·옥탑 등 | 246 | 205 |
| **원문에서 층 표현을 읽을 수 있음** | **14,277** | **12,666** |

수치는 인허가 관측 기준이다. 현재 입점·층을 현장에서 재확인한 결과는 별도다. 101호·B101호는 호 표기로 유지하고 그 숫자에서 층을 만들지 않았다. 지1층·중1층 같은 축약, ‘2층 중 1층’, 복합주소와 층처럼 보이는 도로명도 반례로 검사했다. 축약 지하 표기는 다른 주소의 명시 지하층과 동의하는 경우에만 보강한다. [인허가 층 관측과 검증](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/floors/README.md)

건물 연결 16,988키 중 2,985키는 주소에 층·호 표기가 없고, 1,082키는 호만 있으며, 237키는 문맥 검토, 18키는 주소 열·원본행 사이의 층 표현 충돌이다. 단일 층·복수 층·범위와 번호 미상을 각각 보존했다.

## 소진공의 보조 층 관측

2026-06-30 서울 상가 원본 554,092행의 층정보를 대조했다. 상호·지점명과 구를 포함한 주소가 맞고, 인허가와 공공 상가 행이 양방향으로 유일한 경우에만 보조 관측을 연결했다. 기존 인허가 층을 덮어쓰지 않았다. [공식 상가정보 출처](https://www.data.go.kr/data/15083033/fileData.do)

건물 후보가 있는 인허가에서는 10,717키가 이 주소·상호 대응을 만족했다. 인허가 주소에 층이 없거나 호만 있는 1,455키에서 소진공 층 후보를 얻었다. 두 자료에서 층이 다른 329키는 충돌을 남겼다. 보조 관측에는 6월 기준일, 공공 행 번호와 상가 식별자, 원문 층과 인허가와의 관계를 기록했다. 현재 자료의 서로 다른 관측 시점을 보존한다.

## 건물의 총층수

서울 GIS 건물 원본 2026-08-09의 695,761행을 대조했다. 65동의 건물 조각 117,551개는 고유 원본행 116,780개로 연결된다. 지상층 양수가 기재된 건물은 93,940개, 지하층 양수는 65,750개다. 알려진 두 값을 합산할 수 있는 원본행은 93,804개다.

해당 ZIP의 실제 29열 구조에서 A26은 지상층 수, A27은 지하층 수다. 원문 0, 양수, 결측을 따로 저장했다. 다른 판본의 열 번호를 섞거나 화면상 높이를 실제 층수로 역산하지 않았다. [건물 층수 DB와 설명](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/building-floors/README.md) · [국가교통DB 필드 정의 표5-15](https://www.ktdb.go.kr/DATA/pblcte/20250805093928585.pdf#page=128)

새 SQLite에는 원본행, 원문 층수, 해석값·상태와 동별 r4 건물 ID가 들어 있다. source_row는 고정한 서울 ZIP에서 1부터 세는 행이며 원천 지문을 함께 확인한다.

음식점의 명시 숫자층을 알려진 건물 층수와 같은 지상·지하 방향에서 비교했다. 번호 미상 층과 숫자층을 함께 적은 관측은 숫자로 명시된 부분만 비교했다. 모든 후보 건물의 알려진 층수를 넘는 인허가 28키, 일부 후보에서만 넘는 81키를 검토 목록에 남겼다. 이들은 자료 시점·주소·건물 후보를 다시 볼 항목이다. 실제로 불가능한 입점이나 위법을 판정한 값으로 쓰지 않는다. 원문에 0이 기재된 건물은 별도 검토 상태로 두었다.

## 공식 출입구 조사

서울시 시설물·보행자 출입구·차량 출입구의 공간 원본 ZIP 3개와 세부정의서를 새로 확보했다. 시설 3,606건, 보행자 출입구 16,786점, 차량 출입구 2,273점을 읽고 조사 시설 ID의 연결과 SHP·DBF 좌표를 대조했다. 자료의 행별 기준일은 2022년 11~12월이다. 제공기관은 일회성 조사이며 이후 현행화가 없다고 안내한다. [시설물](https://data.seoul.go.kr/dataList/OA-21698/S/1/datasetView.do) · [보행자 출입구](https://data.seoul.go.kr/dataList/OA-21699/S/1/datasetView.do) · [차량 출입구](https://data.seoul.go.kr/dataList/OA-21700/S/1/datasetView.do)

현재 네 구 경계 후보 안에는 2,254점이 있다. 보행자 1,939점, 차량 315점이다. 이 가운데 243점은 출입구→시설 ID·시설명이 맞고, 시설이 단독 건물로 기록돼 있으며, 시설 지번이 공공 건물 원본의 단일 건물 필지와 일치한다.

243점은 시설 주소를 통한 **건물 후보 연결**이다. 그중 188점은 후보 건물 도형 내부 또는 경계 3m 이내, 55점은 그 범위 밖이다. 좌표를 건물 외벽으로 옮기지 않고 원래 위치와 공간 진단을 보존했다. 실제 매장 문·현재 통행 가능 여부는 추가 확인 대상이다. [공식 출입구 수집과 결속 근거](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/entrances/README.md)

이 자료에서 음식점이 연결된 건물 25조각에 관련 시설 출입구 후보 참조를 붙였다. 음식점별 입구로 선택한 값은 없다. 보행자·차량 구분, 진입 방향, 시설 관계, 기준일을 함께 읽는다.

## OSM 출입구 관측

공개 OSM 지역 조회에서 entrance 태그가 있는 네 구 4,718점을 별도로 저장했다. 중랑 2,429점, 동대문 1,248점, 광진 552점, 노원 489점이고 46개 동에 분포한다. 조회 원천의 스냅샷은 2026-11-15 07:26:38 UTC다. 4,567점은 닫힌 OSM 건물 way의 명시 구성원이다.

OSM 건물과 국토부 건물 ID의 동일성을 확정한 값은 없으므로 공식 건물의 매장 입구에 자동 배정하지 않았다. 상점 입구 태그 20개도 문 노드 자체에 이름·주소·사업장 참조가 없어 별도 검토 목록으로 보존했다. 공식 조사와 중복될 수 있어 두 관측 수를 합산하지 않는다. 출처와 ODbL 표기를 별도 층에 유지한다. [OSM 관측과 출입구 조사 안내](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/entrances/README.md)

## 저장과 조회

기존 음식점 팩의 판본을 고정하고 별도 [보완 목록](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/catalog.json)과 modules/{행정동코드}.json.gz 65개를 만들었다. 건물에는 지상·지하 층수 원문·상태와 시설 출입구 후보 참조, 음식점에는 인허가 층 표현과 보조 관측, 건물 층수 비교를 붙였다. 각 원본 파일·입력 목록·동별 음식점 파일의 지문을 확인한다.

실제 매장 문을 확정한 값은 현재 0이다. storefrontEntranceRef는 미확인 상태를 유지한다. 공식 시설 출입구 후보와 OSM 관측은 별도로 조회할 수 있다.

저장소 루트에서 자료를 읽는 예시는 다음과 같다.

    python -X utf8 artifacts/local/dong-restaurants-floor-entrance-20261115/query.py --dong 1126057500 --limit 2

특정 음식점은 --restaurant 뒤에 기존 관리키를 지정한다. 건물 총층수의 전체 조회는 building-floors.sqlite의 dong_building_floors 뷰를 사용한다. [합본 조회·지문·재실행 검증](../../../../artifacts/local/dong-restaurants-floor-entrance-20261115/verification.json)

## 추가로 확보할 자료

주소기반산업지원서비스의 위치정보요약·내비게이션 DB는 건물 중심과 주·보조 출입구 좌표를 제공한다. 공식 안내에는 별도 신청·본인확인·이용목적 심사 절차가 있어 이번 공개 수집에서 해당 전체 파일은 확보하지 못했다. SGIS는 건물 유일 식별자와 액세스 토큰을 사용하는 건물층별 사업체·시설물 API를 제공한다. API 설명을 보존했으며 이번 개별 점포의 층별 실내도형으로 수집한 행은 없다. [내비게이션 DB 공식 안내](https://www.data.go.kr/data/15050419/fileData.do) · [SGIS 공식 API 안내](https://sgis.mods.go.kr/developer/html/openApi/api/data.html)

다음 정밀 확인에는 대상 음식점의 정확한 건물·층과 개별 출입문을 함께 식별하는 근거가 필요하다. 근접 점이나 건물 중심점을 실제 문으로 대신하지 않는다. 현장·공식 점포 안내에서 확인한 경우 확인일과 근거를 같은 관리키에 덧붙이는 방식으로 이어간다.

이번 산출물은 조사·공공자료 수집·정리·검증 결과다. 기존 원본 DB·게임 코드·실내모형·수집 예약은 변경하지 않았다. 실제 Unity에서 층·출입구를 표시하는 검증은 후속이다. **새 디오라마 규칙 후보 없음.**
