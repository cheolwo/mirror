# 홍달 디오라마 시각 효과와 데이터 모음

2026-11-15 · 기존 자료·현재 표현 코드·공식 기술 문서 조사. [기계가 읽는 대장](2026-11-15-visual-data-effect-catalog.json) · [사용자 관찰 레이어 기획 r243](../../Planning/시스템/PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/data-driven-visual-effects-and-user-layers.proposal.r243.md)

자료 **15종**, 표현 **15가지**, 공식 기술 문서 **8건**, 데이터→표현 연결 예시 **8개**를 모았다. 자료 근거 파일 26개와 소스 줄 앵커 51곳의 지문을 JSON에 보존했다.

각 자료의 원래 기간·단위·좌표계·사용 조건과 현재 화면 연결 상태는 별도로 기록했다. 아래 수량은 읽은 판본에 귀속된다. 기존 파일은 경로와 지문으로 참조하고, 음원·에셋의 현재 연결 방식은 소스에서 확인했다.

| 도로변 가까이 보기 조명 | 현행 소스 구현 | 현재 실측 가로등 점위치·기종·점등 기록을 입력으로 받지 않는다. |
| 보도·연석·점자블록·횡단보도 | 현행 소스 구현 | 개별 보도 경계·경사·접근 가능 여부·신호 주기를 확인했다고 간주할 수 없다. |

| 전국 해상·항공 통계 연결선과 이동 기호 | 현행 소스 구현 | 사용자 거래의 출발·도착 거점과 단위·집계기간이 없으면 통계선과 같은 의미로 합칠 수 없다. |
| 내 화물 예시 경로와 트럭 | 현행 소스 구현 | 배차·상차·배송 실적이나 사용자의 차량 위치가 이 경로를 바꾸지 않는다. |
| 사용자가 선택한 음원에 맞춘 빛 | 현행 소스 구현 | 시스템 전체 소리나 멜론·유튜브 스트리밍을 가져오는 경로는 확인되지 않았다. 이 입력은 공간 자료 반입 기능이 아니다. |
| 명덕에 따른 빛의 크기·세기 | 표현 규칙·검토 촬영만 구현 | 개인 배송 횟수·상호·방문 기록을 명덕으로 자동 해석하는 계산식은 없다. |

표현 코드의 존재·기존 촬영·현재 일반판 적용은 JSON의 소스와 반환에서 범위를 확인한다. 특히 명덕 크기 조회는 촬영용 시험 사전을 읽고, 유동인구 보행 군중의 일반판 연결은 확인되지 않았다.

## 확보한 입력 자료와 공백

일반판은 2023년 역사 경계 후보의 면목 6동을 읽는다. 현행 명부 65동, 역사 64동, 2026년 후보 도형 65동, 별도 정밀 검토판 6동 실행 근거를 구분한다. 공식 현행 행정동 경계를 검증 완료한 수는 이 대조에서 0개다.

| --- | --- | --- |
| 행정동 경계와 인접 지역 | 일반판은 2023 후보의 면목 6동. 2026 후보는 별도 r4 6동 실행 이력. | 선택 동 테두리, 이웃의 낮은 명도. 동 이름과 판본을 함께 표시. |
| 건물 외곽·용도·층수·높이 | 일반판의 기존 건물 표현과 r4 검토판의 새 조각은 다른 판본. | 실제 외곽의 건물 덩어리, 선택 시 층수·높이 근거, 운영 중인 점포만 별도 빛. |

| 가로등 위치 후보 | 일반판 길가 불빛은 장식. 이 시설 목록으로 배치했다는 근거 없음. | 밤에 가로등 후보만 별도 켜고, 실측 등 위치가 확인되면 동일 ID를 결속. |

| 공원 계획면·대표점·비오톱 | 일반판에는 기존 비오톱 기반 녹지. r4 6동에는 공원 계획면 30조각. | 공원 면은 연한 식생색, 대표점은 별도 표식. 계절 분위기의 밑바탕. |

| 거주인구와 주거연면적 대리값 | 일반판 6동 수요팩의 population basis는 residentialFloorArea. | 현재 수요 지표가 면적 대리임을 표시. 사용자가 기준월·행정동코드·인원 단위를 갖춘 집계를 넣으면 별도 인구색 표현. |
| 등록 창고·물류단지·터미널 | 기존 가상 센터 화면과 별도. 수집물의 게임 반영 없음. | 지역·시설유형 표/집계. 위치 검증이 끝난 후보부터 지도 아이콘. |
| 국가별 수출입 물량·금액 | 같은 통계가 현재 홍달 전국/세계 화면에 결속됐는지 미확인. | 국가 간 거래 관계를 가는 곡선과 물량 범례로 선택 표시. |
| 관측 날씨와 계절 분위기 | 날씨 관측 기반 동별 비/빛/수목 배치 확인 없음. 계절 표현 r221은 기획. | 계절 팔레트는 연출로 표시. 비/바람은 가까운 관측소·시각·거리와 함께 실제 관측 또는 사용자 가상값을 선택. |

기간·단위·CRS·실보유량·원본 지문·재이용 조건은 JSON의 datasets와 dataEvidence에서 찾는다. 음식점은 인허가 19,804키 중 건물 후보 연결 16,988키이고, 개별 점포 문 확인은 0개다. 추정 유동인구는 22분기·시간대 6개·선별 1,408행이다. 등록 물류시설 6,100행의 검증된 지도 좌표는 0개다. 이러한 표/집계 자료는 위치 확인 범위가 늘어날 때 지도 표현으로 이어간다.

## 사용자 자료를 연결하는 첫 예제

[합성 지점 입력](../../Planning/시스템/PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/visual-layer-example.r243.json)은 설명용 로컬 미터 좌표 네 개와 숫자 20·80·0·결측을 가진다. 숫자 20·80은 같은 고정 눈금에서 반경 2m·5m의 후광으로 대응한다. 0은 중심점만, 결측은 회색 빈 중심과 자료 없음으로 구분하는 제안이다. 실제 지도 모듈과 원점은 지정하지 않았다.

입력할 자료에서 고유 ID, 위치 또는 건물/동 코드, 값, 단위, 기간을 고르고 표현 설정을 붙인다. 현행 게임의 외부 CSV/GeoJSON 가져오기는 후속 구현이다. 기존 로컬 음원 선택 경로와 임의 공간 데이터 반입은 각각의 준비 상태로 읽는다.

## 공식 기술 자료

| 공식 문서 | 홍달에서 참고할 부분 |

| [Line Renderer properties reference](https://docs.unity.com/en-us/engine/6000.0/manual/visual-effects/lines-trails-billboards/rendering-lines/class-line-renderer/line-renderer-properties) | 확정된 도로 점열에 기사 빛과 같은 계열의 색을 입힌다. 조망 단계에 맞게 모서리만 둥글게 해도 교차로 위치를 지킬 수 있다. |

| [Requirements and compatibility / Visual Effect Graph 17.5.0](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.5/manual/System-Requirements.html) | 많은 입자가 동시에 필요해질 때 후보로 검토한다. 기본 입자나 단순한 점을 표시할 수 있는 형식으로 효과 정의를 보관한다. |

| [TripsLayer](https://deck.gl/docs/api-reference/geo-layers/trips-layer) | 본인 경로 자료를 가져올 때 원본 시각을 보존하고, 재생에 쓸 값만 기준시각으로부터의 경과 초로 계산하는 참고 사례다. |
| [HeatmapLayer](https://deck.gl/docs/api-reference/aggregation-layers/heatmap-layer) | 같은 행정동 오전·점심·저녁을 비교할 때 동일 집계 단위·반경·줌·색 범위를 쓰는 예로 참고한다. 동 총계만 있는 경우 동 면을 칠하고 도로별 관측값은 따로 표시한다. |

GeoJSON의 선택적 세 번째 좌표는 타원체 기준 고도다. 건물 높이·층수는 별도 속성으로 보존한다. [RFC 7946](https://www.rfc-editor.org/info/rfc7946/)

별도 Unity 작업본은 Unity 6000.5.6f1·URP 17.5.0이며 VFX Graph는 설치 목록에서 확인되지 않았다. 기본 선·입자와 현재 셰이더를 재사용하는 후보부터 대조한다. VFX Graph를 채택할 때는 해당 버전의 렌더 파이프라인·색공간·Compute Shader/버퍼 요구를 확인한다. [VFX Graph 17.5 요구 조건](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.5/manual/System-Requirements.html)

각 URL의 확인 시각과 제약은 JSON에 저장했다. Unity 6.0의 선·입자 API 문서는 기반 기능 참고다. deck.gl은 웹 시각화의 표현 방식을 비교하는 참고 자료로 수집했다.

## 이어서 준비할 작은 단위

첫 추천은 사용자 지점 표 한 개를 읽고 점·후광·선택 정보로 보여 주는 흐름이다. 그다음 행정동 통계의 음영, 실제 경로 점열의 이동선, 사건 시각의 파동을 각각 검토할 수 있다. 표현을 켜거나 꺼도 기본 관찰과 같은 업무가 이어지도록 한다. 효과 강도·기본 켜짐과 첫 실제 입력 자료는 제안 단계다.

## 검증 범위

JSON 구문·ID 중복·내부 참조·자료 근거 SHA·현재 소스 지문과 합성 예제를 확인한다. 외부 공식 문서는 URL과 자체 요약만 저장했다. 제품 코드·원본 DB·예약·새 Unity 실행을 변경한 결과는 없다. 새 디오라마 규칙 후보 없음.
