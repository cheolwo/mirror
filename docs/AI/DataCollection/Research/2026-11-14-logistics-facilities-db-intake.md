# 국내 물류시설 조사·실제 수집·DB 저장

2026-11-14 사용자 요청으로 국내 물류센터/창고 후보를 조사하고 **시설 관측6100행을 조회용 SQLite에 저장**했다. 기존 공공자료 MySQL에는 원본/안내의 계보5건을 추가했다. 물류시설의 실제 운영·거래망·게임 지도 연결을 완료한 작업은 아니다.

## 실제 저장 결과

| 구분 | 실제 시설 관측 | 취득/검증 범위 |
| --- | ---: | --- |
| [NLIC 등록창고](https://www.nlic.go.kr/nlic/WhsInfoWarehouseSch.action) | 6011행 | 11월13일 취득 원본2,731,008바이트를 SHA 대조해 재사용하고 이번에 전행/전셀 파싱 |
| [NLIC 물류단지](https://www.nlic.go.kr/nlic/fmComplex0010.action) | 59행 | 공개 다운로드로 XLS50,688바이트 신규 취득 |
| [NLIC 물류터미널](https://www.nlic.go.kr/nlic/fmTerminal0010.action) | 30행 | 공개 다운로드로 XLS11,264바이트 신규 취득 |
| 광양 창고·경기 창고 API 안내 | 시설행0 | 공식 카탈로그JSON2개4,979바이트. 별도 실제 업체 관측으로 합산하지 않음 |

위6100행은 서로 다른 종류의 **출처별 기록 수**다. 대한민국에 고유 물류센터6100개가 현재 가동 중이라는 뜻이 아니다. 원문이 완전히 같은 등록창고 중복26행도 지우지 않고 각 원문 행번호로 보존했다. 운영사·등록 사업장·물류단지·물리 건물·택배 배송캠프는 같은 단위가 아니다.

[등록정보 카탈로그15083282](https://www.data.go.kr/data/15083282/fileData.do)는 일정 규모 이상의 영업용 등록창고와 관련 법률의 창고 정보를 설명한다. 전국 모든 배송센터·자가창고·소형 창고를 포괄한다고 판단하지 않는다. 쿠팡·택배사 등의 실제 센터→허브→배송권 관계, 현재 재고/가동·커피 취급/도매 공급 여부는 이번에 확인한 데이터가 아니다.

신규 수집은 익명 공개 요청5회(단지XLS·터미널HTML/XLS·카탈로그JSON2개)이며 저장한 새 본문은 총119,476바이트다. 터미널HTML52,545바이트는 다운로드 폼/출처를 확인한 안내로, 시설 데이터 파일/행수에 합산하지 않는다. 로그인·계정 발급·활용신청·유료 호출은 하지 않았다.

## DB 위치와 관계

**시설 조회용 DB:** [logistics-facilities.sqlite](../../../../artifacts/local/logistics-facilities-intake-20261114/logistics-facilities.sqlite)

| 테이블/뷰 | 내용·건수 |
| --- | --- |
| `sources` | 출처/자료군·종류·공식URL·취득시각·제약5건 |
| `raw_snapshots` | 원본 위치·SHA·바이트·출처 외래키5건 |
| `facility_observations` | 원본/시트/행에 연결된 시설 기록6100행 |
| `facility_measures` | 면적·사업비·비율 등 단위/원문·파싱 값24487개 |
| `facility_attributes` | 원문 열명·값55163개 |
| `facility_search` | 시설 유형·이름·주소·공표 상태와 출처/원본을 함께 읽는 뷰 |

`sources → raw_snapshots → facility_observations → facility_measures / facility_attributes` 관계를 사용한다. 원문 셀 값/유형·열/행을 감사용 JSON으로도 보존했다. 사업자번호는 문자열이며 물리 시설 기본키로 쓰지 않는다. 시설 유형·이름·주소 원문으로 조회할 수 있고 [조회 SQL](../../../../artifacts/local/logistics-facilities-intake-20261114/ReadFacilities.sql)을 함께 저장했다.

소수값은 정밀도를 잃지 않도록 원문/십진 문자열·단위·파싱 상태를 나눠 저장했다. 수치0인18479개와 공백 셀5229개를 구별했다. 일반/냉동냉장/보관장소/타법률 면적은 서로 다른 원문 필드이며 겹침 검토 없이 합산하지 않는다.

물류단지의 `시행자`는 현행 운영사, `주요입점업체`는 취급품목이 아니다. 독립 검토에서 이 의미 혼동을 발견해 공통 운영사/취급품목 필드는 null로 바로잡고 두 원문 항목은 `facility_attributes`와 원문 셀에 보존했다. 원본 파일은 수정하지 않았다.

## 기존 공공자료 MySQL의 실제 저장

기존 [observer-public-data-db 도구](../../../../eng/observer-public-data-db/README.md)를 현재 소스로 빌드하고, 소유/작업경로·loopback13306을 확인하는 기존 연결 경계로 실행했다. 대상은 **hongdal-mysql-1 / hongdal_dev**의 공공자료 테이블이다.

- `preview`: 기존 상태와 입력 지문·충돌을 읽기 전용 확인.
- `apply`: 원본/실행 계보5건 커밋. 시설 원본3건은 `reference`, 카탈로그2건은 `metadata`.
- 새 연결 `verify`: 저장된5건과 manifest/원본의 일치 확인.
- 두 번째 `apply`: `strictNoOp=true`, 추가 쓰기0. 기존 정규화116735행과 지역대응3행은 그대로다.

**시설별 관측의 기준일이 원문에서 확인되지 않아** 기존 시계열 정규화 테이블에는 새 관측0행을 추가했다. 취득일을 관측 기준일로 바꾸거나 기존 non-null 시점 계약을 완화하지 않았다. 대신 시설별6100행은 위의 관계형 SQLite에서 실제 조회 가능하며 MySQL은 원본 위치/지문·계보를 소유한다. DB BLOB에 XLS를 다시 복제하지 않았다.

실행 명세와 독립 재조회/재실행 영수증은 [보관함](../../../../artifacts/local/logistics-facilities-intake-20261114/README.md)에 있다. 이 데이터 작업은 제품 영업 상태나 Simulation 상태를 바꾸지 않는다. DB migration·새 계정·컨테이너 시작/재시작·운영 DB·게임 반입도 수행하지 않았다.

## 시점·지도·권리와 추가 후보

모든 시설 기록의 **관측 기준일·좌표는 null/미확인**이다. 취득시각은 별도로 보존했다. 물류단지 페이지의 최종자료2024.10 등 metadata 표시를 각 행의 현행 기준일로 대입하지 않는다. 원문의 옛 주소/행정구역명과 현재 명칭을 조용히 치환하지 않고, 주소 첫 토큰은 검색용 후보일 뿐 법정동/행정동 결속이 아니다.

추가 확보한 [광양 창고15104607](https://www.data.go.kr/data/15104607/fileData.do) 안내는 CSV, [경기 창고15059288](https://www.data.go.kr/data/15059288/openapi.do) 안내는 API/원천 다운로드의 후보로 보존했다. 이번에는 두 자료의 실제 업체 행을 별도로 수집하거나 API 활용신청을 하지 않았다. 현재 필요한 전국 자료는 공개 다운로드로 확보돼 추가 신청 없이 진행할 수 있었다.

공식 포털의 자료군 이용허락 선언과 현행 NLIC 원본별 조건의 결속은 구별한다. 이번 결과는 내부 조사/DB 저장이며 게임팩·공개 재배포 승인이나 지도 배치 완료가 아니다. 후속에는 원문 기준일, 좌표/주소·중복 사업장·물리 시설 결속, 실제 운영/거래 가능 여부를 검토해야 한다.

최초 수집 단계에서는 기존 시설 자동수집의 blocked/지역·페이지·키 검토와 기존 물류·무역 예약을 변경하지 않았다. 이후 사용자의 별도 정기 수집 요청에 따라 검증한 NLIC3종만 [정기 갱신](../LogisticsFacilitiesRefresh.md)에 연결했다. 월간/분기 heartbeat2건을 실제 ACTIVE로 등록했으며 기존 예약은 그대로다. 최초 수집/DB 저장과 예약 등록·미래 회차 성공은 별도 근거로 관리한다.

## 검증

독립 원본 대조에서3개 XLS의6100행·55163셀과 모든 원문 속성/측정값이 일치함을 확인했다. 최종 DB의 무결성·외래키, 기준일/좌표 null, 실제0/공백 보존, 재실행 hash 불변도 확인했다. 1차 의미 오류와 교정 후 최종 검사는 별도 기록으로 보존한다. MySQL도 원본/manifest 지문·독립 재조회와 무쓰기 재실행을 각각 확인했다.

초기 `--no-restore` 빌드는 삭제된 자산 파일 때문에 실패했고, 정상 복원을 포함한 현재 빌드는 오류0·경고4로 완료됐다. 경고는 기존 MySqlConnector2.4.0 의존성의 NU1902이며 이번에 패키지 버전을 바꾸지 않았다. 제품/Unity 실행 검증과는 다르다. 문서 경로·diff 검증과 최종 결과는 [검증 기록](../../../../artifacts/local/logistics-facilities-intake-20261114/final-verification.json)을 따른다.
