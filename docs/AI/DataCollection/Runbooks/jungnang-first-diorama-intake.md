## 시안과 실제 게임의 미해결 차이

- C1의 중복 제거는 첫 동의 절단 건물만 남기는 약식이다. 경계 횡단156원행의 다른 조각 약30,825.59㎡가 시안에서 생략된다. 실제 팩은 정상이며 굽기에서 이 약식을 그대로 재사용하지 않는다.
- 시안은 면목6동을 운영 출발점으로 놓은 상황이다. 확인한 현재 게임 초기 구성의 Operating은2동이며 사용자 저장 회차는 열지 않았다. 실제 현재 플레이에서6동이 운영 중이라고 확인한 것은 아니다.
- 망우본동과 면목본동은 점에서 접한다. 점접촉을 포함하면 시안의 첫3후보를 지지하지만 공통 선분 기준이면 상봉2·망우3의2곳이다. 25m 근접 휴리스틱은 공통 게임 규칙으로 승인되지 않았다.
- 신규3후보는 현재 영역 구성에 아직 없다. 현재 `DongDemandModule.Deepens`는 모르는 동에 true를 반환하므로 J3의 별도 수요 미준비 차단이 필요하다. 이 자료 작업에서 게임 코드를 바꾸지 않았다.
- 시안 출력PNG와 전체 생성 입력을 결속한 실행 영수증 및 일부 중간파일이 없어 전체 렌더 재현/실제 Game View 증거는 미확인이다. 메시35/786MB는 실측 용량이 아닌 추정이다.

### 4구 음식점 실제 갱신

```powershell
& $자료Python -B -X utf8 eng/data-collection/collect_public_snapshots.py --manifest eng/data-collection/jobs.json --job seoul-four-district-restaurant-licenses
```

[기존 수집 정책](../../../../eng/data-collection/jobs.json)에 별도 작업 하나를 추가했다. 기존 작업·전역 상한·blocked 원천은 보존했다. OA-23056 일반음식점/OA-23059 휴게음식점에 기관3060000(중랑)·3050000(동대문)·3100000(노원)·3040000(광진)을 각각 정확히 고정한다. 출처별 최소24시간, 실패 시도도24시간 냉각한다. 30분 예약은 이 간격/잠금/동일정책 거절 기록을 확인하며 실제 요청은 하루 간격이다.

매번 기관별 전체 건수를 GET으로 읽고 그 건수로 CSV POST를 요청한다. 정확 헤더·기관·관리번호·전체행수·형식을 검증하고 원문을 SHA별로 불변 저장한다. 구별 법정동/행정동과 실물 영업 확정은 다른 단계다. 결측·0·형식오류·중복키/폐업 이력을 보존하며 최신 취득시각을 모든 업소의 최신 관측일로 바꾸지 않는다. 공개 SAMPLE_VIEW만 쓰고 로그인/쿠키/API키는 사용하지 않는다. 상한은8원천/16요청/64MiB/요청당30초다.

다음 예약의 정리 단계는 이 묶음의 `build_index.py --output-dir <새회차 출력경로> --reuse-index <현재 색인 폴더>`를 사용한다. 원문SHA가 같으면 기존SQLite를 재사용하고 새 출력은 만들지 않으며, 바뀌면 새 출력경로에만 작성한다. 기존 출력 덮어쓰기를 거절하고 `verify_index.py --index-dir <색인 폴더> --no-receipt`로 읽기 전용 재검증한다. 새 원문을 정리한 뒤에는65동 행정동 준비표의 보류를 확인하고, 공간귀속 미확인을 수요/건물 준비 완료로 바꾸지 않는다. 전체행 독립 대조와 재현/덮어쓰기 보호 검증을 통과했으며 사용법은 묶음 README를 따른다.
