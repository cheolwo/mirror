## 현재와 역사 경계를 혼합하지 않은 부분

현재65개와 역사64개에서 코드·정규화 이름이 맞는 것은63개다. 이63개도 **현재 경계가 확인된 것이 아니라 같은 코드의 역사 참고 자료**다.

- 신설동 `1123051500`, 용두동 `1123053300`: 현재 명부는 만들었고 현재 경계/동별 실제 도형은 보류했다.
- 옛 용신동 `1123053600`: 역사 전용으로 보존했다. 옛 경계를 새 두 동으로 복제하거나 임의 분할하지 않았다.
- 현재 공식 `TL_SCCO_GEMD` 경계 → 주소 건물/건물군 → 명시적 출입구의 기존 수집 관문은 유지한다.

현재 `currentBoundaryLayer=null`, `currentAuthoritativeBoundary=false`다. 자료를 눈에 보이게 만들었다는 이유로 실제 주소·건물 ID·행정 관할·통행을 확정하지 않는다.

## Claude가 다음에 이어갈 때

1. 먼저 위 동별 목록·통합 명세와 분야별 검증을 읽는다. 현행65/역사64를 하나의 현재 지도로 합치지 않는다.
2. 대표 한 동의 새 층 읽기와 좌표·고리/결측 표현을 작은 소비 작업으로 준비한다. 기존 HDIO 소비기에 그대로 넣지 말고 어댑터 계약·판본·작은 검증 범위를 합의한다.
3. 500m 구획 색인은 후보 조회용이다. 입력/카메라·실제 mesh분할/LOD·통행 그래프·역할 건물 재결속은 별도 구현/시각 검증이 필요하다.
4. 현행 공식 경계·주소/출입구·권리 문제를 해소한 판본에서만 현재 지도·배포·실제 경사 사용을 검토한다. 이번 문서를 구현 승인이나 Goal/WI/E 자동 활성화로 읽지 않는다.

제품/Unity·기존 자료·DB·공통 수집기/예약·Graph Map·Goal/WI/E는 변경하지 않았다. 게임 빌드·실행·commit·push는 하지 않았다. 기존 결측 명시와 혼합 시점·CRS/권위 보존 규칙의 자료 수준 지지이며 공통 승격·새 E 증거는 없다. **새 디오라마 규칙 후보 없음.**

문서/로컬 링크86개·읽기 예제5조건을 확인했고 대상3문서의 `validate-changes.ps1 -Level Fast -Paths`와 `git diff --check`를 통과했다. 문서/자료 범위이므로 제품 빌드·제품 시험은 생략했다. 약60MB의 로컬 산출물이며 최종 파일 수/바이트·지문은 자료 루트의 `completion.json`에 결속한다.
