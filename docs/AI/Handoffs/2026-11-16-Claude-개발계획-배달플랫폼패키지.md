## 0. 숫자의 출처

시안의 숫자는 **가상**이다. 실제 배달 시장 자료가 아니다. 대부분은 지금 게임 안의 값에서 계산했다.

| 숫자 | 출처 |
| --- | --- |
| 동마다 하루 주문(면목본동 55 · 면목제2동 43 · 면목제3·8동 45 · 면목제7동 44 · 면목제5동 19 · 면목제4동 34) | `Resources/hongdal-dong-demand.json`. 가상 주문이고, 건물 연면적 비율로 나눈 값 |
| 시간대 몫(점심 11~14시 27% · 저녁 17~21시 38% 등) | 같은 파일의 `bands` |
| 주문당 4,800원 · 기사 보수 3,600원 · 모집 20,000원 · 제휴 6,000원 · 기사 1명 시간당 3.5건 · 배차 엔진 60,000원 · 레벨당 +12% | 같은 파일의 `rules`. 엔진 효과는 `Kernel/DongDemandModule.cs`의 기사 처리량 계산 |
| 평균 배달 28분, 기사 카드 값, 모집 흐름 숫자 | **시안 값**. 게임에 아직 없다 |
| 지사 개설비 · 기간 · 지사 운영보상 | **미정**. 0으로 두지 않았다 |

예: 사가정 지사(세 동)는 하루 144건이다. 저녁에는 시간당 13.7건이 들어오니 기사 4명이 필요하다. 92%를 받아내면 132건이고, 본사 차액은 132 × 1,200원 − 모집 20,000원 = 138,400원이다.

## 1. 시안 다섯 장

| 장 | 화면 | 보여 주는 것 |
| --- | --- | --- |
| P0 | 새로 시작 · 패키지 고르기 | 배달 플랫폼만 열림. 프랜차이즈 · 창고·물류 · 자유 시작은 「준비 중」. 공통인 것과 패키지마다 다른 것 |
| P1 | 구 지도 = 지사를 넓히는 판 | 본사 띠(지사 · 소속 기사 · 받아낸 주문 · 평균 배달 · 본사 차액), 오늘 정할 일 3, 사가정 지사와 담당 세 동, 지사 밖 세 동, 다음 지사 후보 카드 |
| P2 | 지사 창(왼쪽) · 기사 카드 | 시간대별 필요/출근 예정, 저녁 출근 요청, 모집 흐름(지원 → 교육 → 첫 배달 → 소속), 그만둘 조짐, 지사 정산, 계약 형태(미정) |
| P3 | 동 디오라마 = 지사 현장 | 소속 기사 고리(배달 중 · 픽업 대기 · 쉬는 중), 제휴 매장 · 대기 주문, 하루 시간대 띠, 저녁 부족 알림 |
| P4 | 하루 마감 · 본사 장부 | 지사별 오늘, 돈(장부 분리 · 운영보상 미정), 내일 아침 본사 결정 3, 성장 사다리(운영팀 → 지사 1 → 지사망 → 구 권역 → 연결 플랫폼) |

- **아래 줄 메뉴:** 지금의 「기사 운영 · 음식점 · 가맹점 · 창고·화물 · 홍달 플레이스 · 플랫폼 장부」 대신 패키지 메뉴를 둔다. 메뉴는 「지사 · 기사 · 배차 · 제휴 매장 · 정산 · 본사 장부」다. 다른 패키지 메뉴는 숨긴다.
- **기호 약속:**
  - 민트 = 내 지사 · 소속 기사 · 받아내는 곳
  - 금색 점선 = 후보 · 지사 밖 · 대기 주문
  - 빨강 = 부족 · 위험
  - 「표현」 = 그림으로만 보이는 것

## 3. 새 단위: 지사

| 칸 | 내용 | 지금 게임 |

- **역 중심 보기와의 관계:** 지사는 행정동 묶음으로 만든다. 그러나 화면은 지금처럼 역 반경으로도 본다. 자료는 동 단위, 보는 자리는 역 중심이라는 앞선 결정과 같다.

## 4. 구현 단계

**단계 0 · Kernel 변경 없음**

- 패키지 정의: 이름 · 시작 자리 · 열린 메뉴 · 성과 숫자 · 첫 목표. WindowsGame 안의 정적 자료로 둔다.
- 새로 시작 화면(P0): 배달 플랫폼만 연다.
- 아래 줄 메뉴를 패키지별로 바꾼다.
- 본사 띠(P1 위): 지금 동 상태의 합계로 만든다.
- 지사 = 동 묶음 보기: 지금 운영 중인 동들을 「사가정 지사」 하나로 묶어 보여 준다. 숫자는 동 합계다.

**단계 1 · Kernel 변경 필요**

- 지사 상태(담당 동 · 소속 기사 · 지사장)와 지사 창(P2), 지사 현장의 소속 기사 고리(P3)
- Kernel은 읽기 전용이라, 사용자 허락과 Codex 기획(새 계약 D7)이 먼저다.

**단계 2**

- 시간대 출근 예정과 출근 요청(r130), 모집 흐름 · 그만둠

**단계 3**

- 지사 개설(후보 → 준비 → 운영), 본사 마감(P4), 성장 사다리

**단계 4**

- 프랜차이즈 패키지의 시작 화면 열기. 카페 1호점 · 가맹 개설 절차 기획을 이어받는다.

단계마다 빌드 · 검사 · 방향 촬영으로 확인한다. 업무 상태는 Simulation 안에서만 바뀐다.

## 7. 지키는 것

- **이름:** 실제 플랫폼 이름 · 로고 · 상호는 쓰지 않는다. 본사 · 지사 · 기사 이름은 모두 가상이다(기사 A~E, 지사장 1명).
- **연결:** 실제 주문 · 배차 · 결제 · 위치 · 계정과 잇지 않는다. 시뮬레이션만 쓴다.
- **개인 자료:** 개인 배달 자료(r233~r235 · r237)는 쓰지 않는다.
- **모르는 값:** 0이나 추측으로 채우지 않고 「미정」 · 「자료 미확인」으로 둔다.
- **공개:** 시안은 내부 검토용이다. 배포하지 않는다.
