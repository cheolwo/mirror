## 연결 순서

1. [축척 색인 DB](../../../artifacts/local/public-data/hongdal-map-scale-index-20261123/map-scale-index.sqlite)의 `v_scale_layer`에서 지도 축척과 필요한 정보 층을 고른다. `v_role_map_layer`는 같은 층에 연결된 역할의 추천 목록이다.
2. `database_path`, `database_sha256`, `source_object`를 읽고 조회 자료의 지문을 확인한다. DB의 경로는 색인 파일 위치 기준이다. `v_scale_pack`은 기존 182개 자료의 우선 표시 후보로, 개별 게임 화면의 적용 상태는 각 자료가 갖고 있는 근거에서 확인한다.
3. 열의 종류는 `lookup_id_columns`, `geography_columns`, `position_columns`, `observation_time_columns`, `measure_columns`로 구분한다. 같은 장소의 위치 자료와 시간대 수치는 같은 점에서 읽는 근거를 확인한다. 위치의 이름이나 인근 관계만으로 같은 시설 수를 더하지 않는다.
4. `v_layer_symbols`에서 조회의 기본 아이콘과 자료 종류별 적용 조건을 확인한다. 기존 자료의 주제 기호는 `v_scale_pack`에 있다. [아이콘 읽는법](../../../artifacts/local/public-data/hongdal-map-scale-index-20261123/symbols/읽는법.md) · [Unity용 투명 PNG](../../../artifacts/local/public-data/hongdal-map-scale-index-20261123/symbols/png/manifest.json)
5. 같은 PC에서는 승인 주소 경계 파생 여부를 먼저 확인한다. 다른 PC에서는 해당 범위에 맞는 이동본을 읽는다. 원본과 함께 고정한 판본에서 읽기 전용 표시를 검증한다.
6. 실제 Unity 자료 층을 개발할 때 우선 범위는 사가정의 타일 한 칸과 구 비교 지표 한 종이 적절하다. `q,r`와 지문 대조, 비어 있는 자료의 표기, 레이어 선택 후 원래 지도로 돌아오는 동작을 검증한 뒤 범위를 넓힐 수 있다.
