DB는 읽기용 색인이다. `role → role_field → field → field_relation → relation_reference → artifact`로 읽고, `artifact`가 관측을 담은 SQLite의 경로와 SHA-256을 가리킨다. `collection_work`는 대기열 순서를 보존하고 `work_field`가 결과를 연결한다. 서울 밖 도서관은 `v_field_extent_reference`가 별도 검증 위치 DB를 연결한다. 관측 원본은 각 자료 폴더의 영수증과 날짜를 따른다.

```sql
SELECT phase, field_key, label, availability, evidence_class,
       database_path, relation_name, guard
FROM v_role_tile_inventory
WHERE role_id = 'store'
ORDER BY CASE phase WHEN 'initial' THEN 0 WHEN 'detail' THEN 1 ELSE 2 END, position;
```

```powershell
python -B -X utf8 eng/data-collection/role_tile_examples.py --tile -32 -179 2 --role rider --role store --role owner
```

원래 공간 단위가 법정동인 값은 법정동 코드의 `referenceKey`로 한 번만 보여 준다. 두 행정동이 같은 관측을 참조하는 관계는 별도로 남긴다. 시점과 출처가 다른 관측은 겹치거나 같은 이름이 나와도 합치지 않는다. 지도에서 쓰는 공간 값은 `hongdal-dong-child-candidate-r1`, EPSG:5179의 `(q,r,slot)`에 연결한다.

## Claude가 D1에서 확인할 순서

1. [작업본과 기존 화면 근거](../../../artifacts/local/public-data/role-tile-intake-20261126/runtime/입장타일-도매농가-조회근거.md)의 구성 대장을 다시 대조한다. 11월 25일 촬영의 세 점수와 11월 26일 제안 층을 구분한다.
2. 사가정 북동 `(-32,-179,2)`에서 역할 전환을 먼저 대조한다. 기본 자료 두 줄을 넣고 카드에서 기준일·출처·`관측/배분/지역 문맥`을 볼 수 있게 한다. 같은 좌표의 음식점 16건·역과 정류소 3점·과거 도로 표본은 데이터 조회 근거를 남긴다.
3. 필드마다 자료 팩을 따로 굽는다. `fieldKey`, `release`, `geometryRevision`, `asOf`, `coverage`, `sourceIdOrGroup`, `visibility`, `sha256`을 머리에서 확인한다. `dataRevision` 또는 좌표 틀이 다르면 그 층을 어떤 모칸·세부칸에서 읽는지 먼저 대조한다. 자료 스냅숏과 점수 식은 별도 승인 범위다.
4. 타일에 값이 없는 자료의 이유와 지역 카드로 내려온 값을 검증한다. 예시의 사가정은 면목제3·8동과 면목제7동에 걸친다. 건축물대장·공시지가·실거래는 법정동 참조를 한 번만 보여 준다. 도로 표본이 없는 홍대, 하천과 산업이 가까운 여의도, 용마산, 서울 밖 빈칸도 검사한다.
5. 주민 도서관·기사 쉼터, 화물 주차, 가락 도매와 팜맵의 양성 사례를 추가한다. 현행 역할 전환에서 위치·시각·읽기 권한이 잘 유지되는지는 Unity에서 별도로 검증한다. 출시 사용 조건이 확인된 판만 외부 팩으로 내보낸다. 서울특별시·KT 원본·아카이브는 내부 분석용으로 두고 이용 조건을 따르는 출처 표시를 사용한다.

기존 자료 창에서는 `road`(길 속도)·`floating`(유동인구)·`fac:0`(보행등·횡단보도)·`fac:2`(보행 출입구)·`fac:4`(자전거)·`fac:5`(공원·나무)·`weather`(비·눈)의 항목명을 먼저 대조한다. 기존 `station-pulse`는 역 불빛이며 `transitBoardings`는 날짜가 붙은 역·정류소의 승하차 조사다. 게임 화면의 기존 항목 ID를 재사용할 때도 관측값이 동일한지 판단한 뒤 연결한다.

## 사가정 제한 공개판 정리

첫 제한 공개의 권장 범위는 **사가정 구 지도에서 입장 하나를 골라 가상 주문 한 건과 상대 입장을 체험하는 Windows 실행판**이다. 구 지도의 큰길·구역·역 이름은 배포 조건을 확인한 자료로 구성하고, 주문·인물·주소는 가상 사례로 준비한다. 지도를 둘러본 뒤 주문 상세에서 준비·픽업·수령을 순서대로 읽고 원래 화면으로 돌아오는 흐름이면 첫 체험을 설명하기 충분하다. [첫 지역 비공개 검토 결정](../DECISIONS.md#d-558-steam-무료-본편은-지역-experience-package를-선택적으로-발견하고-갱신한다) · [출시판과 내부 정밀판 방향](2026-11-19-Claude-제안-출시판과내부정밀판.md)

정밀 동 디오라마, 주소·출입구와 상세 건물 및 길 도형, 수집 원본, 이번 로컬 DB는 내부 검토 묶음에 둔다. 제한 공개판에는 배포 조건과 출처 표기를 확인한 지도 입력 및 집계와 제한 공개용 가상 업무 사례를 묶는다. 공개 전에는 실제 실행 파일과 동봉 파일 목록을 대조하고, 새 Windows 환경에서 첫 기동·입장 선택·주문 한 건·복귀를 확인하고, 가상 업무가 실제 주문·결제·배차에 연결되지 않는 실행 설정을 확인한다. 이번 인계의 검증은 자료와 저장 구조까지다. 제한 공개 후보의 빌드와 직접 조작 검증은 대기 상태다.
