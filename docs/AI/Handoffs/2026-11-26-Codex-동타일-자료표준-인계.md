[타일 계층 합계 시안](2026-11-25-Claude-시안-타일계층합계.md)은 큰 칸 하나를 작은 칸 일곱으로 보여 준다. 별도 Unity 작업본 `C:/Users/user/ssalddel`의 `9b7110c` 위 작업 트리에서 11월 26일 00시대에 확인한 구 지도 코드는 기존 `(q,r)` 모칸을 그린다. 동 진입은 기존 동 연결을 통해 이뤄진다. 세부칸 표시는 시안, 여기 산출물은 실제 자료 조회 검증이다.

Claude가 같은 PC에서 쓸 파일은 [필드 색인](../../../artifacts/local/public-data/dong-tile-intake-20261126/field-catalog.json), [SQLite 지문·검증표](../../../artifacts/local/public-data/dong-tile-intake-20261126/verification.json), [타일과 행정동 관계 DB](../../../artifacts/local/public-data/dong-tile-intake-20261126/dong-tile-evidence.sqlite)다. 기존 [서울 전역 자료](../DataCollection/Runbooks/seoul-area-evidence.md)는 모칸과 행정동 관측의 기준이다.

[출처별 취득판과 이용 조건 대조](../../../artifacts/local/public-data/dong-tile-intake-20261126/quality/source-provenance-review.md)는 전국 공식 경계 원본 16개를 포함한 파일 78개의 지문을 직접 확인했다. 생활인구·센서·교통은 각 SQLite의 원본 지문도 확인했다. 같은 이름이 여러 포털에서 제공될 경우 실제 받은 첨부와 이용 조건을 묶어 읽는다.

## 같은 키로 찾기

| 범위 | 키 | 관계 |
| --- | --- | --- |
| 서울 모칸 | `(q,r)` | 기존 300m 모칸 위치를 그대로 사용 |
| 세부칸 | `(geometryRevision,q,r,slot)` | 후보 규격 `hongdal-dong-child-candidate-r1`, 모칸 하나에 7칸 |
| 행정동 | `admin_code` | `child_admin`으로 교차 면적 연결. 세부칸 하나가 여러 동과 닿을 수 있는 다대다 |
| 법정동 | `legal_code` | `admin_legal`의 행정 코드 관할 관계. 두 코드 체계와 동 이름을 따로 둠 |
| 원본 관측 | 출처 고유 키 + 관측일·월·시각 | 해당 점·선·면의 원래 단위와 기간으로 저장 |

좌표계는 EPSG:5179이고 단위는 m다. 슬롯은 중앙 0, 동 1, 북동 2, 북서 3, 서 4, 남서 5, 남동 6이다. 모칸 내부의 중심점과 약 113.39m 거리의 여섯 기준점 중 가까운 점으로 나눈다. 변의 배열과 면적을 DB에서 읽는다. 가장자리 세부칸은 모칸으로 잘린 다각형이다. 같은 거리의 점은 슬롯 번호가 작은 쪽을 사용한다. 모칸 경계의 tie는 기존 `axial`과 같다. SQL별 모칸 sentinel `-1`은 개별 뷰의 저장 규칙이다.

서울 25구 427행정동에서 모칸 8,127개와 작은 칸 56,889개를 생성했다. 서울과 교차 면적이 없는 1,397칸은 `outside_seoul`로 표시한다. `child_admin` 69,255행을 모칸으로 다시 합쳐 원래 시·동 교차 면적과 대조했다. 한 동에 닿은 타일들의 도시값을 전부 더하면 경계 칸이 중복될 수 있다. 행정동 주민등록 인구는 동 관측에서 직접 읽는다.

관할표의 행정동·법정동 관계는 746행이다. 서울 행정동 중 관할 법정동이 여러 곳인 경우 93곳, 법정동이 여러 행정동에 걸친 경우 136곳을 확인했다. 주민 인구를 법정동이나 작은 칸에 그대로 할당하지 않는다.

새로 받은 원본과 기존 재사용 모두 측정 단위와 기준일을 원장에 남겼다. 공개 출처는 [생활인구](https://data.seoul.go.kr/dataList/OA-22784/S/1/datasetView.do) · [S-DoT](https://data.seoul.go.kr/dataList/OA-15964/S/1/datasetView.do) · [비오톱](https://data.seoul.go.kr/dataList/OA-21126/F/1/datasetView.do) · [그늘막](https://www.data.go.kr/data/15129447/standard.do) · [도로 속도](https://topis.seoul.go.kr/refRoom/openRefRoom_1.do?tab=velocityMonthly) · [교차로 5분 교통량](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=20001) · [따릉이](https://data.seoul.go.kr/dataList/OA-15249/F/1/datasetView.do) · [환승 이동](https://www.data.go.kr/data/15130556/fileData.do) · [점자설비](https://www.data.go.kr/data/15166080/fileData.do)에서 확인했다.

서울 전체를 합산할 때 건수는 원본 식별자 또는 공간 단위로 한 번만 더한다. 속도는 길이×관측속도 합을 실측 길이로 나누고, 평균 높이는 유효 표본의 합과 수를 쓴다. 녹지 비율은 가중 면적에서 다시 계산한다. 역 월 누계는 기간·시간대별 합계이며 시간당 평균으로 읽으려면 해당 기간의 일수 정의를 함께 써야 한다.

$python = 'C:/Users/user/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'

## Claude가 화면에 연결할 때

1. 모칸 키와 세부칸 후보 규격을 구분하고, 숫자·측정 단위·기준 기간·상태를 카드에서 함께 읽는다. 세부칸은 자동 확대나 기존 굽기 교체 전에 사가정·홍대입구·여의도·산자락의 네 사례로 확인한다.
2. 지형과 건물은 도형·높이의 자료층, 승하차·도로 속도·생활인구는 관측층, 주민등록은 동 통계로 읽는다. 계절·보행 연출을 넣을 때 데이터 종류가 바뀌지 않도록 근거를 보인다.
3. Unity 좌표 투영에는 해당 모듈의 좌표 틀을 쓴다. 보존된 공식 모듈 26개와 경기 후보 1개의 헤더를 읽어 대조했다. 공식 모듈 경계의 변환 뒤 공식 원형과의 차이는 최대 약 0.5m이고, 왕복 확인한 세부칸 안쪽 208점은 모두 기존 키로 돌아왔다. GIS 좌표에서 원점만 빼면 대조 표본에서 5.5~45.3m 차이가 났다. HDIO v2의 확인된 변환은 EPSG:5179 → WGS84 경·위도 → 해당 헤더의 로컬 좌표 순서다. 굽기 입력의 ECEF/ENU, 붙여 보기 배치 오프셋, 독립 동 카메라 이동은 각기 별도 값이다. Unity 적용·실제 입력 검증은 대기다. [모듈 좌표 대조](../../../artifacts/local/public-data/dong-tile-intake-20261126/quality/module-frame/읽는법.md)
4. 사가정 캐노피 후보는 OSM에서 동일 역 관계에 직접 속한 1~4번 노드를 찾았다. 3번과 4번 사이 62.8m다. 승인 배경지도의 같은 번호 점은 11.68~32.33m 떨어져 있다. 공식 역·출구 일련번호 관계는 여전히 보류이며 OSM과 공식 데이터의 면허·좌표를 합치지 않는다. 주변 정류소 좌표와 근접 좌표는 번호 확정의 근거로 쓰지 않는다. [OSM 출처](https://www.openstreetmap.org/copyright) · [새 PC 비교](../../../artifacts/local/public-data/dong-tile-intake-20261126/stations/osm-review/sagajeong-exit-readback.json) · [기존 PC 한정 대조](../../../artifacts/local/public-data/diorama-transit-access-pc-only-20261123/읽는법.md)
5. 인계 SQLite에 접근하는 빌드와 배포용 게임 팩은 독립 범위다. 승인받아 수령한 주소·경계·생활인구 원문과 좌표를 출시판 또는 외부 동기화로 넘기기 전에 공급자 조건과 승인 범위를 확인한다.

새 디오라마 공통 규칙 후보 등록은 없다. 기존 규칙 가운데 출처·좌표계·기준일·표현 의미를 보존하는 원칙을 실제 자료가 지지했다. 서울 밖 자료와 시기 차이, 역사별 출구번호, 교차로 좌표, 실제 주문은 보류 근거를 남겼다.
