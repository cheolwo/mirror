## 2. 바꿀 구조 — 「자료 → 환경 상태 하나 → 그리는 층」

```
실제 달력 관측(달력 팩) ─┐
평년값(r11) · 관측일(r50) ┼→  환경 상태(프레임마다 한 번)  ─→  셰이더 전역 값 ─→ 동 디오라마 메시 · 구 바탕 그림
게임 시계(GameSeconds) ──┘    날짜 · 해 높이 · 밤 · 노을         └→ C# 읽기 ─────→ 세계 입자(비 · 눈) · 길가 불빛 · 이름표
                              꽃 · 녹음 · 단풍 · 앙상
                              비 세기 · 젖음 · 쌓인 눈 · 새 눈
```

- **환경 상태가 하나다.** 모든 층이 같은 값을 읽는다. 시간이 쌓이는 값(젖음은 비 그친 뒤 몇 시간에 걸쳐 마르고, 눈은 쌓였다 녹음)도 여기서 계산한다.
- **색과 빛은 셰이더에서 칠한다.** 구 바탕도 머티리얼로 그린다(`Graphics.DrawTexture` + 새 셰이더). 덮개 판은 쓰지 않는다.
- **움직이는 날씨는 세계 안에서 그린다(동).** 빗줄기 · 눈송이는 파티클이다. 그래서 원근이 있고 건물에 가린다. 화면(IMGUI) 그림은 글 · 표지 · 마우스 이름표에만 쓴다.
- **값마다 근거를 단다.** 관측(그날 자료) → 평년(r11) → 규칙(정해 둔 날짜) 순으로 고르고, 오늘 칩에 「관측 · 평년 · 추정」을 적는다.

## 5. 지킬 것

- 2.5D를 유지한다(구 = 그림, 동 = 메시). 완전 3D로 넘어가지 않는다.
- 관측 → 평년 → 규칙. 지어낸 날짜는 「추정」으로 적는다. 동별이 아닌 값(눈은 서울 관측소 한 점, 비는 세 구 평균, 꽃 · 단풍은 서울 관측)은 오늘 칩에 그렇게 적는다.
- IMGUI는 글 · 표지 · 이름표 · 범례만. 색 · 빛 · 날씨 그림은 셰이더와 세계 입자로.
- 프레임 시간을 잰다(close-view 촬영이 이미 재는 값). 늘면 입자 수 · 인스턴스 수를 줄인다.
- 셰이더를 고치기 전 사본을 남긴다(10차처럼).

## 7. 진행 (11-24 00:27)

E0 ~ E4와 E5(나무)를 1차로 넣었다. 「정할 것」은 가안대로 — 실제 달력은 그대로, 자료 창에 날짜 미리 보기. 한 일 · 파일 · 확인 · 남은 것은 [반환 11차](2026-11-23-Claude-생활자료표현-D0-D4-반환.md). 계획과 다른 점:
- E2는 셰이더 재질 대신 미리 구운 철 그림(10 m 칸)을 `GUI.DrawTexture`로 얹었다. IMGUI 묶음 안에서 사용자 재질은 잘림 · 자리 맞춤을 믿을 수 없어서. 날이 바뀔 때만 다시 굽는다.
- E3는 빌드 프로젝트에 파티클 모듈이 없어, 네모 메시 하나를 셰이더가 시간으로 움직이는 방식으로 했다.
- `DrawGuSky`의 노을 · 밤 막은 그대로 두었다(10차에서 검증한 그림).
- E5의 나무 자리는 서울시 가로수 자료가 아니라 메시의 시설물대 · 녹지에서 고른 규칙 자리다(자료 이용조건 대조 전).
