# 2026-11-18 Claude 제안 — 두 기획을 나누고, 명덕은 공통 개념으로

- **작업실 역할.** 개발 작업실(Claude)의 구조 제안. 기획 문서(`Planning/**`)와 코드는 고치지 않았다. 기획 정본 작업은 Codex에 요청한다.
- **사용자의 말(12:02).** 「문명처럼 과거에서 현재까지 다루는 시리즈 기획이 하나 있고, 배달 플랫폼을 어떻게 운영할지에 대한 기획이 따로 있다. 둘을 구분해서 서로 독립적으로 발전시키되, 명덕 같은 개념은 공통 개념이니 두 방면에 활용하면 좋겠다.」
- **이어지는 말.** 같은 날 11:58 「원시 시대엔 명덕을 밝혀도 +3, +4. 기술이 발전하면 40, 50, 60. 플러스냐 마이너스냐는 철학이 정한다.」 12:01 「거칠게 하면 그렇게 할 수도 있다」(시안 D 방향 수용).

## 1. 세 덩어리

| 덩어리 | 무엇을 가지나 | 가지지 않는 것 |
| --- | --- | --- |
| **명덕 공통 개념** | 명덕의 뜻, 한 행위의 두 면(부호=철학 · 크기=기술), 산식, 인의예지 판정과 감광, 빛 표현 규칙, 철학/기술 두 갈래 연구의 원리, 오행 · 중화 같은 공통 언어 | 특정 시대 · 지도 · 업무의 숫자표와 화면 |
| **문명형 역사 시리즈** | 원시 → 현재의 시대 단계, 시대별 기술 · 철학 트리, 문명 단위 플레이, 시대별 크기 배율표(예: ±3 → ±60) | 행정동 · 배차 · 실제 공공데이터 지도 |
| **배달 플랫폼 운영** (`PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION`) | 행정동 · 지사 · 기사 · 배차, 일일일생 회차, 00 오행판, 배차 기술 단계(손 배차 → 엔진)와 그 배율표 | 시대 전환 · 문명 단위 |

두 기획은 서로의 문서를 고치지 않고, 공통 개념만 참조한다. 공통 개념을 바꾸면 두 기획에 각각 영향을 확인한다.

## 2. 같은 산식, 다른 숫자표

```text
한 행위의 명덕 = 부호(철학 판정) × 크기
크기 = 직접 바꾼 만큼 × 기술 배율
```

- **역사 시리즈:** 기술 배율 = 시대. 원시 ±3 · 농경 ±8 · 산업 ±18 · 정보 ±40 · 플랫폼 ±60(예시, 시안 D).
- **배달 플랫폼:** 기술 배율 = 배차 기술 단계. 손 배차 · 전화 배차 · 배차 앱 · 준비 시각 예측 · 구 단위 엔진(예시).
- **공통 규칙:** 악 판정은 기술 성과로 상쇄하지 않는다(r285). 같은 행위는 한 번만 센다(r283 · r284). 판정 근거가 모자라면 보류.
- **아직 정할 것:** 기술 배율을 마이너스에도 똑같이 곱하는가. 사용자 방향은 ‘예’, Codex r282는 ‘일괄로 곱하지 않는다’.
