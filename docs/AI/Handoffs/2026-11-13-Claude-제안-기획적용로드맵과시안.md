## 4. 붙이는 원칙

1. **있는 구현을 보존한다.** Core 배달·우유 5팩 사슬·핀·효과·전국 관찰을 다시 만들지 않고, 그 상태를 읽어 새 판단 화면을 얹는다.
2. **대표 질문 하나 → 근거 → 후보와 대가 → 직접 결과 → 다음 선택**(r161). 할 일이 없으면 정상 운영을 보여 주고 사건을 지어내지 않는다.
3. **계획 확정과 실제 완료를 따로 보인다**(r162). 버튼을 누른 순간 바뀌는 것과 나중에 업무가 끝나야 바뀌는 것을 화면 문구로 나눈다.
4. **시계와 참여 방식은 지도와 독립**(r144·r162). 지도를 바꾸거나 자료를 봐도 시계는 그대로이고, 집중은 대기열에서 일을 꺼낼 때만 시작한다.
5. **관찰 자료와 게임 업무를 색·출처로 나눈다.** 관리 매장 민트, 통계 청·보라, 가상 업무 민트 아치, 후보 점선.

### ① 구 지도 기사 여력 판단 — 시안 A

시안 A (로컬 검토 자료 `artifacts/local/hongdal-unity-claude-20261112/mockups/기획적용-20261113/01-구-기사여력판단.png`)

- **무엇:** 신호 줄 자리에 대표 질문 하나("상봉동 픽업 대기가 늘었다 — 다음 가용 기사를 지원 대기로 돌릴까?"), 오른쪽 카드에 근거·후보 비교(기사 B 지금 / 기사 A 3분 뒤 / 보류)와 대가(면목 여유 감소). `지원 대기 확정`은 **대기 계획만** 바꾸고, 실제 이동·도착은 다음 결과로 따로 보여 준다. 같은 계획을 동네 지도에서 다시 읽고 돌아온다.
- **그대로 쓰는 것:** 구 지도·영역 패널 자리, 신호(`KernelSignals`), 음식 배달 상태 사본의 기사·주문, 후보 정책(`음식배달후보선정Policy`)의 추천 순위.
- **새로 필요한 것:** "지원 대기 계획" 하나의 상태와 명령(확정·보류·취소, Revision). r162 인계의 첫 결과 범위 그대로다.
- **먼저 짚을 것 — 지금 다른 동에는 실제 주문이 없다.** 시안처럼 "상봉동 대기 3"을 실제로 만들려면 (a) 첫 조각을 **면목동 안 두 매장 사이의 기사 여력**으로 좁히거나, (b) 상봉동 가상 매장에 가상 주문이 생기는 규칙이 먼저 있어야 한다. 기획이 정할 선택 하나다. (a)는 바로 할 수 있고 (b)는 구 지도의 재미가 더 크다.
