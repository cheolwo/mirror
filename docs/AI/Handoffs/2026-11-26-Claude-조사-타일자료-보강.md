# 조사 — 타일 수치에 쓸 자료, 굽기 전에 한 번에 (2026-11-26)

사용자(2026-11-26): 「단계를 이렇게 밟아 나가기 전에 관련해서 한번 자료 조사를 한번 할 필요가 있겠다 … 자료가 또 쌓이면은 또 이게 구워야 되는데 … 일단 정보 조사부터 먼저 좀 충분히 하는 게 좋겠다」

이 문서는 조사만 담는다. 자료 내려받기 · 굽기 · 코드 수정은 하지 않았다. 2026-11-25 설계의 D1~D5는 이 문서를 본 뒤로 미룬다.

## 0. 결론

1. **바닥 단위는 250m 격자로 굳힌다.** 서울시 인구 자료가 국가표준격자(250m)로 옮겨 갔다. 옛 집계구 · 행정동 생활인구는 2026-07-31 뒤로 생산이 끝났다. 게임의 `hongdal-data-floating.json`(OA-14991, 2026-07)은 마지막 판이다. 체류인구도 250m다.
2. **배달 주문 자체는 공개 자료가 없다.** 지역별 주문 위치 · 건수는 민간 플랫폼도 공공배달도 내놓지 않는다(공공배달은 합계 보도만 있다). 그래서 콜 · 주문 · 배달은 끝까지 「추정」이다. 크기는 전국 음식서비스 온라인 거래액(월)으로, 시간대 모양은 상권분석 추정매출의 시간대 비율로 맞춘다.
3. **새로 받을 1순위는 여섯 가지다.** 체류인구 250m · 개별공시지가(필지) · 건축물대장 표제부(세대 · 가구 · 주용도) · 승강기(건물 위치 · 운행층수) · 이륜차 사고다발지역 · 공정위 가맹(지역별 가맹점 수 · 평균 매출).
4. **이미 가졌는데 타일 층에 넣지 않은 것이 많다.** 서울 보행 출입구 16,786행, 공동주택 단지 · 세대, 인허가 원본의 개업 · 폐업일, 상가정보 원본, 직장 사업체 · 종사자(4구), 날씨 달력이 그렇다.
5. **굽기는 층마다 따로 한다.** D1의 「수치 팩 하나」 대신 「층 묶음 여럿 + 규칙 표」로 바꾼다. 그러면 자료가 하나 늘 때 그 층만 굽고 나머지는 그대로 둔다. 수치 식은 규칙 표에 두고, 게임이 켤 때 셈한다.

## 4. 바뀌는 것 · 조심할 것

- **옛 생활인구 생산 종료:** 옛 생활인구(집계구 · 행정동)는 2026-07-31에 생산이 끝났다. 게임 floating 묶음은 「[내국인] 행정동별 서울 생활인구(250m)」나 우리가 굽는 250m 자료로 갈아탄다.
- **상권분석 기간:** 2024년부터 공간 단위가 표준단위구역이 됐고, 2026-07-03부터는 2021년 이후 자료만 준다. 2021년 전 시계열에 기대지 않는다.
- **상권분석 소비 자료:**
  - 월평균 소득 칸은 2026-05-13에 삭제됐고, 소득 구간 칸도 삭제될 예정이다. 소득은 국세청 시군구 자료로 본다.
  - 소비-상권은 더 이상 갱신하지 않는다.
- **실거래가 수집 경로:** 실거래가 공개시스템(rt.molit.go.kr)은 크롤러 같은 자동 수단을 금지하고, 대량 · 반복 이용은 공공데이터포털 API를 쓰라고 한다. `hongdal-housing-transactions-20261125`는 `rt.molit.go.kr/pt/xls/xls.do`에서 받았다. 다음 수집은 data.go.kr 실거래 API로 옮긴다.
- **공개판 방침:** 생활인구 250m 원본은 재배포하지 않는다(분석 결과는 출처를 밝히고 쓸 수 있다). 그래서 공개판에는 단계(0~5)만 싣는다. 체류인구도 같은 방침으로 다룬다.
- **보도자료 글:** 온라인쇼핑동향 보도자료 글은 공공누리 2유형(상업 이용 금지)이다. 숫자만 쓰고 글과 그림은 옮기지 않는다.
- **총괄표제부 범위:** 건축물대장 총괄표제부는 한 대지에 건물이 2동 이상일 때만 만든다(서울 19,238건). 집집마다 세대 수는 표제부에서 본다.
- **내비게이션용DB 심사:** 도로명주소 내비게이션용DB는 신청과 이용목적 심사를 거쳐야 해서 시간이 걸린다. 그동안은 이미 있는 보행 출입구와 K-apt 출입구를 먼저 쓴다.

## 5. 층별 굽기 — 자료가 늘어도 통째로 다시 굽지 않기

지금 계획(D1)은 `bake_tile_yields.py`로 `hongdal-tile-yields.json` 하나에 9칸 값을 굽는다. 이러면 자료가 하나 늘 때 팩 전체를 다시 구워야 하고, 셈이 바뀌면 게임 코드(`EnsureHexYields`)도 고쳐야 한다.

그래서 네 겹으로 나눈다.

| 겹 | 파일 | 바뀌는 때 |
|---|---|---|
| 바탕 | `hongdal-tiles-gu.json`(모양 · 이웃 · 세부칸 7) + 칸 순서 지문(sha) | 격자가 바뀔 때만 |
| 층 | `hongdal-tile-<층>.json`: 자료층 하나에 파일 하나. 층 이름은 Codex field-catalog의 `fieldKey`(presence · buildings · roadSpeed …)를 그대로 쓴다 | 그 자료가 새로 나올 때, 그 파일만 |
| 규칙 | `hongdal-tile-yields-rules.json`: 입장 3 × 수치 3마다 쓰는 층 · 칸, 식, 5등분 범위, 태그, 「어떻게 셈했나」 문장 틀 | 셈을 바꿀 때(코드는 그대로) |
| 판 목록 | `hongdal-tile-layers.json`: 층마다 release · asOf · sha256 · 공개 여부 | 층이 바뀔 때 자동으로 |

층 파일 머리는 hongdal-data.v1에 몇 칸을 더한다.

```json
{ "schema": "hongdal-data.v1", "topic": "tile-layer", "title": "머무는 사람(250m 배분)",
  "layer": "presence", "release": "lp-r2", "asOf": "2026-11-21",
  "base": "hongdal-tiles-gu@<칸 순서 sha 앞 12자>", "keys": "q,r,slot",
  "fields": ["wdLunch", "wdDinner", "weLunch", "weDinner"], "unit": "명/시(추정)",
  "missing": "null = 관측 없음(0 아님)", "public": "bands-only",
  "sources": [{ "id": "OA-22784", "url": "…", "sha256": "…" }],
  "values": [ "… 바탕 칸 순서대로, 없으면 null …" ] }
```

규칙 한 줄은 이렇게 쓴다(예).

```json
"store.guest": { "inputs": ["presence.{band}", "stay.{band}"], "mix": [0.5, 0.5],
  "rank": "seoul-quintile", "tag": "실제",
  "why": "{bandName} {presence}명/시 · 머묾 {stay}명 · 서울 5등분 {v}째" }
```

굴러가는 방식:

- **게임의 셈:** 게임은 켤 때 층을 읽고 규칙대로 0~5를 셈한다(지금 `EnsureHexYields`가 하는 일). 층이 없으면 그 칸은 「자료 준비 전」으로 보이고, 0으로 세지 않는다. 「어떻게 셈했나」 줄은 규칙의 `why`를 그대로 채운다.
- **계층 합계:** 세부칸 값이 바탕이다.
  - 타일 값은 7칸의 합(양)이나 평균(비율 · 속도)이다.
  - 동 · 구 값은 `tile_admin`의 겹친 넓이 몫으로 나눠 더한다.
  - 읽을 때 셈하든 층 파일에 미리 넣든, 같은 규칙을 쓴다.
- **공개판:** `public: bands-only`인 층은 내보낼 때 0~5로 바꿔 싣는다.
- **굽는 주기:** 자주 바뀌는 층(생활인구 · 체류 · 승하차 · 날씨)만 자동으로 굽는다. 거의 안 바뀌는 층(공시지가 · 건물 · 지형 · 사고)은 해마다 한 번 굽는다.
- **크기 어림:**
  - 서울 8,127칸 × 정수 4개면 층 하나가 100~200 KB(JSON)쯤이다.
  - 세부칸 56,889 × 4는 1 MB 안팎이라 `.bytes`(정수 배열)로 싣는다.
- **Codex 쪽:** `bake_tile_layer.py <fieldKey>` 하나로 field-catalog의 층 하나를 굽는다. 새 자료가 오면 catalog에 한 줄을 더하고 이 명령을 한 번 돌리면 된다.
- **검사:** `check_data_packs.py`가 판 목록과 Resources를 맞춰 본다. 이미 있는 검사에 층 규칙만 더한다.

D1~D5에 주는 영향:

- D1: 「층 묶음 + 규칙 표」로 바꾼다.
- D2: 「게임이 층과 규칙을 읽어 셈한다」로 바꾼다.
- D5(세부칸 번호 · 길 속도): Codex가 11-26에 넘겨 사실상 끝났다.
