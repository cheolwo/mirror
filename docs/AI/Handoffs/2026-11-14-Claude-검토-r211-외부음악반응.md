# 2026-11-14 Claude 검토 — r211 외부 음악 자동 분석과 빛

- **작업실 역할.** 개발 작업실(Claude)의 검토다. 기획 문서(r211)는 고치지 않았다. 코드 · 음원 · 소리 캡처는 하지 않았다.
- **사용자의 말(2026-11-14).** r211의 요약을 전하며 「이거 검증해봐. 보완할 부분 존재?」
- **확인한 것.** [r211](../Planning/시스템/PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/external-music-auto-analysis-and-light.proposal.r211.md) 전문, Microsoft의 공식 문서 둘(루프백 녹음, 앱 루프백 샘플), NAudio · aubio의 공개 페이지, 이 프로젝트의 빌드 설정과 실행판 폴더. 웹 문서는 2026-11-14에 읽었다.

## 2. 보완할 것

**가. 입력**

1. **게임 자신의 소리를 빼는 길이 이미 있다.** 앱 루프백의 `excludetree`에 이 게임의 프로세스를 주면 「모든 소리에서 이 게임만 뺀」 입력이 된다. r211 6절의 「게임 알림음이 섞인다」는 이것으로 풀린다. 다른 앱의 알림은 여전히 섞인다. 그래서 「장치 전체」 선택지는 「장치 전체 − 이 게임」으로 두는 것을 권한다.
2. **독점 모드로 내는 소리는 받을 수 없다.** 같은 Microsoft 문서: 루프백은 공유 모드 스트림만 가능하다. 음악 앱이 고음질 · 독점 출력을 쓰면 입력이 비어 있다. 「입력 없음」 안내에 이 까닭을 함께 적는다.
3. **앱을 고르는 목록은 「지금 소리를 내는 앱」에서.** Windows의 볼륨 믹서와 같은 오디오 세션 목록이다. 프로세스 이름을 고르게 하지 않는다. 브라우저는 소리를 내는 프로세스가 탭이 아닐 수 있다. 고른 앱에 소리가 없으면 샘플 문서대로 무음이 오므로, 「이 앱에서 소리가 오지 않는다」를 따로 보인다.
4. **음량.** 사용자가 소리를 줄이면 분석값이 같이 작아질 수 있다(루프백이 음량 조절 앞인지 뒤인지는 공식 문서에 없다. 시험으로 본다). 최근 구간 기준으로 맞추는 자동 이득을 둔다.

**나. 시간**

5. **지연은 두 방향이다.**
   - 분석 때문에 빛이 늦는다. 박이 잡힌 뒤에는 「다음 박의 시각」을 미리 계산해 그 시각에 맞춰 퍼지게 한다. 소리를 듣고 나서 반응하지 않는다. 박이 안 잡힌 1단계(강약 반응)에는 약간의 늦음이 남는다.
   - 출력 기기 때문에 빛이 빠르다. 루프백은 기기로 나가기 전의 소리다. 블루투스 이어폰처럼 기기 안에서 늦게 나오는 경우 빛이 소리보다 먼저 퍼진다. 사용자가 맞추는 보정값(빛을 조금 늦추기)이 있어야 한다.

**다. 사람과 배포**

6. **사생활.** 장치 전체 입력에는 통화 상대의 목소리도 들어간다. r211의 「원음은 저장 · 전송하지 않는다」에 더해, 기본은 꺼짐, 켜져 있는 동안 화면에 「소리 읽는 중」 표시를 권한다. 루프백에는 마이크처럼 Windows가 묻는 창이 없을 수 있다(시험으로 확인한다). 그렇다면 게임이 스스로 알려야 한다.
7. **라이선스.** 널리 쓰이는 비트 추정 라이브러리 aubio는 GPL이다([aubio.org](https://aubio.org/)). Steam 판매를 생각하면 넣기 어렵다. 박 추정은 직접 짜거나(스펙트럼 변화 → 템포 후보 → 위상 추적), 허용적 라이선스만 쓴다. 고르기 전에 라이선스부터 확인한다.

**라. 이 프로젝트에 붙일 때**

8. **어댑터의 길.** 이 게임의 Windows 실행판은 Mono로 돈다(실행판 폴더에 `MonoBleedingEdge`가 있고 Standalone의 스크립팅 백엔드 설정이 비어 있다). Windows의 Mono에서는 C#에서 COM을 직접 부를 수 있으므로, 별도 C++ DLL 없이 WASAPI를 C#으로 붙이는 길이 있다. NAudio의 옛 판(2.2.1)은 net472를 대상으로 하지만 netstandard는 아니어서, 이 프로젝트의 API 호환 설정에서 되는지는 시험이 필요하다. C++ DLL은 PC에서 따로 빌드해야 한다.
9. **뒤에 있어도 돈다.** 프로젝트 설정의 `runInBackground`가 켜져 있다. 음악 앱을 앞에 두고 게임을 옆 화면에 둬도 빛이 반응할 수 있다.
10. **박 칸 배정은 지금 코드에서 이어진다.** 지금의 빛마다 엇갈림(`기사불빛Policy.Phase(열쇠)`)은 연속 값이다. 같은 열쇠를 「몇 번째 박에 퍼질지」의 묶음 번호로 바꾸면 r210 · r211이 권한 박 칸 배정이 된다. 대상의 정체는 그대로다.
11. **땅의 빛.** r211 지적대로 시계만 바꿔서는 대상과 땅이 맞지 않는다. 음악에 반응하는 동안 땅은 잔잔하게 두는 r210의 첫 후보가 지금 구조에 가장 가볍다. 땅까지 대상별 박을 따르게 하려면 땅의 그림에 대상별 박을 담을 자리가 필요하다(지금 네 겹이 다 쓰인다).

## 3. 개발 쪽이 먼저 할 수 있는 일 (제안, 하지 않았다)

- **입력 시험 하나.** 「장치 전체 − 이 게임」으로 몇 초를 받아 음량과 저음 세기만 화면에 숫자로 띄우는 확인용 장면. 원음은 저장하지 않는다. 멜론 · 유튜브(브라우저)에서 값이 오는지, 독점 출력 · 블루투스에서 어떤지 표로 남긴다.
- 실제 캡처는 사용자가 「해 보자」고 할 때 한다. r211도 실제 캡처는 구현 범위를 받은 뒤라고 적었다.
