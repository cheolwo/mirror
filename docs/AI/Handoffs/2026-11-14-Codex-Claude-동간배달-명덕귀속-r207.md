## 이번 사용자 방향

기사는 행정동 A에서 B로 자연스럽게 이어 배달한다. **받는 B동도 명덕이 증가**한다. r206의 깨어 있는 모든 활동과 r205의 누적 명덕→빛 확대를 유지한다. 개인 명덕 전체를 배달 성공 한 번의 보상으로 바꾸지 않는다.

## 개발 계획에 결합할 다섯 가지

1. **기존 실제 ID를 재사용한다.** 동별 집계/배회 빛에 실제 개인 ID가 없는 것과, 기존 Core 배달에 주문/기사 ID가 없는 것은 다르다. 현재 `DispatchOrder.id/storeId/driverId/revision`, `DispatchCourier.id`, 주문과 같은 목적지ID가 있다. 이름1은 기존 기사와 증분 고용 명부의 관계·저장 호환을 먼저 명확히 한다.
2. **동 관계를 구분한다.** 기사 소속 동·현재 위치 동·주문의 픽업 동·전달 동·활동/수혜 귀속 동은 같은 값으로 채우지 않는다. 기존 `TerritoryId`를 행정동 코드로 읽지 않는다. 정확 필드/코드 판본/누락은 후속 명세에서 결속한다.
3. **기존 동간 장면을 보완한다.** 첫 화면 반환은 매장=면목제3·8동, 배송지=면목7동이라고 보고했다. 기존 도로/개별 주문을 재사용 후보로 두고 다른 동으로 가서 표식이 숨겨져도 ‘B동으로 배달 중’·선택 이동/귀환으로 읽게 하는 안이다. 경계 순간의 실제 입력은 아직 별도 검증이 필요하다.
4. **도착지 기여는 원활동과 연결한다.** 기사/점포·A/B동에 관련 기여가 보이는 것을 전부 중복으로 금지하지 않는다. 같은 기록의 같은 동/사유 재처리와 A=B의 같은 전달 중복만 구분한다. 정확한 배분량·비율은 미정이다. 경계 통과/표현 애니메이션만의 보너스는 추가하지 않는다.
5. **그림자 주문과 권위를 섞지 않는다.** 개발 제안은 아직 선택되지 않았다. 표현만의 가상 완료를 확정 명덕/동 성장으로 올리지 않는다. 개별 주문 생성 경로·정신 차림/점수·동 승급 통합은 기존 미정을 유지한다.
