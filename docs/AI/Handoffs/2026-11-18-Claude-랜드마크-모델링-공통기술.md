## 1. 조사한 기술과 홍달에서 쓰는 방식

| 기술 | 무엇인가 | 홍달에서 |
| --- | --- | --- |
| 절차적(코드) 모델링 · 형상 문법 | 규칙으로 건물을 만든다. CGA shape는 덩어리(매스) → 면 나누기 → 요소 순으로 세분한다 | **채택.** 손 모델링 대신 스크립트로 만든다. 치수가 바뀌면 다시 돌린다 |
| 바닥 외곽 돌출 | 건물 바닥 다각형을 높이만큼 올린 덩어리 | **채택.** 굽기 건물 자료의 외곽 · 높이를 그대로 쓴다(`extrude`) |
| 회전체 · 훑기 · 매개변수 곡면 | 단면을 돌리거나(타워 · 돔) 길을 따라 보내거나(기와 줄 · 서까래) 식으로 면을 만든다(지붕 · 셸) | **채택.** `lathe` · `tube` · `surface` |
| 부품 키트 · 반복 배치 | 창 칸 · 기둥 · 기와 줄 같은 부품을 한 번 만들어 여러 번 놓는다 | **채택.** 부품 함수 + `merge`. 파일 안 인스턴싱(EXT_mesh_gpu_instancing)은 Unity glTFast가 부분 지원이라 쓰지 않고 메시에 굽는다 |
| 상세 단계(LOD) | 도시 모델 표준 CityGML은 LOD0 바닥 · LOD1 상자 · LOD2 지붕 모양 · LOD3 창 · 문 등 외관 · LOD4 실내로 나눈다 | 홍달 **멀리 = 상자 + 지붕 윤곽**(CityGML LOD1 ~ 2), **중간 = 지붕 · 큰 요소**(LOD2.x), **가까이 = 외관 상세**(LOD3.x). 실내는 만들지 않는다 |
| 엔진의 LOD 전환 | Unity LOD Group은 화면에서 차지하는 높이 비율로 단계를 고르고, Cross Fade로 섞을 수 있다 | 전환 비율 제안: 가까이 50% 이상 · 중간 15% 이상 · 멀리 3% 이상(제안값 · 게임에서 맞춘다) |
| 메시 자동 줄이기 | 모서리를 접어 삼각형을 줄인다(이차 오차 척도 QEM). 도구로는 meshoptimizer · gltfpack `-si` | **보조.** LOD는 부품의 `lod` 값으로 다시 만든다. 실루엣과 색 경계가 지켜진다. 자동 줄이기는 곡면 셸에만 검토 |
| 꼭짓점 묶기 · 부드러운 법선 | 같은 꼭짓점을 한 번만 저장하고, 곡면은 법선을 평균한다 | **채택.** 정자 1만 개가 740 KB였는데, 같은 모양 8천 개가 222 KB로 줄었다 |
| 압축 | KHR_mesh_quantization · EXT_meshopt_compression · Draco. gltfpack이 만들고 glTFast가 읽는다 | **보류.** 지금은 파일이 작다. 보관량이 커지면 gltfpack을 쓴다 |
| 재질 | 텍스처 아틀라스 · 트림 시트 · 노멀 맵 굽기 · 버텍스 컬러 · 단색 재질 | **단색 공용 색표.** 사진 텍스처는 쓰지 않는다. 재질 수가 부담되면 버텍스 컬러 한 재질로 합치기(후보) |
| 사진 측량 · 라이다 스캔 | 사진 · 점군에서 형상을 뽑는다 | **쓰지 않음.** 사진을 근거로 쓰지 않는 원칙 · 권리 미정 |
| 불리언(뚫기 · 합치기) | 덩어리끼리 빼고 더한다 | **쓰지 않음.** 창은 뚫지 않고 유리 면 + 창틀을 덧붙인다 |
| 임포스터 · 빌보드 | 아주 멀리서는 그림 한 장으로 바꾼다 | **후보.** 지금은 멀리 단계 저폴리로 충분하다 |
| 한옥 지붕 곡선 | 처마 끝이 위로 들리는 앙곡, 평면에서 안으로 휘는 안허리곡. 한옥 부재를 매개변수 관계로 모델링하는 연구가 있다 | 지붕 부품에 앙곡(`lift`) · 지붕면 처짐(`sag`)이 있다. **안허리곡은 아직 없다** — 사찰 전각 때 넣는다 |

- 앙곡 · 안허리곡 용어 설명은 일반 지식이다. 치수 규칙(비율)은 근거 자료를 확인하지 않았다.

## 3. 공통 도구 `landmarks/_parts/`

위치: `artifacts/local/hongdal-unity-claude-20261112/landmarks/_parts/`. PC의 python(numpy · Pillow)만으로 돈다.

| 파일 | 하는 일 |
| --- | --- |
| `hongdal_lm.py` | 공용 색표 20색 · 기본 도형(`box` · `cyl` · `lathe` · `extrude` · `surface` · `tube` · `merge`) · 부품(`part_hanok_roof` · `part_round_columns` · `part_railing` · `part_window_grid` · `part_dome`) · `write_glb` · `validate_glb` · `check` · `render` · `previews` |

| `plan-template.md` | 개별 계획서 양식 |

- 규격: LOD마다 glb 한 파일(`lod0.glb` · `lod1.glb` · `lod2.glb`). 한 파일에 셋을 넣으면 일반 보기 도구에서 겹쳐 보이고, glTFast가 LOD 확장(MSFT_lod)을 지원하지 않아 바꿨다(공통 계획 2절도 고침).
- 창 칸 · 돔 부품은 기본형이다. 처음 쓰는 랜드마크에서 다듬는다.

## 4. 개별 요청이 오면(순서)

1. **대상 확인:** [예산표](2026-11-18-Claude-랜드마크-폴리곤-예산표.md)에서 행을 찾는다. 없으면 새 행으로 잡는다.
2. **조사:** `lookup_building.py`로 굽기 건물 자료(외곽 · 높이 · 층수) → 공원 자료 · Codex 랜드마크 대장(r273) → 웹의 공식 안내(높이 · 바닥 크기 · 층수 · 구조). 사진은 받지 않는다. 값마다 근거와 「확인 · 추정 · 미확인」을 적는다.
3. **개별 계획서:** `landmarks/<ID>/rN/plan.md`를 양식대로 쓴다. 모델 단위 · 식별 요소 · 미정을 분명히 한다.
4. **종합:** 공통 계획과 맞춘다. 쓸 부품 · 새 부품 · 예산 배분 · 다른 점을 계획서 「종합」 절에 적는다. 예산표 행도 갱신한다.
5. **모델링:** 덩어리 → 가까이 → 중간 · 멀리. `build.py`가 `hongdal_lm`을 불러 세 파일을 쓴다.
6. **검사 · 보관:** `check` · `validate_glb` · 미리보기 네 장 · `manifest.json`. PC `landmarks/<ID>/rN/`에 두고, MYBOX 접근이 되면 복사한다.
7. **보고:** 미리보기 한 장 · 치수 근거 · 미정 · 물을 것.
- 높이나 바닥 크기의 근거가 하나도 없으면 3번에서 멈추고 묻는다. 추정으로 만들 때는 계획서와 manifest에 「추정」이라고 적는다.
- 새 부품이 생기면 `hongdal_lm.py`에 올리고 자체 시험에 한 줄 더한다.
