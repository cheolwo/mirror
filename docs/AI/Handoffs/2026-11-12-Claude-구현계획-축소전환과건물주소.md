# 2026-11-12 Claude 구현 계획 — 축소 범위·화면 전환과 건물 주소

[혼용 운영 기준](Codex-Claude-혼용운영안-2026-11-12.md)의 Claude 구현 계획이다. [법정동 팩과 Core 통합 계획](2026-11-12-Claude-구현계획-법정동팩과Core통합.md)의 2단계(법정동 팩)에 붙는 내용이고, [Windows 모듈 1단계 반환](2026-11-12-Claude-WindowsGame-1단계-반환.md) 다음 작업이다. 이 문서는 계획이며 코드를 바꾸지 않았다. PLAN 판본은 고치지 않았고, 반영할 사용자 결정을 1절에 모았다.

## 1. 사용자 결정 (2026-11-12) — Codex 기획 반영 요청

| 번호 | 사용자 말의 요지 | 반영할 곳 |
| --- | --- | --- |
| 1 | 축소할 수 있는 범위가 작다. 법정동이 한눈에 내려다보일 때까지 축소할 수 있어야 한다. | 지도 표현 판본(법정동 팩 판본과 함께) |

## 2. 확인한 사실

### 축소와 화면 전환 (`SagajeongDispatchMap.cs`)

- 동네 지도 배율은 70%~400%로 고정이다(`MinMapZoom` 0.7, `MaxMapZoom` 4).
- 100%는 매장과 배송지가 들어오도록 맞춘 값이다. 화면에 담기는 땅은 가로 약 1km로 추정한다. 70%여도 약 1.4km다.
- 70%에서 휠을 한 칸 더 내리면 **묻지 않고** 구 지도로 바뀐다. 안내는 상태줄의 작은 글씨("더 축소하면 구 지도 · 70%")뿐이다.
- 구 지도와 서울 지도는 2D 도로 표본이다. 구 이름을 누르면 법정동 목록이 열린다. 돌아오면 78% 배율이 된다.
- 2.5D 자료는 가로 1,089m × 세로 1,888m 사각형이다(사가정역·면목역 주변). 법정동 경계가 아니다. 이 전체를 지금 카메라 각도(55°/30°)로 한 화면에 담으려면 배율이 약 30%여야 한다(추정, 실제 값은 실행 때 계산).
- 2.5D에서 화면 가운데가 자료 밖으로 못 나가게 하는 장치(`ClampDioramaOffset`)는 이미 있다. 한계까지 축소하면 가운데에 고정된다.

### 건물

- 건물 메시는 전체를 한 덩어리로 합쳐 구웠다. 건물 구분이 없어 지금은 누를 수 없다.
- 실제 외곽 건물은 1,058동, 예시 채움 건물은 3,414동이다. 채움은 가짜라서 주소가 없다.
- OSM 스냅샷의 건물 1,073개 가운데 약 1,000개(93%)에 도로명과 건물번호가 이미 붙어 있다. 우편번호는 960개, 건물 이름은 233개다.
- 지번, 용도, 층수, 사용승인일은 OSM에 없다. 도로명 1건은 로마자 표기다. 한 주소를 여러 동이 함께 쓰는 경우가 50건 있다(학교처럼 한 터에 여러 동).

### 공공 건물 자료 후보 (2026-11-12 공공데이터포털 확인)

| 자료 | 내용 | 이용 조건 표기 |
| --- | --- | --- |
| 국토교통부 GIS건물통합정보 (일별 파일, WMS/WFS) | 건물 공간정보에 건축물대장 속성을 건물 단위로 합친 자료 | 이용허락범위 제한 없음 |
| 국토교통부 건축HUB 건축물대장정보 서비스 | 표제부·총괄표제부·층별개요 등 대장 속성 (API) | 이용허락범위 제한 없음 |
| 행정안전부 도로명주소 전자지도 (건물 도형) | 도로명주소가 붙은 건물 도형 | **미확인** |

세부 항목 이름, 좌표계, 게임에 넣어 배포할 때의 조건은 포털 표기만 보았다. 수집할 때 원문 약관으로 다시 확인해야 한다.

## 3. A — 축소 범위와 화면 전환

### A1. 축소 한계를 "동네 전체가 보이는 배율"로

고정 숫자 70% 대신, 지금 동네 전체가 화면에 들어오는 배율을 계산해 한계로 쓴다.

- 1차(지금 자료로 가능): 2.5D 자료 범위 사각형 기준. 약 30%.
- 2차(경계 자료가 들어온 뒤): 법정동 팩의 경계 도형 기준. 면목동은 지금 자료 범위보다 넓어서 한계 배율이 더 낮아진다.
- 계산: 경계 꼭짓점을 카메라 각도로 투영한 상자가 지도 영역에 여백 8%를 두고 들어가는 배율. 창 크기가 바뀌면 다시 계산한다.
- 평면 지도 모드도 같은 한계를 쓴다.

### A2. 멀리 볼 때 화면 정리

| 배율 | 보이는 것 |
| --- | --- |
| 100% 이상 | 지금과 같다 |
| 한계~100% | 표식을 작게(지금도 85% 아래에서 작아짐), 도로 이름은 대로만 |
| 한계 근처 | 동 경계선과 동 이름, 매장·기사는 점, 주문 상태는 색만 |

배달과 시계는 어느 배율에서도 그대로 진행한다.

### A3. 전환 알림

한계 배율에서 휠을 더 내리면 지도 아래 가운데에 알림 카드가 뜬다.

```
면목동 전체를 보고 있습니다
계속 축소하면 중랑구 지도로 이동합니다   [▓▓▓░░]
[구 지도로]  [머무르기]
```

- 휠을 계속 내려 막대가 차면(3칸 안팎) 구 지도로 넘어간다. 버튼으로도 넘어간다.
- 휠을 올리거나 1.5초 멈추면 카드가 사라지고 막대가 비워진다. 실수로 넘어가지 않는다.
- 구 지도에서는 위쪽에 "면목동 운영 중 · 배차 대기 n건" 띠를 둔다. 배달이 계속 진행 중임을 알린다.
- 돌아올 때(동을 누르거나 휠을 올림)는 동 전체가 보이는 한계 배율로 돌아온다. 지금은 78%로 돌아와 일부만 보인다.
- 구 지도 → 서울 지도에도 같은 카드를 쓴다.
- 처음 한 번은 위 문구 그대로, 그다음부터는 한 줄로 줄인다(r141 순차 소개).

### A4. 구 지도에서 법정동 고르기 (2차)

구 지도에 법정동 경계를 그린다. 팩이 있는 동은 밝게, 없는 동은 흐리게 한다. 동을 누르면 그 동의 전체 보기로 들어간다. 기존 계획 4단계(이웃 동 확장)와 같이 간다.

### 바뀌는 코드

- `SagajeongDispatchMap.cs`: `HandleMapWheel`(한계 계산, 휠 누적), `DrawMapChrome`(안내 문구)
- 새 파일 `SagajeongDispatchLevelPrompt.cs`: 알림 카드
- `SagajeongDispatchMotorcycle.cs`·표식 그리기: 배율 구간별 크기

### 위험

- 트랙패드 관성 스크롤로 막대가 한 번에 찰 수 있다. 기존 대기 시간(`WheelLevelCooldown`)을 유지하고 한 번의 휠 입력이 채우는 양에 상한을 둔다.
- 평면 지도에서 배율이 낮아지면 한 번에 읽는 도로 타일 수가 늘어난다. 한계 배율에서 타일 수와 프레임을 잰다.

## 4. B — 건물 선택과 주소

### B1. 건물 색인

굽기 스크립트가 메시와 함께 건물 색인을 낸다. 건물마다 다음을 담는다.

- 고유 ID (출처 + 원본 ID)
- 바닥 외곽(미터)과 높이
- 메시 안의 정점 범위 (강조 표시에 씀)
- 주소 묶음: 도로명주소, 건물 이름, 우편번호, (2차) 지번·주용도·층수·사용승인 연도
- 출처와 기준일

빠르게 찾도록 32m 격자 색인을 함께 둔다. 법정동 팩에서는 `buildings.geojson`에 주소 필드를 더하고, 팩에 `building-index.bytes`를 추가한다.

### B2. 고르는 방법

물리 엔진을 쓰지 않고 계산한다. 누른 지점의 시선은 건물 높이에서 땅까지 내려오는 동안 지면 위에 짧은 선분을 그린다. 이 선분이 건물 외곽과 만나면 그 건물을 지나간 것이다. 만난 건물 가운데 카메라에 가장 가까운 것을 고른다.

- 높은 건물의 옥상이나 벽을 누르면 그 건물이 선택된다. 뒤에 가린 건물이 선택되지 않는다.
- 후보는 격자로 좁히므로 건물이 수천 동이어도 한 번 누를 때 수십 동만 검사한다.

### B3. 누르기 우선순위

기사·매장·배송지 표식이 먼저다. 표식이 아닌 곳을 눌렀을 때만 건물을 고른다. 끌기는 선택으로 치지 않는다(기존 기준 그대로).

### B4. 보여 주는 방법

- 선택한 건물을 윤곽선과 밝은 색으로 강조한다. 렌더러 1개가 늘어난다.
- 기존 상세 창 자리에 "건물" 카드를 띄운다.

```
건물
사가정로49길 56            ← 도로명주소 (큰 글씨)
까치공원경로당              ← 건물 이름 (있을 때)
02221 · 면목동
[자세히]                   ← 2차: 지번, 주용도, 층수, 사용승인 연도
출처 OpenStreetMap · 2026-11-10 기준
```

- 카드를 닫아도 고른 기사는 유지한다(1단계에서 고친 기준).
- 예시 채움 건물은 누르면 "예시 건물 · 주소 자료 없음"만 보인다. 2차에서 실제 건물로 바꾼다.

### B5. 정보량 (r141)

건물 정보는 눌렀을 때만 나온다. 첫 화면의 정보량은 늘지 않는다. 처음에는 주소만 보이고 "자세히"를 눌러야 대장 정보가 나온다.

### B6. 실행 중에는 인터넷을 쓰지 않는다

주소는 수집 → 정리 → 팩 굽기 때 넣는다. 게임은 팩만 읽는다(r123 오프라인 우선). API 키는 수집 도구에만 있고 게임에 들어가지 않는다.

### 자료 단계

| 단계 | 자료 | 얻는 것 | 상태 |
| --- | --- | --- | --- |
| 1차 | OSM 스냅샷 | 실제 외곽 1,058동의 도로명주소·우편번호·이름 | 지금 가능 |
| 2차 | GIS건물통합정보 | 모든 건물의 실제 외곽과 대장 속성. 예시 채움을 실제 건물로 교체, 높이도 실제 층수로 | 수집·조건 확인 필요 |
| 2차 | 건축HUB 건축물대장 표제부 | 도로명주소, 건물 이름, 주용도, 층수, 사용승인일 | 수집 때만 API 호출 |
| 후보 | 도로명주소 전자지도 | 도로명주소가 붙은 건물 도형 | 이용 조건 미확인 |

보여 주지 않는 것: 소유자, 가격, 위반 여부. 카드에 "공공자료 기준일"을 적고 실제와 다를 수 있음을 알린다.

### 후속 연결

- 매장과 배송지를 건물 ID에 묶는다. "매장 A가 있는 건물"을 누르면 매장 카드로 이어진다.
- r142 시범 영업의 위치 고르기를 건물 누르기로 한다.

## 5. 단계와 관문

기존 계획의 2단계를 셋으로 나눈다. 2A는 새 자료 없이 바로 할 수 있다.

| 단계 | 할 일 | 관문 |
| --- | --- | --- |
| **2A-1 축소·전환** | A1(1차), A2, A3 | 한계 배율에서 자료 범위 전체가 화면 안에 들어온다. 알림 없이 구 지도로 넘어가지 않는다. 휠을 올리면 취소된다. 구 지도에 있는 동안 배달이 진행된다. 돌아오면 동 전체가 보인다. 두 주문 정산이 그대로다 |
| **2A-2 건물 선택 1차** | B1~B5, OSM 주소 | 표본 20동을 눌러 나온 주소가 OSM 원본과 같다. 높은 건물 옥상을 누르면 그 건물이 선택된다. 표식 누르기와 끌기가 그대로 동작한다. 렌더러는 1개만 늘어난다 |
| **2B 법정동 팩 편입** | 경계 기준 한계 배율, 색인을 팩에 넣기, A4, 횡단보도·신호등(기존 2단계) | 기존 2단계 관문. 같은 입력이면 같은 팩 |
| **2C 공공 건물 자료** | 수집·정리, 채움 건물 교체, 대장 정보 표시 | 표본 30동의 주소·층수가 원본과 같다. 이용 조건과 출처 표기가 `provenance.json`에 있다 |

## 7. 사용자에게 묻는 것

1. 전환 방식: 알림이 뜬 뒤 계속 휠을 내리면 넘어가기(제안)로 할지, 버튼을 눌러야만 넘어가게 할지
2. 건물 카드의 범위: 주소만 보일지, 용도·층수·사용승인 연도까지 보일지
3. 2A를 바로 시작할지

## 8. 하지 않는 것

- Core 규칙은 바꾸지 않는다. 건물 정보는 표현과 자료 층에만 있다.
- 실행 중 공공 API를 부르지 않는다.
- 소유자·가격 같은 개인 재산 정보는 넣지 않는다.
