## 2. 확인한 사실

### 기존 모바일 소비 모듈 (`C:/Users/user/ssalddel/Assets/Ssalddel/MobileGame`)

- `IMobileGameSession`은 `RequestJsonAsync(json)`, `Changed`, `SnapshotJson` 세 가지다. 응답(`ok`, `message`, `state`, `roads`)은 2.5D 시제품이 엔진 exe에서 받는 `DispatchReply`와 같은 모양이다. 엔진 exe를 세션으로 바꾸는 일은 **연결부 교체**에 가깝다.
- 차이 세 가지:
  - **시계 소유**: 시제품은 Unity 쪽 시계가 `tick`을 보낸다. 세션은 스스로 시계를 돌리고 화면은 `set-speed`·`pause`·`resume`만 보낸다.
  - **캠페인 필드**: 시제품은 `state.campaign`(일차·방침·경계 시각)을 읽는다. 모바일 `MobileGameState`에는 이 필드가 없다. 세션이 Core 응답을 그대로 넘기는지, 모델에서 빠진 것뿐인지 확인해야 한다.
  - **의존성**: 세션은 `Newtonsoft.Json`과 Core UPM 패키지(`Ssalddel.Sagajeong.Core/UnityPackage`)가 필요하다. 시제품 프로젝트의 `Packages/manifest.json`에는 둘 다 없다.
- 저장은 세션이 맡는다(약 5초마다·일시정지·화면 이탈 때, 이전 정상본 보존). 무념 계산은 아직 시제품 Unity 쪽 임시 계산이다.

### 지도 자료

- OSM 스냅샷(2026-11-10, 사가정·면목 일대)에 횡단보도 노드 132개(표시 66, 무표시 6, 신호 5, 종류 미기재 55)와 신호등 노드 23개가 있다. 지금 2.5D 메시에는 넣지 않았다.
- 스냅샷의 행정 경계는 **행정동**(면목본동, 면목2동 등, admin_level 8)이다. **법정동 경계 도형은 없다.** 법정동 코드는 기존 수집 작업 `geography`(`korea-legal-dong-codes`)가 모으지만 코드표이고 도형이 아니다.
- 지금 게임 자료는 흩어져 있다: 도로 타일(`tiles/*.json`), 법정동 목록(`legal-dong.json`), 법정동별 바탕 그림(`legal-city-board/1126010100~400/`), 2.5D 메시(`hongdal-diorama.bytes` 한 덩어리), 모바일의 `road-graph.json`.

## 3. 법정동 팩 구조 (제안)

자료를 네 층으로 나눈다. 아래 층은 위 층을 모른다.

```
① 원본 (수집)        코드표, OSM 스냅샷, 경계 도형 원본 ─ 기존 수집 정책(출처·SHA·기준시각)
        ↓ 정리 스크립트
② 법정동별 정리 파일  dong-source/<법정동코드>/ ─ 순수 자료, 표현값 없음
        ↓ 팩 굽기 스크립트 (같은 입력 → 같은 결과)
③ 법정동 팩          dong-pack/<법정동코드>/ ─ 게임이 바로 읽는 형태
        ↓ 팩 로더
④ 게임               현재 동 + 이웃 동만 읽고, 무엇을 얼마나 보일지는 r141 규칙이 정한다
```

### ② 법정동별 정리 파일 (예: `dong-source/1126010100/`)

| 파일 | 내용 |
| --- | --- |
| `boundary.geojson` | 법정동 경계 |
| `roads.geojson` | 도로 중심선, 등급, 이름, 일방통행 |
| `buildings.geojson` | 건물 외곽, 높이와 높이 출처(자료·층수·기본값) |
| `crossings.geojson` | 횡단보도 위치와 종류(표시·무표시·신호) |
| `signals.geojson` | 신호등 위치 |
| `places.geojson` | 역·역 출구·버스 정류장·공원·학교 터 |
| `provenance.json` | 원본별 출처, 이용 조건, SHA-256, 기준시각 |

경계 가장자리의 도로와 건물은 양쪽 동이 중복으로 갖지 않도록 "중심점이 속한 동"에 둔다. 이웃 동 목록을 함께 적는다.

### ③ 법정동 팩 (예: `dong-pack/1126010100/`)

| 파일 | 내용 |
| --- | --- |
| `manifest.json` | 코드, 이름, 경계 상자, 좌표 원점, 팩 판본, 입력 SHA, 개수, 이웃 동 |
| `road-graph.json` | 길찾기용 도로 연결 |
| `ground.bytes` | 지면·녹지·도로 메시(대로·이면도로·골목 폭) |
| `buildings.bytes` | 실제 외곽 건물 메시 |
| `fill.bytes` | 예시 채움 건물(선택). 실제 건물과 분리 |
| `markings.bytes` | 횡단보도 줄무늬, 대로 중앙선 |
| `props.json` | 신호등·역 출구·정류장 배치(위치, 방향, 종류) |
| `labels.json` | 도로 이름, 역 이름 |

오늘 만든 `bake_diorama.py`를 쪼개 이 형태로 바꾼다. 굽는 방식(압출, 높이 압축, 채움 규칙)은 그대로 쓴다.

### 경로 정합 (가장 큰 위험)

기사의 이동 경로는 Core가 자기 도로 자료로 계산한다. 팩의 `road-graph.json`과 Core 도로 자료가 다르면 오토바이가 그려진 도로 밖으로 달린다. 1차 팩은 **Core가 쓰는 도로 자료에서 도로층을 만든다**. Core 쪽 도로 자료를 팩으로 바꾸는 일은 규칙 변경이므로 별도 범위다.

### 횡단보도·신호등 표현 (1차)

- 횡단보도: 노드 위치에서 도로 방향에 수직으로 줄무늬를 그린다. 종류를 모르는 55개도 표시하되 색을 약하게 한다.
- 신호등: 기둥과 신호등 머리를 작은 소품으로 세운다. 불빛은 고정 색이고 신호 주기 애니메이션은 넣지 않는다.
- 규칙 효과(신호 대기로 이동 시간 증가)는 넣지 않는다. 넣으려면 Core 경로 계산이 바뀌므로 기획 판단이 먼저다.
- r141의 점진 표현에 따라 첫 화면에서는 대로의 신호 교차로만 보이고, 확대하거나 관여한 매장 주변에서 나머지가 드러나게 한다.

## 4. 단계별 진행

한 단계씩 진행하고 관문을 통과하면 다음으로 간다. 각 단계 끝에 반환 문서를 남긴다.

| 단계 | 할 일 | 관문 |
| --- | --- | --- |
| **0. 결정** | 정식 Unity 프로젝트 위치, 허용 경로, 팩 파일을 저장소에 둘지 빌드 때 굽을지 | 사용자·Codex가 정함 |
| **1. Core·세션 연결** | 2.5D 시제품의 엔진 exe를 `MobileGameSession`으로 교체. 시계는 세션에 맡기고 기존 속도 버튼을 `set-speed`로 연결. 캠페인 필드 확인. 상세 창을 닫아도 배차 선택 유지(r141 확인 기준 3) | 같은 두 주문에서 사건 순서와 가상 정산(플랫폼 수입 9,600원, 기사 보수 7,200원, 보너스 1,200원, 보너스 포함 차액 3,600원)이 엔진 판과 같다. 다시 켜면 이어하기가 된다 |
| **2. 법정동 팩 1개** | 사가정역이 있는 면목동(1126010100) 하나로 ②·③을 만들고, 게임이 한 덩어리 메시 대신 팩을 읽게 한다. 횡단보도·신호등 포함 | 같은 입력이면 같은 팩(SHA 동일). 1단계 회귀가 그대로 통과. 오토바이가 그려진 도로 위로 달린다 |
| **3. 점진 표현** | r141대로 첫 화면은 도로·핀·오토바이만, 픽업한 매장만 낮은 입체, 거래 흔적 저장, UI 순차 소개 | r141 6절의 확인 기준 1~7 |
| **4. 이웃 동 확장** | 이웃 법정동 팩을 추가하고 경계를 넘어 이어 붙인다 | 경계에서 도로·건물이 끊기거나 겹치지 않는다. 성능 기준(렌더러 128, 재질 12) 안 |
| 후속 | r142 군중(회색 반투명 사람 형상), 신호의 규칙 효과, 실제 건물 높이 자료 | 각각 기획 판본과 준비 상태가 먼저 |

방식 B로 넘길 지점은 1단계 뒤다. 1단계가 끝나면 Codex가 2·4단계의 반복 작업(동 추가, 팩 굽기)을 이어받기 좋다.

## 5. 역할

| 일 | 담당 |
| --- | --- |
| 1절 결정을 r141·r142와 새 판본(법정동 팩, 횡단보도·신호등)에 반영 | Codex |
| 법정동 경계 도형 원본 수집과 이용 조건 확인 (`geography` 작업에 추가) | Codex (수집 담당 유지) |
| 1단계 구현과 검증 | Claude |
| 정리·팩 굽기 스크립트, 팩 로더, 횡단보도·신호등 표현 | Claude가 뼈대, 반복 확장은 Codex 가능 |

법정동 경계 도형의 후보는 국토교통부 계열 법정구역 경계 자료나 통계청 SGIS 경계 자료다. 둘 다 이용 조건과 게임 배포 가능 여부를 아직 확인하지 않았다. 확인 전에는 OSM 행정동 경계나 도로로 둘러싼 임시 구역을 쓰고, 팩 `provenance.json`에 임시라고 적는다.

## 6. 하지 않는 것

- Core 규칙 변경(무념 이관, 신호 대기, 도로 자료 교체)은 이 계획에 넣지 않았다.
- 모바일 모듈 원본(`C:/Users/user/ssalddel/...`)은 고치지 않는다. 필요한 파일은 Windows 소비판 쪽에서 참조하거나 복사한다.
- 실제 창업·매출·실시간 인구처럼 보이게 하지 않는다.
