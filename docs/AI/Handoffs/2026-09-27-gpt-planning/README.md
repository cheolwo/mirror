기준일: 2026-09-27 KST / 판본: 1 / 용도: 기획 대화용 상태 사본

## 가장 간단한 사용법

1. GPT 채팅에 [01-프로젝트-기획인계.md](01-프로젝트-기획인계.md)를 첨부한다. 프로젝트 목적, 앱·서버·Unity·공공데이터 진행 상황과 남은 문제, 개발 인계 양식이 들어 있다.
2. 지금 논의할 역할별 정보 정리에는 [02-역할별-정보대장-초안.md](02-역할별-정보대장-초안.md)도 첨부한다.
3. 화면까지 논의하려면 ZIP을 풀어 `menu-list.png`, `menu-editor.png`를 추가로 첨부한다. ZIP 자체의 분석 가능 여부에 의존하지 않고 필요한 파일을 직접 첨부하는 방식이다.
4. 첫 문서 12절의 시작 요청문을 붙여 기획 문답을 시작한다. 결론이 모이면 13절 양식으로 Codex Work에 전달한다.

두 Markdown은 다른 저장소 파일 없이 읽을 수 있다. 본문 코드 경로는 후속 개발자가 다시 조사할 위치이며 GPT가 그 파일을 읽었다는 뜻은 아니다.

## 정보와 승인 경계

- 전체 채팅·소스 코드·DB 덤프를 내보내지 않는다. 계정 비밀값·연락처·정밀 배송 주소·개인 영상 원본은 제외한다.
- 이 사본은 현재 로컬 미커밋 변경을 포함한 설명이다. 기재한 HEAD만으로 최신 코드가 전달되지는 않는다.
- 코드 존재, 이전 자동 시험, 실제 UI, DB/API 실행, 실운영·출시를 분리한다. 이전 시험을 이번 작업에서 다시 실행한 것으로 읽지 않는다.
- 정보대장의 권한·화면 제안은 초안이다. 미답변 정책을 승인한 것으로 해석하거나 새 개발을 자동 실행하지 않는다.
- 다른 계정·기기의 개발 인계에는 확정된 PLAN 판본·hash·정확한 commit과 허용 경로를 다시 맞춘다. 이번 파일화에는 commit·push·배포를 포함하지 않는다.

## 자료의 수명

이 묶음은 날짜가 붙은 기획용 요약이며 canonical 기획 문서를 대체하지 않는다. 후속 개발 시 저장소의 `GptProjectContext.md`, `PLANNING.md`, `CURRENT_WORK.md`, 해당 PLAN과 실제 코드를 다시 확인한다. 이후 상태가 바뀌면 새 기준일/판본의 인계로 교체한다.
