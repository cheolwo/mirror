# 사가정 URP S1 격리 시험 반환

2026-11-24 KST · Windows 격리 렌더링 비교 완료 · 제품 적용 검토 대기

사가정역 주변의 같은 지도와 카페 1호점 선택 장면을 Windows 실행판 세 개에서 비교했다. URP 17.5.0으로 화면이 실제 그려졌다. URP를 Gamma로 설정했을 때 낮·노을·밤의 골목과 건물 밝기가 내장 렌더링 기준판에 가까워졌다. Claude가 현실감 시안을 검토할 때는 이 화면을 현재 스타일의 대조 기준으로 쓸 수 있다.

## 같은 조건에서 비교한 것

- Unity 6000.5.6f1, Direct3D 11, 1600×900, 정사영 카메라를 공통으로 사용했다. 공개 배포가 보류된 내부 검토용 `jungnang-ring26-official-r1`이 세 실행판 모두 26동과 건물 53,857채를 로드했다. 주 비교는 운영 1일차 11시 40분, 사가정역 반경 600m, 카페 1호점 선택 화면이다.
- 양쪽에 복사한 자산 488개를 대조했다. 이 목록에서 빌드 코드 한 파일의 차이는 시험판 저장 이름을 분리하는 설정이다. URP 렌더러 설정과 진단 코드는 시험 사본에 두었다. 복사 뒤 원 Windows 작업본의 셰이더와 화면 코드 6개가 바뀌었다. 이번 비교의 원본은 격리 사본이다. 로컬 공용 패키지들은 같은 작업본을 참조했다.
- URP의 추가 렌더러 효과를 끄고 기존 셰이더를 사용했다. 실행에서 바탕, 그림자, 나무, 계절 입자, 강수 셰이더 다섯 개의 존재와 지원 여부를 확인했다. 캡처에서 건물·골목·역·카페 선택의 지도 표현을 대조했다.

| 시험판 | 실제 Windows 파이프라인 | 빌드 | 커널 기본 검사 |
| --- | --- | --- | --- |
| 기준판 | 내장 렌더링 · Gamma | 성공 · 오류 0 · 경고 786 | 56/56 |
| URP 기본 비교 | URP · Linear | 성공 · 오류 0 · 경고 786 | 56/56 |

Gamma 빌드에는 이전 URP 시험의 가져오기 결과가 재사용됐다. 빌드 경고 수는 해당 회차 기록이다.

## 사가정 화면의 밝기 비교

선택한 카페 오른쪽의 골목·건물 영역에서 내장 렌더링 기준판 대비 RGB 평균 절대 편차를 0~255 값으로 계산했다. HUD를 제외한 비교이며 움직이는 잎이나 빛의 미세한 시각 차이가 포함된다. 차이가 작을수록 해당 영역의 화면이 기준판에 가깝다.

| 동일 장면 | URP Linear | URP Gamma |
| --- | ---: | ---: |
| 낮 · 카페 1호점 선택 | 65.53 | 1.50 |
| 노을 · 동 지도 | 69.55 | 0.76 |
| 밤 · 동 지도 | 69.85 | 0.62 |
| 겨울 밤 · 동 지도 | 63.32 | 2.02 |

화면의 차이가 색공간을 맞추자 크게 줄었다. Gamma를 현 스타일과 비교하는 재현용 기준으로 남긴다. 최종 색공간과 소재·조명의 채택은 사가정 실제 화면에서 다시 판단한다.

## 자동 검사와 남은 검증

화면을 숨긴 초기 실행에서 검은 캡처가 나왔다. 표시 상태의 Windows 시험창에서 다시 찍어 낮·노을·밤·겨울 밤의 화면을 확보했다. 첫 전체 자동 촬영에서는 격리 폴더에 시험용 WAV·MP3가 빠져 음악 항목이 실패했다. 원래 시험 음원 두 개를 격리 증거 폴더에 복사하고 SHA-256을 대조한 뒤 **세 시험판 모두 전체 자동 검사에 통과했다**. 회차별 `view-proof.json`의 `passed`는 모두 `true`이다.

자동 촬영은 타일에서 동을 열고, 카페 창을 닫고, 역과 구로 돌아오는 시험 경로를 확인했다. 일반 진입에서 사람이 직접 조작한 결과와 기준 PC의 비교 성능은 검증 대기다. 전국 굽기가 가동 중이어서 이 PC의 프레임 시간을 성능 기준으로 채택하지 않았다. 기존 Unity 프로젝트·Windows 작업본·전국 바탕 굽기에는 이번 시험의 변경을 적용하지 않았다.

## 증거와 다음 작업

증거 루트는 `artifacts/local/hongdal-sagajeong-urp-s1-20261124/`다.

- `evidence/input-check.json`에 지도·건물 색인·자산 비교 해시가 있다. `evidence/comparison-summary.json`에 시험 실행 파일, 네 장면의 PNG 지문, 렌더 유형·색공간·명암 비교, 재검사 결과와 지문이 있다.
- 낮의 기준 화면 파일명은 `62-close-mid.png`다. `evidence/builtin-gameview/`, `evidence/urp-gameview/`, `evidence/urp-gamma-gameview/`에서 같은 이름을 연다. 노을은 `v-dong-09-dusk-mid.png`, 밤은 `v-dong-08-near-night.png`다. 촬영은 내부 검토 범위로 사용한다.
- 화면 결과는 격리된 장면의 표현 확인이다. 기존 디오라마 규칙 `diorama-rule:game-view-is-presentation-evidence-only.v1`과 `diorama-rule:source-simulation-presentation-separated.v1`을 지지한다. 지도 판본·카메라·조명 또는 캡처 조건이 달라지면 비교를 다시 한다. **새 디오라마 규칙 후보 없음.** E 승격은 대기 상태다. [증거 진화 기준](../../Architecture/역세권디오라마증거진화체계.md)

### Claude가 이어 볼 순서

1. 같은 낮·노을·밤 장면의 기준 캡처를 연다. 현재의 골목과 건물 경계, 선택한 장소 표식을 화면 판독 기준으로 삼는다.
2. 사가정에서 건물 밑의 접지 그늘과 옥상·벽 재질 중 하나씩 바꾸고 같은 카메라로 찍는다. 밤에도 길과 선택 표식이 읽히는지 확인한다. 최종 렌더 색공간은 이 비교와 실제 구↔동 조작·성능 확인 후 고른다.
3. 사가정 기준 화면이 승인되면 완료된 동 모듈 몇 곳에서 덧굽기를 비교한다. 주거·아파트·상업처럼 건물 분포가 다른 동의 화면과 사용한 자료 판본을 함께 반환한다. [후속 단계 S2~S4](../Planning/시스템/PLAN-SYSTEM-STATION-AREA-DIORAMA-MODULES/sagajeong-urp-dong-detail.plan.r1.md#s2--사가정에서-자동으로-옮길-표현을-고른다)

`공표 자료` · `연출` · `자료 없음`은 r2의 자료 의미로 채택했다. 실제 레이어 범례 UI는 해당 표시 작업에서 확인한다.
