## 3. 잇는 걸음(제안) — 누가 고칠 수 있는가

Claude의 작업 범위는 `WindowsGame\` 안이다. 그 안의 `Kernel/`은 읽기만 한다(작업 규칙). 그래서 빈 연결 가운데 셋은 Kernel을 열거나 새 업무 계약(D7)을 정해야 Claude가 손댈 수 있다.

| 걸음 | 내용 | 고칠 곳 | Claude 혼자 가능? |
| --- | --- | --- | --- |
| 카1 | 첫날 끝내기: 한 실행판에서 직접 · 맡김으로 첫날 → 결산 → 다음 날. 맡김 뒤 위험 줄 정리 · 회차 진행 저장 | Runtime(화면 · 회차 · 신호) | 예 |
| 카2 | 제조 5분: 「제조 시작」 → 5분 → 「준비 완료」, 대기열 · 제조 자리 | `Kernel/StoreOperationsModule` | 아니오 — Kernel |
| 카3 | 픽업: 같은 제조 ID의 준비 완료를 배달 주문 하나에 한 번 연결 | `Kernel/FoodDeliveryModule` | 아니오 — Kernel |
| 카4 | 하루 결산: 완료 배달 한 건의 금액을 같은 ID로 오늘 결산에 한 번만, 카페 매출 · 본부 대금과 한 장에 | Runtime `SagajeongDispatchDailyReport.cs` + 금액을 내주는 쪽(Kernel 또는 Core 상태) | 화면은 예, 금액 출처는 확인 필요 |
| 카5 | 명덕 → 빛 크기: 완료 한 건의 사람 · 점포 · 동에 명덕을 귀속하고 빛 크기에 반영 | 귀속은 Kernel, 빛 크기는 Runtime | 반쯤 |
| 카6 | 직원 한 명: 배치 · 실습 · 책임(r227), 매장 창 「인력」 탭 | 명부는 Kernel, 탭은 Runtime | 반쯤 |

- 권함: 카1부터. Runtime 안에서 끝나고, 나머지 걸음을 확인할 무대가 된다.
- 카2 · 카3 전에 정할 것: Kernel의 이 두 모듈을 Claude가 고쳐도 되는지, 아니면 Codex가 계약(D7)을 먼저 쓰는지.
