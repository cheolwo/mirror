# 면목제3·8동 낮 디오라마 미술 제작 준비

이 준비안을 기준으로 ③을 선택한 뒤 진행한 첫 시험은 [실행판·실제 전후 화면·성능 기록](2026-11-15-Codex-면목38동-카페-재질시험.md)에서 볼 수 있다.

2026-11-15 기준. r228의 반실사 건축 모형을 실제 지도에 적용할 때 쓸 자료·외장·검증 순서다. 첫 시험은 면목제3·8동의 가상 운영 카페 한 곳과 그 앞길이다. 제작자가 맞출 대상은 낮의 색, 거리에서 가게를 알아보는 방법, 기사 빛이 지나는 길이다. 시안의 도로와 점포 주소는 생성 이미지에서 가져오지 않는다. ## 지도와 가게를 먼저 고정한다

| 입력 | 제작 시 쓰는 방법 |
| --- | --- |
| 행정동 경계·건물 외곽·도로·건물 선택 색인 | 공통 생성기로 구운 HDIO와 선택 색인을 한 쌍으로 사용한다. 동 코드, 건물의 `sourceFeatureId`, 두 파일의 지문, 높이의 출처를 첫 화면과 함께 기록한다. 외장 위치는 같은 동 원점·미터 단위와 게임에서 실제 표시한 건물 높이에 맞춘다. [공통 생성 절차](../../Architecture/행정동디오라마공통생성절차.md) |
| 가상 카페의 운영 관계 | 기존 Unity 작업본의 `place:cafe-1`은 `osm:way/1256615232`를 가리킨다. r4의 두 건물 대응은 매장 A·B이며 카페 1호점 대응은 없다. 기존 카페 연결을 자료로 확인할 수 있으면 그 건물을 사용한다. 첫 미술 시험에 가상 카페를 따로 두면 대상 건물과 정면을 명시하고 검토용 상태로 표시한다. 음식점의 동일 필지 후보는 소유나 입구를 입증하지 않는다. [r4 실행 근거](2026-11-15-Codex-기사빛-행정동-디오라마-r4.md) |
| 정면·창·가로수 | 현재 자료만으로 점포 정면, 입구 방향, 유리·벽 재질, 각 나무의 자리와 수종을 확정하기 어렵다. 첫 장면은 길을 향한 정면을 미술 설정으로 정한다. 특정 점포를 재현할 때만 사용 가능한 정면·사선 사진과 정면 폭 하나를 받는다. 공원 계획면과 확인된 식재 위치는 따로 취급한다. |
| 배차와 소유 표시 | 소유한 점포만 운영 상태에 따라 채색한다. 기사와 선은 기존 기사 ID·업무 상태·경로에 연결한다. 현재 r4의 픽업 선은 금색이며, 시안의 민트 선은 r212 제안의 예시다. 기사 위치·배달 완료를 장식에서 만들어 내지 않는다. |

## Unity에 연결할 자리

1. **동 지도.** `eng/neighborhood/prepare_dong_dioramas.py`와 `bake_dong_unity_modules.py`가 만든 바탕을 재사용한다. r4의 `SagajeongDispatchDongModules.cs`는 건물 전체를 동별로 합친 메시로 그린다. 모든 건물을 개별 프리팹으로 복제하지 않고, 정면이 정해진 점포에만 작은 외장 그룹을 같은 동의 `module.Part` 자식으로 둔다. 지면 이동·동 분리·숨김을 상속하고, 별도 재질에도 동 밝기·근접 가시성을 전달한다.
2. **바탕과 외장.** r4의 `HongdalDiorama.shader`는 정점색과 창·벽 구분 값을 읽는다. 기존 메시에는 물리 기반 재질에 필요한 노멀과 접선이 준비돼 있지 않다. 바탕의 낮 색과 그림자부터 맞추고, Blender에서 만든 정면 외장에만 노멀·UV·재질을 내보낸다. 벽면과 장식의 깊이를 겹치거나 기존 지면 그림자 위에 진한 그림자를 이중으로 그리지 않는다. r4 검토판은 Built-in·Gamma이며, 일반 Unity 작업본에는 URP를 쓰는 품질 설정도 있다. 실제 적용 대상의 파이프라인과 품질 설정을 기록하고 그 환경에서 창 반사를 확인한다.
3. **거리와 선택.** `SagajeongDispatchCloseView.cs`에서 이미 계산하는 근접 정도를 공유한다. 가까이에서는 차양 테두리·창틀·따뜻한 창 안쪽을 읽고, 멀어지면 정면 세부를 감추고 지붕 표식을 남긴다. 동 경계의 민트는 선택한 동안에만 강조하는 안으로 비교한다. `SagajeongDispatchBuildings.cs`의 건물 외곽 선택을 유지하고 외장 소품의 충돌체는 선택 입력에서 제외한다. `SagajeongDispatchRoam.cs`의 기사는 민트·연보라 중심점으로 읽혀야 한다.

## 첫 비교와 다른 동으로의 확대

같은 면목제3·8동 건물과 도로를 놓고 기존·시험 미술 각각 **동 전체 한 장, 가로 300m 한 장**을 실제 Windows 실행판에서 캡처한다. 화면 크기·낮 시각·카메라 중심·업무 상태를 고정하고 평소 HUD도 켠다. 동 공통 300m 표본의 중심은 비교용 좌표이므로, 카페 근경의 중심으로 사용할 때는 대상 건물 위치를 별도로 기록한다.

- 처음 보는 사람이 화면에서 내 가게를 가리키고 기사 빛과 경로를 따라갈 수 있는지 본다. 효과를 줄이거나 지도를 축소한 뒤에도 같은 점포를 눌러 동일한 건물 ID가 나와야 한다.
- 같은 PC·품질·카메라에서 장식을 켜고 끄며 프레임 시간과 드로 콜을 비교한다. 측정할 수 없는 GPU 시간은 미측정으로 둔다. 줌 경계에서 창이 깜박이거나 선택 영역이 어긋나면 거리 전환과 정면 결속부터 고친다.
- 통과하면 같은 낮 재질을 화양동의 건물과 길에 적용해 밀도 차이를 확인한다. 각 동에는 원래의 도로·건물, 검증된 운영 관계와 필요한 지역별 외장만 넣는다. 외장이 없는 건물은 기본 회색 건물로 표시한다.

이번 단계의 산출물은 시안과 제작 준비다. 새 외장 모델 제작, 재질 적용 후의 실제 Windows 화면, 성능 수치는 후속 시험에서 얻는다.
