## Claude 연결 순서

1. **전국 지도는 시군구·행정 읍면동 코드부터 읽는다.** 공식 SQLite의 `district_map`과 `dong_map`을 사용한다. 지도에서 축소할 때 전국 경계와 구별 집계를 먼저 읽고, 사용자가 상세히 보는 지역의 도형·주소를 이어서 읽도록 구성한다. 행정 읍면동 `TL_SCCO_GEMD`와 법정 읍면동 `TL_SCCO_EMD`의 코드 공간을 구분한다. [공식 지도와 조회 방법](2026-11-19-Codex-전국경계와인구세대-지도인계.md)
2. **주소와 목적지 좌표는 기존 내비 7z를 시도별로 사용한다.** `match_build_*.txt`를 건물관리번호로 읽고 `match_jibun_*.txt`를 관련 지번으로 연결한다. 동봉 명세에서 건물 중심과 출입구는 GRS80 UTM-K다. 보조출입구 공용 파일은 명세상의 제공 대상이 정해져 있어 같은 좌표를 모든 건물에 채우지 않는다. 전체 TXT 해제 크기는 약 **4.06 GB**다. 필요한 지역을 선택해 읽으면 원본과 전체 해제 사본을 함께 상시 보관할 필요가 없다.
3. **전자지도는 상세 지도에 들어가는 지역부터 채운다.** 국내 전국 승인 목록에서 필요한 시도 ZIP을 받고, 시도코드와 ZIP 내부의 레이어를 검사한다. 경기도 원본과 내비 건물관리번호의 대조를 마쳤고, 구리시 도형을 먼저 연결할 수 있게 준비했다. 기존 Unity의 전자지도 연결 도구는 서울 경로가 고정돼 있어 지역코드에 따른 파일 선택은 구현 단계에서 다룬다. [경기 자료 인계](2026-11-19-Codex-경기전자지도와내비-자료인계.md) · [기존 서울 지도 자료 인계](2026-11-19-Codex-홍달지도공공API실수집-인계.md)
4. **배달 도착점과 도로 경로를 이어서 검증한다.** 내비의 25자리 건물관리번호와 별도 출입구의 주소 식별자를 각각 보관한다. 도로명코드·지하여부·본번·부번이 맞는 경우에도 하나의 주소를 여러 건물이 공유할 수 있다. 건물 중심·주소 출입구·확인된 점포 문을 구분한다. 출입구를 길에 연결할 때 일방통행·회전·차량 제한은 교통 도로망에서 읽는다.
