## 1. 지킬 원칙 (Codex 수집 원칙을 화면 규칙으로)

1. **값마다 출처 · 기준일 · 단위를 붙인다.** 화면의 숫자 옆이나 창 맨 아래 한 줄. 서로 다른 자료를 더해 새 숫자를 만들지 않는다(예: 승하차 태그 건수와 생활인구 지수는 단위가 다르다 → 나란히 보이되 합치지 않는다).
2. **0과 "없음"을 구분한다.** 관측이 없는 칸은 빗금 · 「자료 없음」, 0은 0. 추정값은 「추정」.
3. **참고점은 물체가 아니다.** 시설 점은 "그 근처에 이런 시설이 있다고 보고됨"이다. 2.0에서 소품을 세울 때도 "참고점 기준 배치"라고 남기고, 출입구 · 실제 위치로 단정하지 않는다.
4. **1.0에는 공개 배포가 확인된 자료만.** 팩마다 `release: public | internal`을 적고, 기본 판 빌드(`auto-build-base.cmd`)는 `internal` 팩을 뺀다. 확인 전은 `internal`.
5. **보이기 먼저, 규칙은 나중.** 이 계획의 자료는 처음엔 화면에 보이기만 한다. 주문 발생 · 배차 시간 같은 게임 규칙에 잇는 일은 각 단계 끝에 「규칙 연결 후보」로만 적고, 종합 계획의 A0~A1(진짜 주문 한 바퀴) 뒤에 따로 한다.

## 3. 단계

각 단계 = 한 장면. 끝의 기준은 실제 빌드 촬영(view-proof / base-proof)으로 본다.

### D0 · 자료 팩 틀 (바탕, 소)

- **무엇:** Codex SQLite → 게임이 읽는 작은 JSON 팩으로 굽는 도구 하나, 게임 쪽 읽기 하나.
- **팩 꼴(가안):** `Resources/hongdal-data-<주제>.json` · `{schema:"hongdal-data.v1", topic, source, sourceUrl, observed, unit, release, licence, rows:[…]}`. `rows`는 화면에 필요한 만큼만(예: 역 × 시간 × 방향).
- **굽는 도구:** `artifacts/local/hongdal-data-packs-2026112x/bake_packs.py` — Codex의 `디오라마-자료목록.sqlite`에서 묶음 DB 경로를 찾아 읽고, 원천 SHA-256을 팩에 남긴다.
- **게임:** `Runtime/SagajeongDispatchDataPacks.cs`(새) — 팩 읽기 · 없으면 「자료 준비 전」 · 출처 줄 그리기 함수 하나(`DrawSourceLine`).
- **1.0 경계:** `auto-build-base.cmd`의 제외 목록에 `hongdal-data-*-internal.json`을 더한다.
- **끝의 기준:** 팩 하나(D1의 승하차)가 1.0 · 2.0 둘 다에서 읽히고, internal 팩이 base 빌드에 들어가지 않음을 base-proof가 확인한다.

### D1 · 역의 하루 (구 지도 1.0, 중)

- **장면:** 사가정역을 누르면 역 창에 **시간대 막대 24칸**(승차 · 하차 두 색). 게임 시계의 지금 시각 칸이 밝다. 지도에서는 역 불빛이 그 시각의 승하차만큼 크게 숨 쉰다.
- **자료:** r60(서울 전 역 · 시간대 · 방향, 3개월) → `hongdal-data-station-hours.json`. 딸린 동의 생활인구 지수(r80)는 내부 팩으로 2.0에서만 같은 창에 한 줄 더.
- **화면 문구 예:** 「사가정역 · 2026년 10월 · 08시대 승차 70,773건(월 누적) · 교통카드」.
- **파일:** `SagajeongDispatchStationCard.cs`(막대 줄), `SagajeongDispatchSubwayGu.cs`(역 불빛 크기).
- **끝의 기준:** 116a · base-15 촬영에서 막대가 뜨고, 08시 · 18시 장면 두 장에서 역 불빛 크기가 다르다.
- **규칙 연결 후보(나중):** 주문 발생 시간대 가중(`DongDemandModule`) — A1 뒤.

### D2 · 밤과 날씨 (구 지도 1.0, 중)

- **장면:** 게임 날짜의 실제 점등 시각이 되면 구 지도가 저녁빛으로 넘어가고 거리 불빛이 하나씩 켜진다. 비 온 날은 옅은 빗줄기와 젖은 길 빛, 눈 온 날은 흰 결.
- **자료:** r92 가로등 점등 · 소등(날짜별) → `hongdal-data-lamp-times.json`. r61 일별 강우 → `hongdal-data-rain-days.json`. 관측 없는 날은 r11 평년값(「평년」 표지).
- **파일:** 셰이더 전역값(지금 `_HongdalTier`처럼 `_HongdalDusk` 하나), `SagajeongDispatchGu.cs`(밤 덮개), 결산 창 한 줄(「오늘 18:03 점등 · 비 4 mm」).
- **끝의 기준:** 같은 날의 17:50 · 18:10 촬영이 다르게 보이고, 비 온 날짜 하나 · 맑은 날짜 하나가 구분된다.
- **규칙 연결 후보:** 비 오는 날 배달 할증(배달 요금 r2의 시간대 · 추가 할증 칸).

### D3 · 길의 속도와 버스 (구 지도 1.0, 중)

- **장면:** 레이어 「길」을 켜면 큰길이 시간대 평균 속도로 칠해진다(느린 곳 진하게). 레이어 「버스」를 켜면 중랑을 지나는 47노선의 확인된 조각, 끊긴 곳은 점선.
- **자료:** r89(668 링크 · 시간대 속도) · r79(중심선) → `hongdal-data-road-speed.json`. r83 → `hongdal-data-bus-lines.json`.
- **파일:** `SagajeongDispatchSubwayGu.cs` 옆에 `SagajeongDispatchRoadLayer.cs`(새) · 지하철 보기 단추 줄에 「길」 「버스」 두 단추.
- **끝의 기준:** 08시와 14시 촬영에서 같은 길의 색이 다르다. 버스 레이어의 출처 줄에 「서울특별시 버스정보시스템」.
- **규칙 연결 후보:** 기사 빛 이동 속도 · 도착 예상 시각(`길안내Policy.cs`).

### D4 · 타일 그릇 채우기 (타일, 중)

- **장면:** 타일 그릇 창에 「생활 시설」 줄 — 정류장 n · 보행등 n · 공원 n · 시장 n · 학교 n · 도서관 n · 따릉이 n. 시설이 많은 칸은 성격 이름 옆에 작은 표지. 2.0에서는 생활인구 시간대 막대와 공동주택 단지 수가 더 붙는다.
- **자료:** r49 참고점 색인(24범주) → 타일 굽기(`hex-tiles` 도구 r2)에서 칸마다 범주별 개수. r80 격자(250 m)는 육각(300 m)과 크기가 달라 **면적 비례로 나눠 담고 「추정」 표지**.
- **파일:** `SagajeongDispatchHexTiles.cs`(그릇 창 줄), `Resources/hongdal-tiles-gu.json`(필드 추가 · 크기 확인).
- **끝의 기준:** base-18 촬영에서 사가정역 칸의 생활 시설 줄이 보이고, 값이 Codex 색인의 같은 범위 조회와 맞는다(검산 스크립트).

### D5 · 동의 거리 소품 (동 디오라마 2.0, 대)

## 5. 정할 것 — 하나씩

1. **(먼저) 1.0에 넣을 자료의 확인을 누가 하나.** 「1.0?」로 적은 묶음(승하차 · 가로등 · 강우 · 속도 · 시설)의 이용 조건을 Codex가 묶음별로 한 번 확인해 팩의 `release`를 정해 주면, D0~D3을 바로 1.0에 넣을 수 있다. 확인 전에는 internal로 두고 2.0 검증판에서만 본다.
2. 생활인구(서울특별시 · KT)를 1.0에서 쓸 것인가 — 서울시 이용 조건상 원본은 PC 보관, 배포는 별도 검토. 안 쓰면 1.0 역 창은 승하차만, 쓰면 「동네의 사람 밀도」 줄이 더해진다.
3. D2의 밤 전환을 실제 날짜로 할지, 게임 날짜를 실제 달력에 묶을지(가안: 게임 1일 = 실제 달력의 하루, 시작일 = 게임을 켠 날).

## r2 · 사용자 결정 (11-23 16:37)

- **사용자:** 「1.0, 2.0 지금은 구분하지 말고 그냥 될 수 있는 대로 다 표현을 해 줬으면 좋겠어 … 게임 하루가 실제 하루인 걸로, 실제 달력으로 묶는 게 편할 것 같아」
- **판 구분 없음(지금은).** 위 표의 「1.0?」 · 「2.0」 구분으로 막지 않는다. 확인된 자료는 되는 대로 다 화면에 싣는다. 팩의 `release` 칸은 나중 배포 검토를 위해 적어만 두고, 지금은 기본 판 빌드에서도 빼지 않는다(1절 4번과 D0의 제외 규칙은 보류).
- **게임 하루 = 실제 하루(실제 달력).** 운영 1일차 = 게임을 처음 켠 날의 실제 날짜, n일차 = 그날 + (n−1)일. 시각은 게임 시계를 그대로 쓴다. 그 날짜의 관측이 없으면 가장 가까운 해의 같은 날(「작년 같은 날」 표지), 그것도 없으면 「관측 없음」.
- 정할 것 1 · 2(1.0 이용 조건 · 생활인구 1.0 사용)는 출시 직전으로 미룬다. 3은 위로 닫음.
