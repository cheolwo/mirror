## 구현을 맡게 되면 확인할 첫 장면

1. 거리에서 가상 주민 한 명을 고른다. 상의 `Body`, 모자 `Head`, 가방 `Back`의 외관 슬롯에서 고르고 색과 표시 여부를 바꾼다. 데이터 없는 슬롯을 비워도 인물과 관찰을 유지한다.
2. 건물을 열어 이미 있는 공간의 탁자 `Surface` 또는 `Slot`에 탁상등을 놓고 진열 선반을 바꾼다. 실물 포장에 1L 또는 250ml라고 쓰여 있어도 폭·깊이·높이는 미확인이다. 배치 가능 여부는 등록한 **모형 치수**와 출입·통로·겹침 조건으로 판정한다.
3. 상품 데이터는 원천 식별자, 옵션, 관측일, 사용 상태를 보존한다. 실물 치수, 모형 크기, 사용자 색상을 분리한다. 광고·시뮬레이션 매출·실제 재고·장착 능력에는 영향을 주지 않는다. 판매처 사진과 외형의 사용이 허용되기 전에는 독립 모형과 자산 사용 조건이 확인된 표현을 쓴다.
4. 사용자 선택은 대상 고유 식별자, 슬롯 키, 모형 키, 사용자 색, 확인한 카탈로그 판본으로 저장한다. 같은 선택을 읽었을 때 현재 대상과 판본이 맞으면 그대로 복원한다. 맞지 않으면 해당 항목만 미배치로 남기고 이유를 보여 준다. 관찰 표시를 다시 켜면 선택은 그대로 열린다.
5. 시작 조건과 실제 소비 경로를 먼저 확인한다. 인물 외형은 [장착 슬롯](../../../Ssalddel.Simulation.Contracts/UnityPackage/Runtime/SimulationActorEquipmentContracts.cs)의 이름을 참고하되 게임 내 장비 부착을 호출하지 않는다. 내부 공간은 [실내 조립의 VisualKey·슬롯·판본 고정](../../Architecture/상품관측기반실내공간조립엔진.md)과 [상품 검수·제공](../../Architecture/게임현실상품자료운영기반.md)의 기존 경계를 대조한다. 사용자 화면에서 외부 판매처를 직접 호출하는 흐름은 추가하지 않는다.

검증은 같은 주민·건물에서 변경 전후, 데이터가 빠진 항목의 빈 위치, 광역 지도 복귀 후 선택 유지, 저장·재개 후 같은 판본으로 복원을 한 바퀴 돈다. 창 크기별 로컬 결과는 위 화면 검증만 해당한다. Unity 실제 입력·Renderer·시뮬레이션 상태·출시판 배포 적합성은 별도 확인이다.
