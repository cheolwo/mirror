2. **`05-drilldown-dispatch-path.png` — 하향 한 바퀴**

   - **주문 한 건 화면:** 주문(목) → 배정(토) → 픽업 · 전달(수)의 단계를 색 점으로 보인다. 결과는 같은 주문 ID로 붙고, 00의 배달·운송(수) 열 '지금'에 반영된다.

## 2. 화면 구조 — 00 아래의 트리

```text
00 경영 (동 | 구 | 전국)          맨윗줄 = 사업 경로 · 위치 줄은 따로
├─ 주문(목)        → 대기 주문 목록(08) · 주문자 화면/플레이스(10)
├─ 음식점(화)      → 내 매장(09: 09-1~09-5) · 제휴 매장(06) · 음식점 관찰(11)
├─ 배차(토)        → 1호지사(07) → 기사(11-1) → 주문 한 건 → 결과
│                    배차(08) · 모집·연구(r267 스티커 홍보)
├─ 창고(금)        → 검수·재료(09-2) · 센터·화물 관찰(11)
├─ 배달·운송(수)   → 진행 중 배달(11-1) · 운영 회차(13)
├─ 계획            → 12 다음 할 일
└─ 결과 모으기     → 13 회차 · 14 결산 · 15 본사 장부
지도(05→04→03/02)와 20 건물·장소는 옆길: 어디서 들어오든 같은 대상의 경로로 이어진다
```

- 한 화면이 여러 열에서 나올 수 있다(예: 11-1은 배차와 배달·운송 둘 다). 화면의 **기본 자리**는 r259 4절의 묶음을 따르고, 다른 열에서는 지름길로 연다.
- 오행 표기는 업무 대표 의미(r261)만 쓴다. 실제 한 번의 행위 분류나 프랜차이즈 관점(r37)은 바꾸지 않는다.

## 3. 구현 구조 — 새 원장 없이 '경로 + 조회'

| 부품 | 하는 일 | 재사용 |
| --- | --- | --- |
| `NavPath`(경로 스택) | 노드 = {화면 번호, 대상 종류, 대상 ID, 범위}. 위치 줄은 노드와 따로 계산한다. '위로'는 한 칸 위, '00으로'는 스택을 비운다. 돌아오면 이전 선택(같은 지사 · 기사 · 주문, 목록 위치)을 복원한다 | 기존 동 선택 `PickDong()`, 점포 → 동 복귀, 센터 ↔ 화물 → 검수 연결 |
| `Root00Panel` | 다섯 열 · 지금 한 줄 · 계획 영향 한 줄 · '아래로' 목록 · 계획/결과 칸 | 하단 메뉴의 07 · 15 · 06 · 08 · 14 열기 함수 |
| `RootRowQuery` | 열마다 '지금 한 줄'을 기존 상태에서 읽는다. 근거가 없으면 '모름'으로 표시한다 | 주문 대기 · 점포 상태 · 기사/배차 · 검수/재고 · 배달 진행 |
| `PlanImpactLine` | 12의 계획 항목 → 영향을 받는 열과 미리보기 문구. 수치는 기존 미리보기 그대로 쓴다 | `SagajeongDispatchNextTodo` · `BusinessPreview` |
| `BreadcrumbBar` | 화면 위 두 줄(사업 경로 / 위치). 경로 조각을 누르면 그 단계로 올라간다 | — |
| 하향 진입 | 각 화면에 '대상 ID로 열기'를 더한다. 07은 지사 ID, 11-1은 기사 ID, 주문 상세는 주문 ID로 연다 | 기존 창 · 휴대폰. **지사별 기사 · 주문 필터는 새로 결속해야 한다**(r259 1절) |

**지킬 것:**

- 고르기 · 열기 · 위로 · 00으로는 조회일 뿐이다. 계획 · 보상 · 실행을 만들지 않는다.
- 확정은 기존 턴 넘김으로만 한다(r251 · r225).
- 기사 소속 경로는 기사가 지금 있는 동이 바뀌어도 그대로다. 기사에게 동 이동을 지시하지 않는다(r267).
- 예상은 실적에 더하지 않는다.
- 대상이 사라졌거나 둘 이상이면 이유를 보이고 선택을 요구한다. 임의로 고르지 않는다.

| **T2 경로와 복귀** | `NavPath` + `BreadcrumbBar`. 두 줄 표시, '위로' · '00으로', 선택 복원 | 00→07→09→위로→위로에서 00이 같은 상태로 돌아온다(자동 입력 검사) |
| **T3 첫 하향 한 바퀴** | 00 → 배차(토) → 07 1호지사 → 기사 A(11-1) → 주문 한 건 → 결과 → 00. 지사별 기사 · 주문 필터를 결속한다 | 시안 05 장면을 자동 촬영. 같은 주문 ID가 결과와 00 배달·운송(수) 열에 반영 |
| **T4 계획 영향 줄** | `PlanImpactLine`: 12에 담은 계획이 해당 열의 노란 한 줄로 나타나고, 취소하면 사라진다 | 담기 · 취소 · 턴 넘김의 세 경우 |
| **T5 다른 열의 하향** | 음식점(화) → 09 매장 → 재료/검수 → 결과, 창고(금) → 검수 · 센터/화물 11 | 각 경로 위로/00 복귀 검사 |
| **T6 구 범위 탭** | 같은 다섯 열을 구 범위로 집계한다(내 사업, 동간 배달은 원 주문 한 번). '아래로'는 동 목록 → 동 00. 부족 비교 → 모집 · 연구(r267). 재배치는 하지 않는다 | 구 → 동 → 구 왕복. 중복 집계 0 |
| **T7 검증 묶음** | EditMode: 경로 복원 · 조회 불변 · 모름 표시 · 중복 0. 자동 촬영 00 · 하향 4단계 | 검증 JSON과 캡처 |

- **첫 묶음:** T1~T3. 00에서 주문 한 건까지 실제로 내려갔다 올라오는 것을 먼저 보인다.
