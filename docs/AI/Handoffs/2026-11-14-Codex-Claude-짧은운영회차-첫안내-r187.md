## 첫 구현 한 건

**기존 가상 배달의 한 대상 작업 → 안내받는 운영 회차 → 같은 세션의 다음 회차**를 구현/관찰한다. 기존에 준비된 업무를 이용하는 검토 표본이며 다섯 분야의 자유 출발을 바꾸지 않는다. 최소 두 회차를 서로 다른 대상 ID로 이어 기존 세계/원장을 유지하는지 확인한다.

상황 확인·관련 선택/운영 시작·실행/관찰·대상 결과/회차 마감·다음 준비가 읽히면 된다. 새 직무·전체 성장/연구·지도 단계·가상 날짜 넘김·회차 영속 저장을 함께 확장하지 않는다. 첫 안내에 모든 샘플 사업/필수 안건을 완료하는 관문을 넣지 않는다.

버튼명/안내 문구/강조 배치는 기존 화면 안에서 선택하고 실제 화면으로 반환한다. 사용자는 이 범위의 구현을 보고 조정하기로 했으므로 같은 기본 방향의 재승인을 요구하지 않는다. 전면 화면/새 공간 설계로 넓히는 경우는 기존 시안/전문 연구 절차와 분리한다.

## 상태·실패·회복의 최소 계약

- 회차가 대상으로 삼는 기존 작업 ID/Revision과 끝나는 조건을 수용 기록에 적는다. 실제 완료 판단은 기존 Core/Kernel 결과를 따른다. 전달 완료와 이를 포함하는 후속 Settled 상태를 구별해 읽되 둘 다 전달 결과를 만족할 수 있도록 실제 계약에 결속한다. Delivered 한 상태만 비교해 이미 정산된 주문을 미완료로 보지 않는다.
- 선택 없음·요청 처리 중·작업 진행 중에는 성공 마감을 허용하지 않고 이유와 선택/계속 수행/관찰로 돌아가는 경로를 보여 준다.
- 안내 접기·지도 이동·집중/이완 전환은 대상 작업을 복제/취소하지 않는다.
- 마감/다음 준비는 추가 Tick·날짜 전환·재고/지급·전체 초기화를 만들지 않는다. 작업 중의 정상 시간 진행은 기존 규칙을 따른다.
- 첫 정상 마감은 실제 완료된 한 건으로 검증한다. 확인된 실패/보류는 기존 상태와 회복 경로를 보이며 성공으로 간주하지 않는다. 복구 명령이 없다면 상태를 보존한 채 대상 선택으로 돌아가고 새 대상의 기존 가용/할당 조건을 확인한다.
- 다른 사업의 진행 업무는 보존한다. 회차 대상 밖의 장기 작업 때문에 모든 반복을 멈추거나 이를 자동 완료하지 않는다.
- 같은 마감의 중복 입력·완료 대상 재선택에서 기존 완료/보상을 다시 만들지 않는다. 다음 준비는 같은 세션의 새 대상으로 이어진다.
