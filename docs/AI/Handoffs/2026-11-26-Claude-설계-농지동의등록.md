# 설계 — 농지 주인 · 경작자 동의 등록(본인이 직접, 언제든 철회)

2026-11-26 · Claude 설계 · 내부 검토용

## 사용자의 말

> 사용자가 개인이 동의를 하면은 모을 수는 있게 좀 그렇게 해놨으면 좋겠는데, 동의를 거쳐서 모을 수는 있는 그런 절차나 마련을 해놨으면 좋겠어. (14:58)

## 원칙(예전 원장 설계에서 그대로)

| 원칙 | 근거 |
| --- | --- |
| 개인 원장이 원본이고, 본인만 고치고 철회한다 | `GroupPurchaseDemandProcessManager.md` 개별 원함 원장 |
| 동의 · 서명은 원본을 일반 응답에 내놓지 않고 Hash와 시각으로 남긴다 | `OrderRootLedger.md` 개별 주문자 서명 |
| 열람 · 정정 · 삭제 · 처리정지 요청을 받는다. 실제 실행 증거 없이 완료로 두지 않는다 | `CommerceIntermediaryPrivacy.md` |
| 화면 표시는 권한이 아니다 | D-030 · D-043 |
| 만 19세 이상 · 체크박스는 인증 증거가 아니다 | `CommerceIntermediaryPrivacy.md` |

추가 원칙:

- **본인만 등록한다.** 남의 땅이나 남의 이름은 등록할 수 없다. 공무원 · 대표 · 가족 대리 등록은 따로 정하기 전까지 막는다.
- **목적별로 따로 동의한다.** 한 번의 「전체 동의」로 묶지 않는다.

## 흐름

```
① 앱 로그인(Firebase Auth) → ② 「내 밭 등록」 → ③ 지도에서 필지 고르기(팜맵 · 지적 필지)
→ ④ 관계 고르기: 소유 · 경작 · 임차 · 위탁
→ ⑤ 동의 화면(목적별 따로) → ⑥ 증빙(선택 단계마다 다름) → ⑦ 확인 상태로 저장
→ 언제든: 공개 범위 바꾸기 · 철회 · 삭제 요청
```

### ⑤ 동의 화면 — 목적마다 한 장

개인정보보호법상 동의를 받을 때 알릴 네 가지(수집 · 이용 목적, 수집 항목, 보유 · 이용 기간, 거부할 권리와 거부 시 불이익)를 장마다 적는다. 변호사 검토 전 가안이다.

| 동의 | 무엇 | 필수/선택 | 거부하면 |
| --- | --- | --- | --- |
| A 밭 등록 | 필지 · 관계 · 계정 연결 | 필수(등록하려면) | 등록 안 됨, 지도는 그대로 볼 수 있음 |
| B 지도 표시 | 「등록 농가의 밭」 표시 | 선택 | 표시 없이 내 화면에만 |
| C 이름 공개 | 농가 이름(또는 농장 이름) 공개 | 선택 | 「등록 농가」로만 보임 |
| D 연락 받기 | 긴급 수확 제안 · 모임 연결 알림 | 선택 | 알림 없음 |
| E 제3자 제공 | 받는 곳 · 화물 기사에게 연락처 전달(거래가 열릴 때만, 건별) | 선택 · 건마다 | 홍달 안에서만 연결 |

- 동의마다 `문안 버전 · 동의 시각 · 화면 Hash`를 남긴다. 문안이 바뀌면 다시 묻는다.
- 철회는 동의만큼 쉬워야 한다. 같은 화면 · 한 번 누르기.

### ⑥ 증빙 — 단계별

| 단계 | 방법 | 지도 표시 |
| --- | --- | --- |
| 0 자기 신고 | 본인이 고르기만 함 | 「신고」(옅은 점선) |
| 1 농업인 확인 | 농업경영체 등록 확인(본인 동의 하에 조회 또는 확인서 사진) | 「농업인」 |
| 2 필지 확인 | 소유: 등기부 · 토지대장 사본. 임차: 농지대장 임대차 등재 · 계약서. 본인이 올림 | 「확인됨」 |

- 증빙 원본은 확인 뒤 Hash만 남기고 파기한다. 보존 기간은 가안 30일이다.
- 같은 필지에 「소유」가 둘 이상 겹치면 자동으로 고르지 않는다. 둘 다 「확인 대기」로 두고 운영자가 증빙을 본다.

## 저장 구조(가안)

```
farm_party          등록한 사람 · 농장 · 법인 · 기관
  party_id, kind(개인/법인/기관), display_name(공개 동의 C가 있을 때만),
  auth_uid(개인만, Firebase), verified_level(0/1/2), created_at

parcel_party_link   필지 ↔ 사람 관계
  pnu 또는 farmmap_parcel_id, party_id, relation(소유/경작/임차/위탁),
  source(공개자료/본인등록), period_from/to, status(신고/확인대기/확인됨/철회)

consent_record      동의 한 건 = 한 줄
  party_id, purpose(A~E), text_version, granted_at, revoked_at, screen_hash

evidence_receipt    증빙 영수증(원본 아님)
  party_id, link_id, kind, sha256, checked_by, checked_at, purge_at

privacy_request     열람 · 정정 · 삭제 · 처리정지
  party_id, kind, received_at, done_at, done_evidence
```

- 공개 자료(N1b)로 채우는 행은 `source=공개자료`이고 `kind=법인/기관`만 있다.
- 개인 행은 `source=본인등록`이고 A 동의가 있어야만 생긴다.
- 철회하면 `parcel_party_link.status=철회`, 화면에서 즉시 빠진다. 삭제 요청이면 법정 보존 대상이 아닌 개인 필드를 지우고 실행 증거를 남긴다.

## 화면에서

- 지도에는 동의 B가 있는 밭만 「등록 농가」로 보인다. 이름은 C가 있을 때만 보인다.
- 남의 화면에는 필지 단위 「누가 소유」가 없다. 면 단위 합계(개인 · 법인 · 국공유 · 등록 농가 수)만 보인다.
- 긴급 수확 제안은 등록 단계 1 이상만 낼 수 있다. 「배추 한 트럭」의 깃발이 여기서 선다.

## 아직 하지 않는 것

- 실제 수집은 Firebase 로그인(R5) 뒤다. 지금은 표 구조와 동의 문안 가안까지만 만든다.
- 처리방침 · 동의 문안은 출시 전에 변호사 검토를 받는다.

## 정할 것 하나

**지도에 「등록 농가」를 보이려면 증빙을 어디까지 요구할까요?**

가안: 단계 1(농업경영체 확인)부터 지도에 보이고, 단계 0(자기 신고)은 본인 화면에만 둔다. 남의 땅을 내 것처럼 표시하는 일을 막는다.
