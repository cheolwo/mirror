## 2. 직접 결과와 비교 조건

**직접 결과**는 같은 내장 렌더링 기준판과 URP 시험판을 한 PC에서 구별해 다시 빌드하고, 동일 장면의 지도 및 입력 회귀를 확인할 수 있는 증거 묶음이다. 화면 사용자는 사가정역에서 출구·길·건물과 운영 표식을 찾고, 동에서 선택을 시험한 뒤 기존 구 화면으로 돌아온다. 동에 도착하는 조건과 실제 클릭 동작은 일반 실행 기록에서 확인한다.

- 현재 소비판에 쓰인 건물·길의 판본과 기존 Simulation 상태를 양쪽의 공통 입력으로 고정한다. 파일 형식, 업무 방식, 현행 자료·입장 설정은 기존 의미로 읽는다. 동일한 경영 경과와 실제 입력에서 화면 비교 조작에 의한 추가 업무·정산·저장 쓰기는 없어야 한다.
- 먼저 추가 효과의 세기를 올리지 않은 URP 호환 상태를 본다. 주광·그늘과 Linear 색 차이, 선택 표식이 보이는 상태를 각각 남긴다. URP 프로젝트의 설정 값과 실행판의 실제 `GraphicsSettings.currentRenderPipeline` 유형을 별도로 기록한다.
- 바탕·기존 그림자·나무·날림·강수의 다섯 셰이더와 바람 include를 인벤토리로 확인한다. 빠진 셰이더·분홍 재질·색상 판독 실패가 있으면 해당 패스·씬·시간대를 차단으로 적는다. 회복에 필요한 최소 수정은 격리 사본에서 확인한다. 셰이더 효과 추가나 공용 설정 변환의 근거로 확대하지 않는다.
- 전국 바탕 굽기(P5), 동별 표현 덧굽기, 추가 지역 자료 반입, 절기 관찰 화면 자체의 구현, 운영·공개는 이번 결과의 범위 밖이다. 새 디오라마 규칙의 공통 적용과 E 승격도 이 인계로 수행하지 않는다.

## 3. 검증 단계 초안

각 행은 독립 근거를 남긴다. 시작 상태는 전부 **미실행**이다. E 대응은 이후 검증 준비용이며 WI·Goal 등록이나 승격으로 기록하지 않는다.

## 4. 중단과 반환

- 소유권과 고정 입력 결속, 두 복제 프로젝트의 실행 범위가 마련되면 승인된 S1 격리 시험을 시작한다. 소스·패키지가 불안정하거나 해당 PC에서 새 출력·실행이 불가능하면 그 지점을 중단 사유로 남긴다.
- 가장 이른 재개 지점은 입력 확인 실패는 사전 확인, 컴파일 실패는 해당 빌드, 실제 카드·표식·경로 오류는 해당 실행과 입력 검수다. 실패한 효과를 끈 시험 결과는 베이스 렌더링 결과로 남긴다. 공용 Unity와 기존 Windows 빌드에서 회복 조작을 하지 않는다.
- 반환 위치는 `evidence/`의 비교 요약과 실제 증거 목록이다. 양쪽 프로젝트·실행판의 경로 지문, 빌드·시험·실행·입력·측정 증거, 지켜진 범위와 미확인 결과를 각각 적는다. 구현·실행 검증을 마친 시점에 현재 작업 문서의 관련 항목과 연결한다.

이번 기록은 승인과 검증 계약이다. 실행 근거, 공통 디오라마 규칙 후보 및 실제 기준선 변경을 이 문서에서 선기록하지 않는다.
