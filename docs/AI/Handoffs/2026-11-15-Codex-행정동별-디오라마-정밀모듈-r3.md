필지 하나에 건물이 여러 채 있을 수 있고 건물 하나에 점포가 여러 개 있을 수 있다. 동 경계에 걸친 후보는 양쪽에 나타나므로 구 전체 점포 수를 셀 때는 인허가 관리키로 중복을 제거한다. 점포 층·출입구·간판·소유권을 뜻하는 표식은 붙이지 않았다. 원자료는 인허가 관측일 기준이며 현재 영업 여부도 별도다. [건물 데이터](https://www.data.go.kr/data/15083092/fileData.do) · [건물 원본 필드 정의](https://www.ktdb.go.kr/DATA/pblcte/20250805093928585.pdf) · 필지 전수 대조 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/quality/parcel-audit/candidate-2026.json`)

## Claude가 한 동을 열 때

1. 면목제3·8동 ZIP (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/examples/면목제3·8동-20261001.zip`) 또는 신설동 ZIP (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/examples/신설동-20261001.zip`)을 풀고 `module.json`을 읽는다. `layers[].path`는 ZIP 안 상대 경로이며 SHA-256은 포장된 레이어 바이트의 지문이다. 지번층의 `buildingGeometrySha256`은 같은 동 건물층 지문과 일치해야 한다.
2. 경계·건물·도로는 경도/위도, 공원 계획면은 EPSG:5186의 미터 좌표다. 거리층의 정수 좌표는 `frame.originMetres + 좌표 × frame.integerUnitMetres`로 동/북 미터 좌표를 복원한다. 한 지도에 표시할 때 먼저 같은 좌표계로 변환한다. 거리층 형식 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/streets/candidate-20261001/README.md`)
3. 동 하나를 먼저 굽고 이웃을 함께 놓을 때 공통 원점을 사용한다. 선택·건물 주소 연결은 판본, 동 코드, 도형 ID를 함께 사용한다. 테두리에서 잘린 조각의 원본 행을 건물 수로 중복 계산하지 않는다. 게임 내 가맹점이나 기사 배치에는 별도의 게임상 역할 연결이 필요하다.

다른 동은 저장소 루트에서 다음과 같이 내보낸다. `python`은 Python 3.11 이상 실행 경로로 바꿔도 된다. 생성된 ZIP에는 선택한 동의 검토 자료와 코드표가 들어간다.

```powershell
python eng/neighborhood/dong_diorama_review_pack.py list --edition candidate-2026
python eng/neighborhood/dong_diorama_review_pack.py inspect --edition candidate-2026 1126057500
python eng/neighborhood/dong_diorama_review_pack.py pack --edition candidate-2026 1123053300 --output 용두동-검토.zip
```

자료 작성 순서는 경계 수집·분리 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/boundary/README.md`), 원본 건물·도로 절단 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/candidate-detail/README.md`), 각 판의 거리·녹지 생성, [건물·음식점 지번 연결](../../../eng/neighborhood/build_dong_parcel_review.py)의 두 `--edition` 실행, [통합 도구](../../../eng/neighborhood/dong_diorama_review_pack.py)의 `build`다. [기존 r2](2026-11-15-Codex-행정동경계-생활시설-음식점-굽기자료보충-r2.md)와 원자료는 같은 저장소의 로컬 경로에 둔다. 원자료를 다시 받아 지문이 바뀌면 해당 판을 새로 생성·검증한다.

## 확인 범위

2026-11-15에 실제 소비 작업본 `ssalddel/`의 `SagajeongDispatchDongModules.cs`와 `Resources/hongdal-dong-modules.json`을 확인했다. 기존 Unity 명세는 면목 6동, 건물 13,383개, 도로 1,499개이며 HDIO 자료를 읽는다. r3 ZIP은 Claude가 이 소비 형식으로 굽기 위한 내부 검토 입력이다. 이번 결과의 검증은 자료까지이며 Unity 빌드·플레이 실행·공개 배포는 후속이다.

- 2026 후보 경계 65개의 2,080쌍을 검사했다. 면적으로 겹치는 쌍은 0개였다. 원본 건물·도로 130개 레이어 전수 검사와 원본 직접 재절단 390표본을 통과했다. 경계 검사 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/boundary/verification.json`) · 건물·도로 검사 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/candidate-detail/verification.json`)
- 두 판의 인허가 전체를 원본 필지와 검산했고 거리층은 새 경계판에서 원본 대조 585표본을 추가로 확인했다. 음식점 검사 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/quality/parcel-audit/candidate-2026.json`) · 거리 검사 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/streets/candidate-20261001/verification.json`)
- 통합 모듈 129개, 자료·선택 참조 1,351개, ZIP 4조건과 잘못된 판본·기존 ZIP 덮어쓰기 등 실패 6조건을 검사했다. 예제 ZIP 두 개는 같은 입력으로 재생성해 바이트 지문이 일치했다. 통합 검사 (로컬 검토 자료 `artifacts/local/admin-dong-diorama-precision-r3/quality/pack-verification.json`)
