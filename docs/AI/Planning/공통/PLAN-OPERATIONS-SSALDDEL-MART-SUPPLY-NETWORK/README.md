# [기획 · 운영체제·마트 물류 · PLAN-OPERATIONS-SSALDDEL-MART-SUPPLY-NETWORK · r1]

상태: `Approved / FirstOperationalSliceImplemented`

## 목표

살뜰마트의 공급계약 이용부터 점포별 입고 발주, 입고·검수·적재·재고, 고객 주문·할당, 피킹·포장, 라스트마일 인계와 완료·회복까지를 하나의 순서 있는 운영 생애주기로 관리한다.

고객 주문 확정부터 배송 증거 기록까지 내부 목표는 40분, 고객 약속 상한은 50분으로 둔다. 이 값은 서비스 보장이나 법적 약속이 아니라 운영 정책의 초기 목표이며, 실제 약속은 주문별 계약과 고지에서 별도로 확정한다.

## 확정

- 플랫폼 운영 주체가 제조·공급업체와 공급계약을 맺고 각 마트가 이용 계약과 필요 수량을 등록한다.
- 마트 OS는 입고·재고·주문·피킹·포장을 소유한다.
- 음식배달 OS는 기사 후보·제안·수락·픽업·전달·중단·재배차를 소유한다.
- 마트 주문은 부모 업무로 유지하고, 음식배달 OS에는 `MartLastMileDeliveryRequest` 자식 업무만 인계한다.
- 배차 후보는 피킹 시작부터 등록할 수 있다. 기사 제안 시점은 포장 완료로 고정하지 않고 운영 상황과 픽업 준비 예정 시각으로 판단한다.
- 전략 카드는 `PeakImmediate`, `Balanced`, `Consolidation`, `OldestFirstRecovery`, `CourierScarcity`, `PreparationDelayProtection`을 사용한다.
- 판단 우선순위는 상태 정합성·안전, 50분 상한, 40분 목표, 기사 현장 대기, 묶음 효율·비용 순이다.
- 이미 기사가 수락한 배정은 후속 정책 판정이 자동 교체하지 않는다.
- 초기 실행은 결정론적 규칙과 감사 가능한 상태 사본을 사용한다. 향후 AI는 승인된 전략 카드 중 후보를 추천할 뿐 업무 상태를 직접 확정하지 않는다.

## 현재 코드 결속

```text
살뜰마트 도심물류 OS
  공급계약 이용 → 점포별 입고 발주 → 입고·검수 → 적재·재고
  → 고객 주문·할당 → 피킹·포장
  → MartLastMileDeliveryRequest 인계 요청
                              ↓
                       음식배달 OS 수락
                       → 배차 → 픽업 → 전달
```

- 결정론적 정책은 40분 목표·50분 상한, 주문 적체, 기사 부족, 준비 예상, 묶음 후보를 입력으로 받는다.
- 포장 완료 흐름은 직접 음식배달 내부 서비스를 호출하지 않고 전용 Process Manager를 거쳐 인계 원장 요청, 배차 원장 생성, 인계 수락 순으로 진행한다.
- 인계 상태 사본에는 주소·사용자·기사 식별자를 넣지 않고 주문/자식 업무 고유 식별자, 전략, 시각, 수량과 사유 코드만 기록한다.
- 현행 실행에서는 포장 완료 시점의 실제 인계가 결속됐다. 피킹 시작 이벤트와 준비 예정 시각을 운영 원장에 영속하여 조기 기사 제안까지 실행하는 단계는 아직 열려 있다.

## 미정

- 음식배달 자격이 확인된 실제 가용 기사 수를 어느 조회 계약에서 받을지
- 동일 상차지·동선·온도 조건을 반영한 묶음 적합성 계약
- 주문 확정 시각을 결제 승인과 재고 예약 중 어느 권위 이벤트에 결속할지
- 피킹 시작 시점의 픽업 준비 예정 시각과 오차 보정 방식
- 40분·50분 목표의 지역·시간대·품목별 정책 판본화
