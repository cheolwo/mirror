## 확정된 목적과 별도 책임

사용자는 주문 전에 참여에 동의한 기사의 **대략적인 활동 구역과 업무 가능 여부**를 보고 요청할 수 있기를 원했다. 음식점·기사를 직접 선택하고 당사자들이 조율한 일도 실제 완료 근거를 갖췄을 때 알아볼 수 있도록 하는 방향이다. 클릭하거나 상대를 지정한 횟수를 현금·할인 포인트로 지급하는 방향은 아니다.

| 책임 | 주문 전 탐색 | 현재 맡은 주문의 기사 위치 | 완료 활동 인정 |
| --- | --- | --- | --- |
| 질문 | 이 구역에서 요청을 받아 볼 의사가 있는 사람이 있는가? | 내 주문의 현재 배정 기사가 어디까지 왔는가? | 실제로 어떤 약속과 연결을 마쳤는가? |
| 위치 범위 | 별도 동의로 선택한 넓은 활동 구역 | 기존 서버 권한·현재 배정·최근 GPS 조건 | 위치·이동 경로를 새로 공개하지 않음 |
| 실행 효과 | 요청·제안만 생성하는 후속 설계 | 기존 업무의 읽기 전용 표시 | 근거를 조회해 표시하는 후속 설계 |
| 금지되는 합치기 | 공개 참여를 배차 수신 동의로 간주 | 공개 구역으로 현재 GPS나 자택을 추정 | 칭호를 관리 권한·배차 우선권으로 변경 |

## 주문 전 공개 참여와 정보 수명

### 서로 다른 세 가지 선택

1. **신규 배차·배송 제안을 받을지**는 기존 본인 수신 설정이 소유한다.
2. **주문 전 탐색에 내 활동 구역·가능 여부를 보여 줄지**는 별도 공개 참여 동의가 소유한다. 수신 설정을 켰다는 이유만으로 공개 탐색에 등록하지 않는다.
3. **현재 맡은 주문의 위치를 관계자에게 제공할지**는 기존 업무·개인정보 경계가 소유한다. 공개 참여를 철회해도 이미 수락한 업무 자체를 취소하지 않는다.

공개 참여에 필요한 후속 명세는 본인, 동의 판본·시각, 공개 구역 식별값과 기준 자료 판본, 업무 가능 여부, 확인 시각·유효 종료 시각, 철회 여부, 동시 변경 판본이다. 이는 책임을 명시한 설계 목록이며 이번에 DTO·Entity·테이블을 신설한 것이 아니다. 서버가 소유자와 현재 동의·판본을 확인한 결과만 조회에 사용한다.

### 대략적인 활동 구역

- 우선 표현은 **법정동 식별자 또는 설정 가능한 넓은 격자 구역**이다. 행정동과 법정동을 같은 코드로 저장하지 않는다. 기사가 선택한 구역을 사용하며 자택 주소·계좌·정확한 출발점은 필요하지 않다.
- 법정동/격자 경계와 기준점이 필요하면 출처·기준일·좌표계가 확인된 기존 공간 자료를 연결한다. 확인한 경계가 없으면 구역명 목록으로 남기며 임의 위경도나 특정 건물의 가짜 기사 핀을 만들지 않는다.
- 지도에는 구역 경계·넓은 구역 표시를 사용한다. 구역 기준점을 사용하더라도 `활동 구역`이라는 의미를 명확히 하며 실시간 사람 위치를 뜻하는 마커와 구분한다. 특정 크기·격자 해상도·표시 인원 하한은 아직 정하지 않았다.
- GPS를 그대로 반올림해 공개 좌표로 복제하거나, 작은 셀의 반복 조회로 실제 이동 경로를 복원할 수 있게 하는 방식은 채택하지 않는다. 주문 전 탐색을 위해 기사 이동 이력을 공개하지 않는다.
- 기사의 `요청 확인 가능`은 그 순간 수락·도착·운송을 보장하는 표시가 아니다. 수행 중이어도 기존 일정상 후속 요청을 검토할 수 있는지와 실제 배차 적격성은 요청 시점에 다시 확인한다.

### 유효 기간·중지·철회

- 공개 가능 조건은 현재 동의 유효, 본인 공개 참여 활성, 업무 가능 표시 유효, 확인 시각이 설정된 신선도 안에 있음, 유효 종료 전임을 모두 충족하는 것이다. 신선도 초·분 값과 활동 기간 기본값은 미정이며, 승인 전 무기한 공개나 자동 ON으로 구현하지 않는다.
- 확인 시각은 서버가 수용한 본인 갱신의 시각으로 관리한다. 지도 조회·앱 새로고침·클라이언트 시계 조작만으로 공개 유효 기간을 연장하지 않는다. GPS가 없는데 실시간 이동으로 보간하지 않는다.
- **공개 참여 철회·운행 종료·활동 가능 종료·유효 기간 만료** 시 서버 조회와 캐시에서 탐색 노출을 중지한다. 구체 이벤트 연결과 캐시 무효화 방식은 구현 전 명세·시험이 필요하다. 숨김과 과거 거래·완료 증빙의 삭제는 다른 절차다.
- 신규 배차 수신 OFF는 공개 탐색 동의를 삭제하거나 기존 업무를 종료시키는 동작이 아니다. 다만 공개 카드가 `요청 확인 가능` 상태를 유지해 우회 요청을 유도하지 않게 중지 상태로 제외하는 보수적인 구현안을 검토한다. 재개는 기사 본인이 선택하고 공개 동의·기간을 다시 확인한다.
- 오래된/없는 정보는 `확인 필요` 또는 `현재 표시할 후보 없음`으로 다룬다. 수집·동의 기능 미구현을 `근처에 기사 없음`이나 전체 서비스 불가로 표현하지 않는다.
- 철회·계정 변경·재시작·응답 지연 중 이전 공개 결과가 다시 나타나지 않도록 동의/설정 판본을 재검사한다. 공개 검색·요청 횟수·노출 범위 제한도 후속 권한·부하 검증에 포함한다.

## 직접 선택은 요청이며 배차 확정이 아니다

```text
주문 전 음식점·공개 참여 기사 탐색
 → 사용자가 희망 상대와 조건을 선택
 → 유효한 공개 참여·수신 상태 재확인
 → 기존 업무로 요청 또는 제안
 → 기사의 자발적 수락
 → 현재 차량·적재·일정·업무 참여·자격·판본 검증
 → 기존 전문 원장에 배정 확정
 → 현재 주문의 관계자에게만 수행 상태·위치 제공
```

상대 선택은 실제 기사 배정이나 음식점 수락을 대신하지 않는다. 선택 직후 다른 주문을 수락했거나 수신을 중지했거나 자격·차량·여력이 달라지면 기존 관문에서 거절/보류하고 다시 선택할 수 있게 한다. 직접 지정이라는 이유로 새 강제 배차 경로를 만들지 않는다. AI 추천과 직접 선택 모두 기존 서버의 현재 정본·동시성 검사를 따른다.

재사용할 현재 관문은 [화물 수락 적격성](../../../../../Ssalddel/Services/Dispatch/Recommendation/화물배차수락적격성Service.cs), [화물 수락 Command](../../../../../Ssalddel/Application/Driver/DispatchAction/Handlers/배차수락CommandHandler.cs), [일정 삽입 평가](../../../../../Ssalddel/Services/Dispatch/Recommendation/운송일정삽입평가Service.cs)다. 음식은 해당 전문 수락·픽업 관문을 유지하며 일반 회원 배송을 음식 기사 역할로 바꾸지 않는다. [기사 업무 집중 기간 r65](driver-work-focus.design.r65.md)의 승인된 방향과 아직 미구현인 기간 정책도 구분한다.

## 완료 사실에서 활동 인정으로 연결

```text
같은 원거래·원주문의 참여/선택/조율 근거
 → 실제 수행·상호 완료 확인
 → 유상 거래라면 받는 쪽 대금 수령 확인
 → 같은 원거래의 재전송·정정·하위 원장 중복 제거
 → 동일 두 사람의 주간 인정 한도 판정
 → 개인에게 확인 가능한 인정 실적과 보류 이유
 → 별도로 합의한 기준이 생긴 뒤 표시용 칭호
```

- 유상 거래의 양측 완료·대금 수령 확인, 나눔/교환의 양측 약속 이행 확인은 기존 r107을 따른다. 앱 밖 직접 거래도 장기 방향에는 포함되지만 외부 거래 접수·증빙 형식·원거래 식별은 현재 미구현이다.
- 주문 제출·기사 선택·추천 노출·사진 첨부·한쪽 송금 신고만으로 인정하지 않는다. 현재 선택 경로가 저장되지 않았다면 완료 건수를 보고 과거에 그 사용자가 소개·조율했다고 추정하지 않는다.
- 주문·배송·입금·증빙·정정은 같은 원거래의 근거가 될 수 있다. 각각을 독립 거래로 늘려 중복 인정하지 않는다. 피킹·포장 같은 실제 수행 보수와 표시용 인정 실적도 별도다.
- **같은 두 사람 사이에서 일주일에 총3회 정도만 신뢰에 인정**하는 기존 방향을 보존한다. 상품명·수량·역할 변경으로 한도를 새로 열지 않는다. 이 상한은 실제 거래나 수행을 막는 제한이 아니다. 달력 주/최근7일, 경계 시각·정정 순서·일일 상한은 확정 전이다.
- 거래 금액에 가중치를 두지 않는 기존 방향을 유지한다. 신고 접수·상대 미응답만으로 자동 감점하거나 귀책을 확정하지 않는다. 보류·정정·이의제기는 완료/지급 상태와 구분한다.
- 표시용 칭호는 잔액·현금·할인권이 아니며 소비·양도·환전하는 자산으로 만들지 않는다. `조정자`, `준 관리자` 등은 후보 명칭일 뿐 확정 칭호가 아니다. 단계 이름·필요 인정 건수·다양한 상대 조건·유효 기간·정정/회수 기준은 미정이다.
- 기준이 정해지기 전 칭호를 발급하지 않는다. 칭호를 얻어도 다른 사람 위치 조회, 배차 확정, 사건 처리, 정산, 관리 API 권한이나 자동 배차 우선권이 생기지 않는다. 이미 실무 권한을 가진 `집하 조정자` Role을 표시용 칭호로 재사용하지 않는다.
- 인정 근거의 개인 조회와 공개 노출은 별도다. 공개에는 기존 당사자 동의·최소 공개 기준을 유지하고 상대 이름·관계망·계좌·주소·증빙 원본을 자동 공개하지 않는다. 새 회원은 낮은 신뢰로 단정하지 않고 확인된 기록 없음으로 표현한다.
