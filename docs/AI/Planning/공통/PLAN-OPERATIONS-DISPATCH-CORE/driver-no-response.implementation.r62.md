# 연속 미응답 수신 중지와 같은 토글 재개 r62

- 기획 ID·판본: `PLAN-OPERATIONS-DISPATCH-CORE / dispatch-core.r62`, 2026-10-16.
- 승인·결과: `Approved / AcceptedInCurrentThread / Implemented / LocalValidated / AndroidBuilt / DeviceDeferred / OperationalConfigurationUnchanged`.
- 사용자 요청: **직접 재개는 기존 토글을 다시 켜는 것이며, 미응답 자동 중지도 구현한다.** [검토 r61](driver-dispatch-reception-toggle.review.r61.md)과 [횟수 정정 r60](driver-no-response-receiving-off.design.r60.md)을 이어 구현한다.
- 작업 책임: `operations`. 음식 기사 네이티브·공통 화면과 기존 추천 만료·활동 원장·본인 수신 API의 수직 범위다. 화물 기사 앱에 같은 토글을 신설하거나 외부 운영을 활성화하는 작업은 포함하지 않는다.

## 구현 기준

1. 서로 다른 추천 차수의 유효한 미응답 1·2회에는 신규 수신을 유지하고, 3회째부터 신규 수신만 중지한다. 운행 종료·이미 수락한 배달 취소·지급 변경은 하지 않는다.
2. 추천 저장·푸시 발송 성공을 앱 수신으로 간주하지 않는다. 인증된 앱이 현재 제안을 받은 확인 요청을 보낸 건만 집계한다. 앱 확인은 사람의 열람·소리 청취 확인과 다르다.
3. 서버는 본인·현재 추천 기사·추천 차수·추천중/대기·유효시간을 재검사해 확인 사건을 멱등 기록한다. 같은 제안 재알림과 응답 재시도는 횟수를 늘리지 않는다. 구형 앱처럼 확인 근거가 없으면 미응답으로 차감하지 않는다.
4. 정상 만료와 미응답 사건을 같은 저장 경계에 연결한다. 실제 만료 시각을 기록해 재개 이전의 지연 처리된 만료가 재개 이후 횟수로 들어오지 않게 한다. 수락·거절과 경합하면 원장을 재검사한다.
5. 자동 중지는 별도 상태로 재구성하며 본인이 OFF를 선택한 `DriverExplicitIntent`로 기록하지 않는다. 기존 기사 수신 의사와 서버의 다른 제한은 보존한다.
6. 기존 토글이 중지 상태에서 OFF를 표시하고 이유를 안내한다. 기사 본인이 ON으로 바꾼 요청에만 명시적인 중지 해제 의사를 담는다. 운행 시작의 기존 자동 ON·자동 조회·응답 복구는 이를 대신하지 않는다.
7. 재개 요청은 미응답 중지만 해제한다. 운영자 제한·운행/위치/자격 부적합을 해제하거나 배차 확정을 약속하지 않는다. 응답 유실 때 원래 요청 ID와 해제 의사를 유지하고 정본으로 확인한다.

## 구현에서 선택하는 최소 경계

- 연속 횟수는 수락·명시적 거절 또는 기사 본인의 명시 재개가 확인되면 0으로 초기화한다. 일시 통신 오류·전송 실패·동일 제안 재알림은 새로운 미응답이 아니다. 시간 경과만으로 초기화하지 않는다.
- 3회 도달 후 수락·거절 이력이 뒤늦게 반영되더라도 수신 재개는 본인 토글 ON이 담당한다. 횟수 집계와 중지 상태를 구분한다.
- 초기 운행 시작의 기존 자동 ON은 유지하되 미응답 자동 중지를 해제하지 못한다. 세 번째 미응답 이후의 직접 재개와 구분한다.
- 공통 활동 원장을 재사용해 재시작·투영 유실 후에도 복구한다. 중지 여부를 클라이언트 저장만으로 결정하거나 새 통계 DB를 만들지 않는다.
- 이번 새 기준은 구현을 위한 최소 선택이다. 대기시간·우선순위·소득 불이익·모델 학습 정답은 바꾸지 않는다.

## 계약과 책임

- 수신 응답 추가: `미응답자동중지여부`, `연속미응답횟수`, `미응답자동중지시각Utc`.
- 기존 수신 의사 요청 추가: `미응답자동중지해제`, 기본 false. ON과 함께 본인 토글에서만 true를 전송한다.
- 제안 응답 추가: `RecommendationRound`, 구형 계약 기본 0. UI는 유효한 양수 차수만 수신 확인한다.
- 본인 API: 기존 운영 배차 Controller의 `PUT offers/{requestId}/receipt`. 원시 기사 ID·임의 사건 시각을 입력받지 않는다.
- 서버 Domain Policy는 사건에서 횟수·중지를 계산하고, UseCase·추천 만료 전환이 현재 상태와 권한을 검증해 기록한다. UI는 재조회 상태를 표시하며 원장을 확정하지 않는다.
- 구현 범위·기준선·소유 파일은 `driver-no-response.r62.work-order.json`에 기록한다. 기존 다른 미커밋 작업은 보존하고 commit/push는 별도 요청 없이는 하지 않는다.
