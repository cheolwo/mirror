## 목적과 책임

하나의 화물 의뢰를 정상 입력부터 완료까지 확인하고, 예외의 현재 확정 상태·다음 행동·미해결 대응을 기존 역할 화면과 운영 알림에서 추적한다. 새 원장이나 운영 권한을 만들지 않는다.

1. 검증 자료는 상자·명시 팔레트·고객 청구액/기사 약정액 구분을 소유한다. 차량·시간창·계정·수납의 기존 검증 조건을 임의로 완화하지 않는다.
2. 명령 실행/멱등 확인, 정본 대조, 증거 저장/대표 사례 선별을 별도 책임으로 둔다. import만으로 환경·폴더·HTTP를 변경하지 않는다.
3. 운영 알림 조회와 대응 표시를 관측·확인 명령·발송에서 분리한다. 확인된 미해결 건도 기본 대응 목록에 유지한다.
4. 운영자 UI는 현재 사건·확정 상태·다음 행동을 짧게 보여주고 기존 복구 창으로 재조회/업무 복귀를 제공한다. 지원되는 링크만 실제 의미로 표시한다.
5. 수납과 지급 조회의 클라이언트 책임을 분리한다. 관리자 지급준비 조회가 없는 경계는 `미연결`로 유지하며 기사 전용 API·송금 명령을 우회 호출하지 않는다.

## 시간과 인지의 경계

`확인`은 고객 응답·해결·실지급이 아니다. 기존 거래 분쟁의 업무 기한과 개인정보 권리/사고의 별도 기한을 보존한다. 합의한 첫 응답6시간/처리24시간/누적72시간은 별도 서비스 목표다. 근무시간·휴일·기산점이 미정이므로 실제 처리 기한을 만들어내지 않고 `WorkingHoursNotConfigured`와 목표만 표시한다.

`LastVerifiedAtUtc + 2분`은 기존 원장 상태 재조회 기준이다. 운영자가 그 시각까지 사건을 처리해야 한다는 뜻으로 표시하지 않는다. 다음 운영자 검토 시각은 현재 미설정이면 null로 둔다.

## 실행 범위

- 운영 모드는 기존 `Simulation`만 사용한다. Operational·실결제·실송금·공개 배포·외부 알림 발송은 켜지 않는다.
- 기존5363/5364/5365/5368 서버·DB·r20 증거와 기기 연결은 보존한다. 새 제품 HTTP 검증은 고정 loopback5369, 새 r21 전용 DB/증거에서만 진행한다.
- 실제 모델 연결/지도 인증/휴대폰 설치·촬영은 확인된 환경에서만 별도 결과로 기록한다. 규칙 대체·목록 대안을 정상 모델/지도 성공으로 바꾸지 않는다.
- 기존 과거 데이터·비밀 설정·영상·미관련 dirty 작업은 보존한다. 새 코드의 import·자체 시험·UI 렌더·제품 HTTP·자동 진행·기기 결과는 구분한다.

## 검증과 완료 조건

- 정상 시험자료/대표 사례 선별의 결정성·경계 시험, 운영 알림의 확인 후 미해결 유지·긴급 우선·다음 재조회/처리기한 분리·권한/구판 응답 호환 시험.
- 관리자 지급 조회와 표현 분리의 기존 수납·미조회·조회 실패·당월 없음·실지급 미확인 회귀.
- 관련 Fast/Task, UI와 적어도 한 소비 앱 빌드. 빌드는 동시에 수행하지 않는다.
- 실제 렌더에서 모바일/PC의 로딩·정상·없음·조회 실패·복구·복귀를 확인한다. 가능한 경우 새 격리 제품 HTTP에서 정상 운송과 실패/재조회/분쟁을 대조한다.
- 자동 처리·외부 알림·실제 단말·운영 migration 등 미실행 범위와 발견 사항은 완료 결과에 남긴다. 준비 도구만으로 실행 통과를 보고하지 않는다.

허용 경로와 담당은 [작업 명세](cargo-operating-verification-refactor.r21.work-order.json)에 둔다.
