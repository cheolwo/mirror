## 한 가지 결과

같은 화물·기사·실차와 현재 수행 근거에서 가능한 수행 계획을 계산하고, 그 계획만 AI와 사람이 비교하며, 추천 저장과 수락 직전에 현재 조건을 다시 확인한다. 차종 기준, 기사별 물리 적재 확인, 법정 자격, 자기 설정 상한을 서로 대신 쓰지 않는다.

## 순서와 책임

1. **우선순위 2 — 실차·장비 연결.** 기존 용달기사에 선택적인 비공개 적재 확인 JSON과 독립 concurrency 판본을 추가한다. 관리자 기존 차량 관리 업무에서 현재 실차 참조·장비 참조·확인 근거·확인/만료 시각과 물리값을 기록한다. 법정 자격 JSON과 분리한다. 확인된 개별 한도와 공통 차종 기준을 보수적으로 비교하며, 입구가 적용되는지와 미확인 값을 임의로 채우지 않는다. 과거 차종 기준만 있는 자료는 실차 확인 완료로 승격하지 않는다. SQL 변경은 migration 준비에 한정한다.
2. **우선순위 3 — 같은 기준시각의 상태 근거.** 기존 Factory에 기준시각과 조회 구간, 주문/기사/위치/현재 수행·보수/실차 판본의 지문 및 미확인 사유를 연결한다. 외부 위치 저장소와 SQL의 순차 조회를 원자적 snapshot으로 표현하지 않는다. 오래된 위치·만료 자격·수신 OFF·다른 업무 선택·불명확한 수행/반납 책임은 기존 관문과 함께 보수적으로 다룬다.
3. **우선순위 4 — 전체 계획 재검증.** 기존 조율기가 낸 기사별 신규 제안과 기존 수행을 기존 일정 삽입기로 함께 검토한다. 기존 수락의 구간 적재 검사를 공통 순수 검사로 추출해 초기 적재부터 typed 상하차 순서, 중량·부피·팔레트·비적층 면적과 물리 상한을 검사한다. 개별 주문 통과를 전체 조합 통과로 바꾸지 않는다. 상하차 작업시간은 명시한 검토 입력만 사용하며 누락을 0으로 확정하지 않는다. 가능/정보 부족/불가를 구분하고, 무효 묶음은 검증된 단건 또는 보류로 남긴다. 기존 순서를 임의로 뒤집지 않으며 전체 최적성을 주장하지 않는다.
4. **우선순위 5 — 가능한 계획과 사람 검토 결속.** 기존 r67 검토 자료·판본·사람 승인/내보내기 경계를 재사용한다. 선택적인 계획 후보·순서·구간 적재·시간 근거를 입력 지문에 포함하고 모델에는 검증 가능한 후보만 보낸다. AI 원응답·구조/사실 판정·규칙 결과·코덱스 의견·사람 승인을 구분한다. 조합 사례는 새 판본에서 미검토로 시작하고 기존 자료/검토를 보존한다. 자료 준비와 모델 실행, 승인 내보내기와 가중치 학습은 별개다.
5. **우선순위 6 — 저장·수락 재확인.** 기존 Serializable/기사 잠금/라운드·중복 복구를 유지한다. 조율 추천 저장 전에 현재 수신·선택 업무·자격·위치·실차·수행·약속·합의 보수를 다시 검사하고, 입력 근거가 달라졌으면 제안을 저장하거나 알리지 않는다. nullable 추천 근거 JSON을 준비한다. 첫 단독 운송도 실제 경로·약속 근거를 확인한다. 수락 경고의 명시 확인을 추천 생성 단계의 가짜 동의로 대신하지 않는다.

## 미정 정책과 호환

추가 우회·조합 대기·최대 묶음 수·점수 가중치·교차 업무 혼합의 새 운영값을 확정하지 않는다. 기존 설정은 보존하고 새 비교에 필요한 값이 없으면 미확인으로 남긴다. 합성 시험값은 해당 사례에만 결속한다. 기존 public JSON 이름·positional 생성자·과거 검토/모델 기록을 보존하고 추가 필드는 optional로 둔다. 새 엔진·운영 원장을 병렬로 만들지 않는다.

## 분담·검증

- Engine: 실차 적재 자료·조회/관리, 공통 구간 검사, 수락 적격성의 적재/단독 일정 검사와 관련 시험, additive schema 준비.
- State: Factory 상태/지문, 조율 저장과 기존 수락 Command의 최신 보호, 관련 회귀.
- Review: r67 계획 사례·가능 후보 전송·지문/승인 내보내기 및 기존 검토 화면/자체 검사.
- Root: 전체 계획 adapter·기존 실행 연결·DI·공유 API 조율·통합 시험·화면/결과 문서.
- 허용 경로/소유권과 이 계획 SHA-256은 작업 명세에 고정한다. 공유 파일은 한 담당만 편집하며 추가 경로는 먼저 명세에 반영한다. 관련 없는 dirty 변경을 보존한다.
- 모든 소스 편집을 동결한 뒤 집중 Fast → 영향 소비 솔루션/도구 빌드 → 전체 Task를 순서대로 실행한다. 동시 빌드하지 않는다. 화면 변경은 실제 로컬 렌더와 대표 PNG로 검증한다. 실패 및 성공을 분리해 보존한다.

실제 입력/실차 확인·운영 DB/폰·외부 알림·추가 학습·운영 성능의 완료 여부는 로컬 합성 검증과 별도로 보고한다. 이 승인 판본은 구현 중 변경하지 않는다.
