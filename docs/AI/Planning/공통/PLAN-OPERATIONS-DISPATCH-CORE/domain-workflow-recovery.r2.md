# OS 업무 단계·예외·복구 계약 r2

- 승인: 2026-10-21 사용자의 도메인별 예외·복구 정형화 및 우선순위 구현 요청
- 선행: [공통 오류 안내 r1](role-error-recovery.r1.md)
- 작업 명세: [허용 경로·경계](domain-workflow-recovery.r2.work-order.json)

## 책임과 범위

기존 OS·생명주기 단계·전문 원장·UseCase/Policy의 판단을 재사용한다. 생명주기 표시 순서는 실행 DAG가 아니며 복구는 현재 권한·원장·revision·가능 행동에 따라 결정한다. 오류 안내는 업무 상태를 소유하지 않고 내부 코드와 기술 원문을 제품 화면에 그대로 표시하지 않는다.

공통 실패 계약에 선택적 `workflowContext`를 추가한다. 구성은 `operatingSystemId`, `stageId`, `outcomeCode`이며 기존 `errorCode`, 분류·책임·재시도 정책·복구 행동·현재revision을 유지한다. 결과는 GET의 `NotApplicable`, 확정 미적용 `NotApplied`, 저장 확인 `Applied`, 응답 불명 `Unknown`을 구별한다. 서버는 허용 목록의 메타데이터만 전달하고 UI는 역할/단계별 표현과 서버가 허용한 행동만 소비한다. 구판 응답은 현재 페이지 문맥에 맞는 안전한 안내를 사용하며 HTTP404만으로 취소·배차 종료를 확정하지 않는다.

## 우선순위

1. 화물 정상/예외 대응표와 기존 서버→API client→ViewModel→화면의 typed 전달을 완성한다. 현재 운송/상하차 조회·완료 전 guard의 사유와 미확정 결과를 구분한다.
2. 화주 의뢰 조회 문맥과 입고 생성/완료의 저장 성공 후 조회 실패를 구분한다. 저장 응답이 있으면 같은 ID를 재조회하고, 요청 결과 불명은 기존 지원 경계 안에서 확인을 우선한다. 서버 멱등 계약이 없는 명령을 자동 재전송하지 않는다.
3. 음식·창고·정산 등 나머지 단계는 기존 코드/정본과 연결한 대응표로 관리하고, 첫 범위와 구분해 후속 적용한다. 모든 도메인 구현 완료로 표시하지 않는다.

## 화면 책임 카드 보완

- 기사 현재운송/상차/하차: 본인 운송의 현재 단계에서 진행 가능한 행동과 막힌 이유를 확인한다. 현재 단계와 증빙/미확정 상태를 보존하고 재조회·목록 복귀를 선택한다. 다이얼로그는 완료·신고·금액 변경을 실행하지 않는다.
- 화주 의뢰 상세: 같은 의뢰의 접수·진행·결제/증빙을 조회하되 조회 실패와 업무 미확정 결과를 구분한다. 기존 하위 원장/탭·로그인·복귀 경로를 유지한다.
- 입고 신청/완료: 이번 입고의 등록 또는 완료 결과를 확인한다. 저장 응답 뒤 조회 실패는 저장된 ID와 확인 상태를 유지하고 재조회한다. 초안/사진·동의·업무 성공을 UI 닫기로 초기화하지 않는다.

## 불변 경계

새 원장·상태 엔진·서버 route·권한을 만들지 않는다. 기존 상태 전이 조건·사진 요구·업무 보류·Feature 기본값·운영 비활성·기존 API 필드/식별값을 보존한다. 조회 실패를 빈 목록·업무 성공으로 대체하지 않는다. 기술 장애마다 현장 사건을 만들거나 다이얼로그 닫기로 사건을 종결하지 않는다. 선택/계정이 바뀐 뒤 늦은 응답이 다른 업무를 덮지 못하게 기존 수명을 유지한다.

## 검증

구조화된 서버 응답·파서 왕복, 같은 HTTP의 다른 업무 사유, 구판 fallback, 미확정의 POST 재전송 금지, 입고 POST 성공/GET 실패/재조회, 서로 다른 대상/역할의 오래된 오류 차단을 검증한다. 실제 소비 client 빌드와 scoped Fast/Task를 수행한다. 로컬 UI 렌더·APK 제작/설치·휴대폰·외부 서버·금융·운영은 각각 증거를 구분하며 이번 요청에 없는 commit/push는 하지 않는다.

## 완료·후속

[구현·회귀·화면6사례](../../../../Changes/2026-10-21-domain-workflow-recovery-r2.md)를 따른다. 공통 계약과 화주/화물 조회, 상하차 guard→사진 완료 service→VM→안내, 입고 저장/조회/미확정과 대상 전환 보호를 연결했다. 최종 Fast286·Task14,260개 통과/환경16개 미실행, 실제 공통 컴포넌트 가상6사례·Chrome390/1280px12렌더를 확인했다. 첫 Task 분산 회귀3건은 수정·재검증 기록과 함께 보존한다.

다음은 미확정 상태의 재실행 후 복원·명령 결과 조회/멱등 계약, 구판 응답과 추천 수락 사유 전수 적용, 나머지 OS 개별 화면 순서다. 현재 VM 수명의 보호를 앱 종료 이후까지 영속되는 것으로 표시하지 않는다. 새 APK 설치·휴대폰·실제 서버/운영/금융·commit/push는 이번 실행에 포함하지 않았다.
