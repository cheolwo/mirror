# 화물 로컬 서버·세 역할 앱 검증 r30

2026-10-29. 상태: `ApprovedByUser / InProgress / LocalOnly`.

사용자가 최신 프로젝트의 다음 단계로 로컬 서버 검증을 직접 요청했다. 원격 배포 없이 현재 제품 서버·격리 MySQL/Mongo·화주/기사/관리자 검토 APK를 같은 소스에 결속한다. 기존 운영 데이터·앱·다른 작업 변경을 보존한다.

## 이번 한 건과 역할

기존 합성 소형 화물 한 건의 접수·후불 승인 → 제어된 추천 → 기사 수락 → 상차 도착/완료 → 하차 도착/완료 → 화주 완료 조회·허용되는 인수증 등록 → 관리자 동일 운송 확인을 검증한다. 현재 제품에서는 기사 하차 완료가 운송 `인수완료`를 만든다. 화주의 인수증 등록은 고객 수령 확인과 다르며 별도 관리자 완료 승인도 만들지 않는다.

기존 R108 제품 Startup/JWT/Controller/UseCase와 신규 GUID의 실제 migration을 재사용한다. 자동 worker·외부 경로/FCM·금융 효과는 차단된 기존 Simulation 경계를 유지한다. API 접수와 실제 APK 버튼, 합성 사진·좌표와 실제 카메라/GPS를 각 단계별로 구분한다. 불명확한 POST는 자동 재전송하지 않고 같은 ID를 조회한다. 추천 만료를 우회하지 않는다.

## 범위와 검증

- 기사 지도 문구만 `방문 순서`·`방문 지점 연결` 등으로 간소화한다. 오류·좌표 공백·개인정보 보류와 실제 경로를 주장하지 않는 동작은 보존한다. 기존 표시 계약시험을 좁게 갱신한다.
- 실제 검증에서 `+00:00` 입력의 약속 시간이 저장 뒤 한국 시각으로 두 번 변환되는 결손을 발견했다. 생성·수정 Command 진입에서 네 시간창 값을 UTC로 정규화하는 최소 보완과 관계형 왕복 회귀를 이번 범위에 포함한다. 기존 Kind 없는 UTC ticks·누락·기본 날짜는 보존하며 전역 JSON/계약·기존 잘못 저장된 사례는 변경하지 않는다. 이전 APK137의 클라이언트 소스와 후속 서버 보완 지문을 구분한다.
- root가 서버·DB·휴대폰·빌드 순서를 소유한다. 소스 지문과 설치 APK 해시를 기록하고, 같은 업무에서 앱 재진입/재실행과 서버 재시작 후 정본 상태·이벤트 중복 여부를 대조한다.
- Fast/Task, 실제 로컬 HTTP/SQL/Mongo, 실제 APK UI, 미확인 항목을 별도로 기록한다. 추가 결손은 기존 업무를 끝내는 최소 수정만 검토하며 새 배차 기능·고정거점/복귀 기능으로 범위를 넓히지 않는다.
- 원격 서버·운영 활성화·실운송·실수납/지급·메일/FCM 발송·commit/push는 포함하지 않는다.

로컬 근거는 `artifacts/local/cargo-local-lifecycle-r30/`와 연결된 신규 R108 실행 폴더에 보존한다. 결과는 통합1.0의 기존 기준선·마감표에 연결하며 이전 판본의 검증을 현재 실행으로 승계하지 않는다.
