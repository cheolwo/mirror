# 법정동별 소형 화물·퀵 AI 배차 학습 준비 r67

- 기획 ID: `PLAN-OPERATIONS-DISPATCH-CORE`, 판본 `dispatch-core.r67`, 2026-10-19.
- 상태: `Implemented / LocalValidated / BrowserValidated / ActualModelComparedWithQualityLimits / HumanReviewPending / WeightTrainingNotStarted / OperationalDisabled`.
- 승인 범위: 화물 배차 학습을 우선하고 법정동별 가상 주문·기사 상황과 AI 판단을 사람이 데스크톱에서 검토할 수 있도록 준비한다. 기존 [퀵 학습 전략 r55](quick-training-strategy.design.r55.md)의 자료·검토·고정 평가 준비를 좁은 로컬 구현으로 이어간다.
- 책임: 새 로컬 호스트·학습 준비 계약·연결해 사용하는 관리자 검토 컴포넌트다. 기존 운영 지역 판정·관리자 route/DI/메뉴·worker·제품 APK·Unity·영상·외부 운영·가중치 학습을 바꾸지 않는다.

## 1. 현재 자료와 지역 단위

[법정동 지역 투영](../../../../../eng/local-dispatch-ai/cargo-regional-training/legal-dong-regions.json)은 기존 행정표준코드관리시스템 원본 ZIP을 읽어 서울 15개 법정동의 10자리 코드·명칭·존재 상태만 선택한 자료다.

- 중랑구: 면목동·상봉동·중화동·묵동·망우동·신내동.
- 동대문구: 전농동·답십리동·장안동·회기동·휘경동·이문동.
- 광진구: 중곡동. 노원구: 월계동·공릉동.

원본 수집일은 `2026-08-11`, 공급처 효력 기준일은 미제공으로 `sourceAsOfDate=null`이다. 그 수집본의 존재 상태와 현재 현행 상태를 혼동하지 않는다. 원본 ZIP SHA-256은 `7b4b544a6302d26c4f4c89d2c1355beae82e958c786bad8cc8572db0d2e2eb33`이다. 보관 위치·내부 CP949 텍스트 해시·원문 줄 번호와 행 해시를 보존한다. 원본/지역 투영의 해시가 다르거나 코드·명칭이 원문과 맞지 않으면 준비를 중단한다.

코드 자료는 경계 다각형이나 인접 관계가 아니다. 행정동 코드를 혼용하지 않고 운영 권역 키를 교체하지 않는다. 현재 화물 운영 권역의 시군구/시도·격자 판정은 그대로 둔다. 법정동 코드의 일치는 가상 집계에 사용하며 실제 주소의 귀속·주행 경로·카메라/고객 위치·거리·ETA를 추정하지 않는다. 공급처 이용조건은 추가 검토가 필요하며 원문과 파생 자료의 재배포 승인을 주장하지 않는다.

## 2. 한 사례의 입력과 비교

```text
공식 코드·명칭의 지역 이름표
  └─ 가상 주문: 출발/도착 법정동·kg/L·픽업 기한·가상 운임
     └─ 가상 후보: 현재 지역·마지막 목적지/가용 지역·가용까지 남은 분
        ├─ 가용 후 이동 분·대기 분·신규 수신·위치 관측 나이
        ├─ 기존 약속 충족·잔여 kg/L·복귀 방향 가정
        └─ 검토용 적격성·점수 산출
           ├─ 기존 순수 조율 엔진의 비교 기준
           ├─ 선택적으로 실행한 Ollama 제안
           └─ 사람이 승인/정정/미정과 허용 선택 집합 기록
```

주문·기사·시간·적재·위치 나이·보수는 전부 합성이다. 고객 이름·연락처·상세 주소·좌표·실제 기사 식별자를 넣지 않는다. 가상 ETA는 `가용까지 남은 분 + 가용 후 이동 분`으로 계산하며 수행 중인 기사가 현재 위치에서 즉시 출발한 것으로 처리하지 않는다. ETA가 없으면 0분으로 채우지 않는다. 운임 5,000원은 예시 입력이며 확정 요금이나 실제 원가·지급 재원이 아니다.

`CargoTrainingCases`의 검토용 적격성 함수는 수신 의사, 기존 약속, 남은 적재 중량·부피, 위치 나이, ETA와 픽업 기한을 검사한다. 5분 위치 기준과 점수 가중치는 투명한 교육용 fixture이며 운영 정책으로 확정하지 않는다. 실제 차량 자격·특수 취급·구간 적재·현재 원장/동의 guard와 동일한 검사라고 주장하지 않는다.

가능한 후보만 실제 `국내화물배차조율Service().조율`에 가상 입력으로 투영한다. 이 순수 호출에는 운영 DB·추천 확정·수락·실제 알림이 없다. 엔진 결과 출처는 `current_cargo_rule`이며 기존 조율 정책의 비교 기준일 뿐 최적 정답이나 사람 승인 자료가 아니다. 거리·비용·확정 손익은 미확인 값을 유지하고 인접 여부를 임의로 `true`로 만들지 않는다. 개인 평균 4,000원은 이번 목표·정답에 포함하지 않는다.

## 3. 검토와 독립 평가

| 자료 | 상황군 | 구성 |
| --- | --- | --- |
| 학습 전 검토 `review` | 장기 대기·기한 변화·다른 법정동 후보·수행 종료 지역·중량·부피·수신 토글·위치 만료·복귀 방향·ETA 누락 | 10상황군 × 2변형 = 20개 |
| 독립 평가 `holdout` | 기한과 적재 결합·수행 중과 위치 만료 결합·적격 후보 없음·동등한 복수 선택 | 별도 4상황군 × 2변형 = 8개 |

동일 상황군은 두 분할에 섞지 않는다. 사례·입력 식별자와 수치는 결정적이며 현재 시각이나 임의 난수를 섞지 않는다. 입력 해시는 모델·엔진 결과·사람 검토와 분리한다. 지역·기간·실측 경험이 독립된 대규모 평가라는 뜻은 아니다. 평가 문제를 열람하거나 반복 정책 조정에 사용했다면 그 사실을 남기고 이후 승격 평가에는 새로 격리한 자료가 필요하다.

각 사례는 단일 정답을 강제하지 않는다. 적절한 후보 여러 명과 배정 보류를 함께 허용할 수 있다. 부족 자료가 있거나 기준이 미정이면 판단 보류로 기록하고 자동 승인하지 않는다. 기존 엔진 선택을 그대로 승인 자료로 복사하거나 모델 자기 평가를 사람 의견으로 표시하지 않는다.

## 4. 데스크톱 검토 화면

제품 관리자 공용 [검토 컴포넌트](../../../../../SsalddelAdmin/Components/DispatchTraining/CargoRegionalTrainingReview.razor)를 새 [로컬 호스트](../../../../../eng/CargoRegionalTrainingReview/Program.cs)가 연결해 사용한다. 기존 `/admin/freight-delivery/dispatch-ai-review`의 운영 화면·route·DI·메뉴를 교체하지 않는다.

로컬 주소는 `http://127.0.0.1:5595/admin/freight-delivery/dispatch-ai-review/training`이다. Blazor Interactive Server와 SignalR의 loopback HTTP 통신을 사용한다. 기존 운영 API를 호출하거나 운영 DB를 읽고 쓰는 화면은 아니다.

화면 책임은 한 사례의 조건과 판단을 검토해 의견을 저장하는 것이다.

1. 픽업 법정동, 검토/평가, 미검토 여부로 사례를 찾는다.
2. 주문의 출발/도착 지역·기한·물품과 기사별 도착 예상·대기·가용 지역·적재 여력을 비교한다.
3. 필요하면 후보 점수·제외 이유·위치 신선도·수신·기존 약속을 펼친다.
4. 기존 규칙과 선택적 모델 결과를 나란히 확인한다.
5. 적절함/수정 의견/판단 보류와 허용 후보·보류·의견을 저장한다.
6. 상세 출처에서 자료·정책·입력·모델·프롬프트 해시를 확인한다.

입력 의견은 오류나 동시 변경 때 보존하고 최신 기록을 확인한 뒤 재검토한다. 새로 비교한 모델 결과를 보지 않은 예전 검토 명령으로 승인하지 않도록 모델 실행 식별값도 대조한다. 실제 화면 확인과 코드/시험 확인의 결과는 별도 검증 기록에 남긴다.

## 5. 검토 원장의 경계

자료 묶음은 초기 `dataset.json`과 `sources.json`을 불변 파일로 저장한다. 소스 목록에는 실제 엔진·규칙·fixture·지역 투영의 경로와 SHA-256, 실행 중인 도구·서버 엔진·계약 DLL의 해시가 들어간다. 자료 판본은 정책·런타임·지역·사례 내용의 해시로 나눈다.

사람 검토는 자료·사례·입력·정책 해시, 당시 모델 실행 ID, 기존 엔진 선택, 요청 ID, 기대 revision, 판정·허용 후보·메모·시간을 `review-events.jsonl`에 추가한다. 같은 요청 ID의 같은 내용은 재사용하고 다른 내용은 충돌로 처리한다. 오래된 revision, 바뀐 자료·입력·모델 결과, 제외 후보 승인, 선택 없는 확정, 잘못된 이력은 조용히 성공시키지 않는다. 파일 잠금과 다시 읽기를 통해 같은 로컬 저장소의 동시 검토를 조율한다.

모델 비교 기록과 사람 승인 기록은 다른 사건이다. 비교를 다시 실행해도 과거 승인을 삭제하거나 학습을 자동 실행하지 않는다. 소스·초기 자료·출처 파일이 바뀌면 해당 판본의 추가 검토를 차단하며 과거 기록을 새 판본의 승인으로 소급하지 않는다.

`--export-approved`는 `review` 분할에서 사람이 명시적으로 승인하거나 정정한 사례만 입력·허용 답안·승인 근거와 함께 새 해시 파일로 내보낸다. `holdout`과 판단 보류는 제외한다. 승인 전에는 빈 파일이 정상이다. 이 자료는 모델 가중치 변경·SFT/LoRA 실행·완성 학습 모델이 아니다.

## 6. 선택적 로컬 모델 비교

기존 Docker Ollama `http://127.0.0.1:12681/`의 설치된 `qwen3:1.7b`만 사용한다. 모델 설치·다운로드·컨테이너 자동 시작·원격 대체 호출은 없다. `/api/tags`로 실제 모델 digest를 확인하고 한 사례의 허용 후보 ID 또는 보류와 허용 이유 코드만 요청한다. 공급한 수치와 맞지 않는 이유나 제외 후보는 유효 결과가 아니다.

기존 대상 컨테이너는 `mirror-local-dispatch-ai-ollama-1`이다. 실제 추론 경로 `http://127.0.0.1:12681/api/generate`는 JSON Schema와 `temperature=0`, `think=false`, `stream=false`를 사용한다. 공식 기술 근거는 [Ollama 구조화 출력](https://docs.ollama.com/capabilities/structured-outputs), [Generate API](https://docs.ollama.com/api/generate)다. 응답 구조 준수·낮은 무작위성·가중치 학습·실제 판단 품질은 서로 다른 사실이다.

한 비교는 20초 한도로 제한한다. 결과·실패·지연·미설치를 구분하고 모델 digest·입력/프롬프트 해시·실행 ID·경과 시간을 기록한다. 실패를 기존 엔진과 같은 선택이나 성공으로 계수하지 않는다. 모델 응답은 관측용이며 운영 추천·수락·금융·외부 알림으로 이어지지 않는다. 20초는 학습 준비 도구의 상한이고 실제 퀵 운영 지연 목표가 아니다.

## 7. 실행과 검증 책임

구체적인 [사용법](../../../../../eng/local-dispatch-ai/cargo-regional-training/README.md)은 도구 README를 따른다.

| 명령 옵션 | 범위 |
| --- | --- |
| `--prepare` | 공식 지역 근거와 가상 사례·기존 엔진 비교 자료 준비/조회 |
| `--self-check` | 별도 사본·대역 모델에서 해시·재현·동시 검토·이력·내보내기 경계 확인 |
| `--port 5595` 또는 일반 실행 | loopback 검토 화면 제공 |
| `--compare-first 3` | 앞의 세 사례를 실제 설치된 로컬 모델과 비교 |
| `--export-approved` | 정확한 자료 판본에서 사람이 승인한 검토 사례만 내보내기 |

기본 저장은 `artifacts/local/cargo-regional-training-r113/review/<자료해시>/`이며 경로를 바꿀 때도 저장소의 `artifacts/local/` 아래여야 한다. 기존 raw 자료·과거 학습 후보·검토 기록을 덮어쓰지 않는다.

이 문서는 구현 범위·사용법·미검증 경계를 기록한다. 빌드·시험·실제 브라우저·실제 Ollama 호출의 성공 건수나 품질 결과는 여기서 선행 확정하지 않는다. 운영 worker는 기존 비활성 경계를 유지한다. 실제 주소의 법정동 귀속, 차량별 실경로·ETA, 실제 배차·FCM·휴대폰·정산·송금, APK 설치·Unity·영상·외부 배포·커밋/푸시는 별도 범위다.

후속은 사람이 대표 사례를 검토하고 미정 기준을 확정하는 일이다. 승인 자료가 쌓인 뒤 기존 엔진·현재 모델·예시를 준 모델을 고정 평가에서 비교하고, 반복 오류와 이득이 확인될 때만 별도 승인으로 소규모 가중치 학습을 검토한다.

현재 28개 사례·15개 법정동은 시작 범위이며 학습 충분성이나 실제 운영 품질을 증명하지 않는다.
