- Scope: 기존 생활배송·화주 입력, 관리자 실차 확인, 현재 위치·수행에 따른 본인 추천 재검증의 로컬 구현·검증. 기존 dirty 변경을 보존한다.

## 결과와 책임

1. **입력 완결.** 생활배송의 같은 포장 개수·총중량과 선택적 치수·직접 부피·팔레트·회전/적층을 기존 화물 적재 Policy와 정본 생성에 연결한다. 크기 등급을 실측값으로 환산하지 않는다. 누락은 null, 명시 0은 0으로 구분한다. 일반 회원·외부 전달·구형 저장 자료를 임의 완성하지 않으며 내부 기사 배송에 필요한 누락과 보완 행동을 표시한다.
2. **상하차 작업시간.** 기존 픽업/하차 위치 계약에 각각 선택적 `작업시간분`을 추가하고 UI·초안·소비 client 복사·생성/수정·정본·조회·Mongo 투영·계획 입력까지 보존한다. 새 nullable 두 열 migration은 준비만 한다. 미입력을 0분으로 가정하거나 시간창 길이·운임에서 유추하지 않는다. 저장 입력을 기본으로 사용하며 상충하는 운영 조율 입력이 정본을 조용히 덮지 못하게 한다.
3. **실차 확인.** 기존 관리자 차량 route와 actual-loading API를 연결한다. 기존 기사 목록에서 선택해 현재 본인 선택 실차·차종, 확인값·근거·기간과 판본을 조회/저장한다. 본인 차량 선택과 법정 자격을 대신 변경하지 않으며 기대 판본 충돌·미확인·실패를 구분한다. 실제 실측·승인을 합성값으로 생성하지 않는다.
4. **이동 중 갱신.** 위치 관측과 안전 조건을 구분한다. 같은 좌표/정확도의 신선한 heartbeat만으로 새 라운드·알림·대기순위를 만들지 않는다. 이동이나 기존 수행 변화는 기존 실제 경로·일정 삽입·구간 적재·작업시간·약속 검사로 재계산한다. 과거 계획에 새 지문만 붙이지 않는다.
5. **연속 수락과 복구.** 기존 본인·유효 추천·라운드·소유·보수의 경계 안에서 남은 추천만 재검증한다. 첫 수락은 기존 수행으로 포함한다. 계획이 바뀌면 새 판본과 필요한 확인으로 이어지고, 불가·정보 부족·검사 중 변경은 보류한다. 기존 Serializable/기사 잠금·멱등·후속 복구와 기본 worker OFF를 유지한다. 불확실한 수락 POST를 자동 반복하지 않는다.

## 경계와 검증

새 전역 배차 엔진·원장·역할·라우트를 만들지 않는다. 음식 흐름·Unity·영상·Ollama 지연 해결/가중치 학습·클라우드·APK/휴대폰·실제 지급·운영 DB 적용·feature/worker 활성화·commit/push는 제외한다. 미정 우회·대기·최대 묶음·점수 정책을 새 숫자로 고정하지 않는다.

분담과 정확 쓰기 경로는 r77 work-order에 결속한다. 각 소유 파일을 편집 전 다시 읽는다. 입력 왕복·기존 JSON/멱등 호환·음수/명시0·과거 자료 미승격, 신선한 heartbeat·이동 후 시간 초과·첫 수락 후 연속 수락·과적 보류·동시 상태 변경·중복 복구를 확인한다. 소스를 동결한 뒤 집중 Fast → 영향 소비 빌드 → Task를 순차 실행하며 동시 빌드하지 않는다. UI는 실제 로컬 렌더에서 PC/390px와 입력/오류/충돌을 캡처하고 장기 보존 PNG·문서·해시를 연결한다. 로컬 합성 검증과 실제 기기·운영 완료를 구분한다.
