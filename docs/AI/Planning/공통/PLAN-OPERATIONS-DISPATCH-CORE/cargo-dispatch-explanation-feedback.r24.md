## 사용자 완료 결과

화주/주문자와 대상 기사 본인이 기존 운송·추천 상세에서 ‘배차 설명·의견’을 열어 당시 저장된 추천 기록·확인된 조건·판단 시각을 확인하고, 그 설명에 연결된 비공개 의견을 명시적으로 제출해 접수 결과를 다시 조회한다. 기존 배차 수락/진행 알림에서 상세로 이어지는 경로를 유지한다. 추천·수락·완료·의견 접수는 별도 상태다.

## 구현 경계

- 실제 화물 추천 저장의 SQL transaction에 불변 설명 사건을 추가한다. 기존 원장 ID/라운드/대상/결정 시각·입력 지문과 확인된 구조적 사실을 결속한다. 조율 경로와 기존 엔진 추천 경로를 모두 다루며 재추천은 새 사건이다. 실패·rollback을 성공 설명으로 남기지 않는다.
- 현재 재계산, 샘플·정책 검색 결과, 기존 JSON의 나중 값으로 과거 설명을 만들지 않는다. 과거 미기록은 미기록으로 표시한다. AI라는 이름으로 모든 규칙 결정을 표시하지 않고 실제 저장 경로/알고리즘과 근거 한계를 구분한다.
- 다른 기사 후보·점수·집/거점·GPS·고객 상세주소·연락처·원시 prompt는 공개 DTO에 넣지 않는다. 역할별 본인 관계를 서버에서 다시 확인한다. 추천 만료·거절 뒤에도 저장 당시 대상 기사 본인의 해당 설명에 한정해 의견을 접수할 수 있게 하되 다른 기사 이력은 숨긴다. 자유문구를 원래 결정 사유로 승격하지 않는다.
- 사용자 의견은 설명ID·사용자·ClientRequestId에 결속하고 같은 요청/같은 내용은 같은 접수, 같은 요청/다른 내용은 충돌로 처리한다. 선택 사유와 선택적 짧은 의견을 보호 저장한다. 제출 실패/응답 미확정은 입력·요청ID를 보존하고 먼저 접수 여부를 조회한다. 의견은 원 배차·운임·완료·평점·RAG 활성 사례를 변경하지 않는다.
- 기존 알림의 상세 링크를 재사용하고 저장된 설명 조회/의견 접수로 연결한다. 이메일 요약·외부 실제 발송·전역 개인화 설정·자동 학습·배차 재추천·운영 활성화는 이번 구현에 포함하지 않는다.
