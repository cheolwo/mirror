# [기획 · 화물 정보 게시·조회부터 단계적 확장 · PLAN-OPERATIONS-DISPATCH-CORE · r1]

2026-10-25. `InformationPostingFirstSelected / ReviewedWithFindings / ProductUnchanged / LegalApplicabilityOpen / OperationalDisabled`.

사용자는 Unity보다 실제 화물 플랫폼과 모바일·데스크톱 앱에 집중하고, 기능을 넓힐 때마다 법적 요건을 확인하도록 요청했다. 첫 운영 형태는 **화물 정보 게시·조회 중심부터 검토**로 선택했다. 통합 앱 1.0의 전체 목표는 보존하되 이번 우선 범위는 정보 게시의 책임·공개 수명·권한이다. 이 방향 선택은 서비스의 적법성 확인·운영 공개·기관 신청·운송 중개의 승인이 아니다.

## 첫 범위와 업무 의미

로그인한 게시자 → 내 공고 초안 → 공개될 항목 미리보기 → 명시 게시 → 수정·철회/만료, 열람자는 로그인 없이 공개 요약을 조회하는 흐름을 우선 검토한다. 기존 화주·기사·운영자 앱과 공개 조회 컴포넌트를 재사용하고 새 독립 앱부터 만들지 않는다.

공고는 실제 운송 의뢰·배차 대기·기사 수락·운송 계약과 구분한다. 첫 공고 게시로 추천·자동 배차·운행 시작·운송 인계·수납·정산을 자동 생성하지 않는다. 향후 전환이 필요하면 별도 선택과 계약 당사자·기능 권한·법적 준비를 확인한다. 기존 전문 업무는 삭제하지 않고 현재 운영 기본 비활성 기준을 유지한다.

공개 최소 항목 후보는 화물 종류·수량/중량·필요 차량·넓은 출도착 지역·희망 시간이다. 희망 조건과 플랫폼이 확정한 운임/배차를 혼동하지 않는다. 상세주소·정확한 좌표·전화번호·고객/인수 정보는 공개 기본값에 넣지 않는다. 자유 입력·사진에 개인정보가 들어가는 경우, 보관·삭제·신고와 연락 허용 방식은 별도 검토한다. 로그인만으로 연락처를 공개하지 않는다.
