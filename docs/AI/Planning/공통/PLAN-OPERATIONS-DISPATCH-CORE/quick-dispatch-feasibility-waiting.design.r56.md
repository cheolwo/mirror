# 퀵 배차의 수행 가능성과 대기 우선 문답 r56

- 기획 ID: `PLAN-OPERATIONS-DISPATCH-CORE`, 판본 `dispatch-core.r56`, 2026-10-15.
- 상태: `AcceptedDirection / QuestionsOpen / ImplementationNotAuthorized / WeightTrainingNotStarted`.
- 이전 판본: [퀵 우선 AI 배차 학습 전략 r55](quick-training-strategy.design.r55.md). r55의 학습 전략은 유지하며, 이번 문답은 기사 선택에서 픽업 도착시간과 장기 대기를 비교하는 기준만 구체화한다.
- 범위: 기획 답변 기록과 목차 갱신. 제품 코드·설정·학습자료 생성·모델 호출·가중치 학습·운영 배차·commit/push는 수행하지 않는다.

## 1. 사용자 답변과 확정 방향

질문 `quick-eligible-driver-pickup-arrival-window`는 `Answered / FeasibilityBeforeWaitingAccepted / FixedEtaGapNotAdopted`다.

사용자는 픽업지 도착 예상시간 때문에 업무 처리에 지장이 생기면 배차하지 않고, 지장이 없다면 오래 기다린 사람에게 주는 것이 바람직하다고 답했다. 앞선 ‘가장 빨리 도착하는 기사보다 5분 이내’ 제안은 확정 기준으로 채택하지 않는다. 발화의 불명확한 호칭을 특정 기사나 후보의 승인으로 해석하지 않는다.

확정한 선택 원칙은 **업무를 차질 없이 수행할 수 있는 후보를 먼저 추린 뒤, 그 안에서 오래 기다린 기사에게 우선권을 주는 것**이다. 픽업 도착시간의 상대적인 차이만으로 후보를 탈락시키거나 최단 ETA 기사를 무조건 먼저 선택하지 않는다.

## 2. 판단 순서와 기존 책임

1. **기존 후보 조건 확인:** r55의 서버 검사인 자격·수신 의사·차량/적재·취급 조건·원장/판본·이미 수락한 약속을 유지한다. 이번 답변으로 기존 서비스 권역이나 적합성 조건을 없애지 않는다.
2. **업무 지장 여부 확인:** 확인된 픽업 준비/허용 시간, 전달 약속, 기존 수행 일정과 함께 도착 예상시간을 비교한다. 픽업에 도착할 수 있다는 사실만으로 전달까지 수행 가능하다고 단정하지 않는다.
3. **가능한 후보 사이 대기 우선:** 위 조건을 만족한 기사 중 오래 기다린 기사를 우선한다. 더 빨리 도착한다는 이유만으로 짧게 기다린 기사를 자동 승격하지 않는다.
4. **적용 전 재확인:** 추천 적용 시 현재 원장과 후보 상태를 서버가 다시 검사하는 r55 책임을 유지한다. 수행 불가능한 후보를 AI가 복원하거나 기존 시간 약속을 임의로 늘리지 않는다.

수행 중 기사에게 후속 일을 제안할 때는 앞서 정한 마지막 목적지와 종료 예상시각을 출발 기준으로 삼는 방향을 유지한다. 수행 중이라는 이유만으로 전부 배제하지 않으며, 후속 픽업 때문에 이미 수락한 일이 지연되는지도 함께 본다. 수행 중 시간과 신규 배차를 기다린 시간을 같은 값으로 합치는지는 아직 정하지 않았다.

업무 지장 여부가 미확인이면 이를 ‘지장 없음’ 또는 ‘수행 불가능’으로 임의 확정하지 않는다. 위치·ETA·시간 약속의 관측 유효성 및 응답 뒤 재확인은 r55의 서버 책임을 따른다. 불확실성 여유시간의 수치나 시간 약속이 없는 주문의 판단 기준은 별도 문답 대상이다.

## 3. 사람이 검토할 예시

아래는 정책 설명용 가상 사례이며 실제 배송 결과·생성된 학습자료·승인 ready 행이 아니다.

| 후보 | 픽업 도착 예상 | 대기 | 전체 업무 수행 가능 여부 |
| --- | --- | --- | --- |
| A | 2분 후 | 3분 | 가능 |
| B | 6분 후 | 18분 | 가능 |
| C | 9분 후 | 25분 | 가능 |

- 모두 업무에 지장이 없다면 **C를 우선**한다. C가 A보다 7분 늦게 도착한다는 차이만으로 제외하지 않는다.
- C의 계획이 기존 전달 약속을 지키지 못하는 것으로 확인되면 C를 제외하고 **가능한 후보 중 B를 우선**한다.
- C의 자료가 오래되어 가능 여부를 모르면 그 사실을 미확인으로 남긴다. C의 실패나 성공을 학습 정답으로 만들어 채우지 않는다.

## 4. 학습 전략에 연결할 내용

r55의 대표 사례 검토에서 ‘조금 늦지만 지장 없는 장기 대기 기사’와 ‘같은 기사지만 기존 약속을 어기는 경우’를 짝으로 비교한다. 후보별 시간 약속·예상 순서·관측 근거와 탈락/대기 우선 이유를 함께 남기는 자료를 제안한다.

이번 문답은 사람이 확인한 **정책 방향**이다. 개별 사례의 입력·답안·출처가 검토됐다는 뜻이 아니며, 기존 r51/r52 후보의 ready나 사람 승인 상태를 바꾸지 않는다. 실제 자료 생성과 모델 학습·제품 반영은 후속 작업으로 구분한다.

## 5. 미정과 다음 질문 하나

- 대기시간의 시작점·중지/재개 조건, 수행 중 기사의 후속 배차 대기 집계, 동률 기준은 미정이다.
- 시간 약속이 없는 주문의 수행 가능 기준, ETA 오차를 감안한 여유시간도 미정이다. 고정 5분을 대체하는 숫자를 임의로 만들지 않는다.
- r55의 평균 4,000원 집계·수집 상한·비용 미확인 정책은 이번 답변으로 확정되지 않는다.
