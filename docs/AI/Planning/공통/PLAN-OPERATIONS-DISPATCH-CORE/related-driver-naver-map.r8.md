# 관계 기사 위치·주문 전 탐색·활동 인정 r8

- 상태: CompletedLocalAndDeviceFallbackValidation / NaverAuthenticationPending (2026-10-22)
- 승인: 화주·주문자가 현재 관련 기사의 위치를 네이버 지도에서 확인하고, 주문 전 탐색과 직접 조율 활동을 누적하는 사용자 요청.
- 후속 확정: 주문 전에는 **참여에 동의한 기사의 대략적인 활동 구역·업무 가능 여부**를 표시한다. 모든 기사의 정확한 GPS를 공개하지 않는다.

## 먼저 완결할 기존 업무

현재 서버와 공통 역할 Adapter에 이미 존재하는 배정 기사 위치 조회·권한·주기 조회를 재사용한다. 통합 Android앱의 지도 host를 기존 네이버 SDK 바인딩으로 연결하여 음식 주문자·화주의 픽업/전달·기사 마커를 표시한다. 화면 크기/접기/지도 이동 문맥과 기존 목록 대체·실패 복구를 유지한다. 실제 지도 인증/타일, 가상 기사 좌표 표시와 갱신, 만료/로그아웃/완료 시 제거를 구분해 검증한다.

서버는 본인 현재 배정의 유효한 최근 좌표만 제공한다. UI에서 숨기는 것만으로 서버 권한 검사가 끝난 것으로 보지 않는다. 다른 고객/주문·배정 이전 좌표·재배정 전 기사·완료 후 위치를 공개하지 않는다. 오래되거나 없는 GPS를 실시간으로 표시하거나 경로 보간으로 만들지 않는다.

## 주문 전 탐색·직접 선택

음식점/음식은 기존 공개 자료를 사용한다. 기사 공개 활동 구역은 배송제안 수신 동의나 현재 주문 위치 제공 동의와 구분된 별도 공개 참여다. 동의한 본인의 범위·업무 가능 여부만 노출하고 철회/운행종료/오래된 정보는 숨긴다. 사용자의 직접 선택은 요청/제안이며 기사 수락·기존 차량/시간/업무 조건 검사를 자동 생략하지 않는다. 공개 구역 좌표와 수행 중 실제 GPS를 같은 모델로 노출하지 않는다.

공개 참여 입력과 원천이 아직 없는 경우 빈 후보를 실제 기사 없음이나 전체 서비스 불가로 표시하지 않는다. 현재 배정 위치부터 완결하고 공개 탐색은 별도 수용 명세·동의 화면·권한/부하 검증 후 연결한다. 운영/기능 플래그를 임의로 켜지 않는다.

## 활동 인정과 칭호

직접 음식점/기사 선택만으로 점수를 발급하지 않는다. 기존 주문 원장과 상호 완료, 유상 거래의 대금 수령 확인을 연결한 이행 사실을 먼저 인정한다. 같은 상대 반복 주간3회 상한의 기존 기획을 보존하며 주간 경계/칭호별 필요 횟수·유효 기간은 후속 문답으로 정한다. 돈·할인 포인트나 새 별도 정산 원장을 추가하지 않는다.

표시용 활동 칭호와 실무 권한을 구분한다. `조정자`, `준 관리자`라는 표시를 얻어도 다른 사람 위치 조회·배차 확정·사건 처리·정산 권한이 생기지 않는다. 기존 `집하 조정자` 권한 Role도 재사용하지 않는다. 신뢰/칭호의 자동 발급은 기준 수치가 확정되기 전 비활성이다. 기준은 기존 `trust-elevation.design.r107.md`의 후속 관계로 관리한다.

## 범위·검증

허용 변경: 통합앱 지도 SDK host/설정, 기존 관계 위치의 freshness/배정 검사, 해당 공통 UI·집중 시험, 기존 앱 제작 입력의 지도키 전달과 새 비공개 검증 도구/결과. 비밀 키는 소스/문서/로그/캡처에 넣지 않는다. 새 실제기사 가입·추적·정산·관리자권한·자동 운영/commit/push는 하지 않는다. 관련 없는 dirty 작업을 보존한다.
