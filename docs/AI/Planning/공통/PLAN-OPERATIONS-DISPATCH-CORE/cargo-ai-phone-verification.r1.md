# 화물 AI 추천·휴대폰 수행 검증 r1

- 날짜: 2026-10-21
- 상태: `CompletedSyntheticDeviceValidation / LocalOnly`
- 승인: 사용자가 USB 휴대폰에서 화물 추천·수락·픽업·전달을 검증하고 단계별 실제 스크린샷을 남기도록 요청했다.
- 범위 명세: [작업 명세](cargo-ai-phone-verification.r1.work-order.json)
- 선행 구현: [화물 AI 추천 r1](cargo-recommendation-default.implementation.r1.md)

기존 통합앱·합성 계정·전용 SQL/Mongo와 기존 화물 원장/API를 재사용한다. 자동 배우가 먼저 수락하지 않는 수동 시험 호스트에 새 후보 선택 경로만 명시적으로 연결한다. 제품의 운영 기본 OFF·수락/정보 동의·사진/완료 관문을 변경하지 않는다. 기존 호스트·이전 의뢰·검토 기록과 설치 데이터를 보존한다.

가상 주문·위치·요금·경로를 사용하는 시험이며 실제 운송·실제 도로·GPS·외부 FCM·금융·운영 개시와 구분한다. 기존 합성 경로 adapter를 재사용할 때 서버 시험 입력의 complete route 플래그를 실제 주행 검증으로 표시하지 않는다. AI 선택·규칙 복귀의 정본 감사와 휴대폰 UI 수락·촬영·완료 증거를 같은 운송 ID에 연결한다.

순서는 연결/설치판 확인 → 전용 서버/합성 주문 준비 → 운행·신규 수신 → 추천 배너/카드 → 수락/동의 → 픽업 도착·사진/완료 → 전달 도착·사진/완료 → 화주/기사 결과 재조회다. 촬영 준비 응답 전에는 사진을 찍지 않는다. 실제 앱 화면·캡처 시각·해시·단계·정본 상태를 별도 기록하며 미검증 단계는 보류로 남긴다.

직접적인 제품 기능 수정은 이번 검증에 포함하지 않는다. 시험 호스트의 수동 프로필·기존 adapter 연결과 로컬 검증 도우미가 필요한 경우에만 아래 허용 경로에서 준비하고 빌드·로컬 통신·소스 판본을 기록한다. 기존 완료/실패 증거와 원문은 덮어쓰지 않는다.

## 최종 결과

[실제 화면·업무 순서·남은 점](../../../../Changes/2026-10-21-cargo-ai-phone-verification-r1.md)이 이번 검증 결과의 정본이다. 같은 `phone-02` 의뢰·운송 `9`에서 실제 제품 AI `Applied` → 휴대폰 배너·수락 → 실제 카메라 상차/하차 사진 → 인수완료 → 화주 재조회를 마쳤다. SQL/Mongo와 두 사진의 결속·저장 바이트/SHA가 일치했다. 단말 증거는 별도 실제 PNG로 남기며 서버 proof의 단말 미인증 필드는 유지한다.

시험 호스트만 명시적으로 새 제품 AI 경로를 선택하도록 보완했고 구형 프로필·기존 실패 시도·운영 기본 OFF를 보존했다. 사진 전 완료 관문은 별도 UI 조회로 확인했다. 실제 물품 이동·외부 FCM/음성 청취·수금/지급·클라우드·모델 가중치 학습은 미검증이다. 기존 단말 설치판을 재사용했으며 새 APK 설치·제품 화면 수정·commit/push는 하지 않았다. 기사 화면 진입 재현, 화주 개발 문구/증빙 원장 안내, 운영 DB migration health는 후속으로 남긴다.
