# 배차 미응답과 자동 운행 종료 기획 r59

- 기획 ID: `PLAN-OPERATIONS-DISPATCH-CORE`, 판본 `dispatch-core.r59`, 2026-10-16.
- 상태: `DirectionAccepted / ThresholdOpen / SafeguardsProposed / ImplementationNotAuthorized`.
- 후속 정정: **현재 기준은 [r60](driver-no-response-receiving-off.design.r60.md)의 3회째 신규 수신 OFF·자동 운행 종료 없음이다.** 아래는 정정 전 문답 이력으로 보존한다.
- 이전 문답: [기사 관점 검토 r57](driver-dispatch-structure.review.r57.md). [가상 운영 구현 r58](virtual-quick-operations.implementation.r58.md)은 그대로 유지한다.
- 사용자 답변: 배차를 수락하지 않고 그대로 넘기는 경우, 모르고 운행을 켜둔 것일 수 있고 다른 기사에게도 영향이 있으므로 자체적으로 운행이 종료되는 방향을 제안했다.

## 수용한 방향과 해석 범위

배차 제안에 응답하지 않은 채 유효 시간이 지난 경우를 감지해, 방치된 운행을 자동으로 종료하는 방향을 수용한다. 실제 활동 중인 기사와 응답하지 않는 기사를 구별해 주문이 다음 기사에게 이어지도록 하려는 목적이다. 이것은 실제 기사에게 자동 종료를 이미 적용했다는 뜻이 아니다.

이번 답변은 **미응답 만료**의 방향으로 해석한다. 직접 거절 버튼을 누른 경우까지 같은 자동 종료 대상으로 삼을지, 단 한 번에 종료할지, 연속 횟수·확인 알림·유예 시간을 어떻게 둘지는 아직 미정이다. 미응답을 의도적 거절이나 기사 과실로 확정하지 않는다.

기존 질문 `quick-driver-waiting-preserve-on-offer`는 `AnsweredInPart / NonresponseAutoStopDirectionAccepted / WaitingClockUnresolved`로 이어진다. 자동 종료 전후의 대기시간 보존, 수락·완료 중 초기화 시점과 재운행 시 우선순위는 이번 답변만으로 결정하지 않는다.

## 다음 설계를 위한 보호 제안

아래는 개발자가 임의로 확정할 정책이 아니라, 방향을 구체화하기 위한 제안이다.

| 상황 | 제안하는 처리 | 확인할 경계 |
| --- | --- | --- |
| 수행 업무 없이 배차 제안에 미응답 | 정할 횟수·시간 기준을 충족하면 자동 운행 종료, 다음 후보 탐색 | 종료 이유 안내와 본인 운행 재시작 방법 |
| 이미 수락한 업무를 수행 중 | 신규 제안 수신을 중지하고 현재 업무·사진·완료 절차는 보존 | 실제 운행 종료를 현재 업무 종료 뒤로 미룰지 |
| 기사 본인이 명시적으로 거절 | 미응답과 별도 기록 | 거절의 활동 증거와 자동 종료 대상 여부는 별도 문답 |
| 알림 전송 실패·통신 장애·전달 여부 미확인 | 응답이 없다는 관측과 기사 부재 판단을 구분 | 실제 표시/수신 확인, 장애 중 집계·복구 기준은 미정 |
| 만료·수락·종료가 동시에 발생 | 서버에서 현재 제안 차수·기사·수행 업무를 다시 확인 | 성공한 수락을 자동 종료나 다음 추천이 덮지 않도록 함 |

추천 시점, 전송 요청, 실제 알림 전달, 기사 응답을 같은 사실로 합치지 않는다. 알림 전송 성공을 사람이 읽었다는 증거로 사용하지 않는다. AI 학습 자료에 이 미정 기준을 확정 정답으로 넣지 않는다.

## 현재 코드와 구현 인계 한계

현재 `운행종료CommandHandler`는 기사 권한과 운행 전이 잠금 아래 SQL 근무를 종료하고 실행 인덱스를 정리한다. 읽은 `Handle` 범위에는 수행 중 운송 유무로 종료를 보류하는 검사가 없다. 따라서 추천 만료 때 기존 종료 명령을 그대로 자동 호출하는 것으로 보호 설계가 충족된다고 볼 수 없다.

추천 만료·다음 후보 탐색과 자동 운행 종료는 다른 결과다. r58 훈련 배우의 정해진 시각 수신 중단·기존 업무 완료 후 운행 종료도 이번 미응답 정책의 구현 증거가 아니다. 이번에는 문서만 갱신하며 제품 코드·설정·DB·APK·모델·실제 운행은 변경하지 않는다.
