## 구현 기준

1. 후보 선정·추천 저장/조회·신규 수락·연속 탐색은 공통 신규 수신 ON/OFF·미응답 중지를 대조한다. 이미 확정한 업무의 재조회·동일 요청 복구·완료는 신규 수신 중지 때문에 막지 않는다. 현재 상태를 확인하지 못한 경우 신규 추천/수락을 임의 허용하지 않는다.
2. 수행 중이면 기존 전체 업무의 마지막 목적지·완료 예상시각을 다음 픽업 출발 기준으로 사용한다. 현재 위치 밖이라도 끝점 근처의 수행 중 후보를 제한된 후보 집합에서 검토한다. 유휴 이동에는 현재 GPS를 사용한다. 실제 경로·일정 근거 미확인을 0이나 수행 가능으로 채우지 않고 기존 일정·적재·차량·시간창·추천 차수를 보존한다.
3. 후속 기준 보완 자체는 기본 적용하되 실제 자동배차/연속배차를 새로 활성화하지 않는다. 새 `화물수행종료기준사용` 옵션이 필요하면 기본 true이며, 기존 `FreightContinuity.Enabled=false`·`ShadowMode=true`·운임 정책 비활성 및 SharedDriverWork 기본 OFF는 유지한다.
4. 다음 콜 B를 수락해도 서버가 정한 현재 업무 A의 카드·경로를 유지한다. A 완료 후 B로 전환하고 전경에서 제한된 보완 조회·복귀 조회를 수행한다. 중복 조회·계정 변경·늦은 응답·조회 실패 때 마지막 확인 상태와 현재 행동 보호를 유지한다.
5. 퀵 네이티브 지도 좌측 상단의 신규 수신 토글을 기존 화면에 연결한다. 운행 시작의 최초 ON은 시작 전 수신 의사 판본을 서버에서 원자적으로 비교해 수동 OFF를 덮어쓰지 않으며, 미응답 중지 해제 의사를 담지 않는다. 본인의 토글 ON만 명시 재개한다. 실제 표시된 유효 최신 제안 한 건을 기존 인증 표시 확인 API에 연결한다. 사람의 읽음·알림음 청취는 인증하지 않는다.
6. 연속배차 조회/변경 API는 기존 국내 화물 실행 Feature로 분류해 미분류 404를 해소한다. 음식 Feature만으로 화물 기능을 열지 않는다. 다음 콜 보유의 판본·만료·소유와 기존 수락 검사도 보존한다.

## 검증과 경계

- 신규 수신 OFF/세 번째 미응답·초기 자동 ON·수동 재개, 기존 A 복구/완료, 미래 끝점 주변 후보·미확인 경로·시간창·적재, B 수락 뒤 A 유지·A 완료 뒤 B·조회 실패·계정 변경을 시험한다.
- 실제 API Feature ON/OFF, 인증 client 계약, 관련 소비자 빌드와 Android 컴파일, 저장소 Fast/Task를 실행한다. UI는 headless 상태/렌더 근거와 실제 물리 기기를 구분한다.
- 기존 보안 정책으로 차단된 브라우저 미리보기 경로를 재시도하거나 우회하지 않는다. 이번 요청에서 휴대폰 설치·실제 주행/푸시/청취·외부 운영·commit/push는 수행하지 않는다.
- 상세 소유 파일·기준선·해시·검증은 `quick-driver-continuity.r64.work-order.json`과 최종 변경 기록에 결속한다. 구현 전 승인과 실제 시험 완료는 다른 상태다.
