## 승인 범위와 책임

`eng/Ssalddel.DispatchTraining/`의 전용 Development/Simulation 호스트를 기존 화물 HTTP·DB 검증 구조에 맞춰 만든다. 서버 5324, 전용 MySQL 13312의 `ssalddel_dispatch_training`과 Mongo 27023만 사용한다. 제품·기존 검증 환경의 설정·DB·볼륨과 교차하지 않는다. 전체 hosted service 대신 이 훈련의 조율자만 실행하며 실제 접수·운행·추천·수락·수행 API와 전문 정책을 재사용한다.

초기 합성 계정은 관리자·화주·기사 8명이다. 기사 6명이 신규 수신을 시작하고 지원 기사 2명은 운영자의 명시 참여를 기다린다. 합성 차량·주소·요금·사진 입력은 fixture이며 실제 건물·기사·물품·사진 촬영 증거가 아니다. 원장 상태를 도구가 직접 완료로 덮어쓰지 않는다. 외부 결제·송금·푸시·지도 API와 운영 DB는 연결하지 않는다.

제품 변경은 화물 후보 정책의 동작 보존 관찰, 관리자 앱의 훈련 기능 소비, 공유 계약과 관련 검증으로 제한한다. 대기 순서·단가·후속 수행·혼합 운반 정책은 이번에 변경하지 않는다. 기존 미커밋 WAV·Git 보호 도구와 이전 기획 변경을 보존하며 commit/push는 포함하지 않는다.

## 세션과 업무 흐름

- 실제 시계 30분, 0~28분의 2분 간격, 최대 15건이다. 고정 요청 ID·회차·사건 순번을 먼저 보존한다.
- 새 주문 발생 중지 후에도 진행 중인 업무는 계속 처리한다. 30분 뒤 신규 발생을 끝내고 기존 업무를 마감한다. 미확인 요청·미해결 사건을 완료로 바꾸지 않는다.
- 재시작하면 신규 발생은 일시정지한다. 지난 발생 슬롯을 몰아서 접수하지 않는다. 응답 유실은 같은 요청 번호로 정본을 조회하며 무조건 POST를 반복하지 않는다.
- 기존 규칙이 실제 검토한 후보를 기록한다. 거절·추천 만료·신규 수신 중단의 사례를 넣고 지원 기사 참여는 모바일의 명시 명령으로만 진행한다.
- 세션 JSON은 원자 저장한다. 중단된 시험을 명시 보관하는 CLI는 호스트 lease를 확인하고 파일·해시를 보존하며 업무 취소나 DB 초기화를 하지 않는다.
- 완료된 회차에서 새 시작 전에는 이전 세션 원문을 별도로 동결·해시 대조한다. 보존 실패 시 시작하지 않는다. 18분 이후의 기사 부족 사례는 주문 슬롯 생략과 분리하며 기본 기사들은 기존 업무를 마친 뒤 정상 운행 종료 API를 사용한다.

## AI 비교와 모바일 화면

현재 화물 자동 후보 계산을 한 번만 수행해 선택 후보·점수·탈락 이유를 관찰한다. 제품 기본 등록·정렬·선택은 유지한다. local observer만 등록한 훈련 호스트에서 익명 토큰·거리·기본/대기/총점을 비교에 사용한다.

AI는 기존 로컬 `qwen3:1.7b`, loopback 12681만 사용하며 복수 후보에 한해 회차별 최대 15회·요청당 2초다. 지연·오류·허용 밖 선택은 비교 불가로 보존하고 실제 추천을 바꾸지 않는다. 호출 예약 수는 재시작으로 초기화하지 않는다. 모델 설치·다운로드·가중치 학습은 하지 않는다.

기존 관리자 APK의 화물 현황·운송 상세·문제 처리 책임을 유지한다. `/training/dispatch`는 세션 상태와 제어, `/training/dispatch/decisions`는 판단 비교를 소유한다. 현재 회차·잔여 시간·발생/대기/수행/완료·기사·사건·AI 비교를 보여준다. 후보 수치는 접어서 확인하고 미확인을 0으로 표시하지 않는다.

훈련 전용 `/verification/dispatch-training` 계약은 capability·current·start/pause/resume/stop/support-drivers·decisions/incidents를 제공한다. capability는 활성 여부만 공개하고 나머지는 전용 합성 서버관리자 인증을 요구한다. 제품 호스트에는 이 endpoint를 등록하지 않으며 미지원 서버에서 훈련 진입을 숨긴다. 명령 ID와 revision, 전경 5초 조회·복귀 재조회·계정 변경 후 늦은 응답 폐기를 적용한다.

## 검증과 인계

검증은 단계별로 기록한다: 정책/모바일 집중 시험, 가짜 시계 제어 검증, 실제 격리 HTTP·DB 흐름, Razor 화면 검토, 단독 설치 가능한 APK, 실제 휴대폰. 앞 단계 성공을 뒤 단계 완료로 승격하지 않는다.

초기 실제 HTTP 시험에서 기사 설정의 차량 종류와 위치 갱신의 앱 식별자 입력 오류를 발견했다. 실패 회차를 보존하고 `Motorcycle`/`CargoYongdalDriverApp` stable ID로 보완했다.

자동 배차 정책 블록이 붙은 정상 신청 메모를 기존 기사 정보 제공 동의 서비스가 읽지 못하는 제품 오류도 발견했다. 정확한 GUID와 기존 출처·회원 배송·배차 정책 경계를 읽도록 보완하며 소유자·동의 원문·철회·확정 기사·추천 차수 검사는 유지한다. 신규 30개를 포함한 동의 집중 40개와 전체 Task 12,100개가 통과했다(환경 의존 16개 미실행). 실제 호스트 재검증에서는 수정된 동의 이후 사진 픽업·전달 절차를 사용한다.

최종 로컬 회차는 30분 발생 창의 15슬롯 중 7건을 접수하고 8슬롯을 중지·재시작으로 생략했다. 실제 API에서 7건 모두 정상 수락·동의·합성 사진 업로드·픽업·전달 완료됐고 SQL 7건 및 Mongo `cargo-transport` 7건의 완료 상태를 대조했다. 지원 2명 참여와 기본 기사 6명 운행 종료도 확인했다. 15건 무중단 완료는 주장하지 않는다. 가짜 시계·복구 자체 검증 14개를 별도로 통과했다.

회차는 `Completed`이나 재시작 확인 메모 1개는 `ReviewRequired`로 보존했다. AI 기록은 시간 초과·한도 소진·단일 후보 생략이며 성공 비교·판단 품질 개선은 미확인이다. APK 내장 코드 대조는 통과했고 미리보기 기동은 자동 승인 검토의 `blocked by policy`로 거절돼 실제 화면·휴대폰 검증은 별도다. [최종 변경·근거](../../../../Changes/2026-10-16-virtual-quick-operations-r58.md).
