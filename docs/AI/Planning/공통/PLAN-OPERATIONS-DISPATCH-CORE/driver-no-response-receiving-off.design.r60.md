# 세 번째 연속 미응답부터 신규 배차 수신 중지 r60

- 기획 ID: `PLAN-OPERATIONS-DISPATCH-CORE`, 판본 `dispatch-core.r60`, 2026-10-16.
- 상태: `ThresholdAndActionAccepted / RecoveryPolicyOpen / ImplementationNotAuthorized`.
- 후속 답변·검증: [본인 수신 재개와 기존 토글 확인 r61](driver-dispatch-reception-toggle.review.r61.md). 본인이 토글을 켜서 재개하는 방향은 답변됐으며, 아래 질문은 r60 당시 이력이다. 자동 미응답 중지·재개는 제품 구현 전이다.
- 이전 문답: [미응답·자동 종료 제안 r59](driver-no-response-auto-stop.design.r59.md). r59는 당시 이력으로 보존하며 아래 사용자 정정을 현재 기준으로 삼는다. [가상 운영 r58](virtual-quick-operations.implementation.r58.md)의 구현·검증 상태는 유지한다.
- 사용자 최신 정정: **두 번 연속까지는 괜찮고, 세 번째부터 신규 배차를 끈다. 운행 종료까지 하는 것은 과하다.** 발화 초반의 두 번보다 뒤의 세 번 정정을 우선한다.

## 확정한 방향

| 연속 미응답 횟수 | 신규 배차 수신 | 운행·이미 맡은 업무 |
| --- | --- | --- |
| 1회 | 유지 | 유지 |
| 2회 | 유지 | 유지 |
| 3회째 | OFF로 전환 | 유지 |

각 제안의 만료·다음 후보 탐색과 기사 전체의 신규 수신 의사 전환을 구분한다. 세 번째 미응답 이후 **신규 배차 수신만 중지**하며 운행 종료 명령을 호출하거나 이미 수락한 배달을 취소·완료·종결하지 않는다. 맡은 배달의 정보 확인·사진·수행·예외 복구는 계속 가능해야 한다. 이 정책은 새로 제안하는 배차를 대상으로 하며 기존 확정 업무를 새 배차로 세지 않는다.

기존 질문 `driver-no-response-auto-stop-threshold`는 `AnsweredWithCorrection / ConsecutiveMissesThree / ReceivingOffOnly / NoAutomaticWorkStop`으로 기록한다. r59의 자동 운행 종료 방향과 제안된 2회 기준은 이번 정정으로 대체한다. 실제 제품에 이미 적용됐다고 표시하지 않는다.

## 구체화할 경계

다음 항목은 아직 확정하지 않는다.

- 연속 미응답 집계의 초기화 조건: 수락·명시적 거절·수신 재개·시간 경과 중 어떤 경우에 초기화할지.
- 직접 거절 버튼을 누른 경우와 무응답 만료의 구분. 이번 답변을 직접 거절 3회에도 적용된 것으로 해석하지 않는다.
- 알림 실패·통신 장애·전달 여부 미확인의 집계 기준. 전송 요청·FCM 발송 성공을 기사 확인으로 단정하지 않는다.
- 세 번째 제안과 다른 제안의 수락, 수신 OFF가 동시에 발생할 때의 재검사·후속 처리.
- 수신 OFF 이후 다시 켜는 주체·방법, 사유 안내·확인 알림, 대기시간 보존과 재개 후 우선순위.

같은 제안의 알림 재전송을 서로 다른 미응답으로 중복 집계하지 않는 보호를 제안한다. 현재 기사·제안 식별자·추천 차수와 정상 만료 근거를 대조할 수 있어야 하며, 구체 집계 방식은 다음 개발 명세에서 검증한다. 과실·고의 거절·소득 불이익을 새로 결정하거나 미정 기준을 AI 학습 정답으로 넣지 않는다.

## 현재 구조와 구현 경계

프로젝트에는 운행 상태와 별개인 신규 배차 수신 의사 `On/Off` 계약이 있다. 향후 구현은 이 수신 중지 의미를 재사용하는 범위로 검토한다. 기존 `운행종료Command`는 이번 자동 처리의 대상이 아니다. 기존 API가 있다는 사실만으로 연속 3회 집계·알림·복구·모든 전문 엔진 적용이 완료된 것으로 보지 않는다.

현재 본인 수신 의사 변경은 `DriverExplicitIntent`로 기록되고, 서버의 실효 추천 정지는 별도다. 자동 미응답 정지를 기사 본인이 OFF를 선택한 사건으로 위장하지 않도록 원인·주체를 구분하는 설계를 제안한다. 화면의 신규 수신 중지와 재개 방식은 이 차이를 반영해 구체화한다. 근거는 `기사운영배차공통Controller.cs`, `운영배차공통UseCase.cs`, `운영배차수신상태Policy.cs`다.

이번에는 기획 본문·목차만 갱신한다. 제품 코드·설정·DB·APK·모델·실제 운행과 r58 훈련 배우 동작은 변경하지 않는다. 기존 대기시간 질문과 직접 거절·통신 문제의 미정도 보존한다.
