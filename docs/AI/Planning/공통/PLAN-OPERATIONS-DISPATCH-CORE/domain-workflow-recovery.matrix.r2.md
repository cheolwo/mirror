# 업무 단계·예외·복구 대응표 r2

기준: [승인 계획](domain-workflow-recovery.r2.md). 아래 표는 업무 검토·구현 범위를 연결한다. 카탈로그 순서로 상태를 강제하거나 미확정 명령을 반복하지 않는다. 실행 조건과 결과는 전문 원장/Policy/UseCase가 소유한다. 표의 ‘후속’은 이번에 코드 반영·실행 검증 완료라는 뜻이 아니다.

## 화주·화물 한 건

| 단계/정본 | 정상 결과 | 대표 예외·대기 | 복구·담당 | 화면의 주 행동 | r2 범위 |
| --- | --- | --- | --- | --- | --- |
| 화주 접수 `shipper.request-commitment` | 의뢰 ID/조건 확정 | 필수 입력/가격·조건 변경, 접수 응답 불명 | 기존 입력/요청 ID를 보존하고 같은 요청 결과 조회. 화주 | 입력 보완 또는 접수 결과 확인 | 기존 접수 복구 유지. 상세 조회 문맥 연결 |
| 배차 `cargo.dispatch` | 유효 추천과 본인 수락 | 기사 없음은 대기 상태. 제안 종료/다른 기사 수락/응답 불명은 구분 | 현재 제안·운송 조회 뒤 허용 후보 확인. 기사·배차 서버 | 추천 보기 또는 수락 결과 확인 | 기존 배차 규칙/허용 행동 유지. 개별 수락 사유 전수 적용은 후속 |
| 상차 `cargo.pickup` | 필수 확인·증빙 충족 후 상차 완료 | 사진 누락·검증 장애, 창고 인계 미완료, 운송 보류, 상태 변경 | 완료 전 guard는 확정 미적용. 조회/사진 확인/인계 완료 후 현재 상태 확인. 담당 역할은 기존 인계/사건 권한 사용 | 상차 확인·결과 확인·현재 운송 | 사유/문맥·조회 UI 연결. 새 업로드/인계 권한 추가 없음 |
| 운송 `cargo.transport` | 같은 운송 상태와 다음 행동 | 통신 실패·지연·현장 사고/보류 | 통신은 재조회, 실제 사건은 기존 현장 처리로 인계. 기술 오류로 사건 생성 금지 | 현재 운송 또는 문제 처리 | 조회 문맥 연결. 현장 사건 정책 유지 |
| 하차 `cargo.dropoff` | 증빙·인수 조건 충족 후 완료 | 전달 사진/인수 근거 누락, 상태 변경/보류, 응답 불명 | 기존 사진/요청 유지, 같은 완료 결과 조회. 확정 미적용과 미확정 구분 | 하차 확인 또는 완료 결과 확인 | guard 문맥·조회 UI 연결 |
| 화주 인수 `shipper.delivery-acceptance` | 확인된 인수/검수 기록 | 파손·미수령·수량 불일치 | 기존 인수증·보호지원 사건의 담당자/판정 절차 유지 | 증빙 확인·문제 접수 | 기존 업무 그대로, 오류 안내가 사건 종결을 대신하지 않음 |
| 정산 `cargo.evidence-settlement` / 화주 정산 | 완료 증빙·재원·보류 조건에 따른 정산 상태 | 신고 보류·재원 부족·지급 결과 불명 | 전문 정산·지급 원장을 각각 확인. 고객지원/정산 담당자 | 정산 현황·처리 현황 | 도메인 대응표만. 금전·원장 정책 변경 없음 |

각 조회의 `NotApplicable`은 상태 변경을 요청하지 않았다는 뜻이다. `NotApplied`는 서버가 변경 전에 명시적으로 거절했을 때만 사용한다. `Applied`는 해당 저장 응답이 확인된 작업이며 후속 조회까지 성공했다는 뜻이 아니다. `Unknown`은 요청이 반영되지 않았다는 의미가 아니므로 결과 확인을 우선한다.

## 입고 한 건의 결과 확인

| 상황 | 결과 구분 | 보존·복구 | 표시/행동 |
| --- | --- | --- | --- |
| 신청 또는 완료 POST의 성공 응답 확보·후속 GET 실패 | Applied | 응답의 입고 ID/결과 보존, 같은 ID GET만 재조회 | 등록/완료 결과 조회 필요 |
| POST 명시적 업무 거절 | NotApplied | 기존 입력 유지, 거절 조건 보완 | 업무 사유와 입력 보완 |
| POST 통신 끊김/시간 초과/결과 불명 | Unknown | 같은 페이지 세션에서 재제출을 막고 기존 목록/대상 확인 | 접수 또는 완료 결과 확인 |
| 정상 상세 GET 실패 | NotApplicable | 조회 미완료와 실제 대상 없음 구분 | 입고 내역 확인 |

일반 계약 기반 입고에는 서버 멱등 요청 ID·영속 미확정 복구 계약이 아직 없으므로 새 엔진을 이번에 추가하지 않는다. 이번 페이지 세션의 재제출 방지와 앱 재실행 이후 중복 방지 보장을 구분한다. 후자는 별도 계약 보완이 필요하다.

## 다른 OS의 적용 순서

음식은 기존 메뉴 변경 코드와 주문 접수 미확정 복구, 음식점 조리/픽업 허용 조건부터 연결한다. 창고는 검수 수량 보류·피킹/포장·인계 각각의 상태와 기존 담당자를 따른다. 공동구매·수입·생활 신뢰·플랫폼·교육은 각 전문 업무의 허용 행동/동의/사람 검토를 재사용한다. 이러한 후속 목록은 해당 업무의 runtime 적용 완료가 아니다.

## 표현 규칙

필드 누락은 입력 위치, 정상 대기는 업무 상태 카드, 즉시 판단이 필요한 실패는 짧은 다이얼로그, 지속 현장 문제는 기존 문제 처리 화면으로 표시한다. 진단 코드·raw body·trace·개인정보는 제품 본문에 복제하지 않는다. 권한/현재 상태가 불명확하면 취소·배차 종료·사진 손실을 추정하지 않는다. 복구 버튼은 현재 서버 행동과 기존 GET/로컬 navigation에만 연결하며 UI가 새 완료 명령을 만들지 않는다.
