# 화물 Android 업무 복구·설정 연결 r124

상태: `ApprovedByDirectUser / ImplementedAndAndroidValidated / FullConsumerBuildBlocked / PhysicalUiNotVerified / OperationalDisabled`.

실제 결과·검증 범위와 남은 제한은 [r124·기사 후속125 검증 기록](../../../../Changes/2026-10-26-cargo-android-recovery-r124.md)을 따른다.

사용자는 2026-10-26 Android 실화면 점검 뒤 “부족한 부분 보완해 줘봐”라고 수정 작업을 요청했다. [직전 점검](../../../../Changes/2026-10-26-cargo-android-role-review.md)의 재현된 결손을 기존 원장·권한·API 안에서 고친다. 이전 Android 점검과 소스·시험 증거는 보존한다. 구현 지시의 기준은 함께 저장한 `cargo-android-recovery.r124.work-order.json`이다.

## 구현 범위

1. 화주 홈은 본인에게 허용된 입고·재고 요약을 조회한다. 작업자 전용 창고목록에 권한을 추가하거나 조회 실패를0으로 숨기지 않는다. 새 요약이 필요하면 인증 Claim의 본인 소유 범위에서 건수만 반환한다.
2. 통합 기사 작업공간에서 기존 업무·차량·적재 설정을 입력·저장·재조회할 수 있도록 기존 shared form과 정상 제품 API를 연결한다. 별도 기사 앱은 보존한다.
3. 통합 추천 상세에 거절·수락을 구분한다. 거절은 사유·현재 추천 판본·명시 확인과 기존 서버 처리/결과 재조회로 연결하고 미확정 결과를 무조건 재전송하지 않는다.
4. 만료·변경·현재 계정에 없는 추천 선택은 읽기 성공한 현재 추천/운송으로 돌아간다. 조회 실패·권한 실패를 성공으로 바꾸지 않고, 과거 후보를 자동 재추천·수락하지 않는다.
5. 권한 없는 역할에 진입했더라도 해당 계정의 정상 로그아웃·다른 계정 로그인으로 복구할 수 있게 한다. 권한을 자동 부여하지 않는다.
6. 독립 기사 앱은 Firebase가 미설정/초기화 실패여도 일반 업무 UI가 시작되게 한다. Push 실패는 Push 성공으로 표시하지 않고 고정된 비밀정보 없는 진단만 남긴다.
7. 운송주선업무는 기존 `my-ledgers`의 정확한 `국내 화물 운송` 필터와 정본 context 조회, 기존 공개 화물정보·본인 정보공고 관리로 연결한다. 별도 `/workspace/freight-broker` 화면과 primary 로그인 진입을 제공한다. 역할 선택은 인증 권한을 부여하지 않는다. 원장 접근은 서버의 본인 권한을 그대로 사용하며 업체 전체·허가·직원 소속 확인으로 표현하지 않는다. 서버관리자·같이수입 관세사 권한은 재사용하지 않는다. 업체 의뢰 위임·차량 배정·수수료/업체 정산 원장은 이 범위에 없다.
8. 기존 내 정보 화면의 고정 방문자 표시는 실제 복원한 인증 상태와 본인 표시명으로 바꾼다. 새 계정·권한을 만들지 않는다.
9. 실제 GUI 거절은 성공했으나 기존 서버가 사유 없는 overload를 호출해 활동사건을 NotProvided로 남기는 결손을 보완한다. 현재 UI의 정확한 선택 문구와 기존 코드만 안전한 사유 코드로 매핑하며 미입력·기타를 구분한다. 활동사건과 사후 이벤트에는 분류 코드만 전달하고 자유문구를 새 원장·로그에 복제하지 않는다. 과거 사건은 사후 수정하지 않는다. 이 서버 후속 보완은 앞서 만든 APK·실제 거절 사건의 사유 보존 검증으로 승계하지 않는다.
10. 독립 기사 앱의 실제 종료 후 요약이 이전 캐시의 운행중을 계속 표시하는 결손을 보완한다. 확정 시작·종료 뒤 기존 본인 범위 상태를 force 재조회하고 같은 계정·세션을 다시 확인한다. 재조회 실패는 확정된 종료를 실패로 뒤집지 않으며 최신 표시 미확인을 구분한다. 이 변경은 독립 기사 후속 APK125로 빌드하며 기존 APK124의 실행 근거를 보존한다.

## 페이지 책임 카드

### 통합 기사 업무·차량 설정

- 사용자 질문: 어떤 업무를 어떤 차량·적재 조건으로 받을 것인가?
- 경로: `/workspace/cargo-driver/settings`. 기존 `DriverWorkParticipationScreen`과 서버 참여설정 원장을 소비한다.
- 기본 정보: 받을 업무, 차량 종류·수행 가능 중량/부피, 동시업무 조건, 현재 저장 결과.
- 상태: 로그인 필요·권한 없음·조회 중·미설정·저장 중·저장 실패·결과 미확정·저장 확인을 구분한다. 실패 후 입력을 보존하고 서버 재조회 없이 저장 성공을 만들지 않는다.
- 행동/복귀: 명시 저장·재조회, 화물기사 현재 업무로 복귀. 설정 저장만으로 운행·신규배차 수신·추천·계약을 자동 실행하지 않는다.

### 통합 추천 상세의 참여·거절

- 사용자 질문: 현재 제공된 이 한 건의 조건을 확인하고 맡거나 거절할 것인가?
- 정보: 현재 운송의 상하차·중량/수량·시간·예상 보수와 유효기간·차량 적합/주의사항.
- 행동: 왼쪽 거절과 사유, 오른쪽 운송 참여. 수락의 기존 확인과 요청ID·결과 확인을 보존한다. 거절 응답 불명확 시 재조회·상태 복구를 먼저 한다.
- 복귀: 실제 수락된 현재 운송 또는 현재 추천/대기로 이동한다. 만료된 추천을 선택한 채 일반 오류에 갇히지 않는다.

### 화주 홈 요약

- 사용자 질문: 내 운송 의뢰와 내 입고·재고 상태는 어떠한가?
- 권위: 기존 운송 의뢰 및 인증 본인 범위의 입고·소유 재고. 창고 작업자 목록을 대체 권한으로 노출하지 않는다.
- 표시: 성공한 건수, 미집계/실패 경고와 재시도·업무 상세 이동을 구분한다. 타인 소유 범위·연락처·주소·재고 세부를 요약에 반환하지 않는다.

### 운송주선업무 정보 작업공간

- 사용자 질문: 내가 접근하는 화물원장의 현재 내용과 내가 관리하는 정보공고는 무엇인가?
- 경로: `/workspace/freight-broker`. 통합 MAUI·WebApp의 같은 shared 화면이며 홈 화물 그룹에서 진입한다.
- 기본 정보/행동: 본인 접근 국내 화물원장 목록→선택한 원장의 정본 context 조회, 기존 공개 정보공고 탐색·본인 공고 작성/수정/명시 공개/철회 화면 연결.
- 경계: 정확한 WorkflowTag를 쓰고 다른 업무의 응답을 허용하지 않는다. 없는 조건제안·배차·수수료·송금 버튼이나 모의 금융 수치를 만들지 않는다. 업체 조직/허가 검증과 본인 접근 가능 기록을 구분한다.
- 상태/복귀: 로그인 복원·익명·조회 중·빈 목록·403/404·조회 실패·계정 전환을 구분하고 이전 계정의 원장/선택 응답을 지운다. 역할 선택·같은 정보 작업공간으로 복귀한다.

## 검증과 제외

수정된 소유권·만료/거절·미확정/실패 회귀를 먼저 실행하고 영향 소비자 빌드를 확인한다. 실제 검토 APK에서 화주 홈·기사 설정·추천 거절/만료 복귀와 독립 기사 시작을 재현한다. USB 실기기가 잠겨 있으면 에뮬레이터 검증과 분리해 보고한다. 공유 Docker·운영 DB·원래 앱 데이터·다른 dirty work는 보존한다. 법적 적격 판정·운영 게이트·실금전·운영 배포·기관 발송·자동 게시·commit/push는 포함하지 않는다.
