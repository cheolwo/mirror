## 한 가지 결과

화주가 입력한 같은 포장 1개의 외포장 치수·포장 수량·총중량·입력 CBM·회전/적층 조건을 서버 추천, 단건/일괄 접수, 수정·재조회, Mongo 원장과 SQL 투영, 기사 적합성 판정이 같은 의미로 사용한다. 추천 결과가 현재 입력이나 현재 계정과 다르면 적용하지 않는다.

## 계산·호환 경계

1. Contracts의 순수 `화물적재입력Policy`가 원입력, 유효 부피, 치수×수량 추정 부피, 비적층 바닥면적, 계산 판본과 입력 지문·경고·오류를 반환한다. 총중량은 수량을 다시 곱하지 않고 판정용 decimal 정밀도를 보존한다.
2. 양수 직접 입력 CBM과 치수 추정 CBM을 각각 보존하고, 판정에는 두 값 중 큰 값을 쓴다. 직접 입력이 더 작으면 경고와 보수적인 치수 추정 근거를 남긴다. 이 계산은 실측 확인을 의미하지 않는다. 명시된 0/음수는 오류다. 누락 수량은 기존 기본값 1을 경고와 함께 적용하며 원입력 null은 보존한다. 구형 회전/적층 누락도 기존 true 가정과 미확인 경고를 구분한다. 신규 화면은 수량 1과 두 선택을 명시한다.
3. `화주운송의뢰`가 유효 CBM과 원입력 CBM·근거 code·계산 판본·nullable 회전/적층을 소유한다. 새 nullable 5열 migration을 준비하되 DB에는 적용하지 않는다. 구형 자료를 신규 사용자 확인값으로 소급하지 않는다.
4. GET의 기존 Cargo CBM은 유효값을 유지하고 추가 적재조건 snapshot에 원입력/근거를 제공한다. 구형 GET→PUT의 같은 유효값 재전송은 원입력으로 승격하지 않는다. 직접 부피 지우기는 별도 의도이며 양수 값과 동시에 요청하면 거절한다. 핵심조건 잠금·변경 검출, Mongo null 초기화와 재투영을 함께 보완한다.
5. 추천과 기사 판정이 같은 정규화를 읽고 기존 전문 취급/장비 조건·원장 권위·접수 동의·멱등·권한을 보존한다. 새 정책은 DB/차량을 조회하거나 운영 효과를 실행하지 않는다.
6. App/Web은 현재 화물의 서버 응답으로 추천하고 로컬 20kg OR CBM 간이 추천·고정 후보 fallback을 제거한다. 응답은 요청 순번·계정 판본·현재 입력 지문이 맞을 때만 사용하며 차량 적용은 사용자의 명시 행동이다. 초안 복원·초기화·계정 변경은 추천을 폐기한다. 초안의 실제 저장 범위를 확대 주장하지 않는다.

- Persistence 담당: Command/UseCase/handler, 단건·수정·일괄·조회, 도메인·EF·migration, Mongo/SQL 왕복, 관련 시험.
- UI 담당: 공용 작성 상태/화면, App/Web adapter·draft·추천 응답 경쟁 보호, 페이지 책임과 로컬 렌더 fixture.
- 통합 담당: 메인 공유 DTO, 허용 경로/해시 관리, 연계 검토, 최종 시험·화면 증거·변경 기록.
