# 운영후원 공개와 활동 기여자 소개 r11

상태: DesignRecorded / ImplementationNotStarted. 작성일: 2026-10-22.

관련 기획: [누적 성과 홈 r10](home-participation.r10.md). 이번 문서는 사용자와 이어가는 후속 기획이다. r10 제품·검증 상태를 변경하거나 실제 후원 수납·공개 순위·연락처 공개·강사 권한을 활성화하지 않는다.

## 사용자가 정한 방향

- 서버·DB 등의 운영비를 참여자의 후원으로 충당하고, 후원과 실제 사용 내역을 앞단에서 확인할 수 있게 한다.
- 초기에는 운영자가 직접 부담하고, 후원이 들어오면 실제 운영비 중 후원금과 운영자 자체 예산으로 각각 충당한 금액·비율을 사용자에게 보여 준다. 2026-10-22 후속 요청이며 아래 비율 기준으로 구체화했다. 화면·집계 구현은 아직 아니다.
- 활동이 많은 화주와 기사에게 경험을 나누는 기회를 제공한다. 두 역할의 활동은 구분해 소개한다.
- 소개 기준은 **완료 건수·약속 준수·문제 해결을 함께 반영**한다. 사용자가 선택한 기준이며 아직 숫자 가중치나 최종 순위식까지 정한 것은 아니다.
- 후원액은 활동 순위와 분리한다. 상담·교육 참여와 공개 소개는 본인이 동의한 경우에 연결한다.
- 홈의 성과·참여 현황은 기존처럼 전체 누적을 기본으로 한다. 순위의 별도 비교 기간·최소 표본·가중치는 후속 결정이다.

## 홈과 상세의 책임

```text
함께 만든 성과 · 전체 누적
├─ 기존 성과·참여 요약
├─ 운영후원 요약 → 후원·사용 내역
│  ├─ 확인된 후원 입금
│  ├─ 후원으로 충당한 운영비
│  └─ 집계 잔액
├─ 활동 기여자 소개 → 경험 나누는 사람들
│  ├─ 화주 / 기사 별도 목록
│  ├─ 본인이 공개에 동의한 활동 근거
│  └─ 질문·도움 / 검토된 물류 교육
└─ 기존 업무 시작과 안내 링크
```

홈은 짧은 현황과 상세 진입만 소유한다. 후원 전체 장부, 긴 순위표, 상담 접수와 교육 운영을 홈에 펼치지 않는다. 기존 플랫폼 확정 이익·공동분배 지급액을 후원금과 합치거나 후원 사용액으로 재명명하지 않는다.

| 화면 | 이용자의 한 가지 질문 | 기본 표시와 다음 행동 |
| --- | --- | --- |
| 공통 홈의 후원·기여 요약 | 함께 운영하고 활동한 현황은 어떤가? | 확인 가능한 누적 요약·집계 시각·상세 진입. 기존 역할 진입 보존 |
| 후원·사용 내역 | 들어온 후원금이 어디에 쓰였는가? | 입금·반환·서버/DB 등 사용 분류·충당액·집계 범위. 비공개 증빙 원문은 제외 |
| 경험 나누는 사람들 | 어떤 경험을 가진 참여자에게 도움을 청할 수 있는가? | 공개 별명·역할·확인된 활동 근거·상담/교육 참여 의향. 질문 또는 승인된 과정으로 이동 |

위 화면과 진입은 설계이며 아직 새 route가 구현된 것은 아니다. 시각·상태 기준은 [페이지 단일 책임](../../../../Architecture/WholeRoadmapPagePrinciple.md)과 [역할 앱 시각 기준](../../../../Architecture/RoleAppVisualDesignStandard.md)을 재사용한다.

## 후원과 운영비의 기록 기준

후원 약속, 결제 승인, 실제 플랫폼 계좌 입금, 환불과 실제 운영비 지출을 구분한다. 공개값은 다음 근거가 준비된 경우에만 집계한다.

1. 후원별 실제 입금과 반환의 확인 근거 및 중복 방지 식별값.
2. 서버·DB·저장소 등 비용의 실제 청구·지출 근거와 기간.
3. 해당 비용 중 후원금으로 충당한 금액의 연결. 전체 서버 청구액과 후원 충당액은 다를 수 있다. 같은 비용·입금을 중복 충당하지 않는다.
4. 잔액은 확인된 기초잔액 + 입금 − 반환 − 후원 충당 지출이다. 입금 순액에 이미 반영된 수수료는 다시 빼지 않는다. 기초잔액이나 증빙 범위가 불명확하면 잔액은 미집계로 둔다. 이 집계 잔액을 회사 전체의 가용현금이나 은행 대사 완료로 표시하지 않는다.

후원금의 자금 구분은 상품·배송 대금 및 참여자에게 지급할 돈과 분리한다. 기존 재무사건·증빙·원본 revision/hash 패턴을 재사용할 수 있지만 재무 원장을 복제해 별도의 진실을 만들지 않는다. 후원은 운송 주문이 아니므로 주문 원장의 운송 매출·배송 수행 실적으로 넣지 않는다. 주문·운송·보수 원장의 기존 책임을 유지한다.

기본 공개 이력은 날짜별 후원 합계, 지출 일자·비용 분류·후원 충당액·확인 상태다. 개인별 후원 별명·금액 공개는 별도 명시적 동의를 받은 경우만 허용하고, 계좌·결제키·거래번호·PG 원문·개인 연락처·청구서 원문·서버 자원 식별자는 공개하지 않는다. 후원 공개 동의 철회와 재무 보관 의무의 삭제 판단은 같은 결과로 처리하지 않는다.

기록이 아직 연결되지 않으면 `미집계`, 확인된 전체 기록의 조회 결과가 비어 있으면 `0`, 조회 실패는 `확인 불가`다. 실제 수납 경로가 준비되기 전에는 작동하는 후원 버튼이나 ‘후원으로 운영 중’이라는 확정 문구를 제공하지 않는다.

## 운영비 재원 비율 — 2026-10-22 후속 구체화

사용자가 알고 싶은 질문은 **지금까지 실제로 쓴 운영비를 누가 얼마나 부담했는가**다. 기존 전체 누적 홈의 운영 요약에 짧은 `운영비` 카드와 내역 진입을 두고, 실제 지출 합계·후원 충당액과 비율·운영자 직접 부담액과 비율·집계 기준 시각을 표시한다. 상세에서는 월별 지출, 서버·DB·저장소 등 비용 분류와 재원별 충당 내역을 확인한다. 기존 역할 진입과 현재 업무 지도·카드의 책임은 유지한다.

- 분모는 같은 기간에 지출이 확인된 운영비다. 예산 한도 50만원, 향후 예상 청구액이나 거래 총액을 실제 지출로 넣지 않는다.
- 후원 비율은 `확인된 후원금으로 실제 충당한 운영비 ÷ 확인된 실제 운영비 × 100`이다. 후원금 전체 입금액을 곧바로 비용에 쓴 것으로 보지 않는다.
- 운영자 직접 부담 비율은 `자체 예산으로 실제 충당한 운영비 ÷ 같은 실제 운영비 × 100`이다. 후원금이 없거나 입금 기록이 없다는 이유만으로 전부 운영자가 부담했다고 추정하지 않는다.
- 운영비 한 건의 재원별 충당 합계는 해당 지출액을 넘을 수 없고, 하나의 후원 입금액을 여러 지출에 중복 배정할 수 없다. 반환·정정은 기존 원장 근거와 판본을 대조하며 같은 기간의 집계를 다시 산출한다.
- 두 재원으로 전액 충당됐다는 근거가 있을 때만 두 비율의 합계를 100%로 표시한다. 다른 재원이나 아직 연결하지 못한 부분은 각각 별도 표시하고, 확인되지 않은 금액을 운영자 부담으로 채우지 않는다. 지출 전체나 충당 근거가 불완전하면 비율은 `미집계`로 둔다.
- 실제 지출이 0원이면 `지출 없음`으로 표시하고 비율 막대는 숨긴다. 조회 실패는 `확인 불가`로 표시한다. 처음부터 근거 없이 `후원 0% · 직접 부담 100%`를 기본값으로 넣지 않는다.
- 후원 누적 입금·반환·미사용 잔액은 별도 내역이다. 아직 쓰지 않은 후원금이 늘었다고 과거 운영비의 후원 비율이 자동으로 오르지 않는다. 약속만 받은 후원·결제 승인·입금·비용 충당도 각각 구분한다.

**표현 예시 — 실제 운영 수치 아님:** 확인된 운영비 500,000원, 후원 충당 200,000원, 운영자 직접 부담 300,000원이 전액 연결됐다면 `후원 40% · 직접 부담 60%`로 표시한다. 각각의 금액도 함께 보여 주고 색상만으로 재원을 구별하지 않는다. 홈은 이 요약만, 상세는 입금·반환·실지출·충당을 구분한 비식별 내역만 소유한다. 계좌·청구서 원문과 개인별 후원 정보는 기존 공개 기준을 따른다.

현재 공개 홈의 금액 집계와 후원 전용 실입금·실지출·충당 정본은 연결되지 않았다. 이 절은 후속 구현 기준이며 APK나 휴대폰에 표시됐다는 증거가 아니다. 기존 재무 기록에서 필요한 비용/재원 연결을 확정한 다음 공개 읽기 집계 → 홈 요약/상세 → 소비 앱 빌드 → APK 패키지 대조·기기 화면 순서로 검증한다. 수납·계좌 연결·운영 활성화를 이 요청으로 자동 실행하지 않는다.

## 활동 소개와 순위의 근거

| 기준 | 필요한 근거 | 미확인 처리 |
| --- | --- | --- |
| 완료 건수 | 역할·업무·완료 단계가 명확한 전문 원장과 중복 제거 식별값 | 집계 가능한 범위를 표시하며 기사 하차 완료를 상호 수령·실지급·신뢰 인증으로 확대하지 않음 |
| 약속 준수 | 사전에 합의한 약속 시각, 실제 단계 시각, 변경 합의와 책임 구분 | 약속 시각 없는 기록은 제외 표본으로 표시. 지각의 원인을 추정해 기사에게 귀속하지 않음 |
| 문제 해결 | 사건 접수, 해결 결과와 관련 확인 근거, 담당·처리 단계 | 접수됐다는 이유만으로 감점하지 않고, 신고가 없다는 것을 해결률100%로 만들지 않음 |

비교 기간·표본 수·제외 수·산정 기준 판본을 함께 보존한다. 숫자 가중치와 최소 표본이 결정되고 근거가 연결되기 전에는 임의의 종합점수나 공개 순위를 만들지 않는다. 최소 표본 미달이나 품질 기록 미확보는 낮은 점수로 치환하지 않는다. 화주와 기사, 음식·화물 등 서로 다른 업무를 한 순위에 합산하지 않는다. 물량은 단위가 다르므로 단순 수량 합계를 능력 점수로 쓰지 않는다.

소개·순위 공개 동의에는 별명, 역할, 활동 근거, 상담/교육 의향의 항목별 선택과 철회가 필요하다. 기존 친구 연락처 동의나 특정 주문 관계자의 이력 공유 동의를 홈 전체 공개에 전용하지 않는다. 소개를 거절해도 기존 업무 이용·배차 자격을 잃지 않는다. 후원액·개인 연락처 공개·관리자 권한을 순위 기준으로 쓰지 않는다.

## 상담과 교육의 연결

- 처음에는 기존 ‘질문·도움’의 ‘업무 질문·운송 실무’를 경험 공유에 활용한다. 도움을 요청한 글은 상담가 자동 배정·유료 예약·상대방 답변 의무와 다르다.
- 개인 연락은 기존 친구 요청·상대방 수락·목적과 항목에 맞는 연락처 공개 동의를 따른다. 전화번호를 순위표에 일괄 공개하지 않는다.
- 경험 많은 참여자 → 본인 상담/교육 참여 동의 → 활동 근거 확인 → 필요한 검토와 과정 담당 지정 순서로 구분한다. 순위나 칭호만으로 관리자·고객 사건 처리·교육과정멘토 권한을 부여하지 않는다.
- 교육은 기존 신청·승인·등록·참석·과제·수료 엔진을 검토해 재사용한다. 물류 교육의 내용과 과정 정의는 별도로 준비한다. 현재 기본 과정이나 기존 멘토 자격을 일반 기사 교육으로 자동 전환하지 않는다.
- 동료의 실무 안내와 공식 고객센터 사건 처리는 책임과 열람 범위가 다르다. 일반 상담 참여자에게 타인의 주문·고객 주소·분쟁 원장을 공개하지 않는다.

## 구현 순서와 통과 조건

1. **근거 축적:** 후원 입금·반환·실지출·충당 연결과 참여자의 공개/도움 의향을 별도로 준비한다. 실제 입금 경로와 공개 기준을 먼저 구체화한다.
2. **투명 공개:** 집계 정본이 준비된 금액만 누적 요약·비식별 내역으로 공개하고 실제 증빙의 읽기 대조, 중복/환불/정정/실패 처리를 검증한다.
3. **기여자 소개:** 동의한 화주·기사의 확인 가능한 활동과 품질 근거를 소개한다. 종합 순위식은 기간·최소 표본·가중치를 함께 정한 뒤 적용한다.
4. **경험 공유와 교육:** 기존 질문·도움부터 연결하고, 검토된 물류 교육 과정·담당자·열람 범위로 확장한다.

회귀 사례에는 중복 입금·부분 반환·정산 수수료의 이중 차감·한 비용의 중복 충당·기초잔액 불명, 후원액과 활동 순위 분리, 같은 완료 이벤트 중복, 약속 시각 미확보·책임 불명 지연, 신고 접수/해결 분리, 공개 동의 철회·연락처 비노출·권한 상승 금지를 포함한다.

이번 실행은 코드·DB 읽기와 기획 문서 정리만 수행한다. 제품 코드·화면·DB·결제·권한·공개 순위·APK·실제 메시지·commit/push는 변경하지 않았다.
