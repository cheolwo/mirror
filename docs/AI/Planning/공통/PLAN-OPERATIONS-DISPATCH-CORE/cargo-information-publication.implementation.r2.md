## 결과와 설계 선택

일반 커뮤니티 게시판은 비구속 화물 게시 공간과 작성자 권한을 이미 제공하지만 영속 초안·만료·개정/CAS·명령 멱등이 없고 즉시 게시 때 알림/음성 큐를 만든다. 기존 운송 의뢰는 생성 시 운송 원장/OS 인계를 만든다. 두 기능을 그대로 새 정보 공고 생성으로 사용하지 않는다.

따라서 생활보관공간의 Mongo 안정 ID·Revision CAS·요청 증적 패턴을 재사용한 **독립 화물정보공고 문서**를 둔다. 이 공고만 공개의 상태 권위이며 실제 운송 원장의 복사본을 만들지 않는다. 기본 OFF인 별도 공고 옵션으로 운송 기능과 활성 범위를 분리한다.

`초안 → 명시적 공개 → 철회`, 만료는 서버 시각으로 즉시 공개 조회에서 제외한다. 공개 내용 수정 시 공개를 해제하고 현재 내용에 다시 동의해야 한다. 소유자는 인증된 서버 사용자이며 클라이언트 owner 입력을 받지 않는다. 모든 변경에 요청 ID·입력 지문·기대 개정을 결속하고 응답 유실 시 같은 요청의 결과 조회/재시도만 허용한다. 다른 사용자의 변경, 오래된 개정, 같은 요청 ID의 다른 입력을 거절한다.

과거 운송 의뢰의 공개 GET은 명시적 공고 근거가 없는 자료를 더 이상 공개하지 않는 폐쇄 기본값으로 보완한다. 새 공고 DTO는 의뢰 ID·배차/운송/정산 상태·작성자 내부 ID·상세주소·연락처를 반환하지 않는다. 운송 인계·추천·배차·외부 발송·수납/지급 호출은 없다.
