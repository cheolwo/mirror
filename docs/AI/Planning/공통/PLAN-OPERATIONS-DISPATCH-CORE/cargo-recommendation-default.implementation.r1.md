# 화물 추천 기본 경로 보완 구현 r1

- 날짜: 2026-10-21
- 상태: `CompletedLocalValidation / CargoSingleCandidateSelection / OperationalDisabled / BatchActivationDeferred`
- 승인: 사용자 ‘그렇게 좀 진행을 해줘’ — [조사 r1](cargo-recommendation-default.review.r1.md)의 약속/응답 검증 → 화물 AI 선택·규칙 복귀 → 기존 추천/목록 → 화물 조합 순서.
- 작업 명세: [허용 경로·검증](cargo-recommendation-default.r1.work-order.json)

기존 화물 원장과 단건 후보 선정 경로를 재사용한다. 대기 기사의 픽업 약속 검사, 훈련 비교의 모델/완료 응답 검사, 화물 후보 중 모델 선택 및 최신 후보 재검증·현재 규칙 복귀를 보완한다. 다건 적용의 transaction 재시도는 실제 다건 진입을 켜기 전 안전 조건으로 검사한다. 음식·피킹의 새로운 조합, 공개 콜 확장·주소 제공, 운영 활성화와 모델 가중치 학습은 포함하지 않는다.

자동 추천/공개 콜은 노출·수락 방식이고 지도/목록은 같은 허용 자료의 표현 방식이다. 기존 automatic 기본 및 목록 전환을 유지하며 새 목록/운송 원장을 만들지 않는다. 기사 수락·정보 제공 동의·픽업·전달·정산은 구분한다.

화물 모델 선택은 opt-in capability 안에서 우선 사용하며, 제품 운영의 기본 OFF·Simulation/Operational 경계는 보존한다. 루프백·기존 모델·익명 토큰/수치만 사용한다. 모델은 탈락 후보를 복원하거나 차량·약속·희망 업무·자격을 덮어쓸 수 없다. 짧은 요청 기한·공유 추론 한도·실패 시 복귀를 적용하고 응답 뒤 최신 후보를 다시 확인한다. 최초/최신 후보 또는 의뢰 조건이 바뀌면 현재 규칙 결과를 사용한다. 호출자 취소와 저장소 오류는 성공으로 숨기지 않는다.

기존 합성 캠페인·검토 원문은 보존한다. 실행 중인 5324 호스트·5595 검토 서버·12681 Ollama는 임의 중지하지 않고 격리 build/test 산출물을 사용한다. 회차가 자연 종료한 뒤 새 빌드를 명시적 로컬 검증에 사용할 수 있으며 이전 결과를 새 코드의 결과로 표시하지 않는다. 실제 기기·외부 알림·지급·클라우드·commit/push는 이번 범위가 아니다.

검증은 대기/수행 ETA 경계, 응답 봉투·토큰·취소/예산, 모델 선택/지연/무효/최신 조건 변경과 current rule 복귀, transaction 재시도/외부 소유권/중복/취소, 기존 지도/목록 동일 자료를 포함한다. Fast/Task와 도구 자체 검사를 구분하고 가능한 격리 HTTP 검증 결과를 별도로 남긴다. 단계별 실제 결과와 제한은 완료 시 갱신한다.

## 구현한 업무 흐름

```text
화물 주문 접수 — 기존 주문·운송 원장
└─ 규칙으로 가능한 기사·적재·전체 일정 확인
   ├─ 약속 불가능·근거 미확인 → 후보 제외
   └─ 허용 후보
      ├─ AI 옵션 OFF → 기존 규칙 후보
      └─ AI 옵션 ON → 익명 후보 중 모델 제안
         └─ 현재 원장·후보·수신 의사·약속 재확인
            ├─ 유효 제안 → 현재 근거로 추천
            └─ 지연·무효·혼잡·후보 변경 → 현재 규칙 후보
               └─ 기사 수락 → 동의 → 사진 픽업 → 사진 전달 → 정본 완료
```

추천은 자동 수락이나 배송 완료가 아니다. 원장 입력이 달라졌거나 재조회 결과 후보가 없으면 오래된 추천을 반환하지 않는다. 저장소 오류·호출자 취소도 성공으로 바꾸지 않는다.

## 검증 기록과 남은 제한

최종 회귀·실행 결과는 같은 증거 폴더의 `verification.json`과 아래 완료 기록에 결속한다. 첫 전체 시험에서 새 응답 규약을 반영하지 않은 기존 모의 응답 4개와 메타데이터 기대 목록 1개가 실패했다. 모의 응답과 기대 목록을 보완한 두 번째 전체 시험은 14,137개 통과·실패 0개·환경 의존 16개 미실행이다. 기존 실패 로그도 보존한다.

최종 결합 회귀 보완 후 `artifacts/local/validation/20261021-183327/`의 전체 소비 솔루션 빌드가 오류 0·기존 설정 경고 6개로 통과했고, 전체 시험은 **14,139개 통과·실패 0개·환경 의존 16개 미실행**이다. 격리 훈련 도구도 다시 빌드해 오류 0·기존 nullable 경고 17개, 자체 검사 **72개 통과·실패 0개**를 확인했다. 자체 검사는 모의 HTTP/합성 fixture이며 아래 실제 모델/API 실행과 구분한다. 문서 링크 13개·diff 검사도 통과했다.

초기 도구 재빌드는 이 검증이 시작한 호스트 DLL의 사용 중 잠금으로 실패했다. 해당 가상 회차가 완료된 뒤 호스트를 종료하고 같은 명령을 재실행해 통과했으며 기존 5595 서버를 종료하거나 파일을 강제 삭제하지 않았다. 소스 오류·모델 응답 오류·DLL 사용 중 실패를 한 원인으로 합치지 않는다.

다건 적용의 SQL/Outbox를 caller 소유 transaction에 참여시킨 경우, commit을 확인할 수 없는 서비스 안에서 외부 캐시를 먼저 변경하지 않는다. 이 경우 캐시 동기화 완료를 주장하지 않으며 정본 재조회/후속 복구가 필요하다. 소유 transaction commit 뒤 외부 캐시 갱신이 실패해도 이미 저장된 SQL을 재시도하지 않는다. 이 제한과 다건 진입 미활성은 별개다.

`AiResult`/`LatestAiResult`는 그림자 비교 기록이다. 실제 모델 적용 여부는 정본 `운송이벤트`의 `DispatchEngineDecisionAudit`, `CandidateReason`의 `CargoDispatchAI.*`, 추천 전환 성공을 함께 대조한다. `Timeout`·`Cooldown` 등은 규칙 복귀이며 `Applied`와 구분한다. 이미 완료된 이전 15건 캠페인은 이전 코드·규칙 경로의 증거로 보존한다.

두 번째 회차는 220초 유한 관측·120초 접수 간격으로 2건을 만들고 신규 발생을 종료한 뒤 남은 업무를 마쳤다. 두 건 각각의 수락·동의·픽업 도착·사진 업로드/픽업 완료·전달 도착·사진 업로드/전달 완료 8개 명령이 `Confirmed`다. 사진 영수증은 존재하지만 합성 이미지다. 별도 그림자 호출은 `NotRunPrimarySelectionProfile`이며 실제 적용으로 집계하지 않는다. 정본 감사 metadata의 SHA와 실행 DLL 해시를 보존했다.

이 결과는 기존 CPU 모델이 모든 주문에서 5초 이내 판단한다는 보장이 아니다. 콜드 호출은 실제 시간 초과가 발생했고 규칙으로 이어졌다. 다른 주문의 성공을 품질·공정성·복수 서버 처리량·실제 운행의 전수 검증으로 확대하지 않는다. 가중치 학습·사용자 승인도 이루어지지 않았다.

최종 다건 재시도 보완 전 실행한 DLL의 해시를 별도로 남겼다. 이 로컬 실행은 단건 경로이고 다건 transaction 분기는 사용하지 않았다. 최종 소스의 다건 추가 보완은 별도 회귀와 전체 Task 결과로 구분한다. 검증을 위해 시작한 5324 호스트는 완료 후 종료했고 기존 사용자 검토 서버 5595·Ollama와 이전 원문은 유지했다.

### 재시도 결합 회귀

최종 독립 검토에서 ‘commit 응답만 유실됨 + 호출자가 먼저 추적하던 Added/Modified 행’의 결합을 추가했다. 수정 전에는 SQL에 이미 저장된 행이 메모리에서 다시 Added로 남는 실패를 재현했다. 같은 추천 판본이 commit됐음을 확인한 뒤, 해당 호출자 항목만 마지막 저장 상태로 수렴시키도록 수정했다. 전체 추적 초기화나 `AcceptAllChanges`는 하지 않으며 마지막 Save 후의 미저장 Modified 변경은 그대로 남긴다. 관련 11개 시험이 통과했고 `batch-final/regression-red.trx`와 `batch-final/batch-green.trx`를 모두 보존한다.

이 11개는 실제 SQLite transaction에 재시도·commit 응답 유실을 주입한 회귀다. MySQL 다중 연결에서 실제 다건 조율을 부하 운전한 결과는 아니다. 위 API 완주는 전용 MySQL/Mongo의 단건 경로이며 두 검증 범위를 합치지 않는다. 전체 시험의 환경 의존 16개도 실행 완료로 계산하지 않는다.

기존 지도/목록과 공개 권한은 그대로 재사용했다. 이번에는 UI를 새로 만들거나 실제 화면·APK·휴대폰·외부 푸시·운영 DB·실제 사진·정산/입금·클라우드 배포를 검증하지 않았다. 현재 규칙의 차량·적재·자격·신규 수신 관문을 유지하며 음식·피킹 혼합, 공개 콜 마감과 다건 제품 진입은 후속이다.
