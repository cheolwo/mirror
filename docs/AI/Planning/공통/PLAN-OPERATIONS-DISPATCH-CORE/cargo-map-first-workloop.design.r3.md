# 지도 중심 화물 업무와 고정 활동권역 설계 r3

2026-10-25. `DirectionRecorded / FixedAnchorConfirmed / ImplementationNotStarted / OperationalDisabled`.

사용자는 기사님이 화물 목록을 계속 찾거나 다른 기사와 선착순으로 경쟁하지 않고, 지도에서 업무를 시작하면 AI가 한 건씩 제안하고 완료 무렵 다음 업무로 이어지기를 요청했다. 활동 반경은 **집·지정 거점을 중심으로 고정**한다고 답했다. 현재 위치에서 픽업하러 갈 최대 거리는 별도로 설정한다. 이번은 기존 코드 감사와 후속 구현 기준의 기록이다. 제품 수정·실제 배차·운영 설정 활성화·새 시험/기기 실행은 수행하지 않았다.

정보 게시·조회부터 법적 요건을 확인한다는 [r1 방향](cargo-information-first-legal-review.r1.md)과 [공고 r2](cargo-information-publication.implementation.r2.md)는 유지한다. 정보 공고를 실제 운송 접수로 자동 변환하지 않는다. 이 설계는 이후 실제 운송 업무의 기사 경험이며, 기관 확인이나 운영 허용을 대신하지 않는다.

## 확정한 사용자 경험

```text
로그인 → 내 차량·업무·비공개 거점·활동반경 확인 → 위치 동의 → 업무 시작
  → 지도에서 대기 → 나에게만 유효한 추천 한 건 → 수락 또는 거절
    → 상차 → 운송 → 하차·인계 확인 → 정본 완료
       └─ 완료 예상과 다음 상차 약속을 확인할 수 있을 때 다음 한 건 제안
  → 휴식 / 신규 수신 중지 / 맡은 일 마친 뒤 업무 종료
```

- 기사 기본 홈은 지도·현재 업무 한 건·다음 제안 한 건이다. 화물 검색 목록·좌우 후보 넘기기·공개 콜 경쟁을 기본 동선에 두지 않는다. 기존 전문 목록의 주소와 기능을 일괄 삭제하지 않고 진입을 분리한다.
- 화주·운영자의 접수/관리 목록과 로그인 없이 보는 정보 공고는 역할과 목적을 유지한다. 기사 홈의 목록 비노출을 플랫폼 전체 정보 비공개로 해석하지 않는다.
- 추천 대상은 서버가 전용으로 정하며 수락 기한 동안 같은 의뢰를 다른 기사에게 동시에 제안하지 않는다. 화면에 한 장만 보이는 것과 서버의 독점 제안은 별도로 검증한다.
- 추천 자동화와 수락 자동화는 구분한다. 이번 기본 설계는 조건을 읽고 수락/거절하는 단건 전용 제안이다. 사전 조건부 자동 수락은 아직 사용자가 선택하지 않았으므로 켜지 않는다.
- 일감이 충분할 때 불필요한 검색과 대기를 줄인다. 일감·수입·무중단 연속 배차를 보장한다고 표시하지 않는다. 후보가 없으면 범위를 몰래 넓히지 않고 대기 이유를 보여 준다.

## 고정 활동권역과 픽업 접근 거리를 분리한다

| 설정 | 기준 | 판정 의미 |
| --- | --- | --- |
| 내 활동 거점 | 집 또는 기사님이 직접 정한 지점 | 운행하며 자동으로 움직이지 않는 비공개 중심점 |
| 활동 반경 | 거점 중심 20km·50km 빠른 선택, 그 외 값의 허용 상한은 구현 명세에서 확정 | 새 업무 때문에 이 고정 원 밖으로 나가야 하는 후보를 제외 |
| 최대 픽업 접근 거리 | 현재 위치 또는 확인된 현재 업무 종료 예정 지점 → 다음 상차 | 먼 빈 차 이동을 줄이는 별도 한도. 직선거리 사전 필터와 실제 주행거리 판정을 구분 |
| 종료 예정·복귀 선호 | 기사님의 종료 의사와 실제 남은 업무 | 마칠 수 없는 후속 제안을 중지하고 귀가 방향을 우대. 활동권역 제한을 해제하는 근거가 아님 |

기사님이 20km를 선택하면 더 좋은 수입·복귀 가점·AI 판단을 이유로 50km 후보를 살리지 않는다. 활동 거점과 반경은 로그인한 기사 본인의 설정으로 서버에 보존하고 앱 재실행 뒤 재조회한다. 기존 복귀 설정 저장소의 보호·소유권·판본 충돌 패턴을 재사용하되, 기존 7/6km 진입·해제 반경의 값을 20/50km로 재해석하지 않는다.

### 상·하차 두 점만 확인해서는 부족하다

상차와 하차가 모두 원 안에 있어도 강·교량·일방통행 때문에 실제 제안 경로가 원 밖으로 나갈 수 있다. 따라서 다음 수준을 나눠 표시한다.

1. 상·하차 위치의 거점 반경 검사: 빠른 후보 제외.
2. 현재/예상 종료 위치→상차의 접근 거리·시간과 전체 상하차 일정 검사.
3. 접근·운송·이미 맡은 업무를 합친 제안 경로의 형상이 확보되면 **경로 전체**를 활동권역과 대조. 위치 오차·경계 여유와 경로 판본도 기록.

끝점이나 거리·시간 요약만 있는 응답을 ‘경로 전체가 반경 안’으로 확정하지 않는다. 필수 경로·좌표·위치의 신선도·오차를 확인할 수 없으면 제안을 보류한다. 이 판정은 제안한 경로에 대한 것이며 실제 기사가 벗어나지 않았다는 GPS 실운행 증거와 다르다. 차량에 허용되는 실제 경로와 운행 제한도 기존 전문 관문에서 확인한다.

이미 권역 밖에 있으면 이를 알리고 신규 제안을 보류한다. 복귀 우대를 이유로 제한을 자동 해제하지 않는다. 범위 변경 시 맡은 업무를 취소하거나 이행 책임을 없애지 않으며, 현재 업무와 이미 수락한 후속 업무를 마친 뒤 적용할 설정을 구분한다. 오래된 미수락 제안은 새 설정으로 재평가한다.

## 경쟁 없는 전용 제안과 다음 업무

### 제안은 서버에서 한 기사에게만 유효하다

기존 운송 원장·추천 라운드·만료·현재 지정 기사·동시 수락 관문을 재사용한다. 같은 의뢰의 유효한 전용 제안은 한 기사에게만, 같은 기사의 미응답 후속 제안도 한 건만 유지한다. 저장과 재시도는 서버의 동일 요청·판본·원장 상태를 기준으로 한다. 중복 푸시나 화면 재접속이 별도 추천·수락을 만들지 않는다.

거절·기한 만료는 해당 제안을 종료하고 서버가 다음 적격 기사에게 순서대로 제안한다. 이 업무 모드에서는 만료를 이유로 공개 콜로 자동 전환하지 않는다. 다른 업무의 기존 공개 콜·병행 정책까지 일괄 변경하지 않는다. 위치·차량·적재·업무 의사·오래 기다린 정도·빈 차 이동·약속 이행을 적격 후보 사이에서 평가한다. 클릭 속도·유료 우선권 경쟁을 새로 만들지 않는다.

기본 거절과 통신 장애·미응답을 같은 책임으로 처리하지 않는다. 기존 미응답 중지 정책·신규 수신 OFF·휴식을 유지하고, 조건 밖 제안이나 시스템 오류로 기사에게 자동 불이익을 부과하지 않는다.

### 완료 무렵은 고정 몇 분이 아닌 수행 가능성으로 판단한다

현재 업무의 예상 종료 위치·시간, 남은 하차·인수 절차와 다음 상차 시간창·작업시간을 함께 대조한다. 단순히 5분 남았다는 이유로 다음 일을 확정하지 않는다. 실제 경로·전체 일정의 근거가 없는 경우는 완료 뒤 대기/조회로 이어간다.

`현재 A 수행 → 다음 B 제안 → B 수락·후속 대기 → A 정본 완료 → B 수행`을 구분한다. A 수행 중 B를 현재 작업으로 잘못 표시하거나 B 물품을 미리 보유한 것으로 처리하지 않는다. 첫 범위는 다음 한 건이며 혼적 동시 수행이나 여러 미래 업무의 연속 예약으로 확장하지 않는다. 현재 A의 지연·B의 취소·만료·수신 중지 때에는 같은 원장을 다시 읽어 제안/후속 상태를 갱신한다. 이미 확정한 약속을 서버가 조용히 지우거나 다른 기사에게 중복 배차하지 않는다.

## 모바일 화면

- 시작 전: 지도와 내 활동 원, 거점 이름·20/50km·별도 픽업 접근 거리의 짧은 요약, 주 행동 ‘업무 시작’. 로그인·차량 자격·위치 동의가 부족하면 그 항목으로 복귀하도록 기존 흐름을 사용한다.
- 대기: ‘설정한 범위에서 찾는 중’. GPS 미확인·적격 업무 없음·서버 연결 실패·수신 OFF를 별도 상태로 표시한다. 조건을 자동 완화하지 않는다.
- 제안: 지도 아래 한 장. 기존 상차 왼쪽/하차 오른쪽, 총 중량·수량·월일/시간·보수·예상 거리와 소요·독차/혼적 조건을 유지한다. 수락/거절과 자세히 보기를 제공하고 후보를 넘기는 화살표는 기본 동선에서 제외한다.
- 수행: 현재 업무의 다음 행동을 주 버튼으로 둔다. 다음 한 건은 ‘제안’ 또는 ‘수락한 다음 업무’라고 명시하고 현재 업무와 구분한다.
- 휴식·마무리: 신규 수신 중지와 현재 업무 완료를 분리한다. ‘맡은 일 마친 뒤 종료’를 제공하며 종료 요청만으로 물품 인계·운송 완료·정산을 완료 처리하지 않는다.

거점 원과 실제 거점 좌표는 기사 본인의 화면에만 둔다. 고객·다른 기사·공개 공고·AI 자유문·일반 감사 로그에 집 좌표를 복제하지 않는다. AI에는 기존처럼 허용된 익명 후보와 최소 수치만 제공한다.

| 5 | 같은 운송 원장의 격리 업무 완주·운영 준비 확인 | 범위 안 정상·종료 직전 지연·후속 취소·신선하지 않은 위치·통신 단절을 실제 서버/DB와 기기로 구분해 검증 |

첫 구현은 1~2의 **설정과 범위 제한**을 먼저 닫는다. 지도에 원만 그려 놓고 배차가 그 범위를 지킨다고 설명하지 않는다. 이후 전용 제안·후속 상태·모바일을 같은 원장으로 연결한다. Fast/Task·실제 API/DB·기기·운영 허용을 각각 보고한다. 새 별도 배차 DB·원장·무인 실행을 먼저 추가하지 않는다.

## 미정과 후속

빠른 선택 20/50km 이외의 사용자 지정 반경 상한, 전용 제안 유효시간·갱신 기준, 후속 약속 변경 처리의 세부 조건은 구현 명세에서 확정한다. 명시적 사전 동의에 따른 자동 수락, 복수 후속 업무, 전국 운영은 이번 확정 범위가 아니다. 이 문서는 제품 구현·실제 운행·위치 수집·운영 활성화의 증거가 아니다.
