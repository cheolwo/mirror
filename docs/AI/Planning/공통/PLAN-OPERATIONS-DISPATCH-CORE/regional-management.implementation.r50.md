# 지역 배차 판단 준비 r50

상태: 현재 사용자 요청으로 구현 범위 수락. 기준 HEAD는 `86f3eae59328cfe5ef7ec9e3aef48ae351cf54d9`이며 이전 dirty 작업은 보존한다. 이 설계는 구현 시작 시 SHA-256으로 동결한다.

## 목적과 범위

사용자가 선택한 2·3·4·5번을 USB 없이 구체화한다. 2는 주문 대비 기사 처리 여력과 추가 참여 권고, 3은 주문 감소 시 기존 활동·장기 대기 기사 보호, 4는 수행 중 기사 마지막 전달지와 완료 예상 시각에 따른 후속 픽업 검토, 5는 기존 단건·2건 조합의 비교다. 음식 배차 서버의 기존 수신 동의·자격·최신 상태·정원·차량·시간·재조회 관문을 보존한다. AI는 허용된 선택지 중 제안만 하고 상태 변경은 기존 서버 명령이 수행한다.

## 데이터

기존 비공개 r54 역사 배달 자료 574건에서 공개 매장 주소에 중랑구·동대문구·광진구가 명시된 504건·339지점을 파생한다. 원장 sourceRefs의 검증된 stores[i] 참조와 같은 폴더 route-map.points[i]의 이름·주소·locationVerified를 대조한다. point.index에 의존하지 않으며 날짜별 좌표 관측을 보존한다. 확인된 건별 메뉴 267건·488항목과 주문총액 296건을 재사용한다. 방문 요약만 있는 7건은 단건 메뉴로 배분하지 않는다. 역사 가격은 현재 가격이 아니다.

실제 고객 위치·주소·연락처·실제 기사 GPS는 사용하지 않는다. 전달 위치는 공개 매장 좌표의 명시적 합성 오프셋이며 기사 위치·근무·차량 용량·주문 도착 시각·경로 시간·조리 준비 시간은 시험 가정으로 기록한다. 행정동 역사 경계는 현재 배달권으로 승격하지 않는다. 구명과 합성 반경·인접 관계를 구분한다. 원본·파생자료 해시, 제외 사유, 과거 관측 출처를 남긴다. 파생자료와 SQLite는 Git 제외 artifacts/local에만 둔다.

## 서버 변경

수요 참여 정책의 기존 기본 처리율 3.5건/시간과 정책 우선순위를 유지한다. 4건/시간은 별도 민감도 사례로만 검토한다. 참여 권고는 실제 알림 전송·기사 수신 중단이 아니다. 새로운 지역 관리 검토 서비스는 수요 판정·단건/2건 조합을 읽기 전용으로 결합한다. 오래되거나 알 수 없는 수요와 잘못된 조합은 모델에 넘기지 않는다. 모델에는 익명 토큰과 수치 특징만 보내고 매장·메뉴·주소·기사/주문 ID는 보내지 않는다. 엄격한 planToken JSON 외 응답은 기존 규칙 결과로 돌아간다. 복수 대안이 없으면 호출하지 않는다. 실제 적재·모든 약속 시각·멀티 원자적 수락 관문 통과를 이 미리보기로 인증하지 않는다.

후속 픽업은 새 `음식배달수행종료기준사용=false` 옵션으로 둔다. 활성 수행이 없으면 현재 위치, 있으면 기존 음식 수행을 모두 마친 마지막 전달지와 완료 예상 시각을 사용한다. 실제 경로 근거·조리 준비 자료가 없으면 명시적 제외로 처리한다. 남은 수행 시간과 마지막 전달지에서 다음 픽업까지의 차량별 경로 시간을 합산한다. 기존 늦은 준비 허용 기준을 유지하고 수행 중 후속 픽업의 지각을 명시적으로 제외한다. 후보 발견은 기존 현재 GPS 공간 인덱스 범위에 한정되며 미래 전달지 전용 전역 탐색은 이번 범위가 아니다. 화물 수행과 음식 혼합을 허용하지 않는다.

## 로컬 실행과 검증

새 RegionalScenarioRunner는 명시적으로만 실행한다. 3개 구 자료를 사용한 부족·과잉·후속 픽업·멀티 비교 사례를 준비하고 실제 정책·서비스를 호출한다. 기존 r49 HTTP/SQLite/모바일 PageModel 통합 fixture에 선택적 공개 매장·확인된 메뉴 입력을 추가하며 기본값과 기존 시험을 보존한다. 최소 한 지역 사례에서 주문 생성→음식점 수락→추천 저장→기록용 알림→모바일 PageModel 수락→도착·픽업·전달→별도 수령 확인을 실행한다. 실제 고객·운영 DB·외부 FCM·Android 화면과 구분한다.

새 r50 누적 모델 시도 예산은 선호 4회, 최대 6회다. 실패·중단도 시작 전에 예약하여 누적하며 기존 r46~r49 예산을 재사용하지 않는다. 고정 loopback 127.0.0.1:12681와 qwen3:1.7b만 사용한다. 현재 소스·데이터 해시가 일치하는 모의 실행 성공 후에만 대표 실제 추론을 한다. 모델 가중치 학습·자동 정책 승격·사람 검토 완료 인증은 하지 않는다. 판단/기준/선택/보류·검토 대기 자료를 보관한다.

Python 파생자료의 결정성·오연결·보호 필드 제외, 서버 경계·부족/과잉/오래된 수요·잘못된 모델 응답·후속 픽업 근거/시간·통합 흐름을 시험한다. Fast 후 Task 검증을 수행한다. 소스 해시, 독립 SQLite 재조회, 문서 링크와 관련 없는 변경 보존을 확인한다. 실제 USB·FCM·지도 API·운영 DB·Azure·설치·입금 검증은 후속으로 남긴다.

## 제외

Unity, 공유 API 계약 변경, 앱 화면 추가, 운영 플래그 활성화, 외부 메시지 전송, 실제 고객 주소, 원본 영상·MYBOX 변경, 배달 저장소 수정, Azure 배포, APK 설치, 모델 다운로드/가중치 학습, 커밋·푸시는 포함하지 않는다. 기존 r49 알림 생성/재시도 간극은 별도 후속이며 이번 2·3·4·5 완료로 해결됐다고 보고하지 않는다.
