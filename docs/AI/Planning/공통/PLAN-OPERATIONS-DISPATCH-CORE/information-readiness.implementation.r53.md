상태: `Approved / ReadyToDispatch / LocalOnly`. 2026-10-11 사용자가 앞서 제안한 1번, 배차 판단에 필요한 정보의 충분성을 기존 프로젝트 자원으로 구현하도록 요청했다. 현재 스레드의 승인을 적용한다. 기준선은 `08931c2371f29de615f4a4f133b535e5df76bf7f`다.

## 구현 범위

기존 r52의 최초 음식 주문 수집 판단에 구조화한 정보 준비 상태를 결속한다. 주문·현재 조리·픽업과 전달 좌표·주문 풀 조회 완전성·수요·기사 처리 여력은 기존 원장과 서비스에서 읽는다. 각 근거는 `Current / Missing / Stale / NotApplicable`, 고정 사유, 관측시각, 선택적 원천 판본으로 표현한다. 확인된 0은 미확인과 다르다. 선택적인 조리 예정 완료가 없어도 주문과 조리 상태를 확인했으면 그 사실 자체는 현재 자료다.

`SchedulingStateCode`는 짧은 수집 판단에 필요한 여섯 근거만 집계한다. `CoordinationStateCode`는 여기에 주문자 전달 확약·비용 동의·기사의 실제 일정과 적재 검증·현재 후보 요금·플랫폼 확정 재원을 추가로 요구한다. 후자는 이번 수집 시점에서 확인되지 않았으므로 명시적으로 부족하게 유지한다. 수집 정보의 준비를 전체 배차·수익성·약속 준수의 검증 완료로 해석하지 않는다.

## 원천과 경계

- 조리: `음식주문현재조리Policy`가 소유하는 현재 차수를 재사용한다. 재조리 이전의 준비 완료·예정 시각을 새 차수에 재사용하지 않는다.
- 수요·기사 여력: 기존 수요 참여 서비스가 제공한 관측시각을 현재 시각으로 승격하지 않는다. 잘린 조회·현재 큐 누락·조회 실패·필수 좌표 누락을 별도 사유로 남긴다.
- 일반 음식 주문에는 고객에게 확약한 전달시각·확정 배송비 분담·플랫폼 확정 배차 재원이 없다. 상품 주문금액·결제 승인액·미리보기·기간 예비금으로 대체하지 않는다. 선택적인 AutoFulfillment의 희망시각/비용 상한은 Simulation 동의이며, 일반 배차의 실제 확약·운영 재원이 아니다. 이번에는 이 API를 새로 호출하거나 동의를 운영 확정으로 승격하지 않는다.

5. AI 대기 중 관측 유효시간을 넘으면 다시 집계해 추가 대기를 금지한다. AI 입력에는 기존 익명 시간·집계만 유지하고 주문 응답·주소·이름·메뉴·원시 근거는 전달하지 않는다. 로그도 두 집계 상태와 고정 사유만 추가한다.
