## 1. 현재 준비 상태와 첫 판단

음식 AI는 서버가 허용한 기사 후보 선택, 지역 단건/2건 조합 검토, 첫 추천 전 수집/즉시 배차 판단에 연결돼 있다. 실제 다건 수락·운송 전체 약속의 최적화를 모두 수행한다는 의미는 아니다. 퀵 용달에는 같은 Ollama 선택·수집 연결이 아직 없다.

2026-10-15 실물 자료를 읽어 확인한 상태:

| 자료 | 후보 수 | train / validation / test | 승인 ready |
| --- | --- | --- | --- |
| r51 음식 배차 판단 | 4,032 | 2,784 / 856 / 392 | 0 / 0 / 0 |
| r52 음식 배차 시점 | 4,032 | 2,784 / 856 / 392 | 0 / 0 / 0 |

두 자료는 서로 다른 판단 자료이며 8,064개의 독립적인 실제 배송 경험으로 합산하지 않는다. r51 원시 4,041개 중 9개는 동일 입력/교차 분할 문제로 격리됐다. 후속 픽업 ArrivalAnchor 9개가 모두 격리돼 학습 후보(candidates)에도 포함되지 않는다. ready 파일은 모두 0바이트이고 사람 승인·가중치 학습은 0이다.

실제 출처는 배달 기록 504건·매장 339지점·확인 메뉴 488항목이며, 기사·주문 도착·수요·전달점은 합성이다. 현재 정책을 호출해 만든 답안은 `CurrentPolicyDraft / optimalityProven=false / Pending`이다. 기존 엔진 모방 자료와 사용자가 확인한 바람직한 판단, 실제 운영 결과를 구분해야 한다.

r51 원천 70개를 대조한 결과 `음식배달배차업무정책.cs`, `음식주문현재조리Policy.cs`의 현재 해시가 달라졌다. 과거 자료는 10월11일 정책 snapshot으로 보존하고, 최신 코드용 답안은 새 판본에서 재생성·재검토한다. 오래된 승인을 현재 소스에 소급 적용하지 않는다.

따라서 첫 단계는 **퀵에서 무엇을 좋은 판단으로 볼지 확정하고, 사람이 검토한 대표 사례를 만드는 것**이다. 현재 후보 파일을 그대로 학습기에 넣거나 AI 응답을 자동 정답으로 쓰지 않는다.

## 2. AI가 배울 판단과 서버 책임

| 책임 | 역할 |
| --- | --- |
| 서버의 고정 검사 | 자격·신규 수신 의사·차량/적재·취급 금지 조건·유효 원장/현재 판본·이미 수락한 약속·검증된 시간 조건·합의 보수·중복/동시성 검사 |
| 예측 모델 | 자료가 쌓이면 픽업/전달 소요시간·대기·가용 종료 시각·단기 수요를 예측. 관측값과 예측 오차를 함께 남김 |
| 조합 계산 | 가능한 기사·주문·픽업/전달 순서 후보를 시간·적재·비용 제약 안에서 계산. 작은 사례는 전수 비교, 큰 사례는 제한 시간 내 탐색 검토 |
| 학습 모델의 판단 | 허용 후보 중 선택, 허용된 짧은 수집/즉시 배차 선택, 추가 기사 필요의 참고 판단, 정해진 이유 코드 반환 |
| 서버의 최종 적용 | AI 응답 뒤 최신 후보/원장/보수를 다시 검사하고 기존 추천·수락·감사 경로에 적용. 무효·지연·장애면 유효한 기존 엔진 결정으로 복귀 |

모델은 탈락 후보 복원·임의 운임 변경·수락 강제·고객 시간 약속 연장·지급 실행을 결정하지 않는다. 고객/물품 설명의 자유 문장은 지시가 아닌 입력 자료로 처리하며 모델 출력으로 서버 도구의 권한을 확대하지 않는다.

현재 `FoodDispatchOllamaOptions`는 `qwen3:1.7b`와 루프백 주소만 허용한다. 미래 학습 모델은 다른 판본 ID와 해시로 등록·평가해야 한다. 기존 태그의 내용만 바꿔 학습 모델을 숨기거나 arbitrary model/remote URL 허용으로 우회하지 않는다. 등록·허용 목록 변경 자체는 후속 구현 범위다.

## 3. 판단 우선순위 제안

1. **기존 약속·실행 가능성:** 기사 자격, 실제 차량/적재, 허용 품목, 유효한 수신 의사와 현재 수락 업무를 지킨다.
2. **주문 지연과 장기 대기:** 기한이 임박한 주문을 처리하고, 적시에 수행 가능한 가까운 후보 사이에서는 오래 기다린 기사에게 기회를 준다. 정확한 ETA 허용 폭은 미정이다.
3. **연속 수행·권역 균형:** 수행 중 기사는 마지막 목적지와 종료 예상시각부터 후속 픽업을 평가한다. 복귀 방향은 기존 약속을 지키는 후보 안에서 가점으로 검토한다.
4. **수요에 맞춘 참여:** 피크 시간이라는 이름보다 실제 주문량·기사별 남은 처리 여력·관측 신선도를 우선한다. 주문을 모으는 시간 상한은 퀵의 약속과 별도로 정한다.
5. **기사 수입과 플랫폼 손익:** 확정 보수·공차 이동·대기·추가 비용·확보 재원을 함께 비교한다. 미확인 비용은 확정 이익으로 만들지 않고 경제 평가 미확인으로 남긴다.

4,000원은 **기사별 평균 보수를 향하는 보조 목표**로 제안한다. 고액 콜을 감점하는 상한이나 모든 건의 강제 단가가 아니다. 집계 기간·분모·세전/세후·미션/취소/반송 포함 여부는 아직 미정이다. 임시 후보는 당일 완료한 본인 퀵의 세전 약정 보수 평균, 미션·보상 별도 집계다. 시간당 수입과 공차/대기가 악화되는지도 함께 평가한다.

현재 음식 AI 입력에는 개인 평균 4,000원 목표가 없고, 화물의 목표 지급액 보정은 기본값 0인 규칙이다. 그 계산도 현재 후보·묶음의 비용 대용치이며 개인 누적 평균이 아니다. 이미 이 방향으로 학습되고 있다고 보고하지 않는다.

실제/예측/합성/미확인 값을 필드별로 구분한다. 전달지가 없는 과거 영상 기록에는 합성 전달점을 쓸 수 있으나 실제 고객 경로나 실제 ETA로 표시하지 않는다. 매장·메뉴명으로 무게·부피·포장·취급 조건을 추정하지 않는다.

모델 입력에는 실제 기사 ID·고객 주소/이름/전화·원본 앱 화면·민감한 상세 위치를 넣지 않는다. 서버가 필요한 이동·시간·적재 수치와 익명 후보 토큰으로 변환하고, 원출처 연결은 비공개로 분리한다. 반송료·취소비·수납 기준처럼 r103에서 미정인 정책은 임의의 정답으로 채우지 않는다.

## 5. 자료 제작과 문답 방식

- 처음에는 아래 12개 상황군에서 대표 **20개를 사람이 읽을 수 있는 번호형 사례**로 준비하는 것을 제안한다. 20개는 첫 검토 단위이며 모델 학습 충분성을 보장하는 수가 아니다.
- 한 사례에 상황·후보 A/B/C·각 후보의 시간/보수/조건·기존 엔진 선택·AI 제안·선택 이유를 나란히 보여준다. 사용자는 승인·정정·미정으로 답한다.
- 한 조건만 바꾼 짝 사례를 함께 만든다. 예: 후보가 더 오래 기다렸지만 마감이 임박한 경우, 복귀 방향은 좋지만 적재량이 부족한 경우. 비슷한 문장 암기보다 조건에 따른 선택 변화를 검증한다.
- 기존 엔진, 작은 문제의 전수/최적화 비교, 사람의 판단, 실제 관측을 서로 다른 근거로 남긴다. 최적화 도구의 답도 모델링한 비용·제약 안의 결과이며 실제 최적 배송을 자동 인증하지 않는다.
- 승인 자료는 사례·입력·답안·정책·출처 해시와 연결한다. 모델 자기 평가나 도구 성공으로 사람 검토 상태를 채우지 않는다. 여러 선택이 동등하게 좋은 사례는 단일 정답을 억지로 만들지 않는다.

상황군: 장기 대기 / 수행 종료 후 후속 픽업 / 권역 복귀 / 주문 급증 / 주문 감소 / 짧은 수집의 이점 / 주문 마감 임박 / 기사 부재 / 적재·취급 불일치 / GPS·수요 관측 만료 / 높은 비용·재원 미확인 / 거절·취소·통신 장애.

분할은 기존 지점/원주문 묶음을 보존하고 날짜·동일 시뮬레이션 실행·조건 변형도 함께 묶는다. 퀵용 고정 시험에는 보지 않은 기간·지역과 장애 사례를 별도로 남긴다. 동일/유사 입력, 조합의 공유 원천, 미래 결과가 학습과 시험 양쪽에 새지 않도록 검사한다. 시험 답안을 반복해서 프롬프트 예시나 학습 자료로 옮기지 않는다.

## 6. 학습과 적용 순서

| 단계 | 산출물·다음 단계 조건 |
| --- | --- |
| A. 기준·자료 정리 | 퀵의 허용 행동/우선순위·미정 정책 목록, 최신 소스 해시·합성 표시. 기존 후보와 정답 초안의 관계 대조 |
| B. 첫 문답 검토 | 대표 20개 → 승인·정정·미정 기록. 이후 100개 수준의 균형 잡힌 검토 묶음으로 확대하는 제안. 건수보다 상황군별 검토와 일관성을 확인 |
| C. 학습 전 비교 | 기존 엔진 / 현재 모델 / 정책 설명·검토 예시를 준 모델을 고정 시험에서 비교. 반복 오류와 느린 구간을 찾음 |
| D. 소규모 추가 학습 | 검토한 정답으로 SFT와 LoRA의 작은 실험. 후보 선택/허용 행동과 짧은 근거부터 학습하고 시험 자료는 분리. 효과가 없으면 승격하지 않음 |
| E. 선택적 선호 학습 | 사람의 ‘좋은 안/나쁜 안’ 짝 자료가 쌓이면 DPO 검토. 같은 조건의 비교인지 확인하며 자동 점수나 모델 답을 사람 선호로 둔갑시키지 않음 |
| F. 새 가중치의 실행 검증 | 모델·tokenizer·template·base revision·학습 자료·환경/seed·export 해시 보존. Ollama 가져오기와 새 모델 허용 등록, 입력/출력 계약·지연·오류 복귀 확인 |
| G. 실제 적용 전 관측 | AI 제안을 기존 엔진 결과와 병렬 기록하는 관측 단계 → 제한된 로컬 통합/시범 → 명시적으로 승인한 운영 범위. 현재 worker/운영 OFF를 이 기획으로 켜지 않음 |

SFT는 입력과 검토한 답안으로 추가 학습하고, DPO는 좋은/나쁜 응답의 선호 쌍을 쓰는 후속 방식이다. 실제 학습은 TRL/PEFT 같은 도구로 수행하고, 내보낸 모델을 Ollama로 가져와 실행하는 구조를 제안한다. 현재 Q4 실행 파일을 학습용 원본으로 간주하지 않고 일치하는 원 모델·tokenizer·이용 조건과 내보내기 호환성을 먼저 확인한다.

현재 읽기 확인한 PC는 RTX 5050 VRAM 8,151MiB, RAM 약 31.7GiB다. 작은 모델·짧은 입력·작은 배치로 메모리/속도 시험부터 검토한다. 설치된 학습 런타임·GPU/CUDA 호환·실제 훈련 속도는 이번에 시험하지 않았으므로 학습 가능 크기·시간·비용을 보장하지 않는다. 추론용 Ollama와 일회성 학습 작업은 구분하고 학습 결과를 기존 실행 모델에 덮어쓰지 않는다.

## 7. 평가 기준과 중단·복귀

| 축 | 확인할 지표 |
| --- | --- |
| 유효성 | 금지 후보 선택, 동의/시간/적재 위반, stale revision, 중복 추천·수락, 주문 유실 |
| 운영 품질 | 배정/픽업 대기 p50/p95, 미배차·기한 초과, 실제 완료율, 공차와 서비스/대기 시간 |
| 기사 배려 | 오래 기다린 유효 기사의 미선정, 기회 편중, 복귀 방향, 개인 확정 보수 평균과 시간당 수입 |
| 경제성 | 확인한 지급 재원·확정 보수·추가 비용·순기여. 직접 수금과 플랫폼 지급 대상/보류 분리 |
| 모델 품질 | 허용 선택 정확도, 동등한 좋은 선택 인정, 근거 수치/이유 일치, 무효 응답·기존 엔진 복귀율 |
| 속도 | 전체 판단 p50/p95와 마감 내 적용 비율, CPU/GPU·후보 수별 비교. 모델 선택과 복귀 결과를 따로 집계 |

첫 평가 제안은 고정 시험에서 금지 선택·주문 유실·중복 적용 0건, 만료/오류 시 서버 복귀 시험 전부 통과, 기존 엔진 대비 지연·편중·비용의 악화 여부 확인이다. 시험 0건이 현실 전체에서 오류가 없다는 보장은 아니다. 업무 기준 수치와 허용 악화 폭은 별도 승인한다.

온라인 판단의 잠정 성능 검토 목표는 p95 2초 이내다. 현재 지연이나 퀵 SLA로 확정한 값은 아니다. 과거 CPU 설명 검토는 수십 초가 걸린 기록이 있으므로, 짧은 구조화 입력·기존 엔진 후보 축소·GPU·시간 제한으로 직접 재측정해야 한다. 모델 지연으로 고객 약속이나 수집 상한을 늘리지 않는다. 성능이 안 맞으면 기존 엔진을 사용하고 모델 검토는 비동기 관측으로 유지한다.

정답 일치율 하나만 좋아진 경우는 승격하지 않는다. 정책/자료/모델 변경마다 고정 시험과 경계·장애 회귀를 돌리고, 사람 정정·실제 관측을 새 후보로 축적한다. 과거 학습/시험 자료·승인·실행·실패 이력은 보존한다. 대화나 결과가 쌓였다는 이유만으로 모델 가중치가 자동 갱신됐다고 표시하지 않는다.

## 8. 다음 결정과 첫 실행 제안

먼저 퀵의 기사 선택을 학습 대상으로 잡고 수집/묶음은 별도 판단 과제로 평가하는 것을 제안한다. 기존 음식의 30/60초 시험 설정이나 기본 3.5건/시간을 퀵의 확정 정책으로 가져오지 않는다.

다음 문답에서 필요한 결정은 4,000원 평균의 집계 범위, 적시 수행 후보 사이 대기 우선의 ETA 허용 폭, 퀵 수집 상한과 긴급 예외, 실제 비용 미확인 때의 처리다. 아직 답하지 않은 것은 `Pending`으로 남긴다. 초기 대표 20개를 읽고 정정하는 과정이 이 결정을 구체화할 수 있다.

후속 구현 요청이 오면 첫 범위는 **최신 자료 감사·퀵 대표 사례 20개·검토 원장·고정 평가 세트 준비**로 좁힌다. 모델 설치/실학습/운영 배차까지 한 번에 승인된 것으로 해석하지 않는다. 이번 문서 작성만으로 자료가 새로 생성·승인되거나 모델이 학습된 것은 아니다.
