# r20 — 클라우드 배포를 제외한 화물 운영 마감

상태: `CompletedLocalAndDeviceValidationWithFindings / OperationalDisabled`.

2026-10-22 사용자는 운영 준비 제안의 보완을 계속 구현하되 네이버 클라우드 배포를 제외하도록 직접 요청했다. 이는 [r15 조사](cargo-three-role-readiness.review.r15.md)의 남은 F4/F5/F6와 [r16](cargo-prepayment-recovery.r16.md) 이후 정상 로컬 통신·한 건 완주를 이어가는 개발 승인이다. 실제 수납·송금, 클라우드 생성/이전/배포, 운영 기능 일괄 해제, 공개 게시·commit/push 승인이 아니다.

## 업무 결과

같은 의뢰의 고객 청구액·기사 약정/확정 지급액·수납·지급 결과를 혼동 없이 확인하고, 정식 미해결 분쟁이 있으면 지급을 보류한다. 현재 원장·권한·전문 상태와 알림·보호 저장을 재사용한다. 정상 조회와 합성 주문의 접수→결제 확인→추천→수락→상하차→인수·지급 준비를 로컬 제품 HTTP와 역할 화면으로 대조한다.

구체 경로와 담당은 [작업 명세](local-operations-closeout.r20.work-order.json)를 따른다. 공유 소스가 모인 뒤 root가 Fast→Task와 소비 빌드, 실제 렌더·기기 증거를 통합하며 담당 에이전트는 동시에 빌드/서버를 실행하지 않는다.

## 완료 판독

1. 금액 미확인·약정/동결·고객 운임을 포함한 반례 회귀가 통과한다.
2. 수납만 확인된 운송을 정산 완료로 표시하지 않는다. 실제 지급 확인이 없으면 준비/보류/미확정으로 남긴다.
3. 같은 운송의 정식 열린 분쟁·변조/조회 실패는 지급 준비·승인·배치·gateway 직전에서 보류하고 일반 문의와 종결 사건은 구분한다.
4. 기존 조회 전용 5365의404/405와 제품 호스트 readiness503을 기록하고, 최신 정상 제품 HTTP와 새 합성 한 건의 정본을 확인한다. health 검사를 완화해 통과시키지 않는다.
5. 최신 APK·정상/오류 화면과 닫기/복귀, 재실행·추천·사진의 실제 실행 범위를 나눠 보고한다. 카메라/잠금/USB/외부 공급자 인증이 막히면 가능한 로컬 검증을 끝내고 해당 한계만 남긴다.
6. 실제 PG 계약·키/결제창/취소환불·주간 실지급과 외부 알림 수신, 서버 밖 전체 복원은 코드/시험 준비와 실제 완료를 구분한다. 이번 범위에서 운영 효과를 켜지 않는다.

문서·코드·시험·HTTP·APK·실기기·운영/금융을 같은 완료 주장으로 합치지 않는다. 결과와 화면은 새 r20 변경 기록에 연결한다.

## 실행 중 발견한 결제 저장 차단

첫 격리 실행에서는 모의 결제 전 `paymentConfirmed=false`·`배차 미시작`을 확인했다. 실제 MySQL의 재시도 실행 정책과 수동 transaction이 충돌해 FakePG 승인 HTTP400이 발생했다. 이 실패와 최초 소스 결속·DB를 보존하고 새 판본의 격리 DB에서 후속 검증한다. 시험 설정에서 재시도를 끄는 우회 대신 FakePG의 권한·확정 운임·멱등 검사를 유지하며 결제와 승인 Outbox 저장을 기존 실행 정책의 transaction 단위로 묶는 수리를 범위에 포함한다. 저장 실패/커밋 응답 유실과 중복 결제 방지를 관계형 회귀로 확인한다.

모든 Hosted worker는 계속 OFF다. 모의 승인 뒤의 배차 대기 생성은 기존 결제 승인 Outbox를 합성 요청 한 건에 한정해 명시적으로 1회 처리하는 로컬 통제 단계로 구분한다. 자동 운영이나 실제 수납을 활성화하는 변경이 아니다.
