# 단계 진행 알림 실제 휴대폰 검증 r7

- 상태: CompletedDeviceSampleValidation / FullWorkflowAndHumanSoundPending (2026-10-22)
- 승인: 사용자가 샘플 알림을 만들어 연결된 실제 휴대폰에서 동작을 검증하도록 요청했다.
- 선행: [단계 진행 알림 r6](workflow-progress-notifications.r6.md)의 업무 상태/예약/전송/수신 분리를 유지한다.

## 범위

1. 기존 일반앱 Firebase 설정·서버 발송 자격의 프로젝트/패키지 일치를 비밀값 출력 없이 확인한다. 같은 서명으로 최신 standalone Debug APK를 데이터 보존 갱신한다.
2. 기존 격리 Simulation 호스트·합성 계정에서 실제 앱 로그인·설치 등록을 확인한다. 운영 worker/자동 지급은 켜지 않는다.
3. 기존 제품 FCM 전송기와 8개 필드 계약으로 단일 설치에 대표 샘플을 보낸다. 샘플은 실제 입고/배송 완료 사실이 아니다.
4. 전경·배경·클릭·재전송/과거 단계/수신자 보호를 실제 OS 기록·PNG와 대조한다. 강제 종료/잠금/소리 청취는 실행한 범위만 기록한다.
5. 실제 발견한 제품 결함만 좁게 수정하고 해당 시험/소비 빌드를 수행한다. 관련 없는 dirty 작업·설정·데이터를 보존한다.

## 경계

- 단발 발송 시도는 전송 전에 기록하고 결과 불명확 시 자동 재발송하지 않는다.
- 푸시 서버 접수, 휴대폰 표시, 클릭 이동, 알림음 재생 요청, 사람의 실제 청취는 별도 증거다.
- 알림 사진/주소/토큰/키/고객정보를 공개 캡처·문서에 넣지 않는다. 내역을 지우거나 전체 알림을 일괄 삭제하지 않는다.
- 기존 앱을 삭제하지 않고 update install을 사용한다. commit/push/외부 공개/운영 배포는 하지 않는다.

## 작업 경로

`eng/WorkflowProgressDeviceVerificationR7/`, 새 `artifacts/local/workflow-progress-device/20261022-r1/`, 본 계획·변경 기록·문서 목차를 소유한다. 제품 결함이 발견되면 변경 전 해당 파일을 추가로 동결·기록한다.
