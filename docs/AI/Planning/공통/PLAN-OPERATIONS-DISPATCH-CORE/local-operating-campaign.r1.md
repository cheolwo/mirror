# 로컬 가상 운영 시험 누적 r1

- 날짜: 2026-10-21
- 상태: CompletedLocalValidation / SyntheticLocalOnly / BoundedCampaignReady
- 승인: 사용자가 배달하는 동안 가상 주문 접수부터 배송 완료까지 결과를 쌓고 대표 사례를 추리도록 구현 요청.

기존 `Ssalddel.DispatchTraining`의 격리 HTTP·DB·합성 기사 실행기를 재사용한다. 새 주문/배송 상태기계를 만들지 않는다. 30분 동안 최대 15건을 2분 간격으로 접수하고, 거절·만료·기사 부족을 포함해 후속 수행을 관측한다. 별도 캠페인 도구는 유한 실행 시간, 재시작 후 조회 우선, 결과 불명 POST 자동 재전송 금지, 중단·마감 시 신규 생성 정지, corpus 주기 접수만 책임진다.

주문별 원문 snapshot과 해시를 보존하고 대표 사례는 관측 내용 서명으로 유사 묶음을 만든다. 미확인/오류/모델 문제와 정상 결과를 최대 5개로 추린다. 유사 관측 수는 독립 학습 사례 수가 아니다. 사람 검토는 기존 명시적 승인 절차에 남기며 자동 승인·가중치 학습·운영 배차·실지급을 하지 않는다. 화물 실제 배차는 기존 규칙이고 Ollama는 별도 비교 결과다.

현재 5595 검토 서버와 12681 Ollama, 기존 가상 회차 원문, 이전 승인 자료는 보존한다. dedicated 5324 / MySQL 13312 / Mongo 27023만 합성 시험에 사용한다. 사진은 시험용 이미지이며 실제 휴대폰 촬영/FCM 수신/입금 증거가 아니다.

검증: 대표 선별/중복/정상-예외 균형/경계 테스트, 캠페인 불명 응답·중단·재개·마감·실패 시 결과 보존 테스트, 도구 빌드와 기존 selfcheck, 가능한 실제 격리 HTTP 실행. 코드 완료와 장시간 실행 완료를 구분해 기록한다.

실제 실행에서 기존 전용 DB의 컬럼 누락과 추천 재검증의 MySQL 재시도/수동 transaction 충돌이 발견됐다. DB는 전용 backend·계정·합성 namespace·정확 EF 모델을 대조한 nullable ADD만 수행하고 기존 행을 유지한다. 추천 재검증은 기존 잠금·업무 조건·외부 transaction을 보존한 채 전체 transaction을 EF 실행 전략 안에 둔다. 점수·추천 정책·실제 운영 설정은 바꾸지 않는다. 이 실패 기록은 성공으로 소급 변경하지 않는다.

## 구현한 흐름

```text
명시적으로 가상 회차 시작
├─ 30분·120초 간격·최대 15슬롯 (지나간 슬롯 소급 생성 없음)
│  └─ 기존 주문 접수 API → 정본 요청 ID 확인
│     └─ 기존 규칙 추천 → 가상 기사 수락·정보 공개 동의
│        └─ 상차지 도착 → 시험 사진 업로드 → 픽업 완료
│           └─ 하차지 도착 → 시험 사진 업로드 → 전달 완료 정본 조회
├─ 거절·만료·기사 부족 → 별도 사건·결과 보존
│  └─ 선택한 경우에만 시험 사용자가 지원 기사 참여 요청
├─ Ollama 비교 → 규칙 선택과 응답 시간·실패/생략을 별도 기록
└─ 60초마다 원문 판본 접수 → 내용이 비슷한 관측 묶음 → 대표 ≤5개
   └─ 나중에 사용자와 문답 검토 → 명시적 의견만 별도 저장
```

캠페인 실행/중단은 `eng/verification/dispatch-operating-campaign.py`, 원문 접수·검토는 기존 `Experiences/`, 사례 선별은 순수 함수 `DispatchExperienceReviewSelector`가 담당한다. 같은 요청·판본의 원문은 중복 접수하지 않고 이전 사람 의견을 새 원문에 자동 복사하지 않는다. 대표 목록은 실행 중 바뀔 수 있으므로 `reports/review-<SHA>.json`에 목록 번호와 당시 전체 근거를 함께 고정한다. 이전 번호로 검토할 때는 이 고정본을 사용한다.

무한 작업이나 예약 실행은 설치하지 않는다. 기본 관측은 2,200초이며 마지막 조회·저장 정리 시간은 추가될 수 있다. 종료·정지 요청은 본 캠페인이 시작한 같은 회차의 신규 발생만 멈추고 기존 운송은 계속 마감한다. 프로세스가 끊기면 같은 캠페인 ID로 조회부터 재개하며 불명 POST를 자동 반복하지 않는다. PC·호스트·Docker가 꺼져 있는 동안 결과는 쌓이지 않는다.

## 실제 로컬 실행에서 보완한 부분

- 이전 합성 DB의 11개 nullable 컬럼을 전용 backend·계정·DB·모델 대조 후 추가했다. 기존 테이블/행은 삭제하거나 초기화하지 않았다. 이 작업은 운영 DB migration 실행이 아니다.
- 추천 재검증의 기존 transaction 전체를 EF 재시도 전략으로 감쌌다. 외부 transaction·취소·잠금 수명·점수 조건은 보존했다.
- 시험 주문이 제품의 적재/일정 조건을 충족하도록 치수·팔레트 미사용 0개·작업 시간·시간창을 명시했다. 전용 경로 제공자는 한정 합성 격자와 고정 속도만 사용하며 실제 도로·GPS·ETA 근거가 아니다.
- 시험 기사의 차량 주의사항 확인을 실제 역할 UI와 같은 `FreightVehicleAdvisory` 코드로 맞췄다. 일반 표시 문구를 확인 코드로 보내지 않으며 제품의 수락 보호 조건을 완화하지 않았다.
- 사건의 `Resolved`·`Closed` 종결 상태를 서버와 같은 기준으로 분류한다. 사건이 닫혀도 실제 업무가 진행 중이면 정상 완료로 올리지 않는다.
- 입력 부족·거부·응답 불명 회차는 원문과 함께 보관했다. 보관 자체로 기존 주문을 취소하거나 실패를 해결 처리하지 않았다.

## 검증 결과와 확인 범위

`dispatch-training-51b3f0f414b2457ba70c6312e04da1e6`의 동일 주문에서 기존 수락 명령 1~5라운드 거부 기록을 보존한 채 6라운드 수락부터 정보 공개 동의·상차지 도착·픽업 사진·픽업 완료·하차지 도착·전달 사진·완료까지 확인했다. 회차 revision 46은 `Completed`, 정본 조회 성공·완료 1·미완료 0이다. 두 사진은 시험용이며 실제 촬영이 아니다. 원문과 안전한 수행 확인은 `artifacts/local/dispatch-operating-campaign/20261021-r1/completed-session.json`, `completed-workflow-evidence.json`에 있다. actor 보조 기록과 session을 같은 DB transaction의 원자적 판본으로 주장하지 않는다.

이후 `dispatch-training-1b38256f816e43f9b68c5b5701e686b3`은 첫 추천 수락부터 전 단계가 `Confirmed`, revision 71에서 정본 완료 1·미완료 0이었다. 신규 발생 정지는 진행 운송을 취소하지 않았으며 끝까지 마감됐다. `clean-completed-session.json`, `clean-completed-workflow-evidence.json`과 보존된 actor 원문 해시가 연결된다. 후속 2,200초 누적 회차는 별도이며 전체 종료 전에는 완료로 표시하지 않는다.

- 캠페인 회귀 31개, 경험/대표 선별 자체 검사, 시험 호스트 자체 검사와 명시적 도구 빌드를 실행했다. 최종 수량은 같은 증거 폴더의 `runtime-verification.json`을 기준으로 한다.
- 제품 transaction 수정은 Fast 74개 통과, Task 13,993개 통과·16개 미실행 및 소비 솔루션 빌드로 확인했다. 증거는 `artifacts/local/validation/20261021-171103`, `20261021-171136`이다.
- 새 회차의 현재 실행 상태는 `artifacts/local/dispatch-operating-campaign/20261021-r1/current-campaign.json`과 그 `statusPath`를 읽는다. 보고서에 기록한 시점 이후의 결과를 미리 완료로 간주하지 않는다.
- 기존 5595 검토 서버·12681 Ollama와 기존 검토 자료를 보존했다. 후보 비교에서 모델이 시간 초과해도 규칙 수행이 완료되는 것을 확인했다. 실제 모델 가중치 학습·사람 승인·운영 배차·외부 푸시·휴대폰·정산/입금·클라우드 배포·commit/push는 실행하지 않았다.

## 나중에 함께 검토하기

`artifacts/local/dispatch-experiences/current-representatives.md`를 연다. 미확인 결과·업무 문제·모델 응답 문제·정상 흐름이 최대 5개로 표시되며 각 사례의 당시 후보·점수·원문 ID가 연결된다. 반복 횟수는 독립 사례 수나 모델 학습량이 아니다. 모든 사례는 검토 대기이며 사용자가 실제로 판단한 뒤 기존 `--experience-review --human-reviewed` 절차로 의견을 남긴다. 당시 원문에 없는 상세 조건이나 단계별 시각은 추정해 채우지 않는다.
