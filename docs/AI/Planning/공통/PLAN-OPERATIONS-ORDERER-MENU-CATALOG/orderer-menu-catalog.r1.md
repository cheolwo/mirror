# 주문자 메뉴 사진과 배달 기록 자료 연결 r1

2026-10-10. `PLAN-OPERATIONS-ORDERER-MENU-CATALOG`, 주 책임 `operations`. 사용자의 현재 요청인 “지금 수집한 데이터들을 앱에서도 활용하고 주문자가 메뉴·이미지·가격을 함께 보게 조정”을 구현 승인으로 기록한다. 최종 “로컬 준비까지만” 범위의 상태는 `Implemented / LocallyVerified`이며 실제 검증 결과는 [변경 기록](../../../../Changes/2026-10-10-orderer-menu-catalog-r55.md)에 남긴다. Azure 업로드·운영 메뉴 등록·다중 상세 갤러리 완료를 뜻하지 않는다.

## 목적과 기존 경계

주문자는 선택한 음식점의 메뉴 사진·이름·설명·판매가와 수량을 함께 보고 기존 주문 작성을 이어간다. 기존 `음식점메뉴공개응답.대표이미지Url`과 서버 투영을 재사용하고 주문·금액 계산·품절·인증·서버 재확인 책임을 바꾸지 않는다. 사진 로딩 실패가 메뉴와 가격·수량 조작을 없애지 않도록 한다.

수집한 09.23~10.09 배달 기록 574건의 구조화 메뉴 497항목에는 명시 단가가 없으며 표시 항목금액과 주문총액만 일부 있다. 이 자료를 현재 판매가 또는 0원 메뉴로 등록하지 않는다. 수집한 공식 사진도 실제 지점 제공품·촬영 당시 판본·옵션·공개 사용 조건이 미확인이다. 현재는 비공개 로컬 검토 화면에서 실제 기록과 참고 사진을 대조한다. 운영 판매 메뉴에는 음식점이 제공하고 확인한 기존 계약 데이터만 사용한다.

## 구현 범위

1. 실제 주문자 공통 상세 메뉴 목록에 기존 대표 이미지 표시 컴포넌트를 연결한다. 메뉴명 대체 텍스트, 지연 로딩, 누락/실패 안내와 모바일 배열을 제공한다. 임의 파일·스크립트 주소는 표시하지 않는다.
2. 개인 자료를 옮기는 도구는 확정 원장과 이미지 조사 파일의 해시·건/지점/메뉴 연결을 검사한다. 동일명 사진 후보만 연결하고 구성품·모호한 메뉴·브랜드 전체 참고 사진을 실제 주문 메뉴로 주입하지 않는다. 단가·표시 항목금액·주문총액은 별도 nullable 값이다.
3. 로컬 전용 관측 메뉴 화면은 실제 공통 UI에서 음식점별 검색·메뉴·수량·관측일·기록 금액·공식 참고 사진을 표시한다. 현재 판매가나 주문 가능 메뉴라고 표현하지 않으며 주문 제출 포트를 연결하지 않는다.
4. 파일은 `artifacts/local/orderer-menu-catalog-r55/`에만 보관한다. 루프백·명시적 Simulation·등록 파일/해시 허용 목록으로만 사진을 제공하고 외부 주소 프록시나 제품 `wwwroot` 복사·운영 DB 등록은 하지 않는다. 실패 시 다른 예시 자료로 대체하지 않는다.
5. 후속 사용자 요청에 따라 기존 Hongdal Azure Blob 설정·어댑터·컨테이너를 재사용한다. 저장소 설정은 기존 설정/배포 기록에서 조회하며 비밀값을 출력하거나 새 계정·컨테이너·공개 ACL을 만들지 않는다. 로컬 사진 목록으로 재실행 가능한 비공개 Blob 보관 명세와 원격 해시 대조 절차를 준비한다. 현재 수집 후보는 `platform-private` 대상이며 운영 판매 메뉴·공개 URL로 자동 승격하지 않는다. 실제 업로드는 현재 인증·정확한 계정·컨테이너 접근 확인 뒤 별도 실행 상태로 기록한다.
   사용자는 Azure 재인증 질문에 “지금은 로컬 준비까지만”으로 확정했다. 현재 완료 범위는 설정의 기존 구성 조사와 비공개 보관 명세·후속 실행 계약까지이며 실제 계정 접근·업로드·다중 상세 갤러리·운영 메뉴 등록을 완료로 보고하지 않는다.

## 검증과 제외

- 의미 있는 가져오기 시험: 실제 연결, 미확인 단가 보존, 메뉴 후보 구분, 중복 재실행, 해시/경로/개인정보 거부.
- 공통 UI 시험과 실제 소비 호스트 빌드: 사진 유무/오류, 가격 종류, 품절·기존 수량 기능, 검토 화면의 주문 불가 경계.
- 실제 루프백 브라우저: 320/390px 및 데스크톱, 음식점/메뉴 검색, 빈 결과·로딩/오류, 사진 표시/대체 안내, 외부 API/쓰기 없음.
- scoped `validate-changes.ps1` Fast·Task를 수행하고 환경 의존 미실행과 실제 결과를 구분한다.
- 고객정보·원본 전사·플랫폼 주문번호, Unity·영상 수정·공유·외부 게시·Azure 자원 생성/ACL 변경·운영 DB·실결제·단말 설치·commit/push는 범위 밖이다. 기존 Azure 설정 조회와 비공개 사진 보관 준비는 포함하며 실제 외부 저장 성공과 구별한다.

화면 책임은 [주문자·음식점 페이지 책임](../../../../ProjectOverview/page-docs/mobile-workflow-orderer-restaurant-r1.md)의 메뉴 사진·기록 자료 절을 따른다. 기존 dirty 작업은 보존한다.
