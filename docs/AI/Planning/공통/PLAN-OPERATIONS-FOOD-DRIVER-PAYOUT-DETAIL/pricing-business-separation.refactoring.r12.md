# 음식 배달·화물 운송 요금 책임 분리 r12

2026-10-03. 기존 r11 차량·시간대 경로 선택 위에 적용하는 코드 정리다. 음식과 화물의 요금 자체를 같게 만들거나 새 운임을 운영에 활성화하지 않는다.

| 업무 | 계산 책임 | 입력/정책 | 결과 의미 |
| --- | --- | --- | --- |
| 음식 배달 | 음식배달기사제안요금Service → 음식배달기사제안요금Policy | 음식운영정책, 배달기사 차량, FoodDriverRoutePricing, 경로 거리, 기상/한시 수요/시간대 | 기사에게 제시할 기사지급예정액과 동결 근거 |
| 화물 운송 | 화주운송기준운임Service → 화주운송기준운임계산기 | 차량단가, 기본운임/km당 단가/최소운임, 대기료·수작업비·수동 할증 | 화주 기준운임 견적. 기사 지급액이나 확정 협의 운임으로 자동 치환하지 않음 |
| 공통 기술 | I배차추천경로Service → NAVER typed client | 출발/도착 좌표, 경로 옵션 | 거리·소요시간. 요금은 계산하지 않음 |

## 코드 변경

- 기존 화주운송기준운임Service.cs에 함께 있던 운임 계산기와 단가/거리 판정 타입을 화주운송기준운임계산기.cs로 그대로 옮겼다. 기존 namespace·공개 타입·API·수식·기본 단가·입력/직선거리 fallback을 유지한다.
- 음식 요금 service는 두 공개 산정 진입점 모두에서 배차업무유형=음식배달을 검증한다. 용달운송을 전달하면 FoodPricingTaskTypeMismatch로 거절하며 기사 조회나 외부 경로 조회 전에 막는다.
- 음식 시간대 할증의 금액 합산·음수 검증을 음식 도메인 Policy로 모았다. Service는 차량·시간대·자료를 선택하고 Policy가 돈을 계산한다. 시간대할증액은 정책 결과에도 남기며 기존 제안 JSON에도 보존한다.
- 공통 추천 전환 파일에서 음식 전용 제안 동결·근거 저장 코드를 배차대기원장전환Service.FoodPricing.cs로 분리했다. 음식 업무에만 실행되고 화물의 금액/계산 근거는 건드리지 않는다.
- 음식 차량/시간대 설정을 화물 견적에 전달하지 않는다. 경로 서비스만 공유하며 음식 옵션을 공통 NAVER DefaultOption으로 바꾸지 않는다.
- 기존 FoodDeliveryDriverWorkService의 과거 금액 미보유 기록용 표시 계산은 이번에 변경하지 않았다. 신규 제안의 금액 권위는 원장에 저장한 정책 결과다.

## 계산 예

같은 10km라도 음식 가정(픽업1,000+전달1,000+100m당100+시간대1,000, 포함거리/최소보정0)은 기사 제안13,000원이다.
화물 다마스 기준운임 가정(기본15,000+km당1,200+대기3,000+수작업2,000+수동할증500)은 견적32,500원이다.
이 예시는 독립 정책 시험용이며 운영 요율을 설정한 결과가 아니다.
