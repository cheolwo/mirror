# 운영자 설정: 기사 픽업비·전달 기본비·거리 단가

[운영 · PLAN-OPERATIONS-FOOD-DRIVER-PAYOUT-DETAIL · r10]

기준일: 2026-10-03. 사용자는 픽업 비용·전달 기본 비용·100m당 기본 지급액을 운영자가 설정할 수 있도록 요청했다. 선행은 [기존 요금 엔진 연결 r8](dispatch-calculation.integration.r8.md), [네이버 경로 거리 r9](naver-route-distance.integration.r9.md)다.

## 적용 화면과 저장 흐름

기존 관리자 `음식 운영`(`/food/operations`, `/admin/food-delivery/operations`)의 배달 요금 정책을 보완했다. 기사 픽업비·전달 기본비 분리 설정을 선택하면 각각의 원 단위 입력과 기본 지급 합계가 표시된다. 기본 합계는 두 입력의 합으로 자동 계산한다. 거리 단위의 기본값은100m이며 기사 거리 지급액의 레이블에 현재 거리 단위를 표시한다. 해당 단위는 기존 플랫폼 요금과 기사 거리비에 공통으로 적용되므로 화면에 이를 명시한다.

`FoodDriverPricingEditor`는 화면의 독립 금액을 기존 `DriverBasePayout = pickup + dropoff`, `DriverPickupPayout = pickup` 계약으로 변환한다. 입력 순서를 바꿔도 다른 항목의 금액은 유지한다. 전달비용을 새 DB 열이나 중복 정책으로 추가하지 않고 기존 서버의 총액−픽업액을 사용한다. 기존 GET/PUT `api/v1/admin/food-delivery-pricing-policy`와 서버관리자 권한·저장/재조회·수정자 감사를 재사용한다. 기상 정책 등 화면 밖 값도 유지한다.

미분리 정책의 nullable 픽업비를 화면을 여는 것만으로0이나1,000원으로 바꾸지 않는다. 분리 설정을 명시적으로 선택하면 픽업0원·기존 총액의 전달비로 입력을 시작하고 두 항목을 검토하도록 안내한다. 해제하면 총액은 유지하며 픽업 귀속은 다시미정(null)이다. 저장 전까지는 화면 입력이며 자동 저장하지 않는다.

서버는 음수 금액과 총 기본액을 넘는 픽업액을 거부한다. 전달비 음수 입력도 기존 총액/픽업액 관계 검증으로 차단한다. 최소 지급액·포함 거리·거리 단위 올림 등 기존 요율 규칙은 유지하며 견적에 이를 설명한다. 기존 견적은 기본/거리비만 포함하고 기상·시간대 할증 및 기타 운영비는 제외한다. `플랫폼 마진` 대신 `요금 차액(기타 비용 전)`으로 표시한다.

## 이후 새 제안과 기존 동결 금액

저장한 정책은 이후 새 제안 요금 산정에 사용한다. 이미 정책 판본·금액이 동결된 제안은 기존 r8 경계에 따라 유지한다. 기본 정책에 픽업1,000원·전달1,000원·100m당100원을 자동 주입하거나 운영 DB를 수정하지 않았다. 이 금액을 적용하려면 운영자가 실제 설정 화면에서 금액·포함 거리·최소 지급액을 확인하고 저장한다.

당일 정산·고객/음식점 각각3,000원 재원·멀티 픽업 귀속·할증·오토바이 경로 기준은 각각 별도 정책이다. 이 화면의 기사 지급 설정을 고객 청구액이나 예비금 정책으로 재해석하지 않는다.

## 검증과 남은 범위

Fast(`20261003-084351`)의 관리자/시험 프로젝트 build와 관련48/48 시험을 통과했다. Task(`20261003-084500`)는 전체 `Ssalddel.v3.5.slnx` build 통과, 전체 시험5,531/5,538 통과·7실패다. 실패 집합은 직전 r9 Task(`20261003-083326`)와 동일하며 API 분류·문서 문구·WebApp 분류·재료 CSS의 기존 문제다. 전체 시험 게이트 통과로 보고하지 않는다. 시험은 미분리 값의 무변경, 두 금액의 독립 편집/직렬화, 기존 기상 설정 보존, 서버 저장→재조회→신규 Policy 계산→이전 계산 snapshot 보존, 무효 전달비 저장 차단을 검증한다.

실제 관리자 브라우저/화면 렌더·운영 MySQL 저장·기사 기기·운영 요율 활성화·commit/push는 미수행이다. 기존 픽업비 열의 운영 DB migration 이행은 r8의 별도 배포 조건이며 이번 작업이 이행 완료 증거를 추가하지 않는다.
