## 1. 목적

기사의 최근 배달 내역에서 한 건을 누르면 최종 금액만 보여 주지 않고, 그 배달에 적용된 지급 구성과 근거를 기사 본인이 확인할 수 있게 한다.

여기서 `기본 배차 요금`은 주문자가 낸 배달비가 아니라 기사에게 약속된 `기사 기본 지급액`이다. 주문자 결제액·음식점 상품대금·플랫폼 수익·기사 지급액을 같은 숫자로 취급하지 않는다.

## 2. 상세 화면 정보 계층

```text
배달 완료 상세
  → 완료 시각·음식점·거친 도착 지역·완료 거리
  → 지급 구성
      기사 기본 지급액
      거리 추가 지급액
      기상 할증
      한시 수요·피크 할증
      기타 확정 조정
      ─────────────
      기사 지급 예정액
  → 정산 상태
      지급 예정 / 승인 / 송금 처리 중 / 지급 완료 / 보류
  → 계산 근거
      거리·정책 판본·판정 시각·기상 근거 요약
```

표시 예시는 다음과 같다.

```text
기사 기본 지급액             2,500원
거리 추가 지급액               450원
기상 할증                    1,000원  · 비
한시 수요 할증                 500원  · 18:00~18:30 정책
기타 확정 조정                   0원
────────────────────────────
기사 지급 예정액             4,450원
정산 상태                    지급 예정
```

표준 지급 행은 적용 여부와 관계없이 항상 표시한다.

- 정책상 적용 대상이 아니거나 조건이 성립하지 않으면 `0원 · 미적용`
- 해당 판본의 세부 항목을 저장하지 않은 과거 자료이면 `세부 근거 없음`
- 조회 오류이면 `확인할 수 없음 · 다시 조회`

세 상태를 모두 0원으로 합치지 않는다.

지급 구성 카드는 기본적으로 펼친 상태로 열고, 기사가 원하면 접을 수 있게 한다. 다시 들어왔을 때의 접힘 상태 저장은 제품 구현 단계에서 접근성·단말 정책과 함께 결정하며, 기본값은 항상 펼침이다.

## 3. 금액 의미와 시점

- `기사 기본 지급액`은 제안 생성 시 적용된 정책의 기본 금액이다.
- `거리 추가 지급액`은 포함 거리를 넘은 구간에 대해 제안 시점의 거리 단위 정책으로 확정된 금액이다.
- `기상 할증`은 서버가 배차 시점에 유효한 강수 근거를 확인해 동결한 금액과 적용 여부다.
- `한시 수요·피크 할증`은 플랫폼이 부담하는 유효 시간 정책으로 새 제안에 동결된 금액이다.
- `기타 확정 조정`은 취소 수행대금·복구 보상 등 별도 승인 원장에 실제로 확정된 항목만 표시한다. 자동 추정하거나 다른 원장과 상계하지 않는다.
- `기사 지급 예정액`은 위 지급 항목 합계이며 `지급 완료액`과 다를 수 있다. 정산 상태를 함께 표시한다.
- 제안 수락 뒤 정책이 바뀌어도 해당 배달의 동결 금액을 소급 변경하지 않는다.

### 공제 전 지급액·법정 공제·실지급액

`기사 지급 예정액`의 현행 의미는 법정 공제 전 기사 지급 총액으로 유지하고 화면에는 `공제 전 기사 지급액`이라고 병기한다.

```text
공제 전 기사 지급액
- 기사 기본 지급액
- 거리 추가 지급액
- 기상 할증
- 한시 수요 할증
- 기타 확정 조정

법정 공제
- 사업소득세 원천징수액
- 개인지방소득세 특별징수액
- 고용보험 기사 부담분
- 산재보험 기사 부담분

실지급 예정액 = 공제 전 기사 지급액 - 기사 부담 법정 공제
```

- 사업소득세·개인지방소득세는 해당 지급이 원천징수 대상 사업소득으로 판정된 경우에만 적용한다. 앱이 계약 형태를 추측해 항상 `3.3%`를 빼지 않는다.
- 고용보험·산재보험은 기사 가입 플랫폼 수가 아니라 실제 노무제공 관계, 적용 직종·피보험 자격, 보수 신고와 공단 부과·정산 결과에 따라 적용한다.
- 고용·산재보험 기사 부담분은 월 보수 기준으로 확정될 수 있으므로 배달 완료 시점에는 `정산 시 확정`, 정산 결과 수신 뒤에는 실제 공제액과 대상 기간을 표시한다.
- 플랫폼 또는 노무제공사업주의 부담분은 기사 부담분에서 빼지 않는다. 기사 화면에 표시하더라도 `플랫폼 부담 · 실지급액에서 차감하지 않음`으로 분리한다.
- 세율·보험료율·필요경비율과 적용 범위는 유효일이 있는 서버 정책·공식 판정 결과가 소유한다. 앱과 과거 원장을 현재 비율로 재계산하지 않는다.
- 원천징수영수증, 보험료 공제계산서 또는 이에 준하는 공식 근거의 발급·조회 상태를 정산 원장과 연결한다.
- 운영 활성화 전 노무·세무 전문가가 계약 형태, 원천징수의무자, 플랫폼 운영자·이용 사업자 책임과 신고 절차를 검토해야 한다.

### 지급 보류 표시

- 기사 화면에는 내부 보류 사유를 세분하지 않고 `지급 보류`라고만 표시한다.
- 기사에게 다른 당사자의 정보, 귀책 추정, 내부 검토 코드와 오류 원문을 노출하지 않는다.
- 더 자세한 확인이 필요하면 `고객센터 문의` 버튼으로 전화할 수 있게 하고 문의용 배달 번호를 함께 보여 준다.
- 고객센터와 운영자 작업공간은 권한이 허용된 범위에서 원장의 상세 보류 사유와 처리 이력을 확인한다.
- 단순 표시는 원장의 보류 사유를 삭제하거나 모든 보류를 같은 업무 원인으로 변경한다는 뜻이 아니다.

## 4. 계산 근거 표시

- 거리: 제안 당시 서버가 사용한 경로 거리와 `예상/확정` 구분
- 정책: `PricingPolicyRevision`
- 판정 시각: 기사 제안 요금 판정 시각
- 기상: 적용 여부, 강수 형태, 관측 기준 시각, 자료 상태·출처의 사람이 읽는 요약
- 피크: 적용 여부와 유효 시간대·승인 정책 판본

원본 hash, API 응답 원문, 정밀 좌표, 주문자 주소와 연락처는 기사 화면에 노출하지 않는다.

## 5. 과거 자료와 결손 처리

- 상세는 제안·수락 시점에 동결된 지급 구성만 읽는다. 현재 정책으로 과거 금액을 다시 계산하지 않는다.
- 기존 자료에 총액만 있으면 `기사 지급 예정액`은 보여 주되 없는 세부 행은 `세부 근거 없음`으로 표시한다.
- 합계가 세부 항목 합과 다르면 앱에서 보정하지 않고 `정산 확인 필요`로 표시한다.
- 지급 구성 조회 실패를 0원으로 바꾸지 않는다.
- 기상·수요·피크 할증이 적용되지 않아도 표준 행은 숨기지 않고 `0원 · 미적용`으로 표시한다.
- 완료 거리와 거리 추가 지급액은 다른 값이다. 실제 이동 GPS 누계로 지급액을 역산하지 않는다.

현재 코드의 `기본거리지급액`은 정책의 기본 지급액과 거리 단위 추가 지급을 합친 결과다. 새 상세 계약은 앞으로 두 항목을 분리 동결해야 하며, 과거 합산 자료를 현재 정책으로 임의 분해하지 않는다.

## 7. 권위와 개인정보 경계

- 앱은 운송·가격·지급 원장의 읽기 결과를 표시할 뿐 금액을 확정하거나 수정하지 않는다.
- 기사 수행대금, 음식점 상품대금, 주문자 결제·환급, 지사 운영보상과 플랫폼 비용은 서로 다른 원장·상태로 유지한다.
- 음식점-기사 관계 상세에서 기사 개인 지급 구성을 음식점에 공개하지 않는다. 지급 상세는 해당 기사 본인과 권한 있는 운영자만 본다.
- 지급 상태가 보류된 경우 보류 사유의 안전한 코드·안내만 보여 주고 내부 오류 원문이나 다른 당사자의 개인정보를 노출하지 않는다.

## 확정

- 최근 배달 내역 한 건의 상세에서 기사 지급 구성을 확인한다.
- 기본 지급, 거리 추가, 기상 할증, 수요·피크 할증, 기타 확정 조정과 총액을 분리한다.
- 제안 시점에 동결된 금액과 정책 근거만 사용하고 과거 금액을 현재 정책으로 재계산하지 않는다.
- 지급 예정과 실제 지급 완료를 구분한다.
- 기사에게는 보류 상세 원인 대신 `지급 보류`와 고객센터 문의 진입점만 보여 준다.
- 관계 상세에는 기사 개인 지급 구성을 노출하지 않는다.
- 모든 표준 지급 행을 항상 보여 주고 `미적용`, `세부 근거 없음`, `조회 실패`를 구분한다.
- 지급 구성은 기본 펼침이며 사용자가 선택해 접을 수 있다.
- 공제 전 지급액, 기사 부담 법정 공제와 실지급 예정액을 구분한다.
- 자격·소득·보험 판정과 월 공제 확정은 서버가 소유하고 앱은 결과를 표시한다.
- 플랫폼 부담 보험료를 기사 부담분으로 차감하지 않는다.
- 플랫폼 부담 보험료는 기본 지급 화면에서 숨기고, 기사가 `보험료 납부 내역`을 열었을 때만 `플랫폼 부담 · 기사 실지급액에서 차감하지 않음`으로 보여 준다.
