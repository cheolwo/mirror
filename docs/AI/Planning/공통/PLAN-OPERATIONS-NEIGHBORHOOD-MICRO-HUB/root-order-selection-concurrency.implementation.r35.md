# 원주문 선택과 관계 동시 변경 보호 r35

- 상태: `Implemented / LocalValidated / DeviceAndOperationalDeferred` (2026-10-08)
- 승인: 사용자가 r40 후속 중 “원주문 선택 화면 동시변경 보호 … 다른 거를 하기보다”를 구현하도록 요청했다.
- 범위: 기존 분산 주문 작성 화면의 원주문 선택과 Mongo 원장 관계 편집의 동시 변경 보호 두 항목이다. 다른 조사 결과·Unity·APK·운영 활성화·commit/push는 포함하지 않는다.

## 선택 화면

선택한 기존 화물 의뢰의 실제 판매자·고객과 인증 사용자를 서버에서 대조하고, 조회 권한이 있는 열린 원주문만 후보로 제공한다. 내부 ID를 직접 입력하지 않는다. 원주문 연결은 선택 사항이며 기존 미연결 작성도 유지한다. 선택 판본·당사자·상태는 저장 시 다시 검사한다. 계정·화물·묶음 변경과 재조회 실패는 오래된 후보를 무효화하며, 작성 물품과 응답이 불명확한 요청의 기존 복구 수명은 보존한다.

## 동시 변경 보호

진행된 하위 업무를 분리하거나 역할을 바꾸거나 필수 조건을 해제하지 못하도록 기존 정책을 저장 경계에도 적용한다. 관계 변경은 원주문과 변경 대상 하위원장의 같은 저장 작업에서 판본을 검사하고, 하위원장을 실제 쓰기 대상으로 잠가 상태 진행과 충돌하도록 한다. 원주문만 조건부 저장하거나 프로세스 내부 잠금만 쓰는 방식으로 완료를 선언하지 않는다. 일반 저장을 통한 상태 변경도 우회 경로가 되지 않아야 한다.

새 연결·순서 변경·필수 조건 강화는 기존 호환성을 유지한다. 업무 revision·이력·개인정보 복원 차단·투영 및 Event 계약을 유지한다. 다중 문서 원자적 저장을 지원하지 않는 환경에서는 파괴적인 관계 변경을 명시적으로 거부하며 일반적인 비파괴 저장은 보존한다.

## 검증

- 권한·당사자·상태·판본·선택 수명·조회 실패/복구·기존 미연결 작성 및 모바일 화면.
- 일반 저장과 상태 명령 양쪽의 진행/관계 경합, 두 저장소 인스턴스, 거부된 작업의 판본·이력·연결 보존.
- 기존 공용 DB와 분리한 로컬 Mongo replica set 시험. 실제 운영 DB 또는 단말 검증으로 확대하지 않는다.
- 이번 소유 경로의 Fast·Task와 공유 계약 소비 solution 확인, 변경 전후 소스 및 비소유 경로 보존.

화면 책임은 [기존 분산 화면](../../../../ProjectOverview/page-docs/distributed-fulfillment-r36.md)에 기록하고 결과는 r41 변경 기록으로 반환한다.

## 완료 반환

두 후속 항목을 구현하고 공유 소비 solution 빌드, 최종 Fast 308개·Task 9,147개를 통과했다. 실패·건너뜀은 0개다. 격리 MongoDB에서 두 저장소 인스턴스의 경합과 트랜잭션 미지원 환경의 거부를 실제 실행했으며, 예시 응답 검토 호스트에서 제품 화면의 선택·실패·재조회·빈 후보를 확인했다. 소스·화면·환경의 증거와 운영상 제약은 [r41 변경 기록](../../../../Changes/2026-10-08-root-order-selection-concurrency-r41.md)에 구별해 남긴다.
