# 전국 생활 공간 입고 재고 관리 기반 r51

`PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB / r51 / ApprovedCurrentRequestScope`

2026-10-10 사용자의 “문의서보다 코드적으로 먼저 정리하고 아파트를 포함한 전국 공간의 입고·공급망 관리 뼈대를 준비” 요청을 아래의 작은 운영 코드 범위로 수용한다. r30의 분산 공간·위치·입고, r31의 보관 합의·사진 증빙, r32의 정산 책임을 재사용하며 새 OS나 지역별 원장을 만들지 않는다.

## 이번 구현 범위

기존 공간 등록은 지역과 독립적인 `SiteId`, `LocationId`, 기존 창고 주소·좌표를 사용한다. 본인 관리 공간 → 권리자·관리자 동의 → 적재 위치 → 상품 원천 → 입고 예정 → 실제 수령 → 재고의 기존 절차를 유지한다. 등록만으로 실제 보관 운영 권한이나 공간 사용 적합성을 확정하지 않는다.

1. 선택한 공간의 입고·재고를 배송 묶음, 운송 원장, 배차, 공공 건물 후보 없이 읽는 인증 API를 추가한다. 관리자는 본인 소유·담당 공간을, 물품 소유자·판매자는 본인 관련 Lot만 조회한다. 기존 서버 관리자 권한 외의 전국 조회 권한을 신설하지 않는다.
2. 공간을 먼저 권한 검사하고 재고를 SQL에서 범위 제한·고유 식별자 순서·페이지 단위로 조회한다. `skip >= 0`, `1 <= take <= 100`, 기본 50건이며 `HasMore`는 다음 한 행으로 판정한다. 입고 예정·실수령·입고 잔여·가용·예약·기존 불량 수량을 서로 구분한다. 합계는 전국 총계나 실제 서비스 공급률로 표현하지 않는다.
3. 응답은 공간 공개명·상태·revision과 Lot·위치·상품·수량으로 제한한다. 주소·좌표·연락처·출입 안내·바코드·증빙은 포함하지 않는다. 물품 소유자 관점에는 관리용 위치 이름도 노출하지 않는다. 빈 공간도 관리자가 조회할 수 있고 동의 철회 중 잔존 재고도 숨기지 않는다.
4. 중랑구 참고 건물 후보의 지역 밖 주소는 번들 파일 접근 전에 후보 없음으로 끝낸다. 설정된 지역 자료의 손상·판본·hash 오류는 기존 503으로 유지하며 다른 지역 자료나 샘플로 대체하지 않는다.

## 유지할 경계

- 기존 `Enabled + profile + Simulation + 관계형 DB` 관문과 기본 OFF를 유지한다. 새 실행 모드·유료 가입·결제·외부 알림·배차 효과는 없다.
- 무료 소프트웨어 관리 방향과 실제 보관 노동·배송비·당사자 약정은 별개다. 기존 비용 약정을 0원으로 덮어쓰지 않는다.
- 기존 Command·Event·증빙 입력 JSON·멱등 hash·DB 스키마를 바꾸지 않는다. 실제 정상/불량 분리 입고, 격리 장소·폐기·환불은 후속 수직 작업이다.
- 전국 행정구역/건물 자료 수집, 아파트 사용 권한 정책 확장, 행정서식 제품 작성기, IoT 사물함, 피킹·포장 신규 절차, 앱 UI·APK·Unity는 제외한다.
- r48 상세 제안과 r49/r50 문의 준비는 보존한다. 이번 코드 승인을 해당 제안 전체의 운영 승인으로 해석하지 않는다.

## 검증 상한과 반환

격리 SQLite의 기존 Command로 지역이 다른 공간과 입고 예정·실수령을 만들고 새 조회로 대조한다. 관리자·소유자·판매자·무관 사용자·기사 관점, 페이지 경계·빈 공간·동의 철회 잔존 재고, 읽기 중 상태 불변, 개인정보 제외, 기본 OFF·Operational 차단과 인증 HTTP를 시험한다. 참고 후보는 지역 밖 파일 장애 격리와 지역 안 오류 보존을 검증한다.

관련 build·집중 시험·Fast·Task와 문서 링크/공백 결과를 별도 검증 기록에 남긴다. 로컬 SQLite/HTTP 성공은 실제 MySQL·MongoDB·휴대폰·전국 운영·허가 증거가 아니다. 공용 DB 변경, 관공서 연락·발송, commit·push·배포는 수행하지 않는다.

확정은 위 코드 기반 보완이다. 미정은 실운영 공개·공간별 사용 적합성·후속 검수 정책이며 다음 질문 없이 이 범위를 진행한다.
