# 생활 교류 약속과 선택 배송 보완 r23

2026-10-07. 사용자는 지역 교류의 연결·약속 기록·선택 배송을 우선하고, 당사자가 조건과 직접 지급을 결정하는 기존 흐름을 다듬는 계획을 승인했다. 기존 r9 협업·보관과 r22 전달·배차를 재사용한다.

## 승인 범위

생활 지도는 제공·필요·보관·내 할 일과 선택 대상의 현재 처리를 연결한다. 작성과 조건 수정은 독립 화면에 남긴다. 협업 상세는 현재 상태와 다음 행동, 약속 내용, 전달 방법, 금액과 지급 안내 순으로 정리한다. 입력하지 않은 금액은 미정, 확인한 0은 0원이다.

직접 수령과 직접 전달에는 기사 배차나 기사 비용 설명을 붙이지 않는다. 기사 배송을 선택할 때만 기존 견적·동의·접수로 이동한다. 자동 추천·공개 콜·병행 선택과 기사 부재 시 대기·재탐색, 허용된 조건 변경을 유지한다. 추천을 기사 수락으로 표시하지 않는다.

인계와 상호 완료 확인, 수금 기록, 입금 확인은 구분한다. 확인되지 않은 지급 안내는 플랫폼 입금 미확인으로 설명하며 기존 실제 수금 기록을 덮지 않는다. 취소·동의 철회·보관 반환·문제 접수와 모든 관련자가 동의한 최소 공개 이력을 보존한다.

## 구현 경계

- 페이지 책임은 [현재 책임 카드](../../../../ProjectOverview/page-docs/neighborhood-collaboration-r1.md#생활-교류-약속과-선택-배송-보완-r23)가 소유한다.
- 기존 공통 Razor·ViewModel·navigation을 수정한다. 새 공개 API·DB 테이블·금융 확인 필드는 추가하지 않는다.
- 직접 지급이라는 설명은 법적 중개 분류의 면제 근거가 아니다. [거래·개인정보 보호](../../../../Architecture/CommerceIntermediaryPrivacy.md)와 기존 Operational 준비 관문을 유지한다.
- 일반 물품·작은 보관·생활 배송을 다룬다. 음식/화물 원장·기사 권한·요금 정책·플랫폼 결제·정산 자동화·r4 재고/구매 확장은 변경하지 않는다.

## 검증

직접 수령·직접 전달·자동 추천·공개 콜·병행의 기존 상태와 예외 회귀 시험을 재사용한다. 실제 제품 공통 UI에 읽기 전용 예시 DTO를 연결하여 320/390px에서 상태·주 행동 순서, null/0 금액, 대기·오류·완료·수금 구분과 스크롤을 확인한다. 이 렌더 결과를 실제 서버/DB 업무 완료, APK 단말, Azure, 운행이나 입금의 증거로 확대하지 않는다.

최종 실행 결과와 대표 화면은 [변경 기록](../../../../Changes/2026-10-07-life-exchange-facilitation-r23.md)에 결속한다.
