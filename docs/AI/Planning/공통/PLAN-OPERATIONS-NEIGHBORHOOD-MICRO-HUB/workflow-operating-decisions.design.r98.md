## 수용한 답변과 변경한 재원 방향

- 이전 질문 의미 ID: `community-maintenance-contribution-funding-source`
- 이전 상태: r97의 `Asked / Unanswered`
- 현재 상태: `Answered / NegotiatedPickingPackingContributionDirectionAccepted`

사용자는 앞선 공간 이용료·분배 전 잉여금 재원 제안에 대해, **피킹·포장 등 건별 업무 보수에서 사전에 협의한 5% 또는 10%를 공동주택 기여금으로 연결하는 방향**을 제시했다. 이 방향을 기획에 수용한다. 앞선 공간 수익·잉여금 재원은 선행 제안으로 보존하며 유일한 재원으로 확정하지 않는다.

5%와 10%는 합의할 비율의 선택안이다. 전 단지·전 작업자에게 고정 10%를 적용하거나 협의 없이 자동 공제하는 정책이 아니다. 구체 적용 주체·기본 비율·대상 계약은 미정이다. 이미 완료·확정된 보수와 과거 주문에 소급 적용하지 않는다. 기사 배송료·상품대금·입고/보관비까지 일괄 적용하는 것으로 확대하지 않는다.

r97에서 수용한 개인 보수와 단지 공동기여금의 두 경로를 유지한다. 개인에게 남은 금액을 본인 관리비 납부에 사용하는 선택과 단지 기여금으로 공동관리비를 지원하는 목적은 구별한다.

## 계산의 제안과 예시

`기여 기준액 = 해당 건에서 적용하기로 합의한 피킹 보수 + 포장 보수`

`기여 예정액 = 기여 기준액 × 합의한 비율`

`기여 후 잔액 = 기여 기준액 − 기여 예정액`

| 기여 기준액 | 합의 비율 예시 | 기여 예정액 | 기여 후 잔액 |
| --- | --- | --- | --- |
| 10,000원 | 5% | 500원 | 9,500원 |
| 10,000원 | 10% | 1,000원 | 9,000원 |

이는 세금·보험·기타 공제를 제외한 산술 예시이며 세후 수령액·실제 지급·관리비 반영 결과가 아니다. 실제 과세/공제의 기준을 기여 후 잔액으로 자동 바꾸지 않는다. 원 미만 처리·작업자별/작업별 계산과 묶음 정산의 관계는 후속 설계 대상이다.

포장을 실제로 하지 않았다면 예정된 포장비까지 기여 기준에 넣지 않는 방향이다. 고정 보수 약정은 실제 적용 계약에 따른 금액을 확인하며 단순 작업 수 추정으로 금액을 채우지 않는다. 여러 작업자의 보수를 묶을 때에는 각자의 기준액·합의율을 먼저 보존한다.

## 합의와 실제 납부 방식의 구분

업무 시작 전에 기여 대상 항목·비율·귀속 단지·예정액·개인에게 남는 금액·효력 시점을 알 수 있도록 제안한다. 작업자 본인의 동의 확인과 단지/업무 약정 판본을 연결하고, 새 조건을 이미 수락한 업무에 소급하지 않는다. 같은 유효 약정 아래의 매 건마다 동의 버튼을 반복하도록 정한 것은 아니다.

근로관계에 해당하는 경우 [근로기준법 제43조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0043&lsiSeq=285279&urlMode=lsScJoRltInfoR)는 임금의 직접·통화·전액 지급을 원칙으로 하고 법령·단체협약의 특별 규정에 따른 예외를 둔다. 개별 합의가 있다는 이유만으로 임금에서 기여금을 바로 공제해도 된다고 판단하지 않는다. 건별 보수·프리랜서라는 명칭만으로 적용 여부를 확정하지 않는다. 2026-10-15 해당 공식 조문을 다시 확인했다.

따라서 **본인 보수 지급 후 별도 자율 기여**를 우선 검토안으로 둔다. 이는 현재 사용자가 선택한 실행 방식이나 모든 계약에 의무인 방법은 아니다. 계약 단계에서 나누는 방식·직접 납부·반복 납부 동의의 실제 허용 범위는 해당 계약·지급 관계에 맞춰 후속 확인한다. 기여금 납부 실패를 이미 완료한 업무나 개인 보수 지급의 실패로 바꾸지 않는다.

기여율 협의와 실제 관리비 반영은 별개다. [공동주택관리법 시행령 제19조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0019&lsiSeq=287261&urlMode=lsScJoRltInfoR)의 관리규약준칙 사항에는 회계관리, 세대별 관리비 부담·사용 절차, 관리 등에서 발생한 수입의 용도·사용 절차가 포함된다. 실제 단지 규약·관리주체와 맞춰 기여금의 수령·사용·관리비 반영을 확인하는 설계가 필요하다. 조문 확인을 특정 단지의 사업 운영 허가·기여금 회계처리 확정으로 표시하지 않는다.

## 원장 연결과 중복 방지

```text
원주문·실제 피킹/포장 완료 근거
└─ 합의한 총 작업 보수 발생: 한 번만 기록
   ├─ 본인 지급·수령 근거
   │  └─ 본인이 선택한 본인 관리비 사용: 별도 기록
   └─ 같은 보수를 원천으로 삼은 단지 기여 약정·계산
      └─ 실제 기여금 납부 확인 → 단지 공동재원
         └─ 관리주체의 사용·관리비 반영 확인
```

기여금 계산만으로 개인 보수 채무를 줄이거나 단지 현금 잔액을 늘리지 않는다. 총 보수 발생, 기여 예정, 본인 지급, 실제 기여 납부, 단지 수령, 관리비 반영을 구별한다. 본인에게 지급한 돈의 일부가 나중에 단지로 이동한 경우 같은 원천과 이전 근거를 연결하며 새 업무 매출·보수를 다시 발생시키지 않는다.

r61의 플랫폼 잔여금 보유율 5%/10%와 이번 단지 기여율 5%/10%는 서로 다른 정책·기준액이다. 개인의 기여와 플랫폼 몫·공동 성과금·지역 기금에 같은 금액을 중복 귀속하지 않는다. 특정 작업자의 기여금을 다른 주문의 운영 재원으로 자동 쓰지 않는다.

실적·보수 조정이 필요한 경우 기존 원천을 덮어쓰지 않고 별도 조정과 관련 지급/기여 결과를 대조한다. 이미 납부된 기여금을 자동 회수하거나 작업자에게 같은 보수를 다시 청구하지 않는다. 불명확한 납부 응답은 같은 요청의 결과를 먼저 조회한다. 단지 주민에게 공개할 공동재원 합계와 개인별 보수·기여 상세의 접근 범위는 분리한다.
