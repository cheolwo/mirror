# 기사 업무 선택과 공통 수락 보호 r71

2026-10-15. 상태 `Implemented / LocalValidated / OperationalDeferred`. 사용자의 `계속 구현해 줘.`는 직전 제안의 우선 구현 범위인 1·2번을 승인한다. [r36 설계](driver-flexible-multi-work.design.r36.md)의 기존 기사 중심 원칙을 사용한다.

## 구현 범위

한 인증 사용자가 음식·소형 물품 퀵·화물의 희망 업무와 직접 피킹 옵션, 현재 차량 종류·사용 가능 중량/부피·희망 동시 건수·추가 제안 의사를 저장한다. 희망은 실제 기사 자격이나 공간 접근 권한을 만들지 않는다. 음식/화물/마트/분산의 전문 원장과 기존 사진·단가·수락·완료·정산은 보존한다.

서버 설정은 SQL 사용자별 고유 행과 판본으로 관리한다. 같은 행을 수락 트랜잭션의 첫 공통 잠금으로 사용하고 음식·화물·마트의 미완료 확정 운송을 중복 없이 읽는다. 설정 갱신도 이 행과 동시성 제어를 공유한다. 일부 수락·동일 요청 재조회·기존 업무의 조회와 완료는 신규 제안 의사 변경으로 막지 않는다. 기능 OFF는 기존 처리이며 ON에서는 설정 없는 기사의 신규 제안·수락을 보류한다.

이번에는 별도 통합 상태 원장을 만들지 않는다. 음식 최대 3건, 화물 차량/혼적/일정, 일반회원 배송의 배타 보호, 분산 순회의 다른 업무 보호는 유지한다. 공통 희망 상한은 기존 전문 상한을 확장하는 명령이 아니다. 음식 적재량·전달 기한 등 근거가 없으면 음식+화물 동시 수락을 허용하지 않고 이유를 반환한다. 순차 업무 전환과 기존 검증된 유형 내 다건 수행은 지원한다. 향후 혼합 경로는 서버의 전체 시간/구간별 적재 근거가 갖춰진 뒤 이 관문에서 확장한다.

DriverApp 운행 설정과 FDriver 내정보에서 같은 공통 업무 설정 UI를 사용한다. 저장 한 번 뒤 정본 재조회, 판본 충돌, 결과 불명확 시 재조회, 계정 변경/취소/늦은 응답을 보호한다. 지도·현재 업무 전체 통합, APK 합병, 새 요금 산정, 타 역할 앱 확대는 후속 3·4번이다.

## 경계와 완료 기준

- `SharedDriverWork:Enabled` 기본 OFF. 운영 기능/공용 DB/클라우드/푸시/실지급을 켜지 않는다. 새 스키마 migration은 준비만 하며 공용 DB에 적용하지 않는다.
- 공개 값은 안정된 코드, 중량 kg·부피 L이며 주소/고객 정보는 설정에 넣지 않는다. 알 수 없는 제원을 0으로 채우지 않는다.
- 자기 계정 설정 API, 입력 판본/범위/불변성, 실제 서버 추천 필터, 모든 수락 경로의 공통 잠금, 같은 사람의 동시 마지막 여유 수락·설정 변경 경합·요청 재생을 검증한다. SQLite 실제 DB 시험과 MySQL 스키마/잠금 증거의 범위를 구별한다.
- UI 상태/세션/불확실 저장 시험, Fast·Task 명시 Paths, 소비 앱 빌드, 가능한 로컬 화면 확인, 기존 dirty 파일 해시 보존을 수행한다. 휴대폰·APK 배포·실운행 검증과 구별한다.
