# 일반 회원 생활 배송 참여 구현 r39

- 날짜: 2026-10-09.
- 승인: 전체 상황 조사 뒤 사용자가 일반 회원부터, 기존 요금 계산, 등록한 활동 위치, 여러 명 동시 제안을 선택하고 “Implement the proposed plan.”을 요청했다.
- 상태: `Implemented / LocalValidated / DeviceAndOperationalDeferred`. 사용자 선택에 따라 로컬 검증·APK까지 완료했다. 실행 결과는 [r43 변경 기록](../../../../Changes/2026-10-09-neighborhood-member-delivery-r43.md)에 별도 결속한다.
- 최신 실행 범위: 사용자는 Firebase 준비 질문에 “지금은 로컬 검증·APK까지만”을 선택했다. 이번에는 Firebase 실연결·휴대폰 설치·Azure 배포를 진행하지 않으며 알림 구성 미완료를 성공으로 표시하지 않는다.

## 최소 운영 단위

생활 제공·필요 글과 협업을 그대로 사용한다. 글을 등록했다는 이유만으로 배송을 만들지 않는다. 당사자가 배송을 명시적으로 요청하고 물품·장소·시간·요금 및 배송 수행자에게 필요한 정보 제공에 동의한 건만 기존 생활 배송 의뢰에 접수한다. 플랫폼·배차 수수료는 0원이며 배송 수행 보수는 기존 화물 견적의 확정 판본을 사용한다. 거래대금·배송비 신고·상대방 확인·실제 입금은 별도다.

회원이 배송 참여를 켜더라도 일반 계정에 광범위한 기사 역할을 부여하지 않는다. 본인이 수락한 의뢰에만 조회·사진·픽업·전달 권한을 부여한다. 음식 주문·조리와 전문 화물 기사·분산 창고 업무는 기존 독립 원장과 조건을 유지한다. 혼합 다건 수행 r36과 미성년 정책 OFF는 이번 구현으로 활성화하지 않는다.

## 참여·제안·수락

참여 기본값은 OFF다. 본인 비공개 활동 기준점, 초기 반경 3km, 이동 수단·적재 여력·수신 의사를 저장한다. 기준점은 제안 대상을 찾는 고정 위치이며 실제 GPS·현재 기사 위치·ETA로 저장하지 않는다.

적격 회원에게 동시에 제안을 제공하며 유효기간은 최대 5분과 의뢰의 기존 시간창 중 짧은 쪽이다. 수락에는 현재 계정·미만료 제안·조건 판본·현재 GPS·실제 경로·남은 시간·적재 여력을 다시 확인한다. 현재 위치는 5분 이내·오차 100m 이하를 요구한다. 한 회원은 첫 판본에서 진행 배송 1건만 맡을 수 있으며 기존 음식·화물 진행 업무와도 겹치지 않게 확인한다.

기존 기사 수락과 회원 수락은 같은 SQL 의뢰/배차 권위를 경쟁한다. 다중 서버에서 한 사람만 원자적으로 확정하며 다른 제안은 더 이상 수락할 수 없다. 응답이 끊긴 요청은 같은 stable 요청 키로 원 결과를 먼저 확인한다. 회원 수행자를 기존 기사 ID로 가장하지 않는다.

## 수행·증빙·복구

픽업과 전달은 현재 수행 건에 결속된 비공개 사진의 실제 업로드 확인 후 각각 완료한다. 촬영·전송·완료 명령은 구분하고 사진 문자열·클라이언트 해시만으로 완료를 인증하지 않는다. 전달 완료와 받는 사람의 수령 확인을 합치지 않는다. 픽업 전/후 취소·수행 중 문제 접수는 기존 원장과 지원 사건의 복구 경계를 따른다.

제안 목록과 앱 알림 원장이 푸시 누락·거절·만료·앱 재시작에서 복구 경로가 된다. 일반 앱 전용 Firebase 구성과 Android 알림 권한이 있어야 실제 FCM을 수신한다. 토큰은 계정·앱·설치에 결속하고 로그아웃·교체·토큰 갱신을 처리한다. 잠금 화면에는 상세 주소·연락처·정확한 위치를 넣지 않는다. 탭하면 허용된 내부 경로로 이동하여 로그인·현재 제안을 서버에서 다시 확인하며 수락을 자동 실행하지 않는다.

## 화면 책임과 실행 경계

[페이지 책임](../../../../ProjectOverview/page-docs/neighborhood-member-delivery-r43.md)에 참여 설정, 제안 목록·상세, 현재 수행을 분리한다. 지도는 전체 영역을 유지하고 현재 업무 카드는 독립적으로 접는다. 현재 상태에서 필요한 정보와 주 행동을 우선한다. 원시 좌표·내부 판정·푸시 설정 진단은 제품 업무 화면에 나열하지 않는다.

기존 `Simulation` / `Operational` 실행 모드와 운영 준비 관문을 사용한다. 회원 배송 기능 및 Operational 활성화는 기본 OFF다. 로컬 구현·시험·HTTP/DB 대조·APK 빌드와 실제 휴대폰·Azure HTTPS·운행·입금을 별도로 기록한다. 처음 운영할 때는 준비된 환경에서 초대한 성인 3~5명과 생활 물품 하루 1~3건부터 확인한다. 지금 구현한 기능만으로 운영 허가·입금·실제 배송 성공을 인증하지 않는다.
