## 공통 문의의 목적

아직 특정 단지·구획을 정하지 않은 상태에서 필요한 담당 부서, 공간 유형별 절차, 향후 개별 상담에 필요한 최소 자료를 알아본다. 공간 확보·주민 협의·위임·동의·공사·영업이 이미 진행된 것처럼 서술하지 않는다. 일반 질의 답변은 특정 공간의 허가·면제·운영 가능 판정으로 사용하지 않는다.

[공통 사전 문의 원본](administrative-common-inquiry.template.r50.md) 하나를 유지한다. 각 지역 문의는 이 원본에서 수신 기관과 지역명만 바꾸어 시작하고, 내용·연락처·첨부·공식 수신처를 해당 건에서 별도로 확인한다. 지역별 답변과 조건은 서로 대체하지 않는다. 구리시는 구가 아니라 시 단위 수신 기관으로 구분한다.

## 지역별 준비 대장

아래 다섯 곳은 양식의 재사용 대상이며 발송 대상 확정이나 일괄 발송 지시가 아니다. 담당 부서명·이메일·접수 채널·확인일은 공식 안내를 실제 대조한 뒤에만 채운다.

| 지역 | 수신 기관 표기 | 담당 부서와 공식 문의 채널 | 수신처 확인일 | 발송·접수·회신 |
| --- | --- | --- | --- | --- |
| 서울특별시 중랑구 | 중랑구청 | 미확인 | 미확인 | 없음 |
| 서울특별시 동대문구 | 동대문구청 | 미확인 | 미확인 | 없음 |
| 서울특별시 광진구 | 광진구청 | 미확인 | 미확인 | 없음 |
| 서울특별시 노원구 | 노원구청 | 미확인 | 미확인 | 없음 |
| 경기도 구리시 | 구리시청 | 미확인 | 미확인 | 없음 |

주소 문자열이나 인접 지역만으로 담당 부서·법령 적용·이메일을 확정하지 않는다. 홈페이지 접속 성공만으로 문의 수신처가 검증된 것은 아니다. 이번에는 실제 이메일·전화·민원 접수 없이 공통 본문과 대장만 준비한다.

## 최소 입력과 나중에 받을 자료

일반 문의에 먼저 필요한 것은 선택 지역, 문의자 표기, 회신 연락처, 공유할 서비스 개요다. 이름·소속·연락처는 실제 사용자가 확인한 값으로만 작성하고, 조직·사업자·권한을 임의로 만들지 않는다. 불필요한 개인정보나 다른 사람의 연락처를 포함하지 않는다.

단지명·상세 주소·구획 면적·승인 용도·권리자·주민 동의서·사업자 정보·도면은 **대상 선정 후 확인**으로 둔다. 지금 임의의 장소나 면적을 생성해 채우지 않는다. 기관이 일반 질의에서도 추가 정보를 요구하면 필요한 항목만 문답으로 보완하며 자동 조회·공개·전송하지 않는다.

상온 소형 포장 물품, 사람의 인계, 선반·전자사물함 등은 질문을 설명하기 위한 후보로만 적는다. 품목·설비·운영시간·유상 여부·이용 범위·공사 방식은 아직 확정하지 않았음을 본문에서 구별한다. 냉장·식품 취급 등 별도 조건은 허용된 것으로 간주하지 않는다.

## 기관에 확인할 질문

1. 공동주택의 공용부분·전용부분 또는 단지 내 별도 공간을 검토할 때 담당 부서와 협의 순서는 무엇인가?
2. 승인 용도·사용 현황·설비/공사 변경에 따라 허가·신고·다른 절차를 구분하려면 어떤 자료가 필요한가?
3. 권리자·관리주체·입주자대표회의 등의 동의·의결·위임을 어떤 기준과 자료로 확인해야 하는가?
4. 유상/무상, 입주민 전용/외부 이용, 품목·보관 조건에 따라 추가 확인할 기준은 무엇인가?
5. 통행·피난·소방·보안·소음·차량 대기 등 현장 검토 항목과 관련 부서는 무엇인가?
6. 공간 선정 후 상담에 필요한 최소 자료, 최신 공식 서식·첨부, 문의와 정식 접수 채널은 무엇인가?

## 검토와 회신 연결

원본 판본 → 기관별 초안 → 수신처/내용/개인정보 검토 → 건별 발송 승인 → 발송 증거 → 기관 접수 → 회신을 구분한다. 원본을 작성했다는 이유로 기관별 초안이나 발송 승인을 자동 생성하지 않는다.

후속 회신 기록에는 기관·부서·날짜·문의 범위·원문 비공개 참조·추가 요구 자료·다음 담당자를 연결한다. 연락처·민원 번호·회신 원문은 공개 Git 문서에 넣지 않는다. 한 지역의 회신을 다른 지역이나 개별 단지의 사용 승인으로 옮기지 않는다.

## 확정과 미정

- 확정: 특정 공간 없는 공통 문의 원본 한 개와 위 다섯 지역의 준비 대장을 먼저 만든다. 일반 질의와 개별 공간 신청을 구별한다.
- 미정: 실제 문의자·회신 연락처, 공식 담당 부서·채널, 각 건 발송 여부, 대상 공간과 개별 신청, 제품 자동 작성기 구현.
- 다음 질문 하나: 문서 준비 후 실제 문의를 진행할 단계가 되면 어느 한 지역부터 수신처와 내용을 확인할지 정한다. 지금 답변은 필수가 아니며 발송은 별도 요청 전 진행하지 않는다.

## 검증 범위

공통 문구에 특정 단지·권한·허가·수신처를 생성하지 않았는지와 지역 다섯 곳의 분리를 대조한다. 문서 링크·공백·Fast 검증 결과는 `CURRENT_WORK.md`에 남긴다. 제품 코드·DB·앱·Unity·법적 적합성 판정·관공서 연락·발송·민원 접수·commit/push·배포는 이번 범위에서 수행하지 않는다.
