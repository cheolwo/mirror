음식 행동 입력은 typed 명령 응답과 후속 원장 확인을 구분하고, 행동별 대상·이번 요청 이력·변경 상태/값·기대 revision을 대조해 완료를 판정한다. typed 명령 응답을 확보한 뒤의 읽기 실패/이전 상태에서는 조회만 재시도한다. 명령 응답 미확인의 기존 불변 본문·동일 요청 ID, 권한·계정/대상 변경·늦은 응답 보호는 유지한다. 조리 시작·준비·재조리 등 정상 후행 변경도 실제 이력·차수·시각으로 대조한다. 기존 서버 계약과 ActionId를 변경하지 않는다.

기사 카드에는 짧은 기본 요약을 추가해 수락 전 배달료/제안 거리/픽업지, 픽업 중 주소/준비 안내, 전달 중 주소/필수 요청을 표시한다. 상세 접기에는 긴 메뉴와 주문 정보, 기존 보호된 수령인·연락처를 유지한다. 실제 DTO에 없는 거리·주소·금액을 생성하지 않고, 공통 계약의 새 표시 필드는 선택 사항으로 둬 기존 역할 소비를 보존한다.

검증은 상태가 바뀌지 않은 응답, 후조회 실패 뒤 읽기 전용 복구, 요청 응답 미확인 뒤 같은 명령 ID 재시도, 계정/대상 변경, 접힌 기사 카드의 필수 값과 개인정보, 긴 주소/요청과 좁은 폭을 대상으로 한다. Fast/Task와 소비 client 빌드·공유 UI 렌더·최신 내장 Debug APK를 별도 기록한다. 실제 운영 API/DB·휴대폰·Azure·지도 타일 실행은 이번 증거로 확대하지 않는다.

완료 후 다음 업무 선택, 자동 갱신, 목록 페이지 확장은 다음 제안으로 남긴다. 기존 dirty 변경과 r11 결과를 보존하고 commit/push/외부 배포는 포함하지 않는다. 결과는 [변경 기록](../../../../Changes/2026-10-05-role-workspace-completion-card-r12.md)에 결속한다.
