# 근무시간 안내 기한과 운영자·고객센터 관리자 알림 기획 r82

- 기획 ID: `PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB`
- 판본: r82, 2026-10-15
- 상태: `AcceptedDirection / ClarificationPending / ImplementationNotAuthorized`
- 이전 답변: [고객센터 관리자 권한·운영자 알림 r81](workflow-operating-decisions.design.r81.md)
- 기준 구현: [r76](workflow-exception-closeout.implementation.r76.md). 이번 변경은 기획 문서이며 알림 발송·기한 계산·권한 변경을 구현하지 않는다.

## 확정과 미정

- 질문 의미 ID: `reported-delivery-issue-first-response-window`
- 이전 상태: r81의 `Asked / Unanswered`
- 현재 상태: `PartiallyAnswered / BusinessHoursDirectionAccepted / DurationClarificationPending`
- 사용자 답변 원문: **“그래 뭐 그렇게 하는 게 좋긴 한데 내가 보기에는 한 6시간 정도 뭐 근무 시간 내 이제 24시간 영업일 내 24시간 좀 이렇게 좀 고정을 해두는 게 좋겠다라는 생각이 있지. 그렇게 하고 이제 뭐 운영자한테도 알림이 가고 고객센터의 그런 이제 관리자한테도 이제 알림이 가는 그러한 이제 형국인 거지 뭐.”**

운영자와 해당 사건 담당 고객센터 관리자 모두에게 알림이 가는 방향을 확정한다. 신고 접수와 처리 결과를 두 수신자에게 알리되, 운영자의 승인·읽음 확인을 센터 관리자 처리의 선행 조건으로 두지 않는 r81 방향을 유지한다. 모든 센터 관리자에게 사건 자료를 공개한다는 뜻은 아니다.

안내 기한은 근무시간·영업일을 고려하여 고정한다는 방향을 수용했다. 다만 답변에 6시간과 24시간이 함께 있어 어느 수치가 첫 안내에 해당하는지, 별도 경과 안내 기한도 의도한 것인지는 아직 확정하지 않는다. 24시간을 1영업일로 임의 환산하거나 근무시간 24시간과 실제 경과 24시간을 같은 값으로 취급하지 않는다.

## 업무 흐름

```text
고객 신고 접수
├─ 해당 주문의 미지급 정산 보류
├─ 운영자에게 접수 알림
├─ 담당 고객센터 관리자에게 접수 알림
└─ 상담원 1차 확인 → 센터 관리자 처리
   ├─ 근무시간을 고려한 첫 안내 [구체 기한 확인 중]
   ├─ 필요 시 추가 확인·처리 경과 안내
   └─ 처리 결과 안내 및 운영자·담당 센터 관리자 알림
```

첫 안내는 접수 자동 알림과 구분한다. 안내 기한이 지난 것만으로 정산 보류 해제·환불·책임 판정·사건 종결을 자동 실행하지 않는다. 관리자의 처리 결정, 실제 재배송·환불·정산·송금 결과와 알림 전달 결과는 별도로 남긴다.

## 다음 질문 하나: 같은 안내 기한 질문의 구체화

- 질문 의미 ID: `reported-delivery-issue-first-response-window` (기존 질문 유지)
- 상태: `Asked / ClarificationPending`
- 확인 질문: **첫 확인·안내는 근무시간 기준 6시간 이내, 처리 경과·다음 일정 안내는 근무시간 기준 24시간 이내로 나누면 말씀하신 뜻에 맞는가?**
- 대안: 첫 안내만 근무시간 기준 24시간 이내 또는 6시간 이내로 정하는 뜻일 수 있다. 사용자가 구체화하기 전에는 두 단계 기한을 확정하거나 구현하지 않는다.
- 별도 미정: 기한의 기산 시점, 실제 근무 시간표·휴일·시간대, 근무 외 접수 안내, 경과 안내 주기와 최종 해결 기한. 구체 기한 답변을 받은 뒤 필요한 순서로 논의한다.
