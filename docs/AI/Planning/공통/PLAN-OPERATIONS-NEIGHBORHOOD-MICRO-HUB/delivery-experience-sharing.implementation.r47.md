- 구현 책임: 서버가 완료 사실·장소·동의·현재 업무 권한을 판정하고 앱은 허용된 요약만 표시한다.

## 사용자에게 제공할 결과

기사의 현재 픽업 카드에 `이 매장 픽업 완료 4건`, 전달지 카드에 확인된 도로·단지의 완료 건수를 표시한다. 공유를 켠 기사에 한해 음식점은 현재 배정 기사의 자기 지점 경험을, 주문자는 현재 전달 기사의 자기 전달 지역 경험을 본다. 매장·전달 지역의 완료 건수는 서로 다른 지표다.

이는 실제 방문 횟수가 아니다. 같은 현장에서 동시에 픽업한 세 주문은 세 건이다. `N번째 방문`과 예정 방문 순번은 표시하지 않는다. 완료한 업무를 친숙함의 참고 정보로 제공하며 배차 점수·요금·평가에 연결하지 않는다.

## 집계와 장소 근거

- 기존 음식 주문·배달 시도의 픽업/전달 완료를 원천으로 사용한다. 기사·주문·완료 종류당 한 번 집계하며 현재 시도 근거와 실행 모드를 보존한다.
- 완료 transaction 안에 집계 Outbox를 남기고 후속 투영은 멱등 재처리한다. 집계 지연을 업무 완료 실패로 바꾸지 않는다.
- 매장은 지점 ID, 도로는 확인된 도로 관리번호, 단지는 확인된 단지 코드를 사용한다. 단지 건수를 도로 건수로 복사하지 않는다.
- 기존 주소검색의 선택 결과를 수령지 기본주소와 서버에서 대조한다. 기본주소 수정 시 선택 근거를 버리고 상세 동·호수 입력은 유지한다. 공공 데이터 키·확인 근거가 없으면 기존 주문은 허용하고 지역 경험만 미확인으로 둔다.
- 과거 앱 기록은 실제 완료·기사·주문·실행 모드를 대조한 것만 보완한다. 추정 생성 시도·불명확한 지역·영상 원장은 자동 합산하지 않는다. 시뮬레이션과 운영 집계를 분리한다.

## 공유 계약과 화면

- 공유 기본 OFF. 본인 `GET/PUT /api/v1/driver/preferences/delivery-experience-sharing`은 판본을 검사하고 저장 결과를 재조회한다.
- 기존 세 역할 응답의 선택적 `ExperienceSummaries`는 장소 종류/표시명, 완료 건수, 근거 상태, 집계 시점, 실행 모드를 포함한다. 다른 고객·과거 시각·상세 주소·이동 기록·새 공개 기사 ID를 반환하지 않는다.
- 음식점/주문자에게는 현재 유효한 배정 및 진행 중 주문만 허용한다. 공유 철회·계정 전환·재배정·취소·종료 시 요약을 제거한다. 기존 완료 후 3일 고객 상세 제한은 유지한다.
- 기존 카드 안 보조 문구로 한 줄, 전달 지역은 최대 두 줄을 사용한다. 전문 앱과 공용 역할 화면이 같은 요약을 사용한다. null·미확인·조회 실패를 0건으로 표시하지 않는다.
- 음식점의 기존 실시간 상태 갱신 및 주문자의 기존 10초 진행 주문 재조회를 재사용한다. 별도 경험 알림·소리·FCM 인박스를 추가하지 않으며 반복 조회로 기존 업무 알림을 중복 재생하지 않는다.

## 소유권과 검증

서버·공유 계약 담당, 네이티브 기사 담당, 공용 역할 UI 담당을 분리하고 통합 담당이 DI·migration/snapshot·문서·최종 검증을 소유한다. 기존 r45/r46/주문 원장 r7 및 다른 dirty 변경은 보존한다. 구체 쓰기 경계는 [작업 명세](delivery-experience-sharing.r47.work-order.json)를 따른다.

검증은 중복/동시 완료·재배차·취소·Outbox 재처리·과거 기록 재적용·동명 지점/도로·단지 독립 집계·OFF/철회/계정 변경·늦은 응답·3일 제한·기존 업무 회귀를 포함한다. 공유 DTO와 실제 역할 컴포넌트를 작은 화면에서 대조하고 Fast/Task 및 소비 앱 빌드를 진행한다.

신규 기능 기본 OFF. 로컬 격리 검증만 활성화한다. 실제 DB 적용·원격 푸시·실기기·Azure·실운행·Unity·영상 편집·commit/push는 별도이며 이번 구현 승인이 해당 실행을 포함하지 않는다.
