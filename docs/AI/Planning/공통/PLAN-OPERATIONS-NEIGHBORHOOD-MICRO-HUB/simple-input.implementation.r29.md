# 생활 배송 간편 작성과 엑셀 입력 구현 r29

2026-10-07. 상태 `Approved`. 사용자는 [r29 제안](simple-input.design.r29.md)의 다음 질문인 생활 배송 간편 작성·엑셀 우선, 음성 후속 순서에 `어`로 동의했다. 승인 범위는 기존 생활 배송 한 건의 입력을 간편화하고 `.xlsx`의 선택 행을 같은 작성 초안으로 가져오는 첫 구현이다. 음성 인식·외부 AI 전송·전체 역할 앱 확장·외부 업체·실금전은 제외한다.

물품·장소·시간·최종 확인의 단계형 작성과 선택 상세 입력을 제공한다. 주소·연락처·중량·시간창을 임의로 확정하지 않는다. 엑셀은 판본 있는 양식, 최대 2 MiB 파일·100개 업무 행·20 MiB 전체 압축 해제·2 MiB XML part로 제한하고 수식·매크로·암호화·외부 링크를 거절한다. 필수 열은 고정하고 누락 값은 행별 보완 항목으로 표시한다. 임의 열 AI 매핑은 후속이다.

업로드는 인증과 기존 개인정보 동의 확인 후 메모리에서 검토 초안만 만든다. 원 파일·초안·토큰은 DB·디스크·로그에 보존하지 않는다. 한 행을 선택해 기존 ViewModel에 적용한 뒤 견적·동의·접수·원장 재조회로 연결하며 일괄 자동 접수는 하지 않는다. 진행 중·결과 불명확한 접수의 원 요청은 다른 입력으로 바꾸지 않는다. 입력 변경·소유자 변경·로그아웃·늦은 응답은 기존 무효화와 삭제 경계를 따른다.

선택적 행 ID는 유효 GUID이면 기존 요청 번호로 재사용한다. 없는 행은 현재 작성 session에서 고유 요청 번호를 부여해 같은 행의 재선택/재시도를 보호한다. 파일 hash만으로 과거 접수 여부를 보장하지 않으며 재시작·값 수정·새 파일의 행 ID 없는 재업로드는 내 의뢰 확인과 별도 검토가 필요함을 표시한다. 확실한 재업로드 추적에는 행 ID 보존을 사용하며 동일 내용의 다른 배송은 자동 합치지 않는다.

기존 route·원장·UseCase·권한·견적·r28 수행 경계를 보존한다. 새 미리보기 API는 기존 생활 배송 Controller에, 공통 입력 계약은 Contracts에 둔다. 원장 생성·배차·외부 호출 없는 파싱과 실제 접수를 분리하며 새 DB schema는 추가하지 않는다.

검증은 파싱 제한·셀 출처·행별 누락·전화 문자열·시간·중복 행 ID·악성 파일·권한/동의, UI 단계와 선택행 적용·견적 무효화·늦은 응답·로그아웃·접수 불명확 재시도를 시험한다. 공통 UI 실제 320/390px 렌더와 영향 소비 build·Fast/Task를 별도 기록한다. 인증 HTTP/실DB·APK·휴대폰·실제 업체·결제·운영 배포는 수행 결과가 있을 때만 별도 주장한다.

파일 소유권과 정확 경로는 [작업지시서](development-work-order.r29.md)에 결속한다. 기존 dirty 변경은 보존하고 commit·push·배포는 수행하지 않는다.
