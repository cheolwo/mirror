# 고객 신고 24시간·72시간 처리와 운영자 인계 기획 r84

- 기획 ID: `PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB`

- 상태: `AcceptedDirection / QuestionsOpen / ImplementationNotAuthorized`
- 이전 답변: [응답 6시간·처리 24시간 r83](workflow-operating-decisions.design.r83.md)
- 기준 구현: [r76](workflow-exception-closeout.implementation.r76.md). 이번에는 기획 문서만 갱신한다.

## 확정한 답변

- 질문 의미 ID: `reported-delivery-issue-unresolved-deadline`
- 이전 상태: r83의 `Asked / Unanswered`
- 현재 상태: `Answered / HandlingSeventyTwoHoursAccepted / OperatorEscalationAccepted`
- 사용자 답변 원문: **“뭐 그렇게 하는 게 좋기는 답이 나지. 24시간 내 안 되면은 72시간 내 처리하도록 그렇게 해두고 그게 안 되면은 뭔가 문제가 좀 이렇게 심각한 문제가 있다고 판단이 되는 경우니까 그런 걸로 지금 운영자가 처리를 해야 될 부분이라고 생각이 되기는 하네. 뭐 약간 좀 소송까지도 갈 수 있을 만한 그런 여지가 있어가지고 그 정도 시간 내에 또 처리가 안 된 거라면은.”**

24시간 내 해결되지 않은 사건은 72시간 이내 처리를 목표로 이어간다. 그때까지 미해결이면 중요 사건으로 보고 운영자가 직접 처리할 책임을 맡는다. 운영자에게 알림만 보내고 담당자 없이 두는 단계가 아니라, 담당 센터 관리자의 확인 자료·미해결 사유·기존 조치·남은 판단을 운영자에게 인계하는 단계다.

| 단계 | 처리 책임과 기준 |
| --- | --- |
| 첫 응답 | 상담 담당자가 가능한 한 6시간 이내 응답한다. |
| 일반 처리 | 고객센터 관리자가 24시간 이내 처리를 목표로 진행한다. |
| 추가 처리 | 24시간 내 미해결이면 72시간 이내 처리 목표로 이어간다. 당사자에게 미해결 사유와 후속 일정을 안내하는 기존 제안도 함께 유지한다. |
| 운영자 처리 | 72시간까지 미해결이면 운영자가 직접 검토·처리할 사건으로 인계한다. |

72시간은 같은 사건의 처리 시계에서 **누적 72시간까지**로 해석한다. 24시간이 지난 시점부터 72시간을 더해 96시간으로 자동 연장하는 것으로 기록하지 않는다. 이는 현재 문맥에 따른 해석이며 실제 접수·기산 시점과 근무시간·휴일 계산은 미정이다. r83의 근무시간·영업일 고려 문맥을 유지하되 72시간을 곧 3영업일 또는 실제 경과 3일로 환산하지 않는다.

## 업무 흐름

```text
고객 신고 접수
├─ 해당 주문의 미지급 정산 보류
├─ 운영자·담당 센터 관리자에게 알림
└─ 가능한 한 6시간 이내 응답
   └─ 센터 관리자: 24시간 이내 처리 목표
      ├─ 해결 → 결과 안내·후속 실행 확인
      └─ 미해결 → 사유·후속 일정 안내, 72시간 이내 처리 목표
         ├─ 해결 → 결과 안내·후속 실행 확인
         └─ 미해결 → 중요 사건으로 운영자 직접 처리 인계
```

운영자·담당 센터 관리자 모두 알림을 받는 [r82](workflow-operating-decisions.design.r82.md) 방향은 유지한다. 센터에서 처리하는 일반 사건마다 운영자 사전 승인·읽음 확인을 요구하지 않는 [r81](workflow-operating-decisions.design.r81.md) 기준도 그대로다. 72시간 미해결에 대한 운영자 인계는 이 기준을 뒤집는 전체 사건 승인 절차가 아니다.

## 분쟁 가능성과 처리 결과의 구분

사용자가 언급한 소송 가능성은 장기 미해결 사건에서 운영자가 검토할 필요가 있는 사안으로 보존한다. 시간 초과만으로 법적 분쟁이나 특정 당사자의 귀책이 확정되는 것으로 기록하지 않는다. 법적 조치가 필요하다면 사실과 증빙을 검토하고 별도 절차에서 결정한다. 이번 답변은 실제 소송 제기·대리인 선임·법률 결론을 요청하거나 완료한 것이 아니다.

24시간·72시간 경과 자체로 사건 완료·환불·기지급 회수·정산 보류 해제를 자동 실행하지 않는다. 기존 발생 보수와 수행 증빙을 보존하며, 해당 주문의 미지급 정산 보류와 그 해제 결정, 환불·재배송 실행, 실제 지급 확인은 각각 구분한다. 운영자에게 인계한 것만으로 사건 해결이나 지급 완료를 표시하지 않는다.
