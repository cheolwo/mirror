# 업무 예외 마감 보완 r76

2026-10-15. 상태 `ApprovedForLocalImplementation`. 사용자는 직전 읽기 감사의 보완을 진행하고 휴대폰 없이 결과를 업무 트리로 설명하도록 요청했다.

## 승인한 범위

기존 주문·운송·입고·정산 원장과 권한을 재사용해 다음을 보완한다.

1. 복수 화물 사건 종료 순서와 수납 사실 분리, 기사 보수 미확정 수락 보호.
2. 입고 수령·취소·거절의 동일 완료 판정, 마트 보류 해결 및 공간 잔여 재고 인계의 기존 증빙·동의 연결.
3. 기존 활동 지급 신고 화면 연결과 본인 주간 명세, 중복 채무·실제 송금 생성 금지.
4. 장기 음식 배차 대기의 운영 인계, 재조리 요청/실제 시작 분리, 지원 결과의 전문 업무 후속과 금융 상태 분리.
5. 명확한 서버 거절과 운행 시작 응답 유실 구분, 미확정 요청의 안전한 복구.
6. 예외 처리의 담당자·대기 이유·다음 행동을 명확히 하고 로컬 회귀/소비 앱 검증 후 업무 트리로 보고.

## 경계

관련 없는 미커밋 작업과 기존 공개 계약·ID를 보존한다. Simulation/Operational, 기본 OFF, 권한·revision·멱등·사진·사전 동의 관문을 유지한다. 임의 수령·입금 완료, 자동 환불·새 비용/보상·새 관리자 권한을 만들지 않는다. 새 비용 기준이 필요한 예외는 명시적 합의와 운영 검토에 남기고 가능한 기존 업무 해결 경로를 연결한다.

휴대폰·에뮬레이터·실제 FCM·Azure/GCS 배포·공유 DB migration·실금전·Unity·commit/push는 범위 밖이다. APK 재빌드보다 로컬 코드·시험·실제 소비 프로젝트 빌드와 공용 UI 렌더 검증을 우선한다.

## 검증

순서 반전·중복 요청·판본 충돌·무권한·미수납·부분 처리·응답 유실을 의미 있는 회귀 시험으로 보호한다. 담당별 집중 검증을 통합한 뒤 현재 validate-changes의 Fast/Task를 이번 경로로 실행한다. 로컬 실행과 실제 운영 완료는 구분한다.

## 업무 결과 설명

정상 처리와 예외 분기, 다음 담당자, 작업 완료/고객 확인/정산/입금의 서로 다른 마감을 한국어 트리로 남긴다. 구현과 남은 정책·실기기/외부 검증을 구별한다.
