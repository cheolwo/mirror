# [기획 · 생활권 물류 매칭 · PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB · r108]

기준일: 2026-10-24. 상태: `Proposed / SourceReviewed / ImplementationNotAuthorized / OperationalDeferred`.

사용자는 생산물 공급자·공간 제공자·입고검수·선반 적치·피킹·포장·출고·배송 담당자가 연결돼 업무가 반복되는 매칭 방안을 요청했다. 이번 범위는 현재 소스 조사와 제안이다. 제품 코드·DB·앱·서버·기능 관문·실제 계약/배정/금융은 변경하지 않는다. r104 구현 및 다른 기획의 확정·미정을 보존한다.

## 현재 기반과 빈칸

- [공동운영 조건](../../../../../Ssalddel.Contracts/Common/Community/공간공동운영Dtos.cs)은 역할별 수락과 조건 동의를 지원하지만 용량·시간·보수는 자유 문구다. [회차 점검](../../../../../Ssalddel/Services/Community/공간공동운영UseCase.cs)은 역할별 수락자 존재를 확인하며 시간대별 정원·중복 약속·처리량을 계산하지 않는다.
- [전문 참조](../../../../../Ssalddel/Application/Warehouse/공간공동운영전문업무Bridge.cs)는 거점·보관합의·입고·주문·배송·정산을 읽지만 일반창고 적치·포장 작업을 현재 직접 연결하지 않는다.
- [피킹·포장 배치](../../../../../Ssalddel/Services/LogisticsProcessing/Warehouse/피킹배치Engine.cs)는 같은 창고·가능 작업·부하와 통합/분리 배정 계획을 지원한다. [후보 생성](../../../../../Ssalddel/Services/LogisticsProcessing/Warehouse/출고피킹작업생성Service.cs)의 역할 기반 가용 표시는 실제 근무 시간 확인이 아니다. 권장 작업량 정렬은 새 공통 용량 예약을 대신하지 않는다.
- [입고 쌍방 협의](../../../../../Ssalddel/Application/Warehouse/DistributedFulfillmentUseCase.InboundCollaboration.cs), [적치](../../../../../Ssalddel/Application/Warehouse/적재작업UseCase.cs), [포장](../../../../../Ssalddel/Application/Warehouse/포장작업UseCase.cs), [기사 수락 관문](../../../../../Ssalddel/Services/Dispatch/Participation/SharedDriverWorkAdmissionService.cs)을 재사용할 수 있다. 커뮤니티 역할 수락은 기존 HR·전문 작업 권한·기사 수행 자격을 자동 부여하지 않는다.

## 권장 구조: 운영 준비와 개별 작업을 함께 매칭

공동운영 회차 위에 부족한 일과 가능한 자원을 연결하는 공통 매칭을 둔다. 전문 재고·작업·배차·정산 상태는 원래 원장에서 읽으며 새 매칭 상태로 대체하지 않는다. 새 앱이나 모든 일을 수행하는 단일 배차 엔진을 먼저 만들 필요는 없다.

1. **운영 준비 매칭**: 공간 제공자·공급자·공간/설비·반복 참여 인력의 기간·품목·용량·비용·책임을 비교한다. 공간이나 공급처가 없는 제안도 부족 항목으로 모집한다. 관심·후보·사용/보관/공급 합의는 구별한다.
2. **회차·주문별 작업 매칭**: 입고 20상자·검수 1명·적치 1명·피킹/포장 1명·배송 1건처럼 시간창과 처리량이 있는 일을 만든다. 근무 가능 의사와 특정 작업 수락은 별도다.
3. **기존 전문 실행으로 인계**: 해당 조건의 당사자 수락과 시간·수량 예약이 성립한 경우만 기존 작업으로 이어진다. 일반창고 포장·출고와 기사 직접 피킹은 실행 경로가 다르므로 필요한 단계를 작업 방식별로 선택한다.

## 매칭 대상으로 관리할 정보

| 대상 | 필요한 정보 |
|---|---|
| 필요한 일 | 회차/주문·전문 원장 참조, 작업 종류·장소, 시간창·예상 작업시간·마감, 수량/단위·필요 인원·처리량, 선행 업무, 설비·보수·비용/책임 조건 |
| 사람 | 희망 작업·가능 시간·현재 권한·확정한 다른 약속·처리량·이동 시간. 같은 사람이 복수 역할을 맡아도 처리량을 중복 계산하지 않음 |
| 공간·설비 | 사용 권한·기간·허용 품목·용도·위치·잔여 용량·동시 사용 한도. 관심 제안과 실제 사용 합의 구별 |
| 공급 물량 | 품목·수량·공급 가능일·예상/확정 상태. 예상 생산량을 확정 재고로 세지 않음 |
| 연결 제안·예약 | 원본 수요·자원, 추천/불일치 이유, 조건 판본·응답 기한·당사자 응답·예약 시간과 수량, 거절/철회/재배정 이력 |

모르는 값은 0이나 무제한으로 추정하지 않는다. 상자·중량·부피·선반 칸 변환에는 명시 근거가 필요하다. 공개 모집에는 동네와 필요한 역할을 쓰며 상세 위치와 연락처는 필요한 당사자에게만 제공한다. 기존 보관합의를 부동산 임대계약 체결로 표현하지 않는다.

## 선정과 업무 순환

먼저 참여 의사·현재 권한/합의·시간 중복·품목/설비 적합성·실제 잔여 용량을 확인하고, 이후 이동 부담·시간 적합성·부하·희망 조건·참여 기회를 비교해 추천 이유를 보여준다. 거주지의 가까움이나 과거 수행 건수만으로 자격을 확정하지 않는다.

`모집/후보 검토 → 제안 → 본인 수락 → 시간·수량 예약 → 작업 가능 → 전문 작업 진행 → 완료 확인`을 구분한다. 추천·공개 모집·병행은 선택 사항이며 기본값·가중치·제안 기한·자동 재제안 범위는 미정이다. 각 사람에게 현재 제안 한 건을 중심으로 보이되 필요한 정원만큼의 작업 자리는 별도로 관리한다.

앞 단계의 완료와 바로 다음 단계의 수용 능력을 확인한다. 미래의 모든 주문·기사까지 확보해야 입고할 수 있다는 일률적인 규칙은 두지 않는다. 후속 작업은 미리 준비할 수 있지만 선행 완료 전에 실제 실행하지 않는다. 수락 시점에는 시간/용량을 다시 조회해 중복 약속을 막는다.

| 단계 | 연결할 대상과 확인 |
|---|---|
| 공급·공간 | 공급 가능 물량/시기와 사용 가능한 공간/설비·보관 조건 |
| 입고·검수 | 해당 시간 참석 가능한 담당자·수용량과 실제 입고/검수 근거 |
| 선반 적치 | 검수된 물품·빈 보관 위치·적치 담당과 실제 위치 확인 |
| 주문·피킹·포장 | 가용 재고와 약속 가능한 작업량·담당자, 기존 예약/작업 완료 |
| 출고·기사 인계 | 준비 물량·시간·담당자·기사/차량과 실제 인계. 포장 완료와 인수 구분 |
| 배송·수령 | 기존 배차와 물품 보유·전달·반납·고객 수령 |
| 보수·다음 회차 | 작업 완료에 따른 보수 근거와 잔여 재고·공간 점유·인력 공백·재참여 의향. 지급 완료와 구분 |

불참·지연·철회 시 미착수 부분만 다시 제안한다. 실제 이동한 재고·보유 물품·완료 작업·발생 보수는 지우지 않는다. 바뀐 조건은 다시 동의하며 이전 회차 수락을 자동 승계하지 않는다. 포장이 불필요한 전달까지 모든 단계를 강제하지 않고 필요한 작업 범위를 당사자가 확인한다.

## 화면과 구현 순서 제안

공동운영 상세에 `이번 회차에서 무엇이 부족한가?`를 표시한다. 예: `내일 14~16시 검수 1명 필요`, `선반 10칸 확인 필요`, `포장 가능 수량 부족`. 부족 항목에서 모집·후보로 이어지고 참여자는 가능 시간·현재 제안·수락한 작업·보수 근거를 구분해 본다. 알림은 사용자가 켠 업무 범위만 보내고 정상 과정은 당사자가 처리하며 미매칭·불참·용량 충돌·분쟁을 운영 담당자에게 모은다.

1. **조회부터**: r104에 시간·정원·수량·선행 작업을 구조화하고 적치/포장 원장을 읽어 부족한 일과 미확인 정보를 표시한다.
2. **한 공간의 기존 참여자 추천·수락**: 공급자 한 곳·상온 포장상품 1~3종으로 입고검수→적치→피킹·포장 담당을 연결하고 시간/용량을 예약한다. 기존 전문 권한과 명시적으로 대조한다.
3. **출고·배차와 예외 검증**: 한 주문의 매칭·작업·재고·인계·수령·보수 근거를 같은 실행 식별자로 추적한다. 동시 수락·중복 약속·다른 거점 혼합·조건 변경·응답 유실·부분 완료 뒤 재배정을 검증한다.
4. **다음 회차와 확대**: 병목·잔여 재고·참여자 희망으로 다음 물량·작업 시간·모집을 제안하고 이후 공개 모집·복수 공간·설비/공급처 추천으로 넓힌다.

기존 전문 기능의 Simulation/Operational·기본 비활성 관문은 자동 변경하지 않는다. 문서상의 연결·역할 수락을 실행 완료로 보고하지 않는다.

## 확정·미정·다음 검토

- **확인된 요구**: 사람·공간·물품 공급과 전반적인 작업을 연결해 반복 운영하는 방안이 필요하며 이번에는 구현 전 제안을 받는다.
- **제안 단계**: 공통 수요/자원/예약 모델과 두 시점 매칭, 입고검수·적치·피킹포장부터의 단계적 도입. 제품 구현은 아직 승인되지 않았다.
- **미정**: 첫 공간/품목/작업 범위, 정원/처리량 단위, 제안·예약 만료와 추천 우선순위, 보수 방식·자동 재제안 범위. 임대료·임금·운임·법적 자격 기준을 새로 확정하지 않는다.
- **다음 검토 하나**: 첫 구현을 `한 공간의 부족 작업 표시 → 기존 참여자 추천·수락 → 입고·적치·피킹·포장 연결`로 잡을지 검토한다. 답변 전에 구현하지 않는다.
