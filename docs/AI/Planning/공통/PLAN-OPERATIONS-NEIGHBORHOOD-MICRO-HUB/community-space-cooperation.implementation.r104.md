# 공간 공동운영 순환 구현 r104

상태: `Approved / Implemented / LocalValidated / OperationalDeferred`. 기준일은 2026-10-24다. 사용자가 승인한 공동운영 순환의 서버·공용 화면 구현을 기록한다. 소스 구현, 시험 통과, 실제 앱 사용, 현장 운영은 별도 증거다. 이전 r102 역할 화면과 r103 생활 퀵 검토의 권위와 미정을 보존한다.

## 확정한 범위와 참여 방식

첫 검증 대상은 일반 상가의 확인된 공간 한 곳·공급자 한 곳·상온 포장 상품 1~3종·주문 한 건이다. 이는 이번 검증 사례의 범위이며 임의의 공동주택·냉장/조리식품·위험물까지 사용할 수 있다는 뜻이 아니다. 실제 시험이 사용한 상품 종류와 수량은 아래 검증 근거에서 따로 기록한다.

공간 제공자, 공급자, 기사, 주민·이용자, 피킹 참여자, 조율 담당자, 입고 검수 담당자의 관심·수락을 역할별로 기록한다. 한 계정이 여러 역할을 선택할 수 있지만 사람 수는 계정 기준으로 중복 제거한다. 역할을 자칭하거나 수락한 기록은 공간 소유권·사용 허가·직업 자격·근무 또는 배차 권한이 아니다. 실제 공간과 작업 권한은 기존 전문 업무에서 확인한다.

공간 제공자는 기본 운영 담당 후보다. 본인이 역할을 수락하고 운영 담당을 명시적으로 수락해야 확정된다. 다른 공간 제공자 또는 조율 담당자로 바꾸려면 현재 담당자의 인계 제안과 상대의 수락이 모두 필요하며, 상대 수락 전까지 현재 담당자를 유지한다. 인계는 전문 창고·재고·배차 권한을 자동으로 이전하지 않는다.

## 구현한 사용자 흐름

1. 홈의 `생산에 참여해 보세요.`와 기존 역할 진입을 유지하고, 함께할 수 있는 사람·공간과 공개 모집 요약에서 공동운영으로 들어간다.
2. 제안자는 동네, 목적, 공간 사용, 품목, 용량, 운영시간, 비용·보수, 책임, 중지·반환 조건과 필요한 역할을 정한다. 공간을 확보하기 전에도 비구속 제안을 만들 수 있다.
3. 참여자는 관심 참여, 본인 역할 수락, 현재 조건 판본 동의, 공개 소개 동의를 각각 선택한다. 제안 공개와 개인 소개는 별도 선택이며 동의 철회 후 새 조회에서 소개와 집계가 빠진다.
4. 운영 담당자는 회차를 준비하고 본인에게 허용된 거점·보관합의·입고 계획·주문·출고 묶음·정산 참조를 선택한다. 현재 전문 원장의 권한과 같은 거점·업무 관계를 다시 대조하고 부족한 준비와 다음 전문 화면을 표시한다.
5. 주문자와 공급자는 기존 비구속 상품 요청의 같은 상품·수량·가격·수령 방식·기한에 각각 동의한다. 판매자의 명시적 인계에서 기존 주문 원장·분산 예약에 연결하며, 조회·로그인·동의 저장만으로 예약·배송을 시작하지 않는다.
6. 회차 시작은 역할·현재 조건·공간/보관합의와 전문 참조의 준비를 검사한다. 회차 완료는 전문 원천의 실입고, 실제 전달과 고객 수령 근거로 확인하며 일반 완료 문구나 결과 메모로 만들지 않는다. 다음 회차는 빈 참조로 준비하고 기존 주문·배송 단위를 다시 실적으로 세지 않는다. 남은 재고의 입고 계획은 새 주문과 연결해 재사용할 수 있다.

조건 변경은 기존 동의·공개 소개·운영 담당 수락을 새 판본에 자동 승계하지 않는다. 진행 중 회차의 조건을 임의로 바꾸거나 철회로 실물 업무를 삭제하지 않는다. 역할별 철회는 공개 소개를 숨기되 기존 주문·재고·진행 배송과 결과 원장을 보존한다.

## 저장·API와 전문 원장의 권위

- 공동운영 API는 `api/v1/common/space-cooperations`, 공용 화면은 `/community/space-cooperations`와 `/new`, 선택 상세다. 공개 목록·초대 요약은 비로그인으로 볼 수 있고 제안·참여·당사자 상세·명령은 인증을 요구한다.
- [공동운영 원장 저장소](../../../../../Ssalddel/Services/Community/공간공동운영원장Store.cs)는 기존 Mongo `community_ledgers`의 전용 보호 블록에 조건·역할·회차·주문 부록을 저장한다. 원장 ID·소유자·revision과 보호 payload를 결속하고 기존 블록·다이어그램·서명·포함 원장 관계를 보존한다. 별도 공동운영 DB를 만들지 않는다.
- [전문 업무 bridge](../../../../../Ssalddel/Application/Warehouse/공간공동운영전문업무Bridge.cs)는 기존 SQL 거점·보관합의·입고/재고·주문/예약과 Mongo 주문 원장, 본인 정산을 조회한다. 원장을 읽을 권한과 같은 회차로 묶을 관계를 구분한다. 연결 당시 선택한 revision을 확인하되 정상 업무 진행으로 증가한 현재 revision을 과거 선택값으로 막지 않는다.
- [주문 인계 UseCase](../../../../../Ssalddel/Application/Mart/공간공동운영주문UseCase.cs)는 원 요청의 확인 중/확정 상태를 조건부 갱신하고 고정한 명령 ID·payload로 기존 분산 주문을 호출한다. 응답이 불명확하면 원 요청과 영수증을 보존하고 명시적 결과 조회·재개를 제공한다. 재시작 후 조회가 추가 예약을 생성하지 않는다.
- 서버의 명령 영수증과 revision은 저장 근거다. 공용 화면의 초안·원 요청 보존은 같은 계정의 화면/로그인 왕복 범위이며 영구적인 단말 초안 저장으로 표시하지 않는다. 계정·서버 변경의 늦은 응답을 새 화면에 적용하지 않는다.

## 공개·기능 관문과 미확인 사항

공개 화면은 제안자가 공개한 모집과 별도 소개에 동의한 사람의 표시명·역할·동네만 내보낸다. 상세 주소·연락처·내부 사용자 ID·비공개 운영 조건은 공개 DTO에 넣지 않는다. 공개 소개에 동의하지 않은 참여를 공개 사람 수로 세지 않으며, `Simulation` 자료는 시험 제안으로 표시하고 운영 사람·공간·모집·완료 집계를 0으로 분리한다. 조회 실패를 0건 성공이나 예시 자료로 대체하지 않는다.

제안·참여의 커뮤니티 경계는 0.0이고 실제 전문 업무는 기존 기능 관문을 유지한다. 주문 API는 3.5의 `SsalddelMartWorkflow` 관문을 따르며 주문 인계와 분산 전문 bridge는 `Simulation`·`DistributedFulfillment.Enabled`·`distributed-fulfillment-r36` profile 및 관계형 저장소 조건 안에서만 열린다. 공동운영 제안이 있어도 이 관문을 자동으로 켜지 않는다.

공간 제공자의 명시 수락과 기존 거점 동의는 실제 부동산 권리·공동주택 의결·영업 적합성 확인을 대신하지 않는다. 실제 입고·기사 수행·고객 수령·보수 지급·외부 서버/FCM·운영 전환·Unity 반영·자동 게시·commit/push는 이번 소스 구현만으로 완료하지 않는다. 정산 준비와 실제 지급, 재고 예약 생성과 현재 남은 예약 수량도 구분한다.

## 검증 근거

- 관련 시험 537개 전부 통과하며 새 공동운영 시험 66개를 포함한다. 역할·동의·공개 철회·인계·위조 완료·다른 거점 혼합·중복 실적·주문 CAS·응답 유실/명시 재개를 검사했다. 최초 실패와 수정 뒤 재시험을 함께 보존한다.
- 첫 실험은 격리 SQLite의 상온 포장상품 한 종·주문 한 건이다. 기존 입고→양측 주문 동의→명시 인계→피킹→전달→고객 수령 뒤에만 회차 마감을 허용했다. 이 실험의 커뮤니티·주문 Mongo 원장은 시험용 저장소이며 실제 Mongo와 결합한 단일 실행으로 표현하지 않는다.
- 실제 Mongo 전용 UUID DB에서 생성·중복·동시 수정·보호 결속·기존 lease/재시도 28개 검사를 통과했다. 별도 실제 HTTP/공용 UI에서는 생성·역할 수락·동의·운영 수락·회차 준비·관심 참여를 저장하고 서버 재시작 뒤 재조회했다. UI 호스트의 전문 업무 실행은 OFF로 유지했다.
- WebApp·통합 Android 빌드 오류 0, 넓은 화면과 390px 브라우저 표시 확인. 기존 휴대폰 앱과 계정을 보존해 새 APK 설치·물리 단말 검증은 하지 않았다. 표준 Fast는 미관련 기존 EOF 공백에서 중단됐고 이번 소스 범위 diff-check와 실제 관련 시험·빌드를 별도로 실행했다.
- 실제 계약·실물·운영 DB·실지급·외부 발송·Unity·배포·commit/push는 미수행이다. Figma 쓰기는 읽기 전용 모드에서 차단돼 대응 완료를 주장하지 않는다.
