# 국내 화물 한 건 마감 r69

상태: Implemented / LocalValidated / OperationalDeferred. 기준일: 2026-10-14.

사용자는 화물 앱 현황과 네 가지 마감 우선순위를 확인한 뒤 `진행`이라고 승인했다. 범위는 화주 한 명, 기사 한 명, 상차지 한 곳, 하차지 한 곳의 일반 국내 화물이다. 기존 주문 참조·화주 의뢰·운송·증빙·지급 준비 원장을 사용한다. 음식·마트·분산 물류·Unity로 확장하지 않는다.

## 승인된 마감

1. 화주 신규 작성의 수량·중량·부피·온도·설명과 기존 요금 입력을 서버 요청에 보존한다. 접수 복구에 같은 요청 번호와 원문을 유지한다. 기존 수정 원값 보존을 유지한다. 정산 시점이나 수납 주체가 불명확한 표기를 임의의 금융 합의로 바꾸지 않는다.
2. 접수된 원장을 물리 삭제하지 않고 기존 취소·운영 검토 경로로 안내한다. 실제 완료 운송과 완료 인계가 없으면 화주 인수를 완료로 기록하지 않는다. 일반 화물 완료 사진은 현재 기사·운송·단계의 서버 업로드 영수증과 실제 비공개 파일을 대조한다. 과거 문자열 증빙은 자동 승격하지 않는다.
3. 전문 기사 앱의 상차 완료도 같은 운송 재조회로 확인한다. 응답 유실 때 완료 명령부터 반복하지 않는다. 사진·업로드 결과는 계정·운송·단계별로 보호 보관하고 확인된 완료 또는 명시 폐기 시 정리한다. 운송 저장 후 화주 인계·입금 준비가 실패해도 기존 영속 이벤트를 근거로 재개할 수 있게 한다.
4. 기사 운송대금 조회를 기존 지급 준비 API와 연결한다. 목록과 상세는 독립 책임이며 현재 운임·지급 준비·보류 이유를 표시한다. 기존 월 정산의 플랫폼 이용료 의미를 유지한다. 지급 준비나 승인·Outbox를 실제 송금으로 표시하지 않는다.

## 경계와 완료 기준

- 구현·시험·로컬 화면/서버·APK·물리 기기·운영·실제 입금 증거를 구분한다. 이번 작업은 로컬 구현과 검증이며 실제 운영 기능·배차·송금·클라우드 설정을 활성화하지 않는다.
- 기존 공통 권한·개인정보 동의·운영 시장·feature 관문을 유지한다. 동의가 필요한 접수는 실제 본인의 명시적 동의 기록을 연결하며 가짜 증적이나 고정 ID로 우회하지 않는다.
- 기본 호스트 실행 모드와 기능 플래그를 바꾸지 않는다. 별도 격리 검증에서는 명시적인 Simulation 및 합성 참여자만 사용한다.
- 소스 변경 전 기준선은 `artifacts/local/cargo-closeout-r69/baseline.json`이다. 무관한 기존 dirty 파일을 보존하고 새 commit/push는 하지 않는다.
- 반례는 입력값 왕복, 동일 접수 복구, 타 계정/운송/단계/파일 변조, 진행 중 삭제, 완료 전 인수, 응답 유실, 후속 실패·재시작, 지급 조회 실패·로그아웃을 포함한다.
- 집중 시험 후 좁은 `eng/validate-changes.ps1 -Level Fast -Paths ...`와 완료 전 `-Level Task -Paths ...`를 직렬 실행한다. 변경 UI는 소비 호스트에서 실제 렌더를 확인하며 불가능한 기기 경계는 명시한다.

구체 쓰기 경로·담당은 [작업 명세](cargo-closeout.r69.work-order.json)에 둔다. 실행 결과와 제한은 [변경 기록](../../../../Changes/2026-10-14-cargo-closeout-r69.md)에 기록한다.
