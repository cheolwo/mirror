## 수용 범위와 완료 결과

현재 마트 기사 수행 Adapter 부재를 숨기지 않고 r54 구현 순서의 첫 단계인 격리 로컬 표본을 완성한다. 전표 발급·출력 요청 → 기존 상품 피킹·포장 → 픽업용 QR 스캔 즉시 서버 측 표본 인수 기록 → 같은 주문 재조회가 첫 결과다. 한 주문은 한 포장으로 한정한다. 운영 DB, 실제 배차·기사 앱·실물 프린터·외부 효과는 후속이다.

- 전용 `Development + Simulation + loopback` 호스트를 유지한다. 기존 원본 입력과 운영 DB·기능 플래그·마트 기사 차단 정책은 바꾸지 않는다.
- 전표는 선택 주문에서 포장 전에 준비한다. 같은 전표 재출력은 판본을 바꾸지 않고 출력 창 요청과 실제 인쇄 결과는 구별한다.
- 전표는 합성 주문 표시번호·상품·수량·포장 1/1·QR·별도 네 자리 번호만 포함한다. 이름·연락처·주소·원본 주문 ID를 출력하지 않는다.
- 기존 공통 문서 출력·QR 생성기를 재사용한다. 실제 기록 상품은 로컬 비공개 입력으로만 읽고 공개 캡처는 합성 상품으로 만든다.
- 서버 측 표본 Runtime의 격리 SQLite에 전표 판본·활성 상태, 명령 결과·인수 기록을 보관한다. 브라우저 회로 종료·명시적 표본 초기화 시 지워지는 로컬 검증 자료이며 호스트 재시작 후 영속 운영 복구의 증거는 아니다.
- 현재 배정은 합성 기사 한 명으로 제한한다. 실제 인증 사용자·배차 조회라고 표현하지 않으며 서버 Runtime에서 해당 합성 주체·주문·준비·전표 판본을 검사한다.
- **QR 스캔은 곧 픽업 요청**이며 별도 완료 버튼은 없다. 응답 성공 전에 완료로 표시하지 않는다. 선반 QR 입력은 기존처럼 피킹 입력만 채운다.
- 네 자리 입력은 현재 선택 주문의 보조 경로다. `번호로 픽업` 제출 자체가 인수 요청이며 제출 후 추가 확인 버튼은 없다. 제한 횟수·시간을 두고 QR 경로와 구분한다. 이는 단순 표본 조작 방식이며 실제 인증 수단이나 운영 정책을 확정하지 않는다.
- 반복 인식·같은 요청 재전송과 다른 요청 ID의 중복 인수는 인수 기록을 늘리지 않는다. 같은 요청 ID에 다른 입력을 넣으면 거부한다. 취소·오프라인·응답 불확실을 성공으로 대신하지 않는다.
- 재발급은 포장 전으로 제한하고 구 전표를 무효화한다. 다중 포장·부분 인수·운영 취소/재배정은 이 표본에 임의 생성하지 않으며 제품 서버 연결 단계에서 별도 검증한다.

## 화면 책임과 담당

[페이지 책임·연결](../../../../ProjectOverview/page-docs/ssalddel-mart-package-pickup-r56.md)을 먼저 작성한다. 포장 담당자의 전표·상품 확인과 기사의 픽업 입력은 같은 주문을 보는 독립 표시 모드로 구별한다. 역할 전환은 표본을 살펴보기 위한 도구이며 권한 승격이 아니다.

- 개발 통합: 기존 표본 페이지·전표 컴포넌트·인쇄 Adapter·문서·최종 검증.
- 표본 Runtime: 격리 전표·요청 결과·인수 저장과 C# 회귀 시험.
- 카메라 입력: 기존 자원 수명 재사용, 포장 전표용 QR 허용 경계와 JS 시험.
- 읽기 검토: 권한·사전 출력·중복 처리·추가 완료 버튼 부재와 검증 상한 확인.

정확한 쓰기 파일·기준 commit·기획 hash는 [작업 지시](ssalddel-mart-package-pickup.r56.work-order.json)에 결속한다. 관련 없는 dirty 변경은 보존하며 commit·push·배포하지 않는다.

## 검증 기준

1. C#: 미리 발급, 전 품목 피킹·포장 선행, QR/네 자리 정상 인수, 틀린 코드·타 주문·타 합성 기사·낮은 판본·구 전표 차단, 같은/동시 요청 멱등, 요청 ID 입력 충돌, 초기화·번호 제한과 기존 피킹/포장 회귀.
2. JS: 선반 기본 프로필 회귀, 포장 전표 QR-only·정확 일치, URL/혼합/과대/잘못된 입력 차단, 단 한 번의 callback, 카메라 닫기·숨김·연결 해제·늦은 권한/인식·폐기.
3. 실제 로컬 렌더: 320/390/1280px에서 담당자 전표·픽업 관점·스캔 자동 완료·네 자리·실패·재출력·초기화·복귀를 검증한다. 카메라 검증이 가상 stream/모의 decoder면 그 사실을 따로 기록한다.
4. 전표 HTML의 개인정보 불포함·58/80mm 출력 형식과 QR 디코딩을 확인한다. 브라우저 인쇄 요청은 실제 인쇄 성공으로 보고하지 않는다.
5. 관련 build·집중 시험·Fast/Task routing·문서 링크·공백·소스 지문과 실제 캡처를 각각 기록한다. 기존 전체 시험 건수를 이번 결과로 재사용하지 않는다.

## 제외와 반환

실제 마트 기사 API/배차 Adapter·운영 MySQL/Mongo/Outbox·Android APK/단말·Bluetooth/USB 프린터·외부 결제/알림·Unity·운영 활성화·배포는 제외한다. 해당 연결이 없는 상태에서 실제 픽업 성공을 주장하지 않는다. 구현 후 실제 검증 결과와 남은 한계를 이 문서·작업 지시·변경 기록·현재 작업에 반환한다.

## 개발 반환 (2026-10-10)

- 기존 표본 페이지에 포장 담당자/기사 픽업 관점을 분리했다. 담당자는 포장 전에 전표를 출력할 수 있고, 같은 전표 재출력은 QR·판본을 바꾸지 않는다. 공통 문서 서비스의 **80mm** 출력과 QR 생성기를 재사용했다. 58mm 출력·실물 출력은 이번 화면에서 검증하지 않았다.
- 격리 SQLite에 전표·요청 결과·주문당 하나의 인수 기록을 저장한다. QR 스캔 또는 네 자리 제출 한 번으로 현재 주문·합성 기사·포장 준비·판본을 검사하고 확정 결과를 다시 조회한다. 기존 체크박스 모의 인계 우회는 차단했다.
- 네 자리 오입력 5회/60초 대기와 QR 대체를 제공한다. 포장 전 재발급은 이전 QR과 직전 번호를 변경한다. 번호는 표본 조작용이며 실제 인증·권한 정책이 아니다.
- 카메라·인쇄 프레임의 취소/이탈/늦은 응답은 새 요청에 영향을 주지 않게 격리한다. 인쇄 요청과 물리 인쇄 성공, 표본 인수와 운영 출고/배차/지급은 분리한다.
- 독립 코드 검토에서 이전 인쇄 callback이 다음 요청을 정리하는 결손을 발견해 요청별 일치 검사와 회귀 시험으로 보완했다. 추가 차단 사항은 발견하지 않았다.
- 새 집중 C# 69건·JS 62건·320/390/1280px UI 21건·실제 QR 픽셀 디코딩 12건과 별도 preview build(오류 0)를 통과했다. Fast 집중 69건, `Ssalddel.v3.5.slnx` build와 Task 실행 9,993건이 통과했고 실패 0건·환경 의존 Mongo 시험 15건은 미실행이다. UI 전후 소스/호스트 지문 변화 0건과 종료 후 242초 서버 오류 0·stderr 0바이트를 확인했다. [변경 기록](../../../../Changes/2026-10-10-ssalddel-mart-package-pickup-r56.md)에 실행 증거를 구분해 남긴다. 이전 r52/r53 전체 시험 건수는 이번 증거로 재사용하지 않는다.

이 문서의 승인 시점 hash는 작업 지시의 `approvedDesignSha256`에 보존하고 개발 반환이 추가된 현재 hash는 `designSha256`로 구별한다. 원본 입력·제품 운영 플래그·마트 기사 차단 정책과 관련 없는 변경을 유지한다. commit·push·배포는 하지 않는다.
