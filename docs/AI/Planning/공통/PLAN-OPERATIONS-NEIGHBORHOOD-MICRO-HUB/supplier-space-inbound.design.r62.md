## 확정한 방향

공간 제공자는 물품의 종류와 조건을 선택할 수 있고, 공급자는 그 조건에 맞는 물품과 수량을 제안한다. 플랫폼은 적합한 후보를 찾고 협의·확인·후속 업무를 연결한다. 자동 추천이나 AI 판단은 계약 당사자의 동의나 건별 입고 승인을 대신하지 않는다.

농가·공장·식품회사라는 공급자 유형은 소개/탐색 정보다. 같은 사람이 생산자·물품 소유자·판매자를 겸할 수 있으나, 소개나 역할 선택으로 타인의 물품을 계약할 권한을 얻지 않는다. 실제 물품 소유자와 위탁 판매자, 공간 사용에 동의할 수 있는 제공자와 현장 관리자는 계속 구분한다. 화면의 ‘건물주’ 표기만으로 소유권 검증을 완료했다고 기록하지 않는다.

계약은 두 범위로 연결한다. **공급·위탁 약정**에는 공급 품목/수량·도착 약속·물품 소유 관계·판매 권한·미판매 물품 회수를, **공간 보관 합의**에는 위치·수용 조건·수용량·기간·보관 담당·비용·반환을 둔다. 같은 당사자이면 한 흐름으로 작성할 수 있지만 책임과 판본은 분리한다. 자기 물품 입고에 가상의 외부 공급 계약을 만들지는 않는다.

## 제안하는 처리 순서

1. **공간의 수용 조건 등록**: 받을 상품군·거부 조건·보관 가능 기간·입출고 시간·이용 가능한 칸/용량·보관 방법을 설정한다. 공개 탐색에는 대략적 지역과 수용 조건을 표시하고 정밀 사적 위치·출입 방법은 승인된 담당자에게만 제공한다.
2. **공급 제안과 협의**: 공급자가 상품·SKU·수량/단위·포장·필요 보관 조건·희망 도착 시간·보관 기간을 제안한다. 공간 제공자는 수락·거절·수정 제안 중 하나를 선택한다. 미응답을 동의로 바꾸지 않는다.
3. **같은 조건 판본에 양측 동의**: 현재 조건과 변경 제안을 구분한다. 양측이 확인한 공급/보관 약정과 가격 또는 명시적 무상 조건을 연결하고 계약 번호·판본·동의 주체·시각을 남긴다. 계약 합의와 실제 수금/지급은 별개다.
4. **건별 입고 예약 확정**: 유효 계약 아래 이번 품목·수량·도착 시간·적재 위치·받을 담당자를 확인한다. 첫 구현 제안은 공간 제공자의 건별 명시 승인이다. 승인받지 않은 초안은 출발/입고 준비 완료로 표시하지 않는다. 현장 관리자가 받는 권한과 계약 조건을 승인하는 권한도 별개다.
5. **도착·검수·사진으로 입고 확인**: 기존 바코드·실제 수량·사진·관리 권한 검사를 재사용한다. 승인된 예약과 다른 물품/수량은 자동 재고화하지 않고 차이를 협의한다. 부분 수령은 실제 받은 수량만 보관 재고와 작업 근거로 남긴다.
6. **보관·출고·정산 연결**: 기존 Lot·재고 예약·피킹/전달·수령 흐름을 이어 사용한다. 입고·보관 약정과 출고·배송 약정은 r60대로 분리하고, 확정된 입고/보관 비용만 r61의 원가 귀속으로 연결한다. 계약/입고 승인만으로 성과금이나 실제 지급을 완료하지 않는다.

## 수용 조건의 표현

| 조건 | 예시 | 판정 기준 |
| --- | --- | --- |
| 상품군 | 농산물 거부, 공산품 허용 | 상품명이나 공급자 업종으로 추측하지 않고 확인된 상품 분류를 사용한다. |
| 식품·가공·포장 | 식품 제외, 상온 밀봉 가공식품만 허용 | 농산물/공산품과 별도 축으로 관리한다. 가공식품처럼 겹치는 분류는 모든 적용 조건을 만족해야 한다. |
| 온도·취급 | 상온, 냉장, 냉동, 파손주의 | 공간의 확인된 조건과 물품의 요구 조건을 대조한다. 미확인은 적합으로 취급하지 않는다. |
| 수용량 | 상자/칸·중량·부피 및 상품별 수량 | 다른 공급자의 현재 재고와 확정 예약을 함께 계산한다. 기존 소유자별 개수 상한만으로 공간 전체 용량을 보장하지 않는다. |
| 시간·기간 | 화요일 10~12시 도착, 7일 보관 | 계약 기간·출입 시간·예약 일정이 모두 맞아야 한다. |

수용 정책은 탐색 필터와 서버 입고 승인 양쪽에서 같은 판정 결과를 사용한다. 명시적 거부는 허용보다 우선하며, 분류·조건·단위가 불명확하면 협의 필요로 둔다. 정책을 바꾸어도 이미 받은 재고나 과거 작업의 합의 내용을 조용히 소급 변경하지 않는다. 새 입고는 최신 정책과 기존 계약의 충돌을 다시 확인한다.

## 대화·원장·상태의 책임

공개 공간 탐색과 문의는 기존 생활 교류/보관 등록을 재사용할 후보로 둔다. 생활협업의 agreed 상태는 의향/약속이며 전문 분산 보관 합의·실입고·재고를 대신하지 않는다. 새로운 재고 원장을 하나 더 만들지 않고 기존 `SiteId`·`LocationId`·`AgreementId`·입고 `PlanId`·`LineKey`·`LotId`를 연결한다.

협의 메시지는 관련 공급 제안/계약/입고 예약에 결속하고 조건 변경은 구조화된 변경안으로 남긴다. 대화의 “좋아요”를 계약 동의로 자동 해석하지 않는다. 메시지 도착·읽음·수락·실입고 완료는 서로 다른 상태다. 외부 알림 채널과 자동 발송은 후속 구현 범위로 결정한다.

첫 구현에서는 기존 입고 계획 안에 협의 초안과 예약 상태/판본 연결을 확장할 수 있는지 먼저 검토한다. 별도 공급 제안/예약 Record가 필요하면 기존 계획의 자식으로만 두고 새 독립 재고 원장으로 만들지 않는다. API와 DB의 구체 명칭·새 테이블 여부는 구현 설계에서 확정한다.

| 업무 단위 | 제안 상태 | 완료가 의미하는 것 |
| --- | --- | --- |
| 협의 | 초안 → 제안됨 → 수정 협의 → 양측 합의 / 거절·철회·만료 | 같은 조건 판본을 동의했음 |
| 입고 예약 | 초안 → 공간 승인 대기 → 확정 → 도착 대기 / 취소·변경 필요 | 이번 물량과 일정을 받을 준비가 승인됨 |
| 실제 수령 | 미수령 → 부분 입고 → 입고 완료 / 수령 차이 검토 | 사진과 실제 수량을 검증해 재고에 반영했음 |
| 정산 | 기존 입고/보관·출고/배송 각 약정 | 보수 발생·확정·지급 확인을 기존 원장대로 구분 |

| 화면 | 답해야 할 질문 | 기본 정보·주 행동 |

| 계약 조건 확인 | 내가 어떤 판본에 동의하는가? | 현재 조건과 변경 내용, 본인 동의 |

탐색은 기존 지도 중심 화면을 유지하고 선택한 공간의 수용 조건을 카드로 표시한다. 긴 계약·협의·검수는 각 업무 상세로 분리한다. 서버가 돌려준 현재 상태·다음 담당·대기 이유·가능한 행동만 기본 카드에 제공한다. 다른 공급자의 상세 재고나 계약 금액은 노출하지 않는다.

## 예외와 회복 기준

- 거절·기한 초과: 출발/적재를 진행시키지 않고 이유와 다음 담당을 표시한다. 다른 후보 공간을 제안해도 당사자 동의를 새로 받는다.
- 일정·수량·상품 변경: 변경안에 대해 영향받는 당사자가 재확인하고 승인 전 기존 예약을 임의 확대하지 않는다. 재고와 확정 예약이 공유하는 공간 전체 용량을 같은 트랜잭션에서 확인해야 한다.
- 동시 요청/응답 유실: 기존 요청 ID·revision·영수증 재조회 방식을 재사용한다. 마지막 자리를 두 공급자에게 중복 확정하지 않는다. 실패 응답만으로 실제 접수가 없었다고 단정하지 않는다.
- 도착 후 부족·초과·파손·품목 불일치: 실제 수령과 문제 수량을 분리한다. 미승인 물품을 가용 재고로 넣거나 임의 폐기/반환 완료 처리하지 않는다. 비용 부담은 계약과 추가 협의로 확인한다.
- 계약 만료·철회·공간 조건 변경: 신규 예약/수령의 유효성을 다시 검사한다. 남은 물품·이미 인수한 배송·반송 책임과 과거 사진·조건·정산 이력은 보존하며 회수/이전은 별도 합의와 확인으로 끝낸다.
- 변경 협의 중: 현재 유효 계약과 미확정 변경안을 별개로 표시한다. 새 조건 확정이 필요한 업무만 보류하고 이미 맡은 물품의 책임을 지우지 않는다.

## 구현 우선순위와 검증 제안

1. **공간 수용 정책과 상품 분류**: 기존 공간·SKU와 연결하고 농산물 거부/공산품 허용·가공식품 조건·미확인 보류를 서버와 화면에서 일치시킨다.
2. **계약 협의와 입고 예약 승인**: 기존 보관 합의 판본/양측 동의를 재사용하되 공급 약정과 연결하고, 초안/유효 계약/변경 제안/건별 승인/거절/일정 변경을 분리한다.
3. **수령·용량·원가 종단 연결**: 예약부터 실제 사진 수령·부분 입고·반송/기존 배송·r60/r61 정산까지 검증한다. 미수령 예약은 재고나 확정 작업 원가가 아니다.

검증 사례는 농산물 거부 공간, 공산품 허용 공간, 조건 불명확 상품, 두 공급자의 마지막 용량 경합, 계약 동의 후 조건 변경, 만료/철회 후 입고 시도, 일정 변경·미도착, 부분 수령·초과 수령·사진 재전송·응답 유실, 타인 계약 열람, 기존 합의 전 초안 호환, 입고 원가 중복 분배 방지를 포함한다. 이 목록은 향후 검증 계획이며 현재 통과 결과가 아니다.
