## 계산과 근거

새 선택 약정의 잔여금 = max(0, 합의 수익 − 출고 기본 작업 비용 − 연결된 입고·보관 원가 − 기타 비용 − 예비금).
참여자 풀 = floor(잔여금 × (100 − 플랫폼 보유율) / 100), 플랫폼 몫 = 잔여금 − 참여자 풀. 원 단위 내림 잔액은 플랫폼 몫에 명시적으로 포함한다. 이 비율은 매출 수수료나 실제 영업이익률을 인증하지 않는다.

`Economics` 없는 과거 약정은 변경하지 않는다. 새 약정은 출고 기본 작업 비용/기타 비용에 연결 원가를 재입력하지 않는 별도 비용 범위를 사용한다. 선택된 원천 항목은 서버가 실제 예약 Lot·수량, 단일 입고 근거, 불변 원천 약정 판본과 확정 항목/조정을 대조한다. 같은 Lot에 여러 입고가 섞인 경우, 불명확한 원천 수량, 미확정·분쟁 조정, 피킹 시각을 가로지르는 보관 기간은 보류한다. 부분 기간을 추정하지 않는다.

고정 입고비의 분모는 청구 항목의 Quantity=1이 아니라 원래 합의한 전체 작업 수량이다. 원천 비용 전액이 확인되어야 한다. 실제 예약 수량에 비례해 정수 원으로 귀속하고 마지막 전체 수량 귀속에 잔여 원을 보존한다. 미출고 수량에 해당하는 비용은 아직 귀속하지 않는다. 원가 귀속은 기존 작업자에게 다시 지급할 채무가 아니다.

보관 기간별 원가 판정에는 검증된 재고 변화 시각별 상수량 구간을 사용한다. 이후 피킹으로 줄어든 현재 수량을 과거 보관 기간에 소급하지 않으며 기존 연속 보관 구간·입고 작업 목록의 의미는 보존한다.

## 원장·동시변경·접근

원천 항목+주문에 고유한 불변 원가 귀속 기록을 추가한다. 기존 Serializable 명령 안에서 원천 약정 Revision을 확인/증가하고 원가 귀속·성과금·플랫폼 몫·명령 영수증을 함께 확정한다. 전액/전수량을 넘는 귀속, 변경된 계산 digest, 재전송으로 중복 발생하지 않는다. 이후 원천 조정은 과거 귀속을 덮어쓰지 않으며 부족한 예산을 새 계산에서 보류한다.

플랫폼 수령자는 서버 설정 및 기존 서버관리자 역할로 검증하고 해당 약정 동의를 별도로 받는다. 그 사용자를 원래 창고·배송 당사자로 추가하지 않는다. 본인 정산 항목 접근만 허용한다. 주문별 이미 나눈 잔여금의 플랫폼 수익은 기간 성과환원 재원에서 제외하여 이중 분배를 막는다.

## 페이지 책임 카드

기존 활동 정산 상세의 질문은 ‘이 약정에서 내 보수와 분배 조건은 무엇인가’다. 기존 기본 보수와 연결 비용 총액·적용 보유율·플랫폼 몫·참여자 풀만 분리해 보여준다. 원천 항목 ID·증빙·타인별 배분은 기본 화면에 노출하지 않는다. 과거 발생 계산은 저장 당시 비율을 표시한다. 새 route나 지급 버튼은 추가하지 않는다.
