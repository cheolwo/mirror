# 살뜰마트 전표 QR 스캔으로 픽업 완료 방향 r55

- 기획 ID: `PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB`
- 기준일: 2026-10-10
- 상태: `ScanActionDecisionAccepted / ImplementationApprovalPending / OperationalDeferred`
- 관계: [전표·픽업 제안 r54](ssalddel-mart-package-slip.design.r54.md)의 스캔 후 추가 확인 제안을 사용자 선택으로 대체한다. r54의 코드 조사·나머지 제안과 [선반 카메라 입력 r53](ssalddel-mart-camera-scan.implementation.r53.md)은 보존한다.

## 확정한 사용자 선택

기사님이 픽업용 화면에서 상품에 붙은 전표 QR을 스캔하는 행동 자체를 픽업 완료 의사로 취급한다. **스캔 뒤 `픽업 완료` 버튼을 한 번 더 누르게 하지 않는다.** r54의 요약 화면 뒤 추가 확인은 적용하지 않는다.

흐름은 **픽업용 QR 스캔 → 서버 검증·인수 기록 → 픽업 완료 표시**다. 주문 요약은 완료 결과로 보여줄 수 있지만 추가 제출 관문으로 사용하지 않는다. 단순 QR 정보 조회나 선반 QR 입력까지 픽업 Command로 바꾸는 결정은 아니다.

## 그대로 유지할 서버 경계

- 서버가 인증, 현재 배정 기사·배정 시도, 포장 준비, 주문 취소 여부와 유효 전표 판본을 검사한다. 잘못된 전표·미준비·타 기사 배정은 완료하지 않고 이유를 안내한다.
- 스캔 인식만으로 먼저 성공을 표시하지 않는다. 서버 처리 중에는 `픽업 확인 중`, 확정 성공 뒤에는 `픽업 완료`를 표시한다.
- 같은 전표가 연속 인식돼도 같은 요청·결과로 처리하고 인수·재고 감소·Event/Outbox를 중복 생성하지 않는다. 통신 결과가 불확실하면 기존 요청 결과를 먼저 재조회하며 새 요청 ID로 자동 반복하지 않는다.
- 여러 필수 포장이 있는 주문은 포장별 인수를 기록하고 마지막 필수 포장의 유효 스캔 뒤 주문 전체 픽업을 완료한다. 추가 완료 버튼은 두지 않으며, 미지원 단계에서는 다중 포장 주문을 임의 완료하지 않는다. 다중 포장 상세 정책 자체는 r54의 제안 상태다.
- 전표 사전 출력은 포장 완료나 픽업 완료가 아니다. 배달 완료·수령 확인·정산·지급도 픽업과 구별한다. 카메라 화면·원문 인식값을 저장하거나 로그로 남기지 않는다.

## 변경 범위와 남은 항목

이번에는 **QR 스캔 후 추가 버튼을 없애는 상호작용만 확정**했다. 네 자리 번호를 입력한 뒤 제출하는 방식·번호 발급 방식, 첫 프린터와 기사 앱 결속, 실제 마트 수행 Adapter 및 구현 범위는 확정하지 않았다. 번호 입력 방식의 미정을 이유로 확정된 QR 결정을 다시 질문하지 않는다.

현재 마트 기사 연결이 보류되어 있다는 r54의 조사 결과는 바뀌지 않는다. 이 선택을 기능 구현·실제 인계·운영 활성화 승인으로 확대하지 않는다. 후속 구현을 요청하면 승인 범위·작업 지시·쓰기 경로·검증 기준을 먼저 결속한다.

예정 검증에는 정상 전표 스캔 한 번으로 완료, 추가 완료 버튼 부재, 미준비/취소/타 배정/무효 전표 차단, 연속 인식·응답 유실의 중복 방지를 포함한다. 문서 갱신과 제품·인증 HTTP/DB·실물 인쇄·Android 검증은 별개다.

## 확정 / 미정 / 다음 질문 하나

- 미정: 네 자리 입력의 제출 방식과 r54의 나머지 세부안·구현 범위.

이번에는 기획 문서와 목차·현재 작업만 변경한다. 제품 코드·DB·앱·기능 플래그는 변경하지 않으며 업무 시험·실물 인쇄·Android·commit·push·배포를 수행하지 않는다.
