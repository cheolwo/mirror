# 기사 기준 위치와 권역 복귀를 배려하는 배차 설계 r37

- 날짜: 2026-10-08.
- 상태: `AcceptedDirection / ProposedDesign / ImplementationPending`.
- 사용자 방향: 기사 본인의 기준 위치에서 멀어졌을 때 돌아오는 방향의 콜을 우대해 빈 차로 장거리 복귀하는 부담을 줄인다. 사용자가 제시한 7km는 설정 예이며 고정 운영값으로 확정하지 않는다.
- 이번 범위: 기존 소스 읽기 조사와 보완 제안. 정책·제품 소스·DB·APK·실행 환경은 변경하지 않는다.
- 관계: [자율 다건 수행 r36](driver-flexible-multi-work.design.r36.md)의 기사 선택·공동 일정/적재량을 전제로 한다. 음식/화물의 원장·상태·운임·정산은 독립적으로 유지한다.

## 기사 설정과 활성 조건

기존 오늘/기본 복귀지와 `균형 / 복귀우선 / 수익우선`을 우선 재사용하되 목적을 구분한다. 권역 복귀는 지역 안에서 계속 일하려는 선택이고, 퇴근 복귀는 원하는 종료 시각과 목적지로 돌아가는 선택이다. 복귀 우대 활성화가 운행 종료·신규 수신 OFF·이미 수락한 업무 취소가 되지 않게 한다.

최소 설정은 기준 위치, 복귀 우대 사용 여부, 벗어나면 우대를 시작할 반경이다. 지도에서 선택한 활동 중심점도 허용하는 방향이며 실제 집 주소 입력을 모든 기사의 필수 조건으로 만들지 않는다. 현재 계약은 주소와 좌표를 요구하므로 지도 기준점 지원은 후속 계약/검증 보완으로 명시한다. 기존 기본 복귀지가 집이고 별도 활동 중심을 원하는 경우 두 목적지를 덮어쓰지 않는다. 설정 저장의 동시 변경 보호와 현재 운행에서 사용할 판본을 함께 다룬다.

- 설정 예: 기준점에서 직선거리 7km 이상이면 권역 복귀 우대 진입, 6km 이내로 돌아오면 해제한다. 수치와 경계 포함 여부는 설계 후보이며 아직 코드 기본값이 아니다.
- 반경 판정은 신선한 실제 위치와 고정 기준점으로 한다. 도로 경로의 길이/시간은 콜 가치 평가에 따로 사용한다. 교통 우회로가 길다고 지리적 반경 밖으로 이동한 것으로 바꾸지 않는다.
- 경계 근처의 GPS 흔들림에는 진입/해제 반경 차이와 위치 정확도·지속 관측을 적용한다. 현재 위치가 오래됐거나 기준점이 없으면 복귀 판정을 알 수 없음으로 두며 거리 0으로 채우지 않는다.
- 기사가 수동으로 복귀 우대를 켜거나 끌 수 있다. 설정 변경은 새 제안부터 재평가하고 기존 약속·지급 조건은 유지한다. 검색 중심을 사용자가 옮겼더라도 현재 위치를 바꾸지 않는다.

## 전체 수행 후 위치로 평가하는 점수 제안

권한·신규 수신 의사·위치 신선도·차량/배달통 적합성·기한·구간별 적재량이 먼저다. 복귀 가점으로 불가능한 경로를 가능하게 만들거나 음식 기한을 넘기지 않는다. 새 정책은 기존 적격 판정을 통과한 후보 사이의 우대만 소유한다.

기준점은 H, 이미 수락한 전체 업무를 마쳤을 때의 끝점은 E0, 추가 콜을 유효한 순서에 넣고 전체 업무를 마쳤을 때의 끝점은 E1로 둔다. 기존 업무가 없으면 E0는 현재 위치다. 비교 거리는 각각 E0→H, E1→H의 같은 이동수단·경로 정책으로 산정한 남은 복귀 거리이며, 한 주문의 하차지만 보고 다건 수행의 끝점을 대신하지 않는다.

```text
복귀 개선 거리 = 기존 전체 업무 종료 후 복귀 거리 − 후보 포함 전체 업무 종료 후 복귀 거리
최종 추천점수 = 기존 비교 점수 + 제한된 복귀 가점
복귀 가점 = 우대 활성 여부 × W × clamp(복귀 개선 거리 / 목표 개선 거리, 0, 1)
```

W와 목표 개선 거리는 보정용 설정 후보다. 가점 상한 20점은 기존 화물 점수 규모를 참고한 시험 시작 예일 뿐 승인된 운영값이 아니다. 더 멀어지거나 같은 거리에 끝나는 콜에는 이 개선 가점을 주지 않는다. 기존의 복귀 관련 점수에 이 값을 그대로 덧붙이지 않고 활성 정책에서 복귀 항목의 소유자를 하나로 정한다. 조율이 점수를 비용으로 환산하면 같은 새 가점을 별도 비용 차감으로 다시 적용하지 않는다. 음식과 장거리 화물의 기본 점수 척도가 다르므로 같은 20점을 무조건 복사하지 않는다.

복귀 거리가 줄어도 픽업을 위한 공차·추가 운행·조리 대기·피킹/사진·전달 시간이 크게 늘 수 있다. 기존 수익/시간 항목과 기사 추가 시간 한도로 함께 비교하며 같은 비용을 복귀 항목에 중복 감점하지 않는다. 완전한 도로 경로를 얻지 못하면 직선 참고값과 계산 상태를 분리하고 복귀 개선을 확정 가산하지 않는다. 차량별 통행 조건과 경로 판본을 유지한다.

| 예시 상황 | 제안 판정 |
| --- | --- |
| 현재 기준점에서 8km, 기존 업무가 없고 후보 수행 후 5km | 수행 조건을 통과하고 추가 시간도 합리적이면 복귀 가점 후보다. |
| 같은 조건에서 후보 수행 후 11km | 복귀 개선 가점은 없다. 기사가 일반 콜로 선택할 수 있는 여지는 유지한다. |
| 현재 8km지만 기존 3건을 마치면 이미 4km, 새 콜을 넣으면 6km | 현재 위치 대비로는 가까워져도 기존 계획보다 멀어진다. 복귀 개선 가점을 주지 않는다. |
| 하차지는 가깝지만 픽업이 크게 우회하거나 기존 음식 전달을 늦춤 | 전체 삽입 경로·시간 한도로 비교한다. 기존 기한을 깨면 제외한다. |

귀환 콜이 없으면 자동으로 복귀했다고 표시하거나 수신을 중단하지 않는다. 기사에게 우대 적용 중이라는 상태와 적합한 제안이 아직 없다는 결과를 구별해 제공한다. 대기 보정과 기존 참여 기회를 유지하고 거절 자체로 복귀 선호 점수를 불이익에 사용하지 않는다.

## 탐색·화면·정보 보호의 연결

후보 탐색에서 현재 기사와 접근 가능한 권역을 먼저 확정하고, 기존 제외·권한 범위 안에서 일반 후보와 복귀 방향 후보를 함께 비교한다. 화물의 10개 선제 제한과 음식의 단계별 권역 탐색을 보완할 위치를 각각 명시한다. 반경 밖 기사를 어떤 주문의 후보로 포함할지와 포함된 후보의 점수는 별개 책임이다. 집이 7km 밖이라는 이유로 픽업 접근 한도나 주문 검색 반경을 자동 확대하지 않는다. 넓은 탐색을 무제한 지도 API 호출로 구현하지 않고 후보 수·캐시·위치/정책 판본을 제한한다.

음식은 조리·픽업/전달 시간 조건을 만족하는 비교 집합을 먼저 만들고, 그 안에서 거리/시각 차이·대기·복귀 이익을 일관되게 비교하는 정렬 보완을 제안한다. 현재 정렬 앞부분을 무작정 복귀 점수로 대체하지 않는다. 기사의 현재 픽업/전달 순서와 수락 사실은 서버가 소유하며 순위/표시 갱신이 자동 수락이 되지 않는다.

설정은 기존 `내 정보` 안에 작게 두고 수행 지도·접는 현재 업무 카드는 유지한다. 추가 제안 카드에는 `권역 복귀 방향`, `전체 수행 후 기준점까지 8km→5km`, 늘어나는 금액·거리·시간을 기사에게만 표시한다. 직선거리와 도로거리 기준은 혼용하지 않는다. 상세 계산과 가점은 보조 정보로 펼쳐 본다. 기준점의 집 표시·정확한 주소/좌표를 공개 지도, 주문자·매장·다른 기사에게 새로 노출하지 않는다. 저장·로그·조회 보호는 현재 권한 경계와 함께 별도 확인한다.

## 보완 우선순위와 검증 조건

1. **기준점·선호 입력 연결:** Web 현재/복귀 좌표 분리와 표시/코드 불일치, 음식 기사 앱 미전달을 먼저 보완한다. 기존 복귀지 저장을 재사용하고 반경/활성 상태의 판본·보호 조회를 설계한다.
2. **반경 상태와 복귀 평가의 단일 기준:** 유효 위치 → 우대 진입/해제 → 기존/추가 전체 일정의 복귀 이익을 계산한다. 먼저 업무 없는 단건으로 비교를 검증하고 r36 공동 여력이 준비된 뒤 다건·음식/생활 물품 교차 일정으로 확장한다.
3. **실제 탐색·정렬·수락 연결:** 화물 개인 추천/자동 조율/연속 콜, 음식 실제 큐 경로에 각자의 후보 제한과 점수 척도를 맞춘다. 수락 직전 최신 일정·적재·정책 재검사와 기존 영속 보호를 유지한다.
4. **작은 화면과 격리 검증:** 기준점 저장/재조회·7/6km 경계와 GPS 흔들림·수동 전환·8→5/11km·이미 복귀하는 다건 계획·11번째 후보·타 권역 후보·기한/적재 위반·경로 실패·오래된 위치·정책 동시 변경·음식/화물 독립 운임을 대조한 뒤 휴대폰 검증으로 이어간다. 귀환 거리/공차 시간 감소와 기존 배달 지연·기사 대기/기회가 함께 개선되는지는 별도 관찰한다.

이번 완료는 소스 조사와 제안 문서 정리다. 문서 링크/차이 검사는 실행 정책·배차 성능·휴대폰 검증을 대신하지 않는다. 기존 시험 수를 이 제안의 시험 결과로 재사용하지 않는다.
