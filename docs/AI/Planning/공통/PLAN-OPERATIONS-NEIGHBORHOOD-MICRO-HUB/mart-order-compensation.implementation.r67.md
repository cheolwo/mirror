# 주문별 원가·보수와 마트 작업 근거 연결 r67

- 상태: Implemented / LocalValidated / OperationalDeferred.
- 승인: 2026-10-13 사용자의 `네 1번 2번 해줘 1번 2번.` 요청. 앞선 제안의 주문별 원가·보수 구조 연결과 피킹·포장 완료 근거의 기존 정산 연결만 구현한다.
- 기준선: `08931c2371f29de615f4a4f133b535e5df76bf7f` 및 기존 미커밋 r59~r65. 기존 변경은 보존하며 이번 작업에서 커밋·푸시하지 않는다.
- 주 상태 소유자: operations. Unity, 신규 앱 화면, APK, 클라우드 변경은 제외한다.

## 1. 주문별 조회 책임

[주문 원장 구조](../../../../Architecture/OrderRootLedger.md)의 포함 참조와 현재 전문 업무 원장, 기존 정산 항목 및 r61 원가 귀속을 읽기 전용으로 조합한다. 최상위 원장에는 하위 상태·금액을 복제하지 않는다. 하나의 상품 입고가 여러 주문에 사용되어도 입고 작업자 보수는 원천에 한 번만 발생하고 각 주문에는 기존 원가 귀속만 표시한다.

상품 대금, 작업 보수, 입고·보관 원가 귀속, 추가 성과금·플랫폼 몫, 지급 신고와 수령 진술을 서로 구분한다. 주문 제출을 확정 매출·실제 수금으로 보지 않는다. 상품 대금 전체를 플랫폼 수입으로 합산하지 않는다. 금액 미정은 null/계산 대기이며 실제로 합의된 0원과 다르다. 일부 확인 금액의 합은 전체 손익이나 실제 입금을 인증하지 않는다.

인증한 현재 사용자가 조회할 수 있는 원주문 및 하위 업무만 연결한다. 루트·Lot 참여나 공개 조회가 타인의 보수·사진·다른 주문의 조회권을 부여하지 않는다. 정산은 기존 payer/payee 및 과거 판본 접근 범위를 유지한다. 누락·불명확한 참조는 추정 연결하지 않는다. 현재 시각과 원천 ID·판본·상태·확인 여부를 남긴다.

## 2. 마트 작업과 보수 책임

기존 마트 주문에 연결된 피킹·포장 완료 기록의 처리자·품목·수량·시각·원본 식별자를 정산 근거로 재사용한다. 포장 보수 종류와 담당자 역할을 추가하되 기존 코드 값은 보존한다. 배정자와 실제 완료자가 다르면 완료자를 추정하지 않으며, 신규 완료에는 실제 처리자 근거를 보존한다. 확인할 수 없는 과거 기록은 보류한다.

작업 완료는 금액 발생·약정 동의·지급이 아니다. 실제 확인 처리량과 작업 전에 합의된 판본·단가를 기존 명시적 발생 명령에서 검증한다. 단가 미정은 0원으로 만들지 않고 계산을 보류한다. 같은 실제 작업은 반복 요청·다른 약정·다른 원천 별칭으로도 중복 청구하지 않는다. 인계·배송 실패가 과거 수행 근거 또는 이미 발생한 보수를 삭제하지 않는다. 배송비에 포함된 작업은 별도 지급채무로 다시 더하지 않는다.

포장 화면에는 실제 시작 명령이 없으므로 같은 출고 상품의 최초 피킹 시작을 `AgreementDeadlineAtUtc`로 동결한다. 이는 포장 보수의 보수적인 사전 합의 기한이며 실제 포장 시작시각이 아니다. 작업 배정→동일 판본 양측 동의→피킹 시작/완료→포장 완료 순서를 로컬에서 확인한다. 선행 시작 근거가 없거나 작업 진행 뒤 체결한 조건은 소급 인증하지 않는다.

현재 마트 원천의 고객 수령 확인 근거는 이 작업에서 새로 만들지 않는다. 마트 작업 보수 발생과 조회는 연결하지만 고객 수령에 따른 지급 해제는 별도 후속으로 보류한다. 실제 수행자와 배정자가 다른 완료도 잘못된 사람에게 자동 청구하지 않고 보류한다.

## 3. 로컬 완료 기준

- 한 입고 재고를 두 주문에 사용하는 사례에서 주문별 참조·수량·원가 귀속·본인 보수를 대조한다. 원천 입고 보수와 주문 원가 귀속을 중복 합산하지 않는다.
- 피킹과 포장 담당자가 달라도 실제 완료자·수량·근거가 각각 한 번 연결된다. 미완료, 불명확한 원주문, 미정 단가, 완료 후 합의, 반복 요청과 담당자 변경을 검사한다.
- 타 주문·타 작업자의 항목 및 비공개 증빙 비노출, 기본 OFF·Simulation 경계, 기존 source/API/정산 호환을 검사한다.
- 집중 시험, 경로를 한정한 Fast/Task, 소비 프로젝트 빌드 및 문서 링크를 확인한다. 실제 DB 적용·기기·외부 이체·운영 완료로 확대하지 않는다.

교육·기본 보장과 추가 성과금 정책, 구체 단가, 자동 지급 및 실패 비용 배분은 이번 범위에 포함하지 않는다. 다음 단계에서 별도 합의한다.

## 4. 로컬 검증 결과

Fast 집중 250개와 Task 전체 11,202개 시험이 통과했다. 환경 의존 MongoDB 시험 15개는 건너뛰었다. 전체 앱 소비 프로젝트 빌드는 오류 0개이며 기존 경고 61개가 남아 있다. 근거는 각각 `artifacts/local/validation/20261013-113030/`와 `artifacts/local/validation/20261013-113347/`다.

기존 포장 실패 후 재요청 계약을 보존하고 실제 시작 근거와 기존 표시용 시작값을 구분했다. 이번 범위 밖의 기존 변경 파일 154개는 해시가 같고 stage·commit·push는 하지 않았다. 단가 설정·공유 DB 적용·고객 수령 근거와 지급 해제·HTTP/단말/실제 이체는 이 로컬 완료에 포함하지 않는다.
