## 구현과 검증 결속

[변경·검증 기록](../../../../Changes/2026-10-06-neighborhood-flexible-delivery-r22.md)이 구현 경로, 다섯 정상 흐름의 동일 협업/운송 ID, 예외 복구, 비용·이동 부담 비교와 실행 한계를 소유한다. 직접 수령/전달은 운송 원장을 만들지 않으며, 기사 배송은 하나의 운송 원장에서 추천·공개 콜·병행을 선택한다. 기존 지역·역할·음식 업무와 null 계약을 보존한다.

SQL 접수 unique 키·선택 판본과 보호된 Mongo 조건/intent CAS, 연결 전 수락 차단으로 중복·늦은 응답을 제한한다. 기사 확정 뒤에는 기존 취소·재배차·물건 인수 절차를 사용한다. 현재 자동 추천은 기존 정책 엔진의 제안이며 AI 모델의 단독 실행 권한을 추가하지 않는다.

실제 MySQL/Mongo를 사용하는 두 격리 Operational 서버와 공통 웹 UI에서 검증했다. 가상 계정·주소/경로·운임·기사 적격성·알림·증빙 객체와 실제 물품 운행·실지급·휴대폰·Azure 운영을 구분한다. 추천 부재의 재탐색은 기존 정기 큐 스캔에 연결했으며 공개 전환은 건별 선택을 따른다.
