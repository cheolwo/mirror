# 통합 협업 원장과 참여 약속 구현 r115

기준일: 2026-10-24. 상태: `Implemented / FocusedTestsPassed / IsolatedHttpValidated / DeviceFunctionsValidated / ColdStartStabilityUnresolved`.

사용자는 [r114 사전 참여·약속 영향](advance-participation-and-promise-impact.design.r114.md)의 보완을 진행하고, 주문 원장보다 위에 통합 원장을 두어 여러 주문과 그 주문을 처리하는 입고·작업·배송 원장을 묶도록 요청했다. 기존 공동운영 원장을 통합 협업의 상위 정본으로 재사용하며 별도 중복 master나 전문 상태 사본을 만들지 않는다.

## 구현 경계와 책임

- 상위 통합 원장 = 기존 공간 공동운영 원장과 회차. 참여 역할·조건·운영 담당과 전문 참조를 유지한다.
- 주문 원장 = 기존 공동운영 주문 부록의 각 주문과 실제 원 주문 연결. 아직 협의 중인 주문과 실제 생성된 주문을 구분한다.
- 하위 업무 = 현재 권한과 계보가 확인된 입고·작업·배송·정산 참조. 원천의 실제 상태는 전문 원장이 소유한다.
- 같은 입고/작업 원장이 여러 주문을 지원할 수 있으므로 공유 노드와 관계로 표현한다. 회차에 있다는 이유로 모든 주문 아래에 붙이거나 중복 실적을 만들지 않는다.
- 참여 약속은 기존 보호 원장의 별도 부록으로 저장한다. 개별 제안·당사자 수락·거절·취소 전 영향과 변경 이력을 소유하며 고용/근무 권한·실물 작업·대금 청구를 확정하지 않는다.

상위 참여 이력을 다른 사람의 주문·금액·개인 약속 열람권으로 확대하지 않는다. 공개 목록/초대에는 비공개 계층과 약속을 내보내지 않는다. 기존 주문/전문 조회는 현재 사용자의 권한으로 다시 검사하고 미연결·기능 꺼짐·조회 실패를 구분한다.

## 첫 예약 범위

한 통합 원장 안의 각 회차에 공급·구매·입고·피킹·인계 약속을 제안한다. 참여자와 현재 역할·조건 판본·시작/종료 시간·연결 자료를 명시한다. 당사자 각각의 수락과 제안의 존재를 구분하고 정해진 상대방의 수락을 대신하지 않는다.

일반 참여 제안은 회차 전체의 필수 관문으로 승격하지 않는다. 현재 운영 담당자가 본인을 당사자로 포함해 명시한 `RequiredForCycle` 약속만 회차 시작 관문이다. 관련자 전원 수락·현재 조건·유효 시간·확인된 전문 참조가 필요하다. 닫힌 필수 약속은 현 운영 담당자의 명시 대체를 허용하되 같은 회차·업무·필수 지정과 대체 이력을 유지한다. 열린 약속을 인계받은 새 운영 담당자가 강제로 취소하거나 다른 사람의 수락을 대신하는 기능은 포함하지 않는다.

확정 시간 경합은 같은 상위 원장의 모든 회차를 대상으로 검사하고 부모 revision CAS로 경쟁 결정을 막는다. 다른 통합 원장·HR·외부 일정까지 전역적으로 예약을 잠갔다고 보고하지 않는다. 이 범위와 외부 일정 미확인을 화면에 표시한다. 실제 업무 시작은 기존 전문 명령의 현 권한/선행/시간 검사를 다시 통과해야 한다.

취소 영향은 읽기 전용이며 현재 원장·약속·조건·조회 원천 상태에 결속한다. 미리보기 후 상태가 달라지면 다시 확인한다. 실제 전문 원장 취소·물품 반환·금전 부담을 자동 실행하지 않고 이미 진행된 자료와 별도 정리가 필요한 항목을 안내한다. 확인 비용과 기대 손실은 미확정이면 금액을 만들지 않는다. 첫 범위의 변경 안내는 관련 당사자의 앱 내 재조회 이력이며 실제 푸시/문자 발송은 포함하지 않는다.

## 페이지 책임과 검증 계획

기존 통합 앱 공동운영 상세 안에서 “이 통합 원장에 어떤 주문과 업무가 연결되고, 내가 어떤 약속을 확인해야 하는가?”를 답한다. 계층은 조회, 약속 제안/수락·거절/취소 영향 확인은 독립 상태와 명시 행동을 가진다. 수락은 오른쪽, 거절은 왼쪽에 배치한다. 실패/미확인·원 요청 결과 확인·계정/서버/대상 변경의 늦은 응답 차단을 유지한다.

실제 통합 앱 모바일 화면과 가능한 APK 검증을 우선하며 좁은 폭 브라우저/렌더 시험은 보조 근거로 구분한다. 기준은 현재 [페이지 책임](../../../../ProjectOverview/page-docs/community-space-cooperation-r104.md)이다. Figma는 기존 읽기 전용 제한 Pending을 유지한다. 테스트·실제 보호 원장 저장/재조회·HTTP·앱 화면·실제 운영을 구분해 완료 시 기록한다. 기존 r112 93시험은 이번 변경 판본의 결과로 승계하지 않는다.

인증 복귀를 포함한 관련 회귀 219/219 통과(건너뜀 0), 최종 테스트 프로젝트 build 오류 0·경고 202를 확인했다. 실제 격리 Mongo/SQLite와 제품 API의 32검사도 통과했다. HTTP35회·암호화 envelope POST11회·인증 비공개 GET21회이며 콘솔 암호화 어댑터와 실제 브라우저 UI 검증은 구분한다. 실제 휴대폰의 별도 Debug APK에서 로그인 복귀·당사자 수락·서버 저장·읽기 전용 취소 영향을 확인했다. 데이터 초기화 뒤 첫 실행 1회 비정상 종료가 있어 초기 실행 안정성은 미해결이다. 공통 Fast/Task 스크립트는 관련 없는 기존 끝 공백 오류로 중단됐고 좁은 변경 검사는 별도로 통과했다. 상세와 실제 휴대폰 화면은 [변경 기록](../../../../Changes/2026-10-24-integrated-cooperation-ledger-r115.md)을 따른다.

운영 DB/실금전·실제 배차·외부 발송·Unity·게시/배포·commit/push는 이번 구현에 포함하지 않는다.
