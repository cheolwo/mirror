# 협업 변화 조회 구현 r112

기준일: 2026-10-24. 상태: `ImplementationAuthorized / Implemented / FocusedTestsPassed / MobileRuntimePending`.

사용자가 [협업 비전과 객관적 성과 r111](cooperation-vision-and-shared-outcomes.design.r111.md)의 진행을 요청했다. 첫 범위는 기존 공동운영 당사자 상세의 `이번 회차에서 함께 만든 변화` 조회다. 후속 [모바일 예약·상호 수락 제안 r113](mobile-work-appointments.design.r113.md)은 별도 제안이며 이번 구현에 포함하지 않는다.

## 구현

- 기존 비공개 상세 응답에 optional `SharedOutcomes` 조회 결과를 추가했다. 공개 모집/초대 DTO, 저장 회차, 기존 명령·권한은 변경하지 않았다.
- 현재 관심만 있는 인원과 역할 수락 인원은 고유 계정으로 센다. 복수 역할을 사람 수로 더하지 않고 현재 조건 동의 역할과 재확인 역할을 나눈다. 과거 실제 근무 인원으로 표시하지 않는다.
- 회차마다 연결 자료를 현재 조회자의 전문 권한으로 다시 확인한다. 마지막 회차는 같은 상세의 readiness를 재사용하고 이전 회차는 순차 조회한다. 누락·중복·다른 연결의 결과로 확인 실적을 채우지 않는다.
- 최신 회차는 펼치고 이전 회차는 접는다. 저장 당시 마감 기록과 현재 원천 재확인을 구분한다. 연결 자료 수는 상품 수량·고유 주문 수·배달 건수가 아니다.
- 정산 완료는 `지급 준비 확인`이며 실지급·입금 확인이 아니다. 실수령액·이동/대기 시간·비용 절감은 확인 근거 미연결로 표시한다. 자유 입력 문구나 회차 경과시간에서 금액·근무시간을 추정하지 않는다.
- 공용 Workspace 당사자 상세에만 Panel을 붙였다. 기존 회차 메모·전문 링크를 재사용하며 새로운 급여·신뢰·고충 명령은 만들지 않는다.

## 검증과 남은 범위

표준 Fast/Task 검사는 기존 미관련 파일 `Ssalddel.Ui.Common/Areas/App/RoleWorkspace/Cargo/CargoDriverWorkSession.cs:245`의 EOF 빈 줄로 첫 전체 diff 검사에서 중단됐다. 그 파일은 변경하지 않았다. 이번 수정 범위의 diff, 새 파일 포함 줄 끝 공백 검사, r112/r113 상대 링크 확인은 통과했다. 표준 전체 시험 완료로 보고하지 않는다.

공유 DTO, `공간공동운영변화Query`, 기존 UseCase, `공간공동운영변화Panel`과 Workspace를 보완했다. 신규 서버 시험 6개와 UI 사례 21개를 포함한 `FullyQualifiedName~공간공동운영` 관련 93개가 통과했다(실패 0, 생략 0). 선행 전체 테스트 프로젝트 build는 오류 0, 경고 218개였다. 근거는 `artifacts/local/community-shared-outcomes/20261024-r112/`의 restore/build/tests 로그와 TRX다.

격리 새 preview 소스만 준비했으며 새 판본 서버·브라우저/실제 통합 앱 APK 확인은 아직 수행하지 않았다. 앞선 r104 화면/DB 증거를 승계하지 않는다. 화면 검증은 최신 사용자 요청에 따라 실제 통합 앱의 모바일 화면을 우선한다. 좁은 폭 브라우저와 물리 기기/APK는 별개로 기록한다. Figma는 기존 읽기 전용 차단 Pending을 유지한다.

새 예약/매칭·급여 정책·운영 DB·외부 배차/지급·공개·휴대폰 설치·commit/push는 실행하지 않았다. 실제 운영 효과와 밀집도에 따른 개인 소득 증가는 미검증이다.
