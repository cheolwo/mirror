# 생산부터 출고까지 업무 연결도 r116

기준일: 2026-10-24. 상태: `Implemented / FocusedTestsPassed / BrowserValidated / DeviceFunctionsValidated / ColdStartStabilityUnresolved`.

사용자는 넓은 업무 범위를 기존 원장·노드 구조를 활용해 생산·입고·출고를 거쳐 순환하는 연결도로 보도록 요청했다. 별도 업무 실행 엔진이나 통합 상태 DB를 만들지 않고 [r115 통합 원장](integrated-cooperation-ledger.implementation.r115.md)의 현재 허용된 조회를 기존 공동운영 상세에서 소비한다.

## 연결도와 실제 업무의 구분

생산·공급 / 입고·검수 / 보관·재고 / 주문 / 피킹·출고 / 배송·수령 / 정산의 일곱 노드를 넓은 절차 안내로 표시한다. 공급·입고·보관 쪽과 주문 쪽이 출고에서 만나는 분기를 사용한다. 점선과 화살표는 안내 관계이며 실제 필수 순서·실행 가능·인계 수락을 뜻하지 않는다. 정산 뒤 같은 회차의 생산 노드로 돌아가는 전이는 만들지 않고 다음 회차를 별도 기록으로 설명한다.

기존 `OperatingSystemInteractionCatalog`의 네 인계 정의와 `OperatingSystemLifecycleCatalog`의 업무·단계명을 보조 설명에 재사용한다. 카탈로그 정의·Sequence와 실제 인계 기록은 구분한다. 현재 화면은 기존 실제 화주 업무망 조회에 새로운 통합 실행 권한을 부여하거나 모든 OS의 실시간 인계를 조회한 결과가 아니다.

## 현재 원천을 보여주는 범위

| 절차 안내 | 소비하는 기존 자료 | 의미 경계 |
| --- | --- | --- |
| 생산·공급 | 직접 연결 없음 | 공급 약속·입고 기록으로 생산 완료를 만들지 않음 |
| 입고·검수 | InboundPlan | 수령/재고 계보 근거이며 독립 검수·적재 전체 완료 아님 |
| 보관·재고 | DistributedSite, StorageAgreement | 공간/보관 동의이며 가용 재고·적재 완료 아님 |
| 주문 | 당사자 주문, RootOrderLedger | 주문 협의/정본 연결이며 실물 완료 아님 |
| 피킹·출고 | DistributedWave | 출고 묶음·수령 자료이며 개별 피킹/포장 완료 아님 |
| 배송·수령 | DistributedOrder, MartOrder | 전문 자료별 전달·수령 확인이며 같은 묶음 전체 상태로 전파하지 않음 |
| 정산 | Settlement | 지급 준비 확인이며 실입금 아님 |

노드는 연결 자료 수만 표시하며 단계 완료색·완료율·새 실적을 계산하지 않는다. 한 원천은 같은 회차에서 고유 키로 한 번만 소비한다. 정확한 현재 주문-원천 `source-lineage` 관계는 실선 모양의 참고 자료 연결로 표시하고 실행 전이로 바꾸지 않는다. 알 수 없는 종류는 별도 미분류 목록에 남긴다.

상세와 통합 조회의 원장 ID·revision·실행 모드 및 회차 메타데이터가 같을 때만 조합한다. 같은 원본 키의 중복·누락·문맥 충돌 자료는 미확인으로 표시한다. 주문 조회 기능 꺼짐/권한/통신 문제는 자료 없음과 구분한다. 원시 상태코드·참조 ID·주소·담당자 ID는 새로 출력하지 않고 기존 안전한 원 업무 링크만 현재 검증 자료에서 사용한다.

## 화면과 유지 조건

사용 질문과 기본/보조 정보는 [페이지 책임 카드](../../../../ProjectOverview/page-docs/community-space-cooperation-r104.md)의 r116이 소유한다. 넓은 화면은 분기 점선, 좁은 모바일은 줄바꿈 가능한 노드와 다음 절차 문구를 사용한다. 노드 선택·회차 변경은 로컬 보기만 바꾸며 API 명령·DB 저장·배차·지급을 하지 않는다. 기존 통합 계층·참여 약속·조건·취소 영향은 보존한다. 새 공용 그래프 엔진·수정 가능한 다이어그램 사본은 만들지 않는다.

관련 회귀 235/235 통과(실패/건너뜀 0), 테스트 빌드 오류 0·경고 203, 실제 소비 호스트 빌드 오류/경고 0을 확인했다. 브라우저와 390px 보조 화면, Android 16 실제 별도 Debug APK의 노드 선택·주문 상세를 확인했다. 선택 후 격리 원장 revision 16은 유지됐다. 시험 앱 데이터 초기화 뒤 최초 실행 종료 1회(status 255)는 미해결이다. 공통 Fast/Task는 기존 다른 파일의 끝 공백 오류로 시작 단계에서 중단됐고 이번 범위 검사는 별도로 확인했다.

검증 결과와 실제 화면은 [r116 변경 기록](../../../../Changes/2026-10-24-work-procedure-graph-r116.md)에 기록한다. 빌드·집중 시험·실제 브라우저·휴대폰 APK와 운영/게시를 구분한다. Figma 대응은 기존 읽기 전용 제한으로 Pending이며 이 변경을 Figma 동기화 완료로 표시하지 않는다.
