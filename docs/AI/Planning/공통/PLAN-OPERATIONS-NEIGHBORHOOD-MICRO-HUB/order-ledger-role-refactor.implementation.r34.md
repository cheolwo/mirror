# 주문 한 건의 역할·선택 조건 연결 r34

- r40 당시 상태: `Implemented / LocalValidated / RootSelectionUiPending / OperationalDeferred` (2026-10-08)
- 후속: 원주문 선택 양식·관계 편집의 동시 보호는 [r35/r41](root-order-selection-concurrency.implementation.r35.md)에서 구현·로컬 검증했다. 실제 운영 검증은 별도다.
- 승인: 주문자에서 판매자·공간 관리자·기사·수령·정산까지 기존 원장 구조로 내려가며 선택 조건과 필수 절차를 정리하자는 제안에 사용자가 “그렇게 리팩토링을 해줘”라고 요청했다.
- 대상: 서버·공유 계약·기존 주문자 화면. Unity·운영 활성화·실제 금전·APK·commit/push는 이번 구현에 포함하지 않는다.

## 구현 범위

1. 분산 주문의 표시 참조와 고유 식별자를 구분한다. 선택한 기존 주문 루트의 권한·당사자·판본을 확인하고 실제 출고·운송 원장을 기존 포함 관계로 연결한다. 저장 후 연결 실패는 완료로 숨기지 않고 같은 요청의 재확인으로 재개한다. 기존 경로·원장·독립 상태를 보존한다.
2. 현재 음식 수행의 조건 변경 가능 여부와 잠금 이유를 같은 정책으로 판정한다. 조리·픽업·전달·증빙은 설정으로 해제하지 않는다. 개인 표시, 역할 기본값, 건별 합의, 운영 정책을 구별한다.
3. 일반 주문 상세는 현재 단계·대기 이유·다음 업무로 이동을 기본 표시하고 연결 원장 식별자·판본은 상세에 둔다. 업무 실행은 기존 전문 API에서 최신 상태와 권한을 다시 확인한다.
4. 수락 이후 취소·변경은 기존 문제 접수로 인계한다. 요청 접수·사건 종결·수령·정산·실제 지급을 하나의 완료로 합치지 않는다. 새로운 환불액·비용 부담 규칙은 발명하지 않는다.

## 권위와 호환

[주문 원장 구조](../../../../Architecture/OrderRootLedger.md)와 [역할 선택 기준](../../시스템/PLAN-SYSTEM-ROLE-BUSINESS-OPTIONS/role-options.review.r2.md)을 따른다. 주문 루트는 참조를 모으며 하위 업무 상태를 복제하지 않는다. 역할별 조회는 이미 허용된 정보만 조합한다. 원장 연결의 필수 여부 변경·분리는 진행된 업무 사실을 제거하는 우회가 되지 않아야 한다.

기존 주문·출고·운송 식별자는 이행 중에 바꾸지 않는다. 새 분산 주문만 고유 식별자를 사용하고 표시 참조는 별도로 유지한다. 금액이 미확정이면 미확정으로 보존한다. 입고 당시 보관 합의를 덮어쓰지 않고 예약 당시 합의 근거를 별도로 보존한다. 기존 기능 플래그와 `Simulation`/`Operational` 경계를 유지한다.

## 검증과 반환

- 원주문 권한·당사자·revision, 표시명 중복, 재처리·연결 실패 후 재개, 예약 합의 판본 보존.
- 활성 하위원장 분리/필수 해제 차단, 원장 누락·빈 필수 집합·역할별 비공개 상태.
- 음식의 조건 갱신 표시/실행 일치, 조리 전후·진행 중·종료·실패, 기존 신고 인계.
- 주문 상세의 로딩/빈/오류/재시도/비공개·모바일 렌더, 소비 앱 컴파일.
- `validate-changes.ps1 -Paths`의 Fast·Task 및 관련 소비 solution 빌드. 실제 DB·휴대폰·운영 효과와 로컬 시험 증거는 구별한다.

완료 상태와 잔여 범위는 [변경 기록](../../../../Changes/2026-10-08-order-ledger-role-refactor-r40.md)에 기록한다.

Fast 323개·Task 9,078개를 통과했고 환경 의존 MongoDB 시험 2개는 미실행이다. 주문 상세는 실제 제품 Razor와 공유 ViewModel의 예시 응답 호스트에서 두 폭의 접기/펼치기·비공개·조회 실패/재시도를 확인했다. 원주문 선택 목록 양식, 하위 상태 전이와 관계 편집의 공동 잠금, 실제 보호 HTTP/공용 DB/휴대폰은 후속이다.
