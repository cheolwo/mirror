- 사용자 요청: **“일단 기획한 것들이 뭐라고죠 화면상에 구현이 될 수 있도록 좀 한번 구현을 해줬으면 좋겠는데 다른 책임 영역이랑 좀 중복이 되지 않도록 좀 그런 점은 좀 유의를 해서 말이야.”**
- 범위 확인 답변: **“최근 공동주택 기획을 기존 역할 화면에 나눠 반영”**.
- 현재 작업 기준: `dev/mirror-integration`, HEAD `08931c2371f29de615f4a4f133b535e5df76bf7f`, 시작 시 미커밋 566개·stage 0개. 관련 없는 변경은 보존한다. 같은 작업실의 명시적 구현 요청이며 다른 작업실의 미승인 인계를 수용한 것이 아니다.
- 기준 기획: [r95](workflow-operating-decisions.design.r95.md), [r99](workflow-operating-decisions.design.r99.md), [r100](workflow-operating-decisions.design.r100.md), [r101](workflow-operating-decisions.design.r101.md).

## 승인한 구현 범위

| 역할·질문 | 기존 소유 화면과 이번 반영 |
| --- | --- |
| 주민: 어떤 상품이 필요하다고 알릴까? | 기존 생활 교류 작성에 입고 희망 진입을 추가. 기존 필요글·동네·공개 문의를 재사용하며 주문·예약·자동 집계로 바꾸지 않음 |
| 작업자: 이 약정에서 내 보수·조건은 무엇인가? | 기존 활동정산 상세의 본인 기본 보수·수량·유효 조건을 먼저 요약. 기존 서버 약정·동의 행동을 유지 |
| 공간 제공자/공급자: 무엇을 언제 얼마나 받는가? | 기존 분산 공간·입고 화면과 수용된 기간/용량/예정·실입고 기준을 대조하고 실제 표시 누락만 최소 보완 |

주민용 내부 재고·계약 접근권, 자가 피킹 완료 명령, 공개 일감 시장, 단지 기여금 전용 약정/공제/송금·관리비 반영 API는 이번 화면 작업으로 새로 만들지 않는다. 기존 전문 원장·업무 명령을 다른 화면에 복제하지 않는다. 운영비·5%/10% 단지 기여금을 기존 플랫폼 몫으로 대신 계산하지 않는다. 공급자 가격·주민 신분 확인·인력 계약의 미정은 실제 기능으로 승격하지 않는다.

## 책임과 변경 경로

- 주민 작성: `ExchangeWrite.razor`, `ExchangeList.razor`, `NeighborhoodExchangeViewModel.cs`, 관련 CSS와 Web/일반 MAUI의 기존 작성 route query 전달.
- 작업 보수: 기존 `활동정산Screen.razor`와 같은 폴더의 표시 전용 패널/helper/CSS. 본인 수령 기본 보수만 요약하고 배송 포함 참고·미확정은 구분.
- 공간·입고: 기존 `분산공간Screen.razor`/`분산입고Screen.razor`와 필요 시 같은 업무의 표시 전용 패널. 새 계약·재고 상태 머신은 없음.
- 검증: 각 변경의 좁은 시험·기존 실제 공유 Razor를 조립하는 루프백 검증 호스트, 기존 Web/MAUI 소비자 build와 `validate-changes.ps1` Fast/Task.
- 문서: 페이지 책임 카드·변경 기록·현재 기획 목차/작업. 운영 권한·계약·원장 소유자는 기존 서버가 유지한다.

## 검증 계획과 경계

입고 희망 진입이 빈 초안에만 분류를 준비하고 기존 초안을 덮지 않는지, 실제 payload가 기존 필요글인지, 조회 실패/응답 유실에 자동 재전송하지 않는지 확인한다. 보수 표시는 본인·항목 종류·미확정·배송 포함을 대조한다. 실제 공유 UI의 모바일/데스크톱 렌더·화면 이동·조건 표시를 확인한다.

로컬 글 저장·HTML/브라우저·build·APK·실기기·외부 공개 운영·실제 지급은 별도 결과다. 이번 요청에 USB 연결·클라우드 배포·실제 계약/입고/지급·Figma 변경·commit/push는 포함하지 않는다. 결과는 구현/검증 후 같은 계획에 연결한다.

## 구현 결과

세 범위의 공통 UI를 기존 Web/일반 MAUI에 반영했다. Fast 34개·Task 12,017개 통과·실패 0개·환경 의존 16개 미실행이다. 실제 공유 Razor를 조립한 루프백 Chrome 20개 배치와 주민 글 등록·HTTP 재조회·새로 고침, 격리 SQLite 229개 테이블 행 수를 대조했다. 글과 기존 음성/키워드 후속만 증가했고 주문·입고·정산 행 수는 보존됐다.

최신 스키마와 다른 기존 Preview DB는 보존하고 검증 DB 이름 옵션을 추가했다. 최신 글 상세에 필요한 기본 Preview DI도 보완했으며 실제 제품의 공통 등록은 이미 존재했다. 기본 Preview에서 지원하지 않는 협업 공개 조회는 오류 안내로 남는다. 보수·입고 자료는 예시 DTO이며 이 결과를 실제 계약·기기·입출고·지급 또는 전체 협업 통합 검증으로 확대하지 않는다.
