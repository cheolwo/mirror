## 수용한 답변과 조건

- 이전 질문 의미 ID: `piecework-acceptance-rejection-freedom`
- 이전 상태: r99의 `Asked / Unanswered`
- 현재 상태: `Answered / QualifiedByOnsiteWorkAndManagerResponsibility`

건별 참여자의 자유로운 수락·거절 방향은 수용하되, 현장에서 계속 배정된 일을 처리하는 상주 작업은 별도 운영 형태로 구분한다. 사용자의 설명은 창고 현장의 업무 분담 특성으로 기록하며, 모든 상주자에게 무조건 업무 수행을 강제하거나 적법한 거절·휴식·중단을 배제하는 정책으로 확정하지 않는다.

사용자가 지향한 플랫폼 역할은 **누구나 활용할 수 있는 업무 연결·기록·계산 등 소프트웨어 제공**이다. 현장 인력의 계약·업무 지시·보수·근무 운영은 실제로 그 역할을 맡은 단지 운영주체가 담당하는 방향을 수용한다. 그 주체가 입주자대표회의·관리사무소·별도 운영업체·개인 중 누구인지, 누가 법적 사용자/계약 당사자인지는 아직 확인하지 않았다.

‘소프트웨어만 제공하므로 플랫폼은 어떤 책임도 없다’거나 ‘단지 관리자라고 지정하면 모든 법적 책임이 이전된다’는 결론은 수용하지 않는다. 실제 계약과 운영 관계에 따른 의무는 보존한다. 특정 관리자의 등록만으로 서버 권한·개인정보 접근·자금 처분권을 새로 부여하는 구현 승인이 아니다.

## 업무 진입 방식의 구분안

| 형태 | 업무 진입 | 담당과 보수 기록 |
| --- | --- | --- |
| 건별 참여 | 제안된 범위·수량·기한·보수를 확인하고 수락·거절 | 수락한 약정과 실제 완료 실적·본인 보수 연결 |
| 현장 상주 업무 | 현장 운영주체와 맺은 조건 아래 배정된 ‘내 할 일’ 확인·수행 | 실제 배정자·수행자·실적과 적용 계약/보수 기준 연결 |

두 형태는 소프트웨어의 업무 흐름을 나누는 제안이며 법적 고용형태를 확정하는 분류가 아니다. ‘상주’ 표시만으로 시급·월급·건별 보수 중 하나를 자동 선택하거나, ‘건별’ 표시만으로 근로관계를 자동 부정하지 않는다. 상주 작업에 건별 제안의 매번 수락 버튼을 형식적으로 붙여 자율성을 인증하지 않는다.

상주 작업에도 작업 불가·재고 부족·장비 문제·수량 차이·사진 전송 실패 등 예외가 있으면 사유와 대체 담당/보류를 기록하고 기존 복구 절차로 이어가야 한다. 배정은 완료가 아니며, 작업이 남아 있다는 사실만으로 완료 실적·보수·기여금을 만들지 않는다. 수락 전 거절과 이미 맡은 업무의 중단·인계는 구분한다.

## 역할과 책임을 기록하는 제안

```text
실제 현장 운영주체
├─ 계약 당사자·담당 인력·업무 조건 확인
├─ 현장 업무 배정·변경·대체 담당·완료 확인
└─ 적용 보수 기준·지급 책임·필요한 인력 운영 규정 관리

플랫폼 소프트웨어
├─ 업무 제안 또는 내 할 일 표시
├─ 실제 수행자·수량·증빙·원주문/입고 연결 기록
├─ 합의된 보수·운영비·공동기여금의 계산 지원
└─ 지급/단지 수령/관리비 반영 결과와 미처리 사유 표시
```

각 업무/약정에 계약 주체, 업무 배정 주체, 보수 결정 주체, 실제 지급 책임자와 증빙 확인 담당을 구분하는 안이다. 계약 명칭이나 화면의 담당자 한 칸만으로 법적 사용자성을 판정하지 않는다. 공간 제공자가 물품 판매자·작업 발주자·고용주·임금 지급자가 모두 된다고 가정하지 않는다.

플랫폼은 단지마다 실제 역할을 맡은 당사자의 유효 권한·합의에 따라 기록·계산·연결을 돕는 방향이다. 플랫폼이 임의로 현장 근무시간·업무 수행·제재·보수를 직접 통제하는 기능을 추가하면 이번 역할 구분이 실제 운영과 맞는지 다시 검토해야 한다. AI 추천을 실제 현장 담당의 의사결정·수락 또는 법 적용 제외 근거로 자동 대체하지 않는다.

개인 계약·보수·근무 정보는 본인과 필요한 권한 범위에서 다룬다. 단지 운영자라는 이름만으로 다른 단지·고객 상세정보·타인 계좌에 접근하지 않는다. 이번 기획은 책임을 드러내는 방향이며 새로운 관리자 권한 체계를 구현한 것이 아니다.

## 기존 보수·기여금·원장 기준

r99의 사전 제안 보수, 운영비와 단지 기여금 배정의 구분을 유지한다. 상주 업무의 실제 계약에 다른 지급 기준이 있다면 그 기준을 보존하며 임의로 모든 보수를 건별 단가로 치환하지 않는다. r98의 5%/10% 기여 선택안도 해당 계약에 대한 실제 합의·적용 가능성 확인이 필요하다.

원주문·입고 Lot·완료 실적·보수 원장을 재사용하고 근무 형태별로 같은 완료 사건을 이중 발생시키지 않는다. 시급/월급의 작업 실적 기록이 있더라도 그 실적을 별도 건별 지급 채무로 자동 더하지 않는다. 별도 성과 보수를 합의한 경우 그 근거와 기존 기본 보수를 구분하는 후속 설계 대상이다.

보수 발생·확인·실제 지급·기여금 납부·관리비 반영은 계속 다른 결과다. 관리자가 운영을 맡는다는 이유로 기존 완료 증빙·정산 보호·권한·중복 처리 방지를 생략하지 않는다. 근로관계에 적용되는 지급 기준·최저 기준 등을 무시하는 옵션도 만들지 않는다.

## 공식 근거와 적용 한계

2026-10-15 공개 공식 자료를 다시 확인했다. 다음은 역할 구분 시 지켜야 할 판단 근거이며 실제 단지나 플랫폼의 법적 지위를 판정한 것은 아니다.

- [근로기준법 제2조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0002&lsiSeq=285279&urlMode=lsScJoRltInfoR): 사용자에는 사업주 외에도 사업 경영 담당자와 근로자 관련 사항에 관해 사업주를 위해 행위하는 사람이 포함된다. 플랫폼/단지라는 표시만으로 범위를 확정하지 않는다.
- [대법원 2023. 8. 31. 선고 2023도6323](https://www.law.go.kr/LSW/precInfoP.do?precSeq=238955): 실제 지휘·감독, 시간·장소 구속, 독립성 등 근로제공 관계의 실질을 종합한다. 상주 작업의 실제 관계를 별도로 확인해야 하는 근거다.
- [대법원 2024. 4. 25. 선고 2024도1309](https://www.law.go.kr/LSW/precInfoP.do?precSeq=240745): 사용자 범위를 사업주에만 한정하지 않는 취지와 실질 경영자의 책임을 설명한다. 해당 사건은 구제명령 이행 책임에 관한 것으로, 본 플랫폼에 그대로 같은 책임이 인정된다고 확대하지 않는다.

이 근거에서 도출한 설계상 판단은 실제 인력 운영을 맡은 주체와 소프트웨어 제공 범위를 드러내되, 책임을 화면 설정이나 계약 명칭으로 자동 면제·이전하지 않는 것이다. 단순 도구 제공만으로 곧바로 사용자가 된다고 단정하지도 않는다. 실제 계약·지휘·보수 운영 관계는 후속 확인 대상이다.
