# 휴대폰 업무 요약·독립 상세·등록 연락처 r117

기준일: 2026-10-24. 상태: `Implemented / FocusedTestsPassed / HttpValidated / DeviceFunctionsValidated / ColdStartStabilityUnresolved`. [r116](work-procedure-graph.implementation.r116.md)의 절차 조회와 [r115](integrated-cooperation-ledger.implementation.r115.md)의 통합 원장·참여 약속을 보존한다. 사용자는 휴대폰 우선 요약 노드, 노드별 상세 페이지, 기존 업무에 등록된 담당·현장 연락처, 전화 앱의 번호 입력창만 여는 동작을 요청했다.

## 화면과 복귀

### 모바일 연결선 보완 r118

사용자의 후속 요청으로 모바일 요약 노드 왼쪽에도 연결선을 표시한다. 기존 절차의 생산→입고→보관→출고와 별도 주문→출고 합류, 출고→배송→정산 관계만 사용한다. 카드 높이와 여백에 맞춰 선이 이어지며 보관→주문이라는 새 직렬 관계를 만들지 않는다. 선은 장식으로 접근성 트리·클릭 대상에서 제외하고 기존 노드 링크·상세·로그인·연락처 권한은 유지한다. 넓은 화면의 기존 SVG 연결도는 유지한다. 시각 근거는 [r118 변경 기록](../../../../Changes/2026-10-24-mobile-work-connectors-r118.md)을 따른다.

좁은 화면의 노드는 한 열의 짧은 제목·자료 수이며 각 노드가 독립 상세로 이동한다. 경로는 `/community/space-cooperations/{ledgerId}/work/{stageKey}?cycle={cycleId}`다. 일곱 단계만 허용하고 회차를 생략하거나 임의 경로를 로그인 복귀에 끼워 넣지 않는다. 상세에서 같은 원장·회차 요약으로 돌아간다. 웹과 통합 앱은 얇은 경로 호스트와 공용 화면·조회 ViewModel을 재사용한다.

상세는 현재 연결 자료, 허용된 원 업무 링크, 업무 연락처, 역할·입력/전달 안내 순서다. 역할 안내는 실제 담당 배정이 아니며 자료 수·선택·화면 이동으로 업무 완료·수행 가능을 만들지 않는다. 기존 참여 약속 초안·원 요청·미확정 명령을 새 상세에서 소유하거나 변경하지 않는다.

## 연락처 권위

현재 계정이 해당 비공개 공동운영 원장·회차·원천을 볼 수 있어야 한다. 기존 전문 조회가 허용한 등록 정보만 명시적 요청으로 읽는다. 서버는 원천 ID를 클라이언트에서 임의로 받지 않고 현재 회차에 이미 연결된 자료에서 도출한다. 부모 revision·실행 모드·회차·검증된 원천 판본과 실제 하위 관계를 재확인한다.

| 단계·원천 | 첫 지원 범위 | 제외되는 추정 |
| --- | --- | --- |
| 보관·재고 / DistributedSite | 실제 연결 창고 중 현재 계정이 조회할 수 있는 등록 업무 연락처 | 참여자 소개·역할을 개인 담당자로 추정하지 않음 |
| 배송·수령 / DistributedOrder | 실제 연결 화물 의뢰의 기존 당사자 또는 현재 배정 기사 상세가 허용한 현장 연락처 | 계정 프로필 번호·다른 의뢰·동의 보류 번호를 조회하지 않음 |
| 피킹·출고 / DistributedWave | 같은 회차에 이미 검증되어 연결된 해당 묶음 주문의 현장 연락처 | 묶음 전체의 다른 주문을 열거하지 않음 |
| 다른 단계·원천 | 현재 연결/지원/권한/미등록 상태 안내 | 주변 업무 번호나 참여자 번호로 채우지 않음 |

응답은 인증이 필요한 `private, no-store` GET이며 담당 표시명·번호는 기존 ISMS-P 전송 보호를 사용한다. 번호·이름·주소는 URL이나 새 로그에 넣지 않는다. 새 연락처 저장·담당 배정·개인정보 제공 동의·외부 연락·전문 명령은 없다.

## 번호 입력창

전화 앱 버튼을 누르면 현재 연락처를 다시 읽는다. 권한·원천·번호·표시 내용이 바뀌면 입력창을 열지 않고 갱신된 내용을 다시 확인하게 한다. 계정·서버·회차가 바뀌거나 화면이 폐기되면 이전 비동기 결과를 적용하지 않는다. 번호는 제한된 숫자/국제 접두 형식만 허용하며 URI·USSD·확장 명령을 실행하지 않는다.

통합 앱은 MAUI PhoneDialer의 `Open`을 사용하고 Android manifest에는 DIAL 조회만 추가한다. CALL_PHONE 권한이나 자동 발신은 추가하지 않는다. 웹은 지원하지 않는 경우 번호 입력창 버튼을 비활성화한다. [MAUI 공식 안내](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/communication/phone-dialer?view=net-maui-10.0), [Android ACTION_DIAL](https://developer.android.com/reference/android/content/Intent#ACTION_DIAL)을 대조했다.

## 검증 경계

페이지 책임은 [공동운영 페이지 책임 카드](../../../../ProjectOverview/page-docs/community-space-cooperation-r104.md)의 r117을 따른다. 소스·단위 시험·실제 HTTP·브라우저 폭·실제 별도 APK의 상세 이동·전화 앱 입력창 확인을 분리한다. 시험에 사용하는 번호는 실제 사람이 아닌 더미 번호이며 실제 발신은 하지 않는다. 기존 r115 시험 원장은 보존하고 r117 연락처 시험은 별도 격리 원장으로 준비한다. Figma는 기존 읽기 전용 제한으로 Pending이며 화면 검증과 동기화 완료를 혼동하지 않는다.

관련386시험과 실제 격리 HTTP21검사, 브라우저 및 실제 별도 Android APK의 요약·상세·번호 입력창을 확인했다. 최종 시험 수·실행 근거는 [r117 변경 기록](../../../../Changes/2026-10-24-mobile-work-detail-contacts-r117.md)을 따른다. 초기 실행 종료의 기존 미해결 항목은 이번 기능 시험만으로 해결됐다고 표시하지 않는다.
