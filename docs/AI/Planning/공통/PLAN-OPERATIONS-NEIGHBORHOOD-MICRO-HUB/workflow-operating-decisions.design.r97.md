## 수용한 방향과 대상 확인

입주자가 공동주택 내 운영 공간의 유상 업무에 참여하고, 실제 활동에서 나온 보수·기여가 관리비 부담 완화로 이어지게 하는 방향을 수용한다. 입주자는 구매자만이 아니라 가능한 업무를 선택·수락하는 작업자로 참여할 수 있다. 업무 등록·담당 수락·사전 합의 단가·실적 확인은 기존 활동 보수 구조를 검토해 연결한다.

‘관리비 산입’은 관리비 부담을 줄이려는 목적 표현으로 기록한다. 대상 확인 질문 `resident-work-contribution-maintenance-beneficiary`에 사용자가 두 경로를 함께 두되 개인 보수와 단지 공동기여금을 구분하는 것으로 답했다. 상태는 `Answered / BothPersonalAndCommunityAccepted`다. 개인의 관리비 납부와 단지 전체의 관리비 지원을 함께 기획한다. 관리비에 새 비용을 부과한다거나 법정 회계 계정·자동 상계·강제 공제 방식까지 확정한 뜻으로 해석하지 않는다.

r96의 `resident-price-seller-authority-and-self-collection`과 r95의 상품 열람 범위 질문은 미정으로 보존한다. 이번 답변은 입주자의 유상 업무와 관리비 부담 완화에 관한 추가 방향이다.

## 두 가지 연결안

| 구분 | 금액의 출처와 귀속 | 관리비와의 연결 제안 |
| --- | --- | --- |
| 개인 활동 보수 | 실제 입고·피킹·포장·인계 등을 수행한 본인의 합의 보수 | 본인에게 지급된 보수 중 본인이 선택한 금액을 본인 세대 관리비 납부에 사용 |
| 단지 공동기여금 | 단지에 귀속되기로 합의한 공간 제공 대가·확정 공동 성과금 등 | 관리주체와 정한 용도·절차에 따라 공동 관리비 부담 완화에 사용 |

두 경로를 함께 두는 방향은 수용됐지만 기본값·금액·비율은 미정이다. 개인에게 귀속된 작업 보수를 공간을 제공했다는 이유로 자동 공동기여금으로 바꾸지 않는다. 공동 공간의 수익과 개인이 소유·제공한 공간의 수익도 구분하며 개인 공간 수익이 자동으로 단지 공동재원이 되지 않는다.

공동재원의 후보는 해당 공간을 사용할 권한과 단지 귀속 합의가 확인된 수익, 그리고 아직 개인에게 확정 배분되지 않은 공동 잉여금 중 사전 합의한 몫으로 한정하는 제안이다. 이미 개인에게 확정된 성과금을 다시 공동기여금으로 계산하지 않는다.

본인 구매 상품을 스스로 가져가는 자가 피킹은 다른 사람의 주문을 처리한 유상 피킹 업무와 구별한다. 실제 유상 업무를 맡고 완료한 기록이 있어야 그 업무의 보수를 연결한다. 같은 작업을 개인 보수와 공동기여금으로 두 번 발생시키지 않는다.

## 업무 시작부터 관리비 반영까지의 제안

```text
실제 주문·입고·운영 업무와 지급 재원
└─ 업무 범위·단가·담당·완료 조건 확인
   └─ 입주자 수락 → 작업 수행 → 수량·필요 증빙 확인
      └─ 기존 원장에서 본인 보수 발생·금액 확인
         ├─ 개인 보수 지급 → 본인이 선택한 관리비 납부
         │  └─ 관리주체의 납부·반영 결과 확인
         └─ 별도로 합의된 단지 공동재원 확정
            └─ 관리주체의 사용·관리비 반영 결과 확인
```

입고·보관 보수와 출고·배송 보수의 완료·지급 조건은 기존 전문 원장을 따른다. 새 관리비 사용 경로 때문에 기존 정산 관문을 건너뛰거나 확정 보수를 모든 판매 종료까지 새로 보류하지 않는다. 기존 신고·보류·복구 정책은 유지한다.

처음에는 **개인 보수를 지급한 뒤 본인이 관리비에 자율 납부하는 방식**을 우선 검토할 제안으로 둔다. 관리비 직접 대납·차감은 당사자 동의뿐 아니라 적용 계약·관리규약·임금 지급 등 검토가 필요한 후속 방식이다. 단지 연계가 없거나 처리 실패하면 이미 지급한 보수나 근거를 없애지 않고 미반영 사유와 다음 담당을 표시한다. 관리비 처리 실패를 업무 미완료나 임금 지급 보류로 바꾸지 않는다.

‘보수 발생’, ‘정산 확정’, ‘본인 지급’, ‘관리비 납부’, ‘관리주체 반영’은 별도 결과다. 신청만으로 관리비 납부 완료라고 표시하지 않는다. 불명확한 납부 응답은 같은 요청 결과를 먼저 조회하고 중복 납부·중복 반영을 만들지 않는다.

## 기존 원장을 활용할 연결 정보

새 주문·작업 보수 원장을 중복 만들기보다 기존 원주문/입고 Lot·활동 완료 근거·보수 항목·지급 근거를 참조하는 방향이다. 후속 관리비 사용 기록은 귀속 주체, 선택한 사용액, 대상 단지·본인 세대·청구 월, 처리 요청 식별값, 실제 납부/반영 근거와 실패·조정 이력을 구분하는 안이다. 실제 DB 설계나 관리사무소 연동 API가 이미 있다는 주장은 아니다.

같은 돈이 개인 지급·관리비 납부·단지 공동재원·지역 공동기금에 중복 귀속되지 않게 출처와 사용액을 대조한다. r61 원가 배부는 다시 지급할 채무가 아니며, 관리비 사용도 새 업무 보수 발생이 아니다. 지역 기금에서 단지로 실제 이전한다면 원천 잔액과 도착 잔액을 같은 이전 근거로 연결하는 후속 설계가 필요하다.

주민 화면은 본인의 업무·확정 보수·지급·본인이 선택한 관리비 사용·실제 반영 결과를 우선 보여주는 제안이다. 관리주체는 필요한 납부·공동재원 근거만 확인하고, 다른 주민에게 개인 작업자의 상세 보수·세대 정보·고객 주문정보를 공개하지 않는다. 세입자·소유자 등 실제 청구 대상과 본인 권한도 후속 확인 대상이다.

## 조사 근거와 적용 한계

2026-10-15 공개 공식 자료를 확인했다. 아래는 설계 시 구분할 근거이며 특정 단지에서 이 운영을 승인했거나 모든 관리비 차감이 허용된다는 법률 판단이 아니다.

- [공동주택관리법 제23조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0023&lsiSeq=284009&urlMode=lsScJoRltInfoR): 의무관리대상 공동주택 관리비의 납부 상대는 관리주체다. 플랫폼 기록만으로 그 관리비 채무가 소멸했다고 표시하지 않는 설계의 근거다.
- [공동주택관리법 시행령 제19조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0019&lsiSeq=287261&urlMode=lsScJoRltInfoR): 관리규약준칙의 사항에는 세대별 부담액·징수/사용 절차, 회계관리, 관리 등으로 발생한 수입의 용도와 사용 절차가 포함된다. 따라서 실제 단지의 관리규약·관리주체와 별도로 맞춰야 한다는 설계상 판단이다.
- [근로기준법 제43조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0043&lsiSeq=285279&urlMode=lsScJoRltInfoR): 근로관계에 해당하면 임금은 원칙적으로 본인에게 통화로 전액 지급해야 한다. 관리비 전용 적립이나 개인 동의만으로 임금 지급을 대체할 수 있다고 설계하지 않는다. 건별 보수라는 형식만으로 적용 여부를 판정하지 않는다.
- [K-apt 관리비 안내](https://www.k-apt.go.kr/apiinfo/apiComparativeSearch.do): 단지 잡수익 차감 전 공개 관리비와 실제 세대별 부과액이 다를 수 있음을 안내한다. 이를 개인 작업 보수를 잡수입으로 바꾸는 허가나 본 기획의 실제 운영 사례로 인용하지 않는다.
