입구/여권 표현은 문맥상 입고/여건으로 정리하며 원문을 보존한다. 공간은 ‘제공 가능한 공간’으로 기록한다. 이번 발화를 모든 공간의 무료 제공·무상 계약 확정으로 해석하지 않는다.

## 확정한 답변과 방향

- 질문 의미 ID: `first-inbound-planned-split-deliveries`
- 이전 상태: r93의 `Asked / Unanswered`
- 현재 상태: `Answered / PlannedSplitDeliveryAccepted`

회차별 날짜·수량·조건을 합의해 나눠 입고하는 방식을 허용한다. 전체 물량이 준비될 때까지 일률적으로 기다리게 하거나 분할 납품 자체를 금지하지 않는다. 기존 부분 수령 사실과 계획된 분할 납품 약속을 구분하고 회차별 실제 수량·입고 근거를 남긴다.

운영자가 건마다 일정을 정하고 배정하는 방식 대신, 업체가 지도에서 제공 가능한 공간을 찾아 **직접 입고 신청**하는 여건을 우선 제공한다. 공간 제공자가 품목·수량·일정·보관 조건을 검토하여 합의하면 예약·실입고로 이어진다. 일반 신청마다 운영자 사전 승인을 공통 단계로 두지 않는다.

시간이 흐르며 쌓인 실제 입출고 기록을 바탕으로 AI가 적합한 공간·상품·물량·시기를 추천하고, 당사자가 활용하는 방향도 수용한다. 추천의 세부 목표·점수·학습 방식·실행 권한까지 이번 답변에서 확정하지는 않는다.

## 직접 이용이 기본인 업무 흐름

```text
공간 제공자: 제공 기간·용량·허용 상품·업무·약정 조건 등록
└─ 업체: 지도 탐색 → 직접 입고 신청 [분할 가능]
   └─ 공간 제공자: 수락·수정 협의·거절
      └─ 양측 조건 합의 → 회차별 예약 → 실제 입고 확인
         └─ 보관·주문·피킹·출고·배송 기록 축적
            └─ AI 추천 → 당사자 채택/수정/무시 → 다음 입고 신청·변경 협의
```

AI 추천을 기다려야만 신청할 수 있는 구조로 만들지 않는다. 운영자의 매건 승인과 공간 제공자의 당사자 동의는 다르며 후자는 기존 r63대로 유지한다. 서버의 유효 계약·현재 판본·수용 조건·기간·용량·권한 검사는 당사자 자율 신청에서도 유지할 업무 조건이다.

분할 납품 허용은 반복 입고를 무조건 자동 승인한다는 뜻이 아니다. 반복 자동 허용은 r62의 별도 합의 상품·수량·시간·한도에 관한 미정 선택 사항으로 남긴다. 추천이나 지도 선택만으로 기존 예약·가격·기금 출연·보수를 바꾸지 않는다.

## AI 추천을 위한 실적과 설명의 제안

| 확인할 자료 | 추천에 사용할 목적 |
| --- | --- |
| 공간 제공 기간·취급 조건·현재 재고·확정 예약 | 실제 여력과 종료 전 회수 가능성을 대조 |
| 공급 준비·순회 납품 가능 일정 | 실행 가능한 입고 시기와 회차 후보 제안 |
| 실제 상품별 입고·판매/주문·출고 수량과 시점 | 출고 속도·남은 재고를 근거로 다음 물량 검토 |
| 합의 비용·실제 처리 비용·회수/지연 이력 | 빠른 입고뿐 아니라 부담·잔여 위험도 비교 |

이 자료는 확인된 원장 기록과 관측 기간·단위·갱신 시점을 연결하는 설계안이다. 실제 판매가 확인되지 않은 주문·출고를 매출이나 수요로 대신 확정하지 않는다. 자료가 적거나 신규 상품이면 그 한계를 표시하고 임의의 판매 실적·수익·수요를 만들어 채우지 않는다. AI의 예측과 확인된 사실은 구분한다.

추천에는 대상 공간/상품·제안 수량/시기·근거·부족한 자료를 이해할 수 있게 보여주는 안이다. 당사자는 채택·수정·무시할 수 있고 실제 변경은 기존 조건 합의·예약 절차를 거친다. AI가 계약·입고·재고·보수·공동기금 분배를 독자적으로 확정하는 권한은 추가하지 않는다. 실제 학습·모델 실행·성능 검증을 이번 기획 기록으로 완료했다고 주장하지 않는다.
