# 공통 운영 알림·월 50만 원 운영 준비 r45

사용자의 구현 승인에 따라 운영자가 문제를 알아차리고 기존 업무 화면에서 조치할 수 있는 경로를 추가한다. 운영자는 당초 한 명이며 배송 참여를 겸할 수 있다. 이번 범위는 로컬 검증, 운영자 APK, Azure 설정 준비다. 실제 유료 리소스 생성·외부 발송·휴대폰 설치는 하지 않는다. r44 회원 배송 P0 보완은 별도 후속이며 이번 완료 주장에 포함하지 않는다.

## 관찰과 처리

- `OperationsAlerts.Enabled`와 외부 발송은 각각 기본 OFF. 30초 주기로 최근/활성 원장을 keyset 페이지로 제한 조회한다. 페이지/커서는 MySQL에 저장하며 실패한 조회의 누락을 해결로 간주하지 않는다.
- 새 거래 분쟁·개인정보 사고 접수, 픽업 이후 회원 배송 중단, 배차 원장 누락/연결 불일치는 긴급이다. 원문을 분석해 미수령·미지급을 추정하지 않는다.
- 음식은 최신 수행 시도의 픽업 후 중단을 관찰하고, 화물은 기존 현장 사건의 진행 불가/전체 보류를 긴급으로 분류한다. 처리 결정 뒤 알림 해결을 반영하되 운송·사건 자체를 수정하지 않는다. 화물/회원 알림은 기존 운송 관제로 이동하며 음식/지원은 해당 상세로 연결한다.
- 사진 업로드 10분 지연, 원장 동기화 10분 지연, 제안 시간 경과, 알림 재시도 소진, 기존 음식 운영 추적의 업무 지연은 오전 9시 KST 요약 대상이다. 개인정보 권리 요청은 기록된 실제 기한 경과만 경고한다.
- 같은 문제의 같은 발생 회차는 한 알림이다. 해결 뒤 재발·긴급 격상은 새 회차로 만든다. 첫 가동 때 기존 미해결은 일괄 알림 한 번이며 신규 발생과 구별한다.
- 알림 확인은 재알림만 멈춘다. 원주문·배송·지원 사건·수령·입금 상태는 변경하지 않는다. 해결은 원장을 다시 읽어 확인한다. 긴급은 미확인 15분 후 한 번 재알림, 이후 일일 요약에 남긴다.
- 채널별 원장은 MySQL outbox로 기록한다. 성공/설정 필요/실패/재시도/생략을 구별한다. 외부 응답 유실에 따른 중복 가능성이 있는 at-least-once 방식이며 정확히 한 번 실제 수신을 보장하지 않는다.

## 페이지 책임

[페이지·코드·DB 책임](../../../../ProjectOverview/page-docs/operations-alerts-r45.md)을 따른다. 목록은 상태별 탐색, 상세는 해당 업무 이동과 알림 확인만 담당한다. 인증 계정 변경 시 늦게 온 이전 계정 응답을 버린다. 오래된 원장 확인과 조회 실패에서는 확인 버튼을 비활성화한다.

알림/메일에는 일반 문구·알림 ID·시각·로그인 후 열 링크만 넣는다. 주소·연락처·사진·사건 요약·예외 원문은 넣지 않는다. 운영자 ID를 설정한 뒤에도 발송 직전 서버관리자 역할과 활성 관리자 앱 설치를 다시 확인한다. 앱 키 등록만으로 권한이 생기지 않는다.

## 운영 비용과 외부 장애

월 500,000원은 기사 배송비/거래대금과 분리한 서버·저장·알림 예산이다. 서버/DB 120,000, 디스크/IP/네트워크 50,000, 사진/백업 50,000, 모니터/로그/메일 30,000, 지도/API 50,000, 예비 200,000원이다. 정상 목표는 300,000원이며 견적 또는 자동 지출 상한이 아니다.

Korea Central D2as_v5 Linux 단일 VM 제안과 기존 Compose를 재사용한다. Azure 청구 통화에서 400,000원 상당 예산을 80/90/100% 실사용 및 100% 예측에 메일로 알린다. 외부 API·예비 쿼터 100,000원은 별도 관리한다. Azure budget은 지출을 자동 중단하지 않는다.

`/health/live`, `/health/ready`를 아시아 3개 위치에서 5분 주기로 검사하고 2곳 이상 실패 시 Azure 자체 메일을 보낸다. CPU·디스크·heartbeat·백업 누락도 독립 감시 설정을 준비한다. 앱 서버 중단 시 앱 자체 푸시를 보장하지 않는다. 구성 활성화·실제 수신은 배포 후 검증 사항이다.

암호화된 off-VM 백업은 일별 7일/주별 4주를 목표로 한다. MySQL와 Mongo dump는 각각의 snapshot이며 분산 DB 전체의 원자 snapshot은 아니다. 보호 키/인증서/사진 저장소를 별도 복구할 수 있어야 완전한 복구다. 복구 절차는 운영 DB를 자동 덮어쓰지 않는다.

일일 예산 제한은 선택적인 서버 경로 견적만 차단한다. 수행 중인 업무와 증빙 사진은 중단하지 않고 사용량 경고를 남긴다. 네이티브 지도 SDK와 모든 외부 비용을 통제하는 기능은 아니며, 실제 사용량·단가를 관찰해 quota를 조정한다. [배포 준비](../../../../../deploy/azure-vm/operations-alerts/README.md)에 비밀 설정·AMA·복구·활성화 조건을 연결한다.

## 검증과 후속

[변경·검증 기록](../../../../Changes/2026-10-09-operations-alerts-r45.md)에 실행 결과를 갱신한다. 실제 Firebase 프로젝트/관리자 Android 등록, SMTP 앱 비밀번호·운영자 ID·수신 메일, 공개 HTTPS 도메인, Azure 로그인/청구 통화 확인, 외부 감시와 실제 백업 복구 시험은 활성화 전 필요하다. 비밀값은 Git에 넣지 않는다. 전 역할/모든 예외 감시가 완전하다는 주장은 하지 않는다.
