# 공동주택 거점 사전 문의·행정서식 초안 제안 r49

- 기획 ID: `PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB`
- 확인일: 2026-10-10
- 상태: `SourceReviewed / ProposedDesign / ImplementationApprovalPending / SubmissionDeferred`
- 관계: [아파트 적용 검토 r48](apartment-shared-space.review.r48.md)의 행정 절차 준비를 구체화한다. r48의 상세 정책과 첫 현장 사례는 아직 제안이며, 기존 r30/r31/r32 및 r47의 승인·구현을 변경하지 않는다.

## 결론과 이번 범위

모든 작은 보관 공간에 일률적으로 관공서 허가가 필요하다고 단정하지 않는다. 대상 공간의 승인 용도·공용/전용 구분·예정 업무·설비나 구조 변경에 따라 확인할 절차가 달라진다. 관리업체의 참여, 주민 의결·동의, 행정상 허가·신고, 실제 운영 개시는 서로 다른 근거다.

첫 준비물은 **관할 기관에 필요한 절차를 확인하는 사전 문의서 초안**이다. 기관이 절차와 적용 서식을 확인해 준 뒤 공식 신청서·신고서 채움을 준비한다. 신청자가 작성하는 서류와 기관이 발급하는 허가 결과를 혼동하지 않는다. 이 문서는 법적 적합성 판정이나 행정 승인 자체가 아니다.

이번에는 공식 출처·서식 항목·현재 재사용 코드를 조사하고 [사전 문의서 템플릿](administrative-preconsultation.template.r49.md)을 남긴다. 제품 작성기, HWP/PDF 자동 채움, 이메일 발송, 민원 접수, DB 저장 기능은 구현하지 않는다.

## 제안하는 절차와 첫 구현 범위

1. 기존 공간·보관 자료를 읽고 사용자 확인값/원장 참조값/누락값을 구별한다.
2. 공식 기관·서식의 출처, 확인일, 판본을 대조한다. 실제 파일을 가져오는 단계에서는 파일 hash도 기록하고 새 판본이면 기존 매핑을 재검토한다.
3. 사전 문의문, 운영 설명, 문의할 질문, 보유/미보유 첨부 목록을 검토용 초안으로 만든다. 확인되지 않은 법적 행위 구분은 체크하지 않는다.
4. 사용자가 내용·수신처·개인정보·첨부를 확인한다. 첫 구현에서는 복사/내려받기 후 사용자가 직접 문의·접수하는 방식까지를 제안한다.
5. 실제 발송 증거, 기관 접수번호·접수증, 회신 원본을 별개로 연결한다. 회신의 범위·조건·날짜와 대상 구획을 대조하며 문의 회신만으로 영업 가능 상태로 바꾸지 않는다.
6. 필요한 신청 종류와 최신 서식이 확인되면 공식 서식 채움 Adapter를 별도 승인 범위로 구현한다. 신청인 서명·주민 동의·전문 도면·기관 허가서는 만들어내지 않는다.

초안 생성, 사람 검토, 발송, 접수, 회신, 허가/신고 결과, 플랫폼 운영 검토는 독립 상태다. 생성 실패는 원문 입력을 보존해 재시도할 수 있어야 한다. 발송/접수 응답이 불확실하면 정본·접수 여부를 먼저 확인하고 자동 재전송하지 않는다. 외부효과·운영 활성화는 기본 OFF를 유지한다.

첫 제품 구현 후보는 **기존 공간 한 곳에 대한 사전 문의 초안 미리보기**다. 출력·누락 문답·권한·출처 revision·개인정보 마스킹·문자 이스케이프·동일 입력 재생성을 시험한다. 자동 이메일, 공식 민원 제출, 법적 적합성 판정, 신청서 원본 서식 채움은 이 첫 범위에 포함하지 않는다. 구현 전 별도 승인·writePaths·검증 범위를 결속한다.

## 확정·미정·다음 질문

- 확정: 공식 서식의 존재와 작성 항목을 참고하고, 먼저 사전 문의 초안을 준비한다. 모르는 항목은 문답으로 채운다. 초안이 허가·동의·접수 결과를 대신하지 않는다.
- 미정: 첫 실제 공간, 정확한 관할 부서와 연락 경로, 적용 행위/서식, 현장·권한·동의 자료, 제품 구현 승인. r48의 현장 운영 정책은 승인된 것으로 확대하지 않는다.
- 다음 질문 하나: 실제 협의 중인 아파트를 첫 대상으로 할지, 아직 없다면 중랑구를 기준으로 공통 사전 문의 양식부터 준비할지 확인한다.

## 이번 검증과 제외

공식 웹 조문·서식 안내·PDF 텍스트와 좁은 기존 소스를 대조했다. 문서 링크·공백 검사는 수행 결과를 `CURRENT_WORK.md`에 남긴다. PDF 시각 검증·서식 자동 채움·제품 build/업무 시험·DB·관공서 연락/접수·단말·Unity·실제 운영·commit/push·배포는 수행하지 않는다.
