## 확정한 답변

- 질문 의미 ID: `unconfirmed-receipt-earned-work-release`
- 이전 상태: r77의 `Asked / Unanswered`
- 현재 상태: `Answered / AcceptedDirection`
- 사용자 답변 원문: **“일단 물품 전달 증빙이 있고 지급 재원이 있으면은 그 정산을 해주는 게 맞다고 생각해 나는.”**

피킹·포장을 거쳐 배송한 물품 주문에서 물품 전달 증빙과 해당 작업 보수의 지급 재원이 확인되면, 고객의 수령 확인 응답이 없다는 이유만으로 확인된 작업 보수를 계속 대기시키지 않고 별도 검토·정산할 수 있는 방향을 수용했다.

```text
물품 전달 증빙 확인 + 해당 작업 보수 지급 재원 확인
└─ 확인된 작업 보수의 정산 가능
   ├─ 고객 수령 응답 없음 → 수령 상태는 미확인으로 유지
   └─ 실제 미수령·파손 등 신고 있음 → 다음 문답에서 별도 정책 결정
```

기본 작업 보수의 발생·확인, 정산 가능한 상태, 지급 신고와 은행 입금은 서로 다른 사실이다. 지급 재원의 구체적인 확인 방법은 아직 미정이며, 예상 매출이나 지급 신고만으로 실제 사용 가능한 재원을 인증하지 않는다. 전달 증빙도 현재 원주문·물품·실제 수행과 연결해 확인할 대상이며 사진 파일의 존재만으로 모든 전달 사실이나 책임을 자동 확정하지 않는다.

## 기존 결정과의 관계

[r60](receiving-outbound.implementation.r60.md)의 출고 기본 보수 발생 및 고객 수령 뒤 정상 지급 경로를 보존한다. 이번 답변은 고객 무응답인 경우의 별도 작업 보수 정산 방향을 정한 것이다. 입고 독립 지급·원가 배부·고객 수령·공동 성과금·상품대금·반품/환불까지 같은 상태로 합치지 않는다.

기존 본인 주간 합산 기준도 유지한다. 이 답변은 즉시 자동 송금, 주간 지급일 변경, 고객 수령 자동 확정, 공동 성과금 자동 지급, 플랫폼이나 예비금의 전액 보상 승인이 아니다. r76에서 구현한 정상 지급 관문은 아직 그대로이며 r78의 예외 정책은 코드에 반영되지 않았다.

## 미정으로 남은 범위

- 인정할 전달 증빙과 재원 확인 방법, 확인 담당 및 처리 시간.
- 단순 무응답과 실제 미수령·누락·파손 등 문제 접수의 구분 및 보류 범위.
- 이의 제기·중복 지급 방지·이미 지급한 뒤 새 분쟁이 생긴 경우의 정정 절차.
- 재원 부족·추가 작업·취소·손실의 지급 책임과 예비금 사용 조건.
- r77의 나머지 운영 약속은 별도 문답 대상이며 일괄 승인되지 않았다.
