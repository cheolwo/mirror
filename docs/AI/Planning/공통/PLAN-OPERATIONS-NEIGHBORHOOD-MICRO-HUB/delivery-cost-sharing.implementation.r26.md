# 음식 배달 배송비 선택 옵션과 UI 개선 r26

- 기준일: 2026-10-07.
- 상태: `Implemented / LocalSimulationValidated / SimulationOnly / RealProviderPending`.
- 선행: [생활·음식 자동 수행처 선정 r25](fulfillment-routing.implementation.r25.md).
- 승인: 사용자가 네 가지 기본 방식, 매장 조건+주문자 상한, 음식점/주문자 우선, 전액 부담 한도 초과 후보 제외/보류를 선택한 뒤 구현을 요청했다.

## 음식점과 주문자의 설정

음식점은 `주문자 전액 부담 / 정액 지원 / 비율 분담 / 음식점 전액 부담`을 선택한다. 정액은 지원액, 비율은 음식점 부담률과 선택적 최대 지원액, 전액은 선택적 최대 부담액을 설정한다. 자동 배송 사용은 비용 부담 방식과 독립적이며 주문자 전액 부담도 자동 배송을 사용할 수 있다. 주문자는 자신의 잔여 부담 상한을 확인하며 조건이 맞을 때만 접수한다. 새 입력은 저장·동의 전까지 적용하지 않는다.

화면은 선택한 방식의 필드만 보여준다. 음식점 조건/본인 상한과 완료 기한/허용 처리처/정보 동의를 구별한다. 견적 전에는 정책과 명시된 계산 예시, 견적 후에는 총 배송비·음식점 부담·본인 부담을 표시한다. 상세 수식과 판본은 보조 정보로 둔다. [페이지 책임](../../../../ProjectOverview/page-docs/delivery-cost-sharing-r26.md)을 따른다.

## 배분과 실행

누적 확정 발생비용+새 수행 견적을 `C`로 계산한다. 주문자 전액은 고객=C, 정액 S는 음식점=min(S,C), 비율 p는 음식점=floor(C×p/100)에 선택적 음식점 한도를 적용하고 고객은 잔액이다. 음식점 전액은 음식점=C/고객=0이며 C가 선택한 한도를 넘으면 후보를 제외하고 적합 후보가 없으면 보류한다. 고객에게 초과분을 자동 전가하지 않는다. 음식점 정책의 정액 지원액·최대 부담 입력은 정수 원(0~1,000,000), 비율은 0~100 소수 둘째 자리까지다. 주문자의 최대 부담액과 누적 총비용 C에 이 정책 입력 상한을 적용하지 않는다.

선정과 조회는 같은 순수 배분 계산기를 사용한다. 최초 주문 동의에 정책 전체·설정 판본을 동결하고 재선정/동의 갱신마다 초기화하지 않는다. 음식점 설정 변경은 새 주문만 적용한다. 확정 비용 미확인·Unknown·취소 미확정·원천 종료·조리 이후 전환 제한과 현재 수행/판본/멱등 보호는 r25를 유지한다. 새 취소 수수료나 실제 청구/지급 정책을 만들지 않는다.

## 계약과 저장 호환

기존 설정·견적·상태의 `CostSharingPolicy`, 동의의 `ConfirmedCostSharingPolicy`는 nullable/null 직렬화 제외 추가다. `DeliveryCostSharingPolicy`는 Mode와 필요한 FixedAmountKrw/RestaurantSharePercent/MaximumRestaurantChargeKrw를 담는다. 고정 코드는 `CustomerPays / FixedContribution / PercentageShare / RestaurantPays`이며 기존 설정 판본을 재사용한다.

식당 설정과 최초 동의에 nullable 정책 JSON 열을 추가한다. 기존 null은 해당 row의 정액 S로 해석하며 기존 기간/ID/동결 지원액은 변경하지 않는다. 구형 요청은 기존 정액만 허용하고 비율/전액에는 정책 전체 확인을 요구한다. 설정·동의의 응답 유실은 원 정책/ID로 확인하며 mutable 객체는 복사해서 보존한다. 생활/화물 비용 분담은 이번에 켜지 않는다.

## 검증과 남은 경계

네 방식의 금액/상한/반올림, 재선정 누적 비용·정책 동결, 설정 판본/오래된 동의/구형 요청, 응답 유실 복구, 이전 정액/생활/배차/조리/PG 회귀를 확인한다. additive migration의 실제 SQLite 적용/MySQL SQL 생성과 해당 snapshot을 대조한다. 실제 공유 Razor의 320/390px·선택 필드·계산 예시·한도 보류·실패 복구를 확인하고 집중 시험→Fast→Task 및 소비 앱 빌드를 실행한다.
