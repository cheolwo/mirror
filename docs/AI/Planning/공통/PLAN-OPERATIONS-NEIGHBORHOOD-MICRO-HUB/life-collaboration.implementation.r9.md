# 지도에서 시작하는 생활 협업 r9

2026-10-05. 상태 `Approved / Implemented / ValidatedLocal / PublicDeploymentPending`. 사용자가 승인한 네 항목은 지도에서 신청→당사자 조건 확인→진행→완료, 내가 신청한 일/받은 요청·맡은 일, 간단한 보관 공간 등록, 당사자 완료·취소 이력과 별도 동의한 완료 공개 기록이다. 기존 r8 지도와 r7 생활 배송을 확장한다.

## 페이지 책임과 연결

| 화면 | 한 가지 목적 | 상태와 인계 |
| --- | --- | --- |
| `/community/map` | 원하는 동네의 글·보관 제공·내 진행 업무를 선택 | 핀은 검증된 동네 대표점. 작성과 수행은 독립 상세로 이동 |
| `/community/exchange/work` | 내가 신청한 일 또는 받은 요청·맡은 일을 골라 현재 상태 확인 | 로그인·빈 목록·실패·재조회, 계정 변경 시 이전 개인 내용 제거 |
| `/community/exchange/work/new` | 선택 글/공간에 조건을 적어 신청 | 인증 작성자/공간 소유자를 서버에서 확인. 공개 댓글로 합의하지 않음 |
| `/community/exchange/work/{id}` | 이 업무의 현재 단계에 필요한 행동 수행 | 조건 판본별 양측 확인, 진행·인계·수령 확인, 취소, 공개 기록 동의 분리 |
| `/community/exchange/spaces` | 가능한 물건·수량·시간으로 보관 공간 찾기 | 공개 동네·능력만 표시. 정확 주소·연락·인계 정보 없음 |
| `/community/exchange/spaces/new`·`/{id}` | 본인 보관 능력 등록 또는 한 공간의 신청/현재 예약 확인 | 제공 중단은 새 신청만 막으며 기존 인수·반환은 보존 |

상세 페이지의 기본/보조 정보, 실패 복귀와 상태별 주 행동은 [생활 협업 책임 카드](../../../../ProjectOverview/page-docs/neighborhood-collaboration-r1.md)에 연결한다. 전문 역할 앱을 제거하지 않고 같은 계정의 요청자·제공자·참여 관계를 업무별로 관리한다.

## 업무 원본과 권위

- 합의·완료는 보호된 Mongo 업무 원장에 저장한다. generic 공개 커뮤니티 원장이나 자동 완료글 투영에 개인 조건·참여자를 넣지 않는다. 기존 SQL 게시글은 선택 출처와 작성자 권한을 확인하는 데 사용한다.
- 명시적 신청마다 안정 ID, 요청 ID, 입력 지문, 기대 판본을 결속한다. 조건 변경은 이전 동의를 재사용하지 않는다. 한쪽 완료 제안과 상대 확인을 구별한다. 취소·만료·거절도 원 이력과 함께 남긴다.
- 실제 배송은 기존 음식/화물 원장과 기사 권한·배차 관문이 소유한다. 협업 참여나 보관 공간 등록은 전문 기사·창고 운영 권한을 생성하지 않는다. 생활 화물 등록과 협업 연결의 부분 성공은 원 운송 ID를 보존하여 확인·재연결하며 중복 접수를 숨기지 않는다.
- 보관 수량·기간의 겹침은 공간 원장에서 CAS로 판정한다. 예약·인수·반환은 별도 사건이며 협업 완료만으로 실제 반환을 대신하지 않는다. 등록한 공간을 비주거 Pilot로 자동 전환하지 않는다.
- 물품·음식·운송·보관의 공통 탐색과 당사자 협의는 같은 진입을 사용하되 실제 조리·운송·보관 수행 조건은 별도로 유지한다. 플랫폼 결제·은행 입금·실지급을 확인한 것으로 기록하지 않는다.

## 개인정보와 공개 기록

공개 지도는 동네만 표시한다. 정확 주소·연락처·인계 방법은 보호 저장/전송과 본인 또는 확인된 참여자의 별도 제공 동의로 제한한다. 종료·동의 철회·계정 변경·화면 이탈 시 불필요한 개인 정보 표시를 제거한다. 인증 주체·성별·국적·종교 등을 신뢰 점수나 참여 우선순위로 만들지 않는다.

완료 기록 공개는 완료 확인과 별개 동의다. 관련 당사자가 모두 동의한 경우에만 업무 종류·완료 일자 등 비식별 최소 기록을 공개하고, 주소·조건 원문·상대 이름·내부 계정 ID는 제외한다. 공개 동의 철회는 기록 노출을 중단하되 개인 업무 원장 자체를 소거하지 않는다.

## 검증과 단계

첫 검증은 책 한 상자의 신청·조건 확인·인계·수령 확인과 보관 한 상자의 시간/수량 예약·인수·반환이다. 권한, 판본 충돌, 중복 재송신, 늦은 응답, 다른 계정 재조회, 제공 중단·취소·반환 전 완료 차단을 시험한다. 실제 공유 UI→HTTP→SQL 출처/Mongo 원장과 모바일 화면을 대조하고 전체 Task 시험을 실행한다.

실제 외부 경로·기사 자동 배차·개인 휴대폰·Azure 공개 운영·운영 입금과 Figma 대응은 별도 실행 증거다. 로컬 구현·시험·화면·APK 준비는 완료했고 실행 근거와 남은 운영 검증을 변경 기록에 연결한다. 기존 unrelated dirty 변경과 r6/r7/r8 검증 이력은 보존한다.
