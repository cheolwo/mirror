# 통합 원장·시작 보류·정산 흐름 r119

기준일: 2026-10-24. 상태: `Implemented / FocusedTestsPassed / HttpValidated / DeviceFunctionsValidated / ColdStartStabilityUnresolved`.

[r117](mobile-work-detail-contacts.implementation.r117.md)의 독립 업무 상세와 r118 연결선을 유지한다. [페이지 책임](../../../../ProjectOverview/page-docs/community-space-cooperation-r104.md)을 먼저 보완했으며 이번 범위는 현재 허용된 조회 자료를 이용한 시각화다.

## 표현과 권위

- 통합 원장 → 선택 회차 → 생산·입고·보관 / 주문 → 피킹·출고 → 배송·정산을 묶는다. 선은 절차 안내이며 실제 실행·완료나 선행 작업의 충족을 대신하지 않는다.
- 서버 점검에 실제 점검한 `CycleId`, `CycleTermsRevision`, `AsOfUtc`와 구조화된 `Issues`를 추가한다. 기존 `Blockers` 문구·순서와 `CanStart`/`CanComplete` 판정·명령은 보존한다.
- 같은 회차·조건 판본의 점검과 보류 문구의 1:1 일치를 확인한 경우만 시작 조건에 쓴다. 과거 회차·누락/잘못된 점검은 미확인으로 둔다. 시작 전 회차에만 시작 보류를 적용한다.
- 부모 판본이 같아도 전문 원천은 별도로 바뀔 수 있다. 상세 점검과 뒤의 통합 조회에서 선택 회차의 원천 키·확인/주의/완료 상태·상태 코드가 다르거나 조회 시각이 역전되면 점검을 미확인으로 내린다. 화면 확인과 실제 시작 사이의 경합은 기존 서버 명령에서 다시 점검한다.
- `cooperation`, `cycle`, `required-appointment` 범위는 회차 전체에서 표시한다. 부족한 역할 수락은 모임 참여 조건이며 특정 단계의 실제 담당 배정이 아니다. 한국어 사유를 키워드로 해석해 단계에 붙이지 않는다.
- `source` 범위 중 서버가 명시한 입고·보관·주문 문제만 해당 노드에 표시한다. 자료 연결·재확인과 단계 완료는 구분한다.
- 원 주문이 생성되지 않은 당사자 협의는 `주문 협의 연결`로 표시하며 전문 원장 연결로 부르지 않는다. 주문 조회 실패는 0건이 아닌 재확인으로 표시한다.
- 정산 원천의 완료는 기존 전문 bridge의 지급 준비 근거다. 실입금·개인 순이익·플랫폼 이익은 현재 조회에 연결되지 않아 숫자로 추정하거나 0원으로 표시하지 않는다. 원 정산 상세에서 확인하도록 안내한다.
- 이번 결과에서 다음 회차 준비로 이어지는 점선은 검토 안내다. 같은 회차의 되먹임 연결·다음 회차 생성·시작 명령을 만들지 않는다.

## 검증 계획

현재 회차/다른 회차·판본·보류 순서·역할과 단계 구분·준비/진행/마침·원천 재확인·정산 지급 준비 경계를 회귀시험한다. 별도 가상 계정·격리 원장·전문 실행 차단 서버에서 모바일 화면과 상세 이동을 확인한다. 브라우저 렌더·APK 빌드·실제 기기 화면·운영 데이터/실지급은 각각 기록한다. 기존 원장·미확정 요청·연락처 권한은 보존한다.

관련 시험 440건(기존 386 + 새 서버 10 + 새 표시 44)은 실패·건너뜀 없이 통과했다. 실제 보호 Mongo/SQLite 격리 호스트의 typed 상세→통합 HTTP 조회를 이용한 27개 확인도 통과했다. 기존 두 시험 원장의 판본 16/1과 새 시험 원장 1은 조회 뒤에도 같고, 로그인 외 요청은 GET뿐이다. 실제 운영 DB·업무 명령·정산·전화·배포는 실행하지 않았다.

390px 브라우저에서 회차 보류·입고/보관/주문 표시·독립 상세 왕복·정산/다음 회차 안내를 확인했다. 넓은 화면의 카드 높이도 일치시키고 기존 SVG 연결선과 가로 넘침 없음을 실제 렌더로 확인했다. 별도 Debug APK 0.1.119의 서명·정렬·메타데이터와 데이터 보존 갱신 설치를 확인하고, 실제 Samsung SM-A346N / Android 16에서 보류 펼치기·상세 왕복·정산 상세 이동을 확인했다. 정산 항목명을 한 줄로 읽도록 보정한 최종 APK에서도 지급 준비·실제 지급·이익과 다음 회차 안내를 재확인했다. 항목의 설명은 너비에 맞게 줄바꿈된다. 운영 서버 재시작으로 만료된 가상 세션은 기존 계정의 로그아웃과 일반 로그인으로 갱신했으며 앱 데이터를 초기화하지 않았다. 원래 통합 앱 0.1.230은 유지했다.

공통 Fast/Task는 기존 다른 파일 `CargoDriverWorkSession.cs:245`의 끝 공백 때문에 빌드 전에 중단됐다. 이번 범위 공백·문서 링크 검사는 별도로 통과했다. 기존 초기 실행 안정성과 Figma 읽기 전용 Pending은 해결됐다고 표시하지 않는다. 이번 갱신 실행과 전체 기기 안정성은 별개다.

화면·증거의 최신 요약은 [r119 변경 기록](../../../../Changes/2026-10-24-workflow-readiness-settlement-r119.md), 작업 증거는 `artifacts/local/integrated-cooperation/20261024-r119/`에 둔다.

## r120 — 동작을 유지한 내부 정리

2026-10-24 사용자의 “새 구현 없이 리팩토링만” 요청을 따른다. 기존 두 Razor 화면의 동작 블록을 각각의 partial code-behind로 이동하고 흐름 표시 계산을 회차 점검·개별 단계·정산 요약의 순수 helper로 나눈다. 공개 모델·메서드·문구·DOM·CSS·route·수명주기·선택·연락처 확인과 기존 서버/계약/업무 명령을 유지한다. 새로운 기능이나 화면은 만들지 않는다.

상태: `Refactored / ExistingRegressionTestsPassed / ConsumerBrowserValidated`. 두 화면의 원래 템플릿과 동작 본문은 분리 전후 동일 해시로 대조했다. 공용 UI 빌드 오류 0·기존 경고 1, 소비 호스트 오류/경고 0이며 기존 관련 회귀시험 440건을 실패·건너뜀 없이 다시 통과했다. 기존 HTTP 확인 도구를 새 공용 UI 사본과 연결해 27개 읽기 검사를 다시 통과했다. 새 시험·기능·서버 계약을 추가하지 않았다.

390px 브라우저의 보완 사유 5개 펼치기, 입고 상세와 동일 회차 복귀, 정산 상세 이동을 새 소비 호스트에서 확인했다. CSS·서버·계약·업무 상세 ViewModel을 그대로 유지했고 기존 시험 원장의 판본 16/1/1도 변하지 않았다. 이번에는 새 APK 빌드·설치나 휴대폰 실행은 하지 않았으며 r119 기기 증거는 그 판본의 기록으로 보존했다. 공통 Fast/Task는 기존 별도 `CargoDriverWorkSession.cs:245` 끝 공백 때문에 중단됐고 이번 범위 공백·링크 검사는 별도로 통과했다.

이번 증거는 `artifacts/local/integrated-cooperation/20261024-r120/`에 별도로 둔다. 내부 정리로 화면 구조·권한·업무 수행·지급·새 매칭이나 현장 참여 기능이 변경됐다고 표시하지 않는다.
