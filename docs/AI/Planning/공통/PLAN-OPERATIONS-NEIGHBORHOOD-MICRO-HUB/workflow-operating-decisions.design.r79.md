## 확정한 답변

- 질문 의미 ID: `reported-delivery-issue-payment-scope`
- 이전 상태: r78의 `Asked / Unanswered`
- 현재 상태: `Answered / HoldAccepted / PartialReleaseUnresolved`
- 사용자 답변 원문: **“일단 고객이 신고하면은 정산이 보류가 되는 게 맞지.”**

고객이 해당 물품 주문의 미수령·누락·파손 등 실제 문제를 신고하면 정산을 보류하는 방향을 수용했다. 전달 증빙과 지급 재원이 있더라도, 문제 신고가 있으면 고객 무응답과 같은 정상 정산 대상으로 처리하지 않는다.

r78의 ‘문제 관련 금액만 보류하고 나머지 작업비를 선지급’ 제안까지 승인한 것으로 기록하지 않는다. 우선 해당 주문의 미지급 정산을 보류하는 방향으로 정리하고, 항목별 부분 해제·지급 범위는 미정으로 남긴다. 다른 독립 주문이나 주간 전체를 동결하는 정책까지 확대하지 않는다.

```text
물품 전달 증빙·해당 작업 보수 지급 재원 확인
├─ 실제 문제 신고 없음 → 확인된 작업 보수 정산 가능 [r78]
│  └─ 고객 수령 응답 없음 → 수령 상태는 미확인으로 유지
└─ 고객 미수령·누락·파손 신고 → 해당 주문의 미지급 정산 보류 [r79]
   └─ 해결 근거·해제 담당·판정 기준 → 다음 문답
```

보류는 실제 수행 기록·발생액·약정 단가·증빙을 삭제하거나 0원으로 바꾸는 것이 아니다. 미지급 정산의 진행을 멈추고 신고·검토 이력을 별도로 남기는 방향이다. 고객 신고만으로 책임자·미전달·환불·손실 부담을 확정하지 않는다. 이미 지급한 뒤의 신고, 지급 회수·환불·수령 확정은 별도 정책이며 이번 답변에 포함되지 않는다.

## 기존 결정과의 관계

r78의 전달 증빙·재원 기반 정산 원칙에 실제 문제 신고의 보류 분기를 추가한다. 기존 보수 발생/지급 구분, 입고/출고 분리, 본인 주간 합산과 실제 은행 입금의 구분은 유지한다. 부분 지급을 자동 허용하거나 기존 보류를 무시해 지급하는 정책은 확정하지 않았다.

r76의 전문 원장 보류·마트 수령 해결·지원 검토 보호와 혼동하지 않는다. 기존 구현은 그대로이며 r78/r79의 새 예외 정산·해제 결정 경로를 구현 완료로 표시하지 않는다. 실제 신고 유형별 영향 범위와 기존 금융·재고·배송 보류의 해제 조건은 별도 구현 전에 대조해야 한다.
