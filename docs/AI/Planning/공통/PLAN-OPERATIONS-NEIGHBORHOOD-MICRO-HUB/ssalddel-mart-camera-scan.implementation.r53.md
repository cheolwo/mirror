## 페이지 책임과 절차

기존 `/workspace/warehouse/ssalddel-mart-sample`의 질문은 “지금 찾을 상품의 선반을 확인했는가?”다. 진행 중 품목에서만 `카메라로 코드 스캔`을 보조 입력으로 제공한다. 사용자가 버튼을 눌렀을 때만 카메라 권한을 요청한다. 후면 카메라를 우선 요청하며 QR와 Code128 중 브라우저가 지원하는 형식만 사용한다.

인식 → 현재 합성 선반 코드와 대조 → 입력칸 채움 → 상품명·수량 직접 확인 → 기존 피킹 완료의 순서다. 인식만으로 피킹·포장·인계·재고 변경을 확정하지 않는다. 다른 선반·상품·URL·과도한 길이의 값은 입력하지 않는다. URL 이동이나 외부 조회도 하지 않는다. 화면에는 현재 합성 선반의 QR·Code128 연습 표찰을 접어서 제공하고 기존 ZXing.Net 생성기를 재사용한다. 실제 상품의 바코드를 확보했다고 표현하지 않는다.

권한 거절·카메라 없음·브라우저 미지원·인식 실패·시간 초과는 짧은 안내와 직접 입력으로 복귀한다. 인식 후, 닫기, 주문·품목 전환, 표본 초기화, 화면 이탈, 백그라운드 전환, 연결 상실 시 카메라를 해제한다. 비동기 권한 요청·인식이 늦게 끝나도 이전 품목의 결과를 다음 품목에 적용하지 않는다. 카메라 영상·사진·잘못 읽은 원문·토큰을 파일/로그/저장소에 남기거나 서버로 보내지 않는다. 일치한 합성 코드만 기존 메모리 입력으로 전달한다.

## 실행 경계

현재 소비 화면은 loopback 전용 InteractiveServer 표본이다. LAN 공개·HTTPS 배포·MAUI WebView 권한 어댑터·Android APK 결속은 이번에 포함하지 않는다. 휴대폰 친화적 UI와 카메라 입력 구현, 브라우저 자동 시험, 실제 휴대폰 촬영은 서로 다른 증거다. PC의 가상 카메라나 모의 디코더 시험으로 실제 Android 지원을 주장하지 않는다.

브라우저 카메라는 보안 컨텍스트·사용자 권한이 필요하고 BarcodeDetector는 제한 지원이므로 런타임 기능 확인과 직접 입력을 필수로 유지한다. 출처: [MDN BarcodeDetector](https://developer.mozilla.org/en-US/docs/Web/API/BarcodeDetector), [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) (2026-10-10 확인).
