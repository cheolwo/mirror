# [기획 · 협업 비전과 객관적 성과 · PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB · r111]

기준일: 2026-10-24. 상태: `VisionAndCooperationDirectionAccepted / ProposedDesign / DensityIncomeEffectUnverified / ImplementationNotAuthorized`.

사용자는 사람들이 모여 생산·입고·작업·배송을 이어가며 생활과 소득이 나아지는 선순환을 만들고, 협업과 업무의 집적이 만드는 효과를 지속적으로 시각화·수치화하기를 원했다. 관계를 원만히 유지하고 서로의 피해를 줄일 절차와 비전 제시를 함께 요청했다. 이번에는 현재 소스를 바탕으로 제안만 기록하며 제품 코드·DB·HR·보수·신뢰·배차·Unity·외부 알림/공개는 변경하지 않는다. [HR 등록·업무 숙지 r110](hr-onboarding-work-schedule.design.r110.md)과 기존 기획/전문 권위를 보존한다.

## 1. 중심 비전과 검증할 가설

비전 문구의 제안은 **동네에서 함께 일하고, 함께 만든 가치를 확인하며, 각자의 생활을 더 안정적으로 만든다**다. 소개 문구만 반복하기보다 사람의 역할·업무 진행·확인된 결과·개인에게 돌아온 보수·다음 개선을 한 흐름으로 보여준다.

선순환의 가설은 다음과 같다.

`사람과 일감의 연결 → 이동·대기·중복 작업 감소 → 같은 조건에서의 처리 효율 개선 → 비용과 보상 근거 확인 → 합의된 개인 보상·공동 재투자 → 다음 참여와 운영 개선`.

밀집도 상승을 개인 소득 상승으로 단정하지 않는다. 수요·가격·근무시간·고정비·혼잡·과부하·반품 등의 변화가 함께 영향을 줄 수 있다. 사람 수·공간 수·매출이 늘어도 개인의 시간당 보수나 공동 성과가 줄어들 수 있으므로 확인된 기간·업무 조건의 수치를 비교한다. 등록 수와 실제 수행, 생산 예상과 입고, 작업 완료와 고객 수령, 보수 발생과 실제 지급을 구분한다.

## 2. 현재 재사용할 구조와 미연결

- [공동운영 회차](../../../../../Ssalddel/Services/Community/공간공동운영UseCase.cs)는 사람의 역할·조건·전문 원장 참조를 연결한다. [r110](hr-onboarding-work-schedule.design.r110.md)의 HR 안내/일정/신청은 아직 기획이다.
- [홈 집계](../../../../../Ssalddel/Application/Home/HomeParticipationAggregateQuery.cs)는 비모의 용달운송의 명확한 완료·의뢰·계정 결속만 집계한다. 전체 생산·입고·피킹 실적으로 확대하지 않으며 확정 플랫폼 이익·실분배 지급액은 정본 미연결로 null이다.
- [활동성과 배분](../../../../../Ssalddel.Domain/정산/활동성과배분Policy.cs)은 합의 가중치·실제 수행 근거·중복 방지를 갖지만 현재 경제 입력은 Simulation 당사자 진술이다. 계산 잔여금·예정 성과금을 확정 영업이익·실지급으로 표시하지 않는다.
- [수익 환원](../../../../../Ssalddel/Services/Settlement/PlatformProfitReturnService.cs)은 기록 수입과 입력 운영비로 추정 이익·예정 지급을 계산한다. 실제 현금 지급을 증명하지 않는다.
- [정산 이의](../../../../../Ssalddel/Application/Settlement/NeighborhoodSettlementUseCase.Entries.cs)와 [보호지원](../../../../../Ssalddel/Services/PrivacySupport/보호지원UseCase.cs)은 이의/증거 접수·검토·정정·당사자 확인·결과 안내·이의 재개를 구분한다. 신고만으로 귀책·자동 감액을 결정하는 기능이 아니다. 기존 거래 사건을 모든 HR 고충 접수로 확대하는 연결은 별도 설계가 필요하다.
- [신뢰 r107](trust-elevation.design.r107.md)은 구현 전 기획이며 신고만으로 감점하지 않고 공개 동의·배차와의 분리를 유지한다. 이번 비전을 근거로 신뢰 점수·배차 우선권·보수 감점 정책을 활성화하지 않는다.

## 3. 세 수준의 화면 제안

| 화면 | 사용자가 확인할 것 |
|---|---|
| 홈·참여 안내 | 왜 함께 일하는지, 전체 공급→입고→작업→배송 흐름에서 내 역할이 무엇인지, 동의한 집계 범위의 확인된 성과와 다음 참여 방법 |
| 비공개 작업공간/회차 현황 | 필요한/확정한/실제 수행 인력, 현재 담당과 다음 인계, 대기·막힘 사유, 처리량·재작업·확인 비용, 합의한 목표와 다음 개선 |
| 본인 HR·보수 | 숙지 기록·수락 일정·실제 수행/근무시간, 기본 보수·판매 성과 확인 대기·추가 보수 발생·지급 예정·수령 확인과 계산 근거 |

비전은 첫 등록·업무 안내·회차 결과에서 짧게 연결하고 항상 강제 알림으로 노출하지 않는다. 주간 결과에는 `함께 해결한 일 / 내 기여와 받은 보수 / 기다린 부분 / 다음에 바꿀 한 가지`를 제시한다. 참여자는 계속 참여·다른 역할·쉬기·철회를 선택할 수 있다. 성장 목표를 자동 할당량이나 초과 근무 압박으로 전환하지 않는다.

지도/Unity로 작업공간과 인계를 보여주는 것은 후속 표시 수단이다. 서버 정본의 준비·진행·보류·완료를 반영하며, 인물 배치·애니메이션이나 모의 경제를 실제 출근·완료·수익으로 해석하지 않는다. 개인 이름/연락처/관계망의 공개는 별도 동의 범위를 따른다.

## 4. 객관적 변화 지표

| 질문 | 제안 지표·해석 |
|---|---|
| 사람들이 실제로 함께 일하는가? | 등록·관심·수락·실제 수행 인원을 구분하고 같은 사람의 복수 역할 중복 제거. 시간대별 필요한 인력과 맡은 인력의 일치 정도 확인 |
| 협업이 편해졌는가? | 인계 대기·이동·재작업 수량과 시간, 정시 완료 비율. 기록 없는 시간은 0으로 간주하지 않음 |
| 같은 노력으로 더 잘 처리하는가? | 작업 종류·물량 조건을 함께 표시한 처리량/실제 근무시간, 인원별 부담. 총매출 증가만으로 생산성 상승 판정 금지 |
| 참여자의 생활에 도움이 됐는가? | 본인의 확인 보수·추가 성과·실수령, 근무시간/대기 부담과 주차별 변화. 더 오래 일해서 늘어난 금액과 같은 시간의 개선 구분 |
| 공동 성과는 어디에 쓰이는가? | 상품/작업/공간/배송·운영비와 예비금·분배/재투자 조건, 근거가 있는 발생액·예정액·실지급 분리 |
| 문제가 해결되고 있는가? | 실제 확인한 수량 오류·인계 누락·추가 운송/폐기 등과 해결/확인 대기, 다음 회차 개선 이행. 신고 건수 자체를 나쁨이나 보수 감점 기준으로 쓰지 않음 |

수치에는 기간·단위·집계 범위·기준시각·출처·누락·추정/확정/모의를 붙인다. 같은 종류의 업무와 비슷한 시간/물량 조건에서 전후를 비교하되 밀집도와 소득의 상관을 인과 증명으로 부르지 않는다. 미수집·미연결 값은 확인 불가로 표시하고 0건 성과나 성공 사례로 채우지 않는다. 현재 코드에는 이 밀집도/효율/소득 비교 기능이 확인되지 않았다.

공개 화면은 동의한 충분한 범위의 집계를 쓰며 소수 인원의 보수·신고 사실을 역으로 알아낼 수 있는 세부 자료는 제한한다. 개인 보수와 사적인 관계도는 본인/해당 권한 범위로 유지한다. 사람별 경쟁 순위나 친밀도 점수를 만들지 않는다.

## 5. 관계를 유지하고 피해를 줄이는 절차

업무 시작 전에 역할·시간·처리 수량/품질·인계 확인·보수와 변경/중단 시 연락 순서를 공유한다. 인계 시 불일치를 바로 기록하고 사실·의견·미확인을 나눈다. 피해가 전혀 발생하지 않는다고 약속하지 않고 조기 확인·확산 방지·복구·정정 절차를 명확하게 한다.

문제는 업무 진행 문제, 정산 이의, 대인 관계/HR 고충으로 구분해 적절한 담당에게 보낸다. HR 고충의 접수 대상·대체 담당·접근 권한은 추가 설계하며 기존 거래분쟁 API에 임의로 섞지 않는다. 이해관계가 있는 운영 담당을 건너뛸 수 있는 별도 지원 경로도 검토한다.

`문제 접수 → 당사자 설명/증거 → 사실 확인 → 해결안/필요한 책임 검토 → 당사자 안내·확인 → 이의제기/재검토 → 다음 회차 개선`을 구분한다. 신고 접수·사건 종결·기각을 귀책 확정으로 해석하지 않는다. 단순히 입고가 지연되고 포장이 늦었다는 시간 순서만으로 특정 사람의 손해 책임을 확정하지 않는다.

좋은 관계를 이익으로 연결하는 방법은 약속과 역할을 명확히 하고 확인된 기여를 합의대로 인정하는 것이다. 신고하지 않기·무조건 동의하기·사적으로 친하게 지내기를 성과금 조건으로 두지 않는다. 문제 신고만으로 기본 보수나 이미 완료한 기여를 자동 삭제/감액하지 않는다. 다툼이 있는 금액과 이의 없는 확인분을 분리하고 정정은 원기록·근거·검토 이력을 보존한다.

## 6. 성과가 다음 참여로 이어지는 구조

합의한 기본 보수와 추가 성과금, 예비금·공동 재투자의 기준과 지급 주체를 먼저 보이게 한다. 효율이 개선돼도 배분 기준이 없으면 개인에게 돌아갈 이익이 정해진 것은 아니다. 새 분배율·공제·금전 제재를 이번에 확정하지 않는다.

회차가 끝나면 잔여 재고·대기/오류의 원인·역할 부담·수령/지급 확인을 돌아보고 다음 회차의 일정·필요 인력·안내 문서·인계 방법 중 무엇을 바꿀지 제안한다. 잘한 일과 문제 해결의 기여도 사실 근거로 남기되 새로운 자동 성과 보상은 별도 합의 대상으로 둔다. 다음 참여는 새 조건 확인과 당사자의 선택에 따른다.

## 7. 첫 구현 권고와 미정

먼저 한 작업공간의 비공개 `이번 회차에서 함께 만든 변화` 조회를 제안한다. 기존 공동운영 참조·HR 일정/숙지(구현 후)·작업/인계·정산/지원 사건의 현재 상태를 연결해 역할·기다림·실제 완료와 보수 구분을 보여준다. 한 회차의 비용/보상 근거와 다음 개선을 확인한 뒤 주간 비교·공개 요약·지도/Unity 표시로 넓힌다. 공개 신뢰 점수·자동 감점부터 만들지 않는다.

확정한 방향은 비전과 실제 변화를 함께 보여주는 협업 선순환이다. 지표의 정의·집계/공개 범위, 밀집도 산정·비교 기준, 성과 배분·재투자·고충 처리 주체와 권한, 최종 화면은 제안/미정이다. 밀집도에 따른 수입 증대는 미검증 가설이며 실제 고용·임금·보수/운영 정책이나 자동 불이익은 승인되지 않았다. 다음 검토는 한 공간의 회차별 변화 화면에서 우선 보여줄 근거 범위를 정하는 것이다.
