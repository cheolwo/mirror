# 분산 보관 합의와 사진 확인 r31

상태: `Implemented / LocalValidated / ApkPackagingInProgress / DeviceAndOperationalPending`.

사용자는 모바일 앱·서버 구현을 승인했다. Unity·배달 영상은 이번 범위에 없다. 이전 [분산 물류 r30](distributed-warehouse.implementation.r30.md)의 공간·적재 위치·재고·혼합 피킹/전달 경로를 이어 사용한다.

## 승인된 처리 기준

공간 제공자와 실제 물품 소유자가 앱 안에서 같은 판본의 보관 조건에 각각 동의한다. 플랫폼은 계약 당사자나 돈을 받는 주체가 아니다. 장소, 허용 SKU, 수량 상한, 시작·종료 시각, 출입 시간, 무료/비용 조건, 보관 담당, 손실·반환 조건을 기록한다. 관리담당자의 기존 공간 동의는 별개다. 조건이 바뀌면 두 당사자가 새 판본에 다시 동의한다.

입고 계획은 먼저 작성할 수 있다. 실제 적재 확인과 새 재고 예약은 유효한 합의가 있어야 한다. 합의가 만료되거나 철회되어도 기존 물품과 인수 이력은 지우지 않으며, 진행 중인 전달·반품을 마무리할 수 있게 한다. 위탁 판매자는 판매할 수 있어도 물품 소유자를 대신해 서명하지 않는다.

| 절차 | 완료 사진 | 묶음 단위 |
| --- | --- | --- |
| 기존 재고의 위치 등록 | 필요 | 같은 적재 위치의 해당 재고 |
| 입고·적재 확인 | 필요 | 같은 적재 위치와 같은 물품 소유자, 이번에 실제 받은 수량 |
| 피킹 완료 | 필요 | 현재 피킹 정차와 같은 적재 위치·물품 소유자, 이번에 인수한 수량 |
| 전달 완료 | 필요 | 같은 고객의 현재 전달 정차, 이번에 전달한 수량 |
| 반품 입고 | 필요 | 같은 적재 위치와 같은 물품 소유자, 이번에 실제 돌려받은 수량 |
| 거점 등록·합의·계획·예약·배차 수락·고객 수령 확인 | 불필요 | 기존 업무 기준 유지 |

하나의 묶음은 사진 1~3장이다. JPEG/PNG 한 장당 최대 5MiB, 저장본은 긴 변 2048px 이하 JPEG로 다시 인코딩하고 메타데이터를 제거한다. 휴대폰 촬영 → 미리보기/다시 촬영 → `사진 보내고 … 완료` 순서다. 사진 전송만 성공한 상태는 업무 완료가 아니다.

같은 위치라도 서로 다른 소유자의 물품 사진을 함께 공유하지 않도록 입고·피킹·반품 완료 묶음은 소유자별로 나눈다. 같은 정차의 다른 묶음은 현재 묶음 처리 뒤 이어서 처리한다.

서버가 현재 사용자·권한·업무·판본·적재 위치/고객·물품·수량·합의 판본으로 결속을 만든다. 사진은 이 결속과 마지막 완료 요청 번호를 함께 저장한다. 완료 명령의 SQL 트랜잭션 안에서 파일 무결성과 결속을 확인하고 사진 소비와 재고/운송 상태를 함께 반영한다. 실패하면 둘 다 반영하지 않는다. 같은 요청의 재시도는 기존 결과를 조회하며 다른 내용으로 같은 번호를 재사용할 수 없다.

## 보관과 열람

사진은 비공개 저장소에 둔다. 클라이언트에는 영구 공개 URL이나 저장소 경로를 주지 않고 인증된 사진 조회만 제공한다. 해당 물품·공간·주문의 현재 당사자 관계를 SQL에서 다시 확인한다. 기사라는 역할 또는 업로더라는 이유만으로 30일 열람을 주지 않는다. 기존 수행 종료·배정 만료 차단과 최대 3일 제한을 유지한다.

사진의 관련 인수 업무가 끝난 뒤 30일을 보관한다. 입고·반품 사진은 관련 물품의 가용·예약·불량 재고와 운송 중 수량이 남아 있으면 기간을 시작하지 않는다. 피킹/전달 사진은 관련 주문과 인수 수량이 모두 종료되어야 한다. 미수령·문제 접수는 별도이며, 진행 중 사건 또는 조회 불명확이 있으면 정리를 보류한다. 아직 업무 명령에 연결되지 않은 업로드는 24시간 뒤 정리한다.

문제 접수는 입고 `LotId`, 배송 `OrderId` 한 건에 연결한다. 같은 계획의 다른 소유자나 같은 배송 묶음의 다른 고객을 사건 당사자로 묶지 않는다. 신규 접수·재개 때는 SQL 보존 보호를 먼저 기록하고 그 뒤 기존 보호지원 Mongo 사건을 저장한다. 불명확한 저장 결과는 보호를 유지하며 재검토 시각만으로 자동 해제하지 않는다. 관리자 해제는 사건에 기록한 순번을 확인한다.

삭제는 이 기능의 전용 저장소 접두어 안에서만 수행한다. 활성 파일 부재와 Azure의 과거 버전/복사본 부재는 다른 결과로 기록한다. 이미 적법한 정리 순서가 끝난 뒤 새로 접수된 사건이 삭제된 사진을 복구해 주지는 않는다. 관련 재고·계약·업무 영수증은 사진 정리로 지우지 않는다.

## 구현·검증 경계

기준 코드와 DB 관계는 [페이지·코드·DB 문서](../../../../ProjectOverview/page-docs/distributed-storage-photo-proof-r37.md), 실제 결과는 [r37 변경 기록](../../../../Changes/2026-10-08-distributed-storage-photo-proof-r37.md)에 기록한다. 로컬 관계형 DB·실제 파일 저장·HTTP·공통 UI와 APK 패키징을 구분한다. 휴대폰 촬영, 실제 로그인, Azure 저장소·공용 DB 동시 실행은 별도다.

기능 기본값은 OFF이며 정확한 `distributed-fulfillment-r36` profile와 `Simulation`에서만 실행한다. 사진 바이트의 존재·업무 연결을 확인하는 기능이며 물건 내용의 AI 판정, 법적 소유권/계약 인증, 시설 허가, 실제 운임 수취·입금 완료를 제공하지 않는다.
