# 기사 기준 위치·권역 복귀 우대 구현 r38

- 날짜: 2026-10-08.
- 승인: 사용자의 “그럼 그렇게 일단 보완 작업을 진행을 해줘.” 요청에 따라 [설계 r37](driver-return-area.design.r37.md)을 모바일·서버에 구현한다.
- 상태: `Implemented / LocalValidated / DeviceAndOperationalDeferred`.
- [자율 다건 수행 r36](driver-flexible-multi-work.design.r36.md)의 음식/화물 공동 여력·4건 확대는 이번 구현에 포함하지 않는다. 다른 유형의 진행 업무가 있으면 복귀 가점을 확인 불가로 보류한다.

## 선택과 저장

기사 본인의 `내 정보`에서 끄기, 권역 밖에서 자동 복귀, 복귀 우선 켜기를 선택한다. 기본값은 끄기다. 현재 위치를 명시적으로 선택해 집 또는 활동 중심의 고정 기준점으로 저장한다. 이 입력은 실시간 GPS·검색 중심·기존 오늘/기본 복귀지를 덮어쓰지 않는다. 임의 지도 위치 선택은 후속 화면 범위다.

인증된 `GET/PUT api/v1/driver/return-area/settings`만 본인 설정을 조회·저장한다. 새 SQL 테이블이나 운송 상태를 추가하지 않고 Mongo의 `driver_return_area_settings_private`에 보호된 설정과 판본을 보관한다. 초기 저장 경합과 이후 판본 불일치를 거부한다. 설정을 저장하면 위치 판정 상태를 초기화한다. 활성 상태 갱신은 설정 판본과 GPS 시각을 대조하며 과거 위치가 최신 상태를 덮어쓰지 못한다.

앱은 저장 뒤 재조회한 결과만 확인 완료로 표시한다. 응답 손실·계정 변경·충돌 시 성공을 추정하지 않고 재조회를 안내하며 본인 비공개 값을 제거한다. Web 운행 시작의 기존 복귀 좌표도 현재 좌표와 분리하고 `복귀우선` 서버 코드를 올바르게 전달한다.

## 활성 조건과 평가

자동 모드의 초기 설정은 직선거리 7km 이상 진입·6km 이내 해제다. 두 반경은 기사 설정에서 조절하며 해제 반경은 진입 반경보다 작아야 한다. 5분 이내 위치, 미래 시각·정확도 누락·큰 위치 오차와 정확도 범위를 검사하고 경계에서는 위치 오차만큼 보수적으로 판정한다. 수동 켜기도 유효한 현재 위치가 있어야 적용한다.

기존 전체 수행의 마지막 위치 E0와 추가 콜을 포함한 전체 수행의 마지막 위치 E1에서 같은 기준점 H까지 실제 도로 경로로 비교한다. 기존 업무가 없을 때만 E0는 실제 현재 위치다. 가점은 `최대가점 × clamp((E0→H 거리 − E1→H 거리) / 목표개선거리, 0, 1)`이다. 초기 보정값은 최대 20점·목표 개선 3km이며 `DriverReturnArea` 서버 설정으로 조절한다. 이는 시험 시작값이며 실제 운행 효과가 검증된 값은 아니다.

기존 시간창·적재·차량·수신 의사·수락 조건이 우선이다. 확인된 전체 실제 경로가 없거나 더 멀어지는 후보에는 가점을 주지 않는다. 두 도로 응답 뒤 최신 설정 판본·기준점과 활성 GPS 상태를 다시 확인한다. 화물은 실제 차량 명세가 필요하며 기존 화물 일정이 있으면 선택 경로의 구간 적재 근거를 결속하는 후속 보완 전까지 새 가점을 보류한다. 도로 경로 실패를 직선 거리 0으로 바꾸지 않는다. 음식은 등록한 실제 차량의 경로 옵션을 사용한다. 현재 조리 회차·최신 배달 시도와 이미 픽업한 음식의 남은 전달 작업을 확인하며 기존 최대 3건을 유지한다. 음식의 준비 예상+42분은 기존 기사 안내를 재사용한 복귀 평가의 확인 기준이며 새 강제 취소/완료 조건이 아니다.

## 실제 배차 연결

- 화물 개인 추천은 이미 기사에게 허용된 후보와 접근 반경을 유지한다. 우대 활성 중에는 최대 40후보를 평가한 뒤 점수순 10개를 반환해 11번째 복귀 후보가 평가 전에 사라지는 문제를 보완한다.
- 화물 조율과 연속 추천은 같은 전체 일정 평가를 재사용한다. 새 정책을 선택한 경우 기존 개인 복귀 가점·시간대 복귀 부담을 중복 합산하지 않는다. 운송 원가와 운임·정산은 독립적으로 유지한다.
- 음식은 빈 결과를 반환하는 별도 추천 서비스가 아닌 실제 배차 큐에 연결한다. 픽업 시간 적격 단계를 우선하고 그 단계 안에서 확인된 가점을 합산한다. 적격한 인접 권역 후보도 기존 접근 반경 안에서 비교한다. 끄기·미확인·가점 0은 기존 정렬을 유지한다.
- 기준점의 좌표·이름은 고객·매장·다른 기사에게 새로 전달하지 않는다. 추천에는 개선 거리·상태·사유만 제공하고 경로 조회 실패 로그에서 정확한 좌표와 원문 예외를 제거한다.

전체 화면 지도·접는 업무 카드, 기존 서버 수락과 원장 보호는 유지한다. 실제 휴대폰·Azure·실운행·수입 변화는 로컬 시험과 별도다. 구현·검증 결과는 [r42 변경 기록](../../../../Changes/2026-10-08-driver-return-area-r42.md)에 남긴다.
