# 생활 교류 최소 구현 r6

사용자의 최신 방향은 일반인이 제공할 것과 필요한 것을 자유롭게 올려 서로 문의하는 장이다. 공간·상품·배송의 고정 역할이나 플랫폼 결제는 첫 이용의 조건으로 두지 않는다. r4의 재고·예약·배차 설계와 미검증 r5 구현은 후속 후보이며 이번 최소판에 포함하지 않는다.

## 구현 전 페이지 책임 카드

기준: [전체 로드맵 페이지 원칙](../../../../Architecture/WholeRoadmapPagePrinciple.md), [시각 기준](../../../../Architecture/RoleAppVisualDesignStandard.md).

| 페이지 | 사용자 질문과 결과 | 기본 정보 / 주 행동 | 실패와 복귀 |
| --- | --- | --- | --- |
| `/community/exchange` | 누구나 제공/필요 글을 찾아 읽을 대상을 고른다 | 제공/필요 필터, 제목·본문 요약·작성자, 글 상세로 이동 | 로딩·빈 목록·조회 실패/재시도, 서버 20건 페이지 처리 |
| `/community/exchange/write` | 작성자가 제공할 것 또는 필요한 것을 공개한다 | 구분·제목·설명·수정/삭제 비밀번호, 글 올리기 | 유효성 오류·전송 중 잠금·초안 유지, 미확정 전송은 자동 재시도하지 않음 |
| `/community/exchange/posts/{id}` | 방문자가 글을 읽고 공개 문의를 남긴다 | 원문·작성자·공개 댓글, 댓글 등록 | 없는 글/다른 분류·조회 실패·댓글 실패, 목록 복귀; 본인 글 삭제는 기존 비밀번호/권한 정책 사용 |

조회와 작성은 독립 라우트다. 결제·상세 주소·재고·운송·거래 완료 인증·신뢰 점수는 이 페이지가 소유하지 않는다. 댓글은 공개 대화이며 개인 메시지라고 부르지 않는다. 로그인·업무 역할 선택을 강제하지 않고 기존 자유·생활 게시판의 익명 작성·닉네임·삭제 비밀번호 정책을 따른다.

## 페이지 → 코드 → DB

공유 `Exchange` 컴포넌트 → `NeighborhoodExchangeViewModel` → `INeighborhoodExchangeClient` → 기존 `ICommunityPostClient` → `api/v1/community/posts`의 조회/발행/참여 UseCase → 기존 `PlatformCommunityPosts`/`PlatformCommunityPostComments`.

구분은 공통 계약의 `WorkflowTag=생활 교류`, `RoleTag=제공해요/필요해요`로 저장한다. 필터는 서버에서 페이지 처리 전 적용한다. 기존 글을 교류 글로 자동 전환하지 않는다. 새 DB 테이블·마이그레이션·외부 결제나 배차 효과가 없다. 글/댓글의 보존·삭제·신고 권한은 기존 서버 기준이다. 소유권 없는 클라이언트 캐시를 권한 증거로 사용하지 않는다.

작성 비밀번호는 URL/초안 저장/로그에 넣지 않으며 페이지 메모리에만 유지한다. 실패 시 작성 내용을 유지하고, 결과가 불명확한 쓰기는 목록에서 확인한 뒤 사용자가 다시 선택한다. 확인된 실제 거래 내역이나 당사자 동의를 아직 수집하지 않으므로 게시·댓글을 거래 신뢰 기록으로 승격하지 않는다.

## 검증 및 운영 경계

좁은 단위 시험·기존 서버 게시/댓글 시험·소비 앱 빌드·실제 모바일 폭 렌더를 각각 기록한다. 화면 검토용 자료와 운영 서버 자료는 분리한다. 일반인에게 제공하려면 현재 API의 인증/익명 정책, DB 연결, HTTPS 공개 주소와 오류/신고 대응 경로가 실행 환경에서 확인되어야 한다. 로컬 구현을 외부 공개 운영이나 휴대폰 설치 완료로 보고하지 않는다.
