## 이번 수직 범위

비공개 기록에서 독립 대조된 주문 3건의 상품명·수량을 읽고, **살뜰마트**의 합성 선반·SKU·재고로 준비한다. 원본 사업자 명칭은 비공개 출처로만 보존하고 화면·업무 이름에 사용하지 않는다. 봉투값은 선반 상품에서 제외한다. 과거 표시 금액을 현재 단가·판매가·정산 금액으로 사용하지 않는다.

기존 피킹·포장 UseCase를 격리한 로컬 SQLite 표본에서 실행한다. 적재대 코드와 상품·수량 확인 → 주문 전체 피킹 완료 → 품목별 포장 → 주문 전체 포장 완료 → **모의 기사 인계**를 구분한다. 마지막 단계는 실제 기사 수행·운송 완료가 아니며 기존 마트 라스트마일 미지원 관문을 해제하지 않는다.

마트 주문에 연결된 포장은 전체 피킹의 라인·품목·수량을 확인하도록 기존 양 포장 경로와 포장 Event 소비를 보완한다. 비마트 포장 계약은 유지한다. 취소 작업을 완료로 되살리지 않으며 중복 요청은 추가 이력·Event를 만들지 않는다.

## 입력·안전 경계

- `artifacts/local`의 명시된 비공개 입력·SHA-256·선택 기록 ID만 사용한다. 잘못된 입력·hash·실행 모드는 오류로 표시하고 다른 자료로 대체하지 않는다.
- 선반·바코드·재고·담당자·기사는 합성이다. 실물 스캔·재고 존재를 주장하지 않는다.
- 전용 loopback 미리보기에서만 쓰기 가능하며 운영 DB·원본 SQLite·외부 HTTP·알림·결제·배차는 호출하지 않는다.
- 실제 상품명·원문 주문 ID·비공개 입력·화면 캡처는 Gitignored 로컬에 둔다. 공개 시험은 합성 품목을 사용한다.
- 현재 작업트리의 기존 변경을 보존한다. commit·push·배포는 수행하지 않는다.

## 페이지 책임 카드

- 사용자 질문: “이 주문의 상품을 모두 찾아 포장하고 다음 담당자에게 넘길 준비가 됐나?”
- 기본: 살뜰마트 표본 표시, 주문 선택, 현재 품목·수량·합성 선반, 현재 단계의 주 행동 하나.
- 보조: 전체 품목 진행, 합성 정보 안내, 오류와 초기화. 재무·원본 사업자·실제 배송 완료는 표시하지 않는다.
- 실패·복귀: 잘못된 선반/미완료 확인은 상태를 바꾸지 않는다. 같은 주문을 재조회하며 다른 주문은 보존한다.
- 소비 경로: 전용 로컬 미리보기. 기존 읽기 전용 마트 상세나 MAUI 운영 페이지를 쓰기 화면으로 조용히 변경하지 않는다.

## 검증 상한

합성 시험으로 피킹·포장 선행 관문, 재요청·Event 재처리·취소 작업·비마트 호환을 검사한다. 비공개 입력의 3건·22품목·36개 및 원본 hash 불변을 확인하고, 320/390/1280px 실제 렌더·클릭을 검증한다. build·자동 시험·로컬 UI는 구분하며 실제 MySQL/Mongo·Android·스캐너·마트 기사 수행 연계는 미검증으로 남긴다.

## 구현 반환 (2026-10-10)

승인된 범위의 구현과 로컬 검증을 마쳤다. Fast 101건·Task 9,963건이 통과했고 실패 0건, Mongo 환경 시험 15건은 미실행이다. 관련 역할 앱 `Ssalddel.v3.5.slnx`와 전용 미리보기를 build했다. 실제 Chrome의 5모드 × 3폭 = 15건이 통과했으며 기록 상품·합성 상품·입력 없음·hash 불일치·Operational 차단을 구별했다. 소스·입력·빌드 지문 불변과 리셋·Dispose의 메모리 삭제를 확인했다.
