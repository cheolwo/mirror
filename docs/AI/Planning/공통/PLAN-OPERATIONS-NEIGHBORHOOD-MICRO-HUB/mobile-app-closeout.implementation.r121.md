# 모바일 앱 단계별 마감 r121

2026-10-25. `ApprovedByUser / ScopedImplementationVerified / UnifiedReleaseIncomplete / OperationalDisabled`.

사용자는 게임이 아닌 기존 모바일 앱들을 버전별로 완성하는 제안을 승인하고 구현·검증을 요청했다. 후속 사용자 정정에 따라 기존 `0.0`~`3.5`의 전체 범위를 단일 [통합 앱 1.0](../../../../Versions/unified-1.0/README.md) 목표로 묶고 이번 내부 마감 회차를 r121로 구분한다. 기존 업무 코드와 통합 공개 r105의 운영 경계는 보존한다. 기존 전문 앱과 통합 앱의 역할을 보존한다.

## 이번에 닫을 흐름

1. 실제 Android의 설치 판본과 초기 실행·재실행을 확인하고, 초기 실행 종료를 다시 재현할 수 있는 한정된 검증 절차를 마련한다. 원인을 특정할 수 없는 native crash를 임의의 런타임 설정 변경으로 해결했다고 표시하지 않는다.
2. 화주 Native 상세에서 현재 서버 금융 상태를 과거 로컬 FakePG 영수증으로 덮는 경로를 보완한다. 테스트 결제 응답이 불확실하면 기존 계정·서버·의뢰 범위의 보호 저장과 재조회로 다루고 자동 재전송하지 않는다.
3. 현재 소스로 격리 Simulation 서버와 시험 APK를 만들고 같은 의뢰의 접수·수락·상하차·인수/정산 준비를 가능한 단계까지 연결해 검증한다. 기존 완료 원장과 사용자 앱 데이터를 보존한다.
4. 음식·창고·통합 예약은 기존 구현과 검증의 현재 공백을 분리해 후속 마감 목록에 남긴다. 기존 전체 역할 공개 결정을 화물 단독 공개로 변경하지 않는다.

첫 완료 기준은 코드·관련 시험·소비 앱 빌드·같은 판본의 실제 휴대폰 실행이다. 제품 HTTP/DB 완주·휴대폰 화면·실제 촬영/운송·실금융·외부 공개는 각각 별도 상태로 기록한다. APK 번호는 시험 판본이며 제품 `1.0`·`2.0` 등의 공개 완료를 뜻하지 않는다.

## 변경 경계

- Native 화주 상세와 기존 FakePG 테스트 어댑터, 기존 업무 복구 저장 소비, 직접 관련 회귀 시험만 최소 변경한다.
- 초기 실행 검증 도구는 명시한 본인 앱·기기·APK 해시에 한정한다. 앱 데이터 삭제·권한 변경·기기 설정 변경·다른 앱의 로그 저장·무인 감시를 하지 않는다.
- 원장/금융 계약 신설, 실제 PG·송금·배차 발송, 운영 플래그 활성화·클라우드 배포·commit/push는 이번 범위에 포함하지 않는다.
- 기존 변경과 실제 앱 자료·과거 실패 기록은 보존한다. 표준 검사는 이번 파일 범위를 명시해 실행하고 실패·생략을 통과로 집계하지 않는다.

## 검증 중 발견한 직접 관련 보완

실기기의 공통 역할 로그인 입력·버튼 배치를 보완하되 인증·복귀·취소 동작은 유지했다. 전체 회귀에서 드러난 현재 역할/근무·DTO·DI·기능 메타데이터의 정합과 비공개 공동운영 지도 projection 경계를 바로잡았다. API 기본 권한·실행 모드·공개 범위는 넓히지 않았다. 표준 검사를 막던 기존 파일 끝 빈 줄 하나는 동작 본문 보존을 확인한 뒤 정리했다.

관련567·로그인8·전체16,159시험 통과와 환경 의존16개 생략, 제품 HTTP 음식5·화물7·창고 인계/배송8검사, 서버 재시작 후4개 보존 검사를 확인했다. 실제 표준 Release APK0.1.122의 데이터 보존 업데이트·재실행3회·로그인/초안 복구·화면 배치·취소 복귀를 관측했다. 공통1.0의 모든 역할 완주·실물·운영 마감은 별도다. 표준 Fast/Task와 소스·실행 산출물의 최종 결속은 아래 변경 기록과 검증 요약을 따른다.
