## 퀵의 실제 범위

생활 퀵의 신청 진입은 `/community/exchange/deliveries/new`, API는 `api/v1/common/neighborhood-deliveries`다. 기본 차량은 오토바이이며 기존 화주 의뢰와 운송 원장을 재사용한다. 음식 주문 원장과는 분리된다. `QuickDelivery` 업무 분류에는 포장된 마트 배송도 포함되므로 이 값 하나만으로 생활 퀵 전체를 판정하지 않는다.

일반 전문 기사 배송, 선택적인 동네 회원 배송, 외부/자동 처리처는 같은 신청에서 서로 다른 실행·권한·완료 경로를 가진다. 아래는 생활 퀵의 요청자와 수행자가 각각 일을 마무리할 수 있는지에 대한 검토다. 대형 화물 전체나 실제 외부 배송사의 운영 검증으로 확대하지 않는다.

아래 트리는 업무 완결을 대조할 목표 흐름이다. 실제 수령 확인과 조치·비용 합의 후 반송은 일부 경로에서 미연결이며, 현재 구현된 공통 절차로 확정하지 않는다.

```text
보내는 사람: 물품·픽업지·전달지·조건 입력 → 견적 확인 → 접수
└─ 배차 대기 → 기사 제안 → 조건 확인·수락
   └─ 픽업 → 운송 → 전달 증빙
      ├─ 정상: 실제 수령 확인 → 업무 마감 → 지급 조건 확인
      └─ 문제: 신고·증빙 → 해당 업무 보류 → 조치·비용 합의 → 재개/반송/종료

기록한 보수 / 직접 수금 / 플랫폼 지급 준비 / 보류 / 실제 이체는 별도 결과
```
