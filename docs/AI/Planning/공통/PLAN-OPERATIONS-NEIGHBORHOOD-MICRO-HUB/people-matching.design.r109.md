# [기획 · 사람 중심 협업 매칭 · PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB · r109]

기준일: 2026-10-24. 상태: `PeopleMatchingPriorityAccepted / ProposedDesign / ImplementationNotAuthorized / OperationalDeferred`.

사용자는 공간/선반 잔여량의 전산 확인보다 사람을 연결하는 기능이 필요하다고 정정했다. [r108](resource-work-matching.design.r108.md)의 전반적인 자원 매칭 중 이번 우선 범위를 사람 모집·추천·수락·업무 인계로 좁힌다. 공간·재고의 현재 정보는 작업 가능 여부의 배경 조건으로 재사용하고 새로운 용량 매칭을 첫 구현으로 삼지 않는다. 이번에는 제안 문서만 보완하며 코드·DB·앱·알림·실제 배정은 변경하지 않는다.

## 두 종류의 사람 연결

1. **함께 운영할 사람 연결**: 공간을 제공하려는 사람 ↔ 물품을 공급하려는 사람 ↔ 운영을 조율할 사람 ↔ 현장 작업/배송에 참여하려는 사람을 연결한다. 서로 필요한 역할과 제공할 수 있는 역할을 보고 대화·조건 확인·명시적 참여 수락으로 이어진다. 사람을 고정 직종 하나로 분류하지 않고 한 사람이 여러 역할을 선택할 수 있게 한다.
2. **이번 일을 맡을 사람 연결**: 입고검수·적치·피킹·포장·출고 인계·배송에 실제로 필요한 담당자를 시간과 업무 범위에 맞춰 연결한다. 일반적인 참여 의향과 특정 시간의 작업 약속은 구별한다.

## 최소 기능 제안

### 참여자가 등록할 것

- 하고 싶은 일과 맡을 수 있는 작업 범위: 공급, 공간 제공, 입고검수, 적치, 피킹, 포장, 인계, 배송 등 복수 선택.
- 활동 가능한 동네·가능한 요일/시간, 한 번 참여 또는 반복 참여 선호.
- 희망 보수와 조건, 현재 수락한 다른 업무. 시간제/건별 등의 보수 방식은 선택안이며 이번에 확정하지 않는다.
- 추천·모집 알림을 받을 업무 범위와 의사. 비공개 시간표·연락처를 공개 모집 화면에 노출하지 않는다.

기존 커뮤니티 역할 목록을 바로 늘리기보다 기존 전문 작업 종류와 참여 의향을 연결하는 방식을 먼저 검토한다. `피킹 가능` 표시는 특정 창고 접근·재고 처리 권한이나 특정 시간의 출근 확정이 아니다.

### 필요한 사람 모집과 추천

입고 일정·주문·작업 준비에서 `입고검수 1명 / 내일 10~12시 / 업무 범위·보수·요구 조건`과 같은 모집을 준비한다. 운영자가 직접 작성하거나 기존 전문 작업에서 후보 모집안을 만들 수 있지만 자동 외부 게시·전송은 별도 선택으로 둔다.

후보는 참여 의사·가능 작업·실제 업무 권한·시간과 이동 가능성·다른 약속을 먼저 확인하고 희망 조건과 작업 부담을 비교해 추천한다. 추천 이유와 확인이 필요한 조건을 보여준다. 같은 사람의 입고·피킹·배송 약속을 함께 조회해 시간 충돌을 막고, 일이 많거나 가까운 사람에게만 계속 몰리지 않도록 참여 기회를 고려한다. 세부 우선순위·정량 가중치는 미정이다.

### 제안·수락·연결

`필요 인원 발생 → 후보 추천/지원 → 조건 확인·제안 → 본인 수락 및 필요한 당사자 확인 → 해당 시간의 업무 약속 → 기존 전문 작업`을 구분한다. 모집·추천·지원 중 어느 경로를 쓸지는 운영자와 참여자의 선택으로 둔다. 사전에 동의한 조건 내 확정과 별도 확인이 필요한 제안을 구분하며 모든 정상 작업에 관리자 재승인을 강제하지 않는다.

개인에게는 현재 검토할 제안 한 건을 중심으로 시간·장소 범위·할 일·보수·수락/거절을 보여준다. 필요한 사람이 두 명이면 두 자리의 충족 상태를 따로 관리한다. 수락 직전에 최신 시간표·다른 업무·전문 권한을 다시 확인한다. 거절·만료·불참이면 다음 후보나 공개 모집으로 이어지며, 상세한 정책은 후속 명세에서 확정한다.

### 다음 담당자에게 인계

입고 담당이 마치면 적치 담당, 피킹이 마무리되면 포장/출고 담당, 준비가 끝나면 기사에게 기존 전문 원장의 실제 상태와 필요한 인계 확인을 전달한다. 아직 다음 담당자가 없으면 `포장 담당 모집 중`처럼 사람의 공백을 표시한다. 단순 완료 통보를 실제 물품 인수로 취급하지 않는다.

불참·철회 시 미착수 부분을 다시 연결하고 이미 수행한 작업·인수한 물품·발생한 보수와 책임은 보존한다. 반복 참여 희망자는 다음 회차 후보가 될 수 있지만 새 시간·조건의 수락을 자동으로 만든 것으로 보지 않는다.

## 첫 화면과 권장 구현 범위

운영자는 `이번에 필요한 사람`, 참여자는 `내가 할 수 있는 일`에서 시작한다. 예:

| 필요한 사람 | 화면에 표시할 상태 |
|---|---|
| 입고검수 담당 1명, 내일 10~12시 | 후보에게 제안 중 |
| 피킹·포장 담당 1명, 내일 13~15시 | 본인 수락 완료 |
| 배송기사 1명, 내일 15시 이후 | 지원/추천 대기 |

**첫 구현 권고**는 한 공동운영 모임에서 기존 참여자의 가능 시간·희망 작업 등록 → 필요한 사람 모집/추천 → 개별 작업 수락 → 다음 담당자 인계다. 기존 입고·피킹·포장·기사 수락/배차 기능을 재사용한다. 그다음 신규 사람 공개 모집, 반복 참여 팀, 여러 모임 사이의 중복 약속 검사로 확장한다. 기존 참여자로 시작하는 것은 첫 검증 범위이며 신규 참여를 영구 제한하는 정책이 아니다.

## 확정·미정·다음 검토

- **확정한 초점**: 사람 연결을 우선한다. 공간 잔여량 전산화는 이번 제안의 중심이 아니다.
- **제안 단계**: 가능 시간/작업 등록, 모집·추천·수락, 인계와 공석 재모집. 구현 승인은 아직 없다.
- **미정**: 첫 모집 업무, 보수 방식, 제안 기한·우선순위, 자동 재제안 범위와 반복 참여 조건.
- **다음 검토 하나**: 한 모임의 입고검수·피킹포장·배송 담당자를 연결하는 흐름부터 시작할지 검토한다.
