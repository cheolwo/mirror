# 기사 직선거리 요금과 추천 배차 표시 r72

2026-10-15. 상태 `Implemented / LocalValidated / OperationalDeferred`. 사용자가 직전 제안의 구현을 명시적으로 요청했다. 같은 세션에서 거리비 추가·음식/소형 배송 대상·픽업→전달 구간·2.34km=2,340원을 선택했다. [r71](driver-participation.implementation.r71.md)의 공통 자격/여력 보호를 재사용한다.

## 확정 범위

- 음식·소형 퀵의 새 기사 제안에 픽업→전달 좌표의 지표면 직선거리 × 1,000원/km를 적용한다. 첫 구간부터 포함거리 0m, 거리 원값을 사용하며 거리비만 원 단위 AwayFromZero 반올림한다. 기사 접근거리·주행거리·ETA는 별도다.
- 기본/최소/작업비/할증은 유효한 기사 지급 정책 또는 합의 근거를 사용한다. 음식은 기존 음식 기사 정책, cargo 실행 소형 퀵은 명시된 별도 기사 정책을 사용하며 없으면 보류한다. 고객 청구 견적·차량단가를 기사 기본비로 복사하지 않는다.
- 일반 트럭 화물과 기존 유효 합의·동결 제안/수락·과거 정산은 보존한다. 소형 cargo 적용은 생활배송 원천과 확인된 오토바이/승용차 범위로 제한한다. 희망 차량 입력이나 이름 유사도로 소형 자격을 만들지 않는다.
- 새 정책 `StraightLineDriverPricing:Enabled`는 기본 OFF다. OFF는 기존 처리이고 ON인 환경도 기존 적재·시간/경로·동시성·사진/인계 관문을 통과해야 한다. 직선 계산의 성공을 실제 주행 가능으로 간주하지 않는다.
- 기사 제안 contract에 선택적 작업목록과 요금근거를 추가한다. 기존 주행거리 필드를 직선거리로 바꾸지 않고, 원거리/단가/반올림/판본/금액 근거는 기존 저장 경계를 사용한다.
- 음식 파랑 `#2563EB`, 물품/화물 빨강 `#DC2626`, 창고만 회색 `#64748B`, 실제 배정된 피킹/포장/출고와 배송의 결합만 두 색이다. 공통 해석기를 native 두 앱/Razor가 재사용하고 색+단색 아이콘+업무명을 함께 표시한다. 최신 제안 배너와 여러 제안 건수는 구별한다.
- 작업목록은 실제 수행 책임에서 만들며 원천의 창고 선행 bool·개인 희망만으로 포장까지 배정했다고 표현하지 않는다. 독립 창고작업 배차·통합 추천함 신설·혼합 음식/화물 허용은 후속이다.

## 실행 분담

root는 계약/Options/DI, 제안 조회·작업/요금 근거 projection, 문서·통합 검증을 맡는다. 음식 담당은 공통 Domain 수식과 음식 제안 계산·시험, 소형 배송 담당은 cargo 지급 정책·동결/수락/조회 연결·시험, UI 담당은 공통 표시와 두 앱 adapter/시험을 맡는다. 공통 계약은 root가 먼저 확정하고 서로 다른 소유 파일을 수정한다.

## 완료 기준

0/1/2.34km·반올림 경계/좌표 오류, 음식 합의·기본/최소·할증과 소형 정책 부족·트럭 제외, 고객 청구/기존 동결 보존, 추천→조회→수락 근거 일치/중복·응답 유실을 검증한다. 공통 표시/실제 Razor 렌더·두 소비 앱 빌드, 명시 Paths Fast/Task, 기존 dirty 파일 해시 대조를 수행한다. APK 배포·단말·운영 ON·공용 DB/클라우드·commit/push는 이번 범위 밖이다.
