# 생활 배송 간편 입력과 엑셀 음성 초안 r29

> 후속 승인: 사용자가 다음 질문에 `어`로 답해 **생활 배송 간편 작성·엑셀 우선, 음성 후속** 순서를 수용했다. 첫 구현의 동결된 범위는 [승인 r29](simple-input.implementation.r29.md), 소유권·통합은 [작업지시서](development-work-order.r29.md), 실제 결과는 [검증 반환](../../../../Changes/2026-10-07-neighborhood-simple-input-r29.md)이 소유한다. 아래는 승인 전 제안을 보존한 기록이며 현재 상태를 대신하지 않는다.

2026-10-07. 상태는 `Proposed / FirstSliceAsked / NotImplemented`다. 사용자는 입력을 최대한 간단히 하고 말이나 파일로 받은 자료를 서버 업무 입력에 연결하기를 원했다. 파일 형식은 XML이 아니라 **엑셀**로 정정했다. 이 방향 확인은 아래 구현 순서와 세부 정책의 승인으로 해석하지 않는다. [r28 승인](assumed-providers.implementation.r28.md)과 [구현 결과](../../../../Changes/2026-10-07-assumed-fulfillment-r28.md)는 그대로 보존한다.

## 목표와 첫 적용 후보

사용자는 무엇을 어디에서 어디로 언제 보내려는지부터 표현한다. 앱은 이를 입력 초안으로 정리하고 필요한 정보만 묻는다. 직접 입력, 엑셀, 음성이 서로 다른 배송 절차나 원장을 만들지 않고 같은 기존 견적과 접수로 이어지게 한다.

첫 적용 후보는 기존 **생활 배송 한 건**이다. 일반 입력의 간편화와 정해진 엑셀 양식을 먼저 닫고 음성을 같은 초안에 연결하는 순서를 추천한다. 음식 주문·메뉴 등록·화물·창고 전부를 한 번에 확장하지 않으며 각 업무의 필수 조건과 권한은 별도로 유지한다.

## 현재 재사용할 기반

- [기존 입력 계약](../../../../../Ssalddel.Contracts/Common/Community/NeighborhoodDeliveryDtos.cs)은 물품·수량·중량·선택 크기·양측 주소와 연락처·시간창·요청사항을 담는다. 요청 번호와 개인정보 동의 증적도 같은 계약에 있다.
- [작성 ViewModel](../../../../../Ssalddel.Ui.Common/Areas/App/ViewModels/NeighborhoodDeliveryAuthoringViewModel.cs)은 협업 약속의 물품·수량·시간창을 초안에 채우고, 변경된 입력의 기존 견적과 동의를 무효화하며 불명확한 접수를 같은 요청으로 확인한다. 간편 입력도 이 경계를 재사용한다.
- [서버 UseCase](../../../../../Ssalddel/Services/Community/NeighborhoodDeliveryUseCase.cs)는 필수 정보·권한·동의를 검사하고 주소를 좌표로 확인한 뒤 운임을 계산한다. 좌표·요금·동의 증적을 사용자에게 직접 입력하게 만들 필요는 없지만 현재 필수 중량·담당자 연락처 등을 임의로 채워 생략할 수는 없다.
- [화주 일괄 등록 파서](../../../../../Ssalddel/Application/Shipper/Request/화주운송의뢰일괄등록파서Service.cs)는 현재 CSV만 지원하며 엑셀에서 CSV로 저장해 업로드하도록 안내한다. [기존 Controller](../../../../../Ssalddel/Controllers/Shipper/01_Request/화주운송의뢰Controller.cs)의 `bulk/preview`와 `bulk/confirm-preview`는 행별 미리보기와 선택 확정의 재사용 후보다. 생활 배송의 담당자 연락처·시간창·개인정보 동의와 같은 요청 재확인까지 보장하는 계약은 아니므로 일괄 등록을 그대로 호출하지 않고 생활 배송 초안과 기존 UseCase에 연결한다.
- [커뮤니티 AI 초안 정책](../../../../../Ssalddel/Services/Content/CommunityAuthoringAiDraftPolicy.cs)은 구조화된 응답과 사람 검토를 요구하고 주문·결제·배차 실행을 금지한다. 정책과 검토 패턴은 참고할 수 있으나 공개 자료 기반 글쓰기와 비공개 배송 필드 추출은 목적·권한·정보 전송 범위가 다르다.
- [철도역 자료 가져오기](../../../../../eng/Ssalddel.PublicDataPortalImport/철도역기준자료.cs)의 `ParseWorkbook`에는 특정 공공자료 양식의 엑셀 읽기가 있다. 이것은 생활 배송 사용자의 업로드·열 대응·접수 기능이 아니며 공개 업로드의 안전성까지 증명하지 않는다.

현재 생활 배송 작성 화면에는 엑셀이나 음성에서 초안을 만드는 경로가 연결되어 있지 않다. 기존 배송 API와 원장을 대체하지 않고 입력을 돕는 앞단으로 준비한다.

기존 음성 작업은 텍스트를 읽어주는 음성 합성이며 배송 입력용 음성 인식과 구별한다. 이번에 조사한 서버·계약·공통 UI 경로에서는 마이크 입력을 생활 배송 초안으로 연결하는 구현을 찾지 못했다.

## 입력 방식과 공통 흐름

| 방식 | 사용자가 하는 일 | 앱이 하는 일 |
| --- | --- | --- |
| 간편 작성 | 물품, 픽업·전달 장소, 희망 시간을 먼저 선택한다. | 권한 있는 기존 약속 값을 제시하고 빠진 필수 정보만 묻는다. |
| 엑셀 올리기 | 양식을 작성하거나 파일의 시트와 열 대응을 확인한다. | 행별 초안을 만들고 누락·잘못된 값·중복 후보를 표시한다. |
| 말로 입력 | 마이크 사용을 허용하고 배송 내용을 말한다. | 인식한 문장을 보여주고 초안 후보를 만든 뒤 불명확한 값만 확인한다. |

모든 방식은 `입력 → 초안 확인·부족 정보 문답 → 서버 견적 → 현재 금액·개인정보 동의·접수 확정 → 기존 UseCase → 동일 원장 재조회`로 합류한다. 파일 업로드나 음성 인식 완료만으로 배송·외부 위탁·결제를 접수하지 않는다.

간편 화면은 물품, 장소, 시간 순서로 기본 내용을 보이고 포장 크기·상세 요청 같은 선택 정보는 필요할 때 연다. 필수 주소·연락처·중량은 한 번에 긴 표로 요구하기보다 빠진 항목만 묻되 최종 확인에는 실제 제출 값을 모두 확인할 수 있게 한다. 현재 시간창의 화면 기본값도 약속된 값으로 취급하지 않고 사용자가 확인한다.

## 엑셀 입력 제안

첫 양식은 `.xlsx`의 한 행을 배송 의뢰 한 건으로 해석한다. 열은 물품명·수량·중량kg·픽업 주소와 상세주소·픽업 담당자와 전화·전달 주소와 상세주소·전달 담당자와 전화·픽업 가능 시작/종료, 선택 크기·전달 시간창·요청사항에 대응한다. 최종 견적·정보 제공 동의·자동 수행 상한은 업로드 값만으로 확정하지 않는다.

처음에는 판본이 있는 다운로드 양식과 명확한 열 대응부터 제공한다. 임의 파일도 후보 열을 제시할 수 있지만 대응을 확인하기 전에는 접수할 수 없다. 전화번호와 주소는 문자열로 다루며 앞자리 0이 사라진 전화번호·모호한 날짜·누락 중량을 AI가 복구한 사실로 주장하지 않는다. 전체 주소·연락처를 AI에 전달하지 않고 정해진 양식은 서버의 명시적 규칙으로 읽는 것을 우선한다.

기존 CSV 지원은 재사용할 내부 입력 경로이지 사용자가 반드시 엑셀을 CSV로 바꾸게 할 최종 UX는 아니다. `.xlsx` 직접 업로드를 우선 제안하고 서버에서 동일 초안으로 정규화한다. 기존 화주 일괄 등록의 연락처·시간 기본값과 선택적 행 ID를 실제 생활 배송의 확인된 정보나 중복 방지 증거로 사용하지 않는다.

파일은 크기·행 수·압축 해제 크기를 제한하고 확장자와 실제 형식을 함께 검사한다. 매크로·암호화 파일·외부 링크·수식 실행은 허용하지 않으며 필수 값에 수식이 있으면 사용자가 값으로 다시 제출하도록 안내한다. 업로드 권한·조회 소유권·보존과 삭제 정책은 구현 전에 결속한다. 파일이나 셀 내용은 데이터이지 AI·서버의 실행 지시가 아니다.

행마다 원 시트·행·열 출처와 오류를 연결한다. 잘못된 행이 있으면 초안 상태로 남기며 선택한 유효 행만 최종 확인 후 접수할 수 있게 한다. 각 행의 접수 요청 번호와 입력 지문을 보존해 재시도는 같은 요청을 확인한다. 파일 hash만으로 중복 접수를 방지했다고 주장하지 않고, 수정·재정렬·재업로드에서도 이미 제출한 행을 구별할 수 있어야 한다. 동일 내용의 별도 배송까지 자동으로 합치지는 않는다.

## 음성 입력 제안

예를 들어 “면목동 가게에서 중화동으로 상자 두 개를 오늘 오후 보내줘”라는 말은 물품·수량·출발지 후보·도착지 후보·시간 후보를 만들 수 있다. 실제 주소·연락처·중량이 빠졌다면 그 항목만 묻는다. ‘두 개’와 ‘두 kg’를 혼동하거나 장소가 여러 곳이면 확인 전 값을 확정하지 않는다.

음성 인식은 문장을 만드는 기능이고 AI 해석은 문장을 업무 초안으로 분류하는 기능이다. 둘의 오류를 따로 표시하고 직접 수정과 일반 입력으로 돌아갈 수 있게 한다. 개인정보 동의·기사 수락·외부 접수·결제·지급을 AI가 대신 승인하지 않는다.

기기 인식과 외부 서비스 중 어떤 것을 사용할지, 비용 상한, 녹음/전사문 보존 여부와 외부 전송 동의는 미정이다. 비공개 업무 자료를 새 외부 AI에 보내는 것은 별도 확인 전 제외한다. 첫 단계는 합성 문장과 대역 인식기로 초안·문답·검증을 시험하며 실제 마이크와 휴대폰 증거를 구별한다.

## 우선순위와 검증

1. 기존 화면의 필수·선택 정보를 구분하고 초안의 필드별 값·출처·누락·사용자 확인을 정한다. 수정하면 기존 견적과 관련 동의를 무효화하고 불명확한 접수의 원 요청은 바꾸지 않는다.
2. 엑셀 양식·서버 검증·행별 초안 미리보기·누락 문답을 같은 작성 흐름에 연결한다. 업로드만으로 DB 업무 상태·배차·외부 API가 바뀌지 않는지 확인한다.
3. 음성 인식과 자연어 추출을 같은 초안에 연결한다. 인식 실패·허가 거절·불명확 주소·로그아웃·늦은 응답에서 일반 입력과 개인정보 삭제 경계가 유지되는지 확인한다.

기존 경로와 동일 입력이면 같은 견적·접수 의미를 가져야 한다. 누락·단위·열 오대응·수식·과대 파일·중복 행·부분 접수 실패·결과 불명확·재시작/재업로드·권한·개인정보 마스킹을 검증한다. 새 초안·업로드·음성에는 r28의 시험 결과를 그대로 완료 증거로 사용하지 않는다. 실제 UI 렌더, 인증 HTTP/격리 DB, APK/단말, 외부 업체와 실금전은 각각 별도 증거다.
