# 배송료 선결제와 건별·주간 지급 준비 r73

2026-10-15. 상태 `Implemented / LocalValidated / OperationalDeferred`. 사용자가 배송료 선결제 범위를 선택하고 제안한 구현을 요청했다. 기존 주문·화주 의뢰·운송·결제·지급 요청을 재사용하며 상품 대금, 음식/창고 보수 확장은 제외한다.

## 승인 범위와 책임

- 선결제 준비는 신규 의뢰에서 가능하도록 별도 기본 OFF 옵션으로 준비한다. 금액은 서버 확정 운임/결제 예정액과 승인된 혜택으로 만들고 준비 근거를 동결한다. 요청자가 금액을 줄이거나 다른 판본의 운임을 납부해 전액 결제로 승격할 수 없다.
- 토스 승인 성공과 자금 확보를 구분한다. 가상계좌 발급/입금 대기에는 배차·승인 완료 Outbox를 만들지 않는다. 서버의 인증된 PG 조회와 주문번호·금액·통화·결제키 검증을 거친 완료 사실만 기존 승인 후속에 연결한다. 중복/역순/유실 응답은 같은 결제와 정본 조회를 사용한다.
- 결제 후속은 이미 진행·완료·취소된 운송 상태를 되돌리지 않는다. 최초 선결제 확보의 배차 진입만 현재 상태와 함께 검사한다. 실제 환불은 계약/키 연결 전 기본 비활성·모의 검증으로 분리하며 미구현을 완료로 표시하지 않는다.
- 기존 운송별 지급 승인 채무를 건별 또는 주간 지급 준비 배치에 연결한다. 기사·통화·실행 모드·정책 판본이 같은 채무만 묶고 같은 채무의 중복 편입을 DB 고유 제약으로 방지한다. 월정산의 플랫폼 이용료와 합치지 않는다. 완료·계좌·수납·사건 보류를 다시 검사하고 변경된 건은 지급 준비에서 보류한다.
- 새 배치는 지급 준비 명세다. 토스 실제 지급은 계약 적합성·본인 확인·JWE·잔액·영업일·외부 멱등키와 거래 조회가 준비된 별도 Gateway 단계이며 이번에 실송금/운영 ON을 하지 않는다. 기존 준비 전용 Gateway와 실제 입금 미확인 상태를 유지한다.

## 작업 소유권

root: 작업 명세·Options/DI·기존 DB migration/snapshot의 좁은 증분·문서·통합 검증. 결제 준비 담당: 준비 정책/두 준비 handler·준비 근거 Domain 필드·결제 후 운송 event·시험. PG 담당: Toss service/provider·결과 계약·승인 handler·입금 결과 재조회 use case/API·모의 환불/시험. 지급 배치 담당: 배치 Domain/config/context·계약/use case/API·회귀 시험. 같은 파일을 공동 수정하지 않고 API/공유 계약은 먼저 합의한다. 새 사용자 역할·운영 계정/키·외부 통신 실행 권한을 만들지 않는다.

## 검증과 완료 경계

### 사용자 후속 정정

화주가 직접 제시해 저장한 배송료도 정본이다. 플랫폼 참고 견적을 강제로 덮어쓰지 않으며, 명시적 직접 제안 API는 화주 배송료와 기사 제안 보수를 같게 보관하고 알선 차액을 만들지 않는다. 기존 엑셀/CSV/API 접수와 모바일 직접 입력의 전체 시각 연결은 별도 화면 마감 항목으로 확인한다.

사용자는 기사 관점에서 음식·화물·피킹 후 배송의 건별 보수가 누적돼 수요일 또는 목요일에 주 1회 입금되기를 원한다고 정정했다. 현 r73 화물 배치의 기간은 승인일이 아닌 원 운송 완료일 기준으로 바로잡고, 한국시간 수~화 작업주와 수/목 지급 예정일을 구분한다. 기본 목요일 09시·설정 가능한 수요일은 준비 명세의 예정일이며 은행 휴일/PG 잔액·실송금 또는 자동 주간 worker 증거가 아니다. 음식·피킹 보수는 기존 전문 원장에 있고 r73 화물 배치에는 아직 통합하지 않는다. 이 후속은 중복 없는 본인 주간 명세와 공통 실제 지급 단계로 남긴다.

선결제/후불 상태, 요청 금액 변경, 혜택/운임 판본 변경, WAITING_FOR_DEPOSIT/DONE/취소, 결제키·금액 불일치, 중복/역순/응답 유실·운송 상태 보존, 배치 한 줄/여러 줄/동일 채무 중복·권한·모드·보류·동시 생성의 의미 있는 시험을 수행한다. 현재 Fast/Task 명시 Paths와 전체 소비 앱 build·코드맵·diff·기존 dirty 해시 보존을 확인한다. 공용 DB migration·실결제/환불/송금·클라우드·새 APK/휴대폰·Unity·commit/push는 이번 범위 밖이다.
