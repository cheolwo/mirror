# 역할 앱 예외 후 업무 지속 보완 r1

상태: `Implemented / LocalValidated / DeviceAndOperationalDeferred`.

2026-10-10 사용자의 `보완작업진행`은 [예외 지속 조사](../../../../Changes/2026-10-10-cross-app-exception-continuity-audit.md)의 C01~C09 보완을 승인한다. 기존 변경사항과 서버 원장 권위를 보존한다. 구현 소유자는 operations이며 현재 기준 HEAD는 `d1bab3eec08dc0a49c9a87f882590d394205c9a4`다.

## 구현 범위

- C01/C01a: 화주 등록의 요청 번호와 원문을 사용자별 보호 저장소에 고정한다. 본인 요청 번호 결과 GET을 추가하고 응답 유실·재진입에는 조회부터 수행한다. 차량 조회 실패 후 입력을 유지하고 준비 조회를 다시 시도한다. 동일 요청의 동시 제출도 서버 원장 식별·기존 저장 관문으로 보호한다.
- C02: 생활 배송 작성의 미확정 요청을 계정별 복원하고 본인 client request 결과 GET을 추가한다. 자동 재전송하지 않으며 명시 재전송·폐기·만료를 구분한다.
- C03: 분산 업무의 요청 원문·판본·업로드 요청 번호/증빙 참조를 보호 저장한다. 사진 원본은 영속화하지 않고 업로드 결과 GET으로 확인한다. 원본 부재는 재촬영 필요로 안내한다. 기존 업무/증빙 권한을 유지한다.
- C04: 화물 하차 변경 후 같은 운송 정본을 확인한다. 결과 확인 전 완료를 재전송하지 않으며 확인된 완료 카드와 진행 카드를 구분한다. 통신 실패를 미저장으로 단정하지 않는다.
- C05: 기존 지원 사건 종결 후 회원 배송의 최신 복구 가능 상태를 조회하고 기존 Resume/CancelBeforePickup 명령으로 인계한다. 관리자 권한·종결/개별 통지·동의·CAS·멱등 영수증 검사를 유지한다. 주소/연락처/사진을 새 조회에 노출하지 않는다.
- C06: 공통 음식 업무 요청의 응답 유실도 미확정으로 유지한다. GET부터 확인하고 요청 근거 없이 같은 상태를 성공으로 인증하지 않는다. 근거가 없으면 명시적으로 같은 번호/원문을 확인하도록 한다.
- C07: 주문자 지도 상세에서 원주문·복귀 경로가 결속된 기존 문제 접수로 연결한다.
- C08: 회원 수행 지도 중지/재개 수명을 업무 수명과 분리한다. 재개 시 같은 업무의 지도를 복원하고 지도 오류는 카드와 업무를 유지한 채 반복 렌더를 막는다.
- C09: 수입 준비 조회의 원장/요청 세대를 고정하고 늦은 성공·실패·종료 응답을 폐기한다. 기존 30초 읽기 갱신을 유지한다.

## 페이지 책임과 복구 원칙

기존 단일 책임 페이지를 유지한다. 작성 화면은 같은 접수의 확인/명시 재전송, 수행 화면은 현재 단계의 다음 행동, 운영자 지원 화면은 원 사건과 원 배송의 인계만 다룬다. 지도는 부가 표시 장애로 업무를 막지 않는다. 재인증 전 비공개 입력 표시를 금지하고 계정 변경 시 늦은 응답을 무시한다. 보호 저장은 사용자+scope로 격리하고 72시간 후 원문을 제거하되 미확정 요청 번호를 남겨 결과 확인 없이 새 주문으로 우회하지 않는다. 배송·수령·사건 종결·정산·지급은 별개다.

## 검증 및 제외 범위

응답 유실·역순 응답·화면 이탈/재진입·계정 변경·만료·완료 재조회·지도 중지/재개·연속 예외에 최소 회귀 시험을 추가한다. 변경 범위 Fast 이후 Task, 소비 프로젝트 빌드 및 가능한 실제 loopback 화면을 확인한다. 운영 DB·Azure·실제 기기/카메라·외부 알림·배차·송금·배포·커밋/푸시는 실행하지 않는다. 미실행 환경 검증을 로컬 시험 성공으로 대체하지 않는다.

## 개발 반환 (2026-10-10)

- C01~C09의 승인 보완을 구현하고 [변경·검증 기록](../../../../Changes/2026-10-10-exception-continuity-hardening.md)에 화면별 다음 행동과 실제 검증 경계를 반환한다. 새 관리자 권한이나 원주문 상태 복제를 만들지 않았다.
- 화주·생활 배송 접수는 같은 요청 번호·본문을 유지해 결과부터 조회하고 명시적으로 재시도한다. 분산 사진 업무는 업무·판본·업로드 영수증을 대조하며 원본 사진을 복구 기록에 보관하지 않는다. 72시간 후에는 본문 대신 요청 번호·업무 대상 등 최소 조회 정보를 남긴다.
- 화물 하차 정본 확인, 지원 사건과 연결 배송 복구의 별도 행동, 음식 업무의 결과 확인, 원주문 결속 문제 접수, 지도 재개/명시 재시도, 늦은 수입 조회 응답 폐기를 보완했다. 웹 저장 및 C06 음식 행동·운영자 미확정 명령은 현재 화면/계정 수명이며 앱 재시작 영속 복구로 보고하지 않는다.
- 독립 검토에서 발견한 생활 배송 배차 접수 미완료 상태, 잘못된 사진 영수증의 업무/판본, 늦은 하차 촬영 결과도 수정해 시험에 포함했다. 기존 C07 화면 기대와 마트 포장 재확인 알림 시험은 주행동·완료 사실·감사 불변 검사를 보존해 정리했다.
- 최종 Fast 543개·전체 앱 빌드·Task 10,180개가 통과했다. 실패 0, 환경 의존 Mongo 시험 15개 미실행이다. loopback 실제 제품 화면 10항목·지도 수명 8개·현행 OS 카탈로그 선언 63개 검사를 통과했으며 지도 수명 8개는 Fast에 포함된다.
- C01의 Mongo 생성 후 SQL 투영 및 후속 운임/인계 복구, C04 사진 업로드 자체의 응답 유실/재시작 원본, 실제 Android 보호 저장·카메라·지도·인증 HTTP·운영 DB/Outbox·실배차·알림·입금은 별도 검증이다. 실제 기기·Azure·영상·MYBOX/SNS·Unity·commit/push·배포는 실행하지 않았다.

승인 시점 hash는 작업 지시의 `approvedDesignSha256`에 보존하고 개발 반환이 추가된 현재 hash는 `designSha256`로 구별한다. 동시에 진행된 다른 작업과 관련 없는 기존 변경을 보존하며 전체 공유 작업 폴더가 동결되었다고 주장하지 않는다.
