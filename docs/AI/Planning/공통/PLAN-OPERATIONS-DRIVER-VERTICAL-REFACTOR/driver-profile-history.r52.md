## 목적과 범위

기사가 내 정보에서 배달내역이나 설정을 고르고, 완료한 배달 한 건을 확인한 뒤 보던 목록으로 돌아온다. USB의 배민커넥트에서 확인한 지도 홈·마이페이지·날짜별 목록·선택 상세의 정보 분리를 참고하되 실제 수행 중 화면은 관찰하지 않았다. 원본 UI 덤프·스크린샷·고객 정보는 보관하지 않았다.

1. 내 정보에 배달내역 진입을 우선 배치하고 복귀 권역·알림·경험 공유·합의 요금표를 아이콘이 있는 메뉴 행으로 표시한다.
2. 복귀 권역과 경험 공유는 독립 설정 route로 옮긴다. 조회·입력·저장·실패·복귀는 해당 화면의 목적이고 기존 singleton 설정 상태 및 명령을 재사용한다. 이미 읽은 입력 초안은 단순 화면 왕복으로 초기화하지 않는다.
3. 완료 목록의 상호·배달료·시각·거리와 날짜·페이지를 보존하고 행 전체 선택으로 기존 상세 명령을 실행한다. 상세 왕복 시 첫 표시 행으로 복귀하며 다른 날짜·페이지·계정에는 이전 위치를 적용하지 않는다.
4. 운행 종료는 내 정보 맨 아래에 유지한다. 지도·현재 수행 카드·운행/GPS/신규 배차 수신 및 기존 서버의 권한·revision·개인정보 열람 정책은 변경하지 않는다.

## 책임과 완료 기준

기본/보조 정보와 독립 업무의 근거는 [페이지 원칙](../../../../Architecture/WholeRoadmapPagePrinciple.md)과 [현행 책임 카드](../../../../ProjectOverview/page-docs/driver-workspace-sections-r1.md)를 따른다. 요금 상세 재배치와 수행 카드 문구 통일은 다음 범위이며 이번에 함께 수정하지 않는다.

- 내 정보에는 설정 입력 폼이 없으며 배달내역 메뉴를 먼저 찾을 수 있다.
- 설정은 각각 별도 화면에서 기존 값과 저장 조건을 유지한다. 인증이 없으면 입력을 표시하지 않는다.
- 목록 행의 선택은 기존 중복 진입 방지와 상세 열람 검사를 통과한다.
- 상세에서 돌아오면 같은 날짜·페이지·첫 표시 항목을 유지한다. 날짜·페이지·계정이 바뀌면 복귀 위치를 제거한다.
- 관련 VM 회귀, scoped Fast/Task, Android XAML 컴파일·APK 생성 결과를 각각 기록한다. 실제 단말 터치·지도·알림·외부 운영은 별도 상태로 보고한다.
