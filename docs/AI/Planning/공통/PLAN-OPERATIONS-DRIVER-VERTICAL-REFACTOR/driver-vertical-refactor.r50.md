# 음식 기사 DB–API–화면 리팩토링 r50

상태: Implemented / LocalValidated / DeviceAndOperationalDeferred. 2026-10-09 사용자가 음식 기사 흐름 및 구조 정리와 복구 보완을 선택하고 `Implement the proposed plan`으로 승인했다. 현재 소스와 dirty 변경을 보존하며 서버의 업무 상태 권위를 유지한다.

## 책임과 순서

첫 단위는 운행 시작 → 신규 수신 → 제안/현재 카드이며 이후 수락 → 가게 도착 → 픽업 → 전달에 적용한다. SQL 근무·시도·정산은 전문 상태의 원본이고 Mongo 주문 원장은 포함 관계를 소유한다. 두 저장소를 통합하거나 전달/수령/실지급을 합치지 않는다.

1. 기존 근무에 선택적 시작 요청 ID와 입력 지문을 추가한다. 기사별 동일 요청은 같은 근무를 반환하고 다른 입력은 충돌한다. 동시 시작과 이미 진행 중인 근무를 보호한다.
2. SQL 변경과 후속 의도 기록을 같은 트랜잭션으로 저장한다. 원장/알림은 기존 Outbox를 재사용하고 운행 실행 인덱스 복구는 전용 작업 기록과 기존 예열 경로로 연결한다. 늦은 후속 작업이 종료·새 근무를 되살리지 않는다.
3. 현재 업무 조회·상태 전이·정책·후속 처리의 책임을 나눈다. 기존 서비스 facade와 계약을 유지한다.
4. `GET /api/v1/driver/food-deliveries/workspace/current`는 정산 없는 현재 업무 자료만 반환한다. 기존 workspace 및 정산 API는 유지한다. 오류는 기존 구조화 오류 계약을 소비한다.
5. 시작/수신 복구 판단과 카드 값 해석은 공통 순수 정책을 사용한다. SDK·GPS·HTTP·암호화 보류 저장과 앱 수명은 각 호스트에 남긴다. 공통 셸은 특정 기사 어댑터의 내부 구현을 참조하지 않는다.

## 호환과 화면 기준

기존 route·stable ID·상태값·권한·Revision과 Operational/Simulation 게이트를 보존한다. 시작 요청 ID와 수신 변경 ID는 별도다. 시작 POST를 자동 재전송하지 않으며 명시적 OFF를 재조회가 덮어쓰지 않는다. 확정 거절은 시작 보류와 연결된 수신 의도를 해제하고, 응답 유실 복구는 현재 SQL 근무의 요청 ID·실행유형을 대조한다. GPS 갱신도 종료와 같은 기사 잠금을 사용한다. 네이티브의 영속 보류와 공통 화면의 VM 내 보류 보장은 합치지 않는다.

[기사 페이지 책임 r14](../../../../ProjectOverview/page-docs/driver-workspace-sections-r1.md#dbapi화면-책임-분리-r14)에 따라 전체 지도·독립 하단 카드·GPS 자동 갱신·단계별 행동을 유지한다. 미확인 거리와 0km를 구별하고 서버가 행동을 최종 검증한다. 새 AI 모델·자동 수락·요금·수행 상한은 추가하지 않는다.

## 검증 및 실행 경계

동일/동시 시작·응답 유실·후속 실패/재처리·종료 뒤 늦은 작업, 동시 수락·오래된 판본·중복 픽업/전달, 현재 조회의 정산 미호출, 두 화면의 OFF/거리/만료/카드·지도 유지가 완료 기준이다. 집중 Fast → 전체 Task → 실제 공통 Razor 모바일 렌더 → 소비 앱 APK를 확인한다. 새 migration은 추가형으로 준비하고 전용 로컬 DB에만 검증한다.

실제 단말·원격 푸시·Azure·공용 DB migration·실운영·실지급·Unity·영상 편집·commit/push는 포함하지 않는다. 음식점 전체 200건 제한 뒤 필터링 문제는 다른 역할의 후속 범위다. 검증 결과는 [r50 변경 기록](../../../../Changes/2026-10-09-driver-vertical-refactor-r50.md)에 실제 실행 후 기록한다.

최종 Fast 1,061개·Task 실행 9,701개·공통 모바일 18장면을 통과했다. 별도 Mongo 환경 시험 15개는 미실행이다. 추가형 SQLite migration 검증·MySQL 적용 SQL·EF 모델 일치·서명된 ARM64 Debug APK를 확인했다. 기존 거절의 두 단계 저장, 종료 인덱스 정리 실패의 로그 처리 및 외부 알림의 중복 수신 경계는 [남은 운영 경계](../../../../Changes/2026-10-09-driver-vertical-refactor-r50.md#적용-순서와-남은-운영-경계)에 보존한다.
