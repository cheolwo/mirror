## 승인 범위

3. 완료 배달 상세의 배달료 합계·요금 구성·공제/수령액·정산/지급 상태를 읽기 순서대로 정리한다. 요금 구성은 항목명을 왼쪽, 값을 오른쪽에 두며 수락 당시 저장값을 읽는다. 기존 구성 설명은 호환 유지하고 null·0·소수 금액·기본비 미분류·근거 무효를 구별한다. 합계를 다시 계산하거나 미확인 값을 채우지 않는다. 모의 정산/입금 확인 안내도 유지한다.
4. 네이티브·공통 기사 화면의 단계 제목과 주 행동을 `가게 도착 / 픽업 완료 / 전달 완료`로 맞춘다. 음식점명과 다음 행동 안내의 반복을 줄이고 주소는 별도로 온전히 표시한다. 버튼을 사용할 수 없을 때 누르라고 안내하지 않는다. 준비·재조리·실패·복구 안내, 실제 서버 권한과 명령은 보존한다.
5. 로컬 검증과 네이버 지도 설정을 포함한 ARM64 독립 APK 생성 뒤 인증된 USB 휴대폰의 기존 기사 앱을 덮어 설치한다. 기존 앱 자료·로그인·서명은 보존하며 삭제/초기화/서명 불일치 우회는 하지 않는다. 설치와 실행·서버 통신·업무 완주는 각각 기록한다.
