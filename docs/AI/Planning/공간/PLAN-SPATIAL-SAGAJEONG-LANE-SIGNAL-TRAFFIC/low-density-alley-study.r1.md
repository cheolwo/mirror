# 사가정 저밀도 신호·골목 표현 적용 연구 r1

- 연구 ID: `study:sagajeong-low-density-signal-alley.r1`
- 상태: `Accepted` (2026-09-13)
- 승인 근거: 사용자가 첫 검증 프로필을 `저밀도`로 확정하고 전체 보기·부분 보기, 대로뿐 아니라 건물 사이 골목의 오토바이 이동을 함께 고려해 달라고 요청했다.
- 대상 기획: [사가정 차로·신호·합성 교통 r2](README.md)
- 질문: 통행 권위를 과장하지 않으면서 신호 대기와 골목 배달 이동을 한 디오라마에서 읽을 수 있는가?

## 근거 재고

서울시 공식 정적 교통자료 r1은 차선·방향표시·교차로·제어기·신호등 전체 파일 5종에서 사가정 창 후보 1,523행을 비공개 원장에 저장했다. 이 가운데 신호등 125행은 포털 좌표계 표기와 파일 내 SRID가 충돌하므로 지역 귀속을 승인하지 않았다.

후속 [서울시 교차로 및 횡단보도 시설·위치정보 OA-23081](https://data.seoul.go.kr/dataList/OA-23081/F/1/datasetView.do)의 동결 XLSX는 21,776개 자료 행을 가진다. EPSG:5186 사가정 창 안에는 중랑구 84행, 보행등 `유` 40행·`무` 44행, 교차로 관리번호 27개가 있다. 교차로 `3205`·이름 `사가정역`에는 횡단보도 7행이 결속되고 그중 보행등 `유`는 4행이다. 이는 시설 존재와 교차로 식별 관계의 관찰 근거이며 실제 신호 현시·차량 통행 허용을 뜻하지 않는다.

동결 OSM 후보망은 4타일, 2,807노드, 2,574간선이다. 464개 `highway` way 가운데 `residential` 169개와 `service` 145개가 있으며 `service=parking_aisle` 24개를 포함한다. 변환된 Motorcycle 후보 1,810간선은 road class에서 파생됐을 뿐 도로 way의 `access`·`vehicle`·`motor_vehicle`·`motorcycle` 태그가 비어 있고, 방향은 144간선만 `Forward`, 2,430간선은 `Unknown`이다. 범위 안 출입구 510개 중 건물 결속 497개, 도로 결속 16개, 양쪽 모두 결속된 것은 3개다. `kerb/curb` 원천 태그도 없다.

따라서 대로 차로와 골목 통행을 실제 권위로 즉시 결합할 수 없다. 이번 연구는 원본 OSM 선형을 배경 근거로 사용하되, 차로 offset·신호 주기·차량 상태는 분명한 `SyntheticFixture`로 분리하고 `TraversalReady=false`를 유지한다.

## 승인된 저밀도 검증 프로필

아래 값은 실제 사가정 교통량이나 실제 신호 주기가 아니라 첫 화면의 판독·결정성·성능을 확인하기 위한 `sagajeong-low-density-traffic.r1` 설정이다.

| 항목 | 승인 기준 |
| --- | --- |
| 합성 주체 | 선택 배달 오토바이 1대 + 주변 승용차 3대, 화면 최대 4대 |
| Simulation 시간 | 고정 0.25초 Tick, seed `20260913` |
| 신호 주기 | 남북 녹색 10초 → 황색 2초 → 전방향 적색 2초 → 동서 녹색 10초 → 황색 2초 → 전방향 적색 2초, 총 28초 |
| 속도 | 대로 목표 6m/s, 골목 오토바이 목표 2.5m/s |
| 정지 | 정지선 1.5m 전, 같은 차로 최소 6m 간격 |
| 대기열 | 앞 차량부터 0-based 순번을 가지며 녹색에서 같은 순서로 출발 |
| 골목 | 일반 주변 차량은 진입하지 않고 배달 오토바이만 후보 선형을 왕복한다. 좁은 구간은 `이동자원점유Policy`의 단일 점유 후보로 취급한다. |
| 효과 경계 | 주문·배차·경제·NPC 수요·퀘스트·평판·광고 순위를 만들거나 바꾸지 않는다. |

코드에 숨은 기본값으로 이 값을 확정하지 않는다. 상태 사본은 `trafficProfileRevision`, `signalPlanRevision`, `laneGraphHash`, `scenarioSeed`, `simulationTick`을 포함하며, 입력 판본·hash가 맞지 않으면 부분 적용하지 않는다.

## 공간·표현 후보

- 대로 교차부는 기존 `SagajeongReference.json`의 역 중심 부근 OSM `secondary` way `218790209`와 `tertiary` way `218798305`가 만나는 로컬 좌표 약 `(554.576, 3.594)`를 관찰 기준점으로 사용한다.
- 왕복 차로 표시는 OSM 중심선에서 시각적으로 분리한 합성 선형이다. 원본 차선 도형이나 실제 차로 수로 주장하지 않으며 `SyntheticLaneDisplayOnly`를 표시한다.
- 첫 골목 후보는 OSM way `1256772587`, `highway=service`, 이름 `면목로44가길`의 원본 중심선 22.775m다. `service=parking_aisle`은 아니며 시작은 `residential` way `576294786`, 끝은 일반 `service` way `1256772583`에 명시 노드로 연결된다. 네 노드의 로컬 X/Z는 `(668.194,86.381) → (646.429,89.222) → (645.961,89.211) → (645.625,89.089)`이다.
- 동결 이동망의 세 간선은 모두 방향 `Unknown`, `PendingHumanReview`, `runtimeAuthorized=false`다. OSM에는 access·vehicle·motor_vehicle·motorcycle·oneway·출입구·연석 태그가 없으므로 상태는 `ManualVisualReviewCandidate / TraversalApproved=false`다.
- `SagajeongReference.r3` 602동 윤곽과 중심선 충돌은 0건이다. 양쪽 최소 이격 관측값 1.052707m·1.065566m은 서로 다른 위치의 값이며 합계를 실제 폭으로 사용하지 않는다. VWorld 비공개 검토 사본에서는 최소 이격이 0.832665m라 오토바이 폭·회전 반경 검증도 아직 통과하지 않았다.
- 건물 사이 빈 공간, 주소 점과 건물 중심을 잇는 직선, Unity NavMesh가 만든 지름길은 사용하지 않는다.
- `footway`, `cycleway`, `pedestrian`, `service=parking_aisle`, 접근 금지 또는 의미 미확정 구간은 오토바이 골목 후보에서 제외한다.

## 화면 검증

저장하지 않는 runtime-only Root로 canonical `SimulationWorldShell` 안에서 다음 세 화면을 남긴다.

1. 전체 1km 보기: 기존 건물·도로 배경 위에 저밀도 합성 차량 4대 이하와 선택 기사 위치가 함께 보인다.
2. 사가정역 교차로 확대: 합성 횡단보도·정지선·우측 차로, 빨간 신호 대기열과 초록 신호 재출발이 읽힌다.
3. 골목 확대: 원본 OSM `service` way `1256772587`·`면목로44가길` 후보 중심선 위를 배달 오토바이가 이동하고 주변 자동차는 진입하지 않는다.

정지 사진은 공간 판독 증거다. 실제 움직임은 Play Mode 동안 서로 다른 Tick의 적용 횟수, Transform 누적 변화량, 빨간 신호 정지와 초록 신호 재출발 상태 전이를 별도 기록한다. 서버 HTTP·실제 주문·운영 신호·전체 OSM 길찾기·Scene 영속 결속은 이 증거에 포함하지 않는다.

## 무효화·후속

실제 신호 주기, 실제 교통량, 전용 오토바이 통행 자료, 차선 수·회전 허용, 보행자 충돌, 물리 차량, 실제 CurbStop 또는 운영 주문 결속이 필요하면 Logic·Presentation의 가장 이른 E1~E4를 다시 연다. way `1256772587`을 `ReviewedLaneTraversalGraph`에 넣으려면 현장 또는 추가 공식 근거로 access·양방향 여부·유효 폭·장애물·주차·연결 출입구를 사람이 별도 승인해야 한다.
