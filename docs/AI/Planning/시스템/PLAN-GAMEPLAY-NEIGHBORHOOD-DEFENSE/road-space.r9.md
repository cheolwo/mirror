## 날짜·좌표의 한계

- 배포 목록 기준은 2026-08-12, 실제 수집 시각은 `acquisition.json`의 UTC 시각이다. 추출 160개 모두 원문 `UPDATEDATE=20250512`다. 새로 받았다는 이유로 실제 도로 현황이 2026년 관측이라고 주장하지 않는다. 현장 관측일은 미확인이다.
- ZIP의 CPG는 `949`, 엄격한 CP949 디코딩을 사용했다. 터미널 최초 한국어 표시가 깨진 것은 출력 인코딩 문제였고, UTF-8 추출 파일을 별도 읽어 도로명을 확인했다.
- 원본 PRJ는 `ITRF2000_Central_Belt_60` WKT이며 자동 EPSG 식별은 없었다. 다른 좌표계 번호를 임의 대입하지 않고 원본 WKT로 변환했다. 출력은 경도·위도 순 `EPSG:4326`, 원본 미터 좌표도 함께 보존했다.
- pyproj가 실제 선택한 변환 연산의 정확도 메타데이터는 2.02m다. 이는 원본 측량 정확도나 최종 지도 오차의 보증이 아니다. 수치 왕복 오차 최대 약 2.46×10⁻⁹m는 변환 정합성 검사일 뿐 현실 정확도와 다르다.
- 전체 구간 중 범위와 교차하는 선을 고르고 **끝점을 자르지 않았다**. 따라서 끝점은 범위 밖일 수 있다. 연결을 보존하는 검토 자료이며 Unity 배치용 잘라낸 도로가 아니다. 기존 OSM과의 자동 결합은 하지 않았다.

## 활용 트리와 다음 단계

[정보 활용 트리 JSON r9](road-information-usage.r9.json)은 **기존 자료 / 새로 저장한 자료 / 아직 구현하지 않은 사용처**를 구분한다. 실행 계약이 아니라 검토 목록이다.

- 좌표·LINK_ID·F_NODE/T_NODE: 어느 위치의 어느 방향 구간인지 확인하고 기존 도로와 대응 후보를 찾는 데 사용한다.

- 게임용 변환 계층: 승인된 구간 대응과 별도 폭 정책을 입력으로 받아 폭·간격·건물 간섭을 검사할 계획이다. 이번에 구현하지 않았다.
