- 기존 준비 구현 r1의 기획 hash·작업 명세는 유지한다. Unity 높이 적용 전에는 검토된 자료·산식과 지도 소비자 영향 범위를 별도 작업 명세에 결속한다.

## 작업 순서와 판정

1. `SagajeongReference.json`의 고정 판본/hash·건물 ID를 기준으로 목록을 만든다.
2. 기존 `면목동주소공간연결`/사업체 연결 자료에서 주소 후보를 역조회한다. 단일 주소 후보도 공식 건물 식별 확정은 아니며 복수 후보를 자동 선택하지 않는다.
3. 사업체의 정확한 면목동 지번 문자열에서 필지 후보를 얻고 기존 `면목동공간원천.ReadGis`로 해당 필지의 GIS 행을 읽는다. 사업체 소재 층을 건물 총층수로 사용하지 않는다.
4. GIS의 A16 높이(m), A26 지상층수는 [기존 공식 정의서 조사](../PLAN-SYSTEM-MYEONMOK-OBSERVER/source-acquisition.md)의 필드 의미로 원문과 양수 파싱 후보를 구분한다. 같은 필지의 여러 건물은 모두 후보로 남기며, 좌표·윤곽 교차검증과 이용조건이 확인되기 전 Unity 높이에 사용하지 않는다.
5. 임시 높이이고 기존 주소 단일 후보와 필지 정보를 가진 대상 중 필지 ID 순 최대 3곳을 동결해 기존 수집기로 조회한다. 첫 접근 실패 후 나머지 요청은 중단한다. 새 API/우회 수집기를 만들지 않는다.
6. 대장과 GIS 후보 파일을 비공개 원본 계보로 등록하고 기존 공공자료 정규화 테이블에는 건물별 파생 대장 참조를 저장한다. 수치 측정값으로 저장하지 않는다. 같은 입력 재처리와 독립 DbContext 재조회를 확인한다.
7. 실제 적용 가능한 자료가 없거나 산식이 미정이면 기존 Unity 지도를 그대로 유지한다. 불확실성을 숨기는 화면 변경은 하지 않는다.

## 발견한 차단과 다음 문답

이번 추가 건축물대장 조회는 첫 필지 HTTP 403으로 차단되어 나머지 두 필지는 요청하지 않았다. 키 자체의 오류인지 활용신청/접근 정책 문제인지는 403만으로 확정하지 않는다. 기존 GIS는 이용조건 표시 불일치로 게임 사용 검토보류이며 필지 후보는 건물 식별 확정이 아니다. 따라서 이번 대장의 적용 허용 값은 모두 false이고 높이 변경 제안값은 null이다.

다음 사용자 확인: 건축HUB 건축물대장 API의 현재 활용신청·승인 상태를 확인할 수 있는가? 접근 문제를 해소하기 전 같은 요청을 반복하지 않는다. 독립 GIS 대안은 제공처 이용조건 확인·건물 윤곽 대응 검토 후 진행한다.
