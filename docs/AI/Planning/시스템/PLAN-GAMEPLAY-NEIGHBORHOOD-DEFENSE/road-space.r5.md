# [기획 · 역 중심 디펜스 · PLAN-GAMEPLAY-NEIGHBORHOOD-DEFENSE · r5]

상태: `Draft / SourceBasedRoadTransformationConfirmed / AccumulateOnly`. 2026-09-12 문답. [r4](road-space.r4.md)의 임의 큰길 4명 폭 질문을 철회하고, 도로 자료를 먼저 조사한 뒤 중간 변환 계층에서 게임용 비율을 관리하는 방향으로 대체한다. 이것은 도로·자료 모델 구현이나 수집 실행 승인이 아니다. [기존 준비 구현 r1](README.md)의 승인 hash/명세는 보존한다.

## 확정과 기존 기준의 위치

도로 폭을 사용자와 임의의 인원 수만으로 결정하지 않는다. 도로 공공자료의 종류·폭·차로 수 등 확보 가능한 속성을 근거로 상대적인 크기를 정하고, 원자료와 Unity 사이에서 게임 목적에 맞게 조정한다. 큰길과 골목의 차이를 유지하면서 사람/기본 몬스터를 수용하는 것이 목적이다.

골목의 일반 사람 두 명 교행과 기본 몬스터의 사람 유사 크기는 게임용 최소 공간을 비교하는 기존 기획 기준으로 보존한다. 이를 실제 골목 폭이나 공공자료에 기록된 수치라고 표현하지 않는다. 큰길 4명 병렬 수용은 승인되지 않았으며 기본 규칙으로 사용하지 않는다.

## 현재 코드에서 확인한 결손

- Unity `Assets/Ssalddel/Runtime/World/공간참고자료.cs`의 참고도로는 `id`, `kind`, 선분 좌표만 가진다. 폭·차로 수·폭의 근거 필드는 없다.
- `Assets/Ssalddel/Presentation/World/사가정지리MeshBuilder.cs`는 표시 폭을 종류에 따라 10m/4m/1.5m로 정한다. 이는 실측값이 아니다.
- main `Ssalddel/Services/WorldProjection/AdministrativeDongDiorama/행정동디오라마ProjectionBuilder.cs`의 RoadInput도 식별자·양끝 좌표·근거 종류만 가진다. 현재 연결에 도로 폭·차로 속성을 전달하는 계약이 필요하다. 전체 저장소 원자료에 해당 속성이 없다고 단정하지는 않는다.

## 제안하는 중간 계층 — 세부 설계는 미정

명칭 후보는 `도로 공간 변환 계층`이다. 원자료/정규화 → 도로별 변환 규칙 → 주변 배치·통행 공간 검사 → Unity 읽기 표현 순서로 구성한다. 단순 필터뿐 아니라 분류·계산·검증·출처 추적을 맡는다.

1. 자료 계층: 도로 고유 식별자, 형상과 연결, 도로 종류, 폭·폭의 의미(차도/보도 포함 여부), 차로 수·방향별/전체 구분, 일방통행·입체 교차 등 확보한 필드만 보존한다. 원자료 값, 출처·기준일·이용조건·단위·해시를 남긴다. 모르는 값은 미상으로 두고 도로등급만으로 차로 수를 확정하지 않는다.
2. 변환 계층: 자료 근거의 폭, 차로 수 등에서 추정한 폭, 게임 표현 폭을 별개로 관리한다. 등급별 확대 비율·최소 공간·상한·도로별 예외와 규칙 판본을 둔다. 실제/추정/표현값의 계보를 남기며 값이 없는 자료를 몰래 기본값으로 대체하지 않는다. 구체 계수와 추정 허용 여부는 미정이다.
3. 공간 검사: 넓어진 도로가 건물을 덮거나 길이 끊어지지 않는지 검사한다. 교차로·연속 폭·건물 조정·옥상 기호를 함께 검토한다. 그려진 폭과 실제 게임 통행 가능 폭을 구분하며 같은 변환 결과와 판본에 결속한다. 충돌/혼잡/전투 권한은 별도 Simulation 규칙이다.
4. Unity: 검증된 게임용 도로 결과를 읽어 표현한다. 프레임마다 공급자를 호출하거나 Renderer가 실도로 폭을 임의 추정하지 않는다. 운영 지도와 게임용 변형을 프로필로 구별하고 현실 좌표/업무 판단을 변경하지 않는다.

서버의 자료 준비 과정이 출처 결합·파생 결과를 관리하고, 순수 계산 규칙은 필요 시 Core에서 재사용하는 방향을 추천한다. 새 서비스·프로젝트를 반드시 만들겠다는 뜻은 아니며 기존 수집/정규화/공간 투영 구조 재사용을 먼저 검토한다. 같은 원자료와 변환 규칙 판본은 같은 결과를 내도록 한다.

## 자료 조사 범위와 한계

기존 OSM 공개 지리자료와 정부·지자체 공식 자료는 출처 종류를 구별한다. 공식 후보로 [ITS 표준노드링크 조회](https://www.its.go.kr/nodelink/nodelinkStatus?service=inquiryNodelink), [서울 교통데이터 목록](https://t-data.seoul.go.kr/dataprovide/trafficdatalist.do)을 확인했다. 후보 발견만으로 폭 필드·사가정 골목 포함·재사용 권리가 확인된 것은 아니다. ITS 상세 페이지 직접 조회는 시간초과였으며 실제 파일·스키마·범위·이용조건은 후속 확인이 필요하다.

향후 조사는 현재 사가정 지도 범위의 원자료 보유 현황 → 실제 도로 속성·이용조건 확인 → 구간 식별/좌표계/판본 매칭 → 누락·충돌·추정 비율 보고 → 검증된 작은 변환 비교 순으로 제안한다. 다른 자료의 가깝게 보이는 선분을 무조건 같은 도로로 연결하지 않는다. 이번 턴은 기획과 읽기 점검만 하며 신규 데이터셋 수집·DB 저장·외부 게시·Unity 적용은 하지 않았다.

## 장면·영향·미정

플레이 순서: 방어 준비/침입 관찰의 공간 기반. 지금은 사가정 길의 실제 특징과 게임 수용을 함께 읽을 필요가 있고, 여기는 역 주변의 크기가 다른 도로다. 나인 플레이어는 사람과 몬스터를 관찰·지휘하고, 너는 도로/건물/객체다. 이렇게: 자료 기반 상대 비율을 변환해 객체가 식별되는 공간을 만든다. 대가는 자료 결손 처리·도로 연결 정합성·건물 재배치 검토가 필요하다는 점이다. 상위 목적의 보조 층이며 오행/괘 연결과 새 보상은 미정이다.

재사용 H1/신규 H/이동 WI는 확정하지 않는다. Graph Map은 ReviewRequired, 배치 맵은 도로·건물·옥상·통행 결속 검토가 필요하다. 레벨 1은 실제 연결과 게임 경로 관계, 레벨 2는 폭/간격/경계, 레벨 3은 수집·정규화·변환·Unity 계약이 대상이다. 직접 영향은 게임용 도로 파생 결과, 1-hop은 객체·건물 배치이며 실제 배차/업무 원장에는 전파하지 않는다.

미정: 자료별 실제 필드/구간 포괄률, 폭 의미, 누락 폭 추정 허용, 비율·최소/최대 폭, 건물 조정, 세부 소유 코드, 이동·전투 규칙과 실행 증거.
