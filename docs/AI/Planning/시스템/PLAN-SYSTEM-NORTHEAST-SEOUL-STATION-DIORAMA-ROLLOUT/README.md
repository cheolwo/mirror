- r4 확정 근거: 사용자는 화면–기준 건물 결속 원장과 4,062개 화면 건물 주소 상태 원장을 분리한 첫 절편 구현을 승인하고, 역세권 디오라마 증거 체계에 `RoadAddress`·`ParcelIdentifier`·`ParcelGeometry` 수집·coverage 점검을 필수로 포함하도록 확정했다. 승인 범위는 비공개 RDB·관리자/Development 읽기 API와 증거 검사까지이며 공식 건물군 도형 확보·Unity·이동·Simulation은 포함하지 않는다.

## 목적

사가정역을 단순 첫 화면이 아니라 **자료·공간·이동·생활·상호작용·검증을 끝까지 대조하는 기준 모듈**로 만든다. 그 기준을 코드 복사가 아닌 공통 Profile·자료 수집 절차·공간 tile·검증 관문으로 동결한 뒤, 사용자의 실제 이동권에 있는 역과 역 사이 생활 회랑으로 단계적으로 넓힌다.

행정동·법정동은 수집·집계·권한의 정본이다. 역 중심 1km 창과 생활 회랑은 이 정본을 참조하는 조회·표현 단위이며 행정 경계를 대신하지 않는다. Unity는 서버와 Simulation의 읽기 전용 관찰자이고, 역마다 별도 Scene을 만들지 않는다.

```text
공식·검토 원천
  → 출처 영수증·판본·hash·좌표계·권리
  → RDB 정본 식별·주소·집계 + Mongo 불변 공간 tile
  → 역 1km manifest / 생활 회랑 manifest / 지역 Experience manifest
  → 공통 StationDiorama Host의 8개 모듈
  → 실제 Play Mode·Game View·전환·회수 증거
```

## 이번 판본에서 확정한 범위

- 먼저 사가정의 수직 관문을 닫고, 기존 실제 배치·높이·도로 관계와 현재 화면 구도를 회귀 기준으로 보존한다.
- 면목역·용마산역은 이미 존재하는 독립 비공개 공간 사본을 두 번째·세 번째 교차 표본으로 사용한다. 사가정 자료를 이름만 바꿔 재사용하지 않는다.
- 이후 역은 동일한 8개 모듈 구조를 사용하지만 각자 공식 역 식별자·표현 창·출처·결손·판본·hash·권리 상태를 가진다.
- 인접 역의 1km 창이 겹치면 원본 건물·도로·주소를 복제하지 않고 공용 공간 tile을 여러 manifest가 참조한다.
- 역별 비교 기준은 고정 1km × 1km 핵심 모듈로 유지한다. 대학교·공원·대단지처럼 핵심 창 밖까지 이어지는 생활 거점과 역 사이 이동은 역에 억지 귀속하거나 핵심 창을 늘리지 않고 별도 회랑·거점 패키지가 공용 tile로 참조한다.
- 역 사이를 오가는 오토바이·차량·보행자와 OS 생명주기는 공간 권위와 분리한다. 운영 업무는 서버, 합성 생활은 Simulation, 화면 표현은 Unity가 맡는다.
- 실제 사람·가구·기사·주민을 공공 통계에서 생성하지 않는다. 생활인구·승하차·소비 통계는 합성 밀도와 시간대 분포를 검토하는 집계 근거까지만 제공한다.
- 본 판본은 사가정 화면 건물 증거 첫 절편의 로컬 자료 생성·RDB 멱등 저장·관리자/Development 읽기 API·증거 검사만 승인한다. 신규 공식 도형 수집·운영 효과·Simulation·Unity·Scene·Prefab·E 승격·공개·배포는 승인하지 않는다.

## 역 하나와 역 사이를 함께 다루는 포장 구조

### 1. 역 핵심 모듈

- 일반역은 현행 표준대로 공식 기준점 중심의 정북 1km × 1km를 기본 비교 창으로 둔다.
- 이 1km는 전부를 같은 정밀도로 모델링한다는 뜻이 아니라 자료 coverage 포락선이다. `중심 반경 0~250m 역전 핵`을 가장 정밀하게 표현하고, 나머지 1km 사각 핵심 창은 도로·건물·방향 기준점의 중요도에 따라 LOD를 낮춘다. 1km 사각 창의 최대 중심 거리는 약 707m이므로 `600~1,000m 반경` 같은 모순되는 구간은 사용하지 않는다.
- 환승역·철도 부지·출구 분산으로 핵심 구조가 창 밖까지 이어져도 1km 비교 핵심은 유지한다. 추가 범위는 핵심 창의 치수를 바꾸는 정본이 아니라 사유·치수·참조 tile을 가진 선택적 `Overflow/Corridor Profile`로만 제공한다.
- 한 번에 활성화되는 고정밀 역 모듈은 하나로 유지하고, 인접 영역은 필요할 때 낮은 LOD의 공용 tile로 보조한다.

### 2. 생활 회랑 패키지

- `사가정–면목–용마산`: 세 초기 표본의 공통 규칙과 반례를 검증하는 기준 회랑
- `중랑–중화–상봉–망우`: 철도 결절과 상업·주거의 동서 연결 회랑
- `상봉–망우–양원–신내–봉화산`: 철도·신규 주거·녹지 가장자리 회랑
- `중곡 후보–군자–아차산–장한평–답십리`: 간선도로와 오토바이 이동을 중심으로 보는 동서 회랑
- `장한평–답십리–전농–배봉산–회기`: 철도 노선 하나가 아니라 실제 생활 이동을 표현하는 동대문 생활 회랑
- `회기–외대앞–신이문`: 대학·병원·주거·철도 가장자리 회랑

회랑 포장 방식은 r2에서 확정했다. 개별 회랑의 정확 경계·Portal·포함 거점은 계속 후보이며 자료 근거와 별도 질문으로 정한다. 회랑은 새 공간 정본이 아니다. 역 manifest와 공용 tile, 경계 Portal, 생활 거점 참조를 묶는 상위 조회 결과다. 회랑이 아직 없어도 각 역은 독립 실행 가능해야 한다.

### 3. 생활 거점 후보

다음 이름은 바로 건물이나 단지에 귀속하지 않고 `UserMentionedName / OfficialIdentityPending / AddressPending / BuildingBindingPending`으로 시작한다.

- 대학·녹지: 서울시립대학교, 사용자가 별도로 말한 `보건대학교`, 삼육보건대학교, 배봉산
- 답십리·전농 주거: 답십리 파크자이, 두산아파트, 동화아파트, 한신아파트, 우성그린아파트, 전농동 우성아파트 후보, 전농동 SK아파트 후보, 청솔우성1차 후보

사가정 r27에서 도보망 2,902·엘리베이터 1·공원 1·버스정류소 30·가로수 292, 합계 3,226건의 비공개 보충 후보는 수집됐다. 이는 보행·오토바이 접근망 완결 증거가 아니다. 공원 좌표 변환, 원천별 관계 검토, NGII 자료, Unity Adapter와 Game View가 남아 있다. 그 밖의 주요 선행 결손은 화면 건물과 의미 건물의 결속, 신호 자료 좌표계, 출입구·연석 정차점, 통계를 합성 밀도로 바꾸는 규칙, production Host·역 전환·live 서버·실제 입력 증거다. 해결할 수 없는 항목은 `MissingCoverage` 또는 구체적인 대기 코드로 닫을 수 있지만 조용한 보간은 허용하지 않는다.

기존 공간 overlay의 footprint 대조는 화면 건물 4,062개를 `1:1 결속 544 / 배경 전용 3,423 / 모호성 미해결 90 / 약한 후보 미해결 5`로 나눌 수 있다. 반대쪽 기준 건물 602개는 `1:1 결속 544 / 유일한 화면 건물 없음 58`이다. 현재 생성기는 544개 별칭을 보존하지만 기준 건물 쪽 58개 결손을 독립 station-scoped 원장으로 내보내지 않는다. 따라서 첫 구현 질문은 새 공간 추정이 아니라 이 양방향 전수 분류와 불변 hash·읽기 경계를 닫는 것으로 제한한다.

첫 원장의 1차 키는 기존 `station:kr:kric:s1107:0722`다. r27 자료의 `area:kr:seoul:jungnang:sagajeong-station-0722-one-kilometer`와 Experience Package의 `world-region:kr:seoul:jungnang:sagajeong.r1`은 서로 다른 책임의 참조로 보존하며 이름이 비슷하다는 이유로 alias 병합하지 않는다. 구현이 승인되면 기존 Graph Map에 새 플레이 관계나 도형을 만들지 않고 기존 사가정 station·건물·주소·표현 노드의 레벨 3 결속만 `UpdateExisting`으로 인계한 뒤 개발 준비를 다시 판정한다.

화면 건물 4,062개는 전부 국토교통부 GIS 건물통합정보의 고유 식별자와 PNU·지번을 가진다. 2026-08 행정안전부 건물DB와 관련지번을 읽기 전용으로 대조하면 `단일 도로명주소 후보 3,796 / 복수 후보 60 / 공식 후보 없음 206`으로 전수 분류할 수 있다. 기존 544개 footprint 결속을 통해 공식 주소가 전달되는 511개도 PNU 경로와 `일치 491 / 충돌 18 / 후보 없음 2`이므로 필지 일치나 기존 겹침만으로 공식 주소를 확정하지 않는다.

첫 DataEvidence 묶음은 수명이 다른 두 원장을 분리한다. `PresentationBuildingBindingLedger`는 4,062 화면 건물과 602 기준 건물의 관계를 소유하고, `PresentationBuildingAddressAssignment`는 각 화면 건물의 공식·공유·필지 후보·복수 후보·충돌·미해결 상태를 소유한다. station manifest는 두 revision·hash를 참조하되 주소 월판 변경이 footprint 결속 hash를 바꾸지 않게 한다. 공식 확정률은 신청형 도로명주소 건물군 도형과 집합건물 상세주소 동 도형을 별도 확보한 뒤 높이며, 후보 단계에서는 배달·가격·업체·Unity 사용을 차단한다.

### 선택 생활 자료

- 공개 인허가 사업장·전통시장·공공시설은 사실 원장으로 수집하고, 업체 Claim·광고 Campaign·샘플 메뉴와 분리한다.
- 서울 생활인구 250m와 역별·시간대별 승하차·대중교통 O/D는 집계 밀도와 유입·유출 시간대 후보로만 쓴다.
- 공동주택 실거래·공시가격은 건물·단지 주소 결속 뒤 읽기 전용 관찰층으로 제공하고 개인 가구나 NPC 경제력으로 환산하지 않는다.
- 교통 소통·주차·날씨·대기질은 가용 범위와 갱신 주기를 확인한 뒤 선택 레이어로 둔다. 서울 실시간 도시자료가 모든 대상 역을 포함한다고 가정하지 않는다.
- 신호등 위치·교차로 연결은 공식 공간 근거가 있을 때 사용한다. 실제 신호 현시 자료가 없으면 Simulation의 명시적 합성 주기로 표현하고 현실 신호 주기라고 표시하지 않는다.
- 현장 사진·거리뷰·기사 사진은 공간·외관 근거와 이용권을 따로 판정한다. 항목별 상업 배포·변형 권리가 확인되지 않으면 Git·Unity 자원·빌드에 넣지 않는다.

### 저장 책임

- RDB: 역·행정동·법정동·건물·주소·공공시설·사업장 식별, 자료 검토 상태, 집계, Claim·Campaign, 게시 준비 상태
- MongoDB: 불변 station/corridor 공간 사본, tile, 이동 Graph, 투영 manifest와 content hash
- Unity 메모리: 활성 역과 회랑의 검증된 읽기 사본·표시 상태·LOD cache; 운영 원장 저장 금지
- 공용 원천 객체는 한 번 저장하고 역·회랑 manifest가 안정 ID와 hash로 참조한다. 역별로 같은 건물·도로 행을 복제하지 않는다.

## 코드 확장 전에 필요한 구조 관문

현행 공통 Host와 Planner는 8개 모듈·의존성·결정적 hash·교차 역 fallback 거부를 갖췄지만 활성 Catalog는 사가정 하나뿐이다. 서버 역 Catalog는 세 역, 지역 Experience Catalog는 일부 지역이 코드에 고정돼 있고 면목·용마산 공간 사본은 station-scoped 게시 경로가 없다.

따라서 네 번째 실제 역을 추가하기 전 다음을 먼저 닫는다.

1. 역별 스크립트 복사를 `StationProfile`·자료 원천 목록·고정 1km 핵심 창·선택 Overflow/Corridor Profile·품질 상태를 읽는 단일 parameterized 수집·감사 명령으로 바꾼다.
2. station-scoped 불변 payload 저장과 manifest 조회를 행정동 current projection에서 분리한다.
3. 코드 고정 Catalog를 판본화된 역 Profile 대장으로 바꾸고 잘못된 역·지역·tile·hash 결속을 거절한다.
4. 지역 Experience Package가 역 핵심 모듈과 선택 회랑을 참조하되 기존 세부 API의 권한·기능 플래그를 보존하게 한다.
5. Unity `ActiveStationDioramaHost`에 공통 Package Client·hash cache·역 전환·해제·메모리 회수 경계를 연결한다.
6. 사가정 전용 값은 Profile로 남기고 공통 규칙 후보는 면목·용마산 반례 검토와 사람 승인 전 자동 적용하지 않는다.

현행 증거 대장은 2026-09-14 재조회 기준 `출처 7 / Candidate 12 / Provisional 0 / Accepted 0 / 역 Profile 3`이다. 이는 후보를 기록했다는 증거이며 공통 규칙이 승인됐다는 뜻이 아니다. 면목·용마산 자료의 출처 Profile도 실제 공간 사본과 다시 정합화해야 한다.

## 단계별 실행 순서

### 0단계 · 명칭과 범위 동결

- 19개 후보의 사용자 원문, 공식명, 운영기관, 노선, 역번호, 기준 좌표, 주소, 행정·법정동 교차를 대조한다.
- `중공역`, `보건대학교`, `전동동`과 동명이 가능한 아파트는 자동 수정하지 않고 확인 목록으로 남긴다.
- 역별 1km 핵심 창과 회랑·거점 후보의 경계만 계산하며 Unity 구현은 시작하지 않는다.

### 1단계 · 사가정 기준 모듈 동결

- 동시에 변경 중인 r17·r23·r27 기획, 증거 대장과 실제 검증 결과의 판본·상태를 먼저 정합화한다.
- 위 8개 모듈의 현행 증거·결손·대기 코드를 한 Profile에서 다시 산출한다.
- 화면 건물–의미 건물, 주소, 이동망, Portal, Actor 수명, 업체·광고, 환경 목표를 각각 독립 관문으로 닫는다.
- 기존 전체·부분 Game View를 회귀 기준으로 두고 서버 연결, 실제 입력, 역 전환, 메모리 회수를 별도 증거로 검증한다.

### 2단계 · 확장 기반 리팩터링

- data-driven 역 대장, 단일 수집·audit pipeline, station-scoped store/API, 공용 Package Client를 만든다.
- 기존 사가정·면목·용마산 결과가 같은 hash와 화면 상한을 유지하는지 확인한다.

### 3단계 · 면목·용마산 교차 적합성

- 기존 비공개 사본을 새 저장·조회 경계로 이관하되 원천 hash와 결손을 유지한다.
- 면목의 고밀도·경계 교차와 용마산의 녹지·경사·coverage 결손을 사가정 규칙의 반례로 사용한다.
- 두 역의 실제 Play Mode·Game View·전환·해제까지 닫은 뒤에만 공통 규칙 승격을 사람에게 제안한다.

### 4단계 · 3~4개 역씩 자료 우선 확장

1. 먹골역·중화역·상봉역과 중랑역·망우역
2. 망우역과 공유 축을 가진 양원역·신내역·봉화산역
3. 중곡역 후보·군자역·아차산역
4. 장한평역·답십리역
5. 회기역·외대앞역·신이문역

한 묶음에서는 먼저 모든 역의 `DataEvidence`와 `BaseSpatialPresentation`을 모으고, 실제 활성 Unity 모듈은 한 역씩 닫는다. 자료 재사용률 때문에 한 역이 끝날 때까지 다음 역의 공식 원천 inventory를 금지하지는 않지만, 사가정 기준 동결 전 새 역을 `Ready`나 공개 후보로 올리지 않는다.

### 5단계 · 생활 회랑과 거점 결합

- 양쪽 역 핵심 모듈이 독립 실행된 뒤에만 경계 Portal과 공용 tile 참조로 회랑을 만든다.
- 장한평–답십리–전농–배봉산–회기는 대학·공원·아파트의 공식 경계와 출입구를 결속한 첫 비철도 생활 회랑 표본으로 검토한다.
- OS 업무는 전국 공통 `WorkStableId`와 상태 전이를 유지하고, 역·회랑은 화면 Anchor와 집계 범위만 제공한다.

### 6단계 · 지역 Experience Package 검토

- 다운로드 크기·LOD·cache·저사양 성능·오프라인·갱신 실패·판본 전환을 실제 Game View에서 검증한다.
- 광고·후원·실제 서비스·Steam 공개는 공간 모듈 완성과 분리된 승인 관문으로 남긴다.

## 역별 완료 관문

각 역은 다음 산출물이 모두 있거나, 없는 항목이 구체적인 결손 상태로 닫혀야 `PackageReviewReady` 후보가 된다.

1. 공식 역 행과 안정 식별자, 표현 Profile
2. 원천 URL·기준일·수집시각·이용조건·원본 hash·CRS를 가진 출처 영수증
3. 결정적 공간 사본과 coverage audit, 행정·법정동 교차
4. 건물–주소–용도–높이–생활 거점 결속과 `Unresolved` 목록
5. 도로·오토바이·보행 Graph와 출입구·횡단보도·CurbStop·신호 품질 상태
6. 같은 입력 재적용 중복 0과 독립 DB 재조회
7. station/region manifest의 schema·ETag·projection hash·기능 플래그
8. 8개 Unity 모듈의 `Ready / PrivateReview / Blocked / NotProvided`와 의존성 진단
9. 실제 Play Mode·Game View의 전체·부분 화면, 역 전환, Console, 메모리 회수, Scene 비변경 또는 명시적 저장 기록
10. 해당 역이 기존 공통 규칙을 지지·반박·무효화하는지 기록한 `StationEvidenceProfile`

자동 시험 통과, 임시 View 캡처, 실제 Scene 배치, live 서버 연결, 운영 권위, Steam 게시를 서로 대신하지 않는다. 공통 규칙은 여러 역의 지지와 반례를 기록해도 사람 승인 전 적용하지 않는다.

## 미정

- 사용자가 말한 `중공역`이 중곡역인지와 `보건대학교`가 삼육보건대학교와 다른 거점인지
- 동명이 가능한 답십리·전농 아파트의 공식 단지명·주소·건물 범위
- 환승역별 가변 창의 기준과 첫 저사양·권장 기기 성능 예산
- 공식 보도·이면도로·출입구·신호등 위치·신호 현시 자료의 역별 coverage
- 각 회랑의 실제 오토바이 이동 범위와 경계 Portal 수·위치
- 첫 신규 역 묶음에서 생활·사업장·주거 가격 중 어디까지 함께 열지
- 신청형 도로명주소 건물군·상세주소 동 도형의 확보 시점과 배포 허용 범위

첫 절편 검증 뒤 신청형 공식 건물군·상세주소 동 도형을 바로 확보할지, 주소 충돌·결손 사람 검토 표본을 먼저 닫을지는 다음 판본의 질문으로 남긴다. 사가정 첫 절편 구현은 이 선택을 기다리지 않는다.

## 현재 검증 상한

기존 저장소의 역세권 표준·지역 Experience Package·사가정 공공자료·면목/용마산 공간 사본·증거 진화 규칙과 현행 서버 Catalog 구조를 읽기 전용으로 대조했다. 외부 공식 페이지에서 역·생활인구·대중교통·건축물대장·도로명주소 전자지도와 두 대학의 주소 자료가 현재 안내되는 것까지 확인했다. r4는 첫 절편과 증거 체크를 승인했지만, 구현·DB 재조회·API 시험 결과는 별도 구현 기록에서만 확정한다. Unity·Scene·Prefab·Play Mode·Game View·E 승격·commit·push는 수행하거나 승인하지 않았다.
