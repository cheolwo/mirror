## 1. 첫 한 판 — 길을 읽고 직접 배달한다

후속 [집중·이완 혼용 r146](focus-relax-shared-management.design.r146.md)은 같은 주문의 직접/자동 제어권 인계와 직접 완료 구간의 추가 보너스 자격을 정한다. 이 문서의 직접 주행·다른 지도 화면 제한과 자동 운전/자동 픽업 금지는 **집중 모드**에 적용하고, 이완 전환은 회차 종료/중단 없이 같은 주문·가방을 자동 기사에게 맡기는 것으로 구분한다. 이완의 자동 픽업·전달도 Core 조건과 별도 수령 확인을 따른다. 금액·자금 귀속과 기존 충돌 수치 제안은 그대로 후속 검토이며 r146 문서화가 제품 구현을 뜻하지 않는다.

기존 사가정 동네의 검토 가능한 작은 도로 구간에서 오토바이 한 대로 두 주문을 순차 수행한다. 주문 A의 매장→수령지를 완료한 뒤 주문 B를 진행하고 회차 결과로 돌아온다. 첫 가방은 주문 한 건을 담는 한 칸으로 제한해 묶음 배달·재료 생산·창고 인계를 동시에 요구하지 않는다.

| 플레이 상황 | 정의 |
| --- | --- |
| 지금·여기 | 같은 지역·도로·시나리오 판본과 난수값을 고른 짧은 배달 회차. 목표 체험 길이는 3~5분이며 강제 실패 타이머는 첫 안에서 두지 않음 |
| 나 | 지정된 기사 한 명의 오토바이를 직접 조작하는 플레이어 |
| 상대 | 준비된 주문을 내주는 가상 매장, 정확한 수령지, 정해진 경로로 움직이는 가상 차량·보행자 |
| 선택 | 일반도로/이면도로의 경로, 속도 조절·대기, 적절한 정차와 Space 상호작용 |
| 직접 결과 | 같은 주문이 픽업·가방 적재·전달·정산 기록까지 한 번 이어짐 |
| 대가·회복 | 충돌·끼임 복구는 시간과 안전 점수를 소비하며, 주문을 유지한 채 다시 주행하거나 명시적으로 회차를 중단 |
| 다음 선택 | 결과를 보고 같은 조건으로 재도전하거나 동네 경영으로 복귀. 활동권·카페 개설은 별도 후속 기획 |

지도에서 길과 정차 위치를 읽고 직접 행동하는 재미를 먼저 검토한다. 첫 지도는 일반도로와 이면도로, 교차로·검토된 횡단 구간을 함께 포함하고 다른 길을 택할 여지를 둔다. 실제 사고·교통량·현장 배달의 재현으로 표시하지 않는다.

## 2. 도로·카메라·교통을 먼저 읽을 수 있게 한다

| 구분 | 판독과 주행 규칙의 첫 안 |
| --- | --- |
| 일반도로 | 넓은 주행 면·진행 방향·경계선을 선명하게 표시. 일반 차량 경로가 보이며 상대적으로 높은 게임 속도 상한 |
| 이면도로 | 일반도로보다 좁고 경계·골목 입구가 구별됨. 낮은 속도 상한으로 매장 접근과 교차 상황을 읽음 |
| 보도·건물·녹지 | 주행 영역과 대비해 표시하고 통과 주행을 막음. 보도는 편한 지름길로 사용하지 않음 |
| 교차로·횡단 구간 | 차량·보행자의 접근 방향을 미리 읽을 시야를 확보하고 감속할 이유를 보여줌 |
| 매장·수령지 정차 영역 | 입구와 연결된 정차 위치, 현재 주문의 목적지와 Space 가능 여부를 선·문자·표식으로 표시 |

도로망은 기존 원본과 실제 배치를 대조한 **가상 주행 영역**으로 준비한다. 도로·보행망·횡단보도·차선 원본은 이미 있으므로 자료가 없다고 단정하지 않는다. 반대로 원본 보유만으로 현재 장면의 주행 면·차선·보도가 검증됐다고 보지도 않는다. 폭과 속도는 게임 조정값으로 분리하며 OSM 분류만으로 실제 통행 허가나 현장 안전을 확정하지 않는다.

카메라는 현재 2.5D 지도를 바탕으로 오토바이와 전방 도로를 함께 읽게 한다. 주행 중 방향이 뒤집히지 않도록 시점을 고정하고, 가까운 건물이 도로·진입점·교통 주체를 가리면 가림 완화와 명확한 경계를 제공한다. 목적지 안내선은 길을 알려주되 자동 운전하지 않는다. r143의 회색 배경·관리 매장 운영색을 유지하고, 픽업 대상·배송지는 별도 목적지 표식으로 구별한다.

첫 교통 표본은 자동차 2대·보행자 3명의 작은 합성 흐름을 제안한다. 차량은 검토한 차도 경로, 보행자는 보도/횡단 경로만 사용한다. 플레이어 바로 앞에 갑자기 생성하지 않고 이동을 미리 볼 수 있게 한다. 실제 유동인구를 NPC 수·충돌 확률·주문 수로 직접 환산하지 않는다.

### 장식과 충돌 주체의 분리

r138/r143의 장식용 사람·차량은 기존 클릭 없는 배경 표현이다. 이번 미니게임의 충돌 가능한 차량·보행자는 **항상 판독 가능한 필수 교통 주체**로 분리한다. 장식 움직임 끄기로 충돌 대상만 보이지 않거나 페널티가 사라져서는 안 된다. 걷기 동작을 줄여도 필수 주체의 현재 위치·이동 방향은 유지한다. 유효 정차 영역에 멈춘 기사에게 NPC가 일방적으로 진입해 반복 페널티를 주지 않도록 경로를 검토한다.

## 3. 조작과 픽업·가방·전달

| 입력 | 첫 조작안 |
| --- | --- |
| 방향키 ↑↓←→ | 카메라 기준 상하좌우로 이동하고 오토바이가 이동 방향을 향함. 차체 기준 가속/회전 조작은 첫 안에 넣지 않음 |
| 대각선 입력 | 속도를 정규화해 한 축 이동보다 빨라지지 않게 함 |
| 방향키 놓기 | 감속해 정차. 정차 표시가 켜진 뒤 Space 사용 |
| Space 한 번 누르기 | 현재 주문 단계·위치·정차·가방 상태에 맞는 픽업 또는 전달 하나만 요청 |
| Esc | 회차 메뉴에서 전체 가상 시간 정지·계속·끼임 복구·명시적 중단을 선택 |

방향키·Space는 운전 화면에 입력 초점이 있을 때만 처리한다. 입력창·메뉴·결과 창에 둔 키가 오토바이를 움직이거나 주문을 처리하지 않는다. Space를 누르고 있어도 반복 실행하지 않는다.

### 상태 순서

| 단계 | 필요한 조건 | 결과와 화면 |
| --- | --- | --- |
| 매장으로 이동 | 현재 주문과 매장 고유 식별자가 연결됨 | 매장 정차 영역·경로와 가방 `0/1` 표시 |
| 픽업 가능 | 정확한 매장 정차 영역 안, 정차, 현재 주문 준비 완료, 빈 가방 | `Space · 픽업` 표시. 미준비이면 남은 상태/대기를 보여줌 |
| 픽업·적재 | Space 요청이 유효하다고 같은 게임 Core가 판정 | 주문이 기사 가방에 한 번 결속되고 `1/1`·주문/메뉴 표시. 전달 목적지로 안내 변경 |
| 배송 주행 | 가방에 현재 주문을 보유 | 포장된 주문을 유지하며 수령지로 이동 |
| 전달 가능 | 정확한 수령지 정차 영역 안, 정차, 해당 주문 보유 | `Space · 전달` 표시. 다른 건물·다른 주문은 전달 불가 사유 표시 |
| 전달 기록 | Core가 기사의 전달 상태 전이를 한 번 확정 | 가방 `0/1`, `수령 확인 대기` 표시. 기사 Space만으로 주문자의 수령 확인·보수를 함께 확정하지 않음 |
| 수령 확인·정산 | 기존 수령 확인·정산 조건을 Core가 판정 | 주문자 수령과 정산 기록 뒤 다음 주문 또는 회차 결과. 첫 가상 수령자의 자동 확인은 별도 시나리오 규칙·Core 사건으로 기록 |

가방에 보이는 물품·문구는 같은 주문 상태를 읽는다. 픽업·전달 모션 완료나 가방 외형 교체만으로 상태를 확정하지 않는다. 전달과 수령 확인은 기존 계약의 별도 사건으로 보존한다. 첫 안에서 물품 던지기·이동 중 전달·자동 픽업·중복 적재는 허용하지 않는다.

일반도로/이면도로 속도 상한 비율은 `1.0 / 0.6`을 시작값으로 제안한다. 정차 시간·상호작용 반경·가감속의 실제 수치는 지도 좌표/객체 크기를 확인하고 조작 시안에서 확정한다. 실제 교통 속도 기준을 뜻하지 않는다.

## 4. 충돌 페널티와 회복의 첫 안

아래 값은 재미·판독 검토를 위한 초기안이며 실제 보상 규칙의 확정값이 아니다. 첫 회차는 안전 점수 100에서 시작하고 0 아래로 내려가지 않는다.

| 사건 | 즉시 결과 | 안전 점수 |
| --- | --- | --- |
| 차량과 충돌 | 오토바이 정지 2초·충돌 위치/사유 표시 후 재주행 | 10 감소 |
| 보행자와 충돌 | 오토바이 정지 3초·충돌 위치/사유 표시 후 재주행 | 20 감소 |
| 건물·주행 경계 접촉 | 진행을 막고 유효 주행 방향 표시. 접촉 프레임마다 반복 차감하지 않음 | 첫 안은 별도 차감 없음 |
| 메뉴에서 끼임 복구 | 마지막 유효 주행 위치로 복귀하고 2초 정차. 같은 주문·가방·누적 시간/페널티 유지 | 10 감소 |

한 번의 연속 접촉은 한 사건으로 센다. 접촉이 끝나고 최소 1.5초가 지난 뒤 다시 부딪힌 경우에만 같은 대상의 새 사건을 만들며 유예 중에도 대상을 통과하는 지름길로 쓰지 못하게 한다. 오토바이를 NPC가 밀어 건물 밖·지도 밖으로 보내지 않게 한다.

첫 안은 충돌로 음식을 파괴하거나 재고를 차감하지 않는다. 주행 정지 시간과 안전 성과를 통해 대가를 느끼고 같은 주문을 마칠 수 있게 한다. 안전 점수 0도 즉시 게임오버로 만들지 않고 기본 배달을 끝낼 수 있게 하며 결과에서 사고 기록과 개선점을 확인한다.

정산 화면은 완료 건수·소요시간·충돌 종류/횟수·안전 점수·기존 배달 보수와 미니게임 추가 보상을 구별한다. 첫 경제안은 안전 점수가 추가 보상에만 영향을 주도록 제안하며 타인의 기사 보수·기존 플랫폼 차액·제한 자금을 확장 자금으로 바꾸지 않는다. 실제 금액·성장 자금 귀속·카페 개설 비용은 미정이며 이 문서에서 기존 원장을 변경하지 않는다.

## 5. 중단·재시작·경영으로 귀환

- 첫 회차의 직접 조작은 동네 주행 화면 안에서 수행한다. 이 안의 확대·축소로 길을 살피되 구/광역의 다른 경영 화면은 회차 종료 또는 명시적 중단 뒤 이용한다. 이는 운전 입력의 작업 범위이며 사업 해금·권한과는 별개다.
- r144의 긴급 알림·복구 진입은 주행 중에도 유지한다. `주행 일시정지 후 긴급 업무 열기`를 명시적으로 선택하면 공통 가상 시간을 멈추고 운전 입력·오토바이·주문·가방·누적 시간을 보존한 채 해당 업무를 확인한다. 같은 주행으로 돌아온 뒤 `계속`을 눌러 재개하며, 일반 지도 전환 제한이 긴급 진입을 막지 않는다.
- 일시정지는 r144의 같은 가상 시간에 적용한다. 카메라만 멀리 갔다고 주문이 취소되거나 시간이 자동 초기화되지 않는다.
- 중단은 확인된 주문·가방·진행 기록을 일관되게 종료 처리할 후속 계약으로 명시하며, 미완료 주문은 완료 보상을 주지 않는다. 이미 받은 보상을 중단/재진입으로 다시 주지 않는다.
- 재도전은 같은 지도·주문·교통 초기 조건과 seed로 새 시도 고유 식별자를 만든다. 이전 시도의 가방·주문 완료·페널티를 섞거나 같은 시도를 다시 열어 보상을 중복 지급하지 않는다.
- 완료 뒤 결과→기존 지도/운영 관점으로 돌아간다. 성과로 활동권·자금·새 사업을 확장하는 상위 방향은 유지하되 첫 주행 검토에 카페 개설·창고·우유 사슬을 필수 선행으로 연결하지 않는다.

## 6. 구현 인계 전 확인할 것

Unity의 방향키·접촉은 의도와 후보 사건을 전달하고, 픽업·가방·전달·보상·페널티는 같은 회차의 Core 상태·주문 ID·명령 ID·Revision으로 검증한다. 콜라이더·애니메이션이 원장 권위를 갖지 않는다. 이동/충돌 상태의 책임과 기존 자동 이동과의 제어권 전환은 후속 구현 명세에서 결속한다. Claude가 구현 중인 공통 Core 계약을 이 문서만으로 바꾸지 않는다.

[r122](pickup-riding-threeway.prototype.r122.md)는 12초 사전 렌더·영상 재생 시제품이다. 현재 방향키 운전·충돌·Space 입력을 구현했다는 증거가 아니다. 먼저 도로 판독·주행 위치·교통·가방/상호작용이 보이는 [시각안](../../../../Architecture/화면시안선행제작절차.md)을 검토하고, 필요한 주체 준비·전문 연구·WI 하나의 E1~E7 명세·승인 판본/hash·쓰기 경로를 결속한다. 새 공식 Scene·실제 도로 운행·운영 주문 처리를 자동 승인하지 않는다.

| 확인할 상황 | 통과 기준 |
| --- | --- |
| 도로 판독 | 일반도로·이면도로·보도·입구·정차 영역과 전방 교통을 같은 화면에서 구별 |
| 기본 조작 | 방향키·키 놓기·대각선·입력 초점·정차 표시가 예측 가능하며 길찾기 자동 운전이 아님 |
| 정상 두 주문 | 픽업→가방 `1/1`→주행→전달→`0/1`→별도 수령 확인·정산이 정확한 주문 순서로 이어짐 |
| 잘못된 Space | 주행 중·거리 밖·미준비·가방 가득·다른 매장/수령지에서는 상태 무변경과 이유 표시 |
| 충돌과 회복 | 차량/보행자 페널티, 연속 접촉·유예·안전 점수 하한·끼임 복구가 기록과 일치 |
| 표시 옵션 | 장식 끄기·시점·가림 변경으로 필수 교통 주체가 숨거나 충돌 규칙이 바뀌지 않음 |
| 반복·중단·재진입 | Space 연타·동일 명령·저장/복원·재도전으로 물품·완료·보상이 중복되지 않음 |
| 긴급 업무 진입·귀환 | 명시적 정지 뒤 업무 확인과 같은 주행 복귀가 가능하고 주문·가방·입력·누적 기록이 유지됨 |
| 기존 업무 보호 | 일반 기사 자동 이동·배차·정산 및 Claude 진행 작업에 변경을 강요하지 않고 결과를 별도 검증 |

이번 완료는 세부 기획과 문서 연결이다. 코드·주행 모형·새 시안·영상·실제 플레이·Core 계약·예약·commit/push는 변경하지 않는다. 위 항목은 후속 검증 기준이며 이번에 시험 성공이나 E 승격으로 보고하지 않는다.
