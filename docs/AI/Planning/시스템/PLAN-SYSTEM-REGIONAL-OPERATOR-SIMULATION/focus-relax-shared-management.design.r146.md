## 1. 같은 경영을 두 방식으로 즐긴다

후속 [역할별 미니게임 r147](multi-role-minigames-and-realistic-recipes.design.r147.md)은 집중·이완을 바리스타·창고 피킹/포장에도 적용하는 사용자 방향을 문서화했다. 이 문서의 기사 네 구간은 배달 프로필로 유지하고 보너스 자격·인계 원칙을 역할별 작업 구간에 적용한다. 기존의 배달 한정은 첫 상세 표본의 범위였으며 다양한 역할의 후속 기획을 금지하지 않는다. r147은 새 역할이 이미 구현됐다는 근거가 아니다.

**집중 모드는 직접 수행하고, 이완 모드는 맡겨 두고 관찰한다.** 같은 세계·세션·시계·주문·가방·재고·자금·성장 기록을 사용하며 모드 전환으로 새 게임이나 새 회차를 만들지 않는다.

| 참여 방식 | 사용자가 하는 일 | 업무의 진행 |
| --- | --- | --- |
| 집중 | 선택한 기사 한 명을 방향키로 운전하고 Space로 픽업·전달 | r145의 유효한 직접 입력과 기존 Core 규칙으로 수행 |
| 이완 | 기사·동네·창고의 진행을 관찰하고 방침·중요 결정을 선택 | 기사가 기존 운영 방침에 따라 정상 배달·수령 확인·정산을 이어감 |

이완에서도 정상 사업 수익과 성장은 계속된다. 개업·큰 지출·중요 예외는 사용자 선택으로 남기며 정해진 방침·예산·가능 행동을 넘어 임의로 승인하지 않는다. 기존 엔진은 후보를 반환하고 정상 업무의 자동 수행 주체가 허용된 Core 명령을 사용한다. 엔진·NPC 외형이 상태를 직접 확정하지 않는다.

이 기획은 전체 경영의 참여 방식 원칙을 정하되, 첫 상세 직접 조작은 r145의 배달에 한정한다. 창고 관찰에서 집중을 선택했다고 새 피킹·포장 미니게임이 구현된 것으로 표시하지 않는다. 해당 업무의 직접 조작이 미준비이면 준비 상태와 이유를 표시한다.

게임이 실행되고 가상 시간이 재생되는 동안의 자동 업무다. 종료 후 따라잡기·오프라인 수익을 새로 추가하지 않는다. **일시정지**는 별도 기능이며 이완으로 바꿨다는 이유로 시간이 멈추지 않는다.

### 참여 방식과 지도 관점의 분리

지도 높이는 **어떤 경영을 볼지**, 집중·이완은 **어떻게 참여할지**를 정한다. r144의 높이에 따른 자동 초점과 r146의 제어권 전환은 서로 다른 선택이다. 확대·기사 따라보기·창고 내부 진입만으로 직접 조작이 시작되지 않는다. 이완에서는 r144의 동네·구·광역·창고 내부를 살피고 관련 업무로 돌아갈 수 있다. 집중에서는 r145의 직접 주행 화면과 긴급 진입/귀환을 따른다.

`집중/이완`은 플레이 참여 방식이며 기술 실행 경계 `SsalddelExecution:Mode`의 `Simulation/Operational`을 추가·변경하는 설정이 아니다. 화면의 모드 선택만으로 NPC의 경·무념·등급을 올리거나 게임의 성장 결과를 확정하지 않는다.

## 2. 진행 중인 일을 이어받는 제어권 전환

| 상황 | 동작과 보존 |
| --- | --- |
| 집중 → 이완 | 유효한 안전 정차 상태를 거친 뒤 자동 기사에게 넘긴다. 같은 기사·오토바이·위치·주문·가방·진행 단계를 이어받는다. |
| 이완 → 집중 | 선택 기사가 조작 가능한 안전 정차 상태에 도달하고 주행 화면이 준비되면 사용자에게 넘긴다. 준비 전에는 자동 수행을 유지하고 전환 대기를 표시한다. |
| 전환 중 | 현재 수행 주체와 전환 대기를 표시한다. 같은 Tick에 사용자 운전과 자동 운전을 동시에 적용하지 않는다. 새 수행 주체는 이전에 누르고 있던 방향키·Space를 이어받지 않는다. 인계 뒤 이전 수행 주체의 늦은 새 입력은 거절하며 이미 확정된 명령 결과는 보존한다. |
| 픽업·전달 요청 처리 중 | 해당 명령의 결과/실패와 최신 Revision을 확인한 뒤 인계한다. 전환을 이유로 취소·재제출하거나 가방과 주문을 따로 갱신하지 않는다. |
| 경로·정차·상태 미준비 | 이유를 표시하고 현재의 유효한 제어권·상태를 보존한다. 순간이동·가짜 완료·주문 초기화로 전환을 성공시키지 않는다. |

전환 전후의 공통 진행 시간·누적 지연·충돌·페널티·완료·정산 기록은 유지한다. NPC는 같은 도로·정차·조리 준비·가방·충돌 규칙을 따른다. 자동 수행 중 사건과 직접 수행 중 사건의 수행 주체를 구별하고, 이완 전환이 이미 발생한 직접 조작 페널티를 지우지 않게 한다.

화면을 멀리 보고 있을 때도 충돌·수령·정산은 같은 세션의 상태로 처리한다. 다시 집중하면 현재 기사와 진행 중인 업무로 카메라·입력 초점을 결속하며 돌아온 위치에서 신규 조작을 받는다. 기존 r145의 긴급 업무 진입은 명시적 공통 시간 정지와 상태 보존을 유지한다.

## 3. 기본 수익과 직접 완료 구간의 추가 보너스

사용자 확정은 **기본 사업 수익 동일 / 직접 조작 추가 보너스 / 완료한 업무 구간별 인정**이다. 같은 주문·같은 조건에는 같은 기존 기본보수율을 적용하며 수행 방식만으로 차등하지 않는다. 완료 시간·건수까지 같다고 보장하는 뜻은 아니며 실제 결과·지연·비용에 따른 기존 업무 판정과 정산은 유지한다.

| 구간 | 직접 완료의 기준 |
| --- | --- |
| 매장까지 주행 | 해당 주행 구간 시작부터 매장 정차 조건 충족까지 직접 수행 |
| 픽업·가방 적재 | 픽업 가능 상태에서 직접 Space로 요청하고 Core가 해당 픽업·적재 결과를 확정 |
| 배송지까지 주행 | 해당 주행 구간 시작부터 정확한 수령지 정차 조건 충족까지 직접 수행 |
| 전달 | 전달 가능 상태에서 직접 Space로 요청하고 Core가 기사 전달 결과를 확정 |

각 구간을 처음부터 끝까지 직접 수행하면 추가 보너스 자격을 얻는다. 중간에 자동 수행이 섞인 현재 구간은 직접 완료 자격이 없으며, 이후 새 구간부터 다시 직접 완료할 수 있다. 이미 직접 완료한 이전 구간의 자격은 이완으로 바꿔도 보존한다. 같은 구간 안에서 집중으로 돌아와도 자격이 되살아나지 않는다. 구간 시작·완료·제어권 인계의 경계는 Core 사건 순서와 Revision으로 판정하고 저장/복원에서 유지한다.

전환 횟수·제자리 이동·거리 반복·동일 행동 재요청은 보너스가 아니다. 주문·시도·구간의 같은 완료 기록을 한 번만 인정하며, 화면 전환·저장/복원·동일 명령 재처리로 보너스 자격이나 지급을 복제하지 않는다.

구간 완료 시에는 자격만 기록하고, 주문자의 **별도 수령 확인과 기존 정산 조건 충족 뒤** 지급한다. 기사 전달 Space가 주문자 확인·보수를 동시에 확정하지 않는다. 자동으로 남은 구간을 수행해 정산까지 마쳐도 앞서 획득한 직접 구간 자격은 유지한다.

결과 화면은 기본 수익·직접 완료 구간·직접/자동 수행 사건·안전 성과·추가 보너스를 구별한다. r145의 직접 운전 안전 점수와 페널티는 전환으로 초기화하지 않는다. 금액·안전 점수 반영 계수는 아직 미정이므로 임의의 보너스 총액을 확정하지 않는다.

**경제 기획의 남은 경계:** 개인 창업 자금/사업 확장 자금 중 귀속, 기준 금액·계수는 r145의 미정 항목으로 보존한다. 이번에 기존 기사 보수·플랫폼 정산·제한 자금을 옮기거나 모드 전환으로 현금을 추가하지 않는다.

## 4. 후속 반영과 확인 기준

r58 자동 업무·r145 직접 주행·r144 경영 관점에 r146 연결을 남긴다. r145의 다른 지도 화면 제한과 자동 운전/자동 픽업 금지는 집중 주행에 적용한다. 이완의 자동 픽업·전달도 같은 Core 조건과 별도 수령 확인을 따른다. 이완 전환 후의 지도 관찰은 회차 종료/중단이 아니라 같은 업무를 맡긴 상태로 다루며 모드 선택만으로 주문 중단·가방 초기화를 실행하지 않는다.

| 확인할 상황 | 통과 기준 |
| --- | --- |
| 같은 주문 혼용 | 위치·주문·가방·수량·시간·Revision이 전환 전후 이어짐 |
| 제어권·연타 | 전환 중 중복 운전·픽업·전달, 이전 키 입력 잔류가 없음 |
| 정상 자동 업무 | 이완에서도 준비→픽업→배송→별도 수령→정산이 진행되며 기본 수익·성장이 이어짐 |
| 경영 결정 | 개업·큰 지출·중요 예외는 사용자 선택으로 남고 자동 수행 한계를 넘어가지 않음 |
| 페널티 보존 | 반복 전환으로 기존 지연·충돌·안전 성과가 지워지지 않음 |
| 구간 자격 | 전 구간 직접·전 구간 자동·중간 혼용을 구별하고 직접 완료 구간만 한 번 인정 |
| 지급 시점 | 전달 직후 미수령/정산 미완료 상태에 지급하지 않고, 이후 재처리로 중복 지급하지 않음 |
| 관찰·복귀 | 이완 중 다른 지도·창고를 관찰한 뒤 같은 기사·현재 업무로 집중 복귀 |
| 미준비·중단·저장 | 전환 미준비와 주문 중단을 혼동하지 않고 저장·재진입에서도 업무/자격 기록이 정합 |

실제 구현에서는 기존 세션의 수행 주체·인계 요청/승인·구간 완료 기록을 같은 명령/Revision에 결속해야 한다. 정확한 계약과 쓰기 경로는 현재 Claude 통합 기준선을 확인한 뒤 별도 승인 명세로 정한다. 새 공개 API·실행 모드·Core 계약을 이 문서만으로 추가하지 않는다.

이번 산출물은 **참여 방식·제어권 인계·자동 수행 범위·보너스 자격의 문서화**다. 코드·Game View·실제 입력·Save/Replay·화면·경제 지급을 실행/검증한 결과가 아니다. 문서 링크·diff·진입 연결만 확인하며 시각안과 E1~E7 구현 명세는 후속으로 둔다.
