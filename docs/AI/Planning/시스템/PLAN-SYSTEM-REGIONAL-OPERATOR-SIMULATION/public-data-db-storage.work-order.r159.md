## 1. 이번에 마치는 결과

기존 로컬 개발 DB에 조사 후보의 안내 정보와 실제 확보한 관측 자료를 구분해 저장한다. 원본의 출처·파일 지문·취득 시각을 보존하고, 기준일·지역·항목·단위를 확인한 수치만 기존 정규화 테이블에 반입한다. 안내 페이지나 HTML을 실제 관측 자료의 취득으로 세지 않는다.

| 구분 | 저장 방식 | 완료 판단 |
| --- | --- | --- |
| 조사 후보 26항목 | `observer-public-data-research` 범위의 개별 JSON과 DB 원본 계보 | 후보별 조회가 가능하고 원 조사 파일의 SHA를 역추적. 실제 공급자 자료 취득과 구별 |
| 이미 확보한 실제 원문 | 기존 Source/Dataset 식별자·SHA·취득 영수증을 보존한 원본 계보 | 파일 검증 뒤 실제 DB 행과 연결 |
| 수치 관측 | 원본 외래키와 지역·지표·기준시점·단위·판본을 가진 정규화 행 | 별도 연결로 저장 결과를 재조회하고 예상값/건수와 대조 |
| 기준시점·코드 대응 미확인 참조 | 원본만 저장, 정규화는 보류 | 기준일을 취득일로 대신 채우지 않음 |
| 키·신청·파일 취득 미완료 후보 | 안내 정보·미취득 사유만 보존 | 관측 수치·지역 값을 만들지 않음 |

원본 파일은 기존과 같이 로컬 원본 저장소에 두고 DB에는 경로·SHA와 계보를 저장한다. 정규화 관측값은 DB에 저장한다. 모든 원본을 DB BLOB으로 복제하거나 새로운 DB 제품을 추가하는 작업이 아니다.

## 2. DB와 관계

현재 `PublicDataIngestionDbContext`의 `public_data_ingestion_runs` → `public_data_raw_snapshots` → `public_data_normalized_records` 관계를 재사용한다. 원본의 `EvidenceAsOfUtc`는 모를 때 null로 두고, non-null 기준시점을 요구하는 정규화 행은 시점을 확인한 자료에만 만든다. 기존 `public_data_region_mappings`의 미확인 대응을 임의 확정하지 않는다.

실제 DB의 관련 시각 10열은 모두 마이크로초 정밀도다. 기존 관세청 영수증의 7자리 수집시각은 DB 입력에서만 6자리로 절삭하며 차이는 1마이크로초 미만이다. 정확한 원래 시각은 원본 영수증과 정규화 행의 `TextValue.originalCollectedAtUtc`에 보존한다. 관측 기준시점은 바꾸지 않고 이 변환은 준비 판본 `observer-db-preparation.r2`로 명시한다. 도구가 입력 시각을 조용히 변환하지 않으며 저장 후 트랜잭션 안에서도 재조회해 확인한다.

서울 공급자의 8자리 통계 지역 코드를 행정기관의 행정동 코드와 자동으로 동일시하지 않는다. 대응이 확인되기 전에는 공급자 범위 지역과 검토 대기 품질로 보존한다. 분기 집계 유동인구를 특정 도로·건물의 실시간 인원으로 배분하지 않는다. 국가 농지·미국 가격·월별 무역도 원래 공간·시점·통화·중량의 의미를 유지한다.

## 3. 실행 경계와 파일 소유

- DB는 실제 소유·가동·compose 작업경로를 확인한 `hongdal-mysql-1 / 127.0.0.1:13306 / hongdal_dev`로 제한한다. 기존 비root 계정을 메모리에서만 사용한다.
- 새 도구는 `eng/observer-public-data-db/`에 둔다. 기존 고정일·최대7입력의 `eng/neighborhood-data-collection`과 기존 반입 모드의 범위를 완화하지 않는다.
- 반입 명세와 원본은 `artifacts/local/public-data-db-20261113/`에서 준비하고 SHA를 고정한다. 기존 실제 원문은 원래 로컬 경로를 참조한다.
- 코드·문서 쓰기는 위 새 도구, 이 문서, 분야 README, `PLANNING.md`, `CURRENT_WORK.md`, 수집 README와 해당 로컬 증거로 제한한다. 제품 서버·Unity·개인 업무 자료·기존 예약 설정은 수정하지 않는다.
- DB Migration·테이블 생성·컨테이너 재시작·운영 DB·배포·팩/Drive/Excel/레이어·게임 소비 연결은 이번 범위에 포함하지 않는다.

## 4. 반입·재실행·검증

1. 반입 명세 SHA, 로컬 허용 경로, 원본/정규화 JSON SHA, 행수 상한, 필수값·시점·단위를 먼저 검사한다.
2. 읽기 전용 미리보기로 기존 행·충돌과 예상 삽입량을 확인한다. 안내 정보와 관측 자료의 건수를 따로 보고한다.
3. 새로운 바인딩만 하나의 트랜잭션에서 추가한다. 기존 키의 다른 값은 조용히 덮어쓰지 않고 거절한다.
4. 새 연결로 실제 저장 결과를 검증한다. 같은 반입을 다시 적용하면 수집 Run과 `LastSeen`까지 쓰기 0이어야 한다.
5. 오프라인 오류 사례와 실제 DB 전후 건수·원본 연결·결측·기준일·단위·재실행 결과를 영수증에 남긴다. 비밀값·연결 문자열·개인 행은 남기지 않는다.

## 5. 확정·미정·다음 단계

**확정:** 지금은 DB 저장까지 진행한다. 분야별 선택 설치·표현 레이어·게임 참여는 서로 분리할 수 있는 후속 방향이다. 실제 자료와 안내 정보, 원본과 정규화, 로컬 저장과 제품 연결의 완료를 각각 구분한다.

**미정:** 사용자에게 제공할 팩 단위·다운로드 경로·화면·기본 레이어·공개 배포 조건. 이번 저장만으로 이를 승인하거나 구현하지 않는다.

**다음 질문:** 이번 DB 범위를 완료하는 데 추가 사용자 결정은 필요하지 않다. 실제 반입 결과와 취득이 막힌 자료를 반환한 뒤 후속 소비 범위를 정한다.

## 6. 실행 결과

실제 `hongdal_dev`에 원본/안내41개·수집 실행41개·정규화45,654행을 추가하고 commit했다. 44개 준비 입력 중 기존 관세청 원본3개·관측12행은 원문과 DB의 의미가 일치함을 확인해 중복 반입하지 않았다. 신규 수치45,653행과 BLS 결측1행, 기존 무역12행을 합쳐 이번에 확인한 관측은45,666행이다.

DB 전후는 Raw **342→383**, Run **346→387**, Normalized **71,081→116,735**, RegionMapping **3→3**이다. 모든 신규 행은 내부 검토용이고 사람의 해석·배포 승인을 자동 부여하지 않는다. 기존 관세청3원본·12정규화 행은 모든 열과 `FirstSeen/LastSeen`의 전후 지문이 같다. 기존 수집 Run은 사전에 캡처한 필드·참조의 보존까지 확인했으며 사전 전체 행 지문이 없어 다른 필드까지 불변이라고 확대하지 않는다.

최종 반입 명세는 `artifacts/local/public-data-db-20261113/manifest.db-storage.json`, SHA256은 `35a3bd3a202dd5ddae279bb3f5f0c8dc06100add4a99ab788294be56d98becee`다. 새 도구는 [반입 도구 README](../../../../../eng/observer-public-data-db/README.md)를 따른다. 이미 저장된 무역을 제외할 때도 전체44개 명세와 준비 파일의 SHA가 기존 의미 검증 증거와 일치해야 한다.

`apply.json`은 실제 commit·트랜잭션 안 재조회·새 연결의 전체 필드 검증 성공을 담는다. 동일 명세의 `reapply.json`은 **쓰기0·삽입0·Run 추가0·전후 건수 동일·strictNoOp=true**, 독립 명령 `verify.json`도 전체41개와 관측45,654행의 일치를 확인했다. 기존 무역의 사전/사후 증거는 `already-stored-verified.json`과 `already-stored-verified.after.json`이다. 원문 SHA·45,666행의 값/기간/단위/키·결측·지역 범위를 독립 대조했고, 최종 도구 빌드 오류0/경고0·오프라인24검사·오래된 제외 증거 거절2검사를 통과했다. 준비 스크립트 재실행에서도 명세 SHA가 같다.

한우 후보 `15162090`은 공식 연결을6회 확인했으나 최종 응답은 통계표 HTML이며 CSV를 취득하지 못했다. 이 자료는 후보 안내만 저장했으며 실제 한우 관측은0행이다. 키·신청이 필요한 나머지 신규 분야도 안내와 실제 취득을 구별한다. 기존4개 수집 예약은 변경하지 않았고, 정기 수집 결과의 이번 DB 도구 자동 연결은 후속이다.

실행 검증은 이 로컬 CLI와 DB 영속 결과에 한한다. Unity/Windows 실행판·게임 소비·팩/레이어·Drive·Excel·운영 서버·Migration·commit/push는 이번 작업에서 수행하지 않았다. 자동 승인 검토가 실패한 오프라인 시험의 임시 빌드 폴더 삭제를 `blocked by policy`로 거절해 해당 Git 제외 폴더는 보존했다. 추가 정책 사유는 반환되지 않았으며 재시도·우회하지 않았다.
