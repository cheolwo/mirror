## 점심 피크 이미지 시안

기존 Unity 실행 화면을 참조해 내장 이미지 생성 도구로 점심 장면 한 장을 만들었다. 역·상권 주변의 작은 사람 무리와 상대적으로 한산한 주거 골목, 도로 위 일반 차량, 더 선명한 기존 기사 오토바이를 대비했다. 현재 지도 중심의 상단·하단·오른쪽 패널 구성을 유지한다. 화면 안에 가상 유동 표현·이미지 시안임을 표시했다. 공공자료를 실제 적재한 화면이나 Unity 실행 결과가 아니며 코드와 업무 규칙은 바꾸지 않았다.

## 2D 지도에 사람과 차량의 흐름을 더한다

플레이어는 지도에서 사람들이 몰리는 곳과 이동이 느려지는 길을 보고, 어느 곳의 주문과 배송을 더 살펴볼지 판단한다. 현재의 넓은 지도·오토바이 기사·매장 핀·하단 성장 영역을 유지하고 배경 흐름만 독립적으로 더하는 구성을 권한다. 3D 전환이나 지도 전체 교체는 이번 표현의 전제가 아니다.

| 관찰 대상 | 동네를 확대했을 때 | 멀리 축소했을 때 |
| --- | --- | --- |
| 사람 | 작은 탑다운 사람 모형이 가상의 이동 통로를 따라 걷는다. 밀집한 곳에 더 많이 나타난다. | 개별 사람을 줄이고 부드러운 밀집도와 유입·유출 방향을 표시한다. |
| 일반 차량 | 도로 위의 작은 차량이 이동한다. 확인된 속도 자료를 쓸 때는 혼잡 구간의 움직임이 느려진다. | 주요 도로의 혼잡 정도만 요약한다. |
| 업무 기사 | 기존 색깔 오토바이와 선택 강조를 유지한다. | 필요한 업무 위치와 주문 상태를 요약한다. |

기본 보기에서는 사람과 차량을 낮은 대비로, 기사와 주문을 선명하게 둔다. 밀집도 색상은 관찰 보조로 켜고 끌 수 있게 한다. 서울 전역은 구별 분포, 구 단위는 동네별 분포, 동네 단위는 움직이는 소수의 대표 캐릭터로 이어진다. 실제 집계 인구 전원을 화면의 캐릭터로 만들지 않으며, 캐릭터 하나를 실제 사람 한 명의 위치로 해석하지 않는다.

## 공식 자료가 알려주는 것과 가상 표현의 경계

2026-11-11에 공식 안내를 확인했다. 데이터 본문 수집·이용 신청·게임 적용은 아직 하지 않았다. 각 자료의 기준일·공개 지연·공간 단위와 이용 조건은 실제 수집 판본에 함께 기록한다.

| 자료 | 확인한 제공 범위 | 활용 제안과 제한 |
| --- | --- | --- |
| [서울 생활인구](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do) | 서울시·KT 추계. 현재 안내의 비교표는 시간 단위·250m 격자·4일 후 공개로 표시한다. | 시간대별 사람이 많은 영역의 근거. 개별 보행 궤적은 아니다. 화면 일부에는 과거 집계구 안내도 남아 있어 실제 파일의 공간·시간 판본을 확인한다. |

| [서울 실시간 도시데이터 안내](https://data.seoul.go.kr/dataVisual/seoul/guide.do) | 주요 장소의 추정 인구와 도로소통 등을 결합한다. 인구·도로소통 갱신은 각각 5분으로 안내한다. | 지원 장소에서 최근 혼잡도를 참고한다. 모든 법정동·골목을 덮는 자료로 가정하지 않는다. 장소 수는 다른 공식 소개 간 차이가 있어 해당 자료의 지원 장소 목록을 기준으로 확인한다. |

생활인구는 그곳에 머무는 규모, 생활이동은 지역 사이를 오가는 흐름이다. 두 자료를 분리해 사용한다. 유동인구가 많다는 이유만으로 배달 주문을 같은 비율로 늘리지 않는다. 방문 식사 수요와 주거지 배달 수요의 연결은 후속 게임 규칙으로 따로 검토한다.

현재 게임은 법정동을 사용하고 일부 공공자료는 행정동·격자를 사용한다. 경계 교차나 검토한 대응표로 연결하며, 면적 비례 배분 등을 사용할 경우 추정이라고 표시한다. 자료가 없는 곳은 미확인으로 두고 0명·원활로 해석하지 않는다. TOPIS 링크와 현재 도로 표본도 같은 ID라고 가정하지 않고 위치·도로명·방향을 대조한다.

## 현재 지도에서 필요한 좁은 변경

현 검토 프로젝트의 `SagajeongDispatchMap.cs`, `SagajeongDispatchTiles.cs`, `SagajeongDispatchCityBoard.cs`를 읽었다. 도로 배경과 건물 표현, 화면에 들어온 타일의 교체, 동네·구·서울 전환이 이미 있다. 배경을 매 프레임 다시 생성하지 않고 그 위에 움직이는 사람과 차량을 별도로 그리는 편이 적합하다.

현재 화면이 사용하는 도로 선분과 도시 배경 이미지에는 보도·횡단보도·건물 출입구 연결을 판정하는 근거가 확인되지 않았다. 첫 표현은 도로 주변에 둔 검토된 가상 보행 통로에서 움직이게 한다. 차도 중심을 따라 걷거나 건물을 통과하는 표현을 피하며, 이를 실제 보행 경로라고 부르지 않는다. 실제 보행망은 별도 자료를 확보한 뒤 연결한다.

사람·일반 차량은 기본적으로 클릭을 받지 않는다. 기존 기사·매장·주문 선택을 보존하고 캐릭터가 핀을 가리지 않게 한다. 동적 흐름은 배경보다 위, 업무 표식보다 아래에 그린다. 실제 클릭 우선순위는 현재 매장과 기사 선택 처리까지 확인해 결정한다.

## 서버 없이 같은 도시의 하루를 재생한다

자료를 준비하는 단계에서 필요한 동네와 시간대만 골라 출처·관측일·지역 ID·단위·가공 방식을 묶어 로컬에 저장한다. 게임은 기존 가상 시계로 이 묶음을 읽고, 같은 초기 조건과 난수값이면 같은 대표 인물과 차량 흐름을 재생한다. 배속·일시정지도 기존 가상 시간에 맞춘다.

카메라가 벗어난 지역의 캐릭터 표시는 해제하되 지역의 시간과 집계를 초기화하지 않는다. 화면에 보이는 캐릭터 수에 상한을 두고, 더 많은 인구는 캐릭터 전수 생성 대신 밀집도 표현에 반영한다. 공개자료의 실제 관측 시각과 게임 안의 시각을 구분하므로 오프라인 재생을 실시간 관측으로 표시하지 않는다.

첫 회차는 기존 사가정 동네의 역 주변과 주거 골목을 대비하는 좁은 범위로 제안한다. 오전·점심·야간의 사람 밀집과 일반 차량 흐름만 비교하고 기존 주문 수·배차·정산 규칙은 바꾸지 않는다. 처음에는 검증 가능한 합성 흐름을 명시하고, 공개자료를 연결하면 사용한 공간·시간 범위를 함께 보인다.

## 시안 다음에 확인할 조건

- 같은 카메라에서 세 시간대의 밀집도와 이동 차이를 긴 설명 없이 구분할 수 있다.
- 기사 오토바이와 매장 핀의 식별·선택, 배차·배송·정산이 유지된다.
- 확대·축소 때 군중이 갑자기 사라지는 느낌을 줄이고, 표시 해제와 도시 집계의 진행을 구분한다.
- 같은 조건의 재실행·일시정지·배속에서 흐름이 재현되고 네트워크 없이 진행된다.
- 미확인 자료·가상 경로·집계 추정과 실제 관측의 의미를 구분한다.

확정된 사용자 의도는 지도에서 유동인구와 교통 흐름을 직관적으로 읽는 것이다. 2D 유지·줌별 표현·첫 지역의 범위는 이번 추천이며 아직 시안이나 구현 승인으로 간주하지 않는다. 경·소득의 성장 목표를 판단하는 데 필요한 도시 상황을 보여주는 보조 층이며, 군중의 증가 자체를 성장이나 참여자 소득 향상으로 판정하지 않는다.
