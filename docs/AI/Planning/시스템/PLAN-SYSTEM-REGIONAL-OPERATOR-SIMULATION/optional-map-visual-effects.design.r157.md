## 1. 확정 — 표현 취향을 사용자가 고른다

핀 낙하·착지 파동·운송선 위 흐르는 빛 등 장식 효과는 사용자가 선택하도록 한다. r156의 ‘흐르는 빛을 넣을지’ 질문은 **선택형 효과로 제공하는 방향**으로 정리한다. 처음부터 켜 둘지와 실제 제어 화면은 아직 정하지 않았다.

효과 설정은 **집중/이완 참여 방식과 독립**이다. 직접 운전 중에도 간단한 표현을 쓸 수 있고, 관찰 중에도 효과를 켤 수 있다. 효과를 켜거나 끄는 것으로 수행 주체·업무 자동화·시계/배속·보상 자격·기사/차량 이동·수요가 바뀌지 않는다. 컴퓨터의 렌더링 표현량과 Simulation의 업무 처리량도 구별한다.

## 2. 처음 제안하는 선택 방식

| 선택 | 제안하는 모습 |
| --- | --- |
| 간단히 | 정적인 핀·운송 관계선·방향·상태 문구와 건수 중심. 낙하·파동·흐르는 빛은 끔 |
| 효과 사용 | 같은 정보 위에 짧은 낙하·착지 파동·약한 방향 안내 빛을 더함 |
| 개별 설정 | 핀 낙하 / 파동 / 흐르는 빛을 각각 켜고 끌 수 있는 후속 선택 |

이 표는 프리셋 이름·구성의 제안이다. 사용자 승인 범위를 세 가지 UI나 각 항목의 기본 ON으로 확대하지 않는다. 첫 기본값은 **간단히**를 추천하되 미정으로 남긴다. 다른 배경 보행의 끄기 기준은 r143을 유지하며 이번 선택이 교통/기사의 실제 Simulation을 숨기거나 멈추는 설정은 아니다.

## 3. 효과를 꺼도 유지하는 정보와 조작

- 새 주문은 정적 표식·새 건수/문구와 기존 목록으로 알아차린다. 운송의 출발/도착·방향·현재 상태와 선택 경로를 유지한다.
- 파동·빛·낙하를 생략해도 현재 주문·화물·차량·작업 대기열과 개별 ID/Revision은 동일하다. 장식을 끄는 설정을 업무 필터나 알림 전체 끄기로 사용하지 않는다.
- 지연·실패·중요 결정과 복구 진입은 계속 확인할 수 있게 한다. 애니메이션을 끈 것을 알림 확인·문제 해결·작업 완료로 세지 않는다.
- 정적 아이콘·모양·방향·문구를 함께 사용한다. 운영색·선택 강조·운송 상태 의미를 그대로 유지하고 색이나 소리만으로 정보를 전달하지 않는다.
- 움직임 감소에서는 같은 정적 정보를 제공한다. 운영체제의 움직임 감소 설정을 초기값에 반영할지는 실제 구현 환경과 후속 시각안에서 검토한다.

## 4. 설정 변경과 공통 처리

기존 r154의 상태/사건→중복 확인→위치 해석→연출 처리에서 **표현 허용/감소 규칙**을 적용한다. 실제 주문·운송 상태와 사건 수신/소비는 효과의 ON/OFF와 분리한다.

진행 중 효과를 끄면 장식만 정리하고 최신 상태 표식을 즉시 유지한다. 다시 켜도 꺼져 있던 동안의 주문을 한꺼번에 낙하시키거나 이전 사건을 다시 재생하지 않는다. 중복 방지 기록과 중요 알림의 확인 상태도 초기화하지 않는다. 일반 사건·현재 업무는 기존 목록에서 계속 확인한다.

설정은 플레이어 개인의 표현 취향으로 분리하는 안을 제안한다. Hosted의 다른 플레이어 화면이나 공용 세계 상태를 바꾸지 않는다. 재실행 후 취향 유지도 제안하지만 저장 위치·스키마·Migration·기기 간 동기화는 아직 설계/구현하지 않았다. 기존 업무 Save를 임의로 수정하지 않는다.

## 5. 후속 검토와 현재 한계

동일한 신규 주문/운송에서 효과 ON/OFF·중간 전환·집중/이완·정지/배속·재조회/복원·화면 밖 재진입을 대조한다. 정보·선택·중요 알림과 권위 결과가 같고, 이전 효과를 재생하거나 보상을 중복 생성하지 않아야 한다. 실제 설정 UI는 별도 시각 검토와 승인된 구현 명세에 결속한다. 이번 문서만으로 설정 기능·Unity 입력·성능·취향 저장을 검증했다고 보지 않는다.

- **확정:** 지도 장식 효과를 선택형으로 제공한다. 흐르는 빛도 사용자가 고를 수 있는 효과에 포함하는 방향이다.
- **미정:** 프리셋 이름/구성·개별 토글의 배치·처음 켜지는 효과·강도·표현 취향 저장의 세부 계약과 실제 구현.
- **다음 질문 하나:** 처음 실행했을 때는 **간단히**로 시작하고, 원하는 사용자가 효과를 켜도록 할까? 첫 기본값으로 이를 추천한다.
