## 1. 확정된 기본 반복

**상황 확인 → 계획·선택 → 실행·관찰 → 결과 정리·회차 마감 → 다음 운영 준비**

운영 회차는 한 건 또는 명시한 작업 묶음에 대해 목표·계획·결과를 닫는 플레이 단위다. 같은 현실 날짜 안에서 여러 번 반복한다. 하루를 새로 만드는 명령이 아니며 r174의 현실 날짜별 일일 결산은 해당 날짜의 유효 기록을 별도로 누적/조회한다.

첫 안내에서는 작은 일 한 건으로 한 바퀴를 배운다. 이후에는 같은 진행 구조 안에서 여러 작업·자원·사업 범위를 다룰 수 있다. 정확한 확장 조건과 성장 보상은 첫 구현 관찰 뒤 정한다. 다음 작업은 회차 안에서 직무를 계속하는 진입이며, 매 한 건마다 전체 회차를 강제로 끝내게 하지 않는다.

직접 수행과 관찰/위임 모두 같은 회차 흐름을 이용한다. 안내 제공이 모든 시간 약속·실패 조건·업무 적격성을 제거하는 뜻은 아니다. 단계/안내를 넘긴 사실만으로 자금·경험·연구·사업권을 추가 지급하지 않는다.

## 2. 첫 검토용 구현 범위

**기존 배달 작업 한 건을 읽어 첫 회차를 안내하고, 같은 세션에서 두 회차를 이어 확인한다.** 현재 준비된 업무를 재사용하는 검증 표본이며 모든 플레이어를 배달로 시작시키는 규칙이 아니다. 새 직무 미니게임·전국/연구 해금·전체 성장 단계를 이 첫 범위에 함께 만들지 않는다.

| 국면 | 플레이어가 보는 것/선택 | 실제 결과와 경계 |
| --- | --- | --- |
| 준비 | 이번 대상 작업·해야 할 일·끝나는 조건. 관련 담당/방법 선택과 운영 시작 | 대상 주문의 기존 고유 ID/Revision을 결속. 첫 작업과 무관한 샘플 필수 안건을 입문 관문으로 강제하지 않음 |
| 수행·관찰 | 기존 직접 조작/자동 수행 경로와 현재 상태. 다음 필요한 행동을 안내 | 기존 Core/Kernel의 명령/응답이 실제 작업을 진행. 안내가 완료를 대신 만들지 않음 |
| 결과·마감 | 대상 작업의 확인된 결과·남은 일/이유·연결된 금액/시간 | 대상 작업의 권위 상태를 확인한 뒤 마감 가능. 대상과 무관한 다른 진행 업무는 그대로 유지 |
| 다음 준비 | 이번 회차가 끝났음을 읽고 다음 대상/기존 방침을 선택 | 같은 Core/Kernel과 기존 업무·원장을 이어 사용. 새 게임/다음 영업일을 시작하지 않음 |

표시 버튼명·강조 위치/안내 문구는 기존 화면 스타일 안에서 Claude가 선택하고 실제 화면으로 반환한다. 현재 국면과 다음 가능한 조작이 읽혀야 한다. 새 전면 화면 체계/시각 스타일로 확대하면 기존 시안 절차에 따라 따로 대조한다.

배달 표본의 직접 결과는 대상 주문의 전달 완료다. 전달을 이미 포함하는 후속 완료 상태(예: 기존 계약의 Settled)도 인정하며 Delivered 한 상태만 비교해 정상 완료를 놓치지 않는다. 실제 상태 값/판정은 수용 때 기존 계약에 결속한다. 정산 금액·지급/수금은 각 기록과 구별한다. 현재 전체 캠페인 집계를 한 주문의 보수/매출로 표시하지 않는다. 주문별 값이 연결되지 않았다면 미연결로 표시한다.

## 3. 마감 가능·대기·회복

- 대상 선택/요청이 처리 중이거나 작업이 진행 중이면 성공 마감으로 이동하지 않는다. 이유와 계속 수행/관찰/기존 복구 진입을 보여 준다.
- 안내를 접거나 지도/기존 작업 화면으로 이동해도 실제 진행 작업을 취소/복제하지 않는다. 같은 대상과 안내 문맥으로 돌아온다.
- 실패/보류의 권위 결과가 있는 경우에는 그 상태와 기존 회복 경로를 읽는다. 복구 명령이 없으면 상태를 보존해 대상 선택으로 돌아가게 하며 새 대상의 기존 가용/할당 조건을 확인한다. 성공으로 바꾸거나 새 지급을 만들지 않는다.
- 첫 검토용 범위의 정상 마감은 실제 완료된 한 건으로 검증한다. 미완료 작업의 회차 간 이월/강제 취소·장기 운송 규칙은 확장 범위로 남긴다.
- 다른 사업의 진행 작업 전체가 끝날 때까지 회차 마감을 막지 않는다. 회차가 소유한 대상과 다른 업무를 구별한다.
- 마감/다음 준비의 중복 클릭으로 동일 완료·회차 기록·금액을 두 번 반영하지 않는다. 이미 끝낸 대상은 기존 결과로 읽고 새 완료/보상으로 다시 세지 않는다.

첫 목표의 권위 조건·실패/회복은 기존 업무와 연결하며, 표현상 ‘결과’로 넘어갔다는 이유로 실제 업무 완료를 판정하지 않는다.

## 4. 시간·초기화·저장

회차 마감과 다음 준비는 추가 Tick·가상 영업일/현실 날짜 변경·지급·재고 변화·전체 초기화를 실행하지 않는다. 실제 시계의 정상 경과와 수행 중의 기존 Tick은 계속 별도 규칙으로 반영한다. 검사는 시각을 고정해 버튼 자체의 효과와 정상 경과를 분리한다.

현재 `start/campaign-start`는 `kernel.Start(KernelSeed)`를 호출해 다른 모듈/원장을 초기화할 수 있다. 짧은 회차의 ‘다음’에 이 경로를 연결하지 않는다. `AdvanceCampaignBoundary()`도 기존 영업일 경계까지 Tick을 점프하므로 이 마감/다음 준비의 동작으로 쓰지 않는다.

현재 결정 순회의 계획/영업/결산 단계 뼈대를 재사용할 수 있으나, 영업 중 클릭하면 실제 작업 확인 없이 결산으로 넘어가는 기존 동작을 완료 근거로 사용하지 않는다. 대상 작업과 실제 결과 조건을 연결한다.

첫 검토는 **같은 실행 세션의 반복**까지다. 현재 음식/커널 저장을 보존하고 회차 상태의 새 영속 저장·재실행 복원은 별도 범위로 둔다. 사용자가 진행 중인 저장을 초기화하지 않는다. 검증 시작은 구분된 가상/검토용 세션을 이용한다.

r174의 현실 시각 칸·일일 보고 연결은 Claude 진행 중이다. 이번 회차 틀이 그 구현을 대신하거나 과거 가상 시각을 현실 날짜로 바꾸지 않는다. 해당 파일을 함께 수정해야 하면 기존 담당이 같은 판본에서 통합한다.

## 5. 첫 반환에서 볼 것

1. 안내를 따라 실제 대상 한 건의 준비→수행/관찰→결과→다음 준비가 이어지는가.
2. 서로 다른 대상의 두 회차를 같은 세션에서 마치고 첫 결과·다른 사업 원장/인계가 보존되는가.
3. 진행/요청 중에는 이유와 계속하기가 나오며 마감으로 완료를 꾸미지 않는가.
4. 마감/다음 준비·중복 클릭이 시간·날짜·금액·전체 Kernel 상태를 별도로 진행/초기화하지 않는가.
5. 결과가 대상 작업 범위와 일치하고 미연결 값이 구분되는가.
6. 기존 검사와 관련 새 검사·빌드·일반 실행 화면을 각각 확인했는가.

사용자는 **구현을 보고 다시 판단**하기로 했다. 반환 뒤 안내의 양·반복 속도·마감 명칭/배치·첫 개선 선택과 이후 작업 묶음을 검토한다. 첫 반환 전에 상세 성장 전체를 승인받기 위한 추가 질문을 이어가지 않는다.
