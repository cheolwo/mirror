## 1. 한 동네를 만들고 사용 목적에 맞게 보여준다

사가정의 매장·건물·도로·교차로를 같은 공간 판본으로 관리한다. 게임에서는 직접 선택하고 결과를 보는 장소로, 롱폼에서는 실제 배달 이야기의 위치·이동·상황을 이해하는 장면으로 활용한다. 영상에서 본 공간을 나중에 직접 둘러보고 판단해볼 수 있게 연결하는 것이 소개의 기본 방향이다.

```text
확인된 배달 기록·실제 촬영·공간 근거
          ↓ 장소 대응과 사용 범위 확인
      공통 사가정 디오라마
          ├─ 게임: 탐색 → 주문 상황 → 대응 선택 → 결과
          └─ 롱폼: 실제 장면 → 장소/상황 설명 → 게임 체험 소개
                       ↓
       설명·판단에 부족한 정보와 조작을 추출
                       ↓
        앱 개선 명세 → 반영/검증 → 같은 상황 재체험
```

현재 작업은 이 순환의 설계다. 영상 제작 과정에서 설명하기 어려운 지점을 발견해도 곧바로 앱 결함으로 단정하지 않고, 기존 화면·계약·업무 규칙과 대조해 수정 후보로 돌린다.

## 2. 공통 자산과 용도별 표현

| 대상 | 함께 재사용할 것 | 용도에 따라 달라질 것 |
| --- | --- | --- |
| 동네 | 도로·교차로·건물·매장 대응, 공간 판본과 출처 | 게임의 이동/선택 구도, 영상의 조망/추적 구도 |
| 외형 | 건물 형태·간판 근거·재질·조명 기준 | 화면 크기에 따른 가시성·카메라 거리·일시 강조 |
| 배달 흐름 | 주문 상태의 의미, 장소 참조, 확인된 기록 또는 시나리오 조건 | 게임의 선택 UI, 영상의 짧은 해설·동선 강조 |
| 가상 결과 | 같은 회차·규칙 판본의 선택과 결과 기록 | 직접 플레이 표시, 영상의 결과 요약 |
| 실촬영 | 검토된 원본과 실제 사용 구간 | 롱폼 컷, 게임에서 선택적으로 여는 현실 참고 |

게임 조작 화면, 영상용 공간 조망, 영상용 선택/결과 설명은 **표시 관점**이다. 별도 업무 실행 모드를 추가하지 않는다. 기존 [운영·Simulation·Unity 책임](../../../../Architecture/OperationsSimulationUnity작업흐름분리.md)을 유지한다. 공통 공간은 canonical `SimulationWorldShell` 안의 기존 구성과 재사용 자산을 우선하며, 영상마다 다른 공식 Scene이나 복제 월드를 만드는 구조를 기본으로 삼지 않는다.

전체 품질은 [현재 구역을 층별로 함께 높이는 r48](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/area-wide-layered-quality.decision.r48.md)과 [사가정 제작 방식 추출 r50](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/sagajeong-construction-recipe.extract.r50.md)을 따른다. 새 공통 외형 판본을 채택할 때 게임·영상 양쪽에서 대조하고, 이미 만든 영상/회차는 사용한 옛 판본을 유지한다. 영상 한 컷만 정밀하게 꾸며 게임 전체가 같은 수준으로 구현됐다고 소개하지 않는다.

## 3. 롱폼에 넣을 세 장면 초안

매장·메뉴·실제 주행의 흐름을 바탕으로 장소와 판단을 이해하는 데 필요한 지점에 삽입한다. 아래 시간은 후속 시안용 후보이며 현재 롱폼 편성·정책을 변경한 값이 아니다.

| 장면 | 구성 초안 | 보는 사람이 얻는 것 | 길이 후보 |
| --- | --- | --- | --- |
| 장소 소개 | 실제 매장/주행 컷 → 같은 매장 주변 디오라마 조망 → 매장과 연결 도로 강조 | 오늘 이야기가 어느 동네에서 벌어지는지 이해 | 4~6초 |
| 상황 설명 | 실제 기록에서 설명할 상황 → 같은 공간의 주문 한 건·기사 위치/흐름 → 대응 선택 화면 시안 또는 실제 플레이 화면 | 게임에서 어떤 판단을 해보는지 이해 | 8~12초 |
| 짧은 체험 소개 | 실제 이야기로 복귀 → 말미에 같은 동네의 가상 선택/결과 한 장면과 개발 현황 | 영상 속 동네를 직접 체험하는 게임이라는 연결 | 3~5초 |

첫 비공개 구성표는 세 장면 합계 약 15~23초를 후보로 비교한다. 반복 횟수·전체 영상 대비 비율은 미정이다. 모든 픽업마다 같은 게임 소개를 반복하도록 정하지 않는다. 아직 대응 장소가 확인되지 않은 실제 주행에는 동일 위치 전환을 쓰지 않는다.

자연스러운 소개 문구의 예는 “이 동네를 직접 운영해보는 게임도 만들고 있습니다” 정도다. 플레이 가능한 판본이 생기면 실제 조작 장면으로 바꾸고 준비된 링크만 연결한다. 성과·다운로드 전환을 보장하지 않으며, 홍보 지표 수집이나 공개 게시를 이번에 시작하지 않는다.

## 4. 나중에 제작할 때 지킬 최소 연결

- **장소 연결:** 기존 매장·건물·도로의 고유 식별자와 공간 판본을 참조한다. 이름이 같다는 이유로 같은 지점으로 합치지 않는다. 근거가 부족한 동선은 개략 경로/설명으로 두고 실제 이동의 재현이라고 표시하지 않는다.
- **실제 기록과 가상 선택:** 실제 촬영·기록을 설명하는 컷과 가상 상황을 시험하는 컷을 제작 기록에서 구분한다. 실제로 하지 않은 대응을 과거의 사실로 편집하지 않는다. 시청자가 구분할 수 있도록 가상 사례 진입 때 짧게 알린다.
- **플레이와 연출:** 구현 전 화면은 개발 시안으로, 실제 입력으로 수행한 화면은 플레이 캡처로 기록한다. 카메라 연출만 있는 컷을 직접 조작 기능의 실행 근거로 삼지 않는다.
- **재현:** 게임 장면을 영상에 사용할 때 공간/규칙 판본과 해당 회차·행동·결과를 함께 남긴다. 카메라가 결과를 다시 계산하지 않도록 같은 상태 사본/재현 기록을 읽는다. 정확한 저장 계약·캡처 도구는 후속 설계 대상이다.
- **영상 연결:** 원본 해시·실제 시간 구간과 새 영상의 편집 시간을 별도로 남기고, 실촬영의 가림·음성·사용 범위와 자산 이용 범위를 출력별로 확인한다. 고객 상세주소·연락처·주문 개인정보를 공통 게임/공개 영상 자료로 옮기지 않는다. 실제 음식 사진은 확인된 자료를 쓰며 AI 음식 사진을 채움 소재로 쓰지 않는다.

현재 롱폼의 기준 문서는 별도 작업공간 `C:\Users\user\Documents\ChatGPT\배달\edit-kit\riding-vlog\롱폼-제작하며-자료보완-운영절차.md`다. 2026-10-29에 이 문서의 현재 R20 항목과 기존 컷 재사용·원본 보존 기준을 읽었다. 해당 항목에 적힌 렌더/전달 성과를 이번에 재생·해시·재실행으로 검증한 것은 아니다. 이번에는 그 작업공간의 정책·원본·편집·현재 포인터를 변경하지 않는다.

첫 범위는 **사가정 한 구간·대응이 확인된 매장 주변·주문 한 건**이다. 전체 서울 동북권이나 모든 매장 연결을 선행조건으로 두지 않는다.
