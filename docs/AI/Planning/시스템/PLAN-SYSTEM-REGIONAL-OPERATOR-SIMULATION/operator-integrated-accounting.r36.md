- 상위 기획: `README.md` r36
- 선행 기획: `accountant-role-and-ledger.r34.md`, `accounting-operating-conventions.r35.md`
- 목적: 회계 원장·대사·마감 관습은 유지하되 별도 회계사 앱·화면을 만들지 않고 권역 운영자 통합 화면에서 함께 관리한다.

## 1. 확정 구조

회계는 독립 제품 화면이 아니라 운영자 화면의 한 관점이다.

```text
권역 운영자 통합 화면
  ├─ 주문·조리·배차·전달 현황
  ├─ 기사·음식점·권역 가용성
  ├─ 가용현금·오늘 지급·13주 최저점
  ├─ 대사·증빙·마감 예외
  ├─ 정책 Preview와 재무 영향
  └─ 필요할 때만 여는 계정·분개·근거 상세
```

`회계사 역할`은 별도 화면이나 NPC 전용 업무 공간을 뜻하지 않는다. 내부적으로 재무 사건을 분류하고 대사하며 조언 후보를 만드는 역할·권한·검토 이력이다. 운영자는 그 결과를 기존 운영 흐름과 함께 본다.

## 2. 통합 표시 원칙

- 기본 화면에는 가용현금, 오늘·이번 주 지급의무, 13주 현금 최저점, 중요한 미대사·마감 예외만 간결하게 표시한다.
- 주문 적체, 기사 부족, 취소·환급 정책 카드에는 해당 선택이 바꾸는 현금·지급의무·관리계정을 같은 카드 안에서 보여 준다.
- 계정과목, 차변·대변 후보, 증빙 hash, 본인·대리인 가정은 기본 화면에 늘어놓지 않고 상세 펼침·감사 내역에서만 제공한다.
- 정상 거래는 자동 대사·기본 매핑으로 조용히 흐른다. 운영자는 모든 분개를 승인하지 않는다.
- 미대사, 현금 부족, 미승인 매핑, 마감 후 수정, 중요 회계판단만 운영자 확인 또는 회계사 검토 필요 상태로 올린다.
- 외부 회계사가 검토할 때는 별도 앱을 만들지 않고 판본화된 검토 묶음·내보내기·의견 회신 계약을 사용한다.

## 3. 권한과 권위

| 주체 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 운영자 | 통합 현황 조회, 정책 Preview, 예외 담당 배정, 승인된 조정 요청 | 업무 Event·회계 근거 임의 수정 |
| 내부 회계 조언 역할 | 계정 매핑 후보, 대사 차이, 현금 위험, 마감 차단 사유 생성 | 주문·배차·지급·환급 확정 |
| 실제 회계사 검토자 | 적용 기준·계정 매핑·조정 후보 검토와 의견·승인 판본 | 시스템 밖 계약·증빙 없이 자동 확정 |
| 재무 UseCase | 승인된 Command로 원장 변경·재조회 | UI 카드만 보고 상태 변경 |

역할별 권한은 남기되 화면 구조를 역할별로 복제하지 않는다. 같은 통합 화면에서 권한에 따라 상세·조작이 달라진다.

## 4. 운영자 카드 결합 예시

### 점심 피크 기사 부족

- 운영: 예상 주문, 가용 기사, 미배정 대기
- 재무: 모집 정책 비용 후보, 13주 최저 현금 변화
- 선택: 기본값 유지, Simulation 정책 Preview, 원복

### 주문자 취소

- 운영: 조리·기사·결제 단계, 허용 조작
- 재무: 고객 환급, 음식점 보호, 기사 취소수행대금, 플랫폼 부담 후보
- 회계 상세: 관리계정, 분개 후보, 정책·매핑 revision

### 일마감 불일치

- 운영: 영향 주문·PG batch·지급 대상
- 재무: 장부와 외부 명세 차이, 경과시간, 현금 사용 제한
- 선택: 자료 재수집, 담당자 배정, 회계사 검토 요청

## 5. 개발 영향

- 별도 `AccountantApp`, 전용 Controller 묶음, 별도 Unity Scene과 별도 최상위 navigation을 만들지 않는다.
- 기존 운영자 조회에 `FinancialSummary`, `ReconciliationException`, `AccountingAdvice`, `AccountingDetailRef` 같은 읽기 전용 projection을 결합한다.
- 상세 원장·분개 조회는 공통 API와 권한을 사용하되 운영자 통합 화면의 상세 drawer·modal·하위 panel에서 연다.
- Simulation 정책 Preview는 처리량·지연뿐 아니라 현금·지급의무·관리계정 영향을 같은 revision으로 반환한다.
- Unity에는 가용현금 위험·지급 적체·마감 경보 같은 일반화 상태만 표현할 수 있고 실제 전표 쓰기 조작은 제공하지 않는다.
- 외부 회계 검토는 CSV/XBRL을 즉시 생성하는 기능이 아니라 source revision·hash·포함 기간·미정 항목을 가진 검토 패키지부터 설계한다.

## 6. 완료 조건

- 운영자 한 화면에서 업무 지표와 재무 영향을 같은 정책 revision으로 본다.
- 계정 상세를 닫아도 현금 부족·지급 지연·`정산 확인 필요` 사건을 이해할 수 있다.
- 계정 상세를 열면 원 업무 Event와 증빙·보조원장·매핑 판본으로 추적할 수 있다.
- 회계 권한이 없는 사용자는 보호된 분개·증빙 상세를 볼 수 없다.
- 별도 화면을 만들지 않아도 회계사 검토 의견과 승인 판본을 기록·재조회할 수 있다.
- UI가 주문·배차·전표·지급의 권위를 갖지 않는다.

## 7. r37에서 폐쇄된 질문

상단 고정 4개 지표를 사용한다. 운영자에게는 `가용현금`, `향후 7일 지급의무`, `13주 현금 최저점`, `정산 확인 필요`로 표시한다. `미대사 위험 건수`라는 화면 문구는 사용하지 않고 내부 계약에서만 `ReconciliationException` 분류를 유지한다. 상세 기준은 `operator-integrated-accounting-summary.r37.md`가 소유한다.
