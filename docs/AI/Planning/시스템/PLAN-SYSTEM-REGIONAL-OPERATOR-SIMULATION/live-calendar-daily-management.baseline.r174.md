## 1. 용어 — 보고와 업무 처리를 구별한다

이 문서의 활동·금액은 **Simulation에 확정 기록된 게임 내 결과**다. 공공자료는 현실의 참고 근거이고, 실운영 주문·계약·계좌 원장과는 별도다.

| 용어 | 이 기획에서의 의미 | 화면을 읽거나 확인할 때의 효과 |
| --- | --- | --- |
| 결산 | 하루·주간·절기에 속하는 활동/금액 기록을 모아 보는 보고 | 기존 기록을 조회·집계 |
| 결산 확인 | 어느 기간/판본의 보고를 읽었는지 기록 | 확인 상태만 변경 |
| 정산 | 해당 업무 규칙에 따라 대금/수행대금 등을 산정·확정하는 절차 | 기존 업무 원장의 명령/권한을 따름 |
| 지급·수금 | 정산 금액과 구별되는 돈의 이동/그 확인 | 해당 지급/수금 기록이 있어야 표시 |
| 수익·비용 | 게임의 해당 업무 규칙이 기록한 금액 항목 | 현금 수입·지출과 같은 값으로 간주하지 않음 |
| 완료 | 해당 모듈이 정의한 업무 결과 | 전달·수령·정산·지급 등 서로 다른 결과를 같은 완료로 합치지 않음 |

결산을 확인했다고 정산·지급·수금이 실행되지는 않는다. 금액은 확정됐지만 돈의 이동이 끝나지 않은 항목은 각 원장이 제공하는 지급·수금 상태로 구분한다. 아직 금액이 확정되지 않은 항목은 미정산 상태로 구분한다. 지표는 기존 원장의 항목과 포함 범위를 따른다. 문서 편집으로 새 회계 인식 기준·차액 공식·보상/세금 규칙을 만들지 않는다.

## 2. 시간 — 하루는 플레이 리듬, 주간·절기는 검토 기간이다

| 구분 | 기준과 역할 |
| --- | --- |
| 현실 날짜 | 한국표준시 날짜를 계속 따른다. 하루는00:00부터 다음 날00:00 전까지 |
| 일일 경영 주기 | ‘오늘 준비 → 실제 작업/관찰 → 오늘 결산 → 다음 날 준비’의 일일일생 리듬 |
| 주간 경영 기간 | 현실 월요일00:00부터 다음 월요일00:00 전까지의 계획·누적 검토. 기존 문서의 ‘주간 턴’은 이 기간을 뜻함 |
| 절기 적용 기간 | 한국 24절기 달력을 읽고 운영 방침을 적용하는 기간. 첫 프로필은 KST 날짜 단위 |
| 작업 경과 | 실행 중인 배달·제조·포장 등의 진행 시간. 현실 달력과 별도로 기존 작업 규칙을 따름 |

현실의 하루/일주일 안에서 준비된 짧은 작업을 여러 번 할 수 있다. 신규 사용자는 접속한 현재 기간부터 참여한다. ‘다음 결정’은 남은 안건으로 이동하는 행동이고 현실의 다음 날/주를 만드는 행동이 아니다. 작업 배속·일시정지·앱 종료도 현실 달력의 날짜를 바꾸지 않는다.

**결산·카드 확인 명령은 달력이나 작업 시간을 추가 진행시키지 않는다. 현실 시계의 정상 경과는 계속 반영한다.** 기존 문서의 ‘확인 전후 날짜 불변’은 이 명령 효과를 뜻한다. 확인 중 자정이 지나는 정상 상황까지 날짜를 고정하라는 요구가 아니다.

기존 가상 캠페인의 고정 기점·Day/Tick·작업 약속을 현실 날짜로 일괄 치환하지 않는다. 현실 경과를 기존 시간 진행 명령에 넘겨 부재중 영업을 계산하는 방식도 사용하지 않는다.

## 3. 일일 결산 — 언제든 보되 같은 기록을 두 번 지급하지 않는다

당일 `오늘 결산`은 현재까지의 **진행 중 집계**다. 다시 일하면 같은 날짜의 기록에 누적한다. ‘오늘 마무리’는 현재 결과를 정리하는 행동이며 기록 초기화나 다음 날짜 생성이 아니다.

날짜가 지나면 그날의 기록을 지난 일일 결산으로 묶는다. 새 날짜의 안전한 작업 경계 또는 재접속에서 미확인 결과를 안내한다. 보고는 일일→주간→절기 순으로 묶어 제시할 수 있지만, 이 순서는 보고의 표시 순서다. **지난 보고를 모두 열람하는 것을 오늘 업무의 필수 조건으로 만들지 않는다.**

- 일일 보고에는 완료/대기·수익/비용·정산/지급 상태·이월할 일과 그날의 문제를 해당 원장이 제공하는 범위로 보여준다.
- 미확인 날짜는 실제 플레이 기록이 있는 날만 묶는다. 미접속 빈 날짜마다0원 결산이나 필수 확인 창을 쌓지 않는다.
- 미완료 주문·운송·공사·안건은 같은 ID로 이어간다. 보고 마감을 위해 완료·취소·벌금·영업 결과를 생성하지 않는다.
- 주간/절기 보고는 같은 원본 기록을 각 기간으로 조회한다. 일일 화면의 합계를 다시 적립하거나 확인 여부에 따라 수익/비용을 달리 계산하지 않는다.
- 같은 기간/판본의 보고를 다시 확인해도 새 지급·차감·작업 진행은 없다.

### 날짜 귀속과 자정 작업

집계 날짜는 **기존 업무 원장이 해당 기록 항목에 정한 기준시각을 KST로 읽은 날짜**다. 완료 시각·정산 확정 시각·지급 시각은 서로 다른 기록 항목이다. 자료 수집일·파일 저장일·화면 확인일을 그 대신 사용하지 않는다. 기존 ‘실제 기록일’ 표현은 이 의미로 통일한다.

전날23:55에 시작해 다음 날00:10에 완료한 배달은 전날에는 미완료/이월, 다음 날에는 완료로 읽는다. 수익·비용·정산·지급은 각각의 기록 기준에 따라 표시하며 배달 완료일에 모두 발생했다고 합치지 않는다. 이 예시는 날짜 구분이며 새 비용/수익 인식 정책을 정하는 것이 아니다.

늦게 확인한 기존 기록이나 정정 기록도 원장의 기준·판본·관계에 따라 다시 조회한다. ‘부재중 영업 없음’은 미접속 기간의 결과를 추가 시뮬레이션하지 않는다는 뜻이며, 이미 존재하는 기록이나 미정산/정정 내용을 숨긴다는 뜻이 아니다. 기준시각/금액 항목이 아직 연결되지 않은 경우는 개발 연결 미정으로 남기고 수집시각이나0원으로 임의 대체하지 않는다.

## 4. 절기와 카드 — 현재 기간의 방침만 확인한다

첫 프로필의 ‘절기일’은 **게임 절기 적용일**이다. 공식 자료에 있는 천문학적 절입시각은 별도 근거로 보존하고 두 기준을 같은 시각으로 표시하지 않는다. 연도별 검증 달력의 명칭/순서를 사용하며 고정15일로 계산하지 않는다. 자료 근거와 조사 이력은 r172를 계승하고 이번 편집에서 새 수집을 했다고 보고하지 않는다.

새 절기 적용일에 새 업무를 시작하기 전 현재 절기의 방침을 확인한다. 이미 수행 중인 작업은 안전한 종료/인계 뒤 안내하며 이전 작업의 규칙·결과를 소급 변경하지 않는다. 과거 보고 열람과 현재 절기 방침 확인은 별도다. 관찰만 할 때는 선택 없이 볼 수 있고, 경영 참여 전에는 카드 또는 중립 운영을 확인한다.

| 고정 후보 | 일반 추천에서 앞세울 범주 |
| --- | --- |
| 전차 | 운송 준비·배차·인계 점검 |
| 절제 | 재고·인력·예산 균형 |
| 여제 | 계절 상품·점포·제조 준비 |

필수·긴급의 기존 우선순위를 유지하고 일반 추천의 순서/설명만 바꾼다. 적합한 안건이 없으면 없다고 표시한다. 이 프로필에 수치 보정·새 수요/사건·자동 발주/배차를 추가하지 않는다.

같은 절기의 카드/중립 확인은 재접속·일일 결산으로 다시 선택하지 않는다. 다음 절기에는 이전 활성화를 종료하고 같은 카드도 새 기간의 선택으로 허용한다. 며칠 쉬었으면 현재 절기에 참여하며 지나간 절기의 선택을 줄줄이 요구하지 않는다.

기존3일차 운영 방침·기사 개인 타로·세계 문맥형 정역방향·순환 덱은 각 계약을 보존한다. 이 고정3후보 프로필이 기존 덱의 버림/소진/재섞기 구현을 완성했다는 뜻은 아니다.

## 5. 공공자료 — 관측 문맥과 지도 구조를 따로 갱신한다

현실 날짜를 따른다는 것은 모든 공공자료가 오늘의 실시간 관측이라는 뜻이 아니다. ‘최신’은 제공기관이 공개하고 검증을 마친 사용 가능한 판본이다. 관측기간·지역·출처·수집/검증 상태를 함께 표시한다.

| 자료 | 적용 기준 |
| --- | --- |
| 기상·가격·출하 등 관측 문맥 | 새 접속에서 최신 검증 사본을 확인. 진행 작업은 시작한 사본으로 끝내고 다음 안전한 새 작업 시작에 갱신 |
| 도로·건물·주소·경계·이동망 | [r54](session-pinned-public-data-revision.r54.md)/[r55](background-regional-data-update.r55.md)의 세션 판본 고정·다음 세션 또는 Migration Preview 유지 |
| 연도별 달력 | 검증된 연간 판본을 사용. 확인 불가/실패는 표시하고 마지막 검증 자료 보존 |

다운로드 중/실패 시 현재 사용하는 검증 판본과 기준일을 보여준다. 화면만 새 지도 구조로 바꾸거나 검증 전 자료를 활성화하지 않는다. 계절·날씨·가격·제철을 같은 사실로 합치지 않고, 절기명만으로 폭설·가격·매출 증가를 만들지 않는다.

수집/DB·검증 캐시·팩의 기존 소유를 유지한다. Unity의 작업/보고 명령이 외부 수집을 직접 실행하지 않는다. 게임 환경 갱신은 실운영 원장의 주문·지급 실행 권한을 얻지 않는다.

## 6. 개발 해석과 검증 기준

[통합 인계 r174](../../../Handoffs/2026-11-13-Codex-Claude-현실달력일일결산-통합정본-r174.md)는 현재 개발 입력이다. 이전 r172/r173 인계는 당시 승인·추가 범위를 확인하는 이력으로 보존한다. 다음을 같은 의미로 검증한다.

1. 당일 반복 수행/결산 열람은 같은 날짜에 누적되고 날짜 생성·중복 지급이 없다.
2. 자정 작업·지연 정산/정정은 각 원본 기록의 기준시각으로 구별되고 이월 작업을 복제하지 않는다.
3. 미접속 후 현재 환경/기간을 읽되 영업 결과를 추가 계산하거나 빈 날짜의 확인을 강제하지 않는다.
4. 일·주·절기 보고는 같은 기록을 기간별로 조회하며, 현재 절기 선택과 보고 열람을 혼동하지 않는다.
5. 기준시각을 고정한 명령 시험에서 결산/카드 확인이 추가 시간 진행·금액/재고 변경을 일으키지 않는다. 현실 자정의 자연 경과는 별도 달력 갱신으로 검증한다.
6. 같은 절기 선택의 멱등성·다음 절기 동일 카드 재활성화·진행 작업 사본/지도 구조 판본 보존을 확인한다.

**확정:** 현실 달력·일일일생·주간 검토·절기 방침·부재중 환경만 갱신·기존 카드/자료 소유를 계승했다. 이번 변화는 용어/책임/읽기 순서의 통합이다.

**미정:** 각 모듈의 완료/금액/기준시각 필드 결속과 실제 화면·코드 통합/실행 검증은 개발 수용에서 명세로 연결한다. 서울의 구체 경영 역할, 새 회계 인식/수치 효과·오프라인 영업·덱 확장은 이 편집으로 확정하지 않는다.

**다음 검토 하나:** 개발 담당이 이 정본/인계의 판본을 읽고 기존 원장의 완료·정산·지급 및 기준시각을 어떤 값으로 연결하는지 반환한다. 새 사용자 선택 질문은 없다. Graph Map·Goal/WI·실행 E는 변경하지 않는다.
