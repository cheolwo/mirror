## 2. 조사 사실과 게임 가설의 경계

공식 근거의 정본은 [17개 출처와 활동별 조사](../../../DataCollection/Research/2026-11-17-naver-place-user-activities-and-ranking.md)다. 클릭 등 일부 인기도 요소는 공식 설명이 있지만, 모든 활동의 고정 배점은 공개 확인되지 않았다. ‘통계가 존재함’과 ‘그 값이 일반 검색 순위를 직접 올림’을 별도 속성으로 둔다.

**재사용할 관점:** 검색어·위치·시점·의도에 따라 결과가 달라진다. 하나의 전역 장소 점수로 모든 검색 결과를 결정하지 않는다. 홍달의 활동 기록은 실제 이용자가 아닌 NPC 고객의 가상 기록이다.

**이번 미정:** 체류/저장/통화/예약/완료/리뷰 중 어느 신호를 이전반응에 사용할지, 표본/감쇠/보정·갱신 시점, 광고/중개 반응의 별도 취급. 아래는 전부 설계 후보이며 기존 수치를 조용히 바꾸지 않는다.

## 3. 플레이 상황과 오행 연결

- 지금: 같은 동에서 카페 주문을 받을 준비가 되었지만 검색 유입과 실제 주문의 차이를 살펴야 한다.
- 여기: 현재 행정동의 홍달 플레이스와 카페·배달 가능한 주변 지역. 전국 지도로 자동 이동하지 않는다.
- 나: 매장 운영자. 정보/메뉴를 정리하거나 광고·현장 여력을 검토할 수 있고, 고객을 직접 클릭시켜 성과를 만들지는 않는다.
- 너: 검색 목적·시간·이동 여건이 서로 다른 가상 주문자와 실제 처리 여력이 있는 매장/기사.
- 이렇게: 운영자는 키워드별 검색→열람→주문/완료의 차이를 보고 개선안을 선택한다. 주문 실패의 원인이 검색인지 재고/제조/배달인지 구분하고 원래 경영 화면으로 돌아온다.

00오행판의 기본 목=주문, 화=음식점, 토=배차, 금=창고, 수=배달/운송을 유지한다. 검색·관심은 주문 전 단계이고, 물류/제조/이행 완료나 명덕을 대신하지 않는다. 직접 회복 기획은 아니며 판단을 돕는 보조 층이다. 효과를 보려면 상대가 실제로 필요로 하는 메뉴·시간·서비스 여력을 갖춰야 한다.

## 4. 활동을 정리하는 제안 트리

```text
홍달 플레이스 고객 활동 — 전부 게임 내부 기록 후보
├─ 검색 맥락: 가상 고객·세션·검색어·지역/위치·시간·의도
├─ 발견: 순위 판본·결과 표시 위치·일반/광고 경로
├─ 탐색: 상세·메뉴·사진·후기 열람, 선택적인 체류 단서
├─ 의도: 저장/해제·길찾기·전화 시도·문의
├─ 거래: 주문 요청·수락·결제·완료·취소/환불
└─ 경험: 이용 확인·리뷰 작성/수정/삭제·리뷰 반응
```

이는 모든 고객이 거치는 강제 순서가 아니다. 검색 없이 단골 주문을 할 수 있고, 저장만 하고 끝내거나 전화를 바로 걸 수도 있다. 플레이어의 화면 열람은 이 트리 밖의 조회다.

각 사건은 가상 고객/세션·사건 고유 ID·시각·장소·키워드/의도·결과 판본·표시 위치·유입 종류·직접 결과를 연결하는 안이다. 검색을 거치지 않았으면 키워드/순위는 없음으로 두고 만들지 않는다. 주문은 기존 주문 고유 ID를 참조한다. 실제 IP·네이버 계정·영수증 이미지 수집은 필요하지 않다.

## 5. 순위 입력과 성과를 분리하는 제안

| 층 | 다루는 것 | 유지할 구분 |
| --- | --- | --- |
| 활동 원장 | 발생한 가상 사건과 정정/취소 | 기록됐다고 모두 순위 가산하지 않음 |
| 조회 통계 | 키워드 검색 세션, 노출, 매장 열람, 의도, 실제 주문/완료 | 사건 수·사람 수·세션 수·거래 수의 단위를 구별 |
| 순위 입력 | 의도 적합·접근 가능성·정보 상태·이전반응 | 기존 네 요소 유지. 반응 신호 선정/정규화는 후속 |
| 경영 결과 | 실제 주문 이행·비용·정산, 다음 운영 선택 | 조회/순위표만으로 주문·매출·명덕을 생성하지 않음 |

권하는 첫 검토 범위는 **검색 세션·노출·상세 열람·주문 요청·실제 완료**다. 저장·리뷰 등은 기록을 확장할 수 있지만 첫 단계에서 모두 가중치로 넣을 필요는 없다. 메뉴/사진 개선은 정보·고객 선택의 경로로, 제조/배송 개선은 실제 경험의 경로로 설명한다. 운영자는 둘 중 어디가 막혔는지 읽을 수 있어야 한다.

이전반응은 원시 클릭 누계보다 **관측 기회와 표본을 함께 보여 주는 특징**을 후보로 삼는다. 예컨대 노출 대비 상세 열람과 열람 후 정상 주문/완료는 서로 다른 지표다. 정확한 분모·유효기간·초기값/표본 보정·가중치·실패 원인의 책임 귀속은 아직 미정이다. 제안만으로 관측이 없는 현재0.5를 새 값으로 교체하지 않는다.

## 6. 중복·순환을 막을 검토 기준

1. **같은 관심의 중복:** 한 세션에서 메뉴/사진/저장으로 이어진 것을 각각 독립 고객 성과로 합산하지 않는다. 상세 기록과 순위 특징을 분리한다.
2. **순위의 자기 증폭:** 상단 노출→클릭 증가→즉시 재정렬의 순환을 피한다. 세션이 읽는 순위 판본은 고정하고, 반응은 후속 유효 판본에서 검토한다. 노출/위치 보정과 신규 매장의 발견 기회는 후속 밸런스다.
3. **쪽 이동·재실행:** 쪽 넘김/뒤로가기/새로고침/저장 복원으로 새 검색·광고 과금·동일 사건을 복제하지 않는다. 표시는 실제 본 후보를 기준으로 정의하며 아직 보지 않은 페이지를 자동 노출로 세지 않는 안이다.
4. **플레이어 열람:** 검색 순위를 확인한 시간·상세 클릭은 NPC 반응이 아니다. 승인된 매장 정보 수정 명령은 별도의 상태 변화다.
5. **주문 팽창:** 같은 수요 기회가 광고·일반 검색·여러 키워드를 거쳐도 새 고객/주문을 계속 만들어 내지 않도록 기존 수요 예산과 계보를 연결한다. 순위 신호 제외가 정상 완료 주문/정산을 되감지는 않는다.

광고 슬롯/비용은 [r176](place-search-advertising-and-demand.proposal.r176.md), 가상 중개 신호·일시 효과/정제는 [r239](traffic-broker-person-card-and-temporary-ranking.design.r239.md)가 소유한다. 합성 관심을 정상 고객·실제 주문으로 동일시하지 않고, 현실의 IP·계정 운영법이나 제재 회피 조건은 다루지 않는다. 이번 조사에서 중개 기능의 기존 승인 범위·소개 순서·효과 수치를 바꾸지 않는다.
