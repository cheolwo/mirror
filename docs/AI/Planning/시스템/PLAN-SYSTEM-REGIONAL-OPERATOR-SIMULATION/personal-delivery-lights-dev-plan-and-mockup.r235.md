새로 확인한 연결상의 공백:

- 앱 원장의 ID와 지도 DB의 `record_id`가 직접 일치하는 경우는 0건이다. 주소 표기도 서로 다르다(지번형과 도로명형). **도로명+건물번호 키**로 지도 지점 하나에만 맞는 경우가 718/1,462건이다. 시안 3번은 이 후보 연결로 전달 지역과 시각을 붙였으며, 연결이 확정된 것은 아니다.
- r3 동 모듈의 `roads` 층은 간선 149구간뿐이어서 골목이 없다. 매장에서 도로까지는 계산 경로를 만들 수 없고, 시안에서는 ‘골목 구간 · 도로망 미확보’ 점선으로 남겼다. `streets.walkLinks`(979개, 2020 보행 네트워크)를 경로망에 합쳐야 한다.
- 전달 도로명(`destination_road`)과 도로 구간을 대응시키는 자료가 없다. 현재 모듈의 도로 구간에는 도로명 속성이 없다.

## 2. 시안

렌더러는 [`artifacts/local/personal-delivery-lights-r235/render_mockup.py`](../../../../../artifacts/local/personal-delivery-lights-r235/render_mockup.py)다(로컬 전용, 인자는 날짜). 매장명은 가명(매장 A~H)으로 표기했다.

1. [구 지도 개요](../../../../assets/changes/2026-11-15-personal-delivery-lights-r235/01-gu-overview.png): 4개 구 65동이 회색이고, 픽업했던 매장 812곳이 빛난다. 후광 크기는 전체 기간의 방문 빈도이고, 면목제3·8동은 테두리로 강조했다.
2. [동 디오라마 · 하루](../../../../assets/changes/2026-11-15-personal-delivery-lights-r235/02-dong-day-pickup-lights.png): 면목제3·8동 건물 2,722조각을 층수로 돌출했다. 11-03에 들렀던 8곳만 빛나고, 같은 매장은 한 점과 건수 배지로 묶는다.
3. [배달 한 건 선택](../../../../assets/changes/2026-11-15-personal-delivery-lights-r235/03-select-delivery-computed-route.png): 선택한 매장만 밝히고 나머지는 옅게 한다. 전달지는 동 수준인 면목5동이라 경계 쪽에 하늘빛 진입점을 둔다. 기사 빛은 민트색 계산 경로를 따라가며, 실선은 지나온 구간, 점선은 남은 구간이다.

### 빛의 두 채널

| 채널 | 뜻 | 시안 값 |
| --- | --- | --- |
| 후광 크기 | 선택 기간의 방문 빈도 | 1건 1.0 → 2건 1.25 → 3건 1.45 → 4건 이상 1.65배에서 **상한** |
| 중심점·배지 색 | r234 위치 검증 상태 | 시안 후보: 진한 호박색 중심, 지붕 강조 / 주소 검토: 연한 호박색 중심과 ‘주소 검토’ 배지 / 위치 확인 필요: 회색 중심을 지면에만 표시하고 지붕 강조 없음 / 미해소·보류: 지도에 올리지 않고 카드 목록으로 |
| 명덕과의 구별 | — | 명덕은 민트빛이고 호흡하며 배지가 없다. 내 배달 기록은 호박색이고 정지해 있으며 건수 배지가 붙는다. 이번 레이어의 기사 빛(민트)은 선택 재생 중에만 나타난다 |

## 3. 개발 단계 (Claude 구현 범위)

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| D0 개인 기록 팩 생성기 | `eng/` 아래 Python 도구. 지도 DB rev17, r234 대장, 앱 원장을 읽어 `manifest / places / deliveries / links` JSON을 로컬 전용 폴더에 쓴다. 지점은 `branch_id`와 r234의 `r4WorldPointMetres`·건물 ID·검증 상태를 쓴다. 표시용 ID는 불투명 가명이다. 앱↔지도 연결은 `candidate`/`confirmed`로 구분하고, 시각은 원문과 ‘단계 의미 미확인’ 표시를 그대로 둔다 | 같은 입력 SHA → 같은 출력. 매장명·주소·주문번호가 출력에 없음을 검사. 1,505건 = 동별 합계 대조 |
| D1 Unity 정적 레이어 | `PersonalDeliveryLayer`: 팩을 읽어 날짜·현재 동으로 걸러 매장 빛을 그린다. 좌표는 기존 `DongLocal / DongModuleAt` 변환과 ‘띄워 보기’ 이동량을 따른다. 건물 다중 매장 묶음, 건수 배지, 검증 상태 스타일, 레이어 끄기를 포함한다. 팩이 없으면 ‘내 배달 기록을 불러오세요’를 띄운다 | 11-03 면목제3·8동에서 8곳·11건이 시안과 같은 건물에 뜸. 끄면 흔적 없음. 실제 0건과 자료 오류가 구분됨 |
| D2 선택·전달 범위 | 매장 → 배달 목록 → 한 건. 전달은 기록 정밀도대로 표시한다(동: 경계 진입점, 도로: 구간이 대응되면 옅은 띠). ‘다른 동으로 전달’ 진입점을 누르면 이동하고 돌아올 수 있다 | 같은 건물 두 매장, 좌표 없는 기록, 타 동 전달 세 사례 통과 |
| D3 재생 | 간선과 보행 네트워크를 합친 그래프로 계산 경로를 만든다. 카드에 ‘관측 GPS 아님’을 표시하고, 시각 의미가 미확인이면 ‘기록 넘겨 보기’로 바꾼다. 같은 기록 ID를 다시 열어도 정산·주문을 만들지 않는다 | 되감기·재열기 반복 시 위치가 같음. 가상 배차 상태가 변하지 않음 |
| D4 검증 | Play Mode 입력 검사(날짜 바꾸기, 선택·해제, 동 이동·복귀, 레이어 끄기)와 화면 캡처 대조 | r4와 같은 형식의 검증 JSON·캡처 |

D0과 D1이 첫 구현 묶음이고, D2·D3은 아래 자료가 준비되는 순서대로 진행한다.

## 4. 아스트라(Codex)에 요청할 자료

1. 앱 원장 ↔ 지도 DB 배달 연결 확정 규칙(현재 후보 718건). 
2. 전달 도로명 → 도로 구간 대응 자료(도로명주소 도로구간 등).
3. 목록 시각·상세 시각의 단계 의미(배정·픽업·전달 중 어느 것인지).
4. 첫 동을 바꾼다면 그 동의 r3/r4 모듈 묶음(r234가 추천한 상봉제2동 등).

## 5. 결정할 것

- **첫 동**: 시안은 모듈 예시가 이미 있는 면목제3·8동으로 그렸다. r234는 검증 후보가 가장 많은 상봉제2동(28곳)을 제안했다.
- **첫 날짜**: 시안은 11-03(화)이다. 면목제3·8동에서는 10-01(14건·6곳), 10-19(12건·5곳)도 후보다.
- **주소 검토 370곳**: 시안은 빛을 켜고 배지로 구분했다. 시안 후보 318곳만 켜는 방식도 가능하다.
- **후광 단계값**: 위 1.0~1.65배 상한안을 쓸지 정해야 한다.
