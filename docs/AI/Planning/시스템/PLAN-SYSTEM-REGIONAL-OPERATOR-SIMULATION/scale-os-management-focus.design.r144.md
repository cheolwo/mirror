## 확정 — 지도를 고르면 생각할 경영이 달라진다

후속 [집중·이완 혼용 r146](focus-relax-shared-management.design.r146.md)은 같은 세션의 참여 방식을 정한다. 지도 높이의 대표 업무 자동 초점과 사용자/자동 기사의 수행 주체 전환을 구별한다. 지도 확대·기사 따라보기·창고 내부 진입만으로 직접 조작을 시작하지 않으며 이완에서는 지도와 창고를 관찰한 뒤 현재 기사·업무로 집중 복귀할 수 있다.

**지도를 보는 범위를 선택하면 그 범위에 맞는 업무 OS의 경영에 자동으로 초점을 맞춘다.** 건물·동네·구·광역은 각각 다른 경영 질문을 다루며 같은 세계·가상 시간·업무 상태를 공유한다.

플레이어는 건물에서 현장의 막힘을, 동네에서 주문과 배송을, 구에서 점포망·인력·재고의 배분을, 광역에서 센터·차량·납기를 판단한다. 창고 건물에서는 외관과 숫자 카드에 더해 내부의 보관·작업 구역을 모델로 확인한다. 이는 경영 판단과 업무 판독을 돕는 표현이며 화면 진입만으로 물품을 인수하거나 업무를 확정하지 않는다.

## 1. 지도별 주 업무와 기본 화면

| 지도 | 중심 업무 | 처음 보여줄 내용 | 대표 선택 |
| --- | --- | --- | --- |
| 건물 | 매장·가맹점·창고의 현장 업무 | 장소 역할·재고·작업·검수·막힌 일. 창고는 내부 공간 보기 | 조리·검수·피킹·보충 등 기존에 준비된 행동 |
| 동네 | 음식 배달·근거리 배송 | 현재 주문·준비 상태·기사 위치·처리 여력 | 기사 연결·대기 대응·배송 순서 |
| 구 | 가맹점망·도심 물류·지역 운영 | 동별 수요/공급·점포망·기사/재고 부족 | 출점·모집·지역별 자원 배분 |
| 광역 | 물류센터·국내 화물 | 센터 재고·출고 회차·차량·납기 | 출고 회차·차량·공급 경로 선택 |

이는 기존 OS와 업무의 **주된 경영 화면 배치**다. [업무 실행 책임과 기존 OS 목록](../../../../Architecture/EngineOverview.md)을 재사용하며 새 OS 식별자를 만들거나 하나의 OS를 한 높이에만 가두지 않는다. 같은 창고 업무도 건물에서는 작업 위치, 구에서는 지역 재고 부족, 광역에서는 출고 회차로 요약될 수 있다.

확인된 역할이 하나인 건물은 그 업무를 바로 연다. 복합 건물은 역할별 현황을 먼저 보여주고 사용자가 관리할 매장·시설을 고른다. 기존 r143처럼 건물 전체와 개별 매장의 관리 관계를 구분하며 주소·외형만으로 창고 역할이나 운영 권한을 추정하지 않는다.

## 2. 지도 전환·동일 업무·복귀 규칙

| 상황 | 동작 |
| --- | --- |
| 다른 높이로 진입 | 새 높이의 대표 업무 요약과 준비된 주 행동으로 자동 초점을 바꾼다. 관련 OS 전환 진입을 제공한다. |
| 같은 높이에서 지도만 이동 | 선택한 OS와 업무 관점을 유지하고 보이는 지역의 정보만 갱신한다. |
| 동일 업무의 다른 높이 보기 | 같은 업무 고유 식별자·상태 Revision·수량·진행 단계를 유지한 요약 또는 상세를 읽는다. |
| 작성 중 입력·대상 선택 | 지도 전환만으로 지우거나 제출하지 않는다. 상위 지도에는 해당 업무 요약과 상세 복귀 경로를 둔다. |
| 긴급·실패·복구 | 시간·가장 급한 일·실패 사유와 복구 진입은 어느 높이에서도 확인한다. 일반 정보는 현재 경영 관점에 맞춰 줄인다. |
| 지도 전환·확대·축소 | 업무 확정·취소·배차·재고 변경을 실행하지 않는다. 기존 가상 시간은 이어지고 사용자가 정지하면 전체 업무도 같은 정지를 따른다. |
| 사업 미준비·미구현 | 상태와 이유를 표시하고 실행 가능한 버튼처럼 열지 않는다. 지도 높이 자체를 사용 자격·해금·권한으로 해석하지 않는다. |

같은 우유 납품을 건물에서는 인수/격리 수량, 구에서는 점포별 부족과 인계, 광역에서는 센터 출고/차량으로 읽을 수 있다. 이 설명은 Claude가 구현 중인 사슬의 새 작업지시서가 아니며 수량·검수·인계 규칙을 바꾸지 않는다.

건물·동네·구·광역은 경영 관점을 설명하는 표시명이다. 기존 Z 단계·H 계층·자료 타일 주소·법정동/행정동/상권 고유 식별자를 새로 번호화하거나 지도 높이에 일대일 결속하지 않는다. 현재 지역 팩의 미해결 자료는 0값이나 확정 수요로 바꾸지 않는다.

## 3. 창고 건물 선택 → 내부 모델 보기

### 사용자 의도와 첫 표현 기준

사용자는 창고 건물을 눌러 건축 모형·모델하우스를 살펴보듯 내부 공간과 설비 배치를 확인한다. 단순한 외관 확대나 재고 표만으로 내부 보기를 대신하지 않는다.

첫 표현 기준은 **지붕과 앞쪽 가림을 걷어내고 비스듬히 내려다보는 개방형 내부 모델**로 제안한다. 보관 랙·통로·피킹 구역·포장 작업대·입출고 구역이 한눈에 구별되어야 한다. 이 시점·가림 방식과 구체 모델은 시각 검토를 거쳐 확정하며 이번에 실제 모델·Scene을 만들지 않는다.

| 내부 구역·배치 객체 | 사용자가 확인할 내용 |
| --- | --- |
| 입고·하역 대기 구역 | 들어온 물품과 검수 전 대기 위치 |
| 검수·격리 구역 | 확인 중·격리·가용 상태의 구별. 가용 재고와 격리 물품을 같은 랙 표시로 섞지 않음 |
| 보관 랙·적재대 | 어느 위치에 무엇을 보관하는지, 연결된 재고·작업의 상태 |
| 통로·피킹 구역 | 랙과 작업 구역 사이의 연결, 현재 작업의 대상 위치 |
| 포장 작업대 | 포장할 물품과 진행·대기 상태 |
| 출고·인계 대기 구역 | 포장 뒤 나갈 물품과 기존 운송 인계 상태 |

이는 기존 창고 생명주기의 입고·검수·적치·할당·피킹·포장·인계를 공간에서 읽기 위한 구역이다. 신규 재고 규칙이나 운영 작업을 만드는 요구가 아니다. 기존 [살뜰마트 개방형 내부 기준](../PLAN-SYSTEM-MYEONMOK-OBSERVER/mart-center.r3.md)과 [같은 동네의 창고 업무](../PLAN-SYSTEM-MYEONMOK-OBSERVER/shared-neighborhood-warehouse.r1.md)를 재사용 후보로 대조하되 다른 소비판의 구현을 현재 Windows 게임 적용 완료로 세지 않는다.

### 진입과 귀환

1. 단일 창고 역할이 확인된 건물을 선택하면 해당 창고의 내부 보기를 기본으로 연다. 복합 건물에서는 역할 요약에서 창고를 선택한 뒤 들어간다.
2. 건물 주소·창고 이름·현재 관점을 남긴 채 내부 전체를 맞춰 보여준다. 확대·이동·전체 맞춤으로 랙과 작업대를 살펴보게 한다. 첫 범위는 모형 관찰이며 1인칭 보행·건축 편집·설비 재배치는 후속이다.
3. 랙·작업대를 선택하면 연결된 위치/설비·재고·업무의 상세를 읽는다. 상태 사본에 없는 수량·진행률·작업자는 꾸며 채우지 않고 미연결·미확인으로 표시한다. 이번 첫 내부 기획은 읽기 중심이며 클릭이 검수·피킹·포장을 자동 실행하지 않는다.
4. `지도로 돌아가기`로 이전 높이·선택 OS·카메라 위치·확대·선택 창고와 작성 중 입력을 복원한다. 이는 새로운 지도 진입이 아니라 기존 작업 복귀이므로 대표 OS로 다시 초기화하지 않는다. 내부에서도 공통 시간과 긴급한 일의 복귀 경로를 유지한다.

내부 보기는 선택한 건물의 상세 관점이며 별도 세계·지역·다섯 번째 지도 높이를 만들지 않는다. 기존 소비판의 보기/배치 객체를 재사용하는 방향으로 인계하고 새 공식 Scene을 임의 생성하지 않는다.

### 실제 공간과 가상 모델의 구별

실제 건물의 내부 도면·치수·랙 배치는 현재 확인하지 않았다. 외곽 도형과 주소만으로 내부를 복원했다고 표현하지 않는다. 내부 모델은 우선 **가상 창고 배치**로 명시하고 업무 상태와 위치 결속이 준비된 객체만 상태를 연결한다. 내부 모델 자체가 준비되지 않은 건물은 기존 건물 카드에 `내부 표현 준비 중`과 복귀를 제공한다.

실제 공간 자료가 후속 확보되더라도 도면 이용 조건·판본·외부 좌표와 내부 위치의 연결은 따로 확인한다. Renderer·카메라·입체 배치의 변화가 가용 수량이나 업무 상태의 권위가 되지 않는다.

## 4. 시안과 후속 구현의 확인 기준

현재 Claude 시안 0~5는 전체 구조·지도별 업무의 참고다. **창고 내부 모델은 그 여섯 장에 없으며 새 검토 대상**이다. 기존 여섯 장의 전체 색·사업 잠금·Core 통합 방식을 이번에 일괄 채택한 것으로 해석하지 않는다.

후속 시각 검토는 같은 창고의 `동네 외관·선택`과 `내부 전체·랙/포장 작업대`를 대조해 진입·귀환과 공간 판독을 확인한다. [화면 시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 시각안을 검토한 뒤 적용할 범위를 인계한다. 현재 Claude의 코드·실행 소유는 건드리지 않는다.

| 확인 항목 | 통과 기준 |
| --- | --- |
| 지도별 경영 판독 | 건물·동네·구·광역에 들어오면 무엇을 경영하는 화면인지 알 수 있음 |
| 자동 초점·동일 높이 이동 | 높이 변경은 대표 업무로, 같은 높이 이동은 선택 OS 유지로 동작 |
| 동일 업무·긴급 복귀 | 높이가 달라도 수량·Revision·진행이 일치하고 긴급한 장소로 돌아갈 수 있음 |
| 입력·권한·해금 | 전환만으로 입력/선택이 지워지거나 명령·권한·사업 준비 상태가 바뀌지 않음 |
| 창고 내부 진입 | 단일 창고 선택 또는 복합 건물의 창고 역할 선택으로 내부 모델을 확인 |
| 공간 판독 | 랙·통로·피킹·포장·입출고·격리 구역이 구별되고 지붕·벽이 필요한 정보를 가리지 않음 |
| 내부 상태·귀환 | 객체 상세는 같은 업무 상태를 읽으며 지도로 돌아가면 원래 카메라·선택·입력이 복원됨 |
| 미준비·가상 구별 | 가상 내부와 미확인 상태를 표시하고 내부 모델이 없으면 준비 중 카드와 복귀가 제공됨 |

이번에는 기획 문서·진입 링크·diff를 검증한다. 실제 코드·모델·Game View·입력·Save/Replay·서버 연결은 실행하지 않으며 위 통과 기준을 실제 완료로 보고하지 않는다.

## 미정과 다음 검토 하나

확정 범위는 지도별 주 업무·높이별 자동 초점·공통 상태/입력 보존·창고 내부 모델 확인과 귀환이다. 내부의 정확 치수·배치 밀도·자산·시점은 시각안으로 확정한다. 새 API·저장 계약·Core 통합·우유 5팩 구현 범위는 이 문서에서 정하지 않는다.

다음 검토 하나는 **창고 내부의 랙·통로·포장 작업대·입출고 구역이 한 화면에서 읽히는 시각 구성이 적절한가**다. 사용자 전달 기준 구현 중인 Claude 작업은 별도 반환을 받아 현재 문서와 대조한다.
