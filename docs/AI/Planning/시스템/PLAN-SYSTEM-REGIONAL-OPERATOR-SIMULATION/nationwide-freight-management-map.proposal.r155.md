## r253 지도 바탕의 네 상세 수준 — 제안

**확대할수록 같은 위치에 지형·주변 맥락이 추가되는 지도**를 추천한다. 전국→권역→시군/시설 주변→부지로 정보가 자세해진다. 새로운 업무 영역이나 공식 Scene을 만들지 않고 전국 관찰 안의 상세 수준으로 설계한다. 기존 동네/구 이동의 의미는 r184를 유지한다.

## r253 자료를 확대 단계에 연결하는 방법

1. **같은 위경도와 선택 관측 ID를 유지한다.** 타일을 바꿀 때 화면 중심/마우스 아래 좌표와 선택점을 보존한다. 바탕을 맞추려고 시설 좌표를 바꾸거나, 새 지형 메시의 가까운 건물로 점을 자동 옮기지 않는다.
2. **화면 크기에 맞는 바탕을 준비한다.** 전국 요약과 지역 상세를 여러 해상도로 미리 가공하고, 선택 지역/주변 타일만 읽는 안이다. 게임에서 원 공급자를 매 프레임 호출하지 않는다. 실제 원본 해상도 이상의 정밀도를 새로 생긴 것처럼 표시하지 않는다.
3. **자료가 준비된 곳에서만 상세해진다.** 로딩 중에는 마지막 정상 바탕을 유지한다. 미확보/실패/오래된 자료는 구분하며 저상세 확대를 최신 정밀 지도처럼 보이지 않게 한다. 축척 막대와 ‘상세 자료 미확보’ 상태를 제공한다. 타일 경계와 전환 문턱에는 깜빡임/반복 읽기를 막는 처리가 필요하다.
4. **지도 근거와 시설점의 정확도를 따로 읽는다.** 30m 바탕이 있다고 시설점의 정확도가 30m가 되는 것은 아니다. 경기 원문 경위도의 위치 정밀도는 미기재 상태로 두고, 주소·건물·부지 대응 근거를 별도 연결한다. 실제 좌표가 바다/강 위에 보이면 해안으로 자동 보정하지 않고 원천/변환/기준일을 조사한다.
5. **높이는 표현과 배치를 구분한다.** Copernicus는 건물·식생 등을 포함하는 DSM이다. 음영 참고용 표면과 건물 기초·도로의 실제 지표면 높이/수직 기준을 혼합하지 않는다. 지형에 빛을 띄우더라도 수평 좌표와 원본 높이는 보존하고 시각적 띄움/과장은 별도 표현값으로 둔다.
6. **이름표·업무·귀환을 함께 검증한다.** 지형을 가리는 큰 국제 통계판/거점 이름표는 상세 보기에서 줄이는 시안을 만든다. 선택 시설 카드는 유지하고 이전 전체보기 위치로 돌아온다. 바탕/축척·층 전환은 시계·돈·주문·소유·저장 결과를 바꾸지 않는다. 보기 중 정상 시간 경과와 지도 조작의 효과를 구분한다.

## r253 첫 비교와 후속 개발 범위

첫 비교는 **같은 경기 창고 관측을 중심으로 넓게/가깝게 본 실제 표면고도 음영과 시설점**으로 잡았다. [40km/8km 자료 비교도](../../../../../artifacts/local/nation-terrain-detail-r253-20261116/same-facility-dsm-40km-8km.png)를 만들고 직접 판독했다. 같은 S1 중심으로 각각 471개/63개 창고 관측을 표시했으며 상호/주소·도로/강/건물 도형을 추가하지 않았다. 원천은 30m급이고 8km 패널을 크게 표시해도 측량 정밀도가 높아지는 것은 아니다. ## 1. 전국에서는 운송망을 경영한다

전국 화면의 핵심 질문은 **어느 지역의 어떤 화물을 어떤 차량에 맡기고, 하차 뒤 그 차량을 어디에 다시 쓸 것인가**다. 화물 핀·차량·센터·운송 연결을 보고 후보의 이유와 대가를 비교하는 경영 지도다.

전국 판은 처음부터 전체를 관찰할 수 있게 제안한다. 상세 자료가 있는 지역과 현재 운영 가능한 사업/거점은 별도로 표시한다. 전국을 보기 위해 모든 지역의 건물·도로·NPC 상세를 먼저 만들거나, 음식 배달을 전부 끝내도록 강제하지 않는다. 전국을 볼 수 있다는 사실이 모든 지역의 즉시 배차·사업 권한을 뜻하지도 않는다.

‘팔도’는 사용자가 말한 넓은 전국 판의 느낌으로 반영한다. 첫 분류·자료 연결은 판본이 확인된 대한민국 시·도와 하위 지역 ID를 쓴다. 나중에 게임용 운송 권역이나 역사적 권역 이름을 쓰더라도 현대 행정 코드·경계에 덮어쓰지 않는다. 정확히 여덟 칸으로 만들기 위해 지역을 임의로 합치거나 삭제하지 않는다.

## 2. 지도 높이별 책임

| 관점 | 주로 보이는 것 | 주로 결정하는 것 |
| --- | --- | --- |
| 전국 | 시·도 이름, 거점, 권역 간 운송, 미배정 화물·가용/운행 차량·공차·지연 위험 요약 | 어떤 화물을 받을지, 어떤 권역/차량을 지원할지, 복귀 전략 |
| 시·도/운송 권역 | 간선 도로, 센터·집결지, 지역별 작업량·차량 일정 | 차량 후보·회차·배차 시점·가능한 묶음 비교 |
| 시·군·구 | 구체적인 상하차 거점과 지역 접근 경로 | 픽업 순서·지역 차량·지연 대응 |
| 동네/건물 | 같은 운송의 현장과 적재·상하차·검수 작업 | 준비된 현장 행동·직접 수행·인계 |

이는 r144의 광역 화물 경영을 전국과 권역 관점으로 구체화하는 제안이다. 기존 표시명·고유 ID를 조용히 바꾸거나 모든 지역에 ‘구’ 계층을 강제하지 않는다. 운송 서비스 권역은 행정 경계와 별도 관계로 둔다.

높이를 바꿔도 **같은 화물·차량·운송 ID, Revision, 시계와 잔여 일정**을 읽는다. 선택 운송과 작성 중 판단을 보존하고 원래 경영 화면으로 돌아올 수 있게 한다. 지역/지도 선택으로 배차·수락·상차·도착·하차 완료나 정산을 만들지 않는다. 경계 밖으로 이동해도 화물과 차량 상태를 버리지 않는다.

## 3. 전국 화면의 모습과 사건 표현

후속 [옅은 아치형 운송선 r156](soft-arc-freight-links.design.r156.md)은 사용자가 말한 서울→충청처럼 솟았다 내려오는 부드러운 곡선 방향을 기록한다. 실제 도로 경로와 구별하며 선 위의 빛/이동은 아직 선택하지 않았다.

기본 바탕은 낮은 대비의 전국 경계와 지명이다. 관리하는 센터·창고·지사만 역할 표식과 운영색으로 찾을 수 있게 한다. 도시나 도 전체를 소유한 것처럼 칠하지 않는다. 선택 지역 강조·새 사건 강조·운영 관계의 색을 구별한다.

처음에는 권역별 요약만 두고, 화물이나 차량을 고르면 해당 한 건의 출발·도착·남은 정차와 비교 후보를 펼친다. 모든 화물·차량·연결선을 한꺼번에 그리지 않는다. 배경 요약은 다음처럼 단위를 분리한다.

- **현재 업무:** 미배정 화물 건수, 가용/운행 차량 대수, 지연 위험 운송 건수.
- **실행 결과:** 실제 Simulation에서 확정된 이동거리·작업시간·공차 비용·수익 등.
- **참고 통계/예측:** 원자료의 기준 연도·단위·오차/미확인 상태를 가진 지역 간 흐름. 실제 접수 주문이나 현재 차량 수가 아니다.

r154 핀·파동은 전국에서는 해당 권역/거점의 새 사건 요약으로 줄인다. 선택/확대하면 같은 사건과 개별 운송을 확인한다. 많은 사건은 대표 연출과 새 건수로 묶고, 현재 미처리 업무는 별도로 유지한다. 재조회/복원·축척 전환은 재발생이 아니며 화면 밖 새 화물이 카메라나 집중 작업을 자동으로 빼앗지 않는다.

## 4. 화물 배차의 플레이

첫 역할은 **배차실 운영자**를 추천한다. 운전·상하차 미니게임은 이후 같은 업무에 참여하는 방식으로 연결할 수 있지만 전국 배차를 시작하기 위한 필수 선행 작업으로 두지 않는다.

1. 출발지·도착지와 납기가 다른 화물을 본다.
2. 현재 적격 차량의 위치·이미 맡은 일정·상하차 시간·적재 조건을 비교한다.
3. 엔진의 후보·이유·예상 비용을 보고 플레이어가 배차를 결정한다. 확정 경계에서 최신 상태를 다시 검증한다.
4. 같은 세계 시계에서 상차→운송→하차/확인 결과를 관찰한다. 차량 그림의 도착이나 파동 종료를 업무 완료로 사용하지 않는다.
5. 하차 뒤 **현지 대기 / 가능한 복귀 화물 / 공차 복귀**를 비교하고 다음 운영을 선택한다.

예를 들어 수도권에서 충청권으로 보낸 차를 바로 빈 차로 돌려보낼지, 다음 납기를 지킬 수 있는 복귀 화물을 맡길지 판단한다. 지역·시설은 시범 설정이고 물량·운임·거리·시각은 확인한 팩 또는 가상 조건으로 명시한다. 복귀 화물이 항상 나온다고 보장하지 않는다. 차고지·기사의 집·희망 복귀 권역은 서로 다른 값이며 하나로 추정하지 않는다.

처음부터 차량/기사 적격·가용, 유효 경로, 기존 약속, 상하차 작업시간·시간창, 선상차후하차, 구간 중량/부피·혼적/독차 조건을 기존 계약대로 검사한다. 전국화·성장 단계가 이 제약을 낮추지 않는다. 수익뿐 아니라 기사 작업/대기와 보수·지연·공차 비용을 함께 평가한다. 보상 금액과 성장 비용은 미정이며 장식 선택·경계 통과 횟수를 보상으로 세지 않는다.

## 5. 지도·도로·수요·규칙을 잇는 자료 구조

```text
출처/판본을 보존한 원자료
  → 전국/권역 공간 팩 + 거점 팩 + 운송 경로 팩 + 가상 화물 시나리오
  → 같은 Simulation Core의 화물 상태·후보 계산
  → 전국/권역/지역/현장별 조회 결과
  → 기존 지도·표식·선택·공통 사건 표현
```

| 묶음 | 필요한 내용 | 현재 확인과 후속 |
| --- | --- | --- |
| 경계·지역 | 시·도/시·군·구 ID·부모 관계·좌표계·도형·기준일 | 기존 광역 참고 사본과 전국 원본 재고를 대조. 사본 존재가 현행 정본·배포 가능의 증거는 아님 |
| 거점 | 시설 ID·역할·확인 좌표·접근 지점 | 가상 센터는 가상임을 표시. 실제 건물과 같은 주소라는 이유로 역할을 부여하지 않음 |
| 운송 경로 | 연결된 도로 노드/링크·방향·거리·시간 근거·차량별 제한/미확인 | 기존 표준노드링크 가공을 재사용 후보로 조사. 도로 그림·이름 위치가 경로 그래프는 아님 |
| 화물 흐름 | 출발→도착 권역, 품목/차종, 기준 연도·단위·자료 범위 | KTDB 등 공식 자료를 후보로 확인. 통계 분포를 바탕으로 생성한 건별 주문은 가상으로 구별 |
| 규칙·상태 | 차량·화물·현재 일정·후보·수락/작업·권위 결과 | 기존 음식/화물·창고 계약을 재사용하며 게임의 실제 소비 연결은 따로 검증 |

실제 주행 경로가 준비되지 않은 선은 **운송 관계선**으로 표시한다. 행정 경계·직선 연결·거리 근사를 실도로 경로·차량 통행 가능·확정 ETA로 표시하지 않는다. 도로의 연결성과 차종 제한을 확인한 뒤 선택 운송의 실제 경로를 소비한다. 제주 등 별도 운송 연결이 필요한 경우 도로 직선으로 대체하지 않고 연결 준비 상태를 표시한다. 자료 부족을 0분·비용0·수요0으로 채우지 않는다.

전국 경계와 저해상 요약은 가볍게 유지하고, 선택 지역의 상세만 불러온다. 화면 밖 운송은 권위 상태와 같은 시계로 계속 관리하며 상세 객체를 내리는 것은 차량/화물 삭제가 아니다. 기존 단일 World/공식 Scene 경계를 유지한다.

## 6. 이번 공식 자료 확인

2026-11-13 웹 안내 확인 기준, [KTDB 교통통계DB](https://www.ktdb.go.kr/www/selectTrnsportTreeView.do?key=32)는 화물 지역 간 기종점통행량 항목을 안내한다. 해당 항목은 구축기간 2011~2022, 통행/일 단위로 표시돼 있어 현재 실시간 주문이나 톤 단위 물동량으로 바로 쓸 수 없다. 후속 팩에서는 실제 선택 파일의 연도·단위·대상 범위·갱신 시점과 집계 방법을 다시 결속한다.

[KTDB 자료신청 안내](https://ktdb.go.kr/www/contents.do?key=202)는 화물 O/D와 교통분석용 네트워크 등 신청 절차를 안내한다. 이번에는 안내만 읽었고 신청서·약관 동의·다운로드·계정 조작·수집 예약은 수행하지 않았다. 취득·변환·게임 배포 가능은 각각 조건을 확인한다. 원본을 이미 보유했는지 먼저 대조하고 부족한 것만 후속 수집 대상으로 삼는다.

## 7. 이미 있는 기반과 실제 결손

이번 읽기 전용 대조에서 WindowsGame의 지도 수준은 `Dong / District / Seoul`이며 전국 화물 경영판이 연결돼 있지는 않다. 서울 관찰 자료도 서울 윤곽용이다. 현재 게임의 `CargoTransportModule`은 한 대 차량·센터→점포의 최소 사슬과 팩의 고정 `travelSeconds`를 사용하므로 전국 경로 기반 배차·복귀 완료로 확대하지 않는다.

별도 Unity `Presentation/WorldMap`에는 지구본·한반도 곡면 지형·광역 경계 관찰 기반이 있다. 로컬 광역 참고 사본은 남북한을 함께 포함하고 `distributionApproved=false`, 통행 준비 전 경계를 가진다. 대한민국 필터·현재 기준일·코드 매핑·배포 조건을 확인해야 하며 과거 문서의 미확보 목록을 현재 저장소 전체의 부재로 단정하지 않는다.

기존 `prep_gu_roads.py`는 표준노드링크를 구 지도 그림·이름 앵커로 가공한다. 전국 연결 그래프·전국 시군구 정본 팩·도로별 화물 통행 조건이 현재 게임에 준비됐다는 근거는 확인하지 않았다. 기존 자료를 버리거나 전국을 새로 수집하기 전에 이 연결 차이를 감사한다.

서버 쪽의 [시간 약속/정차 순서 r20](../../공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-feasible-stop-order.r20.md)과 [권역 이동·복귀 검증 r23](../../공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-cross-region-return.verification.r23.md)은 재사용 근거다. 서버의 제한된 합성 검증·현재 코드 존재를 Unity 전국 게임 통합·실도로·실운행 완료로 세지 않는다.

## 8. 권장 진행 순서

1. **전국 관찰 화면:** 기존 지리 기반에서 대한민국 범위·시·도·지명을 판독하고 지역 선택/복귀를 준비한다. 미준비 상세는 그대로 표시한다. 전국을 한눈에 볼 수 있는 점을 먼저 확보한다.
2. **전국 판 위의 작은 배차 회차:** 가상 거점 A↔B·차량2대·기본 운송1건과 복귀 후보1건으로 후보 비교→명시 확정→상하차 결과→복귀/대기/공차 선택을 검증한다. 전국의 다른 지역은 관찰 가능하며 모든 지역을 동시에 실행 가능으로 만들지는 않는다.
3. **권역·도로·거점 확장:** 확인한 데이터 팩과 같은 계약으로 경로·거점·화물 프로필을 넓히고 중간 정차·자료 부족·지연/복구를 검증한다.
4. **지역 경영과 선택적 연결:** 구 지도·센터 내부·가맹 공급 같은 준비된 업무와 동일 운송을 다른 높이에서 본다. Farm→Hub→City나 우유 사슬을 전국 화물의 필수 시작 조건으로 삼지 않는다.

첫 회차는 합성 입력이면 이를 명시하고 실제 전국 노선 검증으로 보고하지 않는다. 성공뿐 아니라 복귀 후보가 기존 납기를 어겨 보류되는 경우, 길/좌표 미확인, 취소/지연 후 재선택, 저장/재진입에서 같은 운송·시계·보수가 이어지는 경우를 확인해야 한다. 구현 전에 시각안·기획 revision/hash·주체/WI·작업 명세·쓰기 경로·E1~E7 검증 범위를 별도로 결속한다.

- **확정:** 사용자가 대한민국 전국을 첫 지도/운송 범위로 선택했다. 전국 화물 경영의 제안을 요청했다.
- **제안·미정:** 전국/권역의 화면·역할, 첫 가상 회차·노선·시설, 자료 판본/권리·비용/보상·Core 어댑터·구현 순서. 대한민국 선택은 이 세부안의 일괄 승인이 아니다.
- **다음 질문 하나:** 전국 지도를 먼저 펼치고, 첫 시범 플레이는 **배차실 운영자가 수도권↔충청권의 가상 운송과 복귀/공차를 판단하는 회차**로 잡을까? 넓은 화면과 작은 검증을 함께 얻을 수 있어 이를 추천한다.
