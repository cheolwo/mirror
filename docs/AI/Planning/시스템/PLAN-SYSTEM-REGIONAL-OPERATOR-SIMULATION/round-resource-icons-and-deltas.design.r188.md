## 1. 플레이어가 알아야 할 것

**“지금 얼마나 가지고 있고, 이번 운영에서 무엇이 얼마나 바뀌었으며, 다음에 무엇을 보완할까?”**를 작은 요약 띠에서 읽는다. 많은 사업 수치를 한꺼번에 상시 노출하지 않는다.

- 지금: 같은 현실 날짜의 짧은 운영 회차가 진행되거나 막 끝난 때.
- 여기: 선택한 동/구/전국 지도 또는 카페·창고 같은 사업 공간. 지도 축척과 자원 소유 범위는 서로 다른 선택이다.
- 나: 선택한 사업/작업을 운영하는 플레이어. 직접 수행·관찰/위임 모두 자신의 확인된 결과를 읽는다.
- 너: 해당 업무의 자금·재고·작업 결과·활성 연구. 원장에 기록된 상태와 아직 예상인 값을 구분할 수 있다.
- 이렇게: 아이콘+짧은 이름+단위 있는 값+증감을 읽고, 필요한 항목만 열어 이유를 본 뒤 다음 작업·보충·개선을 고른다. 결과가 나쁘거나 자원이 부족하면 기존 보류/보충/방법 변경 경로로 돌아온다.

이 표현은 경영 판단을 돕는 보조 층이다. 자원을 보는 행위 자체가 사람의 회복·숙련·기여 또는 업무 성공을 만들지 않는다. 괘·오행은 이 숫자의 산식이나 자원 종류로 새로 대입하지 않는다.

## 2. 추천하는 최소 표시

**기본 3항목: 가용자금 · 이번 회차 완료량 · 현재 사업의 핵심 가용자원.** 활성 연구가 있고 실제 진행값이 연결됐을 때만 연구 1항목을 추가한다. 상세 목록은 접어 두고 초보자에게 잠긴 자원 칸을 늘어놓지 않는다. 정확한 칸 수·순서·크기는 시안 검토 대상이다.

| 항목 | 아이콘 의도 | 큰 숫자 | 작은 변화 표시 |
| --- | --- | --- | --- |
| 가용자금 | 동전/지갑 | 현재 실제 사용 가능한 게임 자금, 통화 포함 | 이번 회차에 귀속된 가용자금 변화. 현금 이동과 예약/해제를 상세에서 구분 |
| 완료량 | 현재 직무의 결과물: 전달/음료/포장 등 | 이번 회차의 정해진 단계 완료량 | 새 완료 기록이 올 때 일시적으로 `+1건` 등 표시. 마감 시 같은 값을 다시 더하지 않음 |
| 핵심 가용자원 | 재료/재고/인력 등 현재 병목 | 해당 품목·단위 또는 적격 가용 인원 | 같은 자원의 이번 회차 증감. 소모·예약·해제·폐기 등의 이유와 연결 |
| 활성 연구 | 연구/개선 | 선택한 과제의 진행값 또는 현재 단계 | 같은 과제의 유효 진척만 표시. 진행률 미연결이면 단계명 사용 |

문명의 골드·식량·생산·과학을 동일한 공통 재화로 옮기지는 않는다. 기존 자금·재고·업무 성과·연구를 간결하게 읽는 방식이다. 범용 연구 포인트, 생산 포인트, 회차 고정 수당을 새로 확정하지 않는다.

기존 r37의 4지표(가용현금·향후7일 지급의무·13주 현금 최저점·정산 확인 필요)는 기존 운영자 통합 화면의 회계 요약 책임으로 유지한다. 여기의 게임 기본 요약 띠가 그 지표를 삭제하거나 바꾸는 것은 아니며 별도 회계 화면을 신설하지 않는다.

## 3. 숫자를 읽는 공통 문법

**상태값**은 `우유 8팩`, **회차 변화**는 `이번 회차 −2팩`, **예상값**은 `예상 −1팩`처럼 쓴다. 작업 완료량은 보유 재고와 달리 `이번 회차 전달 3건`처럼 기간 실적임을 이름에 넣는다.

| 구분 | 표현 예시 | 의미 |
| --- | --- | --- |
| 보유/가용 상태 | `가용자금 50,000원` | 표시 시점과 소유 범위가 같은 권위 상태. 매출/이익/미수금을 현금에 합치지 않음 |
| 확정 회차 증감 | `이번 회차 +2,000원` | 이번 회차에 결속된 확인된 기록으로 계산한 변화 |
| 다음 계획 예상 | `예상 −1,200원` | 선택한 계획의 추정. 확정값과 별도 표기하며 근거/가정 확인 가능 |
| 실제 단위 시간당 값 | `시간당 최대 12건` | 처리 능력/추정 속도. 회차 완료 실적과 다른 지표로 표시 |
| 일일 누적 | `오늘 전달 7건` | KST 날짜별 원본 기록 조회. 회차와 함께 더해 새 실적으로 만들지 않음 |

고정 길이가 아닌 운영 회차에 `회차당 +2,000원`을 무조건 보장 수입처럼 표시하지 않는다. **이번 회차의 실제 변화**와 **선택한 계획의 예상 변화**를 구분한다. 회차를 오래 열어 두거나 마감 버튼을 반복해서 눌러도 새 자원은 생기지 않는다.

`+`는 증가, `−`는 감소이며 좋고 나쁨을 뜻하지 않는다. 재고 소모·광고비·연구비는 의도한 비용일 수 있고, 대기/불량 감소는 개선일 수 있다. 색만으로 해석시키지 않고 이름·단위·부호·필요한 이유를 함께 쓴다. 기존 민트/회색 화면 스타일과 가독성을 따른다.

비율은 `+2%p`, 수량은 `−200mL`, 시간은 `대기 −3분`처럼 단위를 붙인다. 작은 유효 변화가 반올림되어 `0`으로 사라지면 `<표시 최소 단위`를 쓰고 상세에 정확값을 둔다. 유효한 0은 `0`, 미연결/미확인은 `—`와 이유로 구별한다. 아이콘을 알아보지 못하거나 효과를 꺼도 짧은 이름과 수치를 읽을 수 있어야 한다.

## 4. 분야별로 달라지는 두 항목

가용자금 외의 완료량·핵심 자원은 선택한 사업에 맞춘다. 아래는 후보이며 실제 가용/완료 의미와 원장 필드는 개발 수용 전에 대조한다.

| 분야 | 회차 완료량 후보 | 핵심 가용자원 후보/주의 |
| --- | --- | --- |
| 배달 | 전달 완료 건수 | 적격 가용 기사/운송 여력. 대기 주문은 별도 수요 상태이며 자원 보유로 합치지 않음 |
| 카페 | 인수 완료 음료 잔수 | 선택한 원두·우유 등 한 품목. 제조 완료·인수 완료·매출은 서로 다른 단계 |
| 창고 | 현재 업무의 입고 인수/피킹/포장/출고 완료량 | 선택 SKU의 가용 재고 또는 포장재. 단계별 수량을 더해 같은 물건을 중복 생산한 것으로 세지 않음 |
| 광고 | 유효 유입 또는 연결된 주문 중 선택한 목표 | 남은 집행 가능 예산. 전체 자금 안의 예산 예약을 별도 자산처럼 합산하지 않음. 노출·클릭·유입·주문도 서로 합산하지 않음 |
| 전자상거래 | 이행 완료 주문/출고 중 선택한 단계 | 판매 가능한 특정 SKU/포장재. 판매·출고·배송·반품의 결과를 구별 |
| 무역/화물 | 검수 인수/운송 완료 중 선택한 단계 | 품목별 가용 물량/적격 운송 여력. 통화·중량·컨테이너 단위를 명시 |

서로 다른 SKU·용량·단위·통화를 하나의 재고/돈 숫자로 단순 합산하지 않는다. 여러 품목은 특정 핵심 품목 하나와 `다른 품목 보기`로 축약한다. 기준 통화 환산은 검증된 환율/기준시각이 연결된 별도 참고 표시일 때만 사용한다. 지도 축척 변경만으로 자금/재고의 소유 범위를 조용히 바꾸지 않는다.

만족도·경 시간·개인 숙련은 이 띠에 더하는 범용 재화가 아니다. r175의 주체별 근거와 성장 규칙을 유지하며 투자/연구 완료와 동시에 `+만족/+경/+소득`을 일괄 지급하지 않는다.

## 5. 한 장면의 읽기 예시

다음은 **가상 카페 회차의 문구 예시**이며 잔액·단가·보상·연구 속도 승인이나 실제 화면/자료가 아니다.

| 표시 | 이번 회차 변화/설명 |
| --- | --- |
| 지갑 · 가용자금 `50,000원` | `+2,000원` · 이 회차 관련 수입3,000원/지출1,000원. 예시에서는 예약 변화 없음 |
| 컵 · 인수 완료 `3잔` | `이번 회차` · 마지막 신규 완료 때만 `+1잔`을 잠깐 표시 |
| 재료 · 우유 `8팩` | `−2팩` · 동일 SKU·용량의 사용 가능한 재고, 제조 소모 |
| 연구 · 동선 개선 `40%` | `+10%p` · 활성 과제의 확정 진척이 연결됐다는 예시에서만 표시 |

계획 단계의 미발생 금액은 위 확정 변화와 별도의 `예상` 항목으로 둔다. 수행대금이 정산됐으나 미수금이면 가용자금 증가로 바꾸지 않고 상세에서 미수금 상태로 읽는다. 연구 진행값이 없는 현재 구현에는 예시40%를 임시로 채우지 않는다.

아이콘을 선택하면 **이번 회차의 증가/감소 이유→관련 작업/품목→현재 가능한 다음 선택**만 먼저 펼친다. 예: 우유 소모 확인→잔량/예약량 확인→기존 보충/메뉴 선택으로 이동→같은 사업 화면 복귀. 지표 선택이 자동 구매·배차·연구 도입을 실행하지 않는다.

## 6. 회차·일일 결산·동시 사업의 연결

1. 준비: 소유 범위·대상 회차·대상 작업을 명시한다. 아직 실행하지 않은 계획은 예상으로만 읽는다.
2. 실행/관찰: 실제 기록이 생긴 만큼 이번 회차 실적/변화가 갱신된다. 화면 그리기·애니메이션·시간 경과 자체가 적립 명령은 아니다.
3. 결과/마감: 마감 시점의 집계 기준을 보여 준다. r187처럼 실제 작업 결과를 확인하며 마감이 지급·재고 변화·추가 Tick을 만들지 않는다.
4. 다음 회차: 새 회차의 실적 조회 범위만 바꾼다. 자금/재고·이전 결과·진행 중인 다른 사업은 보존한다. 새 회차의 유효0과 미연결을 구별한다.
5. 오늘 결산: r174의 원본 기록 시각으로 같은 자료를 날짜별 재조회한다. 같은 회차가 자정을 걸치면 각 기록은 해당 날짜에 속하며 회차합계와 하루합계는 같지 않을 수 있다.

현재 보유량과 회차 실적은 조회 범위가 다를 수 있다. 예를 들어 `전체 자금`과 `카페 2호점 · 이번 회차`를 함께 읽을 때 범위를 명시한다. 동시 사업/지연 지급이 섞이므로 전체 잔액의 종료−시작을 선택한 주문/사업의 회차 성과로 사용하지 않는다.

가용자금 변화는 현금 수입−지출과 언제나 같지는 않다. 기존 가용 기준의 예약/해제 변화도 상세에서 구분하고, 그 필드가 연결되지 않으면 `현금잔액`처럼 실제 제공된 의미로 이름을 좁히거나 `미연결`로 둔다. 광고 예산·연구 예약이 전체 자금과 별도 돈으로 중복 계산되지 않게 한다.

작업·회차에 귀속된 권위 기록을 고유 ID/판본·정정 계보로 조회한다. 이전 회차 관련 후속 지급/정정은 원래 관련 작업과 실제 기록 시각을 보여 주며 새 회차의 직접 수행 성과로 돌리지 않는다. 이미 본 결과의 정정은 기준 판본/시점을 표시해 다시 조회하고 중복 적립하지 않는다. 회차 귀속 계약이 아직 없으면 해당 증감을 미연결로 두고 임의 배분하지 않는다. 영속 저장/지연 귀속의 상세 계약은 별도 설계 대상이다.

## 7. 구현 전에 확정할 작은 범위

추천은 **기존 r187의 한 작업·두 회차 결과에 연결된 읽기 전용 요약**부터 시안으로 확인하는 것이다. 모든 분야의 새 자원·연구 시스템을 동시에 구현하지 않는다. 한 건 결과의 금액이 미연결이면 완료량만 확정 표시하고 금액은 미연결로 남긴다.

개발 전에는 지표별로 의미/단위·소유/작업/기간 범위·권위 필드와 판본·기록시각·가용/예약 기준·예상 산식·결측·정정/중복 처리를 기존 계약에 결속한다. 새 DTO/원장/재화를 이 문서만으로 발급하지 않는다. 승인된 화면 시안과 WI/E1~E7 작업 명세·정확 쓰기 경로/담당을 별도로 수용한다. [화면 시안 절차](../../../../Architecture/화면시안선행제작절차.md)를 따르며 이번 문구 예시는 이미지 시안의 승인이나 Runtime 증거를 대신하지 않는다.

향후 검토에서 볼 것:

- 첫 한 건을 끝냈을 때 플레이어가 보유량/회차 증감/예상과 완료량을 구별할 수 있는가.
- 직접 수행·관찰/위임·지도 축척/사업 변경에서도 같은 근거/범위를 읽는가.
- 미지급·예약/해제·품목/통화·마감/다음 회차·중복 클릭·지연 정정·동시 사업·자정에서 중복/오귀속이 없는가.
- `0`/`—`·부호/단위·비율 변화가 읽히고, 재고 소모/대기 감소의 의미를 색만으로 판단하지 않는가.
- 같은 기록을 다시 보거나 효과를 끄더라도 값이 바뀌지 않고 상세 확인 뒤 원래 사업/회차로 돌아오는가.
