## 확정

사가정·면목제3·8동의 첫 점심 피크 캠페인을 제3괘 `수뢰둔(䷂ 屯)`에서 영감을 얻는 첫 배달 플랫폼 운영 캠페인으로 결속한다.

- 중심 사건은 `예상보다 빠른 점심 주문 증가 + 가용 기사 부족`이다.
- 수뢰둔의 의미는 준비가 부족한 초기에 성급히 크게 확장하지 않고, 작은 기반·관계·권한·운영 질서를 세운 뒤 회복 가능한 손실을 감당하는 흐름으로 번역한다.
- 기존 한스 농장 수뢰둔 캠페인의 인물·농장·H·WI·공간·완료 상태를 배달 운영 캠페인으로 복사하지 않는다.
- `HEX-03-ZHUN`은 의미 참조이고, 실제 운영 Campaign은 별도의 안정 식별자·revision·상태 사본을 가진다.
- 수뢰둔 결속만으로 Graph Map, 디오라마, Unity 객체나 Evidence를 생성·승격하지 않는다. 각 운영 국면의 공간 필요가 승인된 뒤 공간 보완 묶음으로 인계한다.

## 운영 캠페인의 약속

플레이어는 완성된 대형 플랫폼을 지휘하는 것이 아니라, 실제 지역 자료를 읽는 작은 가상 배달 플랫폼의 운영자로 시작한다. 첫 점심 피크에서 기사와 음식점을 무리하게 밀어붙여 모든 주문을 즉시 처리하는 것이 목표가 아니다.

운영자는 다음 질서를 세운다.

1. 주문 증가와 기사 부족을 서로 다른 원인으로 판독한다.
2. 현재 기사·음식점·경로·현금의 안전선을 먼저 확인한다.
3. 기사 가용 의향 알림을 Preview하고 응답한 후보만 별도 배차 계산에 넘긴다.
4. 부족이 이어질 때만 플랫폼 부담의 제한된 피크 할증을 검토한다.
5. 정상 흐름은 자동화하고 판단이 필요한 예외만 직접 처리한다.
6. 피크가 끝난 뒤 서비스·노동·현금·미해소 예외와 회복 가능 손실을 결산한다.

모든 주문을 지연 없이 처리하는 완벽한 결과를 첫 완주의 필수 조건으로 두지 않는다. 안전선과 지급의무를 지키고, 미해소 사건을 숨기지 않으며, 다음 회차에서 회복 가능한 상태로 마치는 것이 첫 완주의 기준이다.

## 첫 공간 보완 관문

초구 상세가 승인되기 전에는 디오라마를 수정하지 않는다. 승인 뒤에도 다음 순서로 좁게 보완한다.

`현행 사가정 디오라마 재사용 감사 → 실제 음식점·기사 대기·도로 자료의 출처 확인 → 필요한 오버레이·앵커만 후보화 → Graph Map·배치 맵 검토 → Unity 표현 검증`

첫 보완은 건물을 새로 꾸미는 작업보다 운영자가 `어디에서 주문이 몰리고`, `어디에 가용 기사 후보가 있으며`, `어느 경로 자료가 미확정인지` 구분해서 읽을 수 있게 하는 데 우선순위를 둔다. 실제 자료가 없는 기사 대기 지점은 현실 시설로 가장하지 않고 합성 후보 또는 `자료 미확정`으로 표시한다.

## 다음 질문 하나

수뢰둔의 육효와 기존 절기 캠페인의 시간 구조를 어떻게 겹칠까?

1. `육효는 상황 변화 국면, 절기는 시간 배경` — 추천. 한 절기 안에서 여러 효가 진행될 수도 있고 한 효가 여러 날 이어질 수도 있어 실제 운영 흐름을 억지로 시간표에 맞추지 않는다.
2. `육효를 절기 구간에 고정 배치` — 화면은 규칙적이지만 사건 진행이 실제 상황보다 달력에 끌려간다.
3. `수뢰둔과 절기 캠페인을 완전히 분리` — 단순하지만 제철·날씨·기사 수요가 운영 사건에 자연스럽게 스며들기 어렵다.
