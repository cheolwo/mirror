- 승인 근거: 사용자가 음식은10~15분으로 설정하자고 제안했고, ‘커피 오븐’의 의미를 묻는 질문에 **‘네, 커피는 약5분’**이라고 답했다. 두 값은 사용자 지정 게임 기준이며 실측 평균/표준이 아니다.
- 관계: [다직무/레시피 r147](multi-role-minigames-and-realistic-recipes.design.r147.md), [시간 r174](live-calendar-daily-management.baseline.r174.md), [개업 r190](cafe-opening-supply-chains-and-map-linked-process.proposal.r190.md), [자료 갭 r201](gameplay-data-gaps-and-collection-priorities.research.r201.md)의 준비시간 항목을 부분 구체화한다. 개업/공급망 준비기간과 다른 값이다.
- WI·PlayableLoop·Graph Map: 신규 등록/활성화 없음. 제조/조리 작업 프로필의 시간·대기/인계 관계 영향 후보이며 코드/계약·Graph Map을 수정하지 않는다.
- 인계 상태: 기본 시간만 확정. 기준 수량/공정 범위·동시 처리·배속/미니게임 표시시간과 정확 작업 명세/개발 수용은 후속이다.

## 확정한 기본값

| 대상 | 게임의 기본 준비시간 | 확정 상한 |
| --- | --- | --- |

| 음식 | **10~15분** | 대표 음식 조리의 기본 범위. 범위 안 선택 방식/메뉴별 시간은 미정 |

현재 플레이 상황은 주문을 준비하는 바리스타/조리 작업자가 재료와 설비를 사용해 제조/조리를 진행하고 다음 인계로 넘기는 때다. 운영자는 준비 예상과 기사 도착/인력 여력을 비교한다. 지연/재작업은 기존 업무 규칙의 시간/비용을 가지며 준비시간 설정만으로 주문·매출·성장/경 유지 보상을 지급하지 않는다. 상위 목적에는 작업 예측과 대기 조율을 돕는 보조 층으로 연결한다.

## 적용 의미와 남은 조정

- **시간 범위 제안:** 두 값은 제조·조리 작업의 기본시간으로 사용한다. 주문 대기·재고/장비 대기·포장/인계·픽업/이동/배달은 항목을 구분해 중복 계산을 막는다. 정확 시작/끝·기준 수량과 포장 포함 여부는 명세에서 확인한다.
- **레시피와 결속:** 커피5분은 계량/추출/조립/마감 등의 전체 제조 기준으로 제안한다. r147의 에스프레소 추출 조건을5분으로 바꾸거나 세부 단계마다5분을 더하지 않는다. 세부 공정시간·예외 메뉴·여러 잔/여러 음식과 병렬/배치 처리 규칙은 미정이다.
- **게임 시간:** 작업 경과의 기본값으로 연결한다. 실제 화면에서 기다리는 시간·집중 조작 연출 압축·배속/일시정지와 현실 날짜/일일 결산은 기존 규칙 및 후속 명세로 구분한다. 시간값만으로 새로운 시계나 현실 달력 변경을 만들지 않는다.
- **진행 보존:** 집중↔이완·창 닫기/다시 열기·회차 전환에서 같은 작업의 진행·재료/설비 점유를 유지한다. 전환할 때마다5분/10~15분을 다시 시작하거나 완료를 두 번 적용하지 않는다.
- **처리량:** 직원·설비·동시 점유/병목이 정해지기 전에는 시간당 처리량을 단순 역산하지 않는다. 현재 `DongDemandRules.partnerOrdersPerHour` 같은 집계 임시값을 이번 답변으로 자동 교체하지 않는다.
- **자료/설계 구분:** r201에서 부족하다고 본 실제 시간 분포·오류/회복·원가 자료는 계속 후속이다. 이번 두 기본값이 모든 업무의 실측/성능 검증을 대신하지 않는다.
