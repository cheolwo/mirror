## 2. 같은 오행, 서로 다른 판단의 크기

**동은 한 주문과 현장, 구는 여러 동 사이 여력 배분, 전국은 거점·운송망·장기 공급**을 먼저 생각하는 안을 권한다. 오행의 기본 업무 의미는 같고, 누가 무엇을 결정하며 어느 범위까지 영향을 보는지가 달라진다.

| 관점 | 먼저 읽을 질문 | 대표 선택의 제안 | 먼저 비교할 영향 |
| --- | --- | --- | --- |
| 동 오행판 | **이 동에서 지금 어떤 일을 어떻게 이어 갈까?** | 같은 주문의 기사 후보, 매장 보충/제조·인력 준비, 현장 대기 대응 | 한 건/한 거점의 가능 조건·지출·재고·업무 대기·결과. 이름 있는 사람과 장소로 내려간다. |
| 구 오행판 | **동과 지사 사이 어디에 여력을 둘까?** | 지원/모집·보충 우선 동, 다음 지사/거점 후보, 준비 예산의 배분 | 한 곳의 개선과 다른 곳의 남는 여력·이동/지원 부담. 정확한 사람·점포는 동/거점 상세에서 확인한다. |
| 전국 오행판 | **어떤 공급·거점·운송망을 갖출까?** | 사용 가능한 센터/공급 후보, 권역별 물량·운송 회차·차량 후보, 장기 투자/운영 방침 | 여러 구/거점의 비용·납기·재고·처리 능력 변화와 적용 시점. 실제 개별 출고·운송·인수는 해당 업무로 이어진다. |

위의 선택은 해당 사업·준비·권한이 갖춰졌을 때의 후보다. 전국 지도를 처음 열었다고 공급망/센터 계약이나 모든 경영 기능을 쓸 수 있게 되지는 않는다. 작은1호지사의 시작은 기존 r257을 유지하고 동 오행판에서부터 익힐 수 있다.

## 3. 목·화·토·금·수를 범위별로 펼치기 — 제안

아래는 업무 대표 관점의 읽을거리다. 정확한 숫자·기여 비율·예측 모형은 확정하지 않았다.

| 기본 업무 | 동에서 볼 초점 | 구에서 볼 초점 | 전국에서 볼 초점 |
| --- | --- | --- | --- |
| **목 · 주문** | 준비된 개별 주문·발생/도착 수요와 미처리 | 동별 주문 부담·시간대 쏠림·서비스 요청 | 권역/거점별 수요·주문 흐름과 공급 필요 |
| **화 · 음식점** | 점포의 주문 응답·조리/픽업 준비·설비/사람 | 여러 매장의 처리 여력·보충/교육 필요 | 연결된 식품 제조·가공/매장망의 공급 대응. 정확한 사업 범위는 관점/준비 상태에 따른다. |
| **토 · 배차** | 어떤 기사가 어떤 주문을 맡을지 | 동·지사 사이 지원과 배차 부담 조정 | 물량·센터·차량·회차의 조정과 담당 인계 |
| **금 · 창고** | 점포/근거리 창고의 재고·검수·출고 준비 | 지역 보충 거점·공동 재고·작업 여력 | 전국 센터/창고망·권역 재고와 출고 능력 |
| **수 · 배달·운송** | 픽업·동간 이동·전달의 실제 흐름 | 여러 동/지사를 잇는 이동·연계 부담 | 권역 간 화물·간선·보충의 연결과 납기 |

이는 기존 음식점/창고 등에 모든 행위를 같은 오행으로 덮는 표가 아니다. 실제 한 번의 행위와 프랜차이즈 공급 관계 등 다른 관점은 r261대로 구분한다. 음양도 검토/계획 등의 수렴 목적과 실제 세계 개입의 문맥으로 읽고 지도 크기·이익/손실·직접/자동과 동일시하지 않는다.

## 4. 트리로 보는 범위별 총괄

```text
00 음양오행 총괄판 ── 같은 판의 범위별 보기
│
├─ 전국 보기 ── 거점·공급·운송망의 큰 선택
│  └─ 선택한 구 보기 ── 동·지사 사이의 배분
│     └─ 선택한 행정동 보기 ── 주문·매장·기사의 현장
│        ├─ 이웃 동으로 이동 ── 같은 동 높이의 대상 변경
│        ├─ 07 지사 · 08 배차 · 11 기사/업무
│        └─ 09 매장 · 20 건물 · 11 작업/검수
│
├─ 12 계획 ── 해당 선택의 적용 범위·예상·확정 상태
├─ 13 회차 · 14 결산 · 15 장부 ── 같은 결과를 범위별로 조회
└─ 05 전국 · 04 구/서울 · 03 동 선택/02 현장 ── 지도로 대상 찾기
```

‘동/구/전국 보기’는00의 범위 구분이며 새 공식 Scene·별도 실행 모드·기획/코드 식별자를 세 벌 만드는 뜻이 아니다. 검토용으로 `00 동`, `00 구`, `00 전국`이라 부른다. 서울 전체를 보면04의 관찰 범위가 넓어진 것이며 새 서울 오행 단계/잠금/순회 정거장을 만들지 않는다. 현재 준비된 서울 구 범위와 향후 다른 시군구의 상세 지도는 별도로 확인한다.

## 5. 지도 이동과 계획의 적용 지역을 구별한다

지도 범위를 선택하면 그 높이에 맞는 경영 초점이 바뀌는 기존 r144 방향을 유지한다. 동 화면의 첫 초점은 행정동 한 곳이다. 팔방/목록 등 어느 진입이든 **목적 동이 선택되었을 때** 판의 제목·내용도 그 동을 읽는 안을 권한다.

- 카메라를 조금 움직여 이웃 동이 함께 보였다는 이유만으로 작성 중인 계획의 대상을 바꾸지 않는다. 선택한 동과 그냥 보이는 지역을 구분한다.
- 구 지도를 서울 전체까지 축소해도 ‘현재 선택 구’와 ‘서울 전체 비교 범위’를 구분해 표시하는 안을 권한다. 화면에 보인 모든 구를 자동으로 내 담당 구로 바꾸지 않는다.
- A동에서 작성한 계획을 둔 채 B동으로 이동하면 새 조회는 B동이지만 그 계획은 A동에 남는다. 계획 줄과 최종 확인에 적용 지역/거점을 표시한다. 다른 동에 같은 계획을 적용하려면 명시적으로 고른다.
- 상위 계획의 적용 범위는 화면에 보이는 사각형이 아니라 선택한 지역/사업/거점과 유효 시점으로 정하는 안을 권한다. 전국 지도에서 A지사만 대상으로 고를 수도 있다.
- 지역/거점 선택의 변경은 기존 주문·기사 소속·배달·원장·정책 적용을 취소하거나 이동시키지 않는다. 실제 구현에서 현재 선택 해제와 복귀를 조정해야 한다.

범위 표시는 `지도 높이 / 지역 이름·종류 / 집계 대상 / 기준 시점 / 관점`을 읽게 하는 안이다. 예: **동 · 면목3·8동 / 내 사업 / 이번 운영 구간 / 업무 대표 오행**. 정확한 UI 배치와 집계 기본 대상은 후속이다.

## 6. 지역과 사업은 별도 범위다

행정동·법정동·상권·지사의 서비스 구역을 같은 ID로 합치지 않는다. 동 기본 보기는 행정동이며 경계/자료의 출처·판본·결측을 보존한다. 한 지사가 여러 동/구를 맡거나 동 밖으로 배달할 수 있으므로 `한 구=한 지사`, `행정동=담당 배달권`으로 고정하지 않는다.

지사 소속·기사의 현재 위치·주문의 픽업 동·전달 동은 서로 다르다. 한 지역에서 공개 관측되는 전체 주문/사업 통계와 플레이어의 실제 운영 기록도 분리한다. 전체 지역 관측을 내 매출·내 기사·확정된 게임 수요로 자동 전환하지 않는다. 기본 집계 대상을 무엇으로 할지는9절의 질문으로 남긴다.

## 7. 아래의 결과를 위로 모으고, 위의 계획을 아래에서 읽기

**아래에서 위로:** 같은 원장/업무/행위 기록을 더 넓은 범위로 조회한다. 같은 시간·같은 관점의 원본 집계를 사용한다.

- A동 픽업→B동 전달인 배달은 두 동에서 관련 업무로 볼 수 있지만, 전국 총 주문 수에는 같은 원 주문을 한 번 센다. 픽업 건수·전달 건수·통과/현재 위치·완료 주문 수는 다른 지표다.
- [r207 동간 배달](cross-dong-delivery-and-recipient-mingde.design.r207.md)·[r208 제조/픽업 기여](pickup-preparation-and-local-mingde.design.r208.md)를 유지한다. 제조·픽업·전달의 서로 다른 실제 활동은 각 기록대로 귀속하되 화면 높이별로 명덕/돈을 다시 지급하지 않는다.
- 인력은 실제 고유 인물·소속/배정과 가용 시간으로 읽는다. 이동 중인 기사를 소속 동과 현재 동의 새 인력으로 두 번 만들지 않는다. 금액은 기존 원장의 귀속을 따르며 지도를 옮겼다고 귀속을 다시 쓰지 않는다.
- 실제 오행 활동은 독립 누적값을 집계한 뒤 같은 조회 기간의 상대 분포를 구한다. 동별 퍼센트를 단순 평균해 구/전국의 활동량으로 쓰지 않는다. 중복 기록·대상 범위·분모/결측을 먼저 확인한다.
- 일부 지역만 자료가 있으면 확인한 범위와 미준비 지역을 표시한다. 자료 기준일/해상도가 다른 관측을 한 시점의 실시간 사실로 합치지 않으며 공백을0이나 임의 예측으로 채우지 않는다.

**위에서 아래로:** 전국의 거점/운영 방침은 여러 구의 조건에, 구의 지원/배분 계획은 동의 선택 여지에 영향을 줄 수 있다는 안이다. 적용 대상·예산 범위·효력 시점·기간·정책 판본·예외/충돌 처리·실제 실행 조건은 별도 명세로 정한다.

예를 들어 전국에서 보충 거점/회차를 준비하면 구에서는 보충 가능한 범위를, 동의 매장에서는 도착할 수 있는 재료/시간을 읽을 수 있다. 실제 물량·출고·이동·검수를 거쳐야 하며 정책 선택만으로 재고가 순간 이동하지 않는다. 구의 지원 예산을 정한 것과 동에서 실제 지출한 것을 두 번 차감하지 않는다. 플레이어의 예외·발주·정산 최종 결정은 기존 r225를 유지한다.

모든 동 업무 전에 구/전국을 방문해 다시 승인하도록 강제하지 않는다. 기존 허용 방침 안의 정상 업무와 관찰은 이어지고, 새 큰 선택만 해당 준비/권한을 거친다. 전국의 ‘장기’는 영향/예측 기간의 성격이지 지도를 올릴 때 현실 날짜를 점프시키는 기능이 아니다. 기존 운영 회차·일일 결산·공통 시간을 유지한다.

## 8. 예측과 구현 인계의 범위

r261의 **현재 / 선택 후 예상 / 실행 후 실제** 구분을 세 높이에서 함께 쓴다. 동에서는 개별 업무의 조건·현재 안내, 구에서는 여러 선택이 같은 인력/자금/시간을 쓸 때의 부담, 전국에서는 거점/납기·공급 가정과 장기 영향을 비교하는 안을 권한다. 정확한 기간·산식·집계 변수는 미정이며 개별 예상치를 더해서 전사 미래 성과를 확정하지 않는다.

후속 구현 후보는 선택 지역이 바뀔 때00의 범위 표시/조회와 기존 계획 대상이 유지되는 작은 경로다. 팔방 이동의 담당·완료 반환·정확한 파일 지문을 먼저 대조하고, 승인 기획 revision/hash·WI 하나·쓰기 경로·E1~E7 검증 명세를 결속한 뒤 개발이 수용한다. Graph Map은 기존 지도/계획/대상/결과 관계의 `ReviewRequired` 후보이며 이 기획이 원본·Goal을 직접 변경하지 않는다.
