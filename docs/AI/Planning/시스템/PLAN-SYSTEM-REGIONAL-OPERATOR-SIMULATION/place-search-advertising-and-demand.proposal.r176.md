## 1. 플레이 상황과 핵심 제안

지금은 개업한 가상 카페의 주문이 적은 오늘 오전이다. 여기에는 동네의 가상 경쟁 매장과 검색 수요가 있다. 나는 카페 운영자로서 제한된 홍보비·제조 여력·기사 여력을 갖고, 고객은 위치·가격·메뉴·약속 시간을 보고 매장을 고른다. 검색어/홍보 경로/시간대를 고르고, 늘어난 관심을 실제 영업으로 받아 낼지 판단한다.

**홍보비 → 관심 있는 가상 고객의 검색/유입 → 상세 확인 → 방문·주문 → 이행·만족 → 다음 검색의 경쟁력**을 한 흐름으로 제안한다. 순위와 페이지는 이 흐름에서 얻는 노출 기회다. 클릭·검색 순위·주문·업무 완료·정산·입금은 각각 기록한다.

핵심 선택은 ‘더 알릴까, 매장 정보를 고칠까, 먼저 처리 여력을 늘릴까’다. 같은 예산으로도 시간대와 고객 의도가 맞으면 효과가 나고, 매장이 준비되지 않으면 이탈·대기·환불 부담이 생긴다. 손실 뒤에는 예산 축소·중단, 대상 조정, 정보 수정, 인력/배차 보완으로 회복하고 같은 지도와 매장 카드로 돌아온다.

상위 목적에서는 매장이 필요한 고객을 만나고 실제 약속을 이행하도록 돕는 **보조 경영 층**이다. 광고 클릭 자체에 개인의 경 유지·성장·소득을 지급하지 않는다. r175의 참여자 변화는 실제 업무 결과를 통해 따로 확인한다.

## 3. 게임 안에 두는 장소 검색 서비스

가칭 **동네찾기**를 가맹/매장 경영의 도구로 둔다. 새 업무 OS나 실제 네이버 연동을 만들 필요는 없다. 사용자에게는 검색창, 현재 조건, 광고 영역, 일반 검색 목록과 페이지 이동이 보인다.

순위의 단위는 매장 하나의 전역 숫자가 아니라 **검색 의도 × 고객 기준 위치/검색 범위 × 시점 × 정렬 방식 × 규칙 판본**이다. ‘면목동 커피’와 ‘사가정 포장 커피’, 다른 고객 위치에서는 같은 매장의 결과가 달라질 수 있다. 플레이어가 다른 동으로 카메라를 옮겼다는 이유로 이미 진행 중인 고객 세션의 위치가 바뀌지 않는다.

첫 검토용으로 일반 결과를 한 페이지 10곳으로 나누는 안을 둔다. 1~10위는 1페이지, 11~20위는 2페이지다. **이 개수는 홍달 화면 설계 후보**이며 네이버의 실제 페이지 크기가 아니다. 경쟁 매장이 적으면 빈자리를 그대로 두고, 광고는 별도 표식/칸으로 표시한다. 광고 노출을 자연 검색 1위로 집계하지 않는다.

고객마다 더보기/다음 페이지로 갈 가능성이 다르게 설정된다. 첫 페이지 진입은 발견 가능성을 높이지만, 원하는 메뉴·가격·거리·운영 상태가 맞지 않으면 주문은 발생하지 않는다. 지도 핀 가시성과 검색 목록 순위도 구별한다.

## 4. IP 대신 가상 고객과 탐색 세션

게임은 실제 네트워크 IP를 모으거나 여러 IP를 만들어 접속하지 않는다. 가상 고객의 고유 식별자와 탐색 세션으로 필요한 관계를 표현한다. 화면에 모든 고객을 실시간으로 그릴 필요는 없으며, 집계된 고객 집단에서도 같은 의미를 유지한다.

| 단계 | 가상 고객의 행동 | 다음 단계에 영향을 주는 것 |
| --- | --- | --- |
| 수요 발생 | 지금 커피/점심/포장 메뉴를 찾음 | 수요 시나리오, 시간대, 이용 목적 |
| 검색·노출 | 조건에 맞는 목록과 광고를 봄 | 관련도, 거리, 가상 평판, 정보, 광고 자격 |
| 상세 열람 | 매장 카드·사진·메뉴·가격을 확인 | 정보의 정확성, 매력, 예산/취향 부합 |
| 의사 결정 | 이탈/저장/길찾기/방문/주문을 선택 | 이동 부담, 예상 대기, 영업·주문 가능 상태 |
| 실제 수행 | 방문·제조·픽업·배달·인수 | 재고·설비·현장/기사 여력과 기존 업무 모듈 |
| 경험·환류 | 만족·문제·재방문 의향을 남김 | 실제 이행 결과, 다음 기간의 제한된 평판 변화 |

상세 열람 시간은 ‘메뉴를 충분히 확인했는가’ 같은 가상 이해 상태에 사용할 수 있다. 일정 시간마다 점수가 무한히 쌓이지 않도록 상한을 두고, 정보가 복잡해 오래 헤매는 경우와 관심 때문에 자세히 보는 경우를 구별한다. 상세 열람 시간과 실제 매장 체류시간은 별도 항목이다.

검색 수요 집단에서 한 번 배정된 고객은 새 가상 영업 세션에서 기존 업무 모듈로 인계하는 안이다. r142의 방문·이용·대기 해석 틀을 참고하되, 무료 합성 입지 시험의 결과를 영업 고객·주문·매출로 전환하지 않는다. 광고 클릭, 일반 검색 클릭, 지도 직접 선택으로 같은 고객이 동시에 여러 명이 되지 않는다. 공공 유동인구를 그대로 검색수/고객수/주문수로 등치하지 않는다.

## 5. 순위와 광고의 계산 뼈대

### 5.1 일반 검색 경쟁력

다음 구조를 **게임 규칙 후보**로 둔다. 실제 네이버 산식이 아니며 정확 가중치는 미정이다.

```text
일반 검색 경쟁력 = 검색 의도 부합 + 접근 편의 + 정보 충실도
                 + 이전 기간의 유효 관심 + 실제 이용 경험
```

각 항목은 같은 척도로 정규화하고, 유효 관심은 노출 기회·표본 수·최근성을 함께 본다. 누적 클릭수만으로 기존 1위가 영원히 이기는 구조를 피한다. 새 매장의 제한된 발견 기회, 적은 표본의 불확실성, 중복 행동의 기여 상한, 시간에 따른 감소는 검토 후보이며 값은 미정이다.

이번 노출을 정한 뒤 같은 클릭을 즉시 되먹여 다시 노출하는 순환을 만들지 않는다. **고정된 이전 집계 → 현재 순서 → 현재 행동 → 다음 안전한 집계 경계 반영**으로 판본을 남긴다. 고객 세션이 시작한 순서는 세션 동안 유지한다. 동률·난수 처리와 반영 주기는 구현 전 별도 확정한다.

### 5.2 홍보비와 추가 유입

첫 홍보 선택은 동네 검색 광고, 지역 소식/콘텐츠 유입, 행사/쿠폰 안내 같은 가상 채널 후보로 나눈다. 캠페인의 대상 매장, 관심 주제, 지역/거리, 운영 시간, 예산 한도를 고른다. 이는 실제 네이버 상품의 키워드별 입찰 UI를 복제한다는 뜻이 아니다.

검색 광고를 고르면 가상 입찰·광고 품질·적합성을 통해 광고 칸의 노출 기회를 얻는다. 외부 홍보를 고르면 관심 집단에서 매장 상세로 들어오는 유입을 얻는다. 후자는 광고 검색 노출수와 섞지 않고, 검색을 거치지 않은 유입을 검색 클릭으로 기록하지 않는다.

홍보비는 자연 검색 순위 점수를 직접 사는 가격으로 쓰지 않는다. 실제 유효 관심·이용 결과가 다음 집계의 경쟁력에 제한적으로 반영되는 안이다. 예산 한도, 실제 집행액, 주문 금액은 각각 기록하며 동일 고객의 반복 열람을 무제한 과금/보상하지 않는다. 정확 과금 단위·자금 부족 시 중단·환불 규칙은 미정이다.

‘저렴한 숫자 트래픽을 제안받는 사건’은 후속 비교 콘텐츠 후보로 둘 수 있다. 관심 없는 유입은 열람수만 크고 전환이 낮으며 중복/유효하지 않은 행동은 성장 근거에서 제외하는 식이다. 첫 범위에 실서비스 IP·계정·우회·접속 자동화는 포함하지 않는다. 게임의 필터/불이익도 별도 승인된 가상 규칙과 설명을 요구한다.

## 6. 매출이 늘 수도, 비용만 늘 수도 있는 경영

홍보 효과와 영업 결과 사이에는 가상 고객의 방문/이용 선택과 매장·배차 모듈의 처리 한계가 있다. r142는 이를 읽는 비교 틀로만 참고하고 무료 입지 시험과 영업 세션은 구별한다. 이용 의향이 생겨도 품절·마감·긴 대기라면 이탈하거나 다른 매장으로 이동할 수 있다. ‘광고비를 늘렸으니 주문과 만족도가 자동으로 증가’하는 보상은 두지 않는 안이다.

읽기 예시로 홍보비 2만원, 상세 열람 120회, 주문 의향 24명, 실제 정산까지 끝난 주문 16건을 가정한다. 그 16건의 게임 원장이 제공한 매출에서 포함 가능한 변동비를 뺀 값이 3만2천원이라면, 홍보비 차감 후 1만2천원은 **예시에 포함한 항목 범위의 기여 결과**다. 전체 순이익·현금 유입이나 광고가 없었을 때보다 늘어난 이익을 뜻하지 않는다. 수치와 원가 범위는 모두 가상 예시이며 회계 규칙 승인이 아니다.

광고 기여 주문에는 하나의 주 유입 경로를 배정하고 보조 경로는 별도 기록해 매출을 중복 합산하지 않는다. 비교 시나리오에서 같은 초기 상태·수요·규칙·난수 조건으로 무광고 결과까지 계산했을 때만 광고의 **증분 효과 추정**으로 표시한다. 평소 일일 보고는 관측된 유입/주문 결과와 예측을 구별한다.

## 7. 지도 높이와 사용자의 결정

| 관점 | 대표 결정 | 보일 핵심 정보 |
| --- | --- | --- |
| 건물·매장 내부 | 메뉴/가격·정보 보완, 준비 여력과 약속 | 상세 이탈 이유·제조/픽업 대기·품절 |
| 동네 | 어떤 고객 의도와 시간대에 한 매장을 알릴까 | 조건별 검색 페이지·노출→열람→주문·남은 예산 |
| 구 | 여러 동/가맹점에 예산을 어떻게 나눌까 | 매장별 기여 결과·상호 잠식·처리 여력·지역별 수요 |
| 서울·전국 | 후속 검토 | 해당 높이의 홍보 책임은 이번에 확정하지 않음 |

구 예산을 매장에 배분한 뒤 같은 금액을 매장 비용으로 다시 추가 차감하지 않는다. 한 캠페인의 범위/배분과 실제 집행 내역을 같은 식별자로 잇는다. 실제 정산·지급 권위는 기존 원장/모듈이 소유한다.

## 8. 화면과 시간·모드 연결

동네 지도의 관리색/회색 건물 구분은 유지한다. 매장 카드의 ‘동네찾기’에서 현재 검색 조건, ‘일반 결과 2페이지 4번째’와 광고 상태를 나란히 읽고, 오늘의 노출·상세 열람·의향·실제 주문·정산 결과를 단계별로 본다. 경쟁력 설명은 ‘정보 부족’, ‘가까운 경쟁점’, ‘예상 대기’처럼 바꿀 수 있는 이유를 보여주는 안이다. 실제 점수 가중치나 거대한 관리판을 기본 화면에 쏟지 않는다.

오늘 준비에서 예산/대상을 고르고 실행·이완 관찰 중 실제 시뮬레이션 행동을 기록한다. 집중 미니게임에서 직접 만든 음료/전달 결과도 같은 업무 기록으로 이어진다. 화면을 닫거나 이완으로 바꿨다고 새 광고 계약·예산·고객을 만들지 않는다. 검색 화면 새로고침이나 다음 페이지 열람만으로 플레이어에게 점수/수익을 지급하지 않는다.

일일 결산은 r174대로 기존 원장이 각 항목에 정한 기준시각을 KST로 읽은 날짜에 귀속된 집행액·유입·이행 결과를 조회한다. 저장·발견 시각으로 귀속일을 바꾸지 않는다. 결산 확인이 시간·정산·지급을 추가하지 않는다. 현재 정본대로 앱 종료/부재중 기간을 광고비·주문·벌금의 자동 영업으로 계산하지 않는다. 지난 날짜의 집행 잔액·캠페인 재개/종료 규칙은 승인 전 미정으로 둔다.

관찰자 모드에는 공공자료의 실제 음식점 사실과 기준일을 보여준다. 가상 검색 점수·가상 매출을 실제 사업장의 성적처럼 붙이지 않는다. 기존 [공간 음식점 r3](../../공간/PLAN-SPATIAL-SAGAJEONG-DELIVERY-MOBILITY/restaurant-icons-operational-lifecycle-validation-proposal.r3.md)의 실제 공개관측·Claim·후원/운영 계약, 특히 후원이 주문·배차·검색 순위를 바꾸지 않는 경계를 유지한다. 새 제안은 가상 게임 업체의 Simulation 규칙에만 적용한다.

## 9. 구현을 고려할 때 필요한 최소 기록

별도 DB나 엔진을 지금 만들지 않는다. 승인 후 기존 Simulation 계약에 다음 의미가 들어갈 수 있는지 먼저 대조한다.

| 기록 | 필요한 의미 |
| --- | --- |
| 검색 문맥/목록 | 검색 의도, 지역/고객 위치, 정렬·규칙/자료 판본, 광고/일반 구분, 세션 중 고정된 목록 |
| 가상 매장 프로필 | 가상 매장/건물 식별자, 메뉴/가격·영업/수용 상태, 정보 판본 |
| 홍보 계획/집행 | 캠페인 식별자, 대상/채널·시간, 예산 한도와 실제 집행 기록, 중단 상태 |
| 유입·의향 | 고객/집단·세션 식별자, 노출→열람→선택의 연결, 유효/중복 판정과 사유 |
| 업무 인계 | 같은 주문/방문 식별자에 연결된 주 유입 경로, 이행/정산/지급 결과 조회 |
| 보고 | KST 기간, 집계 판본, 실제/예측/비교 추정 구분, 지표 분모와 비용 포함 범위 |

공공자료는 위치·업종·출처/기준일 등 사용이 허용된 문맥만 제공한다. 실제 클릭 로그·웹 체류·인기도·매출이 수집된 것으로 가정하지 않는다. 세션의 자료 판본/누락을 보존하며 행정동·법정동 복수 대응을 임의로 단일화하지 않는다. 이 조사로 네이버 메뉴/리뷰/순위 대량 수집이나 새 수집 예약을 추가하지 않는다.

## 10. 첫 검토 범위와 이후 확장

첫 후보는 **한 동·가상 카페 한 곳·검색 의도 하나·오늘의 소규모 홍보**다. 비교용 가상 경쟁점 수·페이지 크기·예산은 검토용 설정으로 명시한다. 무홍보/소규모 홍보와 충분한/부족한 처리 여력을 비교하면, 순위 경쟁과 실제 경영의 차이를 읽을 수 있다.

첫 화면에서는 다음만 판독되면 된다.

1. 어느 검색 조건에서 몇 페이지에 보이고, 왜 그러한가.
2. 무엇을 알리는 데 얼마를 쓰기로 했고, 실제 얼마를 썼는가.
3. 늘어난 관심 중 몇 명이 주문했고 어디서 이탈했는가.
4. 처리·정산된 결과와 비용을 보고 다음에 홍보/정보/여력 중 무엇을 바꿀까.

후속으로 복수 키워드·경로, 구 단위 여러 가맹점 예산, 반복 방문/브랜드 인지, 저품질 홍보 사건을 검토한다. 처음부터 모든 높이·업종의 순위 엔진을 구현하지 않는다.

## 11. 승인 후 검증해야 할 조건

- 검색 조건/판본/시드가 같으면 같은 순서를 재현하고 세션 도중 집계 변경으로 목록이 흔들리지 않는가.
- 같은 고객의 광고/일반 검색·재열람이 고객/주문·매출의 중복 생성이나 무한 점수로 이어지지 않는가.
- 광고 칸을 일반 검색 1페이지 성과로 잘못 세지 않고, 직접 상세 유입에 검색 노출을 붙이지 않는가.
- 예산·집행·업무 이행·정산·지급·조회가 각각 이어지고 재진입/결산 재확인으로 중복 차감·보상이 생기지 않는가.
- 홍보 증가에 비해 재고/현장/기사 여력이 작으면 원인과 회복 선택이 읽히는가.
- 현재 날짜와 작업/세션 판본을 보존하고 부재중 광고/주문을 임의로 생성하지 않는가.
- 실제 음식점 공공관측·후원/운영 상태와 가상 게임 성적이 섞이지 않는가.

이는 향후 개발 명세의 후보 조건이다. 이번에는 제품 시험·Unity Runtime·실제 입력·Save/Replay를 실행하지 않았다.

## 12. 확정 / 미정 / 다음 질문 하나

- **제안·미정:** 가칭 서비스, 점수/감쇠·표본/신규 발견, 광고 과금·예산/자금 부족, 세션/집계 주기, 날짜 경계의 캠페인 처리, 정확 화면·WI·저장/구현 범위. 공식 사실 확인은 이 게임 규칙의 승인과 다르다.
