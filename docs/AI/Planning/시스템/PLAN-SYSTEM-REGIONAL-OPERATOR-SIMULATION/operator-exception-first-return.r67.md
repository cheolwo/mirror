## 확정

운영자가 화면에 계속 붙어 정상 주문을 감시하도록 만들지 않는다. 운영자는 자동 처리 뒤에도 판단이 필요한 **예외를 우선해서 본다**.

- 정상 주문·배차·전달·정산은 승인된 기본 정책 안에서 자동으로 진행하고 기본 목록에서 접는다.
- 복귀 시에는 자동 조치 이력 전체가 아니라 아직 해소되지 않은 위험과 사람 판단 필요 사건을 먼저 보여 준다.
- 첫 인계 카드는 `현재 예외`, `발생 원인`, `이미 수행된 자동 조치`, `발생·예상 비용`, `다음 결정`을 같은 사건 식별자와 원천 revision으로 묶는다.
- 기사 부족, 조리 지연, 위치 갱신 중단처럼 원인이 다른 사건은 별도 원인으로 표시하되 같은 주문 사건을 중복 카드로 만들지 않는다.
- 정상 흐름과 전체 시간순 기록은 버리지 않고 상세 조회로 내린다.
- 자동 처리 완료를 운영자의 승인으로 가장하지 않는다. 어떤 기본 정책이 언제 적용됐는지 다시 확인할 수 있어야 한다.
- 예외가 없으면 `현재 확인할 예외 없음`과 짧은 안정 요약만 보여 주고 불필요한 결정을 요구하지 않는다.

## 운영자 복귀 카드

```text
현재 예외
├─ 무엇이 위험한가
├─ 왜 발생했는가
├─ 시스템이 이미 무엇을 했는가
├─ 비용·지급의무·현금 방어 영향
├─ 지금 허용된 조작
└─ 상세 기록·디오라마 위치로 이동
```

이 카드는 정상 업무 원장을 대체하지 않는 읽기·결정 진입점이다. Unity는 서버 또는 Simulation 상태 사본의 원인·허용 조작을 표시할 뿐 예외 상태나 허용 조작을 자체 계산하지 않는다.

## 미정

- 첫 화면에 동시에 노출할 예외 카드 수와 정렬 규칙
- 같은 원인의 다수 주문을 한 카드로 묶는 임계값
- 해소된 예외를 복귀 요약에 유지할 시간
- 카드에서 바로 제공할 조작 수와 상세 화면으로 내릴 조작
- 음성·푸시·화면 강조의 우선순위와 빈도

## 다음 질문 하나

예외 카드 한 장에서 운영자에게 몇 개의 조작을 바로 보여 줄까?

1. `추천 조작 하나 + 상세에서 대안` — 추천. 판단 피로를 줄이되 Preview와 다른 선택 가능성을 보존한다.
2. `허용된 조작을 모두 나란히 표시` — 비교는 쉽지만 긴박한 순간에 선택 부담이 커진다.
3. `카드는 조회만 하고 별도 정책 화면에서 조작` — 안전하지만 대응이 느리고 디오라마와 운영 판단이 분리된다.
