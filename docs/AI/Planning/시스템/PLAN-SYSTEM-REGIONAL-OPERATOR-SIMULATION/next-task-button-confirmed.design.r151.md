# [기획 · 다음 작업 버튼 확정 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r151]

- 기준일: 2026-11-12
- 상태: `NextTaskButtonConfirmed / DesignDocumented / ProductUnchanged`
- 승인 근거: [원하는 직무 연속 수행 r150](preferred-role-continuous-tasks.design.r150.md)의 자동 시작/버튼 시작 질문에 사용자가 **다음 작업 버튼**을 선택했다.
- 확정 범위: 같은 직무의 다음 작업은 사용자가 `다음 작업` 버튼을 눌러 시작한다. 작업 하나를 마쳤다는 이유로 다음 작업을 자동 시작하지 않는다.
- 공통 기준: 직무 선택 유지·개별 작업·성과/정산·안전한 집중/이완 인계는 r150과 그 참조 기획을 따른다. 이번 답변은 정렬·장소 범위·경제 수치를 추가 승인한 것으로 해석하지 않는다.
- 담당: Codex 기획 반영. 사용자 전달 기준 Claude의 Core 통합·우유 5팩 구현 범위와 실행 소유는 유지한다.

## 완료 후의 흐름

1. 현재 작업의 확정 결과를 보여 주고 선택한 직무·현장 화면을 유지한다.
2. 같은 직무의 다음 준비 작업 요약과 `다음 작업` 버튼을 보여 준다.
3. 사용자가 버튼을 한 번 누르면 해당 작업의 최신 상태·담당·가능 행동을 확인해 그 한 건을 시작한다. 매번 전체 지도나 역할 선택으로 돌아가는 절차를 요구하지 않는다.
4. 계속 수행·직무 변경·이완 경영 복귀는 기존 선택으로 유지한다.

버튼을 누르기 전에는 직접 수행을 위한 다음 작업을 수락·배차·예약하지 않는다. 다른 주체의 정상 자동 업무와 공통 가상 시간은 기존 규칙을 따른다. 완료 성과·정산 대기·실제 지급의 구별도 유지한다.

준비된 작업이 없으면 이유와 대기 상태를 표시하고 버튼을 비활성화하는 세부안을 사용한다. 클릭 뒤 다른 주체가 먼저 가져갔거나 조건이 달라졌다면 현재 상태와 새 후보를 알리고 다시 선택받는다. 다른 작업을 대신 자동 시작하지 않는다. 요청 처리 중에는 버튼의 중복 누름으로 여러 작업을 시작하지 않게 하고 이미 확정된 결과는 보존한다. 버튼의 크기·위치·키보드 단축키는 후속 검토다.

## 확정·미정·다음 질문 하나

- **확정:** `다음 작업` 버튼으로 한 건씩 시작한다. 같은 직무를 몰아서 수행하는 흐름과 현장 유지가 이어진다.
- **미정:** 같은 직무 작업의 제안 순서·장소 범위·버튼 배치/단축키·선택 저장 범위. 자동 시작 선택은 이 판본에서 해소했다. 제품 코드는 아직 적용하지 않았다.
- **다음 질문 하나:** 같은 장소의 다음 작업은 오래 기다린 순서로 제안할까? 이는 다음 검토안이며 이번에 확정하지 않는다.

Graph Map 영향 후보는 작업 완료→다음 작업 제안→사용자 버튼 선택→현재 조건 확인→한 작업 시작이다. 이번에는 기획 문서만 변경하며 Goal·WI·E 증거·Graph Map 원본·새 D 결정·예약을 등록/수정/승격하지 않는다. 새 이미지와 Unity 실행 검증도 포함하지 않는다.
