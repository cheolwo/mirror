## 1. 개업한 매장이 검색되는 경험

지금은 사가정역 주변에 가상 카페를 준비하는 시점이다. 나는 가상 점주이고, 고객은 장소를 검색해 메뉴·사진·운영 상태를 보고 방문할지 고른다. 사업자등록을 마치면 홍달 플레이스에 내 매장 페이지가 생긴다. 별도의 홍달 플레이스 신규가입/정보 재입력 절차를 첫 필수 작업으로 추가하지 않는다.

**등록 완료 → 내 매장 페이지 생성 → 준비된 정보 확인/보완 → 개업 → 검색으로 고객 유입 → 실제 이용 경험 누적**을 제안한다. ‘내가 만든 매장이 고객에게 어떻게 보이는지’가 경영의 첫 피드백이다. 사진/메뉴를 보완하거나 광고를 선택하고, 실제 대기·품절·이행 결과까지 확인한 뒤 같은 매장 경영으로 돌아온다.

현재 읽은 기획에는 r190의 ‘해당 신고/등록 확인’과 r168의 준비/개업 흐름이 있지만, 사업자등록 완료의 구체 상태 계약·홍달 플레이스 페이지 저장 계약은 확인되지 않았다. 이 연결을 이미 구현된 기능으로 보고하지 않는다. 이번에 사용자가 정한 게임 방향으로 기록하고 실제 연결은 개발 시 현재 상태 소유자를 확인한다.

## 3. 게임 등록 완료에서 페이지 생성으로

사업자등록 완료를 담당하는 게임 상태가 확정됐을 때, 그 사업에 연결된 **개별 점포**의 홍달 플레이스 페이지를 한 번 생성하는 안이다. 같은 완료 기록을 다시 읽거나 저장을 불러와도 중복 페이지/홍보비/보상을 만들지 않는다. 정확 이벤트·필드 이름은 기존 계약을 확인한 뒤 정한다.

| 시점 | 홍달 플레이스에서 읽는 상태 | 기존 경영 상태와의 관계 |
| --- | --- | --- |
| 등록 전 | 점포 준비 화면에서 입력한 초안 | 사업자등록을 대신 완료하지 않음 |
| 게임 사업자등록 완료 | 페이지 자동 생성. 기존 정보/가상 기본 사진·준비된 메뉴를 연결 | 홍달 플레이스 재신청을 필수로 추가하지 않음 |
| 아직 개업 전 | `개업 준비 중`, 예정 메뉴/일정. 검색에 보일 경우 같은 표식을 유지 | 노출만으로 개업·주문·매출을 만들지 않음 |
| 준비 충족·플레이어 개업 선택 | 영업 일정과 현재 주문 가능 상태를 반영 | r168의 개업 선택/준비 조건을 읽음 |
| 운영 중 변경 | 메뉴·가격·품절·휴무·사진/소개를 해당 판본으로 갱신 | 페이지 편집이 재고/일정/원장을 별도로 덮어쓰지 않음 |
| 휴업·이전·폐업 등 | 해당 가상 점포의 상태 표시/검색 자격을 갱신하는 후속 | 기존 상태 이력·정상 주문 결과를 임의 삭제하지 않음 |

기본 정보가 부족해도 생성 사실을 누락시키지 않고 ‘정보 준비 중’으로 읽는다. 지도 위치 미결속이면 해당 사실과 정보 보완 경로를 표시하고 다른 점포의 핀을 가져오지 않는다. 개업 전 목록의 정렬/필터와 휴·폐업 페이지 보존 상세는 미정이다.

건물 하나에 여러 매장이 있으면 각각의 점포가 자기 페이지를 가진다. 같은 사업자가 여러 지점을 운영해도 페이지를 하나로 합치지 않는다. 건물·점포·사업자·관리 관계를 구별하는 r168의 경계를 유지한다. 실제 사업자번호/서류를 게임 이용자에게 요구하지 않으며 가상 등록 상태를 사용한다.

가상의 사업자등록 상태는 관리 화면에서 확인하고 고객용 화면에 불필요한 내부 등록 세부정보를 늘어놓지 않는다. 광고 예산·중개 계약·원가/매출·처리 여력 수치는 점주/담당 광고 운영자의 **관리 화면**에서 읽는다.

음식점·카페를 첫 전문 프로필로 제안한다. 여러 종류의 장소 검색을 위해 이름·위치·사진·소개·일정은 공통으로 두되, 음식점은 메뉴, 매장은 상품, 다른 시설은 해당 서비스/시설 정보를 후속으로 붙일 수 있다. 모든 장소에 커피 메뉴나 주문 버튼을 강제하지 않는다. 실제 공공자료 관찰 장소와 플레이어의 가상 운영 점포는 출처·목적이 다른 목록으로 구분한다.

## 5. 가상 사진과 메뉴를 채우는 방식

사진은 다음 우선순위의 **제안**이다.

1. 해당 가상 매장의 게임 외관/실내가 준비돼 있으면 그 장면을 촬영·렌더한 이미지를 사용한다.
2. 장면이 아직 없으면 업종에 맞는 사용 가능한 가상 기본 이미지를 두고 기본 이미지임을 표시한다.
3. 인테리어·간판·메뉴가 바뀌면 새 이미지로 교체할 수 있게 한다. 이전 사진이 최신 매장 모습인 것처럼 자동 표시하지 않는다.

개업 준비 중 완성된 실내를 그린 이미지라면 ‘예정 모습’으로 읽는다. 아직 없는 모델/촬영 결과가 만들어졌다고 보고하지 않는다. 이번 작업에서는 새 이미지 생성·게임 촬영을 하지 않았다. 실제 네이버 매장 사진이나 권리 미확인 프랜차이즈 사진을 자동으로 가져오는 계획이 아니다.

가맹점은 **게임 안에서 선택한 본부의 메뉴 템플릿 → 해당 지점에 적용한 판매 메뉴/가격**으로 연결하고, 독립점은 준비한 가상 판매 메뉴를 연결한다. 본부 기본값과 지점 변경의 출처/판본을 구별한다. 메뉴가 아직 없으면 페이지는 존재하되 `메뉴 준비 중`으로 표시한다. 예정 메뉴와 판매 중 메뉴도 구별한다.

제조 레시피는 재료·수량·도구·작업 순서이고, 고객 메뉴는 판매명·설명·사진·가격이다. [다직무/레시피 r147](multi-role-minigames-and-realistic-recipes.design.r147.md)의 현실 근거/게임 조정 구분과 주문 시작 시 판본 고정을 유지한다. 공개 메뉴를 편집했다고 이미 진행 중인 커피 작업의 레시피가 바뀌지 않는다.

공공 음식점 자료의 부분 메뉴·가격이나 기존 메뉴 이미지는 해당 가상 매장에 적용됐다는 근거 없이 현재 판매 메뉴/자유 사용 사진으로 확정하지 않는다. 현재 키워드 후보의 업종 태그도 확정 메뉴를 만들어 주는 자료는 아니다.

## 6. 화면과 광고·성장의 연결

첫 화면 구성은 **상단 대표 사진/상호/운영 상태 + 기본 탭 `홈 · 메뉴 · 사진 · 정보`**를 제안한다. 후기는 경험이 생긴 뒤 읽을 수 있는 영역으로 두고, 소식은 홈에서 우선 노출하는 안이다. 고정 탭 개수·배치는 시안 검토 전 미정이다.

가상 화면 예시: `홍달커피 사가정점 / 카페 / 개업 준비 중` 아래에 기본 사진, 예정 메뉴, 준비 중인 영업 일정, 지도 연결이 보인다. 개업 후에는 같은 페이지에서 영업/품절·이용후기 상태를 읽는다. 이는 예시이며 신규 실제 점포/사진을 만든 결과가 아니다.

홍달 플레이스 검색의 각 결과는 이 페이지로 열린다. 점포 카드의 `[내 홍달 플레이스 보기]`도 같은 페이지를 가리킨다. 검색어·페이지·점포 선택을 보존해 지도↔검색↔상세를 왕복한다. 플레이어의 미리보기/검색/새로고침은 가상 고객 클릭·광고비·후기·주문을 만들지 않는 r193을 유지한다.

광고 소재는 같은 매장의 이름·대표 이미지·판매 정보를 참조하되 광고 칸과 일반 순위를 구별한다. 사진을 등록했다고 곧바로 1페이지 진입·매출을 보장하지 않는다. 정보가 고객 선택을 돕고, 정상 방문/주문과 이행 경험이 이후 경영 결과로 이어진다. 광고 경험 완료→중개업자 소개는 r194의 노출/결과 확인 기준을 그대로 적용한다.

## 7. 첫 구현 준비 범위와 검증 후보

첫 후보는 **가상 음식점/카페 하나의 등록 완료→페이지 한 번 생성→기본 사진/메뉴 확인→개업 전후 상태 변경→지도/검색 왕복**이다. 사업자등록 상태의 현재 구현/소유자를 먼저 확인하고, 기존 점포/메뉴/영업 상태를 읽는 조회 표현으로 준비한다. 플레이스 전용 영업 원장이나 새 Core를 먼저 만들지 않는다.

확인 후보는 다음과 같다.

- 같은 등록 완료/저장 재진입에도 한 점포의 페이지가 중복 생성되지 않는가.
- 건물 내 복수 점포·동일 사업자의 복수 지점을 혼동하지 않는가.
- 페이지 생성과 개업·주문 가능·광고 집행이 독립이고, 준비 중/품절/미정 정보가 읽히는가.
- 가맹 기본 메뉴와 지점 적용값, 사진의 기본/예정/현재 판본이 구별되는가.
- 고객용 정보와 관리용 광고/경영 수치가 구분되고, 페이지 열람이 고객/비용/매출을 만들지 않는가.
- 메뉴/사진/일정 변경 뒤 같은 매장·검색·지도 문맥으로 돌아오며 기존 업무 결과/날짜를 바꾸지 않는가.

이 목록은 구현 전 명세 후보다. 승인된 상세 판본/hash·필수 연구·WI 하나의 E1~E7 명세·정확 쓰기 범위·개발 수용은 별도로 결속한다. 이번 문서로 Scene·모델·사진·UI·DB·계약·자동 수집을 생성/승격하지 않는다.
