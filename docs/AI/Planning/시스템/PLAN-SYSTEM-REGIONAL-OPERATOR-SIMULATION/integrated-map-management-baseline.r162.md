## 3. 공통 플레이·표현 계약

### 지도와 운영 역할

| 관점 | 대표 초점 | 먼저 읽는 상태 | 주된 선택 후보 |
| --- | --- | --- | --- |
| 건물·내부 | 한 작업을 정확히 끝내기 | 작업·레시피/수량·설비/위치·검수/격리 | 조리·피킹·포장·검수의 준비된 행동 |
| 동네 | 한 주문의 약속 지키기 | 음식 준비·현재 기사·픽업/전달 여유 | 다음 인계·기다림·현재 업무 회복 |

같은 OS가 여러 높이에 나타나며 OS를 한 지도에 가두지 않는다. 음식점은 기존 `FoodDeliveryOS`의 역할이고 창고/센터는 기존 이행 OS/profile을 재사용한다. 독립 가맹/생산/공장 OS가 정본에 이미 구현됐다고 가정하지 않는다. 지도 높이는 권한·사업 해금·Z/H·행정 코드와 일대일 대응하지 않는다. 서울 경영 초점과 Windows 지구본 조달은 후속 상세이며 별도 지구본 관찰 기반의 존재와 구별한다.

### 선택·시간·참여 방식

- 높이 변경은 새 높이의 대표 요약을 열고 현재 업무·입력·상세 복귀를 남긴다. 같은 높이 이동은 선택 OS를 유지한다.
- 같은 업무는 같은 ID/Revision으로 요약·상세를 읽는다. 다른 업무는 실제 인계/관계가 있을 때만 연결한다.
- 확대/축소·레이어·자료 기간 선택은 Command·배차·재고·돈·시계·성장·직접 제어권을 바꾸지 않는다. 공통 정지/진행과 안전 인계는 기존 계약을 따른다.
- 자료 보기는 게임 Tick 없이 읽는다. 이완은 자동 게임 업무가 진행될 수 있고 집중은 준비된 직무를 직접 수행한다. 지도 높이와 서로 다른 선택이다.
- 직무/현장을 고른 뒤 준비된 한 건을 시작하고 결과를 본다. 같은 직무를 이어 할 때도 **‘다음 작업’ 버튼**으로 시작한다. 다른 직무는 강제하지 않는다.
- 직접 수행 보너스의 방향과 수치/귀속·자동 업무의 정상 성과를 구별한다. 미정인 수치를 통합하며 정하지 않는다.

### 색·사건·결과

- 일반 건물은 회색, 확인된 관리 매장 부분은 민트와 운영 표식으로 구별한다. 거래 흔적·공공 통계·선택/새 사건 색은 다른 의미다.
- 생활 보행은 가상 연출이다. 분기 인구를 실시간 보행자·실제 주문으로 바꾸지 않는다. 통계는 바닥 음영·테두리·기호·요약판을 우선한다.
- **새 주문 핀의 기준은 픽업 매장, 첫 효과 기본값은 ‘간단히’**다. 두 선택은 최근 Claude 반환의 사용자 답과 B0 1차 감사 소스에서 확인했다. r154/r157의 당시 미답변 항목을 재질문하지 않는다.
- 상태 사본/복원과 새로운 사건을 구별한다. 복원·재조회·지도 전환으로 주문 연출을 다시 발생시키지 않는다. 효과를 꺼도 업무 상태·새 건수·중요 알림은 남긴다.
- 계획/담당 확정은 즉시 읽을 수 있어야 하지만 실제 이동·픽업·검수·전달·정산은 각 업무가 완료된 뒤 반영한다. 애니메이션 종료를 업무 완료로 쓰지 않는다.

## 4. 자료와 소비 경계

공공 원본→계보/정규화 DB→검토한 읽기 전용 팩→관찰 레이어/표·그래프를 따른다. 시나리오 참고값은 승인된 별도 변환과 회차의 동결 판본을 쓴다. 개인 주문·매출·재고는 공개팩과 별도 저장/권한/동의다. 지도나 게임 Tick이 공급자 API를 직접 호출하지 않는다.

공통 공간·지역/품목 사전은 hash별로 재사용하고 분야팩은 실제 지역·기간·단위를 참조한다. 팩은 설치/갱신, 레이어는 표시/비교 단위다. 현재 Windows의 고정 `Resources` 소비를 선택 다운로드·외부팩 설치·원자 갱신의 구현 완료로 세지 않는다.

r159/r160 점검 기준 공공자료 정규화116,735행은 코드·참조·후보/연구·관측의 혼합이다. 서울 분기 인구45,631행, NOAA 일부 격자 수온63행 등이 있지만 공개 사업장/건물 연결 테이블은0행이고 항만2,431행은 추가 정규화 전 원문행이다. 서울 통계 코드·경계·CRS 대응과 이용 조건이 미확인인 자료는 표/미연결 상태로 남긴다. 신규 연구 후보26개는 안내이며 관측 취득26개가 아니다.

**r159의 DB 저장은 완료 기준선이다.** 수집/DB 도구를 다시 설계·초기화하거나 같은 무역 자료를 중복 반입하지 않는다. 기존4예약·키/계정·USB·수집 소유권과 운영/개인 자료 보호는 이번 통합 범위 밖이다.

**병행 입력 변화:** 통합 문서 작성 중 별도 Unity 작업본의 Host·Map/View·Business/Campaign/Dong·Expansion/LevelPrompt/Signals·README가 바뀌고 전국 N0/N1 소스/검사가 추가됐다. B0 감사값을 덮어쓰지 않고 B1 마감 관찰과 차이 목록을 색인에 따로 기록한다. 이 변화는 이번 Codex 작업이 만든 것이 아니며 현재 소스 전체를 기존 실행 증거와 동일하다고 인정하지 않는다.

현재 Unity README의 전국 관찰은 진입 시 게임 시계를 자동 정지하고 나갈 때 배속을 복원한다고 적는다. 이는 위 공통 시간 계약과 **기획 검토가 필요한 차이**다. 관찰 도구 분리/정지 정책을 기존 수행자와 대조하기 전 자동 수용하거나 이번 통합에서 조용히 시계 규칙을 바꾸지 않는다. 수치/표현용 위치·선과 가상 회차도 독립 검토 대상이다. 이 차이는 구 후보의 문서 계획 검토를 막는 것이 아니라 공유 코드 편집 전 재대조 범위다.

이 표는 반환·소스·기존 산출물 대조이며 새 Runtime/E 증거가 아니다. 반환의 정확 수치·입력·검사 범위는 각 원문이 소유한다. 전체 활성 Goal 원장과 다른 Nature/Farm/Hub/City 작업을 통합 문서의 대기열로 재배정하지 않는다.

## 7. Claude가 지금 준비할 것과 코드 착수 전 남은 것

지금은 이 문서·현황·소스 지문을 읽고 **구 지도 작은 후보 하나의 구현 계획**을 반환할 수 있다. 기존 계약 재사용 위치·직접 결과 경계·상태 소유·정확 쓰기 파일·필요 연구·입력/복귀 시각안·검증을 채운다. 같은 기획 통합을 다시 허락받을 필요는 없다.

새 기능의 실제 코드 착수 전에는 기존 [개발 인계 기준](../../../../Architecture/GitHub기반기획개발교대운영체계.md)의 `Approved` 판본/hash·Ready 주체/WI·E1~E7·필수 연구 `Accepted`·담당/쓰기 경로·기준선·검증/반환을 결속한다. 이 통합 색인과 검토 인계는 그 실행 원장을 대신하지 않는다. 기존 원장을 고치거나 `ReadyToDispatch`를 자동 부여하지 않는다.

**확정:** 기획 공통 진입/중복 정리, 기존 구현 보존, 픽업 핀/간단히 선택 반영, 구 기사 여력 후보 우선 정밀화, 전문/승인/검증 원본 유지.

**미정:** 첫 구 WI가 ‘대기 계획 확정’에서 끝나는지 ‘지원 거점 도착·대기’까지 책임지는지, 실제 허용 행동·저장/명령 계약·정확 쓰기 소유·필수 연구/시각안. 앞의 작은 결과를 첫 후보로 추천하지만 실행 승인으로 쓰지 않는다. 다른 작업줄의 미정은 각 전문에 유지한다.

**다음 검토 하나:** Claude가 기존 계약으로 해결되는 범위를 대조해 첫 직접 결과 경계를 반환한다. 코드로 해소할 수 없는 플레이 선택만 기획에 돌려보낸다. 지금 사용자에게 통합 작업의 허락을 다시 요청하지 않는다.

## 8. 이 통합의 검증과 범위

최근 r140~r161의23원본과 기존 반환/정본을 대조했다. B0 Unity15파일의 반환 지문 일치와 기존 검사/빌드 산출물을 확인했다. B1에서는 WindowsGame 병행 변경/추가를 기록하고 기존 반환과 현재 입력을 구별했다. Core/MobileGame 보호 지문은 일치한다. 문서 링크·색인/hash·원본 보존·diff 검증은 준비 인계/로컬 영수증에 남긴다. 제품·DB·새 빌드/Runtime·시안 이미지·Goal/WI·수집/예약·운영·commit/push는 이번에 실행하지 않았다.
