## 2. 확정 역할 분담

| 주체 | 맡는 범위 | 다음 연결 |
| --- | --- | --- |
| **플레이어** | 공급 구매 발주, 정산 최종 확정, 예외의 최종 처리 | 조건/영향을 보고 명시적으로 결정 |
| **현장 담당자·위탁 수행처** | 승인된 범위에서 제조·검수 실행·피킹·포장·스캔·상하차·운송 등 실제 수행 | 정상 기록·결과/이상 보고 |
| **시스템·엔진** | 재고/작업·금액 집계/계산, 발주/정산 후보·대안/이유, 승인된 정상 규칙 진행 | 플레이어 검토와 현장 실행을 지원 |

위 현장 작업 목록은 역할 분담을 구체화하는 예시이며 업종별 전체 동작을 한꺼번에 개발하라는 승인이 아니다. 직원과 외부 위탁업체의 소속·계약 차이는 r224를 유지한다. 플레이어가 현장 작업을 직접/집중 모드로 수행하는 기존 선택도 유지한다. 위임할 수 있다는 것이 직접 미니게임을 없애는 뜻은 아니다.

### ‘발주’의 범위

원료·상품/공급을 **어디서 어떤 조건·수량으로 구매할지 확정**하는 조달 결정으로 읽는다. 시스템이 재고 부족/예상·수량/비용 후보를 준비하고 플레이어가 거래 범위를 결정하는 방향이다. 승인된 재고/레시피의 사용과 고객 주문 접수·이미 승인한 제조/피킹 작업의 실행까지 매번 신규 구매 발주로 취급하지 않는다.

작업자가 부족한 원료를 알아차리고 발주 요청/근거를 올리는 것은 가능하다. 공급처 변경·대체품 구매·발주 수량/조건 확정은 플레이어에게 남는다. 투자/고용 등 기존 경영 결정도 별도 승인 규칙을 유지하고 이번에 현장 위임에 포함하지 않는다.

### ‘정산’의 범위

작업 완료/매출·비용 발생 기록과 계산·전표/정산안 준비는 지원할 수 있다. **정산의 최종 확정은 플레이어**가 맡는 방향이다. 결산 보고 열람·계산 완료·정산 승인·지급은 같은 사건이 아니며 정확 범위/회차·지급 방식은 후속으로 정한다.

기존 Core에서 이미 Settled/매출로 확정한 기록을 새 정산안으로 이름만 바꾸거나, 승인 시 같은 매출/보수를 다시 지급하지 않는다. 이행·자동 계산/기록·정산 승인·지급을 나눌 구현에서는 현재 저장/원장·세이브/Replay·중복 방지와 과거 기록 호환을 결속한다. 이번 문서로 현재 자동 정산 코드나 기존 잔액/완료를 변경하지 않는다.

예외가 생기면 **영향받는 업무·물량과 실제 의존 작업만 필요한 범위에서 보류하고 다른 정상 작업은 계속하는 안**을 권한다. 미확인 물량을 후속 제조/배송에 사용하거나 정산 불일치를 자동 승인하지 않는다. 회사 전체 정지/부분 진행의 정확 기준은 아래 다음 질문으로 남긴다.

## 4. 사람이 성장하면 달라지는 것

r224의 함께 익히기→부분 위임→현장 책임→다음 사람 육성은 유지하되, 이 판본에서는 **현장 수행을 정확히 해내고 이상을 알아차려 근거/대안을 보고하는 범위**로 구체화한다. 여러 직원의 승인된 작업 순서/배치를 조율하는 역할은 후속 후보이며 발주·정산·예외의 최종 권한은 자동 이전하지 않는다.

육성 결과는 숙련·실수/회복·보고의 정확성·현재 근무 여력 등 해당 근거로 읽는다. 높은 명덕/등급·교육 비용만으로 플레이어 권한을 획득하지 않는다. 깨어서 한 관찰·계획·교육/실패의 명덕 원칙은 r206대로 유지하고 업무 성패/권한과 구분한다.

성장한 사람에게 현장을 맡겨 플레이어는 공급·자금·확장과 예외를 더 넓게 살핀다. 직원에게 모든 경영 판단을 넘겨 게임이 무조건 자동 완료되거나, 반대로 플레이어가 정상 작업 하나마다 승인만 반복하는 구조로 만들지 않는다. 정확 감독/보고 주기와 운영 부담은 미정이다.

## 5. 플레이어에게 돌아오는 흐름 — 제안

```text
플레이어의 발주/업무 범위 결정 → 준비된 현장 담당자의 수행
  ├─ 정상 결과/기록 → 계산·보고/정산안 준비 → 플레이어 정산 확정
  └─ 예외/결정 필요 → 근거·영향/대안 보고 → 플레이어 결정 → 해당 작업 재개/인계
```

- 지금/여기: 현재 한 동의 점포/현장과 운영 회차. 업무를 맡기고 지도에서 관찰하는 상황.
- 나: 발주·정산·예외를 결정하는 플레이어. 현장에 직접 참여하거나 다른 사업을 살필 수 있음.
- 너: 승인된 일을 수행할 사람/위탁처, 재고·시간·작업과 근거가 있는 결정 요청.
- 이렇게: 준비된 요청을 검토·승인/수정/보류하고 같은 대상의 수행·회복 결과를 확인한다.
- 대가: 구매/지원 비용·시간/기회·남은 재고와 타 현장 영향. 승인하지 않은 요청이 시간 경과/창 닫기만으로 승인되지 않는다.
- 귀환: 결정한 업무·현장으로 돌아가 실제 기록/결과를 본다. 화면 이동/관찰 모드가 권한·결정/정산 결과를 바꾸지 않는다.

플레이어의 발주·정산·예외 요청은 기존 업무/운영 요약과 이어 읽는 ‘결정 대기’ 목록 후보로 모을 수 있다. 자료/계산 후보와 작업 대기열·실제 진행/완료를 구분한다. 묶어서 검토할지·승인 단위/마감·UI 위치는 미정이며 매 항목 강제 팝업·전체 묶음 자동 승인까지 채택하지 않는다.

## 6. 확정 / 미정 / 다음 질문 하나

**확정:** 현장 수행은 위임/위탁 가능, 예외·조달 발주·정산의 최종 결정은 플레이어가 담당한다. 기존 직접 플레이/관찰·사람 육성과 확장 방향은 유지한다.

**미정:** 첫 업무/담당자, 정상 검수와 예외별 한도/상태·보고/재개, 승인할 발주/정산의 단위·회차/지급·현재 자동 기록과의 호환, 위임 계약/사람 명부·결정 대기/시안·개발 수용. 새 승인/정산 코드는 구현하지 않았다.

**다음 질문 하나:** 예외가 생기면 **그 업무·물량만 필요한 범위에서 보류하고, 다른 정상 작업은 계속하면서 플레이어에게 판단을 요청하는 방식**을 기본으로 할까요? 여러 현장을 관찰하는 흐름을 살리되 실제 의존 작업/물량은 함께 막힐 수 있다는 영향 표시가 필요하다.
