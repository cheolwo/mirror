## 1. 추천 — 주문과 제조, 픽업이 한눈에 이어지는 한 층

**지도의 카페를 누르면 지붕과 앞벽을 걷어낸 한 층 매장이 보이고, 바리스타 작업을 고르면 제조 바를 크게 보여준다.** 고객의 주문/대기·바리스타의 준비/제조·완성 음료의 인계가 연결돼 보여야 한다. 첫 안은 테이크아웃 중심에 작은 고객 공간을 둔 가상 카페다.

동네에서는 배달의 이동을, 센터에서는 물품/위치를, 카페에서는 **한 잔의 재료와 공정·장비 순서**를 중심으로 플레이한다. 같은 세계·공통 시계·작업 대기열을 사용한다. 장식만 다른 지도보다 해당 직무의 결과를 읽는 공간을 만든다.

## 3. 고객 앞쪽과 작업 바 뒤쪽을 함께 읽는 맵

아래는 공개 자료에서 읽은 기능을 연결한 **가상 배치 추천**이다. 어느 브랜드의 실제 평면도를 재현한 것은 아니다. 첫 시안에서는 ㄱ자 또는 직선 바를 비교하되 제조대와 픽업 위치가 가려지지 않는 쪽을 우선한다.

```text
고객: 입구 → 주문/메뉴 확인 → 대기·작은 좌석 → 수령 위치 → 출구
                                      ↑ 완성·인수 확인
바: 컵·주문표 → 분쇄/계량 → 추출 → 냉음료 조합 → 마감·픽업 준비
       ↑ 원부재료/냉장 보관       ↘ 사용 도구 정리·세척
```

| 구역 | 보이는 물체 | 집중 플레이·관찰의 초점 |
| --- | --- | --- |
| 주문/대기 | 주문 접점·메뉴 표시·대기 위치 | 어떤 주문이 준비됐고 어디서 기다리는지. 주문 확인과 결제/매출을 구별 |
| 재료·컵 준비 | 컵/뚜껑 수납·원료 보관·냉장 위치 | 선택 메뉴/옵션·원료 가용·컵 조건과 준비할 수량 |
| 분쇄·추출 | 그라인더·저울/작업면·머신 | 올바른 주문 컵/레시피, 원두 투입과 추출 결과·장비 점유 |
| 냉음료 조합 | 물·얼음·우유/시럽과 조합 작업면 | 재료량/단위·순서·옵션, 다른 주문의 컵과 혼동 방지 |
| 마감·픽업 | 내용 확인·뚜껑/라벨·픽업 선반/창 | 한 잔 완성·한 주문 준비·기사/고객 인수를 각각 구별 |
| 정리·세척 | 사용 도구 위치·세척대·정리된 도구 | 진행 음료와 별개인 장비 준비 상태·정리 작업. 주문별 정리와 일일 마감을 구별 |
| 고객 공간 | 작은 좌석·대기 공간, 후속 반납 위치 | 이완에서 사람의 체류를 관찰. 가상 고객이며 공개 유동인구를 실주문처럼 쓰지 않음 |

고객/기사의 대기와 바리스타 작업 구역은 이름/바닥/카운터로 구별하고, 제조 재료와 사용 도구의 위치도 읽히게 한다. 실제 통로 폭·설비 간격·작업 인원은 아직 정하지 않는다. 첫 가상 매장의 보급 재료는 독립 Fixture로 준비하며 물류센터·우유 사슬이 완료돼야 카페를 시작하는 필수 선행은 두지 않는다.

### 점포 유형은 같은 작업 모듈의 배치 차이로 둔다

- **입문: 테이크아웃 중심.** 제조 바와 픽업 접점이 가까운 한 층을 먼저 읽는다. 소수의 좌석은 공간감을 위한 제안이다.
- **후속: 좌석 중심.** 같은 제조 바에 고객 홀·반납/정리·서비스 동선의 책임을 더한다.
- **후속: 포장/배달 픽업이 많은 매장.** 주문별 보관/봉인·기사 인계를 강화한다.

세 유형을 브랜드별 고정 성능이나 별도 OS로 만들지 않는다. 좌석 수를 늘렸다는 이유만으로 자동 매출 증가·추출 속도 증가를 부여하지 않고, 어떤 병목을 해결하고 어떤 부담을 더하는지 결과로 확인한다.

## 4. 카페 미니게임 — 고정 제조대에서 한 잔을 정확히 만든다

첫 직접 작업은 **가상 카페1곳·준비된 주문1건·음료1잔**을 추천한다. 기존 r147/r68의 아이스 아메리카노를 첫 후보로, 이어 아이스라떼를 같은 바에서 비교할 수 있다. 새 배합 수치를 만들지 않으며 기존 시범 레시피의 실물/컵 검증 한계와 판본을 보존한다. 핫 스팀·라떼아트·복수 잔 동시 제조·발주는 첫 필수 범위가 아니다.

| 구간 | 조작 제안 | 확인할 결과 |
| --- | --- | --- |
| 주문·컵·원료 확인 | 주문표/옵션과 해당 컵·재료 선택 | 준비 가능한 주문 품목과 레시피/컵·장비 조건 |
| 분쇄·도징/탬핑 | 마우스로 도구를 고르고 계량·정렬을 간단히 조작 | 해당 레시피의 원두 준비. 클릭 순서만으로 잘못된 양을 성공 처리하지 않음 |
| 추출 | 시작 후 목표/현재 산출량과 경과를 보며 정지 | 실제 게임의 추출 판정·재공품, 머신 점유/상태 |
| 조합 | 물/우유·얼음 등 해당 레시피 순서로 같은 컵에 조합 | 재료/단위/옵션에 맞는 음료. 아이스라떼에 핫 스팀을 필수로 넣지 않음 |
| 마감·픽업 준비 | 내용·용기/라벨 확인, 필요한 정리 | 한 잔 제조 결과와 주문의 준비 상태. 아직 고객 수령/배달/최종 정산은 아님 |

카페의 첫 조작은 r147의 **고정 작업대 시점·마우스 선택/계량/타이밍**을 재사용한다. 작업 구역 선택에서 제조대를 크게 보여주며, 센터의 방향키/Space 조작을 모든 카페 공정에 강제하지 않는다. 공간 탐색용 작업자 이동은 후속 후보이고 첫 제조의 필수 조작이 아니다.

추출 기계의 자동 동작은 게임의 정상 공정이며, 버튼을 누른 뒤 기계가 작동했다는 이유만으로 직접 수행이 끊기거나 NPC에게 인계됐다고 세지 않는다. 반대로 애니메이션이 끝났다는 이유로 제조·주문·인수·보너스를 한꺼번에 완료하지 않는다. 공정 시간·연출 압축·공통 게임 시계는 기존 전문 계약으로 결속한다.

## 5. 컵·재료·장비·완료를 연결한다

주문 ID→주문 품목→컵/재공품→레시피 판본→사용 원료/장비→완성 확인→픽업 인수의 계보를 읽는다. 여러 잔 주문에서는 한 잔과 주문 전체 준비를 나누고, 매장/포장/배달 채널의 제조 시작 조건을 보존한다. 화면의 주문 수락만으로 임의 결제·제조 시작·매출을 만들지 않는다.

원료 예약·실제 사용·폐기·소모품과 장비 점유는 서로 다른 상태다. 같은 원두/우유를 준비·추출·완성 때 반복 차감하지 않는다. 원두 g·추출액 g·물/우유 mL·얼음 g·컵 개를 혼용하지 않으며, 취소/재제조 시 이미 사용한 재료를 원재료로 되돌리지 않는다. 원료 부족·장비 사용 불가·내용 불일치는 이유와 회복 경로를 남기고 재료를 자동 생성하지 않는다.

냉장·세척·정리는 맵에서 위치와 상태를 보여주되 이번에 현실 온도/식품 기준·기종별 유지 절차를 새로 고정하지 않는다. 필요한 실제 기준은 해당 제품/장비 자료와 후속 전문 검토로 결속한다. 한 잔 완성이 모든 도구의 준비나 일일 마감 완료를 뜻하지 않는다.

## 6. 집중·이완·혼합 턴과의 연결

계획에서 오늘의 메뉴/준비량·재료·가동 장비와 방침을 보고, 실행에서 바리스타 작업을 직접 고르거나 이완으로 준비된 업무를 관찰한다. 결산에서는 완성/인수·대기·실수·폐기·장비 부담·비용/수익을 각각 확인한다. 카페 진입·작업대 확대·한 잔 완성이 턴/스테이지를 자동 넘기지 않는다.

`커피 제조` 직무를 고르면 같은 매장에서 준비된 주문을 이어 수행할 수 있다. `다음 작업`은 한 건씩 명시적으로 시작하며 다른 직무·다른 장소로 강제 전환하지 않는다. 이완 전환은 같은 주문·컵 내용·추출 상태·사용 원료·장비 점유를 안전한 확정 경계에서 이어받는다. 한 잔을 다 끝내야 관찰로 나갈 수 있게 잠그지 않는다.

공통 시계와 기존 명시적 턴 경계/일시정지·긴급 예외를 유지한다. 인계 미준비 상태는 이유와 현재 상태를 보존하며, 경영/지도 복귀는 원래 카메라·시설 선택·입력을 복원하고 경과 후 현재 업무를 읽는다. 직접 완료 자격과 추가 보너스는 기존 r147의 상위 결과/정산 규칙을 따르고 클릭/한 컵 완성만으로 즉시 별도 지급하지 않는다.

## 7. Claude 시안 입력과 좁은 준비 순서

첫 시각 검토는 **같은 가상 카페의 내부 전체 한 장과 제조대 상세 한 장**을 추천한다. 기존 동네 지도에서 카페를 선택한 진입 관계와 경영 귀환을 짧게 연결한다.

1. 전체: 지붕/앞벽을 걷고 고객 주문/대기·제조 바·냉장/수납·정리/세척·픽업 위치가 읽히게 한다. 위쪽 메뉴보드/장식이 바 작업을 가리지 않게 한다.
2. 상세: 같은 바의 주문1건·컵1개·레시피 판본·현재 공정·막힌 이유를 보여주고 필요한 도구/다음 조작만 강조한다. 원료/설비의 실제 미연결은 준비 상태로 표시한다.
3. 표현: 목재·낮은 대비의 바탕과 명확한 작업 표식을 사용한다. 브랜드 고유색·로고를 복제하지 않고, 기존 민트는 관리/선택 표식에 제한적으로 쓴다. 실제 브랜드 도면/레시피가 아닌 가상 시안임을 밝힌다.
4. 상태: 준비→제조 중→완성 확인/픽업 대기와 원료 부족/재제조를 구별한다. 집중/이완·`다음 작업`·내부 전체/지도 복귀는 각각의 의미를 유지한다.

후속 개발 후보는 한 잔의 제조·완성 확인을 같은 상태로 읽는 직접 결과부터다. 고객 홀 경영·기사 배달 연결·발주/입고·복수 머신/직원·전 매장 확장을 하나의 첫 WI로 묶지 않는다. 새 기획/연구 수용·정확 상태/명령·쓰기 경로·필수 시각/공정 검토·E1~E7 결속은 별도이며, 이번 자료 확인이 제품 실행 권한을 발급하지 않는다.

## 확정·미정·다음 검토 하나

**확정 방향:** 공개 프랜차이즈 자료를 참고한 카페 고유 공간이 필요하다는 사용자 요청을 조사·문서화했다. 동네/센터와 같은 공통 진행 안에서 카페의 제조·픽업을 읽는다.

**제안·미정:** 첫 가상 매장의 바 형태·좌석/픽업 배치·규모·조작·세부 시간/장비 능력·직접 결과 명세. 실제 도면·브랜드 비공개 배합·사진 재사용 권리·시안/코드 구현은 확보/완료하지 않았다.

**다음 검토 하나:** 내부 전체와 제조대 상세에서 ‘고객은 어디서 기다리고, 바리스타는 어떤 순서로 만들고, 완성 컵은 어디서 인계되는지’가 한눈에 읽히는가? 먼저 테이크아웃 중심 한 층으로 검토하는 안을 추천한다.
