## 1. 플레이어가 익힐 흐름

**동은 ‘어디를 경영하는가’, 하단 사업 버튼은 ‘무슨 일을 결정하는가’를 고른다.** 지역 선택마다 여러 사업의 버튼을 새로 찾지 않고 같은 하단 진입을 반복해서 쓴다.

| 단계 | 기사 고용 | 음식점 입점 |
| --- | --- | --- |
| 지역 | 면목3·8동 등 행정동 하나 선택 | 같은 동 선택 |
| 사업 | 하단 `기사 운영` | 하단 `음식점` |
| 운영 창 | 이 동의 기사·업무량·고용 부담 확인 | 이 동의 운영 중/준비 중 점포 확인 |
| 추가 | `기사 고용` → 후보/조건 검토 | `음식점 추가` → 업종/운영 모델 검토 |
| 대상 선택 | 기사 후보 선택 | `지도에서 자리 고르기` → 건물/가상 점포 공간 선택 |
| 결정 | 계약 조건/비용·업무 배정 지역을 보고 확정 | 공간/준비비/필요 조건을 보고 입점 계획 확정 |
| 결과 | 실제 게임 고용 결과를 같은 창에서 확인 | 준비 중 계획을 같은 창/지도에서 확인 |

하단 탭 자체를 누른 것은 조회다. 고용/입점 확정·차감·영업 시작을 만들지 않는다. 구체 버튼 문구와 창의 위치/크기는 시안 검토 전 제안이다.

### 지금·여기·나·너·이렇게

- 지금: 선택한 동의 주문/작업 현황을 보고 인력이나 점포를 늘릴지 판단하는 운영 회차.
- 여기: 행정동 하나의 지도와 그 동 이름이 붙은 사업 운영 창.
- 나: 현재 사업의 운영자. 직접 작업과 관찰·위임의 기존 선택은 유지한다.
- 너: 이 동에서 관리하는 기사/점포, 고용 후보, 게임이 준비한 입점 공간과 비용/부족 조건.
- 이렇게: 사업 버튼→현재 현황→추가 행동→후보/공간→검토/확정→같은 동과 사업 창의 결과로 돌아온다.
- 대가: 고용의 지속 비용, 점포 준비 자금/인력·시간과 기존 운영 여력. 정확 수치는 새로 정하지 않는다.
- 결과/다음 선택: 결과를 확인한 뒤 기존 사업을 개선하거나 확장을 미룬다. 지도 이동이나 창 닫기가 회차/하루를 넘기지 않는다.
- 상위 목적 정렬: 판단할 동과 업무를 좁히는 보조 층이다. 창을 연 횟수만으로 돈·사람 성장·경 시간·만족도를 늘리지 않는다.

## 2. 화면마다 맡는 일

| 화면 요소 | 맡는 일 | 이곳에서 시작할 행동 |
| --- | --- | --- |
| 동 이름/운영 요약 | 선택 지역·핵심 현황/문제와 현재 위치 | 동 선택/사업 창으로 이동 |
| 하단 사업 버튼 | 동일한 사업 운영 창의 공통 진입 | 기사/음식점/가맹점 등 선택 |
| 사업 운영 창 | 선택 동의 해당 사업 현황과 목록·추가 행동 | 고용·추가·기존 대상 관리 |
| 지도 | 운영 대상 관찰, 명시적으로 시작한 위치 선택 | 후보 건물/공간 선택과 부적합 사유 확인 |
| 대상 카드/준비 절차 | 고른 사람·점포·공간의 상세와 결과 | 조건 검토·최종 확정·준비/내부 보기 |

동 운영 카드는 지역 요약으로 축소하고 직접 고용·입점 확정 버튼은 해당 사업 창으로 옮긴다. 인력 부족 안내가 필요하면 `기사 운영 열기`처럼 같은 창으로 가는 링크만 남긴다. 별도 고용 창/입점 창을 지역 카드에도 복제하지 않는다.

동 신호의 빠른 고용/제휴 행동도 같은 사업 창과 해당 동을 여는 안내로 통일하는 안을 제안한다. 신호의 대상 동과 현재 동이 다르면 대상 동을 밝히고 명시적으로 이동해 검토한다. 공통 배차 엔진처럼 전체에 적용되는 상태는 `공통` 범위를 표시하며 선택 동 전용 효과로 바꾸지 않는다. 엔진 투자 규칙 자체는 이번 개정 대상이 아니다.

현재 소스에는 하단 `기사 운영`, `음식점`, `가맹점`, `창고·화물`, `물류센터`, `생산자`가 있다. 기존 이름/순서·해금 상태를 기본으로 삼으며 모두 새 기능을 만들라는 목록이 아니다. 사업 창은 한 번에 하나를 열고 선택 동 이름을 항상 표시한다. 창은 지도를 가리지 않는 측면 패널을 첫 시안 후보로 제안한다.

## 3. 기사 운영 창

먼저 이 동에서 담당/배정된 기사와 현재 작업·대기·부족 사유를 보여 준다. 지도 안에 현재 서 있는 기사와 이 동의 관리 인력은 다를 수 있으므로 화면 좌표만으로 소속을 정하지 않는다. 구체 인력/담당 지역의 기존 계약을 구현 전에 확인한다.

`기사 고용`을 누르면 후보, 가능한 업무, 고용/유지 조건과 부족 사유를 읽는다. 후보 선택 후 최종 조건을 보고 `고용 확정`으로 진행한다. 인력 추가를 위해 건물을 고를 필요는 없다. 성공하면 새 기사와 배정 지역/가용 상태를 같은 창에서 확인한다. 실패하면 사유와 현재 상태를 재조회하고 후보/검토 문맥을 유지한다.

고용과 훈련/성장·배차·실제 주문 수행은 다른 결과다. 이미 고용한 기사에게 일을 연결하는 기존 규칙을 재사용하며 고용 버튼만으로 차량·주문·성과를 자동 생성하지 않는다. 금액/기간·고용 가능 시점은 기존 승인 규칙을 대조하고 미정인 값은 검토 중으로 표시한다.

현재 동별 모집은 기사 수 집계 증가다. 위의 개별 후보/계약 검토와 관리 대상 표시가 이미 구현됐다는 뜻은 아니다. 기존 집계 고용의 진입 이동과 개별 기사 고용 기능의 준비를 분리하고, 집계만 있는 단계에서 실제 이름/기사 객체가 생겼다고 표시하지 않는다.

## 4. 음식점 추가와 건물 선택

1. 하단 `음식점`에서 이 동의 운영 중/준비 중 점포와 `음식점 추가`를 연다. 점포가 없어도 추가 진입과 준비 조건을 읽을 수 있다.
2. 업종/운영 모델과 필요한 공간·준비 부담을 검토한다. 독립 카페 시작을 가맹점/본부 개설 뒤로 강제하지 않는다. 음식점/가맹점 목록의 구체 카페 분류는 현재 구현과 시안에서 정리할 미정 사항이다.
3. `지도에서 자리 고르기`를 선택하면 위치 선택 상태가 된다. 창은 접거나 좁혀 지도를 보이며 사업 종류·선택 동·`자리 선택 취소` 안내를 남긴다.
4. 그 동의 건물을 누르면 **그 건물의 입점 후보 공간을 검토**한다. 준비된 후보가 여럿이면 층/호·사용 가능 공간을 고른다. 후보가 없으면 이유를 보여 주고 다른 건물을 고를 수 있다.
5. 최종 카드에서 같은 건물/공간·사업 유형·준비비/시간·필요 인력/설비·가용 자원과 취소 조건을 확인한다. 명시적 `입점 계획 확정` 뒤에만 기존 규칙으로 계획을 등록한다.
6. 성공하면 준비 중 목록/표식과 다음 준비 절차를 보여 준다. r190/r195/r197에 따라 개업 준비·등록/장소 페이지·조달/내부 작업으로 연결한다. 입점 계획 등록과 개업/판매 가능은 같은 완료가 아니다.

일반 조회 상태에서 건물을 누르면 기존 건물/점포 정보가 열린다. **추가→자리 선택을 명시적으로 시작한 동안만** 같은 클릭을 입점 후보 선택으로 해석한다. 기존 건물의 빈 공간이나 임대 가능·소유권을 공공 주소/건물 모양만으로 만들지 않는다. 가상 후보는 가상으로 표시하고 실제 인허가 점포를 새 입점 가능한 매물로 취급하지 않는다.

후보는 테두리/미리보기로 구별하며 관리 민트색으로 소유를 먼저 표시하지 않는다. 한 점포를 추가했다고 건물 전체를 칠하지 않는다. 기존 건물의 점포 입점은 r170의 신축/재건축 절차와 별개다.

## 5. 다른 사업으로 확장하는 범위

| 사업 | 창에서 확인할 현황/행동 후보 | 이번에 확정하지 않는 것 |
| --- | --- | --- |
| 가맹점 | 기존 가맹 모델/준비 점포 확인 → 준비된 모델의 점포 추가 → 같은 위치 선택 흐름 | 본부/가맹 계약·비용·공급망의 새 규칙 |
| 창고·화물 | 창고/운송을 구분해 현황을 읽고 준비된 창고 개설·운송 관리로 이동 | 창고 추가를 기사 고용/화물 수락과 같은 명령으로 합치기 |
| 물류센터·생산자 | 기존 지도 범위/해금·준비 상태에 맞는 현황 | 동을 골랐다는 이유로 전국 시설/사업을 즉시 추가 |

사업 창 진입 방식은 공통으로 쓰되 각 사업의 결정·공간·준비 상태를 억지로 통일하지 않는다. 아직 구현되지 않은 행동은 `기능 준비 중`, 게임 조건이 부족한 행동은 그 사유를 표시해 구분한다. 구/전국 전용 업무를 열 때는 r184/r197의 명시적 지도 이동/귀환을 따른다. 이번 동 중심 변경으로 서울 독립 단계를 되살리지 않는다.

## 6. 전환·실패·귀환 제안

| 상황 | 권장 동작 |
| --- | --- |
| 사업 버튼 최초 선택 | 현재 동의 창을 열고 해당 목록/현황 조회. 같은 버튼 재선택은 중복 창을 만들지 않고 기존 창을 앞으로 표시 |
| 다른 사업 선택/창 닫기 | 미확정 선택은 자원을 바꾸지 않음. 진행 중 위치 선택은 종료하고 사업/동에 결속한 초안만 보존. 다른 사업에 후보 건물을 넘기지 않음 |
| 동을 이동 | 위치 선택 종료·옛 후보 강조 해제 후 새 동의 현황 조회. 초안이 남아 있다면 원래 동 이름을 표시하고 명시적으로 돌아가 재개. 새 동에 옛 계획을 몰래 적용하지 않음 |
| 입점 중 다른 동 건물 선택 | 현재 동 밖임을 표시하고 확정하지 않음. 동 이동은 별도 사용자 선택으로 처리 |
| 동 미선택/자료 로딩·실패 | 지역 선택/조회 상태와 이유를 표시. 임의 다른 동을 대신 쓰거나 빈 목록을 인력/점포0으로 확정하지 않음 |
| 자금·고용 조건 부족/슬롯 충돌 | 부족 사유·현재 상태와 검토 내용을 유지. 다시 확인하거나 다른 후보 선택/취소 가능 |
| 확정 중 반복 클릭/응답 불명확 | 같은 요청 결과를 확인. 사람/점포/예약/차감의 중복 생성 금지. 임의 재요청으로 성공을 꾸미지 않음 |
| 확정 후 창 닫기/지도 전환 | 이미 등록한 계획·고용을 취소하지 않음. 실제 변경 취소/환급은 기존 별도 규칙으로 처리 |
| 관찰 모드/운영 회차 실행 중 | 창 열기/조회와 상태 변경 허용을 구분. 기존 모드·회차 관문을 유지하고 UI 이동만으로 시간/성과/결산을 바꾸지 않음 |

입력 중 키/클릭은 열린 창 또는 지도 중 현재 목적 한 곳에만 전달한다. UI 버튼 클릭이 뒤의 건물 선택/입점 확정으로 관통하지 않게 한다. Esc는 위치 선택→검토/사업 창으로 한 단계 돌아가는 후보 동작이며 구체 키/창 닫기 순서는 시안과 구현 입력 점검에서 확정한다.
