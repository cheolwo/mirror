## 확정한 방향과 첫 화면

플레이어는 가상 플랫폼 운영자다. 개인용 혼자 플레이를 첫 범위로 두고 사가정역 주변에서 한 주문의 문제를 이해하고 대응한 뒤 결과를 본다. 지도를 통해 동북권을 살펴볼 수 있는 경영 화면을 장기 배경으로 둔다. 개인용 첫 구현은 기존 원칙에 따라 `Solo / LocalProcess` 후보이며 구체 저장·시간·입력 명세는 뒤이어 정한다.

첫 이미지는 권역 지원 예산을 고르는 카드였으나, 사용자 답변에 따라 **주문 한 건의 문제 카드**로 수정했다. 두 이미지의 이력은 보존하고 최종 후보는 `02-one-order-issue-first.png`다. 초기 예산 카드의 선택·수치·행동을 승인된 게임 규칙으로 남기지 않는다.

| 화면 부분 | 사용자가 하는 일 | 현재 판정 |
| --- | --- | --- |
| 큰 디오라마 | 사가정의 전체 상황을 보며 문제 주문 하나를 선택 | 구성 제안. 실제 건물·기사·주문 연결은 없음 |
| 오른쪽 문제 카드 | 주문 진행 상태를 읽고 대응 선택 | 한 주문부터는 사용자 확정. 조리 지연과 대응 버튼은 제안 |
| `M` 권역 지도 | 중랑·사가정에서 노원·동대문·광진 쪽을 살펴보고 지역 선택 | 개략 UI. 정확 경계·확장 조건·지역별 준비는 미정 |
| 매장 상세 | 선택 건물·매장과 실제 사진/내 배달 기록을 확인 | 사진은 연결 예정, 상호/사진/기록의 실제 대응은 미구현 |
| 상단 요약 | 운영 자금·오늘 손익·지연 위험·기사 보수를 살핌 | 기존 수익/품질/보수 균형을 유지한 표시 제안. 예시 값은 미승인 |

기존 r3의 중랑·동대문·광진·노원·구리 범위는 이력으로 보존한다. 이번 첫 시안은 서울 동북권의 사용자 게임 권역을 개략적으로 보여주며 공식 권역 분류나 정확한 행정 경계도가 아니다. 구리는 서울 밖의 후속 연결 후보로 보존하고 이번 서울 그림 안의 구로 표시하지 않는다. 모든 주변 지역의 공간 자료나 플레이 기능이 준비됐다는 뜻도 아니다.

## 첫 사건 후보 — 한 주문의 조리 지연

**아래 사건과 대응은 아직 제안이다.** 사용자는 한 주문부터 시작하는 범위를 골랐고 ‘조리 지연’ 자체를 선택한 것은 아니다.

- 지금: 점심 피크 직전, 주문 한 건의 준비가 예상보다 늦어진다. 시안의1일차11:30은 장면 예시다.
- 여기: 사가정역 주변 디오라마와 선택 주문/매장 카드.
- 나: 주문 상태를 읽고 가상 대응을 선택할 수 있는 플랫폼 운영자.
- 너: 조리 중인 매장, 기다릴 수 있는 기사, 아직 전달되지 않은 주문. 실제 고객/기사의 개인정보나 실시간 운영 상태를 사용하지 않는다.
- 이렇게: ‘준비 시간 먼저 확인’ 또는 ‘기존 계획으로 기다리기’를 비교하는 첫 후보를 둔다. 확인에는 시간이 들 수 있고 기다리기에는 지연 위험이 남을 수 있으나, 정확 비용/시간·응답·성공 조건은 미정이다.
- 직접 결과: 대응이 해당 가상 주문에 기록되고 확인/진행 상태가 변한 뒤 같은 주문을 다시 본다. 기사 수락·조리 완료·배송 완료를 운영자 선택 한 번으로 자동 성립시키지 않는다.
- 실패·회복: 준비 시각 미확인/응답 없음/추가 지연일 때 원인을 남기고 일시정지 상태에서 다시 확인하거나 다른 대응을 고를 수 있도록 설계한다.
- 귀환: 결과를 본 뒤 디오라마의 같은 주문 또는 전체 상황으로 돌아온다. 첫 사건을 해결한 것만으로 권역 해금·경영 성공·실제 업무 완료를 선언하지 않는다.

첫 화면의 순환은 **문제 확인 → 대응 선택 → 진행 관찰 → 결과 확인 → 다음 선택**이다. 기존 주문 lifecycle와 지연/예외 기획에서 재사용할 WI·상태를 먼저 대조하며 현재 새 안정 ID나 WI Goal을 임의로 발급하지 않는다. 상위 회복 이야기와의 직접 결속은 이번 독립 경영 시안에서 해당 없음이다.

## 시각·자료·구현 경계

전체 디오라마에 같은 기본 품질을 적용하고 공통 상세를 한 층씩 더한다는 r48을 유지한다. r50의 공통 창/지붕·도로 조립·선택적 Synty 방식은 다음 제작 입력으로 사용한다. 한 매장만 사진 수준으로 만들고 주변을 기초 덩어리로 남기는 목표로 바꾸지 않는다.

이번 시안은 기존 생성 이미지의 분위기와 UI를 참조한 내장 `image_gen` 결과다. 건물 배치·매장 외관·노면·역 외형·기사·경로·금액·시간·손익은 생성/가상 예시이며 실제 지도·DB·Game View를 보여주지 않는다. 실제 매장/음식 사진은 생성하지 않았고 사진 영역은 대기로 남겼다. 화면의 라디오 선택 표시도 사용자의 대응 선택이나 실행 승인이 아니다.

기획의 상태는 `Draft`다. 첫 사건/행위·대가·실패/회복·반환이 정해지면 관련 주체/WI 재사용과 전문 연구·E1~E7 검증 명세·개발 인계를 준비한다. 새 Unity 코드·Scene·게임 시간/저장·운영 DB·실제 배차/연락/금융·공개/배포·commit/push는 이번에 변경하지 않았다. 기존 연구 r49와 실제 운영 앱의 증거를 이 게임 실행 증거로 승계하지 않는다.
