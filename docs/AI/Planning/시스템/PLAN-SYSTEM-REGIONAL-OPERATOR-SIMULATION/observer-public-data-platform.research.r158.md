## 1. 게임을 하지 않아도 쓸 수 있는 자료 관찰

추천하는 제품 방향은 **지도에서 필요한 자료를 골라 보고, 원하면 가상 실험이나 게임에 참여하는 설치형 도구**다. 관찰을 위해 게임 진행·해금·보상·특정 역할 수행을 의무로 만들지 않는다. 자료 레이어를 모두 끈 채 기존 지도를 보거나 한 분야만 내려받아 쓸 수도 있게 한다.

| 사용 방식 | 하는 일 | 기존 경계 |
| --- | --- | --- |
| 자료 보기 | 공공자료·내 업무 자료의 시점/분포·추세·출처를 읽고 비교 | 게임 Tick·가상 돈/성장·업무 Command를 실행하지 않는 읽기 기능 |
| 가상 실험 | 선택한 자료 판본을 참고하는 독립 가상 조건에서 방침 비교 | 사실 자료와 생성/가정한 수요·비용·결과를 구별하는 Simulation |
| 게임 참여 | 기존 이완 자동 수행 또는 집중 직접 수행 | 같은 게임 상태와 기존 보상·안전 인계 규칙 |

이는 사용자 사용 방식의 구별이며 새 `SsalddelExecution:Mode`를 만들지 않는다. 기존 `Simulation / Operational` 경계를 유지한다. **자료 보기와 이완은 다르다.** 이완은 게임 업무가 자동 진행될 수 있지만 자료 보기에서는 게임을 진행하지 않는다. ‘현재 공공자료가 갱신됨’도 새 게임 주문·매출·기상 재해 사건을 자동 발생시키는 근거가 아니다.

첫 사용은 지역/분야 선택→준비된 자료 팩 열기→기준시점·단위·출처 확인→표/지도 비교→필요하면 Excel 내보내기의 흐름을 제안한다. 내려받은 팩은 오프라인으로 읽고, 최신 자료 확인/업데이트는 선택하게 한다. 사용자의 프로그램이나 매 지도 조회가 공급자 API에 직접 요청하는 구조는 피하고 수집기·키는 서버/수집 환경에 둔다.

## 2. 지금 가진 기반과 연결 결손

읽기 전용 저장소 감사 `artifacts/local/observer-public-data-research-20261113/repo-audit.json`에서 다음을 확인했다.

- 과거 전수 색인168행은 중복·하위목록을 포함한 참조 대장이다. 등록된 농사로·KAMIS/USDA·수협·어획구역·KOSIS·국제 토지/토양 등의 존재를 실제 주기 수집·전국 커버리지로 세지 않는다.
- 현재 정기 수집 루트의 원문 포인터는 **원본 dataset7개 + metadata8개**이며 참조 원문15개의 SHA가 일치했다. 원본7개는 법정동 코드1·서울4CSV·World Bank 한국 경지면적1·BLS 미국 쌀 계열1이다. 이 중 서울 인구2CSV·World Bank·BLS의 **4개가 수치 관측자료**이고 나머지3개는 코드·경계 기준자료다.
- 한국 경지면적은 국가·연간1관측(기준2024)이고 BLS는 미국 가격이다. 전국 농지 위치나 국내 현재 원가로 사용할 자료가 아니다. 서울 인구는2026년2분기이며 경계 CSV의 기준기간은 별도 미확인이다.
- 최신 검토 city 영수증은 11/13 주기 미도달7·보류2·HTTP0, 생산가격 영수증은 11/12 주기 미도달2·보류2·HTTP0이다. 실행 기록을 새 관측자료 취득으로 표시하지 않는다.
- 별도 과거 국내해양 영수증에 2026-06 HS/국가 무역 원문3건과 KHOA 수온의 `ServiceKeyNotRegistered` 실패가 있다. 수산물 무역량은 어획량·수산자원량이 아니다.
- `ExternalDataSourceCatalog`, `PublicDataIngestionDbContext`의 Run/Raw/Normalized/RegionMapping, `AgriculturalFisheriesDbContext`의 품목·HS·가격 관계, Simulation의 KAMIS 읽기 전용 경로와 동결 RealityContext가 있다. 새 공용 데이터 체계를 중복 구축하기보다 이 경계에 연결한다.

현재 4개 수집 예약의 **로컬 등록 설정**은 활성이다: 행정/공간 월요일13:10, 인구/교통 매일09:20, 생산/가격 매일17:20, 물류/무역 매월20일09:40(KST). 실제 예약 회차 완료는 별도 영수증으로 판단한다. `automation-10`의 읽기 전용 도구 조회는 앱 카드만 반환해 실행상태 JSON 증거로 사용하지 않았다. 기존 예약·중단된 예약·USB/개인 배달/원가 예약을 복제·재개·변경하지 않았다.

핵심 결손은 분야별 raw-only 수집·시공간/단위 대응·검증된 DB 반입·사용자 배포 가능 팩·실제 Windows 소비를 한 자료에서 끝까지 잇는 부분이다. legacy 국제가격 CLI는 Migration을 실행하므로 그대로 정기 원본 수집기에 사용하지 않는다.

## 4. 수집부터 사용자 프로그램까지의 한 흐름

```text
기존 출처/자료셋 대장과 수집 정책
  → 주기 도래·키/조건·요청량 확인 → 원본 파일 + 취득 영수증
  → 형식/범위/단위/시점 검증 → 정규화 대기 → 기존 DB 계보/관계 반입
  → 관찰 조회 결과/집계 → Excel·CSV 내보내기
                      → 검증한 읽기 전용 자료 팩 → Windows 자료 보기
                      → 별도 동결 시나리오 참고 → 가상 실험/게임
```

원본 취득·DB 반입·팩 제작/배포는 서로 다른 작업으로 둔다. 새 파일이 생겼다고 곧바로 현재 게임과 사용자 데이터팩을 덮어쓰지 않는다. 같은 원문 hash는 재사용하고 개정/정정은 판본과 계보를 남긴다. 수집 실패·부분 취득·주기 미도달·변경 없음·자격 보류를 구별한다.

## 5. 관계형 DB와 정규화 제안

**원본 Excel/CSV/SHP/JSON/XML은 원형 파일로 보존하고, DB에는 값·키·관계를 저장한다.** 기존 private raw storage와 SHA/Run 연결을 재사용한다. Excel 자체만 DB에 넣는 것으로는 지역·품목·기간을 조인하는 관측 테이블을 대신할 수 없다.

| 논리 묶음 | 재사용/보강 제안 |
| --- | --- |
| 자료원·자료셋·이용조건 | 기존 `ExternalDataSourceCatalog` ID 재사용. 출처별 허락/귀속·기준 판본·마지막 확인을 결속 |
| 취득실행·원본 | 기존 Run/RawSnapshot. 본문은 파일/객체 저장, DB는 원본 위치·hash·판본·취득 결과 |
| 지역·경계판본·관측지점 | 기존 RegionMapping 재사용. 법정동/행정동/해역/교통분석권역/격자/PNU/지점의 종류와 유효기간 유지 |
| 품목·어종·축종·등급 | 기존 농수산 공통 품목·HS 및 관계 검토 재사용. 이름 유사성만으로 동등 코드 확정 안 함 |
| 지표·단위·차원 | 단위·도소매·등급·수층·측정법 등 관측의 의미를 별도 사전/관계로 정리. 원문 단위와 변환 판본 유지 |
| 관측/예측/집계값 | 기존 NormalizedRecord를 공통 계보로 사용하고, 해양 시계열·가격·생산/가축 집계 등 필요한 분야별 typed 사실 테이블/조회 결과를 보강 |
| 대응과 관계 | 기존 지역 대응과 품목 관계를 보존. N:M·유효기간·확정/후보/미연결·대응 근거/판본을 유지 |
| 배포팩·포함자료 | 팩 manifest와 포함 원본/정규화/대응 판본·허락 범위·커버리지·hash 연결. 실제 저장 계약은 후속 |

차원/사전은 중복을 줄이는 관계형 정규화를 적용하고, 화면용 집계와 파일은 이 정규화 자료의 읽기 결과로 만든다. 서로 다른 자료를 한 초대형 공통 테이블이나 무규칙 JSON 한 칸에 몰아넣지 않는다. 기존 맥락별 DB를 전부 하나로 합치거나 기존 지역 대응을 새 이름의 대응표로 중복 대체하지 않는다.

관측 고유성은 자료셋·판본·지리/지점·관측기간·지표·품목/등급/수층 등 실제 입도로 정의한다. 누적량/시점 재고/구간 흐름·평균/총량을 구별하고 월 합계와 같은 기간의 일 합계를 중복 합산하지 않는다. 가격 비교는 조사단위·품종·등급·도소매가 맞을 때만 한다. 값·결측·미제공·품질제외를 구분하고 미제공을 0으로 채우지 않는다.

관측 기준기간, 예측 발표/유효시각, 공급자 수정시각, 취득시각을 구별한다. 현재 RawSnapshot의 기준시각은 nullable이지만 NormalizedRecord의 `EvidenceAsOfUtc`는 non-nullable다. **기준시점이 불명인 원문은 수집시각을 관측일로 채워 정규화하지 않는다.** 보류 구역에 두고 unknown/기간 정밀도 계약을 먼저 설계한다. 기존 upsert가 모든 정정 이력을 불변 보존한다고 가정하지 않고 새 판본 보존·최신 조회와 과거 팩 재현을 별도 보강한다.

## 6. 파일·Excel·자료 팩

- **Excel/CSV:** 선택 지역·기간·품목의 검토/분석용 출력. 값 외에 단위·품질·출처·관측 기준기간·취득시각·자료/대응 판본을 함께 둔다. 지역/품목 코드는 선행0이 사라지지 않게 내보낸다. 수동 편집본은 원본 사실을 덮어쓰지 않고 별도 사용자 입력으로 읽는다.
- **첫 Windows 자료 팩:** 기존 JSON 소비 경계를 우선 재사용한다. manifest + 필요한 조회 결과 JSON + 경계/타일/원본에서 변환한 자산을 분야·지역별로 묶는다. 대량 시계열은 읽기 전용 SQLite 색인/분할 저장을 후속 후보로 두며 현재 Unity에 SQLite 어댑터가 준비됐다고 가정하지 않는다.
- **판본 결속:** 원본 SHA, schema/normalizer, 지역·품목 대응 판본, 좌표계·공간/시간 정밀도·단위·결측·포함/누락 범위·출처·이용조건·앱 호환을 manifest에 둔다. 서버의 최신 자료와 회차 시작 시 동결된 게임 참고 자료는 구별한다.
- **교체와 오프라인:** 새 팩은 임시 위치에서 내용·hash·호환을 확인한 뒤 활성 포인터를 교체한다. 실패하면 기존 정상 팩을 유지하며 마지막 기준일·갱신 실패를 표시한다. 부분 팩은 포함/누락 범위를 명시한다. 실제 원자 교체·저장/재실행 검증은 구현 후 수행한다.

기존 `transfer_snapshot.py`의 내부 인계 ZIP은 공개 배포 미승인이다. 이를 사용자 다운로드 팩으로 그대로 전환하지 않는다. 원본 공개·정규화/가공·프로그램 동봉·상업 이용 조건을 출처/필드별로 검토한 허용 목록만 배포에 넣는다. 이번의 후보 대장이나 포털 ‘무료’ 표기가 팩 배포 승인이 아니다.

## 7. 내 업무 자료와 공공자료를 함께 보기

공공팩·개인업무팩·가상 시나리오·플레이어 Save를 분리한다. 같은 지도에서 레이어로 겹쳐 읽어도 개인 업무값이 공공팩·공용 캐시·배포 파일에 섞이지 않게 한다. 실제 업무값·추정·가상 값을 각각 표시한다.

첫 개인 자료 연결은 로컬 CSV/Excel의 컬럼·날짜·단위·주소/좌표/지역 코드를 미리 보고 대응하는 방식을 제안한다. 기존 역할 API/DB 연결은 현재 계정·조회 범위를 유지하는 선택형 읽기 경로다. 가져온다고 주문·출고·계약·재고를 확정하지 않는다. 좌표·코드가 없거나 대응이 불명확하면 목록에 남기고 임의 건물/지역 중심으로 배치하지 않는다. 개인 자료를 외부 주소변환·업로드로 자동 전송하지 않는다.

표시 기준일을 바꾸는 동작은 데이터 조회다. 게임 시계를 되감거나 없던 과거 관측을 생성하지 않는다. 서로 다른 분야의 최신 기준일도 나란히 보여 준다. 자료를 참고한 가상 수요/날씨/원가는 별도 시나리오에서 판본을 동결하고 실제 업무 결과와 분리한다. 자료 보기·효과 ON/OFF·레이어 선택에 게임 보상이나 성장 조건을 붙이지 않는다.

## 8. 예약 운영과 권장 순서

기존4예약을 유지하고 신규 후보를 Source Catalog/정책에 대응한다. 새 공급자를 정기 실행에 넣기 전에 원본만 받는 명령·자격·한도·응답/스키마·시간/단위·이용조건을 확인한다. 기존 한 회차 요청/용량 상한·OS잠금·교대 소유를 조용히 늘리거나 우회하지 않는다. 관측 고빈도 작업이 필요하면 기존 월 통계 작업과 분리할 수 있으나 중복 여부와 소유·정확 입력을 대조한 뒤 실제 등록한다.

| 자료 성격 | 권장 확인·취득 방식 |
| --- | --- |
| 연간 도형·토지/시설 | 월별 개정 확인, 신규 판본만 취득 |
| 분기/월 통계 | 공표 후 취득, 최근 기간 정정도 확인 |
| 일별 가격·위판 | 공표/마감 뒤 하루1회부터, 필요한 정정 구간 별도 |
| 해양·기상·수문 | 기본 관찰은 일 집계 후보. 필요한 지점만30~60분 등으로 확장하며 이력 조회/게시 지연·한도 확인 |
| 참고 콘텐츠·신청형 자료 | 개정 확인과 조건 검토. 자격 미충족·용도 미합치 자료는 기본 수집에서 제외 |

각 회차는 Source별 `due/not_due/unchanged/partial/blocked/failed`와 신규 원문·정규화·팩 결과를 별도 기록한다. 기관의 공표/갱신 주기보다 자주 돈다고 새 자료가 생기는 것은 아니다. 스키마 변경·권리 변경·행정코드 개정은 현재 정상 팩을 유지한 채 검토 대상으로 보낸다. 예약 시스템에 등록됨, PC/수집 환경에서 실제 실행됨, 원문이 취득됨, DB에 반입됨, 사용자에게 배포됨을 구별한다.

권장 첫 연결은 **지역별 한우 사육통계 CSV 한 자료**의 조건/원본 확인부터 정규화→Excel→읽기 전용 관찰팩→Windows 조회까지 닫는 것이다. 허용 경계 자료와 지역 대응이 준비되면 지도에 연결하고, 미준비면 표/대응 검토 상태로 남긴다. 병렬 독립 후보는 수온/관측소의 해양 관찰팩이지만 키·이용조건을 먼저 확인한다. 모든 분야 수집기·전국 건물·Farm→Hub→City 사슬을 선행조건으로 묶지 않는다.

후속 순서는 ①기존 출처 ID·26후보 대응/우선순위 ②한 자료의 raw-only와 정규화·조회 ③Excel/팩/실제 Windows 관찰·오프라인 재실행 ④그 자료의 기존 예약 연결/실행 영수증 ⑤분야별 확장이다. 실제 구현에는 기획 판본·범위·주체/WI·쓰기 경로·완료 조건을 별도로 결속한다. 게임 입력·운영/DB·서버 연결·다른 PC 실행·배포는 각각 확인한다.
