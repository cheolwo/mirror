## 1. 확정한 방향

면목제3·8동 안의 생활상 이동을 본격적으로 표현하기 전에, 현행 공식 경계 안의 대상 건물을 가능한 한 모두 실자료 기반 건물로 준비한다. 자료가 없는 건물을 임의 모양·주소·높이·출입구로 채우지 않고 명시적인 결손으로 남긴다.

`모두 준비`는 모든 건물을 사진처럼 개별 모델링한다는 뜻이 아니다. 현행 공공자료로 확인 가능한 건물 윤곽과 높이 근거를 사용한 데이터 기반 건물 표현을 기본으로 하고, 외관 자료와 권리가 확인된 중요 건물만 후속 상세 모델로 교체한다.

```text
현행 면목제3·8동 경계 확정
  → 경계 안 대상 건물 전수 판정
  → 실자료 기반 건물 또는 MissingCoverage
  → 주소·PNU·높이·출입 기준점 결속
  → 이동 가능 건물과 상태 표현 전용 건물 분리
  → 점심 정상 배달 이동 표현
```

## 2. 건물 준비 판정

모든 대상 건물은 아래 셋 중 하나의 상태를 가져야 한다.

| 상태 | 의미 | 이동 사용 |
| --- | --- | --- |
| `RenderableBuilding` | 검증된 윤곽·행정동 귀속·표시 높이 근거가 있어 데이터 기반 건물로 표현 가능 | 출입 기준점까지 준비되면 가능 |
| `RenderableWithGeneralizedAnchor` | 건물 표현은 가능하지만 공식 출입구가 없어 건물 경계의 일반화 기준점을 별도 표시 | 실제 출입구로 주장하지 않는 조건에서 제한 가능 |
| `MissingCoverage` | 윤곽·귀속·좌표계·자료 권리 중 필수 근거가 부족함 | 경로 이동 금지, 상태 표현만 허용 |

`BuildingCoverageReady`는 대상 건물이 모두 위 상태 중 하나로 판정되고 원본 판본·hash·CRS·기준일·결손 사유가 기록됐을 때만 성립한다. 표현 가능한 건물 수만 세고 미수집 건물을 누락해서는 안 된다.

## 3. 실자료 기반 건물의 최소 계약

- 건물 안정 식별자와 원본 자료 식별자
- 현행 행정동 단일 귀속 또는 `Unresolved`
- 좌표계가 확인된 건물 윤곽
- 실제 높이·층수 근거 또는 명시적인 일반화 높이 표시
- 주소·PNU 판정 상태와 공개 범위
- 공식 출입구, 일반화 기준점 또는 `EntranceUnresolved`
- 원본 판본·hash·기준시각·이용조건
- Unity 표시 가능 여부와 결손 사유

주소·PNU·필지 도형·출입구는 서로 대체하지 않는다. 건물 윤곽만 있다고 배달 목적지나 진입 가능한 건물로 확정하지 않는다.

## 4. 이동 표현 규칙

1. 출발 건물·도착 건물과 두 기준점 사이의 이동 연결이 검증된 구간만 Actor가 경로를 따라 이동한다.
2. 검증된 구간이 끊기면 마지막 검증 지점에서 Actor를 임의 골목으로 보내지 않는다.
3. 나머지 구간은 선택 카드와 상태 표식에서 `이동 중`·마지막 확인시각·다음 판독 지점을 보여준다.
4. 새 상태 사본에서 검증된 도착이 확인되면 도착 건물 기준점에서 표현을 재개한다.
5. 상대 경로 후보, 직선 보간, 건물 사이 빈 공간 이동은 실제 주행·보행 경로로 설명하지 않는다.
6. 건물이나 이동 자료가 보강되면 같은 안정 식별자를 유지한 채 상태 표현 구간을 실제 검증 경로로 점진 교체한다.

## 5. 기존 자료에 대한 적용 경계

- 기존 면목제3·8동의 건물 250개·도로 선분 722개·타일 3개는 역사 경계와 사가정 기준 건물 602개에서 만든 좁은 후보이므로 전수 현행 건물 기준선으로 승격하지 않는다.
- 사가정 1km 화면 건물 4,062개와 면목제3·8동 전수 건물 집합은 같은 범위가 아니다. 현행 경계를 먼저 결속한 뒤 교차 결과를 새 판본으로 만든다.
- 기존 절차적 건물은 새 판본이 검증될 때까지 화면 회귀 기준으로 유지한다. 불완전한 새 집합으로 일괄 교체하지 않는다.
- 실제 필지 도형·출입구·현행 통행망 결손은 건물 Mesh의 시각적 완성도로 숨기지 않는다.

## 6. 완료 조건

- 현행 면목제3·8동 경계 안 대상 건물 총수와 상태별 수량이 재현된다.
- 모든 대상이 `RenderableBuilding`, `RenderableWithGeneralizedAnchor`, `MissingCoverage` 중 하나이며 누락·중복이 없다.
- 같은 입력으로 건물 투영 hash와 결손 목록이 같다.
- 현재 사가정 디오라마와 새 건물 판본의 차이를 전체·부분 화면에서 비교한다.
- 이동은 검증된 건물·기준점·연결 구간만 사용하고 나머지는 `이동 중`으로 보인다.
- Unity가 건물 귀속·출입구·주문 완료를 독자적으로 확정하지 않는다.
