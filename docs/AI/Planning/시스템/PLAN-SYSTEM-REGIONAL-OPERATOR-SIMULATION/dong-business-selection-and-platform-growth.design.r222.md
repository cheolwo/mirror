## 2. 플레이어가 반복해서 이해할 흐름

**동은 사업을 펼칠 지역, 사업 선택은 할 일의 종류, 점포·지사는 실제 관리 대상이다.**

```text
면목3·8동 진입 → 왼쪽 「이 동의 사업」
  ├─ 운영 중/준비 중 사업 → 해당 사업 현황 → 내 점포·지사·담당자
  └─ 새 사업 검토 → 음식점·카페 / 음식배달 / 퀵서비스 / 다른 사업
                    → 준비·비용/부담 비교 → 필요한 자리·파트너 선택
                    → 계획 확정 → 개업 준비 → 첫 한 건
                    → 결과·막힘 확인 → 개선 하나 → 다음 운영 회차
```

사업을 골랐다는 이유로 즉시 영업/돈·고객·사람을 지급하지 않는다. 확인한 준비 결과에 따라 계획/개업을 구별한다. 직접 작업·집중 미니게임과 관찰·위임은 같은 업무의 참여 방식이며, 사업 카드로 둘 중 하나를 강제하지 않는다.

- 지금: 한 동에 처음 진입했거나 기존 사업을 운영하며 다음 일을 고르는 때.
- 여기: 한 행정동 지도와 그 동 이름이 붙은 왼쪽 사업 창. 예시 동은 면목제3·8동이며 동의 고유 식별자에 결속한다.
- 나: 자본·시간·운영 여력이 제한된 플레이어 사업 운영자. 사업 종류와 직접 일할 역할은 별도로 고른다.
- 너: 필요한 서비스를 가진 고객, 준비된 가상 점포/파트너·기사·공간과 실제 확인된 준비 상태.
- 이렇게: 사업을 비교하고 작은 시작 구성을 검토해 확정한다. 첫 일을 수행/위임하고 결과를 보고 운영을 조정한다.
- 대가: 준비 자금·지속 비용·운영 책임, 다른 투자를 미루는 기회비용. 대기를 줄이지 못하면 확장을 보류하거나 구성을 줄인다.
- 결과/귀환: 등록된 계획 또는 유효 업무 결과를 같은 동/사업에서 확인하고 다음 선택으로 돌아온다. 창을 닫거나 동을 이동한 것만으로 하루/결산을 넘기지 않는다.
- 상위 목적 정렬: 고객의 실제 필요와 현장 사람의 작업 부담을 읽는 보조 경영 층. 화면 조회·사업 추가 횟수만으로 명덕·경 시간·만족/수익을 지급하지 않는다.

## 3. 왼쪽 창의 책임 — 제안

왼쪽 주 창은 한 번에 하나를 사용한다. 동 사업, 사업 현황, 개별 점포/지사 사이를 같은 자리에서 오가며 지도는 남긴다. 현재 어두운 패널·민트 강조·금색 비용·아이콘 언어를 이어 쓰고, 상세 크기/그림 중심 기본 여부는 시안에서 검토한다.

| 자리 | 보여 줄 것 | 행동 |
| --- | --- | --- |
| 고정 머리 | `면목제3·8동 · 사업` · 현재 자금의 소유 범위 · 닫기 | 지역 확인/복귀 |
| 운영 중/준비 중 | 내가 이 동에서 관리하는 사업·대상과 당장 필요한 일 | 기존 사업/대상의 현황 열기 |
| 새 사업 | 음식점·카페 / 음식배달 운영 / 퀵서비스 운영 | 한 사업 상세 비교 |
| 다른 사업 | 광고·전자상거래·무역 등 기존 자유 출발 | 분야에 맞는 작은 시작/연결 화면 검토 |
| 선택 사업 상세 | 하는 일·첫 한 건·필요 준비·지속 비용/부담·다음 확장 | 준비 계획 보기 → 명시적 확정 |

초기 사업이 없으면 새 사업 비교를 먼저 펼치는 안이다. 기존 사업이 있으면 운영 중/준비 중 목록과 `새 사업 검토`를 함께 보여 주고, 동을 재방문할 때마다 처음부터 창업하게 하지 않는다. 다섯 출발 중 다른 분야를 택한 사람에게 음식배달 완주를 선행 요구하지 않는다.

`운영 중`, `준비 중`, `검토 가능`, `게임 조건 부족`, `기능 준비 중`, `자료/상태 확인 실패`는 다르다. 미연결 기능을 연구나 자금만 모으면 풀리는 게임 잠금으로 표시하지 않는다. 목록을 읽지 못한 상태를 ‘사업 없음’으로 확정하지 않는다.

**기존 진입과의 연결**

- 동 선택 후 사업 진입으로 같은 왼쪽 홈을 연다. 자동 펼침의 정확 시점/재방문 기억은 시안에서 정한다. 단순 지도 드래그·확대 중 계속 창을 다시 열지 않는다.
- 하단 `기사 운영` 등은 같은 동 사업 현황의 빠른 진입으로 유지한다. 창업 사업 종류와 현장 업무 버튼의 분류가 다를 수 있으므로 모든 탭을 억지로 일대일 치환하지 않는다. 음식배달·퀵의 메뉴 배치/명칭은 후속이다.
- 내 카페 클릭/F3~F6는 그 점포 운영으로, `← 이 동의 사업`은 동 홈으로 연결한다. 점포 제조/발주를 동 선택 홈에도 복제하지 않는다.
- F2는 현재 동 관리 진입 의미를 유지한다. 새 창업·개업 확정을 단축키에 부여하지 않는다. Esc/Enter의 기존 의미도 유지한다.
- 지도에서 건물/공간을 고르는 것은 해당 사업의 위치 선택을 시작한 동안만 해석한다. 사무실이 필요하지 않은 시작 모델에 건물 클릭을 필수로 넣지 않는다.

## 4. 서로 다른 세 사업과 성장 갈래 — 제안

| 사업 | 처음 집중할 한 일 | 그다음 운영 개선 | 확장 후보 |
| --- | --- | --- | --- |
| 음식점·카페 | 한 점포에서 음식/음료 한 주문 제조·판매/인계 | 재고·제조 자리·직원·시간 병목 개선 | 추가 점포 → 선택적으로 본부/가맹망·판매 채널 |
| 음식배달 운영 | 제휴 매장의 준비된 음식 한 주문을 픽업·전달 | 기사 가용·제조 시각·배차/약속·인계 개선 | 작은 운영팀/지사 → 복수 담당 권역·지사망 → 선택적으로 주문/수행 연결 플랫폼 |
| 퀵서비스 운영 | 소화물/서류 등 한 의뢰의 물품·장소·시간 조건을 확인하고 인수·전달 | 적합한 기사/차량·작업 시간·인수 증빙·예외 대응 | 거점/담당 권역 → 여러 수행처 조율 → 선택적으로 의뢰/수행 연결 플랫폼 |

위 표는 게임 경로의 뼈대다. 업종 등록/허가의 실제 법정 분류·비용·자격·기간을 확정한 자료가 아니다. 향후 현실 절차를 연결할 때 해당 모델의 공식 근거와 별도 관문을 대조한다.

음식점은 제조·판매 주체, 음식배달/퀵은 의뢰 수행·운송 조율 주체다. 음식배달 운영을 시작하기 위해 음식점을 소유할 필요는 없고, 음식점도 자기 배달 지사 소유 없이 준비된 가상 수행처를 사용할 수 있다. 퀵 시작에 창고·센터·전국망부터 소유하게 하지 않는다.

음식배달과 퀵은 배차/시간·인계 도구를 재사용할 수 있지만, 상품 조건·제조 준비·시간창·운송 책임·예외·정산 계약은 사업별로 구분한다. 퀵 의뢰를 음식 주문의 메뉴만 바꾼 기록으로 만들지 않는다. 첫 일은 각 분야의 준비된 파트너/업무로 완결할 수 있게 하고 다른 분야의 선행 완주를 요구하지 않는다.

`지사`는 사업체/본부 아래 지역 운영 단위의 이름 후보다. 새 독립 사업을 골랐다고 존재하지 않는 상위 본부를 생성하지 않는다. **기존 가상 플랫폼 아래 지역 지사를 운영하는 시작**과 **독립 소규모 배달사를 시작하는 방식**은 시작 모델 선택으로 구별할 후보이며 정확 관계/브랜드·계약은 미정이다.

성장은 `처리 여력 → 실제 서비스 개선 → 지속 비용을 감당할 기반 → 확장 검토`로 읽는다. 직원/지사 수만 늘려 연구·플랫폼 자격을 자동 지급하지 않는다. 작은 사업을 오래 잘 운영하는 것도 유효한 플레이이고 플랫폼이 모든 분야의 유일한 종착점은 아니다.

## 5. 플랫폼은 선택적으로 추가하는 사업

플랫폼 성장 방향은 ‘큰 지사 건물로 교체’보다 **독립된 고객/매장과 여러 수행 주체를 연결하고 공통 약속을 운영하는 기능의 추가**로 제안한다.

```text
음식배달 운영 ── 자기 운영팀/지사망의 개선 ──┐
                                            ├─ 선택적 플랫폼 진출 검토
퀵서비스 운영 ── 자기 거점/수행처 조율 ──────┘
           기존 사업을 유지하면서 연결·지원 업무를 추가
```

음식배달 다음에 퀵을 반드시 마쳐야 하는 순서는 아니다. 자기 지사망을 키우는 경로와 준비된 가상 외부 수행처를 연결하는 경로는 별도 후보다. 같은 사업체가 두 역할을 함께 맡으면 자기 수행과 외부 수행의 비용/실적·예외 책임을 구분한다.

| 진출 검토 항목 | 게임에서 새로 맡는 책임 후보 | 아직 정하지 않은 것 |
| --- | --- | --- |
| 참여자/대상 | 독립 매장·고객·지사/수행처의 참여 상태와 제공 범위 | 최소 수·입점/참여 조건 |
| 요청 연결 | 주문/의뢰 접수와 적합한 수행 후보·추천 이유/정책 | 분야별 접수/배차 모델·권한/위임 경계 |
| 약속·품질 | 준비/도착 약속, 지연·취소/분쟁과 회복 담당 | 목표 수준·측정 기간·실패 조건 |
| 비용·지급 | 수수료/비용·보수·지원 부담을 게임 원장으로 추적 | 과금·보상·예산/보증 조건 |
| 운영 도구 | 엔진 연구·모니터링·파트너 지원 | 선행 연구·개설/유지 비용·기간 |

엔진 투자만으로 고객/수행처·플랫폼이 자동 생기지 않고, 참여자가 많아도 이익을 보장하지 않는다. 수요를 점포/지사/플랫폼마다 복제하지 않으며 같은 업무의 인계와 비용을 식별해 중복 매출·성과·명덕을 막는 계약은 후속으로 결속한다. 추천 엔진이 진출이나 계약을 스스로 확정하지 않는다.

실제 앱의 플랫폼/API·실거래·결제·계정 연동을 여는 기능은 이 경로에 포함하지 않는다. 광고/홍달 플레이스 기능도 이번에 자동 활성화하지 않는다. 기존 광고 출발·정식 광고 후 중개업자 소개 순서는 각각의 기획을 유지한다.

## 6. 한 동 집중과 큰 지도의 쓰임

| 관점 | 이 사업 선택과 이어질 결정 후보 | 유지할 것 |
| --- | --- | --- |
| 동 | 내 매장·담당 기사/지사·첫 일·현재 병목 | 한 동 집중, 대상/업무의 개별 결과 |
| 구 지도 안의 서울 연속 보기 | 다른 동의 수요·여력·거점/담당 범위 비교 | 별도 서울 경영 단계 부활 없음 |
| 전국 | 장거리 수행·연결 거점·권역 간 운영 방침이 실제 필요한 때 | 준비된 업무의 관점 이동과 사업 권한을 구분 |

플랫폼이라는 이름만으로 전국 지도를 필수 선행 조건으로 삼지 않는다. 동네 규모 플랫폼/특정 분야의 연결 업무도 가능한 후보로 남긴다. 정확 해금·담당 범위는 별도 후속 선택이다.

기사가 다른 동으로 이동해도 사업 소속이나 운송 업무를 지도 경계에서 끊지 않는다. 사업의 소재 동·담당 지역·현재 위치·주문의 픽업/전달 동을 구별한다. [r207](cross-dong-delivery-and-recipient-mingde.design.r207.md)/[r208](pickup-preparation-and-local-mingde.design.r208.md)의 지역 기여 규칙은 별도 유지하며 이번에 새 배분 수치를 만들지 않는다.

## 7. 초안·확정·실패·귀환

| 상황 | 제안 동작 |
| --- | --- |
| 사업 카드/확장 노드 선택 | 설명/준비 상태만 조회. 자금 차감·업무 시작 없음 |
| 준비 비교 | 가용 자원·일회/지속 부담·파트너/공간과 부족 조건을 표시. 모르는 비용을0으로 대체하지 않음 |
| 계획 확정 | 선택 동·사업 유형/시작 모델·대상/준비 조건의 같은 판본을 검토. 현재 게임 권위에서 확정 후 결과 재조회 |
| 자리 선택/검토 취소 | 미확정 후보 강조만 종료. 기존 사업/진행 업무 취소 없음 |
| 동/사업 이동 | 옛 초안을 원래 동/사업에 묶어 보존하고 명시적으로 돌아가 재개. 새 동에 몰래 개설하지 않음 |
| 준비 중 계획 | 남은 단계/담당·시간을 읽고 준비를 진행. 버튼 클릭만으로 영업 완료가 되지 않음 |
| 자금/공간/파트너 부족 | 사유와 가능한 보완·규모 축소·보류를 제공. 연구 하나로 모든 결손을 감추지 않음 |
| 요청 중복/응답 불명확 | 같은 요청 결과 확인. 중복 사업체/차감/인력/지원 지급 방지 |
| 작은 일 실패 | 현재 업무·부담·회복 선택을 확인하고 같은 사업으로 귀환. 회사 전체를 자동 폐업/초기화하지 않음 |
| 한 분야 유지 | 다른 업종/플랫폼을 선택하지 않아도 반복 운영·연구와 일일 결산 가능 |

현재 동별 기사/제휴 집계, 실제 기사/점포 명부, 사업체/지사 식별자, 사용자 자금의 귀속과 첫 작업의 생성/지원은 서로 다른 계약이다. 새 사업체 명부가 없는 단계에서 집계 수를 실재 회사·직원으로 꾸미지 않는다. 기존 플랫폼 시나리오/세이브는 별도 호환 경계로 남기고 미선택 사업을 기존 권한에서 삭제하지 않는다.

## 8. Claude가 나눠 검토할 제작 범위 — 제안

1. **한 동의 사업 홈 시안:** 같은 실제 동 화면에서 현재 고용/건설 중심 창을 사업 비교 중심으로 재구성. 운영 중 사업 있음/없음과 한 사업 상세·복귀를 비교한다. 새 회사/잔액/지사/매출은 가상 예시로 구분한다.
2. **기존 진입 연결:** 동 홈·하단 사업·현재 점포 창·F2/F3~F6가 같은 선택 동/대상을 유지하는지 확인. 조회만으로 시간/원장 변화가 없는지와 UI 클릭 관통을 검토한다.
3. **사업 하나의 첫 완결 작업:** 선택한 시작 모델의 준비→확정→한 일→실패/회복→결과/귀환을 정밀화. 명부/자금·지원·업무 생성은 승인된 별도 계약/작업 명세와 결속한다.
4. **다른 분야/확장:** 첫 경로의 성공을 다른 사업의 완료로 대체하지 않고 독립 작은 시작을 준비. 플랫폼은 별도 경영 책임/비용·참여자 계약을 갖춘 후 검토한다.

이 순서는 기획 검토 순서이며 실제 개발 대기열/Goal 활성화가 아니다. 기존 Claude 구현 범위를 이 문서로 중단하거나 겹치는 제품 파일을 수정하지 않는다. 시안 승인·기획 revision/hash·정확 수정 경로·검증 상한과 수용을 후속으로 결속한다.

## 9. 확정·미정·다음 질문 하나

**확정:** 동에 들어와 왼쪽에서 사업을 선택하는 방향, 음식점·음식배달/지사·퀵서비스와 이후 플랫폼으로 성장할 수 있는 경로를 마련한다. 기존 자유 출발·한 동 집중·점포 운영/직접·관찰 방식은 유지한다.

**미정:** 초기 자동 펼침·운영 중/새 사업 배치·시안, 시작 모델(독립/기존 가상 본부 지사), 첫 업무/파트너·인력과 자본 지원, 비용/기간·연구/규모 조건, 플랫폼 참여/정산·회사/지사 명부와 저장/호환, 개발 수용/실제 입력 검증.

**다음 질문 하나:** 음식배달을 처음 고르면, 고정 사무실 마련은 뒤로 두고 **준비된 제휴 매장 한 곳·기사 한 명으로 주문 한 건을 운영해 보는 작은 시작**을 기본 후보로 잡을까요? 작은 일→결과→개선 반복을 먼저 익히기 쉽고, 사무실/지사망의 공간·투자 경험은 뒤로 미루는 대가가 있다. 이 구성은 제안이며 인력/자금의 무상 지급 승인으로 해석하지 않는다.
