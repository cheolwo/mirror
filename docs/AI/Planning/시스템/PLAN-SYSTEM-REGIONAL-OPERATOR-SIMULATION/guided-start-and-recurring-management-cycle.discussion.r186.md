## 1. 확정 — 첫 안내는 게임 전체의 기본 동작을 가르친다

지금 플레이어는 시작 분야의 첫 작업 앞에 있다. 나는 이 분야를 익히는 운영자/참여자이고, 상대는 한 건의 필요를 가진 고객/파트너와 현재 작업 상황이다. 안내를 따라 필요한 선택을 하고 수행/관찰한 뒤 결과와 다음 선택으로 돌아온다.

첫 안내를 한 번의 미니게임 조작 설명에만 한정하지 않는다. 이후 경영에서도 ‘지금 무엇을 확인하고, 무엇을 고르고, 어떻게 결과를 보고 다음 운영으로 가는지’ 같은 반복을 사용한다. 처음에는 한 건으로 배우고 다루는 정보/대상이 점차 늘어나는 방향이다.

확장되는 것은 판단의 범위와 조합이다. 모든 분야를 순서대로 완주하거나 같은 작업을 정해진 횟수 채우는 강제 사슬로 확정하지 않는다. 직접 수행·관찰/위임 어느 방식도 이 기본 흐름에 들어온다.

## 2. 공통 반복의 제안

**상황 확인 → 계획·선택 → 실행·관찰 → 이번 결과 정리 → 다음 운영 준비**를 공통 흐름으로 제안한다. 사용자가 의식적으로 한 바퀴를 마치는 조작을 두되 정확한 버튼명·경계 효과는 미정이다.

| 반복에서 하는 일 | 첫 안내의 한 건 | 경영 범위가 넓어진 뒤의 예시 |
| --- | --- | --- |
| 상황 확인 | 해야 할 일·상대·끝나는 조건 하나를 읽음 | 여러 일의 우선순위·자금/재고/인력과 문제를 읽음 |
| 계획·선택 | 준비된 사람/방법 등 필요한 선택 하나 | 담당/자원 배분·방침·연구/도입 계획 |
| 실행·관찰 | 직접 수행하거나 맡기고 진행 확인 | 작업 묶음을 수행/위임하고 예외에 대응 |
| 이번 결과 정리 | 한 건의 결과·보수/비용·시간과 개선점 확인 | 계획 대비 결과·지연/품절·남은 일과 운영 부담 비교 |
| 다음 운영 준비 | 마치는 조작 후 같은 일/작은 개선 선택으로 복귀 | 기존 운영 유지·조정·선택적 확장 준비 |

이 표의 후반 기능이 현재 실행판에 모두 구현됐다는 뜻은 아니다. 첫 안내의 분야별 정확한 작업·상대·시작 자원과 안내 표현은 별도로 구체화한다.

배달 예시라면 ‘주문 확인 → 담당/방법 선택 → 픽업·전달 수행/관찰 → 결과 확인 → 다음 운영 준비’다. 배달을 모든 플레이어의 필수 시작으로 삼는 예시는 아니다. 카페·광고·전자상거래·무역은 자신의 작은 업무 단위로 같은 구조를 배운다.

처음에는 한 바퀴에 한 건을 두고, 이후에는 여러 건을 묶어 다룰 수 있게 하는 안이다. 같은 직무만 몰아서 하는 선택과 다음 작업 버튼을 유지한다. 숙련 이후에도 매 작업 한 건마다 전체 운영 마감을 강제로 누르게 하지 않는다.

## 3. 서로 다른 마무리의 의미

| 조작/경계 | 맡을 의미 | 자동으로 실행하지 않을 것 |
| --- | --- | --- |
| 작업 완료·다음 작업 | 현재 직무의 한 건을 처리하고 대기열의 다음 일로 연결 | 전체 운영 회차/하루 종료 |
| 결정 순회 | 필요한 경영 판단을 찾아 검토/결정 | 실제 배송·제조·공사 완료 |
| 운영 회차 마무리(가칭) | 이번 계획/결과/남은 일을 정리하고 다음 준비를 여는 공통 진행 경계 후보 | 진행 업무 자동 완료/취소·중복 지급·무조건 다음 날짜 생성 |
| 일일 결산 | r174의 현실 날짜별 활동/금액 누적 보고 | 회차마다 하루를 새로 만들거나 보고 확인으로 시간 추가 진행 |

사용자가 말한 마감의 반복 감각은 위 ‘운영 회차 마무리’에 연결하는 안이다. 단순 조회 버튼만 늘리는 것이 아니라, 한 바퀴의 목표/선택/결과를 닫고 다음 운영의 계획으로 돌아왔다는 진행을 읽게 한다. 안내 중에는 현재 국면과 다음 조작을 분명히 알려 준다.

첫 작업을 마쳤거나 결과를 확인했다는 이유로 연구/돈/만족도·새 사업/지도 해금을 추가 지급하지 않는다. 실제 업무/성장 기록의 조건을 확인하고 원래 지급을 중복 실행하지 않는다.

진행 배송/장기 운송은 마감 클릭으로 사라지지 않는다. 안전한 중단/위임·계속 진행·명시된 이월 등 구체 회복/인계 규칙을 정해야 하며, 장기 업무 하나가 모든 운영 반복을 영원히 막는 구조도 자동 채택하지 않는다.

## 4. 시간과 현재 구현의 연결

r174는 현실 KST 날짜와 같은 날 누적·일일 결산을 구분한다. 이에 맞추면 **하나의 현실 날짜 안에서 운영 회차를 여러 번 반복**할 수 있고 하루 결산은 별도로 유지할 수 있다. 첫 안내를 완료하자마자 다음 현실 날짜가 올 때까지 기다리게 할 필요도 없다. 이는 아래 다음 질문의 추천안이며 아직 회차 단위를 확정한 것은 아니다.

사용자가 ‘마감 때 가상 영업일 한 날을 넘긴다’는 설계를 원하면 현실 달력/일일일생과 가상 영업일의 관계를 후속 판본에서 명시적으로 다시 정한다. 이번 비유만으로 기존 시간 계약을 조용히 대체하지 않는다.

[Claude 결정 순회 반환](../../../Handoffs/2026-11-13-Claude-결정순회뼈대-반환.md)의 계획→영업→결산→다음 턴은 실제 시계/현실 날짜와의 연결을 미완료로 기록했다. 이를 이번 공통 반복이나 r174의 구현 완료로 보고하지 않는다.

## 5. 다음 질문 하나 — 반복 한 바퀴의 단위

상태: `Asked`.

**질문:** 이 반복을 **같은 날에도 여러 번 돌릴 수 있는 짧은 ‘운영 회차’**로 잡을까?

- 추천: 짧은 운영 회차. 처음엔 한 건, 이후엔 준비된 작업 묶음을 대상으로 삼고, 마치는 조작으로 다음 운영 계획을 연다. 현실 날짜별 일일 결산은 별도로 누적한다.
- 이유: 첫 안내에서 게임 전체의 반복을 바로 경험하고 같은 날 여러 번 선택/개선할 수 있다. 다섯 분야의 서로 다른 작업 길이에도 적용하기 쉽다.
- 대가: 운영 회차 마무리와 하루 결산의 용어/표시를 구분해야 한다. 버튼명·진행/이월/중단·저장/재진입 규칙을 후속 설계해야 한다.
- 대안: 마감 때 가상 영업일 한 날이 넘어가는 진행. 이 경우 현실 날짜/공공자료 기준시각과 가상 영업일의 관계를 먼저 정한다.
