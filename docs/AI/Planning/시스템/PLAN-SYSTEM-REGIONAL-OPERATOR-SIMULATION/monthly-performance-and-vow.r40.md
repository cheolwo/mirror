# [기획 · 운영·회계 Simulation · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · 월간 실적·서원 r40]

- 상태: `Draft / PreviousMonthComparisonOnly / MonthlyVowConfirmed / AccountingPlanBoundaryConfirmed / NonBindingReflectionConfirmed`
- 상위 기획: `README.md` r40
- 선행 기획: `weekly-settlement-summary.r39.md`
- 목적: 월간 결산의 객관적인 비교와 운영자가 월초에 세우는 게임적 방향인 `서원`을 분리한다.

## 1. 월간 결산 비교

월간 운영 결산의 기본 수치 비교는 `이번 달 실적 ↔ 전월 실적`만 사용한다.

- 월초 계획 대비 달성률은 기본 회계 비교에 넣지 않는다.
- 전월 대비 현금 변화, 정산 총액, 지급의무, 예외 발생·해결, 서비스 수준을 같은 기준으로 비교한다.
- 계절성이나 영업일 수가 달라 단순 비교가 왜곡되면 차이를 숨기지 않고 보조 설명을 붙인다.
- 전월 자료가 없는 첫 달은 비교 없음으로 표시하고 임의 기준값을 만들지 않는다.

## 2. 월초 서원

`월초 서원`은 운영자가 “이번 달에는 이 방향을 지켜 보겠다”고 스스로 세우는 비구속 운영 약속이다.

예시:

- 기사 현장 대기를 조금이라도 줄이겠다.
- 정산 확인 필요 사건을 오래 방치하지 않겠다.
- 음식점 조리 지연의 반복 원인을 살펴보겠다.
- 가용현금 방어선을 무리하게 낮추지 않겠다.
- 전통시장·지역 사업자의 정상 주문 흐름을 안정적으로 관찰하겠다.

서원은 회계 예산, 외부 계약, 직원 성과평가, 기사 배차 우선순위, 자동 보상·불이익 근거가 아니다. 서원 자체가 돈이나 업무 상태를 바꾸지 않으며, 실제 정책 변경은 별도의 Preview·확정 절차를 거친다.

## 3. 월말 회고

월말에는 전월 실적 비교와 서원 회고를 같은 운영자 통합 화면에서 서로 다른 영역으로 보여준다.

| 영역 | 질문 | 판정 |
| --- | --- | --- |
| 월간 실적 | 전월보다 무엇이 얼마나 달라졌는가 | 서버 원장 수치와 출처로 계산 |
| 서원 회고 | 이번 달에 세운 방향을 얼마나 지켰는가 | `지킴 / 일부 지킴 / 이어서 살핌` |

`실패`나 벌점 중심으로 표현하지 않는다. 서원과 관련된 실제 지표·사건을 근거로 보여주되, 숫자 하나가 서원의 의미 전체를 자동 판정하지 않는다. 운영자는 회고를 확인하고 다음 달 서원을 새로 선택하거나 쉬어 갈 수 있다.

## 4. 데이터 경계

- 내부 Stable ID 후보: `MonthlyOperatingVow`
- 필수 항목: 권역, 대상 월, 서원 종류, 운영자 표시 문구, 관련 관측 지표, 선택시각, 판본, 월말 회고 상태
- 서원 원장은 재무 원장과 분리하고 월간 결산 판본에서 참조만 한다.
- Unity는 서원 카드와 관련 생활상 변화를 읽기 전용으로 표현할 수 있지만 서원을 근거로 운영 사실을 확정하지 않는다.
- 아르카나·주역 카드와 결합할 수 있으나, 그 결합도 Simulation 효과 판본을 거쳐야 하며 회계 실적을 임의 보정하지 않는다.

## 5. 완료 조건

- 월간 기본 수치 비교에 월초 계획 달성률이 포함되지 않는다.
- 전월 실적과 월초 서원을 같은 숫자로 혼합하지 않는다.
- 서원을 선택하지 않아도 정상 운영·정산·결산이 가능하다.
- 서원 회고가 기사·음식점·주문자에게 자동 불이익을 만들지 않는다.
- 서원과 관련된 정책을 적용하면 실제 효과는 해당 정책 revision과 Simulation 결과에서 추적한다.

## 6. r41에서 폐쇄된 질문

운영자가 별도 서원을 고르지 않으면 `안정 운영 유지`를 기본 서원으로 둔다. 이 서원은 승인된 기본 운영정책 판본을 참조하지만 서원 자체가 정책을 발동하지 않는다. 상세 기준은 `stable-operations-vow-policy.r41.md`가 소유한다.
