## 1. 현장마다 다른 손맛을 준다

**동네에서는 목적지까지 이동하는 재미를, 센터에서는 정확한 물건을 찾아 다음 작업으로 넘기는 재미를 만든다.** 같은 게임·상태·공통 시계 안에서 서로 다른 공간과 조작을 사용하는 제안이다.

| 현장 | 공간의 중심 | 집중에서 할 일 | 결과를 확인할 곳 |
| --- | --- | --- | --- |
| 동네 배달 맵 | 도로·교차로·매장 앞·배송지·오토바이 | 매장 이동→포장완료 주문 픽업→가방 적재→주행→전달 | 같은 주문의 인수/전달·수령/정산 기록 |
| 센터 작업 맵 | 입고 구역·검수대·선반·통로·포장대·컨베이어·도크 | 검수·적치·피킹·포장·분류/출고 중 준비된 직무 | 해당 작업의 물품 위치·수량·포장물/인계 결과 |

배달의 **픽업은 준비된 주문을 인수하는 동작**, 센터의 **피킹은 선반에서 지시된 상품을 집품하는 동작**으로 구별한다. 센터에서는 상품 바코드·선반 위치·수량과 집품 용기가 중요하고, 동네에서는 이동 경로·정차·가방과 전달 대상이 중요하다.

지도를 둘로 구분해도 새로운 OS·저장 세계를 만들지 않는다. 카페 역시 준비된 건물 내부 작업 현장으로 같은 진입/귀환 구조를 재사용할 수 있다. 각 현장의 규칙은 해당 업무 전문이 소유한다.

## 2. 센터 전체와 작업할 한 층을 구별한다

센터 건물 선택 → **다층 전체 모형**으로 흐름 확인 → **작업이 있는 한 층**을 고름 → 준비된 작업 선택 → 해당 작업 구역에서 수행 → 같은 현장/경영으로 복귀하는 흐름을 추천한다. 대기열에서 준비된 작업을 바로 고르면 대상 층/작업 구역을 보여줄 수 있지만, 카메라 이동만으로 작업자·상품을 순간이동시키거나 작업을 자동 완료하지 않는다.

- 다층 전체: 랙·포장·층간 이송·1층 분류/차량의 연결과 병목을 관찰한다. 기존 r164를 유지한다.
- 한 층 상세: 위층을 숨기고 통로와 작업대를 크게 보여 작업 위치·상호작용 대상이 읽히게 한다. 작업자가 걸을 수 있는 구역과 설비의 물건 이동 구역을 구별한다.
- 작업대 상세: 스캔·수량 확인·포장 같은 짧은 조작만 같은 현장 위 상세 패널로 연다. 개별 미니게임마다 별도 창고/Scene을 만들지 않는다.

Claude 시안 D의 1층 라인이 2층에 가려지는 문제는 **전체에서는 연결, 선택 층에서는 작업 판독**을 맡기는 방식으로 보완한다. 첫 시각 검토는 5층 전체를 더 복잡하게 만들기보다 한 층의 작업 공간을 읽히게 하는 데 집중한다.

## 3. 한 층의 공간 연결안

첫 맵 시안은 **가상 소형 FC 작업 층**으로 제안한다. 위치를 익히기 쉬운 한 바퀴 흐름으로 두고, 입고 쪽과 출고 쪽을 이름/표식으로 구별한다. 실제 업체 도면·안전 설비·처리능력을 재현한 배치는 아니다.

```text
입고 도크 → 검수·입고 대기 → 적치·보관 선반
                 ↘ 보류/격리          ↓
                                  피킹 통로·집품 용기
                                         ↓
출고 도크 ← 출고 대기·분류 출구 ← 포장·라벨 작업대
```

이것은 공간 연결의 예시다. 보류품은 정상 선반으로 자동 편입하지 않고, 준비된 재확인/해제 절차를 거친 뒤 허용된 경로로 돌아간다. 상하차 대기·작업자 통로·벨트 투입부도 서로 구별한다.

| 구역 | 플레이어의 행동 제안 | 확인할 직접 결과·실패 회복 |
| --- | --- | --- |
| 입고·검수 | 도착 물품과 입고 지시 확인, 대상 스캔·수량/상태 대조 | 인수/검수 결과. 다른 물품·부족·파손 의심은 사유와 보류로 남김 |
| 적치·보관 | 허용된 선반 위치를 확인하고 물품을 옮김 | 검수 결과·가용/격리 상태에 맞는 위치 인계. 빈자리 클릭만으로 재고 생성 안 함 |
| 피킹 | 지시 품목·로트/단위·잔량을 보고 맞는 선반에서 용기에 담음 | 정확한 집품과 잔량. 다른 품목/과다 집품은 확인·되돌리기 경로 제공 |
| 포장·라벨 | 집품 내용 재확인→포장재/완충→밀봉→라벨 확인 | 포장완료 물류단위와 내용물 연결. 내용 불일치는 수정 후 재확인 |
| 분류·출고 대기 | 포장물을 투입해 목적 출구/버퍼를 확인 | 정상 A/B 출구 도착 또는 명시적 보류. 차량 상차와 구별 |
| 출고 도크·상차 | 허용된 대상 차량/묶음과 물건을 대조해 인계 | 실제 게임의 차량 인수/적재 결과. 잘못된 차량은 미인수로 유지 |

입고는 도착·하차·검수/인수·재고 반영·가용화·적치의 경계를 작업별로 정해야 한다. 인수·격리·거절 수량을 구분하고 검수 대기/격리품을 피킹 가능한 재고로 세지 않는다. 적치 때 이미 반영된 수량을 또 더하거나, 피킹한 물건을 창고와 용기 양쪽의 독립 재고로 세지 않는다. 품목/SKU·로트·수량 단위와 개별 소포·케이지·작업 ID를 구분하며 포장재 소모도 보존한다. 정확 예약/재고 차감·소유 이전 시점은 기존 Core와 후속 명세로 결속한다.

모든 소포가 이 전체 흐름을 거칠 필요는 없다. **FC는 상품 보관/피킹/포장**, **택배허브는 이미 포장된 소포 하차/분류/상차**를 중심으로 작업 구역을 고른다. 외부 포장소포는 1층 입고 버퍼에서 분류로 합류하며 무조건 개봉·피킹·재포장하지 않는다. 다층에서는 해당 층의 포장물이 r164의 이송 구간으로 이어지되 상품 보충/집품물 이송과 포장물 하향 벨트를 혼동하지 않는다.

## 4. 한 공간에서 직무를 골라 수행한다

작업 대기열에는 입고·피킹·포장·분류·상차 중 **실제로 준비된 작업**만 활성화한다. 오늘 포장만 하고 싶으면 포장 직무를 고르고, 피킹만 하고 싶으면 같은 현장의 피킹을 연속 수행한다. 입고부터 상차까지 전부 직접 해야 한 건이 끝나는 강제 코스로 만들지 않는다. 다른 준비 업무는 기존 허용 방침과 자동 주체가 이어간다.

집중의 첫 조작안은 r147을 재사용한다. **방향키로 작업자/집품 용기를 이동하고, 정차한 유효 대상에서 Space로 상호작용**한다. 포장대의 선택/배치는 마우스를 사용할 수 있다. 스캔 상세를 연 동안은 해당 입력만 받고 Space 한 번이 이동·집품·스캔·포장 확정을 동시에 실행하지 않게 한다. 입력 방식의 최종 채택은 시안/작업 명세 검토 전이다.

r148의 상하 빨간 레이저·중앙 Space는 사람의 확인 미니게임으로 재사용한다. 타이밍 성공 후에도 작업·물품·위치·수량 검증을 통과해야 다음 단계로 간다. 이를 컨베이어 자동 센서에 매번 요구하지 않고, 스캔 횟수만으로 별도 중복 보상을 주지 않는다.

## 5. 혼합 턴 안에서의 위치와 복귀

- **계획:** 오늘 준비된 물량·인력·공간과 막힌 곳을 보고, 수행할 직무/운영 방침을 고른다.
- **실행·관찰:** 같은 센터 맵에서 이완으로 흐름을 보거나 준비된 한 작업을 집중 수행한다. 층·작업대 보기로 공통 시계와 다른 업무가 따로 멈추지 않는다.
- **결산:** 처리/대기/오류/회복·비용/수익·남은 일을 해당 작업 결과로 집계한다. 단순 이동·스캔·포장 애니메이션을 완료로 세지 않는다.

한 작업을 마치면 같은 직무의 `다음 작업` 한 건 또는 경영 복귀를 선택한다. 작업 완료·맵 진입/귀환이 새 턴이나 스테이지를 자동 생성하지 않는다. 직접 완료 보너스는 r147의 자격/상위 정산 규칙을 따르며 수치는 새로 정하지 않는다.

이완 전환/복귀는 작업·위치·용기 내용·남은 지시량·로트/예약·포장 진행·설비 점유를 안전한 확정 경계에서 자동 주체에게 넘긴다. 전체 공정을 끝내야 나갈 수 있게 잠그지 않는다. 단순 화면 닫기가 작업 취소/완료는 아니며 인계 미준비이면 상태/이유를 보존한다. 지도 귀환은 원래 카메라·선택·입력을 복원하고 업무는 경과 후 현재 상태를 읽는다.

## 6. 첫 시안과 개발 범위를 나눈다

**첫 시안은 한 층에 입고·선반·피킹 통로·포장대·분류/출고의 자리가 보이는 작업 맵**을 추천한다. 가상 작업자1명·간단한 선반·두 품목·집품 용기·포장대와 보류 위치 정도로 작업 판독을 검토한다. 예시 수량/시간은 밸런스 값이며 실제 처리능력으로 쓰지 않는다.

기존 r163의 첫 상태 개발 후보인 `포장완료 소포1개→벨트/읽기→정상 A/B 출구 또는 보류`는 보존한다. 이 문서가 입고부터 차량 상차까지 전체 업무를 한 WI에 넣거나 현재 최소 우유 사슬을 대체하지 않는다.

후속 직접 직무 후보는 r147의 **한 출고 지시·두 품목 피킹→집품 확인**을 좁혀 준비하고, 포장→출고대기·입고 검수/적치·직원 상차는 각자의 직접 결과로 나눈다. 첫 분류·피킹의 실제 개발 우선순위와 정확 상태/쓰기 소유는 별도 결속 대상이다. 독립 센터 Fixture를 사용하고 외부 공급·배달·다른 지역의 완료를 필수 선행으로 삼지 않는다.

## 7. Claude 시안에 더할 입력

기존 시안 D에서 **선택 층 상세 한 장**을 파생하는 안을 추천한다. 현재 요청은 제안 문서화이며 이번에 새 이미지를 만들지는 않는다.

1. 위층을 가린 한 층에 입고·검수/보류·선반·피킹 통로·포장대·분류/출고를 이름과 모양으로 구별한다.
2. 준비된 피킹 작업 하나를 선택하고, 현재 선반·집품 용기·다음 확인 지점만 강조한다. 다른 물건/경로를 동시에 모두 빛나게 하지 않는다.
3. 작업대 상세의 바코드/수량 확인과 원래 작업 층으로 돌아오는 관계를 표시한다. 실제 미구현·가상 배치/수량을 밝힌다.
4. 아래 직무 대기열과 `다음 작업`, 이완 전환, 전체 모형/원래 지도 귀환을 구별한다. 긴급/필수 예외의 복귀 경로를 유지한다.

## 확정·미정·다음 검토 하나

**확정 방향:** 동네 배달과 센터 내부 작업에 맞는 현장을 구별하자는 사용자 요청을 기존 다층 모형·직무·혼합 턴에 연결한다.

**제안·미정:** 한 층 배치·조작·첫 직접 직무와 단계별 재고/인계 명세. 기존 시안 D/코드가 새 작업 맵으로 구현·승인됐다는 뜻은 아니다.
