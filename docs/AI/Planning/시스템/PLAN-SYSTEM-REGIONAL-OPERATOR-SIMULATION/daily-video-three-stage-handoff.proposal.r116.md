## 제안의 중심

사용자는 원본 묶음의 위치와 업로드 완료를 알려주고, Codex가 기존 도구와 직접 판독을 사용해 이어간다. 원본 하나를 분석할 때 도로 이동과 건물 외관을 함께 관측하고, 검증된 작은 부분부터 다음 단계로 넘긴다. 같은 지역의 전체 영상 분석을 모두 끝내는 것을 Unity 보완의 선행조건으로 두지 않는다.

```text
사용자: 촬영분·원본 묶음·업로드 완료 알림
└─ 1. 접수와 분석
   ├─ 원본 식별·중복·시계·실제 화면·글자·이동/회전 관측
   └─ 원본 SHA → 실제 PTS/프레임 → 관측 ID
      └─ 2. 공간 연결
         ├─ 도로: 기존 선분 ID·순서·방향·확인/추론/공백
         └─ 건물: 공개 지점·정확 건물 ID·외관 속성별 근거
            └─ 3. 디오라마 보완과 결과 환류
               ├─ 정확 대상·판본 대조 → 바뀔 속성만 비공개 시안
               ├─ 전후 정지 화면·표시 제거/복구 → 기존 결과 보존
               └─ 일일 기록에 근거·적용 결과·보류를 연결 → 다음 촬영분에 재사용
```

도로와 건물은 같은 관측에서 갈라지는 별도 인계다. 전체 주행 경로가 미확정이어도 건물의 위치·외관 근거가 독립적으로 맞으면 해당 외관 보완은 진행할 수 있다. 건물 하나를 알아본 것으로 차량 위치·모든 중간 선분·픽업을 확정하지 않는다.

## 1. 접수와 분석

촬영분/접수일·카메라·파일 목록과 업로드 완료/읽기 가능 여부를 구분한다. 기존 원본 색인과 SHA를 재사용하며 같은 원본 사본을 새 분석 실적으로 세지 않는다. 원본은 한 곳에 유지하고 도로·건물별로 반복 복사하지 않는다. 같은 SHA라도 현재 stat와 입력 판본이 달라졌으면 기존 근거를 다시 검사한다.

시간순 이동·회전/유턴·분기/정차·시선·가림과 간판·도로표지를 실제 PTS/프레임에 연결한다. OCR은 글자 후보이며 위치 정답이 아니다. 관측/연결 추론/대안·보류를 나누고 읽히지 않는 구간은 전후 기점으로 보강한다. 원본 전체 비공개 분석과 공개 가능한 외관·영상 사용 구간은 분리한다. 공개되지 않은 고객 상세주소·연락처를 새 공간 자료로 복사하거나 복원하지 않는다.

새 제공분은 새 접수 묶음 안에서 숫자순으로 검토하고, 기존 번호순 미완료 목록/다른 날짜의 같은 번호는 별도로 유지한다. 파일 번호는 촬영 연속성을 뜻하지 않는다. 한 원본 접근 실패·애매한 위치 때문에 나머지 원본을 멈추지 않는다.

## 2. 공간 연결

영상의 시간 구간과 기존 지도 선분을 대응시킨다. 지도 판본·선분 ID/코드·시간순 순서·정역방향·근거·공백을 기록한다. 선분을 새로 만들거나 물리적으로 영상을 자르는 일은 별도다. 개별 진입/이탈이 확인되지 않으면 공통 관측창의 탐색 후보로 남기고 시간을 균등 분배하지 않는다. 네이버 길찾기는 참고 경로일 뿐 실제 촬영 경로의 빈칸을 채우는 정답이 아니다.

같은 분석에서 매장명·공개 지점·건물 원형을 대조한다. 간판색·차양·유리·틀·높이·층수·지붕은 속성별로 확인 범위와 근거를 남긴다. 같은 건물이 다시 찍히면 기존 미확인 속성을 보완하고, 이전 관측과 모순되면 충돌로 남긴다. 가까운 건물에 대신 배정하거나 층수만으로 실제 높이·창 배열을 만들지 않는다.

## 3. 디오라마 보완과 환류

변경 묶음마다 원본 SHA·실제 PTS·관측 ID·공개 건물 ID/원형 hash·Unity targetBuildingId/공간 판본·속성 변경 전후·표현 Profile·검증 결과를 기존 기록의 참조로 연결한다. 새 승인 원장이나 별도 운영 DB는 만들지 않는다.

정확 대상이 있는 경우 기존 비공개 표현 범위에서 변경분만 조립하고 전후 PNG·제거 후 복구·가림/오류·임시 자원 정리를 확인한다. 정확 대상이 없으면 그 건물만 연결 대기로 둔다. 새 사진을 입력한 것만으로 정본 Scene 저장·사용자 승인·공개/운영 반영을 자동 실행하지 않는다. 이번 절차의 기본 결과는 정지 화면과 기록이며 영상 제작은 별도다.

검증 결과는 그날 원본과 관측으로 되돌려 연결한다. 다음 촬영분에서는 기존 사실·보류·실제 보완 이력을 먼저 조회하고 필요한 관측만 추가한다. 원본/관측 변경, 지도 판본 변경, 보호/승인 변경이 있으면 영향을 받는 연결·표현만 재확인하며 이전 결과는 보존한다.

## 현재 확인한 핵심 결손과 후속 순서

기존 `video_diorama_daily_batch.py`는 근거 연결/재검사 도구다. 전체 도구를 자동 실행하는 실행기가 아니며 의미 판독을 대신하지 않는다. 현재 `comparison_and_restore`는 구형 `private-building-facade-study-render.v1`만 받는다. 새 `private-detailed-building-preview-render.v1` 및 영상선분 Demo 결과를 원본별 일일 기록으로 환류하는 adapter는 아직 없다. `diorama_change_review`도 전용 소비 관문이 필요해 보류된다. 현재 Overture 정본과 세 GIS 연구 대상의 정확 대응도 별도 미해결이다.

후속 구현은 다음 순서가 적합하다.

1. **일일 원본별 인계 기록 보강**: 각 단계의 입력/결과 참조, 부분 완료·보류·다음 작업을 같은 묶음에서 조회한다. 기존 manifest/state를 대체하지 않는다.
2. **분석 결과를 두 갈래로 인계**: 기존 선분 후보·건물 관측을 원본 SHA/관측 ID별로 연결하고 현재 보호·지도 판본을 재검사한다.
3. **새 Unity 결과 환류**: 상세 외형/영상선분 결과의 원본별 대상·관측·실제 비교/복구를 검증해 일일 기록에 연결한다. 대량 일괄 완료로 처리하지 않는다.
4. **좁은 반복 운영 후 실행 연결**: 실제 하루 묶음을 반복하며 재사용·실패 재개를 확인한 다음 실행 자동화 범위를 따로 정한다. 무인 감시·예약 실행은 이번 제안에 포함하지 않는다.

## 매일 사용자에게 보여줄 결과

`접수 / 실제 분석 / 도로 연결 / 건물 보완 / 보류·다음 촬영 권장`을 짧게 보여준다. 대표 근거 사진·지도 후보·디오라마 전후 PNG만 추리고 상충하는 판단이 있을 때 선택적으로 검토받는다. 사용자에게 모든 선분을 수동 입력하게 하지 않는다. 실제 사용자 승인과 AI 판독은 계속 구분한다.

단계별 `대기/진행/부분 검증/재사용/보류/실패/재확인 필요`를 사용한다. 원본 하나에 단일 완료 표시를 붙이거나 중첩 관측창을 더해 전체 완성률을 만들지 않는다. 신규·보완·재사용·비공개 시안·정본 실제 반영을 별도 집계한다.

## 이번 정리의 범위

기존 문서·현재 일일 연결 consumer를 읽고 제안만 기록했다. 새 영상 접수·분석·선분 등록·Unity 실행·렌더·운영 DB·자동화·게시·commit/push는 하지 않았다. 앞선 r115의 실행 중이던 시험은 완료 XML을 읽어 175/175 통과를 확인했지만 새 높이·유리의 PNG/Game View 검증은 아직 이어가지 않았다. 새 공통 디오라마 규칙 후보 없음.
