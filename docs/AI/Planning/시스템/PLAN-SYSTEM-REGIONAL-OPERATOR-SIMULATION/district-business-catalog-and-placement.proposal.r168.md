## 왼쪽 상세와 3D 지도에서의 선택

1. **왼쪽 「사업 → 음식점 차리기」:** 첫 카드는 소형 배달 음식점이다. 비용 항목과 필수 준비를 먼저 보여 준다. 위치를 고르기 전 금액·기간은 범위이거나 ‘자리를 고르면 계산’으로 표시한다.
2. **「지도에서 자리 비교」:** 같은 행정동의 준비된 가상 슬롯만 표시한다. 건물을 누르면 왼쪽 상세에서 해당 공간이 선택되고 A/B를 바꿔 볼 수 있다. 가상 임대 조건, 3D 도형과 층·문·진입로의 확인 수준, 지사의 픽업 대응 여력을 따로 보여 준다. 후보 선택은 다른 건물의 관리나 배차 명령을 함께 보내지 않는다. 취소 시 같은 지도로 돌아온다.
3. **「이 자리에서 준비 시작?」:** 예약할 초기 자금, 보증금, 준비 지출, 별도의 월 고정비, 필요한 시간과 가장 오래 걸리는 일, 막힌 조건·취소 시 영향을 읽고 한 번 확정한다. 자금/슬롯/시설 상태가 바뀌면 새 조건을 보여 주고 다시 확인한다. 미리보기에는 돈·턴·소유권 변화가 없다.
4. **준비 → 개업:** 같은 위치에 ‘준비 중 · 남은 턴 · 지연 사유’를 보여 준다. 준비 조건을 갖추고 플레이어가 ‘개업’하면 해당 가상 점포의 운영창으로 간다. 위치 선택·공사 완료·개업·첫 주문은 각각 다른 결과다. 구 지도는 여러 동의 후보와 준비 현황을 읽는 곳이다.

### 상세에서 바로 비교할 것 — 가상 숫자

두 후보는 **같은 행정동, 같은 업종**이다. 동 단위 분기 유동인구를 두 점포 앞의 차이로 적용하지 않는다. A/B는 실재 빈 매물이 아니며 아래 단위는 임의 게임 자금이다.

| 표시 항목 | A · 큰길, 주방 일부 사용 가능 | B · 이면도로, 환기 보강 필요 |
| --- | ---: | ---: |
| 보증금으로 묶이는 돈 | 750 | 450 |
| 시설·식당 내부 공사 | 220 | 550 |
| 조리기기·냉장고·작업/포장대 등 첫 설비 | 480 | 480 |
| 첫 재료·포장재 | 120 | 120 |
| 개업 준비(가상 신고 준비·교육 등) | 80 | 80 |
| **초기 필요 자금(보증금 포함)** | **1,650** | **1,680** |
| 별도 월 임대료 | 160 | 100 |
| **개업 준비 예상** | **3턴** | **5턴** |
| 기사 픽업 | 시나리오의 큰길 쪽 인계 지점 확인 | 골목 쪽 인계 지점 확인 필요 |

공사나 설비가 이미 포함된 곳에는 같은 항목을 다시 붙이지 않는다. 보증금은 당장 필요한 자금에 포함하지만 소비한 공사비와 구별한다. 월 임대료는 첫 준비비와 섞지 않고, 청구 시점과 준비 중 부담 유무는 계약/경제 검토에서 정한다. 인력 보수·재료 재구매·공과금은 운영비의 별도 항목이다. 준비 목록에서 본부 발주·채용 같은 각 업무로 이동해 처리하는 안을 검토한다.

### 3턴·5턴이 나오는 이유

두 곳 모두 **임차·현장 확인 1턴 → 공사·장비 배송·채용/재료 준비를 병행 → 현장 설치·최종 확인 1턴**이다. A의 병행 구간은 가장 긴 작업이 1턴, B는 환기 공사가 3턴이어서 각 3턴과 5턴이다. 공사와 별개로 가능한 장비 발주·배송은 병행하나 설치는 공사가 끝나고 장비가 도착한 뒤다. B의 픽업 인계 확인이 미완료라면 5턴 이후에도 준비 중에 남고, 확인하거나 준비된 대안으로 바꿀 수 있다.

‘턴’은 [같은 날 반복하는 운영 회차 r187](operating-round-first-play.prototype.r187.md)다. [현실 날짜·일일 결산 r174](live-calendar-daily-management.baseline.r174.md)는 별도다. 시나리오가 정의한 유효 진척을 해당 회차 경계에 한 번만 반영한다. 실제 신고 처리시간·공사 일수를 기계적으로 턴으로 바꾸지 않는다. 취소 때 미사용 예약과 이미 지출한 비용을 구별하고, 준비 조건·잔여 기간·부분 진행은 저장/재개에서도 각각 보존하는 안이다.

## 1. 추천 — 지역을 선택하고 ‘입점·설치’ 목록을 연다

**구 지도에서 어느 동에 무슨 사업을 둘지 고르고, 동네 지도에서 정확한 후보 공간을 선택한다. 사업을 개설하면 그 건물의 내부 작업과 운영이 이어진다.** 지도가 사업을 구경하는 화면에서 내가 지역의 구성을 바꾸는 경영판으로 확장되는 제안이다.

구 지도에서는 선택 구/동의 사업 분포·준비 중 계획·필요/여력과 비용을 요약하고, 동네 지도에서는 출입 위치·도로 접근·주변 점포와 준비된 입점 후보를 읽는다. 둘은 같은 목록/계획의 요약과 상세이며 확대·축소로 새 계획·개설·턴을 만들지 않는다.

계획 국면의 기본 진입은 선택 지역 카드의 **`입점·설치`**다. 오른쪽 목록에서 사업을 고른 뒤 지도에 후보 위치를 표시한다. `운영 중`·`준비 중` 사업도 같은 지역 맥락에서 확인한다. 실행 중 목록을 살펴볼 수 있어도 이미 진행 중인 준비/주문을 몰래 바꾸지 않고, 새 확정의 허용 시점은 턴 명세와 결속한다.

## 2. 첫 사업 목록은 세 가지로 시작한다

| 첫 목록의 이름 제안 | 만드는 운영·작업 | 위치를 고를 때 볼 것 | 개업 이후 확인할 대가 |
| --- | --- | --- | --- |
| 소형 카페 | 음료 제조·매장/포장·준비된 픽업 인계 | 고객/기사 접근·제조 바를 넣을 후보 공간·재료 준비 | 원료·컵/포장재·장비 점유·인력/유지비와 대기 |
| 배달 음식점 | 주문 준비·조리·포장·기사 픽업 | 주방형 후보 공간·픽업 접근·기존 기사 여력 | 식재료/포장·준비시간·기사 부족과 운영비 |
| 창고형 매장 | 보관 재고를 갖춘 **상품 판매·픽업 매장** | 선반/판매·픽업 공간과 입출고 접근 | 재고 묶임·품절·집품/포장 부담·보관/운영비 |

여기서 창고형 매장은 판매 기능을 가진 유형으로 **제안**한다. 보관/피킹/출고만 맡는 `도심 창고`와는 다른 항목이다. 도심 창고·지역 지사·물류센터 등은 준비된 후속 목록으로 묶고 처음부터 모든 사업 카드를 펼치지 않는다. 구체 업종/규모와 각 유형의 기능은 검토 전이다.

실제 브랜드명·로고·매장 외형은 목록에 넣지 않는다. 우선 `업종 + 규모/운영 특성`으로 고르고, 이후 자신의 가상 운영 모델을 여러 점포에 적용하는 가맹 확장을 연결할 수 있다. 같은 사업 유형과 같은 가상 운영 모델을 쓰더라도 각 점포의 위치·재고·직원·성과는 독립적으로 남긴다. 가상 가맹 모델의 본부/공급/수수료 등은 별도 기획이며 실제 가맹 계약이 아니다.

### 카드에 먼저 보여줄 정보

목록은 **사업명/기능 → 개설 준비비와 가용 자금 → 소요 턴 → 필요한 공간·설비/인력 → 개업 후 생기는 일**이 읽히게 한다. 예상 유지 부담과 주의점도 짧게 보인다. 임의 수익 보장값은 제시하지 않는다. 상세 비용·규모·준비 턴과 동시 준비 능력은 시나리오/밸런스 미정이다.

`선택 가능`, `자금/인력 등 게임 조건 부족`, `이 위치에 맞지 않음`, `기능 준비 중`을 구별한다. 미구현 기능을 사용자가 돈이나 턴을 더 쓰면 열리는 사업처럼 표시하지 않는다. 미확인 비용/공간을0원·0턴·무제한으로 채우지 않는다.

## 3. 실제 지도 건물과 가상 입점 공간을 나눈다

**첫 안은 기존 건물의 가상 점포 공간에 입점하는 방식**을 추천한다. 별도의 가상 부지에 시설 모형을 짓는 방식은 후속 배치 유형으로 둔다. 이렇게 하면 실제 동네의 건물/도로를 보존하면서 카페·음식점의 입점을 표현할 수 있다.

| 구분 | 의미 | 구별할 것 |
| --- | --- | --- |
| 지도 건물 | 주소/외곽을 가진 배경 또는 공간 객체 | 등록 주소가 소유권·빈 점포·업종 허용을 증명하지 않음 |
| 입점 후보 공간 | 게임 시나리오가 선언한 동/건물/층·호의 가상 슬롯 | 실제 임대 가능 매물이라는 표시를 하지 않음 |
| 사업 유형/가상 모델 | 기능·공간·준비 조건과 메뉴/내부 배치 등의 규격 후보 | 물리 건물·사업 인스턴스·실제 브랜드와 동일하지 않음 |
| 개별 점포 | 해당 후보 공간에 개설한 지속 사업과 담당/관리 관계 | 한 건물의 다른 사업이나 건물 전체 소유와 동일하지 않음 |
| 가상 부지 | 시나리오가 설치 가능하다고 선언한 게임 공간 | 실제 건물/도로 철거·공공 토지의 사용 권한으로 확장하지 않음 |

한 건물에 여러 점포가 있을 수 있다. 후보 공간이 없는 건물에는 해당 이유를 표시하고, 주소/외형만으로 빈 슬롯을 생성하지 않는다. 위치 연결이 정밀하지 않으면 핀/표식을 사용한다. 공공 상권/유동인구는 근거가 확인된 참고 자료이며 실제 주문·매출·사업권으로 자동 전환하지 않는다.

첫 후보는 기존 운영 자료를 읽을 수 있는 면목동 안의 가상 슬롯을 추천한다. 다른 동의 새 주문/사업 규칙이 이미 있다는 전제로 확장하지 않는다. 이 지역 선택도 후속 범위 검토 대상이며 새 지역 개발을 자동 활성화하지 않는다.

## 4. 목록 선택에서 개업까지

| 단계 | 사용자에게 보일 것 | 게임에서 바뀌는 범위 제안 |
| --- | --- | --- |
| 지역/사업 선택 | 선택 동/구·목록 카드·조건 | 초안만 변경. 비용·관리 관계·주문은 바뀌지 않음 |
| 위치 미리보기 | 가능한 가상 슬롯·부분/핀 미리보기·부적합 이유 | 후보 이동/취소 가능. 실제 배치/소유로 세지 않음 |
| 입점 계획 확정 | 최종 위치·유형·준비비/턴·필요 자원·취소 조건 요약 | 현재 슬롯/자금/준비 조건 재검증 후 계획·자원/슬롯 예약을 한 번 등록 |
| 준비 시작/진행 | 준비 목록·남은 턴·진행/막힌 이유 | 실행 시점의 승인된 준비 비용/업무를 적용. 실제 진척은 동일 턴 경계에 결속 |

자금은 보유·예약·현재 가용을 구별한다. **계획 확정에서 예약하고 실행 시작에 준비비를 적용하는 안**을 추천하되 지출/반환 시점의 확정은 경제 명세가 소유한다. 준비 전 취소는 예약 해제 후보이고, 이미 진행/소비된 자원의 취소·환급은 미정이다. 확정 전에 적용 규칙을 읽을 수 있어야 하며 무조건 전액 환급으로 가정하지 않는다.

준비 중 항목은 목록/지도에 남은 턴과 사유를 함께 표시한다. 동일한 턴 경계를 다시 읽거나 화면/저장을 열었다고 준비가 두 번 진행되지 않는다. 단순히 턴 수가0이 됐다는 이유로 필수 인력·장비·메뉴 조건을 생략하지 않는다. 첫 검증 후보는 계획1건이지만 전 지역에 고정 동시 준비 상한을 선언하는 것은 아니다.

## 5. 배치가 지역 발전과 선택으로 이어지게 한다

계획에서 사업/위치와 자원 배분을 고르고, 실행/관찰에서 준비/운영 결과를 보며, 결산에서 비용·수요 충족·대기·작업 부담과 다음 투자를 판단한다. 카페를 늘리면 음료 제조와 픽업 여력이, 음식점을 늘리면 조리/픽업의 요구가, 창고형 매장을 열면 재고/집품·상품 인계의 책임이 늘어난다. 정확 효과는 해당 준비된 업무 규칙과 시나리오에 따라 계산한다.

새 건물을 놓는 횟수만으로 지역 레벨·엔진 단계·기사·고객·재고·수익을 자동 생성하지 않는다. 비슷한 사업을 더 늘릴지 기존 매장의 인력/설비를 개선할지의 대가가 보여야 한다. 유지비·자금 묶임·부족한 원료/인력 때문에 확장을 미루는 선택도 남긴다. 진행 스테이지는 관련 선택을 소개하는 역할이며 지도 접근권·실제 사업 준비를 대신하지 않는다.

목록과 준비 내역은 새 입력 화면이지만 기존 공통 시계·작성 초안·선택/카메라·미완료 작업을 유지한다. 운영 중 사업의 철회/이전은 진행 주문·재고·예약/인계·직원 상태를 처리하는 별도 절차가 필요하다. 모델을 지우거나 다른 위치로 드래그해서 사업을 닫고 손실을 없애는 방식은 쓰지 않는다. 이번은 실제 철회 기능을 구현하지 않는다.

## 6. 기존 시험 영업·관리색·현장 맵과의 연결

- **r142 무료 시험 영업:** 별도 합성 실험/비교를 유지한다. 시험 결과를 참고해 정식 입점 목록으로 돌아올 수 있으나 가상 시험 매장을 지속 사업·자산·관리 관계로 자동 전환하지 않는다. 시험에서 성공했어도 별도 입점 확정/준비가 필요하다.
- **r143 관리 강조:** 후보/초안은 점선·미리보기, 준비 상태는 이름/진척 표식, 관리 관계가 확인된 사업 부분은 기존 민트와 상태 표식으로 구별한다. 준비 계획만 있다는 이유로 소유하지 않은 건물 전체를 민트로 칠하지 않는다.
- **r166/r167 내부 현장:** 카페는 제조 바, 음식점은 준비된 조리/포장, 창고형 매장은 판매/집품·포장 구역으로 들어간다. 내부 맵 자산이 있다는 것과 해당 사업 기능/직무 준비는 구별한다. 개업/내부 진입만으로 집중 미니게임이 시작되지 않는다.
- **r165 다음 작업/턴:** `다음 작업`은 기존 준비 작업 한 건을 시작한다. 입점 목록·준비 계획 목록과 다른 의미이며 개업이 턴/스테이지를 자동 넘기지 않는다.

현재 사업 탭·지도 영역의 진출/운영 표식·센터/우유 최소 사슬은 기존 구현이다. 영역 진출 명령이 임의 건물 입점 명령이거나, 설치 목록·비용/준비·개업·가상 가맹 모델이 이미 완성됐다는 뜻은 아니다. 이번 제안은 새 OS·Scene·상태 권위를 만들지 않고 기존 준비된 사업 모듈과 상태 사본을 재사용할 경계를 남긴다.

## 7. 첫 작은 결과의 후보

같은 동의 **가상 입점 슬롯1개·소형 카페 유형1개**로 `목록 열기→위치 미리보기→조건/비용 확인→계획 확정→등록된 계획 재조회 또는 시작 전 취소`를 첫 구현 후보로 추천한다. 직접 결과는 입점 계획/예약의 정확한 등록 또는 해제이며 아직 제조·매출·전체 개업 완료가 아니다.

후속으로 준비 진척→개업 조건 확인→영업 시작을 각각 결속하고, r167 한 잔 제조/픽업 준비와 잇는다. 창고형 매장의 판매 규칙·전국 센터·임의 건물 편집·실재 임대 정보는 별도 후속이다. 기존 r162 구 여력/r163 분류/다른 독립 현장의 진행을 이번 후보가 자동 선점하지 않는다. 카페를 시작하기 위해 우유 사슬이나 다른 센터/Farm/City 완료를 필수로 요구하지 않는다.

중복 확정/저장 복원에서 사업·슬롯 예약·비용이 늘지 않는지, 슬롯 충돌/부족 자원 때 이유와 초안이 남는지, 지도 축척 왕복·취소·턴 재진입이 상태를 보존하는지 확인해야 한다. 정확 명령/저장·경제·주체/WI·연구/시각·E1~E7·쓰기 경로는 별도 준비 대상이다. 이 문서 작성은 구현 관문 통과가 아니다.

## 8. Claude 시안 입력

새 지역/시설을 여러 개 그리기보다 같은 동네의 다음 상태를 연결한 시안을 추천한다.

1. **지역 선택/목록:** 선택 동/구 이름을 남기고 오른쪽 `입점·설치` 목록에 세 유형과 비용·턴·조건을 표시한다. 미정 수치는 가상 예시 또는 검토 중으로 밝힌다.
2. **위치 선택:** 소형 카페를 고른 상태에서 가상 입점 후보 공간·선택 위치·부적합 이유를 지도에 표시한다. 원본 건물/도로는 유지한다.
3. **확정/준비:** 같은 위치와 사업의 계획 요약·확정 결과·준비 목록/진척을 구별한다. 보유/예약/가용 자금과 취소 조건의 표시를 제안한다.
4. **개업 후:** 관리 관계가 확인된 점포 부분/핀과 `내부 보기`를 보여주고 r167 카페 맵으로 이어지는 관계를 설명한다. 이 장면은 후속 목표이며 첫 계획 등록 기능의 완료 근거로 쓰지 않는다.
