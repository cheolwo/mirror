## 플레이어 주체

사용자는 첫 실행부터 `가상 배달 플랫폼의 사가정·면목제3·8동 권역 운영자`다.

- 공공자료 기반 디오라마는 운영 대상 지역과 현실 공간 기준선을 보여 준다.
- 음식점·기사·주문자·차량은 Simulation Core의 가상 주체로 움직인다.
- 플레이어는 Actor를 직접 운전하거나 강제로 순간이동시키지 않는다.
- 플레이어는 공급·배차·알림·할증·예산·예외 처리 정책을 선택하고 결과를 관찰한다.
- Unity는 운영 상황을 읽고 정책 Preview와 Command 진입점을 제공하지만 업무 결과의 최종 권위는 Simulation 상태 원장에 있다.

## 첫 실행

첫 정상 음식배달 Fixture는 수동적인 영상 튜토리얼이 아니라 첫 운영 회차의 기준 업무다.

1. 동봉된 사가정 지역 기준선을 연다.
2. 현재 주문·음식점·가용 기사·위험·가용현금과 기본 정책을 확인한다.
3. 운영자는 즉시 정책 카드를 열어 Preview할 수 있다.
4. 선택하지 않으면 판본화된 안전 기본 정책으로 시간이 흐른다.
5. 선택하면 예상 서비스 효과·기사 추가 지급·현금 영향을 확인한 뒤 Simulation에 적용한다.
6. 주문·조리·배차·이동·전달과 예외가 디오라마에 나타난다.
7. 회차 종료 때 서비스·재무·정책 결과를 비교하고 유지·수정·원복한다.

정상 흐름을 이해하기 전 정책을 잠그지는 않는다. 대신 처음 선택하는 정책마다 `무엇이 바뀌고 무엇은 바뀌지 않는지`와 예상 비용을 Preview한다.

## 운영자가 직접 결정하는 것

- 기사 가용 의향 알림의 대상 범위와 발송 여부
- 승인된 범위 안의 피크 부족 할증 활성화
- 정책 예산과 현금 방어선 안에서의 시간창
- 자동 처리 범위를 벗어난 예외 사건 담당·재조회·보호 조치
- 회차 종료 뒤 정책 유지·수정·원복

## 시스템이 자동 처리하는 것

- 주문·조리·기사 수행의 정상 생명주기
- 안전·거리·권역·가용성 필터와 후보 계산
- 승인된 정책 판본 안의 반복 계산·상태 전이
- 정상 정산 후보·재무 사건 기록과 상태 사본 생성
- 선택이 없을 때의 안전 기본값

운영자는 정상 주문을 건별 승인하지 않는다. 사람 판단이 필요한 위험과 정책 선택에 집중한다.

## 첫 화면

- 중앙: 사가정 디오라마와 음식점·기사·전달지·진행 경로
- 상단: 진행 주문, 가용 기사, 미배차·지연 위험, 가용현금
- 오른쪽: 현재 정책, Preview 후보, `AvailableActions`
- 하단 또는 선택 카드: 선택 Actor·건물·업무 단계와 원인
- 회차 마감: 서비스 수준, 기사 지급, 플랫폼 비용, 현금 최저점과 다음 선택

## 권위·안전 경계

- 모든 운영은 합성 데이터와 Simulation 모드에서 시작한다.
- 실제 주문·기사 알림·배차·결제·정산을 실행하지 않는다.
- 공공자료는 현실 기준선이며 운영자의 게임 선택으로 수정되지 않는다.
- Unity 객체나 Animation이 주문 완료·지급·책임을 확정하지 않는다.

## 미정

- 첫 회차에 열어 둘 정책 카드 수
- 첫 성공·실패·회복 조건

## 다음 질문 하나

첫 플레이 가능한 운영 회차의 시간 범위를 어디까지로 둘까?

1. `점심 피크 한 회차` — 추천. 짧은 운영에서 주문 증가·기사 부족·할증·회복·결산까지 경험하고 결과를 일·주·13주 전망에 누적한다.
2. `하루 전체` — 생활 변화는 넓게 보이지만 첫 폐루프 완주와 원인 비교가 길어진다.
3. `13주를 한 번에 연속 운영` — 장기 현금 흐름은 보이지만 초기 게임의 조작과 결과 관계가 흐려진다.
