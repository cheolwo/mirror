## 1. 중심 제안

**팩은 설치·보관·갱신할 자료 묶음이고, 레이어는 설치한 자료를 화면에 표시하는 선택이다.** 팩 하나가 여러 레이어와 표/그래프를 제공하고, 레이어 하나가 공통 공간팩과 여러 분야팩을 참조할 수 있다. 레이어를 꺼도 설치한 자료는 남으며 게임 진행·재고·매출·작업은 그대로다.

예를 들어 ‘서울 생활·상권 2026년 2분기’를 설치하면 유동인구 음영·업종별 점포·기간 비교를 따로 켠다. 사용자가 가격팩도 설치하면 같은 장소에서 상권과 원가 자료를 비교할 수 있다. 지도에 정확히 붙일 수 없는 값도 표와 전국/지역 요약판으로 읽을 수 있어야 한다.

```text
공공자료 DB ── 판본·출처·공간/시간·권리 점검 ── 읽기 전용 자료팩
                                                   │
                         공통 공간팩 + 선택 분야팩 ──┤
                                                   ▼
                          지도 레이어 / 요약판 / 표·그래프

가상 시나리오·현재 게임 상태 ── 별도 출처와 표시 ── 게임 업무 레이어
```

기존 네 분류(공간·생활·업종·표현)는 제작 구조로 유지한다. 사용자에게 보이는 팩 목록은 분야와 지역으로 나누는 아래 구성을 제안한다. 새로운 등록부를 만들지 않고 기존 지역 Catalog/Experience Manifest와 팩 목록에 자료 참조를 연결한다.

## 2. 사용자가 고르는 팩

| 팩 | 담는 자료 | 주요 표시 | 제공 범위 원칙 |
| --- | --- | --- | --- |
| 공통 지도·지역 | 경계·코드·도로·건물·주소, 확인된 지역 대응 | 회색 기본 지도·도로·이름·건물 선택 | 전국은 개요, 상세 도로/건물은 선택 지역만. 다른 팩이 같은 도형을 복제하지 않음 |
| 생활·상권 | 분기 유동인구·상권·공개 사업장/업종 | 영역 음영·업종 아이콘·비교 표 | 실제 행정동/상권 단위를 유지. 법정동·도로로 임의 배분하지 않음 |
| 식품·가격 | 품목·규격·도소매·단위·통화·조사기간별 가격 | 시장/지역 가격 카드·추세 그래프 | 조사 지역이 없는 값은 국가 요약. 미국 쌀 가격을 한국 원가로 덮어쓰지 않음 |
| 농업·축산 | 경지면적·생산/축종 집계, 취득·검증된 필지/시설 자료 | 제공 지역의 면적/생산 지표·농장 후보 정보 | 국가1값은 전국 요약만. 한우·필지별 자료는 실제 취득 후 추가 |
| 해양·수산 | 어종별 생산/유통/무역, 취득한 해양 관측·예측 | 어종/기간 요약·관측 지점·해역 표현 | 현재 수산물 무역을 수온·어장·어획량으로 바꾸지 않음 |
| 물류·무역 | 실제 제공된 항만·공항·품목/상대국 통계·시설, 검증된 O/D | 거점 규모·물량/기간 비교, 근거 있는 구간 연결 | 실제 출발/도착 정보가 있는 경우에만 통계 운송선. 가상 화물 경로와 구분 |
| 날씨·환경 | 취득한 관측소/격자별 기상·수질·대기, 별도 예측 | 관측 지점·영역 값·시간 그래프 | 미취득 분야는 준비 중. 예측 발표/유효시각을 실제 관측과 구별 |

표의 분야는 **목표 목록**이며 전부 데이터가 갖춰져 있거나 설치·배포 가능한 상태라는 뜻이 아니다. 자료가 여러 분야에 쓰이면 동일 자료 ID/판본을 참조한다. 예컨대 수산물 무역은 해양·수산 화면과 물류·무역 화면에서 같은 값을 읽는다. 같은 수치를 서로 다른 팩에서 받아 두 번 합산하지 않는다.

표현팩의 건물 외형·보행자·타로 등은 이 공공 통계팩과 분리한다. 개인 업무자료도 별도 보관·동의·로컬 연결을 사용하며 공개 다운로드팩에 포함하지 않는다.

행정·법정동 대응과 HS/품목분류는 **공통 사전 참조**로 공급한다. 사용자에게 수만 개의 분류 항목을 지도 레이어로 직접 표시하지 않고 분야팩의 검색·품목 선택·지역 연결을 돕는다. 공식 분류와 후보 대응은 다른 상태로 유지한다. 수동 소매 후보/검색·광고 노출 연구는 내부 검토 영역에 두며 공식 통계나 대표 시장 가격으로 기본 배포하지 않는다.

## 3. 지역·기간으로 필요한 만큼만 받는다

사용자는 **분야 → 제공 지역 → 기간**을 고른다. 실제 설치 식별자는 분야·공간 범위·기간·판본을 결속한다. ‘서울 생활·상권 / 2026년2분기’와 ‘전국 농업 개요 / 2024년’처럼 원 자료의 범위를 이름부터 드러낸다. 전국 자료를 시·도나 동별 팩으로 나눌 때 새로운 지역별 값을 생성하지 않는다.

- 공통 지도는 전국 개요와 선택 지역 상세를 구분하고 hash별 캐시를 재사용한다.
- 분야팩은 처음에는 최신 공표 기간을 작게 제공하고 과거 기간은 선택 설치한다. 이 방식을 일별·월별·분기별 공급 주기와 맞춘다.
- 기존 도형/지역 대응/품목 사전의 판본을 참조한다. 경계·행정구역 변경이 있는 기간 비교는 대응을 검증한 범위에 한한다.
- 설치 전 용량·포함 지역/기간·출처·제외 범위·마지막 기준일을 보여준다. 아직 공개 배포할 수 없는 자료는 내부 검토/준비 중으로 구분한다.
- 설치 상태(미설치/설치/업데이트)와 자료 준비·검토·게시 가능 상태를 다른 항목으로 관리한다. 기존 `Ready / Disabled / Planned` 계약과 게시/기능 플래그를 설치 여부로 대신하지 않는다.

## 4. 레이어의 표현과 지도의 높이

일반 건물의 회색과 내 관리 매장의 민트색은 [r143](gray-neighborhood-managed-stores-and-walkers.design.r143.md)을 유지한다. 공공 통계는 **바닥 음영·영역 테두리·점/기호·숫자판**으로 표현한다. 데이터가 높다는 이유로 일반 건물 전체를 내 사업 색으로 칠하지 않는다.

| 높이 | 주로 읽을 정보 | 표현 제안 | 제한 |
| --- | --- | --- | --- |
| 건물·내부 | 주소·용도·공개 인허가 업종, 내 재고/작업 | 건물 카드 + 실제 게임의 설비/작업 객체 | 지역 집계에서 특정 건물의 매출·재고·창고 내부를 만들어내지 않음 |
| 동네 | 도로·매장·기사, 확인된 주변 통계 범위 | 회색 지도 + 실제 점포 기호 + 선택 영역 테두리 | 분기 유동인구를 도로의 실시간 보행자 수나 배달 주문 수로 표시하지 않음 |
| 구 | 행정동/상권의 분포·업종·기간 비교 | 한 지표의 음영 + 선택한 점 정보 + 비교 표 | 코드·경계 대응이 검증된 구역만 채색. 미연결 값은 표에 보존 |
| 전국·광역 | 시·도/국가의 생산·물량·가격 맥락 | 실제 지역 해상도에 맞는 색/막대·거점·국가 요약판 | 국가값을 시·도별로 나누지 않음. 운송선은 검증된 O/D 또는 가상 업무라는 표시 필요 |

지도 높이를 바꾸면 r144의 주 업무에 맞는 기본 자료 조합을 제안하되, 관찰 자료를 특정 사업 해금이나 게임 성과에 묶지 않는다. 같은 자료를 볼 수 있는 최소/최대 높이는 실제 공간 해상도로 정하고, 그 밖에서는 지역/전국 요약으로 접는다.

처음 제안하는 조합은 ‘기본 지도’, ‘상권 살펴보기’, ‘먹거리 가격 보기’, ‘농수산 살펴보기’, ‘물류 살펴보기’다. 조합은 켜는 레이어의 편의 설정이며 추가 데이터를 자동 다운로드하거나 업무를 실행하지 않는다.

## 5. 화면에서 조절할 것

- **레이어별:** 켜기/끄기, 항목·기간·범위 선택, 불투명도, 범례·단위·출처 확인. 색 음영 지표는 하나를 중심으로 두고 점/선 자료를 겹치게 한다. 동시 음영 수와 기본 배치는 후속 시각 검토에서 정한다.
- **비교:** 다른 기간을 나란히 보거나 차이를 표시하되 같은 공간·지표·단위와 비교 가능한 범위에 한한다. 기간을 바꿀 때 범례 기준도 함께 관리한다.
- **결측과 미연결:** 0, 결측, 미수집, 범위 밖, 위치 연결 확인 중, 오래된 자료를 구별한다. 그림을 만들 수 없더라도 표/그래프와 미연결 이유는 읽을 수 있게 한다.
- **날짜:** 자료별 기준기간을 보인다. 분기 유동인구와 오래된 사업장 자료를 동시에 켜도 전부 ‘현재’라고 쓰지 않는다. 과거 자료 선택으로 게임 시계를 이동하지 않는다.
- **움직임:** 자료 표시와 장식 효과는 독립이다. 핀·파동·흐르는 빛을 꺼도 값·출처·선택은 유지한다. 생활감을 주는 보행자와 자료의 실제 인구는 구분한다.

수집 완료는 업무 사건이 아니다. 새 팩을 받았다고 주문 핀·배차·매출이 생기지 않으며, 기존 게임의 실제 주문 사건만 그 사건 레이어에서 핀/파동으로 표현한다. 전국의 옅은 곡선도 공공 통계 흐름과 현재 가상 운송을 다른 범례/출처로 구별한다.

## 6. 관찰·게임·개인 자료의 연결

‘자료 보기’는 게임 Tick·보상·업무 Command 없이 읽는 기능이다. ‘이완’은 게임의 자동 업무가 진행될 수 있는 상태다. 두 사용 방식은 r158처럼 구별하고 기존 `Simulation / Operational` 실행 경계는 유지한다.

관찰 레이어는 확인한 공공 사실을 그대로 읽는다. 시뮬레이션에 쓸 때는 별도의 승인된 변환/가정으로 시나리오 참고값을 만들고, 사용자가 고른 회차 시작의 팩 판본에 고정한다. 기존 생활팩 제안의 ‘유동인구→수요 곡선’은 게임 규칙으로만 사용하며 관찰값을 대체하지 않는다. 현실의 인구 갱신이 현재 게임 주문·농장 생산량·가상 운임을 자동 변경하지 않는다.

개인 주문·매출·재고·작업 자료는 공개팩과 별도 저장소/접근 권한/철회 경계를 가진다. 내 업무 레이어에서 공개 통계와 비교해 볼 수는 있지만 공개 통계팩의 원본이나 공개 다운로드 목록으로 역류하지 않는다.

## 7. 파일과 갱신

첫 연결은 r158의 **기존 JSON 조회 결과 + manifest + 필요한 지리 자산**을 우선한다. 압축 파일 하나로 받더라도 내부에서 공통 공간 참조와 분야 자료를 구분한다. 대량 시계열에는 읽기 전용 SQLite를 후속 후보로 검토한다. SQLite는 여러 객체와 관계를 담는 앱 파일 형식으로 활용할 수 있지만, 현재 Windows 게임의 SQLite 어댑터·성능이 준비됐다는 뜻은 아니다. [SQLite 공식 설명](https://www.sqlite.org/appfileformat.html).

현재 Windows에는 파일 SHA·출처·배포/개인정보를 적는 `hongdal-pack-manifest.v1` 제작물이 있으나, 게임 커널과 지도는 고정된 `Resources` 자산을 읽는 구현이다. 사용자 선택 다운로드·외부팩 설치/의존성 해결·원자 갱신은 아직 검증되지 않았다. 제안의 manifest는 이 기존 규격과 지역 Experience Package를 확장/참조하는 방향이며 새 병렬 등록부를 만들지 않는다. 실제 소비 코드 근거는 `artifacts/local/public-data-packs-layers-20261113/pack-architecture-review.json`에 남겼다.

팩 목록에는 자료/팩 ID·schema·revision·파일 SHA·공통 공간 의존성·지원 앱 판본·자료의 공간/시간 단위·통화/측정 단위·포함/누락 범위·지역/품목 대응 판본·출처·이용조건·공개 배포 승인·표현 가능한 레이어를 결속한다. 배포물에는 API 키·원본 DB 연결정보·개인 원장을 넣지 않는다.

원본 좌표계와 변환 이력을 보존한다. 표준 GeoJSON으로 내보낼 때는 확인된 좌표를 WGS84 경도·위도 순서로 변환한다. 좌표계가 미확인인 대표점/도형은 포맷 이름만 바꿔 싣지 않는다. [GeoJSON RFC 7946](https://www.rfc-editor.org/rfc/rfc7946.html).

새 팩은 임시 위치에서 hash·schema·권리·참조·공간/시간 범위를 확인하고 활성 판본을 교체하는 안이다. 실패하면 마지막 정상 팩과 실제 기준일을 유지한다. 관찰 도구의 새 판본 선택과 진행 중 게임의 동결 판본은 독립이며, 레이어 끄기·팩 제거가 게임 저장을 지우지 않는다. 현재 회차가 참조 중인 팩은 필요한 동결 자료를 보존하거나 회차를 끝낸 뒤 제거하도록 설계한다. 실제 교체·제거·Save/Replay 동작은 구현 검증 전이다.

로컬 폴더·다운로드 서버·Drive는 팩을 전달하는 수단이다. 어디서 받든 같은 명세와 지문으로 검증하도록 하고, 특정 계정 연결을 필수 전제로 만들지 않는다. 기존 내부 인계 ZIP과 공개 배포팩의 승인은 구분한다.

## 8. 첫 제작 제안

첫 목표는 **‘서울 생활·상권 관찰팩’ 한 개를 구 지도에서 켜고 끄는 경로**다. r159의 총 유동인구와 기존 지도 자산을 출발점으로 삼고, 실제 지역 코드·경계 판본·좌표계·이용 조건을 먼저 결속한다. 현재 공개 사업장·건물 연결 테이블은0행이므로 해당 DB에서 업종 점포를 즉시 생성하지 않는다. 현재 게임의 가상/관리 매장 표현은 출처를 구별해 유지한다.

1. 지역/기간·값·단위·출처를 가진 작은 JSON 검토팩과 읽기 목록을 만든다.
2. 코드/경계 대응이 확인된 행정동 또는 상권만 구 지도 음영으로 표시한다. 연결 전에는 표/그래프로 읽고 임의 면 채색을 하지 않는다.
3. 별도 자료 확보·반입 후 실제 공개 위치가 확인된 업종별 점을 추가한다. 이 후속 작업 없이도 유동인구 한 지표의 켜기/끄기 경로는 먼저 검증할 수 있다. 관리 매장 민트색과는 구분한다.
4. 모든 자료 레이어를 껐을 때 기존 지도·선택·게임 상태가 그대로이고 오프라인 재실행에서도 같은 판본을 읽는지 확인한다.
5. 이 한 경로를 검증한 뒤 가격·농업·수산·물류 분야를 같은 계약으로 추가한다.
