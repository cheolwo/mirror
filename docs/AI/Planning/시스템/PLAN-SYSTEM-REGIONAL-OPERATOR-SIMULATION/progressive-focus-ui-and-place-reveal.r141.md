- 기준일: 2026-11-12

- 대상: [r140 Unity Windows 실행판](unity-windows-development-direction.r140.md). 플랫폼 우선순위는 유지한다.
- 이번 범위: 기획 문서와 순차 이미지 시안 네 장. 게임 코드·Scene·명령·저장 형식·운영 정책은 바꾸지 않는다.

## 확정 — 플레이가 필요한 정보와 장소를 드러낸다

처음에는 도로·매장 핀·오토바이·현재 주문과 다음 행동에 집중한다. 플레이 성과와 실제 필요에 따라 UI를 소개하고 관여한 장소부터 낮은 입체 표현을 더한다. 처음부터 배경 건물과 모든 관리 설명을 펼치지 않는다.

사용자 선택은 **성과·필요 기준 / 관여 장소부터 입체화 / 기존 기능은 접어두고 순차 소개 / 거래 흔적은 다음 실행에도 유지**다. UI 소개는 기능 사용 자격이나 지역 해금이 아니다. 기존 기능은 접힌 운영 메뉴에서 직접 열 수 있고, 진행·실패 원인·복구 행동은 항상 확인할 수 있다. 가맹·생산·공장은 현재 정보 미리보기이며 이 문서가 경영 기능을 추가하지 않는다.

## 1. 표현 단계와 전환 조건

| 표시 단계 | 실제 게임 상태에서 읽을 조건 | 앞에 놓을 정보·행동 | 장소 표현 |
| --- | --- | --- | --- |
| 첫 배차 | 해당 게임에서 첫 주문을 처리하기 전 | 현재 주문·적격 기사·기사→매장 연결 안내 하나 | 평면 도로·핀·오토바이. 활성 주문은 모두 찾을 수 있게 유지 |
| 대상 선택 | 사용자가 기존 기사/매장을 선택 | 대상 상세 하나와 기존 추천·지정 행동 | 선택 매장의 낮은 입체 표현을 임시 표시. 선택 해제 시 원래 표현으로 복귀 |
| 픽업·전달 | 배차 수락과 이동은 진행 상태로, 픽업 확인은 별도 사건으로 읽음 | 접근 경로→준비/픽업 상태→전달 경로·예상 보수 | **픽업이 확인된 매장**을 거래 흔적으로 기록. 지정·도착·선택만으로 영구 흔적을 만들지 않음 |
| 첫 회차 정산 | 수령 확인과 가상 정산이 완료됨 | 결과 요약: 처리 건수·기사 보수·플랫폼 차액과 보너스 구분 | 거래 흔적은 남기고 완료된 경로 강조는 정리 |
| 관리 필요 | 대기 주문이 있고 현재 배차 가능한 기사가 없음 | 원인과 기사 현황, 기존 기사 관리 화면 진입 | 해당 주문·활동 기사만 강조. 새 모집 기능을 가짜로 활성화하지 않음 |

표현 단계는 명령을 실행하거나 배차 가능 여부를 바꾸지 않고 현재 상태와 기존 사건을 읽는다. 관리 필요는 이전 단계를 모두 본 뒤에만 나타나는 강제 순서가 아니다. 실제 막힘이 생기면 즉시 원인과 복구 행동을 보여준다. 관리 필요 안내를 닫아도 주문과 복구 진입은 남는다.

같은 단계의 첫 소개는 게임별 한 번이며 이후에는 현재 대상과 진행 상태만 갱신한다. 안내는 하나만 표시하고, 클릭으로 닫거나 관련 행동을 완료하면 사라진다. 긴급한 진행 실패가 생기면 소개 안내보다 우선한다. 강제 카메라 이동·시간 정지·자동 다음 업무 실행을 추가하지 않는다.

## 2. 1.5D와 장소 기억의 경계

여기서 **1.5D**는 새 엔진이나 별도 게임 모드를 뜻하지 않는다. 같은 평면 도로·객체 좌표 위에 해당 매장의 지붕·낮은 측면·짧은 그림자를 더하는 표현 수준이다. 도로 위치·지도 범위·기존 휠/끌기와 선택 관계는 유지하고 시안 간 카메라와 배치를 고정한다. 배경 건물의 노후화나 물리적 신축을 경영 성과로 해석하지 않는다.

표현 우선순위는 현재 기사·주문/매장·경로 → 선택 상세 → 거래한 장소 → 단순한 배경이다. 거래하지 않은 주변은 낮은 대비의 평면 윤곽으로 남기고, 이전 거래 장소는 현재 업무보다 덜 강조한다. 전체 배경의 합성 건물 채움을 자동 확장하지 않는다. 주문자 배송지는 현재 업무 표식으로 유지하며 매장 거래 흔적과 동일하게 저장하지 않는다.

**임시 선택 표시**, **픽업한 매장 ID 집합**, **이미 소개한 안내의 종류**를 별도 표현 상태로 구분하는 것이 후속 구현 요구다. 같은 게임/세이브에서는 재실행 뒤 유지하고 새 게임은 초기화한다. 기존 세이브에 표현 기록이 없으면 거래했다고 추정하지 않고 빈 기록에서 소개를 시작한다. 이 개념은 기존 배차·정산 상태와 분리하며 이번에 새 공개 API·저장 스키마를 만들지는 않는다.

## 3. UI 집중과 닫기·복귀

- 화면 대부분은 지도다. 상단에는 가상 시각·정지/배속·운영 상태를 간결하게 유지하고 미산정 지표를 임의 수치로 채우지 않는다.
- 기존 기사·가맹·생산·공장 진입은 접힌 운영 메뉴에서 찾는다. 실제 필요한 기존 화면만 소개하며 새 기능 해금 조건은 만들지 않는다.
- 상세 창은 하나만, 소개 안내도 하나만 표시한다. 성장 설명과 대상 상세를 겹치지 않는 기존 초점 구조를 재사용한다.
- **상세 접기와 배차 선택 해제는 별개로 설계한다.** 창 접기나 표시 단계 전환으로 선택한 기사·주문을 잃지 않는다. 명시적인 선택 취소·다른 대상 선택은 기존 명령 경계를 따른다.
- 정상·대기·실패·완료를 색만으로 구별하지 않는다. 기존 지도만 보기·목록·복귀에서 상태와 실행 가능한 주 행동을 확인할 수 있게 한다.

## 5. 같은 동네의 순차 시안

문서를 작성한 다음 아래 순서로 제작·제시한다. 남색 지도·민트 강조와 기존 오토바이 표현을 참조하며, 네 장의 지도 범위·카메라·매장 A/B와 기사 A/B의 정체성을 고정한다. 차량 위치만 업무 진행에 따라 달라진다. 합성 경로·건물은 게임 표현이며 실제 지점의 정밀 재현을 주장하지 않는다.

모든 그림에는 **표현 기획 시안 · 미구현**, 단계 번호와 가상 상황을 표시했다. 이미지의 버튼·건물은 구현 증거가 아니다. 문서 뒤 내장 이미지 도구로 최초 시안 4회와 국소 보정 2회를 수행해 선택 출력 4장을 만들었다. ②의 미배정 배송지로 뻗은 불필요한 경로와 ③의 매장 B 입체 표현을 보정했고 중간 원본도 보존했다. 첫 시안의 구도와 색·배치를 후속 시안의 참조로 사용했다. [네 장 순서대로 보기](../../../../assets/concepts/hongdal-progressive-ui-r141/README.md) · [실제 사용 프롬프트](../../../../assets/concepts/hongdal-progressive-ui-r141/generation-prompts.md). 참조·출력 지문과 검토·검증은 [제작 기록](../../../../../artifacts/local/hongdal-progressive-ui-r141-20261112/completion.json)에 연결한다. 사용자가 의견을 주면 채택 시안 판본을 후속 기록에 반영하고 구판은 보존한다.

## 6. 문서 완료와 후속 개발의 확인 기준

이번 완료는 문서·연결 경로·네 시안과 연속성 검토까지다. 문서 전용 Fast/Task 계약을 따르고 제품 시험·게임 실행 완료로 보고하지 않는다.

후속 개발 담당은 다음을 완료 조건으로 사용한다. 먼저 r140의 프로젝트·허용 경로·지문과 Core/uGUI 통합 범위를 정한 뒤 검증 가능한 한 부분씩 구현한다.

1. 새 게임에서 주문과 다음 행동이 보이고, 접힌 메뉴를 직접 열어 소개 순서를 건너뛸 수 있다.
2. 선택만 한 장소는 임시 상세이며, 지정/도착만으로 지속 기록이 생기지 않고 픽업 확인 때 한 번 기록된다.
3. 창 접기·지도만 보기·복귀가 배차 선택을 지우지 않는다. 취소·배차 불가·진행 실패와 복구 행동은 숨겨지지 않는다.
4. 같은 게임 재실행은 거래 흔적·소개 기록을 보존한다. 새 게임/구판 세이브에서 근거 없는 흔적을 만들지 않는다.
5. 현재 업무와 거래 흔적의 우선순위가 유지되고, 지도 입력·사건 순서·보수·가상 정산이 기존 두 주문 결과와 일치한다.
6. 관리 필요는 실제 대기와 적격 기사 상태를 읽고 기능을 자동 실행하지 않는다. 미구현 경영 기능은 미리보기로 구분한다.
7. 실제 Windows 넓은 창·작은 창에서 상태·주 행동·접기/복귀와 평면·입체 입력을 확인한다. `--sagajeong-` 촬영만으로 2.5D 화면 확인을 대신하지 않는다.

## 미정과 다음 질문 하나

구체 건물 높이·미세 애니메이션·배치 밀도는 시안 피드백으로 조정한다. 게임 규칙·관리 기능 추가·자료 배포는 별도 범위다. 다음 질문은 **네 시안 중 첫 화면의 정보량과 장소가 드러나는 정도가 집중하기에 적절한가**다. 시안 검토 후 선택한 표현을 후속 구현 계획에 결속한다.
