## 1. 플레이 상황과 확정 구조

지금 여러 동의 점포·인력·재고 상황을 비교하고 있다. 여기는 구 지도이며, 나는 지역별 여력을 배분하는 운영자다. 상대는 같은 화면에 놓인 구·동·사업 요약과 지금 처리해야 할 안건이다. 휠로 시야를 넓혀 서울 전체의 관계를 살펴본 뒤 구를 골라 가까이 보고, 상위 지도를 선택하면 대한민국 전국으로 간다. 이동 자체에는 비용/보상이나 업무 확정이 없다.

상위 목적은 한 화면 계열에서 가까운 운영과 여러 구의 배치를 이어 읽어 길을 잃지 않게 하는 것이다. 기사/현장 작업자의 직접 회복·연구 성장 규칙은 건드리지 않는 정보 보조 층이다. 새 괘/효·능력치 의미는 부여하지 않는다.

| 항목 | 적용할 구조 |
| --- | --- |
| 지도 이동 | **동네 ↔ 구 지도 ↔ 대한민국 전국** |
| 구 지도 안의 시야 | 특정 구 근접 보기부터 서울 전역 보기까지 연속 확대·축소 |
| 서울의 의미 | 구 지도의 최대 관찰 범위·지리적 이름. 독립 경영 단계/메뉴/순회 정거장 없음 |
| 건물 내부 | 기존 동네/건물의 상세 진입·귀환 유지 |
| 세계/지구본 | 기존 기획/구현의 경로·정거장 유지. 이번에 새 단계/연출을 추가하거나 삭제하지 않음 |

행정동 한 곳에 집중하는 r182의 기본 동네 화면은 유지한다. 여러 구의 관계를 보는 일은 사용자가 구 지도로 올라온 뒤 시작한다.

## 2. 구 지도에서 서울까지 보는 규칙

구 지도에 처음 들어오면 기존 운영 구/사업 범위에 맞춰 보여 준다. **첫 화면 맞춤 배율과 축소 한계는 분리**한다. 첫 화면에 맞췄다는 이유로 다음 축소가 막히거나 상위 단계로 넘어가지 않는다.

휠 축소는 같은 구 지도 안에서 끊김 없이 서울 전체가 들어오는 배율까지 이어진다. 양 끝에 도달하면 해당 배율을 유지한다. 상위 전환은 기존 상위 지도 조작으로 전국에 바로 연결한다. 휠 한계에서 반복 입력이 뜻하지 않은 단계 전환을 만들지 않게 한다.

서울 전역 맞춤은 실제 투영 좌표의 서울25구 전체 바운드를 화면의 지도 안전영역에 **모두 포함**시키는 방식이다. 가로/세로 비율 중 작은 맞춤 비율과 여백을 사용한다. 화면을 채우기 위해 일부 구를 자르거나 한 축을 눌러 맞추지 않는다. 가로·세로 모니터, 패널 펼침/접힘·창 크기 변화에서도 이 기준을 유지한다. 정확 배율·여백 픽셀은 Claude가 현행 화면/투영에 맞춰 정하는 구현 값이다.

| 시야 | 주로 읽을 정보 | 선택과 업무 |
| --- | --- | --- |
| 한 구에 가까움 | 동별 배분·점포망·기사/재고 부족 | 기존 구의 준비된 안건과 동 상세 진입 |
| 여러 구가 보임 | 구별 사업/처리 여력의 기존 요약 | 구를 명시적으로 골라 상세로 이동 |
| 서울 전체 | 25구 경계·구명·관리 관계/선택 강조, 연결된 구 요약 | 필요한 구를 고르거나 전국으로 이동 |

카메라 축소만으로 선택 구·OS·업무 ID/Revision·입력 초안을 초기화하지 않는다. 다른 구를 고를 때만 그 구의 준비된 정보를 연다. 열람과 경영권/사업 해금은 구별한다. 미소유·미연결 구는 경계/이름과 준비 상태를 표시하고 없는 수요·점포·매출·군중을 만들어 채우지 않는다.

서울 전체에서 모든 건물·사람·이름표를 동시에 그리지 않는다. 기존 구/동 상세의 표현 밀도를 줄이고 구 요약을 우선한다. 서울 전체를 봤다는 이유로 모든 행정동 모듈을 한 번에 적재하지 않는다.

## 3. 전환·순회·귀환

- 구 지도의 상위 이동은 전국이다. 상위/하위 선택, 전환 안내, 직접 이동 버튼에 독립 서울 항목/자물쇠를 남기지 않는다. enum 정수에 ±1을 하는 방식 대신 명시적인 인접 경로를 사용한다.
- 전국에서 서울 권역의 구 지도로 들어오는 기존 진입은 새 구 지도에 연결한다. 다른 전국 지역을 선택했다고 준비된 서울 화면으로 대체하지 않는다.
- 전국에 가기 직전의 구 지도 중심·배율·선택 구/OS·선택 대상을 같은 세션의 귀환 문맥으로 보존한다. 돌아오면 그 문맥을 복원한다. 이전 문맥이 없는 서울 권역 진입은 서울 전체 맞춤으로 시작하고 구를 선택하게 한다.
- 결정 순회에서 동→구→서울→전국 구간은 동→구→전국으로 연결한다. 준비되지 않은 단계/안건의 기존 건너뛰기 규칙과 전국 이후의 기존 세계/지구본 경로·정거장은 유지한다. 서울을 정리하는 이번 변경으로 다른 정거장을 추가하거나 삭제하지 않는다.
- 기존 `seoul` 정거장에 속한 보충/올림 안건은 지우거나 완료 처리하지 않는다. 동일 안건 ID·이행/자원 소유를 보존해 **구 지도의 서울권역 공통 안건**으로 도착하도록 연결한다. 구 정거장 안에서 원래 동별 배분과 구 간 보충 안건을 구별한다. 실제 보충망의 새 규칙·재고 이동을 구현하라는 요구는 아니다.
- 지리적 주소/경로 설명에 ‘서울특별시’는 남길 수 있다. 시작 연출에서도 서울 범위를 지나갈 수 있으나 독립 잠금 단계·관리 버튼·필수 정차를 만들지 않는다.

지도/순회 enum의 기존 서울2·전국3 값은 삭제 후 당기지 않는다. 독립 서울 진입은 사용 경로에서 제외하고, 남은 내부 참조는 구 지도 서울 전체 범위로 읽는 호환 연결을 둔다. 지리적 서울 좌표·코드·원본 이름을 문자열 검색으로 일괄 삭제하지 않는다.

점검한 현재 `SaveEnvelope`에는 지도/배율/순회가 영속 저장되지 않는다. 이번 필수 범위는 같은 세션의 왕복 복원과 기존 음식/커널 저장 보존이다. 새 영속 지도 저장 형식은 추가하지 않는다. 다른 소비판의 서울 저장값이 발견되면 현행 계약을 확인한 뒤 호환 범위를 반환한다.

r174의 공통 시계·정지·일일 결산, 안건/명령·돈·인력·재고·주문·연구는 같은 원장을 유지한다. 지도 전환만으로 시간을 넘기거나 자동 결산/완료하지 않는다. r183의 자유 출발과 광고 입문·전국 광고망 구분도 유지한다. 기존 제안의 ‘이웃 구1곳/서울 안3구’ 등을 새 전국 해금 조건으로 채택하지 않는다.

## 4. 서울 전역 바탕과 상세 자료

현재 `hongdal-gu-space.json`은 동북권 약20.7×11.6km·서울9구 일부와 구리의10개 명칭/3구 초점 자료다. `SagajeongDispatch/seoul.json`도 도로0·개략 외곽44선·이름표1개다. 이 자료의 축소 하한만 내려서는 서울 전체가 채워지지 않는다.

서울25구 경계의 기존 후보는 다음 두 파일이다. 이번에는 새 수집/가공을 하지 않고 존재·지문·개수만 읽기 대조했다.

| 자료 | 이번 확인 | 적용 경계 |

개수 확인은 전체 도형 유효성이나 현재 Unity 연결 성공이 아니다. 후보를 저상세 바탕으로 재사용할 때 출처·판본·CRS/좌표 변환·원점·배율을 검증한다. 기존 동북권 상세와 위치가 맞아야 하고 전국 범위의 임의 늘이기로 대체하지 않는다. 원본/파생 지문은 인계에 고정한다.

표시는 **서울 전체 저상세 경계 바탕 + 자료가 있는 지역의 상세**로 나눈다. 구별 건물/골목/주문이 서울 전역에 확보됐다고 표현하지 않는다. 전체 바탕의 서울25구가 범위에 들어오면 이번 공간 목표를 충족할 수 있으며, 전 서울 정밀 도로·건물 수집을 선행조건으로 추가하지 않는다.

기존 `distributionApproved=false`·역사 후보/내부 검토 표시를 유지한다. 화면 출처/도움말에는 ‘2023 역사 경계 후보 · 상세 자료 지역별 상이’를 남긴다. 바탕을 못 읽으면 원인과 준비 상태를 표시하고 일부 동북권 자료를 ‘서울 전역 완료’로 대신하지 않는다.

## 5. Claude가 구현할 순서와 완료 조건

한 번에 지도 기능 전체를 다시 만들지 않는다. 기존 카메라 리팩토링(A1~A6) 담당과 같은 파일 쓰기 소유를 맞춘 뒤 다음 순서로 통합한다.

1. **진입 경로·순회:** 구↔전국 명시 연결, 서울 직접 진입/안내 제거, 기존 서울 안건의 구 지도 귀속과 enum 호환.
2. **서울 바탕·연속 축소:** 검증한25구 저상세 바탕과 상세 좌표 결속, 첫 맞춤/최소 배율 분리, 전체 포함·팬·화면 크기 대응.
3. **같은 세션 귀환·대조:** 전국 왕복 문맥 복원, 선택/업무/시간 불변과 일반 실행 화면 확인.

시안이 필요한 시각 배치는 기존 구 지도 스타일을 기준으로 [시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 구현 전에 대조한다. 이번 문서는 시안 이미지나 실제 화면 검증이 아니다.

| 확인 | 완료 기준 |
| --- | --- |
