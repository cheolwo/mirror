## 1. 현재 인지와 유지할 방향

기획에는 다섯 분야의 자유 출발·선택적 전문화/확장, 집중·이완 혼용, 동네의 한 행정동 집중, 구 지도 내 서울 전체보기/전국 직접 전환이 있다. 현실 달력/일일 결산과 연구·엔진 성장도 각각의 정본을 가진다.

실행판에는 배달/커널·지도·결정 순회 등의 부분 구현과 Claude의 진행 작업이 있다. 다섯 출발·테크트리·모든 역할 미니게임이 현재 실행판에서 완성됐다는 뜻은 아니다. 이 문답은 준비된 요소를 처음부터 어떤 순서로 경험하게 할지 정밀화한다.

유지할 것:

- 배달·카페·광고·전자상거래·무역 중 원하는 분야에서 시작한다.
- 한 분야를 깊게 계속하거나 타 분야로 확장한다. 배달→카페 등 하나의 강제 경로로 만들지 않는다.
- 직접 수행과 관찰/위임 어느 방식으로도 같은 경영을 이어간다. 첫 성장 목표를 이유로 참여 방식 하나만 강제하지 않는다.
- 동네를 보는 기본은 한 행정동에 집중한다. 모든 시작 분야를 면목동 배달 작업에 묶지는 않는다.
- 지도 시야·사업권·연구/도입·개인 숙련/경 유지·수익을 서로 구분한다.

## 2. 이번 확정 — 작은 일 한 건이 첫 성장 목표

지금 플레이어는 시작 분야를 고른 직후이고, 여기는 그 분야의 작은 작업 공간이다. 나는 아직 이 사업의 흐름을 익히는 운영자/참여자다. 상대는 구체적인 필요가 있는 고객/파트너와 한 건의 작업이다. 해야 할 일과 끝나는 조건을 읽고 직접 수행하거나 준비된 위임/관찰로 결과까지 이어간다.

처음부터 여러 매장·많은 주문·복수 사업의 완성을 첫 목표로 두지 않고, **작은 일 한 건을 끝까지 마치는 것**을 첫 성장 경험으로 삼는다. ‘한 건’의 정확한 업무와 시작 자원은 분야별로 후속 설계한다.

다음은 아직 선택하지 않은 분야별 첫 작업 **예시 후보**다.

| 분야 | 작은 일 한 건 후보 | 완결로 구별할 것 |
| --- | --- | --- |
| 배달 | 준비된 주문 하나를 픽업해 전달 | 추천/수락·픽업·전달·정산은 기존 상태대로 구별 |
| 카페 | 주문 음료 한 잔의 제조와 인수 | 레시피·재료·품질·인수 결과 |
| 광고 | 작은 가상 캠페인 하나의 대상/예산 선택과 첫 결과 확인 | 실제 외부 광고 집행이나 검색량 취득이 아님 |
| 전자상거래 | 준비된 주문 하나의 포장·인계 | 포장 완료와 배송/거래 전체 완료는 다름 |
| 무역 | 준비된 소량 거래의 조건/비용 검토 한 건 | 조건 검토 완료를 통관/국제 운송 완료로 표시하지 않음 |

각 작업은 상대의 필요와 약속을 실제 게임 결과로 확인해야 한다. 돈/성공을 첫 안내의 고정 보상으로 보장하지 않으며, 실패했으면 미완료 사유와 회복/다시 하기 경로를 제공하는 방향으로 정밀화한다. 정확한 실패/회복 비용은 미정이다.

## 3. 다음 성장을 연결하는 제안

추천 흐름은 **한 건을 마침 → 결과를 이해함 → 작은 개선을 고름 → 다음 일에서 차이를 확인함**이다. 첫 목표의 크기는 확정됐지만 아래 세부 표시/연구·해금 방식은 제안이다.

결과에는 기존 원장에 있는 보수/비용·소요시간·약속/품질을 사용한다. 근거가 있는 잘된 점 또는 개선할 점 하나를 먼저 보여준다. 모든 성공 뒤에 가짜 문제를 만들어 내지 않는다. 근거가 없으면 확인 불가/문제 없음으로 구분한다.

첫 개선은 작업 방식·준비·일감 선택·도움/도구·운영 방침 같은 작은 차이를 후보로 둔다. 한 건 완료가 연구·엔진 업그레이드·새 지도·가맹점을 자동 지급하는 계약은 아니다. 돈의 사용·연구/도입·성장 기록은 기존 승인 규칙과 연결할 때 확정한다.

익숙해진 뒤 작업의 다양성·동시 처리·반복 가능한 운영·선택적 확장으로 나아가는 큰 방향은 유지한다. 정확한 단계 수·횟수·성공률·자금·해금 조건·노출 순서는 아직 정하지 않는다. 직접/관찰 전환은 초반부터 가능하고, ‘나중에 위임을 배운다’는 이유로 이완 모드를 잠그지 않는다.

짧은 한 건을 끝냈다고 현실 날짜를 넘기거나 일일 결산을 새로 발생시키지 않는다. 학습/성장 진행과 현실 달력·보고 주기는 별개다.

## 4. 다음 질문 하나 — 첫 한 건의 부담과 안내

상태: `Asked`. 답변 전 확정하지 않는다.

**질문:** 첫 한 건은 **안내를 받으며 시간 압박이 적은 작업**으로 시작할까, 처음부터 **일반 영업과 같은 마감/실패 조건**을 적용할까?

- 추천: 안내가 있고 시간 압박이 적은 한 건. 배달 예시라면 매장 한 곳·손님 한 명의 픽업/전달을 따라가며 결과를 읽는다. 이는 첫 흐름을 설명하는 예시이며 배달 시작 강제가 아니다.
- 이유: 처음 목표를 이해하고 끝내는 감각을 얻은 뒤 복잡한 판단을 추가하기 쉽다.
- 대가: 초반 긴장감과 현실적인 여러 제약의 학습은 다음 작업으로 미뤄진다.
- 대안: 처음부터 일반 영업 조건. 운영의 판단/회복을 바로 경험하지만 초반 정보량과 실패 부담이 크다.
- 구현 결속: 안내/유예의 정확 조건·실패/재시도·보수/자금·원장·첫 시작 자원은 다음 문답에서 확정한다. 원장/시계/다른 업무를 조용히 바꾸지 않는다.

오행/괘·H/WI의 새 안정 ID는 부여하지 않는다. 현재 선택은 초반 정보와 작업 부담의 진행 설계이며 기존 업무/주체의 재사용과 결과 계약부터 확인한다.

## 확정·미정·인계

**확정:** 점진적 성장 흐름을 처음부터 논의하며, 선택 분야에서 작은 일 한 건을 첫 목표로 둔다.

**미정:** 첫 한 건의 안내/압박·분야별 실제 작업·시작 자원/소유·결과·회복·첫 개선/연구·후속 단계/해금 조건.

**인계:** `NotReadyToDispatch`. 이 새 성장 문답에 대해 제품 코드·새 구현 명세/Goal/WI·Graph Map·자료/DB·수집/예약·기존 Claude 작업/실행·commit/push를 변경하지 않았다.
