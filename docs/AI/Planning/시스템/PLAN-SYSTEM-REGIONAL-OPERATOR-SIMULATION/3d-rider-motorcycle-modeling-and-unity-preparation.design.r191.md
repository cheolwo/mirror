## 1. 첫 대상 — 배달통이 달린 생활형 스쿠터 한 종

**낮은 다각형 수의 스쿠터 본체 + 분리된 보온 배송함 + 탑승 기사 + 오토바이용 헬멧**을 첫 모델 조합으로 추천한다. 실제 차량 브랜드/로고를 복제하지 않는 가상 디자인이다. 현재 그림의 실루엣·민트/보라 구분과 회색 건물·남색 바탕에 맞는 재질을 출발점으로 삼되 최종 형태/배색은 시안 검토 대상이다.

- 지금: 기존 배달 업무를 직접 수행하거나 관찰하고, 카메라를 회전/확대해 기사를 보는 때.
- 여기: 같은 한 행정동의 도로. 위에서 보는 경영 시점과 근접/원근 보기에서 동일 객체를 읽는다.
- 나: 같은 기사·주문을 선택/조작하거나 위임해 보는 플레이어.
- 너: 차량·탑승 기사·현재 적재와 다음 목적지. 외형이 입체로 바뀌어도 기존 고유 ID·위치/업무 판본은 유지된다.
- 이렇게: 기사 선택→방향/적재/단계 확인→기존 조작 또는 관찰→현재 업무/지도에 복귀한다. 모델이 준비되지 않았거나 렌더가 실패하면 기존 표식으로 같은 대상을 읽고 원인을 확인한다.

이 외형은 판독과 몰입을 돕는 보조 층이다. 모델·바퀴·적재함·탑승 동작 자체가 전달/지급·성장·경 유지의 결과를 만들지 않는다. 괘·오행을 모델의 이동/성능 산식으로 추가하지 않는다.

## 2. 현재 확인한 것

WindowsGame의 `SagajeongDispatchMotorcycle.cs`는 `rider-b` Texture2D와 민트 변형을 `GUI.DrawTexture`로 그린다. 3D 배경을 보는 경우에도 이미지에 지면 방향의 변환을 적용하는 구조다. 따라서 모델 파일을 넣는 것과 이 표시 경로를3D 객체로 연결하는 것은 별도 작업이다.

프로젝트 설정은 Unity6000.5.6f1, URP17.5.0이며 현재 선언된 PC 품질/GraphicsSettings가 `PC_RPAsset`을 참조한다. 실제 실행의 재질/그림자·조명 상태를 이번에 새로 검증한 것은 아니다. 기존 오토바이 PNG와 Claude의 운영 회차 촬영 합성본을 보았으며, 이 확인은 현재 새 Game View 실행이나3D 모델 시안의 승인이 아니다.

기존5팩 기술 대장과 현재 `Assets/Synty`의 Prefab/FBX 이름·Prefab `m_Name`에서 오토바이/스쿠터 계열을 좁혀 찾았으나 본체는 확인하지 못했다. 형상 분석/임의 별칭 메시까지 조사한 것은 아니므로 보유하지 않는다고 단정하지 않는다. 대장 범위를 사용자의 전체 보유 범위와 동일시하지 않는다.

재사용 우선 후보는 **City 재킷 캐릭터**다. 원본 Prefab의 Avatar 참조·Animator/Humanoid 설정은 있으나 Controller/탑승 Clip은 준비된 것으로 확인되지 않았다. `importAnimation:0`과 빈 Clip 목록을 확인했다. Town 캐릭터는 예비이며 참조 Controller의 현재 대응 파일을 찾지 못했다. 실제 Avatar 유효성/현재 재질 렌더는 미검증이다.

상자와 배송트럭도 후속 소품/차량 후보로 확인했다. 일반 상자는 전용 보온 배송함과 다르며, 트럭은 첫 스쿠터 한 종의 제작 범위에 포함하지 않는다. 후보4개의 경로/GUID·파일 지문과 대장의 기존 Bounds 기록은 위 입력 색인에 내부 참조로 둔다. 기존 Bounds는 현재 재측정값이나 탑승 자세의 치수가 아니다.

## 3. 모델을 분리해 만드는 이유와 규격

| 구성 | 첫 제작/재사용 후보 | 제작 시 확인할 것 |
| --- | --- | --- |
| 차체 | 신규 생활형 스쿠터 | 본체·안장·발판·핸들/앞바퀴 조향부·앞/뒤 바퀴를 구분. 차체의 진행 방향과 바퀴 접지를 읽을 수 있게 |
| 배송함 | 신규 분리 소품 | 차체 뒤 연결 위치, 빈/적재 표식·필요 시 열림 표현. 상자 개수가 실제 주문 수량인 것처럼 보이지 않게 |
| 기사 | 기존 City 몸체를 우선 검토, 필요 시 독립 가상 몸체 | 손잡이·좌석·발판에 맞는 탑승 자세와 관절 관통. 사용권/원본 보존과 Avatar/재질 검토 |
| 헬멧/복장 | 주행용 헬멧·가상 작업 복장 | 원거리 실루엣과 기존 색 구분. Construction 안전모를 오토바이 헬멧으로 동일시하지 않음 |
| 연결 지점 | 모델/프로젝트 wrapper에서 명시 | 좌석·양손 그립·발판·배송함 부착·바퀴 회전 중심. 실제 이름/위치는 제작 후 측정 |

신규 모델은 미터 치수를 기록하고 바닥 접촉면·중심/피벗·전방/상방·회전/배율을 정한 뒤 export/import 왕복으로 확인한다. 목표는 프로젝트 지면 좌표/차량 진행 방향과 맞는 하나의 측정 가능한 기준이다. 기존 FBX의 단위/축을 보지 않고 일괄 배율이나 회전을 적용하지 않는다. [Unity 모델 가져오기 설정](https://docs.unity.com/en-us/engine/6000.5/manual/assets-and-media/asset-types/models/importing/fbximporter-model)의 단위/축 변환 항목과 실제 결과를 함께 확인한다.

모델 원본은 Blender 같은 편집 도구의 원본 파일, 전달은 FBX·재질/텍스처, 프로젝트 적용은 Prefab으로 나누는 안이다. 도구 설치/판본·실제 제작 담당은 미정이다. 특정 Blender export 옵션 값을 이번에 고정하지 않는다. 치수/피벗/연결 지점 표와 정면·측면·사선/실제 지도 구도의 검토 이미지도 함께 남긴다.

## 4. 같은 객체의 외형으로 Unity에 연결한다

기존 고유 ID·업무/위치 상태를 가진 주체 아래에 프로젝트 전용 외형 Root를 두고 그 안에 차체·기사·배송함을 조립한다. 원본 Synty Prefab/FBX/atlas는 보존하고 프로젝트 wrapper/변형에서 표현한다. 기술 이름은 기존 `VisualRoot`/표현 연결과 대조한 뒤 재사용하며 새 공통 계약에 유료 자산 경로를 넣지 않는다.

- 위치/속도/진행 방향은 기존 Core/Kernel의 위치·경로 상태를 읽는다. 모델의 Transform·RootMotion·차량 물리를 또 하나의 이동 권위로 만들지 않는다.
- 현재 기사 후보의 원본 `m_ApplyRootMotion`은1이다. 기존 경로가 이동을 맡는 적용에서는 wrapper/Animator 제어와 결속해 중복 이동을 막고 실제 대상 Rig에서 확인한다. 원본 전체를 일괄 수정하지 않는다.
- 바퀴·조향/기울임은 같은 이동 결과를 읽는 후속 표현 후보다. 준비되지 않으면 정적인 탑승 자세와 위치/방향·업무 표식으로 읽는 최소 표현을 허용한다. 임의로1인칭 운전 물리/충돌 규칙을 새로 넣지 않는다.
- 손·발/안장 맞춤과 [Humanoid Avatar](https://docs.unity.com/en-us/engine/6000.5/manual/assets-and-media/asset-types/models/importing/configuringthe-avatar) 매핑을 확인한다. Avatar 참조가 있다는 사실만으로 탑승·내리기·픽업 Clip이 준비됐다고 보지 않는다. Clip/리깅이 불일치하면 원인과 정적 자세 대체를 기록한다.
- 선택 영역/업무 상호작용과 모델 Renderer를 분리한다. 축척/모델 교체로 선택 ID·현재 작업·방향키/Space 입력·목록/귀환을 잃지 않게 한다. 기존 화면 선택과3D Collider를 중복 실행시키지 않는다.
- 적재 표식은 실제 픽업/적재 확인 뒤 바뀐다. 오토바이가 점포에 닿거나 동작이 끝났다는 이유로 인수/전달·돈/재고 변화를 실행하지 않는다.

3D 지도에서만 모델을 먼저 검토하고 기존 평면 보기의 표식/이미지는 같은 ID의 대체 표현으로 유지하는 안이다. 한 대상에 두 외형/선택이 중복되지 않게 한다. 새 공식 Scene이나 별도 게임 모드/상태 저장을 추가하지 않는다.

## 5. 지도에 맞는 가독성과 부담

위에서 보면 헬멧·차체 진행 방향·배송함이 먼저 읽히고, 회전/근접 보기에서는 차량 두께·안장/탑승·바퀴 접지가 보이는 형태를 추천한다. 과도한 작은 나사·내부 엔진·실사 질감은 첫 후보의 판독 요건에 포함하지 않는다.

실제 모델 치수와 선택 표식의 화면 최소 크기를 구별한다. 멀어질수록3D 모델을 계속 크게 키우기보다 단순 모델/표식으로 요약하고 구/전국에서는 r189의 건수/관계 표현으로 전환한다. 상세↔요약이 주체·경로·적재 상태를 바꾸지 않는다.

민트는 관리 관계/기존 기사 구분의 범례와 함께 사용하고 선택 테두리·단계 기호를 별도로 둔다. 건물 가림·그림자·도로/보행자·이름표/업무 패널을 함께 비교한다. 효과 기본 간단히를 유지하며, 모델의 실제 위치 변화와 장식 빛/잔상을 구분한다.

삼각형 수·재질/텍스처·동시 표시 수·LOD 전환값은 첫 모델과 현재 PC 시점의 실제 측정 뒤 결정한다. 근거 없는 성능/프레임 보장이나 전 자산 재질 변환을 제작 기준으로 삼지 않는다. URP에서 재질/색·오류 shader·그림자를 실제로 확인하고 source와 프로젝트 변형을 분리한다.

## 6. 제작물과 검토 순서

1. **외형 시안/간단한 입체 형태:** 기존 PNG·현재 지도와 같은 가상 기사 한 명을 기준으로 스쿠터/기사/배송함 비율·색·위/옆/사선 모습을 비교한다. 현재 실제 화면과 후보를 구분해 [시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)를 따른다.
2. **모델 제작물:** 편집 원본·FBX·재질/텍스처와 출처/사용권, 실측 치수/축·피벗/연결 지점, 필요한 정적 탑승 자세 또는 검증할 Clip 후보를 준비한다. 신규 모델링/리깅 작업 자체의 담당·범위도 정한다.
3. **Unity 한 대상 적용:** 기존 기사 한 명의 외형을 프로젝트 wrapper에서 연결하고 Renderer/Bounds·접지·재질·선택/현재 위치·단계/적재를 확인한다. 기존 한 건 배달·운영 회차와 동일 판본의 입력/결과를 대조한다.
4. **동작/수량 확장:** 실제 Rig/Clip·정지/출발/회전·중단/귀환, 복수 기사·원거리 요약을 검증한 뒤 다른 외형/트럭을 검토한다. 자동3D 지도 전면 교체나 전체 물류차량 제작으로 확대하지 않는다.

현재는 1단계에 들어갈 자료/규격 준비다. 모델 파일·새 시안 이미지·Prefab·배치 결과는 아직 없다. 기존 카메라 A6/도로·건물 B 조각은 Claude가 진행하는 소유를 유지하고, 이 표현 후보를 현재 작업에 조용히 추가하지 않는다. 실제 개발에는 승인 판본/hash·시안·필요한 전문 연구/주체/WI·E1~E7 명세·정확한 허용 경로와 담당 수용이 필요하다.

완료를 나누어 확인한다: 원본/내보내기 → Unity import/정렬/재질 → 실제 World 배치·선택 → 같은 위치/업무·입력/왕복·중단/귀환 → Game View 판독/성능. FBX 파일 존재·정적 대장·빌드 성공이 실제 탑승/이동·화면 검증을 대신하지 않는다.
