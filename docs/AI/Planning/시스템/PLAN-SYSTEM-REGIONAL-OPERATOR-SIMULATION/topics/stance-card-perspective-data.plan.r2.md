가상 사건은 시뮬레이션 시각으로, 지도 자료는 해당 원천 기준일로 읽는다. 같은 주문 문자열이 다른 회차에 반복됐으므로 회차·세션과 원 주문 ID를 함께 유지한다. 한 시점의 비교는 표시할 상태 사본을 고르는 방식으로 시험한다. 현재 시간의 관찰과 재연은 각각 기존 흐름에서 들어간다.

같은 주문 판본에서도 시뮬레이션 시각에 따라 픽업 확인 가능 여부가 바뀌었다. 비교 자료에는 조회한 상태 사본의 시각과 기록 범위를 함께 적는다. 안내의 실제 발생 시각과 조회에서 확인된 시점도 구별한다. 예를 들어 12:12 수신이 12:14에 기록으로 들어왔다면 12:12를 다시 비교할 때 그때 조회할 수 있던 정보만, 12:14에서는 확인된 수신 시각 12:12를 읽는다. 수신 확인의 의미는 전달 기록이며 사람의 열람은 별도 근거가 있을 때 읽는다.

## 한 장면에서 누가 무엇을 보는가

검토 장면은 사가정역 주변의 가상 음식점이다. 카드에는 한 주문과 그 입장의 첫 확인 질문 하나를 둔다.

| 입장 | 첫 문구 | 같은 기록 시점에서 우선 보이는 사실 |
| --- | --- | --- |
| 음식점 | 「이 주문을 건넬 준비는 어디까지 됐을까?」 | 기사 도착, 준비 완료, 기사 인계, 내가 보낸 안내의 수신 여부 |
| 배달 기사 | 「어디서 받고, 어떤 안내를 받았을까?」 | 본인 도착, 픽업 위치의 확인 범위, 본인에게 도달한 안내 |
| 주문자 | 「내 주문은 어디까지 왔을까?」 | 본인에게 도달한 진행 안내와 시각, 확인한 수령 기록 |

가상 검토 주문 H-028에서 12:11에 음식점은 안내를 보냈음을 보고, 기사는 수신 기록이 없어서 기존 정보를 읽는다. 12:12에 기사에게 도달한 안내를 표시하되 주문자는 자기에게 도달한 접수 안내를 그대로 읽는다. 12:14에는 음식 준비 완료가 확인되지만 12:15 인계까지 기사는 픽업 대기다. 배달 완료 기록과 주문자에게 도달한 안내, 수령 확인은 이어지는 세 순간이다. 「받은 안내 없음」은 해당 기간의 수신 기록을 읽을 수 있을 때와, 「안내 기록 미확인」은 기록 연결 상태를 알 수 없을 때 각각 사용한다.

**첫 표시의 추천안은 「기사 도착 · 픽업 전」이다.** 현재 기록만 쓰는 장면에서도 이 문구를 뒷받침할 수 있다. 가게의 준비 상태를 함께 보는 버전은 가상 예시에서 먼저 비교한다. 실제 장면에서 준비 중을 표시하려면 그 주문의 가게 기록을 연결한다.

## 픽업 위치 자료에서 먼저 확인할 범위

면목제3·8동의 인허가 관리키 390개를 건물·동과 대조했다. 하나의 건물과 동으로 연결된 후보가 315개, 같은 동 복수 건물 64개, 건물 경계 때문에 동이 둘 이상인 후보 11개다. 명시층과 소진공 층 표기가 맞으며 건물 총층수 범위에 드는 후보는 122개이고, 그중 1층 표기는 109개다. 현장으로 확인된 매장 픽업문은 0개다. 이 수는 판본이 일치하는 후보 수이며 실제 영업과 인계 위치는 확인 대기다. [층과 입구 조사](../../../../DataCollection/Research/2026-11-15-restaurant-floor-entrance-enrichment.md) · [이번 집계 재현](../../../../../../artifacts/local/hongdal-stance-pickup-review-20261123/pickup-place-count-evidence.json)

첫 화면은 기존 건물 카드의 공용 출입구와 건물 총층수 표기를 재사용한다. 음식점 입점층은 출처의 표기 층으로, 인계 장소에는 확인된 점포 안내 또는 승인된 현장 관찰의 근거를 붙인다. 지도 표식의 공개 대표점과 인계 위치는 별도 키로 유지한다. 실제 사례를 보완할 때 판본이 맞는 후보 중 한 곳의 **점포 → 보행 진입문 → 입점층 → 인계 위치**를 같은 시기에 확인한다. 문이 불명인 사례 하나도 같이 보아 참고 위치와 인계 표식이 각기 표현되는지 확인한다.

실제 점포를 확인할 때 수집할 항목은 점포·건물 식별자와 자료 판본, 보행 진입 종류, 점포가 쓰는 층, 인계 위치의 유형, 안내 또는 관측의 확인일과 이용 범위다. 입점 업체의 공개 찾아오는 길은 점포 안내의 한 후보이며, 픽업 용도는 표시 내용이나 점포 확인으로 좁힌다. 네이버의 등록 안내도 지도 핀과 선택형 찾아오는 길 정보를 별도 항목으로 둔다. [스마트플레이스 신규등록 도움말](https://help.naver.com/service/30026/contents/20366?osType=COMMONOS)

## 검수 기준과 문답

1. 같은 매장의 주문 두 건이 있어도 가게→기사→주문자와 복귀에서 원 주문과 조회 시점이 유지된다. 배정이 바뀌면 선택한 주문에서 새 담당을 알리고 이전 기사의 안내를 넘기지 않는다.
2. 가게의 발송과 기사·주문자의 수신 시각을 나눠 표시한다. 기록 부재와 기록 연결 미확인을 다르게 표현한다.
3. 준비 완료, 픽업 인계, 전달 완료, 수령 확인을 각각의 기록으로 읽는다. 위치 참고점은 픽업 성공 근거로 쓰지 않는다.
4. 왕복과 닫기 뒤 이전 지도 위치·확대·선택·모드가 복원되는지는 실제 화면에서 검수한다. 같은 경과 시간의 무열람 결과와 비교해 조회로 생긴 명령과 장부 차이가 없는지 확인한다.

**확정** · 한 주문의 첫 연구 순서와 기존 관찰·복귀 원칙이다.  
**미정** · 픽업 대기를 첫 장면으로 삼는 선택, 준비 기록과 수신 이력의 앱·원장 연결, 실제 점포 인계 장소.
