# 홍달 플레이스 게임 기획 점검표

2026-11-20 KST · 기획 점검표 r1 · 공통 검토 양식

[기획 트리](../../../../PLANNING.md#기획에서-화면까지)에서 가지 하나를 고르고, 한 장면이나 한 회차를 기준으로 체크한다. 게임 전체를 보려면 **처음 시작 → 첫 결과 확인 → 다음 회차 → 저장 후 돌아오기**를 대표 범위로 잡는다. [주제별 판본](README.md)에는 결정 원문을, [기획·화면 연결](planning-screen-tree.md)에는 화면 번호와 검증 근거를 둔다.

**기록 칸:** `주제·판본 / 역할과 상황 / 기존 화면 번호 / 비어 있는 결정 한 가지 / 확인할 장면`

체크는 기획에 답이 있고 어디에 적혔는지 가리킬 수 있을 때 한다. 임시값이나 제안만 있으면 `가안`, 선택이 남았으면 `미정`, 해당하지 않으면 `해당 없음`과 이유를 적는다. 화면 상태는 `시안 / 코드 확인 / 자동 촬영 / 실제 조작 검증 / 미확인`으로 따로 남긴다.

## 1. 모든 기획에서 먼저 볼 공통 항목

- [ ] **플레이어와 목표.** 누가, 어떤 상황에서, 무엇을 보고 이해하거나 달성하려 하는가? 시작했을 때 먼저 볼 곳과 원하는 경험을 한 문장으로 말할 수 있는가?
- [ ] **역지사지.** 같은 일에서 상대는 무엇을 알고 기다리는가? 그 사정을 알게 된 뒤 내 역할에서 무엇을 바꿀 수 있고, 상대가 실제로 받은 결과는 어디서 확인하는가? [역지사지 r1](../warmth-perspective-taking-and-shared-light.direction.r269.md#역지사지-r1--모든-업무에-적용하는-플레이-원칙)
- [ ] **반복할 흐름.** 어디에서 시작해 무엇을 고르거나 관찰하고, 무슨 결과를 본 뒤 다음 선택으로 이어지는가? 처음 보는 사람도 첫 행동을 알아볼 수 있는가?
- [ ] **행동과 규칙.** 가능한 행동, 그 조건, 게임이 결과를 확정하는 시점이 정해졌는가? 관찰·자동 수행·직접 확정의 역할과 적용 범위를 알 수 있는가?
- [ ] **선택과 대가.** 각 선택으로 얻는 것과 쓰는 자원·시간·처리 여력은 무엇인가? 잠시 기다리거나 맡기는 것까지 포함해 상황에 따라 고를 이유가 있는가?
- [ ] **결과를 알아보는 화면.** 조작 전에는 어떤 일이 일어날지, 조작 후에는 성공·대기·실패와 바뀐 상태를 읽을 수 있는가? 필요한 단서가 색이나 소리 한 가지에만 의존하지 않는가?
- [ ] **막혔을 때와 복귀.** 대상 없음, 취소, 지연 또는 실패 때 어떻게 되는가? 이유와 가능한 다음 행동이 표시되고 원래 보던 주문·가게·역으로 돌아갈 수 있는가?
- [ ] **수행의 끝과 다음 선택.** 완료된 일의 기록이 어디에 남는가? 그 결과로 다음 회차에 무엇이 달라지는지 알 수 있는가? 계속 관찰할 때도 상태 변화를 읽을 수 있는가?
- [ ] **검증할 장면.** 대표 상황 한 가지를 골라 `입력 또는 관찰 → 상태 변화 → 화면 표시 → 결과와 복귀`의 예상값과 확인 방법을 적었는가? 현재 확인한 근거와 아직 볼 것을 정확히 표시했는가?

Fullerton의 설계 요소에서 플레이어·목표·절차·규칙·자원·제약·범위·결과를 검토 항목으로 가져왔다. MDA는 설계한 규칙이 실제 플레이에서 어떤 행동과 경험으로 이어지는지 확인하는 데 썼다. 목표 판독, 버튼의 의미, 오류와 복구, 정보 표현은 Xbox 접근성 가이드에서 확인했다. 연속해서 관찰하는 게임에서는 장면의 결과나 회차의 끝을 먼저 확인할 수 있다. [Game Design Workshop 5판 3장](https://www.oreilly.com/library/view/game-design-workshop/9781003858447/xhtml/C_010_c3.xhtml) · [MDA 원문](https://www.cs.northwestern.edu/~hunicke/pubs/MDA.pdf) · [목표 이해](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109) · [화면 맥락](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/114) · [오류와 복구](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/115) · [여러 정보 전달 방식](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)

## 2. 해당 기능을 만들 때 추가로 볼 항목

- [ ] **시간·회차·저장.** 실시간과 턴이 언제 흐르는가? 정지·자리 비움·종료 후 어디서 이어지는가? 저장을 다시 열어도 이미 완료한 일이나 지급 기록이 한 번만 남는가?
- [ ] **자금·재고·성장.** 수입·비용·잔액·정산 시점과 수치의 단위가 정해졌는가? 돈이나 경험을 모으면 어떤 새 선택이 열리는가? 수치가 부족하거나 한도를 넘는 경우가 정해졌는가?
- [ ] **지도·공공자료.** 역·동·가게·주문이 어떻게 이어지는가? 출처·기준일·이용 범위, 현실 자료와 가상 값, 자료가 없는 장소의 표시가 정해졌는가?
- [ ] **여러 역할·자동 수행.** 각 역할이 무엇을 볼 수 있고 무엇을 확정할 수 있는가? 맡긴 일과 직접 개입 단계가 겹치거나 이미 끝났을 때 어떻게 이어지는가?
- [ ] **화면·입력·접근성.** 필요한 문구와 버튼을 실제 창 크기와 지원하는 입력 방식에서 읽고 조작할 수 있는가? 뒤로 가기와 주요 상태 표시가 알아보기 쉬운가? 안내를 다시 열 수 있는가?
- [ ] **부가 콘텐츠.** 이야기·음악·장식·광고·확장 사업은 어떤 장면에 도움을 주는가? 이용 여부가 선택인 기능이라면 사용하지 않고 기본 흐름을 어떻게 경험하는가?

플레이어가 보는 상황에서 직접 결과를 닫고 귀환하는 기준과 개발 단계별 검증은 기존 문서를 사용한다. [플레이어 중심 개발 업무 구조](../../../../../Architecture/플레이어중심게임개발업무구조.md) · [수직 검증과 안정성 증거](../../../../../Architecture/E1-E7수직폐루프와E8-E10수평증거체계.md)

## 3. 적용 예 · 배달 운영 r5, 사가정역 첫 주문

| 점검 항목 | 기획에 있는 것 | 빠져 있거나 검증할 것 |
| --- | --- | --- |
| 목표와 반복 | 주문 접수음 → 수락 방식 선택 → 기사 자동 배달 → 결산과 게임 자금이 첫 반복이다. | 등급별 보상액과 기사 모집 지출의 표시 기준을 정한다. |
| 선택과 규칙 | 엔진이 대상 기사에게 제안한다. 플레이어는 방향키 순서, Space 타이밍, 기사에게 맡기기 중 하나를 고른다. | 등급 조건을 정한다. 1.0 기본판에서 역 카드의 행정동과 주문·결산의 운영 범위를 일치시켜야 한다. |
| 화면과 복구 | 04 역 카드, 11-1 기사 화면, 14-1 결산의 기존 촬영이 있다. 미니게임을 닫으면 자동 처리로 돌아오는 안이다. | 시험 값인 역 카드를 게임 주문에 연결한다. 주문 없음·기사 없음·제안 만료·이미 수락된 주문의 표시와 복귀를 확인한다. |
| 결과와 검증 | 같은 주문의 수락과 결산 보상은 각각 한 번이다. 관찰에서도 기본 정산이 이어진다. | `04 → 지도 또는 11-1 → 14-1 → 04`의 같은 주문과 원래 역 복귀를 확인한다. 추가 지급은 정상 결산 때 한 번이고, 미참여·실패·저장 복원에서도 자동 처리와 기록이 이어지는지 확인한다. |
