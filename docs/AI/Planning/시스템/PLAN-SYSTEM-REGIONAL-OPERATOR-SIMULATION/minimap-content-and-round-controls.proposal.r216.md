## 2. 작은 공간에 담을 내용 세 가지

| 후보 | 채울 내용 | 좋은 점 / 대가 |

| B. 내 사업 연결 | 내 매장·거점, 선택한 한 업무의 픽업/전달 또는 공급 관계 | 사업의 연결을 읽기 쉬움. 밀집·관계선/실제 도로·대상ID 결속을 추가로 정해야 함 |

## 3. A안의 첫 내용 — 한 동을 읽는 작은 위치 안내

1. **집중하는 동 이름과 윤곽:** 현재 관리하는 행정동 하나를 가장 또렷하게 둔다. 이웃 동은 준비된 경계/위치 관계만 약하게 보이고 새 운영 안건을 강제로 펼치지 않는다.
2. **내 점포/선택한 대상:** 실제 운영 관계와 위치가 확인된 점포, 현재 선택 매장이나 회차 대상 정도를 표시한다. 전체 음식점·기사·군중·주문을 같은 강도로 찍지 않는다.
3. **현재 판/시야의 범위:** 첫 범위는 근거가 있는 선택 동/역 판 경계다. 실제 카메라와 지도 평면의 대응이 검증되면 ‘현재 보는 범위’를 추가한다. 원근/정사영·회전 상태를 고려해야 하므로 무조건 축 정렬 사각형으로 단정하지 않는다.
4. **화면 밖의 선택 업무:** 같은 기사/주문이 다른 동으로 이어지면 목적지 이름/방향을 보조한다. 화면 밖으로 갔다고 업무가 사라지거나 새 배달을 생성하지 않는다.
5. **짧은 복귀:** `내 동으로` 또는 `진행 중인 일로`는 해당 대상을 찾아 큰 지도로 이동하는 행동이다. 배차·발주·회차 마감/보상을 만들지 않는다.

새 지역의 도로·건물이 없으면 있는 자료까지 표시한다. **자료 미준비 / 게임에서 미진출 / 운영권 없음**은 다른 상태이며 같은 검은 안개로 합치지 않는다. 이동 대상이 준비되지 않았으면 이유를 알리고 기존 지도를 유지한다. 위치 미확인 점포를 임의 중심점에 놓거나 존재하지 않는 도로로 빈 공간을 채우지 않는다.

처음 만드는 범위는 현재 동의 작은 안내 하나다. 나중에 구/전국에서 같은 UI를 쓰면 현재 범위를 요약하되, 구 지도 안 서울 전체보기와 전국 전환을 구분한다. 세계/시설 내부 미니맵까지 이번에 만들지는 않는다. 내부 공간을 보는 동안에는 우선 ‘이 매장의 동네 위치’ 같은 지름길로 유지할 수 있다.

## 4. 위쪽 큰 버튼은 운영 회차를 맡기는 안

**추천은 실제 운영 회차의 버튼을 위에, 작은 위치 지도를 아래에 두는 구성**이다. 왼쪽 아래의 현재 회차 안내를 이 영역으로 옮기는 시안 후보이며, 별도 회차 체계를 새로 만들지 않는다.

| 회차 상태 | 위 영역에서 읽을 것 / 행동 |
| --- | --- |
| 준비 | 운영 시작/대상 선택의 기존 안내. 해당 실제 주문/작업이 무엇인지 표시 |
| 실행·관찰 중 | 현재 대상·진행/기다리는 이유. 아직 완료되지 않았다면 회차 마감 불가 |
| 대상 완료 확인 | **회차 마감**. 그 회차가 맡은 대상의 실제 조건을 확인하고 결과로 이동 |
| 결과 | **다음 운영 준비**. 다음 회차를 준비하며 새 작업은 기존 선택/수락 절차를 따름 |

처음 재사용하는 실제 대상은 r187의 배달 표본이다. 커피/창고 등으로 넓히려면 해당 작업·결과·귀환 계약을 결속해야 하며 이름만 바꿔 완료를 판정하지 않는다. 회차 마감 때문에 다른 모든 점포/장기 운송이 끝나야 하는 것은 아니다.

기존 결정 순회 도크의 배치/접기 틀은 표현 후보로 재사용할 수 있으나 **동작을 그대로 `Cycle.Press()`로 연결하지 않는다.** 다음 네 행동은 자리/이름이 가까워도 다른 계약이다.

| 행동 | 의미 |
| --- | --- |
| **다음 결정** | 다음 확인할 안건으로 초점 이동. 실제 상태에 결속되지 않은 시제품 안건을 실제 결품/문제 건수로 세지 않음 |
| **회차 마감 / 다음 준비** | r187의 실제 대상 결과와 해당 회차. 시간·금액·업무 완료를 대신 생성하지 않음 |
| **다음 작업** | r151의 선택 직무/현장에서 준비된 한 건을 사용자가 시작. 자동 작업 시작으로 바꾸지 않음 |
| **오늘 결산** | r174의 KST 날짜별 유효 기록 조회/확인. 현실 날짜를 넘기는 명령이 아님 |

따라서 큰 버튼을 곧바로 ‘턴 넘기기’로 이름 붙이기보다 **회차 마감/다음 운영 준비**처럼 현재 행동을 읽히게 하는 안이다. 버튼을 눌렀다고 커피5분·운송 납기·검사 대기·현실 날짜가 끝나지 않는다. 명덕·돈·수령/정산을 새로 만들지 않는다. 기존 결정 순회는 별도 역할/현재 검증 상태를 유지하고 통합 여부를 후속으로 정한다.

관찰만 할 때도 작은 지도/복귀를 사용할 수 있다. 활성 회차가 없으면 그 상태를 읽히게 하고, 버튼을 채우려고 일을 자동 수락시키지 않는다. 회차 버튼을 매번 눌러야 다른 정상 업무/세계가 움직이는 방식으로 바꾸지 않는다.

## 5. 왼쪽 매장 창과 함께 쓰는 배치

- **왼쪽:** r215의 선택 점포 운영 창. 기계/재료/인력 등 그 점포에서 내릴 결정.
- **가운데:** 현재 동의 큰 지도·선택 매장/기사·실제 진행.
- **오른쪽 아래:** 현재 위치와 회차 진행을 찾는 작은 고정 영역.

현재 오른쪽 상세/결정 카드와 도크는 겹칠 수 있어 영역을 단순히 덧붙이면 안 된다. 시안에서 작은 지도의 일정한 자리와 상세 카드의 최대 높이/접힘·스크롤을 함께 확인한다. 정확 크기·비율·표식 수는 아직 정하지 않는다.

작은 지도를 접어도 회차 안내/필요한 버튼을 찾을 수 있게 하는 후보를 둔다. 지도 대신 C 업무 요약을 고르더라도 업무·시간·결과는 동일하다. 음악/명덕 맥동을 모든 작은 표식에 복제하지 않고 판독에 필요한 상태만 표현한다. 간단한 표현/관찰 선호를 유지한다.

작은 지도의 클릭/드래그·버튼·스크롤은 뒤 큰 지도/왼쪽 매장의 배차·입점·구매로 전달되지 않아야 한다. 위치 이동도 의미가 분명한 범위에서 수행한다. 지역 전체를 클릭했다고 여러 동의 운영권/관리 초점이 자동 확장되지는 않는다.

ESC는 기존 설정 동작을 유지한다. 현재 Enter는 결정 순회에 연결돼 있으므로 새 회차 버튼에도 중복 배정하지 않는다. 새 단축키/입력 우선순위는 정확한 입력 명세와 실제 클릭·중복/모달 검토에서 정한다. 지도/회차 버튼 때문에 미확정 매장 초안이나 진행 중 작업을 초기화하지 않는다.

## 6. 첫 시안과 후속 확인

첫 시안은 **같은 한 동 화면에서 A 작은 위치 지도 + 위쪽 회차 마감/다음 준비**를 보여 주는 안이다. 선택 매장 하나·근거 있는 동/역 판 범위와 그 회차의 실제 대상만 사용한다. 확인되지 않은 viewport·실적/문제 숫자는 그려 넣지 않는다. 대조로 작은 지도를 접은 C 업무 요약 모습을 함께 검토할 수 있다.

새 이미지 생성과 실제 UI 구현은 하지 않았다. [화면 시안 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 Claude가 현 화면 기준 시안을 만들고 사용자 의견을 반영한 뒤 실제 상태/대상·범위/좌표·입력·판본/작업 명세와 쓰기 경로를 결속해 수용한다. 기존 Cycle/Round/지도 계층을 이름만 바꿔 통합하지 않는다.

현재 한 동의 위치/복귀와 실제 회차 상태부터 검토하는 범위이며 전체 지형/동네/사업망·새 세계지도 완성을 선행 조건으로 붙이지 않는다. 시안은 실행 증거가 아니고, 자료 지문/자동 검사도 실제 마우스·모달·화면 판독/복귀를 대신하지 않는다.
