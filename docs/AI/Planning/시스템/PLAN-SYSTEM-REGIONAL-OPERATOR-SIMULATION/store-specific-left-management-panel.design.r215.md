## 2. 동은 확장, 매장은 그곳의 운영

**동 관리에서 ‘어디에 무엇을 늘릴까’를 보고, 매장 창에서 ‘이 점포를 어떻게 운영할까’를 결정한다.** 동 관리의 지역 기사 고용과 매장 안 바리스타 고용은 별개다.

| 진입/문맥 | 주로 맡는 것 | 다음 연결 |
| --- | --- | --- |
| 동 관리·하단 사업 버튼 | 지역 인력/점포 현황·입점/확장·관리할 매장 선택 | 매장 목록의 같은 점포를 선택하면 그 점포 창 |
| 지도에서 내 매장 클릭 | 그 점포의 준비/영업·작업·재료/발주·설비·직원·실적 | 필요한 카탈로그/후보/절차·지도/내부 보기 |
| 전국/구의 내 회사·본부 업무 | 공급 계약/거점·회차·연결 점포 배분 방침 | 그 계약 아래 선택 점포의 발주·입고/사용 |

전국 지도에서의 경영은 **내 회사/본부의 전국 규모 공급 결정**이며 관세·검역 기준이나 국가 정책을 플레이어가 정하는 권한이 아니다. 점포 주문과 본부 전체 계약 변경도 다른 행동이다.

입점이 확정돼 점포 대상이 생겼으면 **개업 준비 중에도 매장 창**을 열 수 있게 하는 안이다. 설비/초기 원료/고용을 준비하고, 영업 조건이 갖춰지기 전 제조/판매를 준비 완료로 만들지 않는다. 자리 검토 중인 계획은 입점 초안이지 운영 중 점포가 아니다.

## 3. 왼쪽 창 구성 — 제안

기존 어두운 패널·민트 강조·금색 비용·접기/스크롤의 모습을 이어 쓴다. 기존 왼쪽 운영 현황/동 관리와 같은 자리에 **주 관리 창 하나**를 표시하며 세 창을 겹쳐 놓지 않는 안이다. 지도는 남기고 선택 점포를 강조한다. 선택 강조를 명덕 성장으로 읽히게 하지 않는다.

| 자리 | 내용 |
| --- | --- |
| 고정 머리 | `← 동 관리` · 매장명 · ×, 소재 동/건물·개업 준비/영업 상태·독립/가맹 등 운영 모델 |
| 작은 요약 | 지금 작업/대기·가용 직원/자리·재고 부족·예산/자금의 소유 범위. 미연결 값은0 대신 확인 상태 |
| 짧은 탭 | **요약 / 재료 / 설비 / 인력 / 이력** |
| 내용 영역 | 선택 탭의 목록→항목 상세/조건→해당 행동. 긴 목록은 내부 스크롤 |
| 결과/귀환 | 방금 확정한 대상·결과/거절 사유·다음 행동. 상세에서 `목록으로`, 다른 지도에서 `이 매장으로` |

처음에는 요약에서 ‘왜 운영이 막혔는가’와 바로 갈 행동을 먼저 읽는다. 예: 원두 부족→`원두 준비`, 머신 미설치→`설비 준비`, 작업자 없음→`직원 준비`. 실제 상태/원인이 있을 때만 표시하며 새 주문/직원/부족을 화면에서 만들어 내지 않는다. 정확 배치/크기·첫 탭/접힘은 시안에서 조정한다.

오른쪽 기존 건물 주소/배달 카드는 보조 정보와 기존 배차 문맥을 유지하는 후보이며, 새 점포 운영 행동의 주 진입은 왼쪽에 둔다. 전체 오른쪽 카드 기능을 이번에 삭제하지 않는다. `내부 보기`는 해당 공간이 준비됐을 때의 명시적 연결이며 카페 내부 모델이 이미 있다는 뜻은 아니다.

## 4. 네 가지 주요 행동

| 행동 | 점포 창에서 확인/선택 | 확정 뒤 읽을 결과 |
| --- | --- | --- |
| **기계 구입·설치** | 현재 장비/제조자리·품목·성능/호환·구입/운영 부담·공간/전기/급배수 등 필요한 조건·도착/설치 | 구매 계획→도착→설치/점검→사용 가능. 구입 버튼만으로 즉시 생산력 증가하지 않음 |
| **원두 국내 구매/직접수입** | 선택 메뉴/원두·로트/상품 단위·가용/예약/격리·오는 물량·부족 예상·수량/납기/비용 | 발주/약속→운송/입고→검수→가용 원료. 직접수입은 관련 담당/절차·전국 지도와 연결 |
| **가맹본부 주문** | 이 점포의 본부/계약·공급 카탈로그·허용 상품/수량·가격/희망일 | 같은 점포의 본부 발주/인계·입고. 본부 내부 이전과 외부 판매를 중복 합산하지 않음 |
| **점포 직원 고용·배치** | 바리스타 등 직무·후보/조건·비용/근무·시작 가능·현재 직원/제조자리 | 해당 점포 명부·고용/근무 시작·작업 배치. 동 기사 집계 증가나 실제 작업 완료로 대신하지 않음 |

공통 흐름은 **목록/후보 선택 → 수량·비용·시간/필요 조건 확인 → 명시적 확정 → 진행/결과·같은 매장 귀환**이다. 조회·탭/지도 이동만으로 지출/발주/고용이 확정되지 않는다. 준비되지 않은 계약/필드는 이유와 상태를 보여 주고, 다른 점포의 전역 명령으로 우회하지 않는다.

자금은 실제로 연결된 사업자금·본부자금·점포 예산의 소유를 표시한다. 아직 점포별 지갑/예산이 없는데 공용 자금을 ‘이 매장 현금’으로 이름만 바꾸지 않는다. 견적·지출 약속·지급·사용 원가·매출/수금은 구분하고 같은 비용을 여러 창에서 다시 차감하지 않는다. 수치/단위의 초기 기준은 r214를 참조하며 새 장비 가격/법정 기간을 이번 UI 기획에서 임의 추가하지 않는다.

### 운영 모델에 따른 재료 탭

- **독립 카페:** 국내 원두 구매를 기본 진입으로 두고 직접수입 검토를 연결한다. 본부 주문을 억지로 요구하지 않는다.
- **가맹 카페:** 해당 계약의 본부 발주를 주요 행동으로 둔다. 외부 구매/직접수입 가능 여부는 실제 가상 계약/역할에 따르며 모든 가맹점을 일괄 금지/허용하지 않는다.
- **직접수입 검토:** 점포의 수요·상품·예산 문맥을 가져간다. 필요한 수입 담당/준비·조건이 있으면 해당 계획으로 잇고 미준비면 이유/열리는 조건을 보여 준다. 지도 열람이나 매장 등록만으로 수입 준비가 충족된 것으로 보지 않는다.

점포에서 필요한 양을 주문하는 행동과 본부의 공급처/계약을 바꾸는 행동은 권한·영향 범위를 따로 읽는다. 수입/조달의 실제 확정은 준비된 Simulation 업무 계약에서 처리하며 화면에 새 권위를 주지 않는다.

| 일반 건물·다른 사람 점포·제휴만 된 음식점 | 기존 정보 조회/해당 권한 범위. 건물 소유/제휴를 점포 전체 운영권으로 간주하지 않음 |
| 동 목록/하단 사업 창에서 특정 매장 선택 | 지도 클릭과 같은 점포 문맥/창으로 연결. 별도 구매/고용 창을 복제하지 않음 |

현재 `ConnectStore`에는 선택 기사/대기 주문 조건에서 배정하는 효과가 있다. 새 매장창 열기에서 이 함수를 무조건 호출하면 안 된다. ‘일반 조회 / 배차 대상 선택 / 입점 자리 선택’ 의도를 구분하고 기존 플레이어의 배차 행위를 보존하는 정확 입력 명세가 필요하다. 단순 UI 함수 이름 변경만으로 처리하지 않는다.

창 안의 클릭/스크롤·모달 확인은 뒤 지도 선택/확대·배정에 전달되지 않게 한다. ESC는 최근 Claude 설정 화면의 열기/닫기 동작을 유지하며 매장창 닫기 키로 재정의하지 않는다. 설정을 닫으면 기존 매장 선택/초안으로 복귀하는 후보로 두고, 설정 아래에서는 매장/지도의 행동이 발동하지 않아야 한다.

## 6. 같은 점포의 초안·지도·작업 보존

머리의 소재 동과 현재 매장 자료는 선택 점포의 실제 연결에서 읽는다. 전에 보고 있던 동을 근거로 다른 점포의 재고/고용을 바꾸지 않는다. Core 매장ID·카페 장소ID·가맹점ID·건물ID의 명시된 관계를 쓰고, 좌표가 가깝다는 이유로 실제 점포/운영권을 생성하지 않는다.

공급처/수입/운송 노드를 열면 r197/r214의 관련 구/전국 지도에서 같은 대상이 강조된다. `이 매장으로 돌아가기`는 **같은 점포·상품·수량/조건·선택 노드·이전 지도/목록 위치**로 돌아온다. 지도를 바꿨다고 다른 매장을 자동 선택하지 않는다. 진행 중인 컵·발주·설비 설치는 창의 위치와 별도인 업무 상태다.

점포A의 미확정 초안을 남긴 채B로 이동할 때 수량·후보를B의 확정에 재사용하지 않는다. 초안은 대상별로 구분하고 같은 세션의 복귀에서 보존하는 안이다. 앱 재시작까지의 UI 초안 저장은 기존 저장 범위/새 계약을 확인한 뒤 정한다. 이미 확정된 주문/고용/지출을 뒤로 가기·×·탭 전환·재진입으로 취소/반복하지 않는다.

한 잔의 재료·300초 공정·직원/자리 점유·손실/비용은 r214의 초기 설계를 참조한다. 실제 시간/저장·직원 결속은 후속이며 이 창이 열린 시간이나 음악 반응을 제조/명덕 완료 근거로 쓰지 않는다. 공용 본부 정책을 바꾸더라도 기존 로트/확정 발주·시작 작업의 조건은 보존한다.

## 7. Claude 시안/첫 제작 후보

첫 시안은 **기존 가상 카페를 클릭 → 왼쪽 매장 창의 재료 탭 → 보충 발주 검토 → 결과와 입고 대기 확인** 장면을 권한다. 기존 카페의 재고/발주/검수/제조를 재사용할 수 있다. 새로운 설비·원두·고용은 요청한 메뉴/상태로 보여 주되 기존 우유 발주를 원두 공급이 이미 구현된 사실로 그리지 않는다.

현재 화면은 동 관리300폭 패널·지도·오른쪽 카드의 방향 촬영으로 확인했다. 위 명세는 새 UI의 실제 이미지/입력 완주 결과가 아니다. [화면 시안 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 Claude가 현 화면 기준 시안·정상/부족/진행/결과·귀환을 보여 주고 의견을 반영한 뒤 정확한 구현 범위를 수용한다. 이번에 별도 이미지/HTML/새 Scene을 만들지 않는다.

첫 제작 후보는 현재 카페 한 곳에 올바르게 고정된 매장 창과 기존 행동의 재배치다. 전체 다점포·직접수입·직원·설비 시스템을 그 재배치의 필수 선행으로 요구하지 않는다. 다만 둘째 카페를 표시하려면 **점포별 명부/상태·명령의 대상 결속**을 먼저 해결해야 한다. 존재하지 않는 점포별 재고/직원을 단일 전역 사본으로 채우지 않는다.

검토할 항목은 정상 클릭/명시적 배차·입점 선택, 동/점포 귀환, A/B 대상 분리, 미연결/부족/명령 대기/실패·재시도, 설치/입고/고용 준비와 완료 구분, 스크롤/설정 모달·좁은 화면, 중복 지출/소모 방지다. 이번 기록은 검토 명세 후보이며 실제 입력·제품 시험·E 승격을 선언하지 않는다.

## 8. 확정 / 미정 / 다음 질문 하나

**확정:** 내 매장 클릭→왼쪽 해당 매장 운영 UI. 그 매장의 기계 구매·원두 구매/수입·가맹본부 주문·인력 고용을 시작할 수 있는 구조를 기획한다.

**제안/미정:** 다섯 탭/첫 요약·세부 배치/더블클릭, 조회/배차/입점 입력 분기, 운영점포/직원·자금/계약 권한 결속, 실제 업무·저장/다점포 명세·시안/개발 수용. 기존 r214 수치 위임과 판본·현실 일일 결산/작업 시계는 유지한다.

**다음 질문 하나:** 첫 시안은 **‘카페 클릭 → 왼쪽 매장 창 → 재료/보충 발주’** 흐름으로 잡을까? 기존 동작을 활용하면서 새 매장 중심 구조를 가장 작게 확인할 수 있다.

이번에는 기획/색인·현재 작업/해당 현황만 갱신한다. 기존195개 기획·지원 JSON4개·README 보존 본문을 유지하고 관련 지문/링크·문서용 빠른 검증을 확인한다. 제품 코드/이미지·실행/빌드/시험·저장/DB/수집/예약·Graph Map/Goal/WI/E·전역 D·commit/push는 변경하지 않는다.
