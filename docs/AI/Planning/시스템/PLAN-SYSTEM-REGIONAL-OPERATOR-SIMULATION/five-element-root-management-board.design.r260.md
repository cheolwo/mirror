## 2. 최상위는 무엇을 하는 자리인가

**00 오행 총괄판은 전체를 읽고, 선택을 비교하고, 각 업무 화면으로 내려갔다가 결과를 다시 모아 보는 자리**다. ‘대통령’은 이 사용자 경험의 비유다. ‘장관’은 해당 업무의 정보·선택지·현장 결과를 담당하는 하위 화면의 비유이며 새 NPC 직책/자동 승인 규칙을 추가하지 않는다.

사업 화면에서 선택한 계획은 같은 계획 묶음의 일부로 총괄판에 보인다. 총괄판의 변화나 이유를 고르면 관련 거점·사람·업무 창으로 내려가 상세 근거를 읽고 수정한다. 결과를 보고 돌아오면 같은 대상과 계획을 이어 본다. [r259](top-down-screen-hierarchy.design.r259.md)의 선택 맥락·복귀 원칙을 재사용한다.

## 5. 선택 전후의 예측을 읽는 방법 — 제안

| 구분 | 판과 상세 창에서 보여 줄 것 | 구분할 근거 |
| --- | --- | --- |
| 현재 | 현재 범위·기준 시점의 현금/재고/인력/업무, 분류 근거 또는 실제 활동 분포 | 기존 상태 사본·원장·행위 기록. ‘없음’과 ‘미연결/모름’을 구별한다. |
| 선택 후 예상 | 아직 확정하지 않은 계획 묶음, 예상 방향/범위·비용·조건·영향 시점 | 같은 상태 판본과 계획 후보. 미래 결과이며 실적으로 합산하지 않는다. |
| 실행 후 실제 | 같은 계획에서 생성된 업무·실제 수행·지급/재고/기여 결과 | 같은 업무/행위 고유 식별자와 현재 상태. 예상의 달성·미달·대기/실패 이유를 읽는다. |

예측은 먼저 다음을 구별한다.

- **현재 계산 가능한 것:** 기존 미리보기의 비용·수량·실행 조건 등. 실제 실행 전에는 여전히 재검증이 필요하다.
- **조건을 둔 예상:** 교육 완료·배송 도착·가용 시간 등이 충족될 때 기대하는 처리 여력과 대기 변화. 기간·가정·오차/범위를 표시한다.
- **아직 알 수 없는 것:** 다중 선택 상호작용·연결되지 않은 주문/수요·가중치 등. 빈 근거를0이나 임의 점수로 채우지 않는다.

예를 들어 ‘기사 한 명의 채용·교육 계획’을 고르면 **단기 지출/교육 부담**, **교육 뒤의 처리 여력**, **필요한 주문·기존 기사/거점의 여건**을 함께 보여 주는 안을 권한다. 고용만으로 매출 증가를 확정하거나 새 인력이 즉시 모든 일을 처리한다고 예상하지 않는다. 이 예시는 시작 인원·모집 비용·교육 기간을 확정한 것이 아니다. 어느 오행에 얼마를 더할지는 기본 관점/산식 결정 후다.

오행 칸을 누르면 관련 계획 목록과 금액·인력·주문 등의 실제 단위를 함께 연다. 판의 모양만 보고 돈·처리 능력·명덕을 같은 수치로 해석하지 않게 한다. **오행 분류만으로 미래 결과를 계산하지 않고 기존 업무 규칙과 준비된 예측 모형이 근거를 제공**한다.

## 6. 실제 활동과 예상은 같은 누적값에 넣지 않는다

[오행 활동 발자국](../../../../Architecture/WI괘성분류체계.md)의 현행 기준은 실제 행위의 목·화·토·금·수 독립 누적과 조회 기간별 상대 분포다. 미확정 계획·Preview·계획 취소·중복 조회만으로 기여를 만들지 않는다. 실제 취소 업무가 별도 행위 기록을 남기는 경우의 분류는 해당 업무 규칙을 따른다. 같은 행위를 플레이어와 NPC·지사·동·전사 집계에서 중복 보상하지 않는다.

총괄판의 예상은 현재 상태 위에 별도 표시하는 안을 권한다. 실제 활동 분포와 예상 업무 부담/자원 영향은 구분해 표시한다. 독립 누적값이 차감된 것처럼 표시하지 않으며, 조회 기간이나 다른 활동 증가로 상대 비율이 바뀌는 것은 별도로 설명한다. 전체 활동0을 각20%로 가정하거나 계획만으로 명덕·수익을 적립하지 않는다. 상생·상극 등 관계 표시는 검증된 업무 인과/승인 해석과 연결하며 새로운 수치 효과를 임의로 만들지 않는다.

## 7. 계획·확정·현장 진행의 연결

12의 기존 계획 묶음을00에서 모아 보는 방향을 권한다. 하위 창에서 **계획 선택**을 하면 임시 계획과 예상이 갱신되고, 수정/취소하면 같은 항목을 다시 반영한다. 버튼을 열어 보거나 선택 대상을 바꾼 것만으로 계획·보상을 만들지 않는다.

r251의 **턴 전 수정 가능한 계획 → 턴 넘김 확정 → 실행·관찰**을 유지한다. 실제 확정은 기존 명령과 최신 조건 검증을 통한다. [업무 흐름 Runtime](../../../../Architecture/업무흐름Runtime.md#오행괘상-분류의-위치)의 분류는 실행 권한이 아니며 UI의 루트 위치가 상태 소유자를 바꾸지 않는다.

턴 후의 준비된 현장 수행은 그 시점의 유효한 업무로 다룬다. 루트 판을 거쳐야만 모든 픽업·검수·제조가 진행되는 추가 승인 절차를 만들지 않는다. 턴 후 새 경영 방향을 차기 계획으로 이월할지는 r251의 미답변 그대로다. 같은 현실 날짜의 운영 회차/일일 결산도 유지한다.

현재 세계가 진행돼 기준 판본·시간이 바뀌면 예상의 기준 시점을 표시하고 필요한 범위만 다시 계산하는 안을 권한다. 서로 자금·재고·작업자·시간을 공유하는 여러 계획은 개별 예상치를 단순 합산하지 않는다. 계획 묶음 검증/부분 실패/저장·복원은 구현 전 별도 명세가 필요하다.

## 8. 다음 시안·구현 준비의 좁은 범위

1. 확정된 기본 업무 대표 관점으로 첫 총괄판의 자료/표현을 정리한다. 이번 승인 상한은 루트 역할과 기본 관점이다.
2. 현재 대표 캡처와 같은 스타일에서00의 현재/예상/실제, 한 하위 창과의 왕복을 보여 주는 시안을 만든다. **접힌 총괄 띠 + 펼친 판**은 지도 관찰을 유지하기 위한 제안이며 크기/배치는 미정이다. 이번에는 새 이미지나 실제 화면을 만들지 않았다.
3. 첫 검증 후보는 기존 업무 한 건의 미리보기·계획·실제 결과를 모아 비교하는 경로다. 다중 사업 전사 예측과 모든 오행 산식을 동시에 구현하지 않는다. 정확한 첫 업무는 별도 선택한다.
4. 승인된 기획 revision/hash·관점/지표/예측 상한·담당/경로·WI 하나·E1~E7 논리/표현 명세를 결속한 후 개발 수용한다. Graph Map 영향은 기존 전체 경영/계획/대상/결과 관계의 `ReviewRequired` 후보만 남기며 원본·Goal을 직접 바꾸지 않는다.

## 9. 확정 / 미정 / 다음 질문 하나

**확정:** 오행판이 최상위 루트이며, 하위 업무 화면의 선택과 예상 변화를 모아 전체를 판단한다. 기본 관점은 **목=주문·화=음식점·토=배차·금=창고·수=배달/운송**이다. 업무별 화면은 각자의 상세 책임을 유지한다.

**미정:** 다섯 축의 측정치/가중치·음양 표현·예측 기간/모형·한눈에 보이는 범위·UI 시안·첫 검토 업무·구현. ‘오행판=대통령’이 자동 경영권/새 NPC를 승인한 것은 아니다.

### 답변 완료 — 기본 관점 (`root-board-default-perspective`, `Confirmed`)

질문은 첫 오행판을 주문(목)·음식점(화)·배차(토)·창고(금)·배달/운송(수)로 모아 볼지였다. 사용자가 「그래, 그런 식으로 한번 좀 정리를 하는 게 좀 좋아 보여.」라고 답해 이 기본 관점으로 정리한다. 실제 행위 분류와 프랜차이즈 r37 등의 별도 관점은 보존한다.

### 다음 질문 하나 — 첫 배차 비교 (`root-board-first-dispatch-comparison`, `Asked`)

**지금** 1호지사에 배정 대기 주문이 있고 비교 가능한 기사 후보가 준비돼 있다. **여기**는00총괄판과08배차 창이다. **나**는 지사 운영자, **너**는 같은 주문과 배정 가능한 기사다. **이렇게** 후보를 골라 기존에 확인되는 조건·안내를 비교하고, 확정한 같은 주문의 진행/결과를 다시 총괄판에서 읽는다. 후보가 없거나 비교가 불가능하면 이유를 표시하고 가상 후보/효과를 만들어 채우지 않는다.

업무 대표 관점에서는 주문(목)·배차(토)·배달/운송(수)을 이어 읽되 실제 한 번의 행위 귀속은 기존 분류를 따른다. 관계없는 오행까지 매 선택에서 증가시키거나 다섯 칸을 강제로 채우지 않는다.

**다음 질문:** 첫 검토는 「배달 한 건에 어떤 기사를 배정할지 고르고, 그 예상과 실제 결과를 오행판에서 비교하는 장면」으로 잡을까요?

**권함:** 이 장면부터 정밀화한다. 기존 주문·기사 후보·배차 미리보기·실제 결과를 재사용할 수 있다. **대가:** 처음에는 기존에 확인되는 후보·조건·상태만 비교하며 새 ETA·만족도·매출 효과까지 예측하려면 별도 모형/검증이 필요하다. 기사 채용의 비용·교육·효과와 r257 지사장 경로는 미정 그대로다. Graph Map은 기존 계획/배차/역할/같은 주문 결과 관계의 `ReviewRequired` 후보이며 원본·새 WI/Goal은 변경하지 않는다.
