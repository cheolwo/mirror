## 1. 기능을 더 열기 전에 진행의 문장을 하나로 만든다

**스테이지마다 경영 질문 하나를 맡고, 그 안에서 ‘계획 → 실행·관찰 → 결산’을 반복한다. 익숙해지면 같은 일의 조건을 바꾸거나 다음 책임을 선택한다.** 매 턴 새로운 사업을 의무로 추가하기보다, 이미 아는 일을 다른 여력·시간·예외 조건에서 판단하게 한다.

| 플레이어가 보는 말 | 맡는 역할 | 기존 개념과의 관계 |
| --- | --- | --- |
| 스테이지 | 지금 집중할 경영 질문·쓸 수 있는 도구·확인할 결과를 묶음 | 지도 높이/사업 소유/기술 버전이 아님. 같은 스테이지를 여러 턴 반복 가능 |
| 턴 | 계획과 결과가 이어지는 운영 한 주기 | 첫 연결은 기존 배달의 **가상 영업일 한 날**을 후보로 삼음. 정확 시간은 기존 캠페인과 대조 |
| 작업 | 배달·제조·피킹·포장·분류·상차 등 준비된 업무 한 건 | 한 턴 안 여러 작업 가능. `다음 작업`은 턴을 넘기는 버튼이 아님 |
| 지도/내부 보기 | 현재 경영의 장소·범위를 읽는 관점 | 확대·층 선택으로 스테이지·턴·참여 방식이 바뀌지 않음 |

설명용 스테이지 이름은 아래 4개를 제안하지만 새 저장 ID를 발급하지 않는다. 기존 `FoodCampaignStage`의 지역 확장 ID/결과를 공통 진행 이름으로 치환하지 않는다. Claude 로드맵의 개발 조각 ①~⑤, 하루의 시간대, 지도 높이도 각각의 의미를 유지한다.

## 2. 스테이지는 넓이보다 책임을 기준으로 묶는다

| 제안 스테이지 | 대표 질문 | 처음에는 접어 둘 것 | 결과를 보고 고를 다음 선택 |
| --- | --- | --- | --- |
| 한 일을 끝내기 | 이 일을 맡기거나 직접 수행해서 제대로 마칠 수 있는가? | 다른 사업의 일반 상세·비긴급 알림·복잡한 추천·전국 운송 | 같은 직무의 다음 일 / 이완 관찰 / 이번 턴 결과 |
| 제한된 여력으로 운영하기 | 여러 일이 겹칠 때 누구를 언제 어디에 둘까? | 재고·분류 설비·전 세계 자료의 상시 패널 | 같은 지역 재운영 / 여력·방침 개선 / 준비된 현장 책임 |
| 한 현장의 흐름 개선하기 | 어디에서 기다리거나 잘못되어 다음 인계가 막히는가? | 전국망 전체·불필요한 다른 직무 | 카페 또는 창고/센터 중 선택한 분야를 더 깊게 운영 |
| 거점 사이의 약속 조율하기 | 출발·도착·용량·복귀 약속을 함께 지킬 수 있는가? | 모든 물류센터/세계 공급망의 동시 개방 | 같은 권역의 다른 조건 / 준비된 광역 회차 / 기존 분야 유지 |

추천 입문은 이미 실행되는 음식 배달에서 시작한다. 이후에도 **배달만·커피만·포장만 반복하면서 해당 분야의 질문을 깊게 경험**할 수 있다. 카페를 해야 창고가 열리거나, 음식 배달/우유 사슬을 마쳐야 독립 센터가 실행되는 필수 사슬은 만들지 않는다. 별도 분야의 준비된 입문 시나리오를 고르는 안도 유지한다.

이 표는 플레이 안내의 깊이이며 `동네→구→전국`을 자동 해금하는 표가 아니다. 경영 스테이지에서 새 책임을 소개할 때 관련 지도/카드를 기본으로 보여주되 기존 관찰 접근권은 유지한다. 자료만 보는 사용자는 캠페인 성공 없이도 설치된 팩과 지도를 볼 수 있다. 준비되지 않은 직무/사업은 준비 상태로 표시한다.

초점 밖의 일반 상세를 접어도 긴급한 일·필수 예외와 해당 장소로 돌아가는 경로는 기존 공통 계약대로 유지한다.

## 3. 한 턴의 세 국면

| 국면 | 사용자의 행동 | 시간·상태 | 다음으로 넘어가는 조건 |
| --- | --- | --- | --- |
| 계획 | 오늘의 질문·예고된 물량·현재 인력/재고·진행 일을 보고 방침/준비된 계획을 선택 | 턴 경계의 **명시적인 공통 정지**를 제안. 후보/초안과 확정된 계획을 구별 | 유효한 계획 또는 기존 방침 유지가 확인되면 `실행 시작` |
| 실행·관찰 | 배달·제조·설비 흐름을 보며 준비된 직무를 집중 수행하거나 이완으로 맡김. 필요한 현장 판단은 같은 턴에서 처리 | 공통 시계가 진행. 미니게임·지도·층/자료 보기 때문에 다른 사업의 시계를 따로 멈추지 않음 | 정해진 마감/업무 경계를 만나 마감 처리로 진입 |
| 결산 | 선택과 실제 결과·비용/수익·대기·실패/회복·남은 일을 비교하고 다음 운영을 고름 | 확정 결과와 진행 중 잠정 집계를 구별. 최종 결산 가능 시 명시적 경계 정지 | 남은 일/필수 선택/실패 상태가 확인된 후 `다음 턴 계획` 또는 같은 질문의 후속 운영 |

계획과 결산의 경계 정지는 **혼합 턴에 추가할 기획안**이며 현재 Windows에 적용됐다는 뜻이 아니다. 지도나 자료 패널을 열 때 생기는 자동 정지와는 다르다. 기존의 일시정지 선택은 보존하고, 이완은 실행 국면의 자동 수행/관찰 방식으로 유지한다. 턴/스테이지 변경을 `SsalddelExecution:Mode`의 새 기술 실행 모드로 만들지 않는다.

### 마감이 진행 중인 일을 없애지 않도록 한다

현재 음식 캠페인은 마감 이후 진행 배송을 이어가며 다음 날 진입/건너뛰기에 제한을 둔다. 첫 연결은 이 동작을 보존한다. **진행 배송이 남았으면 ‘마감 정리 중’으로 실행을 계속하고 잠정 집계만 보인다.** 결산 화면 때문에 필요한 시계까지 멈춰 배송이 끝나지 않는 교착을 만들지 않는다. 이미 시작한 배송·처리 중 명령의 결과를 확인한 뒤 최종 결산 경계를 닫는다.

다만 기존 **3일차 방침 관문**은 진행 배송이 남아도 먼저 멈춘다. 이때는 해당 방침을 사용자가 명시적으로 확정한 뒤 같은 배송의 마감 정리를 이어간다. 공통 턴이 기존 관문을 자동 통과하거나 별도 방침 선택을 중복 생성하지 않는다.

미배차 주문의 익일 이월·실패 처리와 장기 화물의 다일 운송/부분 결산은 별도 명세가 필요하다. 이번에 자동 취소/완료·무료 보관·인위적인 하차로 해소하지 않는다. 첫 구현 후보에서는 기존 캠페인으로 결과가 닫히는 입력만 사용하고, 다일 화물은 그 경계가 준비된 뒤 붙인다. 장기 운송이 끝날 때까지 모든 게임 턴을 영구히 막는 방식을 공통 규칙으로 채택하지 않는다.

단계/턴/작업을 다시 열어도 주문·물류단위·정산·보너스를 새로 만들지 않는다. 저장/복원은 같은 턴과 국면·진행 업무·확정 명령을 이어가고, 반복 연습은 별도 시도에서 같은 입력 조건을 재사용한다. 같은 결과를 중복 보상하지 않는다. 오프라인 시간 따라잡기/수익은 추가하지 않는다.

## 4. 턴이 지날수록 ‘판단의 조합’을 넓힌다

처음에는 익숙한 일 하나를 유지하고 **새 판단 요소는 한 번에 하나씩 소개**하는 안을 추천한다. 이후에는 소개된 요소를 조합한다. 이것은 화면/학습 밀도 기준이며 개발 WI의 전역 WIP 상한이 아니다.

| 같은 분야의 운영 예시 | 이전 턴에서 유지할 것 | 새로 비교할 요소 |
| --- | --- | --- |
| 첫 정상 운영 | 준비된 업무·장소·기본 방침 | 누구에게 맡기고 결과를 어디서 확인하는지 |
| 대기가 생기는 운영 | 같은 업무와 결과 판정 | 지금 투입 / 준비 후 투입의 차이 |
| 여력이 부족한 운영 | 대기와 기본 약속 | 인력·설비가 부족할 때의 우선순위·보류 |
| 예외와 회복 | 기존 적격/안전·권한 제약 | 읽기 실패·품절·지연 중 분야에 맞는 예외 하나 |
| 조합 운영 | 이미 익힌 요소 | 자원·시간창·외부 조건의 제한된 조합 |

턴 수만 늘었다고 새 OS·지도·사건을 계속 강제로 추가하지 않는다. 예상 가능한 변화를 먼저 예고하고, 새 기능을 소개하는 턴에는 돌발 변수를 줄인다. 익숙한 정상 턴·재시도·회복도 남긴다. 난이도와 사건 빈도의 수치는 미정이다.

조건은 시나리오/시도·입력 팩/정책 판본·난수 기준과 결속해 같은 시도를 다시 열어 주문/사건을 새로 뽑지 않게 한다. 다음 턴의 예정량과 당시 볼 수 있는 후보만 보여주며, 숨겨진 미래 정보를 엔진 추천에 흘리지 않는다. 공개 통계 원문을 현재 주문/현장 사고로 바로 바꾸지 않는다. 공공자료 수집 예약은 게임 턴과 독립이며 팩 갱신이 진행 중 시나리오를 몰래 바꾸지 않게 한다.

### 처음 세 턴의 추천 흐름

별도 입문 시나리오에서 첫 턴은 기존 기사/매장의 배달 결과, 두 번째는 같은 장소의 픽업 대기와 여력, 세 번째는 운영 방침 비교를 연결하는 안을 추천한다. 기존 3일차 방침 선택을 재사용할 수 있는지는 현재 명세와 대조하고 같은 날 선택 화면을 두 번 띄우지 않는다. 이 예시를 적용하려고 사용자의 진행 중 3일차 저장을 초기화하지 않는다.

결과가 좋으면 다음 질문을 **선택할 자격**을 제안한다. 더 넓은 책임은 준비된 사업/자원·해당 분야 결과를 확인한 뒤 사용자가 선택한다. 이완 결과도 진행 근거로 인정하고 직접 조작은 기존 구간별 보너스와 구별한다. 단순 클릭 수·돈·턴 수만으로 모든 분야 엔진 역량을 올리지 않는다. 안전·적격·권한 검사는 처음부터 동일하다.

## 7. 실패·회복·선택의 보존

실패한 턴은 결산에서 무엇이 밀렸고 어떤 선택/제약이 원인이었는지 보여준다. 비용·정확성·납기·작업 부담과 실제 게임 수익을 함께 읽고 무조건 최대 처리량만 정답으로 삼지 않는다. 이후 같은 책임으로 계획을 바꿔 운영하거나, 독립 연습 시도에서 비교한다. 새 시도로 바꿨다고 본 진행의 이미 확정된 손실/보수를 되감지 않는다.

스테이지 전환은 기본적으로 결산 뒤 선택으로 제안한다. 진행 중 작업·작성 입력·담당/권한을 버리거나 새 사업을 자동 개업하지 않는다. 분야를 바꾸면 해당 준비 상태와 보존할 기존 운영을 먼저 설명한다. 이전 분야가 백그라운드에서 어떻게 이어지는지는 기존 허용 방침을 따르며 무제한 자동 개업/실운영을 허용하지 않는다.

상위 목적에서는 흩어진 경고를 한 질문과 결과로 모아 운영자의 이해와 회복 선택을 돕는 보조 층이다. 오행/괘·직접 회복·보상 효과는 이번 진행 이름에서 새로 추정하지 않고 기존 분야 기획과 연결한다.

## 8. 첫 검증 후보는 사업을 더 여는 대신 두 턴을 닫는다

다음 구현 **후보**는 기존 배달 한 지역·기존 주문/기사로 `첫 계획 → 실행/관찰 → 마감 처리 → 결과 확인 → 다음 턴 계획`이 이어지는 작은 흐름이다. 같은 대표 질문을 두 턴 반복하면서 방침 하나를 바꿨을 때 결과 차이를 읽는지 확인한다. 새 사업·상봉동 주문·직접 운전·물류센터 전체·전국 회차를 한꺼번에 요구하지 않는다.

이 후보는 기존 r162의 구 기사 여력 작업을 취소하거나 자동 선점하는 지시가 아니다. 공통 진행 틀의 우선 적용 여부·정확 결과/쓰기 소유는 후속 구현 계획에서 결속한다. Logic/Presentation·작업 명세·필수 연구·시각 검토·실행 범위가 준비되기 전에는 제품 코드를 바꾸지 않는다.

확인할 것은 계획 확정과 실제 수행 결과의 구분, 계획/결산의 명시적 경계 정지, 실행 중 공통 시계, 진행 배송이 남은 마감의 교착 방지, 다음 작업/다음 턴 구분, 같은 턴 복원/재진입 시 중복 주문·보상 없음, 이완 결과 인정과 실패 회복이다. 이 문서 작성이 해당 검증을 수행한 근거는 아니다.

## 9. Claude에게 넘길 시안 보완 입력

새 전체 화면을 여러 개 더 만들기보다 **기존 A 또는 B 한 화면의 같은 배치를 유지해 세 국면을 나란히 비교**하는 안을 요청한다.

1. 상단에 `현재 스테이지의 질문 · 운영 턴/일차 · 계획/실행/결산`만 간단히 둔다. 기존 가상 시각/배속/정지와 역할을 구분한다.
2. 계획에서는 오늘의 예고·선택한 방침·후보/대가와 `실행 시작`이 읽히게 한다. 정확 수치/기능 준비는 예시로 표시한다.
3. 실행에서는 같은 지도와 작업 대기열·집중/이완·긴급한 일을 유지한다. `다음 작업`은 준비된 한 건에만 연결한다.
4. 결산에서는 ‘내 선택→실제 결과→비용/대기/실패·남은 일→다음 운영’의 인과를 보여준다. 잠정 마감 정리 중과 최종 결산을 구별한다.
5. D는 전체/1층 상세의 가림 처리를 별도 비교하고 r164의 의미를 유지한다. 이 수정은 공통 혼합 턴의 첫 배달 시안과 동시 필수 제작 범위가 아니다.

시안6장의 원본/스크립트·Claude 제안은 보존한다. 이번은 새 이미지 생성·모델·제품 코드·Goal/WI·DB/예약·공용 E·commit/push 없이 본 진행 기획과 README/목차/현재 snapshot만 갱신한다.
