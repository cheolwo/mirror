## r309 시작 화면 세 단계

| 화면 | 플레이어가 보는 것 | 다음 화면으로 가는 기준 |
| --- | --- | --- |
| **1. 역할 선택** | 화면 전체에 역할 카드와 각 역할이 하는 일 한 줄, ‘선택’ 버튼. 카드를 고르면 고른 카드만 강조한다. | 플레이어가 선택 가능한 역할을 고르고 버튼을 누른다. 그때 선택 역할 기준으로 로딩을 요청한다. |
| **2. 로딩** | 선택한 역할 이름과 실제로 진행 중인 작업. 예시는 ‘시작 지역 지도 불러오는 중’, ‘역할 데이터와 업무 화면 준비 중’이다. | 해당 역할의 시작에 필수인 지도·초기 상태·표시 대상과 업무 UI가 준비된다. |
| **3. 지도** | 준비된 시작 지역 지도가 처음 열린다. 상단에는 선택한 역할과 핵심 수치가, 지도와 업무 패널에는 그 역할에 해당하는 내용이 나타난다. | 지도와 업무 화면을 조작할 수 있다. |

### 화면 전환 기준

- 역할 선택에 필요한 목록과 설명을 먼저 읽는다. 시작 지역 지도와 역할 자료를 읽는 작업은 ‘선택’ 버튼을 누른 뒤 로딩 화면에서 시작한다. 진행률을 계산할 근거가 없으면 진행 중인 단계 이름을 표시한다.
- 지도 준비와 역할 데이터 준비가 다른 시점에 끝나도, 둘 다 준비된 뒤 같은 초기 상태를 기준으로 지도·표시·업무 패널을 함께 연다. 예를 들어 **배달 플랫폼 본사**를 고르면 지사·배달권과 처리 여력이 첫 지도에 연결된다. **가맹점주**라면 내 점포와 대기 주문·재고가 먼저 보인다. [역할별 표시 예시 r308](#r308-첫-화면에서-지도까지) · [관점별 경영 패키지 r296](#r296-보존--관점별-경영-패키지-통합)
- 필수 자료를 불러오는 데 실패하면 로딩 화면에서 이유와 ‘다시 시도’·‘역할 다시 고르기’를 표시한다. 첫 확인은 확정 전 역할 카드만 표시되는지, 확정 후 로딩 화면을 거치는지, 준비 완료 뒤 선택한 역할의 지도가 처음 등장하는지를 순서대로 본다.
- 지도에 들어간 뒤 한 주문이나 출고의 상대를 잠깐 관찰하는 일은 기존 지도 안 관찰과 복귀 흐름을 따른다. [기존 관찰 전환 반환](../../../Handoffs/2026-11-16-Codex-역할관찰-중화모드-인계반환.md)

**확정** · 역할 선택, 로딩, 지도를 독립된 화면으로 순서대로 보여 준다. 지도는 선택한 역할의 준비가 끝난 뒤 나타난다.

**미정** · 첫 화면에 열어 둘 역할, 이어하기에 마지막 역할을 미리 표시하는 방식, 역할별 필수 자료 목록의 상세.

**다음 질문 하나** · 이어하기에서는 마지막 역할 카드를 미리 골라 둘까? 미리 골라 두되 ‘선택’을 누르면 같은 로딩 화면을 거치는 안을 추천한다.

## r308 첫 화면에서 지도까지

1. **입장 고르기.** 왼쪽 역할 카드에는 ‘누구의 입장인지’와 ‘처음 보게 될 일’을 한 줄씩 보여 준다. 카드 선택 시 같은 동네 미리보기에서 관련 지사·점포·경로만 강조한다. 첫 조각은 대표 카드 하나의 선택과 지도 연결로 확인한다.
2. **지도에서 시작.** 선택을 확정하면 상단에는 현재 입장과 그 역할의 핵심 수치가, 지도에는 주요 대상이, 업무 패널에는 그 자리에서 할 수 있는 일이 뜬다. 처음에는 핵심 수치 두세 개와 대표 업무 하나를 제안한다.
3. **입장 바꾸기와 복귀.** 지도 안 상단에 현재 입장과 ‘입장 바꾸기’를 보여 준다. 시작 입장을 바꾸는 경우에는 선택창을 다시 열고, 주문·출고에 참여한 상대를 잠깐 보는 경우에는 기존 관찰·복귀를 쓴다. 같은 주문을 볼 때는 주문 ID를 유지하고, 상대 관찰을 끝내면 원래 입장·대상·지도 위치로 돌아온다.

| 입장 예시 | 지도에서 먼저 보는 것 | 수치와 첫 업무 화면 |
| --- | --- | --- |
| **배달 플랫폼 본사** | 지사, 담당 배달권, 제휴점과 주문이 몰린 곳 | 할당한 세트·처리 여력·지연. 지사를 선택해 할당 현황 확인 |
| **가맹점주** | 내 점포, 주문 픽업 위치, 연결된 납품 거점 | 대기 주문·준비 예상·재고. 내 점포를 선택해 매장 운영 화면 확인 |
| **음식 배달기사** | 내 빛, 픽업지·전달지, 현재 주문 경로 | 픽업 준비·도착 예상. 해당 주문의 인계와 경로 확인 |
| **창고·물류 운영자** | 물류 거점, 출고 차량과 연결된 점포 | 출고 대기·예정 물량. 센터를 선택해 출고 현황 확인 |

표는 역할에 따라 무엇이 달라지는지 보여 주는 예시다. 첫 안은 **배달 플랫폼 본사로 시작 → 같은 주문에서 음식점·기사·주문자 관찰 → 원래 운영 화면 복귀**다. 독립 시작이 준비 중인 역할은 카드에 상태와 가능한 관찰 범위를 표시한다. 이어하기에는 이전 입장으로 돌아가는 선택을 제안한다.

입장 선택은 지도에 보일 정보와 업무 창을 정한다. 지도·게임 시간·주문·장부는 같은 세션에서 읽고, 실제 배차·발주 같은 확정은 해당 역할의 기존 권한과 별도 조작을 따른다. ‘직접 할지, 맡기고 볼지’는 기존 중·화 전환에서 고른다. [집중·이완 기획 r146](focus-relax-shared-management.design.r146.md)

첫 검토에서는 같은 주문을 본사·음식점·기사·주문자 입장으로 열어 화면마다 강조 대상과 수치가 달라지는지 확인한다. 상대를 본 후 원래 위치와 주문으로 돌아오는지, 전환이 턴 진행이나 주문·자금 변경을 일으키는 명령을 내보내지 않는지 확인한다.

**확정** · 게임 첫 화면에서 입장을 고르고, 선택한 입장에 따라 지도 데이터와 업무 화면이 달라진다.

**미정** · 첫 화면에 노출할 역할 수와 순서, 역할별 독립 시작 시점, 이어하기의 기본 동작.

**다음 질문 하나** · 이어하기에서도 바로 입장 선택창을 열까, 마지막 입장으로 계속하는 버튼을 먼저 둘까? 첫 화면에서 두 경로를 고를 수 있게 하되 ‘마지막 입장으로 계속’을 주 버튼으로 두는 것을 추천한다.

## r295 한 배달에서 상대의 사정을 보는 첫 장면안

점심에 같은 가상 주문의 준비가 늦어지는 장면부터 시험한다. 점주는 주문이 몰린 상황과 준비 예상 시각을 본다. 기사는 매장에 도착해 전달받은 안내를 보고 기다릴지 지사에 알릴지 판단한다. 주문자는 새 도착 안내를 보고, 운영자는 어느 픽업에 지연이 생겼고 지사가 지원이 필요한지 살핀다. 점주가 예상 시각을 알려 줬을 때 기사에게는 기다릴 시간을 판단할 근거가 생기고, 주문자에게는 기다림의 끝이 조금 더 분명해진다. 전달받지 못한 사유와 예정 정보는 확인 대기로 둔다.

1. **지금·여기.** 면목제3·8동의 가상 점포에 픽업 대기 주문 한 건이 있다. 주문을 열면 내 역할이 볼 수 있는 대기 이유와 다음 행동을 읽는다.
2. **상대 보기.** 같은 주문을 유지한 채 음식점·기사·주문자 중 한 입장을 선택한다. 상대가 받은 안내, 기다리는 것, 실제로 확인한 결과를 읽는다. 상대를 구경하는 동안에는 그 사람의 업무를 대신 확정할 수 없다.
3. **결정과 귀환.** 원래 지도 위치와 주문으로 돌아온다. 점주라면 준비 안내를 갱신하고, 운영자라면 필요한 경우 지사에 지원이나 조정을 제안한다. 실제 지연과 인계의 변화는 같은 주문 기록에서 확인한다. 관점을 바꾸는 행동만으로 경영 점수나 명덕이 달라지지 않는다.
4. **막힘과 확인.** 상대 쪽에 연결된 역할 기록이 없으면 확인할 수 없는 항목으로 남기고 원래 업무에서 계속한다. 같은 주문 ID·귀환 위치와 조회 전후 주문·장부 상태의 차이를 검사한다. 먼저 기존 가게↔기사 연결을 확인하고 주문자 진행·운영자 진입을 붙인다.

현재 기사 휴대폰의 ‘음식 준비 중’은 기사 이동 단계에서 고른 문구다. 음식점 화면의 수량 ‘1’도 고정 표시다. 이 둘을 실제 주방의 제조 진척·실제 주문 수량으로 연구 서술에 옮기면 잘못된 인과가 생긴다. 화물 대본의 화면 전환 간격도 현실 상차 소요시간의 근거로 쓰지 않는다.

## 3. 역할별로 무엇을 연구·서술할까

각 역할의 원고는 **지금 있는 곳 → 지금 하려는 일 → 직접 아는 정보 → 기다리는 것 → 가능한 선택과 대가 → 상대에게 건네는 것 → 일이 끝난 뒤**의 흐름으로 쓴다. 일상적인 정상 진행을 먼저 서술하고, 지연이나 부족이 생긴 하루를 같은 기준으로 비교한다.

| 입장 | 첫 연구 질문 | 관찰에서 보일 장면과 확인할 공백 |
| --- | --- | --- |
| 음식점·카페 점주 | 손님에게 약속한 주문을 언제 기사에게 줄 수 있을까? | 같은 가게에 주문과 기사가 오고 간다. 조리·포장·인력 배분은 해당 작업 기록과 연결해 설명한다. |
| 음식 배달기사 | 지금 어디로 가고, 도착해서 무엇을 확인하며 기다릴까? | 한 사람의 빛을 따라 픽업지→전달지→다음 대기를 본다. 주방 사정은 받은 안내나 확인 기록이 있을 때 알 수 있다. |
| 주문자 | 내가 주문한 것이 어느 단계이고 기다림이 달라졌는지 알 수 있을까? | 플레이스 검색과 선택은 기존 자료를 재사용한다. 접수·제조·배달 안내와 수령 경험은 아직 연구·연결할 부분이다. |
| 센터 현장 담당 | 어떤 물건을 어느 위치에서 꺼내 누구에게 인계할까? | 출고·수량·로트는 현재 자료를 읽는다. 개별 랙·스캔·피킹·포장·상차의 몸 움직임은 현장 절차를 조사한 뒤 장면으로 구체화한다. |
| 화물기사 | 내가 받은 짐을 어디에, 어떤 확인을 거쳐 넘길까? | 상차·운송·하차지 도착·검수 인계를 구분한다. 실제 운임·대기시간·기사 피로는 별도 근거가 필요하다. |
| 배달 플랫폼 운영자 | 누가 무엇을 기다리고 있고, 내가 바꾸면 누구에게 영향이 갈까? | 기존 배차와 운영 지표에서 시작한다. 고객·점포·기사에게 보이는 정보와 운영자만 볼 수 있는 정보를 구분해 연구한다. |

바리스타·피커처럼 같은 사업장 안에서도 서로 다른 일을 하는 사람은 후속 원고에서 나눈다. 별도 원고의 수와 작성 순서는 진행하면서 고른다.

연구에는 세 가지 근거를 붙인다. 현재 게임의 동작은 소스·같은 판본의 실행 기록으로, 현실 업무는 공식 절차·공개 업무 자료·범위를 확인한 경험 기록으로, 인물의 바람이나 속마음은 가상 서술의 설정으로 남긴다. 공공 인구·교통·시설 통계는 지역 환경을 설명하는 데 쓰고 특정인의 감정이나 선택을 단정하는 데 쓰지 않는다. 이번 원고는 프로젝트 자료 대조와 가상 장면 초안까지다.

## 4. 첫 서술 예시

**가상 장면 A.** 한 주문의 기사가 음식점 앞에 도착했고, 상품 인계는 아직 이루어지지 않았다. 아래는 같은 순간을 입장별로 쓴 원고 예시다. 상품 준비 상황과 인물의 생각은 연구용 설정이며, 일반판의 조리 상태를 관측한 기록이 아니다.

**음식점의 입장**

> 기사가 가게 앞에 왔다. 나는 지금 주문을 마저 확인하고 있다. 이 한 건을 서둘러 건네고 싶지만, 빠진 것이 없는지도 봐야 한다. 기사에게 어느 정도 더 기다려야 하는지 전할 수 있으면 좋겠다. 이 사람이 떠나도 나는 여기 남아서 다음 주문을 준비한다.

**기사의 입장**

> 나는 안내받은 가게에 도착했다. 안에서 얼마나 준비됐는지는 아직 알 수 없다. 먼저 내가 가져갈 주문이 맞는지 확인한다. 기다리는 이유와 얼마나 더 걸릴지 알면 다음 움직임을 생각하기가 쉽다. 물건을 받으면 나는 이 가게를 떠나 주문한 사람에게 간다.

**주문자의 입장**

> 주문한 것이 오기를 기다리며 다른 일을 하고 있다. 음식점과 기사가 지금 어떤 일을 나누어 하고 있는지는 보이지 않는다. 준비 중인지, 이동 중인지, 기다림이 달라졌는지 필요한 때 알 수 있으면 좋겠다. 도착하면 나는 내 물건을 받고 일상으로 돌아간다.

관찰자는 같은 가게에 계속 머물거나 그 주문의 기사를 따라간다. 세 원고를 읽는 순서를 과제로 두지 않는다. 이미 있는 기록으로 설명할 수 있는 장면부터 보여 주고, 다음 입장의 실제 연결이 준비됐을 때 선택할 수 있게 한다. 첫 원고를 이 배달 장면으로 할지, 직업별 하루로 할지는 제안 상태다.

## 5. Claude가 이어받을 때 확인할 경험

- 실행 중 아무 입력 없이 정상 업무와 날짜가 이어지는가. 관찰 중 지도 이동·확대·정보 열람만 한 경우에도 같은 방침으로 진행하는가.
- 같은 초기 상태와 경과 시간에서 관찰·설명 열람·역할 전환 자체가 주문·재고·금액·명덕을 추가하거나 누락하지 않는가.
- 회차 결과와 결산을 읽지 않아도 다른 정상 업무가 이어지는가. 아직 결정하지 않은 출점이나 발주가 임의 확정되지 않는가.
- 직접 참여를 끝내거나 맡기고 돌아왔을 때 같은 사람·주문·위치·진행 결과를 이어 볼 수 있는가.
- 음식점에 잠시 머문 관찰자가 기사가 왔다가 물건을 받아 떠난 변화를 알아차릴 수 있는가. 궁금하면 같은 주문 기록을 열어 확인할 수 있는가.
- 설명을 접어도 지금 하는 일과 기다리는 이유를 알아볼 수 있는가. 일반적인 대기는 조용한 상태로 읽히고, 관찰자의 무입력을 벌점 사유로 쓰지 않는가.

현재 맡김의 입력 감지와 역할별 조회는 보완 후보이고, 화면·저장·정산·자동 승인 범위는 제작실에서 기존 소유권과 계약을 대조한다. 연구 서술이 새 작업 절차·감정 수치·자율 승인 권한을 자동으로 만들지는 않는다. Graph Map 영향은 역할→보는 정보→연결 업무→상대→복귀와 직접/자동 수행 인계의 검토 후보다.

**확정** · 역할의 입장을 연구·서술한다. 켜 둔 세계를 편안하게 관찰하는 것이 충분한 기본 경험이고, 직접 참여는 선택이다.

**미정** · 역할별 연구 원고의 작성 순서, 선택적 정신 차림·보너스의 세부 균형, 사업별 자동 수행의 승인 범위와 예산, 제작실 수용·구현·실제 관찰 검증.

**후속 사용자 답변** · 첫 연구는 배달 한 건을 음식점·기사·주문자 입장으로 이어 읽는다. 위 r295에서 보존했다.

**사용자 방향.** 시작의 역할 선택 화면에서 여러 역할의 운영을 함께 볼 수 있는 입장을 고른다. 이 입장은 필요한 레이어를 각각 켜고 끄면서 같은 구 지도를 읽는다. 표시 이름은 **총괄 운영자**를 제안한다. [기존 역할 선택·로딩·지도 3단계](#r309-시작-화면-세-단계) · [관찰과 선택적 개입](optional-observation-and-intervention.design.r328.md)

### 들어가고, 보고, 돌아오는 흐름

1. **역할 선택 → 로딩 → 04 구 지도.** 시작 카드에서 `총괄 운영자`를 고른 뒤 로딩을 거친다. 지도 상단에 선택한 입장이 표시된다. 배달 플랫폼 본사 등 기존 역할도 각자 선택할 수 있다.
2. **레이어 버튼 → 오른쪽 패널.** 사가정역 또는 면목제3·8동을 선택한 채, 지금 보고 싶은 업무를 조합한다. 왼쪽 역 카드와 지도 위치를 유지한다. 다른 지역을 선택해도 켜 둔 종류를 유지하며, 현재 지역에 데이터가 부족하면 상태를 표시한다.
3. **대상 선택 → 상세 → 같은 지도.** 필요하면 선택한 주문의 음식점·기사 진행, 선택한 창고의 출고 상태를 자세히 본다. 상세를 닫으면 같은 동·시야·레이어 선택으로 돌아온다. 조회는 같은 게임 상태를 읽고, 발주·정산·고용 같은 확정은 해당 역할의 기존 화면과 권한을 따른다.

| 레이어 | 구 지도에서 읽는 내용 |
| --- | --- |
| **배달·주문** | 대기 주문, 지사 처리 여력, 기사 픽업·전달 진행 |
| **음식점·카페·가맹** | 운영 점포, 제조 준비·픽업 대기, 가맹점의 보충 필요. 우유 같은 개별 재고의 자세한 내용은 점포에서 읽는다. |
| **창고·화물** | 출고 대기, 배송 차량과 다음 인계 거점 |
| **플레이스·광고** | 집행 중인 키워드·노출 상태. 구 지도 연결이 준비된 범위부터 읽는다. |
| **인구·세대 등 지역 데이터** | 확인한 지역의 주민등록·세대나 유동인구. 출처·기준일·집계 단위를 함께 표시한다. |

가맹·무역·정산 등은 이 방식으로 연결이 준비된 현황을 추가한다. 같은 주문의 점포 준비와 기사 이동은 같은 주문의 서로 다른 상태로 읽는다. 범례는 업무 상태를 나타내는 게임 표식과 행정동 단위의 공식 자료를 구분한다. 면 채색은 한 공공 지표와 해당 범례를 써서 업무 표식을 배경 색에 묻히지 않게 한다. 역할 카드나 레이어 선택은 보이는 항목을 정하고, 지도에 보이는 사업의 소유권과 권위 상태는 기존 계약으로 읽는다.
