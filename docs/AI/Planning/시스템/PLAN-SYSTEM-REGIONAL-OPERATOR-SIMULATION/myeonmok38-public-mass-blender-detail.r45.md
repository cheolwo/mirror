## 1. 확정

면목제3·8동 전수 건물의 첫 표현은 사가정역 디오라마와 같은 공공데이터 기반 절차적 매스로 만든다. 모든 건물의 실제 외관 모델을 기다리지 않는다.

역·시장·아파트 단지·공공시설 등 생활상 판독에 중요한 건물은 정확한 공간 근거와 외관 자료 이용조건이 확보된 뒤 Blender 상세 모델로 점진 교체한다.

```text
공식 경계와 대상 건물 전수 판정
  → 공공데이터 기반 절차적 매스
  → 주소·PNU·높이·역할·출입 기준점 결속
  → 중요 건물 후보 선정과 근거·권리 검토
  → Blender 상세 모델 제작
  → 같은 건물 식별자의 VisualRoot만 교체
```

## 2. 공공데이터 기반 매스 기준

- 좌표계와 판본이 확인된 건물 윤곽을 사용한다.
- 높이·층수 자료가 있으면 출처와 기준시각을 보존한다.
- 높이 자료가 없으면 일반화 높이임을 별도 상태로 표시하고 실제 높이처럼 설명하지 않는다.
- 행정동 귀속, 주소·PNU 상태, 필지 자료, 출입 기준점과 건물 역할은 각각 독립 자료로 결속한다.
- 건물별 안정 식별자를 유지해 자료 갱신과 상세 모델 교체 전후를 추적한다.
- 공개·재배포가 불명확한 사진이나 도형은 Unity 배포 자산으로 사용하지 않는다.

## 3. 중요 건물 상세화 원칙

Blender 상세화는 전체 공간의 완성 조건이 아니라 후속 표현 개선이다. 후보는 다음 기준으로 선정한다.

- 역 출구·환승·방향 인지를 돕는 건물
- 전통시장 입구와 대표 골목처럼 생활 흐름을 설명하는 건물군
- 대형 아파트 단지·공공시설·학교·공원 경계처럼 원거리에서 위치를 구별하게 하는 대상
- 음식점·창고·지역 거점 등 승인된 생활 업무에서 반복 선택되는 건물
- 외관 근거·사진·라이선스·모델링 비용을 검토할 수 있는 대상

유명하거나 상업적으로 중요하다는 이유만으로 자동 선정하지 않는다. 실제 역할, 공간 판독 효과, 자료 품질과 이용조건을 함께 평가한다.

## 4. 교체 불변 계약

절차적 매스를 Blender 모델로 교체해도 다음은 바꾸지 않는다.

- 건물 안정 식별자와 행정동 귀속
- 주소·PNU·필지·출입 기준점의 데이터 계보
- 음식점·주거 전달지·창고 등 건물 역할 결속
- 주문·이동·선택 카드가 참조하는 상호작용 기준점
- 상태 사본 revision과 업무 권위
- 기존 Collider·Bounds·LOD·성능 상한의 검증 책임

Blender 자원은 건물 View의 `VisualRoot` 아래에 연결하는 교체 가능한 표현이다. 모델 이름이나 메시 구조를 서버 계약과 업무 식별자로 사용하지 않는다.

## 5. 완료 조건

- 면목제3·8동 전수 대상의 공공자료 매스 또는 `MissingCoverage` 판정이 재현된다.
- 실제 높이와 일반화 높이를 화면·계약·진단에서 구분한다.
- 중요 건물 후보마다 선정 이유, 공간 근거, 외관 자료, 이용조건, 모델 revision을 남긴다.
- 상세 모델 교체 전후에 같은 건물 선택 카드와 업무 결속이 유지된다.
- 전체·부분 Game View에서 위치 판독과 성능을 비교한다.
- 실제 자료가 없는 건물을 다른 지역 외관으로 꾸미거나 상세화 완료로 보고하지 않는다.
