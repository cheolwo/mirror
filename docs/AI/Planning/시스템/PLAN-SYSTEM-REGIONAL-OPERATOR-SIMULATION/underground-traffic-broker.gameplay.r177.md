## 1. 플레이 약속 — 두 경로를 고를 수 있다

지금은 가상 매장의 검색 노출이 부족한 오늘이다. 동네 지도에서 나는 운영 예산과 처리 여력을 가진 점주다. 정식 광고 도구와, 순위를 올려주겠다고 제안하는 트래픽 중개업자가 선택지로 있다. 누구에게 얼마를 맡길지, 효과를 보고 더 맡길지 멈출지를 판단한다.

**정식 광고는 광고 노출 기회를 사고, 중개업자는 일반 검색에 반영되는 관심 신호를 조작한다.** 중개 경로가 게임에서 실제로 순위를 올릴 가능성을 갖게 한다. 계약이 곧 성공 확정은 아니며, 상승 폭/기간·검증/제재·매장 운영이 결과를 가른다. 항상 효과를 0으로 처리하거나 모든 계약을 강제 적발해 사용자 방향을 무력화하지 않는다.

| 선택 | 직접 얻는 것 | 성과와 대가 |
| --- | --- | --- |
| 정식 광고 | 광고 표시 영역의 노출 기회 | 집행 비용, 광고 경쟁, 고객 적합성에 따른 전환 |
| 트래픽 중개 | 일반 검색용 잠정 관심 신호 | 계약 비용, 일시적 순위 상승 가능성, 납품 불이행·신호 제외·노출 제한 위험 |
| 매장 개선 | 정보/메뉴·품질·처리 여력 개선 | 준비 비용/시간, 실제 고객의 선택과 이용 경험 변화 |

같은 매장이 정식 광고와 중개를 병행할 수도 있는 안이다. 두 경로의 비용·신호·순위·주문 기여는 각각 추적한다. 상위 목적에서 이는 자원 배분·유혹·성과/위험을 비교하는 보조 경영 층이며, 중개 계약 자체에 개인의 경 유지/성장 보상을 붙이지 않는다.

## 2. 중개업자 NPC와 거래

중개업자는 가상 보유 풀의 규모, 납품 신뢰, 제시 가격, 과거 계약 결과를 갖는다. IP·계정은 그가 다룰 수 있는 **합성 접속 신원 집단의 자원량**을 뜻한다. 실제 주소/로그인 정보 대신 ‘가용 접속 규모’, ‘오늘 수용 가능한 계약’, ‘납품 이력’을 읽는다.

플레이어는 대상 매장·지역·검색 의도·의뢰 규모·운영 구간·비용 조건을 고른다. 세부 행동 운용은 NPC의 게임 능력으로 추상화한다. 실제 검색 서비스의 행동 순서·초 단위 체류·IP 교체/계정 운영 지침을 설정하는 도구는 만들지 않는다.

거래 흐름의 제안은 **제안 확인 → 비용/조건 확정 → 수행 중 → 납품 보고 → 효과/검증 확인 → 지속·중단·분쟁/회복**이다. 계약 수락, 비용 확정/지급, 납품 보고, 실제 반영은 같은 상태가 아니다. NPC가 보여주는 ‘1페이지 보장’ 같은 말은 그의 주장으로 표시하고 독립적인 게임 순위 결과와 비교한다.

선불/분할·환불·해약 손실·분쟁 처리·해금은 미정이다. 계약의 규모·유효기간·총 행동량과 집행 한도를 유한하게 두고, 반복 클릭으로 무한 자원/점수를 만들지 않는다.

## 3. 게임 검색 알고리즘이 영향을 받는 과정

```text
중개 계약과 비용
→ 합성 신원 집단의 조작된 관심 행동
→ 아직 검증되지 않은 잠정 관심 집계
→ 다음 고정 판본의 일반 검색 순위에 제한적 반영
→ 올라간 노출을 본 정상 수요 고객의 발견/방문/주문
→ 기존 매장·배차 모듈의 실제 게임 이행
```

조작된 관심과 정상 수요를 Simulation 상태에서 구분한다. 게임 내 검색 모델은 검증 전 신호를 일부 받아들일 수 있지만, Core는 출처·계약·반영 판본을 보존한다. 이렇게 해야 검색 서비스가 속는 장면을 만들면서도 실제 공공자료나 업무 원장을 위조하지 않는다.

r176의 중복 제한은 **같은 행위 기록의 재전송을 다시 세지 않는 것**과 **서로 다른 합성 신원의 조작 여부를 나중에 판정하는 것**으로 구체화한다. 동일 행위 ID는 즉시 중복 제거한다. 별개 합성 신원의 새 행동은 계정/기간별 기여 상한 안에서 잠정 집계될 수 있다. 중개 출처라는 이유만으로 처음부터 전부 0으로 처리하지 않는다.

의뢰 적합도·가용 규모·시장 경쟁·검색 규칙 판본에 따라 반영 효과가 달라지는 안이다. 정확 산식·상한·유효기간·반영/검증 시점은 미정이며 실제 네이버 공식을 뜻하지 않는다. 같은 세션 중 순서를 바꾸거나 현재 노출의 클릭을 즉시 재노출로 되먹이지 않는 r176의 판본 경계는 유지한다.

## 4. 순위 상승과 실제 게임 매출은 다르다

합성 계정의 열람은 고객·주문·매출을 직접 생성하지 않는다. 순위 상승으로 늘어난 노출을 **게임 내 정상 수요 고객**이 보고 매장을 선택해야 방문/주문이 생긴다. 같은 고객을 광고·일반 검색·중개 성과로 중복 계산하지 않는다.

예를 들어 일반 검색 3페이지의 가상 카페가 잠정 신호로 1페이지에 진입할 수 있다. 여기에 관심을 가진 고객이 늘어도 메뉴·가격·거리·대기 조건이 맞아야 주문한다. 재고나 바리스타·기사 여력이 부족하면 품절·이탈·지연이 증가할 수 있다. 이는 가상 상황 예시이며 순위 보장이나 고정 수치가 아니다.

따라서 ‘오늘 중개비를 더 지출할까’, ‘올라간 동안 고객 경험을 개선할까’, ‘실제 주문이 적으니 중단할까’가 의미 있는 선택이 된다. 정상 이행이 만든 만족/재방문 결과는 조작 신호와 별도 근거로 남긴다.

## 5. 지연 검증·대가·회복

가상 플랫폼 검증은 잠정 신호를 나중에 재평가할 수 있다. 비용·위험을 보여주되 효과와 적발을 항상 같은 확률/시간으로 강제하지 않는다. 계약 전에는 알려진 위험 범주와 예상 범위를, 결과 후에는 판정된 사유를 읽을 수 있게 한다. 실제 서비스의 검증 기준이나 회피 방법을 재현하지 않는다.

상태 후보는 **잠정 상승 / 효과 유지 / 검토 중 / 관련 신호 제외 / 노출 제한 / 회복 중**이다. 조작 판정이 나면 해당 계약의 신호를 다음 집계에서 제외해 일반 검색 순위가 내려갈 수 있다. 노출 제한의 범위·기간, 추가 비용/벌점 여부와 중복 제재 방지는 승인 전 미정이다. ‘중개비 손실’과 ‘추가 제재’를 같은 금액으로 두 번 차감하지 않는다.

검증으로 조작 신호를 제외해도 이미 정상 이행된 주문·정산을 되감지 않는다. 환불/보상이나 별도 업무 문제는 기존 원장의 사유·명령으로 처리한다. 순위 회복은 순위 1위로 되돌리는 뜻이 아니라 제한 해제와 현재 유효 신호에 따른 재계산이다.

회복 선택은 추가 의뢰 중단, 계약 종료/분쟁 확인, 매장 정보·실제 서비스 개선, 정식 광고로의 예산 전환이다. 페널티만 누적되고 다시 운영할 수 없는 막다른 상태로 만들지 않는 안이다.

## 6. 지도·화면·일일 결산

동네에서는 매장 카드의 **정식 홍보 / 중개 의뢰 / 유입·순위 결과**를 구분한다. 중개업자는 소개/연락 카드 등 인물 상호작용으로 만나며, 화면 배치와 자산은 후속 시안에서 정한다. 광고 순위·일반 검색 순위, NPC의 납품 주장·게임의 실제 결과도 구분한다.

구에서는 매장별 중개/광고 비용과 정상 고객 전환·처리 여력·검토 상태를 비교해 예산을 분배하는 후속을 제안한다. 중개업자의 IP·계정을 지도 위 사람 숫자로 직접 그리거나 공공 유동인구에 합치지 않는다.

r174에 따라 실행 중 게임 활동을 기록하고, 원장 항목별 기준시각을 KST 날짜로 읽어 일일 결산에 귀속한다. **계약비/지급, 납품 신호, 일반 검색 변화, 정상 고객 주문, 이행/정산 결과, 검증/회복 상태**를 따로 보고한다. 수익/비용과 현금 이동도 구별한다.

결산 열람·다음 페이지·재접속으로 추가 효과/차감을 만들지 않는다. 부재중 트래픽·순위 조작·광고 영업·벌금은 임의 계산하지 않는다. 캠페인의 자정/앱 종료 경계 처리는 r176과 함께 미정이며, 현재 세션/작업 판본을 보존한다.

관찰자 모드의 실제 음식점 정보에는 이 가상 순위·중개 의뢰·부정행위 평가를 붙이지 않는다. 실제 네이버와 실제 업체의 성과/행위를 주장하는 기능이 아니다.

## 7. 후속 기록·검증의 최소 조건

- 중개업자/계약 식별자, 합성 풀의 할당량, 비용·지급과 납품 보고를 분리한다. 같은 풀을 여러 계약에 무제한 중복 할당하지 않는 규칙은 후속 설계한다.
- 행위 식별자·합성 출처·잠정/검증/제외 상태와 어떤 순위 판본에 기여했는지 결속한다. 같은 행위 재처리는 중복 집계하지 않는다.
- 중개 의뢰가 일반 검색 순위에 실제 영향을 줄 수 있는 경우와 효과가 적은 경우를 모두 검토한다. 광고 칸 상승으로 대체해 일반 검색 효과를 없애지 않는다.
- 합성 열람과 정상 수요 고객의 주문·정산을 구분하고, 주 유입 경로 하나와 보조 경로를 따로 기록한다.
- 지연 검증·관련 신호 제외·노출 제한·중단/회복을 같은 계약 이력으로 이어 재진입/재확인에 따른 중복 차감·무한 보상을 막는다.
- 검증 전후의 이미 이행된 정상 주문 보존, 세션 판본 고정, 시간/날짜·실제 자료 경계를 확인한다.

이는 구현 전 검증 명세의 후보이며 새 DB·계약·코드·시험을 만든 결과가 아니다.

## 8. 확정 / 미정 / 다음 질문 하나

- **확정:** 정식 광고와 별도로 트래픽 중개업자 NPC와 합성 IP·계정 집단의 순위 개입 경로를 게임에 포함한다. 이전 r176의 단순 저품질 홍보 사건 후보를 이 방향으로 구체화한다.
- **미정:** 접촉/해금, 계약비·환불/분쟁·동시 의뢰, 잠정 신호의 반영/검증 규칙, 효과/기간·제재/회복, 첫 대상 매장·화면·개발 명세. 확정된 포함 방향은 이 수치들의 승인을 뜻하지 않는다.
- **다음 질문 하나:** 중개업자는 정식 광고를 한 번 경험한 뒤 소개로 만나게 할까? 추천 이유는 두 경로의 차이를 먼저 이해한 뒤 위험 있는 거래를 선택할 수 있기 때문이다.

문서와 진입부만 갱신했다. 제품 코드·Unity Runtime·공공자료/DB·실제 계정/트래픽·수집/예약·Goal/WI·E·commit/push는 변경하지 않았다.
