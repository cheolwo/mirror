## 1. 한 번의 스캔이 작은 손맛이 된다

선반의 물품을 집거나 입고 물품·포장 라벨을 확인할 때 현재 업무의 대상에 스캔 창을 연다. 창에는 대상 바코드, 작업 종류와 품목/단위/지시 잔량, 중앙 판독 대역을 고정해서 보여준다. 빨간 가로 레이저 선만 위↕아래로 움직인다.

1. 레이저가 중앙 판독 대역에 접근하는 것을 본다.
2. 선의 중심이 판독 대역 안에 들어왔을 때 Space를 한 번 누른다.
3. 타이밍 성공이면 선을 멈추고 `읽기 성공 · 확인 중`을 표시한다.
4. Core가 현재 작업·대상·수량 등의 유효성을 판정한다.
5. 올바른 대상이면 해당 업무의 스캔 확인 단계가 진행되고 다음 대상 또는 원래 작업 화면으로 돌아간다.

타이밍이 맞았다는 것과 올바른 상품·위치·수량이라는 것은 별개다. 읽기 성공 후 실제 업무 조건이 틀리면 `품목 불일치`, `위치 불일치`, `수량 확인 필요`, `이미 확인`처럼 이유를 표시한다.

## 2. 레이저·Space·피드백의 첫 안

| 요소 | 제안 규칙 |
| --- | --- |
| 이동 | 가로 레이저가 위에서 아래로 약 1.5초에 이동하고 반대 방향으로 반복. 실제 장비 속도가 아닌 게임 조정값 |
| 목표 | 바코드 표시 영역의 중앙 높이 약 20%를 판독 대역으로 표시. 선 중심이 대역 경계 안에 있는지 같은 시각 기준으로 판정 |
| 입력 | 스캔 창에 초점이 있을 때 새 Space 누름 한 번만 받음. 누름 유지·처리 중 연타는 추가 시도가 아님 |
| 창 진입 | 선반 상호작용 등으로 창을 연 Space는 읽기 입력으로 재사용하지 않음. 키를 놓은 뒤 새 누름을 받음 |
| 성공 | `읽기 성공 · 확인 중` 뒤 업무 판정 결과를 표시. 완료 표식·짧은 소리·문자를 함께 사용하고 색만으로 구별하지 않음 |
| 타이밍 실패 | `다시 맞춰 보세요`와 실패 위치를 표시. 약 0.5초 뒤 재시도하며 상품·재고·검수 상태는 바뀌지 않음 |
| 난이도 | 첫 안은 판독 대역 하나의 성공/실패로 시작. 속도·폭 조절은 후속이며 정밀 등급·다중 연속 타이밍은 추가하지 않음 |

레이저 위치·입력 시각·판정은 같은 회차의 시각을 기준으로 한다. FPS·입력 지연이나 창을 닫았다 열었다는 이유로 성공 판정이 달라지지 않게 후속 명세에서 시간 해상도를 확인한다. 일시정지는 r146의 공통 가상 시간 정책을 따르며 독립된 숨은 업무 시간을 만들지 않는다.

이 게임은 합성 작업 대상의 바코드 정보를 읽는 연출이다. 실제 카메라 디코딩·USB 스캐너·실물 입고 시스템과 연결된 결과로 표시하지 않는다. 스캔 창·타이밍 값·소리는 이번에 제작하지 않는다.

## 3. 피킹·입고·포장에서 같은 조작을 쓴다

| 업무 | 무엇을 확인하는가 | 성공 후 진행할 것 | 스캔만으로 하지 않는 것 |
| --- | --- | --- | --- |
| 피킹 | 지시된 선반 위치와 상품·로트·수량/단위·예약 | 해당 위치/물품 확인과 Core가 허용한 피킹 기록 | 다른 작업 물품 차감·전량 자동 피킹 |
| 입고 | 입고 근거와 도착 물품·로트·수량/단위 | 해당 입고 물품 식별·확인 기록 | 미검수 재고의 가용화·격리 해제·전량 적치 |
| 포장 | 집품 내용과 주문/용기·포장 라벨 | 해당 포장 대상 대조와 다음 포장 단계 | 포장재 검증 생략·상차·납품 완료 |

위치 바코드·상품 바코드·포장 라벨은 현재 단계에서 정한 서로 다른 대상 종류다. 같은 무늬가 보인다는 이유로 서로 대신 읽지 않는다. 읽힌 값은 현재 작업 고유 식별자·Revision·담당·품목·로트·수량과 대조한 뒤 해당 행위만 진행한다.

상품 바코드는 품목을 식별하는 정보와 연결하고 실물 하나의 고유 번호와 동일시하지 않는다. **같은 SKU 여러 개**는 서로 다른 실물/집품 처리 단위와 지시 잔량으로 확인한다. 동일 대상·명령의 재스캔은 수량을 더하지 않으며, 바코드만 보고 새 실물이나 수량을 만들어 내지 않는다. 처리 단위가 준비되지 않았으면 기존 수량 확인을 요구하고 한 번의 스캔을 무조건 1개로 세지 않는다.

검증과 상태 변경은 기존 Core가 소유한다. 레이저·효과음·녹색 표식·Space 결과만으로 영속 재고를 고치지 않는다. 읽기 성공 뒤 업무 검증 실패는 기존 정상 재고·예약·격리 상태를 보존하며 대상을 다시 고르거나 원래 작업으로 돌아갈 수 있게 한다.

## 4. 실패·중복·집중/이완 인계와 보너스

- 타이밍 실패는 비파괴 재시도다. 첫 안에서는 재고 손상·금전 벌금을 만들지 않고 소요 시간과 시도 기록만 남긴다. 잘못된 상품을 읽었다면 정상 품목으로 성공 처리하지 않는다.
- 같은 대상의 처리 중 입력은 잠그고 동일 명령의 결과를 기다린다. 이미 확정된 결과는 보존하고 늦은 응답이나 재진입으로 수량·완료를 다시 반영하지 않는다.
- 스캔 창을 닫으면 현재 작업·확인된 대상·집품/포장 수량을 보존한다. 이미 성공한 스캔을 재적용하지 않으며 미확정 타이밍 시도는 완료로 세지 않는다.
- 이완 요청은 r146/r147처럼 현재 시도의 확정 여부와 업무 상태를 확인한 뒤 자동 주체에게 인계한다. NPC도 같은 품목·위치·로트·수량 규칙을 따르되 사용자의 타이밍 입력을 흉내 내거나 직접 수행 보너스를 얻지 않는다.
- 다시 집중하면 미완료 대상부터 이어간다. 전환이나 창 재열기로 실패·시도·기존 확인 기록을 지우지 않는다. 집중/이완이 섞인 현재 상위 구간의 직접 완료 자격은 r146을 따른다.
- 스캔 하나·재시도 횟수·연타마다 별도 보너스를 지급하지 않는다. 해당 스캔을 포함한 **역할별 업무 구간 전체**의 직접 완료·정상 결과에 자격을 기록하고 해당 업무의 정식 완료/정산 뒤 보너스를 지급한다. 부모 구간과 하위 스캔에 같은 성과를 중복 보상하지 않는다.

## 5. 첫 검토와 인계 기준

첫 시각 검토는 r147 창고 한 주문의 피킹 대상 하나를 고르고 스캔 창을 여는 장면으로 제안한다. 초기 상황은 중앙 타이밍 성공·타이밍 실패 재시도·잘못된 품목·같은 물품 재스캔·같은 SKU 두 처리 단위를 구별하는 경우다. 물품의 실제 수량과 스캔 성공 수를 다른 값으로 표시한다.

[화면 시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 바코드·상하 선·중앙 대역·현재 작업·수량·Space 안내·판정/복귀가 보이는 시각안을 먼저 검토한다. 이는 실제 광학 인식·입출고·게임 입력의 검증 증거가 아니다. 기존 계약과 Claude의 현재 통합 기준선을 대조한 뒤 필요한 주체·WI 하나의 E1~E7 명세·쓰기 경로·검증 상한을 별도로 결속한다.

| 후속 검증 | 통과 기준 |
| --- | --- |
| 방향·판독 | 바코드는 고정, 가로 레이저는 상하 이동하며 중앙 목표와 Space 시점을 읽을 수 있음 |
| 입력·경계 | 대역 안/밖/경계, 왕복 방향, 키 유지·연타·창 진입에 판정/요청 중복 없음 |
| 비파괴 실패 | 타이밍/품목/위치 불일치가 재고·검수·격리 상태를 바꾸지 않음 |
| 수량·중복 | 같은 SKU의 서로 다른 처리 단위와 동일 실물 재시도를 구별하고 지시 잔량을 넘지 않음 |
| 업무 분리 | 입고 물품 확인·피킹·포장 대조가 각각의 승인된 단계만 진행하며 검수·상차·수령을 건너뛰지 않음 |
| 모드·재진입 | 처리 중 인계·창 닫기·저장/복원·늦은 결과에서 물품·확인·보너스가 중복되지 않음 |
| 보상 | 스캔 개수 대신 상위 구간 직접 완료 자격과 정식 정산 관문을 적용 |

이번 산출물은 문서·목차·현재 작업·r147 연결이다. 제품 코드·실제 바코드 장치/카메라·재고/API·시안/음성/영상·Core 계약·예약·Goal·새 D 결정·commit/push는 변경하지 않는다. 기존 우유 5팩과 Core 통합의 실제 구현 결과를 이번 미니게임 증거로 승계하지 않는다.

## 미정과 다음 검토 하나

상하 레이저·중앙 Space·입고/피킹/포장 활용은 사용자 방향이다. 속도 1.5초·폭 20%·재시도 0.5초와 첫 피킹 장면은 제안이며 실제 조작감·바코드 모양·소리·시간 해상도는 미정이다.

다음 검토 하나는 **레이저 속도와 중앙 판독 폭이 한 번 보고 타이밍을 맞출 수 있는 정도인가**다. 이번에는 시각안이나 실제 스캔을 만들지 않는다.
