## 최신 사용자 요청과 관계

사용자는 앞선 첫 플레이 제작 요청을 정정해 **주행 영상·디오라마·직접 플레이로 쌓는 시뮬레이션 경험을 하나로 연결하는 방안부터 제안**하도록 요청했다. 이번에는 코드·Scene·자료 연결·학습을 구현하지 않는다. [학습 환류 제안 r1](gameplay-experience-learning.proposal.r1.md)의 수익·배송 품질·참여자 보수 균형은 유지하고, 첫 구현 착수는 보류한다. 장래 Steam 출시 방향은 제품 구상이며 이번 공개·업로드·SDK 연동 승인이 아니다.

이 문서는 기존 [지역 운영자 기획](README.md)의 공간·관측·경험 연결 제안이다. 상위 기획·기존 승인 장면·WI·Goal을 바꾸지 않는다. 게임 기획과 운영 AI 학습은 r1에서 정한 두 소유 경계를 유지한다.

## 하나의 동네를 세 방식으로 이용한다

세 개의 독립 자료실을 만드는 대신 **같은 도로·교차로·매장을 중심으로 실제 기록 보기, 공간 둘러보기, 가상 업무 플레이를 오갈 수 있게** 제안한다. 기존 자료를 합쳐 복사한 새 원장이 아니라, 판본이 있는 관계표를 둔다.

| 이용 방식 | 하는 일 | 새로 쌓이는 기록 |
| --- | --- | --- |
| 실제 주행 보기 | 같은 도로의 확인된 영상 구간·촬영일·방향·밝기를 확인 | 실제 원본 관측, 위치·도로 후보의 보완 근거 |
| 디오라마 둘러보기 | 대응 도로·교차로·공개 매장 외관과 공간 관계를 확인 | 검토된 공간 표현과 원본 근거 참조 |
| 같은 동네에서 플레이 | 가상 주문·기사·작업의 상황을 보고 허용된 선택을 하고 결산 | 선택 당시 정보·행동·가상 결과·사용 공간 판본 |

예를 들어 지도에서 한 도로 구간을 선택하면 관련 영상 목록, 그 구간의 3D 장면, 같은 공간의 시나리오를 함께 찾는다. 플레이 도중에도 공개 근거가 있는 지점을 선택해 실제 주행 컷을 볼 수 있다. 정확한 프레임별 위치가 없는 구간은 관련 참고 영상으로 표시하며 게임 카메라와 실제 영상의 실시간 위치 일치로 꾸미지 않는다.

첫 목표는 익숙한 동네에서 현장 모습을 보고 선택의 영향을 체감하는 것이다. 간판·선분 검토는 선택적 보완 경로이며, 계속 정답 라벨을 입력해야만 게임이 진행되는 구조로 만들지 않는다. 기존 전체 조망과 선택 추적 UI를 재사용하고 새 공식 Scene을 만들지 않는다.

## 공통 연결표의 최소 구조

```text
기존 지도 판본·선분·교차로 + 확인된 매장/공간 참조
  ├─ 원본 SHA·실제 PTS·검토 범위·방향·촬영 조건
  ├─ 디오라마 RoadStableId/공간 ID·geometry hash·근거 판본
  └─ Scenario/공간 기준 판본 → Session → Decision → Task → Effect
```

1. **장소를 가리키는 관계:** 도로명 문자열 전체가 아니라 특정 구간·방향·연결 노드·지도 판본을 쓴다. 지도 `JN-S...` 코드와 Unity `RoadStableId`는 서로 다른 체계이므로 판본·근거를 가진 다대다 대응표로 잇는다. 같은 이름이라는 이유로 ID를 합치지 않는다. 매장도 같은 브랜드의 다른 지점을 합치지 않는다.
2. **영상 참조:** 선분 하나에 여러 촬영일·방향·시간대·계절의 컷을 허용한다. 같은 영상이 여러 선분을 지날 수 있다. 원본 전체나 후보의 공통 관측창을 선분마다 복사하거나 시간을 균등 분할하지 않는다. 실제 PTS·기존 컷·보호창·현재 승인 범위를 보존한다.
3. **공간 표현 참조:** 기존 geometry·Scene·카메라·Synty 자산에 출처 관계를 연결한다. 실제 영상은 참고 자료이며 공개 텍스처·정밀 3D 복원·통행 허가가 자동으로 되는 것은 아니다.
4. **회차 기준 동결:** 플레이 시작 때 사용한 지도·공간·규칙·현실 참고 조건을 고정한다. 지도나 모델이 바뀌어도 과거 영상의 PTS를 늘이거나 지난 게임 결과를 새 조건으로 다시 해석하지 않는다. 이후 판본 전환은 별도 대조·재현·검토 대상으로 둔다.
5. **관측과 결과의 출처:** 실제 영상에서 관찰한 도로 모습, AI 위치 추정, 검토된 공간 사실, 게임의 가상 이동/성과를 별도 상태로 남긴다. 게임에서 잘 통과했다는 이유로 실제 도로 통행이나 운영 배차를 승인하지 않는다.

고객 상세주소·동호수·연락처는 이 공간 관계표나 배포용 게임 자료로 복사하지 않는다. 원본 비공개 분석과 공개 가능한 3D·영상 컷을 분리하고, 공개용 후보는 기존 공개 검수·권리·보호 절차를 거친다. 열린 검토 창·원본·Premiere 컷/마커·사용자 승인 DB를 이 제안으로 초기화하거나 새로 만들지 않는다.

2026-10-25 읽기 조사. 원본 미디어를 새로 분석하거나 Unity를 실행한 결과가 아니다.

## 첫 제안 단위

사가정·면목 일대에서 **현재 원본·지도·공개 근거를 대조할 수 있는 짧은 도로 구간과 매장 주변**을 후보로 삼는다. 정확한 구간은 후속 설계에서 최신 검토 근거로 선정한다. 여러 지역이나 339개 전체 연결을 첫 플레이의 선행조건으로 두지 않는다.

1. 같은 구간의 실제 영상과 지도 위치를 함께 확인한다.
2. 그 공간의 기존 Synty 디오라마를 열어 이동·조망한다. 아직 모르는 부분은 간략 표현/미확인으로 남긴다.
3. 같은 공간의 가상 음식 주문 한 회차를 관찰하고 선택 가능한 업무 한 가지에 참여한다. 직접 선택 기능의 추가 범위는 기존 정책·현재 계약과 별도 설계한다.
4. 수익·배송 품질·참여자 보수와 선택 결과를 보고, 사용한 공간·조건·행동 기록으로 되돌아갈 수 있게 한다.
5. 잘못된 위치나 부족한 근거를 발견하면 기존 검토 절차에 보완 후보만 남긴다. 게임 진행·점수가 승인 기록을 대신하지 않는다.

창고·마트·화물·생산은 같은 공간 참조와 경험 기록 규약으로 확장하되 각 영역의 독립 플레이와 업무 결과를 먼저 검증한다. Farm→Hub→City를 첫 필수 연결로 삼지 않는다.

## 학습으로 이어지는 두 환류

- **공간 보완:** 새 주행 영상·사용자 검토 → 확인된 도로/장소 관측 → 디오라마 표현 보완 → 같은 동네를 더 잘 이해하고 플레이. 가상의 통과 성공으로 실제 공간 근거를 만들지 않는다.
- **운영 판단 보완:** 당시 공간·업무 조건과 선택·가상 결과 → 적격 자료 검토 → 미사용 평가와 현실 관측 비교 → 제한된 운영 추천 후보. 현실 결과는 허용된 별도 자료로 기록해 작업 시간·수요 등의 Simulation 가정을 보정한다. 모델 추천은 실제 실행·성과로 기록하지 않는다.

게임 성과는 사용자 답변대로 수익·배송 품질·참여자 보수를 함께 본다. 각 축의 수치 가중치·최소 기준은 미정이다. 게임을 즐기는 기능과 학습 기여 동의를 분리하고, 장래 공개 사용자 자료의 수집·보관·철회/삭제 정책은 출시 전에 구체화한다. 실제 모델 학습·운영 적용·Steam 배포는 이번 작업에서 하지 않는다.
