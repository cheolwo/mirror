## 2. 플레이어가 처음 경험할 반복

**동 선택 → 사람들이 찾는 키워드 확인 → 내 점포의 검색 위치 확인 → 제공 정보나 운영을 하나 개선 → 실행·관찰 → 다음 결과 비교**를 권한다.

첫 시험은 면목제3·8동 한 곳, ‘카페’와 ‘라떼’ 두 검색 의도와 플레이어 점포 1곳·명시적인 가상 경쟁점으로 제안한다. 특정 동·키워드·경쟁점 수는 이번 설계자의 추천값이다. 기존 한 동 집중 방향을 유지하고, 검색 결과를 위해 다른 동의 매장을 몰래 끌어오지 않는다.

처음에는 게임 점포가 실제 판매 중인 라떼의 검색 태그를 보완하는 선택이 적합하다. 라떼 검색의 적합도는 달라지고 일반 카페 검색 순위는 그대로일 수 있어 키워드별 효과를 비교할 수 있다. 판매하지 않는 메뉴 태그를 무제한 추가하면 순위가 오르는 규칙은 만들지 않는다. 인력·제조 개선이 완료율과 지연에 영향을 주는 경영 연결은 해당 기존 업무가 실제로 결속된 뒤 확장한다.

## 3. 인구에서 검색을 만드는 규칙

~~~~text
검증된 동별 인구·활동 프로필 + 시간대 + 게임 시나리오
  → 처리한 시간구간의 잠재 고객 기회
  → 검색하지 않음 / 홍달 플레이스 검색
  → 검색 의도·키워드 선택
  → 후보와 순위가 고정된 검색 세션
  → 결과 노출 / 이탈 / 매장 열람
  → 주문 의향 → 기존 주문 경로의 요청·수락·완료·정산
~~~~

화면의 군중은 같은 환경을 표현하는 별도 결과다. 사람 모형·빛의 수, 줌·레이어·효과 설정은 검색량을 바꾸지 않는다. 모든 잠재 고객을 실제 인구와 일대일로 생성할 필요는 없으며, 첫 판은 고객 집단과 재현 가능한 가상 세션으로 계산한다.

첫 모형은 한 기회가 해당 구간에서 검색하지 않거나, 검색 의도 하나와 검색 세션 하나를 갖도록 단순화한다. 따라서 잠재 기회 = 비검색 기회 + 검색 세션이며 키워드별 검색량의 합은 전체 검색 세션 수와 같다. 실제 고유 사람 수라는 이름은 붙이지 않는다. 재검색을 도입하는 후속 판에서는 검색 횟수와 가상 고유 고객 수를 따로 센다.

| 입력 | 첫 연결의 제안 |
| --- | --- |
| 주민등록 인구 | 검증된 거주 규모가 있을 때 독립적인 기준으로 사용한다. 미취득 값은 미준비로 둔다. |
| 추정 유동인구 | 원래 기간·집계 단위의 상대적 활동 지표로 사용한다. 분기 총계를 오늘의 사람 수나 검색 횟수로 나누어 확정하지 않는다. |
| 시간대·요일 | 검증한 열의 의미와 범위에서만 선택한다. r200의 시간대/요일 합계 불일치 원인은 여전히 미해결이다. |
| 게임 기본 기회·검색 성향·키워드 비중 | 별도 판본의 시험 수치다. 실제 검색 통계라는 표기를 하지 않으며 동 간 비교 조건을 보존한다. |

주민과 유동 지표를 단순 합산해 총 고객을 만들지 않는다. 동 코드·기준 경계가 맞지 않으면 해당 공간 적용을 보류하고 이유를 읽는다. 첫 계산은 원천 동의 상대 변화 검토이며 현행 경계 안의 실제 인구 분포를 확정하는 작업이 아니다.

검색 사건은 기존 시뮬레이션이 **아직 처리하지 않은 활성 시간구간**을 진행할 때 생긴다. 운영 회차 마감·창 열기·다음 결과 조회만으로 새 구간이나 새 수요를 만들지 않는다. 저장에는 처리 구간, 자료/정책 판본, 재현 seed와 진행 위치를 함께 보존한다. 같은 seed·구간·판본의 재실행과 저장 복원은 같은 사건으로 복원한다. 부재중 구간은 r174에 따라 추가 영업으로 채우지 않는다.

기회 예산은 고정된 모형 시간구간마다 한 벌만 배정하고, 그중 허용된 활성 경과에 비례해 소비한다. 소수 잔여·처리 위치와 기회 일련번호를 저장한다. 고객 선택의 재현값도 프레임 번호가 아닌 구간·기회 번호에 결속한다. 같은 활성 경과를 한 번에 처리하거나 여러 Tick으로 나누거나 저장 후 이어도 합계와 사건이 같아야 한다. 시간대별 기본 예산을 Tick 호출마다 다시 주지 않는다.

현행 캠페인의 가상 영업시계와 원장 기록의 현실 시각은 구별한다. 기존 동 수요는 긴 시각 도약에서 끝의 최대 60초만 집계하는 코드이며, 검색 모형에서 건너뛴 구간 전체를 보충하면 두 모형의 수요가 달라진다. 첫 연결은 같은 활성 Tick 구간만 소비하는 방향을 권한다. 현실 날짜별 보고는 사건의 실제 기록 시각으로 묶고 캠페인의 ‘다음 영업일’을 현실 내일로 표기하지 않는다. 시계 통합은 이번 검색 기능에 포함시키지 않는다.

## 4. 키워드와 검색 기록

키워드는 표시 문자열과 안정적인 의미 ID를 구별한다. ‘면목 카페’의 지역 조건·카페 의도와 ‘사가정역 카페’의 역세권 조건은 각각 보존한다. 동과 역세권을 같은 경계로 취급하지 않는다. 첫 판은 자유문 전체를 이해하는 엔진을 만들기보다 준비한 지역×분류·메뉴 의도를 읽는다. 동의어 표도 판본으로 관리한다.

| 기록 | 최소 보존할 의미 |
| --- | --- |
| 검색 세션 | 세션 ID, 가상 고객 집단, 발생 시각/시간구간, 동·검색 범위, 키워드 ID, 자료·모형 판본 |
| 검색 결과 | 세션이 읽은 색인/점수 판본, 후보 수, 정렬된 게임 점포 ID, 점수 요소와 제외 이유 |
| 노출 | 세션·점포·일반/광고 슬롯, 실제 본 페이지·슬롯과 시각 |
| 열람·주문 의향 | 해당 노출/점포와 연결된 사건 ID, 가상 고객 행동 상태 |
| 주문 연결 | 실제로 결속된 기존 주문 ID·요청/완료 상태. 의향만 있는 경우 주문 ID를 꾸며 넣지 않는다. |

후보 0건인 검색도 검색량 1회다. 같은 세션의 2페이지 이동은 새 검색이 아니며 같은 결과 새로고침·뒤로가기도 검색량을 더하지 않는다. 노출은 세션·점포·슬롯 종류별 고유 노출과 반복 조회를 구분한다. 플레이어가 직접 검색하거나 자료를 확인하는 행위는 가상 고객 검색량·광고비·주문을 생성하지 않는다.

화면은 기본적으로 **이번 운영 구간 / 오늘 누계**를 제공하는 안이다. KST 날짜별 집계는 같은 유효 사건을 읽는다. 자정의 진행 작업과 지연 완료는 원래 발생/완료 시각을 각각 보존한다. 일일 결산·주간 조회를 열어 검색을 재발행하지 않는다. 오늘 시작 전의 비접속 기간은 0 실적으로 단정하지 않고 미진행 구간으로 설명한다.

## 5. 검색에 맞는 후보와 순위

첫 후보의 필수 정보는 게임 점포 ID·표시 이름·업종/판매 태그·위치/서비스 범위·게임의 등록/영업 상태다. 사진·리뷰·상세 메뉴 완성도를 필수로 요구하지 않는다. 게임 사업자등록에 따른 등재는 r195 방향을 따르고, 공개 인허가 행을 게임의 사업자등록 완료로 간주하지 않는다.

검색과 맞지 않는 매장은 같은 점수표에서 억지로 경쟁시키지 않는다. 먼저 지역/서비스 범위와 의도 적합 여부를 가른 뒤 해당 후보 사이에서 계산한다. 일시 주문 불가·휴업의 목록 유지/제외는 명시된 조회 필터와 게임 상태를 따른다. 원본에 없는 영업시간을 24시간으로 채우지 않는다.

| 필요한 정보의 정확성 | 15 | 필수 사실의 일치·유효성. 사진 수나 글 길이가 많다고 가산하지 않음 |
| 이전 유효 반응·이행 | 20 | 직전 확정 구간의 노출 대비 반응·완료/지연. 연결 전이나 저표본은 중립값 사용 |

각 요소는 0~1로 정규화하며 총점 = 40×적합도 + 25×접근성 + 15×정보 + 20×이전 반응이다. 첫 시험의 이전 반응은 모두 0.5로 두어 관측이 없는 점포에 성과를 만들어 붙이지 않는다. 품질/주문 연결 후의 평활화·기간·상한은 별도 밸런스 항목이다. 키워드 총검색량·원시 클릭 수·플레이어 자본을 일반 순위의 직접 가산점으로 쓰지 않는다.

점수는 **키워드·검색 지역/조건·판본별**이다. 카페 1위가 피자 1위가 되는 구조는 아니다. 같은 점수는 게임 점포의 안정 ID로 정렬하며 현재 열어 둔 세션은 페이지를 바꿔도 같은 순위표를 읽는다. 새 정보/운영 결과는 다음 유효 색인 판본에 반영하고 현재 고객의 페이지 이동 중 재정렬하지 않는다.

상위 노출이 원시 클릭을 늘리고 그 클릭이 다시 무제한 가산되는 순환은 피한다. 이전 반응은 노출 대비 지표·저표본 중립값·기간 감쇠/상한으로 제한하는 안이다. 신규점도 검색 적합도·접근성과 정확한 정보로 경쟁한다. 낮은 페이지를 탐색하는 고객도 허용하되 모든 점포의 노출이나 주문을 보장하지 않는다.

## 6. 페이지·고객의 탐색·주문 경계

한 페이지 일반 결과 10곳, 최대 10페이지는 첫 제안이다. 순위 r의 페이지는 floor((r−1)/10)+1이며 같은 점포를 여러 페이지에 복제하지 않는다.

| 고유 적합 후보 수 | 표시 |
| --- | --- |
| 0 | 결과 없음. 검색량은 기록 |
| 9 | 1페이지 9곳 |
| 11 | 1페이지 10곳, 2페이지 1곳 |
| 24 | 3페이지, 마지막 4곳 |
| 100 | 10페이지 |
| 101 이상 | 앞 100곳까지 10페이지. 나머지는 표시 범위 밖이며 존재/후보 수를 숨기지 않음 |

가상 고객도 모든 페이지를 끝까지 보지 않는다. 첫 시험은 페이지에서 매장을 열람하거나, 다음 페이지로 이동하거나, 이탈하는 세 갈래를 제안한다. 페이지 위치가 노출 기회에 영향을 주며, 결과에 나타났다는 이유만으로 모든 후보에 노출·클릭을 주지 않는다. 실제 화면에 보인 슬롯을 노출로 집계하고, 다른 페이지의 행은 아직 미노출이다.

카드 열람 후에는 해당 매장을 선택하거나 주문 없이 떠날 수 있다. **검색량 → 노출 → 열람 → 주문 의향 → 주문 요청 → 수락 → 완료 → 정산**을 각각 보여 준다. 첫 구현의 필수 범위는 검색·순위·페이지·노출 비교까지다. 열람·주문 의향을 시험 집계해도 기존 Core에 수락된 주문과 매출로 표시하지 않는다.

실제 주문을 붙일 때는 기존 주문 생성 권위를 하나로 유지한다. 검색은 같은 잠재 수요 중 홍달 플레이스 경로를 선택한 몫이다. 기존 동 수요 전량에 검색 유입 주문을 덧붙이지 않는다. 연결 계약이 준비되기 전에는 기존 묶음 수요/매출과 검색 실험을 나란히 별도 표시하고, 검색 실험은 금액·재고·기사 보상·명덕을 변경하지 않는다.

정식 광고를 추가하면 별도 광고 슬롯으로 읽고 일반 순번/페이지 계산을 보존한다. 중개업자 소개 순서와 후속 광고망은 r194·r183의 기존 기획을 따른다. 이번 첫 검색 구현에 실제 IP·계정·외부 트래픽 연동이나 중개업자 기능을 선행시키지 않는다.

## 7. 최소 화면과 경영 피드백

기존 지도에서 홍달 플레이스를 열면 선택 동·시간 범위와 검색어가 보인다. 왼쪽에는 키워드별 가상 검색량과 전 구간 증감, 가운데에는 작은 결과 카드와 페이지 이동, 내 점포 행에는 순위·페이지와 점수 이유를 보여 주는 안이다. 원자료 인구의 출처·기간과 ‘게임 가상 검색’ 표시는 짧게 구별한다.

카드에는 이름·게임 업종/판매 태그·동/거리 조건·주문 가능 상태 정도를 먼저 둔다. 행을 고르면 해당 건물을 강조하며 지도에서 돌아왔을 때 키워드·페이지·선택 점포를 복원한다. 사진/상세 프로필·리뷰는 이 최소 시안의 선행조건이 아니다. ‘내 점포 13위 · 2페이지’와 ‘검색 적합도 낮음’처럼 행동으로 바꿀 수 있는 이유를 읽게 한다.

검색량이 늘었다고 내 점포의 실적이 늘었다고 단정하지 않는다. 같은 조건에서의 전후 순위, 고유 노출·열람, 주문 의향/연결 주문과 실제 처리 한계를 나누어 비교한다. 비교용 오전·점심·저녁 선택은 조회 전용이며 진행 시계와 통계를 만들지 않는다. 직접 관찰·직원 위임 모두 같은 검색 모형을 읽는다.

이 레이아웃은 Claude가 현재 화면에 맞춰 시안을 준비할 입력이다. 새 단축키는 이번에 배정하지 않으며 실제 Game View 판독·입력은 후속 검증이다.

## 8. 기존 자료와 독립 계산 예제

[계산 예제와 검산](../../../../../artifacts/local/hongdal-place-population-search-r238-20261115/examples/README.md)은 실제 원본 지문과 합성 계수를 분리한다. 면목제3·8동 음식점 인허가 390키 중 업종 분류상 카페 24키는 10곳/페이지일 때 3페이지가 된다는 **규모 참고**다. 인허가 키 수는 현재 실제 점포 수나 홍달 플레이스의 등록 경쟁점 수가 아니다. 메뉴 취급 여부를 분류명·상호만으로 확정하지 않는다.

원천 동의 2026년 2분기 11~14시 추정치 743,205와 전년 같은 분기 707,525의 비율을 계산 예제에 썼다. 합성 기회 기준 1,000에 그 비율을 적용하면 반올림 1,050, 그중 검색 성향 20%이면 검색 210과 비검색 840으로 나뉜다. 1,000·20%·키워드 비중·페이지 전환·열람/의향 비율은 모두 예제 가정이다. 실측 검색량이나 생산용 기본값으로 승인한 값이 아니다.

예제의 익명 순서는 페이지 산술을 보기 위한 고정 순열이며 5절의 순위 알고리즘 구현이 아니다. 공개 매장에 실제 영업 순위·좋고 나쁨을 매기지 않는다. 개인 픽업 빈도·과거 메뉴·플레이어 자료 열람을 가상 고객 행동의 실측 근거로 쓰지 않는다. 공개 자료를 가상 경쟁점 구성에 사용할 때도 게임 점포 ID·가상 운영 상태와 실제 자료의 관계를 분리한다.

새 외부 수집은 이번 범위에 없다. 첫 검색에 추가로 필요한 것은 게임용 분류/의도 대응표·가상 점포 목록·수요 분할/점수/탐색 정책이다. 실제 Naver 검색 통계가 나중에 들어오면 제공자·관측기간·단위/약관을 가진 별도 비교 지표로 읽는다.

## 9. Claude 개발 계획에 넘길 작은 범위

1. 한 동·소수 키워드·게임 점포 목록과 최소 카드 시안을 선택한다. 자료/색인·점수 정책을 고정하고 소스/팩·수정 경로를 다시 대조한다.
2. 미처리 시간구간에서 가상 검색을 한 번만 생성해 키워드별로 집계한다. 0결과·조회·페이지 이동·회차 마감·저장 복원에서 검색량이 보존돼야 하며, 같은 활성 경과의 분할/연속 처리도 같은 합계여야 한다.
3. 후보/점수 이유·고정 순위·10곳/페이지를 연결하고 내 점포의 순번과 페이지를 읽는다. 0·9·10·11·24·100·101 후보와 동점/필터 변경을 가상 시험 자료로 확인한다.
4. 한 가지 정보 개선 전후를 두 구간에서 비교한다. 페이지별 고객 도달·노출을 연결하며 기존 동 매출·전표·명덕이 조회/실험 때문에 변하지 않는지 확인한다.
5. 주문 연결은 별도 범위로 준비한다. 잠재 수요 분할·기존 주문 ID·수락/실패·결산의 일대일 귀속이 닫힌 뒤 판매 효과를 구현한다.

기획 승인·정확 판본/hash·상호작용 검증 명세·수정 경로·수용의 기존 절차를 따른다. 이 문서만으로 Claude가 작업을 수용했다고 표시하지 않는다. 첫 목표는 검색 실험 한 번과 개선 후 비교 한 번이며 전체 광고·주문·프로필 완성을 함께 묶지 않는다.

## 확정 / 미정 / 다음 질문 하나

**확정:** 인구를 배경으로 가상 고객이 홍달 플레이스를 검색하고, 키워드별 검색량과 점수에 따른 순위·페이지를 갖게 하는 사용자 방향. 상세 프로필을 전부 채우는 것을 이 첫 기획의 선행조건으로 두지 않는다. 이 작업실에서 기획을 준비한 뒤 Claude가 구현 계획을 잡는다.
