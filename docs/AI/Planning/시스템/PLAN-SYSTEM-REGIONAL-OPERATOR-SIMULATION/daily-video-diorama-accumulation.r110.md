## 기준 문서와 범위

운영 절차의 정본은 배달 작업공간 `edit-kit/riding-vlog/매일-영상접수에서-디오라마까지.md`, 기계가 읽는 단계·기록 양식은 `premiere-control/video_diorama_daily_workflow.json`이다. 배달 루트 AGENTS와 기존 접수/분석 안내가 이 기준을 가리키도록 연결했다. 본 문서는 기획 관계·현재 구현 수준만 소유하며 절차를 복제하지 않는다.

사용자가 제공한 원본 묶음마다 접수·중복 확인→실제 시점/OCR 후보→시간순 판독으로 진행하고, 도로 선분 후보와 공개 건물/외관 관측을 별도 갈래로 축적한다. 전체 도로 경로가 미확정이어도 독립 건물 근거가 맞는 외관 자료는 계속할 수 있다. 대상·지도 판본이 맞는 경우에만 기존 외관 Gate로 검토하며 도로 후보나 독립 연구를 정본 적용으로 승격하지 않는다.

원본 SHA·실제 PTS/프레임·관측·공개 건물·정본 대상/판본·외관 Profile·비교/복구 증거의 참조를 기존 카탈로그/검토 저장소에 연결한다. 새 승인 DB나 운영 권위는 만들지 않는다. 중복 실적을 제외하고 단계별 재사용·부분 검증·보류·실패·재확인을 기록한다.

## 실제 코드 확인에서 남은 연결

1. 구형 `longform_sign_batch.py`는 디코더 `pts_time`의 실수 초만 출력하므로 정수 PTS/time_base가 필요한 후속 계약에 그대로 넘길 수 없다. 기존 실제 PTS 근거를 대조하며 역산하지 않는다.
2. 표본/OCR 실행 결과는 접수 state에 의미 분석 완료로 자동 역등록되지 않는다. 일일 작업 기록에 실제 receipt와 직접 판독 결과를 별도로 연결한다.
3. 기존 고정 카탈로그의 분석/번호순 포인터와 신규 접수는 구분한다. 과거 날짜 고정 스크립트는 공통 실행기로 간주하지 않는다.
4. 현재 Overture 지도와 첫 GIS 외관 연구 대상의 직접 대응은 아직 없다. 기반 도형/ID를 바꾸지 않고 해당 대상만 보류한다.

기존 도구를 자동 실행하고 결과를 회수하는 실행기, 신규 원본의 일반화된 분석 연결, 정본 GIS 대응 보완은 후속 구현이다. 이번에는 절차·단계 정의·공통 진입 안내를 저장했으며 새 영상 처리·추가 렌더·Unity 실행·Scene 저장·운영 DB·자동 감시·배포·commit/push는 하지 않았다.

## 일일 보고와 다음 구현 순서

원본 접수/중복/접근 대기, 직접 판독 범위/미검토 꼬리, 도로 후보/확인 연결, 건물 관측/비공개 시안/정본 실제 적용, 다음 보완을 구분해 보고한다. 대용량 원본 반복 복사와 동일 입력의 불필요한 재분석을 줄이고 실패한 원본은 분리해 다른 작업을 계속한다. 전체 지역의 임의 완성률은 만들지 않는다.

다음 구현은 **실제 PTS 출력 계약 정리 → 기존 실행 영수증의 재개 가능한 연결 → 건물 ID/공간 판본 대응 → 건물별 전후·복구 검증** 순서다. 아직 후속 구현 전체가 완료되거나 무인 실행이 승인된 상태는 아니다. 기존 원본·사용자 승인·Premiere 컷/마커·Synty 자산·Scene·운영 DB를 보존한다. 새 공통 디오라마 규칙 후보 없음.
