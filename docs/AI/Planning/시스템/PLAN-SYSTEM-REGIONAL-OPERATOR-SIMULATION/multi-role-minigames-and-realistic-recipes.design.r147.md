## 1. 공통 틀 — 역할은 달라도 같은 경영으로 돌아온다

같은 세계·가상 시간·사업·주문·재고·자금·성장 안에서 사용자가 어떤 일을 직접 수행할지 선택한다. **이완 관찰 → 건물/주체의 역할 선택 → 집중 미니게임 → 이완 자동 수행·관찰**을 공통 진입/귀환으로 사용한다.

| 역할 | 집중 미니게임에서 하는 일 | 이완에서 이어지는 일 | 경영에 연결되는 결과 |
| --- | --- | --- | --- |
| 기사 | 오토바이 운전·픽업·가방 적재·전달 | 같은 주문과 가방으로 기사 자동 수행 | 수령·정산·배송 성과 |
| 바리스타 | 주문표·레시피 확인, 원료 준비·계량, 추출·조립·마감 | 같은 주문·레시피·재공품을 바리스타가 이어서 제조 | 완성 음료·사용 재료·준비 완료·판매/인계 |
| 창고 작업자 | 선반 위치·품목 확인, 피킹, 포장·라벨·출고대기 | 같은 작업·집품 용기·재고 상태를 작업자가 이어받음 | 정확한 집품·포장·기존 운송 인계 |

첫 동시 직접 조작 대상은 한 역할의 한 작업이다. 다른 역할로 집중을 옮기기 전 현재 작업을 자동 주체에게 인계하며, 두 곳에 사용자 입력이 동시에 적용되지 않게 한다. 다른 주체의 정상 업무는 공통 가상 시간을 따른다.

지도 높이는 경영 관점, 집중·이완은 참여 방식, 역할은 직접 수행할 업무다. 건물 클릭만으로 임의 작업이 시작되거나 관찰만으로 추가 보너스를 받지 않는다. r144의 창고 내부 읽기 화면에서 작업자·준비된 작업을 선택해야 직접 피킹/포장으로 진입한다.

캐셔·입고 검수·조리·적재 등은 후속 역할 후보로만 둔다. 미준비 역할은 준비 상태를 표시하고 실행 가능한 미니게임으로 열지 않는다. 각 역할은 다른 영역의 전체 공급 사슬 없이 독립된 가상 Fixture로 검토할 수 있어야 한다.

## 2. 바리스타 — 실제 절차를 이해하고 한 잔을 만든다

### 현실 근거와 시범 배합

제조사 공개 교육·레시피를 2026-11-12에 확인했다. 특정 매장의 비공개 레시피를 확인했다고 주장하지 않으며 원두·바스켓·장비·컵에 따른 차이를 보존한다.

| 확인한 공개 근거 | 기획에 반영할 것 | 적용 한계 |
| --- | --- | --- |
| [La Marzocco 추출 가이드](https://home.lamarzoccousa.com/how-to-make-espresso/) | 깨끗하고 마른 바스켓, 계량·분배·수평 탬핑, 그룹 준비, 장착·추출·목표 산출량 정지 | 1:2·25~30초는 출발점이며 원두·장비별 조정값 |
| [La Marzocco 추출 비율](https://home.lamarzoccousa.com/using-espresso-brew-ratios/) | 투입 원두와 산출 추출액을 질량 비율로 관리 | 특정 비율을 모든 커피의 정답으로 고정하지 않음 |
| [Breville 아이스라떼](https://www.breville.com/us/en/coffee-journey/recipes/iced-latte.html) | 찬 우유·얼음 준비와 에스프레소 추출·붓기·섞기 | 도징 18~22g·약 30초는 해당 예시. 우유 mL는 명시하지 않음 |

첫 게임 검토는 기존 r68의 다음 시범 배합을 재사용한다. **16oz 시범 컵의 시작값**이며 실물 컵 유효용량·얼음·맛·공정 검증을 마친 공통 표준이나 실제 프랜차이즈 배합은 아니다.

| 첫 메뉴 | 시범 재료 | 주요 조립 |
| --- | --- | --- |
| 아이스 아메리카노 | 원두 18g → 추출액 목표 36g, 물 180mL, 얼음 150g | 추출과 별도로 물·얼음 준비 후 해당 레시피 순서로 혼합 |
| 아이스라떼 | 같은 에스프레소, 찬 우유 170mL, 얼음 150g | 찬 우유·얼음에 추출액을 조립. 스팀을 넣지 않음 |

원두 g·추출액 g·우유/물 mL·얼음 g·용기 개를 구별한다. 추출액 36g을 36mL로 바꾸거나 추출액 무게만큼 원두를 다시 차감하지 않는다. 우유 170mL·물 180mL·얼음 150g은 게임 시범값이며 위 제조사가 같은 배합을 보증한 값이 아니다.

레시피에는 메뉴/옵션·판본·출처/확인일·장비/컵 조건·원료와 단위·작업 순서·산출 목표·시간·허용 오차·청소 단계를 연결한다. 한 주문은 시작할 때의 레시피 판본을 유지하며 집중/이완 전환이나 새 자료 수집으로 중간 배합이 바뀌지 않는다. 허용 오차·난이도는 후속 시각/조작 검토값이며 현실 근거와 게임 조정값을 나란히 표시한다.

### 첫 제조 미니게임 제안

| 구간 | 조작·판단 | 완료로 인정할 것 |
| --- | --- | --- |
| 주문·원료 준비 | 주문표의 메뉴/온도/옵션 확인, 올바른 컵·원료·설비 선택 | 주문과 레시피·가용 원료·설비의 연결 |
| 분쇄·계량·탬핑 | 저울 계량, 분쇄량 조절, 분배·수평 탬핑의 짧은 조작 | 해당 배합의 도징과 준비 조건 충족 |
| 에스프레소 추출 | 머신 장착·추출 시작, 시간과 산출 질량을 보며 정지 | 레시피의 산출량·추출 조건 판정 |
| 음료 조립 | 물/우유·얼음의 양과 순서, 올바른 주문 컵에 붓기 | 재료·단위·옵션·용량 조건에 맞는 음료 |
| 마감·전달 준비 | 내용 확인·뚜껑/봉인/주문표, 사용한 작업대·도구 정리 | 해당 주문의 준비 완료와 기존 판매/픽업 인계 가능 상태 |

첫 조작안은 작업대 고정 시점에서 마우스로 설비·재료를 선택하고 계량/타이밍을 조작한다. 기사의 방향키 운전을 모든 역할에 강요하지 않는다. 작업 카드에는 현재 레시피·목표량·현재량·막힌 이유를 남긴다. 분쇄도 선택·탬핑 정렬 등은 간소화할 수 있지만 클릭 순서만 맞추면 원료·양이 틀려도 완성되는 방식으로 만들지 않는다.

실제 추출 시간과 게임의 표현 시간을 구별한다. 연출을 압축한 시간을 실제 제조 표준처럼 표시하지 않으며 생산 여력·세계 시계에 영향을 주는 배속/작업 시간은 같은 시나리오 판본에 결속한다.

핫라떼는 후속 메뉴로 스팀·온도·거품을 별도 추가한다. 아이스라떼의 찬 우유 공정에 그대로 스팀을 붙이지 않는다. [공식 핫라떼 예시](https://www.breville.com/us/en/coffee-journey/recipes/latte.html)와 [장비 설명서](https://assets.breville.com/BES870/BES870_ANZ_IB_R23_LR.pdf)의 퍼지·밸브 종료·도구 정리 순서를 검토하고, 기종별 시간·조작을 상업용 머신 공통 규칙으로 바꾸지 않는다. 라떼아트는 첫 필수 완료 조건에서 제외한다.

## 3. 창고 — 선반에서 찾아 정확히 집고 포장한다

후속 [바코드 타이밍 미니게임 r148](barcode-scan-timing-minigame.design.r148.md)은 입고·피킹·포장의 확인 동작으로 상하 레이저·중앙 Space 조작을 제안한다. 스캔 창의 입력은 역할별 상호작용 안의 하위 단계이며 읽기 성공이 기존 품목·위치·수량·검수 조건을 대신하지 않는다. 개별 스캔에 별도 중복 보상을 주지 않고 본문의 상위 구간 완료 자격을 따른다.

첫 표본은 창고 한 곳·작업자 한 명·출고 주문 한 건·두 품목을 제안한다. 예시로 종이컵 2묶음과 뚜껑 1묶음을 사용하는 독립된 가상 작업을 둔다. 이는 실제 포장 규격이 아니며 묶음당 개수를 임의로 환산하지 않는다. Claude의 우유 5팩 통합 표본을 새로 복제하거나 필수 선행으로 삼지 않는다.

| 구간 | 집중에서 하는 일 | 완료 조건 |
| --- | --- | --- |
| 작업·위치 확인 | 출고 지시와 선반 위치·품목·로트·가용/예약 상태 확인 | 해당 작업에 허용된 정확한 집품 대상 |
| 피킹 | 통로를 이동해 맞는 선반에서 지정 수량을 집품 용기에 담기 | 지시 품목·로트·단위·수량 일치, 중복 집품 없음 |
| 포장 | 작업대에서 내용 재확인, 맞는 포장재·완충·밀봉·라벨 처리 | 포장 조건과 주문/인계 대상 일치 |
| 출고대기 배치 | 포장물을 맞는 인계 위치로 옮기기 | 기존 운송 인계에 사용할 준비 상태. 상차·납품 완료로 승격하지 않음 |

첫 조작안은 내부 모델에서 방향키로 작업자를 이동하고 Space로 선반/용기/작업대 상호작용을 한다. 포장대에서는 마우스로 포장재·내용·라벨을 확인한다. 위치·품목·수량·작업 조건이 틀리면 이유를 표시하고 재선택하게 한다. 선반 클릭·걷기 도착·포장 애니메이션만으로 재고를 확정하지 않는다.

물품은 보관 위치→작업자/집품 용기→포장대→출고대기 위치의 상태로 이어진다. 예약·재고 이동·포장재 소모는 기존 Core 규칙을 따르고, 보이는 물건을 숨겼다는 이유로 원장 수량을 지우지 않는다. 부재 재고는 0을 꾸며 채우거나 자동 보충하지 않고 부족·격리·예약 충돌 사유와 회복 진입을 제공한다.

## 4. 역할 공통 인계·재료 보존·추가 보너스

어느 역할에서도 이완 전환을 요청할 수 있다. 아직 끝나지 않은 작업을 처음부터 재생하지 않고 **같은 업무·주체·판본·현재 단계·재공품·소모 기록·설비 점유**를 다음 수행 주체가 이어받는다.

| 역할 | 인계할 상태·경계 |
| --- | --- |
| 기사 | r146의 안전 정차, 같은 위치·주문·가방·진행·충돌 기록 |
| 바리스타 | 컵 내용·분쇄/추출 상태·사용 원료·레시피 판본·머신 점유. 장비가 안전한 확정 경계에서 자동 주체에게 이어짐 |
| 창고 작업자 | 작업 위치·집품 용기 내용·남은 지시량·예약/로트·포장 진행·설비 점유 |

추출·스팀·물품 이동처럼 진행 중인 행위는 즉시 입력만 바꾸지 않는다. 전환 대기를 표시하고 안전한 단계 경계를 확정한 뒤 넘긴다. 인계가 미준비이면 이유를 표시하고 기존 일시정지·명시적 선택을 제공한다. 중요 예외·대체 재료·큰 지출을 모드 전환으로 자동 승인하지 않는다. 사용자가 모든 공정을 끝내야만 이완으로 나갈 수 있게 잠그지는 않는다.

머신의 정상 자동 추출은 레시피 안의 설비 동작이며 NPC에게 제어권을 넘긴 것과 구별한다. 구간 전체를 직접 맡아 필요한 시작·정지·확인을 수행했다면 기계가 작동한 시간 자체를 자동 인계로 세지 않는다. 집중 중간에 NPC가 맡아 남은 판단을 수행한 구간은 r146처럼 직접 완료 자격을 주지 않는다.

제조는 r68의 예약·실사용 구분을 이어받아 본 안에서 시작 시 원료 예약→완료 시 실제 사용 기록을 제안한다. 중간 분쇄·붓기의 사용 증거와 최종 재고 반영을 결속해 이중 차감하지 않는다. 사용하지 않은 예약은 해제할 수 있지만 이미 분쇄/투입한 재료는 취소했다고 원재료로 복원하지 않는다. 사용·폐기·재제조를 구별한다. 이는 제조사 레시피의 사실이 아니라 이 계획의 게임 상태 보존 규칙이다.

**보너스는 공통 원칙과 역할별 업무 구간을 분리한다.** r146의 네 구간은 배달 프로필로 유지하고, 카페·창고는 위의 역할별 완료 구간을 사용한다. 동일 업무·시도·구간의 시작부터 끝까지 직접 수행해 정상 결과를 냈을 때 한 번 자격을 기록한다. 구간을 잘게 나누거나 역할·모드를 반복 전환해 같은 일을 여러 번 보상하지 않는다.

완료 구간은 자격 기록일 뿐 즉시 현금이 아니다. 제조·피킹·포장이 끝났다고 음식 판매·운송·고객 수령을 완료시키지 않으며 **각 업무의 정식 완료·정산 관문** 뒤 해당 보너스를 지급한다. 역할별 기준 보너스·난이도/시간 보정·품질 계수·자금 귀속은 후속 경제 기획이다. 매출·기사 보수·원료 비용·숙련 보너스를 같은 금액으로 합치지 않는다.

## 5. 기존 작업 보존과 검토 순서

r71의 우유 1L 5팩 출고→4팩 인수/1팩 격리→가용 4,000mL 중 라떼 170mL 사용→잔량 3,830mL는 Claude가 구현 중인 기준선이다. 새 미니게임이 격리 재료를 사용하거나 같은 로트를 두 번 차감하거나 해당 배합·수량을 바꾸지 않는다. 연결은 기존 계약·반환 결과를 대조한 뒤 필요한 업무 구간만 별도로 인계한다.

후속 준비 순서의 제안은 ① 역할별 공통 인계·구간 기록 정의 ② 바리스타 아이스 음료 한 주문 시각안 ③ 창고 한 주문 피킹/포장 시각안 ④ 각 역할의 독립 검증과 배달 연결이다. 코드 착수 순서를 자동 활성화하는 지시가 아니다. [화면 시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)에 따라 기존 내부 모델·머신/랙/작업대·목표량·현재량·현재 수행 주체·이완 복귀가 보이는 대표 화면을 검토한다.

| 후속 확인 | 통과 기준 |
| --- | --- |
| 역할 공통성 | 기사·바리스타·창고의 같은 참여 방식·제어권과 역할별 서로 다른 조작/구간을 구별 |
| 레시피 사실·가정 | 제조사 근거·시범 배합·시간·허용 오차의 출처/판본/단위를 구별하고 아이스에 스팀을 넣지 않음 |
| 정상 제조 | 주문·레시피·도징·추출·조립·마감이 연결되어 원료와 완성품이 일치 |
| 잘못된 제조·회복 | 품절·다른 원료/컵·양 오류·중도 취소·재제조의 사용/폐기를 보존 |
| 정상 집품·포장 | 위치·품목·로트·예약·수량·포장·라벨·출고대기가 일치 |
| 잘못된 집품·회복 | 오피킹·초과/부족·격리/다른 작업 재고·포장재 부족에서 무단 완료 없이 원인과 재선택 제공 |
| 중간 인계 | 어느 역할도 같은 주문·재공품·설비 점유를 이어받고 입력·소모·완료가 중복되지 않음 |
| 보너스·저장 | 역할별 직접 구간 자격·정산 시점·저장/복원·재시도에서 보너스 중복 없음 |
| 기존 기준선 | r71 수량·로트·별도 수령/정산과 Claude의 코드 소유를 유지하고 새로운 통합 성공으로 승계하지 않음 |

이번 완료는 기획 본문·목차·현재 작업·r146 연결이다. 제품 코드·공개 API·저장 계약·실제 재고·경제 지급·모델·시안/영상·예약·Goal·새 D 결정·commit/push는 변경하지 않는다. 위 표는 후속 시험 기준이며 실제 실행 성공·E 승격 근거가 아니다.

## 미정과 다음 질문 하나

다양한 역할의 집중 미니게임과 이완 귀환, 직접 완료 구간의 추가 보상, 현실 근거를 가진 레시피는 사용자 방향이다. 세부 조작·품질 오차·시범 컵/배합 확정·역할별 금액/귀속·구현 계약은 미정이다.

다음 질문 하나: **첫 바리스타 시각 검토는 공통 추출·조립을 익히는 아이스 아메리카노와 우유 계량까지 보는 아이스라떼 중 무엇으로 시작할까?** 이번에 실제 메뉴·프랜차이즈의 비공개 레시피를 수집하거나 시안을 제작하지 않는다.
