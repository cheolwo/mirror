## 성장 경로를 보여주는 한 장면

사용자는 기사 확보와 운행 시간 관리로 시작해, 가맹점 운영·생산자와의 연결·공장 운영으로 경영 범위가 점차 넓어지는 게임을 원한다. 처음에는 기존 Unity 지도 캡처와 보유 아이콘으로 이미지 시안을 만들었고, 사용자 채택 뒤 별도 Unity Windows 검토판의 실제 화면에 적용했다. 시안에 넣었던 성장 수치와 진행 상태는 가상 예시다.

지도는 넓게 두고 하단에 다음 네 성장 영역을 표시한다.

| 성장 영역 | 플레이어가 넓힐 책임 |
| --- | --- |
| 기사 운영 | 모집·출근·배차·운행과 휴식 |
| 가맹점 운영 | 주문자 가까운 곳의 최종 조리·조합과 판매 |
| 생산자 연결 | 필요한 품목·수량·공급 시각의 조율 |
| 공장 운영 | 원재료의 1차 가공과 반제품 준비 |

현재의 기사 운영은 밝게 표시하고 가맹점 운영은 다음에 살펴볼 선택으로 보여준다. 생산자와 공장은 후속 구상으로 읽을 수 있게 한다. 단계별 정확한 해금 조건·비용·성장 수치는 미정이다.

## 다음 투자의 이유

오른쪽 패널은 기사 확보 후 주문에 맞춰 준비할 음식이 부족해진 상황을 보여준다. 가상의 시간당 주문 9건, 출근 기사 3명과 배송 여력 9건에 비해 매장 준비 여력은 6건인 조건이다. 다음 가맹점을 검토하는 이유를 음식 준비의 부족량과 연결한다.

상단의 경 유지 시간과 시간당 순소득은 경영자가 지향하는 개인별 개선을 읽는 자리다. 감의 배송, 태의 최종 조리, 진의 생산, 리의 1차 가공 표시는 기존 역할 분류를 읽는 보조 정보다. 주문 무토와 판매 기토는 r136의 구분을 따른다.

## Unity에 적용한 범위와 확인

최신 오토바이 표시 검토판의 프로젝트를 복사해 지도·오토바이·기존 배차와 정산을 유지했다. 하단 네 영역은 오른쪽 설명을 전환한다. 가맹점 둘러보기는 기존 매장 상세를 열며 기사를 자동 배정하지 않는다. 배차 보기는 기존 데스크를 열고, 기존 화면과 지도만 보기에서 돌아올 수 있다. 기사 선택은 성장 영역 전환 뒤에도 보존하며 상세 초점은 선택한 정보 패널로 옮긴다.

기사 수·대기 주문·수령 정산은 현재 Simulation 상태를 표시한다. 경 유지 시간과 시간당 순소득은 현재 엔진에 원자료가 없어 기록·산정 대기로 표시한다. 시간당 주문 9건/준비 6건은 계획 예시로 명시했다. 기사 모집·가맹점 개설·생산 계약·공장 가공의 새 규칙은 이번에 실행하지 않는다.

실제 Windows 창에서 네 영역 전환과 닫기, 기존 화면에서 상세를 숨긴 뒤 경영 화면으로 복귀, 오토바이 선택 → 매장 클릭의 두 배차를 확인했다. 두 주문은 수령과 가상 정산까지 이어졌고 수입 9,600원·기사 보수 7,200원·차액 3,600원이었다. 같은 초기 합성 상태를 쓰는 처리기 검증은 선택 보존·지도 입력 차단/반환·정산 결과를 별도 확인한다. 확대된 창에서 선이 흩어지는 문제는 기존 선분 그리기의 행렬 조합을 수정했고 아이콘 가져오기, 기사 상세와 출처 겹침, 상세 숨김 뒤 복귀도 보완했다.

이 실행판은 원본 Unity 작업 폴더를 덮지 않은 별도 프로젝트다. Simulation 실행 파일은 직전 검증판과 같은 SHA-256으로 유지했다. 변경 전 화면은 보존한 직전 실행판을 같은 1600×900·11:30·초기 주문 두 건으로 재현한 것이며 수정 전 시각에 새로 촬영한 화면과 구분한다. 다음 한 가지는 같은 수요에서 음식 준비가 가능한 매장 여력을 연결하는 규칙 검토다.
