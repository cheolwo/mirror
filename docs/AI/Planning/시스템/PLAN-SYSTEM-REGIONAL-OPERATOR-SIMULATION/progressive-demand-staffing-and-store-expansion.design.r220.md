## 2. 플레이어가 익힐 성장 흐름

**손님/주문 기회 → 대기와 부하 확인 → 고용/교육·작업자리 보강 → 점포 병목 확인 → 추가 출점 검토 → 여러 점포 운영**을 기본 성장 흐름으로 삼는다.

| 걸음 | 보이는 상황 | 내리는 결정 / 결과 |
| --- | --- | --- |
| 작은 매장 | 적은 손님·한 작업자·몇 건의 실제 작업 | 주문→제조/조리→인수·결과를 익힘. 시작 프로필에 따라 점주 직접 작업/직원 운영을 구분 |
| 바쁜 시간 | 손님/주문이 몰려 대기·미제공이 생김 | 직원/교대·교육을 보강할지, 지금 여력으로 운영할지 비교 |
| 인력 보강 | 가능한 직원/작업자리가 있어 대기가 줄어듦 | 추가 인건비와 줄어든 대기·제공량을 확인 |
| 점포 한계 | 사람은 있어도 제조대·설비·포장/인수 공간·공급이 막힘 | 병목 설비/자리·보충·메뉴/수락량·증설을 비교 |
| 다음 점포 | 기존 장소의 여력만으로 목표 수요를 처리하기 어려움 | 같은 동/준비된 인근 입지에2호점 계획·비용/기간·수요 겹침 검토 |
| 다점포 운영 | 점포별 재고·직원·대기/성과가 달라짐 | 어느 점포에 인력/보충을 우선할지, 더 확장할지 결정 |

이는 카페/음식점 분야의 성장 경로다. 모든 플레이어의 출발을 카페로 고정하거나 배달→카페→무역의 의무 순서를 만들지 않는다. 한 동에 집중하면서 그 동 안의 여러 점포도 비교할 수 있다.2호점마다 새 동/전국 지도를 반드시 열 필요는 없다.

‘주문이 늘면 고용을 검토한다’는 뜻이며 자동 고용·자동 출점이 아니다. 바쁜 상태를 알리고 후보/비용/기대 효과를 보여 주되 확정은 플레이어가 한다. 작은 매장을 유지하거나 확장을 미루는 선택도 남긴다.

## 3. 손님 방문·주문·제조를 같은 사건으로 읽기

방문 기회/접근 → 점포 선택/입장 → 주문/수락 → 대기 → 제조/조리 → 준비/인수 → 떠남/결과를 잇는 안이다. 손님이 줄 서 있는 모습은 실제 게임 대기 상태의 표현이며, 고객을 그렸다는 이유로 주문·돈을 만들지 않는다.

- **사람 수와 잔/인분·주문 수 구분:** 한 일행이 여러 잔을 주문할 수 있다. 원수요/주문과 품목 수량의 단위를 보존한다. 아래 수치 예시는 한 기회가 라떼1잔인 단순 조건이다.
- **채널 구분:** 방문·포장·배달을 구별하되 같은 구매기회를 여러 채널로 중복 생성하지 않는다. 기존 배달 주문ID/원장은 재사용하고 카페 제조로 연결할 계약은 별도로 준비한다.
- **대기와 이동 분리:** 제조5분/음식10~15분에 주문/재료/설비·픽업 대기를 다시 숨겨 넣지 않는다. 현재 대기 이유가 인력인지 원료인지 읽히게 한다.
- **관찰/집중 일치:** 직접 바리스타/조리 작업을 하든 관찰/위임하든 같은 작업·재료·설비·결과를 사용한다. 모드/창 전환으로 새 주문을 만들거나 진행을 되감지 않는다.
- **표현량과 실제량 구분:** 군중/고객 표시를 줄여도 실제 대기/주문은 같아야 한다. 많은 작업을 대표 인원으로 그릴 때는 실제 줄/수량을 UI에서 읽게 한다.

현재 방문 손님·점포 큐가 이미 구현됐다는 뜻은 아니다. 접수/대기·포기/취소·인수 상태와 재료 예약/소모는 해당 업무의 정확 계약으로 결속하고, 현재 없는 전이를 화면에서 임의로 완료시키지 않는다.

## 4. 직원을 늘리는 효과와 점포의 한계

처리능력은 같은 시간/품목 단위로 **가용 인력·독립 제조자리·공용설비·포장/인수·재료 공급의 병목**을 비교한다. 인력 수×자리 수×머신 수로 곱하지 않는다. 같은 직원의 시간을 제조·포장 양쪽에 동시에 중복 배정하지 않는다.

r214의 첫 직렬 커피 프로필에서는 한 작업자가 한 잔300초를 맡는다. 출근/배치 인력과 사용할 제조자리 중 적은 수가 동시 작업을 제한하고, 공유 머신30초 점유/다른 공정·재료가 추가 상한을 만든다. 추가 직원에게 빈 작업자리가 없다면 제조량 상한이 그대로일 수 있지만 교대/휴게·접객/보충의 효과는 별도로 읽을 수 있다.

공간은 **내 점포가 실제 쓰는 면적/배치** 기준이다. 건물 전체 연면적을 내 카페 작업공간으로 간주하지 않는다. 제조대·포장/픽업대·냉장/선반·통로의 제약을 표시한다. 기존 r214의1/2자리 비교나 냉장40L는 시험 조건이지 모든 매장의 최대2자리·일일 잔수 고정 상한이 아니다. 냉장 용량은 한 시점 보관량이며 보충이 있으면 하루 사용량과 다르다.

고용 인원·출근 가능 인원·현재 배치 인원을 구분한다. 새 직원을 뽑아도 근무 시작·설비/자리·재료가 준비돼야 실제 일을 맡을 수 있다. 설비만 사도 인력 병목이 해결되지는 않는다. 임금·설비/자리 비용·준비기간과 그 효과가 시작되는 시점을 나눠 보여 준다.

카페와 음식점은 공통 흐름을 공유하되 **레시피·직무·기구/화구·작업/배치 점유 프로필**은 다르다. 커피300초의 처리량을 음식10~15분에 그대로 복사하지 않는다. 일일 상한과 피크 대기/이탈·근무 여유도 따로 본다.

## 5. 추가 점포는 같은 수요를 복사하지 않는다

지역/시간/업종의 구매기회를 먼저 구분하고 거리·접근·대기·가격/선호·채널 조건으로 점포에 배분하는 안이다.2호점이 생겼다고 기존160잔을 두 점포에 각각160잔씩 만들지 않는다. 한 시점의 같은 단위에서는 **원수요 = 점포별 제공 + 진행/대기 + 미배정 + 포기**로 보존한다. 대체 점포로 이동한 이력은 별도의 새 수요가 아니다.

가까운 두 점포는 기존 고객을 나눌 수 있고, 새로운 입지는 원래 지역 수요 중 지금까지 접근하지 못하던 기회를 맡을 수 있다. 매장을 늘린 것 자체가 지역 인구·고객·매출을 생성하는 보상은 아니다. 기존 공공 통계와 가상 수요/계절·재방문/광고 효과의 입력·출처를 구분한다. 매 회차마다 일정 비율로 수요가 무조건 증가하는 규칙은 이번에 확정하지 않는다.

각 점포의 직원·주문 귀속·작업·장비·재고/인수·매출을 분리한다. 공용 회사 자금/본부 계약/공급 거점은 실제 연결 범위만 공유한다. 새 점포를 열면서1호점의 재고·교육·계약 효과·매출을 복제하지 않는다. 독립 점포 두 곳 운영과 가맹본부 사업/가맹망 확장은 별개이며, 다점포가 곧 본부 자격을 만드는 것은 아니다.

입점 계획→공간/설비·직원·초기 재료 준비→개업의 기존 가지를 재사용한다. 플레이어가 먼저 전국 수입/센터·화물 사업을 완주해야2호점을 열 수 있는 의무 사슬을 추가하지 않는다. 준비된 가상 외부 공급처와 카페/음식점 각각 독립적으로 시작할 수 있다.

## 6. 기존 게임값으로 비교할 첫 표본

## 7. 플레이어가 읽을 화면과 성장 안내
