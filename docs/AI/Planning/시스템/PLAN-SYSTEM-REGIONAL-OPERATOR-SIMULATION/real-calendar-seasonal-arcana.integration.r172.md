## 1. 확정 — 현실 환경은 계속 흐르고 경영은 실제 수행 기록으로 쌓인다

**현실 달력·계절·절기와 최신 검증 공공자료를 플레이의 현재 환경으로 읽고, 그 안에서 사용자가 이번 주의 운영 방침과 준비된 작업을 선택한다.** 현실 자료가 말한 사실과 게임의 해석/추천을 구별한다.

| 항목 | 승인한 기준 |
| --- | --- |
| 날짜·지역 시간 | 현실 날짜를 계속 따르며 한국표준시를 사용 |
| 경영 주간 | 월요일00:00부터 다음 월요일00:00 전까지. 첫 접속은 현재 주의 남은 기간에 참여 |
| 짧은 플레이 | 같은 현실 주간 안에서 배달·제조·피킹/포장 등 준비된 작업을 여러 번 수행 |
| 절기 전환 | 절기가 드는 날짜의 첫 영업 전에 절기 결산·카드 선택. 작업 중이면 안전한 종료 뒤 안내 |
| 재접속 | 현재 날짜/절기·사용 가능한 최신 검증 자료를 확인. 부재중 수익·비용·업무 완료를 생성하지 않음 |
| 카드 | 해당 절기의 운영 방침과 일반 추천 우선순위. 수요·비용·처리량 수치 보정 없음 |
| 서울의 역할 | 사용자 답변은 ‘아직 정해진 것이 없음’. r171의 보충 회차 중심안은 미확정으로 유지하고 이번 작업의 전제로 삼지 않음 |

이 승인으로 r165의 ‘턴=가상 영업일’ 후보와 병행 Claude 제안의 ‘영업7일 일괄 진행’을 현실 달력 프로필에 그대로 적용하지 않는다. 기존 가속 캠페인의 저장·규칙을 조용히 바꾸지 않고 개발 수용 시 프로필/저장 호환을 결속한다. 13주 전망·절기 집계는 같은 기록을 읽는 보고 단위이며 또 하나의 시간 진행이나 수익 원장이 아니다.

## 2. 두 시간의 책임과 결정 순회

| 시간/변경 | 책임 | 경계 |
| --- | --- | --- |
| 현실 달력 문맥 | 현재 날짜·주간·계절/절기·예정 경계 계산 | 앱 종료·일시정지 중에도 실제 날짜는 경과. 그 경과를 업무 진행 명령으로 전달하지 않음 |
| 작업 경과 | 실행 중 허용된 배달·제조·포장 등의 시간과 상태 전이 | 기존 업무의 권한·안전·수량·비용·기록 규칙을 따름. 종료 중 따라잡기 없음 |
| 선택/확인 | 카드·운영 방침·안건의 명시적 확정 | 선택만으로 날짜·주차·WorldTick·금액/재고·작업 완료를 진행시키지 않음 |

기존 일반 Core의 `OneTickOneDay`와 [WorldTick 경계](../../../../Architecture/WorldTick과실시간실행경계.md)는 해당 프로필의 계약이다. 이를 현실 하루마다 자동 호출하는 것으로 해석하지 않는다. 특히 [LocalCampaign](../../../../../Ssalddel.Sagajeong.Core/UnityPackage/Runtime/LocalCampaign.cs)의 고정2026-01-01 기점·가상 `Day`와 현실 날짜는 별개다. 기존 작업의 약속/기한을 현실 시각으로 일괄 재해석하지 않는다.

### 한 주 안의 절기 전환

예를 들어 수요일이 절기 변경일인 주는 다음과 같다. 실제 연도별 날짜를 지정한 예가 아니다.

```text
월요일 주간 계획·결정 순회 → 월·화 실제 수행
→ 수요일 첫 영업 전: 지난 절기 집계·확인 → 현재 절기 카드/중립 운영 확인
→ 같은 주의 수~일 작업 → 주간 집계·확인
```

- 주간 계획·진행 업무·자금·업무 ID를 초기화하지 않는다. 계획/순회 재진입은 새 주의 생성이 아니다.
- ‘다음 결정’은 남은 안건/작업/결산으로 안내한다. 현실의 다음 날이나 다음 주를 즉시 만들지 않는다. 배속도 현실 날짜·절기·주차를 앞당기지 않는다.
- 절기 집계와 주간 집계는 동일 행위/재무 기록을 각 기간으로 조회한다. 결산 확인 자체에 새 영업 수익·급여·보상을 붙이지 않는다.
- 며칠 쉬었으면 현재 주/절기에서 다시 참여한다. 지난 절기의 선택을 순서대로 요구하거나 활동 없는 주간의 영업 결과를 합성하지 않는다.
- 지난 기간에 실제 기록이 있으면 기간별 결과로 조회할 수 있다. 미완료 작업·안건은 보존하고 현재 허용 행동/인계 가능 여부를 다시 확인한다. 지난 날짜라는 이유만으로 완료·손실·비용을 만들지 않는다.
- 현실 날짜는 앱을 정지해도 바뀐다. 직접 조작 중에는 안내가 카메라/입력을 빼앗지 않고 다음 안전한 작업 시작에서 현재 문맥을 읽는다.

## 3. 달력과 공공자료의 적용

첫 운영 프로필은 **한국표준시 날짜 단위**로 절기를 적용한다. 공식 원문에 절입 시각이 있으면 원문 근거로 보존하되, 게임의 일 단위 적용과 천문학적 절입 순간을 같은 값으로 표시하지 않는다. 절기 날짜·주간 경계·자료 판본은 표현 프레임에서 재계산하지 않고 공통 조회 결과로 전달한다.

한국 24절기의 명칭/순서와 연도별 날짜는 [한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do) 및 [공식 월력요항](https://astro.kasi.re.kr/life/post/almanac?year=2026)을 입력으로 삼는다. 달력자료의 사전 계산표와 공식 발표를 구별하고 매년 같은 날짜·한 절기15일을 사용하지 않는다. 공식 안내/서비스 설명은 2026-11-13 조사에서 확인했으며 이번에 새 원자료 취득·DB 반입·수집 예약 변경을 수행한 것은 아니다.

| 자료 종류 | 새 접속/갱신에서 할 일 | 진행 작업 보호 |
| --- | --- | --- |
| 기상·가격·출하 등 관측 문맥 | 사용 가능한 최신 **검증** 사본을 확인하고 원래 기준기간·관측/수집일·지역·출처 표시 | 현재 작업은 시작한 사본으로 끝내고 다음 안전한 작업 시작에 새 문맥 적용 |
| 도로·건물·주소·경계·이동망 | r54/r55의 지역 manifest·projection 고정, 다음 세션 또는 별도 Migration Preview 유지 | 이동 중 도로/건물을 교체하지 않음. 저장 영향 검토 실패 시 기존 판본 보존 |
| 연도별 달력 | 공식 근거와 검증된 연간 판본 사용 | 자료 없음/검증 실패는 확인 불가 상태와 마지막 검증 자료를 표시. 미래 절기를 추정해 확정하지 않음 |

‘최신’은 제공기관이 공개하고 우리가 검증한 판본이라는 뜻이다. 분기 인구를 오늘의 실시간 인구로 표시하거나 수집일을 관측일로 바꾸지 않는다. 다운로드 중에는 현재 사용할 검증 판본/기준일을 표시하고, 검증되지 않은 파일을 활성 자료로 바꾸지 않는다. Unity가 외부 공공 API를 직접 매 프레임 호출하지 않으며 기존 수집/DB·검증 캐시·팩 경계를 소비한다.

봄·여름·가을·겨울과 절기는 공통 시간 문맥이고, 날씨·가격·제철은 각각의 자료다. 겨울을 이유로 폭설을 만들거나 제철 품목이라는 이유로 매출 증가를 확정하지 않는다. 카드 추천에 자료가 부족하면 근거 부족을 표시하고 기존 업무 선택을 유지한다.

## 4. 첫 절기 운영 카드 프로필

첫 버전은 기존 카드 정체성/그림을 재사용하는 **전차·절제·여제 고정3후보**다. 새 순환 덱·복사본·확률 뽑기를 만들지 않는다. 기존 일반 타로 `starter-12.r1`이나 r15의 버림/소진/재섞기 완료로 보고하지 않는다.

| 후보 | 일반 추천에서 앞세울 준비/대응 |
| --- | --- |
| 전차 | 운송 준비·배차·인계 점검 |
| 절제 | 재고·인력·예산 균형 |
| 여제 | 계절 상품·점포·제조 준비 |

- 필수·긴급의 기존 우선순위를 유지한 뒤, 일반 추천에서 관련 범주를 앞에 두고 근거를 설명한다. 적합한 안건이 없으면 없다고 표시한다. 카드를 위해 가짜 수요·사건·작업을 만들지 않는다.
- 확인은 현재 절기의 방침을 저장할 뿐 발주·배차·개업을 자동 확정하지 않는다. 현실 관측값과 가상 수요·비용·처리량을 변경하지 않는다.
- 관찰만 하는 사용자는 선택 없이 볼 수 있다. 경영 참여 전에는3후보 중 하나 또는 중립 운영을 확인한다. 중립도 기본 업무를 완료할 수 있다.
- 소유 주체·절기 기간·프로필 판본에 결속해 같은 절기의 선택/확인은 한 번만 적용한다. 저장/복원·재접속으로 다시 선택하거나 중복 활성화하지 않는다.
- 새 절기에는 이전 활성화를 종료하고 새 활성화를 만든다. 다음 절기에 같은 카드를 골라도 새로운 기간의 선택으로 허용하며 이전 결과는 소급 변경하지 않는다.
- 첫 운영 프로필에 정·역방향과 수치 효과를 추가하지 않는다. r15의 세계 문맥형 방향, 바보 여정 루트, 기사 개인 타로와 [기존3일차 운영 방침](../../../../../Ssalddel.Sagajeong.Core/UnityPackage/Runtime/LocalCampaign.cs)은 각 계약을 보존한다.

기존 [턴 마감 Confirm](../../../../../Ssalddel.Simulation.Domain/UnityPackage/Runtime/SimulationTurnClosing.cs)은 시간 진행을 포함하므로 절기 선택용으로 그대로 호출하지 않는다. 기존 문맥형 카드의 [활성화 수명](../../../../../Ssalddel.Simulation.Domain/UnityPackage/Runtime/SimulationArcanaTownLife.cs)도 이 프로필의 절기별 종료/재활성화와 같다고 가정하지 않는다. 카드 정체성·검증/이력의 순수 규칙을 재사용하고 시간 진행 없는 선택 경계를 결속한다.

## 5. 표현과 공통 계약

상단에 오늘 날짜·계절·절기일/현재 절기 문맥·이번 주 기간·다음 절기를 읽게 한다. 자료 상세에는 사용 중인 실제 기준일·출처·검증 상태를 표시한다. 같은 절기 선택을 동/구/서울/전국에서 각각 다시 묻지 않고 지도와 독립된 공통 안건으로 한 번만 처리한다.

공통 연결 의미는 다음 네 가지다. 이름은 새 공개 wire 계약을 확정한 것이 아니며 기존 안정 ID·직렬화 필드를 재사용/확장하는 명세에서 결속한다.

1. 현실 달력 조회: 기준 시각/시간대·현재 날짜·주간 기간·절기/다음 절기·달력 판본과 확인 상태.
2. 자료 문맥 조회: 관측기간·지역·manifest/projection 또는 관측 사본 판본·출처/검증 상태.
3. 절기 운영 선택: 소유 주체·절기 기간·프로필/제안·선택 또는 중립·확인 이력. 카드 선택은 작업 경과를 진행하지 않음.
4. 기간 집계 조회: 기존 행위/재무 기록의 주간/절기 요약·미완료/대기. 보고 열람/확인은 기록을 재지급하지 않음.

현재 결정 순회/지역 역할 구현은 개발 담당이 실제 소유 경로·현행 계약을 대조한 뒤 연결한다. 새 공식 Scene·새 OS·다른 Core·수집 예약·지구본/서울 업무를 이 기획만으로 추가하지 않는다. 화면 개발은 기존 시안 선행/대조 절차를 따르며 이번 문서에는 새 이미지/실제 화면이 없다.

## 6. 완료 조건과 개발 반환

| 검증 상황 | 필요한 결과 |
