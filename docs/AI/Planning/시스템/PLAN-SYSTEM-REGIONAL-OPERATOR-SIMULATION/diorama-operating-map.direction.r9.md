# [기획 · 디오라마 운영 지도 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r9]

2026-10-25. `DioramaOperatingMapDirectionConfirmed / MobileDesktopPriorityRetained / PlanningOnly`.

사용자는 디오라마 자체를 맵으로 두고 그 지도를 보며 운영하는 Unity 방향을 제시했다. 직전의 모바일·데스크톱 앱 집중 기준과 연결해, Unity의 우선 역할을 공간을 통한 운영 상황 파악과 기존 업무 진입으로 좁힌다. 이번은 방향 정리이며 Unity 코드·Scene·추가 플레이 실행을 재개하지 않는다. [r8의 첫 가상 출고 플레이와 보류 기록](multi-center-fulfillment.unity.r8.md)은 보존한다.

## 화면의 중심

디오라마 지도가 화면 대부분을 차지한다. 매장·공간·물류 거점과 기사·작업자의 상태, 주문/입출고/운송의 연결을 지도 위에서 요약한다. 대기·진행·완료·담당 부재·지연은 색과 상태 문구/아이콘을 함께 써서 구분한다. 색만으로 업무 상태를 전달하지 않는다.

지도 객체 선택 → 해당 장소/사람/업무 요약 → 기존 업무 상세의 순서로 연결한다. 예를 들어 거점을 선택하면 재고·입고 대기·출고 지시·담당 공백을 보고, 기사를 선택하면 현재 맡은 업무와 그 업무에서 허용한 위치 정보를 본다. 로그인·권한과 공개 범위는 원래 앱의 기준을 유지한다. 정확한 고객 전달지·비공개 연락처는 지도 기본 화면에 올리지 않는다.

지도에서 간단한 업무 버튼이 필요해지면 기존 원장과 명령 포트를 그대로 사용한다. 수락·취소·배차·피킹 같은 명령을 지도 자체의 규칙으로 처리하지 않고 기존 로그인·권한·개정 충돌·업무 조건 검사를 거친다. 복잡한 입력·증빙·계약·정산 상세는 모바일·데스크톱 앱의 기존 업무 화면으로 이어진다. 상세 화면 진입 방식과 허용 버튼은 후속 구현 범위에서 정한다.

## 상태와 자료의 기준

- 업무 원장이 상태를 소유하고 디오라마는 그 조회 결과를 표현한다. Unity용으로 별도의 주문·재고·배차 상태를 복제 운영하지 않는다.
- 모의 회차는 기존 Simulation Session, 실운영은 기존 서버 원장을 사용한다. 모드·출처·개정·마지막 수신 시각과 조회 실패를 표시한다. 모의 재고/인물/위치를 운영 화면에 섞지 않는다.
- 실제 위치·관측 위치·추정 위치·분위기용 애니메이션을 구분한다. 캐릭터가 목적지에 도착한 표현만으로 픽업·전달·업무 완료를 만들지 않는다. 실제 GPS 연결이 없는 대상은 현재 위치로 표시하지 않는다.
- 지도 보기 저장은 카메라 위치·확대·필터·선택 같은 표시 설정으로 한정한다. 업무 상태 저장·복구는 기존 원장의 기능을 재사용한다.
- 기존 도로 선분·매장·거점 고유 ID와 자료 판본을 연결한다. 실제 주소/도로와 3D 배치의 대응이 검증되지 않은 모형을 실제 지점으로 표시하지 않는다. 주행 영상·도로/디오라마의 준비 수준은 별도로 유지한다.

## 첫 화면을 만들 때의 범위

기존에 근거가 있는 작은 지역/거점 하나에서 시작한다. 지도와 업무 조회 결과를 연결하고, 장소 선택·업무 요약·기존 상세 진입·연결 실패/오래된 자료 표시부터 검증한다. 기존 데이터가 없는 NPC·운송 동선·건물 내부를 새로 채우는 작업을 선행조건으로 두지 않는다. 전체 계약·고용·물류 게임이나 전국 디오라마 제작으로 범위를 넓히지 않는다.

후속 구현 시 모바일·데스크톱의 실제 업무 완성을 우선하며, Unity는 같은 업무를 공간에서 살펴보는 지도 역할부터 붙인다. 이번 문서 정리로 실제 데이터 연결·지도 클릭 연동·운영 활성화·학습·배포가 완료된 것은 아니다.
