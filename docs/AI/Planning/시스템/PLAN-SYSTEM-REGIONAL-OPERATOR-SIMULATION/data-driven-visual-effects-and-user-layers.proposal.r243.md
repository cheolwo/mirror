| 묶음 | 모으는 내용 | 현재 준비 결과 |

자료가 있는 상태, 효과 코드가 있는 상태, 실제 일반판에서 그 자료로 효과를 확인한 상태를 각각 남긴다. 예를 들어 군중이 배회해도 유동인구 통계와 연결됐는지는 별도로 확인한다.

## 2. 데이터 모양에 맞는 표현을 고른다

| 입력의 모양 | 연결할 표현 | 읽는 의미 |
| --- | --- | --- |
| 위치가 있는 지점과 숫자 | 중심점과 제한된 후광, 작은 기둥 | 확인된 위치별 값과 차이. 원값은 눌러 확인한다. |
| 행정동 코드와 기간별 집계 | 동 경계의 음영·테두리와 범례 | 같은 기간·같은 단위의 동별 비교. 공간 대응이 안 된 값은 목록에 남긴다. |
| 실제 연결된 출발·도착 또는 경로 점열 | 관계선·도로를 따른 선·운송 곡선 | 출발/도착 관계와 경로의 차이. 점열이 없을 때는 관계선임을 표시한다. |
| 위치와 시각을 가진 사건 | 짧은 핀·착지 파동·일시 강조 | 언제 어디에서 어떤 일이 기록됐는지. 오래된 사건 재생은 재생 시각을 표시한다. |
| 시각별 위치 기록 | 경로 위 점과 지나간 흔적 | 해당 기록의 이동. 자료가 없는 구간은 공백으로 남긴다. |
| 건물 ID와 상태 | 건물 테두리·지붕 강조·선택 카드 | 같은 건물의 자료 연결. 내 사업의 소유 색과 다른 레이어의 지표 색은 범례로 구분한다. |
| 공표된 인구·시간대별 유동 통계 | 영역 비교와 통계 참고 군중 연출 | 통계의 분포·시간대 차이. 군중은 모형에 따른 표현임을 표시한다. |
| 관측·예측 기상 또는 게임 계절 | 빗방울·안개·나무색·지면 분위기 | 관측/예측의 지역·유효시각 또는 가상 계절. 각 입력의 종류를 읽을 수 있게 한다. |
| 음악의 재생 위치·음량·주파수 특징·박 정보 | 느린 호흡과 약한 밝기 변화 | 장식적 음악 반응. 업무·명덕의 기본 값은 해당 상태 기록을 따른다. |

행정동 전체 인구를 동 중심 한 점의 밀도로 그리면 실제로 그 지점에 사람이 몰린 것처럼 보일 수 있다. 이 경우 영역 음영을 먼저 사용한다. 국가별 무역 합계로 개별 선박의 항로·위치를 만들어 표시하는 것도 별도 가상 모형이 필요하다.

## 3. 사용자 자료를 들여오는 제안 흐름

1. **자료 고르기.** 처음에는 로컬 CSV/GeoJSON의 읽기 전용 사본이나 기존 DB 조회 내보내기를 후보로 삼는다. 원본을 선택하면 열 이름·행수·자료 기간·단위·출처를 먼저 본다.
2. **위치 연결하기.** 검증된 경도/위도, 해당 지도 판본의 건물 ID·행정동 코드, 사용자가 명시한 로컬 배치 중 맞는 방식을 고른다. 좌표계·ID의 판본·단위를 확인한다. 주소만 있는 행은 주소 연결 검토 결과를 먼저 받는다.
3. **값과 표현 연결하기.** 어떤 열을 숫자·분류·시각으로 읽을지 정하고, 점·영역·선 중 맞는 표현을 고른다. 값→크기/색/높이/진행 속도의 대응과 범례를 미리 본다.
4. **확인한 범위 표시하기.** 연결된 행과 미연결 행 수를 보여 주고 미리보기에 적용한다. 같은 고유 ID의 갱신·삭제는 기존 점을 따라 처리한다. 레이어를 꺼도 원본 값과 게임의 정상 업무 기록은 각자의 상태로 유지한다.

첫 입력 후보는 **지점 위치와 숫자 하나를 가진 작은 표**다. 지점을 찍고 후광 크기로 값을 비교하는 흐름부터 준비하면, 공공 시설·개인 관찰·사업장 지표를 같은 방식으로 검토할 수 있다. 이는 추천 범위이며 실제 가져오기 도구는 후속 개발이다.

## 4. 공통으로 남길 항목

| 항목 | 의미 |
| --- | --- |
| 자료 ID·판본·파일 SHA | 같은 자료의 갱신·중복·재현을 확인한다. |
| 출처·기준/유효시각·단위 | 무엇을 어느 기간에 센 값인지 표시한다. 순간값과 일/분기 합계를 구분한다. |
| 원본 좌표계·변환·지도 모듈 판본 | 원본 위치가 어느 화면 좌표로 옮겨졌는지 보존한다. GeoJSON은 확인된 WGS84 경도·위도 순서를 쓴다. |
| 대상 고유 ID·위치 연결 상태 | 지점·건물·행정동 중 무엇에 연결했는지와 미연결 이유를 남긴다. |
| 표현 설정·눈금·범례 | 같은 기간·다른 동을 볼 때도 같은 값은 같은 크기와 색으로 읽히게 한다. |
| 결측·0·범위 초과 | 결측과 0을 구분하고, 화면 크기 상한을 적용해도 원값과 상한 적용 사실을 보존한다. |
| 표시할 열·공유 범위 | 개인 자료는 사용자가 선택한 표시 정보만 레이어로 연결한다. 공유용 자료에는 허용된 열을 별도로 내보낸다. |

[합성 예제](visual-layer-example.r243.json)에는 미터 단위의 지점 네 개와 값 `20`, `80`, `0`, `null`을 넣었다. 실제 업소·지리 위치와 연결되지 않은 설명용 입력이다. 같은 고정 눈금에서 후광을 비교하고 결측과 0을 다르게 읽는 대응을 확인할 수 있다. 지도 모듈과 원점은 아직 지정하지 않았다. 이 예제의 형식은 기획 검토용이다.

## 5. 편안한 관찰 화면에 맞추기

[r242 자율 관찰](role-perspective-research-and-relaxed-observation.design.r242.md)과 [r157 선택형 효과](optional-map-visual-effects.design.r157.md)를 이어간다. 표시할 레이어와 움직임의 양은 사용자가 고른다. 첫 표현 후보는 약한 정적 후광·영역 음영이고, 파동·흐르는 빛·음악 반응은 추가 선택으로 둔다. 이 기본값과 강도는 추천안이다.

선택한 자료 한두 개가 먼저 읽히도록 나머지는 접고, 수치의 단위·기간과 범례를 함께 본다. 확대해도 중심점은 구별되고, 겹친 후광은 상한과 옅어짐을 둔다. 화면의 입자 수·맥동 속도를 업무 수·명덕·실제 사람 수로 읽지 않게 한다. 표시를 끄거나 설명을 읽는 행동으로 시뮬레이션 시계와 정상 업무를 추가 진행시키지 않는다.

## 6. 현재 준비와 다음 구현 단위

현재 준비물은 출처가 붙은 자료·표현·기술 문서 대장, 그 대장을 읽는 안내, 합성 입력 예제다. Unity의 임의 파일 가져오기·설치·실행과 원본 DB 쓰기·수집 예약은 이번 산출물에 포함되지 않는다.

후속 구현의 첫 완료 조건은 같은 표를 읽고 지점 ID·위치·원값을 보존한 채 서로 다른 값·0·결측을 구별해 표시하는 것이다. 다시 불러오기·갱신·삭제, 잘못된 좌표계·중복 ID·범위 밖 값과 지도 복귀를 같은 자료 판본으로 확인한다. 다른 모듈의 통계나 게임 경제가 바뀌지 않는지 대조한다. 이때 사용할 화면은 기존 시안 절차를 따른다.

Graph Map 영향은 자료→공간 대응→표현 레이어→선택 정보→원래 관점 복귀의 검토 후보다. 이번 수집·예제만으로 공용 디오라마 규칙이나 실제 배치 증거를 승격하지 않는다. 새 디오라마 규칙 후보 없음.

**확정** · 표현에 쓸 자료와 방법을 모은다. 사용자 자기 자료를 디오라마에 연결하는 준비 방향을 포함한다.

**미정** · 첫 입력 형식·위치 연결 방식, 효과별 기본 강도·성능 한도, 사용자 레이어 실제 저장·공유·갱신과 개발 수용.

**다음 질문 하나** · 첫 사용자 입력은 위치와 숫자 하나가 있는 지점 표를 후광으로 보여 주는 방식부터 시작할까? 추천은 이 작은 입력으로 위치와 값이 정확히 연결되는지 먼저 확인하는 것이다.
