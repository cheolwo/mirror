## 확정 · 손님이 모이는 화면을 광고 경영의 공통 바탕으로 삼는다

손님은 한 화면에서 여러 음식점과 메뉴를 비교한다. 이곳에서 선택받고 싶은 점주에게 상단의 노출이 가치가 있다. 홍달 플레이스의 장소 검색과 배달 음식 목록은 같은 게임 점포와 손님의 관심을 바탕으로 운영한다. 매장의 정보, 손님이 본 자리, 그 자리에서 이어진 주문을 세 입장에서 읽을 수 있게 한다. r60의 공개 주소는 장소 정보에 쓰고, 여기서 다루는 매장 경쟁·주문·광고는 게임 점포와 가상 손님의 활동으로 구성한다. [주소와 공개 자료 r60](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/hongdal-place-address-data-and-distribution.proposal.r60.md) · [기존 홍보와 주문 유입 r176](place-search-advertising-and-demand.proposal.r176.md)

## 제안 · 같은 매장 정보로 두 목록을 보여 준다

| 화면 | 손님이 찾는 것 | 기본 후보와 비교 기준 |
| --- | --- | --- |
| **장소 찾기** | 근처에 어떤 음식점이 있고 찾아갈 수 있는가 | 역세권·업종·검색어에 맞는 장소. 거리, 업종, 정보 기준일과 확인된 영업 상태를 표시한다. |
| **배달 주문** | 지금 내 위치로 시킬 수 있는 음식이 무엇인가 | 배달 가능 구역 안에서 주문을 받고 해당 메뉴를 판매 중인 점포. 가격과 배달 예상시간을 보여 준다. 가상 점포만 주문 대상으로 사용한다. |

같은 게임 점포의 메뉴·주소·운영 상태는 같은 식별자로 읽는다. 배달이 닫힌 매장도 방문 정보가 있으면 장소 찾기에 남을 수 있다. 장소 찾기의 결과나 광고를 배달 화면에서 자동으로 반복하지 않는다. 손님이 지금 보는 목록과 주변 지역, 원하는 음식, 시간대가 각각 노출의 문맥이다. 지도에서는 역을 고르면 이 화면으로 들어갈 수 있다. 검색·목록·상세가 흩어질 경우 새 메뉴를 만들기 전에 기존 주문자 뷰의 진입을 재사용한다. [주문자 뷰 개발 계획](../../../Handoffs/2026-11-15-Claude-개발계획-홍달플레이스-종합-정본하나뷰셋.md)

공통 기록에는 목록 종류, 세션, 점포, 지역·음식·시간대, 실제 본 기본 또는 광고 자리, 이어진 열람·주문 식별자를 남긴다. 배달 음식 목록은 지금 주문할 후보를 보여 주고, 주문 진행과 이력은 주문 접수 이후의 기존 기록에서 읽는다. 광고 위치를 선택하거나 손님 입장에서 보기만 하는 행동은 접수를 확정하지 않는다.

## 제안 · 상단의 광고 자리와 경영 선택

1. **기본 목록을 먼저 만든다.** 장소 찾기는 검색 의도·거리·정보, 배달 주문은 지금 시킬 수 있는 메뉴·서비스 범위·예상시간을 우선 읽는다. 자연 결과의 점수와 페이지는 r238을 참조하고 이번 판에서 가중치를 새로 고정하지 않는다. [검색·순위와 노출 기록 r238](hongdal-place-population-keyword-search-and-ranking.proposal.r238.md)
2. **조건에 맞는 점포에 광고 자리 한 칸을 준다.** 첫 사례는 목록 상단 `광고` 한 칸이다. 점주는 예산·지역·음식 종류·시간대를 고른다. 확정된 기간에 해당 조건의 가상 손님이 목록을 열면 적합한 광고가 노출된다. 기본 순위는 따로 유지하고 같은 화면에 동일 점포가 두 번 나오지 않게 한다. 주문을 쉬거나 메뉴가 품절이면 그 배달 목록의 광고도 멈춘다. 조건에 맞는 광고가 없으면 기본 목록이 위에서 바로 시작한다.
3. **광고비가 만든 기회와 현장의 결과를 이어 본다.** 같은 결산에서 `목록 노출 → 매장 상세 열람 → 주문 접수 → 배달 완료`를 구별한다. 점주는 광고 경유 주문과 쓴 비용을 보고, 플랫폼 운영자는 노출 지역의 주문 증가와 지사 처리 여력·지연을 함께 확인한다. 경유 건수는 광고가 없었을 때보다 늘어났다는 인과 효과와 구분한다. 플레이어가 결과를 열거나 새로고침하는 행위는 새 노출·비용·주문을 만들지 않는다. [일일 결산 r174](live-calendar-daily-management.baseline.r174.md)

| 같은 점심 회차를 읽는 입장 | 보는 것과 선택 |
| --- | --- |
| 주문자 | 사가정역 주변 `치킨` 배달 목록에서 광고 표시, 가격, 도착 예상시간을 보고 어느 점포를 열지 결정한다. |
| 점주 | 한 점심 회차에 더 보이도록 예산을 쓰거나, 메뉴·영업 준비를 개선해 다음 노출 기회를 기다린다. 마감 뒤 노출·열람·접수·완료를 비교한다. |
| 플랫폼 운영자 | 손님이 많이 찾는 목록과 주문이 몰린 지역을 보고, 노출 확대를 계속할지 지사 처리 여력과 약속 시간을 먼저 보완할지 결정한다. |

## 첫 검증 범위

사가정역의 배달 주문 목록 한 개, 음식 분류 하나, 가상 점포 여러 곳 중 광고 신청 점포 하나, 점심 회차 하나를 먼저 범위로 제안한다. 같은 목록에서 광고 자리와 기본 결과, 점주·플랫폼의 결산 결과를 대조한다. 광고 미집행, 품절, 배달권 밖, 예산 소진에는 추가 집행 없이 기본 목록으로 돌아가는지 확인한다. 같은 회차를 다시 조회하면 실적은 한 번만 기록되어야 한다.

현재 Unity 작업본 `f4b0ac7`의 기존 동 지도 주문자 화면은 검색·목록·상세·지도 핀을 그리며, 상세의 주문 버튼은 준비 전 상태다. 구 지도 K1의 역 키워드 창은 별도 시험 값으로 동작한다. 11월 20일 보관 빌드와 소스에서 창이 있는 것은 확인했으나, 두 화면이 같은 점포·노출 기록을 사용하거나 광고에서 주문까지 이어지는 실행은 확인되지 않았다. 이번은 두 흐름의 공통 설계 제안이다.
