# [기획 · 7턴 배달 위기 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r128]

- [기사 네트워크와 광복 r127](rider-network-and-liberation.proposal.r127.md)의 기사 확대에 운영 압박을 더한다. 첫 검토는 사가정 음식 배달의 6→7턴과 기사 C 한 명의 합류까지다.

## 7턴마다 오는 물량 증가

첫 검토에서는 기존 캠페인의 가상 영업일 하나를 운영 턴 하나로 센다. **7·14·21턴이 시작될 때 해당 턴의 신규 주문 예정 물량이 늘어난다.** 배속은 영업일 안의 시간만 바꾸며, 기존 3일차 마감의 운영 방침 선택과 별도로 센다. 6턴 마감에는 다음 턴의 예정 주문과 예상 처리 여력을 보여준다. 같은 턴을 다시 열거나 재생할 때는 같은 주문 묶음을 사용한다.

첫 안은 평소 주문량을 유지하고 7턴마다 오는 피크의 크기를 단계적으로 높인다. 기존 주문을 더 빨리 발생시키는 규칙과 신규 주문을 늘리는 규칙을 구분한다. 화면은 예정 물량과 기존 운영 방침을 적용한 뒤 배차를 기다리는 실제 건수를 따로 센다. 미처리 주문은 해당 턴 결산에 남기고, 다음 턴으로 넘기는 규칙은 기존 캠페인과 대조한 뒤 정한다.

## 위기 판단과 대응

- **기사 부족**은 해당 피크에 배차 가능한 기사들의 남은 운행 시간과 처리 속도로 계산한 예상 처리량이 배차 대상 주문량보다 적을 때 나타난다. 등록·교육·운행·휴식 상태를 구분한다. 피크에 가상 주문 8건이 들어오고 A·B가 6건을 처리할 수 있다면, 화면에 부족한 2건을 먼저 보여준다.
- **사고 위험과 사고율**은 따로 표시한다. 처리량 부족으로 휴식 없이 운행을 이어가는 경우처럼 가상 위험 요인이 겹치면 경고한다. 사고율은 같은 길이의 비교 구간에서 결과가 확정된 가상 운행 중 사고가 기록된 운행의 비율로 표시한다. 운행이 없으면 미집계로 두고, 표본이 적을 때는 건수와 분모를 함께 보여준다. 사고율이 오르거나 이미 높은 상태에서 주문도 밀리면 위기가 심해졌다고 표시한다. 위험과 사고 기록은 게임 안의 값이다.
- **첫 대응은 기사 한 명 확보**다. 운영자는 예고를 보고 [기존 모집·입교 흐름 r126](rider-profile-draw-and-academy-film.proposal.r126.md)을 통해 기사 C를 준비한다. 교육을 마치고 피크에 배차할 수 있게 된 뒤부터 처리 여력에 포함한다. 같은 주문으로 C 합류 전후의 미배차 건수와 교대 여유를 비교한다.

## 첫 검토 기준

6턴 마감에 예고가 뜨고 7턴 시작에 주문이 한 번 늘어난다. 7턴을 다시 열어도 주문이 중복되지 않으며 14턴 시작에 다음 피크가 한 번 온다. 첫 비교에서는 A·B만 있는 경우와 수료한 C가 들어온 경우의 주문, 처리 여력, 미배차를 같은 조건에서 읽을 수 있어야 한다. 위험 경고와 실제 가상 사고 기록의 차이는 동일한 가상 운행 표본으로 점검한다.

확정한 범위는 7턴 주기의 압박, 기사 부족과 사고율 상승이 겹치는 위기, 모집을 통한 첫 대응이다. 턴별 주문 증가량과 위험 가중치는 시제품 조정값으로 남긴다. 광복 판정은 r127의 정신 차림 시간·소득 추세를 유지한다.
