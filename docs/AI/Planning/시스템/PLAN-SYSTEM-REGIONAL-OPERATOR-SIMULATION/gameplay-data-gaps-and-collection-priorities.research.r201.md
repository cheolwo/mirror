## 1. 결론 — 현실 자료를 한 업무의 선택·대가·결과로 연결할 정보

**가장 큰 공백은 행정동·건물·상품·직원·시간·비용·인계를 같은 업무에 연결하는 정보다.** 이미 지역/인구·인허가/메뉴·시설·가격/무역·공식 절차 자료가 있지만, 그 자료만으로 한 주문의 준비·이동·재료 소모·대기·이익을 계산할 수는 없다.

추가 준비는 세 갈래로 나눈다.

1. **공공 원자료 보충:** 주민등록/세대·업종별 추정매출·주소/출입구·비용 통계·날씨/달력 등.
2. **기존 자료 결속/허용 표본:** 동–건물–접근 경로, 메뉴–재료/양–장비–직원, 공급처–SKU–재고/납기, 작업시간/오류·회복 등.
3. **게임에서 선언/비교할 값:** 연구비/기간·보상·해금·가상 기본수요/전환율·직원/장비 효과. 공개 통계를 찾아 자동으로 정할 값이 아니다.

플레이 상황은 선택한 사업의 작은 업무에서 시작한다. 운영자는 인력·장비·메뉴/상품·일정·예산 중 무엇을 바꿀지 고르고, 고객/파트너의 필요를 같은 업무 결과로 확인한다. 지연·품절·재작업에는 시간/돈과 회복 행동이 든다. 자료는 이 인과를 설명하는 보조 층이며 조회량/다운로드 수가 직접 성장·수익이 되지 않는다.

## 2. 확인 범위와 현재 보유의 의미

[자료 여섯 묶음](../../../DataCollection/GameMaterialGroups/README.md), [현재 수집/예약 진입](../../../DataCollection/README.md), 최근 분야별 실제 수집 보고/갭 대장, r183/r187/r190/r199/r200과 해당 Unity 수요 팩/소스의 좁은 읽기 근거를 대조했다. 공식 후보의 현재 제공 항목/접근 경로를 웹으로 확인했다. 모든 원본/공급자 API/실DB·게임 실행을 새로 전수 검증한 조사는 아니다.

## 3. 부족 자료와 우선순위

**P0는 선택한 분야의 첫 업무를 설명하는 최소 준비, P1은 현실 보정/환경 보강, P2는 이용 분야가 열릴 때의 범위 확장**이다. 모든 P0를 전 분야에 동시에 요구하거나 배달→카페→광고→전자상거래→무역의 선행 사슬을 만들지 않는다. 표의 우선순위는 제안이다.

| 항목 | 우선 | 더 필요한 최소 필드 | 판단/확보 방식 |
| --- | --- | --- | --- |
| 업무 대상의 동일성/판본 | P0 공통 | 고객사/캠페인·상품/거래·파트너 등 해당 대상 ID/역할·자료 지문/판본. 필요한 업무에는 행정동 유효기간/경계·건물/주소/출입구 대응 추가 | 같은 대상의 선택/결과인지. 광고/전자상거래/무역에 동네 건물 결속을 일률 전제로 요구하지 않으며 지도 대응은 필요한 범위부터 검토 |
| 접근 경로/이동시간 | P0 배달/운송 | 유효 노드/링크·방향/통행 제약·입구 연결, 이동/정차/픽업 대기시간 | 기사 추가·경로/약속 선택. 보행망을 오토바이망으로 쓰지 않고 누락/연결 검증·허용 표본과 가상 주행 프로필 분리 |
| 고객/업종 수요 보정 | P1 | 주민등록/세대·직장/활동 규모, 동×업종/기간의 추정매출/거래, 시간/요일의 원래 집계 정의 | 인구가 무엇의 주문 기회가 되는지. 매출/카드거래를 배달 주문 수로 동일시하지 않음. 첫 수요 기본값은 명시한 가상값으로 검토 가능 |

플레이 기록에 결과 ID가 있다는 것과 검토 세션의 통합 비교 데이터가 준비됐다는 것은 다르다. 이 조사는 기존 로그/원장이 전혀 없다는 판정이 아니다. 긴 플레이 시간이 재미·만족·현실의 정신 상태를 증명하는 지표도 아니다. 성공/실패 이유·다음 선택 이해·회복 가능성을 결과/피드백과 함께 본다.

## 5. 공공 원자료가 정하지 못하는 것

**공급처의 실제 재고/MOQ·현재 견적/납기, 현장의 랙/입구/작업 동선·실효 처리량, 업종/고객의 주문 전환·이탈/반품, 가상 연구/성장 효과**는 해당 표본/조건 또는 게임 설계가 필요하다.

- 현실을 보정할 표본은 공개/허용된 운영 자료나 직접 관찰의 집계로 준비하고 시점/조건·권리를 기록한다. 개인 배달 기록은 필요한 비식별 집계의 별도 범위를 확인하며 고객/주소/개인 정산을 배포팩에 넣지 않는다.
- 가상 프로필이면 사업/상품/작업·파트너·시간/비용을 가상으로 밝히고 불확실 값/단위를 남긴다. 실제 업체에 가상 재고/계약·사건을 붙이지 않는다.
- 장식 군중·센터 등록수·연간 무역금액·키워드 검색수를 실제 주문/매출/개별 납품단가로 자동 환산하지 않는다.
- 공개 원본의 제공조건과 파생팩의 배포 가능 여부를 구별한다. 메뉴 이미지·강의·구매 모델/브랜드 자료의 미확인 권리를 새 수집 성공으로 해소하지 않는다.

## 6. 추천하는 다음 준비 묶음

**플레이어가 고른 분야의 기준 거점/거래 하나 + 작은 업무 하나**를 같은 기준의 자료 묶음으로 만든다. 동네 사업은 한 행정동을 먼저 연결하고, 무역/전국 업무는 그 업무에 맞는 거점/거래에 집중한다. 무역을 시작하기 위해 동네 카페나 자체 센터를 먼저 완성할 필요는 없다. Farm·Hub·City도 각각 독립 업무의 결과를 먼저 검토하며 영역 간 운송을 필수 첫 과제로 삼지 않는다.

| 배달 | 가상 매장/수령지·입구/주행 가능한 경로, 준비/픽업/전달 시간, 기사/가격·비용·유효 주문/결과 |
| 카페 | 가상 점포/메뉴 소수·레시피/재료·직원/장비·작업 시간/일일 비용, 가상 공급/재주문 조건 |

첫 비교는 같은 조건에서 기준 운영과 인력/장비/방침 중 한 가지를 바꾼 운영이다. 대기·처리/미충족·비용/성과·실패 회복/다음 선택이 어떻게 달라졌는지 확인한다. 그 뒤 공공자료 보충의 가치가 큰 항목을 선택해 수집한다. 이 비교안은 실제 시험 수행 결과가 아니다.

## 7. 근거·남은 범위와 반환

현재 보유/미확보의 주요 근거는 [지도 수집](../../../DataCollection/Research/2026-11-13-dong-map-source-intake.md), [음식점/메뉴](../../../DataCollection/Research/2026-11-13-restaurants-regions-menus-intake.md), [경영 연구 실제 수집](../../../DataCollection/Research/2026-11-14-management-research-field-intake.md), [카페 공급망](../../../DataCollection/Research/2026-11-14-cafe-opening-supply-chain-intake.md), [물류시설 DB](../../../DataCollection/Research/2026-11-14-logistics-facilities-db-intake.md), [네이버 API 상태](../../../DataCollection/Research/2026-11-14-naver-keyword-api-intake.md)다. 과거 보고의 ‘미연결’은 해당 보고/소비판의 범위이며 모든 다른 앱/모듈이 전혀 없다는 뜻이 아니다.

이번에는 기획/조사·탐색 문서와 검증 기록만 갱신했다. 자료 본문 다운로드·신청/계정 API 호출·실DB 재조회/쓰기·수집기/예약·Unity/제품 코드·빌드/실행·Graph Map/Goal/WI/E·전역 D·commit/push는 수행하지 않았다. 기존 이미지와 Claude 작업도 유지했다.

**확정:** 사용자의 게임 전반 자료 부족 조사를 수행했다. 기존 자료와 연결 부족/허용 표본/설계값을 구분했다.

**미정:** 우선순위 채택, 첫 분야/동과 표본·원자료 취득 범위, 시간/비용/수요 계수·연구/성장 수치, 정확 계약/시안·개발 수용. 표의 P0/P1/P2는 추천이다.

**다음 질문 하나:** 지금 답변이 필요한 질문 없음. 사용자가 이 결과를 검토한 뒤 선택한 범위의 자료 정리/수집을 별도로 구체화한다.
