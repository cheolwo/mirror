# [기획 · 통합 경영·AI 학습 환류 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · 제안 r1]

2026-10-25. `DirectionRequested / BalancedObjectivesConfirmed / ProposedDesign / CaptureAdapterNotImplemented / WeightTrainingNotStarted / OperationalApplicationNotAuthorized`.

## 사용자 방향과 소유

사용자는 통합 앱 1.0과 연결되는 Unity 경영 시뮬레이션에서 자신과 다른 사용자가 플레이할수록 경험이 쌓이고, 검증된 자료를 AI 학습과 현실 운영 판단 개선에 활용하는 방향을 요청했다. 후속 답변으로 좋은 판단의 기준을 **수익·배송 품질·참여자 보수의 균형**으로 정했다. 동일 비율이나 구체 보상 함수·운영 손실 허용치는 아직 정하지 않았다.

게임 측 정본은 [가상 권역 운영자 기획](README.md)이다. 기존 상위 `PLAN-SYSTEM-OBSERVER-WORLD`와 [업무 세계 우선 공통 목적 r12](../../../게임상위목적-오행순환과광복기-기획-2026-09-02.md)를 유지한다. 실제 AI의 학습 자료 내보내기·평가·운영 적용은 [기존 배차 학습 연결 검토](../../공통/PLAN-OPERATIONS-DISPATCH-CORE/server-ai-learning-readiness.review.r1.md)에 연결한다. 통합 앱 1.0은 제품 목표이며 Unity의 E·WI·기존 승인 기획을 통합 출시 완료로 승격하지 않는다.

이 문서는 게임 경험에서 검토·학습으로 이어지는 제안이다. 기존 게임의 구체 장면·이야기·지역·정책 승인과 개발 인계 상태를 바꾸지 않는다. 기존 README 제목 r108과 기획 판본 필드 r41의 이력도 이 제안 번호로 다시 쓰지 않는다. 새 Goal·WI·자동 수집·학습 작업·운영 적용은 시작하지 않는다.

## 플레이어가 경험할 반복

기존 음식 배달 세계의 자율 반복과 지역 운영자 역할을 첫 연결 후보로 재사용한다. 세계가 계속 업무를 수행하는 동안 사용자는 현재 주문·기사·대기를 보고 허용된 운영 선택에 참여한다. 선택 뒤 시간 경과와 수익·지연·보수 변화를 보고 같은 조건의 다른 선택과 비교하거나 다음 회차로 넘어간다. 별도 교육 문제에 계속 답해야만 게임이 진행되는 구조로 만들지 않는다.

예를 들어 점심 주문이 몰렸을 때 단건 추천·가능한 묶음·대기 중에서 선택하고, 그 결과 기사별 작업과 주문 지연·운영 비용이 어떻게 달라졌는지 결산한다. 선택 가능한 행동과 부작용은 현재 Simulation의 검증된 정책만 사용한다. 새 혼적·인사·정산 정책을 이 예시로 승인하지 않는다. 창고·마트·화물은 각 영역의 독립 플레이와 기록이 확인된 뒤 같은 기록 규약으로 확장한다. Farm→Hub→City 연결을 첫 필수 플레이로 삼지 않는다.

사용자가 제안한 최종 흐름은 다음과 같다.

```text
게임의 상황·가능한 선택 → 플레이어/NPC 판단 → Simulation의 실제 결과
        ↓ 당시 입력과 결과를 분리해 보관
검증 가능한 경험 묶음 → 학습 후보·평가 자료 분리 → 별도 모델 학습
        ↓ 보지 않은 시나리오와 현실의 허용된 관측으로 성능 확인
기존 운영 판단과 나란히 비교 → 검증된 모델 판본의 제한적 추천
        ↓ 현실 결과는 별도 출처로 남기고 Simulation 조건을 보정
다음 게임 회차·다음 모델 평가
```

플레이 수가 늘면 자료를 쌓을 기회가 늘어난다. 이것만으로 자료 적격·모델 성능 향상·현실 전이 성공을 보장하지는 않는다. 같은 시나리오의 반복·대리 플레이·쉬운 상황 편중은 별도로 집계한다.

## 학습에 필요한 기록 제안

영상이나 클릭 횟수만으로는 경영 판단의 조건을 복원하기 어렵다. 기존 기록을 참조하는 별도 파생 adapter가 다음 항목을 묶도록 제안한다. 아래는 설계 항목이며 새 API·DB 필드의 확정 계약이 아니다.

- 출처: 게임/검토된 현실 관측 구분, 회차·시나리오 가족·seed·Core/규칙/경제 조건 판본·입력 hash.
- 판단 직전: 플레이어가 실제로 볼 수 있었던 주문·기사·재고·시간과 허용 후보·배제 사유. 미래 주문이나 숨겨진 전지적 서버 정보는 학습 입력에 섞지 않는다.
- 행동: 선택 후보와 보류·취소, 직접 조작/추천 수락/NPC 자동 실행의 구분, 추천 모델·버전, 선택 이유는 선택적 입력.
- 권위 결과: 명령 접수와 최종 확정, 기대/결과 revision, 작업 종료와 실제 Simulation 효과, 실패·중단·복구. Animation 종료를 업무 완료로 사용하지 않는다.
- 결산: 같은 관찰 기간의 수익/비용·배송 지연/취소·기사와 작업자 보수·대기/작업량. 예상과 확정, 가상 금액과 실제 금융을 분리한다.
- 품질·수집 동의: 중복/무결성·검토 판본·자료 사용 동의와 목적·출처를 연결한다. 공개 사용자 수집의 동의·보관·철회·삭제 방안은 출시 전에 설계하며, 학습 기여를 꺼도 플레이할 수 있게 한다.

선택하지 않은 행동의 결과는 실제 관측으로 만들지 않는다. 같은 seed에서 다시 실행했다면 별도의 가상 비교 회차로 표시한다. 중단한 플레이와 실패도 보존하고, 결과가 없는 경우 실패라고 단정하거나 성공 사례만 남기지 않는다. 과거 기록의 빈 입력은 현재 DB에서 소급 추정해 채우지 않는다.

## 균형 평가

| 평가 축 | 확인할 값 | 설계 경계 |
| --- | --- | --- |
| 수익 | 비용을 반영한 기간 손익·이익률·현금 부족 | 매출 증가를 이익으로 바꾸거나 가상 수입을 현실 실적으로 합치지 않음 |
| 배송 품질 | 약속 시각, 지연·취소·완료율, 실패 후 회복 | 빠른 배송 한 지표만으로 전체 품질을 대신하지 않음 |
| 참여자 보수 | 기사/작업자별 보수·대기/작업시간·부담 편중 | 총 보수만으로 모든 참여자의 편익을 대신하지 않음 |

수익을 위해 보수나 품질을 희생하는 선택이 게임 점수만 높이는 구조가 되지 않도록 세 지표를 함께 보여 준다. 초기는 각 축과 절충을 따로 평가하고, 특정 비율의 단일 점수로 합치는 것은 후속 결정이다. 기존 적재·수락·현재 상태·권한·동의 등의 필수 조건은 점수보다 먼저 검사한다. 별도 운영 정책에 없는 임금·벌점·공제 규칙을 보상 함수로 만들지 않는다.

## 학습과 운영 연결 순서 제안

1. **기록과 재현:** 기존 승인된 음식 배달 반복에서 판단 한 건의 입력→선택→결과를 같은 판본으로 재현한다. 학습을 실행하지 않고도 플레이·저장·결산은 성립해야 한다.
2. **자료 정리:** 기존 corpus에 참조 adapter를 두고 중복·누락·허용 후보를 확인한다. 플레이어 행동은 관측이며 자동으로 정답이 아니다. 기존 사람 검토와 적격 기준을 거친 자료를 구분한다.
3. **첫 학습 후보:** 가능한 주문 조합/기사 후보의 우선순위부터 검토한다. 사례 검색·비교/예측을 먼저 기준선으로 두고, 모방학습·강화학습이 실제 개선을 보일 때 확장한다. AI가 모든 업무 권한과 물리 조건을 스스로 결정하는 범용 모델로 시작하지 않는다.
4. **평가:** 같은 시나리오 가족·유사 반복이 학습/평가에 동시에 들어가지 않도록 나눈다. 미사용 시나리오와 변경된 수요·조리/작업 시간·기사 여력에서 기존 규칙 대비 세 축의 결과·위반·지연을 비교한다. 현실 자료와 차이가 큰 영역은 현실 적용에서 제외하고 시뮬레이터 보정 대상으로 둔다.
5. **운영과 나란히 비교:** 현재 운영은 기존 엔진이 처리하고 새 모델은 판단만 기록한다. 모델이 골랐을 때의 실제 결과는 실행하지 않은 이상 관측 성과로 표시하지 않는다. 성능·지연·실패 복귀·현재 조건 재검사와 별도 적용 승인이 갖춰진 판본만 제한된 추천 단계로 넘긴다.

학습은 별도 작업에서 실행하고 모델·자료·평가 판본을 고정한다. 사용자가 플레이하는 중간이나 실제 주문 처리 중에 모델 가중치를 무조건 갱신하거나 새 모델을 자동 배포하지 않는다. 운영 결과도 게임 기록과 같은 출처로 합치지 않으며 허용된 비식별 파생 자료로 재검토한다.

## 도구 검토

Unity ML-Agents는 관측·행동·보상과 시연 기록, 모방학습·강화학습을 지원한다. 공식 자료를 2026-10-25 확인했다. 이 능력은 게임 기록을 학습으로 연결할 수 있다는 근거이며 이 프로젝트의 구현 완료나 현실 성능 근거는 아니다.

- [ML-Agents 4.1 학습 개요](https://docs.unity3d.com/Packages/com.unity.ml-agents@4.1/manual/ML-Agents-Overview.html): 시연 학습·강화학습·환경 변화 학습.
- [Agent 설계와 시연 기록](https://docs.unity3d.com/Packages/com.unity.ml-agents@4.1/manual/Learning-Environment-Design-Agents.html): 관측·행동·보상·시연의 명시적 구성.

이번 설치·패키지 추가·현재 Unity 버전과의 호환 빌드는 하지 않았다. 경영 판단은 UI 픽셀이나 조작 키보다 기존 Core의 구조화된 상태·허용 행동·효과를 우선한다. ML-Agents의 `.demo`를 기존 업무 원장 형식으로 간주하지 않으며, 실제 모델 종류와 실행 위치는 성능·비용 평가 뒤 정한다.
