## 1. 확정 구조

운영자가 월초 서원을 따로 고르지 않으면 `안정 운영 유지`를 기본 서원으로 둔다. 이 서원은 해당 월에 활성화된 승인 기본정책 판본을 참조한다.

```text
월초 서원: 안정 운영 유지
  └─ 참조: StableOperationsBaselinePolicyRevision
       ├─ 지급의무 보호
       ├─ 가용현금 방어선
       ├─ 정상 경로 자동화
       ├─ 관련 예외만 격리
       ├─ 서비스 안전선
       ├─ 알림·인센티브 상한
       └─ 미승인 실험정책 자동 활성화 금지
```

서원 선택이 정책을 발동하지 않는다. 정책은 운영 서버 또는 Simulation의 별도 승인·활성화 절차로 이미 유효해야 하며, 서원은 그 판본을 참조해 월말에 얼마나 안정선을 지켰는지 돌아본다.

## 2. 안정 운영 기본정책 묶음

| 정책 축 | 기본 의미 | 미정일 때 |
| --- | --- | --- |
| 지급의무 보호 | 기사·음식점·지사·고객 환급의 확정 의무를 임의로 다른 비용과 상계하지 않음 | 실제 지급 활성화 차단 |
| 가용현금 방어선 | 확정 의무·보호 준비금을 제외한 가용현금의 하한을 지킴 | Simulation 범위값만 비교 |
| 정상 경로 자동화 | 정상 주문·정산·지급은 자동 처리 | 외부 효과 없는 모의 처리 |
| 예외 격리 | `정산 확인 필요` 관련 사건만 제한 | 관리자 검토 대기 |
| 서비스 안전선 | 안전·권역·가용성·개인정보·소비자 보호 기준을 우회하지 않음 | 보수적으로 해당 조작 차단 |
| 알림·인센티브 상한 | 승인된 시간대·대상·빈도·예산 안에서만 동작 | 자동 발송·실지급 비활성 |
| 실험정책 제한 | Preview되지 않은 정책을 자동 적용하지 않음 | 기본정책 유지 |

정확한 현금 하한·서비스 임계값·알림 빈도·인센티브 금액은 별도 승인 전 확정하지 않는다. Fixture 수치를 실제 운영 기본값으로 승격하지 않는다.

## 3. 월초·월중·월말

- 월초: 운영자가 다른 서원을 고르지 않으면 `안정 운영 유지` 카드와 참조 정책 판본을 자동 결속한다.
- 월중: 운영 화면은 방어선 정상, 주의, 이탈과 관련 예외를 보여주되 서원 카드가 직접 상태를 변경하지 않는다.
- 월말: 전월 실적 비교와 함께 어느 안전선을 지켰고 어느 항목을 다음 달에도 살펴야 하는지 회고한다.
- 정책 판본이 월중 변경되면 변경 전후 기간과 승인자를 분리해 기록한다. 새 판본으로 과거 월초 기준을 덮어쓰지 않는다.

## 4. 권위와 실패 처리

- 유효한 기본정책 판본이 없으면 기본 서원을 성공 상태로 꾸미지 않고 `정책 기준 미확정`으로 표시한다.
- 운영 모드에서 미승인 금액·계약·외부 Adapter는 계속 비활성이다.
- Simulation은 승인된 범위 또는 명시적인 Fixture 판본 안에서만 정책 효과를 계산한다.
- Unity는 서원·안전선·이탈 상태를 읽기 전용으로 표현하며 정책을 활성화하거나 원장을 변경하지 않는다.
- 아르카나·주역 카드는 기본 안전선을 우회할 수 없다.

## 5. 완료 조건

- 기본 서원과 참조 정책 판본을 독립적으로 재조회할 수 있다.
- 서원 선택·변경만으로 업무·재무 상태가 바뀌지 않는다.
- 같은 정책 판본·입력·seed로 같은 월간 회고 결과가 생성된다.
- 정책 판본이 없거나 만료되면 자동 활성화 대신 명시적 차단 상태가 된다.
- 실제 값이 미정인 정책을 Fixture로 운영 활성화하지 않는다.

## 6. 다음 질문 하나

안정 운영정책의 안전선을 벗어났을 때 기본 대응을 어떻게 나눌까?

1. `강한 안전선은 자동 차단, 운영 편차는 경고·Preview` — 추천: 지급 중복·권한·개인정보·안전 위반은 막고, 현금 여유·대기시간 같은 운영 편차는 관리자 판단으로 남긴다.
2. `모든 이탈 자동 차단`: 안전하지만 작은 편차에도 운영이 자주 멈출 수 있다.
3. `모든 이탈 경고만`: 유연하지만 외부 지급·개인정보·안전 사고를 막기 어렵다.
