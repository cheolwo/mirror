| 기초 지리 | 공식 행정동/법정동·건물/건물군·도로면·주소/출입구의 명세/식별자 대조 | 동 경계·집합건물·길과 도착 위치가 서로 맞는 바탕 |
| 공통 외관 | 지붕/옥탑·외벽/창면·상가 정면·수목/산책로·옹벽/난간·역 출입구 등의 반복 가능한 조각 | 랜드마크 사이의 주거지/골목에서도 일관된 품질 |
| 지역 고유 형태 | 용마폭포·봉수대·공공청사·역사·공원 핵심 시설을 선별 모델링 | 멀리서도 어느 동네인지 떠올릴 수 있는 기준점 |

원래의 회색/저채도 동네와 운영 매장 표식·기사의 빛은 유지한다. 석재·콘크리트·유리·목재·수목은 형태와 표면 차이로 읽히게 하고 색/반사를 과하게 늘려 내 사업의 판독을 가리지 않는다. 실제 사진을 모든 건물의 텍스처로 붙이는 방식은 이번 기준이 아니다. 표시 높이 압축·계절·낮/밤과 같은 조건에서 비교해야 한다.

## 3. 주소 자료를 받아 넣을 개발 순서

신청 완료·승인·다운로드 가능·실제 수령·원본 검사·게임 적용은 서로 다른 상태다. 아래 자료명은 **공개 카탈로그의 반입 후보**이며 사용자 계정에서 승인된 실제 목록이라는 주장이 아니다. 내비DB 신청 완료는 종전 사용자 전달로 보존한다.

| 순서 | 준비/개발 내용 | 산출물과 완료 조건 |
| --- | --- | --- |
| A. 신청/파일 목록 확인 | 자료명·처리 상태·제공 기준월·지역/전체분·변동분 여부를 대조. 개인 식별정보는 기록하지 않음 | 신청/수령을 분리한 목록. 미확인 항목은 그대로 대기 |
| B. 원본 검사 | 실제 ZIP/명세·파일목록·행수·SHA·CRS/축순서·코드·라이선스·기준월 확인 | 메타페이지 날짜나 안내 PPTX를 실제 공간자료로 대체하지 않음. 수령 원문은 압축 정본으로 보관 |
| C. 경계/건물 식별 | 구역의 도형의 실제 행정동/법정구역을 구분. 건물DB·전자지도·건물군 내 건물 동 도형을 기존 GIS 건물과 대조 | 기존sourceId와 주소 건물키의 대응표: 유일 일치/복수 후보/미발견/신규·소멸. 두 기관의 키가 같다고 가정하지 않음 |
| D. 목적지/출입 | 내비DB·주소단위 출입구·전자지도 연결선의 의미를 확인하고 개별 건물/단지 접근점을 결속 | 건물중심·대표점·주/보조출입구를 구별. 도로망/통행가능성은 별도 검증 |
| E. 배경 지리 | 실제 도로면·공원·철도·교량·하천을 기존 보행/차선·지형과 대조 | 높이/교량 상하·보행 가능성·출입구 전체 커버리지를 임의 보장하지 않음 |
| F. 영향 동 후속 굽기 | 현 굽기 기준선을 고정한 뒤 달라진 동과 인접 의존 범위를 계산. 중랑16동에서 먼저 비교 | 구판/신판/변경 이유·건물/역할 이전·경계 중복/누락을 확인. 이상이 있으면 구판으로 읽을 수 있음 |

TXT 건물DB는 메시가 아니다. 건물군 안의 동(棟)은 행정동이 아니다. 내비DB 좌표는 일방통행/회전제한이 담긴 주행 그래프가 아니다. 이 세 가지를 반입의 기본 확인 사항으로 둔다. 상세주소 층·호 자료를 주민 개인 생활/주문자 정보로 게임에 노출하지 않는다.

현재 Claude의 서울 굽기는 그 담당이 검사하며 이어 간다. 새 공식 자료가 도착해도 사용 중 입력을 조용히 바꾸지 않고 새 판본의 변경 범위만 후속으로 비교한다. 이 계획은 진행 중 작업 중단 지시나 전체 서울의 즉시 재굽기 지시가 아니다. 대용량 원본을 동마다 복제하지 않고 압축 원본1개와 지역별 정리/참조를 둔다. 자동 갱신/예약은 재개하지 않는다.

## 4. 모델 제작의 첫 후보와 분업

지역 후보9개·제외1건과 각 주소/근거/결손은 [조사 정본](../../../DataCollection/Research/2026-11-17-jungnang-landmarks-and-address-map-quality.md)이 소유한다. 우선 **면목4동의 용마폭포공원과 가까운 거리 한 장면**을 품질 비교 기준으로 제안한다. 중심 폭포/암벽·주변 수목/보행부가 함께 보여 공통 환경과 고유 형태를 한 번에 비교할 수 있다. 구체 카메라·범위·형태는 시안 검토 전이다.

| 작업 묶음 | 제작 후보 | 먼저 필요한 근거/연결 |
| --- | --- | --- |
| 공통 거리/녹지 | 수목·보행면·가로시설·옹벽/난간·상가 외장 조각 | 기존 자산 후보·실제 배치/간격·가림·재질 톤. 자료 없는 시설 배치는 합성 미술로 표시 |
| 용마폭포 | 암벽/수면·각 폭포 흐름을 나눈 모델 | 폭포/공원/접근 지점의 다른 좌표를 구별하고 상세 지형/사진·실제 크기/운영 변형 확인 |
| 봉화산의 아차산 봉수대 | 석축/개구부·계단·주변 정상 공간 | 공식 시설 정체성은 확보, 일반명 OSM점과의 동일성·치수·모델 참고 권리는 후속 |
| 중랑망우공간 |2층 매스·기둥·유리·데크·주변 숲 | 실제 건물ID/지지면/입면. 공원 전체와 별개 모델 |
| 역/구청·캠핑/장미길 | 지상 철도/출구·청사·데크/사이트·제방의 조립 | 대표점/다중 출입/복수 동·현행 상태/계절을 구분. 주소점만으로 전체를 한 동에 넣지 않음 |

기존 사가정시장 입구·대표 골목 후보도 보존한다. 현행 사진/공간/권리의 보류를 해소하기 전에는 제작 완료로 올리지 않는다. 다른 랜드마크를 추가했다는 이유로 기존 미확인을 자동 통과시키지 않는다.

### 독립 자산 묶음의 규격 — 제작 전 합의할 항목

모델별로 m 단위·피벗/정면·실측/추정 치수·기본 bounds·지면/벽 결속점·재질·상세 수준별 표현·출처/권리를 기록한다. `.blend` 원본과 기존 Unity 경로에 맞는 내보내기 파일, 미리보기, 파일 지문을 함께 둔다. LOD0/1/2의 정확한 삼각형·텍스처·성능 목표는 카메라/동시 표시량을 측정한 뒤 정하며 임의 FPS를 약속하지 않는다.

공통 프로필은 건물14m 위를 비율0.32로 압축하고 표시 높이24m 상한을 사용한다. **실측 모델 원본과 지도 표시용 변환을 구별**해야 한다. 실제 크기 모델을 구운 건물 위에 바로 겹쳐 놓고 일치한다고 선언하지 않는다. 폭포/지형의 고저차는 건물 높이 정책과 별도로 확인한다.

모델 참조에는 원 건물 고유 ID·자료 판본·모델 판본·기준점/앞 방향을 남긴다. 가까운 건물을 임의 선택해 가게/시설 정체성으로 쓰지 않는다. 외관 교체가 되더라도 기존 선택 도형·주소/업무 상태·기사 빛·도로를 보존하는지 후속 확인한다. FBX/재질 파일이 만들어졌다는 사실은 일반판의 읽기·Renderer/Collider·실제 World 배치를 증명하지 않는다.

## 6. 이번 질문과 상위 목적 정렬

플레이어는 동을 둘러보며 길과 익숙한 장소를 알아보고, 내 매장/기사와 상대의 위치를 찾는다. 실제 지역 형태와 가독성을 함께 높이면 이동·선택·관찰의 부담을 줄일 수 있다. 이것은 지도 표현의 보조 품질 개선이며 건물 수/색/모델 정교함으로 명덕·회복·사업 성립을 판정하지 않는다.

- 확정: 지도 품질 우선, 중랑구부터 조사, 서울 굽기와 독립 준비 병행, 주소포털 자료를 계획에 반영.
- 제안: 기초 지리→공통 외관→고유 형태의 작업 구성, 용마폭포 주변 첫 비교 장면, 후속 영향 동 재굽기·자산 규격.
- 미정: 계정 신청/수령 목록·실제 파일 명세/권리, 첫 시안·모델 우선 확정·치수·재질/LOD·정확 건물 결속·일반판 통합·일정/비용.
- 다음 확인 하나: 신청 목록의 자료명·처리 상태·기준월. 사용자에게 텍스트 확인을 요청했으며 비밀번호/계정 식별정보는 요구하지 않는다. r270 인물 질문은 미답변/보류다.
- 검증 상한: 이번 자료·소스/이미지 읽기·지문/위치 검사·문서 검사. Blender 실행/모델 생성·Unity 새 굽기/실행·제품/공용DB·Graph Map/Goal/WI/E·예약·commit/push 없음. 새 디오라마 규칙 후보 없음.
