# [기획 · 운영·회계 Simulation · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · 운영자 통합 회계 요약 r37]

- 상태: `Draft / FourPersistentMetricsConfirmed / OperatorFriendlyReconciliationLabelConfirmed / InternalReconciliationTermPreserved`
- 상위 기획: `README.md` r37
- 선행 기획: `operator-integrated-accounting.r36.md`
- 목적: 운영자 통합 화면에 항상 보이는 회계 요약과 사람이 읽는 표시 용어를 확정한다.

## 1. 상단 고정 4개 지표

운영자 통합 화면에는 다음 네 지표를 항상 표시한다.

1. `가용현금`
2. `향후 7일 지급의무`
3. `13주 현금 최저점`
4. `정산 확인 필요`

`정산 확인 필요`는 회계 오류가 확정됐다는 뜻이 아니다. 주문·PG·은행·기사·음식점·환급 기록 가운데 서로 맞춰 보아야 할 미해결 사건의 수를 운영자에게 이해하기 쉬운 말로 표시한다.

## 2. 표시 용어와 내부 용어

| 구분 | 사용하는 이름 | 의미 |
| --- | --- | --- |
| 운영자 화면 | `정산 확인 필요` | 운영자가 원인 확인이나 담당자 배정을 해야 하는 사건 수 |
| 상세 분류 | `PG 입금 미확인`, `기사 지급금액 불일치`, `환불 결과 미확인` 등 | 사람이 바로 이해할 수 있는 구체적 이유 |
| 내부 계약·코드 | `ReconciliationException` | 대사 과정에서 발견한 불일치·미확인 사건의 안정 식별 분류 |
| 회계 감사 자료 | `미대사`, `대사 차이` | 회계 검토자가 사용하는 전문 표현 |

운영자 화면에 `미대사 위험 건수`라는 표현은 사용하지 않는다. 기존 내부 Stable ID·계약 이름을 표시 문구 변경 때문에 바꾸지는 않는다.

## 3. 표시와 조작

- 상단에는 `정산 확인 필요 3건`처럼 건수만 간결하게 표시한다.
- 선택하면 같은 운영자 화면의 상세 영역에서 원인별 건수, 영향 금액, 최초 발생시각, 경과시간, 담당자와 가능한 조작을 보여준다.
- 확인이 필요한 사건이 0건이어도 `정산 확인 필요 0건`을 표시해 자동 대사가 정상 작동 중임을 알린다.
- 오류가 확정되지 않은 사건을 손실이나 부정으로 표현하지 않는다.
- 전체 주문·지급을 일괄 정지하지 않고 해당 사건의 권위 정책이 정한 범위만 제한한다.
- 계정과목·차변·대변·증빙 hash는 권한 있는 상세 조회에서만 제공한다.

## 4. 완료 조건

- 운영자는 전문 회계 용어를 몰라도 네 지표의 의미를 이해할 수 있다.
- 화면 문구는 `정산 확인 필요`, 내부 분류는 `ReconciliationException`으로 일관된다.
- 요약 건수에서 원인별 사건과 원 업무 revision까지 추적할 수 있다.
- 같은 사건의 재처리가 건수를 중복 증가시키지 않는다.
- 별도 회계사 앱·화면·Unity Scene을 만들지 않는다.

## 5. r38에서 폐쇄된 질문

정상 경로는 자동 처리하고, 관리자는 예외를 주로 확인한다. `정산 확인 필요`가 생기면 관련 사건만 격리하고 나머지 정상 업무는 계속한다. 정기 확인은 주간·월간·13주 주기로 수행한다. 상세 기준은 `exception-first-financial-review.r38.md`가 소유한다.
