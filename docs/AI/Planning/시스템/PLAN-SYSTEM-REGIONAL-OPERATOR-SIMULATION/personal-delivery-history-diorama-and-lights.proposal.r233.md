## 3. 빛이 무엇을 뜻할까

화면에는 **「내 배달 기록 · 선택한 날짜 · 픽업 매장 수 / 배달 건수」**가 보인다. 기록에 있는 곳이 회색 동네에서 빛으로 떠오르고, 점을 누르면 해당 매장에 얽힌 기록을 읽는다.

기본 건수는 기록의 완료 상태를 읽어 완료·취소·미확인을 나눠 보여 준다. 취소만 있는 미확인 픽업을 방문 완료로 세지 않으며, 픽업이 확인된 취소 건은 확인한 단계까지만 읽는다.

| 대상 | 빛으로 보여 줄 것 |
| --- | --- |
| 픽업 매장 | 매장 대표점 또는 결속한 건물 위의 작은 진한 중심점과 부드러운 바닥 후광. 같은 매장의 여러 배달은 한 점으로 묶고 건수 배지를 붙인다. 많이 간 곳은 후광을 단계적으로 조금 키우되 상한을 둔다. |
| 선택한 배달 | 픽업은 따뜻한 작은 표식, 전달은 하늘빛 점 또는 옅은 구간·범위로 읽는다. 중심점과 카드에 픽업·전달 문구를 함께 둔다. 선택한 건의 연결을 강조하고 나머지 매장의 후광은 옅게 한다. |
| 기사 | 기존처럼 하나의 빛으로 표현한다. 같은 배달자 ID의 빛과 이동선은 공통색을 쓴다. 이동선의 점선·실선과 짧은 문구가 위치 근거와 현재 재생 단계를 설명한다. |
| 여러 매장이 붙은 건물 | 선택한 매장 중심을 읽을 수 있게 하고, 확대 전에는 ‘픽업 매장 N곳’ 묶음과 건수를 보여 준다. 겹치는 빛을 단순 합산해 흰 덩어리로 만들지 않는다. |

## 4. 지도 위에서 ‘그날의 이동’을 보는 단계

첫 화면은 매장 빛을 고정해서 보는 방식으로 시작한다. 다음으로 배달 한 건을 골라 확인된 픽업과 전달 범위를 연결한다. 경로와 시간의 근거가 준비된 경우에는 **「계산 경로로 재생」**을 선택해 기사 빛이 도로를 따라 움직이는 모습을 볼 수 있게 제안한다. 기록된 위치·시각과 표현용 보간 구간을 카드에서 구별한다.

- 실제 위치 시계열이 있으면 그 기록의 시각으로 재생한다.
- 양 끝의 위치와 구간 시각이 확인되면 계산 경로를 해당 간격에 맞춰 표현할 수 있다. 대기·정차 근거가 없으면 중간 정차 시간을 만들어 표시하지 않는다.
- 목록 시각·상세 시각만 있고 그 의미가 미확인이면 순서대로 ‘기록 넘겨 보기’를 제공한다. 실제 픽업·전달 완료 시각으로 변환하지 않는다.
- 전달 동만 확인되면 기사 빛을 특정 집까지 운전시키지 않고 픽업 매장과 전달 지역의 관계를 보여 준다. 다음 배달의 픽업 좌표를 앞 배달의 전달지로 대신 쓰지 않는다.

한 번에 여러 주문을 픽업한 방문은 **방문 한 번·배달 여러 건**으로 표시한다. 기록 날짜 필터에는 한국 시각 기준과 원본의 시간 정밀도를 남긴다. 재생을 되감거나 같은 날을 다시 열어도 같은 기록 ID로 같은 위치를 읽으며 중복 주문·정산·보상을 만들지 않는다. 이동 모습은 현재 가상 배차와 같은 색·선의 문법을 쓸 수 있지만 개인 기록 관찰에 필요한 위치와 시각을 입력으로 사용한다.

다른 동으로 이어지면 같은 배달·기사 ID를 유지한다. 현재 동 화면에 ‘다른 동으로 전달’ 진입을 남겨 사용자가 원할 때 도착 지역으로 옮겨 보고 돌아오게 한다. 도착 동 모듈이 없으면 지역명과 범위 밖 상태를 읽는다. **화면은 한 동에 집중**하며 카메라가 배달마다 자동으로 다른 동으로 뛰지 않게 한다. [동간 연속성 r207](cross-dong-delivery-and-recipient-mingde.design.r207.md) · [기사색과 이동선 r212](soft-road-following-delivery-lines.design.r212.md)

현재 `FoodManagementSession`은 주변 도로에서 가상 목적지를 고르고 경과시간에 따라 기사를 움직인다. 개인 주소를 이 샘플 주문에 곧바로 넣기보다 **기록 조회 결과를 기존 지도·빛 그리기에 전달하는 연결**이 필요하다. 기존 가상 순찰도 실제 개인 배달자의 이동 기록과 구별한다. 새 전역 실행 모드는 추가하지 않고 기존 관찰 자료와 Simulation 상태의 책임을 따른다.

## 6. Claude가 먼저 준비할 범위와 검토 기준

1. **한 동·한 날짜의 정적 지도.** 그 날짜에 연결된 픽업 매장과 배달 건수, 위치 확인/보류/범위 밖 수가 보이게 한다. 현재 공간 판본으로 기존 매장 후보를 재계산한다.
2. **기록 하나 선택.** 매장·건물·배달 목록을 왕복하고 전달지가 가진 정밀도에 맞는 점 또는 범위를 비교한다. 같은 건물의 두 매장, 좌표 없는 기록, 전달지가 다른 동인 기록을 검토 사례로 둔다.
3. **선택적 이동 재생.** 확인된 시각·좌표가 있는 건 또는 계산 재생임을 표시한 한 건에서 기사 빛과 선을 본다. 첫 개발 계획에서 이 단계의 입력 준비 여부를 적는다.

기획 결과는 날짜·공간 판본과 후보 여부를 적은 시안으로 먼저 본다. 구현 결과는 실제 Unity에서 같은 날짜·위치·선택·해제·동 이동/복귀·레이어 끄기를 확인한다. 입력 판본을 바꿨을 때 연결 검토가 필요한 건물이 드러나는지도 본다. 현재 요청은 기획이며 새 지도 반입·코드·Unity 실행·원본 수정은 수행하지 않았다. 기존 r44의 점-도형 관계는 후보 유지 원칙을 지지한다. **새 디오라마 규칙 후보 없음.**

**확정 요청**은 본인의 배달 정보를 먼저 인지하고 지도 매핑·빛 표현을 기획해 Claude에 넘기는 것이다. **제안**은 면목제3·8동의 하루 픽업 매장을 첫 비교로 삼고 전달 범위와 이동 재생을 이어 붙이는 순서다. **미정**은 첫 날짜와 시각의 단계 해석, 전달 범위의 실제 공간 연결, 방문 빈도별 후광 크기다.
