## 이번에 구체화하는 것

사용자는 **선반의 위치 바코드를 확인해 적치한 재고를 기록하고, 주문이 들어오면 출고 배치가 그 위치를 출고 사원에게 알려 주는 과정**을 추가하도록 요청했다. 여기서 적재는 선반·칸에 물건을 놓는 적치이며 차량 상차와 구분한다.

단순히 창고 재고 총량을 보여 주는 대신 **어느 거점의 어느 선반·칸에 어떤 물건이 얼마나 있고, 누가 무엇을 꺼내 다음 단계에 넘겨야 하는지**까지 연결한다. 음식점 직접 픽업과 개별 화물은 r4의 별도 흐름을 유지하며 이 선반 절차를 모든 주문에 강제하지 않는다.

## 게임 안의 상황과 경영 선택

- 지금: 입고검수를 마친 물건을 보관하고, 주문이 들어와 출고할 시점이다.
- 여기: 계약·준비한 거점의 입고 대기장, 선반·칸, 포장대, 출고 대기장이다.
- 나: 플랫폼 운영자로서 위치 배치·직원·작업 우선순위를 정한다. 직원 NPC가 현장 확인과 이동을 수행한다.
- 너: 보관 조건과 수량이 다른 재고, 수령 약속이 있는 주문, 현재 일할 수 있는 직원이다.
- 이렇게: 적치 위치를 확정하고 주문별 재고와 작업을 배정한다. 잘못된 위치·부족 수량이 나오면 해당 작업을 보류하고 다른 적격 재고·담당·일정을 비교한다.

오행 메타데이터는 기존 상위 기획의 보조 해석을 유지하며 이번 문답에서 괘나 오행을 새로 확정하지 않는다. 상위 목적에 대한 기여는 정확한 물품 인계와 불필요한 탐색·재작업 감소다. 주문자의 필요는 약속한 물품 수령, 직원의 필요는 수행 가능한 지시와 보수다. 위치 불일치 해소에는 재확인·이동·재배정의 시간과 비용이 들며, 수익·배송 품질·참여자 보수의 균형으로 환류한다. 스캔·애니메이션은 확인을 돕는 표현이며 전문 원장의 권위 결과를 대신하지 않는다.

## 위치와 물품의 식별을 분리한다

| 구분 | 기록·표시할 내용 | 의미 |
| --- | --- | --- |
| 거점·창고 | 안정 거점 ID, 이름 | 어느 현장인가 |
| 보관 위치 | 안정 위치 ID, 위치 바코드, 구역·랙·단·칸의 읽기 쉬운 이름 | 어디에 놓는가 |
| 물품 | SKU, 상품 바코드, 상품명, 수량 단위 | 무엇인가 |
| 재고 묶음 | 입고 근거, 로트, 소유자, 해당 품목의 보관·사용 기한 조건 | 같은 상품 중 어떤 재고인가 |
| 위치별 수량 | 현재 보관량, 주문 예약량, 이동/피킹 진행량과 각 근거 | 지금 무엇을 얼마나 꺼낼 수 있는가 |
| 표현 | 위치 판본, 3D 선반/칸 ID, 표시 좌표 | 어떤 칸을 화면에서 강조하는가 |

예시 표시는 `A구역 → 3번 랙 → 2단 → B칸`이다. 이는 설명용이며 현재 코드의 `LocationId`·`DLOC-*` 등 안정 식별자를 교체하는 규칙이 아니다. 선반 라벨을 바꾸거나 배치를 옮길 때는 위치 판본과 재고 이동을 구분하고, 기존 위치 코드 재사용만으로 이전 물건이 새 장소에 있다고 간주하지 않는다.

한 SKU가 여러 칸에 있거나 한 입고 물량을 여러 칸에 나눠 놓을 수 있다. 각 위치의 실제 수량과 로트·소유자 관계를 유지하며 상품명만 같다는 이유로 합치지 않는다. 창고 안 선반 좌표는 바깥 도로 선분과 다른 공간 체계다.

## 입고부터 전달까지의 연결

```text
입고검수 완료·대기 재고
  → 적격 보관 위치 선택
  → 위치 바코드 + 물품/로트 + 실제 적치 수량 확인
  → 위치별 재고·이동 이력 확정
                                  고객 주문
                                      ↓
                     출고 배치: 창고·재고·수량 선택
                                      ↓
                     현재 조건 재검증·주문 수량 예약
                                      ↓
                     피킹 배치: 직원·위치·작업 순서 배정
                                      ↓
                     위치 안내 → 현장 확인 → 실제 피킹
                                      ↓
                     주문/용기 대조 → 포장 → 출고 대기
                                      ↓
                     기사 인수 → 배송·수령 → 회차 결산
```

이는 목표 업무 흐름이다. 기존의 서로 다른 창고 경로 전체가 이미 이 순서로 통합돼 있다는 뜻은 아니다.

### 적치할 때

1. 검수를 통과한 입고 재고와 수량을 확인한다. 미검수·격리·보관 조건 불충족 재고는 일반 가용 재고에 넣지 않는다.
2. 거점·온도 등 필요한 보관 조건과 위치의 용량·사용 가능 상태를 보고 후보를 정한다. 화면의 권장 위치와 직원이 실제 확인한 위치를 구분한다.
3. 현장에서 위치 바코드를 확인하고 물품/로트와 실제 놓은 수량·단위를 확인한다. 바코드 한 번을 읽었다는 이유로 전량 적치 완료를 만들지 않는다.
4. 확정 명령은 현재 위치·재고 판본, 담당 권한, 수량과 조건을 다시 확인하고 위치별 재고와 이동 이력을 함께 남긴다. 일부만 적치하면 나머지는 입고 대기 상태로 남긴다.
5. 재시도는 같은 사건을 재사용한다. 이미 보관한 물건을 옮길 때는 별도 위치 이동으로 원위치와 목적 위치를 함께 갱신하며 새 입고로 더하지 않는다.

### 주문이 들어왔을 때: 두 배치의 역할

**출고 배치**는 주문의 품목·수량에 대해 적격 재고, 거점의 배송권·거리/비용·시간 조건을 보고 어느 창고의 어떤 재고를 사용할지 계획한다. 한 곳에서 충족하지 못하면 허용된 분할·대기·대안을 비교한다. 계획만으로 예약하거나 재고를 차감하지 않고 확정 단계에서 최신 조건을 다시 확인한다.

**피킹 배치**는 확정한 출고 라인과 현재 보관 위치를 받아 어느 직원이 어느 위치에서 얼마나 꺼낼지 배정한다. 피킹·포장 통합/분리, 현재 업무·근무 가능 시간과 작업 간 인계를 함께 본다. 선반 위치를 안내하는 것과 최단 보행 동선을 계산하는 것은 별도 기능이며, 실제 공간 경로가 준비되기 전에는 최단 경로라고 표시하지 않는다.

위치와 재고가 바뀌면 이미 발행한 작업의 판본을 확인해 재배정·보류한다. 예전 작업 화면에 위치가 적혀 있다는 이유로 현재 재고 위치가 맞다고 간주하지 않는다. 같은 직원의 같은 시간을 여러 작업에 중복 배정하지 않는다.

### 출고 사원에게 보일 지시

작은 모바일 화면에서는 **위치·물품·수량·다음 행동**을 먼저 보여 주고 주문/로트·소유자·보관 조건·변경 근거는 펼쳐서 본다.

```text
다음 피킹  |  A구역 · 3번 랙 · 2단 · B칸
물품 예시  |  생수 500mL · SKU 예시-001
필요 수량  |  3개  (박스 수량과 구분)
확인 순서  |  위치 확인 → 물품·로트 확인 → 실제 수량
다음 단계  |  포장대 P1의 이 주문 용기에 인계
```

예시 상품·수량·위치는 실제 주문이나 기본 상품 카탈로그를 새로 등록하는 값이 아니다. 게임 화면에서는 해당 선반을 강조하고 직원의 현재 작업·다음 이동·막힌 이유를 보여 준다. 작업자는 안내된 위치 바코드와 물품을 대조한 뒤 꺼낸 수량을 기록한다. 작업별 용기/주문을 대조해 여러 주문의 물건이 섞이지 않게 한다.

위치·물품 코드의 일치, 수량 입력, 현장 실물 확인은 각각 다른 근거다. 카메라/스캐너 입력·수동 입력·게임의 모의 스캔 출처를 구분하며 스캔만으로 실물 수량과 올바른 적치를 증명했다고 표시하지 않는다.

## 수량과 단계 완료를 혼동하지 않는다

선반 보관, 주문 예약, 피킹 후 포장 대기, 포장 완료, 출고 대기, 기사 인수, 고객 수령을 별도로 표시한다. 예약은 가용량을 점유하는 것이며 그 자체로 물건이 선반에서 사라진 것은 아니다. 실제 이동과 수량 변경은 전문 생명주기에서 정한 사건이 한 번만 소유하도록 후속 설계한다.

일반 창고와 분산 물류의 현재 차감/완료 의미는 같지 않다. 피킹·포장·기사 인수 때 같은 수량을 반복 차감하거나, 피킹 작업 상태 완료만으로 실제 운송 인계·판매·현금 수령을 만들지 않는다. 위치별 수량과 예약량이 전체 재고와 맞는지도 재조회한다.

| 예외 | 직원 안내와 후속 처리 |
| --- | --- |
| 다른 선반 또는 다른 물품을 확인 | 불일치 항목과 올바른 위치/물품을 보여 주고 해당 완료 차단 |
| 지시 수량보다 적게 발견 | 실제 수량·부족을 기록하고 영향 주문만 보류. 다른 적격 위치/로트의 재배정 또는 일정 조정 비교 |
| 같은 SKU가 여러 칸에 있음 | 이번 작업에 배정된 위치·로트·수량을 명시. 임의로 다른 칸을 써서 완료하지 않음 |
| 예약 뒤 재고 이동·조건 변경 | 현재 위치·수량·예약 판본을 재검증하고 오래된 지시를 갱신/보류 |
| 근무 종료·담당 부재·처리량 초과 | 작업 대기와 담당 재배정, 예상 지연을 표시. 보수와 같은 시간의 업무 중복도 확인 |
| 주문 취소·피킹 도중 변경 | 미수행 예약 해제와 이미 꺼낸 물건의 반납/격리·재배정을 구분 |
| 통신 실패·중복 스캔/확정 재시도 | 요청·입력·결과를 대조해 중복 이동/중복 작업 생성을 방지. 미확정 상태를 완료로 표시하지 않음 |

## 플레이 방식과 경험 축적

기본은 플레이어가 위치 배치·직원·우선순위를 관리하고 NPC가 작업하는 경영 방식으로 제안한다. 원하는 경우 한 작업의 위치 찾기·바코드 확인을 직접 체험할 수 있지만 매 상품 스캔을 모든 플레이의 필수 조작으로 만들지는 않는다. 직접 조작과 NPC 작업에도 같은 가상 상태·검증 규칙을 적용한다. 상세 조작과 우선순위는 후속 확정 대상이다.

자주 나가는 상품의 위치를 바꾸면 탐색·이동·혼잡·재적치 비용과 주문 지연이 어떻게 달라지는지 비교한다. 빨리 처리한 수량만 보상하지 않고 오피킹·재작업·손상·기한·직원 부담·보수와 수익을 함께 본다. 구체 점수와 처리 시간은 미정이다.

경험에는 공간/위치·재고·예약·규칙 판본, 주문·작업·직원 관계, 가능한 선택과 제외 사유, 확인 방법, 실제 가상 수행량·시간·오류·복구·인계 결과를 남긴다. 화면 애니메이션과 모의 스캔은 실제 현장 증거가 아니며, 학습 적격 판정·모델 학습·현실 운영 추천은 r1의 별도 단계다. 주행 영상은 거점 접근과 외부 물류의 참고로 쓰며 영상에 없는 선반 배치나 실재고를 복원하지 않는다.

## 확정·미정과 다음 검토

- 사용자 요청으로 확정한 방향: 위치 바코드에 근거한 적치 기록과, 그 위치를 활용한 주문 출고·직원 안내를 경영 제안에 포함한다.
- 이번 제안: 상위 출고 재고 선택과 하위 직원 피킹 배정을 연결하고 위치·물품·실제 수량 확인, 예외 보류·재배정과 회차 결산을 구분한다.
- 미정: 첫 가상 선반의 규모·라벨 체계, 직접 체험 조작, 작업 시간/동선 계산, 부분 피킹과 예약의 정확 전이, 평가 수치와 구현 명세.
- 다음 검토 질문: 첫 시제품에서 준비된 선반을 운영하게 할지, 상품의 적치 위치를 직접 배치하는 것부터 체험하게 할지. 지금은 이 선택이나 구현 승인을 요구하지 않는다.

이번 변경은 제안서·참조·현재 작업만 보완한다. 코드·재고/주문 DB·바코드 장치·실제 적치/예약/출고·Unity Scene/Play Mode·학습·배포·commit/push를 실행한 결과가 아니다.
