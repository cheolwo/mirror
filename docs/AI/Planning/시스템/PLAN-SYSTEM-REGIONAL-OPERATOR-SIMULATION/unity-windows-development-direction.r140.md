# [기획 · Unity Windows 개발 집중 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r140]

- 기준일: 2026-11-12
- 상태: `UserDirectionConfirmed / PlanningAndStatusRefactor / ProductUnchanged`
- 대체 관계: [WPF 우선 r139](wpf-first-development-direction.r139.md)의 개발 우선순위를 대체한다. 기존 WPF·Unity·모바일 소스와 검증 이력은 보존한다.

## 확정

홍달 경영 시뮬레이션의 현재 개발 대상은 **Unity 기반 Windows 설치형 실행판**이다. Windows에서 실행되는 검은 지도 화면은 Unity 게임이며, 네이버 지도를 쓰는 기존 WPF 도구와 구분한다. 모바일·Android 검증이나 WPF의 선행 고도화를 이 실행판의 필수 조건으로 두지 않는다. 개인용 로컬 실행과 가상 업무·가상 정산 경계는 유지한다.

Codex는 사용자와 게임 기획을 구체화하고 기획 판본·구현 현황·완료 조건을 정리한다. Claude는 이를 읽고 승인된 범위의 구현 계획·구현·검증 결과를 반환한다. 작업별 역할과 실제 편집 경로는 [혼용 운영 기준](../../../Handoffs/Codex-Claude-혼용운영안-2026-11-12.md)을 따른다. 방향 변경이 모든 후속 기능의 구현 승인이나 현재 시제품의 정식 채택을 뜻하지는 않는다.

기획과 구현의 대조 정본은 [Unity Windows 구현 현황](../../../Handoffs/Unity-Windows-구현현황.md)이다. 기획만 있음, 다른 소비판에 구현됨, 시제품에만 구현됨, 현재 대상에 통합됨을 나누고 정적 대조·빌드·시험·실제 화면의 증거를 따로 기록한다. 과거 통과를 변경된 소비판의 새 검증으로 승계하지 않는다.

## 이번 정리의 완료 조건

- Claude가 어느 파일과 실행판을 이어받는지, 기존 구현 중 무엇을 재사용할지 읽을 수 있다.
- Core 내장·uGUI·저장 복원이 별도 모바일 소비 모듈에 이미 있다는 사실과, Claude 2.5D 판에 아직 통합되지 않았다는 사실을 구분한다.
- 가맹점·생산·공장 안내 탭과 실제 경영 규칙을 구분한다. 자료나 검증이 부족한 항목은 미확인으로 남긴다.
- 기존 배차·수락·픽업·전달·수령·가상 정산 결과, 기획 ID·원본·세이브·구판과 다른 작업의 변경을 보존한다. 이번 회차는 문서만 정리한다.

## 미정과 다음 작업 하나

정식 Unity 프로젝트 경로, 2.5D 시제품의 통합 범위, 구운 지도 자료의 추적/생성 방식과 배포 조건은 아직 미정이다. 합성 채움 건물과 실제 도형, 구매 Synty 원본의 이용 조건을 섞지 않는다. 앱·서버·수집·영상 작업이나 예약을 이번 요청으로 재배정하지 않는다.

다음 작업은 **Claude 2.5D 시제품과 기존 Core·uGUI의 통합 계획 한 건**이다. 개발자는 현황표의 현재 지문을 다시 대조하고 프로젝트·허용 경로·보존할 결과·필요 검증을 먼저 명시한다. 기존 기능을 다시 만드는 계획 대신 연결 차이를 적는다. 계획 확정 전 제품 파일 이동·코어 규칙 확장·UI 교체는 이번 문서 작업에서 실행하지 않는다.
