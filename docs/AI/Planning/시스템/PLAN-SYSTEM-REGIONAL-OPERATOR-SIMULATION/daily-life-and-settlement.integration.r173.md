# [기획 · 일일일생·일일 결산 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r173]

- 기준일: 2026-11-13 · Unity Windows 경영 게임.
- 상태: `DailyClosingRequestedByUser / PlanningIntegrated / DevelopmentHandoffPrepared / ProductUnchanged`.
- 사용자 요청: **‘일일일생’**의 리듬으로 하루 단위 결산이 이루어지도록 조정한다. 직전 발화의 용어는 사용자의 후속 정정 ‘일일일생’으로 기록한다.
- 관계: [현실 달력 통합 r172](real-calendar-seasonal-arcana.integration.r172.md)의 일일 결산 정밀화다. 현실 날짜·현실 월~일 경영 주간·절기 운영 방침·부재중 환경만 갱신·기존 카드/자료 경계를 유지한다. r172 원문과 인계 hash는 보존하며, 결산의 기본 주기는 본 r173을 함께 적용한다.
- 담당/범위: Codex 기획 작업실. [Claude 후속 입력](../../../Handoffs/2026-11-13-Codex-Claude-일일일생결산-r173.md)을 준비한다. 현재 Claude의 결정 순회/가맹점 구현·제품 코드·실행판·DB/수집예약·Goal/WI·Graph Map·연구 Accepted/E·commit/push는 변경하지 않는다.

## 1. 확정 — 하루가 기본 경영 주기다

**오늘 준비 → 실제 일하기·관찰 → 오늘의 결과 정리 → 다음 날 준비**를 ‘일일일생’의 기본 리듬으로 둔다. 집중 직접 수행과 실행 중 위임 업무의 실제 결과를 함께 읽는다.

| 주기 | 하는 일 | 결산의 역할 |
| --- | --- | --- |
| 일일 | 오늘의 안건·작업·자원 확인과 실제 수행 | 하루의 완료/대기·수익/비용·미정산·잘된 점/문제·내일 이어갈 일 확인. 기본 결산 |
| 주간 | 실제 월~일의 큰 계획·동별 자원/사업 검토 | 같은 일일 기록을 묶어 추세·누적 부담과 다음 주 배분 검토 |
| 절기 | 현재 계절 문맥과 운영 방침 선택 | 해당 기간의 대응을 돌아보고 다음 절기 카드/중립 운영 확인 |

일일 결산을 위해 일주일을 기다리지 않는다. 주간/절기 결산도 유지하되 하루의 결과를 다시 지급하거나 별도 영업 원장을 만들지 않는다. 날짜/절기·공공자료의 현실 연동과 짧은 작업의 경과 시간 분리는 그대로다.

## 2. 날짜 경계와 하루 중 마무리

- 하루는 **한국표준시00:00부터 다음 날00:00 전까지**다. 현실 날짜와 같은 기간 ID를 사용하고, 기존 가상 `LocalCampaign.Day`/2026-01-01 기점을 결산 날짜로 쓰지 않는다.
- 당일에도 `오늘 결산`으로 현재까지의 결과를 볼 수 있다. 아직 날짜가 끝나지 않았으면 **진행 중 집계**로 표시하고, 그날 다시 일하면 같은 날짜의 기록에 누적한다. 열람/‘오늘 마무리’ 확인으로 날짜를 넘기거나 기록을 초기화하지 않는다.
- 날짜가 바뀌면 지난 날짜의 실제 기록을 일일 결산 대상으로 묶는다. 직접 작업 중에는 종료/안전 인계 뒤, 앱을 껐다 켰으면 재접속 후 안전한 진입에서 확인한다. 자정 알림이 조작/카메라를 강제로 빼앗지 않는다.
- 일일 결산 확인은 해당 기간/기록 판본의 확인 상태만 갱신한다. 작업 진행·WorldTick·현금/재고·수익/비용을 추가하지 않는다. 확인을 반복해도 같은 결과다.
- 여러 날 미접속한 경우 **실제 기록이 있는 미확인 날짜만 묶어** 볼 수 있다. 기록 없는 미접속 날짜마다0원 결산/필수 확인을 쌓지 않는다. 현재 날짜의 업무로 돌아갈 수 있게 한다.

## 3. 자정을 넘기는 일과 금액 귀속

완료·수익·비용·취소/조정 등은 각각 **권위 행위/재무 기록에 보존된 현실 KST 날짜**에 한 번만 집계한다. 표현상의 오토바이 도착이나 결산 화면 확인일을 발생일로 쓰지 않는다. 기존 업무 기록의 원래 시각/판본을 덮어쓰지 않고 현실 날짜 문맥을 연결한다.

예를 들어 전날23:55에 시작해 다음 날00:10에 완료한 배달은 전날 결산에 미완료/이월로 남고, 완료 기록은 다음 날에 포함된다. 비용이 전날 실제 기록됐다면 비용은 전날에, 수익이 다음 날 기록됐다면 수익은 다음 날에 포함된다. 작업을 한 번 더 생성하거나 완료/보상을 양일에 중복 반영하지 않는다. 미정산·미지급은 실제 지급/수금과 구별한다.

주간/절기 집계는 확인된 일일 화면의 합계를 다시 적립하는 방식이 아니라 **같은 원본 기록을 해당 기간으로 조회**한다. 일일 확인을 미뤘어도 원본 기록은 보고에 포함된다. 뒤늦은 정산/정정은 원본의 실제 새 기록과 판본을 따라 표시하고 과거 금액을 조용히 바꾸거나 중복 차감하지 않는다.

## 4. 일·주·절기 경계가 겹칠 때

```text
지난 실제 활동일의 일일 결산
→ 해당하면 주간/절기 요약을 같은 결과 검토에서 확인
→ 현재 절기 선택이 필요하면 카드/중립 운영 확인
→ 오늘 준비·결정 순회 → 오늘의 실제 작업
```

- 일일 결산·주간 계획·절기 카드의 기간/의미는 각각 유지한다. 일일 결산을 이유로 매일 카드를 다시 고르거나 절기 활성화를 새로 만들지 않는다.
- 주간·절기 검토가 겹쳐도 같은 결과/금액을 중복 보상하지 않는다. 보고 확인은 새 안건 처리·발주/배차 확정이 아니다.
- 당일의 준비된 안건만 결정 순회에 나타나며, 다음 결정/결산 버튼은 현실의 다음 날을 앞당기지 않는다. 날짜는 앱 종료·정지 중에도 경과하지만 그동안 영업 결과를 계산하지 않는다.
- 미완료 주문·공사·운송·안건은 같은 ID로 이월한다. 하루 마감을 위해 가짜 완료·자동 취소·일괄 벌금·빈 날짜 영업을 만들지 않는다. 필요한 회복/보완은 기존 규칙의 현재 허용 선택으로 남긴다.

## 5. 개발 인계의 완료 조건

1. 당일 여러 번 작업/결산 열람을 해도 같은 날짜에 누적되고 금액/완료가 중복되지 않는다.
2. 자정 전후의 진행 작업과 완료/수익/비용이 원본 기록 날짜에 각각 귀속된다.
3. 재접속 시 실제 활동일의 미확인 결과를 묶고 미접속 빈 날짜의 강제 결산·수익·비용을 만들지 않는다.
4. 일·주·절기 경계가 겹쳐도 원본 한 건은 각 보고의 기간에만 포함되고 새 지급/차감이 없다.
5. 결산 확인 전후의 작업 경과·Tick·현금/재고가 불변이고, 같은 절기 카드 선택도 유지된다.
6. 기존 날짜/자료/정책·개인 타로·현재 Claude 소유를 보존하며 실제 코드·시험·Unity 화면/Runtime 검증은 별도 반환한다.

**확정:** 하루 결산을 기본으로, 주간은 누적 검토·절기는 운영 방침으로 조정한다. **미정/별도 범위:** 일일 화면의 실제 배치·제품 연결/검증은 개발 수용 대상이며 새 보상/회계 제도·오프라인 영업을 추가하지 않는다. **다음 검토 하나:** 현재 결정 순회에 실제 활동일의 결산/확인과 오늘 준비를 중복 없이 연결하는 경계를 대조한다. 새 사용자 질문은 없다.
