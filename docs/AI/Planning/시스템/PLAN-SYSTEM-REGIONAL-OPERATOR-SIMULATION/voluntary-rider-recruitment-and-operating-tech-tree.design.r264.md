## 2. 기사 자율성과 모집의 경영

이 시나리오에서 운영자가 바꿀 수 있는 것은 **모집을 알리는 범위·방식, 제안 조건, 운영 안내와 준비**다. 기사별 이동/참여는 본인의 활동 범위·현재 업무·선택을 반영하는 방향으로 설계한다. ‘인원 여력 부족’ 조회를 특정 기사 이동 명령으로 연결하지 않는다.

권하는 모집 흐름은 **홍보 준비 → 가상 홍보 집행 → 관심/지원 → 참여 조건 확인 → 필요한 등록/안내·준비 → 실제 참여 가능한 기사**다. 정확한 단계·기간·모형은 미정이다. 지원자 수·참여 인원·지금 가용 인원은 다른 값이며 모집 성공을 보장하지 않는다.

스티커는 기사에게 **지사 홍보 참여를 제안**하는 후보로 둔다. 기사 선택과 제작/배포·지원 비용 등을 거친 뒤 가상 홍보 결과를 읽는다. 스티커를 붙였다는 이유로 활동 지역·주문 수락·전속/이동 의사를 운영자가 확정하지 않는다. 기존 기사 빛의 표현에는 지사 표식/홍보 상태를 붙이는 후보가 있으며 실제 시각안은 후속이다.

모집 홍보의 목적은 기사 지원이다. 음식점 검색 광고의 고객 유입·순위·주문, 중개업자 기획과 같은 결과로 합치지 않는다. [r183](multi-entry-management-research-tree.design.r183.md)이 허용한 기초 광고와 별개로도 모집 안내는 초반에 가능해야 하며, 모집 스티커를 전국 광고망 해금 뒤로 미루지 않는다.

## 3. 처음에는 배달권을 준비해 준다 — 제안

첫1호지사에는 **시나리오에서 준비한 기본 배달권**으로 들어가는 안을 권한다. 지도는 한 행정동에 집중해도 그 배달권은 여러 행정동에 걸칠 수 있다. 처음부터 다각형을 그리고 행정동을 전부 골라야 첫 운영을 할 수 있게 하지 않는다.

초반에는 권역 이름·포함 동·진행 중 업무/모집 지역을 읽고 바로 운영한다. 필요할 때 기본 권역을 확인하거나 변경 후보를 비교한다. 이후 연구는 권역별 모집 현황 비교·범위 추천·변경 영향 검토 같은 도구를 넓힐 수 있다. 기존 수동 편집/저장 기능을 새 게임 연구 때문에 소급 잠그는 것은 승인하지 않았다.

현재 법정동 `memberDongIds`를 행정동 ID로 읽거나 기존 저장을 덮지 않는다. 지역 종류·식별자/경계 판본·지사와의 관계·겹치는 권역을 허용할지·기사의 활동 범위/소속/가용을 별도 명세로 정해야 한다. 기존 편집기의 중복 금지도 새 행정동 모델 전체의 확정 규칙으로 승계하지 않는다.

배달권은 모집/운영을 읽는 기준이다. 경계를 넘어가는 기존 배달을 중단시키거나 지도를 옮긴 것만으로 기사/권역/모집 계획을 다른 곳에 배치하지 않는다. 새 경계가 업무 허용·제안 범위에 미치는 정확한 효과는 미정이다.

## 4. 문명에서 참고한 연구 화면

[공식 자료 조사](../../../DataCollection/Research/2026-11-17-civilization-research-tree-and-voluntary-recruitment.md)에 V/VI의 확인 범위를 정리했다. V 공식 매뉴얼85쪽은 선행 기술 연결과 목표 기술에 필요한 경로를 설명한다. VI 공식 배포 매뉴얼의 연구 설명에는 턴별 과학 누적·예상 턴·해금 대상·전체 트리가 있다. 새 게임 화면을 직접 실행해 검사한 것은 아니다.

홍달에는 **무엇을 연구 중인가 / 무엇이 먼저 필요한가 / 얼마나 진행됐는가 / 완료하면 어떤 일이 편해지는가 / 그다음 무엇을 고를 수 있는가**를 한 창에서 읽는 구성을 가져오는 안을 권한다. 과학 자원·세부 밸런스·기술 명칭과 외형을 그대로 복제하지 않는다.

## 5. 21 경영 연구 창 — 제안

00오행 총괄판 아래 새 연구 창에 검토용21을 붙인다. 기존01~20과12계획·19방침은 유지한다.21은 실제 구현/촬영된 화면 번호가 아니다.

```text
00 오행 총괄판
└─ 21 경영 연구
   ├─ 현재 연구 · 진척 · 예상 완료 · 완료 효과

   │  └─ 창고의 위치 확인·작업 안내
   ├─ 구·배달권 운영 기술
   │  ├─ 여러 권역의 모집·지원 현황 비교
   │  ├─ 여러 매장의 인력·보충 계획 비교
   │  └─ 여러 거점의 재고·출고 후보 비교
   └─ 전국망 운영 기술
      ├─ 전국 파트너/모집망 검토
      ├─ 공급·거점·운송 회차 계획
      └─ 넓은 범위의 운영 분석·추천 보조
```

전체 트리는 동네/구/전국의 깊이와 분야별 갈래를 함께 보여 주는 안이다. 각 카드에는 이름·효과·선행 조건·비용/필요 진척·적용 범위·완료 후 실제로 필요한 준비를 둔다. 완료/연구 중/선택 가능/조건 미충족을 구별하고, 잠긴 카드에서는 이유와 선행 경로를 본다.

연구가 끝나도 팝업을 읽어야 정상 업무가 계속되는 구조는 피한다. 권장 연구·원할 때 펼치는 전체 트리를 제공하고, 다음 연구 자동 선택/예약은 명시적 선택의 범위를 후속으로 정한다. 필수 가격·잔액·현재 주문·기사/재고/작업 위치의 기초 상태·기본 작업절차/레시피·권역 기본 정보·필수 안전/권한 정보를 연구 뒤로 숨기지 않는다.

## 7. 턴을 거치며 연구를 얻는 방법

**연구 선택 → 운영과 함께 진척 → 조건을 채우면 완료 → 새로운 도구/선택을 사용**하는 방향이다. 첫 지사 스티커 홍보 연구는 실제 운영이 진행된 턴1회를 마치면 완료한다. 그 턴을 식별/확정할 기록과 운영 회차/시간의 결속은 후속 명세다. 다른 연구의 필요 진척·운영 시간/경험/투자 적용, 비용·동시 연구 수·중단/변경과 진척 보존은 미정이다. 처음에는 한 연구에 초점을 맞추는 안을 권하지만 아직 승인한 규칙은 아니다.

진척을 반영하는 유효 운영 턴/기간의 정의를 먼저 정해야 한다. 같은 턴·결과의 재조회/저장 복원으로 진척을 중복 지급하지 않는다. 단순 창 열기·닫기·마감 버튼 반복을 여러 운영 성과로 세지 않는다. 직접 조작 미니게임을 연구 진척의 필수 경로로 두지 않고, 준비된 맡김/관찰 중 실제 운영도 기존 규칙에 따라 연결하는 안을 권한다.

같은 현실 날짜 안의 운영 회차·턴 계획과 일일 결산은 기존 구분을 유지한다. 턴을 넘기는 조작이 현실 날짜 점프·음식 즉시 완성·실제 광고 집행·모집 완료가 되지 않는다. 광고로 시작하는 분야처럼 아직 배달 실적이 없는 경우에도 연구가 순환 선행조건에 막히지 않도록 기본 준비/대체 경험을 설계한다.

조직의 운영 기술과 기사/직원의 개인 숙련·명덕·정신 차림은 구분한다. 같은 실제 기록을 참고할 수 있지만 연구 완료만으로 사람의 성장/수행 의사·명덕을 지급하지 않는다.

## 8. 연구와 상위 경영 해금의 연결

일정 선행 기술 뒤 구/전국의 심화 연구가 열리는 방향은 사용자 요청이다. **필요한 기술을 익힘 + 그 책임이 필요한 상황 + 실제 업무/자료/인력·자금/권한 준비**를 함께 보는 안을 권한다. 정확한 조합/대체 경로는 미정이다. 연구 완료는 준비된 도구와 선택지를 열며 실제 새 지사·계약·지원자·재고·고객을 지급하지 않는다.

기술은 대기·반복 입력·비교 부담을 줄이고 추천 근거를 읽기 쉽게 하는 효과로 먼저 설계한다. 발주안 작성·정산 자료 정리 같은 보조가 가능해져도 r225의 플레이어 최종 발주·예외·정산 결정은 유지한다. 연구로 생산·배달의 실제 절차/시간을 없애거나 모든 광고·모집을 무조건 성공시키는 배율은 추가하지 않는다.

00오행판에는 연구/홍보 계획의 현재 조건·예상 영향과 실행 후 결과를 구분해 모은다. 모집 지원·합류·현재 가용은 구별하고, 정확한 오행 기여/가중치·예측값은 r261/r262의 미정으로 둔다. 연구/Preview를 실제 활동 발자국에 미리 적립하지 않는다.

## 9. 구현 전 필요한 결속

기존 법정동 권역 저장과 행정동 모듈·지사 집계·개인 기사, 현재 엔진 투자와 연구 노드, 유효 운영 턴과 저장/재생을 각각 대조해야 한다. 기존 저장/지출/성장을 보존하고 새 진척·완료·효과의 중복을 막는 명세가 필요하다. 이 문서는 새 저장 필드/연구 자원을 확정하지 않는다.

첫 연구는 지사 스티커 홍보로 정했다. 후속 장면 후보는 기존1호의 기본 배달권에서 이를 선택·연구하고, 홍보 준비와 자발적인 지원/참여의 결과를 확인하는 흐름이다. 실제 구현은 기본 권역·연구 진척·홍보·지원의 주체/실패/회복/귀환을 정한 뒤 승인 기획 revision/hash·WI 하나·담당/정확 경로·E1~E7 명세로 수용한다. Graph Map은 기존 모집/연구/권역/업무 관계의 `ReviewRequired` 후보이며 원본·Goal을 여기서 바꾸지 않는다.

| **모집·인력** | **지사 스티커 홍보** · 홍보 준비를 열고 기사 참여 의사를 받는다. | **권역별 모집 분석** · 어느 동과 시간대에 지원이 필요한지 비교한다. | **공동 모집 현황** · 여러 지사의 지원과 실제 가용 인원을 비교한다. |
| **픽업·배차** | **픽업 대기 분석** · 오래 기다린 매장과 시간대를 찾는다. | **도착 시점 추천** · 준비 예상과 기사 도착을 맞추는 후보를 비교한다. | **지사 간 피크 분석** · 여러 지사의 동시 지연과 대기 변화를 비교한다. |

각 행은 왼쪽에서 오른쪽으로 진행하는 선행 경로 후보다. **첫 연구는 기존 확정대로 1호지사 기본 배달권 전체를 대상으로 하는 지사 스티커 홍보이며, 실제 운영이 진행된 턴 한 번을 마치면 완료**한다. 홍보 집행은 이후 제작·배포·기사 동의를 거치며, 지원자와 실제 가용 기사를 따로 본다. [첫 연구의 확정 범위](#6-첫-연구-갈래의-후보)

### 운영 정책 트리 후보

| 갈래 | 첫 지사에서 적용하는 정책 | 다음 정책 | 지사망에서 적용하는 정책 |
| --- | --- | --- | --- |
| **사람·교대** | **희망 교대제** · 기사 희망 시간으로 피크를 준비한다. 지사장이 편성 시간을 쓴다. | **신규 기사 동행 교육** · 익숙한 기사와 초보를 연결한다. 교육 시간에는 처리 여력이 줄 수 있다. | **협력 지사 지원** · 지원 의사가 있는 기사와 지사에 다음 회차의 도움을 요청한다. |
| **서비스·대기** | **픽업 준비 우선** · 조리 예상에 맞춰 요청 시점을 고른다. 준비 예측이 빗나가면 지연될 수 있다. | **피크 수용 한도** · 감당할 주문만 받는다. 대기는 줄고 당장 처리한 주문 몫도 줄 수 있다. | **지사별 운영 기준** · 지사별 수요와 처리 여력에 맞춰 수용 한도를 다르게 둔다. |

정책의 선행 관계와 집행 방식은 후보다. 예를 들어 준비 시각을 처음 비교하는 지사는 `픽업 대기 분석` 결과로 `픽업 준비 우선` 적용 대상을 정한다. 데이터가 없으면 기본 운영 방식으로 업무를 이어가고, 정책 카드에서 부족한 관측을 알려 준다. 기사 참여와 협력 지사 지원은 각자의 의사가 확인된 뒤에 편성한다.

첫 `희망 교대제` 카드에는 적용할 지사와 시간대, 그 시간에 일하겠다고 답한 기사 수, 편성에 필요한 시간을 보여 주는 안이다. 기존 기사부터 편성할 수 있고, 스티커 홍보 뒤 실제로 합류한 기사도 참여 의사를 확인해 편성할 수 있다. 인원이나 시간대가 비면 다음 회차 편성을 보류하고 기존 방침으로 운영한다.

### 대표 인계 제안 · 온라인 주문 한 건

1. 커머스에서 확인한 주문의 번호, 품목, 수량, 출고 기한을 창고로 넘긴다.
2. 창고는 가용 재고와 처리 여력을 확인해 출고 가능 여부와 예상 시각을 회신한다. 배정이 확정되면 재고를 예약하고 작업을 진행한다.
3. 포장품을 운송에 인계하면 커머스가 해당 주문의 출고 상태를 갱신한다. 품절이나 지연이면 기존 주문을 찾아 고객에게 안내하고, 필요한 경우 취소·반품은 커머스에서 접수한다. 반품이 도착하면 창고가 검수 결과를 커머스로 보낸다.

커머스 결산은 약속한 출고·취소·매출을, 창고 결산은 재고 차이·마감 준수·작업 여력을 읽는다. 같은 주문의 인계는 두 화면에서 찾아갈 수 있다. 두 갈래의 승리 판정에는 각자 정한 역할 목표와 깨어 있는 사람의 증가를 함께 적용한다. 구체적인 목표 수치는 각 입장 기획에서 정한다.
