## 확정

기존 64괘 기획 방식을 배달 플랫폼 운영 게임의 장기 기획 틀로 재사용한다. 새 64개 목록을 따로 만들어 기존 스토리 기획을 덮어쓰지 않는다.

- 괘는 운영 상황과 변화의 의미를 찾는 영감·저작 단위다.
- 효는 한 운영 캠페인 안에서 상황이 달라지는 구체 국면을 문답하는 단위로 사용할 수 있다.
- 정식 64괘 순서는 빠진 기획을 찾고 차례로 공부하는 기준이지, 플레이어에게 384개 사건을 일직선으로 강제하는 진행 순서가 아니다.
- 괘 이름만으로 주문·배차·정산 상태, WI, H, Graph Map 노드, Unity 객체 또는 Evidence를 자동 생성하지 않는다.
- 배달 운영 캠페인은 기존 공통 Campaign Core, 저장·재생, Preview·Confirm, 안전 기본값과 예외 우선 복귀 구조를 재사용한다.
- 현실 공공자료와 운영 관측은 기준 사실, 괘·아르카나·절기 해석은 Simulation의 이야기와 선택 문맥, Unity 디오라마는 읽기 전용 표현으로 분리한다.

## 운영 캠페인 문답 형식

각 괘 또는 효를 운영 상황으로 번역할 때 다음 한 장을 먼저 닫는다.

```text
지금     운영 지표와 발생 사건, 시간대·절기·현금 상태
여기     행정동·배달운영권역·사가정 관찰 창과 필요한 공간
나       가상 배달 플랫폼 운영자
너       주문자·음식점·기사·지원 담당·정책 대상
이렇게   유지할 기본값 또는 Preview 뒤 선택할 정책
결과     서비스·노동·현금·예외·회복의 변화
다음     자유 운영, 다음 국면, 원복 또는 다른 캠페인
```

같은 괘를 사용하더라도 원문을 운영 수치로 직접 환산하지 않는다. 먼저 운영 사건과 사람의 이해관계를 정하고, 괘는 그 변화의 긴장과 판단을 설명하는 데 사용한다.

## 디오라마 축적 방식

운영 기획에서 공간 필요가 드러날 때 기존 디오라마 전체를 다시 만들지 않고 **공간 보완 묶음**을 누적한다.

1. 현재 행정동·역세권 디오라마와 H1~H4·AreaSet·경로·배치 객체의 재사용 가능성을 먼저 확인한다.
2. 캠페인의 판독에 꼭 필요한 장소·경로·상태 표현만 추출한다.
3. 현실 공간이면 공식 출처·기준일·좌표·주소·품질·배포 가능성을 함께 기록하고, 합성 요소면 `SyntheticFixture`로 명시한다.
4. 관계 변화는 Graph Map, 상대 배치는 배치 맵, 외형 보완은 Blender 후보, 실제 화면 결속은 Unity 표현 검증으로 각각 인계한다.
5. 자료가 없으면 임의 건물이나 길을 만들지 않고 `자료 미확정`, `이동 중`, 또는 승인된 일반화 표현으로 남긴다.
6. 승인된 한 캠페인의 공간 보완만 기존 사가정·면목제3·8동 기준선에 더하고, 다른 행정동에는 검증 없이 복제하지 않는다.
7. 공간 보완 뒤에도 서버·Simulation이 상태 권위를 유지하며 디오라마의 애니메이션이나 배치가 업무 결과를 확정하지 않는다.

공간 보완 묶음은 최소한 다음을 가진다.

| 항목 | 내용 |
| --- | --- |
| 캠페인·국면 | 괘·효 참조, 운영 사건 안정 ID, 기획 revision |
| 필요한 판독 | 운영자가 공간에서 무엇을 알아야 하는가 |
| 재사용 대상 | 기존 AreaSet, H, 도로·보도·건물·거점·UI 앵커 |
| 결손 | 필요한 데이터·모델·경로·상태 표현 |
| 근거 | 원천, 기준일, 품질, 배포 승인, 합성 여부 |
| 표현 상한 | 지도 아이콘, 상태 카드, 절차적 매스, Blender 상세 등 |
| 검증 | 정적 검사, 상태 사본, Play Mode, Game View를 분리한 증거 |

이 방식이면 사가정 디오라마의 현실 기반 형태는 보존하면서도, 운영 캠페인이 요구하는 시장 적재 지점, 음식점 밀집 구간, 기사 대기·휴식 위치, 병목 교차로, 지원센터 같은 공간을 필요가 확인된 순서대로 깊게 만들 수 있다.

## 첫 적용 후보

현재 프롤로그인 `예상보다 빠른 점심 주문 증가 + 가용 기사 부족`은 사업 초기에 질서가 아직 잡히지 않은 상황을 다루므로 제3괘 `수뢰둔`의 영감과 잘 맞는다. 다만 이는 아직 결속 후보이며, 기존 수뢰둔 스토리를 배달 운영 사건으로 덮어쓰거나 여섯 효를 그대로 복사한다는 뜻이 아니다.

첫 국면에서 예상되는 공간 보완 후보는 다음과 같다.

- 기사 현재 위치와 가용 후보가 모이는 대기 지점
- 음식점 밀집 구간과 픽업 접근 지점
- 주문 적체·기사 부족을 행정동 단위로 읽는 운영 오버레이
- 실제 도로·골목 자료가 있는 이동 경로와 자료 결손 시 `이동 중` 대체 표현
- 운영자 예외 카드에서 해당 위치로 이동하는 선택 결속

이 후보는 승인된 구체 효 사건과 자료 감사 전에는 Graph Map·디오라마·Unity 수정 작업이 아니다.

## 미정

- 64괘 각각을 운영 캠페인 하나와 1:1로 대응할지, 일부는 보조 해석으로 둘지
- 첫 점심 피크 캠페인을 수뢰둔에 결속할지
- 운영 캠페인의 여섯 국면과 기존 절기 초·중·후반·두 분기의 관계
- 캠페인별 공간 보완 묶음의 정확한 원장·stable ID·승인 흐름
- 첫 공간 보완에 포함할 실제 위치와 합성 Fixture의 범위

## 다음 질문 하나

사가정·면목제3·8동의 첫 점심 피크 캠페인을 제3괘 `수뢰둔`에서 영감을 얻는 첫 운영 캠페인으로 결속할까?

1. `수뢰둔에 결속` — 추천. 초기 혼란 속에서 기사 공급·주문 적체·현금 안전선을 하나씩 정돈하는 여섯 운영 국면으로 재해석한다.
2. `건·곤부터 새 운영 순서로 시작` — 64괘 전체 형식은 선명하지만 기존 스토리 기획과 중복될 가능성이 크다.
3. `아직 특정 괘에는 결속하지 않음` — 공통 운영 Core와 디오라마 보완 방식만 쓰고 첫 캠페인의 의미는 나중에 정한다.
