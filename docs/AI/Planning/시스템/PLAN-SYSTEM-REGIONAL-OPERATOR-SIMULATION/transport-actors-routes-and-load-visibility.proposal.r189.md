## 1. 추천 — 누가 어디서 무엇을 싣고 어디로 가는가

**기사 형상 + 현재 위치 표식 + 다음 목적지까지의 경로 + 적재/업무 상태**를 한 묶음으로 읽는다. 선택한 한 명을 중심으로 자세히 보며 전체 지도에 같은 강도의 선과 효과를 깔지 않는다.

- 지금: 주문 수행 중이거나 운송이 대기/진행/보류된 때. 현실 날짜와 작업 경과는 기존 시간 규칙을 따른다.
- 여기: 현재 선택한 한 행정동의 도로와 건물, 또는 축소한 구/전국의 거점 관계.
- 나: 직접 조작하거나 관찰/위임하는 플레이어. 기사/차량을 선택해 다음 상황을 판단한다.
- 너: 게임 운송 주체·현재 적재/작업·다음 정차와 확인된 위치/경로. 통계 관계/후보/게임 진행을 구분해 읽는다.
- 이렇게: 위치/방향/상태를 읽고 필요한 때 기존 작업 상세를 연다. 막힘이 있으면 이유와 기존 회복 선택을 확인한 뒤 같은 대상/지도에 돌아온다. 효과를 끄거나 선택을 바꿔도 업무 결과는 동일하다.

이것은 상황 판단과 몰입을 돕는 보조 층이다. 화면상의 이동·빛·물건 모델 자체가 업무 성공·보상·숙련/경 유지의 근거가 되지는 않는다. 괘·오행을 새 운송 수치나 위치 산식으로 대입하지 않는다.

## 2. 동네에서 보이는 네 층

| 층 | 제안하는 모습 | 플레이어가 읽는 의미 |
| --- | --- | --- |
| 기사/차량 | 기존 오토바이·트럭 형상에 짧은 그림자와 판독 가능한 바닥 표식. 선택 시 이름/짧은 ID·방향을 표시 | 누가 지금 어디에 있는가. 모델은 확인된 위치에 붙고 건물/배경에 묻히지 않음 |
| 경로 | 선택한 대상의 현재 위치→다음 정차까지 확인된 도로 경로를 강조. 지나온 구간은 낮은 대비, 남은 구간은 선명하게 | 다음에 어느 길로 어디를 향하는가. 중간 정차/픽업을 생략하지 않음 |
| 적재 | 픽업/적재 확인 후 배달통·상자 등의 작은 적재 표식과 필요 시 수량/작업 연결 표시 | 빈차/픽업 이동과 적재 운송의 차이. 그림 개수를 실제 화물 수량으로 간주하지 않음 |
| 단계/예외 | `픽업 이동`, `대기`, `운송 중`, `전달 확인 필요` 같은 기존 상태에 맞춘 짧은 문구·모양 | 현재 필요한 다음 행동. 지연/보류/경로 없음은 원인·기존 상세 진입과 연결 |

기사의 크기는 축소 때 최소 판독 크기를 확보하는 방향을 검토하되 실제 도로/차량 규모와 화면 표식의 크기를 구분한다. 겹치는 기사 여러 명을 하나의 객체로 오해하지 않도록 목록/건수에서 개별 대상으로 접근할 수 있게 한다. 건물 뒤 가림에는 표식/윤곽의 선택 강조를 우선 검토하며 모든 건물을 투명화하지 않는다.

민트는 기존 관리 관계/운영 매장의 의미를 유지한다. 기사·경로의 강조색은 같은 범례에서 별도 검토하고, 선택은 테두리/굵기·상태는 작은 기호/문구로 함께 구분한다. 색만으로 소유·선택·적재·완료를 동시에 해석시키지 않는다. 기사와 경로가 도로 종류·교차로·보행자를 가리지 않아야 한다.

## 3. 움직임은 두 종류로 구분한다

**차량의 이동은 확인된 게임 위치의 변화**, **선 위의 흐르는 빛은 선택 가능한 방향 안내**로 둔다.

- 차량: 기존 위치/경로/시각 상태 사본을 읽어 표시한다. 부드러운 연결은 같은 유효 경로의 확인된 위치 사이에서만 검토한다. 미래 위치를 임의로 만들어 도착시키거나 도로 밖을 가로질러 이동시키지 않는다.
- 방향 안내: 선택 경로 위의 약한 화살표/빛이 진행 방향을 반복해서 보여 줄 수 있다. 이동 속도·개수·끝점 도달은 현재 차량 위치·진행률·ETA·화물량을 뜻하지 않는다.
- 짧은 잔상: 선택 차량 뒤에만 옅은 자취를 두는 선택지를 제안한다. 확인된 경로/위치가 없으면 주행 이력처럼 만들지 않는다. 미선택 차량의 긴 궤적으로 동네 전체를 덮지 않는다.
- 픽업/전달: 기존 권위 응답을 읽은 뒤 적재 표식을 갱신하거나 짧은 인계 강조를 보여 준다. 모델이 건물 앞에 도착하거나 상자 애니메이션이 끝난 것을 픽업/전달 완료로 판정하지 않는다.

확인된 경로가 없으면 `경로 미연결`로 표시하고 확인 가능한 정차/목록으로 접근한다. 요약 관계선을 쓸 경우 `관계선`임을 표시하며 실제 도로 주행 경로처럼 차량을 달리지 않는다. 위치가 오래됐거나 불명인 대상도 각각 마지막 확인 위치/시각 또는 위치 미확인 목록으로 읽는다. 구 중심/다른 기사 위치에 임의로 배치하지 않는다.

## 4. 지도 높이에 따라 읽는 정보

| 범위 | 기본 표현 | 선택했을 때 |
| --- | --- | --- |
| 동네/직무 | 기사·차량 형상, 현재 단계, 필요한 목적지 표식. 도로망은 선명하게 | 한 대상의 도로 경로·현재 적재·다음 정차와 업무 상세 |
| 구 지도, 서울 전역까지 연속 축소 | 거점/지역별 건수·운송 방향, 제한된 대표 표식 | 선택한 기사/운송의 상태·다음 거점. 판독 가능한 축척에서는 확인된 경로를 보여 주고 혼잡한 겹침은 요약 |
| 전국 | 확인된 거점 사이 옅은 운송 관계선·방향·건수 | 선택한 운송의 인접 정차/단계·적재 정보. 실제 경로를 확보했을 때 별도 구분해 확인 |

r184처럼 구에서 서울 전체까지 연속 축소하고 구↔전국으로 이동한다. 독립 서울 지도 단계를 다시 만들지 않는다. 어느 축척을 보아도 같은 운송 ID/상태를 읽으며 차량을 새로 생성하거나 일을 다시 시작하지 않는다. 축소로 개별 객체를 대표선/건수로 줄여도 실제 게임 운송 주체를 제거하지 않는다.

전국의 아치형 곡선은 r156의 출발→도착 **관계선**이다. 아치 위에 오토바이가 날아가는 식으로 동네 주행과 같은 의미를 부여하지 않는다. 지상/해상/항공은 각 지리/경로 근거와 운송수단 표현을 따르며 선 모양으로 거리·시간·도착 여부를 계산하지 않는다.

## 5. 해상 흐름에서 차용할 것과 자료 구분

Claude N0·N1 반환은 청색 해상선·보라 항공선, 선택 강조, 방향 쐐기/흐르는 빛·상징을 보고한다. 해당 선은 통계 관계이고 배/비행기 상징의 수·속도는 통계와 무관하다. 가상 회차도 당시 반환상 업무 상태와 연결되지 않았다. 이 표현을 이미 검증된 육상 운송 구현이나 실시간 선박 추적으로 간주하지 않는다.

다음 세 종류는 범례·기간·상세에서 구별한다.

| 표시 대상 | 읽는 의미 | 표현 경계 |
| --- | --- | --- |
| 게임 운송 | 같은 게임 세션의 확정된 작업·주체·현재 위치/상태 | 업무/위치 근거가 있을 때 그 대상 표시. 실운영 GPS나 실제 계약 운송이라는 뜻 아님 |
| 공공 통계 흐름 | 특정 관측기간의 지역/항만/공항 사이 통계 관계 | 대표선/지표/기간/출처 표시. 움직이는 상징을 현재 한 대의 위치처럼 해석하지 않음 |
| 계획/후보·표현 예시 | 아직 채택하지 않은 경로 또는 가상 시안 | 점선과 `후보`/`가상` 표시. 선이 보인다고 출발/배차/수요 발생이 확정되지 않음 |

공통으로 차용할 것은 **출발/도착 연결·방향·선택한 대상 강조·정보량 조절**이다. 서로 다른 자료의 시간을 맞춰 보이는 연출 때문에 과거 통계가 현재 게임의 위치나 주문이 되지 않게 한다.

## 6. 선택·간단히·직접 조작

- r162의 현행 기본값 **간단히**를 유지한다. 현재 위치 표식/방향·단계·다음 정차·선택 경로는 남고 빛·잔상·파동 등 장식은 선택형으로 둔다. 효과를 꺼도 확인된 위치 변화는 계속 표시한다. r157의 과거 기본값 질문을 다시 미정으로 돌리지 않는다.
- 효과는 집중/이완 참여 방식과 독립이다. 효과 전환이 업무/시계·배속·차량 속도·충돌·보상/경로 선택을 바꾸지 않는다. 켤 때 지나간 출발/픽업/전달 연출을 한꺼번에 재생하지 않는다.
- 기본 카메라는 사용자가 유지한다. `선택 기사 따라가기`는 명시적으로 켜는 후속 후보이며 수동 이동/기존 복귀와 충돌하지 않게 설계한다. 첫 작업을 이유로 자동 카메라 점프를 강제하지 않는다.
- 지도·목록에서 같은 대상을 고를 수 있게 한다. 패널을 접어도 대상 선택을 잃지 않으며 장식 경로/빛이 클릭·휠/드래그·기존 방향키/Space 작업을 가로채지 않는다.
- 화면 밖 선택 대상은 위치 근거가 있을 때 가장자리 방향/이름과 `다시 보기` 후보로 찾게 한다. 패널이 가리거나 표식이 겹치면 기존 목록으로 접근하고 가짜 위치를 만들지 않는다.
- 중요 실패/복구·현재 업무/선택 표식이 먼저 읽힌다. 새 주문 핀은 기존처럼 픽업 매장을 가리키며, 파동은 기사·경로·업무 패널 아래에서 선택적으로 표현한다.

## 7. 공통 처리의 뼈대

기존 r154의 **상태/사건 관찰→중복 확인→위치 해석→표현**을 확장하는 방향이다. 주체/운송 고유 ID·상태/경로 판본·위치/기준시각·다음 정차·적재 근거를 기존 계약에서 읽고, 축척·선택·효과 옵션에 따라 모델/표식/선/문구만 바꾼다.

오토바이·트럭·선박·항공기는 같은 의미를 읽되 각 표현 프로필을 가진다. 새 공통 원장/별도 시뮬레이션 엔진을 추가하지 않는다. 지속 위치/관계선과 신규 사건의 일회 효과를 분리하고, 재조회·저장 복원·축척 전환·취소/완료·선택 변경에서 오래된 경로/적재/효과를 정리한다. 최근 판본보다 오래된 상태로 차량이 되돌아가 보이는 문제도 검토한다.

표현량 상한/화면 밖 처리·겹침 묶음은 렌더링 정책이다. 미선택 차량의 표식/갱신량을 줄여도 Simulation의 이동·업무량을 줄이거나 새 차를 생성하지 않는다. 정확한 빈도·개수·성능 기준은 현재 실행판과 한 장면 시안에서 정한다.

## 8. 첫 시안과 Claude 구현 제안 순서

첫 장면은 **한 행정동·한 기사·한 주문의 픽업 전→픽업 확인→적재 이동→전달 확인**이다. 현재 판본의 실제 캡처/위치·경로·적재 상태를 먼저 대조하고, 같은 구도에서 `간단히`와 `효과 사용`을 비교하는 시안을 제안한다. 예시 지점/차량/시간이 가상이면 명시한다. [시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md)를 따르며 이번에는 이미지나 제품 화면을 새로 만들지 않았다.

1. **판독:** 기존 기사/차량의 표식·선택 테두리·짧은 단계·다음 목적지·확인된 경로부터 시안/결속한다.
2. **선택 효과:** 같은 정보 위에 약한 방향 흐름·짧은 잔상·적재 갱신 강조를 얹고 간단히와 비교한다.
3. **축척/수단 확장:** 검증한 규칙을 구/전국 요약과 트럭 등 다른 운송수단으로 확장한다. 통계 표현은 별도 프로필을 유지한다.

이 순서는 제안이며 r187의 현재 작업/인계에 자동 추가되는 구현 우선순위가 아니다. 실제 착수에는 승인 판본/시안·기존 WI 재사용·E1~E7 명세·현행 공유 파일/쓰기에 대한 담당 수용이 필요하다. 기존 모델/표식을 우선 대조하고 새 자산이 필요하면 별도 후보 조사로 좁힌다.

후속 검토는 기사/목적지/상태의 즉시 판독, 도로·건물 가림, 복수 기사 겹침/화면 밖, 픽업/전달과 적재 일치, 경로 없음/오래된 위치, 효과 ON/OFF, 직접/관찰, 정지/배속, 복원/취소/완료·이전 판본 수신, 확대/축소·선택/귀환을 같은 업무 판본에서 본다. 정적 시안·자동 검사·실제 Game View/입력·업무 결과 증거는 각각 구분한다.
