## 1. 확정

사가정·면목제3·8동 생활상의 첫 실제 Game View 판독 후보를 `점심 정상 배달 1건`으로 확정한다. 예외나 운영 정산보다 정상 업무의 시작·진행·완료를 먼저 닫는다.

- 음식점 역할 건물 하나, 합성 기사 한 명, 전달지 역할 건물 하나를 사용한다.
- 세 대상은 면목제3·8동 귀속과 일반화 표시 위치가 확인된 후보만 사용한다.
- 실제 상호명·개인·주문·결제·GPS는 사용하지 않는다.
- 면목제7동 등 인접 행정동은 배경으로 보일 수 있지만 이번 주문의 면목제3·8동 집계에 들어가지 않는다.
- 기존 사가정 건물·도로 Mesh와 카메라·색·밀도는 회귀 기준으로 보존한다.

## 2. 한 업무 계보의 정상 7단계

```text
1. 주문 접수
2. 음식점 수락
3. 조리 중
4. 픽업 준비
5. 기사 픽업
6. 전달지 이동
7. 전달 완료
```

모든 단계는 같은 `WorkStableId`, 주문 revision, 공간 자료 revision과 Simulation 시각을 가진다. Unity가 자체 타이머로 다음 업무 상태를 확정하지 않고 서버 또는 합성 Simulation의 새 상태 사본을 받아 표현한다.

각 단계에서 최소한 다음을 판독할 수 있어야 한다.

| 단계 | 공간 표현 | 선택 카드 | 금지 |
| --- | --- | --- | --- |
| 주문 접수 | 음식점·전달지 표식 | 주문 접수시각, 현재 단계 | 실제 주문 생성처럼 표시 |
| 음식점 수락 | 음식점 강조 | 수락시각, 다음 예상 단계 | 조리 시작과 동일시 |
| 조리 중 | 음식점 상태 변화 | 준비 예정시각, 경과 상태 | 실제 메뉴·조리시간 추정 |
| 픽업 준비 | 기사에게 픽업 준비 표시 | 픽업 가능, 다음 조작 | 자동 배차 확정 |
| 기사 픽업 | 음식점에서 기사 상태 전환 | 픽업시각, 수행 상태 | Animation으로 픽업 확정 |
| 전달지 이동 | 승인된 경로 표현 또는 단계 이동 표시 | 최신 위치 시각, stale 여부 | 미검증 도로를 실제 경로로 주장 |
| 전달 완료 | 전달지 결과 표시 | 완료시각, 정상 수행 결과 | Unity만으로 지급·정산 확정 |

## 3. 첫 구현 전 필수 관문

1. 음식점·전달지 역할 건물의 행정동 단일 귀속 또는 결손을 확인한다.
2. 정확 주소는 보호 영역에 두고 Unity에는 일반화 위치와 공개 가능한 역할만 제공한다.
3. 같은 상태 사본의 업무·공간·표시 revision과 projection hash를 결속한다.
4. 검증된 이동 graph가 없으면 단계 6은 직선·도로 추정 이동 대신 `이동 중` 상태와 두 기준점 사이의 비권위 표현으로 제한한다.
5. 낮은 revision, 중복 `WorkStableId`, 행정동 전환 뒤 남은 객체를 거부한다.
6. 정상 완료 뒤 메모리와 실시간 위치 구독을 정리하고 같은 주문이 다시 나타나지 않는지 확인한다.

## 4. 검증 묶음

- **Logic:** 동일 seed·입력·정책 revision에서 7단계 순서와 결과 hash가 같다.
- **계약:** 누락·역행·중복 단계, 잘못된 행정동 귀속, 낮은 revision을 거부한다.
- **표현:** 전체 조망에서 주문 발생을 찾고 음식점·기사·전달지를 선택해 현재 단계와 다음 상태를 읽을 수 있다.
- **권위:** GameObject 이동·Animation·카드 선택이 주문 상태나 지급 원장을 바꾸지 않는다.
- **회귀:** 기존 사가정 화면의 건물 수·배치·카메라·표시 그룹과 무관한 운영 경로가 변하지 않는다.
- **실행 증거:** EditMode 결과와 실제 Play Mode·Game View 캡처를 분리해 보고한다.

## 5. 후속 순서

```text
정상 7단계
  → 조리 지연
  → 기사 보호 해제와 재배차
  → 수령자 부재
  → 주간 정산·13주 운영 관찰
```

정상 절편이 실제 구현·검증되기 전 예외 표현을 같은 작업 묶음에 합치지 않는다.

## 6. 다음 질문 하나

검증된 통행 graph가 준비되기 전 단계 6의 기사 이동을 어떻게 보여줄까?

1. `검증된 구간만 경로 이동, 나머지는 이동 중 상태 표현` — 추천. 사실성을 지키면서 준비된 구간부터 점진적으로 늘릴 수 있다.
2. `기존 상대 경로 후보를 따라 전 구간 이동`: 화면은 풍부하지만 실제 도로 주행으로 오해될 위험이 있다.
3. `기사 이동 없이 출발·도착 상태만 전환`: 안전하지만 생활상과 거리감이 약하다.
