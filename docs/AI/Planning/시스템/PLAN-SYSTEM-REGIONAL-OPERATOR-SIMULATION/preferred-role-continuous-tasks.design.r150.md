# [기획 · 원하는 직무를 연속 수행하는 작업 대기열 · PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION · r150]

후속 [다음 작업 버튼 확정 r151](next-task-button-confirmed.design.r151.md)에서 사용자가 버튼 시작을 선택해 본문의 자동/버튼 시작 질문을 해소했다. 직무·현장을 유지하고 다음 작업 한 건을 버튼으로 시작한다. 그 외 미정은 유지한다.

- 기준일: 2026-11-12
- 상태: `PreferredRoleDirectionConfirmed / ContinuousTaskFlowDocumented / NextTaskStartProposed / ProductUnchanged`
- 사용자 방향: 하단 작업 대기열에서 오늘 하고 싶은 일을 골라 배달만·커피만·포장만 몰아서 할 수 있다. 역할을 번갈아 수행하도록 강요하지 않는다.
- 이번 범위: 기존 [작업 대기열 r149](task-queue-role-minigame.concept.r149.md)의 직무 선택과 반복 흐름을 정밀화한다. 사용자가 이미지 시안은 충분하다고 밝혔으므로 새 이미지는 만들지 않는다. 기존 이미지 전체 배치의 채택으로 확대 해석하지 않는다.
- 공통 기준: [집중·이완 r146](focus-relax-shared-management.design.r146.md), [역할별 미니게임 r147](multi-role-minigames-and-realistic-recipes.design.r147.md), [바코드 타이밍 r148](barcode-scan-timing-minigame.design.r148.md).
- 담당: Codex 기획 문서화. 사용자 전달 기준 Claude가 구현 중인 Core 통합·우유 5팩의 코드·계약·실행 소유는 유지한다.

## 1. 한 종류의 일을 오래 해도 된다

플레이어는 같은 세계에서 여러 사업을 경영하면서 **지금 직접 하고 싶은 일**을 고른다. 직무 선택은 현재 작업 종류의 선택이며 캐릭터의 영구 직업이나 새 실행 모드가 아니다. 집중·이완 두 참여 방식은 그대로 유지한다.

하단 대기열에 `전체 / 배달 / 커피 / 피킹 / 포장 / 입고`처럼 작업 종류를 고르는 작은 선택부를 두는 구성을 제안한다. 선택 종류가 유지되면 해당 작업 원만 우선 보이고 한 건을 마친 뒤에도 같은 종류의 다음 작업을 이어서 제안한다. 정확한 이름·개수·도형·세부 배치는 미정이다. 준비되지 않은 직무는 실행 가능한 것으로 열지 않는다.

| 하고 싶은 일 | 연속해서 직접 수행하는 경험 | 다른 직무로 넘기는 경계 |
| --- | --- | --- |
| 오늘은 배달만 | 매장까지 주행→픽업/가방 적재→전달의 기존 배달 회차 뒤 다음 배달을 고른다 | 음료 제조·창고 작업을 플레이어에게 강요하지 않는다 |
| 오늘은 커피만 | 주문/레시피 확인→제조→마감 후 같은 카페 작업대에서 다음 준비된 주문을 고른다 | 준비 완료 음료는 기존 픽업/판매 인계로 넘기고 직접 배달을 요구하지 않는다 |
| 오늘은 포장만 | 집품이 준비된 주문을 확인→포장/바코드·라벨 확인→출고대기로 넘긴 뒤 다음 포장을 고른다 | 피킹·운송은 각 담당의 기존 업무로 이어지며 포장을 하려고 사용자가 먼저 피킹할 필요는 없다 |

`배달만`은 픽업 단계를 건너뛴다는 뜻이 아니다. r145/r147의 한 배달 업무 안에 필요한 이동·픽업·전달은 유지한다. `포장만`을 선택했어도 집품이 준비되지 않았으면 준비 대기로 보여 주며 포장 가능한 상태로 바꾸지 않는다.

## 2. 완료 뒤 같은 현장에서 이어간다

1. 플레이어가 작업 종류를 선택한다. 선택은 대기열 표시·다음 제안 기준에 적용된다.
2. 그 종류의 준비된 개별 작업을 골라 기존 제어권 인계 후 집중 수행한다.
3. 결과를 짧게 보여 준다. 업무 완료·직접 수행 성과와 아직 기다리는 정산을 구분한다.
4. **같은 종류의 다음 작업을 해당 현장에서 제안**한다. 한 건마다 전체 지도·역할 선택 화면으로 강제 복귀하지 않는다.
5. 계속 수행하거나 작업 종류를 바꾸거나 이완 경영으로 돌아간다.

다음 건은 `다음 커피 만들기`, `다음 포장하기`, `다음 배달하기` 한 번으로 고르는 방식을 첫 세부안으로 제안한다. 완료 알림이 다음 작업 선택을 매번 가로막지 않게 한다. 실제 시작은 최신 작업·담당·현재 단계·가능 행동을 다시 확인한다. 같은 종류를 골라 뒀다는 이유만으로 미래 작업을 미리 수락·배차·예약하지 않는다.

현장 유지에는 작업 가능한 같은 장소·주체의 작업을 우선 제안하는 구성을 사용한다. 다른 장소를 고르면 카메라/업무 초점과 기존 수행 인계 규칙을 따른다. 선택만으로 작업자·물품을 순간이동시키지 않는다. 장소 범위와 다음 작업 정렬 기준은 후속 검토다.

이 흐름은 r149의 `완료 후 경영 복귀`에 **같은 직무 계속하기**를 추가한다. 경영 복귀는 매 작업 뒤 의무 절차가 아니라 사용자가 고르는 귀환 경로다.

## 3. 일이 없거나 마음이 바뀌면

- 선택한 직무에 준비된 일이 없으면 `커피 주문 대기 중`처럼 이유와 상태를 보여 준다. 해당 현장 관찰/대기, 작업 목록 갱신, 다른 직무 선택, 이완 경영 복귀를 제공한다. 다른 직무로 자동 전환하거나 순환 숙제를 주지 않는다.
- 다른 주체가 먼저 가져간 작업은 최신 상태를 반영하고 같은 직무의 다른 준비 작업을 제안한다. 대기열 표시가 남아 있다는 이유로 완료 결과를 복제하지 않는다.
- 직무를 바꾸거나 이완으로 돌아갈 때 현재 요청의 확정 결과와 안전한 인계를 먼저 처리한다. 가방·집품 용기·재공품·재료 소모·공통 시간·실패/페널티·이미 얻은 성과를 보존한다. 한 번에 직접 조작하는 주체는 한 명이다.
- 다른 직무의 정상 자동 업무는 기존 방침·예산·주체·설비·재고·시간 조건에 따라 진행된다. 필터는 그 업무를 멈추거나 즉시 완료시키는 기능이 아니다. 경영의 중요 예외 알림과 큰 지출 등의 사용자 결정은 계속 볼 수 있게 한다.

## 4. 연속 수행의 성과와 보상

연속 수행은 **같은 종류의 독립 작업을 차례로 플레이**한다는 뜻이다. 각각의 작업 고유 식별자·주문·품목·수량·재료/용기·결과·정산을 유지한다. 여러 주문의 합짐·동시 제조·일괄 차감·일괄 보상을 새로 허용하는 규칙이 아니다.

사용자가 같은 종류만 골랐다는 이유로 그 역할의 기본 보수율을 낮추거나 다른 역할의 수행을 보상 조건으로 추가하지 않는다. 직접 수행 보너스는 r146/r147의 역할별 상위 구간 완료 자격과 정식 정산을 따른다. 화면의 연속 완료 수는 성과 요약 후보이며 그 자체로 별도 금전 보상을 만들지 않는다. 대기열 선택·반복 진입·한 번의 스캔마다 중복 보상을 주지 않는다.

## 5. 확정·미정·다음 질문 하나

- **확정:** 하단 작업 대기열에서 원하는 직무만 골라 연속 수행할 수 있게 한다. 여러 직무를 번갈아 하거나 매번 전체 지도로 돌아갈 필요 없이 집중과 이완을 오간다. 새 이미지 없이 문서화한다.
- **세부 제안:** 선택 직무 유지, 같은 현장의 다음 준비 작업 제안, 한 번 눌러 다음 작업 시작, 짧은 완료 결과와 선택 가능한 경영 복귀.
- **미정:** 다음 작업 자동 시작 여부, 장소 범위·정렬·표시 개수·선택 유지의 저장 범위, 연속 성과의 시각 표현. 구현·경제 수치·실제 입력 검증은 후속이다.
- **다음 질문 하나:** 같은 직무의 다음 작업은 자동으로 시작할까, 아니면 `다음 작업` 한 번으로 시작할까? 첫 제안은 한 번 눌러 시작하는 방식이다.

Graph Map 영향 후보는 직무 선택→준비된 작업 목록→직접 수행→완료 결과→동일 직무 다음 작업 또는 이완 귀환이다. 이번에는 기존 Goal·WI·E 증거·Graph Map 원본·새 D 결정을 등록하거나 승격하지 않았다.
