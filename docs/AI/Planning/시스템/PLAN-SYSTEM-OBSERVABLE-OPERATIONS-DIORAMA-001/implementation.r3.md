## 구현

- `사가정지리MeshBuilder`는 도로·건물 Mesh 계산만 소유한다. 기존 배달 관찰과 새 운영 관찰 모두 같은 계산을 재사용한다.
- `사가정운영디오라마View`는 자료 검증 후 지리층, 표현용 접지 그림자, 전용 관찰 카메라, 전체/선택/귀환과 확대·이동을 담당한다. 다른 영역과의 충돌을 피하려고 공식 Root 안에서 지역 표현 원점을 옮기며 원자료 좌표는 변경하지 않는다.
- 기존 `단일PlayerViewController`의 `TryRegisterRuntimeEnvironment`에 자신의 Root만 소유자와 함께 등록한다. 미등록 환경을 숨기는 기존 정책은 유지하고, 비활성화 시 등록을 반환한다. 전역 Renderer 강제 활성이나 다른 환경 허용은 하지 않는다.
- `SagajeongObservationPlacement.json`은 여섯 `synthetic-place:*`와 지도 revision/hash·좌표계·위치·역할을 결속한다. 표식은 실제 업소나 운행 중 차량이 아닌 **완료 업무의 역할 기호**다. 지역 배치가 누락되거나 불일치하면 임의 배치를 하지 않는다.
- `운영관찰WorldView`는 위치 연결, 객체 재사용, 판본별 동결 유지, 만료 제거를 담당한다. 기존 해시 기반 네 구역 좌표는 제거했다.
- `운영관찰WorldController`는 매 프레임 메모리·표현 만료를 확인하고, 비활성화 때 취소·삭제하며 재활성화 때 커서 0으로 새 조회한다. 공유 Client는 비동기 응답과 만료/삭제의 메모리 접근을 직렬화하고 취소된 늦은 응답을 적용하지 않는다.
- API·DB schema·운영 원장·실제 위치·운영 Command는 변경하지 않는다. 정적 가상 배치 설정과 휘발성 업무 데이터는 별도 수명주기를 가진다.

## 실제 실행 결과

첫 시도는 지도/배치 Ready, 미배치 0, Controller Success였으나 이전 표본의 30분 TTL이 지나 업무 객체 0/6이었다. 이 결과를 실패 기록으로 보존하고 TTL을 연장하지 않았다. 기존 DB 볼륨을 보존한 채 새 전용 600초 실행 `observable-operations-run:6dc1f458e32a4d38a1369ea4d17f0bdc`을 시작했다.

새 실행은 600초 Completed, 6/6 발행, Outbox 대기 0·실패 0으로 종료했다. 첫 카메라 캡처는 Camera.main인 농장 화면으로 확인되어 사가정 증거에서 제외했다. 관찰 카메라를 명시한 후에는 파란 배경만 나왔고, 조사 결과 지도 Renderer 5개가 미등록 환경으로 숨겨진 것을 확인했다. 기존 표시 정책의 환경 등록으로 수정했다.

수정 뒤 전체 지도와 6건 표식은 정상 캡처됐으나, 후속 캡처 과정에서 표시 등록 해제와 `Update`의 Client null 참조가 관찰됐다. 정확 재로드 시점은 미관측이므로 원인을 단정하지 않는다. Awake만 의존하던 연결을 OnEnable에서도 재생성하고, OnDisable에 생성 지리/카메라를 해제·다음 활성화에서 재조립하도록 보완했다. EditMode는 수명주기 메서드를 직접 호출하는 경계 시험이며 실제 Editor 재로드 증거와 구분한다.

수명주기 보완 뒤 검증 담당은 실제 Play Mode의 전체·첫 업무 근접·전체 귀환 세 캡처에서 업무 6건, 지도 Renderer 5개 활성, 관찰 카메라 1개를 확인했다. 최근 Console 표본에는 새 Controller null 참조가 없었으나 다른 영역까지 포함한 전체 Console 무오류를 선언하지 않는다. 카메라 전환은 메뉴를 통한 호출로 확인했으며 실제 사용자 클릭·휠·드래그 입력 검증을 대신하지 않는다.

실제 OnGUI 포함 화면에서 하단 안내창과 기존 시점 버튼, 일부 업무 라벨의 겹침을 발견해 안내창을 왼쪽 카드로 옮기고 라벨 겹침 방지 배치를 추가했다. 최종 전체·근접·귀환 UI 재캡처에서 겹침 해소를 직접 판독했고 업무 6건·지도 Renderer 5개 활성 상태가 유지됐다. 검증 담당은 Play Mode 종료·Scene 저장 0·소스 변경 0으로 점유를 반환했다. 최종 Scene SHA-256은 `D0F313FA19B4AB1FB935AD76D081783CAC647082E37A7048147EE0D05F08D732`다. 대표 화면은 [시각 변경 기록](../../../../Changes/2026-09-12-sagajeong-diorama.md)에 보존한다.

## 검증 한계와 다음 단계

- 이번 결과는 동결 지도와 가상 완료 업무의 **정적 관찰 첫 구현**이다. 생성 콘셉트의 세밀한 건물·식생·캐릭터·차량 품질을 완성한 결과가 아니다.
- 실제 운영 전체 업무의 종단 간 검증, 실사용자·GPS 연결, 이동 애니메이션, 모바일/Web 및 Player build는 범위 밖이다. 검증 자료의 유효기간을 우회하거나 서버 실패를 샘플로 숨기지 않는다.
- 자동 시험은 위 실행 시점과 대상 범위의 증거다. 동시에 진행되는 행정동 디오라마 등 다른 스레드 변경은 이 결과에 포함하지 않는다. 별도 E 승격, commit·push·운영 활성화는 하지 않았다.
