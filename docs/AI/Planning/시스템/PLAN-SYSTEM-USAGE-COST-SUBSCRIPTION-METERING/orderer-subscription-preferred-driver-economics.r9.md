## 1. 목적

주문자 구독이 활성이고 기사님이 수요일~화요일 정상 완료 150건 이상인 경우에만 기사 지정 제안을 열되, 구독료·기사 혜택·기술 원가·운영비·환불·유보금을 함께 계산해 지속 가능한 가격과 포함량을 찾는다.

이 문서는 관리 Simulation과 `ShadowMetering` 기준이다. 실제 구독 결제, 자동 갱신, 기사 보너스 송금, 세무·보험·회계 전표를 승인하지 않는다.

## 2. 기능 자격과 금전 자격을 분리한다

```text
주문자 구독 자격
  + 기사 150건+ 활동 배지
  + 기사 공개·후속 업무 제안 동의
  + 현재 배차 적격
  → 지정 제안 기능 사용 가능

지정 제안 기능 사용
  → 실제 제안 Event
  → 기사 수락·서버 배정
  → 정상 완료 Event
  → 포함량·원가·보너스 후보 1건 확정
```

- 구독 결제만으로 기사 수락이나 배정을 보장하지 않는다.
- 기사에게 제안을 보냈으나 거절·만료된 경우 기술 원가는 기록할 수 있지만 완료 보너스는 발생하지 않는다.
- 정상 완료된 지정 제안만 구독의 완료 사용량과 기사 보너스 후보에 한 번 포함한다.
- 일반 배차·일반 주문은 주문자 구독이 없어도 계속 이용할 수 있다.
- 구독 만료 뒤에도 이미 서버가 배정한 주문은 취소하지 않는다. 주문 제출 시 결속한 `SubscriptionEntitlementRevision`으로 해당 주문만 끝까지 판정한다.

## 3. 돈을 세 단계로 본다

### 3.1 지정 주문 1건의 증분 원가

```text
지정 제안 1건 증분 원가
  = 정상 완료 기사 지정 보너스
  + 추가 지도·경로 API 원가
  + 추가 알림 원가
  + 추가 서버·전송·저장 원가
  + 지정 제안 관련 고객지원·분쟁 기대비용
```

- 음식 상품대금과 기사 기본 수행대금은 계약상 다른 주체에게 지급할 통과자금이면 플랫폼 매출로 잡지 않는다.
- 기본 배달료를 주문자가 별도로 부담한다면 구독료가 이를 대신 지급한다고 가정하지 않는다.
- 구독 혜택으로 배달료를 할인하거나 면제하면 그 할인·보조액을 별도 변동비로 추가한다.
- 기사 지정 보너스는 기본 수행대금, 거리 할증, 기상 할증, 보험·세무 항목과 분리한다.

### 3.2 구독자 1명·1개월의 기여금

```text
구독자 월 순기여금
  = 주문자 구독 보유매출
  - 구독 결제 수수료
  - 구독 기본 기능 직접 원가
  - 지정 완료 건수 × 건당 지정 보너스
  - 지정 기능의 지도·알림·서버 증분 원가
  - 고객지원·환불·분쟁 기대비용
  - 공유 운영비 배부 추정
```

- 세금·PG·환불·회계상 수익 인식은 국가·관할 Adapter의 승인된 판본을 사용한다. 승인 전에는 후보와 미확정을 구분한다.
- 월 순기여금이 음수인 구독자는 많이 사용할수록 손실이 커지므로 가격·포함량·보너스 중 하나를 조정해야 한다.
- 실제 사용량이 없는 구독자에게 가상의 보너스 원가를 배부하지 않는다. 실제 사용량과 전체 서비스 준비 고정비를 분리한다.

### 3.3 플랫폼 기간 전체의 지속 가능성

```text
플랫폼 보유 매출
  = 주문자 구독 보유매출
  + 음식점 등 다른 구독 보유매출
  + 계약상 플랫폼 귀속 용역 대가

영업이익 후보
  = 플랫폼 보유 매출
  - 변동비
  - 고정비

목표 영업이익 후보
  = 플랫폼 보유 매출 × 4%
```

4%는 지정 주문마다 공제하는 비율이 아니다. 기간 전체에서 운영 지속 가능성을 판단하는 목표다. 기사 수행대금·음식점 상품대금·환불 예정액 같은 통과자금을 매출 분모에 넣지 않는다.

## 4. 보너스 상한을 역산한다

예상 지정 완료 건수가 0보다 클 때 관리 Simulation은 다음 후보를 계산한다.

```text
월 지정 보너스 가용 예산
  = 주문자 구독 보유매출
  - 보너스 외 구독 변동비
  - 공유 운영비 배부 추정
  - 목표 영업이익 배부 후보
  - 안전 유보금 적립 후보

지속 가능한 건당 보너스 상한 후보
  = max(0, 월 지정 보너스 가용 예산)
    / 예상 지정 정상 완료 건수
```

- 이 값은 실제 지급액이 아니라 가격·포함량·보너스 정책을 비교하는 상한 후보다.
- 예상 완료 건수가 0이거나 입력 원가가 미확정이면 상한을 숫자로 단정하지 않는다.
- 구독료를 올리는 것만 답으로 두지 않고 포함량, 보너스, 지도 호출, 지원 비용과 일반 배차 전환 시간을 함께 비교한다.

## 6. 세 시나리오를 함께 본다

| 시나리오 | 지정 사용량 | 보너스·외부 원가 | 목적 |
| --- | --- | --- | --- |
| 기준 | 관측 중앙값 | 현재 단가 후보 | 평상시 지속 가능성 |
| 스트레스 | 상위 사용량 | 보너스·지원·환불 증가 | 헤비유저와 피크 손실 확인 |
| 보수 | 구독자 감소 | 고정비 유지 | 규모 축소 시 현금 버팀 확인 |

각 시나리오는 구독자 월 순기여금, 플랫폼 영업이익률, 손익분기 구독자 수, 현금 최저점, 유보금 충족 여부를 함께 보여 준다. 평균 주문자 하나만 보고 가격을 정하지 않는다.

## 7. 첫 운영 원칙 후보

- 구독은 우선 `기사 지정 제안 이용권`이며 기본 배달료 면제 상품으로 해석하지 않는다.
- 무제한이라는 문구는 비용 분포를 확인하기 전 사용하지 않는다.
- 지정 제안 1건당 기사 혜택을 유지하려면 월 포함 횟수·공정 사용 상한 또는 구독료 중 적어도 하나가 보너스 원가를 감당해야 한다.
- 포함량 초과 시 자동 과금·기능 차단은 아직 승인하지 않는다. `ShadowMetering`에서는 초과 후보와 원가만 표시한다.
- 가격·보너스·포함량 변경은 새 `SubscriptionPolicyRevision` 이후 주문에만 적용하고 소급하지 않는다.

## 확정

- 주문자 구독 활성은 150건 활동 기사 지정 제안의 필수 조건이다.
- 기사 150건 배지와 기사 동의·현재 적격성도 모두 필요하다.
- 주문 1건, 구독자 월, 플랫폼 기간 손익을 분리한다.
- 기사 기본 수행대금·통과자금과 지정 보너스를 분리한다.
- 4%는 플랫폼 보유 매출 대비 기간 목표이며 주문별 공제율이 아니다.
- 실제 과금 전에 `ShadowMetering`으로 사용량·원가 분포를 확인한다.

## 미정

- 주문자 월 구독료
- 월 지정 제안 포함량 또는 공정 사용 상한
- 정상 완료 건당 기사 지정 보너스
- 구독자가 지정 제안을 사용하지 않았을 때 혜택 구성
- 포함량 초과 시 안내·추가 구매·다음 달 대기 중 어느 경로를 제공할지

## 다음 질문 하나

첫 주문자 구독은 **기사 지정 제안 이용권만 포함하고 기본 배달료는 주문마다 별도로 유지**할까요? 추천은 그렇다. 그래야 기사 기본 수행대금과 지정 보너스를 구독료가 불투명하게 대신 부담하지 않고, 구독 기능 자체의 원가와 기여금을 정확히 볼 수 있다.
