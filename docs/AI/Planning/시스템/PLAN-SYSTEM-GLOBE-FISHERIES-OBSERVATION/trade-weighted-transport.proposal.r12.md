# [기획 · 지구본·무역 관찰 · PLAN-SYSTEM-GLOBE-FISHERIES-OBSERVATION · r12]

상태: `Proposed / ExistingCodeAndOfficialSourcesInspected`. 2026-09-23 사용자는 한국의 국가별 수출입 통계를 근거로 선박·항공기·화물이 오가는 양을 표현하기를 요청했다. r11의 균등 12척 합성 시연을 즉시 통계 기반이라고 바꾸지 않는다.

## 확정된 방향

- 한국↔상대국의 거래 규모와 수출/수입 방향을 공간에서 관찰한다. 실제 운송수단 대수나 실시간 위치로 주장하지 않는다.
- 원본 통계, 해석/표현 배율, Unity 객체 수를 분리한다. 출처·기간·단위·수집 시각·원본 hash·개정판·자료 품질을 보존한다.
- 현재 r11의 중국↔동남아·일본↔미국 합성 경로는 한국의 무역 통계로 설명할 수 없다. 한국 관련 통계 표현에는 한국을 출발/도착 의미점으로 하는 별도 연결이 필요하다. 기존 장식 항로는 숨기거나 명시적으로 분리한다.

## 현재 코드·자료 확인

- `eng/Ssalddel.PublicDataPortalImport/무역소매Batch.cs`: UN Comtrade 2025 대한민국 품목별 수입, 금액/USD·순중량/kg의 수집·정규화·저장·재조회 흐름 존재. 일부 HS 품목과 상위 상대국 자료여서 국가 전체 수출입 총량이 아니다. 품목 부모/자식·세계 합계를 중복 합산하지 않는다.
- `국내해양자료Pipeline.cs`와 서버 `국내해양통계RevisionNormalizer.cs`: 관세청 품목·국가별 자료 수집 및 `impWgt/impDlr/expWgt/expDlr` 해석 존재. 현재 acquire는 특정 수산물 3건 중심이다. r6 로컬 미리보기도 이 자료의 제한된 조회다.
- Unity r11: 통계와 무관한 합성 경로 6개, 고정 선박 12척. 항공기와 국가별 통계 기반 객체 수 배분은 아직 없다.
- 이번 확인은 코드·문서와 공식 공급원 메타데이터 조사다. 국가 전체 수치 수신·DB 저장·재조회·Unity 연결은 수행하지 않았으며 완료로 표시하지 않는다.

## 공식 공급원 확인 (2026-09-23)

1. [관세청 국가별 수출입실적](https://www.data.go.kr/data/15101612/openapi.do): 국가별 통관 통계. 금액 USD, 순중량 kg, 월 단위 갱신/정정. 수입은 원산국·CIF, 수출은 최종목적국·FOB 기준. 무료·이용허락범위 제한 없음으로 안내되지만 대상 API 접근 권한과 실제 응답은 별도 검증한다.
2. [관세청 품목별 국가별 수출입실적](https://www.data.go.kr/data/15100475/openapi.do): 국가/HS별 상세 근거 후보. 수집기를 재사용하되 전체 합계와 품목 상세를 같은 합산 집합으로 쓰지 않는다.
3. [UN Comtrade 데이터 설명](https://uncomtrade.org/docs/content-of-data/) 및 [가용성 설명](https://uncomtrade.org/docs/data-availability/): 운송수단 제공 여부는 보고국·자료 집합마다 다르다. 한국의 대상 기간에 해상/항공 구분이 있는지는 아직 확인하지 않았다.

국가별 무역 상대국은 실제 직항/직송 또는 마지막 기항지를 의미하지 않는다. 해상·항공 화물 톤수, TEU, 실제 선박 입출항 횟수, 항공기 운항 횟수는 서로 다른 지표다. 통관 건수 역시 운항 횟수가 아니다.

## 제안하는 구현 순서

1. 대상 기간·국가·지표를 좁힌다. 추천: 2025년 연간 한국↔중국·일본·미국·호주·베트남부터. 베트남은 첫 동남아 사례일 뿐 동남아 전체를 대변하지 않는다.
2. 기존 수집/가져오기 경로로 원본 확보→기존 로컬 MySQL 비공개 검토 상태 저장→독립 재조회·동일 입력 중복 방지를 검증한다. 원격 운영·정기 대량 수집·자동 공개는 제외한다.
3. 보고국·상대국·수출입·기간·품목 범위·운송수단·단위·판본을 키로 정규화한다. 결측은 0으로 바꾸지 않고, 서로 다른 기간/단위/통계 기준을 섞지 않는다.
4. 읽기 전용 상태 사본에 실제 금액/중량과 `VisualUnitScale`, `SyntheticRepresentation`, `ModeAvailability`를 분리한다. 같은 화면/기간 비교에는 같은 배율을 사용한다. 카메라 성능 상한으로 수를 줄인 경우 배율 변경/압축 여부를 표시한다.
5. 해상 중량이 확인되면 선박, 항공 중량이 확인되면 항공기, 수단 미확인이면 중립 화물 표식으로 표현한다. 실제로 확인되지 않은 해상:항공 비율은 임의로 배분하지 않는다. 중량 기반과 금액 기반 화면은 별도 모드로 두고 혼합하지 않는다.
6. 수출은 한국→상대국, 수입은 상대국→한국으로 별도 배분한다. 왕복 한 바퀴를 같은 수출입량으로 계산하지 않는다. 긴 경로에 물체가 오래 남아 무역량이 커 보이지 않도록 이동 거리와 발생 빈도를 분리하고, 수치 카드로 정확한 비교를 보조한다.
7. 선택하면 기간·국가·수출입 금액/중량·자료원·최종 갱신·화면 기호 환산 기준을 보여준다. 국가 간 연결선은 통계 관계이며 실제 항공/해상 항로가 아니다.

## 미정·검증

- 화면 주 지표(물류 중량 또는 거래 금액), 첫 기간·대상 국가, 기호당 배율·총 객체 상한은 제안 상태다.
- 해상/항공 구분의 실제 확보 여부·수치 완전성·공개 배포 검토는 미완료다. 운송수단 미확보는 항공기를 임의 생성하는 근거가 아니다.
- 향후 시험: 세계 합계/상대국 중복 방지, 수출입 방향, 결측≠0, 동일 사본 결정성, 단위/판본/기준 분리, 시점 변경 배율 표시, 객체 풀 상한·TTL, 실제 Game View와 출처 카드 확인.
- 이번에는 조사·기획 문서만 변경했다. 코드·DB·Unity 실행 변경·commit·push 없음. 새 디오라마 규칙 후보 없음.
