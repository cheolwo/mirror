# 지구본 위경도 기준선 r7

## 확정 범위

2026-09-22 사용자 요청: 기존 지구본에 촘촘한 흰색 위경도선을 넣어 향후 위치별 수온을 읽는 기준으로 사용한다. `ApprovedScopedPresentation`. 위도는 가로 원, 경도는 극을 잇는 세로 곡선이다.

- 기존 구면 좌표 변환·GlobeVisualRoot·카메라·Canvas를 재사용한다. 새 Scene·지형 권위·자료 타일은 만들지 않는다.
- 전체 10도 주선, 가까운 관찰에서 2도 보조선을 표시한다. 확대 진입 40/복귀 42 Unity 단위로 경계 떨림을 방지한다. 이 간격은 화면 판독 기본값이며 수온 관측 해상도를 뜻하지 않는다.
- 선은 흰색 계열, 주선/보조선 밝기 구분. 보조선은 극 부근 밀집을 피하도록 위도 ±76도 이내만 그린다. 주선은 극까지 이어진다.
- 한반도 주변 좌표 표기(N/E)를 소수 표시하며 구면 회전·뒤쪽 가림을 따른다. 수온 값이나 어군 이동은 생성하지 않는다.
- 수정 범위: 별도 Unity `지구위경도선View.cs`·전용 시험·meta, 기존 `세계지구본View.cs`의 초기화 결속, 이 기획·목차·현재 작업·화면 증거. 기존 변경 보존.
- 검증: 같은 구면의 좌표/반지름/자오선 이음/위도 폐합, 10→2→10도 전환 및 객체 재생성 없음, 실제 Play Mode 전체/확대 Game View, Console 구분. 읽기 전용 표현이며 WI·E 승격 없음.

## 결과

- 별도 Unity에 `지구위경도선View`·전용 EditMode 시험과 `.meta`를 추가하고 기존 `세계지구본View.Initialize`에 결속했다. 선 259개를 한 번 생성하고 활성화만 전환한다. Collider·업무 상태 쓰기 없음.
- Unity 컴파일 성공. 새 시험 4/4, 기존 `세계지구본Tests` 21/21 통과. 이후 선 굵기만 보정하고 재컴파일·실제 화면을 다시 확인했다.
- canonical `SimulationWorldShell` 실제 Play Mode에서 거리 53→37→53을 카메라 API로 적용해 10→2→10도, 선 수 259 유지 확인. 물리 마우스 휠 입력·모바일·Windows 빌드 시험은 아니다.
- 실제 697×621 Game View에서 초기 얇은 선의 끊김을 관찰해 주선/보조선 굵기를 0.06/0.03 Unity 단위로 보정했다. [전체/확대 화면 기록](../../../../Changes/2026-09-22-globe-graticule.md)은 생성 이미지가 아닌 `ScreenCapture.CaptureScreenshot` 결과다.
- Console에는 기존 `OSLifecycleValidationRuntime` 종료 시 부모 변경 오류가 재현된다. 시험 도구의 `TestResultCollector.RunFinished` 중복 완료 오류도 별개로 관찰했다. 위경도선 오류는 관찰되지 않았으나 전체 Console 0을 주장하지 않는다.
- Play Mode 종료, Scene 저장·commit·push 없음. 수온은 기존 인증 차단 그대로이며 새 DB 조회·외부 수집은 하지 않았다. 실제 수온·어군 이동 결속은 후속이다.
- 자료 출처는 기존 구면 좌표 변환과 Natural Earth 배경을 그대로 유지한다. 사실/표현 분리 경계를 지지하며 새 디오라마 규칙 후보 없음. E 승격 없음.
