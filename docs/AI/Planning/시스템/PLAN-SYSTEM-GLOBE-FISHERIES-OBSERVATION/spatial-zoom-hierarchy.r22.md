# 공간 확대 계층 보완 r22

상태: 사용자 요청 반영 설계 초안. r21 전환 구현은 보존한다. 신규 지도 계층의 코드·장면 구현 완료를 뜻하지 않는다.

## 현재 코드 확인

별도 Unity 저장소의 `공간의미확대전환Models.cs`는 Hidden → Region → AdministrativeArea → StationArea → LocalDiorama를 제공한다. Region은 서울 전체가 아니라 사가정 생활권 후보이고, View는 주로 단계 선택 UI다. 한반도 지형에서 서울·중랑구 공간 표현으로 내려가는 실질적인 중간 지도는 이 경로에 결속되어 있지 않다.

Resources에서 WorldGlobeCountryCatalog, KoreanPeninsulaTerrainPreviewManifest, SagajeongReference와 건물 높이·도로명·방향 기준점을 확인했다. 이 확인은 DB에 서울·중랑구 자료가 없다는 판정이 아니다. 중간 계층에 재사용할 DB/배치맵 자료와 판본·출처는 별도 대조가 필요하다.

## 표시 계층 제안

| 단계 | 관찰 범위 | 읽히는 정보 |
| --- | --- | --- |
| 0 | 지구 | 국가 간 선박·항공 상징 이동 |
| 1 | 동아시아·한반도 | 해안·산맥·큰 강·도시 거점 |
| 2 | 수도권 | 서울과 주변 도시, 주요 연결 축 |
| 3 | 서울 | 한강·구별 위치·주요 역 |
| 4 | 중랑구 | 동별 위치·역·간선도로 |
| 5 | 선택한 동 또는 역세권 | 동네 도로와 건물 분포, 관찰 범위 |
| 6 | 사가정 상세 디오라마 | 기존 건물·도로·업무 객체와 애니메이션 |

이것은 관찰 축척의 순서이지 모든 단계가 엄격한 행정구역 포함 관계라는 뜻은 아니다. 역세권은 여러 행정동에 걸칠 수 있다. 기존 Region 고유 식별자를 서울/수도권으로 개명해 의미를 바꾸지 않는다. H1/H2/H3와 표시 단계 번호도 동일시하지 않는다.

## 전환 계약

- 같은 위경도 관심 지점을 유지하면서 화면의 지상 표시 폭이 연속적으로 줄어든다. 단계별 별도 공식 Scene은 만들지 않는다.
- 휠은 연속 확대, 정보의 종류·정밀도만 표시 범위에 따라 바뀐다. 단계마다 버튼을 누르거나 전체 화면 페이드를 반복하지 않는다.
- 각 계층은 고유 식별자, 실제 범위, 좌표 원점/변환, 자료 참조·판본·hash, 준비 상태, 표시 가능한 축척 범위를 가진다. 정확한 임계값은 실제 화면 판독 시험으로 정한다.
- 카메라 안정 뒤 주변 타일을 준비한다. 이전 요청보다 오래된 응답은 적용하지 않는다. 다음 계층 준비 완료 후 교체하고, 실패하면 현재 지도와 실패 상태를 유지한다.
- 확대/축소 경계는 서로 다르게 두어 작은 휠 변화로 지도 계층이 반복 전환되지 않도록 한다.
- 데이터가 없는 단계는 기존 저해상도 지형 확대와 자료 미준비로 표현한다. 임의 강·도로·경계를 생성하거나 자료가 있는 것처럼 장식하지 않는다.
- 정보창은 기본 접힘, 공간·움직임 우선, 선택 시 근거 조회. 지리 배경과 합성 업무 경로를 구분한다.

## 구현 우선순위

1. 기존 DB·Graph Map·배치맵에서 서울/중랑구 범위와 지형·도로 자료, 좌표 변환·출처를 대조한다.
2. 한반도 → 서울 → 중랑구를 첫 좁은 구현 대상으로 삼아 실제 지도 표시와 동일 관심 지점 보존을 검증한다. 수도권은 자료 준비 수준에 따라 저해상도 중간 표현부터 연결한다.
3. 중랑구 → 기존 사가정 디오라마를 연결하고 복귀·자료 지연·역순 응답·경계 왕복을 시험한다.
4. 각 축척 Game View로 위치 관계와 정밀도 증가를 비교한다. 단계 UI 변경만으로 공간 계층 구현 완료를 선언하지 않는다.
