# 새벽 식자재 인수 관찰 — 기존 코드 조사·첫 범위 r29

상태: 방향 승인·좁은 소스 조사 완료 / 구현 명세 준비 단계. 제품 코드·DB·Unity 장면 변경 없음. 이 문서는 실행 승인 hash와 WI 작업 명세를 대신하지 않는다.

## 사용자 의도와 확정 범위

음식이 전달되기까지 보이지 않는 시간에도 일하는 사람의 하루를 알아볼 수 있게 한다. 새벽 배송기사 한 분과 음식점 담당자 한 분의 식자재 인수를 첫 장면으로 삼는다. 준비·대기·검수·인계를 표현하고 속도 순위나 지연만으로 귀책을 표시하지 않는다.

처음에는 기존 사가정 공간의 가상 음식점 한 곳과 합성 도착 사례를 사용한다. 실제 이천 업체·프랜차이즈 계약·납품 관계를 만들거나 실제 운송 경로라고 표시하지 않는다. 창고와 음식점의 독립 준비를 먼저 확인하고, 센터→음식점 운송은 이후 통합 범위다.

## 상향식 우선순위

1. **음식점 식자재 인수 한 건:** 기존 수량·재고·부분 인수 계약 조사 → 대표 WI/주체/명세 결속 → 정상·중복·부분 보류 검증.
2. 같은 revision의 인수 결과를 기존 Unity 관찰 경로에 연결. 하차/검수/인계 표현은 결과를 읽을 뿐 완료를 확정하지 않는다.
3. 인수 재고와 기존 조리 준비의 연결. 재고 부족 시 무조건 조리하지 않도록 정책을 별도 결정·검증한다.
4. 독립 출고가 준비된 물류센터와 화물 운송 인계 통합.
5. 여러 매장 순회와 하루 시간대 표현, 다른 행정동 확장.

## 첫 WI 명세에 필요한 내용

- 상황: 합성 식자재 배송 건이 음식점 도착 지점에 있다. 차량 도착은 인수 완료가 아니다.
- 주체: 배송기사, 음식점 인수 담당자. 실제 개인/위치가 아닌 모의 주체.
- 직접 결과: 담당자가 확인한 정상 수량만 인수 기록·가용 재고에 한 번 반영한다.
- 선택: 정상 인수 또는 문제 수량 보호 보류. 수량 불일치·중복·낮은 revision은 자동 정상 처리하지 않는다.
- 회복: 담당자 부재/확인 미완료는 대기. 파손 보류의 귀책·보험·폐기·배상은 자동 확정하지 않는다.
- 귀환: 인수 후 기사 다음 이동과 음식점 준비를 별도 단계로 보여준다. 애니메이션 도착/종료로 다음 업무를 확정하지 않는다.
- 검증: 동일 명령 재요청 시 재고 중복 증가 없음, 인수+보류 수량 보존, 저장 재진입, 관찰 중 권위 불변.

아직 미정: 재사용할 정확한 Lot/수량 계약과 WI ID, 작업 명세의 승인 revision/hash·writePaths, 물품/단위와 인수 예외 입력. 이번에 임의 번호·Goal을 활성화하지 않았다. 다음은 해당 코드 대조와 명세 마련이며 새 화면·장면을 먼저 늘리지 않는다.
