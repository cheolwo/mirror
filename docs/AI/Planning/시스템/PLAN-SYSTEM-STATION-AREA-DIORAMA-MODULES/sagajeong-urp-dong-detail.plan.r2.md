[r1 개발계획](sagajeong-urp-dong-detail.plan.r1.md)의 검토 질문에 사용자가 「어, 한번 진행해봐, 진행해봐.」라고 답했다. 자료의 출처를 항목별로 표시하는 방식과 사가정의 독립 Windows URP 비교를 시작하는 범위에 반영한다. r1의 S2~S4는 후속 단계의 설계로 남긴다.

## 확정 · 자료를 읽는 범례

| 표기 | 의미 |
| --- | --- |
| **공표 자료** | 확인된 출처의 값이나 위치를 표시한다. 항목을 열면 기관·기준일 또는 기간·단위를 확인할 수 있다. |
| **연출** | 규칙으로 배치하거나 그린 결과다. 실제 가로수, 사람 수, 특정 점포의 옥상 설비 등으로 해석하지 않는다. |
| **자료 없음** | 지역·시점·판본에서 확인된 자료가 없다. 관측된 0과 구분한다. |

한 항목에 공표 도로와 연출 차량이 함께 쓰이면 각각의 근거를 알린다. 자료가 없는 지역도 동일한 렌더링 기준에서 볼 수 있다. 이용 조건이 충돌하거나 적용이 보류된 원천은 출처 대장에 보존하며 화면의 공표 자료로 채택할 때 해당 파일 판본과 사용 범위를 확인한다. 범례 결정은 화면에서의 의미를 확정한다. 범례 UI의 구현·배포는 해당 화면 판본의 검토를 거친다. [원천과 자료 결손 기준](../../../../Architecture/역세권디오라마증거진화체계.md)

## 확정 · S1의 대상과 결과

사가정역 출구와 골목이 함께 읽히는 동일한 Windows 장면을 **내장 렌더링 기준판과 URP 시험판**에서 비교한다. Unity `6000.5.6f1`을 맞추고 시험판에는 설치된 URP `17.5.0`의 입력을 사용한다. 원본 Unity에 URP가 연결된 사실과 전용 Windows 게임 빌드가 URP로 실행된 사실은 각각 확인한다. 같은 지도·선택·카메라·비교 날짜와 시각에서 색, 길, 기사 빛, 건물 선택, 동에서 구로의 복귀를 대조한다.

독립 작업 루트는 `artifacts/local/hongdal-sagajeong-urp-s1-20261124/`다. 그 아래 `project-builtin/`, `project-urp/`, `player-builtin/`, `player-urp/`, `logs/`, `evidence/`를 사용한다. 기존 Windows 빌드 작업본의 `Assets/`, `Packages/`, `ProjectSettings/`는 읽기 전용 입력이다. 파일 소유권과 고정 지문, 복사와 실행 범위, 결과별 검수 기준은 [승인 S1 인계와 검증 명세](../../../Handoffs/2026-11-24-Codex-인계-사가정-URP-S1-격리시험.md)에 결속한다.

S1에서 얻을 결과는 복제된 프로젝트에서의 URP 기본 렌더링 비교와 차단 기록이다. 두 실행판의 렌더러 유형·빌드 로그·동일 장면 촬영·실제 조작은 각각의 증거로 평가한다. 광원과 효과의 최종 승인, 절기 관찰 UI의 제작, 공유 Unity 경로 병합, 덧굽기 개발과 전국 확대는 S1 승인과 별도로 다룬다. 진행 중인 Claude 작업본과 전국 바탕 굽기에는 쓰지 않는다.

## 미정과 다음 판정

- 사가정의 최종 소재·조명과 효과 강도, 운영 표식의 실제 가독성, 두 실행판의 성능 차이는 첫 대조에서 확인할 항목이다.
- S1 결과가 나오면 실제 URP 장면에 맞춰 어느 표현부터 풍부하게 만들지 살핀다. 프로필·지역 자료·전국 적용은 r1의 후속 계획을 따른다.

이 판은 사용자 결정을 개발 범위에 묶는다. 실행 증거, Graph Map 채택, E 승격, 공통 디오라마 규칙 승격은 각각 별도 결과다.
