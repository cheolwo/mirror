## S1 · Windows용 URP 시험을 먼저 닫는다

1. **Codex**가 기존 Windows 빌드의 복사 입력·소스 파일 지문·데이터 판본을 고정한다. `auto-build-check.cmd`의 입력 복사 절차를 참고해 독립된 시험 프로젝트·실행판 경로를 정한다. 내장 렌더링의 `project`·`project-base`와 원본 Unity 설정을 기준선으로 보존한다. 시험 전용 URP 패키지와 Pipeline/Renderer/Quality/Volume을 구성한다. 같은 입력에서 두 실행판을 다시 만들 수 있게 기록한다.
2. **Claude**가 실제 셰이더와 사용처를 점검한다. 바탕, 기존 그림자, 나무, 날림, 강수 셰이더 및 바람 include를 출발점으로 삼고 구 지도용 계절 표현과 같은 이름으로 찾는 재질까지 확인한다. 계절 가중치·나무 흔들림·비눈의 기존 계산에서 호환되는 부분을 이어 쓴다. 공용 렌더 설정의 일괄 변환은 별도 범위다.
3. **함께 검수**할 첫 장면은 사가정역 출구와 골목이 함께 읽히는 하나다. 같은 모듈·카메라·날짜·해상도에서 내장 렌더링과 URP 기본을 가깝게 대조한다. Linear 차이로 길·건물·가게 및 기사 빛의 기존 색이 달라지는지 먼저 본다. 실제 실행에서 `GraphicsSettings.currentRenderPipeline` 유형과 게임 화면, 마우스 선택·동/구 복귀를 확인한다.

**첫 통과 조건**은 실제 Windows URP 실행, 렌더 오류와 누락 재질 없는 화면, 운영 표식 판독과 이동·선택 회귀 통과다. CPU/GPU 프레임 시간의 중앙값·95백분위, 처음 진입 시간과 메모리 기준을 같은 PC에서 측정한다. SSAO·블룸·얕은 초점·대량 인스턴싱은 기본 렌더가 통과한 뒤 한 가지씩 비교한다. 관찰용 흐림은 선택 효과 후보이고, 업무 표식의 가독성을 우선한다. 실패하면 해당 효과를 끈 비교판과 기존 내장 렌더링판으로 돌아갈 수 있게 둔다. [Unity 전환 절차](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/upgrading-from-birp.html) · [Unity GPU Resident Drawer 설정](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/gpu-resident-drawer.html)

## S2 · 사가정에서 자동으로 옮길 표현을 고른다

| 겹 | 첫 적용 | 확인 방법 |
| --- | --- | --- |
| A · 공통 렌더 | 해 방향·시간대 조명과 벽 아래 접지 그늘부터. 근거리 실시간 그림자와 원거리 계산 그림자를 같은 해 방향에 맞춘다. 계절·날씨는 기존 환경값과 출처를 읽는다. | 같은 장면의 낮·노을·밤과 가까운 곳/먼 곳을 비교한다. 거리 전환에서 그림자가 겹쳐 검게 되거나 갑자기 끊기는지 확인한다. |
| B · 동별 표현 보강 | 사가정 저층 주거의 옥상색·외벽·창 규칙과 두세 종류의 작은 옥상 소품을 프로필로 고정한다. 멀리서는 옥상색과 건물 윤곽이 먼저 읽힌다. | 옥상 안에 배치되는지, 건물 아래나 길을 가리지 않는지, 같은 입력에서 같은 결과가 나오는지 확인한다. |
| C · 지역 기록 | 보유 자료 가운데 용도와 사용 범위가 확인된 자료 하나로 출처 표시와 선택을 검증한다. | 관측 범위·기준일·공표 자료 여부가 해당 항목에서 읽혀야 한다. 예시 자동차나 나무에는 연출임을 표시한다. |

사가정 프로필은 첫 검수 기준이다. 다음 프로필은 체감 차이를 가려내기 위해 **고층 단지와 읍면 농촌**에서 먼저 검토한다. 농촌·해안·산자락·산업과 같은 지역 특징은 해당 범위의 자료가 있을 때 반영한다. 용도 분포와 출처가 있는 층수·높이, 토지피복을 함께 읽고 자료가 빈 동에는 중립 프로필을 둔다. 추정 높이의 비중이 높으면 고층·저층 유형 확정을 유보한다. 사가정역과 같은 고유 모델은 위치와 이용 범위를 확인한 장소의 목록에서 적용한다.

## S3 · 완료된 모듈에 덧굽기 파일을 붙인다

- 전국 굽기 실행기의 **검증 완료 체크포인트와 출력 지문이 일치하는 묶음**에서 읽는다. 새 출력·임시 파일·재시도 기록은 별도 경로에 둔다. P5가 쓰는 중인 파일은 다음 읽기로 넘기고, 디스크·메모리·작업 경합이 나면 덧굽기만 멈췄다가 재개한다.
- 바탕 모듈의 동 고유 식별자, SHA-256, 좌표 원점·단위, 건물색인 지문, 프로필 판본·지문, 규칙 도구 판본, 선택 자료 판본과 이용 범위를 기록한다. 같은 건물 고유 식별자와 같은 판본은 같은 장식을 만든다. 현 HDIO의 정점 필드에는 기존 창·시설 태그가 있으므로 고유 건물 ID와의 결속을 실제로 확인한다. 정점 순서나 최근접 좌표로 추정 연결하지 않고, 결속을 확인한 건물/범위부터 적용한다.
- 완성한 파일을 검증한 뒤 게시한다. 바탕 판본이나 건물 결속이 다르면 해당 동 보강을 비우고 검증된 바탕을 그린다. 다시 굽거나 프로필을 바꿀 때는 영향 받은 동을 재계산한다. 미설치·일치하지 않음·미지원 지역과 자료 없음은 기록에서 구별한다.
- 지역 자료는 레이어마다 출처와 기준 범위를 확인한다. 현 가로수 OA-23040 포털은 제한 없음으로 표시되나 같은 파일의 과거 4유형 기록이 있어 현재 프로젝트의 사용 보류를 이어간다. OA-1325는 2012년 일회성 자료로 종로구가 비어 있다. 서울 밖 세분류 토지피복도는 시점과 반입 조건을 확인한 뒤 결정한다. 주소자료 보안각서 범위와 기 배포 승인 값은 기존 증거 대장을 따른다. [OA-23040 현재 표시](https://data.seoul.go.kr/dataList/OA-23040/S/1/datasetView.do) · [OA-1325 설명](https://data.seoul.go.kr/dataList/OA-1325/S/1/datasetView.do) · [토지피복지도 자료 신청](https://egis.me.go.kr/req/intro.do)

**첫 통과 조건**은 사가정과 다른 유형 1개 동에서 같은 입력 재실행의 결과 지문이 같고, 중단 재개·파일 누락·지문 불일치 때 기본 지도와 선택이 살아 있는 것이다. 표시가 가능한 건물 비율, 보강 파일 크기, 생성 시간, 소품 수·겹침, 실제 사용 프로필과 결손 원인을 기록한다. 실패한 동은 따로 남기고 정상 동을 다시 처리하지 않는다.

## S4 · 작은 묶음에서 전국으로 넓힌다

1. 사가정 통과 후 **중랑 16동 → 현재 실행판의 26동**에서 동일한 도구로 읽는다. 대표 동의 낮·노을·밤·계절 네 장을 실제 렌더링 가능한 환경에서 촬영하고 사람이 화면을 비교한다.
2. 서울의 다른 유형, 경기 고층 주거·인천 수변 또는 항만·완료한 P5 읍면에서 각각 표본을 고른다. 항만에 주거용 소품이 붙거나 추정 높이로 유형을 단정하는 반례를 검사한다. 사가정 외 표본과 사람이 검토한 결과를 [기존 규칙 승격 기준](../../../../Architecture/역세권디오라마증거진화체계.md)에 연결한다.
3. 검증된 완료 묶음까지 시군구 단위로 넓힌다. **전수는 파일·좌표·ID·판본 검사**, 실제 촬영은 시군구 대표와 이상 값 중심으로 한다. 표본에서 걸린 문제는 같은 유형의 동을 추가 촬영한다. 실행 1회와 장면 1장당 시간을 재서 전국 비용을 산정한 뒤 전수 네 장 촬영 여부를 정한다.

시군구 모아보기에는 바탕 자료 완성도, 보강 성공·대기·기본 지도 복귀, 사용한 프로필, 자료가 있는 레이어와 프레임 결과를 각각 둔다. 자동 통과는 실제 화면 검수나 배포 승인에 이어지는 근거로 기록한다. 각 지역의 배포 범위는 기존 자료의 승인 기록을 따른다.
