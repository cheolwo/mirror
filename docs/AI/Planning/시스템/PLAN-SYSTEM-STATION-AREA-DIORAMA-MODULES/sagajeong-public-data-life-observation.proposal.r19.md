## 1. 제안의 목표

사가정역 디오라마를 단순한 도시 모형에서 **시간대에 따라 사람들이 드나들고, 차량과 업무가 움직이며, 선택한 건물과 합성 Actor의 현재 생활을 읽을 수 있는 지역 관찰 모듈**로 심화한다.

다만 실제 주민이나 기사 개인을 공공자료에서 재구성하지 않는다. 공식 자료는 공간·시설·시간대별 집계의 근거이고, 화면의 개별 주민·방문자·기사·차량은 `SimulationSession`이 생성하는 합성 Actor다. Unity는 서버 또는 Simulation의 상태 사본을 읽어 표현하고 업무 상태·건수·금액을 계산하거나 확정하지 않는다.

사가정은 계속 깊게 만드는 첫 참조 Profile이다. 이 제안에서 확립한 자료 대장, 표시 그룹, 경계 포털, Actor 카드와 검증 규칙은 후속 역에서 같은 계약을 쓰되 사가정의 좌표·수치·건물·업체를 복사하지 않는 표준이 된다.

## 2. 지금·여기·나·너·이렇게

- 지금: 기존 사가정 모형·건물 선택·H/역할 카드·저밀도 교통·네 OS 합성 생명주기의 부분 구현이 서로 다른 검증 수준으로 존재한다.
- 여기: 사가정역 기준 기존 명목상 1km × 1km 표현 창이다. 행정동 경계나 실제 생활권 전체와 같은 범위로 간주하지 않는다.
- 나: 전체 생활상을 조망하거나 건물·업체·합성 Actor 하나를 선택해 추적하는 관찰자다.
- 너: 주민, 통근자, 방문자, 음식 배달 기사, 상점·창고 종사자와 저밀도 차량처럼 Simulation이 만든 Actor 및 읽기 전용 업무 사본이다.
- 이렇게: 자료 품질이 확인된 공간망과 경계 포털을 따라 유입·이동·대기·업무·유출하고, 사용자는 표시 그룹을 켜고 끄거나 Actor 카드를 열어 현재 상태를 읽는다.
- 결과: 현실 자료의 근거와 한계를 숨기지 않으면서도 사가정의 생활 흐름을 게임적으로 관찰할 수 있다.
- 다음 선택: 개별 Actor 정보의 생성 권위를 먼저 확정한 뒤 공공자료 전수 대장과 첫 수직 절편을 승인한다.

## 3. 제안의 핵심 원칙

1. 기존 사가정 건물·도로·카메라·색·조명·지도 판본을 기본 회귀 기준으로 보존한다.
2. 공공자료, Simulation 상태, Unity 표현을 한 레이어나 한 원장으로 합치지 않는다.
3. 결손 자료를 추정으로 채우지 않고 `Blocked`, `NoCoverage`, `Unresolved`, `BackdropOnly`로 남긴다.
4. 개별 NPC는 합성 인물이며 실제 주민·기사·사업자 개인의 신원·직업·동선·수입을 추론하지 않는다.
5. 레이어 온·오프는 로컬 표시 선택일 뿐 Simulation Tick, 업무 생명주기, 원장, 조립 hash와 가상 정산을 바꾸지 않는다.
6. 1km 바깥 세계는 상세 도형을 임의 생성하지 않고 `OutsideWindow` 상태와 검증된 경계 포털로만 이어 간다.
7. 음식점 사실, 상인 Claim, 광고·후원 Campaign, 운영 주문과 합성 시나리오를 별도 원장과 권한으로 유지한다.
8. 같은 입력 자료·seed·시각·규칙 판본은 같은 일정·Actor 상태·투영 hash를 만들어야 한다.

## 4. 먼저 구분할 세 가지 레이어 축

“레이어”라는 말을 다음 세 축에 공용으로 쓰되 서로 대신하지 않는다.

### 4.1 자료 원천 분류

[생활 여덟 영역](../../자료/PLAN-DATA-EIGHT-LIFE-DOMAINS-001/README.md)의 기존 안정 코드를 재사용한다.

1. `food-and-livelihood` — 먹고사는 일
2. `goods-and-commerce` — 물건과 장사
3. `community-culture` — 공동체 문화
4. `home-road-and-place` — 집, 길, 터전
5. `teaching-and-learning` — 가르치고 배우는 일
6. `safety-and-public-order` — 치안과 법질서
7. `visitors-and-exchange` — 손님과 바깥 교류
8. `defense-and-emergency` — 방위와 비상대응

이는 공공자료를 찾고 계보를 관리하는 다대다 분류다. 새 H 단계, WI, Unity 물리 Layer 또는 사용자 메뉴가 아니다.

### 4.2 Unity 실행 모듈

현행 여덟 상위 모듈을 유지한다.

```text
ActiveStationDioramaHost
├─ DataEvidence
├─ BaseSpatialPresentation
├─ SpatialMeaning
├─ Mobility
├─ Interaction
├─ LifeSimulation
├─ BusinessOverlay
└─ EnvironmentPresentation
```

각 모듈은 자료 준비도·의존성·판본·조립 hash와 Adapter 수명을 소유한다. 사용자 토글 상태를 준비도에 섞지 않는다.

### 4.3 사용자 표시 그룹

사용자가 Game View에서 독립적으로 켜고 끄는 표현 채널이다.

```text
사가정 생활 관찰
├─ 기본 공간
│  ├─ 건물·표면
│  ├─ 도로
│  └─ 행정 경계·역 중심·범위
├─ 이동 기반
│  ├─ 차로·진행 방향
│  ├─ 교차로·정지선·신호
│  ├─ 횡단보도·보행망
│  └─ 경계 진입·이탈 포털
├─ 생활 이동
│  ├─ 보행자
│  ├─ 차량·오토바이
│  └─ 업무 Actor
├─ 생활 목적지
│  ├─ 공원·시장·주차·화장실
│  ├─ 교육·의료·안전·응급
│  └─ 음식점·상점·창고
├─ 운영 관찰
│  ├─ 음식배달
│  ├─ 화물
│  ├─ 창고
│  └─ 마트 피킹
├─ 공개 표시
│  ├─ 검증된 사업장
│  └─ 광고·후원
├─ 환경
│  ├─ 시간·날씨
│  ├─ 대기·녹지
│  └─ 계절 표현
└─ 상호작용·진단
   ├─ 건물 카드
   ├─ Actor 카드
   └─ 출처·품질·결손
```

`DataEvidence`는 화면 장식이 아니라 모든 표시를 검증하는 비가시 기반이다. 기본 공간은 최초에는 보존 잠금하고, 진단·시설·업체·Actor·차량·환경부터 독립 토글한다. 기존 `사가정운영디오라마View`가 여러 모듈을 함께 소유하므로 당장 쪼개지 않고 신규 Adapter부터 독립 표시 그룹 계약을 적용한다.

표시 상태는 최소 `Off / Loading / Ready / Stale / Blocked / NoCoverage`를 구분한다. `Off`는 자료가 없다는 뜻이 아니며, `Blocked`를 빈 화면으로 조용히 대체하지 않는다. 다시 켰을 때는 꺼 두기 전 프레임이 아니라 최신 Simulation Tick을 표시한다.

## 6. 공공자료 “전수 조사”의 완료 정의

전수 조사는 현실의 모든 주민·업체·시설을 확보했다는 선언이 아니다. **선언한 공식 카탈로그와 검색 어휘에서 사가정 생활 표현에 관련된 모든 데이터셋 후보를 빠짐없이 열거하고, 각 후보를 판정한 상태**를 뜻한다.

각 후보에는 다음을 기록한다.

- 안정 자료 ID, 공식 명칭, 제공기관, 원본 URL
- 접근 방식과 자격·호출 제한
- 원천 판본·자료 기준시각·수집시각·갱신주기
- 원본 hash와 파생 hash
- 공간 범위·공간 정밀도·원 좌표계·변환 판본
- 주요 필드·단위·누락 처리
- 이용조건·출처표기·변경/상업/재배포 허용 여부
- 개인정보·안전·오해 가능성
- 사가정 창 coverage와 건물/도로/포털 결속 가능성
- 대상 자료 영역·실행 모듈·표시 그룹
- `Included / Excluded / Blocked / NoCoverage / Superseded` 판정과 근거

공식 조사 범위는 서울 열린데이터광장, 공공데이터포털, 도로명주소·국가공간정보, KOSIS·서울 통계, 서울교통공사·국가철도공단, 기상청, 중랑구 공식 공개자료를 우선한다. 네이버지도·배달 플랫폼의 메뉴·리뷰·영업정보는 공공자료가 아니며 별도 이용허락·계약·수집 승인이 없으면 수집하지 않는다.

기존 `ExternalDataSourceCatalog`, 원문 사본, 정규화 원장을 재사용한다. 두 번째 공급원 카탈로그를 만들지 않는다. 제안된 전수 대장은 다음 상태를 구별해야 한다.

- 이미 로컬 원장에 수집·독립 재조회된 자료
- 공식 후보를 확인했지만 아직 받지 않은 자료
- 키·이용조건·좌표계·판본 때문에 차단된 자료
- 사가정 공간 coverage가 없는 자료
- 공간 해상도가 낮아 지역 분위기 카드에만 쓸 수 있는 자료
- 실제 개인이나 운영 사실로 해석할 수 없어 합성 규칙의 집계 근거로만 쓸 자료

## 8. 1km 바깥과 이어지는 경계 포털

밖에서 사람이 들어오거나 차량이 나가는 모습은 창 중앙에서 갑자기 생성·삭제하지 않는다.

```text
ExternalDemandZone
  → OutsideWindow
  → TransitionHalo
  → StationBoundaryPortal
  → CoreWindow 1km
```

- `ExternalDemandZone`은 역·인접 지역·외부 주거·외부 상권 같은 추상 수요 권역이다.
- `OutsideWindow`는 외부에 있다는 상태이며 외부 상세 좌표나 건물을 요구하지 않는다.
- `TransitionHalo`는 카메라 밖 또는 저 LOD의 짧은 준비 구간이다.
- `StationBoundaryPortal`은 검토된 차량·오토바이·보행 그래프가 창 경계를 만나는 지점이다.
- `CoreWindow` 안에서만 디오라마 상세 이동을 표현한다.

포털 최소 계약 후보는 다음과 같다.

- `PortalStableId`, `SourceEdgeStableId`
- `ModeCode`: `Pedestrian / Vehicle / Motorcycle / Transit`
- `DirectionCode`: `Ingress / Egress / Both`
- 경계의 `LocalXZ`, 진입 방향, 폭과 연결 Node
- `GraphRevision`, `SourceRevision`, `EvidenceStateCode`
- 합성 표현 허용 여부와 실제 통행 권위 부재 표시

이동 유형은 `Inbound / Outbound / Through / Internal`, Actor 수명은 `ScheduledOutside → Entering → Inside → Exiting → CompletedOutside`로 둔다. `ActorStableId`, `VisitStableId`, `TripStableId`, 포털 ID, Simulation revision과 WorldTick을 유지해 pool·LOD·GameObject가 바뀌어도 같은 Actor로 이어진다.

선택한 Actor가 밖으로 나가면 카메라는 외부 미구현 공간을 추적하지 않는다. 카드는 잠시 `영역 밖으로 이동`을 표시하고 전체 보기 또는 이전 관찰 지점으로 돌아간다.

## 9. 합성 생활 Actor와 밀도 규칙

공공 통계는 다음 두 역할만 맡는다.

1. 시간대·요일·공간 구역별 합성 Actor 밀도의 근거
2. 어떤 포털과 목적지 범주 사이의 흐름이 더 자연스러운지 검토하는 집계 근거

공공 통계가 직접 정하지 않는 것은 개별 이름, 직업, 집·직장, 이동 경로, 주문, 완료 건수, 수입, 평판이다. 이것들은 승인된 Simulation 규칙과 결정적 seed가 만드는 합성 프로필이다.

첫 생활 역할 후보는 다음과 같다.

- 주민: 귀가, 장보기, 산책, 휴식
- 통근자: 역·버스 포털과 주거·업무 목적지 사이 이동
- 방문자: 시장·공원·의료·상점 방문과 이탈
- 지역 종사자: 음식점·상점·창고·시설 근무와 휴식
- 업무 Actor: 음식 배달 기사, 화물 기사, 창고 작업자, 마트 피커
- 통과 Actor: 내부 목적지 없이 서로 다른 포털을 잇는 보행자·차량

보행자는 보행망·횡단보도, 차량은 방향성 차로, 오토바이는 승인된 차로와 골목 접근망, 대중교통 승객은 역·정류장 포털을 사용한다. 통행망이 없는 구간을 건물 사이 직선 이동으로 숨기지 않는다.

첫 성능 후보는 화면 내 보행자 최대 12명, 차량·오토바이 최대 4대, 공용 Actor pool 16~20개다. 이는 승인값이 아니며 기준 Game View의 frame time과 화면 판독성을 측정한 뒤 확정한다. 가까운 Actor만 선택 가능한 저폴리 모형을 쓰고, 먼 Actor는 단순 모형 또는 비선택 집계로 낮춘다.

## 10. Actor 선택 카드

선택 Coordinator는 한 번에 `None / Building / Actor / Business` 가운데 하나만 활성화한다. 기존 건물 선택과 새 Actor 선택이 서로 다른 카드를 동시에 열거나 카메라를 다투지 않게 한다. 대량 Collider 대신 현재 보이는 Actor의 화면 투영 인덱스에서 가장 가까운 선택 후보를 찾는다.

공통 `ActorObservationCardProjection` 후보는 다음을 포함한다.

- 합성 별칭, 생활 역할과 업무 역할
- 현재 행동, 현재 의미 위치, 경로 진행률
- 현재 OS와 업무 생명주기 단계
- 마지막 행동, 다음 행동, 대기·실패·회복 이유
- 이번 시나리오의 진행·완료·실패·회복 건수
- 선택적 가상 매출·비용·예상 지급·정산 요약
- 출처 종류, 자료·규칙 판본, 기준시각, 품질 상태
- `SyntheticSimulation=true`
- `ActualPerson=false`
- `ChangesAuthorityState=false`

예시는 다음과 같다.

```text
합성 배달 기사 · 기사-07
현재: 사가정로 교차로 신호 대기
업무: 음식 픽업 완료 · 전달지 이동 중
이번 시나리오: 완료 4건 · 진행 1건 · 회복 1건
모의 예상 지급: 총 18,000원 - 모의 비용 3,200원 = 14,800원
합성 Simulation 자료 · 실제 기사·위치·정산 아님
```

건수와 금액은 Unity가 화면 Event나 애니메이션 횟수로 계산하지 않는다. Simulation의 합성 업무·경제 원장이 계산하고 Unity는 같은 revision의 읽기 사본만 표시한다. 금액은 통화 코드와 최소 화폐 단위 정수 또는 서버에서 검증된 decimal wire 형식을 쓴다. 경제 활동이 없는 Actor는 0원 대신 `NotApplicable`로 숨긴다.

실제 이름, 상세 주소, GPS, 번호판, 연락처, 소속 업체의 비공개 정보, 실제 주문 상세, 개인 평점과 실제 정산은 공개 Steam 디오라마에 제공하지 않는다. 향후 운영 자료는 합성 자료의 fallback이 아니라 별도 권한의 `OperationalProjection`으로 제공하고, 공개 가능한 일반화 상태만 관찰 세계에 투영한다.

## 11. 서버·저장·Unity 책임

```text
공식 원천
  → ExternalDataSourceCatalog
  → RawSnapshot + 원본 hash
  → 정규화 RDB 원장
  → 공간·시간·품질 검토
  → 판본화된 역/지역 투영
  → Simulation density profile + synthetic ledger
  → 읽기 전용 Unity Adapter
  → 표시 그룹 + 선택 카드
```

- RDB는 코드·원천 계보·정규화 자료·집계·검토·업무/가상 경제 상태를 맡는다.
- MongoDB는 불변 공간 자료, 타일과 판본화된 디오라마 투영을 맡는다.
- 역 manifest는 원자료를 복제하지 않고 행정동·법정동·타일·자료 판본·표시 Profile을 참조한다.
- `SimulationSession`은 시작 시 승인된 Reality Context와 밀도 Profile을 동결한다. 공급자를 매 Tick 직접 호출하지 않는다.
- Unity는 위치 보간·LOD·선택·카드 표시만 맡고 서버 또는 Simulation revision을 변경하지 않는다.
- 운영 장면 사본은 업무 단계와 카드 갱신에 쓰고, 부드러운 합성 이동은 Simulation Tick 사본과 Unity 보간으로 표현한다.

## 12. 단계별 제안

### G0 — 자료 대장과 회귀 기준

- 여덟 생활 영역의 공식 후보 전수 대장을 만든다.
- 현행 전체/부분 Game View, Scene hash, 지도 hash, 모듈 상태, renderer/material/triangle, Actor 수와 frame time을 기준선으로 봉인한다.
- 화면 건물 4,062개와 기준 건물 602개의 결속·`BackdropOnly` 판정을 닫는다.

### G1 — 차량·보행 공간망

- 신호 125개의 좌표계 충돌을 해소하거나 계속 별도 차단한다.
- 차로·진행 방향·교차로·제어기·신호등·정지선·횡단보도 관계를 검토한다.
- 보행망·골목·건물 출입 접근점·연석 정차점의 결손을 수집한다.
- 이 단계만으로 `TraversalReady=true`를 선언하지 않는다.

### G2 — 생활 밀도와 경계 흐름

- 250m 생활인구, 행정동 생활인구, 역사 승하차, 버스·자전거·교통량·보행량을 같은 시각·공간 단위로 일반화한다.
- 검토된 그래프 경계 교차에서 차량·오토바이·보행·대중교통 포털을 만든다.
- 같은 seed·시간대·Profile로 같은 유입·유출 일정이 생성되는지 검증한다.

### G3 — 생활 목적지와 업체

- 교육·의료·시장·공원·편의·안전·응급시설을 공식 좌표 또는 검증된 건물에만 결속한다.
- 공공 사업장, 상인 Claim, 광고 Campaign, 운영 주문과 합성 메뉴를 분리한다.
- 미결속 시설·사업장은 집계·진단에 남기고 아이콘을 임의 배치하지 않는다.

### G4 — 환경 문맥

- 날씨·대기·녹지 자료의 관측시각과 해상도를 표시한다.
- 사가정 전용 카메라·layer 광원·강수 대상이 준비되기 전 기존 전역 환경이나 Nature 프로필을 바꾸지 않는다.
- 첫 환경 연결은 표현만 바꾸고 NPC 일정·속도·경로·업무 결과에는 영향을 주지 않는다.

### G5 — 첫 합성 Actor 수직 절편

- 기존 합성 음식 배달 기사 한 명을 선택한다.
- 현재 업무 단계, 경로 진행, 합성 건수와 모의 예상 지급 카드까지 같은 revision으로 표시한다.
- 기사 표시를 껐다 켜도 Simulation은 계속되고 같은 Actor의 최신 상태가 복구되는지 확인한다.
- 기존 도형·카메라·조명·Scene을 바꾸지 않는 검증 조립부에서 먼저 수행한다.

### G6 — 경계 생활상

- 검토용 포털 2~4개에 차량 1대와 보행자 2명의 유입·유출을 붙인다.
- 통근자 2, 장보기 2, 산책 1, 통과 보행자 1의 작은 저밀도 Profile로 시작한다.
- 평일 저녁 배달 시간대를 첫 화면 후보로 두되 실제 시간창은 문답 뒤 확정한다.

### G7 — 모듈 분리와 화면 검증

- `LifeSimulation`, `BusinessOverlay`, `EnvironmentPresentation`을 각각 독립 Adapter로 결속한다.
- 기존 Interaction 소유를 중복하지 않고 하나의 선택 Coordinator에 건물·Actor·업체 provider를 등록한다.
- 전체, 교차로, 골목, 선택 Actor 카드의 Game View와 Console·메모리 회수·전환을 검증한다.

## 13. 검증 완료 조건 후보

- 같은 자료 hash·Profile·seed·기준 시각으로 같은 Actor 일정·포털 선택·상태 hash가 생성된다.
- 1,800 Tick 동안 창 중앙 임의 생성 0, 포털 중복 생성 0, 건물 관통 0을 확인한다.
- 검토된 신호·횡단 계약을 쓴 표본에서는 적색 횡단 0, 정지선 초과 0을 확인한다.
- 표시 그룹을 꺼도 Simulation hash·업무 상태·가상 경제 원장이 바뀌지 않는다.
- 다시 켜면 최신 Tick을 표시하고 Actor 선택은 `ActorStableId`로 유지된다.
- Actor가 유출돼도 같은 업무 수명은 `OutsideWindow` 상태로 이어지고 화면 밖 상세 좌표를 만들지 않는다.
- 실제 주민·기사·주문·정산·상세 주소·GPS·번호판·연락처가 Unity 계약이나 캡처에 포함되지 않는다.
- 미결속 건물·시설·사업장은 아이콘·목적지·출발지로 임의 승격되지 않는다.
- 자료가 낡거나 CRS·hash·라이선스가 맞지 않으면 게시와 Simulation Profile 생성을 거절한다.
- 성능 상한은 전체 보기와 근접 보기에서 각각 측정하고 Actor 수·LOD·pool 예산을 판본화한다.
- 사가정에서 통과한 계약을 두 번째 합성 역 fixture에 적용해 좌표·건물·업체 누출이 없는지 확인한다.

## 17. 다음 질문 하나

첫 사가정 주민·기사 Actor는 **공공 통계를 시간대·공간별 밀도 근거에만 사용하고, 클릭 가능한 개인의 별칭·직업·이동·완료 건수·가상 정산은 모두 별도 합성 주민 Simulation이 생성**하는 방식으로 확정할까?

추천은 **그렇게 한다**다. 공공자료의 현실감을 살리면서 실제 주민·기사 개인을 추론하는 오류를 막고, 같은 규칙을 다른 역에도 안전하게 재사용할 수 있다. 대가는 직업 구성과 경제 수치가 현실 통계가 아니라 명시적인 게임 규칙이 되므로 이후 계산식과 표시 문구를 별도로 기획해야 한다는 점이다.
