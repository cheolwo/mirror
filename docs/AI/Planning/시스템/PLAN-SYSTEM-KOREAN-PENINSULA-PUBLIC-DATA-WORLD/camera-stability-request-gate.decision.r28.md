# [기획 · 월드·공간·관찰 · 카메라 안정 요청 관문 · 확정 r28]

## 결정

빠른 확대·축소·이동 중에는 매 프레임 공간 자료를 요청하지 않는다. 마지막 카메라 입력 뒤 **0.3초 동안 관찰 문맥이 안정되면 최종 확대 수준과 화면 범위에 필요한 상태 사본만 요청**한다.

```text
카메라 입력 시작
  → 기존 검증 화면 유지
  → 관찰 문맥 후보만 로컬 계산
  → 마지막 입력부터 0.3초 대기
    → 문맥이 같으면 새 RequestGeneration 발행
    → 다시 움직였으면 대기 시간 재시작
```

## 동작 원칙

- 카메라 이동·회전·휠·핀치 입력은 즉시 반응한다. 0.3초는 화면 조작 지연이 아니라 서버·디스크 요청의 안정 관문이다.
- 대기 중에는 마지막으로 검증된 상위 또는 현재 수준 표현을 유지한다.
- 안정 뒤 요청할 때 `FocusSpatialStableId`, `ObservationLevelCode`, `ViewBounds`, `ActiveLayerIds`를 한 세대로 묶는다.
- 새 입력이 생기면 진행 중 요청을 취소할 수 있고, 취소가 불가능한 응답은 `RequestGeneration` 불일치로 적용하지 않는다.
- 동일 요청 키의 캐시가 있으면 네트워크 요청 없이 즉시 적용한다.
- 상세 카드 선택은 카메라 관문과 별도다. 사용자가 정지된 객체를 명시적으로 선택하면 카드 요약은 즉시 열고, 큰 상세 자료만 별도 지연 적재한다.
- 0.3초 값은 첫 Game View 기준선이다. 실제 프레임 시간·입력 장치·서버 지연 검증에서만 조정하며 플랫폼마다 임의로 다른 업무 의미를 부여하지 않는다.

## 검증

- 1초 동안 연속 휠 입력을 해도 중간 확대 수준마다 요청이 발생하지 않는다.
- 마지막 입력 0.3초 뒤 최종 문맥 요청이 한 번 발생한다.
- 0.3초 전에 다시 움직이면 기존 대기가 취소되고 시간이 다시 시작된다.
- 늦게 도착한 과거 세대 응답은 화면과 선택 상태를 되돌리지 않는다.
- 캐시 적중·부분 자료층 실패·축소 복귀에서도 같은 관문을 유지한다.
- 요청 수 변화가 Simulation Tick, 운영 revision과 업무 원장에 영향을 주지 않는다.

## 확정

- 안정 대기 시간 첫 기준은 0.3초다.
- 조작 반응과 자료 요청 시점을 분리한다.
- 요청 대기 중 마지막 검증 화면을 유지한다.
- 최종 확대 수준만 요청하고 중간 요청은 만들지 않는다.

## 미정

- 자료를 불러오는 동안 사용할 진행 표시의 모양과 위치.
- 터치 관성 이동이 끝났다고 판단하는 세부 조건.
