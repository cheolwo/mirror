# 지구본 다중 규모 상향식·하향식 수집·표현 계획 r6

- 상위 기획: `PLAN-SYSTEM-KOREAN-PENINSULA-PUBLIC-DATA-WORLD`
- 상태: `Proposed / MultiScaleDirectionAccepted / CollectionNotStarted`
- 목적: 지구본부터 건물 디오라마까지 자료의 원래 공간·시간 단위를 보존하면서 생활과 물자의 흐름을 관찰한다.
- 기준: 수집 방향은 자료 성격이 정하고, 화면 확대 수준은 표현 정밀도를 정한다. 모든 자료를 면목동에서 상향 집계하거나 세계에서 하향 배분하지 않는다.

## 핵심 구조

```text
하향식 관측
  세계·국가·광역 통계 / 무역 / 기상 / 해양 / 광역 교통
                    ↓
공통 결속층
  RegionStableId / NodeStableId / FlowStableId
  관측시각 / 공간정밀도 / 출처판본 / 품질 / 공개범위
                    ↑
상향식 관측
  건물 / 주소 / 점포 / 시장 / 창고 / 역 / 행정동 / 현장 검증
```

하향식 자료와 상향식 자료는 서로의 빈칸을 추정으로 메우지 않는다. 같은 지역·거점·기간에 결속할 수 있을 때만 하나의 관찰 화면에 함께 표시한다.

## 규모별 자료와 표현

| 규모 | 우선 자료 | 지구본·Unity 표현 | 금지하는 과장 |
| --- | --- | --- | --- |
| 세계 | 국가 경계, 국가 통계, 국가별 무역, 광역 기상·해양 | 국가 색상, 흐름 호, 기간별 밀도, 자료 가용성 | 통계만으로 실제 개별 선박·화물 위치 생성 |
| 동아시아·한반도 | 항만·공항·철도·고속도로·물류 거점, 수산 유통, 환경 | 광역 거점과 연결선, 시계열 pulse, 권역별 집계 | 출발·도착 근거 없는 국내 경로 추정 |
| 대한민국·광역권 | 시도·시군구·행정동, 창고·시장·역·공동주택 | 지역별 밀도, 거점 상태, 자료층 켜기·끄기 | 행정구역을 실제 서비스·배달권으로 자동 간주 |
| 행정동·생활권 | 건물, 주소, 사업장, 전통시장, 도로·보도·시설 | 아이소메트릭 디오라마, 건물·시설 카드, 검증된 이동 | 집계값을 특정 건물·사람에게 자동 배분 |
| 건물·현장 | 출입구, 점포, 사진 검증, 운영 상태 사본 | 상세 건물, 표식, 읽기 전용 생활·업무 overlay | 개인정보·상세 주소·현재 영업을 무검증 공개 |

## 자료 유형별 수집 방향

### 하향식이 우선인 자료

- 국가별·품목별 수출입, 전국·광역 통계
- 광역 기상·해양·환경 관측과 재난 경보
- 전국 교통망·철도·항만·공항의 기준정보
- 전국 가격·생산·수급 시계열

이 자료는 원래 제공되는 국가·시도·시군구·격자 단위를 보존한다. 행정동이나 건물로 임의 배분하지 않으며 확대 시에는 `이 수준보다 세분화 불가`를 표시한다.

### 상향식이 우선인 자료

- 건축물대장, 도로명주소, 필지·건물·출입구
- 공개 사업장, 전통시장 점포, 창고·공동주택·공공시설
- 현장 사진 검증, 개별 시설의 출처가 있는 상태
- 실제 운영 시스템의 비식별 상태 사본

이 자료는 건물·시설에서 행정동·시군구로 집계할 수 있지만, 미결속·경계 중첩·중복을 별도 보존한다. 합계가 상위 공식 통계와 다르면 한쪽을 덮지 않고 출처·기준일·포함 범위 차이로 진단한다.

### 양방향 결속이 필요한 자료

- 수산 위판장·창고·재고·입출고
- 전통시장·물류창고·급식 계약
- 항만 반입 이후 내륙 물류와 지역 소비 관측
- 지역 생산·가격·수요와 국가 수출입의 관계

양쪽 끝점과 기간이 모두 확인될 때만 흐름을 만든다. 한쪽만 있으면 거점 또는 집계 카드로 남기고 경로를 생성하지 않는다.

## 물류·수산·무역의 화면 표현 단계

### M0 — 집계 흐름

관세청 품목별 국가별 수출입실적처럼 국가·기간·품목 합계만 있는 자료는 상대 국가와 대한민국 사이의 `집계 흐름 호`로 표현한다. 선의 두께·색·pulse는 금액이나 중량의 정규화된 구간이며 실제 항로·선박·도착시각이 아니다.

### M1 — 거점 흐름

항만·위판장·공판장·창고의 공식 위치와 입출고 자료가 결속되면 한반도 확대 화면에서 거점과 기간별 이동을 보여 준다. 출발·도착 쌍이 없는 재고 변화는 거점 안의 증감으로만 표현한다.

### M2 — 운항·입출항 관측

공식 선박 입출항·항만 호출 자료에서 선박·항만·시간이 확인되면 항만 진입·출항 애니메이션을 허용한다. 실제 항적이 없으면 해상 직선 이동은 `상징 경로`로 명시한다.

### M3 — 실제 항적

이용 권리와 갱신 조건이 확인된 AIS 등 위치 시계열이 있을 때만 실제 관측 선박 궤적을 표시한다. 위치가 오래되거나 끊기면 보간으로 현재 위치처럼 연장하지 않고 `갱신 중단`으로 멈춘다.

따라서 현재 포털 목록의 관세·수협 자료만으로 바로 실제 배가 한반도 주변을 항해한다고 표현하지 않는다. 먼저 M0·M1을 만들고, M2·M3에 필요한 공식 자료는 별도 출처 조사와 승인 관문으로 둔다.

## MySQL 공통 결속 모델

기존 네 수집 원장을 유지한다.

- `public_data_ingestion_runs`: 수집 실행과 실패·재시도
- `public_data_raw_snapshots`: 원본 위치·hash·판본·관측시각
- `public_data_normalized_records`: 지역·기간·지표별 멱등 관측
- `public_data_region_mappings`: 외부 지역 코드와 안정 지역 식별자 결속

다중 규모 조회에는 다음 읽기 투영을 후보로 둔다. 구현 전 기존 모델로 충족 가능한지 다시 확인하며, 필요 없으면 새 테이블을 만들지 않는다.

- `공공공간NodeProjection`: 국가·항만·시장·위판장·창고·역·건물 등 위치가 확인된 거점
- `공공흐름ObservationProjection`: 출발·도착·기간·품목·수량·금액과 실제/집계/상징 구분
- `공공시계열ObservationProjection`: 지역·거점·지표·단위·관측시각별 값
- `공공자료CoverageProjection`: 확대 수준별 사용 가능·부분 가능·결손·제한·역사 자료 상태

모든 흐름은 최소한 다음을 가진다.

```text
FlowStableId
SourceNodeStableId / TargetNodeStableId
SourceRegionStableId / TargetRegionStableId
CommodityCode / Unit / Value
ObservedFrom / ObservedTo / FetchedAt
EvidenceLevel = Aggregate | NodeLinked | PortCall | Tracked
SourceId / DatasetId / Revision / RawHash
Quality / Limitation / Distribution
```

## 확대·축소 시 관찰 규칙

```text
지구본
  └─ 국가별 흐름·통계·환경
       └─ 한반도
            ├─ 항만·공항·광역 물류 거점
            ├─ 수산 위판·창고·시장 흐름
            └─ 대한민국 행정 권역
                 └─ 행정동 생활 관찰
                      └─ 사가정·면목제3·8동 상세 디오라마
```

- 축소 화면은 원본 객체를 전부 그리지 않고 서버가 만든 집계·LOD 상태 사본을 사용한다.
- 확대하면 집계값을 개별 객체로 분해하는 것이 아니라, 해당 정밀도의 별도 근거 자료로 교체한다.
- 확대 전후 수치가 다르면 기준일·포함 범위·결손을 표시한다.
- 세계 흐름, 한반도 거점, 행정동 생활, 건물 운영 overlay는 독립적으로 켜고 끈다.
- 화면에 움직임이 있어도 실제 관측, 집계 재생, 가상 Simulation을 색·범례·시간 표시로 구분한다.

## 병렬 첫 수집 묶음

첫 수집을 상향식 하나에만 묶지 않고 두 개의 독립 수직 슬라이스로 준비한다.

### L1 — 지역 생활 기반

- 행정표준코드 법정동
- 건축HUB 건축물대장
- 범위: 면목동과 면목제3·8동 결속
- 결과: 건물·주소·행정 귀속의 MySQL 저장·독립 재조회

### G1 — 지구본 물자 흐름 기반

- 관세청 품목별 국가별 수출입실적
- 범위: 대한민국과 주요 교역국의 한 기준 기간·소수 품목
- 결과: 국가 간 `Aggregate` 흐름의 MySQL 저장·독립 재조회와 지구본 읽기 투영 계약 후보

L1과 G1은 선후행 종속 관계가 아니다. 같은 수집 원장·출처 계보·검증 방식은 공유하지만, G1 값을 면목동 건물로 내리거나 L1 건물 합계를 국가 무역값으로 승격하지 않는다.

## 검증 관문

- 같은 원본을 재실행해 raw hash와 정규화 key가 중복되지 않는다.
- 상향 집계와 하향 통계의 차이를 누락 없이 진단하고 자동 보정하지 않는다.
- 실제 위치가 없는 흐름은 `Aggregate`, 양쪽 거점이 확인되면 `NodeLinked`, 입출항 근거는 `PortCall`, 항적은 `Tracked`로만 승격한다.
- 지구본에서는 집계 흐름만 보이고 건물·상세 주소는 적재되지 않는다.
- 행정동에서는 검증된 지역·시설 자료만 보이고 국가 집계가 개별 생활 사실처럼 보이지 않는다.
- 동일한 source revision과 projection hash로 서버 재조회와 Unity 읽기 결과가 일치한다.
- 자료층을 끄면 렌더·메모리·Simulation 판단에서 제거되고 운영 상태는 바뀌지 않는다.

## 제외

- 통계 흐름을 실제 선박·차량·사람 이동으로 위장하는 것
- 출발·도착 근거 없는 국내 물류 경로 생성
- 국가 통계를 행정동·건물에 비례 배분해 현실 값처럼 표시
- 건물·점포 자료를 북한 또는 해외 지역에 복제
- 이번 r6에서 실제 API 호출·MySQL 적재·Unity 흐름 애니메이션 구현

## 다음 결정

첫 하향식 수직 슬라이스 `G1`을 관세청 국가별 수출입의 소수 품목·한 기준 기간으로 고정할지 결정한다. 추천은 L1 지역 생활 기반과 G1 국가 간 집계 흐름을 각각 독립 실행한 뒤, 한 화면에 같이 표시하기 전에 출처·시간·공간 정밀도 차이를 먼저 검증하는 것이다.
