# [기획 · 월드·공간·관찰 · 확대 기반 공간 자료 적재 · 확정 r27]

## 결정

사용자가 지구본과 공간을 확대·축소·이동할 때 **현재 관찰 수준과 화면 범위에 필요한 정보만 적재**한다. 모든 지형·거점·건물·NPC·업무 자료를 처음부터 한꺼번에 내려받거나 Scene에 유지하지 않는다.

```text
카메라 이동·확대
  → 안정된 관찰 문맥 계산
    → 필요한 자료층과 tile 판정
      → 캐시 확인
        → 없는 상태 사본만 요청
          → revision·hash·범위 검증
            → 기존 표현과 교차 전환
              → 화면 밖·상위 정밀도 객체 회수
```

확대는 정보 요청의 조건이지 업무 명령이 아니다. 자료 적재 성공·실패·취소는 NPC, 주문, 운송, Simulation과 운영 원장의 상태를 변경하지 않는다.

## 주요 하천 표시 확정

한반도 `Z2 PeninsulaTerrain`에서는 광역 형태를 읽는 데 필요한 주요 하천만 기본 표시한다.

- 한강
- 대동강
- 압록강
- 두만강

실제 HydroRIVERS 절단 결과와 출처 검토에서 식별이 확정된 선만 표시한다. 이름 결속이 불명확한 선은 이름 없는 수계 표현 또는 `ResearchPending`으로 남긴다. 낙동강·금강·영산강 등 남측 주요 수계와 지역 하천은 Z2 화면 혼잡도 검토 후 선택 자료층으로 추가하거나 Z3 이하에서 연다.

## 관찰 문맥

한 번의 자료 요청은 다음 문맥으로 식별한다.

```text
SpatialObservationContext
├─ FocusSpatialStableId
├─ ObservationLevelCode
├─ ViewBounds
├─ CameraScaleBucket
├─ ActiveLayerIds[]
├─ RequestedAt
├─ ClientKnownRevisions[]
├─ ClientKnownHashes[]
└─ RequestGeneration
```

- 연속 휠·핀치 중에는 매 프레임 요청하지 않는다. 짧은 안정 구간 뒤 최종 문맥만 요청한다.
- `RequestGeneration`이 오래된 응답은 수신되더라도 화면에 적용하지 않는다.
- 동일 공간·수준·자료층·revision·hash가 캐시에 있으면 다시 내려받지 않는다.
- 카메라 거리는 직접 계약값으로 저장하지 않고 `CameraScaleBucket`과 관찰 수준 판정의 입력으로만 사용한다.

## 요청 단위와 수명

| 요청 단위 | 예시 | 수명 |
| --- | --- | --- |
| 광역 정적 tile | 표고, 해안, 주요 하천 | 긴 캐시, source hash 변경 시 무효화 |
| 지역 정적 tile | 행정 경계, 도로, 건물 윤곽 | 지역·판본별 캐시 |
| 거점·관계 상태 사본 | 도시, 역, 항만, 교류축 | revision 기반 갱신 |
| 동적 관찰 상태 사본 | NPC, 차량, 주문, 운송 작업 | 짧은 TTL, 화면 범위에서만 갱신 |
| 상세 카드 | 선택 객체의 근거·관계·현재 상태 | 선택 시 지연 적재 가능 |

정적 공간 자료와 동적 운영 자료를 하나의 응답 실패 단위로 묶지 않는다. NPC 상태 조회가 실패해도 마지막 검증 지형은 유지하고, 지형 tile 하나가 실패해도 다른 지역의 운영 상태를 되감지 않는다.

## 확대 단계별 적재

```text
Z0 지구
  load: 국가 경계·국가 표식

Z1 동아시아
  keep: 지구 저해상 배경
  load: 동아시아 해안·광역 지형·지역 표식

Z2 한반도
  unload: 세계 국가 세부 표식
  load: SRTM 단순 높이 tile·해안·4개 주요 하천·저지대 후보

Z2.5 거점
  keep: Z2 지형
  load: 부산·서울·도라산·개성·평양·신의주와 교류축

Z3 지역
  simplify: 한반도 전체 지형
  load: 선택 지역 경계·교통·거점 관계

Z4 동네
  unload: 화면 밖 지역 상세
  load: 행정동·역세권 도로·건물·시설

Z5 디오라마
  keep: 상위 공간 저정밀 배경 또는 breadcrumb
  load: 승인된 배치 객체·NPC·차량·업무 상태 사본
```

상위 수준은 복귀 문맥과 저정밀 배경에 필요한 만큼만 남긴다. Z5에 들어갔다고 지구 전체 자료가 메모리에 남아 있어서는 안 된다.

## 캐시와 회수

- 캐시 키는 `공간 ID + 관찰 수준 + 자료층 ID + schema + revision/hash`다.
- 정적 tile은 용량 제한이 있는 디스크 캐시 후보가 될 수 있지만, license·배포 범위를 manifest로 검증한 자료만 허용한다.
- NPC·운영 상태·토큰·원문 응답은 메모리 캐시만 사용하고 Save·Replay·PlayerPrefs·로그에 저장하지 않는다.
- 인접 tile 한 겹은 사용자의 진행 방향이 안정된 뒤에만 사전 적재한다. 빠른 카메라 이동 중 무분별한 사전 적재를 하지 않는다.
- 메모리 압박 시 화면 밖의 가장 상세한 표현부터 회수하고, 상위 breadcrumb와 선택 문맥을 우선 보존한다.
- 축소 시 선택 객체가 더 이상 현재 수준에서 유효하지 않으면 상세 카드를 닫되 상위 집계·거점 선택으로 안전하게 복귀한다.

## 준비 상태와 실패 표현

```text
Unknown
Declared
Loading
Ready
Partial
Stale
Unavailable
Restricted
Failed
```

- `Ready`가 아닌 자료를 추정 객체로 채우지 않는다.
- `Partial`은 확보된 부분과 결손을 함께 표시한다.
- `Stale`은 마지막 성공 자료의 기준 시각을 보여 주고 최신값처럼 표현하지 않는다.
- `Restricted`는 권한·license·공개 범위 때문에 열 수 없는 이유를 표시한다.
- 일시 실패는 마지막 정상 정적 지형을 유지할 수 있지만, TTL이 지난 동적 상태는 흐리거나 제거한다.
- 하위 수준이 준비되지 않았으면 카메라 확대는 가능하더라도 상세 진입을 멈추고 `상세 자료 준비 안 됨`을 표시한다.

## 선택과 상세 카드 적재

- 화면 표식의 최소 요약 정보는 공간 상태 사본에 포함한다.
- 상세 근거·연표·관계가 큰 객체는 선택 시 `DetailCardRef`로 지연 적재한다.
- 선택이 바뀌면 이전 상세 요청을 취소하거나 결과 적용을 무시한다.
- 같은 객체를 다른 확대 수준에서 다시 선택하면 동일 `ObjectStableId`로 카드 문맥을 복원한다.
- 카드에서 하위 공간을 여는 동작은 해당 공간의 `MaximumObservationLevel`과 `Readiness`를 다시 확인한다.

## 서버와 Unity 책임

서버·자료 도구는 공간·tile·객체 식별자, 포함 관계, 좌표 변환, 단순화 판본, 계보, revision·hash, 공개 가능한 비식별 상태 사본과 결손·TTL을 책임진다.

Unity는 카메라와 선택에서 관찰 문맥을 계산하고, 상태 사본 요청·검증, LOD·가시성·교차 전환·선택 강조·상세 카드, 오래된 응답 거절만 책임진다. 서버 자료가 없다는 이유로 거점·건물·NPC를 임의 생성하지 않는다.

## 첫 개발 인계 조건

```text
지구본 대한민국 선택
→ Z2 한반도 지형 요청
→ SRTM·해안·4개 주요 하천 표시
→ Z2.5 확대
→ 6개 거점 지연 적재
→ 서울 선택·상세 카드
→ 축소
→ 카드·거점 회수와 지구본 문맥 복귀
```

검증은 같은 요청의 멱등 결과, 오래된 응답 거절, 빠른 확대·축소 중 요청 취소, 부분 자료층 실패, 캐시 재사용, 화면 밖 객체 회수와 운영 권위 불변을 포함한다.

## 확정

- 확대·이동에 따라 현재 사용자가 볼 자료만 적재한다.
- Z2 기본 하천은 한강·대동강·압록강·두만강으로 제한한다.
- 정적 공간 자료와 동적 운영 자료는 cache·TTL·실패 경계를 분리한다.
- 선택 객체의 큰 상세 정보는 카드 열기 시 지연 적재할 수 있다.
- 보이지 않는 자료층은 로딩·렌더·NPC·Simulation 판단에 영향을 주지 않는다.

## 미정

- 카메라 안정 대기 시간과 수준별 사전 적재 반경.
- Z2 height tile 해상도와 메모리 예산.
- 디스크 캐시 최대 용량과 삭제 정책.
- 남측 추가 주요 하천을 Z2 선택층으로 열지 Z3에서만 열지.

## 다음 질문 하나

빠르게 확대·축소할 때는 **약 0.3초 동안 카메라가 안정된 뒤 최종 수준만 요청**하는 방식으로 할까? 불필요한 서버·디스크 요청을 줄이면서 조작 반응은 즉시 보이게 할 수 있어 이를 추천한다.
