# [기획 · 월드·데이터·관찰 · PLAN-SYSTEM-KOREAN-PENINSULA-PUBLIC-DATA-WORLD · 구현 r12]

## 목적

HS 코드 전수조사를 일회성 검색 목록이 아니라 중단·재개 가능한 비공개 자료 대장으로 시작한다. 공식 코드, 무역 관찰, 소매 채널 적합성, 대표 상품 후보와 개별 상품의 실제 HS 판정을 서로 다른 사실로 보존한다.

## 공식 모집단

- WCO HS 2022의 법정 6단위 소호는 `5,612개`다.
- UN Comtrade `H6.json`의 6단위 leaf는 `5,613개`이며 `999999`는 법정 상품 코드가 아니라 `품목 종류 미상` 통계 특수행이다.
- 관세청 2026 HS 부호 총대장은 `12,469개` 계층 행을 제공하며, 이 가운데 말단 10단위 HSK는 `11,327개`다(`7단위 52 / 8단위 918 / 9단위 172 / 10단위 11,327`). 국내 특수 `2424000000` 이사화물은 WCO 법정 HS6와 분리해야 한다.
- 관세청 성질별 분류는 소매 조사 우선순위를 정하는 보조자료일 뿐, `소비재`를 곧바로 쿠팡 판매 적합으로 해석하지 않는다.

## 구현

`trade-retail-census-*` 실행기를 추가해 UN H6 원본 전체를 내려받고 다음 두 자료를 기존 공공자료 원장에 저장한다.

1. 공식 분류 대장 `5,613행`
   - 법정 HS6 `5,612행`: `OfficialReference`
   - UN 통계 특수 `999999` `1행`: `StatisticalSpecialCode`
2. 소매 조사 대기열 `5,613행`
   - 각 법정 HS6마다 정확히 한 개의 현재 조사 상태
   - 대표 상품 후보가 없어도 `미조사`, `검색 결과 없음`, `소매 부적합`, `검색 차단`을 정식 결과로 남길 수 있는 상태 계약
   - `999999`는 `NotApplicable`로 분리

원본 hash, 정책 hash와 수집 시각을 보존하고 400행씩 MySQL에 upsert한다. 같은 입력은 같은 `RecordKey`로 중복 저장되지 않는다. 현재는 단일 작업자용 비공개 전수 대장이며 다중 작업자 임대·재시도 전용 테이블은 후속 확장이다.

## 이번 실제 수집

세 번째 반복 배치 `whole-spices-01`에 다음 4개 법정 HS6와 대표 상품 후보 한 건씩을 추가했다.

| HS6 | 관찰 품목 | 2025년 대한민국 수입 세계 합계(USD) | 대표 상품 결속 |
| --- | --- | ---: | --- |
| `090411` | 부수거나 갈지 않은 후추 | 52,470,010 | 검토 보류 |
| `090421` | 부수거나 갈지 않은 건조 고추류 | 11,354,255 | 검토 보류 |
| `090611` | 부수거나 갈지 않은 실론계피 | 3,412,054 | 검토 보류 |
| `090931` | 부수거나 갈지 않은 커민 씨 | 1,603,107 | 검토 보류 |

UN Comtrade 원본 `85행`에서 무역 `48행`, HS 분류 `4행`, 소매 카테고리 후보 `4행`, 쿠팡 공개 색인 상품 관찰 `4행` 등 `60행`을 만들었다. 쿠팡 직접 검색은 `403`으로 거절되어 우회하지 않았고, 공개 검색 색인에서 확인된 상세 URL·제목·시점 가격·배송·원산지 주장만 `PendingHumanReview`, `affiliate=false`, `distributionApproved=false`로 저장했다.

## 저장·검증 결과

- 대상: 로컬 Docker MySQL `hongdal-mysql-1 / hongdal_dev`
- 전수 대장: `11,226행` 저장·독립 재조회
  - 공식 분류 `5,613행`
  - 조사 대기열 `5,613행`
  - 법정 HS6 후보 관찰 `12개`, 대기 `5,600개`, 통계 특수 `1개`
- `whole-spices-01`: `60행` 저장·독립 재조회
- 같은 전수 대장 재실행: 신규 `0`, 수정 `0`, 기존 `11,226`
- 같은 상품 배치 재실행: 신규 `0`, 기존 `60`
- 실행기 build: 경고 `0`, 오류 `0`
- 전수 대장 자체시험 `10개`, 상품 배치 자체시험 `12개` 통과

첫 교정 실행에서는 이전에 법정 코드처럼 취급했던 `999999` 두 행과 새로 관찰된 4개 HS6 조사 상태를 포함해 `6행`이 갱신됐다. 바로 이어진 동일 입력 재실행은 수정 `0행`이었다.

## 완료와 미완료 경계

이번 단계는 **전수조사 모집단과 진행 대장을 모두 저장한 것**이지 대표 상품 조사를 끝낸 것이 아니다. 현재 반복 배치 기준 진행률은 `12 / 5,612`이며, 남은 `5,600개`는 다음 배치에서 계속 판정한다.

다음 구현은 관세청 HS 계층 총대장 `12,469행`과 말단 HSK10 `11,327행`의 성질별 보조 분류를 별도 계보로 반입한 뒤, 법정 HS6별로 `소비재 후보 / 혼합 용도 / 산업재 / 제한·민감 / 채널 부적합`을 먼저 나누는 것이다. 그 뒤 쿠팡 관찰은 소매 후보를 우선해 코드당 `0~3개`를 기록한다. 모든 코드에 억지 상품을 붙이지 않는다.

읽기 API, Unity 투영·Game View, 외부 게시, 개별 상품의 법적 HS 확정, 쿠팡 숫자 카테고리 코드 확인, commit·push는 수행하지 않았다.
