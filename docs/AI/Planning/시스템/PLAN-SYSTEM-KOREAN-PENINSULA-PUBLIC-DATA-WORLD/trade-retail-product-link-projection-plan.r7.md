# 무역 품목·소매 카테고리·대표 상품 연결 계획 r7

- 상위 기획: `PLAN-SYSTEM-KOREAN-PENINSULA-PUBLIC-DATA-WORLD`
- 상태: `Proposed / MarketplaceBoundaryReviewed / CollectionNotStarted`
- 목적: 국가 간 품목 흐름을 사용자가 이해할 수 있는 소매 카테고리·대표 상품 후보와 연결하고 Unity에서 출처와 한계를 보존한 채 조회한다.
- 핵심 경계: 관세 품목, 소매 카테고리, 개별 판매 상품은 서로 다른 사실이다. 자동 동일시하지 않고 검토 가능한 다대다 연결을 둔다.

## 사용자가 보는 흐름

```text
지구본에서 대한민국 수입 흐름 선택
  → 교역국·기준 기간·관세 품목 집계
  → 이해하기 쉬운 소매 카테고리 후보
  → 검토된 대표 상품 관찰 카드 1~3개
  → 확인 시 외부 쇼핑몰로 이동
```

Unity는 상품 구매처가 아니라 공공 통계와 시장 관찰을 연결하는 읽기 전용 탐색 도구다. 구매·장바구니·결제·주문 연동은 이번 범위에 포함하지 않는다.

## 세 원장의 분리

### 1. 관세 품목 원장

- HS 판본, 품목 코드·명칭, 수출입 구분
- 상대 국가, 기준 기간, 금액·중량·단위
- 관세청 자료 출처, 가져온 시각, 원본 hash
- 자료의 공간·시간 정밀도와 정정 여부

### 2. 소매 카테고리 연결 후보

- `HsCommodityStableId`
- `RetailCategoryStableId`
- 플랫폼 독립 표시명과 검색어 후보
- `Pending / Verified / Rejected / Revoked`
- 연결 근거, 검토자·검토시각, 판본
- `Exact / Broad / Ingredient / ProcessedDerived` 연결 유형

HS 품목 하나는 여러 소매 카테고리에 연결될 수 있고, 가공식품 하나는 여러 원재료 품목과 관련될 수 있다. 원재료 비율·원산지 근거가 없으면 가공식품의 수입 흐름을 특정 국가와 동일시하지 않는다.

### 3. 대표 상품 관찰

- 플랫폼, 플랫폼 상품 ID 또는 외부 URL
- 관찰 당시 상품명·브랜드·판매처
- 소매 카테고리와 연결 상태
- 표시 가격·통화·관찰시각·가격 포함 조건
- 원산지·제조사·성분 근거와 확인 상태
- 링크 확인시각, 만료·삭제·품절 상태
- 광고·제휴 여부와 고지 문구
- 이미지 사용 권리와 Unity 배포 가능 여부

상품 링크와 가격은 현재 판매·최저가·재고의 정본이 아니다. 링크가 사라지거나 상품 정보가 바뀌면 과거 관찰은 보존하되 현재 링크는 `Stale / Unavailable`로 바꾼다.

## 플랫폼별 경계

### 네이버

기존 NAVER Developers 쇼핑 검색 API는 2026-07-31 종료됐으므로 신규 자동 수집 기반으로 사용하지 않는다. 후속 공식 상거래·제휴 인터페이스가 확인되기 전에는 사람이 검토한 외부 링크와 검색어만 제한적으로 등록하며 가격 자동 갱신을 하지 않는다.

### 쿠팡

일반 Coupang Open API는 판매자·통합 사업자의 등록 상품, 주문, 물류, 반품 관리가 중심이므로 전체 소비자 상품 검색 API로 간주하지 않는다. 쿠팡 파트너스 기능은 별도 가입·승인·표시 의무·링크 정책을 확인한 뒤 `Affiliate` 출처로만 연결한다. 제휴가 없으면 공개 페이지를 자동 수집하지 않고 사람이 확인한 일반 외부 링크만 후보로 둔다.

### 공통

- HTML 화면 구조를 긁는 scraper를 기본 수집기로 만들지 않는다.
- 인증키·partner ID·추적 parameter는 서버 secret/config 경계에서만 관리한다.
- 제휴 링크는 `광고` 또는 `제휴`를 명확히 표시한다.
- 외부 URL은 허용 도메인·HTTPS·최종 redirect를 서버에서 검증한다.
- Unity에서 외부몰 이동 전 플랫폼명과 외부 이동 사실을 확인시킨다.

## MySQL 후보 구조

기존 공공데이터 수집 원장과 분리하되 같은 출처 계보 규칙을 사용한다.

```text
customs_commodity_observations
  └─ trade_retail_category_bindings
       └─ representative_product_observations
            └─ external_product_link_checks
```

실제 구현 전에 기존 범용 `public_data_normalized_records`와 상품·카테고리 원장 재사용 가능성을 먼저 확인한다. 위 이름은 책임 경계를 설명하는 후보이며 자동으로 새 테이블 생성을 승인하지 않는다.

### `trade_retail_category_bindings`

- 무역 품목과 소매 카테고리의 다대다 연결
- 상태·연결 유형·근거·판본
- 검색어는 결과를 찾기 위한 보조값이며 사실 식별자가 아니다.

### `representative_product_observations`

- 특정 시점에 관찰한 상품 후보
- 플랫폼 상품 ID·URL·상품명·가격·통화
- 원산지·브랜드·제조사 확인 상태
- `distributionApproved`, `affiliateDisclosureRequired`

### `external_product_link_checks`

- 확인 시각, HTTP 상태, 최종 허용 URL
- 품절·삭제·redirect 변경·정책 제한
- 상품 페이지 본문 전체를 저장하지 않고 검증에 필요한 최소 메타데이터만 보존

## Unity 읽기 계약 후보

```text
GET api/v1/world/trade-flows/{flowStableId}
GET api/v1/world/trade-flows/{flowStableId}/retail-categories
GET api/v1/world/retail-categories/{categoryStableId}/representative-products
```

응답은 다음을 분리한다.

- `tradeEvidence`: 교역국·품목·기간·금액·중량·통계 출처
- `categoryBinding`: HS와 소매 카테고리의 연결 상태·유형·근거
- `productObservation`: 상품명·플랫폼·관찰시각·링크 상태
- `commerceDisclosure`: 외부 이동·제휴·가격 유효성·구매 비보증

Unity 카드에는 `무역 통계`, `카테고리 연결`, `상품 관찰`의 세 판독 단계를 표시한다. 상품이 같은 카테고리에 있다는 이유만으로 해당 교역국에서 수입됐다고 표시하지 않는다.

## 첫 대표 품목 후보

첫 조사는 소비자가 이해하기 쉽고 원재료·소매 상품의 관계를 비교하기 쉬운 세 묶음으로 제한한다.

1. 커피류: 원두·생두·볶은 커피의 품목 차이와 소매 원두 상품
2. 바나나류: 신선 과일 무역 품목과 소매 신선식품
3. 냉동 새우류: 수산 품목의 가공·냉동 상태와 소매 냉동식품

정확한 HS 세번, 최근 확정 기간, 주요 상대국은 관세청 응답과 현행 품목표로 다시 확인한다. 상품 후보는 품목당 플랫폼별 최대 1~2개만 사람이 검토하며 인기·추천·최저가를 주장하지 않는다.

## 첫 검증 시나리오

1. 관세청에서 기준 기간·품목·상대국별 집계를 수집해 MySQL에 적재한다.
2. 품목 코드와 소매 카테고리 후보를 생성하되 `Pending`으로 둔다.
3. 검토자가 카테고리 연결을 승인한다.
4. 허용된 방식으로 대표 상품 링크를 1~2개 등록한다.
5. 링크·가격·원산지·제휴 여부를 관찰시각과 함께 저장한다.
6. Unity 지구본에서 무역 흐름을 선택해 통계 → 카테고리 → 상품 카드를 조회한다.
7. 외부 링크를 열기 전 고지하고, 닫은 뒤 Unity 선택 상태를 보존한다.
8. 링크 만료·상품 변경·가격 누락 시 통계 흐름은 유지하고 상품 카드만 `Unavailable/Stale`로 내린다.

## 완료 조건

- HS 품목과 소매 카테고리가 다대다·판본화된 상태로 분리된다.
- 개별 상품이 특정 수입국·통계값의 직접 구성품이라고 잘못 표시되지 않는다.
- 가격·재고·원산지·링크의 관찰시각과 확인 상태가 각각 보인다.
- 제휴 링크는 광고·제휴 고지가 있고 일반 링크와 구분된다.
- 링크가 없어도 무역 통계와 카테고리 조회가 계속 동작한다.
- Unity는 상품 검색·가격 수집·결제를 직접 수행하지 않고 서버의 승인된 읽기 결과만 사용한다.
- 동일 관세 원본과 동일 상품 관찰 입력을 재실행해 중복되지 않는다.
- 허용되지 않은 도메인·HTTP·의심스러운 redirect는 거절한다.

## 제외

- 쇼핑몰 HTML 무단 대량 수집
- 판매 순위·추천 순위·최저가의 근거 없는 생성
- 상품 링크만으로 제조국·원산지·수입국 확정
- Unity 내 구매·결제·주문·수수료 정산
- 제휴 승인 전 affiliate parameter 생성
- 상품 이미지의 권리 확인 없는 다운로드·Unity 포함
- 이번 r7에서 실제 관세·상품 수집, MySQL migration, API·Unity 구현

## 다음 결정

첫 상품 연결은 자동 검색 없이 `커피류·바나나류·냉동 새우류`의 사람이 검토한 일반 링크로 시작할지 결정한다. 추천은 가격 자동 갱신과 제휴 링크를 뒤로 미루고, 품목당 1~2개 외부 링크의 연결·만료·잘못된 원산지 표시 방지부터 검증하는 것이다.
