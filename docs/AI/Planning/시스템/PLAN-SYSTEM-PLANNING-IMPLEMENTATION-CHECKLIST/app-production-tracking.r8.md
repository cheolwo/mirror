## 범위

전체 기획 문서 목록과 등록 원문의 판본·대체 관계를 조회한다. 역할 앱 상세는 주문자·음식점·기사·운영자부터 시작한다. 메뉴 등록·조리시간·결제 승인 연결을 첫 대조 사례로 삼고 기존 문서/코드/시험/화면/APK를 참조한다. 전체 기획의 의미 충족·코드 전수 재판정은 이번 목록화와 다르다.

기존 Markdown이 의미·승인 정본이다. 관계 자료에는 기획·업무 항목·역할·제품 코드·시험 코드·작업지시서·실행 증거의 참조만 연결한다. 별도 운영 DB/API/서버와 새 WI는 만들지 않는다. 기존 검색 도구와 나란히 JSON·Markdown·외부 통신 없는 읽기 전용 HTML을 생성한다. 생성물 직접 편집은 금지한다.

## 제작 절차

자료 접수 → 기존 기획/코드/증거 대조 → 업무 하나와 영향 역할·화면·실패 경로 검토 → 명시 승인·판본/hash·쓰기 경로 고정 → 기존 앱/API 구현 → 시험·실제 화면·테스트 APK → 결과를 같은 기획/업무에 연결 → 사용자 검토.

이 도구의 목록/추천/내보내기는 개발 자동 실행이나 승인 생성이 아니다. 기록으로 코드 존재, 시험 소스 존재, 실제 시험 실행, HTTP/DB, UI, APK, 장치 설치, 배포를 구분한다. 앱 제작의 기본 결과물은 실제 화면·시험·테스트 APK이나 이번 관리 도구 작업 자체가 네 앱을 다시 빌드하거나 테스트 APK를 이미 만들었다는 뜻은 아니다.

## 현재성·안전

- 관련 입력의 hash·실행 환경·범위·결과·기준 commit/로컬 변경·산출물을 결속한다. 과거 증거에 없던 기준선을 현재 파일로 소급 생성하지 않는다.
- 결과(Passed/Failed 등)와 현재성(Current/Stale/Unknown/Missing)을 분리한다. 관련 코드/기획 변화는 재검증 대상으로 드러낸다. 근거 없음과 미실행 선언, 해당 없음을 구분한다.
- 파일명/최대 revision만으로 최신 기획을 결정하지 않는다. 원문의 상태/목차 관계와 원문 링크를 보여준다. 불명확한 관계는 검토 대상으로 둔다.
- 경로는 저장소 안으로 제한한다. 외부 링크/원시 HTML/스크립트는 상태판에 실행하지 않는다. 내보내기는 안전한 요약·명시 기획 참조만 포함하고 raw 로그·DB·계정·키·연락처를 자동 복사하지 않는다.
- 운영 설정·DDL·실결제·환불·지급·실기기·배포·commit/push는 제외한다.
