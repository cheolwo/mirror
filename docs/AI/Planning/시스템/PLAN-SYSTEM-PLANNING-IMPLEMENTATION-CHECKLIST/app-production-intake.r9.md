## 확정

기존 기획과 코드를 AI가 먼저 읽고 입력 초안을 채운다. 사용자는 실제 제품 선택이 남은 항목만 검토한다. 제품 기획 정본은 개별 PLAN이고 입력표는 그 판본과 출처를 연결하는 제작용 요약이다.

1. 앱 공통 프로필은 대상 앱·프로젝트·플랫폼·탐색·표현·인증·서버·시험 환경을 보관한다. 대상 앱과 영향받는 역할을 구별한다.
2. 작업별 입력은 목적/범위, 정보/권한/비식별 표본, 시작/행동/서버/재조회/종료, 화면 상태, 실패/회복, 결과물의 여섯 묶음이다. 기존 확인·제안·미정·사유 있는 해당 없음과 출처/판본/hash를 기록한다.
3. 입력 준비, 사람 검토, 기존 작업지시서 승인, 환경 준비, 실제 실행 증거는 독립 상태다. 입력 확인은 개발 승인이나 출시 완료가 아니다. 중요 미정·출처 누락·충돌은 인계 차단으로 드러내고 환경 결손은 관련 결과물만 막는다.
4. 기존 대장에 프로필·입력표·검토 기록 참조를 선택적으로 추가한다. 미연결 과거 업무는 미검토이며 미구현으로 판정하지 않는다. 참조 및 그 출처가 바뀌면 관련 증거의 현재성을 다시 확인한다.
5. 읽기 전용 현황표와 안전한 인계 내보내기에 대상·입력 상태·질문·환경 차단을 표시한다. 비밀값·원문 로그·임의 JSON을 자동 첨부하지 않는다.
6. 기존 Android 포장 도구에 대상 앱 선택을 추가한다. 생략 시 기존 네 앱 모두를 유지하고 HTTPS·서명 경계는 유지한다. 이번 작업에서는 계획 출력만 시험하며 APK를 생성하지 않는다.
7. 첫 예제는 기존 음식점 메뉴 등록/수정이다. 정상, 응답 유실 후 중복 요청, revision 충돌, 저장 성공/재조회 실패, 다른 가게 수정 금지의 검증 요구를 연결한다. 새 음식 업무를 구현하거나 미실행 사례를 통과로 바꾸지 않는다.

## 절차와 검증 상한

기획/코드 근거 → AI 입력 초안 → 누락·충돌 점검 → 사람 검토 → 기존 승인/작업지시서 수용 → 구현·시험 → 결과 반환.

향후 개별 앱 제작의 기본 결과물은 업무 검증·화면 근거·Android 시험 APK이다. 정적 시안, 공용 Razor 모의 미리보기, API 연결 UI, Android UI, APK, 설치, 배포는 별도 증거다. 이번 관리 도구의 완료는 앱이나 장치 실행 완료가 아니다.

누락·잘못된 참조·hash 변화·검토와 승인 분리·환경 차단·과거 형식 호환·선택 APK 계획을 자동 시험한다. 생성물을 재생성/검사하고 실제 브라우저는 가용할 때만 검증한다. 사용할 수 없으면 미검증 사유를 남긴다.

## 미정 및 제외

음식점 예제는 AI 초안이며 새 앱 제작의 사람 검토·실행 승인·환경 확정은 아직 없다. 이 보완안 승인을 예제 업무 승인으로 전용하지 않는다. 비밀값은 입력하지 않고 준비 여부만 기록한다.

제품 앱·서버 업무 코드, 운영 DB, 실결제, 알림 외부 효과, Unity, 실제 APK 포장·설치·게시, commit·push는 제외한다. 새 Goal·증거 성숙도 승격도 수행하지 않는다.
