# 음식점 모바일 기본 탐색 r4

- 2026-09-27, 사용자 승인한 r3 후속의 첫 UI 범위 구현.
- 주문은 `/`·`/orders` 기본 진입이며 이전 운영 홈은 `/store` 가게 관리로 옮긴다. 로그인 후 주문 진입은 기존 그대로다.
- 인증된 제품 화면 하단에 주문/메뉴/가게를 제공한다. 기존 서랍·상세 경로는 보존하고 `/store`를 Release 허용 경로에 추가한다.
- 메뉴 목록과 입력은 같은 `/menus` 컴포넌트 안에서 별도 화면 상태로 분리했다. 추가·수정→저장→서버 재조회→목록 복귀이며 별도 URL은 아니다.
- 입력 중 내부 화면 이동을 막고 저장 또는 명시적 입력 취소를 안내한다. 등록 결과 미확인 시 입력 취소도 막아 기존 동일 요청 재시도 경계를 유지한다. 외부 이탈은 브라우저 확인을 요청한다.
- 가게 화면은 기존 메뉴·조리시간 설정 연결을 재사용한다. 영업 상태 변경·정산 내역은 아직 미연결임을 표시하고 가짜 금액·지급 완료를 만들지 않는다.

## 검증

- Android build 경고0·오류0(첫 실행). 최종 문구 변경 후 재빌드 결과는 CURRENT_WORK에 기록한다.
- 집중시험 29/29 통과: 화면 구성·정상 음식 생명주기·결제 승인 Outbox. 정산을 대체 구현으로 건너뛰는 기존 정상 시험 한계는 r3 그대로다.
- 실제 Razor 메서드 인메모리 검사 10개 통과: 추가 화면·저장 후 복귀·응답 유실 중 취소 차단 포함.
- 로컬 Headless Edge 390px에서 실제 버튼으로 목록→추가→이동 차단→등록→목록→수정→목록 확인, pageerror 0·가로 넘침 없음. 합성 메뉴·메모리 Client이며 실제 API/DB 저장·Android 터치 증거가 아니다.
- Task 전체 solution build 성공. 첫 전체시험 5403/5411 통과·8실패 중 Home 경로 가정 1건을 수정해 위 집중시험 재통과. 나머지 7건은 API metadata 4·WebApp capability 1·용어 문서 1·공식 재료 UI 1이며 이번 범위 밖이다. 최종 전체시험 재실행은 하지 않았다. 전체 통과를 주장하지 않는다.
