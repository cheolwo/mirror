# `SsalddelAdminApp` Android 첫 출시 완수선

## 확정

- 다음 제품 마감의 중심은 새 화면 수를 늘리는 일이 아니라 기존 `SsalddelAdminApp`을 실제 Android 배포물로 끝까지 닫는 일이다.
- 첫 출시 대상은 새 만능 앱이 아니라 현재 로그인·운영 개요·운송 관제·안전 재시도·읽기 전용 현금 흐름을 가진 `SsalddelAdminApp`이다.
- Unity·디오라마, 역할 앱 통합, 실결제·실정산·실배차 활성화는 이 첫 출시의 필수 범위가 아니다.
- 기능 하나는 `화면 존재`나 `build 성공`으로 끝내지 않고 `서버 정본 조회 → 허용 행동 → Command → 같은 원장 재조회 → 실패·재진입`까지 닫혀야 한다.
- 첫 외부 배포 단계는 본인과 지정된 소수 사용자만 설치하는 Google Play 내부 테스트를 권장한다. 공개 Production 출시는 내부·비공개 시험에서 운영 폐루프와 개인정보 고지를 검증한 뒤 별도 관문으로 둔다.

로컬에서 생성된 `*-Signed.aab` 이름만으로 Google Play 배포 서명을 증명하지 않는다. .NET Android는 전용 release keystore를 지정하지 않으면 개발용 서명을 사용할 수 있으므로, 전용 upload key와 비밀 주입을 별도 확인한다.

## 첫 출시 범위 동결

### 포함

1. 관리자 로그인, 세션 복원·갱신·로그아웃
2. 운영 개요와 마지막 성공 갱신 시각
3. 음식 배달 중심의 운송·배차 대기·예외 관찰
4. 서버가 허용한 `RetryIdempotent` 안전 재시도 예약과 정본 재조회
5. 오늘·최근 7일 현금 유입·유출·순변동 및 미수·지급의무 후보의 읽기 전용 조회
6. 통신 끊김, 인증 만료, 낮은 revision, 앱 종료·재진입의 회복

### 제외

- Unity·디오라마와 게임 화면
- 기사 임의 배정·호출·지시
- 실제 결제·송금·정산 지급
- 귀책·보험금·보상 자동 확정
- 모든 OS 화면을 첫 판에 완성하는 일
- 앱 안에서 새 운영 계정을 만드는 기능
- 공개 Production 출시와 불특정 다수 가입

현재 범위 밖 메뉴는 첫 릴리스에서 완료된 것으로 주장하지 않는다. 노출한다면 `준비 중` 또는 기능 플래그로 구분하고 핵심 폐루프의 완료 조건에 포함하지 않는다.

## 출시 작업 순서

### R0 — 소스 기준선 동결

- 현재 진행 중인 현금 흐름 절편을 별도 맥락으로 검증·커밋한다.
- 첫 출시가 소유하는 route, contract, 화면, 시험 목록을 고정한다.
- 기능 추가 요청은 보안·회복·출시 차단을 해결하는 경우가 아니면 다음 판본으로 보낸다.

### R1 — 출시 구성

- 표시 판본과 version code 정책을 정한다. 첫 후보는 `0.1.0`과 단조 증가 정수다.
- 실제 기기에서 읽을 수 있는 HTTPS 서버 주소를 환경별 설정으로 주입한다. 주소와 비밀은 소스에 고정하지 않는다.
- Release에서는 평문 HTTP를 닫고 필요한 네트워크 권한만 유지한다.
- 전용 upload keystore를 만들고 저장소 밖의 비밀 저장소에서 주입한다. keystore·암호를 commit하거나 로그에 출력하지 않는다.
- 동일 명령으로 AAB와 SHA-256, 판본, commit을 재생성하는 출시 영수증을 남긴다.

### R2 — 운영 폐루프 검증

- 격리된 HTTPS 서버와 관리자 시험 계정을 준비한다.
- `로그인 → 개요 → 예외 상세 → 안전 재시도 → 같은 원장 재조회 → 로그아웃`을 실제 Android 앱에서 수행한다.
- 현금 흐름은 읽기 전용으로 조회하고 전표·송금·잔액을 추정하거나 만들지 않는다.
- 네트워크 단절·복구, 토큰 만료·갱신, 백그라운드·복귀, 앱 강제 종료·재실행을 같은 표본으로 확인한다.
- 화면 성공과 서버 원장 revision을 함께 대조한다.

### R3 — 배포 준비

- Play Console 앱 항목, 내부 테스트 대상, 앱 설명·아이콘·스크린샷·연락처를 준비한다.
- Privacy policy와 Data safety 답변을 실제 앱의 수집·전송·보존과 맞춘다.
- 앱 내 계정 생성이 없고 관리자가 계정을 발급하는 첫 판의 경계를 명시한다. 향후 앱 내 가입을 열면 계정 삭제의 앱 내부 경로와 웹 요청 경로를 함께 마련한다.
- 내부 테스트 링크로 설치하고 업데이트·롤백·세션 유지 여부를 확인한다.

### R4 — 다음 단계 판단

- 본인 도그푸딩과 지정 사용자 피드백에서 치명·중대 오류가 없고 운영 폐루프가 반복되면 비공개 시험으로 넓힌다.
- Production 공개 여부는 실제 운영 효과, 법률·세무·보험, 개인정보, 고객지원, 모니터링과 장애 대응을 별도 승인한 뒤 결정한다.

## 완료 조건

다음이 모두 사실일 때만 첫 모바일 출시를 완료로 기록한다.

- 전용 upload key로 서명한 `0.1.x` AAB가 재현 가능하게 생성된다.
- Google Play 내부 테스트 트랙에서 실제 Android 기기에 설치·업데이트된다.
- 출시 HTTPS 서버에 로그인하고 핵심 운영 자료를 읽는다.
- 안전 재시도 한 건을 실행하고 같은 원장의 새 revision을 다시 읽는다.
- 통신 단절·세션 갱신·백그라운드 복귀·앱 재시작 뒤 잘못된 완료 상태를 만들지 않는다.
- 실제 화면에서 390px 세로 폭의 핵심 정보와 버튼이 잘리지 않는다.
- 앱과 서버 로그에 토큰·연락처·주소·원문 오류가 노출되지 않는다.
- Privacy policy·Data safety·지원 연락처·릴리스 노트가 실제 동작과 일치한다.
- 산출물 hash, commit, 서버 판본, 시험 계정 범위, 기기·OS, 결과를 출시 영수증으로 남긴다.

## 미정

- 첫 실제 배포 채널을 Google Play 내부 테스트로 확정할지, Play Console 이전에 전용 서명 APK로 본인 기기 설치를 한 차례 둘지
- 운영 서버의 첫 호스팅 주소와 인증서·장애 대응 소유자
- 관리자 시험 계정의 발급·회수 절차
- 첫 판에서 숨길 미완성 메뉴와 그대로 둘 읽기 전용 메뉴
