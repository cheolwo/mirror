# 사가정역 주거 가격 관찰층 제안

- 상태: `Proposed / PublicSourceReviewed / BuildingAddressCompletionRequired / FirstDisplayMeaningDeferred / CollectionNotApproved / ImplementationNotStarted`
- 요청 근거: 2026-09-14 사용자는 사가정역 디오라마의 도로명주소에 주택 매매·전세·월세 자료를 결속해 DB에 축적하고, 원하는 경우 디오라마에서 조회하는 방향을 제안했다.
- 상위 기획: [역세권 디오라마 모듈 표준 r16](../PLAN-SYSTEM-STATION-AREA-DIORAMA-MODULES/README.md), [행정동별 서버 기반 디오라마 r3](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/README.md)
- 필수 선행 기획: [사가정역 건물 도로명주소 완결 관문 r1](../PLAN-DATA-SAGAJEONG-BUILDING-ADDRESS-COMPLETION/README.md)
- 기존 근거: [사가정 건물 자료 연결 대장 r12](../PLAN-GAMEPLAY-NEIGHBORHOOD-DEFENSE/building-evidence.r12.md), [도로명주소 표현층 r15](../PLAN-GAMEPLAY-NEIGHBORHOOD-DEFENSE/road-address-presentation.r15.md)

## 결론

가능하다. 다만 이를 H1의 새 역할이나 건물의 단일 `현재 시세`로 만들지 않고, 주소·건물과 근거 수준을 가진 별도 **주거 가격 관찰층**으로 둔다.

```text
공식 주소·건물 식별 자료
  + 국토교통부 실거래 관측(매매·전세·월세)
  + 선택적 공시가격 관측
        ↓
RDB 원본·정규화·연결·집계
        ↓
배포 승인된 불변 지역 투영
        ↓
건물 선택 카드 / H2 블록 요약 / H3 생활 회랑 요약
```

H1·H2·H3는 가격의 의미를 정하지 않고 조회 범위만 제공한다. 건물이나 역할 Profile을 클릭했을 때 해당 건물에 확실히 결속된 관측을 보여 주고, 결속이 불확실하거나 표본이 적으면 H2 또는 H3 집계로 낮춘다.

## 공식 자료 조사 결과

### 1. 실거래 자료

국토교통부 실거래가 공개시스템은 아파트·연립/다세대·단독/다가구·오피스텔 등에 대해 매매와 전월세 자료를 제공하고 도로명주소 조건 검색도 지원한다. 그러나 공개 자료는 계약일 기준 참고자료이고 신고 변경·해제에 따라 내용이 달라질 수 있다. 대량·반복 수집은 공개시스템 화면 자동화가 아니라 공공데이터포털 API를 사용해야 한다.

첫 Adapter는 공공데이터포털의 건물유형별 실거래 API를 시군구 법정동 코드 앞 5자리와 계약년월로 수집한 뒤, 사가정 1km 범위와 면목동 주소·건물에 다시 결속한다. API가 제공하지 않는 정확 주소를 추정해 채우지 않는다.

### 2. 주소·건물 식별 자료

도로명주소 검색 결과의 `bdMgtSn`만 영구 단일키로 믿지 않는다. 주소기반산업지원서비스 안내에 따라 `행정구역코드 + 도로명코드 + 지하여부 + 건물본번 + 건물부번` 복합키를 주소 판본과 함께 보존하고, 모든 건물관리번호가 필요하면 건물 DB를 사용한다. 건축HUB 건축물 정보와 기존 지도 건물은 별도 식별자로 유지하고 근거 있는 연결 관계로만 결속한다.

### 3. 공시가격

표준주택가격·공동주택 공시가격은 실제 계약 가격과 다른 연간 공시 관측이다. 포함하더라도 `실거래`, `공시가격`, `호가`를 한 숫자로 합치거나 서로 대체하지 않는다. 첫 절편에서 민간 지도·중개 플랫폼의 매물 호가와 메뉴를 크롤링하지 않는다.

## 현재 사가정 결속 가능성

기존 사가정 지도에는 건물 602개가 있고 580개에 주소 문자열이 있다. 하지만 기존 수집 자료와 연결된 주소 후보는 244개이며, 그중 단일 후보 204개·복수 건물 후보 40개다. 주소가 있어도 기존 수집 후보가 없는 건물이 336개이고 주소 자체가 없는 건물이 22개다.

따라서 첫 수집에서 602개 건물 모두에 가격을 채운다고 약속할 수 없다. 다음 상태를 명시적으로 보존한다.

- `ConfirmedBuilding`: 공식 주소 복합키와 건물 식별 근거가 하나로 확인됨
- `AddressLevelOnly`: 도로명주소 수준 관측만 확인되고 디오라마 건물은 미확정
- `AmbiguousBuilding`: 한 주소가 여러 건물 후보에 걸림
- `AreaAggregateOnly`: 개인정보·자료 해상도·표본 수 때문에 블록/회랑 집계만 허용
- `Unresolved`: 주소·건물·지역 어느 쪽에도 안전하게 결속할 수 없음

문자열 유사도나 가장 가까운 건물만으로 `ConfirmedBuilding`을 만들지 않는다.

## 저장 책임 제안

### RDB 원본·검토 영역

- `부동산자료원Snapshot`: 제공기관, 자료 ID, 요청 지역·월, 원본 hash, 수집 시각, 기준일, 이용조건
- `주거실거래Observation`: 주택 유형, 거래 유형, 계약일, 거래금액 또는 보증금·월세, 면적, 허용된 층·건축연도, 정정·해제 상태
- `도로명주소건물Assignment`: 주소 복합키, 건물 고유 식별자, 연결 방법, 신뢰도, 주소·건물 판본
- `주거가격Aggregate`: 공간 범위, 기간, 유형, 표본 수, 중앙값·범위, 단위, 품질·누락 상태

원본은 append-only로 보존하고 정정·해제는 이전 행을 덮어쓰지 않는 revision으로 반영한다. 같은 원본 hash·요청 조건의 재처리는 중복 행을 만들지 않는다.

### 지역 패키지 투영

`station-housing-market-overlay.v1` 후보에는 배포 승인된 집계와 카드 자료만 넣는다.

- `stationStableId`, `sourceVintage`, `projectionHash`, `readinessCode`
- 공간 범위 `Building | H2Block | H3Corridor`
- `Sale | Jeonse | MonthlyRent | OfficialPrice`
- 관측 기간, 표본 수, 금액 범위·중앙값, 면적 구간
- 연결 방법·품질·누락·출처·이용조건
- `ObservationPresentationOnly=true`
- `CurrentMarketPrice=false`, `FinancialAdvice=false`, `GameplayAuthority=false`

소유자, 임차인, 상세 호수, 개인 연락처, 원본의 비공개 상세 위치는 Unity 계약에 넣지 않는다. 이는 기존 World 기본 투영의 주택가격 제외 원칙을 폐기하는 것이 아니라, 사용자가 명시적으로 연 별도 선택형 관찰 계약 후보다.

## 디오라마 표현 제안

- 기본 화면에서는 가격 숫자·색칠·순위를 표시하지 않는다.
- 사용자가 건물을 선택하고 `주거 관찰` 탭을 열었을 때만 최근 관측과 출처·기간·표본 수를 보여 준다.
- 건물 결속이 확정되지 않았거나 표본이 최소 기준보다 적으면 `건물 단위 자료 미확정`을 표시하고 H2 블록 또는 H3 회랑 요약만 보여 준다.
- 매매·전세·월세·공시가격을 서로 다른 행과 색상으로 표시한다.
- 가격은 NPC의 거주 선택, 주문·배차, 광고 노출, 건물 가치, 평판, 퀘스트와 오행 분류에 영향을 주지 않는다.

첫 공개 안전 기준 후보는 동일 유형·동일 기간의 관측 3건 이상일 때만 건물 집계를 표시하고, 그보다 적으면 넓은 공간 집계로 낮추는 것이다. 정확한 임계값은 구현 전에 개인정보·통계 왜곡 검토로 확정한다.

## 단계적 진행안

1. 필수 선행 기획에서 사가정 602개 건물의 `AddressResolutionState` 대장을 완결한다.
2. 첫 화면 의미를 `실거래만` 또는 `실거래+공시가격` 중 확정한다.
3. 중랑구·계약년월 단위 API와 주소 DB의 이용조건·필드·키 판본을 동결한다.
4. 최근 24개월의 매매·전세·월세를 비공개 로컬 검토 영역에 수집한다.
5. 원본 hash, 정정·해제, 같은 입력 중복 방지와 독립 재조회를 검증한다.
6. 공식 주소 Assignment→건축HUB/기존 주소 대장→사가정 건물 순으로 연결하고 모호한 건은 미해결로 남긴다.
7. 개인정보·표본 기준을 통과한 건물/H2/H3 집계를 결정적으로 생성한다.
8. 서버 읽기 계약과 지역 Experience Package 계층을 먼저 검증한다.
9. 이후 별도 승인으로 Unity Decoder·메모리 모델·선택 카드에 연결한다. Scene 배치와 게임 규칙 결속은 별도 Goal로 둔다.

## 검증 조건

- 동일 원본·주소·건물 판본으로 같은 연결 결과와 투영 hash가 생성된다.
- 거래 정정·해제 뒤 최신 유효 집계가 바뀌고 이전 revision은 감사 가능하다.
- 매매 금액과 전세 보증금, 월세 보증금·월세가 서로 섞이지 않는다.
- 주소 문자열이 같다는 이유만으로 복수 건물에 같은 거래를 복제하지 않는다.
- 표본 부족·주소 일부 마스킹·건물 결속 실패를 0원이나 무거래로 표시하지 않는다.
- Unity 계약에 소유자·임차인·상세 호수·연락처와 검토 중 원본 행을 포함하지 않는다.
- 관찰층 활성화 여부가 OS 상태, NPC 의사결정, 주문·배차·광고·경제 결과를 바꾸지 않는다.

## 확정

- 가격 자료는 H1 역할이 아니라 주소·건물에 결속되는 별도 관찰층이다.
- 사가정 602개 건물의 주소 상태 대장 완결을 가격 수집·건물 투영의 필수 선행 관문으로 둔다.
- H1은 선택 건물, H2는 블록, H3는 생활 회랑의 조회 범위로만 재사용한다.
- 공식 실거래·공시가격·민간 호가를 서로 다른 자료 종류로 유지한다.
- 주소와 디오라마 건물의 결속이 불확실하면 건물 가격을 임의 생성하지 않는다.
- 첫 단계는 기획과 공식 자료 검토이며 아직 수집·DB·API·Unity 구현을 승인한 상태가 아니다.

## 미정

- 첫 화면에 실거래만 보여 줄지 공시가격도 함께 보여 줄지
- 첫 수집 기간과 주택 유형 우선순위
- 건물 단위 표시의 최소 표본 수와 H2/H3 집계 경계
- 서버 API를 독립 route로 둘지 지역 Experience Package 하위 계층으로만 제공할지
- 실제 자료의 게임 경제·NPC 행동 활용 여부. 현재는 명시적으로 제외한다.

## 보류된 질문

첫 `주거 관찰` 카드의 가격 의미를 어디까지 열지는 주소 완결 기획의 공유 주소 정책을 확정한 뒤 다시 묻는다.

- **A안 — 실거래만(추천):** 매매·전세·월세의 실제 계약 관측을 유형별로 보여 준다. 의미가 가장 분명하고 첫 검증 범위가 작다.
- **B안 — 실거래+공시가격:** 실제 계약 관측과 연간 공시가격을 나란히 보여 주되 서로 비교 가능한 한 숫자로 합치지 않는다.
- **C안 — 호가까지 포함:** 민간 매물의 현재 제안 가격도 별도 자료로 다룬다. 이용조건·변동·중복·수집 방식 검토가 커져 첫 절편에는 권하지 않는다.
