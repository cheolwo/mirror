# 가맹·센터·배송의 정보 경계와 연결 계획 r72

2026-11-09 계획 제안. [r71 통합 운영 제안](integrated-franchise-logistics-operations.proposal.r71.md)의 회차와 인계를 검토하기 전에, 각 영역이 업무를 끝내는 데 필요한 정보와 기록 책임을 정한다. 배달 쇼츠가 방문·촬영·편집 자료를, 쇼츠 드라마가 대본·배역·장면 판본을 중심으로 운영되는 것처럼, 각 영역의 내부 자료는 업무 목적에 맞게 유지한다. 다른 영역이 쓸 정보는 목적과 전달 조건을 정해 연결한다. [기능 작업영역 분할](../../../../Architecture/FunctionalWorkAreaPartitioning.md) · [업무 실행 책임](../../../../Architecture/BusinessWorkflowResponsibilityModel.md)

## 1. 영역별 정보 대장

세 사업 단위는 유지한다. 가맹본부와 점포가 확정하는 정보가 다르고, 배송 플랫폼의 화물과 음식 배달이 취급하는 정보도 달라 기록 책임을 다섯 줄로 나눈다.

| 기록 책임 | 직접 기록·수정할 정보 | 다른 곳에서 받아 쓸 정보 | 범위 밖의 예 |
| --- | --- | --- | --- |
| 가맹본부 | 브랜드·점포 관계, 공급 조건과 적용일, 승인 품목·레시피 판본, 발주 수락·변경 | 점포 수요, 센터 가용 수량, 점포 인수 결과 | 고객 배송 주소, 기사 실시간 위치 |
| 점포 | 주문 수락·제조·픽업 준비, 재료 인수·사용·폐기·실사, 보충 발주 요청 | 적용 레시피·공급 조건, 납품 예정, 배차 결과 | 다른 점포의 재고, 센터의 전체 피킹 현황 |
| 물류센터 | 입고 검수, 위치·로트·기한·보관 상태, 재고 예약, 작업 묶음, 실상차 | 수락된 발주행·수량·납품 조건, 배차 차량·시간창 | 고객 주문 상세, 점포 레시피와 판매 가격 |
| 화물 운영 | 운송의뢰, 적재 조건, 차량·기사 배정, 상차·하차 증빙과 사고 | 실제 출고 대상·물량·납품지·시간창, 점포 검수 예외 | 고객 음식 주문·개인 주소, 센터 전체 재고 |
| 음식 배달 운영 | 배달 시도, 배차·픽업·전달과 예외 | 해당 주문의 픽업 정보·준비 상태, 배송에 필요한 전달지 | 공급가, 레시피 배합, 센터 입고·재고 |

정보 대장에는 필드마다 **사용 목적·기록 담당·원본·단위 또는 식별자·공유 대상**을 붙인다. 필수 입력, 판단에 도움이 되는 참고, 접근 범위 밖 정보를 구분한다. 점포·센터·품목처럼 여러 영역에서 같은 대상을 알아봐야 하는 값은 공통 식별자로 연결한다. 식별자를 공유해도 세부 기록과 수정 권한은 원래 담당에 둔다. [화물·음식 배차 책임](../../../../Architecture/DispatchQueueResponsibility.md)

## 2. 인계 표

각 인계에 받는 쪽의 질문과 그 질문에 답하는 필드를 적는다. 예를 들어 센터의 질문이 “어느 점포에 어떤 규격으로 몇 개를 언제까지 준비해야 하나?”라면 발주행, 점포, 품목·포장 단위, 수락 수량, 납품창이 필요하다.

| 인계 | 기준 상태와 최소 정보 | 이어받는 행동 |
| --- | --- | --- |
| 본부 → 센터 | 발주 수락. 발주행 ID, 점포 ID, 품목·단위, 수락량, 납품창 | 센터가 가용 로트를 확인하고 예약한다. |
| 센터 → 화물 | 운송 준비. 출고행 ID, 납품지, 계획 수량·단위, 보관 조건, 시간창. 상차 때 실수량·시각을 추가한다. | 플랫폼은 차편을 잡고, 기사는 실제 상차를 확인한다. |
| 화물 → 점포 → 재고 | 화물 도착은 운송의뢰 ID·하차량·증빙. 점포 검수는 검수행 ID·로트·인수량·격리량·단위. | 점포가 검수한 인수량만 해당 점포의 가용 재고에 반영한다. |
| 점포 → 음식 배달 | 해당 주문 ID, 픽업 장소, 준비 상태와 시각, 전달에 필요한 정보 | 배차와 픽업을 기존 정책에 따라 진행하고, 전달 결과를 같은 배달 시도에 남긴다. |
| 점포 → 본부 | 실사 시각, 확인 재고, 미도착량, 보충 요청량 | 본부가 다음 보충 회차의 공급 가능량을 확인한다. |

정보의 쓰임에 따라 세 형태를 둔다. **원본**은 해당 업무 담당이 기록·수정한다. **인계 사본**에는 전달 당시의 조건과 수량을 고정한다. **조회 사본**은 담당자가 현재 상태와 원본 위치를 확인할 때 쓰며 마지막 확인 시각을 표시한다. 원본이 개정돼도 이미 수락한 발주에 적용된 조건은 그 인계 사본에서 다시 확인할 수 있다. [발주 조건 보존 기준](../../../../Architecture/PlatformSupplyBrokerage.md)

인계에는 원본 ID, 확정 담당, 시각, 판본 또는 처리 번호와 받는 쪽의 점포·조직 범위를 둔다. 예를 들어 화물의 `하차 완료` 뒤에는 점포의 `검수 대기`가 올 수 있다. 통합 조회는 이 상태들을 나란히 표시하고, 담당자가 확인할 원본으로 연결한다. 같은 인계의 재수신, 오래된 결과, 일부 수량만 전달된 경우에도 원본을 대조할 수 있게 한다.

## 3. 실행 순서와 통과 조건

1. **정보 대장부터 채운다.** r67~r71과 현재 앱·서버를 대조해 실제 기록 위치, 작성 담당, 소비 화면을 찾는다. 근거를 찾지 못한 항목은 미확인으로 둔다. 결과물은 영역별 필수·참고·범위 밖 항목 표다.
2. **영역별로 먼저 확인한다.** 본부는 수락 수량, 센터는 출고와 실상차 수량, 점포는 인수·격리 수량을 각각 한 건으로 검토한다. 화물은 하차, 음식은 픽업과 고객 수령의 완료 근거를 자기 기록에서 확인한다. 결과물은 각 업무의 정상 사례와 책임자다.
3. **가상 우유 발주 한 건을 연결한다.** 출고·하차 5팩, 점포 인수 4팩, 격리 1팩을 같은 발주행과 로트로 따라간다. 라떼 한 잔에 쓴 170mL를 점포 재고 이동과 연결하고, 음식 배달에는 픽업과 전달에 필요한 정보만 전달한다. 수량 불일치, 중복 수신, 타 점포 조회, 앞 단계 확인 지연도 확인한다.
4. **검증한 연결만 넓힌다.** 두 점포를 같은 출고 회차에 넣어 묶어도 각 발주·상차·인수 수량이 유지되는지 대조한다. 이후 운영자 조회에서 현재 막힌 단계, 다음 담당, 확인 시각을 보여주는 설계를 검토한다.
