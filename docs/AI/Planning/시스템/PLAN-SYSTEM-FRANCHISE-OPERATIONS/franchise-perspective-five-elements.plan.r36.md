## 확정·사용자 표현 정리

사용자의 후속 정정 **"운영자 간괘"**에 따라 프랜차이즈 운영 주체는 이 관점에서 **토(간괘)**로 기록한다. 앞 발화의 운영자 감괘 표현을 확정값으로 사용하지 않는다. 앞 발화의 생산자·제조업체·음식점 분류는 아래처럼 기록하며, 현금에 관한 감괘 해석은 사용자가 잠정적으로 말한 부분이므로 제안과 구분한다.

| 프랜차이즈 관점의 대상 | 오행·괘 | 역할 해석 | 상태 |
| --- | --- | --- | --- |
| 생산자 | 목(진괘) | 원재료 생산·공급의 출발 | 사용자 제시 분류 |
| 제조업체 | 화(리괘) | 원료를 가공하여 공급할 제품을 만드는 역할 | 사용자 제시 분류 |
| 프랜차이즈 운영자 | 토(간괘) | 공급망·매장 관계의 중심에서 기준·계획·운영을 조율 | 사용자 정정 확정 |
| 음식점·가맹 매장 | 금(태괘) | 공급된 제품이 모이고 소비자 판매로 이어지는 매장 접점 | 사용자 제시 분류 |
| 현금·자금 흐름 | 수(감괘) | 매입 대금·매출 수납·정산 등 자금의 순환 | 의미 범위 제안·미확정 |

표의 역할 설명은 이번 기획의 해석이며 전통 괘상의 유일한 뜻이나 실제 업체의 역할 조사 결과가 아니다. 운영자가 중앙에서 조율한다는 의미이지 모든 물품과 대금이 본부를 반드시 거친다는 뜻은 아니다.

## 같은 객체를 관점에 따라 읽기

괘상은 업체의 영구 속성 하나로 덮어쓰지 않는다. 기존 음식점 운영의 화(리괘) 분류는 조리·판매 업무를 설명하고, 이번 금(태괘)은 프랜차이즈 공급망에서 매장이 맡는 접점을 설명한다. 두 관점은 같은 음식점 ID를 참조하며 별도 음식점·원장을 생성하지 않는다.

후속 관계 자료에는 적용 관점·역할·대상 고유 식별자·기획 판본과 분류 근거를 함께 연결할 수 있어야 한다. 기존 대표 업무 괘나 개별 WI의 행위·대상 괘, 화면 색상을 이 문답만으로 전역 변경하지 않는다. 오행·괘상은 설명·검색용이며 실행 권한, 실제 상태 전이, 결제·정산의 판정을 맡지 않는다.

중도매인·식자재 업체는 생산자나 제조업체라는 이름으로 일괄 합치지 않는다. 제조·보관·유통·납품을 겸할 수 있으므로 이번에는 실제 역할과 기존 공급 관계를 보존하고, 세부 괘 대응은 미정으로 둔다. 각 업체에 다섯 역할을 억지로 채우지 않는다.

## 감괘의 자금 의미 — 제안

현금 자체를 물품이나 기관과 같은 역할 주체로 취급하기보다는 **대금이 오가는 자금 순환 관계**를 수(감괘)로 읽는 안을 제안한다. 현금 잔액과 매출·매입·지급·수납·정산 상태는 서로 구별하며 매출 발생을 현금 입금으로 간주하지 않는다. 분류에 맞추려고 기존 회계 계정이나 결제 원장을 바꾸지 않는다.

이 안은 기존 운송의 수(감괘) 분류를 없애지 않는다. 돈의 흐름과 물품의 흐름은 서로 다른 관계이며, 같은 괘로 읽더라도 실제 ID·원장·상태·근거는 별도로 유지한다.

## 후속 범위·다음 질문 하나

r33의 수평 적층과 r35의 공급/조율 관계 구분을 유지한다. 두 번째 관계 층에서 이번 관점별 분류를 설명 정보로 연결할지를 검토하며, r34의 기존 공통 조회 구현·증거는 그대로 보존한다. 이번에는 새 스키마·업무 코드·Graph Map 원본·DB·Unity를 변경하지 않는다.

미정: 감괘를 현금 잔액 중심으로 볼지 자금 순환 관계로 볼지, 중도매인·식자재 업체의 역할별 세부 분류.

**다음 질문 하나:** 감괘는 현금 보유액 자체보다 **매입 대금·매출 수납·정산처럼 돈이 순환하는 흐름**으로 잡을까? 추천은 흐름 중심이며 사용자 확인 전에는 확정으로 승격하지 않는다.

이번 변경은 기획 문서만이다. 제품 코드·DB·Runtime·Unity 검증·commit·push 없음. 새 디오라마 규칙 후보 없음.
