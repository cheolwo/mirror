## 확정 — 프랜차이즈 운영자가 보는 관계

사용자의 이번 정정에 따라 **플랫폼은 금(태괘), 본부가 관리하는 가맹 음식점은 수(감괘)**로 분류한다. 프랜차이즈 운영자는 토(간괘)를 유지한다. 자금 흐름은 특정 괘의 주체로 두지 않고 이들 관계 사이를 순환하는 **기운**으로 읽는다.

| 이 관점의 대상 | 오행·괘 | 기획상의 역할 설명 |
| --- | --- | --- |
| 생산자 | 목(진괘) | 원재료 생산·공급의 출발 |
| 제조업체 | 화(리괘) | 원료를 가공하여 제품으로 만드는 역할 |
| 프랜차이즈 운영자 | 토(간괘) | 공급망부터 매장 판매까지 관리·조율하는 중심 |
| 플랫폼 | 금(태괘) | 참여 주체의 연결·거래·업무를 지원하는 기반 |
| 관리 대상 가맹 음식점 | 수(감괘) | 본부의 공급·운영 관계로 연결된 실제 매장 |

대상별 괘 대응은 사용자 분류이고 역할 설명은 그 의미를 풀어 쓴 것이다. 전통 괘상의 유일한 해석이나 실제 업체의 계약 사실을 주장하지 않는다. 특히 플랫폼과 가맹본부 운영자는 서로 다른 역할이며, 본부가 플랫폼을 이용한다는 사실만으로 플랫폼을 소유하거나 플랫폼 전체의 권한을 갖지는 않는다.

## r36에서 바뀌는 부분

- `음식점 = 금(태괘)`는 이번 관점에서 더 이상 사용하지 않는다. `플랫폼 = 금(태괘)`로 대체한다.
- `자금 순환 = 수(감괘)` 제안은 채택하지 않는다. `관리하는 가맹 음식점 = 수(감괘)`로 정한다.
- 자금은 오행의 주체들 사이를 오가는 기운으로 설명한다. r36의 현금/순환 선택 질문은 이번 정정으로 닫으며 재질문하지 않는다.
- 생산자 목·제조업체 화·운영자 토와 r35의 각 업체 책임·권한 구분은 유지한다. r36은 변경 전 이력으로 보존한다.

## 주체와 기운의 구분

그래프로 설명하면 **주체의 역할이 노드이고 자금의 순환은 그 사이의 관계**다. 예를 들어 매장이 공급업체에 지급하는 매입 대금과 계약에 따른 플랫폼 이용료는 서로 다른 자금 관계로 표현할 수 있다. 이는 설명 예시이며 실제 거래·지급·수수료 정책이 있다는 증거가 아니다.

기운이라는 표현은 관계를 이해하는 비유다. 금액·통화·발생 시각·보낸 주체·받는 주체·지급 상태·원장 근거를 없애거나 하나의 게임 점수로 바꾸지 않는다. 현금 잔액, 매출 발생, 지급 예정과 실제 입금도 구별한다. 모든 돈이 가맹본부를 거치거나 다섯 주체가 고정 순서로 순환한다고 가정하지 않는다.

물품·정보·노동까지 같은 기운으로 통합할지는 이번에 확정하지 않는다. 별도 관계와 단위는 유지하며 돈과 합산하지 않는다. 괘상이나 기운의 표현만으로 결제·정산·회계 처리 또는 업무 완료를 발생시키지 않는다.

## 관점과 구현 경계

이번 분류는 **프랜차이즈 운영 관점**에 한정한다. 기존 조리 업무에서 음식점을 화(리괘)로 읽는 분류나 운송을 수(감괘)로 읽는 분류를 전역 변경하지 않는다. 동일 음식점의 ID·원장은 유지하고 적용 관점·역할·판본을 구별한다. 기존 Graph Map의 감괘 관계 표기를 이번 자금 흐름에 자동 상속하지 않는다.

r33의 수평 적층 순서와 r34 첫 층 구현은 그대로 둔다. 후속 공급 관계 층에서는 주체별 괘 분류와 그 사이의 자금 관계를 별개 설명 정보로 연결할 수 있도록 검토한다. 이번에는 Graph Map 원본·공통 계약·DB·업무 코드·Unity·색상 체계를 수정하지 않는다.

미정: 중도매인·식자재 업체의 역할별 세부 분류, 실제 계약과 자료의 연결, 구체적인 관계 조회 형식. 이름만으로 제조업체와 합치거나 임의의 괘를 부여하지 않는다.
