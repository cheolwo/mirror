# 매장 실태와 구분한 메뉴·재료 참고 관계와 Unity 탐색 r40

- 선행: [재료 연결 r39](menu-ingredient-supply-analysis.plan.r39.md), [콘텐츠 순환 r38](delivery-content-data-cycle.plan.r38.md), [공통 기반 r34](ingredient-foundation.implementation.r34.md)

## 사용자 정정과 해석

사용자는 해당 음식점에서 직접 일하거나 내부 운영을 확인한 것이 아니므로 자료를 특정 매장의 실제 재료·공급 관계로 연결하는 데 한계가 있음을 지적했다. r39의 첫 결과물에서 매장별 실제 재료 사용이나 실제 납품을 암시하는 관계를 만들지 않는다.

사용자의 “유닛이상으로 표현”이라는 발화는 문맥상 “유니티상에서 표현”으로 해석했다. 이는 보조자의 해석이며 구체적인 Unity 화면·Scene 구현 승인이 확인됐다는 뜻은 아니다. 자료 축적과 표현 가능성의 기획을 계속 진행한다.

## 관계를 두 종류로 분리

1. **현장 관찰 기록:** 특정 날짜에 방문한 매장과 확인된 메뉴명, 촬영·사용자 기록의 근거를 보존한다. 매장 내부 레시피·구매·납품·사용량은 미확인이다.
2. **일반 참고 관계:** 메뉴 유형 → 공개 참고 레시피 → 해당 레시피가 명시한 재료·가공품의 관계를 출처·판본과 함께 쌓는다. 관찰 메뉴와 메뉴 유형의 대응도 후보·확인 상태를 표시한다.

관찰 메뉴에서 참고 자료로 이동할 수 있지만, 그 연결을 “그 매장이 이 재료를 사용한다”로 해석하거나 재료→실제 매장 사용 관계로 재투영하지 않는다. 브랜드 공식 설명이 확보돼도 그 설명의 적용 범위까지만 별도 근거로 기록한다. 실제 공급처는 별도 확인 전까지 연결하지 않는다.

## 다음 자료 정리 단위

기존 메뉴–공공 레시피 색인과 12개 재료 공통 기반을 먼저 대조한다. 기존 자료를 재수집하기 전에 메뉴 유형·레시피·재료 ID·관계 출처·확인 상태의 결손을 확인한다.

첫 결과물은 매장별 공급망이 아니라 **메뉴 유형–참고 레시피–재료 관계표**다. 재료를 선택하면 어떤 참고 레시피와 메뉴 유형에 연결되는지, 연결 근거와 미확인 부분을 함께 찾을 수 있게 한다. 출처 없는 관계는 빈칸을 추론으로 채우지 않는다.

소스·육수·반조리품은 참고 레시피에 명시된 경우 그 자체를 재료 항목으로 보존할 수 있다. 구성 원재료·외부 구매 여부·매장 직접 제조 여부는 별도 근거 없이 분해하거나 확정하지 않는다. 실제 공급 형태의 초기 포함 범위는 여전히 미정이며 r39 질문에 대한 전면 승인으로 처리하지 않는다.

## Unity 표현 제안과 단계

1. 자료 단계: 기존 메뉴·레시피·재료 연결을 대조하고 출처·판본·결손을 같은 형식으로 조회한다.
2. 탐색 단계: 기존 조회 결과로 메뉴 유형과 재료 간 관계를 확인할 수 있는 읽기 전용 관계표를 준비한다.
3. 표현 명세 단계: 재료를 선택하면 연결된 참고 메뉴·레시피가 나타나고, 메뉴를 선택하면 구성 재료 근거가 보이는 Unity 탐색 구성을 설계한다. 공급망 모형을 추가한다면 가상 시나리오임을 구분한다.
4. 구현 단계: 현재 공통 조회 계약과 기존 Unity 진입점을 대조한 뒤 별도 명세·검증 범위로 구현한다. 새 공식 Scene을 만들거나 실제 매장 디오라마에 미확인 공급 관계를 배치하지 않는다.
5. 콘텐츠 단계: 검증한 관계에서 설명 카드·영상 대본을 만들고, 원본 자료가 수정되면 연결된 설명도 재검토한다.

Unity 표현은 자료를 탐색하고 이해하는 수단이며, 애니메이션이나 연결선이 실제 공급·제조·납품의 증거가 되지는 않는다. 이번에 Unity 화면·객체·Scene이나 분석 실행 결과는 생성하지 않았다.

## 다음 논의

지금은 새 확인 질문을 반복하지 않는다. 다음 작업 명세의 출발점은 기존 자료의 메뉴 유형–레시피–재료 연결과 결손 점검이다. 공급 업체 조사, 실제 운영 모델, 구체적인 Unity 화면 선택은 그 결과를 보고 세분화한다.

이번 변경은 기획·목차·현재 상태 문서뿐이다. 신규 수집·DB 쓰기·코드·Unity 실행·영상 제작·commit·push 없음.
