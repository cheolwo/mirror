## 1. 결론과 첫 화면의 약속

**새 지도를 만드는 것보다, 기존 동별 지도를 같은 좌표에 이어 붙이고 그 위에 기록 순서 재생을 얹는 것이 우선이다.**

```text
기존 방문 기록 → 순서·장소 검증 → 재생용 방문 목록
                                   ↓
기존 동별 지도 → 공통 좌표 조립 → 가게 ① → 가게 ② → 가게 ③
```

- 지금: 자신이 방문한 음식점·메뉴·순서 기록을 선택한 상태.
- 여기: 그 방문들이 포함된 동과 동 사이의 작은 연속 지도.
- 나: 방문 기록의 당사자이자 재생을 조작하는 관찰자.
- 상대: 기록에 등장한 가게의 위치 표시와 자신의 대체 기사 캐릭터. 실제 상대가 접속하거나 업무를 수행 중이라는 뜻은 아니다.
- 행동: 재생·일시정지·앞/뒤 방문 선택. 캐릭터가 기록 순서로 이동하고 도착한 가게가 잠깐 강조된다.
- 결과·다음 선택: 어디를 어떤 순서로 방문했는지 확인하고, 특정 방문을 눌러 메뉴·근거를 보거나 다른 구간을 선택한다.
- 대가·실패·회복: 지도나 위치 근거가 부족한 구간은 재생을 보류한다. 누락을 숨기지 않고 근거 보완 후 같은 방문부터 재개한다.

화면에서는 애니메이션을 우선한다. 방문 번호·현재 순서·작은 재생 조작부만 기본으로 보이고, 음식점·메뉴·출처·확인 상태는 선택 시 펼친다. 기본 카메라는 전체 구간이 보이는 기존 아이소메트릭 관찰 시점을 재사용하며 정교한 추적 카메라는 후속으로 둔다. 이 계획은 생활 관찰의 보조 표현이며 새 성장 규칙·오행 역할·배달 완료 조건을 만들지 않는다.

## 3. 보완 A — 방문 순서 재생

### 기록을 재생 자료로 정돈

기존 `RegionalPickupRecord`는 보존한다. 재생 준비 검사와 읽기 전용 재생 목록을 그 뒤에 둔다. 초기 단계에 새 DB나 업무 원장을 만들 필요는 없다.

- 명시적으로 선택한 비공개 최소 JSON 사본을 읽는 decoder/입력 Adapter부터 확인·보완한다. 형식/크기 제한·필수 값·원본 hash를 검사하고 실패를 가짜 샘플로 대체하지 않는다. 같은 기록을 재생할 때 매번 SQLite나 외부 API를 호출하지 않는다.
- `RecordId + 원본 hash + 선택 범위`로 입력을 식별하고 `VisitId`를 재생 항목의 고유 식별자로 유지한다.
- 양의 `Sequence`를 기준으로 정렬한다. 중복·누락은 진단으로 남기며 거리순으로 바꾸거나 자동 재번호화하지 않는다. 선택 구간이 8~12이면 원래 번호를 보존한다.
- `StoreId`는 가게 객체 재사용에 쓰고 `VisitId`는 매 방문에 쓴다. 같은 가게를 다시 방문하면 건물 하나와 방문 여러 건으로 표현한다. 이름만 같은 다른 지점을 합치지 않는다.
- 좌표의 유한값·범위·주소 대조·확인 근거·공간 변환 결과를 검사한다. 행정동은 판본이 있는 경계와 점의 관계를 확인하며 법정동·역세권·이름 힌트로 대체하지 않는다. 경계 위·중복 포함·범위 밖은 미해결로 남긴다.
- 건물/출입구 결속이 없어도 검증된 공개 가게 위치라면 중립 방문 표지를 사용할 수 있다. 그 표지를 실제 출입구로 표현하지 않는다.
- 미해결 방문은 목록에 남긴다. 2번을 못 그린다고 1→3을 실제 연속 방문 구간처럼 자동 연결하지 않는다. 별도 검토 구간을 명시적으로 선택할 수 있게 한다.

### 표현 전용 재생 상태

추천하는 최소 상태는 `준비 → 재생/일시정지 → 재생 종료`와 `자료 보류`다. 재생 종료는 기록을 끝까지 보았다는 뜻이며 실제 업무 완료가 아니다.

- 현재 방문 ID, 현재 연결 구간, 구간 진행률, 재생 배속, 연출 시간을 메모리에 둔다.
- 같은 입력·설정·경과 시간으로 같은 방문과 위치가 나오게 순수 계산을 먼저 만든다. 프레임 수나 실제 날짜 변경에 따라 방문을 건너뛰지 않는다.
- 이전/다음 방문·특정 번호 선택은 해당 방문의 표시 위치와 강조만 바꾼다. 메뉴 카드·번호·현재 방문을 함께 갱신하며 이벤트를 다시 업무로 발행하지 않는다.
- 시각 자료가 없는 현재 기록에는 균등 또는 제한된 거리 비례 연출 시간을 쓰는 안을 추천한다. 실제 속도·도착 시각·운행 거리 통계로 사용하지 않는다. 세부 초·배속은 첫 화면 확인 때 정한다.
- 재방문·같은 위치의 연속 방문은 0거리 나눗셈이나 캐릭터 중복 없이 표현한다.
- 지도 준비 실패·기록 교체 시 진행 시간을 멈추고 입력 판본을 섞지 않는다. 해제 후 복귀는 재생 위치와 지도 준비 상태를 재결속한 뒤 수행한다.

이는 Simulation의 Save/Replay나 운영 상태 사본 TTL을 과거 방문 자료에 그대로 적용하는 기능이 아니다. [생활상 표현 수명 r46](living-world-semantic-streaming.implementation.r46.md)의 상세 객체 해제·재조립·소유 자원 정리 방식은 참고하되 해당 운영 사본 Session을 방문 기록의 권위로 바꾸지 않는다.

## 4. 보완 B — 행정동 사이 공간 연결

**동은 자료의 소속 단위이고, 화면의 이음매나 이동 장벽은 아니다.**

### 하나의 공통 좌표로 배치

1. 선택한 방문과 연결 구간을 포함하는 작은 범위를 잡는다. 출발·도착 동뿐 아니라 그 사이에 지나가는 공간의 자료도 필요하다. 우선 인접 동 경계 하나를 포함한 작은 표본을 찾는다.
2. 동별 상태 사본은 별도로 검증한다. 좌표 변환 방식, 원점 위경도, `WorldOffsetX/Z`, `MetersPerUnit`, 타일 규격·출처 판본의 호환 여부를 비교한다. 불일치는 임의 보정으로 숨기지 않는다.
3. 현행 지역 중심 좌표를 재사용할 때 자식 Root를 `(동의 SourceCenterX/Z - 공통 표시 원점) / MetersPerUnit`만큼 이동한다. 이 식은 동일한 원본 좌표계·단위가 확인된 경우에만 적용한다. 자료 변환과 Root 이동으로 offset을 이중 적용하지 않는다.
4. 동별 MeshBuilder와 자식 Root를 재사용하고 상위 조립 객체가 공통 원점·카메라·선택 범위를 관리한다. 동별 자동 관찰 카메라는 끈다. 새 Scene이나 전역 Map Manager를 만들지 않는다.
5. 현행 `행정동디오라마검토MeshBuilder.Build`는 각 동 bounds에 여백을 더한 중립 사각 지면을 도형과 같은 MeshBatch에 생성한다. 다중 동 조립에서는 이 지면을 분리하거나 생성 생략 옵션을 두고 공통 중립 지면을 한 번만 만든다. 기존 단일 동 기본값은 보존한다. 이는 배경 받침의 중복 방지이며 실제 고도·연속 지형 완성을 뜻하지 않는다. 현 검토 경로의 `MetersPerUnit=1` 검사도 임의 완화하지 않는다.

### 물리 타일과 동별 조각을 구분

현재 [ProjectionBuilder](../../../../../Ssalddel/Services/WorldProjection/AdministrativeDongDiorama/행정동디오라마ProjectionBuilder.cs)는 `tile:{행정동 ID}:500m:x…:z…` 형태의 ID를 만든다. 같은 `(x,z)`라고 동별 타일 하나를 버리면 다른 동의 건물·도로 조각이 사라질 수 있다.

- 물리 격자 키는 호환되는 좌표계·타일 규격·격자 인덱스로 묶는다. 공용 지면·동일 기초 자료를 재사용하되 동별 도형 조각과 출처/hash는 보존한다.
- 캐시에는 동 ID·자료 hash를 함께 사용한다. 동마다 다른 내용의 hash가 같은지를 요구하지 않고, 선택한 동별 판본들의 호환 묶음을 고정한다.
- 완전히 같은 객체/도형만 근거를 대조해 중복 제거한다. 같은 건물 ID라도 서로 다른 절단 조각이면 보존·조립한다. 상호명이나 공간 근접성만으로 합치지 않는다.
- 도로 `:part:n` 번호는 원본별 절단 과정에서 다시 시작한다. 전역 고유성을 가정하지 않고 동 ID·원본 계보·절단 조각을 함께 확인한다. 필요할 때만 좁은 보조 연결 자료를 제안하고 기존 직렬화 ID는 보존한다.
- 끝점이 가까워도 다른 도로·높이가 다른 교차로일 수 있다. 근접 점을 자동으로 붙여 오토바이 통행 가능 경로로 승격하지 않는다.

### 로드·해제는 첫 단계와 후속을 분리

첫 표본은 **선택된 소수 동의 완전한 사본을 기존 방식으로 검증한 뒤 필요한 범위만 표시**한다. 현재 해석기에 부분 타일을 넣고 전체 목록 검증을 끄지 않는다. 정한 메모리 예산을 넘으면 표본을 줄이거나 후속 부분 조회 계약부터 준비한다.

후속은 현재/다음 재생 구간의 타일을 미리 준비하고 이전 표현 자원을 유예 후 해제하는 방식이다. 부분 조회를 구현하려면 완전한 구성 대장과 요청한 부분 집합의 관계·hash를 검증하는 별도 계약을 먼저 마련한다. 느린 이전 요청의 응답은 요청 세대로 구분해 버리고, 현재 구간의 필수 자료가 준비되기 전에는 캐릭터를 빈 화면으로 진행시키지 않는다. 한 동의 오류 때문에 다른 동의 정상 사본을 모두 지우지 않는다.

지도 사본과 재생 상태의 수명을 분리한다. 지도 캐시를 해제하더라도 현재 방문 번호는 유지하고, 기록을 닫으면 방문별 카드·캐릭터·선택 상태를 지운다. 비공개 위치 자료나 원문 JSON을 로그·공개 자산·운영 Save/Replay에 새로 기록하지 않는다.

## 5. 도로 주행으로 오해하지 않는 이동 표현

첫 버전은 **방문 순서 연결선 위의 기사 기호 이동**을 추천한다. 실제로 탔던 길이 없으므로 도로 주행·완료 경로로 표시하지 않는다. 선은 배경 도로와 다른 점선/리본으로 구분하고 `방문 순서 재구성 · 실제 주행 경로 아님`을 작은 범례로 유지한다. 다음 가게 사이에 고객 전달지를 만들어 넣지 않는다.

지역 사이 공간은 실제 상대 좌표를 유지하되, 연결선 자체가 건물 사이를 지나면 표현용 안내선임이 보여야 한다. 실제 도로를 따라 달리는 장면은 다음 단계에서 도로 연결 근거를 검사한 뒤 추가한다. 보행망·과거 도로 중심선만으로 현행 이륜차 통행을 확정하지 않는다. 이 단계도 실제 주행 기록이 없다면 도로 기반 재구성이다.

가게 배치·방문 순서·지도 조립은 유지하고 연결선 제공 부분만 교체할 수 있게 해두면 이후 도로 표현으로 확장할 때 기존 작업을 버리지 않아도 된다.

## 7. 후속 개발의 인수 점검표

이 표는 현재 통과 결과가 아닌 **앞으로의 검증 항목**이다.

- [ ] 방문 입력·채택 판본·위치/지역 근거가 고정되고 원본은 변경되지 않는다.
- [ ] 1→2→3 순서, 같은 가게 재방문, 중간 번호 선택, 일시정지/배속 변경 후 재개가 재현된다.
- [ ] 중복 순서·누락·불명확한 위치를 숨기지 않고 자료 보류로 남긴다.
- [ ] 두 동을 한 번에 표시해도 지역 중심 겹침·지형 이중 렌더·경계 조각 유실이 없다. 좌표 오차 허용치는 선택 자료 정밀도에 맞춰 작업 명세에서 정하고 화면 느낌만으로 판정하지 않는다.
- [ ] 같은 원본 도로의 동 경계 절단 관계는 추적되지만 임의 통행 경로는 생성되지 않는다.
- [ ] 조회 실패·판본 불일치·느린 이전 응답·왕복 선택·해제 후 복귀에서 기존 정상 상태를 훼손하지 않는다.
- [ ] 자동 시험, 실제 자료 로드, Play Mode, Game View는 각각 별도 증거로 남긴다. 현재 기존 시험의 과거 통과 수를 새 기능 완료로 쓰지 않는다.
- [ ] Game View에 재생 시작·동간 경계 이동·방문 선택/종료 화면을 남기고 Console 및 객체/Material 누적을 확인한다. 캡처는 기존 담당 분담에 따라 인계한다.
- [ ] 애니메이션으로 주문·배차·픽업·배송 완료 원장이나 Event가 생성되지 않는다. 원본 기록·운영 상태가 불변이다.
- [ ] 비공개 검토와 공개 영상 제작을 구분한다. 공개용 내보내기는 지도·자산의 이용조건과 공개 범위를 별도로 확인하기 전 차단한다.

## 8. 제외·인계·이번 증거

이번 제안에서는 영상 분석, 새 촬영, 고객 집 표시, 실시간 GPS, 실제 주행 경로 복원, 도로 길찾기, 자동 배차, 운영 로그인 기능 확장, 새 공식 Scene, 30개 동 전체 재생성, 새 DB, 영상 렌더/게시를 하지 않는다. 남은 결손을 새로운 자료 수집·외부 API 호출로 자동 치환하지 않는다.

후속 구현을 수용할 때는 선택한 하나의 상호작용과 명세에 이번 기획 판본/hash, 기존 입력 hash, 지도 판본, 담당/쓰기 경로, Logic·Presentation 검증 상한을 결속한다. Graph Map 영향은 승인 판본으로 인계하되 구현이나 증거 성숙도를 자동 승격하지 않는다.

이번에 확인한 증거는 코드·기존 JSON·문서의 읽기 전용 감사와 문서 검증뿐이다. 단일 동 중심 좌표·단일 사본 교체·미해결 방문 결속은 보완 근거이며 실제 Play에서 확인한 결함으로 보고하지 않는다. 출처/판본·사실/재구성 분리와 부분 자료 보호에 관한 기존 규칙을 지지하는 설계 점검이다. 기존 규칙을 무효화할 실행 증거는 없으며 **새 디오라마 규칙 후보 없음**.

## 확정 / 미정 / 다음 질문

- 확정: 기존 방문 데이터 기반, 기록된 순서 우선, 행정동 사이 공간 연결을 보완하는 제안서를 작성한다. 영상 입력으로 되돌아가지 않는다.
- 제안: 입력 검증→재생 논리→연속 공간→작은 실제 화면 순서. 소수 방문·소수 동, 표현용 연결선부터 시작한다.
- 미정: 실제 첫 기록/방문 구간, 위치·지역 결속 완료, 연출 시간/배속, 메모리 예산·경계 오차 기준, 도로 재구성 도입 시점. 아직 구현 승인·배치/동작 검증은 없다.
- 다음 질문: 지금 없음. 후속 준비의 첫 일은 기존 자료에서 재생 가능한 작은 표본과 미해결 결속 목록을 확정하는 것이다.
