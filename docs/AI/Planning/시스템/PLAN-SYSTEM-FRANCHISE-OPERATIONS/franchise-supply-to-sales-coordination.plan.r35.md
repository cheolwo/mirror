## 확정한 의미

**프랜차이즈 운영 주체인 가맹본부는 생산자·중도매인·식자재 업체·제조시설·음식점을 연결하여, 공급망 관리부터 음식점의 판매 운영까지 종합적으로 관리·조율하는 주체가 될 수 있다.** 단순히 음식점 바로 앞에서 물품을 납품하는 업체 하나로만 표현하지 않는다.

이는 모든 공급망에 가맹본부가 필수라는 뜻이 아니다. 독립 음식점의 직접 매입, 중도매인 매입, 식자재 업체 납품도 유지한다. 모든 가맹본부가 생산·제조·보관·운송을 직접 수행하거나 모든 시설을 소유한다고 가정하지 않는다. r2의 플랫폼과 외부 가맹본부 구분, r3의 자체/위탁 제조 구분, r32의 실제 거래와 추론 후보 구분을 보완하며 대체하지 않는다.

## 물품 흐름과 총괄 관계를 분리

| 관계 관점 | 표현할 내용 | 혼동하지 않을 내용 |
| --- | --- | --- |
| 물품·업무 흐름 | 생산 → 유통·가공 → 납품 → 음식점 입고 → 조리·판매. 중간 단계 생략·복수 공급 경로 허용 | 본부가 관리한다는 이유만으로 물품이 본부 시설을 거쳤다고 표시하지 않음 |
| 운영·조율 관계 | 본부가 계약된 범위의 조달 계획·공급 기준·품질 기준·매장 운영 지원·판매/재고 현황을 연결해 관리 | 총괄 조회를 개별 업체의 소유권이나 무제한 실행 권한으로 해석하지 않음 |

이 관계명은 설계 의미이며 새 API enum이나 DB 스키마 확정이 아니다. 구현 때 기존 업체·시설·계약·담당자·권한 참조와 관계 계약을 먼저 대조한다. Graph Map 원본은 이번 문서 작업에서 변경하지 않는다.

## 주체별 책임과 연결

| 주체 | 기본 역할 | 본부 관점에서 연결할 정보 |
| --- | --- | --- |
| 생산자 | 생산·공급 가능한 물품 관리 | 공급 가능 품목·규격·일정과 확인된 계약/공급 관계 |
| 중도매인 | 매입·유통·판매 | 조달 후보·확인된 거래와 공급 조건 |
| 식자재 업체 | 품목 구성·납품 | 발주·출고·납품·인수의 기존 업무 참조 |
| 제조시설 운영 주체 | 원료 인수·가공·품질 확인 | 원료/제품 규격, 투입·산출 및 검수 상태 |
| 음식점 운영 주체 | 발주·입고·조리·판매 | 재고·주문·판매 및 보충 필요 정보 |
| 가맹본부 | 위 관계의 종합 관리·조율 | 계약 범위의 공급 계획부터 매장 판매까지 연결된 현황 |

업체, 업무 역할, 실제 시설은 분리한다. 한 업체가 제조와 식자재 공급 등 복수 역할을 맡을 수 있고, 한 공급사가 여러 브랜드·본부와 거래할 수도 있다. 본부 소유 시설과 외부 계약 시설을 구별하며, 브랜드 소속이라는 이유만으로 다른 업체의 모든 자료를 조회하거나 업무를 대신 확정하지 않는다.

플랫폼 총괄 운영자와 가맹본부 운영자도 별도 역할이다. 같은 앱에서 조회하더라도 자료 접근 범위와 명령 권한은 해당 계약·담당자 위임에 따라 구분한다.

## 공급 관계 층에 함께 기록할 항목

r33의 두 번째 층에서 기존 12개 재료를 같은 규칙으로 다루되, 물품 공급 관계와 운영 책임 관계를 함께 표현할 수 있도록 한다.

- 본부/브랜드 또는 운영망 참조, 참여 업체·역할·시설 참조.
- 관리 대상 재료·제품 규격·매장과 적용 기간·판본.
- 소유·공급·운영 위탁·관리 조율의 관계 종류와 확인 근거.
- 계약/담당자 위임 참조, 조회 범위와 업무 요청·확정 권한의 구분.
- 확인된 관계·추론 후보·미확인, 출처·기준 시각·결손 이유.

없는 실제 업체·거래·계약 ID는 만들어 채우지 않는다. 공공 레시피·HS·KAMIS는 품목/가격 참고 근거이며 특정 프랜차이즈의 실제 공급망을 증명하지 않는다. 소속되지 않은 음식점과 본부 밖 조달 경로도 표현할 수 있어야 한다.

## 기존 OS와의 조화

가맹본부 OS는 여러 업무를 연결해 관리하지만 제조·창고·화물·음식 판매 OS를 새로 복제하거나 원장을 합치지 않는다. 각 OS가 자기 업무의 상태 전이와 완료를 소유하며 본부 화면은 권한 범위 내 기존 조회 결과를 모은다. 업무 요청이 필요하면 기존 API/Command의 권한·현재 상태·revision 검증을 거친다.

예를 들어 매장 판매·재고 현황에서 보충 필요를 확인하고, 조달 계획과 제조·출고·운송·매장 인수 상태를 이어서 살펴볼 수 있다. 판매 실적을 조회했다는 사실만으로 발주·계약·결제·정산을 자동 실행하지 않는다. 실제 업무 실행은 기존 승인과 책임 경계를 따른다.

## 다음 단계와 미정

첫 층 r34의 구현·검증 사실은 그대로 유지한다. 다음 공급 관계 층의 검토에서는 물품 흐름만이 아니라 **누가 그 관계를 운영·조율하는가**도 같은 형식으로 조회할 수 있는지 확인한다. 품목 하나나 프랜차이즈 하나를 끝까지 확장하는 방식으로 개발 순서를 바꾸지 않는다.

미정: 실제 본부·공급사·매장별 계약 범위, 기존 ID/권한 계약과의 정확한 결속, 저장/조회 구현 경로. 이번 문서는 실거래 조사나 법률 적용 판단, 두 번째 층의 구현 완료가 아니다.

**다음 질문: 없음.** 이번에 정한 역할을 후속 공급 관계 설계의 기준으로 사용한다. 제품 코드·DB·Graph Map 원본·Unity·commit·push는 변경하지 않았다. 새 디오라마 규칙 후보 없음.
