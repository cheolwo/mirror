# 가맹 운영 앱 골격 r70

2026-11-09 사용자 요청으로 기존 음식점 앱에 읽기 전용 검토 화면을 연결했다. [공급·물류 r67](supplier-franchise-logistics.research.r67.md), [카페 운영 r68](cafe-store-operations.research.r68.md), [업종별 운영 정보 r69](franchise-category-operating-data.research.r69.md)의 후속이다.

## 페이지 책임

| 항목 | 이번 범위 |
| --- | --- |
| 사용자와 진입 | 음식점 운영자가 `가게 관리`에서 `가맹 운영 미리보기`를 연다. 앱의 기존 음식점 인증을 거치는 Debug 검토 경로다. |
| 화면의 질문 | 본부와 점포가 어떤 정보를 주고받고, 그 정보가 매장 업무에 어떻게 쓰이는가? |
| 기본 정보 | 공급업체 계약, 물류 준비, 가맹점 계약, 개점 준비, 첫 납품, 반복 공급의 담당과 확인 항목을 펼쳐 본다. |
| 시범 사례 | 카페 한 곳의 라떼·우유로 레시피 → 제조·폐기 → 실사 → 발주 초안을 따라간다. 표시 수량은 r68의 가상 표본이다. |
| 이어갈 업무 | 메뉴 등록·품절은 기존 메뉴 관리, 주문 진행은 기존 주문 수신함에 맡긴다. 미리보기에서 가게 관리로 돌아갈 수 있다. |

## 확장할 정보 구조

| 정보 | 기록하는 단위와 담당 |
| --- | --- |
| 업종·브랜드·점포 | 업종별 공통 항목은 재사용하고 실제 제조 방식과 운영 조건은 점포에서 확인한다. |
| 운영 단계와 근거 | 단계마다 담당, 확인 항목, 다음 인계에 필요한 결과를 둔다. 공개 자료와 내부 승인 자료의 출처·적용일을 구분한다. |
| 메뉴 기준 | 본부가 메뉴 옵션과 레시피 판본, 재료 규격과 단위를 정한다. 주문을 받을 때 적용한 판본을 주문 품목에 연결한다. |
| 매장 기록 | 점포가 받은 재료의 수량, 제조 사용량, 폐기와 실사를 기록한다. 확인된 잔량에서 발주 초안을 계산하고 점주가 확정한다. |

같은 구조에서 카페는 우유·원두와 추출, 피자는 도우·오븐, 족발은 선조리 배치와 판매 시한을 확인한다. 다음 연결 단위는 **가상 라떼 주문 품목 한 건과 우유 재고 이동 한 건**이다. 먼저 레시피 판본과 중복 처리 방지 키를 정하고, 제조 전 취소와 제조 후 폐기를 대조한다. 이번 화면의 수량과 발주 초안은 고정 예시다. 실제 저장과 발주 실행은 이 다음 단위의 검증 범위다.

## 확인한 화면

음식점 앱의 Razor 화면을 기존 로컬 미리보기에 연결했다. 실제 Chrome에서 320·390·1280px로 가게 관리 진입, 키보드와 클릭으로 운영 단계 펼치기, 우유 수량 표시, 주문 수신함 이동, 가게 관리 복귀를 확인했다. 메뉴 관리는 기존 `/menus` 경로를 연결했다. 미리보기는 합성 가게와 주문을 사용한다.
