# 생활상 상향식 구성과 확대별 자료 로드·해제 제안 r45

- 작성일: 2026-09-26
- 상태: 사용자 목표 기록 / 설계 제안 / 구현 승인·실행 전
- 요청: 지구본·행정구역 지도·디오라마에서 생활상을 표현하고, 상향식 개발 순서와 확대별 로드·해제 기준을 먼저 정한다.
- 관계: [자료 정밀화 r44](diorama-public-data-refinement.proposal.r44.md)는 공간 자료 준비, 이 문서는 그 공간 위 생활상의 표현과 수명 관리를 다룬다. [수평 적층 r33](horizontal-layer-development.plan.r33.md)·[관점별 역할 r37](franchise-platform-store-circulation.plan.r37.md)을 보존하며 기존 게임 기획이나 중지된 별도 작업을 활성화하지 않는다.

## 1. 제안의 중심

**생활 상태는 작은 행동에서 위로 쌓고, 관찰 화면은 멀리서 요약하다 가까워지면 같은 상태를 펼쳐 보여준다.** 확대할 때 새로운 세계를 만들거나 축소할 때 사람의 업무를 없애지 않는다. 장소·행동·출처를 먼저 연결하고 카메라 전환 연출은 그 위에 붙인다.

기본 화면은 일하는 사람, 이동하는 차량, 쉬거나 대화하는 주민 등 행동을 중심으로 한다. 글과 상세 근거는 선택했을 때 카드로 연다. 휴식·대화도 생활상 후보이며 모든 사람을 생산·배송 업무로만 표현하지 않는다. 단, 공개 통계만으로 특정 개인이 실제로 쉬거나 대화했다고 만들지는 않는다.

## 3. 상향식으로 쌓을 공통 층

1. **장소·주체·근거:** 사람/시설/차량/물품 ID, 활동 장소 또는 합성 기준점, 자료원·시간·판본·이용 범위와 결손을 연결한다.
2. **작은 생활 행동:** 준비·작업·대기·이동·인계·휴식 등의 시작/진행/종료와 실패·중단을 정의한다. 실제 업무의 완료 판정은 기존 OS, 가상 행동은 기존 Simulation이 소유한다.
3. **같은 행동의 표현 규칙:** 상태마다 간단한 자세/도형/애니메이션과 선택 카드를 연결한다. 한 건의 행동을 서로 다른 확대 수준에서 다른 정밀도로 표현한다.
4. **지역 요약:** 작은 행동들을 같은 시간 범위·자료원·판본으로 묶어 동·구·광역의 활동량과 이동 흐름을 만든다. 상위 숫자와 하위 객체를 중복 합산하지 않는다.
5. **로드·해제 연결:** 카메라가 요구하는 지역/정밀도에 맞춰 준비된 자료만 요청하고 표시·구독·자원을 정리한다.

각 층은 공통 계약을 얇게 만들고 독립 조회·시험까지 확인한다. 한 품목/도시 전체를 끝내야 다음으로 가는 방식도, 전국 데이터를 한꺼번에 내려받는 방식도 아니다. 장소가 준비되지 않은 행동은 미연결로 남긴다.

생활 기록의 최소 의미는 **누가, 어디서, 무엇을, 언제부터/어느 단계까지, 누구와, 어떤 근거로 하는가**다. 기존 Actor/Work/Area/Place ID·LifecycleStage·revision·시각·출처 종류를 대조하여 재사용한다. 단순 애니메이션용 별도 업무 원장을 만들지 않는다.

## 4. 확대 수준별 관찰·자료 정책 제안

다음은 관찰 단위다. 새 H1/H2/H3 정의나 고정된 기술 LOD 번호가 아니다. 행정 경계는 의미/집계 범위, 타일은 전송·메모리 단위, H는 기존 공간 의미 계층으로 구분한다. 역세권은 행정동과 겹칠 수 있으므로 반드시 동의 자식이라고 가정하지 않는다.

| 관찰 수준 | 눈에 보일 생활상 | 새로 필요한 자료 | 아래 수준에서 올라올 때 정리할 것 |
| --- | --- | --- | --- |
| 지구본 | 국가·권역 사이의 선박/항공 흐름 기호 | 가벼운 육지 윤곽·거점·통계 요약·출처 | 도시별 건물, 개별 사람/차량의 상세 표현과 조회 |
| 한반도·국가 | 광역 거점 사이 생활·물류 흐름 | 시도 경계·거점·검토된 간선 연결·권역 요약 | 시군구 이하 상세 메시·지역별 고빈도 조회 |
| 시도·도시권 | 시군구별 활동 밀도·물류 차량 대표 기호 | 시군구 경계·지역 요약·검토된 경로 | 동별 건물·주민 개체의 상세 자원 |
| 시군구 | 동별 상권·거점·생활 활동 묶음 | 읍면동 경계·거점·동별 활동 요약 | 비선택 동의 세부 시설·배우·애니메이션 |
| 읍면동·역세권 | 디오라마의 건물·도로·대표 사람/차량 | 승인된 공간 타일·시설·활동 상태 사본 | 시야 밖 블록의 상세 표현·사용하지 않는 구독 |
| 거리·시설·선택 대상 | 조리·상차·픽업·대화 등 가까운 행동과 상세 카드 | 선택 대상의 상세 상태·필요 자산·검증된 작업점/경로 | 상세 카드 자료·개별 애니메이션·선택 전용 자원 |

근거가 없는 광역 경로는 생성하지 않고 거점 또는 집계로만 표현한다. 통계에서 만든 선박 수는 실제 선박 추적과 구별하며, 광역 기호 하나를 확대했을 때 실제 운송 건 하나로 바꾸지 않는다. 실제 업무 ID가 연결된 대상만 같은 건으로 추적한다.

정확한 진입 거리는 지금 확정하지 않는다. 카메라 초점의 지상 가시 범위·화면상 크기·자료 해상도·장치 예산으로 결정한다. 한반도 밖을 보고 있는데 거리만 가깝다고 서울 자료를 로드하지 않는다. 초기에는 거리→동→구 세 수준에서 정책을 검증한 뒤 상위 지구본에 연결하는 순서를 제안한다.

## 5. 로드·전환·해제의 수명

**요청 → 준비 → 표시 → 비표시 대기 → 해제**를 구분하고, 자료 대기/실패도 정상적인 조회 결과로 남긴다.

- 입력 중에는 현재 부모 표현을 유지한다. 카메라 안정 뒤 최신 요청만 처리하며 기존 안정 요청 관문을 재사용한다. 초기 검토값은 안정 대기 약 0.5초, 화면 밖 상세 표현 정리 유예 약 5초를 제안하되 아직 확정값이 아니다.
- 현재 보이는 범위를 우선 요청하고 이동 방향의 인접 자료를 예산 내에서만 미리 준비한다. 행정동 전체를 한 번에 GameObject로 만들지 않는다.
- 자식 자료가 준비되고 좌표·판본이 맞으면 교체한다. 전환 중 부모/자식이 함께 그려져도 통계나 상호작용 대상으로 중복 등록하지 않는다. 실패하면 부모 요약과 자료 결손 표시를 유지한다.
- 요청에는 지역·확대 단계·필터·세션을 식별할 세대값을 두는 안을 검토한다. 빠르게 다른 지역으로 이동하면 이전 요청을 취소하고 늦게 도착한 응답은 현재 화면에 적용하지 않는다. 기존 취소 코드만으로 이 조건을 충족했다고 단정하지 않는다.
- 확대/축소의 진입·복귀 기준을 다르게 두어 경계에서 반복 켜짐을 막는다. 선택 대상은 예산과 권한이 허용하는 작은 상세 사본만 유지하고 주변 전체를 붙잡지 않는다.
- 비표시는 Renderer/애니메이션/선택 처리를 끄는 일이다. 실제 해제는 지역 구독·이벤트 핸들러·요청을 정리하고 전용 메시·텍스처·객체를 반환/해제하는 일이다. 공유 자산은 다른 지역의 참조가 남으면 해제하지 않는다.
- 동시 요청 수·캐시 바이트·풀 객체 수·활성 Renderer/Animator 수에 각각 상한을 둔다. 풀도 상한 밖은 반환/파기하며, 메모리 압박 때 사전 준비→화면 밖 상세→비필수 장식 순서로 줄인다. 구체 상한은 실제 장치 측정 뒤 결정한다.

## 6. 공간·상태·표현을 따로 유지

| 자료 종류 | 유지·해제 원칙 |
| --- | --- |
| 공개 공간 정적 자료 | 지역·레이어·판본/hash를 키로 캐시. 허용된 이용 범위 안에서만 디스크 보존하고 용량 상한 적용. 새 판본을 기존 타일과 무검증 혼합하지 않음 |
| 운영 상태 사본 | 기존 인증·읽기 전용·TTL·비식별 정책 유지. 관찰 지역 이탈 시 불필요한 조회/구독 중단, 만료 상태 제거. 로그아웃·권한 철회 시 즉시 메모리 삭제하며 Save/Replay·일반 캐시에 쓰지 않음 |
| 가상 생활 상태 | 기존 Local/Hosted Simulation이 소유. 화면 이탈은 표현 해제일 뿐 업무 취소·Actor 삭제·세션 재시작 명령이 아님. 화면 밖 계산 빈도 변경은 별도 결정성 검증 대상으로 남김 |
| Unity 표현 자산 | 화면 범위·선택·상세도·예산에 따라 생성/갱신/풀 반환. 재진입 때 최신 허용 상태를 읽고 과거 로컬 애니메이션 완료로 업무를 앞당기지 않음 |

운영 데이터·공공 통계·가상 시나리오는 출처를 구분한다. 자료 실패를 가상 생활로 조용히 대체하지 않는다. public 통계의 갱신 주기, 운영 사본의 TTL, 가상 Tick, 매 프레임 애니메이션은 서로 다른 시계다. 카메라 입력마다 서버나 외부 공공 API를 호출하지 않는다.

## 7. 첫 검토 범위와 인수 기준

추천은 기존 **City 한 지역의 음식 준비·픽업·전달 표본을 거리→동→구에서 같은 상태로 읽는 범위**다. 기존 사례·배치 기준점·권위 기록의 준비 여부를 먼저 확인하며 이번 제안만으로 실행하지 않는다. 실제 도로가 검증되지 않았으면 합성 작업점/경로임을 구별하고 실도로 주행으로 주장하지 않는다. Farm/Hub와의 통합이나 전국 지형 완성을 선행 조건으로 만들지 않는다.

1. 자료·생활 상태·표현의 소유자를 표로 정리하고 기존 ID/조회 경로를 연결한다.
2. 같은 상태 사본에서 상세 행동·동 요약·구 요약이 일치하는지 순수 시험한다. 상태 전진 예측, 중복 집계, 통계/실제 업무 혼합은 거절한다.
3. 가짜 시계/지연 응답으로 빠른 확대·축소, 요청 역전, 자료 결손·만료·권한 철회·부분 실패를 검사한다.
4. 실제 Unity에서 세 수준 왕복을 반복하며 Game View를 각각 남긴다. Console 신규 오류, 활성 객체/캐시/풀 상한, 해제 뒤 구독 잔존과 메모리 증가를 따로 점검한다.
5. 화면 밖에 있던 동일 업무가 최신 revision으로 다시 보이고 관찰 조작으로 권위 상태가 변경되지 않는지 확인한다. 그 뒤 새 생활상과 상위 지도 수준을 같은 계약으로 늘린다.

## 확정·미정·질문

확정: 생활상을 공간 위에서 관찰하며 확대별 자료 관리 규칙을 먼저 정리한다는 사용자 목표. 이번 작업은 조사·제안 문서까지다.

미정: 첫 표본 수용, 계층별 정확한 임계값·요청/메모리 예산·갱신 간격·기존 consumer의 구체 변경 경로. 0.5초/5초와 첫 표본은 제안값이다.

다음 질문 하나: **첫 검증은 기존 음식 배달 생활상 하나를 거리→동→구로 오가며, 상태는 이어지고 상세 표현만 로드·해제되는 범위로 잡을까?** 추천은 이 범위이며 승인 전 구현하지 않는다.

출처는 위 저장소 소스와 기존 검토 문서다. 이번에는 외부 수집·DB·제품 코드·Scene·실제 Play/Game View·commit·push를 수행하지 않았다. 기존 디오라마 규칙의 승격·무효화를 뒷받침할 새 실행 증거는 없으며 **새 디오라마 규칙 후보 없음**이다.
