- 기준일: 2026-09-25
- 상태: 사용자 방향 확정 / 단계와 첫 수집 명세 제안 / 구현·새 수집 전
- 선행: [메뉴 기반 조사 r28](delivery-menu-ingredient-research.plan.r28.md), [방문 기록 저장 r30](delivery-editorial-archive.implementation.r30.md), [수평 적층 r33](horizontal-layer-development.plan.r33.md), [재료 공통 기반 r34](ingredient-foundation.implementation.r34.md)

## 확정한 방향

사용자는 배달 영상을 만들고, 영상과 그 근거 기록을 분석해 정보를 하나씩 축적하며, 축적한 정보를 후속 영상이나 다른 결과물로 다시 만드는 흐름을 원한다. 이번에는 자료 수집을 단계적으로 세분화한다. 특정 영상 제작·자동 게시·정기 수집 실행까지 확정한 것은 아니다.

촬영 원본과 받아쓰기·방문 기록을 근거로 보관하고 편집 영상은 그 기록의 결과물로 연결한다. 편집으로 생략된 내용 때문에 원본 기록을 덮어쓰지 않는다. 같은 영상을 다시 분석한 결과는 새 방문으로 중복 집계하지 않는다.

흐름: 촬영 → 방문·메뉴 기록 → 배달 영상 → 자료 보충 → 분석 → 후속 콘텐츠 초안 → 확인된 정보와 수정 이력의 재사용.

## 단계별 범위와 완료 기준

| 단계 | 수집·처리 범위 | 결과물과 다음 단계 조건 |
| --- | --- | --- |
| 1. 하루 기록 | 기존 원본·받아쓰기·사용자 정정에서 날짜, 방문, 매장 지점, 메뉴 언급과 근거 시각을 정리 | 방문 누락·중복을 검사한 하루 목록. 미확인은 빈칸 대신 이유를 남김 |
| 2. 메뉴 자료 보충 | 매장·브랜드 공식 메뉴 설명을 우선 대조하고 일반 참고 레시피를 별도로 연결 | 메뉴별 출처·확인일·연결 이유·확인/후보/결손 상태가 있는 카드 |
| 3. 재료 자료 연결 | 확인된 설명과 참고 레시피에서 재료 후보를 구분해 기존 공통 재료 기반에 연결 | 공통 ID·규격·근거를 갖는 재료별 연결. 이름 유사성만으로 동일 품목 확정 금지 |
| 4. 기록 분석 | 내 방문의 반복 메뉴, 음식 유형, 공통 재료, 날짜별 변화와 자료 결손을 집계 | 분석 대상 날짜·기록 수·결손·계산법을 붙인 하루/주간 요약 |
| 5. 후속 콘텐츠 | 분석 항목마다 근거 기록을 연결해 설명 카드·대본·영상 구성을 작성 | 사실·참고·해석을 구분한 초안. 실제 제작과 공유는 선택한 초안 기준으로 진행 |

하루 전체 메뉴에 같은 기본 항목을 채우는 방식으로 진행한다. 품목 하나를 끝까지 깊게 조사한 뒤 다음 품목으로 넘어가는 방식으로 r33을 되돌리지 않는다. 가격·무역·공급 관계는 식별과 근거 연결이 준비된 뒤 필요한 분석에 맞춰 확장한다.

## 첫 단계 수집 명세 — 제안

기존 09.23·09.24 기록을 연결 점검 표본으로 삼고, 이후 새 하루 촬영분에 같은 규칙을 적용한다. 이번에 실제 기록을 다시 가져오거나 DB에 저장한 것은 아니다.

| 구분 | 남길 항목 | 처리 원칙 |
| --- | --- | --- |
| 방문 | 기록 ID, 날짜, 방문 번호·순서 | 같은 매장을 재방문해도 방문은 별도 유지 |
| 매장 | 발화·메모의 원문 상호, 정리된 상호·지점, 공개 주소의 확인 상태 | 같은 이름의 다른 지점 병합 금지. 기존 위치 정정 재사용 |
| 메뉴 | 발화·메모 원문, 정리된 메뉴명, 옵션·구성, 확인 상태 | 세트와 단품을 임의 분해하지 않음. 미언급은 메뉴 확인 대기 |
| 근거 | 원본 파일 식별·hash, 시각 구간, 사용자 정정과 확인일 | 영상 구간은 비공개 편집 대장에 유지. 홍달에는 기존 식별자로 연결할 계약을 먼저 대조 |
| 결과물 | 편집 날짜·판본과 해당 방문 기록의 연결 | MYBOX 공유본 교체와 방문 ID를 분리. 기존 자료의 판본 보존 |
| 조사 대기 | 새 메뉴 여부, 기존 자료 존재, 부족한 항목, 우선순위 이유 | 실패·미확인을 성공으로 처리하지 않음. 기존 자료가 유효하면 재수집 생략 |

촬영 중 매장 이름만 말하는 기존 방식도 허용한다. 메뉴가 기록되지 않았으면 영상에서 실제로 판독되거나 사용자 메모로 확인된 정보까지만 사용하고 상호로 메뉴를 추정하지 않는다. 사용자에게는 불확실한 항목을 하루 목록 하나로 묶어 제시한다.

첫 단계 완료는 같은 입력을 두 번 처리해도 방문·메뉴가 중복 생성되지 않고, 독립 재조회로 원본 근거와 정리 결과를 다시 찾을 수 있는 상태다. 사용자 정정은 이력과 영향을 남기고 관련 분석·대본에 재검토 필요를 표시할 수 있어야 한다.

## 자료 수집의 공통 규칙

- 촬영에서 관찰한 사실, 매장 공식 설명, 일반 참고 레시피, 분석 가설을 구별한다. 참고 레시피를 매장의 실제 배합·납품처·원산지로 확정하지 않는다.
- 매장·메뉴 설명은 새 항목이나 변경 확인이 필요한 항목부터 보충한다. 시세 등 시간에 따라 바뀌는 자료는 관측 날짜별로 보존하고 공급자에 맞는 갱신 주기는 별도로 정한다.
- 관찰한 배달 건수는 사용자의 촬영·방문 표본이다. 지역 전체 수요·매출·인기도로 일반화하지 않는다.
- 외부 사진·설명 원문은 출처 확인과 영상 재사용 권리를 별도로 관리한다. 자료를 읽을 수 있다는 이유로 후속 영상에 그대로 삽입하지 않는다.
- 개인정보 보호·주소/핀 검증 등 기존 영상 제작 조건은 유지한다. 추가 레시피 연구가 끝나야 기존 배달 영상 편집을 진행할 수 있는 새 의존성을 만들지 않는다.
- 기존 SQLite 편집 대장과 홍달 공공자료 저장소를 재사용한다. 새 DB, 운영 주문 생성, 자동 배차, 정기 수집 서비스, 자동 게시를 이번 기획으로 추가하지 않는다.

## 현재 결손과 다음 논의

기존 방문 저장·레시피 대조·재료 공통 조회는 부분 기반이다. 새 하루 입력의 일괄 처리, 새 메뉴 판별, 조사 대기 목록, 분석과 대본의 근거 연결, 정정 시 영향 전파는 연결 구현이 필요하다. 이미 자동화된 흐름으로 보고하지 않는다.

미정: 공식 메뉴 자료원 우선순위와 수집 가능 범위, 조사 갱신 조건, 첫 분석의 중심, 초안 결과물 형식.

후속 답변: 사용자가 메뉴 간 공통 재료 분석을 우선 선택했다. 이 질문은 종결하며 상세 수집 제안은 [r39](menu-ingredient-supply-analysis.plan.r39.md)에 기록한다. 기본 방문 기록은 근거로 유지한다.

이번 변경은 기획과 색인·현재 상태 문서뿐이다. 새 수집·DB 쓰기·분석 실행·영상 제작·자동화 설정·commit·push 없음.
