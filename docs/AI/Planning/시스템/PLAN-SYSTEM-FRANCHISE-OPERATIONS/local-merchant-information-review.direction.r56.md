## 이번 문답에서 확정한 방향

사용자는 실제 배달과 지역 소개를 몇 년간 이어가면서 자료·관계·소프트웨어를 함께 발전시키려 한다. 쇼츠는 현재 설정으로 약 한 시간에 편집할 수 있다고 설명했고, 이번 문답에서는 쇼츠 제작 개선을 제외했다. 이미 남는 방문·음식점·메뉴 기록의 재사용은 제외하지 않는다.

음식점 사장님이 자기 가게 정보를 확인하고 잘못된 부분의 정정을 요청할 수 있도록 미리 준비한다. 서울 동부 지역에서 사용자·가게·기사가 자신의 시스템을 선택해 이용하기를 바라는 장기 방향이다. 특정 업체의 대체 성공·시장 점유·가입·매출을 이미 이룬 것으로 기록하지 않는다. 새 운영 권역·출시일·가격·독점 이용 조건도 이번 답변으로 확정하지 않는다.

기존 자료를 기반으로 부족한 선택만 문답하고, 필요한 작은 보완을 검토하는 방식을 유지한다. 이번에는 새 앱이나 DB를 만들지 않는다.

## 준비할 흐름 — 제안

1. 기존 가게 식별자에 연결된 소개·위치·메뉴 등 자료와 출처·확인 시점을 조회한다. 구체적 첫 항목 목록은 미정이다.
2. 가게를 대표해 정보를 관리할 권한을 확인한다. 기존 로그인만으로 가게 권한을 자동 부여하지 않으며 확인 수단·위임 절차는 후속 문답 대상이다.
3. 현재 값과 요청 값을 구분해 정정 요청을 남긴다. 원본 방문 기록이나 공공자료를 조용히 덮어쓰지 않는다.
4. 요청의 검토·반영·보완 필요 여부를 요청자가 확인한다. 반영 주체와 시점은 아래 질문의 답변 전까지 미정이다.
5. 반영된 판본은 허용된 조회·표현에서 재조회한다. 조회 가능한 범위나 Unity 사용 권한을 자동 확대하지 않는다.

자료 열람·정정 참여가 서비스의 첫 접점이 될 수 있다는 제안이며, 가입 유도나 실제 상인 연락을 실행하는 지시가 아니다. 실제 사용에서 확인된 입력 부담·정정 결과를 보고 후속 앱 보완 범위를 정한다.

## 기존 경계 유지

- 공개된 가게 자료, 당사자의 설명·정정 요청, 플랫폼 판매 메뉴와 주문 수신 상태는 같은 사실이 아니다. 정보 정정만으로 판매·주문·배차를 활성화하지 않는다.
- 관찰 메뉴와 일반 참고 레시피·재료 연결은 구분한다. 확인 전 실제 가게의 배합·원산지·매입처로 표시하지 않는다.
- 정정 요청 수락과 실제 반영을 구분한다. 요청 접수만으로 조회 화면의 정본이 바뀌었다고 표시하지 않는다.
- 확인되지 않은 개인정보·증빙을 공개 자료에 포함하지 않는다. 소유 확인 자료의 보관·접근·철회는 구체 구현 전 별도 결정한다.
- 영상 게시·수정·제외 요청 절차와 가게 정보 정정을 혼동하지 않는다. 이번에는 영상 편집·게시 기능을 바꾸지 않는다.
