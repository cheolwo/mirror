# 공공 공간자료 수집 우선과 촬영 위치 기록 연결 r43

[기획·수집 · 거리·부지 정밀화 · PLAN-SYSTEM-FRANCHISE-OPERATIONS · r43]

- 기준일: 2026-09-26
- 사용자 방향: 촬영할 때 길 이름·번호를 말로 남길 수 있다. 지금은 공공데이터를 수집해 디오라마의 공간 근거를 먼저 정밀화한다.
- 변경: [r42](diorama-existing-data-first.proposal.r42.md)의 기존 사본 점검 중심 우선순위를 **공식 공간자료 접근·수집·축적 우선**으로 구체화한다. 촬영물 전달은 수집 시작 조건이 아니다.
- 실제 진행 범위: 공식 자료 접근 확인, 공개 도로명 파일 한 묶음 확보, 중랑구 핵심 4개 도로의 참고 식별자 소표본 검사. 실제 건물/도로 형상·Unity 화면 정밀화 완료와 구분한다.
- 후속 상태: 사용자 최신 요청 “그냥 있는 거를 바탕으로 일단 좀 제안서를 작성을 해줘”에 따라 [r44 제안서](diorama-public-data-refinement.proposal.r44.md)로 정리했다. 아래 저장 절차는 준비 상태이며 DB 반입은 실행하지 않았다.

## 1. 역할을 나누는 방식

공공자료에서는 지역 경계, 건물 도형·높이, 도로와 출입구의 위치·관계를 축적한다. 사용자의 촬영에서는 길 이름·건물번호·매장명·바라보는 방향과 최근 외관 변화를 보완한다. 두 자료가 동일 대상을 가리키는지 확인한 뒤 공간에 연결한다.

촬영 멘트는 예를 들어 **“도로명 ○○, 건물번호 ○○, ○○매장 앞, ○○ 방향”** 정도면 충분하다. 방문 순서 번호와 실제 주소의 건물번호는 구분한다. 골목 이름에 포함된 `○○길` 숫자도 건물번호와 섞지 않는다. 녹음한 번호가 공식 주소와 맞는지는 나중에 대조하며, 발화만으로 건물·입구를 확정하지 않는다.

## 2. 정밀화에 필요한 공공자료의 우선순위

| 순서 | 자료 | 공간에 주는 개선 | 다음 완료 조건 |
| --- | --- | --- | --- |
| 1 | 현행 행정구역 경계 | 정확한 지역 범위와 소속의 기준 | 공식 원본의 기준월·해시·좌표계·대상 30개 코드·도형 검증 |
| 2 | 같은 배포 세대의 건물·건물군 도형 | 건물 윤곽, 건물군과 개별 건물의 관계 | 공식 연결 키 보존, 미연결·복수 후보 구분 |
| 3 | 주소 기준 출입구와 연결선 | 건물 접근 지점 후보 | 주소/건물군의 출입구인지 개별 건물 출입구인지 대조 |
| 4 | 도로·실폭도로·보도·횡단보도·높이 보완 | 이동 공간과 높낮이 참고 정밀화 | 자료별 기준일·단위·형상/통계 구분 후 연결 |
| 병행 | 공개 도로명·주소 식별자 | 촬영 발화와 장소 후보를 연결하는 사전 | 공식 도로 코드·법정동 연결을 보존하고 위치를 추정하지 않음 |

기존 [현행 경계→건물/건물군→출입구 수집 관문 r16](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/current-boundary-building-entrance-collection-gate.decision.r16.md)을 먼저 대조했다. 공개 도로명 참고 사전이 확보돼도 이 관문의 도형 수집·current 결속 상태를 통과시키지 않는다. 한 단계의 접근 대기가 다른 독립 공개자료 조사까지 막지는 않는다.

## 3. 공식 제공 경로에서 실제 확인한 상태

공식 [주소정보 다운로드](https://business.juso.go.kr/jst/jstAddressDetailsSearch)의 제품 카탈로그·제공 달력과 브라우저 표시를 확인했다. 개별 제품은 화면 내 선택 상태를 사용하므로 목록 URL과 제품 번호를 함께 기록한다.

| 제품 번호 | 제품명 | 현재 확인한 제공 방식 | 달력상 최신 월 |
| --- | --- | --- | --- |
| 24 | 구역의 도형 | 제공하는 주소, 장바구니·신청 경로 | 202608 |
| 16 | 도로명주소 건물 도형 | 제공하는 주소, 장바구니·신청 경로 | 202608 |
| 17 | 건물군 내 상세주소 동 도형 | 제공하는 주소, 장바구니·신청 경로 | 202608 |
| 15 | 도로명주소 출입구 정보 | 제공하는 주소, 장바구니·신청 경로 | 202608 |
| 6 | 도로명 | 공개하는 주소, 직접 다운로드 | 202608 |

앞 네 제품은 신청 전에 본인확인을 검사하는 경로가 있다. 신청·본인확인·약관 동의·제출은 실행하지 않았다. 사용자의 해당 계정 권한을 확인하거나 승인이 거절된 것은 아니다. 원본 파일을 받지 않았으므로 달력의 월을 실제 도형 파일의 판본·hash 검증으로 대신하지 않는다.

`구역의 도형` 화면의 행정동 레이어는 `TL_SCCO_GEMD`, 코드 필드는 `EMD_CD` 문자10으로 표시됐다. 실제 파일의 CRS·내용은 아직 미검증이다. 건물 도형 제품은 집합건물을 건물군으로 제공할 수 있고, 출입구 제품도 주소 기준 주·보조 출입구이며 집합건물의 개별 동 단위가 아님을 설명한다. 따라서 출입구 점 하나를 모든 개별 건물의 입구로 복제하면 안 된다.

핵심 도형의 가장 이른 재개점은 공식 목록에서 위 제품의 본인확인·자료 신청을 진행하고 승인된 원본을 확보하는 것이다. 대상은 서울 중 기존 30개 행정동 범위를 포함하는 제공 단위로 좁히며, 이번에는 임의 신청 목적을 작성하거나 외부 제출하지 않았다.

도로명코드는 시군구코드5자리와 도로명번호7자리의 조합이다. 읍면동일련번호 `00` 총괄행과 개별 법정동 행을 보존했다. 법정동을 행정동으로 바꾸거나 도로명을 기준으로 행을 합치지 않는다. 선택11행의 사용여부는 공식 원문 `0`(사용)이었으며, 이는 도로명 사용 상태이지 매장 영업·도로 통행 상태가 아니다.

시작·끝 기초번호도 원문 그대로 보존한다. 이 범위에 포함된 모든 번호의 건물이나 출입구가 존재한다고 추정하지 않는다.

원본·제품 카탈로그·제공 달력·수집 영수증은 `artifacts/local/public-data/diorama-spatial-20260926-r1/`에 비공개 보존한다. 최초8MiB 상한에서는 다운로드를 중단해 파일을 쓰지 않았고, 공식 HEAD로 12,129,067 bytes 단일 파일을 확인한 뒤 16MiB 상한의 한 파일 다운로드로 확보했다. 완료 원본을 다시 다운로드하는 방식으로 중복 검증하지 않는다.

## 5. 저장과 검증

기존 ASP.NET Core 프로젝트를 참조하는 공공자료 CLI에 `juso-road-name-preview|self-test|apply|verify`를 추가한다. 원본 등록 서비스·기존 공공자료 MySQL 테이블을 재사용한다. 새 DB·테이블·권한 변경이나 전체 마이그레이션은 필요하지 않다.

현 로컬 컨테이너는 `hongdal-mysql-1`, 실제 확인한 공공자료 DB는 `hongdal_dev`, 포트는 루프백13306이다. 현재 컨테이너 환경의 기본 DB 표기와 실제 조회 권한이 달라, 기존 비root 계정과 명시적 로컬 연결 설정으로 확인된 DB만 사용한다. 기존 연결 보호를 완화하거나 연결 비밀을 명령줄·문서에 출력하지 않는다.

저장 대상은 도로명 참고11행과 원본의 해시·비공개 경로 계보다. 원본 ZIP 바이트를 DB에 통째로 복제하는 방식은 아니다. 출처·판본·원본 행·필드를 보존하고 `PendingHumanReview`, 비공개, 공개/Runtime/건물·출입구 결속 없음으로 관리한다.

실제 실행은 빌드 성공(오류0·경고0), 로컬 preview의 372,063행 중 11행 선택, 자체검사25건 통과까지다. 최초 검사의 수집시각 UTC 형식 오류는 동일 시각의 UTC 표기로 바로잡은 뒤 재검사했다. 보존 결과의 `databaseWriteAttempted=false`, `committed=false`, `unityApplied=false`를 확인했다. DB 반입·독립 재조회·DB 동일 입력 재실행은 미실행이며, 최신 사용자 요청으로 후속 제안만 작성한다. 파일 수신·로컬 검사를 DB 반입 완료로 확대하지 않는다.

## 6. 이용조건과 증거 한계

공식 카탈로그에서 제품6은 공개 다운로드로 표시됐다. 개별 공공누리 유형과 보관기간의 명시 표기는 확인하지 못했으므로 임의로 유형을 부여하지 않는다. 이번 저장은 공식 공개 파일의 출처를 보존하는 비공개 검토 범위다.

[현재 일반 이용약관](https://www.juso.go.kr/Terms)은 2026-08-20 시행본이다. 과거 공식 Q&A의 공개 데이터 활용 안내는 검색 색인으로만 확인했으며 현재 직접 본문 열람은 실패했다. 과거 안내를 현행 제품의 재배포·상업적 이용 조건 확정으로 확대하지 않는다. 원본 영수증의 `OfficialPublicDownloadPrivateReview`는 내부 보관·검토 범위 표시이며 자유이용 라이선스 코드가 아니다.

독립 후보로 [서울시 보도통계자료 OA-22240](https://data.seoul.go.kr/dataList/OA-22240/F/1/datasetView.do)도 확인했다. 공식 페이지에 `서울시 보도 통계자료_2025.xlsx` 0.56MB, 파일 수정일2026-09-15, 연간 갱신·공공누리1유형, 노선별 폭·포장 등의 제공이 표시된다. 이번에는 해당 XLSX 원본을 수신하지 않았다. 보도 통계는 정확한 보행면 polygon이나 특정 문 앞의 폭을 대신하지 않는다.

## 7. 다음 작업과 현재 결론

**확정:** 공공데이터의 수집·축적을 우선하고 촬영 멘트는 나중에 장소를 연결하는 보완 근거로 쓴다. **현재 진척:** 공식 도형 제품의 접근·신청 경로를 확인하고 공개 도로명 원본과 핵심4도로의 참고 관계를 확보했다. **남은 핵심:** 승인된 행정구역·건물·출입구 원본 확보와 검증, 실제 공간 반영이다.

공식 도형 확보 후 경계→건물/건물군→출입구 순서로 수집·저장·독립 재조회를 진행한다. 그 사이에는 사용 조건과 입력을 확인할 수 있는 보도 통계 같은 독립 자료를 비공개 후보로 보충할 수 있다. 현재 공간의 정확도가 높아졌다고 보고하는 시점은 자료 결속과 공간 검증이 끝난 뒤다.

이번 수집은 Unity/Scene/Prefab·영상·MYBOX·리셋권을 변경하지 않는다. 새로운 현장 관찰에 따른 규칙 승격은 없으며 **새 디오라마 규칙 후보 없음**이다.
