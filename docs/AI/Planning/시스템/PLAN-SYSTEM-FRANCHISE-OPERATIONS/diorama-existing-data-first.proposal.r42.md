- 상태: 사용자 제약 반영 / 실행 순서 제안 / 구현 미착수

## 1. 무엇부터 할 것인가

**첫 작업은 저장된 사가정 건물·도로 자료를 점검하고, 그 결과를 작은 구간의 검토 지도로 보여 주는 것이다.** 새 촬영물을 받지 않아도 자료의 잘못된 연결·중복·좌표 이상·높이 결손을 드러낼 수 있다. 그다음에는 확인된 항목과 임시 표현을 분리해, 나중에 촬영값이 들어온 대상만 바꾸는 구조를 준비한다.

추천 순서는 **기존 사본 진단 → 후보 구간 평면도 → 개별 교체 구조 → Unity 표시·선택 검증 → 촬영 기반 외관 보완**이다. 첫 완료 조건에서 '매장 3곳의 실제 외관과 입구를 완성한다'를 뺀다. 현재 자료만으로 끝낼 수 있는 결과를 먼저 쌓는다.

사용자가 당장 영상을 전달하거나 추가 촬영 일정을 확정할 필요는 없다. 기존에 접근 가능한 방문·매장 기록은 보조로 대조하되, 새 영상이나 미확인 매장 연결이 없다는 이유로 자료 점검 전체를 멈추지 않는다.

### 첫 작업의 상세 범위

우선 `SagajeongReference.json` 사본과 관련 보완 자료의 판본·파일 해시를 고정한다. 구조 검사는 ID 중복, 비정상 숫자, 범위 이탈, 퇴화한 건물 윤곽, 도로의 길이 0 구간, 높이 근거 누락을 다룬다. 윤곽 폐합 방식은 기존 형식의 계약을 확인한 뒤 판정한다.

사본 간 결속은 원본 ID와 적용 대상 판본을 기준으로 확인한다. 비슷한 이름이나 가장 가까운 좌표만으로 건물·매장을 자동 확정하지 않는다. 좌표 변환의 일관성과 데이터 내부 연결은 검사할 수 있지만 현재 현장 위치·폭·높이의 정확도는 별도 근거가 필요하다.

검사 결과는 `오류 / 주의 / 미확인 / 통과 / 미실행`을 구분한다. 남은 오류가 있다면 영향받는 대상과 가장 작은 수정 단위를 제시한다. 원천 검사를 생략한 실행이 전체 검사 성공으로 집계되지 않도록 한다.

### 구간은 어떻게 정할 것인가

기존 사가정 범위 안에서 도로·건물 자료가 충분하고, 좌표·대상 결속에 충돌이 적으며, 향후 사용자가 재촬영하기 쉬운 구간을 우선한다. 처음에는 약 100~200m를 비교 범위의 초깃값으로 쓰되, 데이터 상태에 맞춰 줄일 수 있다.

기존 방문 기록과 확인된 건물 연결이 있으면 가산 요소로 활용한다. **매장 3곳의 연결이나 외관 확인을 시작 조건으로 강제하지 않는다.** 특정 매장의 동일성이 해결되지 않으면 건물 ID를 기준으로 공간 검토를 계속하고 해당 매장 연결만 미확인으로 남긴다.

후보 지도는 도로 중심선과 건물 윤곽을 우선 보여 준다. 높이 근거와 상징값은 구분하고, 없는 보도 폭·출입구·필지 경계는 실제 값처럼 채우지 않는다. 자료 사용이 허용된 검토 범위 안에서만 출력한다.

## 4. 영상 없이 개선할 수 있는 모습

첫 화면은 기존 도로와 건물 배치를 정리한 간단한 공간이다. 건물을 선택하면 자료가 있는지, 높이가 근거값인지 임시값인지, 무엇을 추가 확인해야 하는지를 볼 수 있도록 한다. 상세 근거는 검토 화면에 두고 일반 관찰 화면은 간단하게 유지한다.

기존 구조 안에서 다음 항목은 영상 전달 전에 개선할 수 있다.

- 건물·도로 선택이 어느 원본 대상과 연결되는지 확인하는 기능.
- 확대해도 기준점·대상 ID가 바뀌지 않는 관찰 흐름.
- 원본 형태와 보완 후보를 비교하고 한 대상만 교체하는 기능.
- 근거가 빠진 후보를 거절하고 기존 표현을 유지하는 동작.
- 화면을 다시 열 때 중복 배치나 이전 선택이 남지 않는지 확인하는 절차.

공통 외관 부품은 필요한 최소 범위만 준비한다. 임시 벽·지붕·표식은 명확히 임시 표현으로 두고 특정 매장의 실제 간판·문·창문을 재현했다고 설명하지 않는다. 첫 단계의 성과는 **자료 일관성, 판독성, 교체 가능성, 화면 안정성**으로 평가한다.

## 5. 나중에 영상을 받으면 이어 할 작업

영상이 들어오면 처음부터 다시 만들지 않고 다음 순서로 보완한다.

1. 기존 구간 ID·건물 ID와 촬영 장면을 연결한다. 식별이 애매하면 해당 연결만 확인 대기로 둔다.
2. 정면 방향, 실제 입구, 간판 위치, 창문·캐노피, 계단·경사 등 관찰 가능한 항목을 채운다.
3. 실제 치수 근거가 확보된 항목만 축척과 오차를 검토한다. 영상만으로 정확한 미터값을 확정하지 않는다.
4. 해당 건물의 보완층만 교체하고 기존 사본 기준 검사와 실제 화면 검증을 반복한다.
5. 촬영 시점에 맞춘 비교 장면으로 현장과의 유사성을 확인한다. 영상 제작은 이후 편집 요청과 기존 편집 전 검증 절차에 따라 진행한다.

전달 전에는 사용자가 원본 파일을 보관하고 촬영일·매장명·거리 방향 정도만 남겨도 된다. 복잡한 양식 입력이나 별도 편집본 제작은 지금 필요하지 않다. 원본·타임코드·고객 정보는 공개 방문 계약이나 MYBOX 완성 영상 공유 폴더로 옮기지 않는다.

## 6. 리셋권을 활용할 작업 묶음

리셋권의 실제 수량·만료는 미확인이다. [r41의 사용량 계획](delivery-street-diorama-detail.proposal.r41.md#7-codex-리셋권을-어떻게-배분할-것인가)을 이어 쓰되, 당분간 새 촬영에 의존하지 않는 아래 작업에 집중한다. 각 묶음은 리셋 한 장으로 완료된다는 약속이 아니다.

| 묶음 | 권장 작업 노력 | 집중할 결과 |
| --- | --- | --- |
| A. 기존 자료 점검 | 30% | 사본·결손 목록, 좁은 검사와 오류 진단 |
| B. 구간 비교 | 25% | 검토 지도와 추천 구간 |
| C. 교체 구조 | 25% | 보완층의 개별 적용·거절·복구 |
| D. 실제 표시 검증 | 20% | Unity 동작·회귀·재개 기록 |

리셋 전에 다음 묶음의 입력과 허용 수정 경로, 완료 조건을 준비한다. 촬영 대기나 원천 파일 부재가 원인이면 해당 단계만 보류하고 독립적으로 끝낼 수 있는 작업을 진행한다. 같은 원천 접근 실패를 반복하는 데 추가 사용량을 쓰지 않는다.

자료 점검과 검토 지도 제작은 공유 입력 형식을 정한 뒤 분업할 수 있다. 공통 좌표 변환·식별자와 Unity Scene 통합은 담당자를 하나로 정해 충돌을 줄인다. 기존 검증·조립 코드 재사용을 우선하며, 광범위한 리팩터링이나 새 공통 프레임워크 제작은 첫 완료물에 포함하지 않는다.

## 7. 첫 완료물과 실행 경계

첫 목표는 **'촬영 자료를 받으면 대상만 보완할 수 있는 사가정 한 구간의 검토 기반'**이다.

- 대상별 오류·결손을 담은 자료 진단표와 재실행 방법.
- 기존 자료에서 고른 구간 1개와 근거가 표시된 비공개 검토 지도.
- 건물 하나의 보완 후보 적용·거절·복구를 확인한 기록.
- 기존 자료 기준 Unity 전체/확대 화면과 선택·재진입 검증 기록.
- 이후 촬영으로 채울 항목만 남긴 짧은 보완 목록.

현재는 이 완료물의 **제안 단계**이며 검사기·지도·모델·Game View를 새로 제작한 상태가 아니다. 후속 구현은 해당 작업 범위와 저장소의 기획·명세 절차에 맞춰 진행한다. 자료가 `PrivateReviewOnly` 또는 `Blocked`인 상태, 별도 출구 Blender 기획의 중지 상태는 이 제안으로 해제되지 않는다. 기존 허용 사본의 관찰 개선과 차단된 신규 자료 적용을 구분한다.

**확정:** 새 영상은 현재 전달받을 수 없으므로 기존 자료로 가능한 작업을 앞당긴다. **미정:** 추천 구간의 정확한 위치와 후속 촬영 전달 시점. **다음 질문:** 지금 없음. 첫 실행은 추가 입력 없이 접근 가능한 사본 목록·내부 일관성 점검부터 시작하도록 제안한다.
