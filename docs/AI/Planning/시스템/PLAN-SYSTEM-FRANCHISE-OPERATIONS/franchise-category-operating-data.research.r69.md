기준 정보는 판본과 효력 기간을 기록한다. 거래와 작업은 행위 시각·기록 시각·고유 ID를 두고 중복 전송을 막는다. 정정은 원 기록에 근거를 연결한다. 판매 가능량·예상시간·이론 소모량·손익은 기준과 사건에서 계산하며 계산 시점과 가정을 함께 남긴다. 원재료와 제조품 재고는 로트나 배치에 연결한다. 품질 실측에는 측정 대상·항목·단위·시각·담당자와 적용 기준 판본을 연결한다. 예를 들어 장비 설정 온도, 원료 입고 온도, 조리품 중심 온도는 각각 다른 기록이다.

주문에는 판매 당시 변형·단가·레시피 판본을 보관한다. 취소로 준비 전 예약을 돌려줄 때와 실제 투입 뒤 폐기하거나 다른 용도로 전환할 때를 구분한다. 가용 재고는 검사 통과 수량을 기준으로 계산하고 격리품은 승인 전까지 제외한다. 정보가 없으면 미확인, 해당 공정을 수행하지 않으면 해당 없음, 실제 0은 0으로 표시한다.

## 프로젝트에서 재사용할 정보

통합 DB의 기존 매장·메뉴·주문 품목·참고 레시피 ID를 후속 연구에서 재사용한다. 앱 관측 메뉴의 연결 근거와 공시 브랜드 식별은 별도 검증한다. 공개 레시피, 본부 승인 레시피, 점포의 실제 사용·폐기는 각각 출처와 상태를 기록한다. 브랜드·점포와 분류는 복수 관계를 허용하고, 판매 변형은 적용 점포·채널과 기간별 승인 레시피에 연결한다. 공통 작업·로트 기록에 업종에서 필요한 항목을 붙이면 피자와 카페의 오븐 작업, 치킨과 족발의 원육 로트를 같은 구조로 기록할 수 있다.

## 조사한 정보를 운영에 적용하는 순서

1. 업종별 대표 메뉴 한 개씩에서 주문 옵션, 필요한 SKU와 단위, 작업 순서, 재고와 장비 한계, 폐기 판단을 목록화한다. 이름이 같은 정보라도 단위와 계산 기준을 맞춘다. 예를 들어 생족 g과 가식부 g, 피자 한 판과 한 조각, 주문 수와 제조 잔 수를 구분한다.
2. 공개 메뉴·정보공개서에서 확인한 값, 제조사 사양, 가맹본부 승인 기준, 점포 실측, 모의 가정을 각 행에 표시한다. 증거가 부족하면 추정으로 채우는 대신 필요한 자료와 확인 담당을 남긴다. 가격·유효기간·점포/채널 적용은 변동 시 새 판본으로 기록한다.
3. 같은 주문 기록에 네 가지 예외를 대입한다. 치킨 솥 점검은 조리 약속시간, 피자 도우 부족은 특정 크기 품절, 족발 판매시한 경과는 해당 배치 격리, 카페 우유 품절은 영향 음료 판매 상태에 반영된다. 원재료 부족과 장비 용량 부족을 분리하면 품절과 대기시간을 각각 안내할 수 있다.
4. 현장에서는 주문당 실제 소모·폐기, 약속과 실제 인계 차이, 품절·격리 시간, 작업대별 처리량을 수집한다. 월별 가맹점 손익과 본부 공급 손익은 같은 거래를 각 당사자 관점에서 대조한다. 초기에는 관측을 통해 작업 기준과 발주량을 수정할 근거를 확보한다.

모의 예로 족발 배치 하나의 가식부가 4,800g이고 중 사이즈가 320g이면 중 사이즈만 팔 때 최대 15개를 준비할 수 있다. 같은 배치에서 대 사이즈 480g 주문을 하나 받으면 중 사이즈는 최대 13개가 된다. 남은 유효 재고에만 주문 예약을 걸어 여러 채널이 같은 물량을 중복 판매하지 않게 한다. 배치가 승인된 판매 가능 시한을 넘기면 남은 물량을 격리한다. 수량과 시간은 해당 점포의 실측과 승인 기준으로 채운다.

확정한 범위는 네 업종의 정보 조사와 공통·특화 항목 구분이다. 실제 브랜드의 공시 업종 매핑, SKU·레시피 기준, 점포별 기한·장비 성능은 확인이 필요하다. 다음 검토 질문은 카페의 주문 후 제조와 족발의 선조리 후 판매를 한 번씩 대조해 공통 기록 구조를 먼저 검증할지다.
