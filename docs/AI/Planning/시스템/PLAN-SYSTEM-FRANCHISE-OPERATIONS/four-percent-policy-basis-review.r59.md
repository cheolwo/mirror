# [기획 · 정산·4% 기준 대조 · PLAN-SYSTEM-FRANCHISE-OPERATIONS · r59]

> 후속 [r60 기존 목표 유지와 앱 완성](delivery-app-parallel-completion.direction.r60.md): 사용자가 기존 영업이익 4% 목표 유지를 확인했다. `four-percent-fee-or-margin-basis`는 종결하며 아래 `Asked`는 당시 문답 이력이다. 건당 4% 수수료로 변경하지 않는다.

- 기준일: 2026-09-28.
- 상태: `ExistingOperatingProfitTargetLocated / CurrentFourPercentMeaningAsked`.
- 선행: [본인 정산의 플랫폼 수수료 표시 r58](participant-platform-fee-visibility.decision.r58.md). 이번에는 금액 기준을 먼저 확인하고 주문자 표시 질문은 보류한다.

## 최신 사용자 말씀과 기존 기준

사용자는 플랫폼 수수료를 언급하며 “4% 정도만 남기고” 처리하는 기준으로 진행하길 원한다고 말했다. 4%라는 기준을 사용하려는 의향은 확인되지만, 거래에 부과하는 수수료율로 변경하려는지 기존 이익 목표를 다시 지칭한 것인지는 확정하지 않는다.

기존 [사용량·구독 기획의 영업이익 4% 목표](../PLAN-SYSTEM-USAGE-COST-SUBSCRIPTION-METERING/README.md#영업이익-4-목표와-자금-순환)는 플랫폼 보유 매출 대비 약 4%를 기간 영업이익 목표로 정한다. 같은 기준은 [주문자 구독 경제성 r9](../PLAN-SYSTEM-USAGE-COST-SUBSCRIPTION-METERING/orderer-subscription-preferred-driver-economics.r9.md)에도 연결되어 있다.

- **기존 목표:** 플랫폼 보유 매출에서 운영비용을 뺀 영업이익 후보 / 플랫폼 보유 매출 ≈ 4%.
- **다른 의미:** 정해진 거래 금액 × 4%를 플랫폼 수수료로 청구. 이는 기존 목표와 다른 과금 정책이며 이번에 도입하지 않는다.

플랫폼 보유 매출에는 계약상 플랫폼에 귀속되는 구독료·용역 대가를 쓰고, 다른 주체에게 전달할 상품대금·기사 대금·환불금 등 통과자금을 분모로 합치지 않는 기존 경계를 유지한다. 구체 회계 인식·실제 운영 적합성을 이번 대조만으로 확정하지 않는다.

## 이번 문답의 처리

1. r58의 사장님·기사님 본인 거래 수수료/계산 기준 표시 결정은 유지한다. 표시 결정이 수수료율 4% 확정은 아니다.
2. 기존 사용량·구독 기획을 금액 기준의 원문으로 연결한다. 이번에는 과금 정책·가격·요율·계약·구독 모델을 변경하지 않는다.
3. 4% 이익 목표를 지급 보장, 주문마다 이익이 난다는 보장, 자동 배분 가능한 현금으로 취급하지 않는다. 지급 의무·운영비·유보금과 실제 순환 가능 현금의 판정은 기존 기획을 따른다. 나머지 96%를 자동 배분한다는 뜻도 아니다.
4. r58의 `orderer-own-platform-fee-visibility` 질문은 `DeferredPendingFeeBasisClarification`이다. 사용자 답변을 주문자 공개 범위의 일괄 동의로 해석하지 않는다.

## 미정 / 다음 질문 하나

- 미정: 이번 4% 발언이 기존 기간 이익 목표의 유지인지, 새 거래 수수료율로의 변경인지.
- 질문 의미 ID: `four-percent-fee-or-margin-basis` / `Asked`.
- 다음 질문: **이번에도 주문마다 4%를 떼는 수수료가 아니라, 운영비를 뺀 뒤 플랫폼 매출의 약 4%를 영업이익으로 남기는 기존 목표를 말씀하신 것이 맞을까?**
- 추천: 기존 목표를 유지하되 사용자 의도를 먼저 확인한다. 새 수수료율을 원하면 계산 대상 금액과 부담 주체를 별도 후속 문답으로 정한다. 이 질문에서는 그 둘까지 함께 승인받지 않는다.

## 작업 범위
