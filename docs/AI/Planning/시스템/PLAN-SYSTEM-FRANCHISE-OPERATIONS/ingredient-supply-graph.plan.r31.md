## 확정한 방향

메뉴와 재료를 가격표로만 나열하지 않고, 재료가 제조시설에 입고되고 가공된 뒤 음식점에 납품되는 관계를 따라가며 이해할 수 있게 한다. 공공자료를 실제 업체의 거래 사실로 해석하지 않는다. 현재 목표는 자료 관계 정리이며 실제 발주·입고·제조·납품 기록이나 Unity 객체를 생성하는 것이 아니다.

저장은 기존 관계형 테이블·업무 원장을 활용하고 화면에서는 노드·엣지로 조회하는 방식을 제안한다. 관계형 DB와 그래프 표현은 양자택일이 아니다. 새 그래프 DB나 범용 Map Manager를 먼저 도입하지 않는다.

## 이해용 관계도

아래는 연결할 의미를 설명하는 모식도다. 특정 제조시설·음식점의 실제 거래 또는 이미 실행되는 종단 기능을 나타내지 않는다. 실선은 물품 처리 절차, 점선은 분류·통계 참고 관계다.

```mermaid
flowchart LR
    material["원재료 묶음"] --> receiving["제조시설 입고·검수"]
    receiving --> processing["가공 작업"]
    processing --> product["가공품 묶음"]
    product --> shipment["출고·운송"]
    shipment --> acceptance["음식점 입고·인수"]
    evidence["HS·가격 통계 근거"] -.->|"원재료 규격 참고"| material
    evidence -.->|"가공품 규격 참고"| product
```

가격 근거는 물품을 공급하는 주체가 아니다. 무역 통계만으로 특정 수출자 → 제조업체 → 음식점의 납품선을 만들지 않는다. 실제 인수와 메뉴 조리 사용도 별개이며, 공개 레시피 연결은 일반 구성 참고로만 표시한다.

## 노드와 관계의 최소 의미

| 노드 | 구별할 내용 | 관계 예시 |
| --- | --- | --- |
| 업체·시설 | 운영 주체와 실제 작업 장소를 분리 | 시설에서 수행, 발송지, 인수지 |
| 재료·제품 규격 | 원물/가공, 부위, 냉장/냉동, 품종·포장 등 | HS 후보 연결, 가격 항목 후보 연결 |
| 물품 묶음·생산 배치 | 같은 제품이라도 입고·제조 이력이 다른 물량 | 입고됨, 투입됨, 산출됨, 일부 출고됨 |
| 입고·제조·출고·운송·인수 업무 | 시각·상태·revision을 가진 기존 업무 참조 | 선행 업무, 처리한 물량, 후속 업무 |
| 메뉴·레시피 | 관찰 메뉴, 공개 참고 구성, 확인된 매장 구성을 구별 | 참고 레시피, 재료 후보, 확인된 사용 |
| 자료 관측·원본 | 통계/가격/업체 조사와 그 출처 | 분류 근거, 참고 가격, 관계 근거 |

업무 관계와 근거 관계는 같은 선으로 합치지 않는다. 관계에는 고유 식별자, 양 끝 식별자, 관계 종류, 출처/원장 참조, 기준 시각, 판본과 검토 상태를 둔다. 수량·단위는 근거가 있을 때만 기록한다. 공개자료·가상 시나리오·운영 원장 참조의 구분은 자료의 성격이며 새 실행 모드가 아니다. 기존 `SsalddelExecution:Mode` 경계를 유지한다.

### 가공·부분 인수

- 제품 정의 하나와 실제 물품 묶음 하나를 혼동하지 않는다. 같은 원재료를 여러 차례 입고해도 입고 이력을 합쳐 지우지 않는다.
- 제조 작업을 독립 연결점으로 두어 여러 투입물 → 한 제조 작업 → 여러 산출물을 표현한다. 가공을 단순 운송 화살표로 축약하지 않는다.
- 분할 출고·합류·부산물·손실·격리·반품을 참조할 자리를 둔다. 수율이나 폐기·배상 결과를 통계에서 자동 결정하지 않는다.
- 출고 물량 전체가 인수되었다고 간주하지 않는다. 정상 인수·보호 보류 수량과 남은 물량의 관계를 보존한다.
- kg·L·개·포대는 근거 있는 환산만 허용한다. 현재 정수 입고 수량 필드를 소수 kg 저장에 그대로 쓰지 않고, 선택한 업무 계약의 수량 의미를 먼저 확인한다.

### 가격 근거

- 수출입 단위가액에는 HS/판본, 보고국·상대국 범위, 기간, 수출입 방향, 금액·중량 원값, 통화·단위와 산식을 연결한다. 분모 결손은 0원으로 바꾸지 않는다.
- KAMIS에는 품목·등급·포장 단위·지역·관측일·도소매 구분과 해석 제한을 유지한다. HS와 KAMIS 품목은 별도 분류이며 이름 유사성만으로 확정 매핑하지 않는다.
- 통계 단위가액은 실제 매입/납품 단가가 아니다. 다른 기간·규격·방향의 관측을 빼서 가공 이익으로 표시하지 않는다.
- 실제 원가 계산은 매입 증빙, 실제 투입량·수율, 가공·운송 등 비용과 환율 근거가 별도로 준비된 뒤 검토한다. 이번 기획에서 수익성을 확정하지 않는다.

## 저장과 조회 제안

1. 원본 조사 자료·기존 재료/제품·업체·업무 원장을 유지한다. 저장소 간 참조에는 자료원과 고유 식별자·판본을 함께 사용한다.
2. 이미 있는 재료–레시피, 재료–HS, 재료–가격, 업체 조사 관계를 우선 재사용한다. 부족한 관계만 목적이 명확한 FK/연결 테이블로 검토한다. 모든 업무를 단일 범용 `edges` 테이블로 이관하지 않는다.
3. 조회 계층이 기존 관계에서 작은 `nodes/edges` 상태 사본을 만든다. 메뉴·제품·제조 업무 한 건 주변부터 제한된 깊이와 항목 수로 읽는다. 전체 공급망을 매번 로드하지 않는다.
4. 클릭 시 원문 출처·관측일·규격·관계 이유를 상세로 보여준다. 실제 업무 참조에는 권한 검증이 필요하며, 개인·계약 정보를 공개 조사 화면에 자동 노출하지 않는다.
5. 조회는 입고·제조·인수 상태를 바꾸지 않는다. Unity는 나중에 이 조회 결과를 읽어 표현할 후보이며 이번 범위에 포함하지 않는다.

## 구현 후보와 순서

첫 업무 예시는 기존 원두 시나리오 방향을 재사용한 **생두 → 로스팅 → 포장 원두 → 카페 입고**를 추천한다. 현재 생두·볶은 커피 HS 조사 자료가 있어 근거 연결을 검토하기 좋다. 특정 실제 공장·카페, 생산량·수율·거래 단가와 납품 사실은 미확정이다.

1. 재료/제품 규격과 조사 관측의 식별자 대조, 후보/확정/누락 표시.
2. 공공자료 관계를 읽는 최소 조회 모델과 결정적 노드·관계 목록 검증.
3. 별도로 명시한 가상 제조·납품 예시에 기존 투입/산출·입출고 참조를 결속. 공공자료의 부족분을 가상 자료로 대체하지 않는다.
4. 동일 참조 중복 방지, 끊긴 관계, 역순/낮은 revision, 다중 투입·분할 인수, 단위 결손과 공개 권한 시험.
5. 실제 업무 연계는 해당 운영 원장·API 준비와 승인 범위를 별도 확인한다. 읽기 화면을 만들었다는 이유로 종단 운영이나 Unity 검증 완료로 보지 않는다.

현재 저장소의 Graph Map은 기획·배치·코드 결속을 위한 체계다. 여기서 제안하는 공급·가공 관계 조회의 운영 원본으로 재정의하지 않는다. 후속 구현이 WI/배치에 영향을 줄 때 승인된 범위와 판본으로 인계하며, 이번에는 Graph Map 원본·생성물·검사 도구를 수정하지 않는다.
