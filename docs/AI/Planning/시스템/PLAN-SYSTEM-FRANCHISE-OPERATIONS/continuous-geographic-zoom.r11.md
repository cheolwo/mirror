# 연속 지리 확대 조사·제안 r11

2026-09-23. 사용자 요청: 독립 지형판이 아니라 지구→한반도→권역→시군구→읍면동→상세 공간으로 같은 위치를 자연스럽게 확대한다. 이번은 기술 조사·제안이며 구현 승인/기존 r10 삭제가 아니다.

## 현재 코드에서 확인한 단절

- `세계지구본View.ReadMouseInput`: 최소 카메라 거리에서 추가 휠 입력 시 `서울중간공간View.ShowLevel(0)`를 호출한다. 현재 코드 경로는 시선 지역별 진입이 아니라 서울 자료 존재 조건이다.
- `서울중간공간View`: 별도 orthographic 카메라와 root 활성화로 구/동을 표현한다. 경계 자료는 재사용하되 별도 화면 선택과 좌표 전환은 개선 대상이다.
- `이천입체지형검토View`: `Center=(100000,0,100000)`와 별도 카메라를 쓰는 로컬 검토 표본이다. 실제 지구 위치에 결속된 확대 결과가 아니다. 데이터/메시 검증 용도로 보존하되 정식 탐색 경로로 사용하지 않는다.

## 공식 자료 조사

- [OGC 3D Tiles](https://www.ogc.org/standards/3dtiles/): 대규모 지리 콘텐츠의 계층적 구조와 스트리밍 표준. [명세](https://docs.ogc.org/cs/18-053r2/18-053r2.html)는 geometric error와 screen-space error에 의한 상세도 선택을 설명한다. 이 원리를 적용한다는 뜻이지 현행 데이터를 이미 3D Tiles 호환이라고 주장하는 것이 아니다.
- [Cesium Unity 지구 객체 배치](https://cesium.com/learn/unity/unity-placing-objects/): 지구 규모 double 좌표와 Unity 로컬 좌표, origin shifting, 지리 anchor, 화면에 필요한 tile/LOD 로딩을 설명한다. 원점 이동 시 기존 물리/조명/객체 좌표에 주의가 필요하다.
- [Cesium Unity 지리 sub-scene](https://cesium.com/learn/unity/unity-subscenes/): 지리 원점에 결속한 상세 객체의 근접 활성화 예시. 프로젝트의 공식 Scene을 늘리자는 제안이 아니며 동일 canonical Scene의 자료/객체 활성화에 참고한다.

## 제안: 두 계층을 분리

1. 지형 상세도: 지도 타일·고도 메시·영상 해상도. 화면 오차, 시야, 메모리 예산으로 선택한다. 행정 경계 모양대로 지형 타일을 자르지 않는다.
2. 정보 의미: 국가·시도·시군구·읍면동·역세권·시설. 같은 지형 위의 경계/선택/표시 정보다. 역세권은 행정동의 고정 자식이 아니며 여러 동에 걸칠 수 있다. H1/H2/H3 업무 공간과 행정 계층도 혼동하지 않는다.

사용자 경험은 `지구→한반도→수도권→서울→중랑구→행정동→사가정 상세` 또는 `지구→한반도→수도권→경기도→이천시→준비된 읍면동/상세 지형`이다. 경기도/이천 자료 범위는 별도 확인하며 이천을 서울 구 계층에 억지로 넣지 않는다.

## 구현 우선순위 (제안, 아직 구현 안 함)

1. **같은 초점 유지:** 시선/마우스 아래 위경도·고도·북쪽 방향·카메라 거리 상태를 공통 소유한다. 확대 시 지역을 자동으로 서울로 바꾸지 않는다. 선택 지점이 화면에서 튀지 않도록 한다.
2. **지리 결속:** 기존 축소 구체 반경과 미터 단위 지형의 축척·datum을 명시한다. 지구 좌표는 double, 근경은 카메라 인근 로컬 좌표로 변환한다. origin shift 전후 카메라와 객체 모두 변환해 상대 화면 위치를 유지한다. 이천의 EPSG32652 원점을 실제 위경도로 연결한다.
3. **부모 지형부터 채움:** 현재 3km 지형만 올리면 섬처럼 보인다. 확보한 N37/E127 DSM의 적절한 주변 범위에서 저해상도 부모 메시를 만들고 내부만 정밀하게 바꾼다. 경계 정점·고도 기준과 색상 차이를 확인한다. 별도 직사각형 판을 앞에 띄우지 않는다.
4. **연속 상세화:** 화면 오차에 따라 필요한 자식만 로딩한다. 자식 준비 전 부모를 유지하고, 같은 위치/방향/축척으로 맞춘 뒤 교체한다. 양방향 확대의 히스테리시스, 오래된 요청 취소, 예산 제한, 로딩 실패 시 부모 유지가 필요하다. 단순 crossfade만으로 좌표 불일치를 감추지 않는다.
5. **행정 경계 결합:** 기존 구/행정동 경계를 같은 지형 좌표에 올린다. 줌에 따라 필요한 경계만 나타내고 클릭은 동일 지점으로 부드럽게 초점을 옮긴다. 상세 미준비 지역은 상위 지형을 유지한다.
6. **생활 객체 후속:** 지형 연결이 확인된 뒤 공장·트럭·NPC를 지리 anchor에 결속한다. 애니메이션과 운영 권위는 기존처럼 분리한다.

첫 검증 대상은 **지구에서 이천 한 지점까지 휠 확대 후 같은 경로로 축소**다. 지구·한반도·권역·이천 원경·근경에서 동일 anchor의 화면 좌표/방향/축척, 타일 빈틈과 이중 면, 실패 시 부모 유지, 객체 개수/메모리를 확인한다. 실제 전체 Game View로 검증하고 지정 카메라 렌더만으로 대체하지 않는다.

## 선택과 범위

추천은 기존 코드/자료를 보존한 위 최소 연결 검증이다. Cesium 도입은 원점·LOD·타일 스트리밍을 재사용할 대안이지만 기존 축소 지구본·UI·지리 객체의 이전 비용과 자료 공급/라이선스/비용을 별도 비교해야 한다. 현 단계에서 무조건 자체 개발 또는 전면 엔진 교체를 확정하지 않는다.

확정: 사용자 의도는 같은 장소의 연속 확대다. 미정: 기존 엔진의 작은 연결 실험 결과에 따른 Cesium 채택 여부와 성능 예산. 다음 질문: 먼저 별도 판을 추가하지 않고 이천 한 지점의 왕복 확대를 구현 기준으로 삼을지.

이번은 공식 문서와 현재 코드 조사만 수행했다. 새 공공자료 수집/DB 쓰기·제품 코드 변경·Unity 실행·commit·push 없음. 출처/표현 분리 원칙 유지, 새 디오라마 규칙 후보 없음.
