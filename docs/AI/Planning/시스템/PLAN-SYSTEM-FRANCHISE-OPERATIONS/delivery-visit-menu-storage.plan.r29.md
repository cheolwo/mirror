# 방문·매장·메뉴 기록의 DB 축적 방향 r29

- 기준일: 2026-09-24
- 상태: 저장 방향 기록 / 구체 저장 계약·가져오기 구현 전
- 선행: [메뉴·재료 조사 r28](delivery-menu-ingredient-research.plan.r28.md)

## 확정한 방향

배달 프로젝트에서 정리하는 방문·음식점·메뉴 기록을 파일에만 남기지 않고 DB에서 조회·연결할 수 있도록 축적한다. 기존 편집 원본과 판본은 보존한다. DB 저장을 곧바로 매장 가입, 판매 메뉴 등록, 주문/배송 완료, 공개 게시로 해석하지 않는다.

## 논리적 기록 단위 제안

| 기록 | 주요 정보 | 구분 원칙 |
| --- | --- | --- |
| 관찰 매장 | 고유 식별자, 상호·지점, 공개 주소/좌표의 근거와 확인 상태 | 이름이 같다는 이유로 같은 지점을 합치지 않음 |
| 관찰 메뉴 | 매장 연결, 메뉴명 원문/정리명, 옵션, 근거·확인 상태 | 일반 음식 종류와 매장별 메뉴는 별개, 운영 판매 메뉴 자동 생성 금지 |
| 방문 | 방문 고유 식별자, 기록일, 순서, 매장 연결, 사용자 메모 | 같은 매장에 다시 방문하면 별도 기록, 실제 시각 미확인은 추정하지 않음 |
| 방문 메뉴 연결 | 방문 ID와 메뉴 ID, 확인된 옵션·수량 및 근거 | 한 번 방문에 여러 메뉴 가능, 수량 미확인은 null/미상으로 보존 |
| 미디어 연결 | 비공개 자산 식별자/hash, 원본 구간, 편집본 판본·구간 | 영상 바이너리를 업무 테이블에 넣지 않음, 편집 시각을 실제 사건 시각으로 사용하지 않음 |
| 조사 연결 | 재료 후보·HS 매핑·날짜별 가격 관측과 출처 | 매장 실제 재료와 일반 추론, 국내 가격과 무역 단위가액을 분리 |

이 표는 논리 모델 제안이며 테이블 수나 새 Entity 생성을 확정하지 않는다. 날짜별 방문 순서가 수정되어도 고유 식별자를 바꾸지 않는다. 동일 원본 재가져오기는 중복 생성을 막고, 수정은 revision·원본 hash와 함께 기록한다. 불명확한 매장/메뉴도 비공개 미확인 기록으로 보존할 수 있지만 공개 지도·편집 적용 관문은 통과한 것으로 처리하지 않는다.

## 기존 코드 확인과 저장 경계

- `Ssalddel.Domain/음식/음식점공개프로필.cs`에는 공개 주소·좌표·주문가능여부가 있다.
- `Ssalddel.Domain/음식/음식점메뉴.cs`에는 판매가·공개/품절 상태가 있다. 관찰 메모를 이 테이블의 판매 사실로 바로 가져오지 않는다. 이미 등록된 업체와의 연결도 지점 일치 검토를 거친다.
- `PublicDataIngestionDbContext`에는 수집 Run·RawSnapshot·정규화 Record·공개 사업장 등 자료 기반이 있다. 공식 가격/무역 자료는 기존 수집 경로 재사용을 검토하되 개인 방문 원문을 공공자료로 위장하지 않는다.
- 기존 배달 편집 JSON·전사·메뉴 근거는 가져오기 원본 후보다. 최신 사용자 정정과 확정본/검토본을 구분한 뒤 목록을 만든다. 원본 파일을 삭제하거나 DB 값으로 기존 편집을 자동 덮어쓰지 않는다.

MySQL은 매장·메뉴·방문 관계와 조회/집계 후보로 우선 검토한다. 개인 방문 원문을 MongoDB에 추가할지는 기존 비공개 기록 계약을 대조한 뒤 결정하며, 두 DB에 이중 원장을 새로 만들지 않는다. 대상 DB의 소유·실행 환경을 확인하기 전 쓰지 않는다. 원격 운영 DB는 범위 밖이다.

## 첫 적용 제안과 미정

9월22·23일 기록의 최신 입력을 대조 → 가져오기 미리보기(신규/재방문/수정/미확인) → 확인된 로컬 DB에 작은 묶음 저장 → 독립 재조회와 같은 입력 재적용으로 중복 방지 확인 순서다. 먼저 방문·매장·메뉴 관계를 닫고 재료·가격은 후속으로 붙인다.

사용자 개인 방문 내역·원본 영상·전사는 기본 비공개다. 고객 주소·전화·전표 등 불필요한 주문 개인정보는 가져오기 대상에서 제외하고 공개 매장 자료와 분리한다. Unity·영상은 허용된 조회 결과만 소비한다.

미정: 정확한 저장 계약/DB와 권한, 두 날짜 입력 판본·고유 ID 대응, 가져오기 범위. 다음 질문은 지금 없음. 구현 착수 때 위 항목을 확인하며 이번 사용자 의도 기록만으로 운영 DB 저장·공개·편집을 승인하지 않는다.

이번에는 관련 코드 조회와 문서 변경만 수행했다. DB 생성·Migration·가져오기·저장·재조회, 자료 수집, Unity/편집 변경·실행 시험·commit·push 없음. 새 디오라마 규칙 후보 없음.
