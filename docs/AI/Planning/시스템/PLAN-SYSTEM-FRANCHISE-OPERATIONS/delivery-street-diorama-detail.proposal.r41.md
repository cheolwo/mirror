## 1. 추천안: 익숙한 거리 한 구간을 먼저 완성한다

**사가정 기존 디오라마 안에서 약 100~200m 거리 한 구간과 매장 3곳을 선정해, 도로·보도·건물 전면·출입구를 실제 촬영과 대조하는 작업을 추천한다.** 이 길이와 매장 수는 작업량을 제한하기 위한 초깃값이며, 이미 선정되거나 측정된 값은 아니다. 실제 방문 기록과 기존 건물 자료가 겹치는지를 확인한 뒤 구역을 정한다.

첫 결과는 위에서 내려다봐도 매장 순서와 골목 모양이 맞고, 가까이 가면 매장 입구와 보도 단차를 구별할 수 있는 작은 동네다. 이후 배달 영상의 지역 소개·방문 요약과 매장·메뉴 정보 탐색에 반복해서 활용한다. 공급망 배송 표현도 같은 공간 위에 후속으로 연결할 수 있다.

공간 범위는 H2 블록 일부, 상세 대상은 그 안의 H1 행동·작업 공간으로 잡는다. 이번 완성 목표는 공간의 판독성과 근거 있는 배치이며, 공급 계약·발주·재고·배송 운영의 완성을 포함하지 않는다.

### 처음 보여 줄 장면

1. 전체 보기에서 거리 한 구간과 매장 3곳의 순서를 알아본다.
2. 매장 하나를 선택하면 해당 건물 전면과 확인된 입구가 보인다.
3. 접근 방향을 따라 이동하거나 관찰하며 도로·보도·문턱을 구분한다. 실제 통행 검증은 이동 기능을 구현한 범위에서 별도로 수행한다.
4. 선택한 매장의 확인된 방문 기록을 읽고 전체 보기로 돌아온다. 미확인 입구는 미확인으로 표시한다.

## 2. 현재 자료에서 출발할 수 있는 범위

2026-09-26 로컬 파일·코드·기획 대장 점검 기준이다. 이번 제안서 작성 중 Unity 실행이나 원본 영상 전체 재생, DB 재조회는 하지 않았다.

| 확인한 기반 | 지금 활용할 점 | 이번 정밀화에서 해결할 점 |
| --- | --- | --- |
| 기존 r27에 영상·매장·건물 대조 후 대표 구역을 정하는 계획이 있음 | 기존 계획을 이어서 상세화 | 아직 특정 거리와 매장 3곳의 대응표는 없음 |
| Unity `SagajeongReference.json` r3에 건물 602개·도로 구간 2,397개가 있음 | 주변 배경과 위치 비교 기준 | 이 원본의 높이는 30개가 OSM 태그 기반, 572개가 상징값이며 태그도 실측 검증과 다름 |
| 기존 조립 코드에 좌표 변환·공간 사본·추가 표현 계층이 있음 | 새로운 공식 Scene을 만들지 않고 기존 구조에 국소 보완 | 기존 ID·좌표 기준·원본 판본을 보존하며 후보를 교체할 방법 필요 |
| 도로 Mesh 생성은 `SymbolicRoadWidthMeters`를 사용 | 길의 연결 형태를 참고 | 대상 구간의 실제 도로 폭·보도 폭·전면 여백·단차를 별도 확인 |
| 후속 주소·필지 대장에 화면 건물 4,062개와 고유 PNU 3,774개가 기록됨 | 건물·주소 후보를 대조할 출발점 | 실제 필지 도형은 0/3,774로 미수집·차단 상태. 후보 주소도 입점·출입구 확정 근거가 아님 |
| 공간 보충 r27에 보행망·가로수·정류소 등의 과거 수집 기록이 있음 | 재수집 전에 범위·시점·사용 조건 대조 | DEM 수집 및 Unity 적용 완료로 간주할 수 없음 |
| 배달 작업공간에 날짜별 방문·좌표 근거·전사·원본 대응 기록이 있음 | 공개 매장과 촬영 구간 후보를 찾음 | 매장 위치 확인과 건물 외형·입구·높이 측정은 별개 |

602개 원본과 4,062개 후속 화면 자료는 서로 다른 판본·대상이다. 숫자를 합치거나 같은 완성도로 설명하지 않는다. 지도 건물 수가 많아도 실제 거리의 높낮이와 보행 폭까지 정밀해진 것은 아니다.

이 문서의 **부지 정밀화**는 우선 도로·건물·앞마당·출입구의 공간 관계를 맞추는 뜻이다. 법적 필지 경계와 경계 측량 수준의 정확도는 별도의 자료와 검증이 필요한 후속 범위로 둔다.

## 4. 거리 촬영을 자료 수집 루틴으로 만든다

배달 중에는 기존의 간단한 매장명 호출과 픽업 기록을 유지한다. 거리 자료는 정차하거나 도보로 안전하게 기록할 수 있을 때 별도로 보충한다. 한 번에 동네 전체를 촬영하기보다 선정한 구간의 결손을 채우는 방식이 적합하다.

| 자료 | 한 구간의 촬영 제안 | 확인할 정보 |
| --- | --- | --- |
| 거리 전체 | 같은 구간의 양방향 전경, 시작·끝·교차로에서 잠시 정지 | 건물 순서, 골목 방향, 가림과 연결 관계 |
| 매장 전면 | 매장마다 정면·좌측 사선·우측 사선, 주변 건물도 함께 포함 | 전면 폭의 비례, 간판 위치, 창문·캐노피·문 위치 |
| 접근부 | 보도에서 입구까지, 문턱·계단·경사 부분 | 입구 방향, 높이 변화, 보행 공간 |
| 맞은편 기준 | 가능하면 맞은편에서 거리와 건물을 함께 기록 | 도로 양쪽 상대 위치와 촬영 시점 비교 |
| 치수 기준 | 확보 가능한 실제 치수나 확인된 도면 치수와 측정 지점 기록 | 축척과 높이의 기준. 출입문 크기나 차량 크기를 임의의 정답으로 쓰지 않음 |

위 촬영은 참고 장면 수집안이다. 겹치는 영상이 있다는 이유만으로 자동 3D 복원 성공이나 미터 단위 정확도를 보장하지 않는다. 가려진 건물 뒤쪽·지붕·실내는 추정 표현 여부를 따로 표시한다.

원본 파일과 촬영 메타데이터를 보존하고, 기록에는 `촬영일 / 구간 ID / 매장 ID / 원본 파일 / 시작·끝 시각 / 바라본 방향 / 확인 대상 / 가림·불확실성`을 남긴다. 개인정보가 포함된 원본은 비공개 보관하고 검토·공개 자료는 얼굴·번호판·전표·개인정보 음성을 점검한다.

Premiere는 필요한 구간의 타임코드 정리와 비교용 장면 제작에 활용한다. 치수 판단은 잘라내거나 확대·안정화한 편집본만으로 하지 않고 원본과 기준 자료로 되돌아간다. 이번에는 촬영·편집·프레임 추출을 실행하지 않는다.

### 자료를 섞지 않는 연결 구조

`매장 ID → 건물 후보/확인된 건물 ID → 입구 근거 → 해당 공간 판본`을 공간 자료로 관리한다. 날짜별 방문은 별도 방문 ID로 연결한다. 같은 매장을 여러 날 방문해도 건물을 중복 생성하지 않는다.

영상 파일 경로와 원본 타임코드는 배달 작업공간의 비공개 근거 대장에 둔다. 기존 `delivery-visits.v2.json`의 공개 가능한 방문 계약에 원본 경로를 추가하거나, 제거된 Unity 영상 카드 기능을 복구하지 않는다. Hongdal에는 검토용 근거 참조와 공간 연결 상태를 남긴다. MYBOX 공개 공유 폴더는 기존 최신 완성 MP4 정책을 유지한다.

## 5. 정밀도의 기준을 먼저 정한다

각 치수·위치는 다음 중 하나로 기록한다. 항목 전체에 일괄적으로 '정확함' 표시를 붙이지 않는다.

| 구분 | 필요한 근거 | 사용 방식 |
| --- | --- | --- |
| 확인값 | 측정 방법·날짜·기준점 또는 동일 대상이 확인된 도면/원천 자료 | 오차·현행성 한계를 함께 기록한 기준값 |
| 계산값 | 확인된 기준과 변환식·좌표계·단위·원본 판본 | 변환 후 별도 기준점으로 교차 확인 |
| 추정값 | 추정 방법·가림·누락·범위 | 임시 외형으로 구별하고 치수 검증의 정답에서 제외 |
| 미확인 | 부족한 자료와 확인 항목 | 빈칸이나 명시 상태로 유지. 인근 건물·입구로 임의 대체하지 않음 |

파일럿 시작 때 공통 기준점·북쪽·원점·미터 단위를 고정한다. 확보 가능한 경우 한 직선에 몰리지 않은 기준점 3개 이상으로 정렬을 확인하고, 맞추는 데 사용하지 않은 별도 지점도 비교한다. 절대 좌표 정확도와 같은 장면 안의 상대 비례를 따로 평가한다.

도로 폭·전면 폭·입구 위치·높이의 허용 오차는 자료의 해상도와 측정 방식 확인 후 항목별로 정한다. 현재는 수치 오차 기준을 확정하지 않는다. 모든 필드가 채워졌다는 이유로 측량 수준의 정밀도가 달성됐다고 판정하지 않는다.

아래는 후속 구현을 위한 제안이다. 작업 차수와 리셋권 한 장은 같은 단위가 아니다.

| 단계 | 작업과 선행 조건 | 남길 결과물 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- | --- |
| 0. 구간 선정 | 09.22~09.24 방문 기록과 기존 공간 범위 대조. 새 자료 수집 없이 먼저 후보 검토 | 후보 최대 3개 비교표, 추천 구간 1개, 매장·건물 결손표 | 대상의 동일성·자료 상태·재촬영 용이성 확인. 구체 구간 미정이면 이 결과로 좁힘 |

## 7. Codex 리셋권을 어떻게 배분할 것인가

사용자가 리셋권을 보유했다는 설명을 전제로 계획한다. 보유 수량·만료 시점·계정별 적용 대상 한도는 이번에 확인하지 않았다. 공식 문서에는 Codex 사용량 리셋 적립 기능이 안내돼 있지만, 이 문서 작성이 리셋 사용을 의미하지 않는다. 실제 적용 조건은 사용 시 계정 화면을 기준으로 확인한다. [OpenAI 변경 기록](https://learn.chatgpt.com/docs/changelog#codex-2026-06-11-app)

모델·문맥·작업 복잡도·도구 사용에 따라 사용량이 달라지므로 '리셋 한 장당 거리 몇 m·건물 몇 개·몇 시간'으로 환산하지 않는다. 아래 비율은 **프로젝트 작업 노력의 배분안**이며 토큰·한도 계산식이 아니다. [OpenAI 사용량 안내](https://learn.chatgpt.com/docs/pricing)

| 작업 노력 배분 | 권장 비중 | 집중할 결과 |
| --- | --- | --- |
| 대상·근거·결손 정리 | 20% | 바로 구현 가능한 입력 묶음 |
| 도로·보도·건물 공간 뼈대 | 30% | 실제 거리와 맞는 큰 비례 |
| 매장 전면·입구와 반복 부품 | 30% | 가까운 화면에서 구별 가능한 공간 |
| 통합·비교·회귀·인계 | 20% | 검증된 상태로 남는 결과 |

### 리셋 전 준비할 다섯 가지

1. 지금 막힌 이유가 사용량인지, 촬영·자료 접근·설계 결정인지 구별한다.
2. 바로 처리할 작업 3~5개에 입력 파일·수정 경로·완료 기준을 붙인다.
3. 마지막 확인된 공간 판본, 변경 파일, 검증 결과와 다음 한 작업을 저장한다.
4. 계정의 리셋 수량·만료·적용 조건을 확인한다. 만료가 임박했다면 준비된 독립 작업의 순서를 조정한다.
5. 리셋 후에도 같은 범위에서 이어 간다. 새로운 동네나 새 기능을 동시에 늘리지 않는다.

| 활용 여건 | 권장 진행 |
| --- | --- |
| 추가 사용 여력이 한 번 정도 | 한 구간의 자료 대조·공간 뼈대·검증을 우선. 외관 범위를 줄이더라도 통합·검증 분량을 남김 |
| 추가 사용 여력이 여러 번 | 같은 구간의 뼈대 → 외관 → 통합·반복 절차 순으로 완성한 뒤 두 번째 구간 검토 |
| 촬영·공식 자료 접근이 막힘 | 확보된 자료의 결손표·변환/검사 명세·기존 자산 정리처럼 독립적으로 끝낼 일을 진행. 같은 실패 요청을 반복하며 리셋을 소진하지 않음 |

분업은 자료 대조, 독립 외관 부품, 검증 검토처럼 쓰는 파일이 겹치지 않는 범위에서 한다. 공간 계약·기준 좌표는 한 담당자가 정리하고 **Unity Scene·공유 Prefab·Editor 통합은 한 담당자만 수행**한다. 병렬 작업 수가 늘었다고 일정이나 사용량이 같은 비율로 개선된다고 가정하지 않는다.

모든 구현 작업에는 '대상 / 근거 입력 / 허용 수정 경로 / 산출물 / 확인 방법 / 결손 시 처리'를 붙인다. 작업 종료 때 다음 세션이 재조사 없이 이어 갈 수 있도록 현재 판본과 남은 차이를 짧게 남긴다.

## 9. 확정·미정·첫 실행 제안

**확정한 요청:** 리셋권을 활용할 디오라마 부지 정밀화 제안서 작성. 배달·거리 촬영을 공간 자료로 축적하려는 방향.
