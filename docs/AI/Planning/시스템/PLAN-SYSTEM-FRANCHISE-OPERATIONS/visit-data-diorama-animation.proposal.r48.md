# 음식점 방문 데이터로 순서 있는 디오라마 애니메이션을 만든다

- 기준일·상태: 2026-09-26 / `VisitDataFirstConfirmed / SequentialAnimationProposed / ProductImplementationDeferred`.
- 사용자 정정: 영상을 분석하거나 Unity에서 재생하려는 것이 아니다. 이미 있는 음식점·메뉴·음식점 주소·방문 순서 데이터를 활용해 기사 캐릭터가 1번→2번→3번 가게를 이동하는 모습을 만들려는 것이다. 결과물의 후속 편집 활용과 입력 자료인 방문 기록을 구분한다.
- 관계: [배달 편집용 정밀화 r27](delivery-video-diorama-detail.plan.r27.md), [기존 방문 저장 r30](delivery-editorial-archive.implementation.r30.md), [자료 우선 정밀화 r44](diorama-public-data-refinement.proposal.r44.md)의 구체화. [본인 중심 관찰 r7](../../공통/PLAN-OPERATIONS-FOOD-RESTAURANT-RIDER-RELATIONSHIP/self-centered-on-demand-observation.decision.r7.md)의 운영 로그인 조회와 별개인 과거 기록 재구성이다.
- 이번 범위: 제안·문서화. 새 Goal·WI 등록 없음, `ReadyToDispatch=false`. Unity 구현·영상 분석/편집·촬영·DB 반입·공개 승인을 포함하지 않는다.

## 1. 만들고 싶은 모습

**확인된 방문 장소와 순서는 사실로, 장소 사이 이동은 재구성임을 구분하여 표현한다.**

`날짜/기록 선택 → 순서가 있는 방문 목록 → 가게 위치 연결 → 필요한 지역 지도 → 기사 캐릭터의 순차 방문`

예시는 `① 가게 A(기록된 메뉴) → ② 가게 B → ③ 가게 C → ④ 가게 A 재방문`이다. A 건물은 하나를 재사용하지만 첫 방문과 재방문은 서로 다른 방문 ID로 남긴다. 가게 이름이 같다는 이유로 다른 지점을 합치지 않는다.

표현 제안:

- 선택한 기록의 가게들을 지도에 방문 번호와 함께 표시한다.
- 본인을 나타내는 대체 기사 캐릭터 하나가 기록 순서대로 이동한다.
- 가게에 도착하면 짧게 멈추고 그 방문의 음식점·메뉴 정보를 표시한다. 메뉴가 미확인이면 꾸며 넣지 않는다.
- 재생·일시정지·속도 조절·특정 방문 선택을 통해 원하는 구간을 반복해서 본다. 표시 시간과 캐릭터 속도는 연출값이며 실제 소요 시간·운행 속도를 뜻하지 않는다.
- 카메라가 따라가는 방식은 선택적 후속 연출이다. 우선 지도와 순서가 제대로 연결되는지를 확인한다.

## 3. 이동 표현의 두 단계

### 첫 대안 — 방문 순서 연결선 위 이동 (추천)

확인된 가게 위치를 1→2→3 순서로 잇는 표현용 선 위에서 기사 기호/캐릭터가 움직인다. 지형 위에 살짝 띄운 안내선처럼 구분하여 실제 도로 운행으로 오해하지 않게 한다. 가게 사이 실제로 어떤 길을 탔는지는 없어도 시작할 수 있다.

건물 사이를 가로지르는 선이 실제 통행로라는 뜻이 되지 않도록 `방문 순서 재구성 · 이동 경로는 표현용`을 기본 범례 또는 재생 시작 안내에서 확인할 수 있게 한다. 실제 주소·상대 위치·방문 순서는 근거를 유지한다.

### 후속 대안 — 도로 자료에 맞춘 재구성 경로

선택 구간의 도로 연결·단절·통행 관련 자료가 준비되면 그 자료를 따른 표현용 경로로 바꿀 수 있다. 이것도 실제 주행 기록이 없으면 ‘그날 실제로 지나간 길’이 아니다. 보행망이나 과거 중심선만으로 오토바이 경로를 확정하지 않는다. 실제 경로 재현을 요구할 때만 그에 맞는 추가 근거가 필요하다.

첫 대안을 쓰더라도 가게 배치와 지역 배경을 버리지 않는다. 경로 표현만 후속으로 교체하는 구조를 제안한다.

## 4. 행정동 사이를 정밀하게 만드는 방법

**행정동은 자료를 분류하는 단위로 유지하고, 화면은 방문 장소들을 이어 주는 하나의 연속 공간으로 조립한다.** 동마다 중심을 0으로 돌려 별도 섬처럼 놓지 않는다.

1. 선택한 방문들의 확인된 좌표와 표현용 연결 구간을 기준으로 필요한 타일을 고른다. 실제 주행 구간이라고 부르지 않는다.
2. 현재 동 경계 양쪽 타일을 공통 원점·좌표계·판본에 맞춰 함께 배치한다. 같은 물리 타일·도로·건물은 중복 표시하지 않고 동별 귀속 정보는 별도로 유지한다.
3. 원본 도로가 동 경계에서 잘린 경우 원본 ID·절단 관계와 좌표를 확인한다. 서로 끝점이 가깝다는 이유만으로 다른 길을 자동 연결하지 않는다.
4. 정밀화는 우선 **방문 가게 주변과 선택한 연결 구간의 교차로·경계부**에 집중한다. 그 밖은 기존 단순 블록을 유지한다. 동 전체·30개 동을 매번 다시 고도화하지 않는다.
5. 공간자료가 없거나 권리/좌표/경계 결속이 불확실한 구간은 자료 부족으로 남긴다. 임의 건물·출입구·고객 집을 만들어 사실처럼 채우지 않는다.

[r29 공통 격자](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/thirty-admin-dong-terrain-private-generation.implementation.r29.md)의 동-타일 관계와 물리 타일 구분을 재사용 검토한다. [r39 집중 정밀화](../PLAN-SYSTEM-ADMIN-DONG-DIORAMA/focused-area-refinement.decision.r39.md)의 범위 축소는 유지하며 첫 대상 변경은 별도 검토한다. 지금 특정 날짜·가게·동 경계 구간을 임의 확정하거나 구현하지 않는다.

## 5. 첫 결과물 제안과 검증

한 기록에서 연속된 방문 3~5개 정도를 후보로 뽑아 **정지한 전체 방문 지도 → 순차 이동 → 방문 번호 선택**까지 검토하는 작은 표본을 추천한다. 숫자는 작업량 제안이며 사용자 확정이 아니다. 가능하면 인접 동 경계를 넘는 연결 하나를 포함하되 방문 기록을 아직 전수 대조하지 않았으므로 실제 대상은 미정이다.

- 방문 ID·순서 중복/누락·재방문을 검사한다. 방문을 거리순으로 재정렬하지 않는다. 제외/미해결 방문을 조용히 빠뜨려 실제 순서처럼 보이게 하지 않는다.
- 기존 주소·좌표·핀 근거를 확인한다. 애매한 지점·좌표·건물 연결은 사용자 확인 또는 미해결 상태로 두며 가장 가까운 가게로 대체하지 않는다.
- 건물 결속이 불명확해도 확인된 좌표의 중립 방문 표시는 별도 제안으로 검토할 수 있다. 실제 건물·출입구로 승격하지 않는다.
- 동 경계 이음부의 도로 단절·건물 중복·좌표 어긋남과 같은 방문의 재생 중복을 확인한다.
- 재생·정지·순서 이동은 표현만 바꾸고 운영 원장·배차·완료 상태는 변경하지 않는다.
- 실제 Unity 실행·Game View·편집용 출력·공개는 각각 별도 증거다. 지도 원천의 비공개 검토/이용조건 제한은 동영상 출력에서도 자동 해제되지 않는다.

이번에는 제안서만 작성했다. 자료 수집·DB 열람/변경·Unity 실행·영상 분석/편집/렌더·commit·push 없음. 기존 출처/사실·추정 분리 규칙의 재사용이며 새로운 실행 반례는 확인하지 않았다. 새 디오라마 규칙 후보 없음.
