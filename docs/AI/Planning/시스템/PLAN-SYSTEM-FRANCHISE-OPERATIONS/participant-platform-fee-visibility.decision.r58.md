# [기획 · 정산 공개 범위 · PLAN-SYSTEM-FRANCHISE-OPERATIONS · r58]

> 후속 [r59 4% 기준 대조](four-percent-policy-basis-review.r59.md): 사장님·기사님 수수료 표시 확정은 유지한다. 주문자 표시 질문은 4%의 의미를 먼저 확인하도록 `DeferredPendingFeeBasisClarification`로 보류하며, 새 과금률·주문자 공개 동의로 해석하지 않는다.

- 기준일: 2026-09-28.
- 상태: `ParticipantPlatformFeeVisibilityConfirmed / OrdererFeeVisibilityAsked`. 기획 선택 확정이며 제품 구현·실제 지급·공개 실행 승인이 아니다.
- 선행: [공동 참여·정산 투명성 r57](participatory-settlement-transparency.direction.r57.md). 금액·계산·지급 정책은 [기존 운영·재무 기획](../PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/README.md)을 따른다.

## 확정

질문 `participant-settlement-platform-fee-visibility`에 사용자가 “그렇게 진행해줘”로 동의했다. **음식점 사장님과 기사님은 본인 업무에 연결된 정산 상세에서 해당 거래의 플랫폼 수수료와 계산 기준을 함께 확인한다.** 질문은 `Confirmed`로 종결하며 반복하지 않는다.

수수료를 플랫폼 순이익으로 표시하지 않는다. 실제로 존재하는 건별 부과 항목을 근거로 연결하며, 기간 구독료처럼 건별 금액이 없는 항목을 임의로 나누어 표시하지 않는다. 새로운 수수료를 부과하거나 기존 금액·지급 주기를 바꾸는 결정이 아니다.

## 표현·계약 준비 기준

- 어떤 거래·정산 항목에 연결되는지, 금액·통화·산정 기준과 적용 판본을 대조할 수 있도록 한다. 다른 청구 주체의 비용을 플랫폼 수수료에 섞어 표시하지 않는다.
- 아직 예상인 금액과 확정된 금액을 구분하고 실제 지급 완료 여부는 별도 근거로 표시한다. 수수료 자료가 없거나 연결되지 않았으면 0원으로 단정하지 않는다.
- 수정이 필요하면 기존 내역과 조정 근거를 추적한다. 표시 승인만으로 과거 금액을 재계산·소급 변경하지 않는다.
- 본인 거래에 연결된 플랫폼 수수료의 확인 범위만 확정했다. 다른 가게·기사의 전체 수입·계좌·세무 증빙·플랫폼 전체 재무 공개는 포함하지 않는다.
- 기존 기사 이용료 청구·기사 수행대금·가게 상품대금·플랫폼 재무 사본의 책임은 r57대로 구분한다. 정보 참여·이의 제출은 확정 원장을 직접 수정하는 권한이 아니다.

이 기준은 후속 화면·API 계약 대조의 입력이며 화면 설계나 재무 정책 전부를 승인한 것으로 해석하지 않는다. 새 제품 코드를 만들거나 전용 정산 원장을 생성하지 않았다.

## 미정 / 다음 질문 하나

- 미정: 구체 화면·API 계약, 주문자에게 보여 줄 범위, 기간 구독료와 건별 항목의 탐색 연결, 정산 이의 처리, 실제 실행 검증 범위.
