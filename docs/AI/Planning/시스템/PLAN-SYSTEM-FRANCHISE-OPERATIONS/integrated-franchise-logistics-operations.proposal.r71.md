# 가맹 운영·물류센터·배송 플랫폼 통합 운영 제안 r71

2026-11-09 제안. 본부와 물류센터를 직접 운영하고, 배송 플랫폼에서 점포 보충 화물과 소비자 음식 배달을 조율하는 형태다. 사업을 잇는 기준점은 **점포의 검수 인수와 확인된 재고**다. 점포의 재료 소모와 실사가 다음 보충 발주로 돌아오도록 한다. [공급·물류 r67](supplier-franchise-logistics.research.r67.md) · [카페 운영 r68](cafe-store-operations.research.r68.md) · [운영 화면 골격 r70](restaurant-franchise-scaffold.r70.md)

## 역할과 완료 책임

| 영역 | 운영 책임 | 다음 담당에게 넘기는 결과 |
| --- | --- | --- |
| 가맹본부·점포 | 본부는 공급 조건, 승인 SKU, 레시피 판본과 적용일을 관리한다. 점포는 발주·검수·실사·판매·제조를 맡는다. | 본부의 수락 발주행은 센터로 넘긴다. 점포의 인수 기록은 가용 재고와 공급 정산의 근거가 된다. |
| 물류센터 | 입고 검수, 로트·기한·보관 상태, 예약·피킹·포장, 상차 확인을 맡는다. | 품목·수량·온도대·납품지·납품창을 확정한 운송 준비 자료와 실제 상차 증빙을 각각 넘긴다. |
| 배송 플랫폼 | 센터→점포 화물과 점포→고객 음식 배달의 배차·이행·예외를 관리한다. | 화물은 도착·하차 증빙을 점포에, 음식은 픽업·전달 결과를 점포와 주문자에 넘긴다. |

센터는 기존 출고 예정·재고 할당·운송의뢰 연결과 상차 검증을 재사용할 수 있다. 음식과 화물은 장소·지도·통합 조회를 공유하고, 배차 대기열·기사 자격·수락 조건·정산은 각 업무에서 관리한다. 본부가 매입해 재판매하는 모의 흐름은 r67의 표본을 따른다. 외부 공급자 직거래는 실제 판매자와 청구 책임을 별도로 표시한다. ## 배치 회차와 인계 시점

아래 시각은 한 권역의 운영을 설명하기 위한 예시다. 실제 마감과 납품창은 센터 용량, 점포 수령 가능 시간, 운송 여건에 맞춰 정한다.

| 예시 시점 | 처리 단위 | 확인하고 넘기는 시점 |
| --- | --- | --- |
| 전날 16시까지 | 점포별 보충 발주 | 점포는 실사와 예상 수요를 보고 제출한다. 본부는 유효 공급 조건과 납품 가능량을 확인해 수락량·미수락량을 기록한다. 수락량을 센터의 출고 후보로 보낸다. |
| 전날 17시 출고 회차 | 센터·납품일과 회차·온도대·권역·납품 시간창으로 묶음 | 센터가 검수 통과한 가용 로트와 수량을 예약한다. 운송 플랫폼은 점포별 납품지·물량과 시간창으로 차편을 계획한다. 예약과 차편 준비는 실제 상차와 별도다. |
| 당일 7시 상차 | 피킹·포장 묶음과 점포별 화물 | 센터와 기사가 실물 수량·차량·보관 조건을 확인한 뒤 상차를 확정한다. 부족·대체·파손으로 바뀐 수량은 원 발주행에 연결한다. |
| 당일 오전 점포 도착 | 점포별 도착·하차·검수 | 기사가 도착·하차를 기록한다. 점주가 품목·로트·수량·상태를 확인한 뒤 인수·격리·거절로 나눈다. 인수 확정량만 점포 가용 재고에 반영한다. |
| 영업 중 수시 | 소비자 주문 품목과 배달 시도 | 점포가 주문을 확인하고 적용 레시피와 가용 재료를 대조한다. 현재 음식 배달의 유효 기사 배정 조건을 거쳐 제조한다. 준비 완료 후 픽업과 고객 수령을 각각 기록한다. |
| 영업 마감 | 점포 실사와 다음 보충 초안 | 실제 제조 사용·폐기·실사 차이와 미도착 발주를 대조해 초안을 계산한다. 점주가 다음 회차에 제출한다. |

한 작업 묶음에 여러 점포가 들어가도 원 발주행, 점포별 수량과 인수 결과를 유지한다. 예를 들어 같은 냉장 회차에 A점 우유 5팩과 B점 3팩을 함께 피킹할 수 있다. 같은 가용 재고를 두 발주에 중복 예약하지 않으며, 부족한 행은 본부로 돌려보내 수량이나 회차를 조정한다. 차편이 분리되거나 일부만 상차됐으면 해당 행과 수량만 새 운송의뢰에 연결한다. 마감 이후 신규 발주는 다음 회차에 두고, 긴급 건은 책임자가 재고·기사·납기 가능 여부를 확인해 별도 의뢰로 승인하는 안이다.

음식 배달은 주문과 배달 시도 단위로 시작한다. 합배송을 검토할 때는 각 주문의 준비 시간, 약속 시각, 이동 경로, 음식 취급 조건을 먼저 대조하고 픽업·전달·수령 결과는 주문별로 남긴다. [기존 음식점 주문 진행 정책](../../../../../Ssalddel/Services/Food/음식점주문진행Policy.cs)

## 연결 기록과 통합 화면

- 공급 흐름에서는 `발주행 → 출고행·로트 → 화물 의뢰 → 점포 검수 → 점포 재고 이동`을 연결한다. 주문 흐름에서는 `음식 주문 품목·레시피 판본 → 사용한 점포 재료 로트 → 음식 배달 시도 → 수령 확인`을 연결한다. 한 로트가 여러 주문에 쓰일 수 있으므로 주문에 사용량을 함께 남긴다.
- 각 인계는 보내는 담당, 받는 담당, 대상 ID, 확정 수량·단위, 시각, 확인 근거를 보존한다. 응답이 끊기면 기존 결과를 다시 조회한다. 같은 인계를 다시 받아도 같은 업무·품목·처리 단계에 재고나 출고를 두 번 반영하지 않는다.
- 운영자에게는 **현재 막힌 건, 다음 담당, 약속 시각, 실제 증빙**을 함께 보여준다. 본부·센터·기사·점포는 현재 쓰는 업무 화면에서 자기 단계를 처리한다. 예외 목록은 발주 미수락, 피킹 부족, 상차 지연, 점포 검수 대기, 음식 픽업 지연을 구분한다.
- 공급대금, 센터 보관·출고 비용, 화물 운임, 음식 판매대금과 배달료는 서비스별로 대조한다. 점포가 일부만 인수하면 공급대금 조정의 근거가 되며, 이미 수행한 운송료 처리 기준은 각 계약에서 확인한다.

## 첫 모의 검증

본부 1곳·센터 1곳·카페 1곳·냉장 우유 1종으로 검증한다. 기존 r70의 우유 5팩 발주 예시를 쓰되 **이전 잔량이 없는 독립된 가상 이행 회차**로 둔다.

1. 우유 1L 5팩을 출고한다. 점포에서 4팩을 인수하고 1팩을 격리한다. 공급·화물 화면에는 출고·하차 5팩이, 점포에는 가용 4팩과 격리 1팩이 남아야 한다.
2. 확인된 로트로 라떼 한 잔을 제조해 170mL를 기록한다. 다른 소비가 없는 가정에서 가용 잔량은 3,830mL다. 별도 음식 배달로 픽업과 고객 수령까지 이어간다.
3. 재시도에도 인수·차감이 중복되지 않는지, 제조 전 취소와 제조 후 폐기의 기록이 다른지, 다른 점포에서 재고를 조회하거나 쓸 수 없는지 확인한다. 다음 검증에서 두 점포를 같은 회차에 넣어 한 번에 피킹하고, 부분 출고와 점포별 인수를 대조한다.

현재 통합 앱의 격리 검증은 창고 입고·검수, 화물 인수, 음식 수령을 각각 확인한 근거다. 이번 판본은 이들을 이어서 검증할 **업무 설계 제안**이다. 후속 작업은 발주행과 센터 출고행의 연결, 로트·온도·부분 인수와 점포 가용 수량을 먼저 결속하는 것이다. [통합 앱 마감표](../../../../Versions/unified-1.0/checklist.md)
