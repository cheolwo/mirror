# 행정 경계 표현 정밀도 보완 r20

2026-09-23. r19 화면에 대한 사용자 피드백 후 기존 관찰 표현만 좁게 보완한다. 업무 상태·WI·Scene·공식 경계 권위는 변경하지 않는다.

## 확인한 원인

- 광역 생성기에서 Natural Earth 원본에 추가로 0.002도 단순화를 적용했다.
- 세계지구본View의 한반도 육지 표본은 0.25도 간격이다. 따라서 행정 경계를 세밀하게 그려도 거친 바탕 해안과 일치하지 않는다.
- 위경도 꼭짓점을 구면에 올린 뒤 긴 직선으로 연결하면 그 중간은 구면 안쪽으로 들어갈 수 있다.

## 이번 변경

- build-korea-admin-context.py에서 추가 단순화를 제거했다. 광역 28개·원본 경계점 8,929개를 보존한다. 소수점 7자리 직렬화는 기존과 같다.
- 서울중간공간View.ProjectBoundary는 원본 꼭짓점을 보존하고 최대 0.01도 간격으로 구면 보간한다. 광역/서울 상세 선에 적용한다. 보간점은 새로운 측량 근거가 아니다.
- 파생 사본 2,997,151 bytes, SHA256 `4c68afd0e0b7946315c3b5b748dd722863d6a0b5dd919c12470c2897dc163ba8`. 두 번 재생성해 동일 hash 확인. 로컬 Editor 자동 준비 hash도 갱신한다.
- 기존 Natural Earth 1:10M 원본·출처·비공식 참고 경계 경고를 유지한다. 수집/이용조건은 [r19](capital-admin-context.r19.md)를 따른다. 신규 외부 자료나 DB 쓰기는 없다.

## 검증

연결된 Editor의 Pipeline에서 서울중간공간Tests 17/17 통과. 끝점 보존·구면 반경·비정상 좌표 거부 검사를 추가했다. 별도 batch test 명령은 열려 있는 Editor 때문에 실행되지 않아 Pipeline으로 전환했다.

## 남은 범위

실제 Play Mode에서 ContextAreaCount=28, 수도권 API-direct 전환 후 Game View를 확인했다. Unity `Documentation/Changes/2026-09-23-boundary-precision-r20/capital.png`에 저장했다. 확대 화면의 계단형 해안 바탕은 여전히 눈에 띄며 시각적 개선이 충분하지 않다. Play 종료, Scene 저장 없음. 물리 입력 완주 및 Console 오류 0은 검증하지 않았다.

정밀도 문제 전체 완료가 아니다. 저해상도 육지 바탕과 1:10M 참고 경계 자체의 일반화가 남아 있다. 다음 작업은 단순히 점을 늘리는 것이 아니라, 공식 시도/시군구 자료의 이용조건·좌표계·판본을 확인하고 해안 및 육지 면을 일관된 출처로 결속하는 것이다. 서울 상세와 광역 자료의 출처 차이도 유지한다. 경기·인천 하위 행정동을 추정 생성하지 않는다.

운영 효과·Scene 저장·commit·push 없음. 새 디오라마 규칙 후보 없음.
