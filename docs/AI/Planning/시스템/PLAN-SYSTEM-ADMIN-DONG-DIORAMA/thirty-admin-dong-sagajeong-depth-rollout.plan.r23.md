## 1. 확인 결과

사용자 발화의 `삼팔동`은 기존 고유 식별자와 사가정역 문맥에 따라 **면목제3·8동** `region:kr:hjd:1126057500`으로 정리한다. 사가정역 1km 관찰 창과 면목제3·8동 행정동 모듈은 겹치는 부분이 있지만 같은 공간 단위는 아니다. 역세권 창은 여러 행정동을 가로지를 수 있고, 행정동 모듈은 경계와 자료 귀속의 기본 단위다.

30개 행정동을 처음부터 새로 만들 필요는 없다. 기존 기록에는 다음 공통 기반이 있다.

| 공통 기반 | 보존 기록의 범위 | 현재 판정 |
| --- | --- | --- |
| 역사 경계·건물·기초 도로 | 30개 동, 건물61,897개, 도로 선분11,769개, 500m 타일297개 | 과거 공식 경계 후보의 비공개 검토 기반. 현행 정본 아님 |
| 주소·PNU 후보 | 건물61,897개 전수 상태, 후보 보유49,876·복수1,351·없음10,670 | 확정 주소·실제 필지 도형·출입구 아님 |
| 횡단보도·교차로·도보망 | 횡단보도1,533개, 교차로554개, 역사 도보망40,739개 | 점·과거 관측 후보. 현재 통행 graph 아님 |

r23 최초 확인에서는 Unity 캡처 원장의 화면 30개만 재확인했고 캡처가 가리키는 r2 생성 세대와 원본 폴더를 찾지 못했다. 후속 r24 실행에서 `OA-22160` 역사 경계, `AL_D010` 건물, 2026-08-12 국가표준 NodeLink, 행정안전부 행정동-법정동 원본을 기존 기록의 길이와 SHA-256으로 복구했다. 이 동결 입력으로 정확 30개 행정동·건물 61,897개·도로 선분 11,769개·500m 타일 297개의 r2를 다시 생성·검증하고 Unity 검토 bundle 30개를 export해 실제 Game View 31장을 다시 남겼다. 이 결과는 `HistoricalBoundaryBootstrapOnly / WaitingForAdministrativeBoundary`이며 현행 행정동 경계나 공개 가능한 현재 정본으로 승격하지 않는다.

사가정 쪽에서 더 깊게 갖춘 부분은 차선·방향표시·신호 시설 후보, 역 출구, 엘리베이터·공원·버스 정류소·가로수, 화면 건물 주소 상태, 건물 역할 카드와 합성 이동·생활 관찰이다. 이 항목도 모두 완성 정본은 아니다. 사가정에도 현행 행정동 경계, 실제 필지 도형, 검증된 건물 출입구, 정확 보행면·연석·정지선·신호 현시와 현재 통행 graph가 없다.

## 2. 이번에 확정하는 방향

30개 동 모두가 **같은 공통 계약과 깊이 검사표**를 갖도록 한다. 여기서 비슷한 깊이는 사가정 자료를 다른 동에 복사하거나 모든 동에 같은 수의 건물·시설을 강제로 만드는 뜻이 아니다.

행정동마다 다음을 독립적으로 갖춘다.

1. 공식 고유 식별자와 경계·건물·주소·출입구의 자료 계보.
2. 도로·보행·횡단·교차로·대중교통과 결손 상태.
3. 공원·공공시설·시장·사업장 등 지역 고유 장소 후보와 공개 범위.
4. 같은 공통 조립기로 여는 Unity 읽기 전용 모듈과 자료층별 표시 상태.
5. 자료가 없는 층을 숨기지 않는 `Missing / Blocked / NotAssessed` 상태.
6. 필요할 때만 결속하는 합성 Simulation·운영 관찰 Adapter.

행정동마다 전용 Scene·전용 클래스를 복사하지 않는다. 기존 `AdministrativeDongDiorama` 계약, manifest·500m tile, 공통 검토 View와 `SimulationWorldShell`을 재사용한다. 사가정역 1km 창은 면목제3·8동의 고정밀 자식 관찰 창으로 유지하고, 다른 역세권 창도 행정동 정본을 대신하지 않는다.

우선 완료선은 `G0~G4 + G6`의 **사실 기반 공통 모듈**이다. `G5·G7`은 같은 슬롯과 상태 계약을 준비하되, 지역 공간 근거와 승인된 Simulation 흐름이 있는 동부터 붙인다. 자료 결손을 임의 생성해 모든 슬롯을 `Ready`로 맞추지 않는다.

## 4. 실행 순서

### A. 30개 전체의 현행 공간 정본

이 단계는 동별 순차 작업이 아니라 30개 전체를 같은 공식 배포 세대로 처리한다.

1. 공식 `TL_SCCO_GEMD` 현행 행정동 경계를 확보하고 정확30개 코드·도형·CRS·위상을 검사한다.
2. 같은 배포 세대의 건물·건물군을 공식 연결 키와 함께 결속한다.
3. 주소 기준 출입구를 건물 또는 건물군에 명시적으로 연결하고 미결속을 분리한다.
4. 원본·hash·기준월·이용조건을 비공개 원장에 저장하고 독립 재조회·동일 입력 무쓰기를 확인한다.
5. 2023 역사 경계 후보와의 변화만 진단하며 기존 후보를 조용히 덮어쓰지 않는다.

이 순서는 r16 관문 그대로다. 공식 원본이 없으면 현재 후보를 `current`로 승격하거나 Unity 화면만 먼저 완성 처리하지 않는다.

### B. 첫 다른 행정동 재사용 검증

면목제3·8동을 참조 모듈로 보존하고, **면목본동** `region:kr:hjd:1126056500`을 첫 다른 행정동 검증 대상으로 둔다. 같은 면목 법정동 자료 범위를 공유하면서도 독립 행정동 고유 식별자·경계·건물 집합을 가지므로, 사가정 전용 가정을 찾기에 적합하다.

첫 절편은 새 엔진이 아니라 기존 공통 View에 다음을 붙이는 범위다.

- 현행 공간 사본과 결손 상태.
- 기존 수집기를 재사용한 버스 정류소·공원·가로수 등 한 종류의 환경/접근 레이어.
- 선택·해제·재진입과 다른 동 자료 잔류 방지.
- 출처·기준일·공개 범위와 `TraversalReady=false`, `GameplayReady=false` 표시.

구체 레이어는 A단계에서 실제 원본 coverage를 확인한 뒤 가장 근거가 온전한 하나를 고른다. 한 동 검증이 통과하면 같은 Adapter를 범위 인수만 바꿔 나머지 동에 적용한다.

### C. 화면·검토 적용 묶음

공식 공간 원본 수집은 A단계에서 전체30개를 한 번에 처리하고, 화면 조립·검토는 다음 묶음으로 나눈다.

1. 참조 유지: 면목제3·8동 1개.
2. 첫 재사용: 면목본동 1개.
3. 나머지 면목권: 면목제2·4·5·7동 4개.
4. 나머지 중랑구: 상봉·중화·묵·망우·신내 10개.
5. 동대문구: 전농·답십리·장안·휘경·이문 10개.
6. 광진구: 중곡제1~4동 4개.

각 묶음은 앞 묶음의 지역 값을 복사하지 않는다. 공통 계약·검사·표현만 재사용하고 원본 수량·결손·랜드마크·높이·접근 관계는 각 동의 자료로 결정한다.

## 5. 행정동 하나의 완료 조건

행정동 하나를 “사가정과 비슷한 깊이로 갖췄다”고 보고하려면 다음을 함께 기록한다.

- 공식 행정동 ID, 경계·건물·주소·필지·출입구의 판본과 상태.
- 이동·교통·공공시설·지역 장소의 원본 수량과 결손.
- 원본→정규화→행정동 귀속→투영의 hash와 동일 입력 재실행 결과.
- 공통 Profile의 각 층 `Ready / Missing / Blocked / NotAssessed`.
- Unity 전체·근접·선택·해제·재진입과 다른 동 자료 잔류 여부.
- 수집·DB·API·Unity·Play Mode·Game View·공개 승인을 각각 분리한 증거.

모든 자료층이 존재해야만 모듈을 열 수 있는 것은 아니다. 자료가 없는 동도 정직한 결손 상태로 열 수 있어야 한다. 다만 현행 경계·기본 공간·출처 계보가 없는 모듈을 공개 가능한 현재 디오라마로 부르지 않는다.

## 6. 현재 실행 가능 범위와 차단

공통 생성기, 서버 계약·API, Unity 검토 View와 30개 화면 기준선은 그대로 재사용한다. 후속 r24 실행은 동결 원본의 역사 bootstrap 재생성, 행정동-법정동 관할 원장의 로컬 MySQL 복구·독립 재조회, Unity 검토 입력 export와 실제 Game View 캡처까지 닫았다.

다음 좁은 단계는 승인받은 JUSO `TL_SCCO_GEMD`와 같은 배포 세대의 `TL_SPBD_BULD / TL_SPBD_EQB / TL_SPBD_ENTRC`를 새 revision으로 반입해 정확 30개 집합과 계보를 검증하는 일이다. 이 승인 원본이 없으면 역사 bootstrap을 `current`로 승격하거나 current pointer를 바꾸지 않는다.

## 7. 확정·미정·다음 작업

**확정:** 면목제3·8동만 깊게 유지하는 우선순위를 30개 행정동의 단계적 깊이 확장으로 넓힌다. 면목제3·8동과 사가정역은 참조 구현이며 다른 동도 같은 계약·깊이 검사표·결손 표시를 사용한다.

**미정:** 공식 원본 승인 시점, 정확한 보도면·연석·정지선·신호 현시의 확보 범위, 행정동별 대표 랜드마크와 `G5·G7` 적용 순서.

**다음 작업:** JUSO 신청·관할기관 승인을 거쳐 현행 경계·건물·건물군·출입구 원본을 확보하고, 역사 bootstrap과 분리된 새 revision에서 정확 30개 집합·hash·기준월·이용조건을 검증한다. 별도 보관한 2026-09-14 최신 NodeLink는 그 새 세대의 관계가 확인되기 전 기존 r2에 섞지 않는다.

r23 자체는 기존 파일과 보존 화면을 재확인해 방향·순서·완료 조건을 확정한 기획 판본이며, 작성 당시 새 자료 수집·DB 쓰기·API·Unity 코드 변경은 수행하지 않았다. 후속 r24 구현에서 동결 원본 복구, 역사 bootstrap 재생성, 로컬 MySQL 관할 원장 적용·독립 재조회, Unity 검토 입력 export와 Game View 검증을 수행했다. Scene·Prefab 저장, current pointer 변경, 공개·배포, 운영 권한 변경, E 승격, commit·push는 여전히 완료 범위가 아니다. **새 디오라마 규칙 후보 없음**.
