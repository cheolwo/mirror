## 확정

1. **첫 지역은 면목제3·8동** `region:kr:hjd:1126057500`이다. 사가정 1km 관찰 창과 이 행정동 모듈은 겹치지만 동일한 범위가 아니므로 고유 식별자·경계·건물 집합을 유지한다.
2. 면목제3·8동의 기존 건물·도로 모판에 개인 배달 기록의 **매장 위치 검토층**을 얹는 순서로 준비한다. 위치 점을 건물에 포함시키는 것은 후보 산출이며 실제 상호·호실·출입구·현재 영업의 확정이 아니다.
3. 첫 지역의 선택·해제·날짜 필터·한 건물의 여러 매장 선택·위치 미확인 상태를 확인한 뒤, 아직 담지 못한 실제 매장의 위치와 공식 공간 근거를 기준으로 **다음 행정동 모듈을 하나씩** 추가한다. 지역 사이에 별도 정본 Scene을 만들지 않고 기존 공통 조립 계약과 `SimulationWorldShell`을 재사용한다.
4. **같은 수준**은 건물 수나 점포 수를 맞추는 뜻이 아니다. r23의 동일한 `G0~G7` 깊이 검사표를 모든 새 지역에 적용하고, 사실 기반 우선 완료선 `G0~G4+G6`을 지역별로 검증한다. 자료가 없는 층은 `Missing / Blocked / NotAssessed`로 보여준다. 사가정의 시설·높이·외관을 다른 지역에 복사하지 않는다.
5. r39의 집중 정밀화는 첫 지역의 검토 단위로 이어진다. 이전의 30동 **일괄 정밀 렌더 보류**는 유지하며, 이번 결정은 필요한 매장 범위를 따라 지역을 점진 추가하는 방향을 확정한다.

## 첫 플레이어 관찰 절편

- **지금·여기:** 개인 배달 이력을 살피는 지역 운영자가 면목제3·8동 지도를 연다.
- **나·너:** 운영자는 읽기 전용 조회 주체이고, 상대는 특정 건물과 그 안에 있을 수 있는 하나 이상의 기록 매장이다. 실제 고객·현재 기사 위치는 등장하지 않는다.
- **이렇게·직접 결과:** 건물 또는 매장 위치 후보를 선택하면 선택 상태와 날짜별 방문 기록·위치 근거를 오른쪽 카드에 보여준다. 같은 건물에 두 매장이 있으면 어느 기록을 볼지 한 번 더 선택한다. 확인된 실제 매장 사진이 없으면 사진 대기를 보여준다.
- **선택의 대가:** 지도에서 한 대상에 집중하는 동안 다른 위치의 정보는 접힌다. 위치 근거가 불확실하면 상세 건물 대응을 확정하지 못하고 검토 대기로 남는다. 경영 점수·비용·기사 배차의 새 규칙은 아직 정하지 않는다.
- **실패·회복·귀환:** 건물 불일치·좌표 없음·오래된 자료·사진 미확인은 각각 이유를 표시한다. 선택을 해제하거나 다른 지역을 고르면 이전 선택과 사진이 남지 않고 해당 지역의 공간 상태로 돌아온다. 지도에서 업무 원장을 변경하지 않는다.

## 미정·인계

첫 매장 선택 기능에 대한 `Approved` 기획 관문, 대표 WI·Goal, E1~E7 상호작용 수직 검증 명세, 공간 전문 연구 수용 상태, 기획 revision/hash와 승인 근거, 정확한 `writePaths`와 `ReadyToDispatch` 작업 명세는 아직 없다. 따라서 이 판본은 **확정한 지역·확장 방향과 실제 입력 대조**이며 제품/Unity 코드를 변경하는 실행 지시는 아니다. 필요한 인계를 준비한 뒤 기존 개발 작업실이 현재 기준선과 소유권을 확인한다.
