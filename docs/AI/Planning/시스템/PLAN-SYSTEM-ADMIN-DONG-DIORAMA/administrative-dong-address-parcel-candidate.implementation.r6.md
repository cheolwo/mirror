# [기획 · 월드·공간·배치 · PLAN-SYSTEM-ADMIN-DONG-DIORAMA · 구현 r6]

## 승인 근거와 목표

2026-09-14 사용자는 동북서울 30개 행정동 디오라마를 사가정역 검토 깊이에 맞게 발전시키고, 건물별 도로명주소·도로·골목·신호´생활 자료를 계층별로 보강해 배달 기사와 주민의 생활상을 표현할 수 있게 해 달라고 요청했다. 이 판본은 `G2 AddressParcelEntrance`의 첫 절편으로, 이미 로컬에 동결된 원본만 사용해 30개 동 건물의 PNU와 도로명주소 후보 상태를 만든다.

## 정확한 권위 상한

- `AL_D010 A1` 건물 식별자와 `A2` 19자리 PNU를 원본에서 읽는다.
- 로컬 2026-08 행정안전부 도로명주소 건물DB를 PNU로만 결합한다.
- 결과는 `ParcelAddressCandidate`, `MultipleParcelAddressCandidates`, `NoCandidateInFrozenJusoVintage`로만 판정한다.
- `ExactBuildingAddress`, `OfficialAddress`, 주출입구, 배달 목적지, 가격 권위, Unity 표시 권위는 만들지 않는다.
- 같은 필지의 여러 건물이나 여러 건물관리번호를 하나로 병합하지 않고 수와 충돌 상태를 보존한다.
- 주소를 공개 표시용 디오라마 계약에 넣지 않고 RDB 보호·검토 영역에 둔다.

## 기대 기준선

- 모듈 건물 61,897개 모두에 PNU 관찰 상태를 기록한다.
- 고유 PNU는 54,296개다.
- 동결 JUSO 판본에서 주소 후보가 있는 건물 기준선은 51,227/61,897(82.76%)이다.
- 주소 그룹이 복수인 PNU 361개와 건물관리번호가 복수인 PNU 2,326개를 단일 주소로 선택하지 않는다.
- 10,670개는 현실의 무주소 건물이 아니라 `NoCandidateInFrozenJusoVintage`로 남긴다.

이 수치는 구현 후 생성기와 로컬 DB의 독립 재조회로 다시 계산해야 하며, 다르면 기준선을 억지로 맞추지 않고 차이를 차단 사유로 남긴다.

## 저장·재조회

1. 원본 파일 크기·hash·판본·필드 계약을 먼저 검증한다.
2. 정확히 30개 행정동·61,897개 건물만 처리하고 예상 밖과 중복 건물을 거절한다.
3. 입력을 정렬해 결정적 projection hash를 만든다.
4. 로컬 MySQL의 전용 후보 원장에 `PendingHumanReview`로 저장한다.
5. 동일 입력 재적용은 새 행 0건이어야 하며, 새 DB 연결에서 exact set·상태 분포·hash를 독립 재조회한다.
6. Mongo 디오라마 `current`, 배달권, 주문·배차·정산, Unity 계약은 변경하지 않는다.

## 완료 관문과 다음 단계

이 절편은 30개 동의 PNU·주소 후보 원장이 생성·저장·재조회되고 권위 플래그가 모두 false일 때만 완료다. 다음 `G2b`는 승인형 전자지도·위치정보요약DB의 건물관리번호·주출입구와 `AL_D002` 필지 도형을 같은 판본으로 결속하는 일이다. 그 전에는 이 원장의 주소를 배달 가능 지점이나 건물 카드의 확정 주소로 표시하지 않는다.
