# 배달 매장을 담는 행정동 디오라마 공간 우선

[기획 · 월드·공간·배치 · PLAN-SYSTEM-ADMIN-DONG-DIORAMA · r43]

- 사용자 방향: 2026-10-29, 9월 27일~10월 28일 개인 배달 기록의 매장과 디오라마 건물을 연결하고, 매장을 선택하면 실제 매장 사진을 볼 수 있는 경영 화면을 원한다. 2026-10-29 후속으로 공공데이터포털을 활용해도 좋으며 **매장을 담을 공간 디오라마를 먼저 만들자**고 했다.
- 상태: `StoreCoverageFirstDirectionConfirmed / PrivateHistoricalCandidateAuditCompleted / CurrentBuildingIdentityPending / ScopeExpansionPlanned / NoNewUnityApplication`.
- 선행: [소수 구역 집중 r39](focused-area-refinement.decision.r39.md), [공식 자료 축적 r42](required-data-collection.implementation.r42.md), [디오라마 운영 지도 r9](../PLAN-SYSTEM-REGIONAL-OPERATOR-SIMULATION/diorama-operating-map.direction.r9.md), [화면 시안 선행 절차](../../../../Architecture/화면시안선행제작절차.md).

## 확정한 제작 순서

1. 개인 배달 기록의 **공개 매장 위치만** 읽는 비공개 공간 투영을 준비한다. 9월 27일~10월 28일의 매장 식별자와 날짜별 방문을 유지하고 고객 전달지·주행 경로는 공간 지도에 올리지 않는다.
2. 먼저 중랑구·동대문구·광진구의 기존 30개 행정동 후보를 이어 보는 **다중 행정동 디오라마 모판**을 설계한다. 기존 사가정 1km 정본을 전체 659개 매장의 건물 지도라고 확장 해석하지 않는다. 30개 동에서 다루지 못하는 매장 위치는 다음 영역 모듈의 수집 대상으로 남긴다. r39의 사가정 집중 정밀화는 상세 품질 기준선으로 유지하고, 그때 보류한 30동 일괄 정밀 렌더를 자동 재개하지 않는다.
3. 지도에서는 확인된 매장 위치, 건물 도형 포함 후보, 건물 동일성 검토, 범위 밖, 좌표 보완을 구분한다. 같은 건물에 여러 매장이 있어도 건물을 복제하지 않고 각각의 매장 식별자를 한 건물 후보에 연결한다.
4. 매장 선택 시 오른쪽 카드에서 해당 매장의 방문 날짜·기록·위치 근거를 읽기 전용으로 보여준다. 실제 매장 외관은 **그 지점·방문과 연결된 본인 촬영 원본** 또는 별도 사용 조건이 확인된 사진만 보여주며, 연결 전에는 사진 대기를 표시한다. 사진만으로 현재 영업·실제 건물 동일성·출입구를 확정하지 않는다.
5. 선택 시안 검토 뒤 정확한 기획 revision/hash·작업 명세·소유 경로·검증 상한을 결속하고 기존 개발 관문을 통과한 작은 영역부터 구현한다. 첫 화면은 30동 전체를 동시에 정밀화하기보다 한 동의 지도→매장 선택→근거 카드와 영역 전환을 검증한다.

## 현재 자료를 대조한 수량과 의미

비공개 지도용 DB `delivery-map.sqlite3`의 2026-09-27~10-28 구간에는 배달 기록 1,189건, 매장 식별자 678개가 있다. **659개는 좌표가 있는 매장 수**이며 전체 매장 수가 아니다. 좌표 없는 매장은 19개다. 기존 `northeast-seoul-administrative-dong-dioramas.r2`는 중랑구 16동·동대문구 10동·광진구 4동의 건물 61,897개를 가진 역사 경계 기반 비공개 자료다.

| 비공개 대조 결과 | 매장 수 | 다음 처리 |
| --- | ---: | --- |
| 역사 건물 도형 하나에 매장 점이 포함 | 494 | 서로 다른 건물 429개의 **동일성 검토 후보**로 보존 |
| 30동 역사 경계 안, 포함 건물 도형 없음 | 69 | 좌표·원형·주소와 건물군/출입구를 재검토 |
| 30동 역사 경계 밖 | 96 | 실제 주소와 현행 경계로 추가 행정동 범위를 정함 |
| 매장 좌표 없음 | 19 | 공개 매장 위치 근거를 보완할 때까지 미배치 |

이 수량은 `artifacts/local/store-diorama-binding-20261029/`의 읽기 전용 대조 결과다. `summary.private.json`에 원천 DB·범위 manifest·30개 모듈의 지문과 기준 기간을 남기고, `candidate-ledger.private.json`에 매장별 상태를 비공개로 보존했다. `coverage.private.png`는 실제 좌표 분포를 보여주는 **진단 그림**이며 Unity Game View가 아니다. 점이 도형 안에 들어간 494개도 상호·호실·건물관리번호·실제 출입구가 일치한다고 판정하지 않는다.

## 공식 자료와 차단

- 기존 30동 건물의 원천은 [국토교통부 GIS건물통합정보 SHP](https://www.data.go.kr/data/15083092/fileData.do)의 2026-08-09 판본이다. 포털의 현재 표시도 같은 판본이므로 같은 파일 재수집만으로 494개 매장 동일성을 높일 수 없다. 로컬 manifest의 `RightsConflictUnresolved / DistributionNotApproved`는 이번 읽기 조사만으로 바꾸지 않는다.
- 특정 건물·별동의 주소와 식별자는 [건축HUB 건축물대장 API](https://www.data.go.kr/data/15134735/openapi.do) 및 기존 r42 대조를 재사용하되, GIS A1과 건축물대장 PK가 다르면 동일 필지·가까운 점만으로 확정하지 않는다.
- [도로명주소 주출입구 위치 요약DB](https://www.data.go.kr/data/15050410/fileData.do)는 별도 신청과 이용 목적 심사가 필요하다. 필요한 첫 대상이 좁혀지면 접근 조건을 확인하며, 로그인 상태만으로 사용 승인을 추정하지 않는다.
- 현행 행정동 경계 polygon, 건물·건물군 식별자, 공개 매장 주소와 호실, 사진 원본 대응과 사용 조건을 단계별로 검증한다. 2023 역사 경계와 건물 후보를 현행/공개/게임플레이 권위로 승격하지 않는다.

## 첫 수직 검증 범위와 인계 조건

첫 지역은 기존 사가정 상세 모판이 있는 면목제3·8동에서 고른다. 읽기 전용 매장 선택과 상태별 카드, 같은 건물의 복수 매장 선택, 날짜 필터, 영역 전환/복귀, 위치·사진 미확인 표시를 시안과 실제 화면에서 대조한다. **실제 저장·주문·배차·정산은 이 화면이 수행하지 않는다.** 다른 두 구와 범위 밖 96개는 독립 지역 모듈의 coverage가 확인된 뒤 확장한다.

개발 인계 전에는 이 판본의 사람 검토, 대표 WI의 E1~E7 상호작용 수직 검증 명세, 공간/건물 연구 기준선, `Approved` 기획 관문, `ReadyToDispatch` 작업 명세와 정확한 `writePaths`를 준비한다. 현 단계의 비공개 후보 생성·시안은 Unity Scene·Play Mode·Game View·운영 DB·공개 승인이 아니다.

## 미정과 다음 질문 하나

- 미정: 현행 경계 polygon의 정확 판본, 96개 범위 밖 매장의 추가 영역 순서, 매장과 특정 건물/호실의 확인 기준, 매장 사진의 원본별 연결과 사용 조건, 첫 WI·작업 명세.
- 다음 질문 하나: 첫 실제 화면 검증을 **사가정 면목제3·8동의 매장 선택**부터 시작하고, 나머지 지역은 같은 모판에 순서대로 넓히는 안으로 확정할까? 추천은 이 안이다. 전체 659개를 한 번에 정확 건물로 붙였다고 표시하지 않으면서 실제 클릭 흐름을 먼저 검증할 수 있다.

## 규칙 후보 점검

기존 역세권 규칙 r5와 비교해 점-도형 포함은 동일성 확정이 아니라는 기존 경계를 지지한다. 96개 범위 밖, 69개 도형 미포함은 범위/자료 결손 사례이며 공통 규칙 반례·무효화 또는 새 일반 규칙 승격 근거가 아니다. **새 디오라마 규칙 후보 없음.**
