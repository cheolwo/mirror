# 한 구역의 정밀도를 먼저 완성한 뒤 인접 구역으로 확장

[기획 · 월드·공간·배치 · PLAN-SYSTEM-ADMIN-DONG-DIORAMA · r46]

> 후속 [전체 품질의 층별 누적 r48](area-wide-layered-quality.decision.r48.md)이 한 구역을 먼저 충분히 완성한 뒤 옆으로 넓히는 제작 우선순위를 대체한다. 이 문서의 원본 감사 결과와 기존 자료 경계는 보존한다.

- 사용자 확정: 2026-10-29 — “일정 구역을 되게 정밀하게 만들고 확장해 나가는 방식이 좋아보여.”
- 상태: `FocusedPrecisionThenExpansionConfirmed / FirstWindowSourceAuditCompleted / DetailStudyDraft / UnityHandoffPending`.
- 선행: [작은 구역 집중 r39](focused-area-refinement.decision.r39.md), [점진 확장 r44](delivery-store-iterative-expansion.decision.r44.md), [실제 자료와 시각 목표 r45](myeonmok38-precision-first.proposal.r45.md).
- 전문 연구: [첫 구간 건물·공간 연구 r1](myeonmok38-precision-detail-study.r1.md) — `Draft`.
- 관련 WI·PlayableLoop: 미등록. 기존 읽기 전용 관찰·건물 선택의 재사용을 먼저 검토하며 이번 문답으로 새 게임 행위 ID를 만들지 않는다.
- 플레이 순서: 자유. 핵심 회복·성장 이야기의 직접 결과가 아닌 공간 관찰 보조 층이다.

## 확정한 제작 순서

**작은 구역을 충분히 정밀화하고, 실제 화면으로 그 품질을 확인한 다음 주변을 같은 기준으로 넓힌다.** r39의 집중 정밀화와 r44의 점진 확장을 이 순서로 결속한다. 같은 방향을 다시 승인 질문으로 묻지 않는다.

첫 작업은 면목제3·8동 `region:kr:hjd:1126057500` 안의 사가정역 주변이다. r45의 **250m × 250m 창**을 기존 자료 감사·화면 비교의 첫 작업 창으로 이어간다. 정확 좌표는 r45가 소유하며 이번 발언을 창의 모든 건물 외관·실제 높이·도로 폭이나 전체 Unity 명세의 승인으로 확대하지 않는다.

이 창에서 교차로와 연결 골목처럼 연속된 거리의 건물·길 관계를 먼저 구체화한다. 한 구역의 결손을 남긴 채 새 행정동을 동시에 넓히는 방식은 보류한다. 구체적인 거리 선택은 원형·매장 위치·도로 근거를 대조한 연구에 기록한다.

## 이 구역에서 확인할 정밀도

| 확인할 층 | 첫 구간의 품질 기준 | 자료가 부족할 때 |
| --- | --- | --- |
| 건물 형상 | 원본과 건물 ID를 일치시키고 외곽·분리 부분·내부 빈 공간의 소실을 확인한다. | 없는 형상을 추정하지 않고 대상별 결손을 기록한다. |
| 높이 | 원천 숫자 높이와 임시 4m 높이의 출처를 유지한다. | 층수나 주변 건물로 높이를 확정하지 않는다. |
| 거리·보행 | 건물 간 틈과 길의 위치 관계를 판독하고, 실폭·보도·출입구는 정확 구간 근거가 있는 곳부터 연결한다. | 중심선·후보 위치의 사용 상한을 유지한다. |
| 근접 외관 | 정확히 대응하는 촬영 원본과 사용 조건이 있는 대상부터 간판·차양·창·전면을 검토한다. | 공통 재질과 기초 형상으로 표현하며 실제 외관 복원을 주장하지 않는다. |
| 공통 화면 | 같은 공간·카메라에서 재질·조명·가림·건물 선택·해제·재진입을 비교한다. | 시안·연구 그림과 실제 Unity 결과를 각각 기록한다. |

첫 창에는 건물 외곽 346개(원천 숫자 높이 91개·임시 4m 255개)와 매장 위치 17개/후보 건물 16개가 있다. 이 수량은 r45의 역사 자료 후보 대조 결과이며 정밀화 완료율이나 현행 매장 동일성 결과가 아니다.

## 다음 구역을 여는 조건

첫 구간의 전후·복구 화면과 원본 대응, 건물·길 관계의 근접 판독, 선택·해제·재진입, 실제 Game View와 같은 환경의 성능 측정을 확인한다. 필요한 자료가 없는 층은 상태를 기록하고 사람의 화면 검토에서 남은 결손과 다음 확장 범위를 함께 판단한다. 기존 `G0~G4+G6`의 출처·동일성·표현 검사를 지역별로 재사용한다.

그다음 실제 배달 매장을 살피며 필요한 **인접 구간 하나**를 고른다. 기존 품질 기준과 사용 가능한 자료를 재사용하되, 첫 구간의 건물·외관을 다른 지역에 복사하지 않는다. 다음 행정동이나 확장 방향은 이번 문답에서 미리 확정하지 않는다.

## 지금 진행하는 준비와 남은 관문

346개 건물을 동결 GIS 원본과 대조하는 비공개 형상 감사를 완료하고, [건물·공간 전문 연구](myeonmok38-precision-detail-study.r1.md)에 형상·카메라·대체 표현·검증법을 모았다. 원본 695,761개 레코드에서 대상 346개 ID가 각각 한 번씩 일치했고, 기존 1mm 정규화 계약의 외곽·높이값·높이 종류도 346/346 일치했다. 이 창에는 생략된 내부 ring이나 추가 분리 부분이 없어 새 형상 복원 후보는 0개다. r40의 단일 보완 건물은 이 창 밖이다.

따라서 원본을 다시 압출하는 것만으로 이 창의 정밀도가 크게 늘어난다고 계획하지 않는다. 다음 준비는 기호 높이의 실제 근거·사진 외관·정확 도로/보행 자료의 대상 결속과 공통 재질·카메라 판독 비교다. 감사 결과는 `artifacts/local/store-diorama-binding-20261029/precision-source-audit-r1/audit.private.json`에 건물별로 기록했다.

건물·공간 연구는 `Required / Draft`다. 새 소품 배치·Actor 동작이 없는 현재 연구의 배치·애니메이션은 사유 있는 `NotRequired`로 둔다. 연구의 `Accepted`, 구현용 `Approved` 기획 revision/hash, 대표 WI의 E1~E7 검증 명세, 소유 경로와 `ReadyToDispatch` 작업 명세는 남아 있다. 방향 동의를 이 관문의 자동 통과로 기록하지 않는다.

이번 변경은 기획 방향 확정과 기존 원본의 비공개 감사다. Unity 코드·Scene·실제 Game View·운영 DB·공개·E 증거·commit/push 변경을 의미하지 않는다.

## 미정과 다음 질문

- 미정: 대표 거리의 정확 경계, 실제 높이·도로/보행·외관 자료, 카메라·성능 기준선, WI 재사용과 개발 인계. 현재 원본 감사에서는 새 형상 복원 대상이 발견되지 않았다.
- 다음 질문 하나: 지금 새로 묻지 않는다. 확정된 방법으로 자료 감사를 진행하고, 결과에서 실제 제작 범위를 바꾸는 선택이 생기면 그 한 가지를 시각 비교와 함께 제시한다.

## 이번 변경 검증

원본 ZIP·모듈·원본 reader·감사 script의 SHA-256을 독립 재계산해 감사 JSON과 4/4 일치함을 확인했다. 결과 행346개·고유 ID346개·외곽/높이 불일치0개를 별도 재집계했다. 두 새 문서의 로컬 링크10개와5문서 범위 Fast/diff 검사를 통과했다. Fast 로그는 `artifacts/local/validation/20261029-164637/`이며 문서 변경으로 build/test는 생략됐다. 디오라마 규칙 r5의 Validate도 통과했다. 이 검사는 Unity·Scene·Play Mode 실행 검증이 아니다.

## 디오라마 규칙 점검

기존 원본 우선·기호 높이 구분·동일성 미확정·원형 복구·실제 화면 검증 원칙을 지지한다. 작은 구역부터 완성한다는 이번 선택은 이 PLAN의 제작 순서이며 새 공통 규칙으로 자동 승격하지 않는다. **새 디오라마 규칙 후보 없음.**
