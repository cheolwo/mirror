## 이번에 확정한 우선순위

**공간 자체의 밀도·현실감·일관성을 먼저 높이고, 그 위에서 픽업/라이딩 영상을 뽑는다.** 게임·롱폼·앱 개선의 순환은 유지하되, 매번 새 게임 규칙이나 화면을 늘리는 방향으로 범위를 넓히지 않는다.

사가정에서 시작하고 중랑구·동대문구·광진구·노원구 공릉/태릉 일대를 후속 대상으로 삼는다. 전반의 표현 수준을 한 층씩 높이는 r48을 유지하며, 정확한 작업 구간은 실제 배달 기록·반복 방문·공간 근거·촬영 시점에서의 효과로 고른다.

## 하루 한 번의 실제 작업

1. **증분 점검:** 현재 브랜치·기존 변경·공용 컨텍스트·기획 목차/현재 작업·자료 대장을 확인한다. 전날의 판본/해시·완료/미완료를 이어 사용하고 전체 코드·자료를 매일 다시 훑지 않는다. 프로젝트 전반을 가볍게 살핀 뒤 관련 범위만 깊게 읽는다.
2. **작은 결손 선택:** 주행 시점에서 눈에 띄는 도로/보도·연석과 경계, 건물 전면 깊이·출입 방향·창문/간판/옥상, 거리 소품/녹지, 재질·조명·그림자·가림 중 효과가 큰 하나를 고른다. 기존 Synty와 공통 자산·제작 추출을 먼저 재사용한다.
3. **수집 또는 보완 실행:** 현재 승인/경로 안의 작은 보완이나 원본을 바꾸지 않는 opt-in 시안을 실제로 진행한다. 자료가 필요하면 기존 관측/수집기와 공식 출처를 대조하고 [D429 수집·저장·재조회](../../../../Architecture/게임자료조사전문운영.md)의 기존 승인 로컬 경로에서 가능한 작은 수집을 완료한다. 접근이 막힌 해당 자료는 미확보로 남기고 독립 가능한 작업을 계속한다.
4. **같은 조건으로 확인:** 중요한 시각 변화는 같은 입력·카메라의 전후 화면 또는 짧은 주행 비교로 검토한다. 실제 형상/높이/매장 동일성과 기호/표현 후보를 구분하고 임시 객체·원본 복구와 출처 대응을 확인한다. 시험·PreviewScene·Game View·MP4·실제 앱/운영은 각각 보고한다.
5. **다음 실행으로 인계:** 의미 있는 변경은 현재 작업 snapshot과 실제 결과/근거에 연결한다. 실패 원인과 시도한 안전 대안을 남겨 같은 실패를 같은 방식으로 반복하지 않는다. 단순 보고만 반복하지 않고 가능한 수집/보완 결과를 남기며, 할 수 없으면 필요한 입력과 이유를 명확히 적는다.

이 목록은 매일 모든 항목을 전수 수집하거나 모든 레이어를 한꺼번에 수정하라는 뜻이 아니다. 자료/시안/승인된 구현의 준비 상태와 공유 파일 소유권을 확인하고 그날 닫을 수 있는 작은 범위를 진행한다.

## 자료·에셋과 사용자에게 돌려줄 것

공공자료에는 공식 출처·기준일·좌표계/단위·수집일·해시·이용조건·대응/결손 상태를 연결한다. 실제 형상·매장·건물·출입구가 확인되지 않으면 근접점·이름·가상 주행만으로 일치를 만들지 않는다. 알려지지 않은 상세는 기호/표현 후보로 남긴다.

추가 에셋은 **필요한 종류/후보 → 쓸 장면 → 기존 자산의 한계 → 대체 방법 → 이용조건/확인된 비용 여부 → 우선순위**로 보고한다. 보유 자산으로 가능한 범위를 먼저 구분하고, 구매·구독·유료 호출을 자동 수행하지 않는다. 사용자가 운영 상황을 구체화할 수 있도록 장소·이동·정차·선택이 읽히는 실제 시안/장면과 부족한 정보도 함께 남긴다.

매일 보고의 기본 내용은 다음과 같다.

- 오늘 실제 수집/저장/보완한 것과 근거
- 전날 대비 달라진 화면/출력과 검증 범위
- 남은 문제와 다음 작은 작업
- 필요한 자료·추가 에셋 또는 사용자 결정

실행 가능한 일이 없으면 이유/필요한 입력을 짧게 남긴다. 완료하지 않은 구현·실행·공개를 완료로 보고하지 않는다. 에셋이나 사용자의 새 결정을 기다리는 항목이 있어도 다른 안전한 작업은 이어간다.

## 기존 경계 유지

현재 요청은 일일 점검·수집·안전한 정밀화 순환을 허용한다. 기존 승인 범위의 보완과 opt-in 후보는 진행하되, 미정인 제품/공통 규칙을 조용히 확정하지 않는다. [디오라마 증거 규칙](../../../../Architecture/역세권디오라마증거진화체계.md)의 Observed/Candidate 점검을 유지하고 공통 규칙·정본/공식 Scene·E 단계는 자동 승격하지 않는다.

다른 작업의 변경·원본·이전 판본·공유 Editor/서버를 보존한다. 이 예약을 다른 스레드 메시지·새 스레드 생성, 운영 DB/실제 배차/연락/결제, 외부 업로드/공개, commit/push 권한으로 확대하지 않는다. 새 설계 선택이 필요한 부분은 구체 시안과 필요한 결정을 보고하고 현재 가능한 작업은 계속한다.

- 다음 질문 하나: 지금은 추가 선택을 요구하지 않는다. 실제 후보가 준비되면 **어떤 구체 에셋/표현 차이가 필요한지** 한 가지를 근거와 시안으로 검토한다.
