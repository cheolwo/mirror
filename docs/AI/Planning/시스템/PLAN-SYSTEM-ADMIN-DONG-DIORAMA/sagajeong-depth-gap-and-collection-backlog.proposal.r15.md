# [기획 · 월드·공간·배치 · PLAN-SYSTEM-ADMIN-DONG-DIORAMA · 조사·수집 계획 r15]

## 조사 목적

사가정역 1km 디오라마에서 실제로 확보·검증한 자료 깊이를 비교 기준으로 삼아, 동북서울 30개 행정동이 이미 가진 자료와 아직 수집해야 할 자료를 구분한다. 이 문서는 30개 동을 사가정 화면처럼 보이게 꾸미는 목록이 아니라, 현실 자료를 추측 없이 같은 계약으로 축적하기 위한 수집 대기열이다.

조사 기준일은 2026-09-16이다. 저장소의 동결 원본·생성 결과·보호 원장·Unity 검증 기록과 공식 제공기관 페이지를 함께 대조했다. 이번 판본에서는 새 원본 수집, DB 저장, API 게시, Unity 적용·실행·캡처를 수행하지 않았다.

## 결론

- 30개 행정동은 `G1 BaseGeometry`, `G2a AddressParcelCandidate`, `G3a CrosswalkPoint`, `G3b IntersectionPoint`, `G3c HistoricalWalkNetwork`, `G4a PrivateBusinessCandidate`, `G6 UnityBaseView`까지 공통 후보를 갖는다. 따라서 건물·도로만 있는 초기 r5 표는 현재 상태를 충분히 설명하지 못한다.
- 사가정역이 더 깊은 부분은 1km 창에 한정된 차선·방향표시·신호제어기·신호등 부착대, 역 출구, 엘리베이터·공원 정체성·버스 정류소·가로수, 화면 건물 주소·PNU와 합성 이동 관찰이다.
- 사가정역도 현행 행정동 경계, 실제 필지 도형, 검증된 건물 출입구, 실폭 보행면·연석, 정지선·실제 신호 현시, 현재 통행 graph를 갖추지 못했다. 이 항목은 “사가정에서 30개 동으로 복사”할 수 없고 공식 원본부터 다시 확보해야 한다.
- 30개 동을 같은 깊이로 만드는 첫 우선순위는 생활 NPC가 아니라 `현행 경계 → 필지·건물·출입구 → 이동 표면·신호 관계 → 지역 장소·시간 통계`다. 이 네 층이 같은 판본으로 결속되기 전에는 생활상 화면을 실제 지역 재현으로 부르지 않는다.

## 수집 실행 순서

### A. 공간 정본

1. 최신 월 주소 전자지도 서울 전체분과 `TL_SCCO_GEMD`를 승인된 방식으로 확보한다.
2. 정확 30개 코드, 유효 polygon, 겹침·틈, CRS 변환, 경계 hash를 검사한다.
3. 같은 판본의 건물·건물군·도로구간·출입구를 건물관리번호로 연결한다.
4. `AL_D002` 실제 필지 도형을 PNU로 연결하고, 단일·복수·미결속을 전수 기록한다.

### B. 이동 표면과 신호 관계

1. 횡단보도·교차로 기존 후보를 현행 경계로 재판정한다.
2. 차선·방향표시·제어기·신호등의 전체 원본을 30개 동과 경계 halo까지 추출한다.
3. 실폭도로·보도 통계·도보망·출입구를 서로 다른 원장으로 유지한 채 관계 후보를 만든다.
4. 정확 보도면·연석·정지선·현시가 공개 자료에 없으면 `SourceGapOrDataRequest`로 남긴다. 근접 보간으로 채우지 않는다.

### C. 지역 생활 장소

1. 기존 사업장 후보를 건물·출입구에 확실한 경우만 결속하고 현재 영업·공개 허용·Claim을 분리한다.
2. 사가정 r27의 공원·가로수·엘리베이터·버스정류소 Adapter를 30개 scope로 일반화한다.
3. 학교·의료·복지·공공청사·안전시설과 전통시장의 공식 위치·기준일·이용조건을 수집한다.
4. 시장 점포와 일반 사업장을 자동 병합하지 않고 원천 식별자와 시장 소속 관계를 보존한다.

### D. 시간대별 생활 관측

1. r14 생활인구 후보는 생성기 존재·22,320행 완결 산출물·RDB 독립 재조회부터 닫는다.
2. 개편된 250m 생활인구를 별도 dataset/revision으로 수집하고 과거 행정동 집계와 합산하지 않는다.
3. 생활이동·버스·지하철 승하차를 행정동 또는 250m 집계로 저장하되 개인·직업·주문을 파생하지 않는다.

### E. API·Unity 적용

1. 수집 자료별 검토 승인 뒤에만 불변 투영을 만든다.
2. 레이어마다 `sourceVintage`, `sourceHash`, `projectionHash`, `qualityCode`, `distributionApproved`를 노출한다.
3. Unity는 레이어별 켜기/끄기와 결손 표시만 먼저 제공한다. NPC·차량·신호 Simulation은 별도 승인된 E7 작업 명세가 있을 때만 붙인다.
4. 30개 동의 기초 화면을 다시 찍는 것은 A~C 중 화면을 실제로 바꾸는 읽기 전용 Adapter가 연결된 뒤다.

## 행정동별 완료 기록 형식

30개 동마다 한 행의 진행률만 두지 않고 다음 항목을 exact set으로 기록한다.

- 행정동 고유 식별자·표시명·현행 경계 판본·hash·CRS
- 건물 총수와 현행/역사/미결속 수, 주소·PNU·필지·출입구 상태 분포
- 도로·실폭도로·보도·도보망·횡단보도·차선·교차로·정지선·제어기·신호등 수와 관계 결손
- 역·출구·정류소·공원·가로수·시장·학교·의료·복지·공공시설 수와 기준일
- 사업장 후보·건물 결속·현재 영업 검토·공개 승인 상태
- 생활인구·생활이동·승하차의 시간 범위·공간 단위·결측률
- 원본 파일명·byte 길이·SHA-256·수집시각·제공기관·이용조건·좌표계·단위
- 원본 → 정규화 → 행정동 귀속 → 투영의 각 hash와 반복 적용 무쓰기·독립 재조회 결과
- `current`, 공개, 통행, Simulation, gameplay, Unity 적용 허용 여부

동 하나의 자료가 없으면 0으로 성공 처리하지 않고 원천 미제공, 범위 밖, 좌표 결손, 외부 접근 차단, 사람 검토 대기 중 하나로 기록한다.

## 완료 조건

- 30개 동 모두 같은 체크리스트와 상태 코드로 비교된다.
- A~D 각 원본의 공식 출처·실제 파일 판본·hash·CRS·이용조건이 보존된다.
- 현행 경계가 없는 역사 후보와 현행 정본을 같은 current 세대로 합치지 않는다.
- 주소·업체·생활 통계를 Unity 공개 계약에 넣기 전에 개인정보·공개 허용·정확 위치 일반화를 검토한다.
- 통계·가까운 점·합성 경로로 필지·출입구·정지선·신호 현시·실제 개인을 만들어내지 않는다.
- 같은 입력은 같은 후보 hash를 만들고, 로컬 RDB/Mongo 저장 절편은 새 연결 재조회와 반복 무쓰기를 통과한다.
- Unity 화면 증거는 실제로 연결한 레이어만 주장하며, 수집·DB 검증·API·Scene·Play Mode·Game View를 각각 구분한다.

## 확정

- 현실 공공자료의 출처·판본·결손을 있는 그대로 표현하는 일이 NPC·게임 효과·아르카나·시장 발전 규칙보다 우선한다.
- 사가정역은 완성품이 아니라 깊이와 결손을 함께 보여 주는 비교 기준이다.
- 30개 동 공통 수집은 A 공간 정본부터 시작하고, 수집 원본을 확보하지 못하면 조용한 대체 자료나 합성값으로 메우지 않는다.

## 미정

- 최신 월 주소 전자지도와 `TL_SCCO_GEMD`·건물·출입구 원본의 실제 승인 획득 시점
- `AL_D002` 실제 파일 접근과 30개 scope 추출 권한
- 공개 자료로 얻을 수 있는 정확 보도면·연석·정지선·신호 현시의 범위
- 서울 빅데이터캠퍼스 250m 생활이동 원자료의 반출·이용 조건
- 지자체별 전통시장 현행 원장과 개별 사진·외관 자료의 상업적 이용 가능 범위

## 증거 규칙 판정

이번 조사는 기존의 `출처·판본·hash·결손·권위 상한을 분리한다`는 규칙을 지지한다. 새 보편 규칙 후보나 E 단계 승격은 만들지 않는다. 새 디오라마 규칙 후보 없음.
