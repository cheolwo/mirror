# 활동·정산 화면의 입고·출고 책임 r60

[수용 범위](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/receiving-outbound.implementation.r60.md)와 [r59 기반](activity-settlements-r59.md)을 따른다.

| 페이지 | 사용자 질문과 한 가지 결과 | 표시와 행동 |
| --- | --- | --- |
| `/activity-settlements` | 내 정산이 어느 업무에 속하는가 | 입고·보관/출고·배송/기타·기존 약정 목록에서 한 약정 선택 |
| `/activity-settlements/{agreementId}` | 이 약정에서 무엇을 확인하고 다음에 무엇을 해야 하는가 | 현재 업무 단계·약정 지급 기준·본인 발생 항목별 대기 사유와 기존 서버 허용 행동 |

`활동정산Screen`/`활동정산표시`가 공통 UI이고 WebApp·일반 살뜰 앱의 기존 route가 소비한다. 금액·당사자 필터·동의·완료 관문은 서버 `NeighborhoodSettlementUseCase`가 소유한다. UI 문구나 버튼은 지급 허가가 아니다. 기존 정산 원장과 JSON 판본을 재사용한다.

새 입고·보관 약정의 완료 조건은 출고·고객 수령과 독립이다. 새 출고·배송 약정은 실제 수행 보수의 발생 기록을 유지하고 고객 수령까지 정상 지급 신고를 기다린다. 각 발생 항목은 당시 약정 판본을 따르므로 최신 약정 요약과 과거 항목의 지급 조건이 다를 수 있다. 기존 혼합 약정은 과거 조건 유지로 표시하고 추정 재분류하지 않는다.

재고 연결은 건수만 표시하며 ID·사진 원문·고객 주소를 표시하지 않는다. 로딩/없음/오류/재조회/비활성·응답 유실 복구는 기존 기능을 유지한다. 신규 route·정책 편집 UI·외부 지급 기능은 추가하지 않는다. 이번 화면 증거는 HtmlRenderer이며 실제 브라우저·APK·휴대폰 사용은 별도다.
