# 공개 화물 둘러보기 · 페이지 책임 카드

## 한 가지 질문과 결과

로그인하기 전에 어떤 공개 화물이 있는지 살펴보고, 의뢰 또는 기사 배차 추천이 필요할 때 해당 역할로 로그인한다. 공개 목록을 개인 의뢰·수락 가능한 공개 콜·맞춤 추천과 혼동하지 않는다.

## 진입과 정보

- 전문 기사 앱 `/`는 저장된 인증이 확인되면 기존 기사 홈으로, 미로그인·인증 저장소 확인 실패면 `/driver/public-cargo`로 이동한다. 통합 화주 홈의 `로그인 없이 화물 목록 둘러보기` → `/shipper/public-cargo`, 웹의 같은 공개 경로를 제공한다. 직접 공개목록 진입은 인증 복원을 요구하지 않는다.
- 미로그인 공통 `/workspace/shipper`·`/workspace/cargo-driver`에도 같은 공개 목록을 표시한다. 다른 역할과 권한 거부 화면의 기존 인증 경계를 유지한다.
- 기존 익명 `GET api/v1/shipper/requests/public`의 `공개화물요약응답`만 조회한다. 화물 종류·운송/차량 조건·수량·중량·공개 상태를 페이지 단위로 표시한다.
- 연락처·상세 주소·개인 운송/정산·서버 내부 오류를 표시하지 않는다. 목록의 의뢰 번호를 개인 상세 조회 링크로 만들지 않는다.

## 상태와 주 행동

로딩, 실제 빈 목록, 조회 실패·같은 페이지 재시도, 이전/다음 페이지를 구분한다. 실패를 샘플 목록이나 빈 결과로 숨기지 않는다. 화면 이탈/새 조회 뒤 늦은 응답이 현재 결과를 덮지 않게 한다.

주 행동은 화주 `로그인하고 운송 의뢰`, 기사 `로그인하고 배차 추천받기`다. 전문 기사는 기존 운행 시작 화면의 인증을 거쳐 같은 화면으로 복귀한다. 공통 화주는 인증 뒤 정확한 `/shipper/request` 작성 화면으로 복귀한다. 다른 역할·외부 주소는 새 복귀 허용에 포함하지 않는다. 로그인 완료는 신청·수락·운행 시작·추천 수신 ON을 자동 실행하지 않는다.

## 책임과 후속 인계

공개 목록의 상태는 `공개화물목록ViewModel`, 공개 조회는 `공개화물Client`, 표시와 재시도는 `CargoPublicBrowseScreen`이 소유한다. 서버의 공개 여부·권한·기능 설정은 기존 Controller/UseCase가 소유한다. 개인 신청·추천·운송은 기존 보호 화면과 원장에 인계한다. 운영 기본 비활성·상세 정보의 업무 권한을 변경하지 않는다.

이 카드는 구현 책임이며 실제 렌더·Android APK·물리 단말·HTTP 검증 결과는 별도의 작업 변경 기록에서 보고한다.
