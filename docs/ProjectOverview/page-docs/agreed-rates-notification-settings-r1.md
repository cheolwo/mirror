# 사전 합의 요금표와 알림 설정 책임 r1

2026-10-08 승인 범위는 [업무 옵션 r4](../../AI/Planning/시스템/PLAN-SYSTEM-ROLE-BUSINESS-OPTIONS/agreements-alerts.implementation.r4.md)다. 기존 수행 지도와 독립 하단 카드 r34를 보존한다.

| 화면 | 한 가지 질문 | 표시·행동과 제외 |
| --- | --- | --- |
| 합의 요금표 | 상대방과 어떤 수행 조건에 동의할 것인가 | 본인 제안·상대 응답·기간·판본·검산·철회. 서버가 허용한 행동만 표시. 합의 수락은 배차 수락이 아니며 실제 지급을 하지 않음 |
| 특정 업무의 요금표 | 이번 주문·의뢰에 어떤 합의안을 적용할 것인가 | 원 상세의 실제 WorkId를 전달. 선택 결과와 판본을 재조회. 관리 진입에는 적용 버튼을 두지 않음. 동결된 업무의 소급 변경 금지 |

| 음식점 주문 알림 | 새 주문을 어떻게 받을 것인가 | 주문 목록에서 독립 페이지로 진입. 현재 계정의 Android 기기 설정을 저장. 주문 상태·계약·금액 변경 없음 |

요금표는 음식점·음식기사·화주·화물기사 역할만 사용한다. 역할 선택이나 상대방 ID 입력은 권한이 아니다. 음식과 화물 계산기는 각각 유지하고, 실제 업무의 권한·합의·기간·운송수단·수행자·판본을 서버에서 다시 검증한다. 명시 선택이 부적합하면 기본안으로 조용히 대체하지 않는다. 합의판본과 산정 근거는 배차·정산 원장에 연결하고 실제 청구·입금 완료와 구분한다.

인증 확인·로딩·빈 목록·읽기 실패·유효기간 종료·변경 결과 미확정 상태를 표시한다. 서버 ACK 이후 확인 조회가 실패하면 결과를 확정으로 표시하지 않고 재조회한다. 수정 요청은 멱등 키와 판본을 유지하고 계정 변경·화면 이탈 뒤 이전 응답을 적용하지 않는다. 복귀는 기존 상세 또는 내 정보이며 외부 URL을 허용하지 않는다.

새 배달 알림 제목은 `살뜰 배달 · 새 배달 요청`, 새 주문은 `살뜰 주문 · 새 주문`이다. 짧은 자체 생성 기계음을 Android 알림 채널에 넣으며 음성 합성은 사용하지 않는다. 알림에 고객 주소·전화번호·메뉴 세부 내용을 싣지 않는다. 같은 유효 배차의 푸시와 조회 수신을 하나의 발행 대장으로 중복 차단하되 기존 인앱 미확인 상태를 지우지 않는다.

소리·진동은 별도 설정이며 야간 무음을 선택하면 한국 시각 22:00~07:00에는 메시지만 표시한다. 기사 서버의 기존 알림 OFF 기본값을 그대로 유지한다. OS 권한·앱/채널 차단·무음·방해금지 설정이 우선이며 새 모드 채널로 기존 차단이나 사용자의 무음을 우회하지 않는다. Android 채널의 소리·진동 설정은 생성 후 앱에서 바꾸지 못하므로 모드별 채널을 사용한다. [Android 채널 기준](https://developer.android.com/develop/ui/compose/notifications/channels), [알림 권한 기준](https://developer.android.com/develop/ui/compose/notifications/notification-permission)을 따른다.

음식점 알림은 기존 앱 실행·실시간 연결과 주문 정본 재조회 경로를 사용한다. 강제 종료된 음식점 앱에 대한 원격 푸시 전달을 구현했다고 주장하지 않는다. 기사 푸시는 기존 등록·서버 공급자 연결의 조건을 유지한다. 이번 r35 기사 APK는 Firebase 수신기가 없으므로 앱이 열린 상태의 조회 알림 경로만 포장됐다. APK 포함, 권한 정책 시험, 실제 단말 표시·알림음 청취는 서로 다른 검증이다. 기기·에뮬레이터·Azure 검증은 이번 실행에 포함하지 않는다.
