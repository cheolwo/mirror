# 플랫폼 서비스 소개 화면 책임 카드 r2

2026-10-16. 퀵 우선 공개 대신 음식·퀵·화물·공간·작업을 함께 준비한다. 통합앱·웹을 중심으로 제공하며 현재는 운영 준비 안내다. 실제 업무·수납·지급을 이 화면에서 활성화하지 않는다.

| 항목 | 책임 |
| --- | --- |
| PageKey / route | `Common.Quick.Introduction` 호환 유지 / `/services`, 기존 `/quick` 별칭 유지 |
| 사용자·대상 | 주문자·의뢰인·기사·공간 제공자·현장 작업자 |
| 한 가지 질문 | 어떤 서비스이며 어디서 의뢰/진행/기사 업무를 시작하는가? |
| 결과 | 준비 상태·의뢰부터 전달까지의 절차를 이해하고 기존 전문 화면으로 이동 |
| 기본 정보 | 운영 준비 중, 지역을 한 곳으로 한정하지 않는 방향, 물품/두 장소/조건 확인, 배정/증빙/지급의 구분 |
| 보조 정보 | FAQ에서 요금·배차 시점·직접 지급·문제 문의의 현재 제공 범위 |
| 주 행동 | 기존 역할 선택 홈. 배송 작성·진행·기사 참여는 서비스 문맥의 보조 탐색 |
| 제외 | 공개 주소/전화/이메일 수집 폼, 허위 고객·후기·통계, 미검증 APK 링크, 즉시 배차/실입금/보험 보장 광고 |
| 코드·DB | 공통 `QuickServiceIntroduction` + Web/통합 앱 route wrapper. 조회/저장 API·DB·새 원장 없음 |
| 후속 인계 | 기존 생활 배송 작성→본인 조회→기사 업무. 소개에서 주문/배차/회원가입을 자동 실행하지 않음 |
| 실행 경계 | 현재 정보 공개 단계의 읽기 전용 화면. 기존 DomesticTransportWorkflow·권한·Operational/Simulation 설정을 변경하지 않음 |
| 경계 정본 | Web/통합앱의 `/services`·`/quick`을 기존 공통 PageCapabilityCatalog에 익명 읽기 전용으로 등록. 소개의 표시 가능 상태가 업무·금융의 운영 권한을 뜻하지 않음 |
| 실패·복귀 | 같은 호스트의 실제 route와 안전한 returnUrl로 연결, 역할 선택 홈과 거래 안내로 복귀 |
| 시각 기준 | 기존 역할 시각 기준·단색 아이콘·명확한 주 행동, 모바일/데스크톱 반응형; 실제 지도/GPS처럼 보이는 가짜 위치 없음 |
| 검증 계획 | 공통 컴포넌트 소비 빌드, 320/390/1280px 렌더·가로 넘침·FAQ/링크·외부/업무 요청0·대표 캡처 |

기존 역할 선택 홈을 보존하고 보조 안내 링크만 `/services`로 연결한다. 소개에서 주문·배차·회원가입·권한 부여·결제를 자동 실행하지 않는다. 공개 조건의 정본은 [통합 공개 r105](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/integrated-public-release.r105.md)다. 과거 퀵 우선 미완성 초안 링크를 대체한다.
