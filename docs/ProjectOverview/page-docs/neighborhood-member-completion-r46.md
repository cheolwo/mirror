# 회원 생활 배송 한 건 완주 화면 책임 r46

기준은 [승인 기획](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/member-delivery-completion.implementation.r46.md)과 [기존 회원 배송 페이지](neighborhood-member-delivery-r43.md)다. 기존 지도·장소·물품·배송비·문제 접수·복귀·동의/권한 경계를 유지하며 새로운 정산 화면은 만들지 않는다.

| 항목 | 현재 책임 |
| --- | --- |
| 사용자 질문 | 내가 맡은 물품을 어느 단계까지 인계했고 상대가 실제로 받았는가? |
| 진입 | 내 배송 목록 → 기존 `NeighborhoodMemberWork` 상세 |
| 기본 정보 | 현재 단계의 장소·연락처·전달 요청, 물품·약정 배송비, 인계/수령 확인 상태 |
| 보조 정보 | 기존 접기 가능한 지도·물품 정보와 오류·재조회 안내 |
| 첫 픽업/전달 | 사진이 없더라도 서버의 `EvidenceStageCode`가 있으면 촬영. 사진 저장 확인 뒤 서버 완료 권한을 조회하여 같은 단계의 완료 명령 |
| 전달 완료 | ‘전달 기록 완료 · 수령자의 확인 대기’. 사진/촬영·완료 버튼과 주소·연락처는 닫힘 |
| 수령 확인 | 기존 양측 협업 상세에서 제공자의 완료 제안 → 반대 실제 수령자의 확인. 수행자·운영자가 대신 확정하지 않음 |
| 최종 결과 | 회원 업무는 `Delivered`를 유지하고 `ReceiptConfirmedAtUtc`로 수령 확인을 표시. 지급 완료는 추정하지 않음 |
| 실패/복귀 | 사진 원본은 메모리에만 보유. 응답 유실은 같은 키의 결과 조회/재요청, 판본·단계·계정 변경 시 다음 단계 진행을 차단 |
| 종료/기한 | 기존 종료/취소 즉시 개인정보 숨김과 배정 후 72시간 열람 제한 유지 |

제품 Razor의 320/390px 미리보기는 모의 자료를 사용하며 실제 휴대폰·업무 HTTP·DB·지도·사진 저장·지급 증거가 아니다. 최종 화면/시험/실DB/APK의 실행 범위는 [변경 기록](../../Changes/2026-10-09-neighborhood-member-completion-r46.md)에 각각 따로 기록한다. 시안은 확정 디자인이 아니라 현재 제품의 샘플 화면이다.
