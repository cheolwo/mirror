# 선택 약정의 책임·동의 확인 r1

[기존 활동·정산 책임](activity-settlements-r60.md)과 [페이지 단일 책임 기준](../../Architecture/WholeRoadmapPagePrinciple.md)을 따른다. 기존 정책·원장을 바꾸지 않고 선택 약정의 확인 가능한 관계를 읽기 전용으로 보완한다.

## 페이지 책임

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 본인 활동 정산의 당사자. 기존 `/activity-settlements/{agreementId}`의 `활동정산Screen`을 Web·일반 앱이 소비한다. |
| 대상·진입 문맥 | 기존 인증·조회에 통과한 선택 약정과 현재 사용자. 새로운 역할·원주문 조회 권한을 만들지 않는다. |
| 한 문장 목적 | 당사자가 선택 약정에서 자기 지급·수령 관계, 물품 담당 연결, 현재 판본 동의와 미확정 조건을 확인한다. |
| 완료 결과·상태별 주 행동 | 패널은 판단 근거만 제공한다. 동의·철회·발생 항목 이의·지급 신고·수령 확인은 기존 서버 허용 행동을 유지한다. 패널이 동의나 지급을 실행하지 않는다. |
| 기본 정보 | 상품 업무인 경우 물품 소유자·판매 담당자 연결 유무와 약정 수금 방식, 현재 조회 범위·판본의 필요 당사자·확보 동의 수. 빈 필요 당사자·표시 항목의 담당 누락·불명확한 판본은 동의 완료로 표시하지 않는다. |
| 보조 정보 | 본인이 지급자 또는 수령자인 약정 항목만 펼쳐 표시한다. 내부 작업·배송비 포함 참고와 금액/단가/수량 미정은 별도 안내한다. 원시 당사자 ID·항목 ID·타인 금액은 표시하지 않는다. |
| 독립 업무·제외 정보 | 마트 법적 운영자·현장 배정자·사업자/계약 인증은 현재 DTO만으로 판단하지 않는다. 입고/보관 조건 정정은 기존 원업무 협의에서, 허용된 발생 항목의 이의는 기존 항목 절차에서 다룬다. 없는 수정 route를 만들지 않는다. |
| 진입·실패·복귀 | 기존 화면의 로그인·로딩·오류·재조회·응답 유실 복구와 업무 복귀를 유지한다. 새 요청·초안·선택·멱등 ID를 만들거나 초기화하지 않는다. |
| 코드·API·DB | `활동정산Screen` → 표시 전용 `약정책임확인Panel`/`약정책임확인표시` → 이미 조회된 `NeighborhoodSettlementSummaryDto`. 기존 Client/API/원장 변경 없음. |
| 책임 판정·검증 | 선택 약정의 같은 판단을 돕는 구성. helper·렌더 회귀를 준비하며 실행·소비 앱 빌드·실제 브라우저는 통합 담당 검증 후 구분해 보고한다. 이 문서 작성 시점에는 새 시험을 실행하지 않았다. |

## 변경 전후 정보 배치

| 정보 또는 행동 | 필요한 이유 | 변경 후 위치 | 근거 |
| --- | --- | --- | --- |
| 물품 소유/판매 연결·수금 방식 | 누가 담당으로 기록됐는지와 수금 경로를 확인 | 상품 업무의 약정 상세 요약 | 기존 `Terms.GoodsOwnerUserId`, `SellerUserId`, `GoodsPaymentRoute`만 사용 |
| 동일 판본의 당사자 동의 | 과거 동의나 철회를 현재 완료로 혼동하지 않음 | 기본 표시 | 현재 `TermsVersion`, `RequiredConsentUserIds`, `Consents`. 같은 시각의 상반된 동의는 미확인으로 유지 |
| 본인 지급·수령 항목 | 타인의 거래를 새로 공개하지 않고 내 책임·미정 조건을 파악 | 접는 보조 목록 | 기존 항목의 payer/payee와 합의 금액. 약정은 실제 발생·지급과 별개 |
| 확인할 수 없는 운영/배정 책임 | 담당 식별자를 법적 운영주체로 오인하지 않음 | 접는 확인 안내 | 현재 계약·권한 DTO에는 법적 운영주체/업무 배정 책임을 인증하는 필드가 없음 |

신규 수납·후원·결제·수수료·단가·계약·배정·지급·권한을 생성하지 않는다. 상품대금을 플랫폼 매출로 바꾸거나 현재 표시를 실제 계약·입금·기기/운영 검증으로 표현하지 않는다.

`NeighborhoodSettlementUseCase.Read`는 본인에게 허용된 약정 항목을 필터한 뒤 필요 동의자를 반환한다. 따라서 패널의 동의 수는 현재 조회 범위에 한정하며 전체 계약 전원의 동의·법적 계약 성립·서버 실행 허가로 표시하지 않는다. 응답에 있는 항목의 지급/수령/배송 부담 담당이 필요 당사자 목록에서 빠져 있으면 재확인으로 남긴다. 원래 보이지 않는 당사자를 역추적하거나 추가 공개하지 않는다.
