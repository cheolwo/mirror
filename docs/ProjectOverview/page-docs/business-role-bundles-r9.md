기준은 [승인 기획 r9](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/business-role-bundles.r9.md), [페이지 단일 책임 원칙](../../Architecture/WholeRoadmapPagePrinciple.md), [역할 앱 시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)이다. 기존 [역할 선택·지도 책임 카드](role-map-workspace-r11.md)의 홈 진입을 이번 승인 범위에서 보완한다. 과거 [통합 홈 설명](SsalddelApp/SsalddelApp-P00/README.md)의 화주·창고 홈 구성은 이전 화면 기록이며, 현재 홈 소스는 공통 역할 선택 화면을 소비한다.

## 관리자 업무 문맥의 책임

관리자 페이지의 질문은 “선택한 업무의 현재 진행과 다음 확인 대상을 무엇으로 볼 것인가”다. 화물은 운송·상하차지·운임·기사·과거 신고 기록을, 음식은 주문·현재 인계·중단 검토를 각각 표시한다. `operator`는 기존 인증 역할이며 두 진입의 차이는 업무 문맥이다. 선택·조회·지도·오류·미확정 요청 ID와 로그인/독립 업무 복귀는 그 문맥을 보존한다. 임의의 잘못된 업무 쿼리는 로그인 요청이 아니라 역할 재선택 안내로 처리한다.

화물의 과거 신고는 현재 미처리 사건이나 운송 보류를 의미하지 않는다. 사건 판단은 기존 사건 원장이 소유하며, 공통 홈·운송 카드는 이를 새로 결정하지 않는다. `화물 사건 목록`은 별도 조회 도구로만 연결하고 선택 운송의 사건 상세나 강제 다음 단계로 표시하지 않는다. 음식 관리자에 화물 사건·분산 창고 업무를 섞지 않고 생활·창고의 기존 진입은 홈 아래에서 유지한다.

구판 `/workspace/operator`는 음식 관리로 호환하며 새 관리자 링크는 `business`를 명시한다. 다른 고유 역할은 기존 URL을 유지한다. 업무를 구분한 화면이나 가상 자료의 정상 렌더만으로 기존 전문 원장의 전체 정상/예외 흐름·실제 운송·정산·지급을 재검증했다고 판단하지 않는다. 현재 통합 상태는 **CompletedLocalAndDeviceGroupingValidation / MapFindingsRemain**이며 코드·브라우저·실제 HTTP/DB·APK·물리 단말의 결과를 변경 기록에서 구별한다.
