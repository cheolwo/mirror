# 기사·작업자 주간 누적과 주 1회 지급 연결 확인 r73

2026-10-15. 사용자가 말한 목표는 음식·화물·피킹 후 배송의 건별 보수를 한 사람의 작업 주간에 모아 수요일 또는 목요일에 한 번 입금하는 것이다. 주문자의 선결제 시점, 작업 완료에 따른 보수 발생, 지급 가능액 확정, 실제 기사 계좌 입금은 각각 다르다.

## 현재 코드로 확인한 범위

| 구간 | 현행 근거 | 남은 연결 |
| --- | --- | --- |
| 음식 배달 | `FoodDeliveryDriverWorkspaceUseCase.DailySettlement.cs`는 음식 건별 정산을 한국 날짜의 하루 단위로 조회하고 실제 송금 완료 건수 0·입금 합계 null을 명시한다. | 본인 주간 조회, 화물·피킹과의 공통 명세, 외부 지급 결과 |
| 화물 배송 | `기사지급준비UseCase`·`기사지급승인UseCase`가 완료 운송·수납·계좌·사건 보류와 운송별 지급 요청을 관리한다. r73 배치는 이 요청들을 참조한다. | 자동 주간 마감·PG 실제 지급·입금 대조 |
| 기사 직접 피킹 | `NeighborhoodSettlementUseCase.Entries.cs`가 합의 단가·완료 근거로 활동 보수를 발생시키며 기존 배송 대가를 다시 신규 채무로 만들지 않는다. | 활동 보수와 배송료의 같은 주 명세, 지급대상 연결 |
| 월정산 | `기사월정산Service`는 배차 건수에 따른 플랫폼 이용료다. | 기사에게 지급할 주간 수입으로 재사용하지 않는다. |
| 실제 송금 | `준비전용기사지급Gateway`는 Simulation 검증만 하고 Operational은 차단한다. | 지급대행 계약·계좌/본인확인·잔액·실행·결과 조회 |

r73 화물 배치의 `Weekly`는 원 운송 완료일의 한국시간 수요일~다음 화요일을 대상으로 정리하고, 기본 목요일 09시 또는 설정된 수요일 지급 예정 시각을 따로 기록한다. 예정일은 실제 송금이나 은행 휴일 처리를 뜻하지 않는다. 음식·피킹의 전문 보수 원장은 아직 이 화물 배치에 편입하지 않는다.

사용자는 업무별 기록이 따로 쌓이는 것은 맞고 **정산을 주마다 하면 된다**고 재확인했다. 전문 원장별 누적과 한 사람의 주간 합산을 구분한다. 기존 화물 배치는 한 요청 200행·명시한 지급요청만 포함하고 같은 사람·주에 서로 다른 명세가 있을 수 있다. 주 마감 전 준비도 가능하므로 `Prepared`를 주간 확정이나 지급일 도래로 해석하지 않는다. 늦게 승인된 채무는 원 완료 주에 남지만 누락 자동 수집·다음 지급일 이월·한 번의 지급 실행 묶음은 후속이다.

중복 합산은 `NeighborhoodSettlementUseCase.Validation.cs`·`Entries.cs`·`Read.cs`의 현재 필터를 유지한다. 배송료에 포함된 피킹과 원 배송료 참조는 신규 수입에서 제외하고, 입고비의 주문별 원가 배부를 작업자 보수로 다시 지급하지 않는다.

## 본인 주간 명세 화면의 책임

| 항목 | 기준 |
| --- | --- |
| 한 가지 질문 | 이번 주 어떤 일을 했고, 얼마가 누적됐으며, 언제 얼마를 받을 예정인가? |
| 기본 정보 | 작업 주간·지급 예정일·누적 보수·지급 가능액·보류액 |
| 상세 목록 | 음식 배송·화물 배송·피킹 작업·피킹 후 배송의 원천별 실제 건수와 보수. 피킹과 배송의 합의 대가를 구분한다. |
| 다음 행동 | 보류 사유 확인·증빙 보완 또는 입금 결과 확인. 단순 명세 조회가 송금을 실행하지 않는다. |
| 중복 방지 | 동일한 배송 원천과 활동 발생 키를 재사용한다. 전문 원장 참조나 입고 원가 배부를 새 지급 채무로 복제하지 않는다. |
| 실패/복귀 | 미확정·통신 실패·보류를 0원이나 지급 완료로 바꾸지 않고 같은 요청/원장으로 재조회한다. |
| 검증 경계 | 이 책임 카드는 통합 화면 구현 또는 실제 주간 입금 완료 증거가 아니다. |

## 다음 순서

1. 기존 음식·화물·피킹 보수를 본인 권한의 읽기 전용 주간 명세로 연결한다. 작업 완료 주간과 실제 보수 발생 근거를 대조한다.
2. 명세의 각 원천을 검증된 지급 채무에 연결하고 중복 없는 주간 마감과 행별 보류·이월을 구현한다.
3. 지급대행 계약 범위에 맞춰 지정 요일 실행·은행 휴일·잔액 부족·실패·응답 유실·최종 입금 결과를 연결한다.

선결제와 현재 로컬 구현·검증은 [r73 변경 기록](../../Changes/2026-10-15-transport-prepayment-settlement-r73.md)을 따른다. 운송 원장과 업무 상태의 최종 권위는 기존 서버 전문 원장에 있다.
