# 운송 중 기사 위치 확인

## 페이지 책임 카드

- 사용자·질문: 화주는 본인 운송의 담당 기사가 어디에 있는지, 관리자는 관리 권한 안의 선택 운송 기사가 어디에 있는지 확인한다.
- 대상·진입: 기존 `/workspace/shipper` 및 `/workspace/operator?business=freight-delivery`의 운송 ID·현재 배정 원장을 사용한다. 별도 공개 기사 검색이나 위치 조회 API를 만들지 않는다.
- 같은 목적의 구성: 기존 지도·운송 목록·선택 카드 안에 기사 위치 핀과 마지막 갱신 시각·위치 미수신/지연/종료 상태를 표시한다. 운송 조건·사건 검토·명시적 갱신과 복귀는 보존한다.
- 기본 정보: 현재 운송·담당 기사·서버가 허용한 최근 위치·갱신 시각. 원시 좌표와 과거 이동 이력은 기본 화면에 표시하지 않는다.
- 주 행동·결과: 운송 선택 후 현재 위치를 조회한다. 수락·상하차 완료·운영 조치와 별도이며 지도 핀을 보고 업무 완료로 처리하지 않는다.
- 실패·권한: 로그인/권한 실패는 기존 인증 흐름을 따른다. 미수신·지연·운송 종료는 다른 상태로 표시하고 현재 위치 핀을 만들지 않는다. 조회 실패·화면 숨김·계정 전환은 기존 요청 수명과 위치 만료 보호를 따른다.
- 역할·데이터: 기사 앱은 명시적 운행 중 위치를 서버에 전송한다. 서버가 현재 배정·근무·기록 시각을 판정하며 공통 UI는 그 응답만 표시한다. 완료·취소·재배정 이전 위치를 현재 운송의 위치로 복원하지 않는다.
- 도입·후속: 기존 화물 운송 기능 안에서 보완한다. 위치 기록·최신 위치 색인·기존 지도 호스트를 재사용하고 운영 배차·결제·Unity 반영을 켜지 않는다.
- 검증: 위치 전송 수명·서버 투영/권한·양측 adapter/만료와 실제 화면을 따로 확인하며 합성 좌표를 실제 GPS로 보고하지 않는다. 검증 결과는 변경 기록에 연결한다.

## 페이지 → 코드 → 원장

`DriverLocationForegroundService` → 기존 기사 운행 위치 API → `기사위치기록` 및 최신 위치 색인 → 권한이 확인된 운송별 조회 → `ShipperWorkspaceAdapter` / `CargoOperatorWorkspaceAdapter` → `RoleMapWorkspace`의 기존 지도 호스트다. 웹과 모바일 지도 제공자 및 실제 기기 검증의 범위는 변경 기록에서 구분한다.
