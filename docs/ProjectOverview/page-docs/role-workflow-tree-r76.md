# 역할별 업무 처리 트리 r76

2026-10-15. 휴대폰 없이 서버·공용 앱 코드와 로컬 회귀 시험을 보완하는 범위다. 아래의 업무 완료, 고객 확인, 보수 발생, 지급 신고, 실제 입금은 각각 다른 결과다. 실제 기기·클라우드·송금 완료를 뜻하지 않는다.

```text
업무 시작
├─ 기사 운행
│  ├─ 현재 근무 확인 → 새 요청 번호 저장 → 운행 시작 요청
│  ├─ 서버 확정 확인 → 위치 송신 → 배차 제안 수신
│  ├─ 응답 유실 → 같은 요청·현재 근무 재조회 → 확정 후 이어가기
│  └─ 같은 요청의 명확한 거절 + 정본 대기 → 요청 정리 → 입력 보완 후 재시작
│
├─ 음식 주문
│  ├─ 주문 조건 확인 → 제출 → 음식점 확인 → 기사 확보 대기
│  │  └─ 대기 지연 → 주의/운영자 확인 → 당사자 안내·적격 기사 재탐색
│  ├─ 기사 수락 → 음식점 조리 시작 → 준비 완료 → 픽업 → 전달
│  ├─ 주문자 수령 확인 → 기사 보수·지급 조건 확인
│  ├─ 픽업 전 기사 중단 → 조리·준비 이력 보존 → 재배차
│  ├─ 픽업 후 기사 중단
│  │  └─ 재조리 요청 → 새 기사 수락 → 음식점 실제 조리 → 준비 → 다시 픽업
│  └─ 취소·미수령 문제 → 지원 사건 → 최신 결과를 당사자 전체에 안내
│     ├─ 가능한 현재 대기열 → 적격 기사 재탐색 요청 기록
│     └─ 취소·재배송·비용 합의 필요 → 운영 검토 유지
│        ※ 상담 종결이 주문 취소·환불·수령·입금 완료를 대신하지 않음
│
├─ 화물·생활 물품 배송
│  ├─ 화주 접수 → 수금 조건 확인 → 기사 보수 합의 → 추천
│  ├─ 기사 본인 수락 → 고객 운임과 별개로 기사 보수 보존
│  ├─ 상차·증빙 → 이동 → 하차·증빙 → 화주 인수 확인
│  ├─ 보수 미확정/제시액 변경 → 수락 보류 → 최신 합의 확인
│  └─ 문제 사건 발생 → 업무/정산 보류 → 검토 → 사건 종료
│     ├─ 다른 보류 존재 → 보류 유지
│     ├─ 같은 보류 직전 금융 근거 확인 → 그 상태만 복원
│     └─ 금융 근거 없음/불일치 → 보류·운영자 확인 유지
│
├─ 공간·입고·출고
│  ├─ 공간·보관 조건 합의 → 입고 행별 승인 → 사진·실수량 수령
│  │  └─ 수령/취소/거절/합의 수량 변경 → 같은 규칙으로 계획 완료 판정
│  ├─ 주문 → 재고 예약 → 피킹 → 포장/인계 → 기사 배송 → 고객 확인
│  ├─ 누락·파손·부분 수령 → 원래 수령·문제 증거 보존
│  │  ├─ 주문자·판매자 해결 제안 → 각자 실제 수량·근거 확인
│  │  │  └─ 현재 원천 + 전량 + 양측 동의 일치 → 수령 재확인 → 지급 조건 재검사

│  └─ 공간 사용 철회 → 새 업무 차단·잔여 물품 보존
│     └─ 공간 제공자·물품 소유자 반출 합의 → 지정 담당자

│           ├─ 반출된 물품의 보관기간 재확인 → 새 보관료·기간 원가 배부 보류
│           ├─ 미수령 입고/예약/기사 보관/불량·잔여 물품 존재 → 종료 보류
│           └─ 잔여와 미완료 반출 없음 → 공간 제공자 확인 → 공간 종료
│
└─ 보수·주간 명세
   ├─ 전문 업무 완료 기록 → 합의 단가·수량으로 보수 발생
   ├─ 본인 주간 명세 → 음식/화물/피킹 등 완료 주간으로 조회

   ├─ 금액·지급 조건 확인 → 보류 또는 지급 가능한 범위 확인
   ├─ 지급자: 실제 지급 내역 신고 → 수령자: 별도 수령 진술
   └─ 실제 은행 입금 확인 → 별도 외부 연동·운영 검증 필요
```

## 현재 완성 범위와 남은 단계

- 기본 OFF·Simulation 경계, 전문 원장 권위, 본인/당사자 권한, 판본·같은 요청 복구를 유지한다. 실제 송금이나 임의의 비용·보상 기준을 추가하지 않는다.
- 새 마트 해결은 전량 수령 재확인만 기존 지급 관문에 연결한다. 부분 정산·반품·환불·비용 배분의 구체적인 결정은 운영 검토에 남는다.
- 음식 지원 후속은 기존 배차 재탐색 요청 또는 운영 검토 인계다. 수락 이후 취소·전달 후 재배송·재조리 비용·기사 보수 책임의 실제 결정 명령까지 완료했다고 표시하지 않는다.
- 주간 명세는 기존 활동·정산 화면에서 조회한다. 자동 주간 송금과 실제 은행 확인은 후속이다. 지급 신고의 미확정 복구는 현재 로그인 세션 범위이며 앱 프로세스 종료 뒤의 영속 복원은 후속이다.
- 전체 결과와 실제 검증 범위는 [r76 구현·검증 기록](../../Changes/2026-10-15-workflow-exception-closeout-r76.md)을 따른다.

## 음식 지원 후속 화면 책임

기존 보호지원관리 상세에서 현재 음식 사건과 원 주문만 다룬다. 사용자는 서버관리자이며 질문은 “안내한 지원 결과를 어느 다음 업무로 인계할까?”다. 기본 정보는 최신 사건·주문 판본, 결과 통지 확인과 가능한 행동이며, 마지막 인계 기록과 운영 추적 링크는 보조 정보다. 주문 취소·수령·환불·입금은 독립 결과다. 응답 유실에는 같은 요청 결과와 정본부터 확인하고 사건/계정 변경의 늦은 응답을 버린다.
