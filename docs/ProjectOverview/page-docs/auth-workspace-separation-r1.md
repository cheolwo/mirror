# 로그인과 업무 화면 책임 분리 r1

사용자가 로그인 화면과 업무 화면의 겹침을 지적하고 단일 책임 원칙에 따른 보완을 요청했다. 기준은 [페이지 원칙의 인증/업무 경계](../../Architecture/WholeRoadmapPagePrinciple.md#인증과-업무의-경계)다. 공용 디자인 토큰·기존 route·서버 권한·작성 수명은 유지한다.

## 책임 카드

| 대상 | 업무 화면의 질문과 결과 | 인증 화면의 질문과 결과 | 분리·복귀 |
| --- | --- | --- | --- |

| 판매자·운영자 앱/운영자 웹·기사 `/login` | 상품·출품·운영 원장·기사 업무 | 해당 역할 계정 인증 | 기존 로그인 route의 인증 전용 Layout. 기존 공용 Providers를 유지하고 업무 drawer/footer를 함께 조립하지 않음. 운영자 웹은 Providers를 Router가 한 번 소유 |

| 공동구매 상품·수요 | 공개 카탈로그 탐색·로컬 수요 작성 | 저장 계정 인증 | 공개 탐색/작성에는 CTA만, 별도 인증 모드에 명시 진입·취소. 같은 선택·메모·동의·기존 수요 식별자 복귀, 자동 저장 없음 |

인증 화면에는 계정 입력·인증 오류/로딩·로그인·취소/공개 이동만 둔다. 기본 업무 화면의 대상·금액·작성·주 행동과 업무 이력은 인증 이후 또는 명시 복귀 이후에만 조립한다. 다른 화면을 단순 접기만 한 것으로 분리 완료를 판정하지 않는다.

## 공통 역할 로그인 페이지 책임 — 2026-10-25 보완

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 통합 앱·통합 웹에서 선택한 역할로 인증할 사용자. 두 호스트의 `/workspace-login/{RoleKey}`가 같은 [RoleWorkspaceLogin](../../../Ssalddel.Ui.Common/Areas/App/RoleWorkspace/RoleWorkspaceLogin.razor)을 소비한다. |
| 대상·진입 문맥 | 선택한 `RoleKey`와 `ReturnUrl`을 받는다. 외부 주소를 제외한 기존 `/workspace/` 복귀와 화주 역할의 `/shipper/request` 작성 복귀만 허용하며, 허용되지 않은 값은 해당 역할의 기본 workspace로 돌아간다. |
| 한 문장 목적 | 선택한 역할로 인증한 뒤 허용된 원업무 화면으로 복귀한다. |
| 조회·기본 정보 | 역할 표시명과 인증 진행·실패 상태를 표시한다. 로그인 페이지에서 화물·주문·배차 목록이나 금융 원장을 조회하지 않는다. |
| 입력·보조 정보 | 아이디·비밀번호만 입력하며 각 라벨과 입력의 `for`/`id`를 연결한다. 입력·로그인·취소는 모바일 한 열, 전체 너비로 배치하고 최소 48px 높이를 적용한다. 업무 초안·요청 ID는 원업무의 기존 복구 책임에 남긴다. |
| 상태별 주 행동·성공 | 대기에는 로그인, 요청 중에는 `로그인 중`과 입력·제출 비활성 상태를 표시한다. 기존 `IRoleWorkspaceAccess.SignInAsync`가 성공하면 허용된 복귀 경로로 이동한다. 인증 성공은 의뢰 등록·배차 신청/수락·송금 등 원업무 실행의 성공이 아니다. |
| 실패·재시도 | 인증 실패에는 아이디·비밀번호 확인 안내를 표시하고 서버 내부 오류를 노출하지 않는다. 아이디는 유지하고 비밀번호는 지운 뒤 사용자의 명시적 재제출을 받는다. 자동 재로그인·업무 명령 재전송은 하지 않는다. |
| 취소·이탈·반복 실행 | 취소는 현재 로그인 수명을 취소하고 비밀번호를 지운 뒤 같은 안전한 복귀 경로로 이동한다. 페이지 이탈도 로그인 수명을 취소한다. 요청 중 중복 제출은 막으며 완료·실패·취소 후 비밀번호를 보관하지 않는다. |
| 독립 업무·제외 정보 | 개인 목록·작성·추천·운송·정산은 각각 기존 보호 화면으로 인계한다. 로그인 화면에 업무 입력과 자격 입력을 섞지 않으며 로그인이나 취소를 업무 제출·철회로 간주하지 않는다. |
| 코드·API·DB | [MAUI 호스트](../../../SsalddelApp/Components/Pages/RoleWorkspaceLoginPage.razor)·[웹 호스트](../../../Ssalddel.WebApp/Pages/RoleWorkspaceLoginPage.razor) → 공통 로그인 → 기존 `IRoleWorkspaceAccess` 인증 어댑터. 토큰·세션 저장과 서버 권한은 기존 인증 계층, 원업무 변경은 기존 API/UseCase/원장이 소유한다. 이 화면은 새 인증 저장소나 업무 원장을 만들지 않는다. |
| 책임 판정·검증 | 인증과 허용된 원업무 복귀라는 같은 목적의 구성이다. 한 열 배치·입력 연결·요청 중 상태·실패·재시도·취소·복귀는 관련 컴포넌트 시험과 검토 APK 0.1.122의 실제 휴대폰 근거를 구분해 [r121 변경 기록](../../Changes/2026-10-25-mobile-app-closeout-r121.md)에 결속했다. 전체 페이지 검토 상태는 변경하지 않으며 로그인 대상 Figma node는 미연결로 `Figma Pending`이다. |

## 코드와 DB

음식점·판매자·운영자·기사는 기존 Login과 공용 Providers를 유지하며 Layout을 독립시킨다. 운영자 웹의 공용 Providers는 업무 Layout에서 Router로 옮겨 인증/업무 화면 모두 한 번 제공한다. 주문자 음식점 탐색은 조립 VM의 인증 표시 상태와 기존 작성 VM을 나누고 Workspace가 하나의 fragment만 렌더한다. 마트는 기존 인증/작성/상품 VM을 유지하며 인증 패널과 로그인된 계정 toolbar를 분리한다. 주문자 바깥 셸은 현재 페이지가 소유하는 표시 문맥으로 인증 중 업무 메뉴/하단 탭을 숨기며 이탈 후 늦은 표시 콜백이 다음 페이지를 바꾸지 못한다. 화주 공용 화면은 앱에서 자격 입력을 제공할 때만 분리 모드를 사용한다. 공동구매·기사도 기존 API와 입력 수명을 재사용한다.

로그인 자체의 권한 판정·토큰 저장은 기존 Auth 서비스, 업무 저장은 기존 API/UseCase/원장이 소유한다. UI 모드 전환이 인증·주문·배차·지급의 권위가 되지 않는다. DB 스키마·요율·원장·공개 계약을 바꾸지 않는다.

창고의 공통 인증 Panel은 현재 페이지 표시 소유권만 결속한다. 로그인 여부만으로 창고 업무 권한을 추정하지 않으며 기존 페이지가 인증 Panel을 조립하는 조건을 그대로 사용한다. 페이지/셸은 그 표시를 구독하고 업무 헤더를 제외하되 ChildContent를 다시 생성하거나 업무 입력을 초기화하지 않는다. 마트의 이탈 후 늦은 요청 선택 콜백도 현재 페이지 표시 소유권을 확인한 뒤에만 화면 이동에 적용한다.

## 검증 상태

최종 Fast 관련122/122와 전체3.5 build가 통과했다. Task는6,071/6,078이며 직전 기준과 기존7실패 이름·오류·첫 시험 소스가 같고 신규39건은 모두 통과했다. 전체 게이트는 미통과다. 음식점·주문자 Android Debug 설치 지문과 로그인/업무 복귀 화면을 확인했다. 다른 역할은 컴파일·관련 렌더/표시 수명 시험 범위다. 실제 화면·소스 지문·검증 범위는 [변경 기록](../../Changes/2026-10-03-auth-workspace-separation-r1.md)에 결속한다. 전수 앱 화면의 준수 판정이나 물리 단말·운영 업무·은행 지급 완료로 확대하지 않는다.
