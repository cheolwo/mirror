# 로그인과 업무 화면 책임 분리 r1

사용자가 로그인 화면과 업무 화면의 겹침을 지적하고 단일 책임 원칙에 따른 보완을 요청했다. 기준은 [페이지 원칙의 인증/업무 경계](../../Architecture/WholeRoadmapPagePrinciple.md#인증과-업무의-경계)다. 공용 디자인 토큰·기존 route·서버 권한·작성 수명은 유지한다.

인증 화면에는 계정 입력·인증 오류/로딩·로그인·취소/공개 이동만 둔다. 기본 업무 화면의 대상·금액·작성·주 행동과 업무 이력은 인증 이후 또는 명시 복귀 이후에만 조립한다. 다른 화면을 단순 접기만 한 것으로 분리 완료를 판정하지 않는다.

## 코드와 DB

음식점·판매자·운영자·기사는 기존 Login과 공용 Providers를 유지하며 Layout을 독립시킨다. 운영자 웹의 공용 Providers는 업무 Layout에서 Router로 옮겨 인증/업무 화면 모두 한 번 제공한다. 주문자 음식점 탐색은 조립 VM의 인증 표시 상태와 기존 작성 VM을 나누고 Workspace가 하나의 fragment만 렌더한다. 마트는 기존 인증/작성/상품 VM을 유지하며 인증 패널과 로그인된 계정 toolbar를 분리한다. 주문자 바깥 셸은 현재 페이지가 소유하는 표시 문맥으로 인증 중 업무 메뉴/하단 탭을 숨기며 이탈 후 늦은 표시 콜백이 다음 페이지를 바꾸지 못한다. 화주 공용 화면은 앱에서 자격 입력을 제공할 때만 분리 모드를 사용한다. 공동구매·기사도 기존 API와 입력 수명을 재사용한다.

로그인 자체의 권한 판정·토큰 저장은 기존 Auth 서비스, 업무 저장은 기존 API/UseCase/원장이 소유한다. UI 모드 전환이 인증·주문·배차·지급의 권위가 되지 않는다. DB 스키마·요율·원장·공개 계약을 바꾸지 않는다.

창고의 공통 인증 Panel은 현재 페이지 표시 소유권만 결속한다. 로그인 여부만으로 창고 업무 권한을 추정하지 않으며 기존 페이지가 인증 Panel을 조립하는 조건을 그대로 사용한다. 페이지/셸은 그 표시를 구독하고 업무 헤더를 제외하되 ChildContent를 다시 생성하거나 업무 입력을 초기화하지 않는다. 마트의 이탈 후 늦은 요청 선택 콜백도 현재 페이지 표시 소유권을 확인한 뒤에만 화면 이동에 적용한다.

## 검증 상태

최종 Fast 관련122/122와 전체3.5 build가 통과했다. Task는6,071/6,078이며 직전 기준과 기존7실패 이름·오류·첫 시험 소스가 같고 신규39건은 모두 통과했다. 전체 게이트는 미통과다. 음식점·주문자 Android Debug 설치 지문과 로그인/업무 복귀 화면을 확인했다. 다른 역할은 컴파일·관련 렌더/표시 수명 시험 범위다. 실제 화면·소스 지문·검증 범위는 [변경 기록](../../Changes/2026-10-03-auth-workspace-separation-r1.md)에 결속한다. 전수 앱 화면의 준수 판정이나 물리 단말·운영 업무·은행 지급 완료로 확대하지 않는다.
