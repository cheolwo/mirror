# 기사 추천 알림 설정

## 페이지 책임

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 기사, 기존 `/driver/notifications/settings`, 음식 앱의 `food-notification-settings` |
| 대상·진입 문맥 | 현재 로그인한 기사 본인의 추천 알림 설정 |
| 한 문장 목적 | 기사가 음식 배달·화물 운송 중 어떤 추천을 알림으로 받을지 선택하고 저장 결과를 확인한다. |
| 완료 결과·상태별 주 행동 | 처음에는 조회, 확인 후에는 저장, 실패 시에는 다시 조회. 저장 후 같은 계정의 서버 설정을 재조회한다. |
| 기본 정보 | 전체 추천 알림과 두 업무별 허용, 식기·트럭 그림의 알림 예시, 소리·진동·야간 무음 |
| 보조 정보 | 기기 알림 허용과 받을 업무 선택은 별도라는 짧은 안내 |
| 독립 업무·제외 정보 | 업무 자격·배차 수신·추천 수락·현재 수행은 기존 화면과 권한을 유지. 토큰·내부 오류·고객 주소는 표시하지 않음. |
| 진입·실패·복귀 | 조회 전/실패/저장 결과 미확인 시 편집 비활성. 계정 또는 로그인 판본이 바뀌면 이전 설정 응답을 폐기. |
| 코드·API·DB | 공통 폼 → 설정 ViewModel → 호스트별 Client → 기존 본인 GET/PUT `api/v1/driver/notifications/settings` → UseCase → 기존 설정 저장소 |
| 책임 판정·검증 | 같은 목적의 구성. 앱·웹 화면, 서버 발송 정책, Android 리소스/소비 빌드, 기기 실수신을 각각 구분하여 변경 기록에 남긴다. |

## 변경 전후 정보 배치

| 정보 또는 행동 | 사용자에게 필요한 이유 | 변경 후 위치 | 근거 |
| --- | --- | --- | --- |
| 업무별 허용·알림 그림 | 서로 다른 추천을 바로 구분 | 기본 표시, 그림과 업무명 함께 표시 | 사용자 요청 |
| 전체 알림·소리·진동 | 원하는 수신 방식 선택 | 기본 표시 | 기존 설정 계약 |
| 배차 수신·자격 | 알림 허용만으로 배차 수락이 되지 않음을 이해 | 짧은 안내 및 기존 업무 설정으로 이동 | 기존 권한 경계 |

신규 업무별 허용 값은 기본 끔이다. 추천 알림만 제어하며 진행 중 업무·정산·취소 알림 정책을 바꾸지 않는다. Android의 작은 그림은 단색 리소스이며, 알림 본문에는 같은 벡터를 음식의 파란 원·화물의 빨간 원 안에 그린 큰 아이콘도 제공한다. 웹/앱 안의 예시는 동일 의미의 선 아이콘을 사용한다. 음식 네이티브 폼은 경로 문자열을 명시적으로 `Geometry`로 변환해 표시한다.

## 실제 기기 확인 · 2026-10-23

Galaxy A34 `SM-A346N`, Android 16에서 음식·화물 211의 실제 OS 알림창 오른쪽 식기/트럭과 기본 끔·종류 끔·전체 끔 차단을 확인했다. 실제 음식/화물 설정 폼의 종류별 저장과 GET 200 재조회도 확인했다. 음식 212에서 설정 화면의 두 그림을 보완한 뒤 OS 알림 재게시·끔 차단도 다시 확인했다. 최종 시각 증거는 음식 212·화물 211이며 음식 211의 이전 증거는 별도 보존한다.

이 시험은 실제 Android 게시기에 합성 자료를 전달한 무음·무진동·90초 알림이다. 외부 FCM·잠금 화면·알림 클릭·소리/진동·iOS 검증과 구별한다. 확인용 Activity는 명시적으로 선택한 Debug 빌드에만 포함되며 기본 또는 Release에는 이 경로를 정의하지 않는다. 실제 계정·배차·수락을 만드는 도구가 아니다.

판본별 증거·대표 화면·남은 범위는 [변경 기록](../../Changes/2026-10-23-driver-recommendation-alerts-r1.md#실제-휴대폰-확인과-보완--2026-10-23)과 `artifacts/local/driver-recommendation-alerts/20261023-device-r1/validation-device-final.json`을 따른다.
