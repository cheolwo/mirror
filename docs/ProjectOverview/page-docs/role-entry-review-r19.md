# 여덟 역할의 첫 진입과 후속 점검 r19

2026-10-05. 사용자는 사람들이 기능을 자유롭게 활용해 서로 잘 살아가는 장을 우선하고 여덟 입장의 사용성을 계속 보완하고자 했다. 공통 방향은 [현재 결정](../../AI/DECISIONS.md#2026-10-05-수수료-중개보다-참여자의-교류와-생활-개선을-우선), 홈 책임은 [r19 책임 카드](role-map-workspace-r11.md#처음-이용하는-사람의-역할-선택-r19)가 소유한다.

## 현재 진입점 대조

| 입장 | 처음 할 일 | 기존 연결 | 다음 이용자 관점 점검 |
|---|---|---|---|
| 생활 | 제공/필요를 둘러보고 이웃에게 문의 | `/workspace/community`는 제품에서 `CommunityNeighborhoodMapPage` 사용 | 공개 글/문의와 비공개 배송 의뢰를 구별하고 익명 탐색 뒤 필요한 입력으로 복귀하는가 |
| 주문자 | 음식 주문 또는 내 주문의 진행 확인 | `OrdererRoleWorkspaceAdapter`의 현재 주문과 별도 음식 주문 입력 | 처음 주문과 이전 내역, 취소/수령 확인의 결과가 분명한가 |
| 음식점 | 받은 주문을 확인하고 현재 조리·인계 처리 | `RestaurantRoleWorkspaceAdapter`, 준비/재조리/픽업 이후 안내 | 기사 배정 전 조리 시작 제한, 재조리와 일반 조리의 현재 회차가 분명한가 |
| 음식기사 | 운행·신규 배차 수신 상태와 요청 확인 | `FoodDriverRoleWorkspaceAdapter`, 현재 수행 우선 선택 | 일거리 없음·수신 꺼짐·배차 연결 실패를 구별하고 요청을 수락/거절할 조건을 볼 수 있는가 |
| 화주 | 보낼 물건의 운송 요청과 진행 확인 | `ShipperRoleWorkspaceAdapter`, 별도 `/shipper/request` | 의뢰 등록·배차 대기·직접 지급 예정/지급 확인을 혼동하지 않는가 |
| 화물기사 | 추천 운송의 조건과 현재 상하차 확인 | `CargoDriverRoleWorkspaceAdapter`, 운송 상태·필수 증빙·보류 | 추천 없음과 권한 문제를 구별하고 보류/재개 뒤 수행 버튼이 같은 상태를 따르는가 |
| 창고 | 현재 수령·검수·보관·출고 처리 | `WarehouseWorkspaceAdapter`, 같은 역할 세션의 독립 검수/운송 요청/인계 | 공정별 허용 권한과 현재 재고를 구별하고 저장 후 다음 공정으로 연결되는가 |
| 운영자 | 음식 주문과 배차 예외의 진행 확인 | `OperatorRoleWorkspaceAdapter`, 관리자 전용 읽기/검토 | 일반 역할과 관리자 권한이 분리되고 확인/보류/재개가 당사자에게 같은 의미로 보이는가 |

근거는 [공통 역할 목록](../../../Ssalddel.Ui.Common/Areas/App/RoleWorkspace/Core/RoleWorkspaceCatalog.cs), [제품 Web 역할 진입](../../../Ssalddel.WebApp/Pages/RoleWorkspacePage.razor), [통합 앱 역할 진입](../../../SsalddelApp/Components/Pages/RoleWorkspacePage.razor)과 해당 adapter다. 표의 마지막 열은 후속 검토 질문이며 모두 미구현 결함이라고 판정한 목록이 아니다. r18이 검증한 상태·연결은 [r18 변경 기록](../../Changes/2026-10-05-state-card-polish-r18.md) 범위로 보존한다.

## 이번 보완

홈의 설명을 역할마다 현재 할 수 있는 행동으로 바꿨다. 주문자를 모든 상품 구매가 가능한 화면처럼 표현하던 문구는 현재 구현인 음식 주문으로, 운영자는 현재 음식 주문/배차 관리에 맞게 좁혔다. 홈 표시명과 제품 Web/통합 앱 홈 제목은 현행 Mirror(거울)로 맞췄다. 여덟 역할의 키·표시 이름·순서·href·선택 상태·로그인과 권한은 유지한다. 신규 기능이나 광고·후원·플랫폼 결제를 추가하지 않았다.

## 보완 순서

1. **첫 진입:** 여덟 설명을 실제 제공 범위와 맞추고 홈의 선택/복귀를 확인한다. 이번 범위다.
2. **빈 상태와 인증 복귀:** 역할마다 처음 이용/일거리 없음/로그인 필요/권한 없음/조회 실패를 실제 제품 호스트에서 구별한다. 생활의 실제 지도와 공통 예시 화면의 차이를 먼저 확인한다.
3. **역할 간 완료 확인:** 음식점·기사·주문자·운영자가 같은 한 주문의 수락·준비·픽업·전달·수령과 예외를 재조회하는 좁은 실행을 검증한다. 화물·창고는 별도 원장을 유지한다.
4. **공개 전 환경:** HTTPS·서버 설정·휴대폰/Azure 통신·오류/문의 경로를 확인한다. 배달 영상의 관심 유입과 앱 공개 운영을 같은 완료로 보고하지 않는다.

지역 광고·후원은 방식이 정해진 후 별도로 검토한다. 주문·운전·증빙·주소·연락처의 업무 상태를 광고 타깃이나 참여 자격으로 바꾸는 구현은 이번 범위가 아니다.

검증 결과와 캡처는 [r19 변경 기록](../../Changes/2026-10-05-role-entry-review-r19.md)에 결속한다. 소스/기존 시험/예시 웹 렌더와 실제 운영 서버·DB·단말·공개 운영을 구별한다.

후속 업무 인계 조사와 확인된 보완 명세는 [r20 여덟 역할 조화 조사](role-handoff-audit-r20.md)에 기록한다. r19의 첫 진입 검증을 역할 간 실제 업무 완주 증거로 확대하지 않는다.
