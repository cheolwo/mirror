# 창고 묶음의 인력 계획과 근무 가능 수신함

- 업무 질문: 선택한 피킹·포장 묶음의 남은 수량을 처리할 인력을 얼마나 요청하고, 누가 가능하다고 답했는가?
- 우선 정보: 실제 묶음·남은 수량과 관측 시각, 요청 시간·필요 인원, 본인 답변과 관리자의 계획 확정.
- 관리자 진입: 기존 출고 단계의 창고·조회 구간에서 `/warehouse/general/workforce`로 이동한다. 기존 번호·공정 순서는 바꾸지 않는다.
- 작업자 진입: `/community/work-availability`. 본인 수신 동의와 받은 요청에 대한 가능·불가·철회만 처리한다.
- 출처: 기존 출고 검토 UseCase의 명시 묶음 키·구성 수량. 미확인·범위 밖·완료 묶음으로 요청하지 않는다. 조회 구간은 실제 근무 회차가 아니다.
- 계산: 관리자가 입력한 시간당 처리량·순작업시간으로만 필요 인원 참고치를 계산한다. 실제 생산성·출근·자동 채용으로 간주하지 않는다.
- 동작: 같은 창고 등록 + 별도 수신 동의, 본인 답변, 관리자 계획 확정. 기존 고용·HR 역할·출근·정산은 변경하지 않는다.
- 화면: 넓은 폭에서는 입력과 결과를 나눠 읽고 390px에서는 세로 카드로 읽는다. 상태·수량·시간을 주 행동보다 앞에 둔다. 기본 키보드·라벨과 같은 묶음 복귀를 유지한다.
- 연락: 앱 수신함 기본. 카카오 인력 요청용 승인 템플릿·응답 주소·인증 연락처와 별도 동의가 있을 때만 공급자에 요청한다. 문자 실행기는 미연결로 표시한다. 발송 접수와 수신·답변·인력 계획 확정은 다르다.
- 검토: 신규 화면 이전 상태는 기존 출고 묶음 화면으로 별도 보존한다. 신규 화면이므로 같은 화면의 레이아웃 변경 전후라고 주장하지 않는다.
