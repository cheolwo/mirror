# 주문자 음식 주문 상세 갱신 마감 r1

## 페이지 책임 카드

| 항목 | 기준 |
| --- | --- |
| 사용자·진입 | 로그인 주문자가 기존 `/orders/food?orderNo=...`에서 본인 주문을 선택한다. |
| 한 가지 목적 | 같은 주문의 최신 진행을 읽고 서버가 허용한 취소·수령 확인을 직접 실행한다. |
| 기본·보조 정보 | 기존 주문·상품·수령 정보와 접기를 유지한다. 갱신 중·이전 정보·실패·다시 확인은 작은 상태 안내로 표시한다. |
| 완료·주 행동 | 성공 조회 후 같은 주문의 허용 행동을 사용한다. 최신 상태를 확인하지 못하면 새로고침이 복구 행동이고 취소·수령 확인은 잠긴다. |
| 수명·복귀 | 동일 주문 갱신은 마지막 성공 내용을 유지한다. 다른 주문·계정·401·403은 이전 개인정보와 행동을 비운다. 비활성·연결 없음은 자동 조회를 억제하고 복귀·재연결은 정본 조회를 기다린다. |
| 제외 | 새 route·지도·결제·요율·DB 변경·접수 영속 복원은 이 문서 범위 밖이다. |

[페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)과 [역할 앱 시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 적용한다. 조회 수명은 [기존 상태 갱신](food-state-refresh-r1.md)과 [사용 흐름 안정화](app-flow-stability-r1.md)를 보완하며 인증 입력과 업무 화면은 기존대로 분리한다.

## 구현과 검증 상태

책임 카드를 먼저 작성하고 기존 상세 ViewModel·갱신 Controller·공유 Razor에 연결했다. 같은 주문은 마지막 성공 내용을 유지하며 작게 갱신·이전 정보·다시 확인을 표시한다. 취소 초안과 수령 메모는 유지하지만 정본 확인 전 변경 행동을 잠근다. 다른 주문 응답은 선택 번호와 대조하고, 계정 전환·401·403에는 이전 개인 상세를 제거한다.

기존 역할 앱 생명주기 State를 공유 Workspace가 구독한다. 비활성·연결 없음은 현재 조회를 취소하고 정기 조회를 억제한다. 복귀·재연결은 실행 중인 사용자 작업 뒤 선택한 주문과 목록을 바로 다시 읽으며, 선택이 없으면 목록만 읽는다. 이미 끝난 주문도 복귀 시 확인하고 같은 활성 신호의 중복 호출은 건너뛴다. 화면 종료는 생명주기 구독과 조회 수명을 함께 정리한다.

최종 401은 명시 로그아웃과 구분해 인증의 세션 만료 경로를 사용한다. 개인 상세와 현재 자격은 비우되 모바일 보안 저장소의 미확정 주문 제출은 보존한다. 동일 계정 재로그인 뒤 접수 결과를 확인할 수 있으며 사용자가 직접 로그아웃하면 저장된 미확정 제출을 지운다.

`OrdererFoodOrderRefreshPolishTests`의 17개 사례는 느린 조회·일시 실패·취소/수령 관문·복귀 직렬화·다시 비활성화된 늦은 응답·주문/계정 전환·401/403·공유 Razor 안내와 잠긴 버튼·Workspace 생명주기 구독을 검증하도록 작성했다. 실제 모바일 인증 adapter와 공통 인증 ViewModel을 함께 사용한 시험은 최종 401·같은 계정 재로그인에 미확정 요청 ID가 유지되고 명시 로그아웃에서만 삭제됨을 확인한다. 기존 회귀시험 1개는 같은 주문 조회 실패 시 마지막 상세를 유지하는 최신 기준으로 수정했다.

1차 통합 Fast(`20261004-144910`)의 기존 회귀4개 실패를 수리했다. 재로그인·인증 복구 중 익명/선택 비움을 실제 주문 전환으로 반영하지 않는다. 정확한 응답 번호 검증은 유지하고 기존 로그인 복원 시험의 빈 상세 대역에 요청 번호를 채웠다. 최종 전용17개와 관련 시험은 Fast `20261004-145754`의409/409에 포함해 통과했다. 전체3.5 빌드도 통과했으며 Task의 기존7실패·새 실패0과 상세 근거는 [통합 기록](../../Changes/2026-10-04-role-app-polish-r1.md)에 둔다.

실제 서비스 HTTP·Android/iOS 앱 복귀·APK·물리 단말 검증은 별도다. 공유 Razor HtmlRenderer와 대역 서비스 시험을 소비 앱 기기 실행으로 보고하지 않는다. OS 종료 뒤 주문 접수 영속 복원은 별도 작업이며 이 문서 범위에 포함하지 않는다. 원시 사본/지문/시험 결과는 Git 제외 `artifacts/local/role-app-polish-r1/orderer-refresh/`에 보존한다.
