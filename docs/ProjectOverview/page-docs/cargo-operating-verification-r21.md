# 화물 정상 자료·예외·운영 대응 검증 r21

기준은 [승인된 r21 작업](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-operating-verification-refactor.r21.md)이다. 제품 업무 상태는 기존 주문·운송·수납·지원 원장을 따른다.

## 책임 카드

| 경계 | 한 가지 책임 | 저장·권위 | 다음 단계 |
|---|---|---|---|
| 시험자료 | 상자·팔레트·시간창·운임 조건을 준비 | 명시된 가상 입력 | 제품 HTTP 명령 |
| 명령 실행 | request ID를 보존하고 접수 결과 확인 | 기존 제품 API·명령 영수증 | 같은 의뢰 재조회 |
| 정본 대조 | 화주·기사 상태, 확정 운임·증빙 비교 | 기존 전문 원장 | 실행별 증거 저장 |
| 증거·대표 사례 | 불변 실행 결과와 검토할 사례 선별 | r21 전용 로컬 자료 | 사람 검토 |
| 운영 알림 목록 | 확인 전·후의 미해결 건 탐색 | 관리자 알림 조회 API | 상세 |
| 운영 알림 상세 | 현재 확인 상태와 다음 행동 표시 | 서버 표시 정책·최신 조회 | 기존 업무 화면 |
| 수납·지급 표시 | 각각의 조회 범위와 확인 한계 표현 | 기존 관리자 API | 기존 전문 업무 |

## 화면 계약

- `/operations-alerts`: 기본은 미해결이며, 확인한 건도 해결 전에는 남는다. 긴급 건과 오래된 건을 먼저 표시한다.
- `/operations-alerts/{id}`: 알림 상태·다음 행동·원장 재확인 시각을 보여준다. 알림 확인은 고객 응답·사건 종결·실지급이 아니다.
- 로딩·빈 목록·조회 실패·응답 유실·오래된 원장·다른 계정/사건 이동을 구분한다. 실패 뒤에는 기존 복구 창을 통해 조회하고 업무로 복귀한다. 결과 불명 명령을 자동 재전송하지 않는다.
- 상세에서 목록으로 돌아갈 때 필터·페이지를 보존한다. 기존 지원·음식 주문 링크만 해당 업무로 안내하고 화물의 `/operations` 링크는 `운영 현황`으로 표시한다. 관리자 통합앱에 없는 화물 상세 경로를 만들지 않는다.
- `eng/RoleWorkspacePreview`의 같은 경로는 실제 공통 UI를 사용하는 메모리 내 화면 검토다. 제품 HTTP·DB·휴대폰·외부 알림 확인과 별개이며 상단에 시험 자료임을 표시한다.
- 모바일은 한 열, PC는 기존 공통 카드와 버튼 정렬을 사용한다. 기술 오류 원문·고객 주소·사진·지급 정보를 알림 화면에 복제하지 않는다.

## 혼자 대응하는 순서

```text
미해결 목록
 ├─ 긴급 건 → 최신 원장 확인
 │   ├─ 조회 불가·오래됨 → 재조회, 결과 불명 명령 반복 금지
 │   └─ 현재 상태 확인 → 기존 지원·운영 업무로 이동
 │       ├─ 배송·사진 문제 → 기존 복구 절차와 증빙 확인
 │       ├─ 거래 분쟁 → 기존 보류·검토·결정 절차
 │       └─ 지급 문제 → 수납·지급을 따로 확인
 └─ 확인한 미해결 건 → 같은 목록에서 계속 추적
     └─ 원인 해소 뒤 정본 재확인 → 기존 관측으로 해결 상태 확인
```

처리할 수 없는 경우 알림 확인만으로 해결 처리하지 않는다. 접수 제한 여부는 운영자가 현재 진행 중인 업무의 복구 경로를 보존하며 별도로 판단한다. 이 작업은 전체 기능을 끄는 새 스위치나 자동 송금·강제 사건 종결을 추가하지 않는다.

첫 응답 6시간·처리 24시간·누적 72시간은 거래 분쟁의 서비스 목표다. 근무시간·휴일·기산점이 미정이므로 실제 운영자 처리 기한은 미설정으로 둔다. `LastVerifiedAtUtc + 2분`은 원장 상태 재조회 기준이며 사람의 처리 기한이 아니다. 기존 지원 사건·개인정보 업무 기한은 그대로 유지한다.

## 실행과 한계

제품 HTTP는 새 loopback 5369·r21 전용 DB에 제한한다. 기존 서버·DB·자료는 보존한다. worker·외부 발송·Operational·실결제·실송금은 비활성 상태를 유지한다. 가상 사진과 모의 수납은 실제 촬영·은행 입금이 아니다. 결과는 [r21 변경 기록](../../Changes/2026-10-22-cargo-operating-verification-refactor-r21.md)에 별도로 기록한다.
