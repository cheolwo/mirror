# 페이지 책임 카드 양식

[기준 문서](../../Architecture/WholeRoadmapPagePrinciple.md) · [화면별 문서 색인](README.md) · [적용 예](page-responsibility-review-r1.md)

아래 카드를 기존 대상 페이지 README의 **페이지 책임** 항목에 채운다. 새 상세 README를 만들 때도 같은 형식을 쓴다. 정책을 복제하거나 사용자의 화면에 이 개발 표를 표시하지 않는다. 확인하지 못한 항목은 미확인과 이유를 적는다.

## 페이지 책임

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 역할, 기존 PageKey/route, 실제 소스와 소비 앱 |
| 대상·진입 문맥 | 선택한 주문/매장 등 식별자, 앞 화면에서 받은 상태·필터 |
| 한 문장 목적 | 누가 어떤 대상을 무엇을 판단하거나 완료하는가 |
| 완료 결과·상태별 주 행동 | 완료로 보는 결과, 각 상태에서 강조할 행동과 서버 조건 |
| 기본 정보 | 각 항목이 어떤 판단/행동에 필요한지 |
| 보조 정보 | 같은 목적의 상세 근거, 기본 접기/펼치기 이유 |
| 독립 업무·제외 정보 | 다른 페이지/업무로 인계할 항목과 목적, 제품 화면에서 제외할 구현 정보 |
| 진입·실패·복귀 | loading/empty/error/retry/disabled, 뒤로 갈 때 선택·필터·초안 보존 범위 |
| 코드·API·DB | 기존 page → ViewModel/Session → Client/API → 원장, 조회·변경 권위 |
| 책임 판정·검증 | 같은 목적의 구성/분리 필요/책임 미검토와 근거, 소스 판본, 시험·실제 화면의 확인 범위와 한계 |

## 변경 전후 정보 배치

| 정보 또는 행동 | 사용자에게 필요한 이유 | 변경 후 위치 | 근거 |
| --- | --- | --- | --- |
| 작성 | 작성 | 기본/상세/다른 업무/제외 | 실제 코드·화면·사용자 요청 |

기존 **페이지 → 코드 → DB** 설명과 실제 검증 기록을 링크해 중복 설명을 줄인다. 모든 화면을 자동으로 채우지 않으며 책임 미검토를 완료로 표시하지 않는다.
