## 기간과 수량의 의미

보완 W2 구성 부분 완료(2026-11-07): 질문은 “선택 묶음의 구성 자체가 없는가, 현재 구성 페이지만 비었는가?”이다. 선택 묶음·창고/구간/공정, 전체 구성 수·현재 페이지, 구성 수량·상태·같은 원출고 상세를 우선한다. 웹의 성공·전체 구성 양수·현재 행0에서 **첫 구성 페이지로**는 같은 묶음·범위·다른 페이지를 유지한 Member0 조회다. 정상 구성과 기존 이전 내역·전체0·오류/로딩·회차 모드를 보존하고320/390/1280px 실제 웹·같은 원출고 상세/복귀를 대조했다. [실제 수정 전후·검증·한계](../../Changes/2026-11-07-warehouse-member-page-empty.md)에 연결한다.

보완 W2 목록 부분 완료(2026-11-07): 웹 단계 묶음 목록에서 전체 묶음은 남고 현재 페이지만 빈 성공 응답을 구별한다. **첫 묶음 페이지로**는 선택 창고·구간·공정·원출고 페이지를 유지한 기존 BatchPage=0 조회와 주소 갱신이다. 웹 단계의 번호 상한 표시도 음수가 되지 않는다. 기존 이전 이동·정상 표·전체 0건·로딩/오류와 회차 모드를 보존했다. [실제 웹·전후 비교·검증](../../Changes/2026-11-07-warehouse-batch-page-empty.md)에 근거를 연결하며 당시 후속이던 구성 MemberPage 복구는 [구성 부분 기록](../../Changes/2026-11-07-warehouse-member-page-empty.md)에서 별도로 마감했다.

기간 입력의 용도는 조회 구간 선택이다. 시작을 포함하고 종료를 제외하는 최대 24시간을 UTC로 전송한다. 기준은 출고예정의 `CreatedAt`이며 재검토로 달라지는 `UpdatedAt`은 접수 귀속과 대기 경과에 사용하지 않는다.

이전 접수 미완료는 선택 시작 전에 생성되어 조회 시점에 남아 있는 출고다. 선택일·직전 7일도 접수 코호트의 현재 상태를 보여 준다. 각 응답의 서버 확인 시각을 표시한다.

접수, 피킹 확인, 포장 확인, 인계 완료는 같은 물량의 공정별 수량이다. 피킹이 작업자 여러 명에게 나뉘면 완료된 작업 수량만 합산한다. 작업 연결이 없거나 수량·완료 근거가 불명확하면 확인 필요 사유를 표시한다. 포장 실제 시작 시각과 교대별 확정 생산능력은 현재 원천에서 확인되지 않는다.

배치 실행·작업 배정·접수 마감·재고 이동·운송 인계의 상태 변경은 기존 전문 업무의 명령이 담당한다. 이 화면의 조회와 기간 전환은 같은 출고 ID와 최초 접수 시각을 이어 읽는다.

## 조회 계약의 호환

기존 목록 요청에 `WarehouseId`, 선택적 `PeriodStartUtc`·`PeriodEndUtc`를 함께 보내면 응답의 `Period`에 회차 현황을 받는다. 두 기간 값은 UTC이며 둘 다 필요하다. 기간을 보내지 않는 기존 목록 호출은 기존 검색·상태·페이지 동작을 사용한다. 회차 전체 집계는 목록 검색과 페이지 제한을 적용하기 전에 선택 창고 전체를 읽고, 회차 항목은 별도로 페이지를 나눈다.

## 공정과 작업 묶음

`Period.Workflow`는 같은 조회 대상 전체에서 공정별 연결을 읽는다. `PeriodStage`는 `review`·`picking`·`packing`·`handoff` 중 하나다. 묶음 목록은 `BatchPage`·`BatchPageSize`(기본 6개), 선택한 `BatchKey`의 구성 내역은 `MemberPage`·`MemberPageSize`(기본 12개)로 조회하며 원래 개별 출고의 `Page`와 독립적이다. 선택한 묶음은 현재 창고·기간·공정 안에서 다시 확인한다.

기존 출고묶음 연결이나 서로 일치하는 포장 완료 근거가 확인된 경우만 기존 묶음으로 표시한다. 명시 묶음 연결이 없는 작업 원장 하나는 개별 작업, 검토·인계 원장은 개별 출고로 표시한다. 시간대·주문 문자열·작업자 바코드만으로 묶음을 만들지 않는다. 연결이 잘못되거나 불명확한 경우는 연결 미확인으로 남기고 수량을 완료로 추정하지 않는다.

묶음 전체에 조회 범위 밖 구성원이 있으면 현재 범위의 수량임을 표시한다. 범위 밖 원출고 번호·작업자 식별값·바코드·완료 근거 원문은 반환하지 않는다. 선행·후속 작업의 창고·원출고·재고·수량과 상호 연결이 확인될 때만 연결 확인을 표시한다.

공정의 표시 순서는 자동 실행 지시가 아니다. 검토 완료량과 처리 기한 등 근거가 없는 값은 미확인이다. 정시 마감·작업 배정·일괄 승인·새 상태 전이는 추가하지 않는다. 이전 회차 조회와 업무별 명령을 그대로 사용한다.

## 웹 단계별 진입과 복귀

웹은 기존 경로의 `stage=review/picking/packing/handoff`로 해당 단계의 처리 묶음을 연다. 이 값은 UI 진입 문맥이며 API의 `PeriodStage`와 구별한다. `warehouseId`·`periodStartUtc`·`periodEndUtc`·`batchPage`·`batchKey`·`memberPage`·`planPage`와 개별 검토의 `outboundPlanId`를 보존한다. 입력 구간은 한국 시간으로 표시하고 URL의 날짜 쌍은 UTC로 해석한다. 주소에 단계가 없으면 기존 검토 모드를 사용한다.

각 묶음의 **구성 내역 보기**는 선택 상세로 전환하고, **같은 출고 검토**는 현재 구성 페이지에서 확인한 원출고만 연다. 개별 상세의 **묶음 구성 내역으로**와 구성 상세의 **묶음 목록으로**는 원래 문맥으로 돌아간다. 늦게 완료된 이전 조회는 새 단계의 상세 주소를 덮지 못한다. 통합 웹과 `/roles/05/` 역할 웹의 기준 경로 안에서 이동한다.

로그인이 필요하면 기존 `/login` 진입에 현재 경로와 전체 조회 조건을 `returnUrl`로 담아 같은 단계·묶음·개별 출고로 돌아온다. 역할 분리 웹은 기존 `/roles/01/` 공통 로그인에서 같은 출처의 창고 경로 `/roles/05/warehouse/general/outbound-plan-review`와 별칭 `/roles/05/work/outbound/plans`만 추가로 허용한다. 기존 안전한 복귀 주소 검사는 유지하며 다른 역할이나 창고의 다른 경로로 허용 범위를 넓히지 않는다.

조회 후 현재 창고·기간·확인 시각은 계속 표시한다. 조건은 **조회 조건 바꾸기**로 열고 처음 조회하거나 결과가 없는 오류에서는 펼친다. 정상 0건과 조회 실패를 구별한다. 수량 설명의 펼치기와 실제 업무 조회·완료 처리는 별개다.

웹 단계 진입의 시안은 `artifacts/local/warehouse-stage-entry-20261107/mockup`, 공정·묶음의 이전 시안은 `artifacts/local/warehouse-batch-flow-20261107/mockup-390.png`, 최초 회차 시안은 `artifacts/local/warehouse-periods-20261107/mockup-390.png`에 있다. 실제 렌더와 시안 수치는 각각의 검증 기록을 따른다.

## 구성 작업 시각의 상한 표시 검증

한국 시간으로 표현할 수 없는 기록/시작/완료 시각만 **미확인**으로 표시하며 수량·담당·상태와 같은 출고의 검토/복귀를 보존한다. 정상/마지막 표현 가능 값/그다음 값/최댓값의 실제 웹46확인·전후10쌍과, 사용자 승인 후 같은 가상 계정으로 재로그인한 등록USB의139→140 실제 전후5쌍을 [W3 변경·검증 기록](../../Changes/2026-11-08-warehouse-member-time-boundary.md)에 연결했다. native는 작업903 구성6개→같은 출고1102 전체10개→상단 **회차별 현황**의 같은 구성 복귀를 확인했다. 웹 단계의 **묶음 구성 내역으로**와 구별한다. 운영 인증/DB·물리 한글IME·운영 사용은 미실행이며 예전 인증 중단 원본도 변경 기록에 보존한다.
