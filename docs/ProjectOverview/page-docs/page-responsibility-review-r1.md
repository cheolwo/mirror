# 기존 세 화면의 페이지 책임 점검 r1

후속 구현: [기사 업무 영역 분리 r1](driver-workspace-sections-r1.md)에서 배달·정산·내 정보 표시와 복귀를 보완했다. 아래 표의 기사 판정은 구현 전 점검 이력이며 최종 검증은 후속 문서를 따른다. 관리자 지급 테스트 분리는 아직 후속 대상이다.

2026-10-03 사용자가 요청한 단일 책임 기준을 [기존 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)에 보강하고 최근 정보 정리 세 화면에 대조했다. [UI 정리 r2](ui-user-simplification-r2.md)의 소스와 실제 화면 근거를 재사용하며, 이번 작업은 책임 문서·작업 지침 연결이다. 새로운 화면·route·API·DB 변경이나 앱 재빌드는 하지 않았다.

## 후속 구현의 경계

1. **기사:** 기존 배달 홈은 현재 상태·다음 행동·업무 진입을 조립한다. 요청 수락과 현재 배달은 같은 수행 흐름의 상태로 구성할 수 있다. 완료 정산과 내 정보는 기존 navigation/진입 파라미터를 조사해 독립 표시·상태 수명·복귀를 정한다. 기존 `entryfocus`와 인증/위치/자동 갱신을 임의로 제거하지 않는다.
2. **관리자:** 추적은 읽기·진단 책임을 유지하고 지급 테스트는 별도 개발 보조 업무로 인계한다. 기존 Simulation·수령 확인·입력 주문번호·금액 동결·revision·멱등 조건을 그대로 재사용한다. 접힌 폼을 이동하는 것만으로 실행 권한이 바뀌지 않는다.
3. **주문자:** 현재 주문 탐색·선택 상세·수령 흐름을 재사용한다. 목록 복귀의 필터/선택, 직접 주문번호 진입, 로그아웃/취소·조회 실패를 별도로 확인하고 새 주문 입력·설정은 이 화면에 넣지 않는다.

단일 책임 기준이 생겼다는 이유로 기존 페이지를 일괄 분할하거나 새 route를 먼저 만들지 않는다. 각 후속 구현은 [책임 카드](page-responsibility-template.md), 해당 소스와 사용 문맥, 기존 코드·원장 인계를 먼저 대조한다. 다른 역할별 화면은 이번 책임 점검 범위 밖이며 미검토 상태를 유지한다.
