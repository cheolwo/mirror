# 기존 세 화면의 페이지 책임 점검 r1

후속 구현: [기사 업무 영역 분리 r1](driver-workspace-sections-r1.md)에서 배달·정산·내 정보 표시와 복귀를 보완했다. 아래 표의 기사 판정은 구현 전 점검 이력이며 최종 검증은 후속 문서를 따른다. 관리자 지급 테스트 분리는 아직 후속 대상이다.

2026-10-03 사용자가 요청한 단일 책임 기준을 [기존 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)에 보강하고 최근 정보 정리 세 화면에 대조했다. [UI 정리 r2](ui-user-simplification-r2.md)의 소스와 실제 화면 근거를 재사용하며, 이번 작업은 책임 문서·작업 지침 연결이다. 새로운 화면·route·API·DB 변경이나 앱 재빌드는 하지 않았다.

## 후속 구현의 경계

1. **기사:** 기존 배달 홈은 현재 상태·다음 행동·업무 진입을 조립한다. 요청 수락과 현재 배달은 같은 수행 흐름의 상태로 구성할 수 있다. 완료 정산과 내 정보는 기존 navigation/진입 파라미터를 조사해 독립 표시·상태 수명·복귀를 정한다. 기존 `entryfocus`와 인증/위치/자동 갱신을 임의로 제거하지 않는다.
2. **관리자:** 추적은 읽기·진단 책임을 유지하고 지급 테스트는 별도 개발 보조 업무로 인계한다. 기존 Simulation·수령 확인·입력 주문번호·금액 동결·revision·멱등 조건을 그대로 재사용한다. 접힌 폼을 이동하는 것만으로 실행 권한이 바뀌지 않는다.
3. **주문자:** 현재 주문 탐색·선택 상세·수령 흐름을 재사용한다. 목록 복귀의 필터/선택, 직접 주문번호 진입, 로그아웃/취소·조회 실패를 별도로 확인하고 새 주문 입력·설정은 이 화면에 넣지 않는다.

단일 책임 기준이 생겼다는 이유로 기존 페이지를 일괄 분할하거나 새 route를 먼저 만들지 않는다. 각 후속 구현은 [책임 카드](page-responsibility-template.md), 해당 소스와 사용 문맥, 기존 코드·원장 인계를 먼저 대조한다. 다른 역할별 화면은 이번 책임 점검 범위 밖이며 미검토 상태를 유지한다.

## 2026-11-05 대표 업무 화면 재점검·구현 전 제안

상태: **Proposed / UserReviewPending / ProductUnchanged**. 사용자가 단일 책임과 요약·상세 분리를 점검하고 구현 전에 제안하도록 요청했다. 이번은 현 소스·기존 화면 자료와 대조한 정보 구조 제안이며 승인·구현·새 런타임 검증이 아니다. 앞선 세 화면의 점검·후속 구현 기록은 당시 근거로 보존한다.

### 범위와 판단

화주 홈/운송 목록/의뢰 상세/창고 허브, 화물기사 추천/진행/운송대금/이용료, 웹·모바일 운영자 음식 운영/주문 추적/정산, 음식점 주문 수신함/상세, 주문자 음식 이력, 판매자 주문 목록/상세, 창고 입고·피킹 목록/상세를 대표로 읽었다. 공통 커뮤니티·음식배달기사·모든 설정/보조 화면의 전수 준수 판정은 하지 않았다.

기본 분리 구조는 이미 있다. 남은 문제는 목록 속 상세의 반복, 조회와 독립적인 설정 저장/모의 실행의 혼재, 같은 주문의 긴 이력이 기본 화면을 차지하는 경우다. 카드나 버튼이 여러 개라는 이유만으로 단일 책임 위반으로 판정하지 않는다. 동일 업무의 보조 근거는 펼침, 독립 저장·실행은 별도 업무, 여러 업무의 홈은 현황 요약과 진입을 맡는 기존 원칙을 적용한다.

### 이미 나뉜 구성은 유지

- 화주 의뢰 상세는 `/shipper/request/{RequestId}`와 `/timeline`, `/payment`, `/proofs`로 이미 나뉜다. 요약 안의 현재 상태·기사·경로·비용은 같은 의뢰 판단에 필요한 문맥이다.
- 기사 추천의 기본 조건/상세 펼침과 별도 배차 설명, 현재 운송과 상하차 증빙, `/driver/payouts` 목록과 `/{TransportId}` 상세는 기존 경계를 활용한다.
- 음식점은 PC 목록+선택 상세, 모바일 `/orders/{OrderNo}`를 이미 사용한다. 같은 주문 처리의 목록/상세를 함께 놓는 것 자체는 문제가 아니다.
- 주문자 음식 이력은 같은 주문 선택·진행·수령 확인의 문맥이다. 판매자 주문은 목록/상세 모드와 목록 복귀 경로가 분리돼 있다.
- 창고 입고 검수·피킹의 목록/상세/실행, 마트 피킹 주문 목록/단일 주문 상세의 경계는 유지한다. 현재 읽기 전용 마트 조회를 실행 완료로 승격하지 않는다.
- 모바일 운영자 목록/주문 상세/중단 검토, 웹 화물 개요/이벤트/증빙/수납·지급, 읽기 전용 현금 흐름도 별도 업무 책임이 있다.
