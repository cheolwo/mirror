# 예외 복구 화면 책임 분리 r2

기준: [승인된 r2](../../AI/Planning/공통/PLAN-OPERATIONS-EXCEPTION-CONTINUITY/exception-continuity.refactoring.r2.md). 기존 route·입력·정보 순서·버튼·원장 권한은 유지하며 내부 조립만 분리한다. 페이지 책임 판단의 정본은 [전체 로드맵 조화형 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)이다.

| 책임 | 음식 역할 행동 | 운영자 지원 사건과 배송 인계 |
| --- | --- | --- |
| 주 사용자·대상 | 주문자·음식점·기사·운영자가 선택한 음식 주문/배달 시도 | 기존 서버 관리자와 선택 지원 사건·연결된 생활 배송 |
| 한 문장 목적 | 허용된 이번 행동을 확인하고 같은 요청의 처리 결과를 확인한다 | 사건을 판단하고 종결 사건에 연결된 배송의 별도 복구를 선택한다 |
| 기본 정보·주 행동 | 역할별 사유/주소/시간/판정 → 요청 내용 확인 → 명시 전송 → 결과 확인 | 사건 처리와 배송 복구 조회 → 처리 선택·명시 확인 → 별도 복구 요청 → 결과 확인 |
| 보조 정보 | 처리 불확실성·입력 오류·현재 가능 행동 | 안내 완료·종결·최신 배송 판본/가능 행동·복구 보류 이유 |
| 독립 결과 | 요청 전송·응답·정본 확인을 구분하고 역할마다 완료 근거를 유지한다 | 사건 종결·배송 재개·수령·정산·지급을 구분한다 |
| 상태 소유 | 요청 준비/완료 근거는 내부 순수 함수, 화면 ViewModel은 계정·전송·조회 수명 조율 | 배송 복구 내부 상태와 표시 Panel, 부모 ViewModel은 계정·세대·취소·사건 명령/복구의 상호 차단 |
| 실패·복귀 | 응답 유실은 같은 번호/원문 유지·GET 우선·명시 재시도. 계정 변경/이탈의 늦은 응답 무시 | 원 배송/사건/요청 영수증 대조. 실패 조회를 미저장으로 단정하지 않고 같은 요청을 확인한다 |
| 페이지 구성 판정 | 같은 목적의 입력·확인·결과 단계를 컴포넌트로 조립한다 | 별도 결과·상태 소유자·명시 인계가 있는 조립. 사건 종결만으로 복구를 자동 실행하지 않는다 |

공개 API/contract·DB·저장 형식·72시간 만료·화면/계정 pending 수명은 변경하지 않는다. 공유 저장소를 전문 업무의 완료 판단 엔진으로 확대하지 않는다. 음식 입력 DOM/CSS와 배송 복구 Panel은 실제 loopback 호스트에서 확인하되 네이티브 단말·운영 DB 증거로 보고하지 않는다.

검증 결과는 [변경 기록](../../Changes/2026-10-10-exception-continuity-refactoring-r2.md)을 따른다.
