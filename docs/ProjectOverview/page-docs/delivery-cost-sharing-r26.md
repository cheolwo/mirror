# 음식 배송비 선택과 부담 확인 r26

2026-10-07. [승인 구현 범위](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/delivery-cost-sharing.implementation.r26.md)를 따른다. 기존 음식점 설정·음식 주문 작성/상세를 재사용하고 비용 분담과 배송사 선정 조건을 구분한다.

| 페이지/역할 | 업무 질문·결과 | 기본 정보와 주 행동 | 보조 정보·오류·복귀 |
| --- | --- | --- | --- |
| 음식점 배송비 설정 | 새 주문의 배송비를 어떻게 부담할 것인가 | 자동 배송 사용·네 방식 선택·해당 금액/비율/한도 → 확인 후 저장 | 예시 계산은 실제 견적과 구별. 응답 유실은 원 설정 ID/조건으로 확인. 기존 주문의 동결 정책은 변경하지 않음 |
| 음식 주문 작성 | 음식점 조건과 내 부담 한도에서 주문할 수 있는가 | 매장 정책 한 줄·내 최대 부담액·계산 예시 → 정책/정보/자동 접수 동의 후 주문 | 완료 시각·허용 처리처는 별도 묶음. 정책 판본 변경은 확인을 다시 받고 초안/원 요청은 유지 |
| 음식 주문 상세 | 비용은 어떻게 나뉘고 지금 무엇을 해야 하는가 | 총 배송비·음식점 부담·내 부담과 적용 정책 → 서버 허용 행동 | 견적/확정 발생비용/청구·지급을 구별. 미확인·한도 초과는 사유/재확인. 기능 OFF는 조회 전용 |

선택 카드는 `주문자 전액 부담 / 정액 지원 / 비율 분담 / 음식점 전액 부담`이다. 선택한 방식의 필드만 표시하고 비율·전액의 한도 유무를 명시적으로 선택한다. 전액 부담 한도 초과는 자동 고객 전가 없이 적합 후보 탐색/보류다. 비율 한도는 음식점 부담을 제한하고 나머지는 고객 상한으로 검사한다.

금액·비율 새 입력에는 암묵적 값을 채우지 않는다. 기존 설정은 그대로 불러오며 신규 매장의 설정은 저장/동의 전까지 적용하지 않는다. 식당 전액의 한도 없음도 사용자가 선택한 조건으로 표시한다. 예시는 배송비 6,000원의 계산임을 명시하며 실제 견적이나 지원금 출금으로 나타내지 않는다.

기존 공통 토큰·모바일 한 열 흐름·오류/재시도/미확정 경계를 유지한다. 실제 소비 앱 빌드, 실제 공유 Razor의 320/390px 렌더, 합성 응답, 격리 HTTP/SQLite, 실제 단말·업체 실행은 분리한다. 검증 결과는 [변경 기록](../../Changes/2026-10-07-delivery-cost-sharing-r26.md)에 연결한다.

## 로컬 화면 확인
