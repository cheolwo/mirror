## 단일책임

인증된 사용자가 영속 판매 주문 원장을 검색하고 동기화 범위, 상태와 페이지를 바꿔 정확한 주문 한 건으로 이동하는 일만 담당한다. 피킹·포장·재고 변경과 알림 정책 Command는 실행하지 않는다.

상세 링크는 목록 상태를 안전한 local `from`으로 보존한다. 기존 `?orderId=...` 링크는 같은 검색·필터·페이지 문맥을 유지한 stable-ID 상세 route로 호환 이동한다.

### 동일 계정 접근 재확인 중 입력 지속 · 2026-10-16 후속

- 같은 사용자 ID와 역할 집합에서 접근 상태를 다시 확인하는 동안 검색 입력·필터 DOM을 유지한다. 화면을 로딩 분기로 교체하지 않으며 조회 행동만 잠시 비활성화한다.
- 기능 OFF·조회 오류·로그아웃 또는 사용자/역할 변경을 관측하면 기존 목록과 필터를 즉시 표시하지 않는다. 다른 계정의 기존 목록을 다시 노출하지 않고, 명시적 재확인 후 해당 계정의 새 목록 조회가 끝나야 표시한다.
- 주기 재확인은 읽기 전용이며 주문 생성·저장·불명확한 쓰기를 재전송하지 않는다. 브라우저의 실제 입력 요소·포커스·입력값 유지와 오류/권한 변경 차단은 코드 시험과 별도로 확인한다.

### 인증 변경 신호 전달 · 2026-10-17 후속

판매자·일반 앱·Web 인증 세션의 기존 `Changed` 이벤트를 선택적 공통 변경 알림으로 전달하고 판매 Workspace가 직접 구독한다. 부모 화면의 재렌더에 의존하지 않으며, 화면 종료 시 구독을 해제한다. 같은 사용자 ID·역할의 토큰 갱신은 입력 요소·포커스·초안을 유지한다. 계정·역할·로그아웃 변경은 접근 재확인 응답을 기다리는 동안에도 이전 자료를 숨긴다. 잠시 다른 계정으로 바뀌었다 원래 계정으로 돌아온 경우에도 명시적 새 조회 전까지 이전 자료를 다시 표시하지 않는다.

격리 브라우저 검사에서 발견된 변경 신호 누락을 수정한 것이며, 이전 `6개 통과/6개 실패` 결과를 성공으로 덮어쓰지 않는다. 신규 단위 검사와 브라우저의 실제 DOM·포커스·초안·계정 차단 검사는 새 소스로 다시 실행하며, 결과와 APK 빌드 여부는 통합 검증 기록에서 별도로 확인한다.

## 검증 경계

### 수집 실패와 출고 보류 책임 · 2026-10-17

판매자는 출고 후보와 별도로 본인 채널의 수집 실패·상품 연결 미확인·재고 부족 원인을 확인하고 채널 계정·상품 연결·재고 담당 화면으로 이동한다. 진단 조회는 외부 주문 수집이나 예약 재실행을 자동 수행하지 않는다. 일부 품목이 매핑되지 않은 주문은 전체 출고를 보류하고 동기화 커서를 유지한다. 보류는 주문 취소나 외부 주문 없음이 아니며, 원인을 보완한 뒤 기존 권한 있는 Operational 동기화 담당이 다시 확인한다. 개인정보·외부 원문/예외 문자열은 진단에 저장하지 않는다.

Web과 모바일이 같은 공용 Screen과 navigation contract를 사용한다. 실제 캡처는 통합 Web host에서 인증되지 않은 상태의 공개 경계를 확인한 것으로, `SsalddelApp` shell 자체의 실기기 캡처는 아니다. 개인정보나 영속 주문 데이터, Command는 사용하지 않았다.
