# 음식점 빌지 출력 장수 설정 r26

[승인 범위](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/restaurant-receipt-copies.r26.md)와 [페이지 책임 원칙](../../Architecture/WholeRoadmapPagePrinciple.md), [역할 앱 시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 따른다. 기존 [음식점 주문 상세 책임](restaurant-order-usability-r1.md)을 유지하며 설정과 주문 처리를 분리한다.

## 페이지 책임

| 항목 | 책임 |
| --- | --- |
| 사용자·소스 | 음식점 운영자, RestaurantDeskApp의 `ReceiptSettings.razor`, `/settings/receipts` |
| 대상·진입 | 이 기기의 빌지 출력 장수. `/store`·탐색 메뉴·기존 주문 상세의 설정 링크에서 진입한다. 주문번호나 고객 정보를 설정에 복사하지 않는다. |
| 질문·결과 | 이 기기에서 빌지를 한 장 또는 두 장으로 만들 것인가. 저장 후 현재 설정을 다시 확인한 결과가 완료다. |
| 기본 정보 | 현재 확인된 장수와 선택 중인 장수를 구분한다. 2장은 조리용·포장용, 1장은 조리·포장용이다. 설정이 없으면 기본 두 장이라는 서비스 정책을 사용한다. |
| 주 행동 | 조회 성공 후 `설정 저장`. 조회 실패 시 `다시 불러오기`가 복구 행동이며 저장하지 않는다. 로드·저장 중에는 선택과 중복 요청을 잠근다. |
| 보조 정보 | 기기 설정과 다른 기기 동기화를 구분한다. 출력 문서와 프린터 부수는 별개이므로 인쇄 창은 1부인지 확인하도록 안내한다. 실제 인쇄·절단 완료는 장치에서 확인한다. |
| 독립 업무 | 주문 수락·조리·배차·전표 재출력은 기존 주문 상세에 남긴다. 장수 설정 저장이 주문이나 인쇄를 실행하지 않는다. |
| 실패·복귀 | 오류 문구를 기본 화면에 표시한다. 저장 결과를 확인하지 못하면 성공으로 표시하지 않고 선택을 보존한다. `다시 불러오기`는 기기의 현재 값을 다시 읽어 선택에 적용한다. 가게 관리·주문 수신함으로 복귀한다. |
| 코드·저장 권위 | `ReceiptSettings` → `I음식점전표출력설정Service.현재조회/저장Async` → 기존 기기 설정 저장 경계. UI는 저장소를 직접 쓰거나 서버 설정을 만들지 않는다. |
| 책임 판정·검증 | 독립 설정 화면과 기존 상세의 명시적 인계로 구성했다. 소스·합성 시험·실제 Razor 렌더·Windows/Android 실행·물리 출력의 결과는 각각 실행한 근거로 기록한다. 문서 작성이나 빌드만으로 화면/인쇄 완료를 표시하지 않는다. |

## 기존 화면 연결

- [가게 관리](../../../RestaurantDeskApp/Components/Pages/Home.razor)와 [탐색 메뉴](../../../RestaurantDeskApp/Components/Layout/NavMenu.razor)에 설정 진입을 추가한다. 기존 메뉴·조리시간·알림 진입은 유지한다.
- [주문 상세](../../../RestaurantDeskApp/Components/Pages/OrderDetail.razor)의 출력 보조 영역에는 `장수는 빌지 출력 설정에서 선택` 안내와 링크만 둔다. 기존 수락·진행·새로고침·전표 출력은 보존한다.
- 실제 문서 구성과 단일 인쇄 요청은 기존 `OrderDetail.razor.cs` 및 문서 출력 서비스의 책임이다. 설정 화면에서 인쇄 창을 열지 않는다.

## 화면과 회귀 확인 항목

기본 두 장·저장한 한 장의 선택, 저장 후 재확인, 조회/저장 실패·복구, 중복 저장 잠금, 화면 종료 후 늦은 결과 제외를 확인한다. 320/390px에서 라디오 두 선택과 안내가 줄바꿈하고, 조작 영역은 48px 이상으로 구성한다. 실제 제품 Razor를 연결한 로컬 미리보기는 합성 자료이며 실제 주문·프린터 검증과 구분한다.
