# 사용자 화면 정보 정리 r2

기존 앱의 음식 주문·기사 배달·관리자 주문 추적 화면에서 이용자의 다음 행동에 필요하지 않은 기술 정보와 중복 표시를 줄였다. API·DB·주문 상태 전이·요금과 지급 조건은 기존 r1을 유지한다.

| 역할 | 기본 화면에 남긴 정보 | 제외하거나 접은 정보 | 주요 코드 |
| --- | --- | --- | --- |
| 주문자 | 음식점·메뉴·주문 금액·진행·수령 확인·실패 복구·다시 시도 | 영속원장/샘플/Workflow 설명, 영문 진단 제목, 위경도·정확도, 중복 요약. 수령 정보와 진행 기록은 기존 접기 유지. 모바일 제목과 주문하기 버튼의 줄바꿈 정리 | `OrdererFoodOrder*` shared components, `OrdererApp/Components/Pages/FoodOrderHistory.razor` |
| 기사 | 요청별 지급액·픽업/전달 주소·유효 시간·수락/거절·수행 버튼·정산·행동이 필요한 오류 | 생명주기 배지·FCM 준비·정상 동기화 시각/주기·원시 좌표·미수락 추천 운임 합계·비어 있는 현재 배달/경로 카드·단계와 버튼의 중복 | `FDriverApp/Pages/MainPage.xaml`, `MainPageModel.cs` |
| 관리자 | 매장·주문/배차/전달·최근 변경·기사 정산·경고/복구. 진행 기록은 단계·상태·시각 | 내부 ID·원장·추천 회차·기술 설명·Outbox·감사 기록은 기본 닫힌 상세 정보, 모의 지급 폼/이력은 기본 닫힌 지급 테스트. 복구 항목이 없으면 빈 카드 제외 | `FoodOrderOperationsTrace.razor` |

기사 정산에는 음식점과 완료 시각, 배달료·공제·수령액을 표시한다. 공제와 수령액이 없으면 미확정을 유지하며 0원으로 대체하지 않는다. 테스트 결과는 `테스트 정산 · 실제 입금 아님`을 남긴다. 월 이용료는 내 정보에 별도 표시한다. 주문번호·정산 ID·시험 증빙은 원장에 보존한다.

정상 자동 갱신 진단만 화면에서 제외했다. 갱신 실패 시 이전 정보일 수 있다는 경고와 아래로 당겨 새로고침하는 안내를 표시하고 성공 조회 후 지운다. 지도는 실제 로딩/설정/인증/연결 실패 안내를 짧게 유지한다. 추정 경로는 실제 경로와 다른 가능성을 유지한다.

주문자 오류는 HTTP 상태와 오류 코드를 사용자 행동으로 설명하며 내부 예외 문구를 화면에 직접 출력하지 않는다. 인증·수명 취소·새로고침 직렬화·배차 실패 복구·실제 수령 확인의 조건은 변경하지 않았다. 관리자 지급 테스트의 현재 서버 Simulation·주문번호 일치·수령 확인·고정 금액·revision·멱등 조건도 유지한다.
