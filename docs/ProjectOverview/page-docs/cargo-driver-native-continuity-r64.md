# 퀵 기사 지도·현재 업무 화면 r64

- 화면: `DriverApp/NativeDriverHomePage.xaml` / `NativeDriverHomePage.xaml.cs`.
- 단일 책임: 지도 위에서 **서버가 지정한 다음 정차 한 곳**을 강조하고 검증된 나머지 상하차 순서를 함께 확인한다. 신규 추천 검토는 별도 배너이며 핀 선택만으로 현재 운송이나 업무 상태를 바꾸지 않는다. 수락 후에는 r20의 같은 정차 순서를 재조회해 B 우선 수행도 표시한다.
- 정책 정본: [퀵 후속 콜 보완 r64](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/quick-driver-continuity.implementation.r64.md). 요율·추천 순위·수신 제한·완료 판정은 서버가 소유한다.

## 연결 수명과 좌표 확인 r29

[r29 보완](../../Changes/2026-10-28-cargo-client-lifetime-r29.md)은 저장된 푸시 등록의 늦은 결과를 전경·세션에 결속한다. 실패는 기존 운송 오류를 덮지 않는 별도 짧은 안내로 표시하며 이탈·계정 변경 때 정리한다. 업무 fallback 지도는 상하차 좌표 쌍을 각각 검사하고 다음 상차 위치가 없으면 하차지로 건너뛰는 선을 만들지 않는다. 현재 원장/정차 순서·권한·수신 의사는 이 표시 보완으로 변경하지 않는다. 단위 회귀와 실제 FCM·GPS/운행의 검증은 구분한다.

| 업무 상태 | 화면에서 필요한 정보 | 허용되는 다음 행동 |
| --- | --- | --- |
| 운행 전 | 운행 시작 안내 | 기존 운행 시작 화면 이동 |
| 운행 중·현재 운송 없음 | 지도·신규 배차받기 토글·유효 추천 배너 | 수신 변경, 추천 조건 검토·수락/거절 |
| 현재 운송 A 수행 | 서버가 지정한 현재 운송 카드·위치·단계별 버튼 | 현재 단계의 다음 행동, 별도 추천 검토 |
| A 수행 중 B 수락 | 수락 결과와 서버 정본을 확인하고 첫 미완료 정차 강조 | A·B 약속과 적재를 지키는 저장 순서가 B 우선이면 B로 전환 |
| 연속 3회 미응답 | 현재 업무 유지·신규 배차 중지 안내 | 기사 본인이 지도 좌측 상단 토글을 켜면 명시 재개 |
| 현재 운송 재조회 실패 | 마지막 확인 업무·실패 안내 | 다시 확인; 미확인 상태에서 업무 변경 버튼 실행 금지 |
| 수락 응답 미확인 | 현재 업무 유지·처리 결과 확인 안내 | 정본 조회; 같은 수락을 새 요청으로 반복하지 않음 |

## 코드와 데이터 책임

- `DriverNativeHomeWorkspaceState`는 한 계정·세션·전경 화면의 갱신과 마지막 확인 상태, 미확정 변경 식별값을 관리한다. 전경 30초 간격 보완 조회와 복귀 즉시 조회를 합류하고 이탈·계정 변경 뒤 늦은 응답을 버린다.
- `IDriverSampleDataService`의 기존 정본 조회가 현재 운송·추천·운행 상태를 제공한다. `CurrentTransport` 실패 slice도 예외와 같은 실패로 처리한다.
- `DriverOperationalDispatchApiService`는 기존 인증 client로 공통 수신 의사·실효 상태를 조회하고, 사용자가 실제 화면에서 확인할 수 있게 표시된 유효 최신 추천의 ID·차수를 ACK한다. ACK는 사람의 읽음이나 알림음 청취 증명이 아니다.
- 운행 시작의 최초 수신 ON은 시작 전에 본 판본을 조건부로 비교해 저장한다. 그사이 수동 OFF가 발생하면 덮어쓰지 않고, 미응답 자동 중지는 기사 본인의 토글 ON으로만 해제한다.
- 원장은 기존 `운송원장`·`용달기사`·`운영배차활동원장` 및 기존 운행 복구 저장소를 사용한다. 현재 운송을 위한 별도 원장·복제 완료 상태를 만들지 않는다.

## 다중 정차 지도 r21

기준은 [약속을 지키는 다중 정차 지도 r21](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-ordered-map.r21.md)이다. 페이지 질문은 “지금 어느 정차로 가고 이후 무엇을 처리하는가”이며 다음 정차 한 곳과 현재 운송의 기존 행동을 기본으로 보여 준다. 추가 업무를 목록에서 수동으로 골라 실행하거나 자동 수락하는 화면을 만들지 않는다.

- 기본: 수락 시 확인한 방문 순서 안내, 첫 미완료 상차의 주황/하차의 파랑 핀, 뒤 순서의 회색 핀과 번호, 기존 현재 운송 카드·길찾기/상세 진입.
- 보조: `방문 순서 보기`로 여러 건의 상하차 순서·마감을 펼친다. 기본은 접고 최대 높이를 제한해 지도를 보며 확인할 수 있게 한다. 접기/펼치기는 표시 상태이며 원장 순서나 수행 상태를 변경하지 않는다.
- 번호는 현재 응답의 미완료 순서다. B 상차 뒤 재조회하면 남은 순서의 첫 하차/상차가 강조되고 완료된 정차는 제거된다. 같은 좌표에 다른 순서가 있더라도 같은 업무 완료로 합치지 않는다.
- 연결선은 지점 순서의 도식이며 실제 도로 경로·전역 최단거리·현재 시각 ETA가 아니다. 약속 시간의 현재 위험 안내와 수락 당시 확인한 순서를 구분한다.
- 조회 실패·보류·불명확/구판 순서는 전체 경로로 강조하지 않고 재확인을 안내한다. 공개 보류·좌표 공백을 주소 검색으로 복원하지 않으며 누락 구간을 건너뛰어 연결하지 않는다. 계정 변경 때 지도·순서 내용·접기 상태를 지운다.

최종 빌드/회귀·실제 지도 SDK/휴대폰 화면 확인은 [r21 결과](../../Changes/2026-10-27-cargo-ordered-map-r21.md)에서 구분한다.
