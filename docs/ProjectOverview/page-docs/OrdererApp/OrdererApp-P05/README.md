## 왜 필요한가

이 화면은 로그인한 주문자가 자신의 개별주문 원장과 현재 단계를 조회하는 0.5 업무 화면입니다. 공동 집계 참여는 별도 동의가 있을 때만 1.0으로 이어집니다.

## 사용자와 참여자

주 사용자: 주문자, 공동구매 참여자 / 보조 참여자: 집단 운영자, 화주 역할 대행자, 관리자

이 화면은 보조 또는 확장 업무 워크플로우 안에서 주문 이력 책임을 갖습니다. 화면 하나가 너무 많은 결정을 떠안지 않도록, 이 문서에서는 이 화면의 주 책임과 다른 화면으로 넘겨야 할 책임을 구분해 관리합니다.

## 화면에서 다루는 일

- 주 책임: 본인의 개별주문 원장 목록과 현재 단계 조회
- 사용자가 확인해야 하는 것: 이 화면에서 상태, 입력값, 다음 행동이 명확히 보이는지 확인합니다.
- 사용자가 조작해야 하는 것: 버튼, 입력, 선택, 업로드, 조회 같은 조작이 이 화면의 책임 안에 머무는지 확인합니다.
- 화면 밖으로 넘길 일: 다른 앱이나 관리자 화면에서 처리해야 하는 상태 변경은 이 화면에 과하게 넣지 않습니다.

## API 경로와 코드 연결

- 화면 소스: [OrdererApp/Components/Pages/OrderHistory.razor](../../../../../OrdererApp/Components/Pages/OrderHistory.razor)
- 클라이언트 서비스/계약: 화면 파일에서 직접 확인하거나 정적/라우팅 화면으로 본다.

목록은 기존 주문자 원장 조회를 사용하며, `/orders/{OrderLedgerId}` 상세는 `주문조회ViewModel`과 `I주문원장Service`의 보호된 조회를 사용한다. 기본 조회는 `GET api/v1/community/order-ledgers/{id}`이며 역할별 조회를 선택하면 `views/orderer`로 이어진다. 로딩·조회 실패·다시 시도를 실제 조회 결과와 구별한다. r40 현재 업무 안내는 이 보호된 결과를 조합하고 음식·분산 전문 명령을 대신 실행하지 않는다.

검증할 때는 이 화면이 직접 메모리 데이터만 보는지, 위 API 응답을 받아 상태를 표시하는지, 실패했을 때 사용자가 다음 행동을 알 수 있는지 확인합니다.

## 보완 메모

### 주문 상세 책임 카드 r40 (2026-10-08)

- 주 사용자·대상: 인증된 주문자가 `/orders/{OrderLedgerId}`의 주문 한 건을 확인한다.
- 질문·결과: 지금 어느 단계이고 누구의 업무를 기다리며 어디에서 다음 행동을 확인하는가? 기존 전문 업무 화면으로 이동해 최신 상태를 확인한다.
- 기본 정보: 주문 제목·현재 상태·담당 역할·대기 이유·현재 업무로 이동·누락/권한/조회 오류.
- 보조 정보: 연결 원장 ID·템플릿·판본·조회 근거·수정시각은 상세에 둔다. 기본 화면에 구현 용어를 반복하지 않는다.
- 독립 업무: 음식 수령·취소/변경 협의·분산 주문 수령·정산/지급은 기존 전문 화면과 서버 명령이 소유한다. 주문 개요 자체가 상태를 확정하지 않는다.
- 선택·필수: 조건 변경은 해당 업무의 현재 판정에 따른다. 진행된 하위원장이나 필수 증빙을 단순 표시 설정으로 해제하지 않는다.
- 실패·복귀: 최초 로딩, 없는 주문, 권한 없음, 재조회 실패를 구분한다. 같은 주문을 재조회하고 전문 업무에서 내 주문으로 복귀한다. 비공개 원장의 상세·담당자·상태는 추정해 공개하지 않는다.
- 코드/API: `OrdererIndividualOrderLedgerDetail` → `주문조회ViewModel` → 기존 보호된 `api/v1/community/order-ledgers/{id}`(역할 선택 시 `views/orderer`). 실제 음식/분산 명령은 기존 API를 유지한다.
- 승인·검증: [r34 구현 범위](../../../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/order-ledger-role-refactor.implementation.r34.md). 현재 캡처는 과거 화면이며 r40 실제 렌더·소비 앱·단말 검증은 [변경 기록](../../../../Changes/2026-10-08-order-ledger-role-refactor-r40.md)에서 별도로 판정한다.
