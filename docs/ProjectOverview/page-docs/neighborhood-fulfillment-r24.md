# 생활 배송 수행 방식 선택·진행 확인 r24

2026-10-07. [승인한 구현 범위](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/fulfillment.implementation.r24.md)는 기존 생활 배송의 작성과 상세를 보완한다. 실제 외부 API 대신 기본 비활성화된 Simulation 공급자를 사용한다. 구현·시험·실제 렌더 상태는 [변경 기록](../../Changes/2026-10-07-neighborhood-fulfillment-r24.md)에서 구별한다.

| 책임 | 내용 |
| --- | --- |
| 주 사용자·페이지/소스 | 생활 배송 의뢰자. 기존 `/community/exchange/deliveries/new`, 배송 상세·목록 및 사유 지도 패널. 공통 `NeighborhoodDeliveryCreate`, `NeighborhoodDeliveryDetail`, `NeighborhoodDeliveryList`. |
| 대상·진입 문맥 | 우리 앱에서 접수하는 생활 물품 한 건. 기존 글·협업 연결과 지도 선택 문맥을 유지한다. |
| 한 문장 목적 | 이 물품의 수행 방식과 비용·시간을 비교해 선택하고 같은 의뢰의 진행을 확인한다. |
| 완료 결과·상태별 주 행동 | 작성에서는 견적 조회→후보 선택·정보 제공 동의→확정. 상세에서는 현재 상태 조회, 허용된 취소, 확인된 취소/실패 이후 새 견적 선택. 결과 불명확에서는 같은 실행 결과 확인만 안내한다. |
| 기본 정보 | 물품·장소·시간 조건, 후보의 총비용·완료 예정·견적 만료·이용 가능 여부, 모의 표시, 현재 선택·진행·다음 행동. |
| 보조 정보 | 상세 제한 사유·취소 안내·기존 자체 배차 방식·동의/직접 지급 안내. 모의 외부 수행에서는 자체 기사 현장 지급으로 안내하지 않는다. |
| 독립 업무·제외 정보 | 로그인·주소 작성은 기존 독립 흐름. 플랫폼 계약·키 설정·자동 위탁·실제 결제·Unity 표현은 이 페이지가 수행하지 않는다. |
| 진입·실패·복귀 | 기존 인증 경계. 견적 실패는 입력 보존 후 재조회, 확정 응답 유실은 동일 요청 재조회. 취소 결과 미확정이면 다른 수행을 접수하지 않는다. 지도/목록에서 같은 상세로 복귀한다. |
| 코드·API·DB | 공통 배송 Client/Authoring·Query ViewModel/Presentation → 기존 Community Controller → 배송 UseCase 및 공급자 coordinator → 견적·현재 선택·실행 기록. 상세·지도는 소유 의뢰에만 수행 snapshot을 포함한다. |
| 책임 판정·검증 | 기존 접수·진행 질문에 속하므로 별도 홈으로 분리하지 않는다. 320/390px에서 실제 공통 Razor 상태·선택·복구 확인, 서버 권위와 영속 중복 방지는 별도 시험한다. |

| 이전 표시 | 보완 표시 | 이유 |
| --- | --- | --- |
| 자체 배차 운임과 동의만 표시 | 기능 활성화 시 수행 후보 비교를 견적 다음에 배치 | 비용·시간 조건을 보고 사용자가 확정한다. |
| 외부 건도 내부 큐 대기로 해석 가능 | 공급자 수행 상태·모의·결과 확인을 기본 카드에 표시 | 자체 기사 수락이나 실제 지급으로 오해하지 않게 한다. |
| 취소 뒤 화면 재시도로 새 수행 가능 | 서버가 확인한 취소/실패 후 새 견적 선택 | 불명확한 접수·취소에서 중복 배송을 방지한다. |

비용 또는 완료 예정 시각 미확인은 `미정`으로 표시하고 확정하지 않는다. 확인된 0원은 유지한다. 공개 지도에 정확 배송 주소·담당자 연락처·외부 접수 payload를 추가하지 않는다.
