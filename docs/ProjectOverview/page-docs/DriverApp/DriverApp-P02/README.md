## 변경 전후 정보 배치

| 정보 또는 행동 | 사용자에게 필요한 이유 | 변경 후 위치 | 근거 |
| --- | --- | --- | --- |
| 홈·추천·운송·정산 | 자주 쓰는 네 업무의 직접 진입 | 기존 하단 네 메뉴 | 기존 `MainLayout` route와 활성 표시 보존 |
| drawer의 개별 업무 14링크 | 긴 반복 나열보다 지도와 보조 메뉴 진입이 필요 | native 지도·전체 메뉴·로그인 3진입 | 주요 업무는 하단, 보조 업무는 기존 `/driver/menu`에서 연결 |
| 4개 계정 카드와 기본 7개 NavMenu 링크 | 같은 경로를 한 번만 찾아 선택 | 목적별 행 목록 | 월 정산 카드/링크 중복 제거; 기존 경로는 하단 또는 허브에서 유지 |
| 사용자 숨김·미등록 route | 설정을 존중하고 새 항목을 누락하지 않음 | 보이는 항목만 표시, 미등록은 기타 | `VisibleItems`, `GetBlockingItem`, case-insensitive route 중복 제거 |

기본 메뉴는 **운행 준비·일정 2 / 문의·배달 3 / 기록·계좌 2 / 알림·설정 4 = 11행**이다. 기존 전체 메뉴의 11개 조작과 숫자는 같지만, 월 정산 중복을 없애고 하단의 주요 업무 3개를 반복하는 대신 drawer의 보조 업무 4개를 이 허브로 옮겼다. 사용자 숨김 설정에 따라 보이는 행 수는 줄어들 수 있으며, 새로 등록된 보이는 route는 기타 메뉴에 유지한다. drawer는 14링크와 지도 1조작에서 전체 메뉴·로그인·지도 3진입으로 줄였다.

## 왜 필요한가

기사가 자주 쓰는 네 업무 외의 준비·기록·계정 업무로 이동할 때 필요한 보조 메뉴를 목적별로 찾는다. 한 화면에서 업무 자체를 처리하지 않고 기존 독립 화면에 넘긴다.

## 사용자와 참여자

주 사용자: 기사 / 보조 참여자: 화주, 관리자, 창고 또는 현장 담당자

이 화면은 보조 또는 확장 업무 워크플로우 안에서 기사 앱 메뉴 책임을 갖습니다. 화면 하나가 너무 많은 결정을 떠안지 않도록, 이 문서에서는 이 화면의 주 책임과 다른 화면으로 넘겨야 할 책임을 구분해 관리합니다.

## 화면에서 다루는 일

- 주 책임: 기존 업무 화면의 목적별 진입.
- 확인과 조작: 보이는 메뉴를 선택한다. 이 화면에서 운송·정산 데이터를 입력하거나 저장하지 않는다.
- 화면 밖으로 넘길 일: 운행 시작, 문의, 음식 배달, 운행 예약, 기록 조회, 계좌와 알림 설정을 기존 route로 넘긴다.

## API 경로와 코드 연결

- 화면 소스: [DriverApp/Components/Pages/Driver/04_Settings/메뉴Page.razor](../../../../../DriverApp/Components/Pages/Driver/04_Settings/메뉴Page.razor)
- 클라이언트 서비스/계약: `NavMenu`는 기존 `DriverViewVisibilityService.VisibleItems`와 route 차단을 소비한다. 서비스의 기본 8항목과 사용자 숨김은 local이며 서버 API 조회가 아니다.

현재 문서와 소스에서 직접 연결된 `api/v1/...` 경로를 찾지 못했습니다. 이 화면은 정적 안내, 라우팅, 메뉴 진입, 오류 표시, 또는 다른 화면으로 넘기는 책임이 중심일 수 있습니다.

검증할 때는 이 화면이 직접 메모리 데이터만 보는지, 위 API 응답을 받아 상태를 표시하는지, 실패했을 때 사용자가 다음 행동을 알 수 있는지 확인합니다.
