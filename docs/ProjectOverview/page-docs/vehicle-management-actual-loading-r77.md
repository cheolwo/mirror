# 차량 관리 — 기사 실차 적재 확인 r77

## 페이지 책임

| 항목 | 기록 |
| --- | --- |
| 주 사용자·기존 경로 | 서버 관리자. `/drivers`에서 기사 한 명의 ‘실차 적재 확인’을 선택하고 기존 `/admin/freight-delivery/vehicles?driverId=...` 또는 `/vehicle-management?driverId=...`로 들어온다. 새 route나 역할은 만들지 않는다. |
| 한 문장 목적 | 기사 본인이 선택한 현재 실차에 대해 관리자가 실제 확인한 적재 한도·장비 근거·유효기간을 저장하고 서버 정본과 대조한다. |
| 대상과 완료 결과 | 기사 한 명의 현재 실차·차종과 그 실측 기록 판본이다. PUT 응답 뒤 GET 정본의 기사·판본·실차·내용이 일치할 때만 저장 확인을 표시한다. |
| 기본 정보 | 현재 선택 실차·차종, 미등록/이전 차량/철회/만료 상태, 현재 저장값, 작성할 근거·기간·치수/중량/부피/팔레트 및 장비 가능 여부. |
| 보조 정보 | 현재 저장 판본과 비공개 근거 참조. 원문 HTTP 예외·인증값은 표시하지 않는다. |
| 독립 업무 | 기사 본인의 차량 선택, 법정 운송 자격 검토, 차량군 추천 기준·요율 변경, 실제 장비·사진 수집, 배차 실행은 이 페이지가 소유하지 않는다. 기존 자격 검토 진입은 기사 목록에 별도로 유지한다. |
| 상태별 주 행동 | 미선택은 기사 목록으로 복귀, 조회 중은 대기, 조회 실패는 최신 기록 확인, 작성 중은 실측 기록 저장, 결과 미확인은 최신 기록 확인, 동시 변경 재조회 뒤에는 현재 저장값과 작성값 비교 후 명시적 재저장이다. |
| 코드·API·DB | `VehicleManagement` → `기사실차적재확인ViewModel` → `차량관리Service` → 기존 관리자 actual-loading GET/PUT → `기사실차적재제원UseCase` → 기사 실측 JSON/판본. 서버 관리자 권한·현재 실차 일치·판본 검증은 기존 서버 경계를 유지한다. |
| 책임 판정 | 현재 실차 한 대의 측정 기록 확인과 편집이 하나의 업무다. 운송 자격과 배차 승인으로 승격하지 않고 해당 전문 업무와 분리한다. |

## 입력과 복구

- 미등록 치수·중량·부피·팔레트와 장비 여부는 빈칸/미확인이다. 임의 적재량, 장비, 확인 시각이나 유효기간을 채우지 않는다. 팔레트 `0`, 장비 `false`, 미확인 `null`을 구분한다.
- 확인 시각·종료 시각은 한국 시각으로 입력하고 UTC로 전송한다. 유효 종료 시각을 자동 연장하지 않는다. 기존 만료·철회 기록도 현재 상태를 그대로 표시한다.
- 실차·차종은 서버가 반환한 본인 선택값으로 읽기 전용이다. 이전 응답에 현재 선택 정보가 없으면 과거 실측 기록으로 추정해 저장하지 않는다.
- 저장은 조회한 판본을 `ExpectedRevision`으로 보낸다. 충돌·응답 유실·저장 후 조회 실패 때 작성값을 유지하고 재저장을 막는다. PUT를 자동 재전송하지 않는다. 최신 기록을 조회한 다음 비교·재저장하거나, 같은 자료가 보관됐음을 확인한다.
- 재조회에서 기사 현재 차량이 바뀌면 이전 차량 작성값을 새 차량으로 복사하지 않는다. 계정 변경·권한 거부·페이지 해제 후 늦은 응답으로 다른 계정의 화면을 갱신하지 않는다.
- 냉장·냉동·리프트 가능은 기존 API 규칙대로 장비 근거 참조를 요구한다. 일부 실측 기록이 존재해도 미확인 한도나 법정 자격까지 확인된 것으로 표현하지 않는다.

## 검증 범위

집중 시험은 빈 입력, null/0/false 보존, CAS 충돌, 응답 유실, 저장 후 정본 조회 실패, 실차 변경, 구판 선택 정보 누락, 이전 판본/다른 기사 응답, 계정 변경·권한 거부와 실제 Razor 상태 표시를 다룬다. 작성 시점의 빌드·시험·브라우저 캡처 결과는 통합 변경 기록에서 별도로 기록한다. 합성 시험·로컬 화면은 실제 실차 측정, 운영 DB 반영, 자격 승인, APK·휴대폰 검증이나 실제 배차가 아니다.
