## 착수 기준과 실행 범위

- 기존 r2 소스18개와 검증 기록을 대조한 뒤 시작했다. 후보는 실제 시험/실행으로 확인하며 미검증 공백을 버그로 단정하지 않는다.
- 주문자는 실제 `OrdererApp` Android shell을 사용한다. 음식점·기사도 기존 APK를 재사용하고 필요하면 보완판을 빌드한다.
- 관리자 주문 추적의 실제 소비 호스트는 `SsalddelAdmin` 웹이다. `SsalddelAdminApp` 모바일에는 해당 페이지가 없으므로 새로 연결하지 않는다.
- 검증은 기존 Development+Simulation의 합성 계정/주문에 한정한다. 실제 영업·PG/은행·물리 단말·Unity 화면 증거로 승격하지 않는다.
- 임시 APK·캡처·제어 도구·원시 결과는 Git 제외 `artifacts/local/app-flow-stability-r1/`에 보관한다. 로그인 비밀번호·토큰·연락처를 문서나 도구 출력에 기록하지 않는다.

## 실제 실행 범위

주문자·음식점은 실제 Android BlazorWebView, 기사는 네이티브 Android 화면을 사용한다. 관리자 추적은 실제 `SsalddelAdmin` 웹 호스트의 layout/navigation에서 조회했다. 관리자 인증은 기존 DevelopmentBootstrap에 정상 합성 계정 로그인 결과를 적용했고, 관리자 로그인 입력 화면 조작 증거와 구별한다.

장애 중계는 loopback 서버 응답503/401을 제어해 주입한다. 실제 인터넷 단절·기기 시계에 의한 토큰 만료·물리 단말 검증으로 보고하지 않는다. 초기 중계의 청크 본문 전달 결함과 준비 화면 오류는 제품 결함 근거에서 제외하고 수정 후 다시 확인했다. 원본 요청 본문·비밀번호·토큰은 기록하지 않는다.

Observer는 Quartz를 제거하며 전용 작업자는 만료된 추천중 원장을 처리하지 않아 동일 주문 재추천을 확인할 수 없었다. 운영 만료 Job의 실행 증거는 아니다. 코드 근거는 [Observer 호스팅](../../../Ssalddel/Services/Development/FoodObserver/음식배달관찰검증Hosting.cs), [전용 배차 작업자](../../../Ssalddel/Services/Development/FoodObserver/음식배달관찰배차작업자.cs), [만료 정리 Job](../../../Ssalddel/Infrastructure/BackgroundJobs/DispatchQueue/추천만료정리Job.cs)다. 서버/작업자를 이번 범위에서 변경하지 않았다.

## 남은 검증과 다음 작업

- 지도 SDK ID가 없어 실제 타일은 미검증이다. 추정 경로·합성 거리와 실제 경로를 구분한다. 물리 단말·실제 인터넷 단절·실제 토큰 시간 만료·저장소 삭제 실패 장치 재현은 별도다.
- 늦은 응답/취소/로그아웃 대기 작업·수령 요청ID 재시도는 실제 코드 회귀시험으로 확인했으며 모든 화면 이동/장치 조합의 UI 재현을 완료한 것은 아니다. 기사의 내 정보는 같은 페이지 스크롤 섹션이므로 모니터 중지의 장치 증거로 사용하지 않는다.
- 추천0건 뒤 남는 파란 알림과 Simulation의 자동 배차 중지 안내는 후속 표시 점검으로 남겼다. 새 프린터·실결제·은행 지급·공개 출시·Unity·영상/MYBOX·commit/push는 수행하지 않았다.
- 다음 개발 우선순위는 기존 책임 점검에 따른 페이지 업무 분리, 지도 설정, 기존7실패 정리다. 실제 캡처는 [변경 기록](../../Changes/2026-10-03-app-flow-stability-r1.md)에 보존한다.
