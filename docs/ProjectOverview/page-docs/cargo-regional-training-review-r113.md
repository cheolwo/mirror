## 정보와 상태 처리

| 정보 또는 행동 | 사용자에게 필요한 이유 | 위치 |
| --- | --- | --- |
| 법정동·자료 분할·미검토 필터 | 어디의 어떤 사례를 검토하는지 유지 | 사례 목록 위 |
| 주문 조건과 후보 표 | 마감·적재·기존 약속을 지키는 후보인지 판단 | 선택 사례 기본 |
| 규칙/모델/사람의 결과 | 규칙을 모델의 정답이나 사람 승인으로 혼동하지 않기 | 선택 사례 기본 |
| 여러 허용 후보·배차 보류 | 동등한 대안을 한 명의 임의 정답으로 줄이지 않기 | 검토 입력 |
| 점수와 판본 해시 | 판단을 같은 입력으로 다시 확인 | 상세 접기 |
| 저장 실패와 최신 기록 재조회 | 입력을 잃거나 응답 유실 뒤 중복 저장하지 않기 | 검토 입력 바로 위 |

제외된 후보는 허용 결과로 선택할 수 없다. 승인·수정은 적격 후보 또는 배차 보류를 하나 이상 명시해야 한다. 미검토 상태는 저장을 뜻하지 않으며 사람 검토·학습 후보·실제 가중치 학습을 구분한다. 법정동은 집계 단위이고 상세 주소·고객 위치는 화면에 포함하지 않는다.

## r76 수행 계획 비교

같은 페이지에서 선택적인 수행 계획을 검토한다. 기존 28개 사례와 과거 검토는 보존하며, `--plan-review`로 준비한 새 판본은 미검토 조합 사례를 더한다. 계획 후보 하나는 **기사 한 명과 상하차 순서 전체**를 뜻한다. 여러 허용 계획을 선택하는 것은 대안을 인정하는 것이며 동시 배차가 아니다.

기본 정보는 가능·불가·정보 부족, 순서, 도착·작업·완료 시간과 구간 적재 요약이다. 상세에서 계획/입력 해시와 구간별 화물·중량·부피·팔레트를 확인한다. 합의 보수가 없으면 미확인으로 표시한다. 모델 원응답·응답 구조와 사실 검사·규칙 결과·코덱스 의견·사람 승인은 별개로 보존한다. 코드와 원응답은 상세로 접어 두고 검토에 필요한 실패 이유는 기본 표시한다.

새 사례는 명시한 가상 차량·화물·이동/작업시간으로 기존 일정 삽입기와 공통 구간 적재 검사를 실행한 로컬 자료다. 실제 서버의 현재 계획, 실차 확인이나 실도로 소요시간으로 표현하지 않는다. 확인된 가능 계획만 모델 입력과 허용 결과에 포함한다. 가능한 계획이 없으면 모델 실행을 하지 않고 보류 또는 정보 확인을 안내한다. 저장과 승인 내보내기는 같은 사례 입력·계획 묶음·정책·모델 실행 판본에 결속하며 실제 가중치 학습은 수행하지 않는다.
