## 검증 상태

구현 전 책임 정리이며 해당 범위의 소스/회귀 시험을 추가한다. 정본 저장과 상태 전이는 바꾸지 않는다. 빌드·시험 실행·실제 브라우저 렌더·APK 설치·기기에서의 정상 업무 흐름은 각각 별도의 증거로 기록한다. 현재 이 문서만으로 APK 설치나 정상 실운영 완료를 주장하지 않는다.

## 창고 홈 진입 책임

창고 관리자의 기존 `/warehouse`와 `/admin/order-warehouse` 진입은 현재 환경의 기능 상태와 기존 창고 업무 인증을 확인한 뒤 작업 창고·유형을 선택하는 한 가지 책임을 가진다. `WarehousePageAvailabilityService`의 서버 메타데이터와 `창고로그인ViewModel`의 창고관리자/서버관리자 접근 정책을 재사용한다. 창고 원장과 서버 권한 정책을 변경하지 않는다.

| 표시 상태 | 필요한 정보·주 행동 | 조회·실행 경계 |
| --- | --- | --- |
| 초기 확인 중 | 짧은 진행 안내 | 작업 창고·유형·업무 링크 숨김 |
| 기능 확인 실패 | 확인 실패와 명시적 다시 확인 | 재시도 전 보호된 창고 조회 없음 |
| 현재 환경에서 비활성 | 기능 안내와 상태 다시 확인 | 로그인·업무 선택·보호된 조회 실행 없음 |
| 익명 또는 접근 역할 없음 | 기존 창고 로그인/계정 안내 | 보호된 창고 조회 없음; 업무 카드와 인증 정보 분리 |
| 인증·기능 확인 완료 | 현재 창고·유형·작업 순서와 기존 업무 링크 | 기존 GET만 수행; 로그인 성공으로 업무 POST 자동 실행 없음 |
| 창고 조회 실패 | 조회 오류와 명시적 다시 확인 | 이전 데이터로 업무 진입하지 않음; 재시도는 기능·인증을 다시 확인 |

선택 창고와 작업 세션은 기존 세션 ViewModel 책임을 유지한다. 조회 성공 전 업무 링크를 열지 않는다. 회귀 시험은 익명·역할 불일치·기능 비활성의 보호 조회 0회와 실패 후 명시적 재시도를 확인한다. 앱 빌드·APK 설치·실제 창고 업무 완료는 부모 작업의 별도 실행 증거로 판단한다.

홈의 업무 표시에는 조회 세대와 인증 사용자 ID를 결속한다. 로그아웃 또는 사용자 변경 중 완료된 이전 GET은 다음 GET이나 업무 표시를 열지 않으며, 현재 계정은 명시적으로 다시 확인한다. 기존 공용 입출고 상태의 저장 구조와 서버 권한 검증은 유지한다. 홈의 표시 차단을 공용 상태 원장 전체의 계정 격리 검증으로 확대하지 않는다.
