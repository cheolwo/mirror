# Android 업무 상태 마감 r1

2026-10-04. 사용자는 기존 앱을 휴대폰에 설치했을 때 각 역할의 현재 업무 단계에 필요한 정보와 행동만 보이고, 상태 전환과 인증 복귀가 자연스럽게 이어지도록 요청했다. 새 업무 기능보다 기존 흐름의 오류와 모바일 복귀를 먼저 보완한다.

## 권위와 검토 기준

[업무 실행 책임 모델](../../Architecture/BusinessWorkflowResponsibilityModel.md)의 음식배달 OS·화물운송 OS는 서버 원장과 Policy·Process Manager·UseCase의 업무 생명주기다. Android 운영체제를 뜻하지 않는다. 화면은 서버 상태와 AvailableActions를 투영하고 사용자의 명시 행동을 요청한다. 로그인 성공·화면 복귀·백그라운드 조회가 업무 명령을 자동 실행하지 않는다.

[단일 책임 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)과 [역할 앱 시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 재사용한다. 공통 음식 규칙은 `Ssalddel.WorkflowRules/UnityPackage/Runtime/업무흐름규칙Catalog.cs`의 `food-delivery.v5`, 화물은 [화물운송 OS](../../Architecture/DomesticCargoTransportOS.md)와 현재 API의 상태·행동을 기준으로 한다. 오래된 설명의 조리 우선 순서를 앱의 실제 배차 선행 정책보다 우선하지 않는다.

## 역할별 현재 업무와 화면 책임

| 역할 | 현재 대상·단계 | 기본 정보와 주 행동 | 완료·실패·복귀 |
| --- | --- | --- | --- |
| 주문자 | 선택 음식점의 주문 작성 / 선택 주문 추적 | 메뉴·수량·확인 금액·수령 입력 / 현재 주문 진행과 허용된 수령 확인 | 가격 변경은 명시 확인, 취소·거절은 수령 대기 문구 제외. 선택 상세와 목록을 분리한 표시 모드로 복귀 |
| 음식점 | 선택 주문 인지·배차 대기·조리·픽업 준비 | 해당 주문·요청 사항·현재 배차·서버가 허용한 다음 행동 | 인증 만료 후 같은 계정의 원래 주문 상세 GET 복귀. 미확정 명령은 기존 ID/입력으로 조회 후 명시 재시도 |
| 음식 기사 | 인증 복원 / 제안 확인 / 현재 픽업·전달 | 복원 중 인증 안내만, 수락 후 픽업 정보, 픽업 후 전달지·요청 사항·주문 | 명령 뒤 오래된 조회는 폐기. 완료 뒤 다음 업무의 정본 상태와 카드로 갱신 |
| 운영자 | 주문·배차 예외 추적 | 선택 원장의 상태·차단 근거·권한 있는 조치 | 기사 없는 조리나 화면 자체 상태 확정 없이 기존 서버 정책 사용 |
| 화주 | 선택 운송의 등록·배차·운행 추적 | 해당 의뢰의 현재 상태·담당 인계·가능한 수정 | 기존 원값 보존·인증/조회 실패 복구 유지 |
| 화물 기사 | 현재 운송의 다음 상하차 작업 | 현재 운송·다음 지점·주소·허용 행동 | 화면 재진입 때 강제 정본 조회, 이탈·계정 변경 응답 폐기, 실패한 이전 카드 실행 차단 |
| 창고 | 선택 입고·피킹·포장·적재·출고 인계 | 작업 원장과 현재 단계의 입력·증빙·주 행동 | 기존 창고 API/권한·인계 조건 유지 |

모든 역할의 모든 화면을 새로 구현하거나 전수 검증 완료로 승격하지 않는다. 이번 구체 수정의 책임·경로는 [주문자·음식점](mobile-workflow-orderer-restaurant-r1.md), [두 기사 앱](mobile-workflow-drivers-r1.md), [Android 환경주소](mobile-workflow-environment-r1.md)가 소유한다.

## Android 검증 범위

SDK/에뮬레이터·기존 실행 도구를 확인하고 현재 소스의 개인 개발 APK를 생성한다. USB/에뮬레이터용 로컬 API와 휴대폰 단독 사용 가능한 HTTPS API를 구별한다. 실제 휴대폰에는 이번 요청만으로 자동 설치하지 않는다. 개발 서명 APK의 생성·서명·기동·화면 조작·서버/DB 업무 완료·물리 단말 검증은 각각 별도 증거로 기록한다.

검증 결과와 남은 제한은 [변경 기록](../../Changes/2026-10-04-mobile-workflow-readiness-r1.md)에 갱신한다. 지도 인증 설정과 Unity·영상 편집·외부 게시·커밋·푸시는 이번 작업에 포함하지 않는다.
