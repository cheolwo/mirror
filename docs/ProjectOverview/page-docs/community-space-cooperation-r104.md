# 공간 공동운영 제안과 회차

2026-10-24 승인 구현의 페이지 책임이다. 제품 행동·저장·기능 관문의 기준은 [공간 공동운영 순환 구현 r104](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/community-space-cooperation.implementation.r104.md)이며, 페이지 구성은 [전체 로드맵 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)을 따른다. 현재 소스 구현과 최종 시험·실앱·운영 증거는 구분한다.

## 페이지 책임 카드

### 통합 원장·시작 보류·정산 흐름 r119

2026-10-24 내부 정리 r120은 화면 템플릿과 동작 코드를 분리하고 표시 계산을 점검·단계·정산별로 나눈다. 페이지 책임·화면·문구·선택 유지·읽기 권한·서버 판정과 업무 명령은 r119를 유지한다. 새 매칭·현장 참여·정산 기능은 추가하지 않는다.

통합 원장 안에 선택한 회차와 개별 업무를 묶어 표시한다. 선택 회차·조건 판본·확인 시각이 일치하는 서버 점검만 시작 조건으로 읽고, 부족한 역할·동의·필수 약속은 회차 전체의 보류로, 단계가 명시된 원천 연결 부족은 해당 노드의 보완으로 표시한다. 역할 수락 부족을 실제 업무 담당 배정으로 추정하지 않는다. 진행·마친 회차를 시작 전 보류로 덮지 않으며 상세에서 같은 회차의 근거와 필요한 조치를 확인한다.

마지막에는 정산 원장의 연결·지급 준비를 보여 주고 실제 지급·수익/비용 근거가 없으면 미확인으로 남긴다. 결과에서 다음 회차 준비로 이어지는 점선은 검토 안내이며 같은 회차의 순환 완료·자동 시작·추가 이익을 뜻하지 않는다. 조회만으로 원장·예약·전문 명령·금액을 변경하지 않는다. [r119 구현 기준](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/workflow-readiness-and-settlement.implementation.r119.md)을 따른다.

### 휴대폰 업무 요약과 독립 상세 r117

2026-10-24 연결선 보완 r118: 모바일 요약 노드의 왼쪽 선으로 생산→입고→보관→출고와 주문→출고의 합류를 표시하고 출고→배송→정산을 잇는다. 보관과 주문 사이를 직렬로 잇지 않는다. 선은 기존 절차 안내 관계이며 완료·현재 수행·필수 실행 순서 표시가 아니다. 클릭·복귀·연락처 권한은 r117을 유지한다. 긴 문구로 노드 높이가 늘어도 연결선은 실제 카드 높이에 따라 이어진다.

휴대폰에서는 일곱 업무 노드를 한 열의 짧은 요약으로 읽고, 노드를 누르면 선택한 원장·회차·업무의 별도 상세 페이지로 이동한다. 상세에서 같은 회차의 요약으로 돌아오며, 기존 참여 약속 초안·미확정 요청·전문 수행 상태는 변경하지 않는다. 상세는 현재 계정과 서버의 읽기 전용 통합 조회에 근거하고 권한·회차·원천 판본이 바뀌면 이전 결과를 표시하거나 사용하지 않는다.

사용자 확인에 따라 연락처는 **기존 업무에 등록된 담당·현장 연락처만** 사용한다. 거점의 접근 가능한 등록 창고 연락처, 당사자 권한으로 조회되는 분산 주문의 현장 연락처, 출고 묶음에 이미 검증되어 연결된 같은 회차 주문의 현장 연락처가 첫 지원 범위다. 역할 안내·참여자 소개 동의로 개인 계정 번호를 조회하지 않으며 등록 정보나 권한이 없으면 그 상태를 보여 준다. 연락처는 명시적으로 요청했을 때 확인하고, 전화 앱을 열기 직전 다시 조회해 변경된 정보는 재확인을 요구한다.

`전화 앱에 번호 입력`은 지원되는 휴대폰 앱에서 번호 입력창만 연다. 실제 통화는 사용자가 전화 앱에서 선택한다. 웹의 미지원 상태, 조회 실패, 등록 없음, 권한 제한을 구분한다. 로드·로그인 복귀·노드 선택만으로 전화 앱이나 실제 통화를 실행하지 않는다. 구현·시험·실제 APK·전화 앱 화면·운영 권한 증거는 각각 기록한다.

### 생산·입고·출고 업무 연결도 r116

질문은 “생산부터 출고·배송까지 어떤 절차가 연결되고, 이번 회차에서 어떤 근거를 확인할 수 있는가?”다. 기존 공동운영 상세의 통합 조회를 소비하는 읽기 전용 표면으로 두며 원본 원장·전문 명령·개별 약속을 대체하지 않는다. 생산·공급, 입고·검수, 보관·재고, 주문, 피킹·출고, 배송·수령, 정산은 넓은 업무 영역 안내다. 노드·화살표는 실제 실행 순서·수행 가능·단계 완료를 확정하지 않는다. 기존 운영 체제·인계 카탈로그는 절차 안내로만 소비한다.

기본은 회차 선택과 절차 노드, 선택한 절차의 역할·입력/다음 전달 내용·현재 허용된 원천 자료다. 기존 통합 원장의 확인된 주문-원천 관계는 참고 자료 연결로 따로 표시한다. 동일 원장 ID·revision의 상세와 조회만 조합하고 불일치·실패·자료 없음은 구분한다. 생산이나 개별 피킹 완료 자료가 없으면 주변 업무로 메우지 않는다. 공간/보관 동의는 재고, 출고 묶음은 개별 피킹, 정산의 지급 준비는 입금으로 승격하지 않는다. 담당 역할 안내는 실제 배정이 아니다.

좁은 모바일에서는 줄바꿈 가능한 노드 선택 목록과 다음 절차 문구로 읽고 넓은 화면에서는 점선 연결도를 함께 표시한다. 실제 자료 상태는 문구로 나타내고 선택 색을 완료색으로 쓰지 않는다. 회차와 절차 선택은 로컬 보기만 변경하며 제출·저장·실제 인계는 하지 않는다. 실제 업무는 현재 권한으로 기존 안전한 원 업무 링크를 연다. 기존 계층·참여 약속·취소 영향은 보존한다.

### 통합 협업 원장·참여 약속 r115

주문 위의 상위 통합 원장은 기존 공동운영 원장을 재사용한다. 상세 사용자는 본인에게 허용된 주문과 검증된 하위/공유 업무 관계를 확인하고, 별도 참여 약속의 제안·수락·거절·취소 전 영향을 명시적으로 처리한다. 공개 모집/초대와 기존 전문 수행을 대체하지 않는다. 계층 조회와 개별 약속 변경은 컴포넌트·상태·미확정 요청을 분리하며, 개인 주문·보수·약속을 모임 참여자 모두에게 노출하지 않는다.

시간 약속은 같은 상위 원장의 전 회차 충돌을 검사하는 첫 범위이며 외부 일정·HR·실제 배차/근무 권한은 별도 확인한다. 전문 원천 미확인·모드/기능 관문·통신 실패는 실제 빈 목록이나 0원으로 바꾸지 않는다. 모바일에서는 짧은 계층과 내 약속을 기본으로 보여주고, 긴 조건/공유 관계·제안 작성·취소 영향은 해당 업무의 상세에서 확인한다. 실제 통합 앱 모바일 검증과 보조 브라우저 검증은 구분한다. 구현/검증의 현행 판본은 [r115](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/integrated-cooperation-ledger.implementation.r115.md)를 따른다.

## 홈과 참여 화면

### 회차 변화 조회 r112 — 구현 전 책임 보완

사용자가 r111 제안의 작업 진행을 요청해, 기존 당사자 상세 안에 `이번 회차에서 함께 만든 변화` 조회를 추가한다. 질문은 “이 공간에서 현재 누가 역할을 수락했고, 각 회차에 연결한 업무가 어디까지 확인되는가?”다. 공개 모집·초대 요약에는 표시하지 않는다. 기존 참여·조건·회차 명령과 전문 업무 이동을 그대로 유지하는 같은 목적의 조회 구성이다.

기본 정보는 기준시각·시험/현재 모드 구분, 현재 고유 관심/수락 인원, 필요한 역할과 조건 동의, 최신 회차의 연결 자료별 현재 확인 상태다. 지난 회차는 같은 조회 안의 보조 정보로 접으며 현재 참여자를 과거 회차의 실제 근무 인원으로 표시하지 않는다. 이전 완료 기록과 현재 전문 원천 재확인을 구분하고, 입고·주문·묶음·정산 참조를 물량이나 고유 배달 건수로 합산하지 않는다.

실수령액·이동/대기 시간·비용 절감은 정본이 연결되지 않은 상태로 표시한다. 자유 입력 비용 문구나 회차 시작/마감 간격을 확정 금액·근무시간으로 계산하지 않는다. 정산 원천의 완료는 `지급 준비 확인`이며 실입금 확인과 구분한다. 신규 급여·성과금·자동 불이익·공개 순위·고충 처리 명령은 이 조회에서 만들지 않는다. 상태 자료 누락은 0명/성공으로 바꾸지 않고 다시 불러오기 안내를 제공한다. 외부 효과 없는 당사자 조회로 검증하며 실제 운영·APK·입금·Figma 증거는 별도로 기록한다.

홈의 기존 `생산에 참여해 보세요.`와 역할 진입을 보존하고, `함께할 수 있는 사람과 공간` 요약에서 모집으로 들어간다. 소개에 동의한 사람 수는 복수 역할을 중복 합산하지 않는다. 공개 제안과 개인 소개는 별도 동의이며, 소개·참여 철회가 새 조회의 소개와 집계에 반영된다. 시험 모드는 실제 실적 숫자와 혼동하지 않도록 `시험 제안 · 실제 실적 집계 제외`로 표시한다.

관심 참여, 역할 수락, 공개 소개, 현재 조건 동의, 실제 업무 실행은 별개 행동이다. 역할 선택만으로 근무·계약·실물 공간 권한을 얻지 않는다. 초안과 원 요청은 같은 계정의 화면/로그인 왕복을 위해 보존하지만 영구 단말 저장이나 재시작 후 자동 실행으로 안내하지 않는다.

## 운영 담당과 회차

공간 제공자는 기본 운영 담당 후보이며 본인이 역할과 담당을 각각 수락한다. 인계 제안은 현재 담당자를 즉시 바꾸지 않고 상대가 명시적으로 수락한 뒤 바뀐다. 실제 전문 창고·배차 권한까지 인계한 것으로 표시하지 않는다. 다른 본인 역할 하나를 철회했을 때 운영 자격 역할이 남아 있으면 운영 담당을 함께 지우지 않는다.

조건이 바뀌면 과거 판본의 조건 동의·공개 소개·운영 담당 수락을 자동 승계하지 않는다. 회차 준비는 현재 역할·조건·전문 근거의 부족분을 보여 주며, 입고·주문·배송·수령은 전문 화면의 현재 상태를 따른다. 진행 중 참여 철회가 이미 예약된 재고나 이동 중 물품을 삭제하지 않는다.

주문 조건은 기존 본인의 비구속 상품 요청에서 가져와 주문자·판매자가 각각 확인한다. 판매자의 명시적 인계 후 기존 전문 주문으로 이어지고, 결제나 송금까지 완료됐다고 표시하지 않는다. 회차 완료 후 다음 회차는 빈 연결부터 준비하며, 남은 재고를 재사용해도 같은 주문·배송 실적을 중복 집계하지 않는다.
