# OS 생명주기 보완과 휴대폰 검증 준비 r24

사용자의 2026-10-06 보완 요청에 따라 r23 조사에서 확인한 결함을 먼저 고친다. 기존 업무·권한·결제 방식과 공개 계약을 보존한다.

1. 음식 배차 재시도 시 진행 상태를 보존하고 알 수 없는 원시 상태를 거절한다.
2. 거래 공개 동의를 인증된 응답자와 결속하고 응답·동의·알림을 함께 저장한다.
3. 창고 신·구 작업 경로의 상태/전체 수량 관문을 통일한다. 확정된 화물의 핵심 조건 변경을 차단한다.
4. 교육 제출은 읽은 원장 Revision으로 저장한다. 전송 완료와 원장 반영을 구별하여 재전송 없이 반영을 복구하고 학교 결정을 보존한다. 원장에 남은 제출 의도로 대기열 누락을 복구한다.
5. 선적 추적은 늦은 이벤트를 이력에 보존하면서 최신 단계와 완료 상태를 되돌리지 않는다.
6. 공통 OS/페이지 메타데이터 누락과 연결 후보를 재검토하고 실제 수정 범위와 남은 외부 검증을 기록한다.
7. 관련 실패·동시성·재요청 시험, Fast/Task 검사 및 Android 빌드를 실행한다. 설치용 APK와 서버 연결/역할별 휴대폰 검증 절차를 준비한다.

## 증거 범위

- r23 보고서는 당시 소스의 조사 기록으로 보존한다. r24 결과에는 문제별 수정/시험/미확인 항목을 구별한다.
- 로컬 시험·Android 빌드·APK 서명 확인은 실제 휴대폰 설치, GPS, Azure 연결, 은행 입금이나 외부 교육기관 수신 증거가 아니다.
- 개발 APK에 확인되지 않은 운영 서버·지도 키를 넣거나 결제 기능을 새로 활성화하지 않는다.
- 시작 시 dirty 파일 1,001개와 HEAD를 `artifacts/local/os-lifecycle-hardening-r24/baseline.json`에 기록했다. 관련 없는 변경과 stage는 보존한다.
