# 기사 현재 업무 모아보기 r1

2026-10-23 사용자 구현 요청. 같은 플랫폼의 전문 업무는 유지하고 현재 할 일의 조회·진입 경험을 공통으로 보완했다. 기준은 [페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md)과 [기사 참여 r71](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/driver-participation.implementation.r71.md)이다. [실제 검증과 제한](../../Changes/2026-10-23-integrated-driver-work-r1.md)을 별도로 기록한다.

## 페이지 책임

| 항목 | 기록 |
| --- | --- |
| 주 사용자·페이지/소스 | 현재 수행 중인 기사. 공통 Ui.Common 컴포넌트와 통합 Web/Android 호스트의 `/driver/current-work` 진입 |
| 대상·진입 문맥 | 기존 기사 로그인 세션과 본인에게 귀속된 음식·화물·직접 피킹 순회. 계정이 다른 역할의 업무를 합치지 않음 |
| 한 문장 목적 | 기사가 본인의 현재 할 일을 구분해서 보고 기존 전문 수행 화면으로 이동한다 |
| 완료 결과·상태별 주 행동 | 조회 성공은 수행 완료가 아님. 해당 현재 업무의 `이어서 하기`가 주 행동이며 수락/완료 명령은 전문 화면이 소유 |
| 기본 정보 | 업무 종류·짧은 상태·다음 행동·현재 업무 제목. 유형은 글자와 아이콘·기존 색으로 구분 |
| 보조 정보 | 수행 범위 및 전문 화면으로 연결하는 안내. 고객 상세 주소·연락처·원본 증빙·지도 경로는 복제하지 않음 |
| 독립 업무·제외 정보 | 추천 수락·운행 시작·위치 갱신·설정 저장·보수 약정·실제 지급·혼합 적재 허가는 별도 기존 업무로 인계 |
| 진입·실패·복귀 | 로딩/익명/권한 부족/기능 준비/조회 실패/성공 빈 목록을 구분. 한 영역 실패는 다른 영역 성공을 숨기지 않음. 계정 변경·로그아웃·늦은 응답에 과거 개인 업무를 남기지 않음 |
| 코드·API·DB | 기존 `IRoleWorkspaceAccess`로 계정 일치를 확인하고 `IRoleWorkspaceApi.GetAsync`로 전문 현재 업무만 읽는다. adapter의 운행/위치 부수효과는 호출하지 않음. 새 원장·수락 정책·상태 전이 없음 |
| 책임 판정·검증 | 같은 목적의 읽기 전용 구성. 동일/상이 계정·영역별 오류·빈/활성 업무·늦은 응답·재시도·GET 전용·전문 링크·만료 시 반납 책임과 허용 행동을 시험하고 실제 공통 컴포넌트 렌더를 확인했다. APK 설치/실기기/실운영은 별도 |

## 직접 피킹 수락 전 요약의 책임

기존 순회 화면에서 같은 순회의 방문 순서·시간창·서버 제안 운임과 실제 표시 가능한 작업 범위를 수락 전에 모아 보여준다. 현재 응답에 없는 피킹 추가 보수·배송비 포함 여부·무료 약정을 추정하지 않는다. 직접 피킹 선택을 포장 동의로 바꾸지 않고 보수/범위 미확정은 확인 필요로 유지한다. 기존 약정 확인 화면으로 인계하며 수락 권한·추가 확인·미확정 요청 복구·실제 지급 규칙은 변경하지 않는다.
