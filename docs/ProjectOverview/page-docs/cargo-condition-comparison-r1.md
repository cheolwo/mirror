## 표시 기준

### 2026-10-24 후속 · 현재 제안 한 건에 집중

사용자는 추천을 목록 탐색보다 한 건씩 판단하는 방식으로 정정했다. 전문 Native 화면은 이전/다음 화살표·목록 번호·가로 넘김을 제거하고 서버의 현재 제안 한 건만 지도/카드에 표시한다. 새 정본에도 같은 ID·차수가 있으면 검토 중인 대상을 유지하며, 종료가 확인된 뒤 다음 서버 제안을 받는다. 기존 조건·상세·수락/거절과 권한은 유지한다. 이 결정이 아래의 상단 이전/다음/스와이프 조립 설명보다 우선하며, 이전228 기록은 이력으로 보존한다. [단건 표시·서버 기본 정책·운영 한계](../../Changes/2026-10-24-cargo-single-recommendation.md)를 함께 따른다.

### 2026-10-24 전문 기사 추천 카드 간략 배치

같은 추천 한 건의 운송 참여를 판단하는 목적과 기존 route를 유지한다. 기본 카드에서는 총중량을 왼쪽 위, 수량을 오른쪽 위에 배치하고 상차 주소·시간을 왼쪽, 하차 주소·시간을 오른쪽에서 비교한다. 시간은 한국 시각의 월일·시분으로 줄이며 펼친 상세에는 연도와 한국 시각, 운송 방식·요청 차량 등 전체 조건을 남긴다. 누락·역전 시간 안내는 요약에서도 숨기지 않는다.

거절은 왼쪽, 수락은 오른쪽이다. 확인된 제안 방식에 따라 오른쪽 이름만 `독차` 또는 `혼적`으로 쓰며 나머지는 `수락`이다. 이는 같은 추천의 기존 수락 절차로 들어가는 버튼으로, 운송 방식을 고르거나 상차를 완료하는 명령이 아니다. 거절 진입은 사유 입력만 펼치며 이동·로그인 성공으로 업무를 자동 실행하지 않는다. Native의 기존 상세·차수·기한·경고·조건 재조회와 미확정 보호는 유지한다. 전문 Razor의 기존 배차처리 경로는 같은 서비스의 권한·예상 차수 검증을 유지하며, Native와 동일한 사전 조건 재조회가 있는 것은 아니다.

Native 추천은 한 시점의 현재 카드와 선택 키를 같은 전환 경로로 갱신한다. 이전/다음 및 스와이프는 선택만 바꾸며 확정 명령을 보내지 않는다. 조건이 갱신되거나 표시한 카드와 실제 선택이 다르면 수락을 중단한다. 실제 APK 확인 결과는 별도 [간략 카드 기록](../../Changes/2026-10-24-cargo-compact-recommendation-cards.md)에 남긴다.

기준 값은 `운송방식`, `차량종류`, `화물중량Kg`, `화물수량`과 상차·하차 시간창의 시작/종료 4개다. `Ssalddel.Contracts.Common.Transport.화물운송조건표시`를 공통으로 사용한다.

- `단독`은 표시만 `독차`로 정규화한다. 실제 원장·요청·응답의 운송 방식 원문을 표시 명칭으로 덮지 않는다.
- 누락된 조건은 `미확인`으로 남긴다. 차량 적합 여부를 요청 차량으로 대신하거나 없는 운송 방식을 혼적으로 기본 설정하지 않는다. 원문에 없는 `협의`를 생성하지 않는다.
- 기존 UTC 시간 계약을 한국 시각으로 한 번 변환한다. 날짜와 시간을 함께 쓰며 같은 날의 종료 날짜만 줄일 수 있다. 자정·연도 경계는 양쪽 날짜를 유지한다.
- 시간창 한쪽만 있으면 확인된 시각을 보존하고 누락된 끝을 명시한다. 역전된 범위는 확인이 필요함을 표시한다. 표시만으로 잘못된 일정을 보정하지 않는다.
- 전문 기사 카드의 간단·표준·자세히 모드에서도 이 조건은 기본 노출한다. Native는 긴 조건을 줄바꿈하고 본문을 측정하며, 가용 화면을 넘으면 기존 본문 스크롤을 사용한다.

## 페이지 → 코드 → 원장

공통 `RoleMapWorkspace`의 목록과 선택 영역은 각 adapter의 `ComparisonFields`를 `화물운송조건Panel`로 표시한다. 화주·기사·관리자 adapter가 원장 응답의 같은 8개 필드를 연결한다. 기사 수락 화면은 `CargoOfferActionViewModel`과 `CargoOfferActionScreen`이 소유한다. 전문 앱은 `ServerBackedDriverSampleDataService` → `DriverRequestItem` → `DriverCargoConditions` 및 `NativeDriverRecommendationPage`를 따른다. 설정 예시는 같은 표시 컴포넌트를 쓰고 실제 의뢰·주소를 참조하지 않는다.

서버 조회는 기존 `api/v1/shipper/requests`, `api/v1/driver/public-dispatches`, `api/v1/driver/recommendations`, `api/v1/driver/requests/{requestId}`, `api/v1/driver/transports`와 `api/v1/admin/transports?business=freight-delivery`의 권한을 유지한다. 인증된 공개 배차 콜과 익명 `api/v1/shipper/requests/public` 요약을 구별하며, 이번에 익명 계약이나 상세 공개 범위를 넓히지 않는다.

## 확인의 수명과 한계

공통 수락은 추천·의뢰 상세의 조건이 일치해야 한다. 확인 뒤 새 조회에서 조건이 바뀌거나 두 응답이 다르면 확인을 해제하고 POST 전에 멈춘다. 두 응답 모두 누락한 값은 미확인으로 일치할 수 있지만, 한쪽의 누락을 다른 쪽 값으로 채워 일치시키지 않는다. Native는 실제 표시한 카드의 조건 사본과 현재 선택·최신 조회를 대조한다.

이 보호는 기존 화면·계정·대상·차수·미확정 요청 guard에 더해진 클라이언트 재확인이다. 새 서버 조건 판본 토큰이나 원자적인 수락 검증을 추가한 것은 아니다. 표시된 일정·조건이 있어도 화물 현장 확인·업무 수락·상하차 완료·실제 지급을 자동 수행하지 않는다.

## 사용자에게 보여주는 검토 자료

사용자 요청에 따라 화물 UI 보완은 가능한 경우 실제 휴대폰에 설치한 APK 화면을 대표 검토 자료로 제공한다. APK 패키징·서명/내장 소스 확인, 데이터 보존 설치와 설치본 SHA 대조, 실제 역할 화면 캡처를 각각 기록한다. 로컬 브라우저나 빌드 성공만으로 휴대폰 확인을 대신했다고 표시하지 않는다. 합성 HTTP 자료를 사용했으면 그 범위와 실제 제품 DB·업무 검증의 차이를 밝히며, 보인 결함도 정상 화면과 함께 보존한다. 초기226 및228의 기록은 보존하며 최신229의 한 건 표시·조회 순서 변경 시 유지·현재 건 종료 뒤 전환·빈 화면 확인과 남은 서버 한계는 [단건 추천 기록](../../Changes/2026-10-24-cargo-single-recommendation.md)을 따른다.
