# 모바일 기사 업무 상태 보완 r1

2026-10-04. 기존 음식·화물 기사 앱의 인증 복원, 현재 수행 정보, 화면 복귀를 서버 원장 상태에 맞춘다. 새 업무·지도 인증·결제·Unity·운영 배차 규칙은 추가하지 않는다.

인증은 인증 상태와 저장소만, 수행 VM은 서버 정본의 표시 순서만, 화물 화면 상태 객체는 조회·계정·화면 수명만 소유한다. 사진·증빙·요금·완료 명령은 기존 서비스 책임을 유지한다. 긴 정산 이력과 설정은 기존 별도 진입을 유지한다.

## 변경 근거와 검증 경계

- 음식 기사 초기 저장소 복원과 새 로그인이 서로 덮어쓸 수 있는 경계를 정리한다.
- 10초 백그라운드 조회의 이전 응답이 더 최근 픽업·전달 후 조회를 덮지 않게 한다.
- 화물 운행 화면 복귀의 `force=false` 캐시 재사용과 실패 뒤 오래된 카드 재표시를 정리한다.

## 반영 범위

수신 ON은 실제 배차 가능을 뜻하지 않는다. 서버 `PausedByServer`·`ConnectionUnavailable`·기록된 `Ineligible`은 대기 카드에서도 제한 안내를 보존한다. 서버 초기 `NoEffectiveEligibilityRecorded`와 판정 기록 없는 초기 `Ineligible`은 배차 가능 여부 확인 중으로 구별한다. 기사의 수신 의사·서버 실효 상태·운행·현재 위치를 서로 덮어쓰지 않고, 기존 업무 권한을 이 표시에서 새로 만들지 않는다.

실제 Android 검증의 `fdriver-ready.png`·`fdriver-ready.xml`에서 인증 완료·운행 전·현재 배달 및 추천 없음 상태에 운행 시작 버튼이 없음을 확인했다. 기존 버튼은 기본으로 접힌 `IsWorkControlsExpanded` 안에 있고 대기 상태의 고정 하단은 숨겨져 있었다. 위치 조건이 운행 시작 명령을 잠그는 문제는 아니었다. r2는 이 대기 표시·기존 명령 접근만 보완하며 지도 인증·운영 배차 규칙·배달료·서버 행동 권한은 그대로 둔다.

- `FDriverAuthSession`은 초기 저장소 조회 전의 세대와 로그인·로그아웃 세대를 대조한다. 저장소 읽기는 새 로그인을 막지 않고, 저장·삭제는 직렬화한다. 복원 중에는 별도 대기 안내를 표시하고 로그인 입력 화면을 숨긴다.
- `MainPageModel`은 업무 명령 시작과 정본 조회 시작마다 조회 세대를 갱신한다. 오래된 업무·배차 의사 응답과 오류는 현재 카드·행동·동기화 안내를 바꾸지 않는다. 다음 업무 선택과 서버 `AvailableActions` 기준은 유지한다.
- `DriverNativeHomeWorkspaceState`는 화물 운행 화면 복귀마다 기존 서버 adapter를 `force: true`로 호출한다. 실패·이탈·계정 변경이면 현재 운송 표시를 해제한다. 화면은 조회 대기 또는 재시도 안내와 정상 업무 정보를 분리한다. 이번 작업이 상시 지도 갱신이나 새로운 수행 명령을 추가한 것은 아니다.

구현과 첫 보완 14개·대기 r2 21개 회귀 사례 작성은 완료했고 통합 시험·APK는 별도로 검증한다. 좁은 변경 경로와 구현 전후 SHA-256은 `artifacts/local/mobile-workflow-readiness-r1/drivers/`에 남겼고 대기 수정은 `waiting-r2/`에 별도 판본으로 보존했다. 담당 범위에서는 빌드·시험 실행·기기 설치·단말 UI·운영 HTTP/DB·지도 표현을 수행하지 않았다. 실제 APK 화면은 root가 수집한 자료만 대조했다. 기존 단일 책임·시각 기준은 [전체 페이지 원칙](../../Architecture/WholeRoadmapPagePrinciple.md), [역할 앱 시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 따른다.
