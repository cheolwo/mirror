# 배차 설명·의견 화면 책임 r24

[구현 범위](../../AI/Planning/공통/PLAN-OPERATIONS-DISPATCH-CORE/cargo-dispatch-explanation-feedback.r24.md)의 사용자 질문은 ‘그때 어떤 정보로 이 배차를 추천했으며, 설명에 의견을 남겼는가’다. 원 배차·운임·완료 상태를 수정하는 화면과 분리한다.

## 진입과 사용자 결과

화주/주문자는 기존 진행 알림의 `/shipper/request/{RequestId}`에서 `배차 설명·의견`을 연다. 통합 Web과 연결된 역할 Web, SsalddelApp의 기존 요약 화면을 함께 연결한다. 전문 기사는 native 추천 상세의 같은 이름 버튼으로 `/driver/dispatch/{RequestId}/explanation`을 연다. 두 역할은 같은 공통 패널과 실제 인증 API를 사용하며 서버가 현재 사용자 관계를 다시 확인한다. 통합 앱과 전문 기사 앱의 기존 수락/거절·다른 상세 정보는 보존한다.

기본은 당시 기록 구분·판단 시각·확인된 조건과 근거 한계다. 과거 미기록은 미기록으로 표시하며 현재 조건을 재계산하거나 sample 자료로 채우지 않는다. 다른 기사 후보·점수·귀가 기준점·GPS·고객 상세주소·연락처는 공통 DTO/화면에 추가하지 않는다.

## 행동과 예외

사용자는 기록을 고르고 의견 종류5개 중 하나와 선택적500자 의견을 제출한다. 선택 항목은 도움됨·정보 다름·시간/경로·설명 부족·기타이며 `received`는 의견 접수만 의미한다. 운영자 검토·답변 완료나 자동 학습 반영을 약속하지 않는다.

의견 POST 전에 기존 보호 복구 저장소에 계정·서버·의뢰·설명ID·요청GUID와 입력을 보존한다. 전송 응답이 미확정이면 입력을 잠그고 먼저 같은 요청의 GET 접수 조회를 한다. 미접수 확인 후에만 사용자의 명시적 다시 보내기로 같은 번호/입력을 전송한다. 계정·세션·서버·의뢰 ABA 전환은 늦은 응답을 버리고 이전 계정의 입력을 새 계정에 보여주지 않는다. 입력 보관기간이 지났으면 원문을 복원하지 않고 남은 설명ID/요청번호로 조회하며 새 작성 전에도 다시 조회한다.

준비·조회 중·기록 없음·조회 실패·제출 중·미확정·미접수·접수됨·로그인 변경을 나눈다. 단말의 보호 저장 실패는 POST를 시작하지 않는다. 채널 전달/실제 배차·수락·금융은 이 패널의 완료 상태가 아니다.

## 모바일 검증

360/390px의 좁은 폭에서 단일 열, 줄바꿈,44px 이상 입력/버튼, 폼 잠금과 전체 이동 없이 표시되는 오류를 확인한다. 공통 패널은 HtmlRenderer 회귀로 기록 없음/실패/복구/접수 표시를 검증하며 실제 Web/MAUI·Android 렌더 및 실제 서버 왕복 여부는 실행한 근거로 별도 기록한다. 이 문서/컴파일만으로 실제 휴대폰 검증 완료를 표시하지 않는다.
