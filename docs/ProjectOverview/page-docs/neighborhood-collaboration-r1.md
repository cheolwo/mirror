# 생활 협업과 보관공간 페이지 책임 r1

[페이지 기준](../../Architecture/WholeRoadmapPagePrinciple.md)과 [시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 따른다. 한 계정이 요청·제공·배송·보관의 당사자가 될 수 있지만, 전문 기사 명령이나 공개 댓글을 업무 합의로 승격하지 않는다.

## 페이지 책임

### 생활 교류 약속과 선택 배송 보완 r23

2026-10-07 사용자 승인 계획의 구현 전 책임 카드다. 기존 조건·권한·원장·보호 안내를 유지하며 새 결제·입금 확인 상태를 만들지 않는다.

| 화면 | 한 가지 질문과 결과 | 기본 표시와 다음 행동 | 보조 정보와 독립 업무 |
| --- | --- | --- | --- |
| 협업 신청·조건 수정 | 무엇을 언제 어떤 방법으로 주고받기로 제안할까? | 물품·수량·기간·전달 방법·선택 금액, 명시 신청. 빈 금액은 미정, 입력한 0은 0원이다. | 조건 변경 후 재동의 안내. 실제 기사 견적·배송 접수는 별도 작성 화면이다. |
| 협업 진행 | 이 약속에서 지금 내가 할 일은 무엇일까? | 현재 상태·허용된 주 행동 → 약속 내용 → 전달 방법 → 금액과 지급 안내 순서다. 직접 수령·직접 전달에는 기사 비용 안내를 붙이지 않는다. | 취소·동의 철회·반환 연결·문제 접수는 접근 가능하게 유지한다. 이력과 모든 관련자 동의에 따른 공개 선택은 보조 정보다. |
| 기사 배송 작성·진행 | 배송 조건을 확인하고 접수하거나 현재 배송을 어떻게 이어갈까? | 견적과 명시 동의, 자동 추천·공개 콜·병행 선택, 현재 상태와 필요한 다음 행동이다. 추천과 기사 수락은 구분한다. | 상세 주소는 권한 있는 당사자에게만 표시한다. 완료와 수금 기록을 분리하고 입금을 확인하지 않은 상태는 플랫폼 입금 미확인으로 설명한다. |

새 공개 API·DB 테이블·정산 자동화는 추가하지 않는다. 실패·중복 요청의 결과 조회와 안전한 지도 복귀는 기존 VM이 소유한다. 실제 공통 UI의 320/390px 렌더와 Fast/Task를 확인하고, 휴대폰·Azure·실제 운행·입금 증거는 별도로 남긴다.

| 페이지 | 주 사용자와 한 가지 목적 | 기본 정보와 상태별 주 행동 | 분리한 업무·실패·복귀 |
| --- | --- | --- | --- |

## 연결과 검증 경계

공통 컴포넌트 → 페이지 ViewModel → 보호 전송 Client → 생활 협업/보관공간 API → 기존 서버 권한과 원장 순서로 연결한다. 서버 DTO와 상태 전이 계약은 각각 `생활협업Dtos.cs`, `생활보관공간Dtos.cs`가 소유한다. 화면은 허용된 행동만 표시하며 서버의 소유권·기능 게이트를 대신하지 않는다.

협업 목록의 `requested` 범위는 **내가 신청한 일**, `undertaken` 범위는 **받은 요청·맡은 일**이다. 필요해요 글에서는 실질적으로 부탁하는 사람이 글 작성자일 수 있으므로 신청자를 제공자로 단정하지 않는다. 작성 페이지는 `?spaceId=`로 공간에 직접 신청하고 `?workId=`로 현재 협업 조건을 수정할 수 있다.

원글 아래 별도 공개 요약은 참여 가능한 협업과 공개에 동의한 완료 이력을 조회한다. 참여 신청은 공개 판본으로 명시 제출하고, 사적 상세를 먼저 열지 않는다. 기록 공개는 완료 확인과 다른 선택이며 양측과 수락한 참여자가 모두 동의해야 종류·공식 동네명·날짜만 나타난다.

보관 조건 동의에는 상세 인계 주소·연락처·인계 방법의 상대방 제공 안내와 문안 판본을 별도로 결속한다. 배송 기사 제공이나 공개 기록 동의로 대체하지 않는다. 제공 조건의 `OfferRevision`과 예약·인계의 공간 CAS 판본을 구분한다. 앱 재시작 후 서버가 반환한 본인의 미확정 예약 번호는 결과 조회에만 사용하며 새 예약을 자동 생성하지 않는다. 예약 결과가 `aborted`이면 성공으로 안내하지 않는다.

지도 보관 레이어는 공식 동네 목록의 대표 좌표만 재사용한다. 같은 동네의 공개 글 핀과 공간 수를 합쳐 핀 겹침을 줄이고 선택 카드에서 공간 목록으로 연결한다. 공간의 실제 위치나 비공개 입력을 지도에 전달하지 않는다.

검증은 ViewModel의 계정 전환·늦은 응답·불명확한 쓰기·상태별 주 행동, Web/MAUI 소비 컴파일, 실제 화면 확인을 구별한다. 신규 `NeighborhoodCollaborationWorkflowViewModelTests` 23개를 포함한 집중 308개와 전수 7,256개 시험이 통과했다. 같은 공유 UI의 실제 화면과 Android 내장 APK 준비는 [변경 기록](../../Changes/2026-10-05-neighborhood-collaboration-r1.md)에 연결한다. 구현 파일은 `artifacts/local/neighborhood-collaboration-r1/ui-paths.json`에 기록한다. 이 문서 자체를 실제 화면·기기 설치·배포 증거로 취급하지 않는다.
