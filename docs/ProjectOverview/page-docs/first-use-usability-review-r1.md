2026-10-16. 기존 화면을 교육 없이 이해할 수 있게 다듬는 사용자 요청에 따른 검토·최소 보완이다. 기준은 [역할 앱 시각 디자인 기준 r8](../../Architecture/RoleAppVisualDesignStandard.md#첫-이용에서-막히지-않는지-확인하는-기준-r8)이며 별도 색·크기·권한 규칙을 만들지 않는다.

## 발견과 적용 결과

공식 기준을 체크리스트로 적용했다. 사용자 시험을 거친 사용성 인증이나 모든 화면의 부적합 판정은 아니다. 우선순위는 사용자가 잘못된 완료를 믿는 경우, 진행이 막히는 경우, 입력을 반복해야 하는 경우, 내부 용어를 해석해야 하는 경우 순으로 정했다.

| 역할·화면 | 사용자가 느낄 불편과 변경 전 근거 | 적용한 보완 | 보존한 책임 |
| --- | --- | --- | --- |
| 화물 기사·계좌 | 고정된 예시 이름·계좌와 클릭만으로 완료되는 패널이 본인 계좌 확인처럼 보임 | 미확인 상태를 명시하고 실제 운송대금/메뉴로 복귀; 미연결 확인·변경 버튼 제거 | 계좌 조회/검증 기능을 새로 구현하거나 실제 지급 준비로 승격하지 않음 |
| 판매자·주문 목록 | 30초마다 컴포넌트를 재생성해 검색어·필터·페이지가 초기화됨 | 같은 목록에서 현재 조건을 유지하며 접근과 데이터를 재확인; 겹친 조회·화면 종료 보호 | 권한 재확인, 조회 전용 갱신, 서버 상태 소유 |
| 판매자·상품/판매 등록 | 재고 미선택 직접 진입의 빈 본문, 준비물 없음과 조회 실패의 혼동 | 첫 진입 안내·기존 재고/상품/채널 화면 링크, 조회 실패의 명시적 재확인 | 새 상품/채널을 자동 생성하거나 실패 시 저장 반복하지 않음 |
| 판매자·접근 불가 | 공통 화면의 화주/커뮤니티 복귀 주소가 판매자 앱에 존재하지 않음 | 기존 공통 기본값은 유지하고 판매자 소비자가 유효한 홈 목적지를 전달 | 각 역할 앱의 route 소유와 기존 권한 |
| 주문자·음식 주문 | 필수/선택과 제출 불가 이유가 버튼 근처에 보이지 않음 | 입력 라벨에 필수/선택 표시, 기존 제출 조건에서 읽은 안내를 버튼과 연결 | 최신 가격 재확인·동의·미확정 접수·서버 제출 관문 |
| 생활·마트 상품 | 기능 OFF/오류에서 돌아갈 행동 부족, 원장·투영 등 내부 용어 노출 | 이용 가능/불가를 명시하고 안전한 복귀와 재시도, 상품/주문 설명을 일상 용어로 정리 | 샘플/실제 구분, 주문 요청이 확정이 아님, 기능/권한 보호 |
| 기사·로그인/알림 | 작동하지 않는 소셜 로그인과 FCM·서버 포트 등 개발 설명 | 미연결 로그인 버튼을 숨기고 연결 재시도/알림함/휴대폰 설정 안내 제공 | 실제 기기 알림 허용·청취를 화면 조회 건수로 인증하지 않음 |

| 창고·업무 시작/보드 | 고정 샘플 작업자 값과 내부 식별자 설명이 업무 안내와 경쟁 | 샘플 값 제거, 현재 작업 중심 용어 | 입고·출고·사진·정산 상태를 합치지 않음 |
| 인력 관리자 | 기능 키·ReadOnly 같은 구현 용어를 이해해야 함 | 이용 가능 범위와 조회 전용 상태를 사용자 언어로 안내 | 기존 권한·기능 OFF와 실제 상태 유지 |
| 운영자·로그인/복구 | 예상 밖 예외 원문, 인증이 필요한 곳에 로그인 행동 없음 | 이해 가능한 재시도 안내와 원래 복구 화면으로 돌아오는 로그인 링크 | 관리자 권한·후속 재예약·미확정 결과 보호 |

제품 파일 위치와 책임 카드는 기존 앱별 상세 README에 연결했다. 조사 원문과 미수정 후보는 Git 제외 `artifacts/local/usability-review-20261016/{driver-admin,shipper-warehouse-hr,orderer-restaurant-seller}.json`에 보존한다. 각 담당의 `실행 검증 대기`는 조사 시점 상태이며 최종 통합 결과는 [변경·검증 기록](../../Changes/2026-10-16-first-use-usability-r1.md)이 소유한다.

| 4 | 복귀 권역 이름이 placeholder에만 있고 반경 실패 원인이 합쳐짐 | 영구 라벨과 단위/범위 안내, 기존 저장 조건을 읽은 필드별 설명 |
| 5 | 인력 필터 최소 폭, 긴 주소, 키보드·뒤로가기·30초 갱신 중 입력 | 좁은 폭의 실제 역할 화면과 기기에서 포커스·가림·초안 보존 검증. 검색값은 보존하지만 접근 재확인의 임시 로더가 입력 DOM을 교체할 가능성은 별도 재현 필요 |

첫 이용자가 실제 과제를 수행하는 관찰 시험도 필요하다. “가입/로그인 → 요청 작성 → 현재 상태 확인 → 오류에서 복귀 → 완료 내역 찾기”에서 설명 요청·되돌아감·오선택을 기록하면 교육 없이 쓸 수 있는지 판단할 수 있다. 정적 체크와 자동 시험만으로 그 목표를 달성했다고 결론내리지 않는다.

## 유지하는 경계

- 음식·화물·창고의 업무·완료·수령·금융 원장은 분리한다. 화면 개선으로 서버 Guard, 권한·기능 플래그, 사진 필수 조건, 운영 worker나 지급을 바꾸지 않는다.
- 사용자 승인된 지도/카드 비율·좌우 넘김·주황 픽업/파랑 전달·회색 비선택·파랑 거절/주황 수락·기사 글자 크기는 유지한다.
- 모의 자료가 실제 계좌·실제 고객·실제 지급 확인으로 보이지 않게 하되 실제 실패·미확정·샘플 상태 안내는 숨기지 않는다.
- 구조적으로 큰 과제는 다음 순서와 근거를 남긴다. 화면마다 필요한 기능을 줄이거나 역할을 삭제하는 전면 재설계를 이번 결과로 자동 승인하지 않는다.
