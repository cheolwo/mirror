# 기사 앱 업무 영역 분리 r1

2026-10-03. 사용자가 다음 우선순위 1번을 승인했다. [페이지 책임 기준](../../Architecture/WholeRoadmapPagePrinciple.md)과 [시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 적용한다. 이번 범위는 기존 네이티브 기사 앱의 배달·정산·내 정보 진입과 복귀다.

## 구현 전 책임 카드

| 항목 | 배달 | 정산 | 내 정보 |
| --- | --- | --- | --- |
| 사용자·대상 | 로그인한 기사·현재 추천/배달 | 같은 기사·완료 주문 정산 | 같은 기사·본인 계정/월 이용료 |
| 질문·결과 | 어떤 배달을 수행하고 다음에 무엇을 하는가 | 완료 주문의 배달료·공제·수령 상태는 무엇인가 | 어떤 계정으로 접속했고 월 이용료 상태는 무엇인가 |
| 기본 정보·행동 | 기존 지도·추천·현재 선택·지급액·픽업/전달 행동 | 기존 Gross/Deduction/Net/Progress/Notice·빈 상태 | 기존 계정·월 이용료·로그아웃 |

| 실패·인증 | 기존 서버 행동 가드·재조회·GPS/배차 안내 | 업무 조회 오류/미확정 유지, 인증 종료 시 비공개 상태 제거 | 조회 오류 유지, 인증 종료 시 비공개 상태 제거 |

현재 실제 root는 `App.CreateWindow`의 기존 MainPage이고 AppShell이 아니다. Shell 전체 전환이나 새 route를 먼저 만들지 않고 같은 페이지의 명시적 표시 모드와 독립 스크롤 상태 소유자를 사용한다. 단순 탭 가림·섹션 스크롤을 업무 상태 격리로 보고하지 않는다. 표시 상태와 서버 업무 상태를 분리하며, 모드 변경은 배차/운행/금액/선택 배달을 변경하거나 API를 호출하지 않는다.

기존 `focus` 키와 dispatch/bundle/delivery/settlement/profile/workspace/restaurant/customer/route 값은 유지한다. 실제 페이지 진입/이탈에서만 기존 인증·위치·10초 자동 갱신 수명 경계를 적용하고 모드 변경은 모니터를 재생성하지 않는다. 로그아웃/인증 종료 시 모드와 개인 스크롤 문맥을 초기화한다.

## 코드·API·DB 연결

기존 `MainPage.xaml` → `MainPageModel` → `IFoodDeliveryDriverApiService` → 음식배달 업무 API/원장 및 완료 정산 조회를 재사용한다. 표시 모드의 순수 상태는 `FDriverWorkspaceNavigationState`가 소유하고 실제 View 측정·스크롤·Android 뒤로 처리는 MainPage가 조립한다. API·DB·요율·서버 상태·App root·DI 등록은 변경하지 않는다.

## 수락 기준과 검증

세 영역은 별도 표시·스크롤 문맥을 갖고 현재 영역이 명확해야 한다. 정산/내 정보에는 지도와 배달 수행 버튼을 반복하지 않는다. 배달로 돌아왔을 때 선택·경로·수행 상태와 스크롤을 유지한다. 새 추천과 현재 행동을 막는 경고는 놓치지 않게 유지한다. 기존 entryfocus와 배달 복귀, 인증 종료, API 무호출을 시험하고 320 DIP·큰 글씨 및 최종 APK의 실제 진입/복귀를 확인한다.
