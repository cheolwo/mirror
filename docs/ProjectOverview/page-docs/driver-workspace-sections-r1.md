# 기사 앱 업무 영역 분리 r1

통합앱 퀵/화물기사의 운행·신규 수신 시작과 픽업/전달 준비 안내는 [r110 책임 카드](quick-driver-usability-r110.md)를 따른다. 아래 전문 기사 앱의 기존 수행·내역 책임과 추천 디자인은 유지한다.

현행 앱 루트는 Shell이며 완료 목록·상세는 독립 route다. 내역 조회 중에는 앱이 활성인 동안 수행 갱신·위치·추천 수신을 유지한다. [완료 내역 책임 카드 r3](driver-completed-delivery-detail-r1.md#수행과-내역의-수명-분리-r3--현행-책임-카드)와 [현재 실행·지도 SDK 확인](../../Changes/2026-10-04-driver-history-lifetime-map-r1.md)을 우선한다. 아래 같은 MainPage의 표시 모드와 페이지 이탈 수명 설명은 r1 구현 이력이다.

2026-10-03. 사용자가 다음 우선순위 1번을 승인했다. [페이지 책임 기준](../../Architecture/WholeRoadmapPagePrinciple.md)과 [시각 기준](../../Architecture/RoleAppVisualDesignStandard.md)을 적용한다. 이번 범위는 기존 네이티브 기사 앱의 배달·정산·내 정보 진입과 복귀다.

## 구현 전 책임 카드

### 기사 로그인·계좌·알림 안내의 실행 범위 정리 r24

2026-10-16 사용성 검토 후 승인된 보완. 기사 로그인은 현재 가능한 아이디/비밀번호 인증과 원래 업무 복귀만 안내한다. 미구현 소셜 인증 버튼을 기본 노출하지 않고 연결 실패에는 사용자가 할 수 있는 재시도를 설명한다. 계좌 정보는 본인 계좌 조회 연결이 없음을 표시하며, 예시 계좌·임의 본인 확인·변경 접수 성공을 표시하지 않는다. 정산·계좌 저장이나 새 은행 API는 추가하지 않고 기존 운송대금 목록과 전체 메뉴로 돌아간다.

알림 설정과 기존 푸시 설정 route는 알림함 확인과 휴대폰 알림 안내로 이어진다. 기기 권한·소리·실제 수신 여부를 이 화면에서 확인한 것으로 표현하지 않고 휴대폰 설정에서 확인할 항목을 안내한다. 토큰·구현 예정 설명과 실제 동작하지 않는 설정 버튼은 기본 화면에 두지 않는다. 승인된 추천 카드의 좌우 넘김·파랑 거절/주황 수락·고정 지도·글자 크기, 서버 배차와 원장·금융 상태는 변경하지 않는다.

### 추천 카드 공백과 응답 색 정리 r23 — r73

2026-10-16 최신 사용자 요청. 같은 추천 한 건을 판단하는 책임과 배달료·픽업지·전달지, 좌측 거절·우측 수락을 유지하면서 흰 공백을 줄인다. 기본 정보는 좌측 금액과 우측 두 주소로 나란히 배치하고 카드 높이는 128 DIP에서 116 DIP로 줄인다. 버튼의 터치 높이 48 DIP는 유지하며 거절은 파란색, 수락은 주황색으로 명시한다. 주소 글자 크기와 긴 주소를 확인하는 세로 스크롤은 유지한다.

지도는 전체 영역을 유지하고 좌우 카드 넘김·핀 강조·추천별 ID/차수·경고 확인·취소·만료·응답 불명확 보호를 변경하지 않는다. 옅은 중립 표면과 경계를 사용하고 기본 카드에 상세 정보나 새 버튼을 추가하지 않는다. 검증은 색 대비·주소 잘림/스크롤·2장/3장 넘김·현재 카드 응답·복귀를 구분하며 실제 APK 확인 전에는 기기 완료로 표시하지 않는다.

최종 APK190에서 합성 추천의 금액·두 주소가 잘림 없이 보이고, 파랑 거절/주황 수락·48 DIP 버튼과 두/세 카드의 양방향 넘김·핀 강조·카메라 유지·확인 창 취소·수신 OFF 복원을 확인했다. 긴 실제 주소의 스크롤은 소스를 유지한 범위이며 실기기 확인으로 확대하지 않는다. [r73 변경 기록](../../Changes/2026-10-16-compact-recommendation-card-design-r73.md)이 판본별 증거와 남은 범위를 소유한다.

### 추천 카드에서 바로 응답 r22 — r72

2026-10-16 최신 사용자 정정. 기본 카드에는 배달료·픽업지 주소·전달지 주소와 하단 왼쪽 거절·오른쪽 수락만 둔다. 상세 진입·보류 버튼과 별도 상세 화면은 제거한다. r71의 96 DIP 카드보다 조금 키우되 지도 중심의 작은 독립 카드·좌우 넘김을 유지한다. 화면 비율은 약 5:1을 목표로 실제 휴대폰에서 확인한다.

| 영역 | 표시·행동 | 보존 |
| --- | --- | --- |
| 기본 추천 카드 | 배달료·픽업지·전달지, 하단 좌측 거절/우측 수락 | 추천별 독립 카드·선택한 한 건 응답·좌우 넘김. 일반 상세 화면과 상시 조건 나열 없음 |
| 추천 지도 | 모든 유효 추천의 핀, 선택 픽업 주황·전달 파랑, 나머지 회색 | 카드 넘김에 따른 색 강조·카메라 위치 유지·만료 핀 제거·조회 실패 후 복구 |
| 응답·확인 필요 | 카드에서 바로 응답하며 필수 주의사항이 있으면 수락 시 해당 건의 확인 안내 | ID·차수·최신 원장 재조회·만료·경고 fingerprint·응답 유실 보호. 카드 전환/취소/새 경고를 이전 동의로 처리하지 않음 |

아래 r21의 상세 overlay와 작은 카드의 상세 버튼은 이전 판본 이력이다. 오류·현재 상태 재조회·운행 지도 복귀는 유지하며 서버 정책·원장·음식 기사 앱·현재 수행 업무를 변경하지 않는다.

r72의 최종 APK189에서 카드 높이 128 DIP, 양쪽 응답 버튼 48 DIP로 확인했다. 합성 추천 2장·3장의 실제 휴대폰 넘김, 세 정보 줄의 잘림 해소, 선택 주황/파랑·나머지 회색 핀과 같은 좌표 집합의 카메라 유지, 확인 창 취소와 수신 OFF 복원을 검증했다. 지도와 카드의 비율은 고정 수치로 인증하지 않는다. 상세 증거와 시험 범위는 [r72 변경 기록](../../Changes/2026-10-16-direct-recommendation-card-actions-r72.md)에 둔다.

### 지도 우선 추천 비교 r21 — r71

2026-10-16 사용자 후속 정정. 별도 추천 지도에서 지도와 기본 카드의 보이는 높이 비율은 약 6~7:1을 목표로 한다. 지도 SDK는 전체 화면에 고정하고, 추천별 작은 독립 카드를 하단에 겹쳐 놓는다. 모든 유효 추천의 픽업·전달 핀은 남기고 현재 카드의 핀만 주황·파랑으로 강조한다. 다른 추천은 회색으로 구분한다.

| 영역 | 기본 표시·행동 | 보조 상세·보존 |
| --- | --- | --- |
| 추천 지도 | 모든 유효 추천의 핀을 함께 표시. 현재 카드의 픽업 주황·전달 파랑, 나머지 회색 | 카드 이동으로 지도 크기·여백을 바꾸지 않음. 현재 수행 지도와 별개이며 실제 경로/예상 연결 구분 유지 |
| 작은 독립 카드 | 추천 순번·배달료·픽업지·전달지, 좌우 넘김·상세 진입 | 긴 주소와 조건·주의사항·수락/보류/거절은 같은 추천의 상세에서 확인. 기본 카드에 맞추어 필수 경고나 수락 보호를 제거하지 않음 |
| 상세·실패·복귀 | 선택한 한 건의 전체 정보와 기존 응답·경고 확인, 작은 카드로 복귀 | ID·라운드·만료·응답 불명확 재조회 보호 유지. 상세를 연 것만으로 수락하거나 현재 업무를 교체하지 않음 |

추천 카드 선택은 지도 강조와 검토 대상만 바꾸며 배차 명령이 아니다. 기본 화면의 핀 비교와 상세 응답은 같은 페이지 책임 아래 분리한다. 아래 r20의 큰 카드 높이와 선택한 추천만 표시하는 이전 기준은 이번 정정으로 대체하고 이력은 보존한다.

### 화물 추천별 독립 카드 r20 — r70

2026-10-16 사용자 정정. 큰 카드 하나의 내용이 바뀌는 표현 대신 추천 한 건마다 독립된 카드를 둔다. 추천 2건은 카드 2장, 3건은 카드 3장으로 구성하며 오른쪽·왼쪽 이웃 카드의 일부가 보여 별도 카드임을 알아볼 수 있게 한다. 기존 별도 추천 지도와 페이지 키 `driver-recommendation-map`은 유지한다.

| 영역 | 책임과 기본 표시 | 보존할 경계 |
| --- | --- | --- |
| 운행 지도 | 추천 도착은 배너로 알림 | 추천 핀을 수행 지도에 미리 표시하지 않음 |
| 독립 추천 카드 목록 | 투명한 하단 영역에 건별 흰 배경·둥근 테두리·간격·순번을 가진 카드 배치. 좌우 스와이프로 옆 카드로 이동 | 큰 공통 흰 카드를 씌워 내용만 교체하는 표현을 사용하지 않음. 옆 카드 탭·별도 선택 버튼 없음. 수직 접기/펼치기 없음 |
| 각 추천 카드 | 해당 건의 픽업지·도착지·배달료·조건·주의 확인과 한 건 응답 | 지도와 명령은 선택한 `(의뢰Id, 추천라운드)`에만 연결. 옆 카드가 보여도 여러 건을 동시에 수락하지 않음 |
| 실패·복귀 | 오류 안내·현재 상태 재조회·운행 지도 복귀 | 기존 만료·현재 업무 보존·응답 불명확 보호·경고 확인·전체 지도 크기 유지 |

정상 상태의 반복적인 긴 설명은 줄이고 오류와 확인이 필요한 안내는 유지한다. 서버 배차·원장·요금·수행 상태·음식 기사 앱은 변경하지 않는다. 아래 r19의 한 큰 하단 영역 표현은 구현 이력이며, 시각적 카드 구분은 이번 r20을 우선한다.

### 화물 기사 추천 지도와 좌우 카드 r19 — r69

2026-10-16 사용자 요청. 화물 기사는 운행 지도에서 새 추천의 도착을 배너로 알아차린다. 배너를 누르면 별도 추천 지도에서 한 건의 픽업지·도착지·금액을 확인하고, 하단 카드를 좌우로 넘겨 다음 추천을 비교한다. 추천 두 건은 카드 두 장이며 선택과 수락은 별개다.

| 화면 | 한 가지 질문·기본 행동 | 지도·정보·복귀 |
| --- | --- | --- |
| 화물 기사 수행 지도 | 맡은 업무를 진행하면서 새 추천이 왔는지 확인 | 추천 핀/경로를 미리 섞지 않고 배너를 표시. 맡은 업무의 핀·경로와 신규 수신 토글 유지 |
| 화물 기사 추천 지도 (`driver-recommendation-map`) | 선택한 추천을 맡을지 판단 | 별도 전체 지도 위 고정 하단 영역에서 건별 픽업지·도착지·배달료·기존 조건 카드를 좌우 스와이프. 선택한 카드만 주황 픽업/파랑 도착 핀 표시. 수직 접기/펼치기 없음 |
| 추천 응답·실패 | 선택한 한 건의 수락·기존 보류/거절을 처리 | 만료·추천 라운드·최신 상태·경고 확인·응답 유실 보호 유지. 실패는 명시 안내·재조회, 0건은 빈 상태. 수락 또는 뒤로가기 시 기존 수행 지도 정본 재조회 |

카드 목록 갱신은 `(의뢰Id, 추천라운드)`로 선택을 보존한다. 카드 선택만으로 배차를 확정하거나 현재 수행 A를 추천 B로 바꾸지 않는다. 현재 지도·하단 카드의 크기와 센서 옵션, 신규 수신 OFF, 서버/정산/음식 기사 앱 경계를 유지한다. 구현·시험·APK·실제 단말은 [r69 변경 기록](../../Changes/2026-10-16-recommendation-map-carousel-r69.md)에 각각 기록한다.

### 화물 기사 현재 위치 방향 옵션 r18 — r68

2026-10-16 사용자 요청. 화물 기사는 기존 화면 설정에서 현재 위치 점과 SDK 기본 방향 화살표 중 표시 방식을 선택한다. 설정의 결과는 이 기기에 저장하는 지도 표현 선택이며 운행·위치 전송·배차 명령과 분리한다.

| 화면 | 기본 정보·행동 | 실패·복귀와 보존 |
| --- | --- | --- |
| 화물 기사 화면 설정 | 현재 위치 표시 방식 선택, 휴대폰이 향한 방향임을 짧게 설명 | 기존 설정 route·다른 표시 설정 보존. 지도 복귀 시 선택 적용 |
| 화물 기사 수행 지도 | SDK 기본 현재 위치와 선택한 방향 화살표 | 지도 전경에서만 방향 센서 사용. 방향 미확인·만료는 점으로, 위치 미확인은 기존 위치 보호 기준 적용 |

지도 크기·카메라 이동/회전·접힌 카드·추천/운송 상태는 유지한다. 방향 값은 GPS 이동 경로나 실제 주행 검증이 아니며 서버로 새로 저장/전송하지 않는다. 이번 대상은 현재 확인 중인 화물 기사 앱이고 음식 기사 앱은 변경하지 않는다. 구현·시험·APK 설치·실제 방향 표시 확인을 구분해 [r68 검증 기록](../../Changes/2026-10-16-current-location-arrow-r68.md)에 남긴다.

### 운행 시작과 자동 갱신 r13 — 사용자 후속 기준

2026-10-09 사용자 정정. 기사는 운행 시작을 한 번 누르고 지도와 현재 업무를 확인한다. 음식 기사 앱의 운행 시작 행동은 기존 운행 시작과 신규 배차 수신 ON을 연결하며 별도의 시작 확인창이나 수신 토글 조작을 요구하지 않는다. 종료의 기존 확인 절차는 유지한다. 지도 왼쪽 위 토글은 이후 신규 제안을 잠시 끄고 켜는 선택으로 유지한다. 운행 상태와 수신 상태의 서버 권위는 합치지 않는다.

이번 범위에서는 카드 크기 기반 SDK 여백·자동 줌/팬, 경로 대기 중 추가 핀 화면 맞춤을 구현하지 않는다. 아래 r2~r6의 지도/카드 높이 분할과 지도 공간 예약 설명은 이 최신 기준으로 대체한다. 기존 목적지/단계 전환 시 최초 경로 맞춤, 사용자의 지도 탐색·현위치 버튼은 보존한다. API·DB·GPS 취득·경로 공급자·업무 상태/명령·금액·개인정보·r33 행동 아이콘을 변경하지 않는다. 소스/시험·APK 준비와 실제 휴대폰 화면·터치/카메라 검증은 구분하며, 기기 시험은 다음 USB 연결 때 진행한다. [이번 변경·검증 기록](../../Changes/2026-10-08-driver-fullscreen-independent-card-r34.md)을 따른다.

### 상태 카드의 행동 아이콘 r9 — 사용자 후속 기준

2026-10-08 사용자는 에뮬레이터 검증을 중지하고 다음 휴대폰 USB 연결 때 APK 검증·설치를 진행하도록 요청했다. 기존 OS 생명주기·절차·상태별 카드 안의 버튼에는 의미를 보조하는 아이콘과 기존 문구를 함께 표시한다. 공통 역할 카드에서는 안정적인 행동 키를 사용하고, 네이티브 기사에서는 기존 상태별 주 버튼과 실제 접기/펼치기 상태에 연결한다. 새로운 업무·버튼이나 다음 상태를 생성하지 않는다.

### 내 정보 안의 배달 내역 r8 — 사용자 후속 기준

### 네이버 지도 경로 화면 맞춤 r4 — 구현 전 책임 카드

2026-10-04 사용자의 최신 선택은 네이버 지도다. 기존 Mobile Dynamic Map SDK를 유지하며 수행 화면의 질문은 “현재 위치와 이번 배달의 픽업·전달 위치, 이동 경로를 지도에서 확인한다”다. 첫 유효 경로와 현재 건·픽업/전달 단계 전환 때 현재 경로와 해당 건의 핀을 실제 지도 영역 안에 한 번 맞춘다. 다른 활성 건은 회색 핀·참고선으로 유지하며 먼 다른 건 때문에 현재 경로를 과도하게 축소하지 않는다.

이후 GPS 갱신은 화면 전체 맞춤을 반복하지 않는다. 사용자가 이동·확대한 중심과 줌을 지도 View 수명에 보관하여 handler 재생성 시 복원한다. 현위치 버튼은 기존 줌을 유지하며 따라가기를 재개한다. 앱 위치 서비스·서버 경로/업무·요금·DB는 기존 책임을 유지한다. 지도 SDK가 자체 위치 추적이나 경로 조회를 추가하지 않는다. SDK 인증·타일 로딩 성공은 핀·실선과 별도로 확인하며 실패를 가짜 배경 지도나 준비 완료로 바꾸지 않는다. 영상용 Static Maps와 앱의 이동 가능한 SDK 지도를 구별한다.

[코드·시험·최종 Android 확인](../../Changes/2026-10-04-driver-navermap-viewport-r1.md)에 연결한다. SDK401의 콘솔 확인은 남아 있으며 실제 타일 완료로 보고하지 않는다.

| 항목 | 배달 | 정산 | 내 정보 |

| 사용자·대상 | 로그인한 기사·현재 추천/배달 | 같은 기사·완료 주문 정산 | 같은 기사·본인 계정/월 이용료 |

현재 실제 root는 `App.CreateWindow`의 기존 MainPage이고 AppShell이 아니다. Shell 전체 전환이나 새 route를 먼저 만들지 않고 같은 페이지의 명시적 표시 모드와 독립 스크롤 상태 소유자를 사용한다. 단순 탭 가림·섹션 스크롤을 업무 상태 격리로 보고하지 않는다. 표시 상태와 서버 업무 상태를 분리하며, 모드 변경은 배차/운행/금액/선택 배달을 변경하거나 API를 호출하지 않는다.

기존 `focus` 키와 dispatch/bundle/delivery/settlement/profile/workspace/restaurant/customer/route 값은 유지한다. 실제 페이지 진입/이탈에서만 기존 인증·위치·10초 자동 갱신 수명 경계를 적용하고 모드 변경은 모니터를 재생성하지 않는다. 로그아웃/인증 종료 시 모드와 개인 스크롤 문맥을 초기화한다.

## 지도 중심 수행 화면 보완 r2 — 구현 전 책임 카드

2026-10-04 사용자 승인. 기존 배달·정산·내 정보 분리를 유지하면서 배달 영역의 질문을 “현재 선택한 한 건의 다음 목적지와 이동 경로를 확인하고 허용된 다음 행동을 수행한다”로 좁힌다.

| 항목 | 현재 한 건의 지도·수행 |
| --- | --- |
| 기본 정보 | 자기 위치, 현재 건의 픽업·전달 핀, 다음 목적지 전체 주소, 현재 건 배달료·단계·허용된 주 행동 |
| 보조 정보 | 다른 활성 건의 회색 핀·픽업→전달 참고 경로, 명시적 배달 선택, 펼친 수령 정보·전달 요청·진행 배달 합계, 운행·신규 수신 조작 |
| 상태 소유 | 서버가 업무/금액/가능 행동을 소유한다. 앱의 지도 표현 상태가 선택 ID·따라가기·경로 조회/캐시를 소유하고 단일 위치 서비스가 포그라운드 GPS 수명을 소유한다 |
| 진입·복귀 | 기존 focus·새 추천 확인·배달 복귀를 보존한다. 회색 핀/목록 선택은 현재 건을 명시적으로 변경하고, 완료 후에는 기존 남은 서버 목록 순서를 따른다 |
| 실패·복구 | GPS 미확인과 도로 경로 실패·추정 응답은 즉시 안내한다. 오래된 응답/계정/선택은 버리고 위치 실패를 지도 중심 좌표의 가짜 현위치로 바꾸지 않는다 |
| 구분 | 현재 픽업 경로는 주황 실선, 현재 전달 경로는 파랑 실선, 다른 건의 참고 도로 경로는 회색. 배달 순서 최적화·음성 안내·화면이 꺼진 상태의 추적은 이번 범위 밖이다 |

기존 경로 API의 현재 위치와 목적지 한 개 요청을 재사용한다. 외부 DTO·DB·요금·배차·서버 행동 조건은 바꾸지 않는다. 위치 표시 변경 이벤트와 서버 위치 전송10초를 분리하며, 현재 건의 이동 재탐색은 최소30초·100m 이동 또는 실제 도로선50m 이탈을 서로 다른 유효 GPS 두 개로 확인한다. 실패/추정 응답은60초 후 복구를 재시도한다. 실제 지도 SDK 설정·타일·도로 응답과 소스/시험/APK 증거는 따로 확인하고 구현 뒤 아래와 연결되는 변경 기록에 결과를 남긴다.

지도 r2는 [변경·검증 기록](../../Changes/2026-10-04-driver-map-first-r2.md)에 연결한다. 기존 API·DB·배달료·가능 행동을 재사용하며 앱 Window 이탈/재개에 위치 수명만 연결한다. 최초/명시적 권한 요청과 자동 GPS 복구를 구별한다.

## 코드·API·DB 연결 — 영역 분리 r1

### 고정 글자 크기 r7 — 사용자 후속 기준

2026-10-04 사용자는 정해진 크기로 기사 화면을 표시하고 별도 확대 구성을 하지 않도록 요청했다. FDriverApp의 Driver 제목/본문/버튼/입력 기반 스타일에서 자동 글자 확대를 끄고 이를 상속하는 섹션·상태·금액·주소·보조 버튼에 적용한다. 중단 사유/메모는 본문16으로, 앱의 Android 지도 안내는 DIP14로 맞춘다. DIP는 화면 밀도에 따라 물리 픽셀로 환산되며 모든 휴대폰에 같은 픽셀 수를 강제한다는 뜻은 아니다.

r6의 자동 글자 확대 유지 기준만 대체한다. 카드 표면/정렬·전체 주소 줄바꿈·필요한 본문 스크롤·업무 상태/행동/접기·지도 준비 안내는 유지한다. Google 지도는 [별도 조사](../../ProjectOverview/driver-google-maps-review-r1.md)의 후보이며 이 글자 수정으로 지도 공급자나 경로/요금 엔진을 변경하지 않는다. [변경 기록](../../Changes/2026-10-04-driver-fixed-font-r1.md)에 소스·빌드·화면 검증 범위를 구분한다.

### 카드 정렬 보완 r6 — 구현 전 책임 카드

2026-10-04 후속 요청은 기존 수행 정보를 카드 안에서 일관되게 읽는 것이다. r5의 단계·주 행동·접기 복귀·본문 스크롤은 유지한다. 접힌 요약도 흰 표면/테두리의 카드로 묶고, 수행 상태 제목은 접힌 요약 또는 펼친 픽업/전달 카드 안으로 이동한다. 카드 내부 여백/왼쪽 축을 통일하며 긴 주소는 일반 굵기로 줄바꿈하고 글자 확대를 제한하거나 주소를 자르지 않는다.

큰 글자에서 지도 상태 안내를 가리는 범례·현위치는 기존 네이티브 타일 준비 상태가 `Ready`일 때만 표시한다. 미설정·로딩·오프라인·인증/타임아웃 안내와 본문 GPS 복구·경로 안내는 유지한다. View의 표시 상태와 예약 높이만 연결하며 서버/API·경로·카메라·배차·금액은 변경하지 않는다. 실제 지도 준비/실패 전환과 설치본 확인은 [정렬 변경 기록](../../Changes/2026-10-04-driver-card-alignment-r1.md)에 구분해 남긴다.

### 수행 단계별 하단 카드 r5 — 구현 전 책임 카드

2026-10-04 후속 요청은 “현재 수행 단계에서 필요한 목적지·주문을 읽고 다음 행동을 완료한다”다. 아래 r4의 항상 전달지 우선 구성을 수락 후 픽업 정보, 픽업 후 전달지 → 고객 요청 사항 → 주문 정보로 세분화한다. 수락 전에는 수행 카드를 숨기고 기존 추천 확인·수락과 운행/수신 설정은 유지한다.

| 서버 재조회 상태 | 기본 정보 | 주 행동 |
| --- | --- | --- |
| 현재 수락 건 없음 | 수행 카드 없음, 추천은 수락 전 영역 | 기존 추천 수락 |
| 픽업 이동·도착 기록 없음 | 음식점·전체 픽업 주소·주문·확인된 준비 예정 시각 | 허용된 가게 도착 |
| 도착 기록 확인 | 픽업 정보·주문·확인된 준비 예정 시각 | 픽업 완료, 권한 없으면 비활성 |
| 픽업 후 전달 단계 | 전달지·고객 요청/수령인·주문 | 전달 완료, 권한 없으면 비활성 |

가게 도착 응답만으로 전환하지 않고 `RestaurantArrivedAtUtc`를 재조회한다. 미도착에 도착·픽업을 함께 허용하면 도착을 우선하고 픽업 명령도 막는다. 도착 행동/시도 ID를 제공하지 않는 기존 계약에서 픽업만 허용하는 경우는 기존 픽업 접근을 유지한다. 준비 예정 시각은 준비 완료 증거가 아니며 최종 명령 허용과 성공은 서버가 결정한다. API/DB·요금·배차·동시 픽업 권위는 변경하지 않는다.

업무 전체의 접기/펼치기는 추천/보조 상세 접기와 분리한다. 접혀도 현재 목적지 요약·배달료·경로 안내·고정 주 버튼은 남는다. 하나의 본문 스크롤과 지도 범례/현위치 공간 예약을 유지한다. 접기 토글 뒤 현재 업무 시작으로 돌아온다. 같은 건·같은 단계의 자동 재조회는 접기 선택을 유지하고 새 건·새 시도·단계 전환은 기본 펼침으로 복귀한다. `delivery` focus는 업무를, `dispatch/bundle`은 기존 추천을 펼친다. 오류/GPS 복구는 접힘 밖에 둔다.

구현·시험·최종 설치본 화면은 [수행 단계별 변경 기록](../../Changes/2026-10-04-driver-stage-cards-r1.md)에 연결한다.

### 전달지 우선 세 카드 r4 — 구현 전 책임 카드

이 항목은 이전 항상 전달지 우선 기준이며 현행은 위 r5다.

2026-10-04 후속 사용자 요청은 “기사가 현재 한 건의 전달 주소·요청·주문을 순서대로 읽고 해당 단계의 행동을 완료한다”다. 이전 r3의 한 카드 섹션 구분을 전달지 → 고객 요청 사항 → 주문 정보의 세 표면으로 바꾼다. 전달지의 전체 고객 주소를 최상단에 놓고 픽업 중에는 음식점 목적지를 보조 섹션으로 표시한다. 고객 요청 및 실제 수령인 정보는 기본 표시하고, 주문 요약·기사 배달료와 기존 상세 접기/현장 처리 행동을 마지막 카드에 둔다. 음식 주문금액이나 메뉴를 만들지 않는다.

카드별 스크롤·새 페이지·독립 상태는 만들지 않는다. 본문 하나·현재 단계의 고정 주요 버튼·지도 공간 예약·오류 복구·추천/설정·다른 배달 목록 제거·완료 후 다음 건 갱신을 유지한다. 배달 focus는 세 카드 시작으로 돌아와 주소를 지나치지 않는다. 표시용 픽업 여부만 기존 목적지 선택 기준에서 계산하고 API/DB·요금·배차 순서는 바꾸지 않는다. 코드/DB 관계는 아래 기존 연결을 재사용하며 [세 카드 변경 기록](../../Changes/2026-10-04-driver-three-cards-r1.md)에서 Android 실제 화면과 좁은 폭·큰 글자를 확인한다.

세 기본 카드가 있으므로 현재 배달이 있으면 기존 확장 높이 상한(70%)을 적용한다. 지도 범례·현위치 예약과 실제 본문/고정 행동 크기 상한은 그대로 유지한다. 추천 선택만 있는 경우와 대기는 기존 접기·펼치기 높이 조건을 유지한다. 상세 버튼은 세 카드 중 주문 정보의 보조 필드를 접고 기존 추천 목록도 펼친다. 수락/완료 시 표시 높이의 변경 알림을 보낸다.

### 카드 내부 정보 구분 r3 — 구현 전 책임 카드

이 항목은 이전 한 카드 기준이다. 현행 수행 기준은 위 r5, 시각 정렬은 r6다.

2026-10-04 사용자 요청. 현재 배달 카드 안의 정보를 섹션 제목·중립 구분선·여백으로 묶는다. 기본 화면의 배달 정보는 다음 목적지·전체 주소·배달료와 진행 안내이며, 펼친 상세는 주문 정보(기존 주문 요약·픽업/전달 주소), 고객 정보(실제 수령인·관계·연락처·전달 요청), 현장 처리(다음 행동 안내·가게 도착·현장 중단)로 나눈다. 고객 정보의 지정 수령인 문구를 유지하고 현재 없는 메뉴·수량·음식값을 만들지 않는다.

같은 날 후속 요청에 따라 카드의 다른 배달 목록·선택 버튼은 제거한다. 현재 건의 픽업 확인에서는 같은 건의 전달 정보로 바뀌고, 전달 완료 후에는 기존 서버 목록의 다음 남은 건이 같은 카드에 표시된다. 완료 실패 때는 현재 건을 유지한다. 다음 건을 미리 나열하거나 앱이 새 배차 순서를 계산하지 않는다.

기존 질문·결과와 접기·펼치기·가시 조건·서버 행동은 동일하다. 제목과 선은 같은 정보의 가시 조건 안에 두고, 본문 스크롤과 외부 고정 주요 버튼·지도 공간 확보를 유지한다. 새 페이지·섹션별 접기·독립 상태는 추가하지 않는다. 실제 Android 화면과 좁은 폭·큰 글자에서 구분·스크롤·주요 버튼을 확인하며, 변경 결과는 [카드 섹션 구분](../../Changes/2026-10-04-driver-card-sections-r1.md)에 기록한다.

기존 `MainPage.xaml` → `MainPageModel` → `IFoodDeliveryDriverApiService` → 음식배달 업무 API/원장 및 완료 정산 조회를 재사용한다. 표시 모드의 순수 상태는 `FDriverWorkspaceNavigationState`가 소유하고 실제 View 측정·스크롤·Android 뒤로 처리는 MainPage가 조립한다. 아래 영역 분리 r1은 API·DB·요율·서버 상태·App root·DI 등록을 변경하지 않았다.

## 본인 권역 복귀 설정 r42

`내 정보`에서 본인의 고정 기준점과 사용 방식을 조회·저장한다. 현재 위치를 명시적으로 기준점으로 선택할 수 있지만 실시간 GPS·기존 복귀지를 덮어쓰지 않는다. 기본 끄기이며 자동/켜기와 진입·해제 반경을 선택한다. 반경은 보조 설정에서 펼친다. 저장 뒤 재조회, 판본 충돌·응답 손실 안내, 계정 변경 시 비공개 값 제거를 화면이 소유한다. 수행 지도·현재 카드와 신규 수신 상태는 이 설정 화면이 변경하지 않는다.

인증 API→UseCase→보호된 Mongo 설정의 연결과 실제 큐/추천 점수는 [r38 기준](../../AI/Planning/공통/PLAN-OPERATIONS-NEIGHBORHOOD-MICRO-HUB/driver-return-area.implementation.r38.md), 검증 범위는 [r42 기록](../../Changes/2026-10-08-driver-return-area-r42.md)을 따른다. 임의 지도 기준점 선택·실제 휴대폰 화면 확인은 후속이며 로컬 컴파일과 ViewModel 시험을 단말 UI 검증으로 보고하지 않는다.
