# 활동 정산 지급 신고와 본인 주간 명세 책임 카드 r76

## 목적·화면 범위

`활동정산Screen`은 본인 활동 보수의 근거와 확인 상태를 조회한다. 목록, 선택 약정 상세, 본인 주간 명세는 한 번에 하나의 모드만 표시한다. 주간 명세를 열면 상세의 지급·동의 버튼을 감추고 목록으로 복귀할 수 있다. 개별 지급 신고는 해당 약정 상세 안에서만 수행한다.

## 지급 신고

서버가 현재 본인에게 허용한 `report-payment`와 `ReportablePaymentAmountKrw`가 있어야 입력을 표시한다. 양수 지급은 지급자, 음수 정정의 반환은 기존 수령자가 신고한다. 지급액·신고 내용·실제 지급 진술 동의를 입력받고 기존 `payment-reports` API로 보낸다. 원본 증빙·계좌·고객 주소는 화면에 추가하지 않는다.

같은 요청 ID·금액·배분·판본을 세션에 보존한다. 응답이 유실되면 새 POST를 보내지 않고 요청 영수증과 같은 약정의 정본을 다시 조회한다. 서버는 기존 미확인 지급 신고도 상한에서 예약한다. 수령 진술을 아직 하지 않았다는 이유로 같은 지급을 다시 신고할 수 없다. 계정 교체 시 입력·자료·미확정 요청을 지우며 늦은 응답은 폐기한다. 앱 프로세스가 종료된 뒤의 영속 복원은 이번 범위가 아니다.

## 본인 주간 명세

서버 claims의 본인 ID로 음식 기사 정산, 인수 완료 화물의 약정 운임, 본인 활동 보수만 읽는다. 기간은 한국 시간 수요일 00시부터 다음 수요일 00시 전까지 실제 업무 완료일 기준이며 지급 예정일·보수 기록일과 구분한다. 완료 시각을 확인할 수 없는 활동은 건수를 알리고 주간 합계에서 제외한다. 조회 실패는 빈 목록이나 0원으로 반환하지 않는다.

기존 음식·화물 채무를 새 활동 채무로 복제하지 않는다. 기존 배송 참고·배송비 포함 항목과 내부·통과금은 별도 수입으로 다시 합산하지 않고 입고 원가 배부는 조회 대상이 아니다. 화물 보수가 null이면 전체 발생액을 미확정으로 표시하고 확인된 부분 금액만 따로 제공한다.

발생액, 지급 조건 충족액, 보류액, 지급 신고액, 당사자 수령 진술액은 서로 다른 값이다. 음식의 모의 지급 성공과 기사 지급 준비·예정일은 은행 입금 증거가 아니다. 실제 은행 확인액은 null·미검증으로 유지한다.

## 권한·오류·경계

기존 정확한 `neighborhood-settlement-r38` Profile와 Simulation 게이트를 유지한다. 실송금 Provider, 자동 운영 마감, Operational 실행을 활성화하지 않는다. 주간 API에는 타인의 ID를 받는 매개변수가 없다. 로딩·인증 오류·금융 조회 오류에서는 값과 정상 빈 문구를 표시하지 않는다.

마트 수령 문제 해결 패널은 `MartOrder`와 양수 주문 ID가 연결되고, 현재 전문 원장이 본인을 실제 주문자 또는 판매자로 확인한 상세에서만 기존 마트 전용 API를 사용한다. 피킹·포장 참여자라는 이유만으로 수령 해결 화면을 열지 않는다. 서버도 같은 당사자 권한을 다시 검사한다. 원래 Hold/수령 증거와 금전 상태는 독립적으로 유지한다.

## 검증

서버의 본인 조회·완료 주간 경계·null 금액·중복 배송 제외, 지급 신고 상한·재조회·권한, 공유 화면 SSR을 회귀 시험으로 확인한다. 실제 모바일 설치·사용자 화면 검토·은행 송금·Operational 환경은 별도 검증이다.
