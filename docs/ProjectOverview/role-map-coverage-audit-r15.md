# 역할 앱의 지도 중심 구성 조사

2026-10-05 현재 소스를 기준으로 조사했다. **통합 앱에는 여덟 역할의 지도 화면이 있지만, 다른 역할의 기본 정보 카드와 전용 앱의 지도 진입은 아직 동일한 수준이 아니다.** 화면을 새로 늘리기보다 기존 업무 정보와 좌표를 지도에 연결하고, 현재 상태에서 필요한 행동을 하단 카드에 올리는 보완이 먼저다.

이번 작업은 소스 조사와 제안이다. 제품 코드 수정·새 빌드·실제 역할별 서버 업무·Android 지도 실행은 수행하지 않았다. [직전 Google 웹 지도 미리보기](../Changes/2026-10-05-google-map-web-preview-r14.md)는 실제 지도 타일 위에 예시 음식 기사 업무를 표시한 근거이며, 다른 역할의 실제 업무까지 검증한 결과는 아니다.

## 현재 화면의 구분

## 역할별 조정 제안

아래의 ‘현재’는 코드에서 확인한 사실이고, ‘조정’은 아직 구현하지 않은 제안이다. 지도는 장소·이동·업무 선택을 맡고, 하단 카드는 **지금 처리할 한 업무**를 맡는다. 입력·증빙·설정·정산은 기존 독립 페이지에 둔다.

| 역할 | 현재 | 지도에서 조정할 부분 | 기본 하단 카드 | 별도 페이지로 유지 |
| --- | --- | --- | --- | --- |
| 화물 기사 | 추천 의뢰의 상하차 핀과 직선 후보선은 있음. 현재 운송 항목에는 좌표가 없음 | 기사 소유의 현재 운송에 상하차 좌표를 서버에서 연결. 현재 목적지와 대기 목적지를 구분하고 실제 위치와 지도 중심을 분리 | 현재 단계, 다음 목적지, 운임, 거리 기준, 다음 현장 확인 | 차량·적재 조건, 상하차 사진·서명, 문제 신고 |
| 화주 | 상차·하차 핀, 최근 기사 위치, 직선 후보선이 있음 | 진행 의뢰를 선택하고 최근 위치의 시각·만료 상태를 표시. 실제 도로 경로와 후보선을 구분 | 운송 단계, 물품·수량, 기사 진행 상태, 다음 확인 | 의뢰 작성, 상세 조건, 증빙, 정산·타임라인 |
| 주문자 | 선택 주문의 추적 중 기사 핀은 있음. 음식점·수령지 좌표는 현재 상세 계약에 없음 | 먼저 기사 위치의 지연·종료 표시를 보완. 매장 탐색은 서버가 제공하는 공개 매장 좌표를 마련한 뒤 연결 | 주문 진행, 조리·픽업·전달 단계, 최근 위치 수신, 수령 확인 | 메뉴·주문 작성, 수령인 입력, 가격 변경 확인, 취소 사유, 주문 내역 |
| 음식점 | 주문별 매장 핀이 같은 좌표에 중복. 조리·재조리·준비 완료 행동은 있음 | 매장 핀 하나에 대기·조리·준비 완료 건수를 묶고, 아래에서 현재 주문 선택 | 메뉴·수량, 조리 단계, 준비 시각, 다음 행동 | 조리시간·거절 입력, 메뉴 설정, 전표 |
| 창고 | 작업 창고 핀과 입고·적재·피킹·포장·인계, 공정별 권한 확인이 있음 | 창고별 핀에 공정 건수를 묶고 현재 작업·운송 인계 선택. 실내 작업을 야외지도에 억지로 옮기지 않음 | 현재 공정, 품목·수량, 보관 위치, 다음 행동 | 검수·수량·보관 위치 입력, 바코드 스캔, 포장·인계 확인 |
| 운영자 | 실제 자료로 확인된 주문의 음식점·전달지 핀을 사용. 실제 기사 좌표 계약은 있지만 지도에 미연결 | 주문·매장·최근 기사 위치를 선택적으로 표시. 지도 조회 장애와 주문 카드 조회를 분리 | 현재 단계·담당자, 예외 이유, 다음 확인 | 중단 판정·근거, 요금 정책, 정산, 감사 기록 |
| 생활 | 지도·목록 전환, 제공·필요·보관 공간 레이어, 지역 요약 핀과 개인 배송 지도, 선택 배송 재조회가 있음 | 이미 있는 레이어와 요약을 유지하면서 제공·필요·보관 공간의 구분을 더 명확히 표시 | 선택 글·공간·할 일의 현재 상태와 다음 행동 | 글·물품·공간 등록, 신청·합의·증빙 |
| 음식 기사 | 통합 카드에 단계별 기본 정보가 있음. 기존 공통 지도 미리보기 확인 완료 | 다른 역할의 기본 카드 기준으로 재사용. 완료 직후 다음 업무 선택과 첫 조회의 경로 연결은 추가 점검 | 수락 전·픽업 중·전달 중 정보 | 요청 사유·증빙·내역·정산 |

현재 공통 `Summary`를 공급하는 역할은 음식 기사다. 다른 역할의 주요 정보는 접힌 `Sections`에 있어, 기본 카드 보완은 새 데이터를 만들기 전에 기존 정보를 옮기는 작업부터 할 수 있다. 긴 조건과 연락처를 모두 기본 카드로 옮기지는 않는다.

## 우선 보완해야 할 실제 간극

### 1. 화물 기사 지도에서 현재 위치와 지도 중심 분리

전용 Android 지도 처리기의 NAVER 위치 오버레이와 Google ‘현재 위치’ 마커는 모두 `CenterLatitude/CenterLongitude`를 사용한다(390~412행). 그런데 네이티브 홈은 추천 경로를 화면에 맞추기 위해 이 중심을 변경한다(514~536행). **소스상 현재 위치 표시가 경로를 보는 화면 중심과 함께 움직일 수 있다.** 실제 단말에서 재현한 결과는 아니다.

서버 기반 위치 변환에도 관측 위치가 없을 때 복귀지 좌표를 사용하고, 위치 시각이 없으면 상태 변경 시각 또는 현재 시각을 넣는 경로가 있다(202~214행). 이를 실제 현재 GPS와 같은 표시로 취급하면 안 된다.

제안: 관측 좌표·관측 시각·출처를 지도 카메라와 별도로 전달한다. 복귀지는 ‘복귀지 기준 위치’로 표시하고, 현재 위치 근거가 없거나 만료됐으면 현재 위치 오버레이를 숨긴다. 기존 직선 연결은 실제 주행 경로로 설명하지 않는다.

### 2. 화면을 보고 있는 동안의 갱신·핀 만료

공통 역할 화면에는 수동 갱신과 화면 복귀 재조회가 있지만, 화면을 계속 보고 있는 동안의 주기적인 업무 재조회는 없다. 주문자 서버는 마지막 위치 수신 후 30초가 지나면 지연으로 안내하지만, 지도 변환에서는 측정·조회 시각을 넘기지 않는다. 조회 당시의 ‘추적 중’ 핀이 화면에 계속 남을 수 있다.

화주는 조회 시 기존 10분 기준으로 오래된 기사 위치를 제외한다. 다만 시간 경과만으로 공통 화면이 갱신되는 흐름은 없다. 생활 지도는 선택 배송을 30초마다 재조회하는 별도 구현이 있으므로 같은 누락으로 분류하지 않는다. 역할별 기존 기준을 일괄 같은 시간으로 바꾸지 않는다.

제안: 화면에 표시 중인 선택 업무만 제한적으로 재조회하고, 위치 시각·지연 상태를 기본 카드에 표시한다. 종료·취소·만료 시 핀을 제거하며 화면 숨김·로그아웃·역할 변경에서는 재조회를 중단한다. 음식점 전용 앱의 기존 실시간 주문 알림과 복구 흐름도 보존한다.

### 3. 현재 화물 운송과 기존 좌표 연결

현재 운송 요약 계약에는 상하차 좌표와 명시적인 의뢰 ID가 없고, 전용 앱의 운송 표시 변환도 네 좌표를 `null`로 넣는다. 반면 기사 의뢰 상세에는 기존 상하차 좌표가 있다. 따라서 원천 자료를 새로 수집하기보다 **현재 기사 소유 운송과 해당 의뢰의 관계를 서버에서 확인하여 연결**하는 것이 우선이다.

운송 ID를 의뢰 ID로 간주하거나, 다른 추천의 좌표를 현재 운송에 붙이지 않는다. 기존 의뢰 상세 조회의 업무 관계·동의 검사는 생활배송 조건 안에 있으므로 일반 화물에도 같은 제한이 보장된다고 단정할 수 없다. 이미 기사 소유를 확인하는 운송 상세 조회를 기준으로 필요한 최소 좌표를 제공하는 방식이 적절하다.

### 4. 다음 업무 선택과 지도 사용 불가 시 목록

공통 선택은 기존 선택을 현재 업무보다 우선한다. 화물 기사에서는 완료된 선택 운송도 상세 조회로 다시 넣을 수 있다. 음식 기사에서는 이전 선택 ID로 경로를 먼저 계산한 뒤 공통 화면이 다른 현재 업무를 선택하므로 첫 조회에 새 업무의 경로·기사 위치가 빠질 수 있다.

제안: 수행 중 기사·창고 작업에서는 완료 후 서버가 알려 준 다음 업무를 우선하고, 주문자·음식점·운영자가 의도적으로 선택한 항목은 유지한다. 모든 역할을 일괄 자동 전환하지 않는다. 공통 지도에도 명시적인 지도/목록 전환을 두고, 지도 실패 때 목록과 행동을 사용할 수 있게 한다. 운영자는 선택적인 지도 자료 조회 실패가 주문 카드 조회까지 막지 않도록 분리하되 인증·권한 오류는 그대로 처리한다.

입력 화면 복귀 시에는 동일 계정·동일 역할의 지도 중심과 확대를 보존할 수 있다. 로그아웃·소유자·역할 변경 시 개인 업무와 좌표를 지우는 기존 경계는 유지한다. 공통 역할의 ‘목록 첫 100건 밖 선택 상세 조회 불가’는 확인되지 않았다. 현재 변환기는 선택 상세를 별도로 조회해 목록에 넣는다.

## 필요한 자료와 기존 정보의 경계

| 대상 | 현재 정보로 가능한 보완 | 추가로 필요한 서버 정보 |
| --- | --- | --- |
| 화주·창고 | 목적지·상태·수량·작업 정보의 기본 카드, 기존 핀 묶음 | 현재 범위의 화면 보완에 새 좌표 수집은 우선 아님 |
| 화물 기사 | 추천 지도와 기존 현장 행동 유지 | 기사 소유 현재 운송에 연결된 상하차 좌표·관측 위치 시각 |
| 주문자 | 기존 기사 위치 시각·지연·종료와 진행 정보 | 공개 매장 좌표, 현재 주문의 허용된 목적지 지도 정보. 화면에서 주소를 임의 좌표화하지 않음 |
| 음식점 | 매장 위치별 건수와 현재 조리 카드 | 접근 기사 위치를 추가하려면 해당 주문과 연결된 허용 범위의 정보 |
| 운영자 | 실제 자료의 기존 기사 좌표·시각을 지도에 연결 | 기존 실제/예시 출처 구분을 유지. 새 위치 수집보다 현재 계약 연결 우선 |
| 생활 | 기존 지역 요약·레이어·보관 공간·개인 배송 정보 | 공개 지도에 정확한 주거지 좌표를 추가할 필요 없음 |

주문자 현재 계약은 주소와 요청 정보를 제공하지만 매장·수령지 좌표는 제공하지 않는다. 운영자 배차 검토 계약에는 기사 좌표와 최근 수신 시각이 이미 있다. 이를 두 역할에서 동일하게 취급하지 않는다.

## 검증 범위

- 통합 역할 화면, 공통 카드·지도 변환, 음식·화물·창고 계약과 조회 권한, 전용 앱 진입·관련 화면을 읽었다. 조사 근거는 현재 로컬 작업 상태이며 HEAD 이후 기존 변경도 포함한다.
- 음식과 화물의 서버 업무·권한은 분리한다. 지도 공통화는 같은 화면 방식을 재사용하는 것이며 배차·정산 엔진을 합치는 제안이 아니다.
- 새 제안의 실행·실제 타일·GPS·도로 경로·Android·Azure·휴대폰 설치는 미검증이다. 구현할 때 해당 변경의 계약·상태 시험과 실제 화면 확인을 따로 남겨야 한다.
- 이번 변경은 이 조사 문서, 화면 안내 목차, 현재 작업 요약이다. 문서 링크 42개에 누락이 없고, 조사 전 변경 파일 중 이번 문서 외 841개 해시가 유지됐다. 이전 작업 요약과 기존 목차 내용도 보존했다. Fast `20261005-195131`·Task `20261005-195138`은 문서 범위로 통과했으며 제품 빌드·시험은 실행하지 않았다. 로컬 대조 결과는 `artifacts/local/role-map-coverage-audit-r15/final-checks.json`이다.

화면 책임 기준은 [전체 로드맵 페이지 원칙](../Architecture/WholeRoadmapPagePrinciple.md), 시각 기준은 [역할 앱 디자인 기준](../Architecture/RoleAppVisualDesignStandard.md), 기존 통합 지도 책임은 [역할 지도 화면 문서](page-docs/role-map-workspace-r11.md)를 따른다. 이번 제안은 새로운 공통 정책이나 구현 승인으로 대체하지 않는다.
